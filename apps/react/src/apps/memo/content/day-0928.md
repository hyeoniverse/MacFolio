이날 main에 들어간 커밋은 65개다. 한 일은 네 가지로 나뉜다.

1. 빌드·배포 정리: Firebase 제거, Cloudflare Workers 배포, 모노레포
2. 테스트와 CI: ESLint·Prettier, Playwright E2E, GitHub Actions
3. 앱 개편: 메모, 메시지, 터미널, 메일
4. 휴대폰 화면: 좁은 화면에서 iOS 홈 화면

이 순서로 한 것이 결과적으로 좋았다. 테스트를 먼저 붙여 둔 덕에, 오후에 앱 코드를 크게 바꿔도 깨진 곳을 바로 알 수 있었다.

![9월 28일 작업 흐름](./images/day-0928-timeline.svg '새벽에는 빌드·배포 정리, 오전에는 테스트, 오후부터는 앱과 휴대폰')

## Firebase 제거와 모노레포

CRA에서 Vite로 옮긴 뒤 남은 정리부터 했다([CRA에서 Vite로 옮기기](/memo/cra-to-vite)). 빌드 결과물과 `node_modules`를 git에서 빼고, 파일 종류별로 나뉘어 있던 폴더를 앱 단위로 다시 묶었다. 앱 목록은 manifest·registry 한 곳에서 관리하게 했다.

다음으로 Firebase를 없앴다. 메모 저장 기능이 Firebase 없이 동작하게 바꾸고, 사이트 호스팅을 Cloudflare Workers로 옮긴 뒤 Firebase 코드를 지웠다. 마지막으로 pnpm workspaces와 Turborepo로 모노레포를 만들었다. 다음 날 API 서버를 같은 저장소에 넣을 수 있었던 것은 이 작업 덕분이다.

## 테스트를 붙이자 나온 버그

ESLint·Prettier, Playwright E2E, GitHub Actions CI를 PR 하나로 붙였다. 테스트를 돌리자마자 버그가 나왔다. **음악 창을 닫으면 그 창뿐 아니라 Dock까지 화면 전체가 사라졌다.** 원래부터 동작하지 않던 기능 몇 개도 이때 발견했다([테스트를 붙이자 보인 버그들](/memo/bugs-found-by-tests)).

이어서 창 관련 코드를 정리했다. 창 위치·크기와 겹치는 순서를 계산하는 부분을 순수 함수로 분리해 Vitest로 시험하고, 창을 상태 기반으로 다시 작성하고, 앱 하나에서 오류가 나도 화면 전체가 멈추지 않게 에러 경계를 넣었다. 설정 앱과 다크 모드도 이때 만들었다.

아침에 0개였던 E2E는 자정에 78개, 단위 시험은 142개가 되었다.

## 다섯 번 바뀐 메시지 앱

앱을 하나씩 다시 만들었다. 메모 앱은 블로그가 되었고, 따로 있던 Blog 앱은 지웠다. 터미널 앱은 명령어로 자기소개를 하고, 메일 앱은 방문자가 연락 메일을 쓰는 앱이 되었다.

메시지 앱만은 네 시간 동안 방향이 다섯 번 바뀌었다.

| 시각  | 메시지 앱                                 |
| ----- | ----------------------------------------- |
| 10:37 | 방명록으로 추가                           |
| 11:13 | 방문자별 공개 대화로 개편                 |
| 13:23 | 사람별 공개 방명록, macOS 26 디자인       |
| 14:21 | 방은 쓰기 단추로만 만든다                 |
| 14:37 | 감상·의견·피드백 공간으로, 예전 목록 정리 |

마지막 모양은 이슈 [#23](https://github.com/hyeoniverse/MacFolio/issues/23)에 처음 적어 둔 내용과 거의 같다. 시작하기 전에 이슈를 다시 읽었으면 중간의 네 번은 하지 않아도 됐다.

## 휴대폰 화면

저녁부터는 휴대폰 화면을 만들었다. 화면이 좁으면 macOS 데스크톱 대신 iOS 홈 화면을 보여 주고, 상태 표시줄·제어 센터·음악 위젯·앱 전환기를 차례로 붙였다.

![지금의 휴대폰 홈 화면](./images/day-0928-mobile-home.jpg '이날 만든 휴대폰 홈 화면의 지금 모습. 위젯과 아이콘은 그 뒤에 더 바뀌었다')

밤에는 메모 앱을 macOS 메모처럼 다듬었다. 목록·갤러리 보기, 폴더 트리, 끌어서 옮기기, 고정, 코드 문법 강조를 넣고, 메모 편집은 관리자만 할 수 있게 바꿨다([메모 편집을 관리자만 하게 한 이유](/memo/read-only-memo)).

![지금의 데스크톱과 메모 앱](./images/day-0928-desktop.jpg '이날 다듬은 메모 앱의 지금 모습. 글 목록은 그 뒤에 쓴 글들이다')

변경량은 메모, 메시지, 데스크톱, 음악 순으로 많았다. 앱을 다시 만든 날이라 지운 줄도 많다.

![9월 28일 영역별 변경](./images/day-0928-areas.svg '더한 줄과 지운 줄. 머지 커밋, 잠금 파일, 그림은 뺐다')

## 돌아보며

잘한 점은 작업 순서다. 빌드 정리 → 테스트 → 앱 개편 순으로 해서, 앱을 여러 번 다시 만들 때마다 E2E가 문제를 잡아 주었다. 새벽에 만든 모노레포 덕에 다음 날 서버도 바로 추가할 수 있었다.

아쉬운 점은 방향을 정하지 않고 만든 부분이다. 메시지 앱은 무엇을 위한 공간인지 정하기 전에 화면부터 만들어서 다섯 번 바뀌었다. 휴대폰의 뒤로 가기도 19시 45분, 20시 18분, 23시 4분에 세 번 고쳤다. 화면마다 뒤로 가기의 동작을 정한 규칙 없이 앱마다 따로 고쳤기 때문이다. 이 문제는 나중에 뒤로 가기를 내용 위에 뜨는 단추 하나로 통일하면서 해결했다.
