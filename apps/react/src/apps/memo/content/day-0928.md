하루 동안 커밋 65개가 main에 들어갔다. 새벽 0시 15분에 시작해 밤 11시 24분에 끝났다. 크게 보면 네 덩어리다. 빌드·배포 판 바꾸기, 테스트와 CI, 앱 다시 짜기, 휴대폰 화면.

![9월 28일 작업 흐름](./images/day-0928-timeline.svg '새벽에는 판 바꾸기, 오전에는 테스트, 오후부터는 앱과 휴대폰')

## 새벽: 판을 새로 깔기

CRA에서 Vite로 옮긴 뒤 남은 일부터 했다. 빌드 산출물과 `node_modules`를 git에서 빼고, 파일 종류별로 나뉘어 있던 폴더를 앱 단위로 다시 묶었다. 앱 목록도 manifest·registry 한 곳에서 관리하게 했다.

그다음은 Firebase를 걷어 내는 일이었다. 메모 저장소를 Firebase 없이도 돌게 떼어 내고, 프론트엔드 호스팅을 Cloudflare Workers로 옮긴 뒤 Firebase를 지웠다. 마지막으로 pnpm workspaces와 Turborepo로 모노레포를 만들었다. 다음 날 API를 같은 저장소에 넣을 자리다.

| 한 일                                            | 글                    |
| ------------------------------------------------ | --------------------- |
| Vite 전환 마무리, 측정 결과 정리                 | CRA에서 Vite로 옮기기 |
| 앱 단위 폴더, manifest·registry                  | CRA에서 Vite로 옮기기 |
| Firebase 제거, Cloudflare Workers 배포, 모노레포 | -                     |

## 오전: 테스트를 붙이자 버그가 보였다

오전 9시 42분부터 ESLint·Prettier를 걸고, Playwright E2E를 붙이고, GitHub Actions로 포맷·린트·타입 체크·빌드·E2E를 돌게 했다. 테스트를 붙이자마자 버그가 나왔다. **Music 창을 닫으면 창만이 아니라 Dock까지 화면이 통째로 사라졌다.** 한 번도 동작한 적 없던 기능도 이때 함께 드러났다.

이어서 창 코드를 손봤다. 창 위치·크기와 쌓임 순서 계산을 순수 함수로 떼어 Vitest로 시험하고, 창을 상태 기반으로 다시 썼다. 앱 하나가 죽어도 화면 전체가 죽지 않게 에러 경계도 넣었다. 설정 앱과 다크 모드도 이때 생겼다.

| 한 일                                              | 글                          |
| -------------------------------------------------- | --------------------------- |
| ESLint·Prettier, Playwright E2E, GitHub Actions CI | 테스트를 붙이자 보인 버그들 |
| Music 창을 닫으면 멈추던 문제                      | 테스트를 붙이자 보인 버그들 |
| 창 계산을 순수 함수로, 상태 기반 창, 에러 경계     | 테스트를 붙이자 보인 버그들 |
| 설정 앱 (화면 모드, 배경화면), 앱마다 다크 모드    | -                           |

하루가 끝날 때 브라우저 E2E는 78개, 단위 시험은 142개였다. 아침에는 둘 다 0개였다.

## 오후: 앱을 하나씩 다시 짜기

오후에는 앱을 하나씩 열어 다시 짰다. 메모 앱은 블로그가 되었고, 따로 있던 Blog 앱은 지웠다. 터미널 앱을 새로 만들어 명령어로 자기소개를 하게 했고, 메일 앱은 방문자가 연락 메일을 쓰는 앱으로 바꿨다. 한 번이라도 연 앱만 그리게 해서 첫 화면도 가볍게 했다.

메시지 앱은 방향이 다섯 번 바뀌었다.

| ----- | ----------------------------------------- |
| 10:37 | 방명록으로 추가                           |
| 11:13 | 방문자별 공개 대화로 개편                 |
| 13:23 | 사람별 공개 방명록, macOS 26 디자인       |

## 저녁: 좁은 화면은 iOS로

저녁 6시 35분부터는 휴대폰이었다. 좁은 화면에서는 macOS 데스크톱 대신 iOS 홈 화면이 보이게 하고, 상태 표시줄·제어 센터·음악 위젯·앱 전환기를 차례로 붙였다. 프로젝트 전반에 애니메이션도 넣었다.

![지금의 휴대폰 홈 화면](./images/day-0928-mobile-home.jpg '이날 만든 휴대폰 홈 화면의 지금 모습. 위젯과 아이콘은 그 뒤에 더 바뀌었다')

밤에는 다시 메모로 돌아와 macOS 메모처럼 다듬었다. 목록·갤러리 보기와 폴더 트리, 끌어 옮기기, 3단까지의 폴더, 고정, 코드 문법 강조가 이때 들어갔다. 마지막으로 메모 편집은 관리자만 하게 하고(방문자는 읽기 전용), GitHub 앱을 지금 프로필에 맞게 새로 만들었다.

![지금의 데스크톱과 메모 앱](./images/day-0928-desktop.jpg '이날 다듬은 메모 앱의 지금 모습. 글 목록은 그 뒤에 쓴 글들이다')

## 돌아보며

- **잘한 것: 테스트를 일찍 붙였다.** 붙이자마자 Music 창 버그가 나왔다. 그 뒤로 앱을 몇 번씩 다시 짜도 E2E가 받쳐 주었다.
- **잘한 것: 판을 먼저 깔았다.** 모노레포와 Workers 배포를 새벽에 끝내 둔 덕에, 다음 날 API를 같은 저장소에 바로 넣을 수 있었다.
- **아쉬운 것: 메시지 앱의 방향을 만들면서 정했다.** 네 시간 동안 다섯 번 바뀌었다. 무엇을 남기는 공간인지 먼저 한 줄로 정했으면 두세 번은 줄었을 것이다.
- **아쉬운 것: 휴대폰 뒤로 가기를 세 번 고쳤다.** 19시 45분, 20시 18분, 23시 4분. 화면마다 뒤로 가기가 무엇인지 규칙 없이 앱마다 고쳤기 때문이다. 이 규칙은 나중에 뒤로 가기를 내용 위에 뜨는 단추 하나로 정리하면서 자리를 잡았다.
