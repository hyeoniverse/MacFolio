리팩터링 계획([#150](https://github.com/hyeoniverse/MacFolio/issues/150)) 4단계 둘째 항목 "새로 뽑을 것"의 둘째 컴포넌트. [Modal 추출](/memo/ui-modal)에 이어, [공통 UI 부품 목록](/memo/ui-inventory)에서 뽑기로 한 `Sheet`를 진행했다.

## 세 곳의 시트

휴대폰 화면에서 아래에서 올라오는 시트는 세 곳에 있었다.

| 시트              | 오버레이 | 모양                                      | 닫힐 때                        |
| ----------------- | -------- | ----------------------------------------- | ------------------------------ |
| 메일 쓰기·답장    | 있음     | 화면 높이에 가까운 시트, 위에 손잡이 막대 | 타이머로 240ms 기다렸다 내려감 |
| 메일 동작         | 있음     | 아래에 떠 있는 카드                       | 같은 타이머                    |
| 음악 지금 재생 중 | 없음     | 화면 전체를 덮음                          | 애니메이션 없이 사라짐         |

세 곳 모두 `translateY(100%)`에서 올라오는 키프레임과 `role="dialog"`를 각자 적었다. 메일은 닫히는 애니메이션을 보여 주려고 `closing` 상태와 `setTimeout(240)`을 두고, 시간이 지난 뒤에 시트를 지웠다. 음악은 닫히는 애니메이션이 없었다.

## Sheet 컴포넌트

![Sheet가 맡는 것과 쓰는 쪽이 정하는 것](./images/ui-sheet-layers.svg '공통 동작은 Sheet가, 콘텐츠와 안쪽 여백·색은 쓰는 쪽이 정한다')

`shared/ui/sheet/Sheet`는 공통 동작만 맡는다.

- **오버레이**: 시트 뒤를 어둡게 덮고, 누르면 `onClose`를 부른다.
- **올라오는 애니메이션**: `sheet-in` 키프레임 하나.
- **닫기**: Esc, 오버레이 누르기.
- **접근성**: `role="dialog"`, `aria-modal`, `aria-label`. 열 때 시트에 포커스를 둔다(스크롤 없이). 안의 입력 칸이 이미 포커스를 가져갔으면(autoFocus) 그대로 둔다.
- **닫히는 애니메이션**: 오버레이의 어두운 바탕이 걷히고 시트가 아래로 내려간다.

모양 차이는 `variant` 셋으로 나눴다.

| variant | 쓰는 곳           | 모양                                                             |
| ------- | ----------------- | ---------------------------------------------------------------- |
| `page`  | 메일 쓰기·답장    | 상태 표시줄 아래부터 바닥까지, 위 모서리만 둥글게, 손잡이 막대   |
| `card`  | 메일 동작         | 홈 막대 위에 떠 있는 카드, 네 모서리를 둥글게, 스프링 애니메이션 |
| `cover` | 음악 지금 재생 중 | 오버레이 없이 앱 화면 전체를 덮는다                              |

오버레이 색·z-index·시트 바탕은 쓰는 쪽 CSS가 `--ui-sheet-dim`·`--ui-sheet-z`·`--ui-sheet-bg`로 정한다. 음악은 `--ui-sheet-bg: #1c1c1e`로 어두운 바탕을 쓴다. 안쪽 여백과 콘텐츠는 `className`과 children이 정한다.

`cover`는 `aria-modal`을 붙이지 않는다. 음악의 시트는 시트 바깥에 떠 있는 뒤로 가기 버튼으로 닫는데, `aria-modal`을 붙이면 화면 읽기 프로그램이 그 버튼을 가려 버리기 때문이다.

## 닫기 타이머를 없앤 방법

닫히는 애니메이션을 보여 주려면 요소가 애니메이션 동안 남아 있어야 한다. 메일은 이것을 상태로 풀었다. 닫기를 누르면 `closing`을 켜고 240ms 뒤에 시트를 지웠다. 그 사이 시트는 아직 열린 상태라, 시험과 화면 읽기 프로그램도 240ms 동안 열린 시트를 봤다.

`Sheet`는 `Modal`과 같이 `useExitMotion`을 쓴다. 쓰는 쪽이 `{sheet && <Sheet />}`로 지우면, React가 요소를 떼어 내기 직전에 겉모습만 복사해 같은 자리에 두고, 복사본에 사라지는 애니메이션을 건다. 실제 시트는 바로 사라지므로 상태와 시험은 닫힌 뒤를 본다.

- 오버레이 복사본에는 `dim-out`을 건다. 오버레이 전체를 흐리게 하는 `fade-out`을 쓰면 안의 시트까지 흐려지므로, 어두운 바탕색만 걷히게 했다.
- 복사본 안의 시트에는 `[data-exiting] .ui-sheet` 선택자로 `sheet-out`(아래로 내려감)을 건다.
- 둘 다 240ms라 기존 메일과 같은 시간에 끝난다.

메일의 `closing` 상태, `setTimeout`, 타이머 정리 `useEffect`, 움직임 줄이기 분기가 모두 없어졌다. 음악 지금 재생 중은 이번에 처음으로 내려가며 닫힌다.

## 열 때 주는 포커스가 화면을 끌어당긴 문제

처음 만든 `Sheet`를 미리보기에서 휴대폰으로 열어 보니, 음악 지금 재생 중이 올라올 때 화면이 위아래로 튀었다. 열리는 순간 시트에 포커스를 주는데, 이때 시트는 아직 `translateY(100%)`에서 올라오는 중이었다. 브라우저는 포커스를 받은 요소를 보이게 하려고 앱 화면(`.music`)을 343px 스크롤했고, 애니메이션이 끝나며 다시 0으로 돌아왔다.

![시트가 올라오는 동안 앱 화면의 스크롤 위치](./images/ui-sheet-scroll.svg '수정 전에는 343px까지 스크롤됐다가 돌아오고, 수정 후에는 0에 머문다')

`focus({ preventScroll: true })`로 포커스는 주되 스크롤은 하지 않게 했다. 함께 고친 것이 하나 더 있다. 포커스와 Esc 처리를 담은 `useEffect`가 `onClose`에 의존하고 있었는데, 음악 화면은 재생 위치가 바뀔 때마다 다시 그려지며 새 `onClose` 함수를 넘긴다. 효과가 계속 다시 돌지 않도록, 최신 `onClose`는 ref에 담아 두고 효과는 열 때 한 번만 돌게 했다. 움직임을 켠 E2E에 "시트가 올라오는 동안 앱 화면이 스크롤되지 않는다" 시험을 더했고, 고치기 전 코드에서는 이 시험이 실패한다.

## 옆으로 밀면 왼쪽 여백이 사라지던 문제

같은 미리보기에서 음악 지금 재생 중의 왼쪽 여백이 사라져 제목과 시간이 화면 끝에 닿는다는 이야기를 들었다. 시트 안의 흐린 표지 배경(`::before`)은 가장자리가 비지 않도록 `inset: -40px`로 시트보다 사방 40px 크게 그린다. 시트는 `overflow-y: auto`였는데, 한쪽 축만 `auto`로 두면 다른 축도 `visible`이 아니라 `auto`로 계산된다. 그래서 넘친 배경 때문에 시트가 가로로 40px 스크롤되었고, 휴대폰에서 옆으로 밀면 내용이 왼쪽으로 밀렸다. 이 문제는 `Sheet`로 옮기기 전부터 있었다.

`Sheet.css`에서 `page`·`cover` 시트에 `overflow-x: hidden`을 주어 세로로만 스크롤되게 했다. 휴대폰 E2E에서 시트를 가로로 밀어도 `scrollLeft`가 0인지 확인한다. 고치기 전 코드에서는 40이 나온다.

## 확인

- 전후 화면: 메일 쓰기 시트와 메일 동작 카드는 픽셀 단위로 같다. 음악 지금 재생 중은 상태 표시줄의 시계만 달랐다.
- E2E: 휴대폰 메일·음악 시험이 그대로 통과한다. 닫힐 때 복사본이 내려가고 끝나면 남지 않는지는 움직임을 켠 `mobile-motion.spec.ts`에 시험을 하나 더했다.
