## 연재를 제목 대신 칸으로 ([#404](https://github.com/hyeoniverse/MacFolio/pull/404))

### 제목 형식에서 칸으로

트래픽 분석 11편, 보안 점검 12편처럼 이어지는 글이 날짜순 목록에 흩어져 있어, 한 연재를 처음부터 이어 읽기 어려웠다. 첫 구현([4e1e8bcac](https://github.com/hyeoniverse/MacFolio/commit/4e1e8bcac))에서는 제목이 `이름 번호 - 제목` 형식인 글을 연재로 판별해 같은 연재 목록과 이전 편·다음 편 상자를 보였다.

> [!WARNING] 제목이 연재 정보를 겸하면 제목을 고칠 때 연재가 깨진다
> 제목을 고치다 형식이 깨지면 그 글은 연재에서 빠진다. 제목이 글 이름과 연재 정보를 함께 담아, 연재 순서를 바꾸려면 제목을 고쳐야 했다.

그래서 첫 구현 1시간 23분 만에 연재를 제목에서 떼어 별도 칸으로 옮겼다([9b89e56c5](https://github.com/hyeoniverse/MacFolio/commit/9b89e56c5)).

| 위치                            | 칸                                                                     |
| ------------------------------- | ---------------------------------------------------------------------- |
| 저장소 글 (`memo/content/*.md`) | 머리말 `series`, `seriesOrder`                                         |
| `Post`                          | 게시본 `series`·`seriesOrder`, 임시본 `draftSeries`·`draftSeriesOrder` |
| `PostRevision`                  | 게시 시각의 `series`·`seriesOrder`                                     |

- **마이그레이션** `20261029120000_post_series`: nullable 열 추가와 CHECK 제약 둘(이름은 공백 문자열이 아님, 순서는 1 이상)뿐이라, 배포가 이미지를 되돌려도 이전 코드가 동작한다.
- **contracts**: `series` 40자, `seriesOrder` 1~999 정수. `openapi.json`을 다시 생성했다.
- **판별** (desktop-core `series.ts`): ==같은 이름의 글이 두 편 이상일 때만 연재로 본다==. `seriesOrder` 오름차순이고 순서가 없는 글은 뒤에 날짜·첫 게시 시각·제목 순으로 놓는다. 화면의 번호는 정렬 위치라 순서 값이 건너뛰어도 1, 2, 3…으로 표시한다.
- **저장소 글**: 연재 글 139편(24개 연재)의 제목에서 `이름 번호 - `를 빼고 기존 번호를 `seriesOrder`로 옮겼다. 같은 날 쓴 연재도 순서가 유지된다.

### 편집 화면의 연재 고르기

편집 화면에서는 읽기 화면의 연재 표시와 같은 자리(제목 바로 위)에서 연재를 고른다. 연재가 있으면 강조색 글자와 순서 칸, 없으면 점선 칩 "+ 연재 지정"을 보이고, 누르면 연재 없음·기존 연재 목록·새 연재… 메뉴가 열린다. 연재를 빼면 순서도 함께 삭제한다. 바꾼 연재·순서는 다른 칸처럼 임시 저장되고 게시하면 게시본으로 옮겨진다.

첫 구현에서는 연재 상자가 읽기 화면에만 있어, 관리자 편집 화면의 제목 아래에도 보이게 했다([79867f780](https://github.com/hyeoniverse/MacFolio/commit/79867f780)).

## 연재 블록과 줄인 목록

![연재 블록](./images/week-1026-series-reader.jpg#float-right '트래픽 분석 2편. 제목 위 연재 표시, 제목 아래 연재 블록과 이전 편·다음 편 카드')

제목 아래에 같은 연재의 목록과 이전 편·다음 편 카드를 담은 블록을 넣었다. 머리 줄에는 연재 이름과 지금 편 / 전체 편 수를 표시하고, 목록은 목차와 같은 모양(왼쪽 세로선, 지금 글은 강조색 막대)이다. 누른 편이 지금 보는 폴더·태그 밖에 있으면 보기를 모든 글로 바꾼 뒤 연다.

본문에는 날짜·폴더 줄과 제목 사이에 강조색 한 줄 `◈ 트래픽 분석 2`를, 글 목록·갤러리에는 제목 위 별도 줄에 `◈ 트래픽 분석 #2`를 표시한다. 목록의 번호 표기는 대괄호(`[2]`)와 `#2`를 거쳐 제목 위 별도 줄로 정했다. 아이콘은 화면 낭독기에 "연재"로 읽힌다.

## 아코디언의 길이와 곡선

줄인 편도 DOM에 항상 렌더링하고, 묶음마다 `grid-template-rows: 0fr ↔ 1fr`로 그 자리에서 펼친다. 사이의 `⋮`는 반대로 접혀 사라진다. 접힌 묶음은 `visibility: hidden`이라 Tab 이동과 접근성 트리에서 빠진다.

처음 값(280ms, `--ease-out`)으로는 움직임이 보이지 않았다. 연재 더보기의 높이를 30ms 간격으로 재자 403 → 579 → 612 → 631px로, ==높이 변화의 77%가 첫 30ms 안에 끝났다==. 초반 가속이 큰 곡선이라 움직임 대부분이 첫 두 프레임에 몰렸다.

| 항목 | 전           | 후                                                         |
| ---- | ------------ | ---------------------------------------------------------- |
| 길이 | 280ms        | `--duration-slow` 400ms                                    |
| 곡선 | `--ease-out` | 새 토큰 `--ease-in-out` (`cubic-bezier(0.65, 0, 0.35, 1)`) |
| 내용 | 바로 나타남  | 위에서 12px 내려오며 나타난다                              |

같은 움직임을 목차, 읽기 화면의 `<details>`, 편집 화면의 토글 블록에도 적용했다([b9532e140](https://github.com/hyeoniverse/MacFolio/commit/b9532e140)). 바꾼 뒤 40ms 간격으로 잰 높이는 다음과 같다.

| 대상                | 높이 (px, 40ms 간격)                    |
| ------------------- | --------------------------------------- |
| 연재 더보기         | 375 → 391 → 447 → 557 → 604 → 627 → 631 |
| 목차                | 38 → 53 → 107 → 273 → 344 → 365 → 367   |
| 읽기 화면 접기 블록 | 52 → 84 → 240 → 441 → 531 → 544         |
| 편집 화면 토글 블록 | 50 → 84 → 191 → 403 → 509 → 541 → 544   |

- **읽기 화면 `<details>`**: `::details-content`의 `block-size`를 `interpolate-size: allow-keywords`로 0 ↔ auto 전환한다. 지원하지 않는 브라우저는 바로 펼친다.
- **편집 화면 토글**: ProseMirror가 그리는 토글은 접힌 내용을 `display: none`으로 감춘다. 펼치는 `@starting-style`을 늘 걸면 편집기를 열거나 토글 안에 문단을 새로 쓸 때도 움직였다. › 를 누른 순간에만 편집기 루트(`view.dom`)에 `.memo-details-animating`을 450ms 붙여 그동안만 전환한다.
- **움직임 줄이기**: `prefers-reduced-motion: reduce`면 모두 바로 펼친다.

> [!NOTE] 편집기 루트의 class는 글 변경이 아니다
> 루트 요소의 속성 변화는 ProseMirror가 글 변경으로 읽지 않아, class를 450ms 붙였다 떼어도 임시 저장이 생기지 않는다.

## 돌아보며

연재 이름·순서처럼 코드가 읽는 값은 처음부터 별도 칸에 보관했어야 했다. 제목 형식으로 연재를 판별한 첫 구현은 제목을 고치는 순간 연재가 깨지는 구조라, 1시간 23분 만에 칸으로 옮겼다. 사람이 읽는 글자(제목)와 프로그램이 판별에 쓰는 값을 한 칸에 담으면 어느 한쪽을 고칠 때 다른 쪽이 깨진다.

줄인 목록의 규칙은 커밋 10개에 걸쳐 바꿨다. 최신 편부터 보이다가 1편부터로 바꾸고, 생략 표시를 `⋯`에서 `⋮`로 바꾸고, 한 편만 빠지는 자리를 따로 처리했다. 연재는 1편부터 읽는다는 전제와, 11편 연재에서 1·6·9편을 열었을 때의 표를 먼저 만들었다면 처음부터 마지막 규칙으로 구현할 수 있었다. [10월 27일 회고](/memo/day-1027)에서 목차 글자색을 다섯 번 바꾼 것과 같은 실수를 반복했다.

"움직임이 보이지 않는다"는 인상을 30ms 간격의 높이 측정으로 확인하자, 변화의 77%가 첫 30ms 안에 끝난다는 것이 드러났다. 길이와 곡선을 바꾼 뒤 같은 방법으로 재어 네 곳 모두 고르게 늘어나는 것도 확인했다. 감으로 길이만 늘렸다면 곡선이 원인이라는 것을 찾지 못했을 것이다.

마이그레이션은 nullable 열과 CHECK 제약만 더해 이전 코드와 호환되게 했다. 배포가 이미지를 되돌려도 DB는 되돌릴 필요가 없다.
