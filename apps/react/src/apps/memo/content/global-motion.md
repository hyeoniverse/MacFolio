메뉴, 경고창, 단축키 창, 편집기의 서식 창은 열 때 `pop-in`으로 살짝 커지며 나타났다. 닫을 때는 그냥 사라졌다. 열 때 부드러운 만큼 닫을 때 끊기는 게 더 눈에 띄었다.

## 사라지는 움직임이 어려운 까닭

여는 쪽은 거의 이렇게 생겼다.

```tsx
{menu && <Menu onClose={() => setMenu(null)} … />}
```

`menu`가 `null`이 되면 React는 바로 `<Menu>`를 지운다. 사라지는 애니메이션을 보여 주려면 지우기를 늦춰야 하는데, 방법은 둘이었다.

- **닫기를 늦춘다.** `onClose`를 140ms 뒤에 부른다. 그러면 그동안 메뉴는 열린 것으로 남는다. 단추의 `aria-expanded`, 초점 돌려주기, "닫혔는지" 보는 시험이 모두 140ms씩 늦어진다.
- **여는 쪽마다 "닫히는 중" 상태를 둔다.** 메뉴를 여는 곳이 수십 군데라 모두 고쳐야 한다.

둘 다 마음에 들지 않았다. 닫기는 바로 끝나야 하고, 여는 쪽은 그대로 두고 싶었다.

## 지우기 직전에 겉모습만 복사한다

React 19의 ref 콜백은 정리 함수를 돌려줄 수 있고, 이 함수는 요소를 떼어 낼 때 불린다. 이때 요소는 아직 문서에 붙어 있다. 그 순간 요소를 복사(`cloneNode`)해 바로 옆에 두고, 복사본에 사라지는 애니메이션을 건다. React는 원래 요소를 지우고, 복사본은 애니메이션이 끝나면 스스로 지운다.

```ts
export function useExitMotion(motion = 'pop-out') {
	return useCallback(
		(element) => {
			if (!element) return;
			return () => playExit(element, motion); // 떼어 내기 직전
		},
		[motion]
	);
}
```

여는 쪽은 바뀌지 않는다. `<Menu>` 안에서 뿌리 요소에 이 ref를 걸기만 하면 된다. 메뉴는 바로 닫히고(상태, 초점, 시험이 모두 닫힌 뒤를 본다), 눈에는 140ms 동안 작아지며 흐려지는 메뉴가 보인다.

| 열린 메뉴                                                                | 닫는 중 (복사본)                                                                                                       |
| ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| ![열린 파일 메뉴](./images/global-motion-menu-open.jpg '열린 파일 메뉴') | ![사라지는 파일 메뉴](./images/global-motion-menu-out.jpg '닫는 중: 복사본이 작아지며 흐려진다. 움직임을 멈춰 찍었다') |

### 복사본이 지켜야 할 것

복사본은 겉모습일 뿐이라, 화면 말고는 아무 데에도 나타나면 안 된다.

- `inert`와 `pointer-events: none`으로 누를 수 없게 했다. 닫히는 메뉴 자리를 바로 누르면 그 밑의 것이 눌린다.
- `aria-hidden`을 걸고 `role`·`id`·`aria-label`을 지웠다. 화면 읽기 프로그램과 시험(`getByRole('menu')`)은 복사본을 찾지 못한다.
- 복사본 안의 나타나는 애니메이션은 끈다. 복사한 요소는 새 요소라서 `pop-in`이 처음부터 다시 돈다. `[data-exiting] * { animation: none }`로 막고, 경고창처럼 바탕과 상자가 따로 움직이는 것만 상자에 `pop-out`을 다시 건다.
- 움직임 줄이기 설정을 켰으면 복사하지 않는다.
- `animationend`가 오지 않아도(숨은 탭 등) 시간이 지나면 지운다.

### 컴포넌트가 null을 돌려줄 때도

처음에는 언마운트 때 도는 효과(`useLayoutEffect`의 정리)로 만들었다. 그런데 로그인 창은 컴포넌트가 그대로 있고 `return null`로 사라진다. 언마운트가 없으니 정리도 불리지 않았다. ref 콜백의 정리는 요소가 떨어질 때마다 불려서 두 경우를 다 잡는다.

## 화면이 바뀌는 칸

데스크톱 앱에서 목록이나 내용이 통째로 바뀌는 곳은 `key`를 바꿔 새로 그리고, 공통 클래스 `motion-swap`(160ms `fade-in`)을 달았다. Finder의 폴더·문서, 메모의 폴더·태그·정렬, 메일의 사서함과 메일, 메시지의 대화, Safari의 탭, 사진의 앨범, 활동 상태 보기의 탭, 이미지 넣기 창의 탭이다.

메모 목록은 감싸는 요소를 더하지 않았다. 휴대폰 CSS에 `.memo-phone-title + .memo-items`처럼 바로 옆을 보는 선택자가 있어서, 감싸면 그 규칙이 깨진다. 대신 `key`를 단 `React.Fragment`로 목록을 새로 그렸다. DOM은 그대로이고 목록만 다시 만들어진다.

## 동작 하나하나에

공통 규칙만으로는 잘 보이지 않았다. 사진을 넘기거나 정보 판을 여는 것처럼, 누를 때마다 무엇이 어디서 오고 어디로 가는지 보여야 했다. 그래서 앱마다 동작을 하나씩 짚어 움직임을 붙였다.

### 넘긴 방향 알기

"다음 사진은 오른쪽에서"를 하려면 방향을 알아야 한다. 넘기는 길이 여럿이라(키, 화살표, 트랙패드, 밀기, 사진 띠, 메뉴 막대), 누른 곳마다 방향을 적는 대신 **보이는 번호가 바뀐 방향**을 그리는 중에 정한다(`useMoveDirection`). 앞 번호를 상태로 들고 있다가 번호가 바뀌면 비교하고, 그 결과를 칸의 `data-direction`에 둔다. 끝에서 처음으로 돌아가는 것은 다음으로 친다(사진). 방문 기록처럼 돌아가지 않는 목록(Finder)은 번호 그대로 본다.

Finder에서 처음에는 방향이 남아 있어서, 보기(아이콘·목록)를 바꿔도 옆에서 밀려 들어왔다. 번호와 상관없이 칸이 새로 그려지는 일(보기, 찾기)을 함께 넘겨, 그것만 바뀌면 방향을 지우고 서서히 바뀌게 했다.

### 흐름 안의 판이 사라질 때

사진의 정보 판은 옆에 자리를 차지하는 판이다. 복사본을 그 옆에 그대로 넣으면 복사본도 자리를 차지해서 사진이 한 번 밀린다. 그래서 흐름 안의 요소는 복사본을 같은 자리·크기로 띄운다(`position: absolute`, 원래 요소의 `offsetLeft`·`offsetTop`·크기).

![휴대폰 정보 판을 닫는 중](./images/global-motion-phone-info-close.jpg '정보를 닫는 중: 판은 아래로 내려가며 흐려지고, 사진은 제자리로 돌아온다. 움직임을 멈춰 찍었다')

### 배경화면

배경화면은 문서의 CSS 변수(`--wallpaper`)라서, 바꾸면 바로 새 그림이 된다. 바꾸기 직전에 옛 배경을 덮개로 한 장 얹고(데스크톱은 창 아래, 휴대폰은 홈 화면 아이콘 아래) 그 덮개를 흐리게 했다.

## 단추

- 누를 수 있는 것(단추, 링크, 탭, 입력 칸)은 바탕·글자·테두리 색, 그림자, 투명도가 160ms 동안 바뀐다. 이 규칙은 `@layer reset` 안에 두었다. 그래서 Dock 아이콘처럼 자기 `transition`을 가진 것은 자기 것을 쓴다.
- 공통 `Button`과 `IconButton`은 생길 때 서서히 나타난다. 편집 도구나 되돌려 놓기처럼 상황에 따라 생기는 단추가 뚝 튀어나오지 않는다.

## 시험

화면 시험은 모두 움직임 줄이기 설정으로 돈다(`playwright.config.ts`). 그래서 복사본은 다른 시험에 나타나지 않는다. 움직임 시험만 따로 움직임을 켜고 확인한다.

- 메뉴를 닫으면 `getByRole('menu')`는 바로 0개이고, 복사본(`pop-out`)이 한 번 생겼다가 없어진다
- 움직임 줄이기를 켜면 복사본이 생기지 않는다
- 단축키 창은 메뉴(`pop-out`) 다음에 창(`fade-out`) 순서로 사라진다
- Finder에서 보기를 바꾸면 `fade-in`, 폴더로 들어가면 `slide-from-right`, 뒤로 가면 왼쪽에서
- 사진은 →면 `slide-from-right`, ←면 `slide-from-left`. 정보 판은 `panel-in-right`로 들어오고 닫으면 `panel-out-right` 복사본이 생긴다
- 배경화면을 바꾸면 옛 배경 덮개가 `fade-out`으로 사라진다
- 메뉴 막대 단추는 색이 전환되고, Dock 아이콘은 자기 전환(`transform`)을 그대로 쓴다

움직임을 켠 채로 전체 시험을 돌려 보기도 했다. 이번 변경 전의 main에서도 31개가 실패했다. 창이 열리는 움직임이 끝나기 전에 위치나 크기를 재는 시험들이다. 이 시험들은 움직임 줄이기를 전제로 쓴 것이라 이번에는 고치지 않았다.
