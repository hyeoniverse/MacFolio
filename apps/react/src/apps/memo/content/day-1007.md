## 돌아보며

- **잘한 것: 시험이 깨진 것을 따라가 배포 구멍을 찾았다.** main에서만 깨지는 시험을 고쳤더니 배포가 빠져 있었다. 그냥 다시 배포하고 끝내지 않고 배포 여부를 서버의 실제 버전으로 정하게 바꿨다. 실패한 실행이 몇 개든 다음 성공한 실행이 서버를 따라잡는다.
- **잘한 것: 큰 기능을 네 단계로 나눴다.** 트래픽 분석은 API → 수집 → 관리자 화면 → 공개를 PR 네 개로 냈다. 10월 4일의 83개짜리 PR과 반대로 했다.
- **아쉬운 것: 서버가 죽은 걸 알 길이 열흘째에야 생겼다.** 9월 30일에 서버를 띄웠는데 감시는 일주일 뒤였다. 그 사이 서버가 내려갔다면 방문자가 먼저 알았을 것이다.
- **아쉬운 것: main에서만 나는 문제.** 로컬과 PR에서 통과하고 main에서만 두 번 내리 실패했다. 이런 시험은 타이밍에 기대고 있다는 뜻이다. 이번에는 "마우스가 움직이지 않은 채 제목만 밀려 오는" 경우를 시험으로 직접 만들어, 고치기 전 빌드에서 실패하는 것까지 확인했다.
