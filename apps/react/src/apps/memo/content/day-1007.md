## CI와 배포: 하나의 문제에서 이어진 세 문제

세 문제가 순서대로 이어졌다.

```text
#115 PR 미리보기의 CORS 수정 (API 변경 포함)
  └→ main에서 메뉴 시험 실패 → 이 실행은 배포 단계까지 가지 못함
       └→ #116 메뉴 시험 수정 (API 변경 없음) → CI 통과, 그러나 API 배포 단계 생략
            └→ #115의 API 변경이 어느 실행에서도 배포되지 않음 → #118 배포 판단 기준 변경
```

### 1. PR 미리보기에서만 "연결할 수 없음"

PR 미리보기에서는 메뉴 막대의 서버 상태가 항상 "연결할 수 없음"이었다. 서버는 정상 동작 중이었고, API의 CORS 허용 목록에 미리보기 주소가 없었다. 미리보기 주소는 브랜치마다 달라서 하나씩 등록할 수 없으므로, 허용 주소에 와일드카드 `*`를 사용할 수 있게 했다([#115](https://github.com/hyeoniverse/MacFolio/pull/115), [no-cors 요청으로 CORS 차단과 서버 중지 구분하기](/memo/server-status-blocked-origin)).

### 2. main에서만 실패한 메뉴 시험

#115를 머지하자 main에서 메뉴 막대 시험 하나가 실패했다. '윈도우' 메뉴를 열었는데 '편집' 메뉴가 열렸다. 로컬과 PR에서는 통과한 시험이고, #115는 메뉴 코드를 변경하지 않았다.

원인은 메뉴 제목이 이동하는 타이밍이었다.

| 순서 | 상황                                                                          |
| ---- | ----------------------------------------------------------------------------- |
| 1    | 시험이 마우스를 '윈도우' 위에 올린다                                          |
| 2    | 메모 앱이 열리며 편집·보기 메뉴가 등록되고, 메뉴 제목들이 오른쪽으로 이동한다 |
| 3    | 정지한 마우스 아래로 '편집' 제목이 이동해 온다                                |
| 4    | 브라우저는 이것도 마우스가 요소에 진입한 것으로 보고 진입 이벤트를 발생시킨다 |
| 5    | 메뉴가 '편집'으로 전환된다                                                    |

마우스가 실제로 움직였을 때만 옆 메뉴로 전환하도록 수정했다([#116](https://github.com/hyeoniverse/MacFolio/pull/116), [앱이 등록한 메뉴를 공통 메뉴와 병합하는 메뉴 막대 구조](/memo/menubar-menus)). "마우스는 정지한 채 제목만 이동하는" 상황을 시험으로 직접 재현해, 수정 전 빌드에서는 실패하는 것까지 확인했다.

### 3. 생략된 API 배포

#116을 머지하자 CI는 통과했지만 서버는 여전히 이전 버전이었다. API 배포 단계가 생략되었다.

| 항목             | 변경 전                                 | 변경 후                                        |
| ---------------- | --------------------------------------- | ---------------------------------------------- |
| 배포 판단 기준   | 직전 push 대비 API 코드 변경 여부       | **서버에서 실행 중인 버전** 대비 변경 여부     |
| 실패한 실행 이후 | 실패한 실행의 API 변경이 누락될 수 있음 | 다음에 성공한 실행이 서버를 최신 버전으로 맞춤 |

#116에는 API 변경이 없었다. #115에는 있었지만, 그 실행은 메뉴 시험 실패로 배포 단계까지 가지 못했다. 그래서 #115의 API 변경은 어느 실행에서도 배포되지 않았다. 판단 기준을 서버에서 실제로 실행 중인 버전으로 변경했다([#118](https://github.com/hyeoniverse/MacFolio/pull/118), [자동 배포를 실제 서버에 걸기](/memo/api-auto-deploy-setup)).

같은 시각에 로컬 API의 환경 변수도 정리했다. 개발용은 `.env`, 배포용 값은 `.env.production`에 보관한다. 로컬 프론트엔드 주소가 허용 목록에 없으면 서버 시작 시 경고를 출력한다([#117](https://github.com/hyeoniverse/MacFolio/pull/117)).

## 메일 앱에서 실제로 메일 발송

이전에는 메일 앱이 방문자의 메일 프로그램을 여는 `mailto:` 링크였다.

| 항목           | 변경 후                                              |
| -------------- | ---------------------------------------------------- |
| 발송           | 서버가 Resend로 발송                                 |
| 답장           | 보낸 사람 주소를 Reply-To 헤더에 넣어 바로 답장 가능 |
| 스팸 방지      | Cloudflare Turnstile과 하루 발송 상한                |
| 서버 설정 없음 | 이전처럼 메일 프로그램을 여는 방식으로 대체          |

자세한 내용은 [Resend API와 Turnstile로 서버에서 메일 발송하고 스팸 차단하기](/memo/contact-mail)([#125](https://github.com/hyeoniverse/MacFolio/pull/125))에 정리했다.

작은 버그도 두 개 수정했다. `#115의`처럼 조사가 붙은 이슈 번호를 메모 태그로 인식하던 문제([#124](https://github.com/hyeoniverse/MacFolio/pull/124))와, 메뉴 막대의 Finder 이름이 1.5px 위에 표시되던 문제([#126](https://github.com/hyeoniverse/MacFolio/pull/126))다.

## 열흘째에 돌아보며

이날은 첫 열흘의 마지막 날이라 열흘 전체를 함께 돌아본다.

**실패한 시험에서 배포 누락까지 추적했다.** 수동으로 다시 배포하고 끝낼 수도 있었다. 대신 배포 여부를 서버의 실제 버전으로 판단하게 바꿔서, 실패한 실행이 여러 번 있어도 다음에 성공한 실행이 서버를 최신 버전으로 맞춘다. 타이밍에 따라 결과가 달라지는 시험은 재실행으로 통과시키지 말고, 그 타이밍을 재현하는 시험을 만들어야 한다.

**트래픽 분석을 PR 네 개로 나눈 것은 10월 4일의 반성을 반영한 결과다.** 단계마다 리뷰하고 머지해서, 한 단계에 문제가 생겨도 앞 단계에는 영향이 없었다.

**서버 감시는 가장 늦게 추가했다.** 서버를 시작하고 일주일이 지나서야 서버 중단을 감지할 수단이 생겼다. 그 사이 서버가 중단되었다면 방문자가 먼저 알았을 것이다. 서버를 처음 배포하는 시점에 감시도 함께 구성해야 한다.
