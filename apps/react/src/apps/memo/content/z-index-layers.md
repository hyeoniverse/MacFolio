새 팝업을 띄울 때마다 "이건 z-index를 얼마로 줘야 Dock 위에 뜨지?"를 물어야 했다. 답을 찾으려면 `Dock.css`, `StatusBar.css`, `Menu.css`, `LoadingScreen.css`를 차례로 열어 숫자를 비교하는 수밖에 없었다. 이번 일은 그 숫자들에 이름을 붙여 한곳에 모은 것이다. 화면은 한 픽셀도 바뀌지 않는다.

## 배경

MacFolio의 데스크톱 화면은 층이 많다. 바탕화면 위에 창이 있고, 그 위에 Dock과 메뉴 막대가, 다시 그 위에 펼친 메뉴, 알림, 로딩 화면, 로그인 화면이 올라간다. 휴대폰 화면에는 상태 막대, 제어 센터, 앱 전환기, 알림이 따로 있다.

이 층들은 서로 다른 파일에서 서로 다른 사람이(정확히는 서로 다른 날의 내가) 정했다. 그래서 새 층을 더할 때마다 기존 숫자를 모두 알아야 했다.

## z-index가 무엇인가

화면에서 요소가 겹칠 때 무엇을 위에 그릴지 정하는 CSS 속성이다. 값이 클수록 위에 그린다. 다만 비교는 같은 쌓임 맥락(stacking context) 안에서만 일어난다. 같은 부모 안의 작은 겹침(목록 위 버튼 등)은 1~10이면 충분하지만, Dock·메뉴 막대·펼친 메뉴처럼 화면 전체에서 서로 겹치는 요소는 서로의 값을 알아야 순서를 정할 수 있다. 쌓임 맥락이 갇혀서 생긴 문제는 /memo/sticky-stacking-context 에 따로 적었다.

## 흩어져 있던 숫자

먼저 CSS 전체에서 `z-index:`를 찾고, 앱 안의 작은 값(1~10)을 뺐다. 화면 전체에서 겹치는 값만 남기니 13개 파일에 20곳이었다.

| 값                        | 쓰는 곳                                                                   |
| ------------------------- | ------------------------------------------------------------------------- |
| 1000                      | Dock, 경고창(Modal) 기본값                                                |
| 1001                      | 메뉴 막대                                                                 |
| 1400 · 2000 · 2100 · 2200 | 휴대폰 앱 전환기 · 제어 센터 · 상태 막대 · 알림                           |
| 1500                      | 이 Mac에 관하여                                                           |
| 2000 · 3000               | Launchpad · 키보드 단축키 안내                                            |
| 9000 · 9999               | 알림 · 로딩 화면                                                          |
| 10000                     | 펼친 메뉴, 소리 조절, 메모의 서식 판·달력·라이트박스·끌어 놓기 표시 (6곳) |
| 15000 · 20000             | 앱 오류 화면 · 로그인                                                     |

이 표에서 문제가 세 가지 보였다.

1. **의도가 숫자에 숨어 있다.** 메뉴 막대가 1001인 이유는 "Dock(1000)보다 위"라는 뜻이지만, 숫자만 보고는 그 의도를 알 수 없다.
2. **같은 숫자가 여러 곳에 있다.** 10000은 여섯 곳에 같은 숫자로 적혀 있어서, 하나만 바꾸면 메뉴끼리 순서가 어긋난다.
3. **같은 값이 다른 뜻으로 쓰인다.** 2000은 데스크톱 Launchpad이기도 하고 휴대폰 제어 센터이기도 하다. 둘은 한 화면에 함께 나오지 않으니 충돌은 없지만, 숫자만 보면 관계가 있는 것처럼 읽힌다.

![1000부터 20000까지 화면 전체 층을 위가 앞이 되게 쌓은 사다리](./images/z-index-layers-ladder.svg '화면 전체에서 겹치는 층과 값')

## 고른 방법과 버린 방법

| 방법                                 | 장점                                      | 단점                                                          |
| ------------------------------------ | ----------------------------------------- | ------------------------------------------------------------- |
| 숫자를 그대로 두고 주석만 단다       | 바꿀 것이 거의 없다                       | 주석은 값과 따로 놀고, 순서 전체는 여전히 안 보인다           |
| TypeScript 상수로 모아 인라인 스타일 | 타입으로 막을 수 있다                     | 대부분의 z-index는 CSS 파일에 있다. 스타일을 TS로 옮겨야 한다 |
| CSS 변수 `--z-*`를 `theme.css`에     | CSS 파일 안에서 바로 쓴다. 한 표로 보인다 | 오타는 여전히 CSS가 조용히 무시한다                           |

색·글자 크기·모서리도 이미 `theme.css`의 변수로 옮기는 중이었다(/memo/color-tokens). 같은 곳에 같은 방식으로 두는 편이 찾기 쉽다고 보고 CSS 변수를 골랐다.

값을 정리하면서 숫자를 "100 간격으로 다시 매기기"도 생각했지만 하지 않았다. 숫자를 바꾸면 화면이 바뀔 수 있고, 그러면 이번 일이 "이름 붙이기"가 아니라 "겹침 순서 바꾸기"가 된다. 두 일을 한 PR에 섞지 않았다.

## 구현

`styles/theme.css`의 `:root`에 `--z-*` 변수로 모았다. 낮은 층부터 높은 층 순서로 적어서, 파일을 위에서 아래로 읽으면 곧 겹침 순서가 된다.

```css
:root {
	--z-dialog: 1000; /* 앱 창 안의 경고창 기본값 (Modal) */
	--z-dock: 1000;
	--z-menubar: 1001;
	/* ... */
	--z-loading: 9999;
	--z-menu: 10000; /* 펼친 메뉴·팝오버·라이트박스: 어떤 창보다 위 */
	--z-app-error: 15000; /* 앱 오류 화면 */
	--z-login: 20000; /* 로그인: 가장 위 */
}
```

쓰는 쪽은 숫자를 이름으로 바꿨다. 예를 들어 앱 오류 화면(`desktop/window/Window.css`)은 이렇게 바뀌었다.

```css
/* 전 */
z-index: 15000;
/* 후 */
z-index: var(--z-app-error);
```

공통 경고창(`Modal`)은 쓰는 쪽이 `--ui-modal-z`로 층을 정한다. Launchpad·키보드 단축키 안내·로그인이 이 값을 숫자로 적던 것도 `--ui-modal-z: var(--z-launchpad)`처럼 이름으로 바꿨다. `Modal.css`의 기본값도 `var(--ui-modal-z, 1000)`에서 `var(--ui-modal-z, var(--z-dialog))`로 바꿨다.

![쓰는 쪽이 --ui-modal-z를 주면 그 값을, 없으면 --z-dialog를 쓰는 흐름](./images/z-index-layers-modal-chain.svg 'Modal이 층을 정하는 순서')

바뀐 파일은 `theme.css`를 포함해 14개 CSS 파일이다(Dock, StatusBar, Menu, LoadingScreen, Notifications, MobileShell, AboutThisMac, KeyboardShortcuts, VolumeMenu, Window, LoginFlow, Modal, Memo).

## 확인

- 값은 하나도 바꾸지 않았으므로, 변수 이름과 원래 숫자가 같은지를 diff에서 한 줄씩 대조했다.
- 바꾼 뒤 CSS에서 `var(--z-`를 쓰는 곳은 22곳이다. 숫자로 남은 `z-index`는 129곳인데, 모두 앱 안의 작은 값이나 창 순서처럼 일부러 남긴 것이다.

## 남겨 둔 것

- **창 순서**: 창은 store가 1, 2, 3…으로 매기는 값이라 CSS 변수로 옮길 대상이 아니다.
- **앱 안의 작은 값(1~10)**: 같은 부모 안의 겹침이라 다른 화면과 비교할 일이 없다.
- **소리 조절 막대(100)**: 소리 조절 상자 안에서만 쓰는 값이다.

## 그 뒤

이름을 붙여 두니 새 층을 더하는 일이 쉬워졌다. 그 뒤 두 층이 더해졌다. 바탕화면 아이콘을 끄는 동안 창과 Dock 위로 지나가게 하는 `--z-drag: 2400`과, 바탕화면에서 띄운 경고창을 모든 창 위에 두는 `--z-alert: 2500`이다. 둘 다 표에서 위아래를 보고 사이에 끼워 넣었을 뿐, 다른 파일은 열지 않았다. 지금 `theme.css`의 층 이름은 17개다.

## 배운 것

- 숫자만 있는 설정값은 그 값을 정한 날의 의도를 잃는다. 이름과 한 줄 주석이 그 의도를 붙잡아 둔다.
- 이름 붙이기와 값 바꾸기는 따로 한다. 그래야 "화면이 그대로인가"를 diff만 보고 확인할 수 있다.
- 다음에 새 팝업을 만들 때는 `theme.css`의 표에서 위아래를 고르고, 그 사이에 이름 하나를 더하면 된다.
