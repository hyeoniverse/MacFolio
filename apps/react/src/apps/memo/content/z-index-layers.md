새 팝업을 추가할 때마다 Dock 위에 표시하려면 z-index를 얼마로 지정해야 하는지 확인해야 했다. 그러려면 `Dock.css`, `StatusBar.css`, `Menu.css`, `LoadingScreen.css`를 차례로 열어 숫자를 비교해야 했다. 이번 작업([#231](https://github.com/hyeoniverse/MacFolio/pull/231))은 그 숫자에 이름을 붙여 `theme.css` 한 곳에 모았다. 값은 바꾸지 않았으므로 화면 렌더링 결과는 같다.

## 배경

MacFolio의 데스크톱 화면은 겹치는 계층이 많다. 바탕화면 위에 창이 있고, 그 위에 Dock과 메뉴 막대가, 다시 그 위에 펼친 메뉴, 알림, 로딩 화면, 로그인 화면이 놓인다. 휴대폰 화면에는 상태 막대, 제어 센터, 앱 전환기, 알림이 별도로 있다.

이 계층의 값은 각 컴포넌트의 CSS 파일에서 서로 다른 시각에 정해졌다. 그래서 새 계층을 추가할 때마다 기존 숫자를 모두 확인해야 했다.

## z-index란

[`z-index`](https://developer.mozilla.org/en-US/docs/Web/CSS/z-index)는 요소가 겹칠 때 어느 요소를 위에 렌더링할지 정하는 CSS 속성이다. 값이 클수록 위에 렌더링한다. 다만 비교는 같은 [쌓임 맥락(stacking context)](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_positioned_layout/Stacking_context)[^stacking] 안에서만 일어난다. 같은 부모 안의 작은 겹침(목록 위 버튼 등)은 1~10이면 충분하지만, Dock·메뉴 막대·펼친 메뉴처럼 화면 전체에서 서로 겹치는 요소는 서로의 값을 알아야 순서를 정할 수 있다. 쌓임 맥락 때문에 z-index가 무시된 사례는 [sticky 도구 막대가 버튼을 가린 이유](/memo/sticky-stacking-context)에 정리했다.

## 흩어져 있던 숫자

먼저 CSS 전체에서 `z-index:`를 검색하고, 앱 내부의 작은 값(1~10)을 제외했다. 화면 전체에서 겹치는 값만 남기니 13개 파일에 20곳이었다.

| 값                        | 사용처                                                                    |
| ------------------------- | ------------------------------------------------------------------------- |
| 1000                      | Dock, 경고창(Modal) 기본값                                                |
| 1001                      | 메뉴 막대                                                                 |
| 1400 · 2000 · 2100 · 2200 | 휴대폰 앱 전환기 · 제어 센터 · 상태 막대 · 알림                           |
| 1500                      | 이 Mac에 관하여                                                           |
| 2000 · 3000               | Launchpad · 키보드 단축키 안내                                            |
| 9000 · 9999               | 알림 · 로딩 화면                                                          |
| 10000                     | 펼친 메뉴, 소리 조절, 메모의 서식 판·달력·라이트박스·끌어 놓기 표시 (6곳) |
| 15000 · 20000             | 앱 오류 화면 · 로그인                                                     |

이 표에서 확인한 문제는 세 가지다.

1. **의도가 숫자에 드러나지 않는다.** 메뉴 막대가 1001인 이유는 "Dock(1000)보다 위"라는 뜻이지만, 숫자만으로는 그 의도를 알 수 없다.
2. **같은 숫자가 여러 곳에 중복된다.** 10000은 여섯 곳에 같은 숫자로 적혀 있어서, 하나만 바꾸면 메뉴 사이의 순서가 어긋난다.
3. **같은 값이 다른 의미로 쓰인다.** 2000은 데스크톱 Launchpad이기도 하고 휴대폰 제어 센터이기도 하다. 둘은 한 화면에 함께 나오지 않아 충돌은 없지만, 숫자만 보면 관계가 있는 것처럼 읽힌다.

![1000부터 20000까지 화면 전체 층을 위가 앞이 되게 쌓은 사다리](./images/z-index-layers-ladder.svg '화면 전체에서 겹치는 계층과 값')

## 검토한 방법

| 방법                                  | 장점                                       | 단점                                                                         |
| ------------------------------------- | ------------------------------------------ | ---------------------------------------------------------------------------- |
| 숫자를 그대로 두고 주석만 추가        | 변경량이 거의 없다                         | 값을 바꿔도 주석은 갱신되지 않고, 전체 순서는 여전히 한 곳에서 보이지 않는다 |
| TypeScript 상수로 모아 인라인 스타일  | 타입 검사로 오타를 검출한다                | 대부분의 z-index는 CSS 파일에 있다. 스타일을 TS로 옮겨야 한다                |
| CSS 변수 `--z-*`를 `theme.css`에 정의 | CSS 파일에서 바로 사용한다. 한 표로 보인다 | 변수 이름 오타는 CSS가 오류 없이 무시한다                                    |

색·글자 크기·모서리도 이미 `theme.css`의 변수로 옮기는 중이었다([색에 이름 붙이기 — 되풀이된 hex 288곳을 --color-* 이름으로](/memo/color-tokens)). 디자인 값을 같은 파일에 같은 방식([CSS 사용자 지정 속성](https://developer.mozilla.org/en-US/docs/Web/CSS/Using_CSS_custom_properties))으로 정의하면 검색 위치가 하나로 줄어들어 CSS 변수를 선택했다.

값을 100 간격으로 다시 매기는 방안도 검토했지만 적용하지 않았다. 숫자를 바꾸면 렌더링 결과가 바뀔 수 있고, 그러면 이번 작업이 "이름 붙이기"가 아니라 "겹침 순서 변경"이 된다. 두 변경을 한 PR에 섞지 않았다.

## 구현

`styles/theme.css`의 `:root`에 `--z-*` 변수로 모았다. 낮은 계층부터 높은 계층 순서로 정의해서, 파일을 위에서 아래로 읽는 순서가 곧 겹침 순서다.

```css
:root {
	--z-dialog: 1000; /* 앱 창 안의 경고창 기본값 (Modal) */
	--z-dock: 1000;
	--z-menubar: 1001;
	/* ... */
	--z-loading: 9999;
	--z-menu: 10000; /* 펼친 메뉴·팝오버·라이트박스: 어떤 창보다 위 */
	--z-app-error: 15000; /* 앱 오류 화면 */
	--z-login: 20000; /* 로그인: 가장 위 */
}
```

사용처는 숫자를 변수 이름으로 바꿨다. 예를 들어 앱 오류 화면(`desktop/window/Window.css`)은 다음과 같이 바뀌었다.

```css
/* 전 */
z-index: 15000;
/* 후 */
z-index: var(--z-app-error);
```

공통 경고창(`Modal`)은 사용하는 컴포넌트가 `--ui-modal-z`로 계층을 지정한다. Launchpad·키보드 단축키 안내·로그인에서 이 값을 숫자로 지정하던 코드도 `--ui-modal-z: var(--z-launchpad)`처럼 이름으로 바꿨다. `Modal.css`의 기본값도 `var(--ui-modal-z, 1000)`에서 `var(--ui-modal-z, var(--z-dialog))`로 바꿨다.

![쓰는 쪽이 --ui-modal-z를 주면 그 값을, 없으면 --z-dialog를 쓰는 흐름](./images/z-index-layers-modal-chain.svg 'Modal이 계층을 정하는 순서')

변경 파일은 `theme.css`를 포함해 14개 CSS 파일이다.

## 확인

- 값은 하나도 바꾸지 않았으므로, 변수 값과 원래 숫자가 같은지 diff에서 한 줄씩 대조했다.
- 변경 후 CSS에서 `var(--z-`를 사용하는 곳은 22곳이다. 숫자로 남은 `z-index`는 129곳이며, 모두 앱 내부의 작은 값이나 창 순서처럼 의도적으로 남긴 값이다.

## 변수로 옮기지 않은 값

- **창 순서**: 창 관리 store가 1, 2, 3…으로 할당하는 값이라 CSS 변수로 옮길 대상이 아니다.
- **앱 내부의 작은 값(1~10)**: 같은 부모 안의 겹침이라 다른 화면 요소와 비교하지 않는다.
- **소리 조절 막대(100)**: 소리 조절 상자 안에서만 사용하는 값이다.

## 이후 변경

이름을 붙인 뒤에는 새 계층을 추가할 때 변수 목록 한 곳만 확인하면 된다. 이 글을 쓴 시각까지 두 계층이 추가되었다. 바탕화면 아이콘을 드래그하는 동안 창과 Dock 위로 표시하는 `--z-drag: 2400`(`cf274032f`)과, 바탕화면에서 표시한 경고창을 모든 창 위에 배치하는 `--z-alert: 2500`(`273500977`)이다. 둘 다 목록에서 앞뒤 값을 확인하고 그 사이에 추가했고, 다른 CSS 파일은 확인할 필요가 없었다. 그 시각 기준 계층 이름은 17개였다.

이후 디자인 토큰을 원시·의미·컴포넌트 세 층으로 나누면서([#286](https://github.com/hyeoniverse/MacFolio/pull/286)) `--z-*` 변수는 `styles/tokens/semantic.css`로 옮겨졌다. 현재는 위젯 갤러리(`--z-widget-gallery: 1450`), 둘러보기(`--z-tour: 9500`), 전체 화면 보기(`--z-fullscreen: 12000`) 등을 포함해 21개다.

## 정리

- 숫자만 있는 설정값은 그 값을 정한 이유가 기록되지 않는다. 변수 이름과 한 줄 주석으로 이유를 기록한다.
- 이름 붙이기와 값 변경은 별도 PR로 진행한다. 그래야 렌더링 결과가 같은지 diff만으로 확인할 수 있다.
- 새 팝업을 만들 때는 변수 목록에서 앞뒤 계층을 정하고, 그 사이에 변수 하나를 추가한다.
