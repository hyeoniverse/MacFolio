macOS의 날씨 앱처럼 생긴 **날씨** 앱을 더했다. Launchpad에 있고(Dock에는 고정하지 않는다), 휴대폰 홈 화면에도 있다.

## 데이터: Open-Meteo

[Open-Meteo](https://open-meteo.com/)는 키 없이 쓰는 공개 날씨 API다(데이터는 CC BY 4.0). 그래서 서버를 거치지 않고 브라우저가 바로 부른다.

- 일기예보 `api.open-meteo.com/v1/forecast`: 지금 날씨, 시간별(이틀), 일별(10일)을 한 번에 받는다. `timezone=auto`면 시각이 그곳의 시간대로 오고, `wind_speed_unit=ms`면 바람이 m/s로 온다
- 장소 찾기 `geocoding-api.open-meteo.com/v1/search`

사이트의 CSP는 `connect-src`에 적힌 곳에만 요청을 보낸다. 그래서 두 주소를 `worker/securityHeaders.ts`에 더하고, 보안 헤더 시험에도 적었다. 화면 맨 아래에는 데이터 출처를 적는다.

## 한국어 이름 찾기

먼저 지오코딩을 직접 불러 봤다.

| 찾은 말 | 결과                                            |
| ------- | ----------------------------------------------- |
| `서울`  | 없음                                            |
| `부산`  | 경상북도 의성군의 마을 'Pusan'이 먼저           |
| `Busan` | 부산광역시 (행정 중심지, 인구 3,285,147)가 먼저 |
| `Tokyo` | 도쿄 (수도)가 먼저, 그다음 파푸아뉴기니의 Tokyo |

한국어로 찾으면 쓸 수 없는 결과가 나온다. 그래서 자주 찾을 도시 39곳(국내 17, 해외 22)을 한국어 이름과 영어 별칭으로 사이트에 넣어 두었다(`places.ts`의 `CITIES`). 찾기는 이렇게 한다.

1. 내장 도시: 한국어·영어 이름에 찾는 말이 들어 있으면 바로 보인다 (`주` → 광주, 청주, 전주, 제주)
2. Open-Meteo: 잠깐(0.3초) 멈춘 뒤 부르고, 수도(`PPLC`) → 행정 중심지(`PPLA`) → 인구 순서로 다시 줄 세운다
3. 같은 곳(약 1km 안)은 한 번만, 8개까지

## 찾기가 느리다

써 보니 장소 찾기가 너무 오래 걸렸다. 재 보니 Open-Meteo 지오코딩이 한 번에 **1~10초**였다(같은 말도 때마다 다르고, 일기예보 API는 1초 남짓). 옵션(`language`, `count`)을 바꿔도 마찬가지였다. 여기에 글자를 칠 때마다 0.3초 멈췄다 다시 묻고, 한글은 조합 중인 글자('ㄴ', '노', '놘'…)마다 물었다. 서버를 빠르게 할 수는 없으니 **기다리는 일을 줄였다.**

- **내장 도시를 39곳에서 211곳으로.** 국내 시·군과 서울의 구 25개, 해외 주요 도시. 지오코딩은 '노원구'·'강남구' 같은 구 이름을 아예 찾지 못하고 '성남'은 같은 이름의 마을을 먼저 주어서, 국내는 좌표를 직접 적었다(도시는 중심, 구는 구청 근처. 날씨 격자가 수 km라 충분하다). 대부분의 검색은 이제 글자를 치는 순간 나온다
- **순서:** 이름이 찾는 말로 시작하는 곳 → 이름에 들어 있는 곳 → 지역 이름에 들어 있는 곳. '서울'을 치면 서울 다음에 서울특별시의 구 25개가 온다
- **Open-Meteo는 뒤에서:** 두 글자 이상을 치다 0.25초 멈추면 묻고, 오는 동안 목록 아래에 '더 찾는 중…'을 띄운다. 내장 결과는 그동안에도 그대로 보인다
- **한글 조합 중에는 묻지 않는다.** 조합이 끝나면 묻는다. 끝났다는 신호를 보내지 않는 키보드도 있어서 입력마다 조합 중인지 다시 확인한다
- **같은 말은 다시 묻지 않는다.** 답을 기억해 두어, 다른 말을 쳤다가 돌아와도 바로 나온다
- **8초가 넘으면 그만 묻는다.** 아무것도 없으면 '결과 없음'

목록을 늘리고 나서 '서울'을 쳐 보니 종로구가 빠져 있었다. 같은 곳을 두 번 보이지 않게 약 1km 안이면 같은 곳으로 보았는데, 서울(시청)과 종로구(구청)가 그 안에 있었다. 기준을 약 500m로 좁히고 시험에 넣었다.

## 화면

- **왼쪽:** 장소 카드. 카드마다 그곳의 하늘 색, 이름, 그곳의 지금 시각, 날씨, 기온, 최고·최저. 올리면 ×로 지운다(마지막 하나는 지울 수 없다)
- **오른쪽:** 고른 곳의 하늘 색 배경 위에 이름, 큰 기온, 날씨, 최고·최저
  - 시간별 일기예보: 지금부터 24칸, 비 올 확률은 30% 이상일 때만
  - 10일간의 일기예보: 10일 동안 가장 낮은·높은 기온을 눈금으로 삼아 그날의 범위 막대를 긋고, 오늘 막대에는 지금 기온 점
  - 상세 칸: 체감 온도, 습도, 바람(방향), 자외선 지수(기상청 단계), 일출·일몰, 강수량

하늘 색은 WMO 날씨 코드를 맑음·구름 조금·흐림·안개·이슬비·비·눈·뇌우 여덟 가지로 묶고, 낮·밤으로 나눠 고른다. 날씨 앱은 macOS에서도 화면 모드와 상관없이 하늘 색이라, 다크 모드에서도 같다.

고른 장소는 이 브라우저(localStorage)에 남긴다. 처음에는 서울 하나다. 휴지통의 '내 브라우저 데이터'에도 '날씨 장소'로 보여서 지울 수 있다(휴지통 시험이 코드가 쓰는 저장 키를 모두 다루는지 확인해서, 빠뜨리면 시험이 실패한다).

현재 위치는 넣지 않았다. 사이트의 `Permissions-Policy`가 위치 권한을 막아 두었고, 위치를 묻는 것보다 도시를 찾아 더하는 편이 개인정보에도 낫다.

## 실제 앱에 맞춰 다시 다듬기

첫 모양을 실제 macOS·iOS 날씨 앱 스크린샷과 나란히 놓고 보니 다른 곳이 많아서 고쳤다.

**맥 (넓은 창)**

- 하늘 색이 창 전체에 깔리고, 사이드바는 그 위에 떠 있는 둥근 반투명 패널이다. 오른쪽 위의 사이드바 단추로 접고, 접으면 신호등 옆에 단추가 나온다
- 장소는 카드를 오른쪽 클릭해 '삭제'로 지운다 (올리면 보이던 ×는 뺐다)
- 위쪽에 지역 이름(대한민국)을 작게 붙이고 크기를 줄였다
- 시간별 아래는 두 단: 왼쪽 10일 일기예보, 오른쪽 상세 칸
- 밤에는 남색 하늘에 별을 흩뿌리고, 칸을 어둡고 투명하게 한다

사이드바를 흐리게(`backdrop-filter`) 하니 그 안의 사이드바 단추가 눌리지 않았다. 흐림이 새 층(stacking context)을 만들어서, 단추의 z-index를 올려도 창 위쪽 끌기 자리(z-index 3) 밑에 깔린 것이다. 사이드바째 위로 올리면 이번에는 사이드바가 신호등을 덮는다. 그래서 사이드바 상자는 누름을 통과시키고(`pointer-events: none`) 안의 것만 누르게 했다. 신호등을 누르는 시험을 더해서 이 실수를 잡았다.

**아이폰 (좁은 창)**

- 홈으로 가는 단추를 없앴다 (iOS 날씨처럼 홈 바로 나간다)
- 아래에 떠 있는 막대: 가운데 장소 점, 오른쪽 목록 단추. 화면을 옆으로 밀어도 앞뒤 장소로 넘어간다 (시간별 칸은 옆으로 스크롤하므로 뺀다). 장소가 하나면 넘길 곳이 없으니 점 막대는 그리지 않는다 (처음에는 점 하나짜리 막대가 떠 있어서 '눌러도 아무 일도 없는 점'이 되었다)
- 시간별 위에 한두 문장: 날씨가 처음 바뀌는 시각과 오늘 돌풍의 최대 풍속 (예: '오전 12시쯤 구름 조금 상태가 예상됩니다. 돌풍의 풍속은 최대 3m/s입니다.'). 돌풍은 Open-Meteo의 `wind_gusts_10m_max`로 받는다
- 목록: 큰 '날씨' 제목, •••(목록 편집, °C 섭씨, °F 화씨), 카드에 '시각 • 지역', 아래에 떠 있는 검색 알약, 맨 아래 데이터 출처
- 카드를 왼쪽으로 밀면 빨간 휴지통이 드러난다. 목록 편집이면 모든 카드에 늘 보인다. 마우스로 밀면 손을 뗄 때 누름(click)이 따라와서 방금 연 카드를 다시 닫았는데, 밀고 난 바로 뒤의 누름은 무시하게 했다. 실제 아이폰에서는 그래도 열리지 않았다. iOS Safari는 미는 손가락이 위아래로 조금만 흔들려도 스크롤로 보고 `pointercancel`을 보내는데, 취소를 '닫기'로 처리하고 있었다. 이제 취소가 와도 민 만큼으로 열지 닫을지 정하고, 옆으로 밀기 시작하면 카드가 손가락을 붙잡으며(`setPointerCapture`), 목록은 위아래로만 스크롤한다고 알린다(`touch-action: pan-y`). 시험도 마우스가 아니라 실제 터치 이벤트(위아래로 흔들리는 손가락)로 민다
- 해는 노랑, 비는 하늘색으로 아이콘에 색을 입혔다
- 팝업(••• 메뉴, 카드의 오른쪽 클릭 메뉴)은 사이트 공통 메뉴의 흰 판이 어두운 하늘 위에서 튀어서, 날씨 앱만 어두운 유리 판으로 바꿨다. ••• 메뉴는 iOS처럼 크고 둥글게, 오른쪽 클릭 메뉴는 휴지통과 '삭제'만 있는 작은 알약으로

**기온 단위**: 섭씨·화씨를 고르면 Open-Meteo에 `temperature_unit=fahrenheit`로 다시 묻는다 (화면에서 바꿔 계산하지 않는다). 고른 단위는 이 브라우저에 남고, 휴지통의 '날씨 장소'에서 장소와 함께 지울 수 있다. 맥에서는 메뉴 막대의 보기 메뉴에 있다.

## 좁은 창과 휴대폰

창 폭이 640px보다 좁으면(컨테이너 쿼리) 위의 아이폰 모양이 된다. 그래서 맥에서 창을 좁혀도 같다. '오후 12시'가 잘리던 시간별 칸은 글자만큼 넓어지게 했다.

## 시험

- 단위: 내장 도시 찾기(구까지, 한국어·영어, 시작하는 곳 먼저, 지역 이름으로도), WMO 코드 → 한국어·아이콘(낮·밤), 시각·바람 방향, 자외선 단계, 지금부터 24시간·오늘부터 10일, 장소 찾기(내장 도시, 큰 도시 먼저, 같은 곳 한 번), 저장(깨진 값이면 서울)
- E2E (Open-Meteo는 가짜): Open-Meteo가 느려도(1.5초) 내장 도시는 바로, 기다리는 동안 '더 찾는 중', 같은 말은 다시 묻지 않음, '결과 없음' / 시간별 위 문장과 돌풍 / 화씨로 바꾸면 다시 묻고 남음 / 오른쪽 클릭 삭제 / 사이드바 접고 펴기, 신호등은 그대로 눌림 / 휴대폰: 홈 단추 없음, 점으로 넘기기, 옆으로 밀어 넘기기, 목록 편집으로 지우기, 카드 밀어 휴지통, 화씨 / 서울의 지금 날씨·시간별 24칸·10일·상세 칸·출처 / 한국어로 찾아 더하고 다시 열어도 남음 / 영어로 찾으면 수도가 먼저, 이미 있는 곳은 더하지 않음 / 지우기와 마지막 하나 / 불러오지 못하면 다시 시도 / 휴대폰에서 목록 열고 골라 돌아오기
