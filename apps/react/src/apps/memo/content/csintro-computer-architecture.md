## 폰 노이만 구조

### 구성

폰 노이만 구조(von Neumann architecture)는 1945년 존 폰 노이만이 EDVAC 보고서에서 정리한 컴퓨터 구조로, 오늘날 대부분의 범용 컴퓨터가 따른다. 핵심은 세 가지다.

1. CPU, 주기억장치, 입출력장치로 구성된다.
2. 명령어와 데이터를 같은 주기억장치에 같은 형태(2진수)로 저장한다.
3. CPU는 명령어를 메모리에서 하나씩 순서대로 가져와 실행한다.

![폰 노이만 구조: CPU(제어장치, ALU, 레지스터 PC·IR·MAR·MBR·AC), 명령어와 데이터를 함께 저장하는 주기억장치, 입출력장치가 주소 버스, 데이터 버스, 제어 버스에 연결되어 있다](./images/csintro-computer-architecture-von-neumann.svg '명령어와 데이터가 같은 메모리와 같은 버스를 공유한다')

### 시스템 버스

버스(bus)는 여러 장치가 공유하는 신호선의 묶음이다. 장치마다 전용 선을 연결하면 장치가 늘어날수록 선의 수가 급격히 늘어나므로, 공용 통로 하나에 모든 장치를 연결하고 한 시점에 한 장치만 데이터를 보내게 한다. CPU와 메모리, 입출력장치를 잇는 시스템 버스는 역할에 따라 세 종류로 나뉜다.

| 버스        | 전달하는 것                            | 방향                        | 폭의 의미                                            |
| ----------- | -------------------------------------- | --------------------------- | ---------------------------------------------------- |
| 주소 버스   | 읽거나 쓸 메모리·입출력 장치의 주소    | CPU → 메모리·입출력, 단방향 | n비트면 `2^n{:math}`개 주소 지정. 32비트면 4 GiB까지 |
| 데이터 버스 | 실제로 읽거나 쓰는 데이터와 명령어     | 양방향                      | 한 번에 전송하는 비트 수                             |
| 제어 버스   | 읽기·쓰기 신호, 클록, 인터럽트 요청 등 | 신호마다 다름               |                                                      |

예를 들어 CPU가 메모리 0x1000번지의 값을 읽는 과정은 다음과 같다.

1. CPU가 주소 버스에 `0x1000`을 싣는다.
2. 제어 버스의 읽기(read) 신호를 활성화한다.
3. 메모리가 해당 번지의 값을 데이터 버스에 싣는다.
4. CPU가 데이터 버스의 값을 레지스터로 가져온다.

32비트 주소 버스를 쓰는 CPU가 RAM을 4 GiB까지만 인식했던 이유가 주소 버스 폭이다. `2^{32}{:math}` = 4,294,967,296개 주소에 바이트 하나씩 대응하기 때문이다. 실제 PC에서는 CPU와 메모리 사이를 전용 메모리 버스가, 그래픽카드와 SSD를 PCI Express가 연결하는 식으로 버스가 여러 개로 나뉘어 있지만 주소·데이터·제어를 구분하는 원리는 같다.

### 폰 노이만 병목과 하버드 구조

명령어와 데이터가 같은 버스를 쓰므로 CPU는 명령어를 읽는 동안 데이터를 읽을 수 없다. CPU 연산 속도는 메모리 접근 속도보다 훨씬 빠르게 발전해 왔기 때문에, CPU가 메모리를 기다리는 시간이 성능을 제한한다. 이를 폰 노이만 병목(von Neumann bottleneck)이라고 한다.

하버드 구조(Harvard architecture)는 명령어 메모리와 데이터 메모리, 각각의 버스를 분리해 두 가지를 동시에 읽는다. 마이크로컨트롤러와 DSP가 이 구조를 쓴다. 오늘날 PC용 CPU는 주기억장치는 하나로 두되 CPU 안의 L1 캐시를 명령어 캐시와 데이터 캐시로 나누는 수정된 하버드 구조를 쓴다.

> [!NOTE] 보안 관점
> 명령어와 데이터를 같은 메모리에 두는 구조 때문에, 데이터로 입력한 바이트열이 명령어로 실행될 수 있다. 현대 CPU와 운영체제는 메모리 페이지마다 실행 가능 여부를 표시하는 NX(No-eXecute) 비트로 스택과 힙의 데이터가 실행되지 않게 막는다.

## 중앙처리장치(CPU)

### 구성 요소

| 구성 요소                  | 역할                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| 제어장치(CU, Control Unit) | 명령어 레지스터의 명령어를 해독하고, ALU·레지스터·버스에 제어 신호를 보내 실행 순서를 조정 |
| 산술논리장치(ALU)          | 덧셈·뺄셈 같은 산술 연산, AND·OR·NOT·XOR 같은 논리 연산, 비트 이동(shift)과 비교           |
| 레지스터(register)         | CPU 내부의 고속 기억장치. 실행 중인 명령어, 주소, 연산 값과 결과를 임시로 보관             |

ALU는 연산 결과와 함께 상태 플래그를 설정한다. 결과가 0이면 Zero 플래그, 음수면 Negative 플래그, 자리올림이 생기면 Carry 플래그, 2의 보수 범위를 넘으면 Overflow 플래그가 1이 된다. `if (a == b)` 같은 조건문은 기계어에서 a - b를 계산한 뒤 Zero 플래그를 보고 분기하는 명령어로 바뀐다.

### 주요 레지스터

| 레지스터                       | 역할                                                         |
| ------------------------------ | ------------------------------------------------------------ |
| 프로그램 카운터(PC)            | 다음에 인출할 명령어의 메모리 주소. x86-64에서는 RIP         |
| 명령어 레지스터(IR)            | 현재 실행 중인 명령어                                        |
| 메모리 주소 레지스터(MAR)      | 읽거나 쓸 메모리 주소. 주소 버스에 연결                      |
| 메모리 버퍼 레지스터(MBR, MDR) | 메모리에서 읽었거나 메모리에 쓸 데이터. 데이터 버스에 연결   |
| 누산기(AC, accumulator)        | 연산의 입력값과 결과를 보관하는 레지스터(단일 누산기 구조)   |
| 범용 레지스터                  | 프로그램이 자유롭게 쓰는 레지스터. x86-64는 RAX, RBX 등 16개 |
| 스택 포인터(SP)                | 스택의 맨 위 주소. x86-64에서는 RSP                          |
| 상태 레지스터(플래그 레지스터) | ALU 연산 결과의 Zero, Carry, Overflow 등 상태 비트           |

PC는 보안에서 특히 중요하다. CPU는 PC가 가리키는 곳의 바이트를 명령어로 해석해 실행하므로, 공격자가 PC 값을 바꿀 수 있으면 프로그램의 실행 흐름을 장악한다. 스택 버퍼 오버플로는 함수가 끝날 때 PC로 복원될 복귀 주소를 덮어써 이를 달성한다.

## 명령어 세트

### 명령어 형식

명령어 세트(instruction set)는 CPU가 이해하는 명령어의 목록과 그 2진 형식이다. 같은 명령어 세트를 쓰는 CPU끼리는 같은 기계어 프로그램을 실행할 수 있다. x86-64(Intel, AMD)와 ARM(Apple M 시리즈, 대부분의 스마트폰)이 대표적이다.

명령어는 연산 코드와 피연산자로 이루어진다.

| 필드              | 내용                                              | 예                     |
| ----------------- | ------------------------------------------------- | ---------------------- |
| 연산 코드(opcode) | 수행할 연산의 종류                                | ADD, LOAD, STORE, JUMP |
| 피연산자(operand) | 연산 대상. 값 자체, 레지스터 번호, 메모리 주소 등 | `R1`, `0x1000`, `#5`   |

연산 코드는 기능에 따라 산술·논리 연산, 데이터 전송(메모리와 레지스터 사이 이동), 제어(분기·함수 호출), 입출력으로 나뉜다.

### 주소 필드 수에 따른 분류

명령어 하나에 피연산자 주소를 몇 개 적는지에 따라 명령어 형식을 나눈다. `X = A + B`를 계산하는 프로그램을 각 형식으로 쓰면 차이가 드러난다.

| 형식   | 사용하는 구조      | `X = A + B` 프로그램                    | 명령어 수 |
| ------ | ------------------ | --------------------------------------- | --------- |
| 0-주소 | 스택 구조          | `PUSH A` / `PUSH B` / `ADD` / `POP X`   | 4         |
| 1-주소 | 단일 누산기 구조   | `LOAD A` / `ADD B` / `STORE X`          | 3         |
| 2-주소 | 범용 레지스터 구조 | `MOV R1, A` / `ADD R1, B` / `MOV X, R1` | 3         |
| 3-주소 | 범용 레지스터 구조 | `ADD X, A, B`                           | 1         |

- 0-주소: 연산 코드만 있다. `ADD`는 스택 맨 위의 두 값을 꺼내(pop) 더한 결과를 다시 넣는다(push). Java 가상 머신과 WebAssembly가 이 방식의 바이트코드를 쓴다.
- 1-주소: 피연산자 하나는 항상 누산기(AC)다. `ADD B`는 `AC ← AC + B`를 뜻한다. 초기 컴퓨터와 단순한 마이크로컨트롤러가 이 방식이었다.
- 2-주소: 첫 피연산자가 입력이자 결과 저장 위치다. `ADD R1, B`는 `R1 ← R1 + B`다. x86이 이 형식이다.
- 3-주소: 두 입력과 결과 위치를 모두 적는다. 프로그램은 짧아지지만 명령어 하나의 길이가 길어진다. ARM과 RISC-V는 레지스터 3개를 지정하는 3-주소 형식을 쓰되, 메모리 접근은 LOAD·STORE 명령어로만 한다.

주소 필드가 적을수록 명령어 하나는 짧아지고, 같은 일을 하는 데 필요한 명령어 수는 늘어난다.

## 명령어 사이클

### 네 개의 부사이클

CPU가 명령어 하나를 메모리에서 가져와 실행을 마치기까지의 과정을 명령어 사이클(instruction cycle)이라고 한다. 인출 사이클과 실행 사이클은 모든 명령어에서 수행하고, 간접 사이클과 인터럽트 사이클은 조건이 맞을 때만 수행한다.

![명령어 사이클: 인출 사이클 다음에 간접 주소 지정이면 간접 사이클을 거쳐, 직접 주소 지정이면 바로 실행 사이클로 간다. 실행이 끝나면 인터럽트 요청이 있을 때 인터럽트 사이클을 수행하고 다음 명령어의 인출로 돌아간다](./images/csintro-computer-architecture-cycle.svg '실선 상자는 항상, 점선 상자는 조건에 따라 수행한다')

### 인출 사이클

메모리에서 명령어를 가져오는 단계다. 레지스터 사이의 데이터 이동을 마이크로 연산(micro-operation)이라고 하며, 클록 한 주기(t)마다 하나 이상 수행된다.

| 시점 | 마이크로 연산                 | 설명                                              |
| ---- | ----------------------------- | ------------------------------------------------- |
| t0   | `MAR ← PC`                    | 다음 명령어 주소를 주소 버스로 보낸다             |
| t1   | `MBR ← M[MAR]`, `PC ← PC + 1` | 메모리가 명령어를 데이터 버스로 보내고, PC를 증가 |
| t2   | `IR ← MBR`                    | 명령어를 명령어 레지스터로 옮긴다                 |

PC는 인출 직후 증가하므로, 실행 단계에서 분기 명령어가 PC를 바꾸지 않는 한 다음 사이클은 바로 다음 명령어를 인출한다. (PC + 1은 명령어 하나가 주소 하나를 차지한다고 가정한 표기이고, 실제로는 명령어 길이만큼 증가한다.)

### 실행 사이클

제어장치가 IR의 연산 코드를 해독(decode)하고, 그에 맞는 제어 신호를 내보내 실행한다. 1-주소 명령어 `ADD B`라면 다음과 같다.

| 시점 | 마이크로 연산         | 설명                            |
| ---- | --------------------- | ------------------------------- |
| t0   | `MAR ← IR(주소 필드)` | 피연산자 B의 주소를 주소 버스로 |
| t1   | `MBR ← M[MAR]`        | B의 값을 읽는다                 |
| t2   | `AC ← AC + MBR`       | ALU가 더해 누산기에 저장한다    |

분기 명령어 `JUMP 300`이라면 실행 사이클에서 `PC ← 300`만 수행하고, 다음 인출 사이클은 300번지에서 명령어를 가져온다. 조건 분기는 상태 플래그를 확인해 PC를 바꿀지 결정한다.

### 간접 사이클

명령어의 주소 필드가 피연산자의 주소를 직접 담고 있으면(직접 주소 지정) 간접 사이클은 필요 없다. 주소 필드가 "피연산자의 주소가 저장된 곳의 주소"를 담고 있으면(간접 주소 지정), 실행 전에 메모리를 한 번 더 읽어 실제 주소를 얻는다.

| 시점 | 마이크로 연산         | 설명                                         |
| ---- | --------------------- | -------------------------------------------- |
| t0   | `MAR ← IR(주소 필드)` | 주소 필드의 값(포인터의 위치)을 보낸다       |
| t1   | `MBR ← M[MAR]`        | 그 위치에 저장된 실제 피연산자 주소를 읽는다 |
| t2   | `IR(주소 필드) ← MBR` | 주소 필드를 실제 주소로 바꾼다               |

C 언어의 포인터 역참조 `*p`가 같은 개념이다. 변수 p에는 데이터 자체가 아니라 데이터가 있는 주소가 들어 있다.

### 인터럽트 사이클

인터럽트(interrupt)는 CPU가 프로그램을 실행하는 도중 처리해야 할 사건이 생겼음을 알리는 신호다. 키보드 입력, 디스크 읽기 완료, 타이머 만료 같은 외부 사건과, 0으로 나누기나 잘못된 메모리 접근 같은 내부 사건(예외)이 있다.

인터럽트가 없다면 CPU는 키가 눌렸는지 계속 확인(폴링)해야 하므로, 사람이 키를 누르지 않는 동안에도 CPU 시간을 낭비한다. 인터럽트 방식에서는 장치가 필요한 시각에 제어 버스로 인터럽트 요청을 보내고, CPU는 그동안 다른 일을 한다.

CPU는 실행 사이클이 끝날 때마다 인터럽트 요청이 있는지 확인하고, 있으면 다음을 수행한다.

1. 현재 PC 값(돌아올 주소)을 스택에 저장한다: `MBR ← PC`, `MAR ← SP`, `M[MAR] ← MBR`
2. PC에 인터럽트 처리 루틴(ISR)의 시작 주소를 넣는다.
3. 다음 인출 사이클은 ISR의 첫 명령어를 가져온다. ISR이 끝나면 저장한 PC를 복원해 원래 프로그램으로 돌아간다.

운영체제가 여러 프로그램을 번갈아 실행하는 것도 타이머 인터럽트로 일정 시간마다 CPU 제어권을 가져오기 때문에 가능하다. 운영체제의 프로세스 관리와 CPU 스케줄링이 이 위에서 동작한다.

> [!TIP] 파이프라이닝
> 위 설명은 명령어 하나를 끝낸 뒤 다음 명령어를 시작하는 방식이다. 실제 CPU는 인출·해독·실행 단계를 서로 다른 회로에서 동시에 진행해, 명령어 1이 실행되는 동안 명령어 2를 해독하고 명령어 3을 인출한다(파이프라이닝). 분기 명령어를 만나면 다음에 실행할 명령어를 예측해 미리 실행하는데(투기적 실행), Spectre 취약점은 이 예측이 틀렸을 때 캐시에 남는 흔적을 이용한다.

## 기억장치

### 계층 구조

빠른 기억장치일수록 바이트당 가격이 비싸므로 큰 용량을 만들기 어렵다. 그래서 컴퓨터는 빠르고 작은 기억장치부터 느리고 큰 기억장치까지 여러 단계를 계층으로 쌓는다.

![기억장치 계층 구조: 위에서부터 레지스터(1 ns 미만, 수백 바이트~수 KB), 캐시 SRAM(약 1~10 ns, 수십 KB~수십 MB), 주기억장치 DRAM(약 50~100 ns, 수~수백 GB), 보조기억장치 SSD·HDD(SSD 수십 μs, HDD 수 ms, TB 단위). 위로 갈수록 빠르고 비싸며 용량이 작다](./images/csintro-computer-architecture-hierarchy.svg '수치는 대략적인 크기 단위다')

계층 구조가 효과적인 이유는 지역성(locality) 때문이다. 프로그램은 짧은 시간 동안 메모리의 일부분만 집중적으로 접근한다.

- 시간 지역성: 최근 접근한 데이터를 곧 다시 접근한다. 반복문의 카운터 변수가 예다.
- 공간 지역성: 접근한 주소 근처를 곧 접근한다. 배열을 처음부터 순서대로 읽는 경우가 예다.

자주 쓰는 데이터를 위 계층에 복사해 두면, 대부분의 접근은 빠른 계층에서 끝난다. 데이터의 흐름은 보조기억장치 → 주기억장치 → 캐시 → 레지스터 순이며, CPU는 보조기억장치에 직접 접근하지 않는다. 프로그램을 실행하면 운영체제가 실행 파일을 SSD에서 RAM으로 적재하는 이유다.

### 주기억장치: RAM과 ROM

RAM(Random Access Memory)은 주소와 관계없이 일정한 시간에 읽고 쓸 수 있는 메모리다. 전원이 꺼지면 내용이 사라지는 휘발성 메모리다. 초기 컴퓨터는 자성체 고리에 정보를 저장하는 자기 코어 메모리를 썼고, 1970년대부터 반도체 메모리로 바뀌었다.

| 구분        | DRAM(Dynamic RAM)                                         | SRAM(Static RAM)                         |
| ----------- | --------------------------------------------------------- | ---------------------------------------- |
| 기억 소자   | 트랜지스터 1개 + 커패시터 1개                             | 트랜지스터 6개로 구성한 플립플롭         |
| 저장 원리   | 커패시터에 충전된 전하의 유무                             | 플립플롭의 두 안정 상태                  |
| 재충전      | 전하가 누설되므로 수십 ms마다 주기적 재충전(refresh) 필요 | 전원이 공급되는 동안 유지, 재충전 불필요 |
| 속도        | 상대적으로 느림(수십 ns)                                  | 빠름(수 ns 이하)                         |
| 집적도·가격 | 셀이 작아 집적도가 높고 저렴                              | 셀이 커서 집적도가 낮고 비쌈             |
| 용도        | 주기억장치(DDR4, DDR5 메모리 모듈)                        | CPU 내부 캐시 메모리                     |

ROM(Read Only Memory)은 전원이 없어도 내용이 유지되는 비휘발성 메모리로, 컴퓨터를 켤 때 처음 실행되는 펌웨어(BIOS, UEFI)를 저장한다.

| 종류       | 기록 방법                                               |
| ---------- | ------------------------------------------------------- |
| 마스크 ROM | 제조 공정에서 내용을 기록. 변경 불가                    |
| PROM       | 사용자가 한 번만 기록(퓨즈를 끊는 방식)                 |
| EPROM      | 자외선을 쬐어 전체 삭제 후 다시 기록                    |
| EEPROM     | 전기 신호로 바이트 단위 삭제·기록. 플래시 메모리의 기반 |

오늘날 메인보드의 펌웨어는 플래시 메모리에 저장되어 업데이트할 수 있다. 업데이트가 가능하다는 것은 공격자가 악성 펌웨어를 기록할 수도 있다는 뜻이어서, UEFI 보안 부팅(Secure Boot)은 서명이 검증된 펌웨어와 부트로더만 실행한다.

DRAM은 공격 대상이 되기도 한다. 행 하나를 매우 빠르게 반복해서 읽으면 인접한 행의 커패시터 전하가 영향을 받아 비트가 뒤집히는 현상을 로해머(Rowhammer)라고 하며, 이를 이용해 커널 메모리의 권한 비트를 바꾸는 공격이 시연되었다.

### 캐시 메모리

캐시(cache)는 CPU와 주기억장치 사이에 두는 SRAM 기억장치다. CPU가 데이터를 요청하면 먼저 캐시를 확인하고, 있으면(캐시 적중, hit) 수 ns 안에 가져오고, 없으면(캐시 실패, miss) 주기억장치에서 가져오면서 그 주변 데이터(캐시 라인, 보통 64바이트)를 함께 캐시에 복사한다.

현대 CPU는 캐시를 여러 단계로 둔다.

| 단계 | 위치                         | 크기(예)      | 접근 시간(예) |
| ---- | ---------------------------- | ------------- | ------------- |
| L1   | 코어마다, 명령어·데이터 분리 | 수십 KB       | 약 1 ns       |
| L2   | 코어마다                     | 수백 KB~수 MB | 약 3~5 ns     |
| L3   | 여러 코어가 공유             | 수 MB~수십 MB | 약 10~20 ns   |

평균 접근 시간은 적중률에 크게 좌우된다. 캐시 접근 시간이 1 ns, 주기억장치 접근 시간이 100 ns일 때를 계산하면 다음과 같다.

| 적중률 | 평균 접근 시간 계산                            | 결과  |
| ------ | ---------------------------------------------- | ----- |
| 90%    | `0.9 \times 1 + 0.1 \times (1 + 100){:math}`   | 11 ns |
| 99%    | `0.99 \times 1 + 0.01 \times (1 + 100){:math}` | 2 ns  |

적중률이 9%p 오르면 평균 접근 시간이 5분의 1 이하로 줄어든다. 같은 계산이라도 배열을 메모리 순서대로 읽는 코드가 무작위로 읽는 코드보다 빠른 이유다.

### 보조기억장치

보조기억장치는 전원과 관계없이 데이터를 영구 보관하는 대용량 저장장치다. 접근 방식에 따라 나뉜다.

| 장치               | 접근 방식 | 원리                                                            | 특징                                     |
| ------------------ | --------- | --------------------------------------------------------------- | ---------------------------------------- |
| 자기 테이프        | 순차 접근 | 긴 테이프의 자성 방향으로 기록. 원하는 위치까지 감아야 한다     | 용량당 가격이 가장 낮아 장기 백업·보관용 |
| HDD(자기 디스크)   | 직접 접근 | 회전하는 자성 원판 위로 헤드가 이동해 읽고 쓴다                 | 헤드 이동과 회전 대기로 수 ms가 걸린다   |
| 광 디스크          | 직접 접근 | 레이저로 원판 표면의 미세한 홈(pit)을 읽는다. CD, DVD, 블루레이 | 배포용 매체                              |
| SSD(플래시 메모리) | 직접 접근 | 플로팅 게이트 등에 전하를 가두는 비휘발성 반도체 메모리         | 기계 부품이 없어 빠르고 충격에 강하다    |

플래시 메모리는 셀 구성에 따라 NAND형과 NOR형으로 나뉜다. NAND형은 집적도가 높아 SSD와 USB 메모리처럼 대용량 데이터 저장에 쓰이고, NOR형은 바이트 단위로 빠르게 읽을 수 있어 펌웨어 같은 코드 저장에 쓰인다.

> [!WARNING] 삭제한 파일과 SSD
> 운영체제에서 파일을 삭제하면 보통 파일 시스템의 목록에서 항목만 지우고 데이터 자체는 남는다. HDD는 그 위치를 덮어쓰면 복구가 어렵지만, SSD는 수명 관리를 위해 쓰기를 다른 셀에 분산(웨어 레벨링)하므로 같은 파일을 덮어써도 원래 셀이 남을 수 있다. 저장장치를 폐기할 때는 제조사의 보안 삭제(Secure Erase) 기능이나 전체 디스크 암호화 후 키 폐기를 쓴다.

## 입출력장치

입출력장치는 외부 세계와 컴퓨터 사이에서 데이터를 변환한다.

| 분류 | 장치              | 원리와 특징                                                                    |
| ---- | ----------------- | ------------------------------------------------------------------------------ |
| 입력 | 키보드            | 키가 눌리면 키보드 컨트롤러가 키 위치의 스캔 코드를 컴퓨터로 보낸다            |
| 입력 | 마우스, 조이스틱  | 이동량과 버튼 상태를 전송. 광학 마우스는 바닥 표면 이미지의 변화로 이동을 계산 |
| 입력 | 터치스크린        | 정전식은 손가락이 닿은 위치의 정전 용량 변화를 감지                            |
| 입력 | 스캐너            | 빛을 비추고 반사광을 이미지 센서로 읽어 비트맵으로 변환                        |
| 출력 | LCD 모니터        | 뒤쪽 백라이트의 빛을 액정이 픽셀마다 통과시키거나 막는다                       |
| 출력 | OLED              | 유기 화합물이 전류를 받아 스스로 발광. 백라이트가 없어 얇고 휘어지는 화면 가능 |
| 출력 | 프린터            | 충격식(도트 매트릭스)과 비충격식(잉크젯, 레이저)                               |
| 출력 | 3D 프린터         | 3차원 설계 데이터를 얇은 층으로 나눠 재료를 한 층씩 쌓아 입체 모형을 만든다    |
| 출력 | 플로터, 햅틱 장치 | 대형 도면 출력, 진동·힘으로 촉각 정보 전달                                     |

CRT 모니터와 PDP는 지금은 거의 쓰이지 않는다. 입출력장치는 CPU보다 훨씬 느리므로, CPU는 앞에서 본 인터럽트로 입출력 완료를 통지받고, 대량 데이터 전송은 CPU를 거치지 않고 장치가 메모리에 직접 쓰는 DMA(Direct Memory Access)로 처리한다.

입력장치도 공격 경로가 된다. USB 장치가 키보드인 것처럼 자신을 등록하고 미리 입력된 명령어를 빠르게 타이핑하는 공격(BadUSB 계열)이 있어, 출처를 모르는 USB 장치를 연결하지 않는 것이 기본 보안 수칙이다.

## 정리

- 폰 노이만 구조는 CPU, 주기억장치, 입출력장치가 시스템 버스로 연결되고, 명령어와 데이터를 같은 메모리에 저장한다. 같은 버스를 공유하므로 폰 노이만 병목이 생긴다.
- 시스템 버스는 주소(어디를), 데이터(무엇을), 제어(읽기·쓰기 등 어떻게)로 나뉜다.
- CPU는 제어장치, ALU, 레지스터로 이루어지며, PC는 다음 명령어의 주소를, IR은 현재 명령어를, MAR과 MBR은 메모리와 주고받는 주소와 데이터를 보관한다.
- 명령어 사이클은 인출과 실행을 항상, 간접과 인터럽트를 조건에 따라 수행한다.
- 기억장치는 레지스터, 캐시(SRAM), 주기억장치(DRAM), 보조기억장치 순으로 느리고 커지며, 지역성 덕분에 대부분의 접근이 빠른 계층에서 끝난다.
