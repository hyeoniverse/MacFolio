## 들어가기 전에

[컴퓨터의 구성과 역사](/memo/csintro-overview)에서 컴퓨터가 입력·처리·기억·출력 장치로 이루어지고, 프로그램을 메모리에 저장해 실행한다는 것을 보았다. [정보의 표현](/memo/csintro-data-representation)에서는 숫자와 문자가 비트열로 저장되는 방식을 보았다. 이 글은 그 두 가지를 잇는다. 메모리에 저장된 비트열을 CPU가 어떤 경로로 가져와, 어떤 부품이 어떤 순서로 처리하는지를 다룬다.

## 컴퓨터 시스템의 구성

### 하드웨어와 소프트웨어

컴퓨터 시스템은 하드웨어와 소프트웨어로 이루어진다. 하드웨어는 CPU, 메모리 칩, 메인보드, 저장장치, 키보드처럼 ==손으로 만질 수 있는 물리적 장치==다. 소프트웨어는 하드웨어에게 무엇을 할지 지시하고 제어하는 ==명령어의 집합==이다. 같은 노트북이라도 문서 편집기를 실행하면 문서 작업 도구가 되고, 게임을 실행하면 게임기가 된다. 하드웨어는 그대로이고 메모리에 적재한 명령어만 바뀌었기 때문이다.

![본체를 연 데스크톱의 부품 사진. 메인보드 위의 CPU와 주기억장치, 비디오 카드, 랜카드, 시디롬과 하드 디스크, 케이스, 그리고 모니터·키보드·프린터가 연결된 모습](./images/csintro-computer-architecture-parts.jpg '데스크톱 컴퓨터를 이루는 하드웨어 부품. 출처: 『컴퓨터 사이언스』(한빛아카데미)')

사진에서 메인보드(main board)는 모든 부품을 꽂는 기판이고, CPU 소켓과 메모리 슬롯, 확장 카드 슬롯이 이 기판의 버스 배선으로 연결된다. 비디오 카드와 랜카드는 각각 화면 출력과 네트워크 통신을 맡는 입출력 장치이고, 하드 디스크와 시디롬은 보조기억장치다.

하드웨어는 기능에 따라 네 부분으로 나뉜다.

| 구성 요소    | 역할                                                                 | 예                                  |
| ------------ | -------------------------------------------------------------------- | ----------------------------------- |
| 중앙처리장치 | 주기억장치에서 명령어와 데이터를 읽어 와 해독하고 연산               | Intel Core, AMD Ryzen, Apple M 계열 |
| 주기억장치   | 실행 중인 프로그램과 데이터, 연산의 중간 결과를 일시적으로 저장      | DDR5 메모리 모듈                    |
| 보조기억장치 | 프로그램과 데이터를 전원과 관계없이 영구적으로 보관                  | SSD, HDD, USB 메모리                |
| 입출력장치   | 외부의 자료를 컴퓨터 안으로 입력하고, 처리 결과를 외부로 표현해 출력 | 키보드, 마우스, 모니터, 프린터      |

예를 들어 사진 편집 프로그램으로 사진의 밝기를 올리는 과정은 다음 순서로 네 부분을 모두 거친다.

1. 보조기억장치(SSD)에 저장된 프로그램 파일과 사진 파일을 운영체제가 주기억장치(RAM)로 복사한다.
2. CPU가 RAM에서 프로그램의 명령어를 하나씩 읽어 와, 픽셀마다 밝기 값에 일정한 수를 더하는 연산을 수행한다.
3. 결과 픽셀 값은 RAM에 다시 저장되고, 그래픽 장치를 거쳐 모니터(출력장치)에 표시된다.
4. 사용자가 저장 단축키(입력장치)를 누르면 RAM의 결과가 SSD에 기록된다.

이 글은 이 네 부분과 그 사이를 잇는 버스를 차례로 다룬다.

## 폰 노이만 구조

### 구성

폰 노이만 구조(von Neumann architecture)는 1945년 존 폰 노이만이 EDVAC 보고서에서 정리한 컴퓨터 구조로, 오늘날 대부분의 범용 컴퓨터가 따른다. 핵심은 세 가지다.

1. CPU, 주기억장치, 입출력장치로 구성된다.
2. 명령어와 데이터를 같은 주기억장치에 같은 형태(2진수)로 저장한다.
3. CPU는 명령어를 메모리에서 하나씩 순서대로 가져와 실행한다.

![폰 노이만 구조: CPU(제어장치, ALU, 레지스터 PC·IR·MAR·MBR·AC), 명령어와 데이터를 함께 저장하는 주기억장치, 입출력장치가 주소 버스, 데이터 버스, 제어 버스에 연결되어 있다](./images/csintro-computer-architecture-von-neumann.svg '명령어와 데이터가 같은 메모리와 같은 버스를 공유한다')

### 시스템 버스

버스(bus)는 여러 장치가 공유하는 신호선의 묶음이다. 장치마다 전용 선을 연결하면 장치가 늘어날수록 선의 수가 급격히 늘어나므로, ==공용 통로 하나에 모든 장치를 연결==하고 ==한 시점에 한 장치만 데이터를 보내게== 한다. CPU와 메모리, 입출력장치를 잇는 시스템 버스는 역할에 따라 세 종류로 나뉜다.

| 버스        | 전달하는 것                            | 방향                        | 폭의 의미                                            |
| ----------- | -------------------------------------- | --------------------------- | ---------------------------------------------------- |
| 주소 버스   | 읽거나 쓸 메모리·입출력 장치의 주소    | CPU → 메모리·입출력, 단방향 | n비트면 `2^n{:math}`개 주소 지정. 32비트면 4 GiB까지 |
| 데이터 버스 | 실제로 읽거나 쓰는 데이터와 명령어     | 양방향                      | 한 번에 전송하는 비트 수                             |
| 제어 버스   | 읽기·쓰기 신호, 클록, 인터럽트 요청 등 | 신호마다 다름               |                                                      |

예를 들어 CPU가 메모리 0x1000번지의 값을 읽는 과정은 다음과 같다.

1. CPU가 주소 버스에 `0x1000`을 싣는다.
2. 제어 버스의 읽기(read) 신호를 활성화한다.
3. 메모리가 해당 번지의 값을 데이터 버스에 싣는다.
4. CPU가 데이터 버스의 값을 레지스터로 가져온다.

![시스템 버스로 메모리를 읽는 과정: CPU가 주소 버스에 0x1000을 싣고, 제어 버스로 읽기 신호를 보내면, 메모리가 데이터 버스로 값 42를 돌려준다](./images/csintro-computer-architecture-bus.svg '주소와 제어 신호는 CPU에서 나가고, 데이터는 양쪽으로 오간다')

쓰기는 방향만 다르다. CPU가 주소 버스에 주소를, 데이터 버스에 기록할 값을 싣고 제어 버스의 쓰기(write) 신호를 활성화하면 메모리가 그 번지에 값을 저장한다. 입출력장치도 같은 버스에 연결되어 있어서, CPU는 장치마다 배정된 주소로 읽기·쓰기를 수행해 장치와 데이터를 주고받는다.

버스의 폭은 두 가지 한계를 정한다.

| 항목           | 결정하는 것                       | 계산 예                                                                           |
| -------------- | --------------------------------- | --------------------------------------------------------------------------------- |
| 주소 버스 폭   | 지정할 수 있는 메모리 주소의 개수 | 16비트: `2^{16}{:math}` = 65,536개(64 KiB), 32비트: 약 43억 개(4 GiB)             |
| 데이터 버스 폭 | 한 번의 전송으로 옮기는 비트 수   | 64비트 버스는 한 번에 8바이트. 같은 클록에서 32비트 버스보다 2배의 데이터를 전송  |
| 클록 주파수    | 1초에 수행하는 전송 횟수의 상한   | 데이터 폭 8바이트 × 초당 32억 회 전송 = 약 25.6 GB/s (DDR4-3200 한 채널의 이론값) |

32비트 주소 버스를 쓰는 CPU가 RAM을 4 GiB까지만 인식했던 이유가 주소 버스 폭이다. `2^{32}{:math}` = 4,294,967,296개 주소에 바이트 하나씩 대응하기 때문이다. 실제 PC에서는 CPU와 메모리 사이를 전용 메모리 버스가, 그래픽카드와 SSD를 PCI Express가 연결하는 식으로 버스가 여러 개로 나뉘어 있지만 주소·데이터·제어를 구분하는 원리는 같다.

### 폰 노이만 병목과 하버드 구조

명령어와 데이터가 같은 버스를 쓰므로 CPU는 명령어를 읽는 동안 데이터를 읽을 수 없다. CPU 연산 속도는 메모리 접근 속도보다 훨씬 빠르게 발전해 왔기 때문에, ==CPU가 메모리를 기다리는 시간이 성능을 제한==한다. 이를 폰 노이만 병목(von Neumann bottleneck)이라고 한다.

하버드 구조(Harvard architecture)는 명령어 메모리와 데이터 메모리, 각각의 버스를 분리해 두 가지를 동시에 읽는다. 마이크로컨트롤러와 DSP가 이 구조를 쓴다. 오늘날 PC용 CPU는 주기억장치는 하나로 두되 CPU 안의 L1 캐시를 명령어 캐시와 데이터 캐시로 나누는 수정된 하버드 구조를 쓴다.

> [!NOTE] 보안 관점
> 명령어와 데이터를 같은 메모리에 두는 구조 때문에, 데이터로 입력한 바이트열이 명령어로 실행될 수 있다. 현대 CPU와 운영체제는 메모리 페이지마다 실행 가능 여부를 표시하는 NX(No-eXecute) 비트로 스택과 힙의 데이터가 실행되지 않게 막는다.

## 중앙처리장치(CPU)

### 구성 요소

| 구성 요소                  | 역할                                                                                       |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| 제어장치(CU, Control Unit) | 명령어 레지스터의 명령어를 해독하고, ALU·레지스터·버스에 제어 신호를 보내 실행 순서를 조정 |
| 산술논리장치(ALU)          | 덧셈·뺄셈 같은 산술 연산, AND·OR·NOT·XOR 같은 논리 연산, 비트 이동(shift)과 비교           |
| 레지스터(register)         | CPU 내부의 고속 기억장치. 실행 중인 명령어, 주소, 연산 값과 결과를 임시로 보관             |

ALU는 연산 결과와 함께 상태 플래그를 설정한다. ==결과가 0이면 Zero 플래그==, 음수면 Negative 플래그, 자리올림이 생기면 Carry 플래그, 2의 보수 범위를 넘으면 Overflow 플래그가 1이 된다. `if (a == b)` 같은 조건문은 기계어에서 a - b를 계산한 뒤 Zero 플래그를 보고 분기하는 명령어로 바뀐다.

### 주요 레지스터

![특수 목적 레지스터를 용도별로 나눈 표. 주소 저장용 MAR, PC, SP, IX, 명령어 저장용 IR, 데이터 저장용 MBR, AC, CPU 상태 저장용 PSR](./images/csintro-computer-architecture-registers.jpg '특수 목적 레지스터의 용도와 기능. 출처: 『컴퓨터 사이언스』(한빛아카데미) 표 3-1')

표의 레지스터를 용도로 묶으면 ==주소를 담는 레지스터(MAR, PC, SP, IX)와 값을 담는 레지스터(IR, MBR, AC)==로 나뉜다. 스택 포인터(SP)는 함수 호출 시 복귀 주소를 쌓는 스택의 꼭대기를, 인덱스 레지스터(IX)는 배열처럼 기준 주소에 일정 간격을 더해 접근할 때의 간격 값을 보관한다. 프로그램 상태 레지스터(PSR)는 뒤에서 설명할 상태 플래그와 인터럽트 허용 여부를 담는다.

| 레지스터                       | 역할                                                         |
| ------------------------------ | ------------------------------------------------------------ |
| 프로그램 카운터(PC)            | 다음에 인출할 명령어의 메모리 주소. x86-64에서는 RIP         |
| 명령어 레지스터(IR)            | 현재 실행 중인 명령어                                        |
| 메모리 주소 레지스터(MAR)      | 읽거나 쓸 메모리 주소. 주소 버스에 연결                      |
| 메모리 버퍼 레지스터(MBR, MDR) | 메모리에서 읽었거나 메모리에 쓸 데이터. 데이터 버스에 연결   |
| 누산기(AC, accumulator)        | 연산의 입력값과 결과를 보관하는 레지스터(단일 누산기 구조)   |
| 범용 레지스터                  | 프로그램이 자유롭게 쓰는 레지스터. x86-64는 RAX, RBX 등 16개 |
| 스택 포인터(SP)                | 스택의 맨 위 주소. x86-64에서는 RSP                          |
| 상태 레지스터(플래그 레지스터) | ALU 연산 결과의 Zero, Carry, Overflow 등 상태 비트           |

PC는 보안에서 특히 중요하다. CPU는 PC가 가리키는 곳의 바이트를 명령어로 해석해 실행하므로, 공격자가 PC 값을 바꿀 수 있으면 프로그램의 실행 흐름을 장악한다. 스택 버퍼 오버플로는 함수가 끝날 때 PC로 복원될 복귀 주소를 덮어써 이를 달성한다.

레지스터가 필요한 이유는 속도 차이다. 레지스터는 CPU 코어 안에 있어 CPU 클록 한 주기(3 GHz CPU라면 약 0.33 ns) 안에 읽고 쓸 수 있지만, 주기억장치에 다녀오려면 수십~백 ns가 걸린다. 그래서 CPU는 연산에 쓸 값을 먼저 레지스터로 가져온 뒤 레지스터끼리 연산한다.

### CPU의 동작 예시

구성 요소가 함께 동작하는 모습을 작은 프로그램으로 따라가 본다. 메모리에 다음 내용이 저장되어 있다고 가정한다. 단일 누산기 구조이고, 명령어 하나가 주소 하나를 차지한다.

| 주소 | 내용        | 뜻                                   |
| ---- | ----------- | ------------------------------------ |
| 100  | `LOAD 200`  | 200번지의 값을 누산기(AC)로 가져온다 |
| 101  | `ADD 201`   | 201번지의 값을 AC에 더한다           |
| 102  | `STORE 202` | AC의 값을 202번지에 저장한다         |
| 200  | 5           | 데이터 A                             |
| 201  | 3           | 데이터 B                             |
| 202  | 0           | 결과 X를 저장할 자리                 |

PC가 100에서 시작하면 레지스터 값은 다음처럼 바뀐다.

| 단계            | PC  | IR          | MAR | MBR         | AC  | 202번지 |
| --------------- | --- | ----------- | --- | ----------- | --- | ------- |
| 시작            | 100 |             |     |             | 0   | 0       |
| 1번 명령어 인출 | 101 | `LOAD 200`  | 100 | `LOAD 200`  | 0   | 0       |
| 1번 명령어 실행 | 101 | `LOAD 200`  | 200 | 5           | 5   | 0       |
| 2번 명령어 인출 | 102 | `ADD 201`   | 101 | `ADD 201`   | 5   | 0       |
| 2번 명령어 실행 | 102 | `ADD 201`   | 201 | 3           | 8   | 0       |
| 3번 명령어 인출 | 103 | `STORE 202` | 102 | `STORE 202` | 8   | 0       |
| 3번 명령어 실행 | 103 | `STORE 202` | 202 | 8           | 8   | 8       |

이 표에서 세 가지를 확인할 수 있다. 첫째, 명령어(100~102번지)와 데이터(200~202번지)가 같은 메모리에 함께 저장되어 있다. 둘째, PC는 인출이 끝나자마자 다음 주소로 증가한다. 셋째, 메모리와 주고받는 모든 값은 MAR(주소)과 MBR(데이터)을 거친다. 이 표가 `X = A + B`라는 한 줄짜리 코드가 하드웨어에서 실행되는 모습이다.

CPU의 처리 속도는 클록 주파수와 클록당 처리하는 명령어 수로 정해진다. 클록(clock)은 CPU 내부 회로의 동작 시점을 맞추는 일정한 주기의 신호이고, 3.2 GHz는 1초에 32억 번 진동한다는 뜻이다. 오늘날 CPU는 한 칩 안에 독립적으로 명령어를 실행하는 코어(core)를 여러 개 넣어, 서로 다른 프로그램이나 한 프로그램의 여러 작업을 동시에 처리한다.

## 명령어 세트

### 명령어 형식

명령어 세트(instruction set)는 CPU가 이해하는 명령어의 목록과 그 2진 형식이다. 같은 명령어 세트를 쓰는 CPU끼리는 ==같은 기계어 프로그램을 실행==할 수 있다. x86-64(Intel, AMD)와 ARM(Apple M 시리즈, 대부분의 스마트폰)이 대표적이다.

명령어는 연산 코드와 피연산자로 이루어진다.

| 필드              | 내용                                              | 예                     |
| ----------------- | ------------------------------------------------- | ---------------------- |
| 연산 코드(opcode) | 수행할 연산의 종류                                | ADD, LOAD, STORE, JUMP |
| 피연산자(operand) | 연산 대상. 값 자체, 레지스터 번호, 메모리 주소 등 | `R1`, `0x1000`, `#5`   |

연산 코드는 기능에 따라 네 가지로 나뉜다.

| 기능        | 하는 일                                           | x86 명령어 예              |
| ----------- | ------------------------------------------------- | -------------------------- |
| 연산 기능   | 산술 연산(덧셈, 곱셈)과 논리 연산(AND, XOR), 비교 | `ADD`, `SUB`, `AND`, `CMP` |
| 데이터 전달 | 레지스터와 메모리 사이, 레지스터끼리 값을 복사    | `MOV`, `PUSH`, `POP`       |
| 제어 기능   | 다음에 실행할 명령어의 위치(PC)를 바꾼다          | `JMP`, `JZ`, `CALL`, `RET` |
| 입출력 기능 | 입출력장치의 포트와 데이터를 주고받는다           | `IN`, `OUT`, `INSB`        |

피연산자 필드에는 연산에 쓸 값 자체(즉치값), 레지스터 번호, 메모리 주소가 들어간다. 그 값이 표현하는 것은 숫자, 문자 코드, 참·거짓 같은 논리 데이터, 또 다른 주소 등 다양하다. 비트열에 어떤 의미를 부여할지는 명령어가 정한다. 같은 4바이트라도 `ADD` 명령어에 쓰이면 정수이고, 부동소수점 덧셈 명령어에 쓰이면 IEEE 754 실수다.

CPU에게 연산 코드는 결국 숫자다. 다음 표는 x86 명령어 세트의 1바이트 연산 코드 일부로, 행과 열이 16진수 연산 코드의 앞 자리와 뒷 자리다. 예를 들어 `0x01`은 `ADD`, `0x50`은 `PUSH eAX`, `0x74`는 Zero 플래그가 1일 때 분기하는 `JZ`다.

![x86 1바이트 연산 코드 표의 일부: 00~05는 ADD, 28~2D는 SUB, 50~57은 PUSH, 58~5F는 POP, 70~7F는 조건 분기 명령어](./images/csintro-computer-architecture-x86-opcode.jpg 'Intel x86 Assembler Instruction Set Opcode Table (sparksandflames.com)')

실제 기계어 바이트를 보면 연산 코드와 피연산자가 어떻게 배치되는지 알 수 있다.

| 기계어(16진수)   | 어셈블리       | 구성                                                       |
| ---------------- | -------------- | ---------------------------------------------------------- |
| `01 D8`          | `add eax, ebx` | `01`이 연산 코드(ADD), `D8`이 두 레지스터(eax, ebx)를 지정 |
| `B8 05 00 00 00` | `mov eax, 5`   | `B8`이 "eax에 즉치값 저장", 뒤 4바이트가 값 5(리틀 엔디언) |
| `74 06`          | `jz +6`        | `74`가 JZ, `06`이 현재 위치에서 건너뛸 바이트 수           |
| `C3`             | `ret`          | 피연산자 없이 연산 코드만 있는 명령어                      |

x86은 명령어 길이가 1바이트부터 15바이트까지 가변적이고, ARM64와 RISC-V는 모든 명령어가 4바이트로 고정되어 있다. 고정 길이는 해독 회로가 단순해 여러 명령어를 동시에 해독하기 쉽다.

### 주소 필드 수에 따른 분류

명령어 하나에 피연산자 주소를 몇 개 적는지에 따라 명령어 형식을 나눈다. `X = A + B`를 계산하는 프로그램을 각 형식으로 쓰면 차이가 드러난다.

| 형식   | 사용하는 구조      | `X = A + B` 프로그램                    | 명령어 수 |
| ------ | ------------------ | --------------------------------------- | --------- |
| 0-주소 | 스택 구조          | `PUSH A` / `PUSH B` / `ADD` / `POP X`   | 4         |
| 1-주소 | 단일 누산기 구조   | `LOAD A` / `ADD B` / `STORE X`          | 3         |
| 2-주소 | 범용 레지스터 구조 | `MOV R1, A` / `ADD R1, B` / `MOV X, R1` | 3         |
| 3-주소 | 범용 레지스터 구조 | `ADD X, A, B`                           | 1         |

- 0-주소: 연산 코드만 있다. `ADD`는 스택 맨 위의 두 값을 꺼내(pop) 더한 결과를 다시 넣는다(push). Java 가상 머신과 WebAssembly가 이 방식의 바이트코드를 쓴다.
- 1-주소: 피연산자 하나는 항상 누산기(AC)다. `ADD B`는 `AC ← AC + B`를 뜻한다. 초기 컴퓨터와 단순한 마이크로컨트롤러가 이 방식이었다.
- 2-주소: 첫 피연산자가 입력이자 결과 저장 위치다. `ADD R1, B`는 `R1 ← R1 + B`다. x86이 이 형식이다.
- 3-주소: 두 입력과 결과 위치를 모두 적는다. 프로그램은 짧아지지만 명령어 하나의 길이가 길어진다. ARM과 RISC-V는 레지스터 3개를 지정하는 3-주소 형식을 쓰되, 메모리 접근은 LOAD·STORE 명령어로만 한다.

주소 필드가 적을수록 명령어 하나는 짧아지고, 같은 일을 하는 데 필요한 명령어 수는 늘어난다.

![주소 필드 수에 따른 명령어 형식: 0-주소는 연산 코드만, 1-주소는 연산 코드와 주소 1개, 2-주소는 주소 2개, 3-주소는 주소 3개를 갖는다. X = A + B에 필요한 명령어 수는 각각 4, 3, 3, 1개다](./images/csintro-computer-architecture-formats.svg '필드 길이는 비율을 나타낸 도식이다')

한 단계 복잡한 식으로 비교하면 차이가 더 분명하다. `X = (A + B) × C`를 0-주소(스택) 방식으로 계산하면 다음과 같다.

| 명령어   | 실행 후 스택(왼쪽이 바닥) |
| -------- | ------------------------- |
| `PUSH A` | A                         |
| `PUSH B` | A, B                      |
| `ADD`    | A+B                       |
| `PUSH C` | A+B, C                    |
| `MUL`    | (A+B)×C                   |
| `POP X`  | (비어 있음), X에 저장     |

같은 식을 3-주소 방식으로는 `ADD T, A, B`와 `MUL X, T, C` 두 명령어로 쓴다(T는 임시 위치). 스택 방식은 피연산자 위치를 적지 않아 명령어가 짧고 컴파일러가 코드를 만들기 쉬워서, 여러 종류의 CPU에서 같은 코드를 실행해야 하는 가상 머신 바이트코드에 쓰인다. 레지스터 방식은 자주 쓰는 값을 레지스터에 남겨 두고 재사용할 수 있어 실제 하드웨어 CPU에 쓰인다.

## 명령어 사이클

### 네 개의 부사이클

CPU가 명령어 하나를 메모리에서 가져와 실행을 마치기까지의 과정을 명령어 사이클(instruction cycle)이라고 한다. 인출 사이클과 실행 사이클은 모든 명령어에서 수행하고, 간접 사이클과 인터럽트 사이클은 조건이 맞을 때만 수행한다.

![명령어 사이클: 인출 사이클 다음에 간접 주소 지정이면 간접 사이클을 거쳐, 직접 주소 지정이면 바로 실행 사이클로 간다. 실행이 끝나면 인터럽트 요청이 있을 때 인터럽트 사이클을 수행하고 다음 명령어의 인출로 돌아간다](./images/csintro-computer-architecture-cycle.svg '실선 상자는 항상, 점선 상자는 조건에 따라 수행한다')

### 인출 사이클

메모리에서 명령어를 가져오는 단계다. 레지스터 사이의 데이터 이동을 ==마이크로 연산(micro-operation)==이라고 하며, 클록 한 주기(t)마다 하나 이상 수행된다.

![CPU 안의 PC, MAR, 제어장치, IR, MBR과 주기억장치 사이의 인출 사이클 순서. 1 PC 값을 MAR로, 2-ㄱ 주소 버스로 주소 전송, 2-ㄴ 데이터 버스로 명령어를 MBR에 수신, 3 PC 증가, 4 MBR의 명령어를 IR로 이동](./images/csintro-computer-architecture-fetch.jpg '인출 사이클의 동작 순서. 출처: 『컴퓨터 사이언스』(한빛아카데미) 그림 3-11')

| 시점 | 마이크로 연산                 | 설명                                              |
| ---- | ----------------------------- | ------------------------------------------------- |
| t0   | `MAR ← PC`                    | 다음 명령어 주소를 주소 버스로 보낸다             |
| t1   | `MBR ← M[MAR]`, `PC ← PC + 1` | 메모리가 명령어를 데이터 버스로 보내고, PC를 증가 |
| t2   | `IR ← MBR`                    | 명령어를 명령어 레지스터로 옮긴다                 |

PC는 인출 직후 증가하므로, 실행 단계에서 분기 명령어가 PC를 바꾸지 않는 한 다음 사이클은 바로 다음 명령어를 인출한다. (PC + 1은 명령어 하나가 주소 하나를 차지한다고 가정한 표기이고, 실제로는 명령어 길이만큼 증가한다.)

### 실행 사이클

제어장치가 IR의 연산 코드를 해독(decode)하고, 그에 맞는 제어 신호를 내보내 실행한다. 1-주소 명령어 `ADD B`라면 다음과 같다.

| 시점 | 마이크로 연산         | 설명                            |
| ---- | --------------------- | ------------------------------- |
| t0   | `MAR ← IR(주소 필드)` | 피연산자 B의 주소를 주소 버스로 |
| t1   | `MBR ← M[MAR]`        | B의 값을 읽는다                 |
| t2   | `AC ← AC + MBR`       | ALU가 더해 누산기에 저장한다    |

분기 명령어 `JUMP 300`이라면 실행 사이클에서 `PC ← 300`만 수행하고, 다음 인출 사이클은 300번지에서 명령어를 가져온다. 조건 분기는 상태 플래그를 확인해 PC를 바꿀지 결정한다.

### 간접 사이클

명령어의 주소 필드가 피연산자의 주소를 직접 담고 있으면(직접 주소 지정) 간접 사이클은 필요 없다. 주소 필드가 "피연산자의 주소가 저장된 곳의 주소"를 담고 있으면(간접 주소 지정), 실행 전에 ==메모리를 한 번 더 읽어 실제 주소를 얻는다==.

| 시점 | 마이크로 연산         | 설명                                         |
| ---- | --------------------- | -------------------------------------------- |
| t0   | `MAR ← IR(주소 필드)` | 주소 필드의 값(포인터의 위치)을 보낸다       |
| t1   | `MBR ← M[MAR]`        | 그 위치에 저장된 실제 피연산자 주소를 읽는다 |
| t2   | `IR(주소 필드) ← MBR` | 주소 필드를 실제 주소로 바꾼다               |

![직접 주소 지정은 LOAD 200이 200번지의 값 7을 한 번에 읽는다. 간접 주소 지정은 LOAD @200이 200번지에서 주소 500을 읽고, 간접 사이클로 500번지의 값 9를 다시 읽는다](./images/csintro-computer-architecture-addressing.svg '간접 주소 지정은 메모리를 한 번 더 읽는다')

C 언어의 포인터 역참조 `*p`가 같은 개념이다. 변수 p에는 데이터 자체가 아니라 데이터가 있는 주소가 들어 있다.

```c
int value = 9;      /* 500번지에 저장되었다고 가정 */
int *p = &value;    /* p(200번지)에는 500이 저장된다 */
int a = value;      /* 직접: 500번지를 한 번 읽는다 */
int b = *p;         /* 간접: 200번지에서 500을 읽고, 500번지를 다시 읽는다 */
```

간접 주소 지정을 쓰면 주소 필드의 비트 수가 적어도 메모리 전체를 가리킬 수 있고, 프로그램 실행 중에 가리키는 대상을 바꿀 수 있다. 연결 리스트, 함수 포인터, 동적 할당한 메모리가 모두 이 방식에 기대고 있다. 대가로 메모리 접근이 한 번 늘어난다.

### 인터럽트 사이클

인터럽트(interrupt)는 CPU가 프로그램을 실행하는 도중 ==처리해야 할 사건이 생겼음을 알리는 신호==다. 키보드 입력, 디스크 읽기 완료, 타이머 만료 같은 외부 사건과, 0으로 나누기나 잘못된 메모리 접근 같은 내부 사건(예외)이 있다.

인터럽트가 없다면 CPU는 키가 눌렸는지 계속 확인(폴링)해야 하므로, 사람이 키를 누르지 않는 동안에도 CPU 시간을 낭비한다. 인터럽트 방식에서는 장치가 필요한 시각에 제어 버스로 인터럽트 요청을 보내고, CPU는 그동안 다른 일을 한다.

CPU는 실행 사이클이 끝날 때마다 인터럽트 요청이 있는지 확인하고, 있으면 다음을 수행한다.

1. 현재 PC 값(돌아올 주소)을 스택에 저장한다: `MBR ← PC`, `MAR ← SP`, `M[MAR] ← MBR`
2. PC에 인터럽트 처리 루틴(ISR)의 시작 주소를 넣는다.
3. 다음 인출 사이클은 ISR의 첫 명령어를 가져온다. ISR이 끝나면 저장한 PC를 복원해 원래 프로그램으로 돌아간다.

![인터럽트 처리 과정: 0x404의 STORE 실행 중 키보드 인터럽트가 오면 다음 주소 0x408을 스택에 저장하고 인터럽트 처리 루틴으로 이동한다. 루틴이 끝나면 스택에서 PC를 복원해 0x408의 LOAD부터 이어서 실행한다](./images/csintro-computer-architecture-interrupt.svg '돌아올 주소를 스택에 저장해 두기 때문에 원래 프로그램은 중단 사실을 알지 못한다')

인터럽트는 발생 원인에 따라 나뉜다.

| 종류                    | 원인                                           | 예                                                          |
| ----------------------- | ---------------------------------------------- | ----------------------------------------------------------- |
| 외부 인터럽트(하드웨어) | CPU 밖의 장치가 제어 버스로 요청               | 키 입력, 마우스 이동, 디스크 읽기 완료, 타이머, 정전 감지   |
| 내부 인터럽트(예외)     | 실행 중인 명령어 자체가 정상적으로 끝나지 못함 | 0으로 나누기, 허용되지 않은 메모리 접근, 잘못된 연산 코드   |
| 소프트웨어 인터럽트     | 프로그램이 일부러 발생시키는 명령어            | 운영체제 기능을 요청하는 시스템 호출(`syscall`, `int 0x80`) |

여러 인터럽트가 동시에 들어오면 우선순위가 높은 것부터 처리한다. 정전 감지처럼 미룰 수 없는 사건은 가장 높은 우선순위를 받고, 처리 도중에 들어온 낮은 우선순위의 요청은 대기한다.

운영체제가 여러 프로그램을 번갈아 실행하는 것도 타이머 인터럽트로 일정 시간마다 CPU 제어권을 가져오기 때문에 가능하다. 운영체제의 프로세스 관리와 CPU 스케줄링이 이 위에서 동작한다. 소프트웨어 인터럽트는 보안 경계이기도 하다. 일반 프로그램은 하드웨어를 직접 조작할 권한이 없고, 시스템 호출로 CPU를 커널 모드로 전환해 운영체제에게 대신 처리하도록 요청한다.

### 파이프라이닝

위 설명은 명령어 하나를 끝낸 뒤 다음 명령어를 시작하는 방식이다. 인출 회로, 해독 회로, 연산 회로는 서로 다른 부품이므로, ==명령어 1이 실행되는 동안 명령어 2를 해독하고 명령어 3을 인출==할 수 있다. 이를 파이프라이닝(pipelining)이라고 한다.

![3단계 파이프라인: 클록 1에 명령어 1 인출, 클록 2에 명령어 1 해독과 명령어 2 인출, 클록 3에 세 명령어가 각각 실행·해독·인출 단계에 있다](./images/csintro-computer-architecture-pipeline.svg '단계마다 1클록이 걸린다고 가정했다')

단계가 k개이고 명령어가 n개일 때 걸리는 클록 수는 다음과 같다.

```math
\text{파이프라인 없음} = k \times n, \qquad \text{파이프라인} = k + (n - 1)
```

| k(단계) | n(명령어) | 파이프라인 없음 | 파이프라인 | 속도 향상 |
| ------- | --------- | --------------- | ---------- | --------- |
| 3       | 3         | 9클록           | 5클록      | 1.8배     |
| 3       | 100       | 300클록         | 102클록    | 약 2.9배  |
| 5       | 1,000     | 5,000클록       | 1,004클록  | 약 5배    |

명령어가 많아질수록 속도 향상은 단계 수 k에 가까워진다. 다만 분기 명령어를 만나면 다음에 인출할 주소를 실행이 끝나기 전에는 알 수 없다. 현대 CPU는 분기 방향을 예측해 미리 실행하고(투기적 실행), 예측이 틀리면 결과를 버린다. Spectre 취약점은 버린 결과가 캐시에 남긴 흔적을 측정해 접근 권한이 없는 메모리 값을 알아내는 공격이다.

## 기억장치

### 계층 구조

빠른 기억장치일수록 바이트당 가격이 비싸므로 큰 용량을 만들기 어렵다. 그래서 컴퓨터는 ==빠르고 작은 기억장치부터 느리고 큰 기억장치까지== 여러 단계를 계층으로 쌓는다.

![레지스터, 캐시 메모리, 주기억장치, 보조기억장치를 쌓은 계층 구조와, 위로 갈수록 접근 속도가 빨라지고 저장 비용이 오르며 기억 용량이 줄어든다는 설명. 아래는 레지스터와 캐시, 주기억장치, 보조기억장치 사이의 데이터 흐름](./images/csintro-computer-architecture-hierarchy.jpg '기억장치의 계층 구조와 데이터 흐름. 출처: 『컴퓨터 사이언스』(한빛아카데미) 그림 3-14, 3-15')

아래쪽 흐름도에서 보듯 ==CPU는 보조기억장치를 직접 읽지 않는다==. 디스크의 데이터는 먼저 주기억장치로 올라오고, 그중 자주 쓰는 부분이 캐시로, 연산에 쓰는 값이 레지스터로 옮겨진다.

![기억장치 계층 구조: 위에서부터 레지스터(1 ns 미만, 수백 바이트~수 KB), 캐시 SRAM(약 1~10 ns, 수십 KB~수십 MB), 주기억장치 DRAM(약 50~100 ns, 수~수백 GB), 보조기억장치 SSD·HDD(SSD 수십 μs, HDD 수 ms, TB 단위). 위로 갈수록 빠르고 비싸며 용량이 작다](./images/csintro-computer-architecture-hierarchy.svg '수치는 대략적인 크기 단위다')

계층 구조가 효과적인 이유는 지역성(locality) 때문이다. 프로그램은 짧은 시간 동안 메모리의 일부분만 집중적으로 접근한다.

- 시간 지역성: 최근 접근한 데이터를 곧 다시 접근한다. 반복문의 카운터 변수가 예다.
- 공간 지역성: 접근한 주소 근처를 곧 접근한다. 배열을 처음부터 순서대로 읽는 경우가 예다.

자주 쓰는 데이터를 위 계층에 복사해 두면, 대부분의 접근은 빠른 계층에서 끝난다. 데이터의 흐름은 보조기억장치 → 주기억장치 → 캐시 → 레지스터 순이며, CPU는 보조기억장치에 직접 접근하지 않는다. 프로그램을 실행하면 운영체제가 실행 파일을 SSD에서 RAM으로 적재하는 이유다.

### 주기억장치: RAM과 ROM

RAM(Random Access Memory)은 ==주소와 관계없이 일정한 시간에 읽고 쓸 수 있는== 메모리다. ==전원이 꺼지면 내용이 사라지는 휘발성 메모리==다. 초기 컴퓨터는 자성체 고리에 정보를 저장하는 자기 코어 메모리를 썼고, 1970년대부터 반도체 메모리로 바뀌었다.

| 구분        | DRAM(Dynamic RAM)                                         | SRAM(Static RAM)                         |
| ----------- | --------------------------------------------------------- | ---------------------------------------- |
| 기억 소자   | 트랜지스터 1개 + 커패시터 1개                             | 트랜지스터 6개로 구성한 플립플롭         |
| 저장 원리   | 커패시터에 충전된 전하의 유무                             | 플립플롭의 두 안정 상태                  |
| 재충전      | 전하가 누설되므로 수십 ms마다 주기적 재충전(refresh) 필요 | 전원이 공급되는 동안 유지, 재충전 불필요 |
| 속도        | 상대적으로 느림(수십 ns)                                  | 빠름(수 ns 이하)                         |
| 집적도·가격 | 셀이 작아 집적도가 높고 저렴                              | 셀이 커서 집적도가 낮고 비쌈             |
| 용도        | 주기억장치(DDR4, DDR5 메모리 모듈)                        | CPU 내부 캐시 메모리                     |

![DRAM 셀은 트랜지스터 1개와 커패시터 1개로, 커패시터의 전하로 비트를 저장한다. SRAM 셀은 서로의 출력을 입력으로 받는 인버터 2개(트랜지스터 4개)와 접근용 트랜지스터 2개로 구성된다](./images/csintro-computer-architecture-dram-sram.svg '셀 구조를 단순화한 도식이다')

DRAM의 커패시터는 아주 작은 전하를 담고 있어서 시간이 지나면 전하가 새어 나간다. 그래서 메모리 컨트롤러는 JEDEC 표준 기준으로 64 ms(고온에서는 32 ms) 안에 모든 행을 한 번씩 읽고 다시 써서 전하를 채운다. 이를 재충전(refresh)이라고 하고, 이름의 Dynamic이 이 동작을 가리킨다. SRAM은 두 인버터가 서로의 출력을 붙잡고 있어 전원만 있으면 상태가 유지되므로 Static이라고 부른다. 셀 하나에 트랜지스터가 6개 필요하므로 같은 면적에 DRAM보다 훨씬 적은 비트를 저장한다. 그래서 수 GB가 필요한 주기억장치는 DRAM으로, 수 MB면 되지만 빨라야 하는 캐시는 SRAM으로 만든다.

ROM(Read Only Memory)은 전원이 없어도 내용이 유지되는 비휘발성 메모리로, 컴퓨터를 켤 때 처음 실행되는 펌웨어(BIOS, UEFI)를 저장한다.

| 종류       | 기록 방법                                               |
| ---------- | ------------------------------------------------------- |
| 마스크 ROM | 제조 공정에서 내용을 기록. 변경 불가                    |
| PROM       | 사용자가 한 번만 기록(퓨즈를 끊는 방식)                 |
| EPROM      | 자외선을 쬐어 전체 삭제 후 다시 기록                    |
| EEPROM     | 전기 신호로 바이트 단위 삭제·기록. 플래시 메모리의 기반 |

컴퓨터 전원을 켜면 RAM은 비어 있으므로, CPU는 ROM(오늘날은 플래시 메모리)의 정해진 주소에서 첫 명령어를 인출한다. 펌웨어가 메모리와 장치를 점검하고, 보조기억장치에서 부트로더를 RAM으로 적재하고, 부트로더가 운영체제 커널을 적재한다. 비휘발성 메모리가 이 시작 과정의 출발점이다.

오늘날 메인보드의 펌웨어는 플래시 메모리에 저장되어 업데이트할 수 있다. 업데이트가 가능하다는 것은 공격자가 악성 펌웨어를 기록할 수도 있다는 뜻이어서, UEFI 보안 부팅(Secure Boot)은 서명이 검증된 펌웨어와 부트로더만 실행한다.

DRAM은 공격 대상이 되기도 한다. 행 하나를 매우 빠르게 반복해서 읽으면 인접한 행의 커패시터 전하가 영향을 받아 비트가 뒤집히는 현상을 로해머(Rowhammer)라고 하며, 이를 이용해 커널 메모리의 권한 비트를 바꾸는 공격이 시연되었다.

![마스크 ROM, PROM, EPROM, EEPROM 칩 사진. EPROM은 자외선으로 내용을 지우는 투명 창이 있다](./images/csintro-computer-architecture-rom.jpg 'ROM의 종류. 출처: 『컴퓨터 사이언스』(한빛아카데미) 그림 3-18')

| 종류       | 기록 방법                       | 지우기                            | 쓰임                       |
| ---------- | ------------------------------- | --------------------------------- | -------------------------- |
| 마스크 ROM | 제조 공정에서 회로로 기록       | 불가                              | 대량 생산 게임 카트리지    |
| PROM       | 사용자가 퓨즈를 끊어 한 번 기록 | 불가                              | 소량 생산 펌웨어           |
| EPROM      | 전기로 기록                     | 칩의 창에 자외선을 쬐어 전체 삭제 | 개발 중인 펌웨어           |
| EEPROM     | 전기로 기록                     | 전기로 바이트 단위 삭제           | 설정값 저장, 플래시의 원형 |

### 캐시 메모리

캐시(cache)는 CPU와 주기억장치 사이에 두는 SRAM 기억장치다. CPU가 데이터를 요청하면 먼저 캐시를 확인하고, 있으면(캐시 적중, hit) 수 ns 안에 가져오고, 없으면(캐시 실패, miss) 주기억장치에서 가져오면서 ==그 주변 데이터(캐시 라인, 보통 64바이트)를 함께 캐시에 복사==한다.

![캐시 적중과 실패: CPU의 요청을 캐시가 바로 처리하면 약 1 ns, 캐시에 없으면 주기억장치에서 64바이트 라인을 복사해 오느라 약 100 ns가 걸린다](./images/csintro-computer-architecture-cache.svg '접근 시간은 대략적인 크기 단위다')

현대 CPU는 캐시를 여러 단계로 둔다.

| 단계 | 위치                         | 크기(예)      | 접근 시간(예) |
| ---- | ---------------------------- | ------------- | ------------- |
| L1   | 코어마다, 명령어·데이터 분리 | 수십 KB       | 약 1 ns       |
| L2   | 코어마다                     | 수백 KB~수 MB | 약 3~5 ns     |
| L3   | 여러 코어가 공유             | 수 MB~수십 MB | 약 10~20 ns   |

평균 접근 시간은 적중률에 크게 좌우된다. 캐시 접근 시간이 1 ns, 주기억장치 접근 시간이 100 ns일 때를 계산하면 다음과 같다.

| 적중률 | 평균 접근 시간 계산                            | 결과  |
| ------ | ---------------------------------------------- | ----- |
| 90%    | `0.9 \times 1 + 0.1 \times (1 + 100){:math}`   | 11 ns |
| 99%    | `0.99 \times 1 + 0.01 \times (1 + 100){:math}` | 2 ns  |

적중률이 9%p 오르면 평균 접근 시간이 5분의 1 이하로 줄어든다. 같은 계산이라도 배열을 메모리 순서대로 읽는 코드가 무작위로 읽는 코드보다 빠른 이유다.

C의 2차원 배열은 행 단위로 메모리에 연속 저장된다. 다음 두 함수는 같은 합을 계산하지만, 메모리 접근 순서가 다르다.

```c
#define N 4096
static int a[N][N];

long sum_rows(void) {          /* a[0][0], a[0][1], a[0][2] ... 연속 주소 */
	long s = 0;
	for (int i = 0; i < N; i++)
		for (int j = 0; j < N; j++)
			s += a[i][j];
	return s;
}

long sum_cols(void) {          /* a[0][0], a[1][0], a[2][0] ... 16 KiB씩 건너뜀 */
	long s = 0;
	for (int j = 0; j < N; j++)
		for (int i = 0; i < N; i++)
			s += a[i][j];
	return s;
}
```

`sum_rows`는 캐시 라인 하나(64바이트)를 가져오면 그 안의 int 16개를 연속으로 쓰므로 16번에 1번만 캐시 실패가 난다. `sum_cols`는 매번 4096 × 4 = 16,384바이트 떨어진 주소를 읽어 거의 모든 접근이 실패한다. 일반적인 노트북에서 `sum_cols`가 몇 배에서 열 배 이상 느리게 측정된다. 정확한 배수는 CPU의 캐시 크기와 하드웨어 프리페치 동작에 따라 다르다.

캐시가 주기억장치의 어느 위치를 어느 캐시 칸에 저장할지 정하는 방식을 사상(mapping)이라고 한다. 주소마다 들어갈 칸이 하나로 정해진 직접 사상, 아무 칸에나 들어갈 수 있는 완전 연관 사상, 그 중간인 집합 연관 사상이 있고, 현대 CPU의 L1·L2 캐시는 대부분 8~16방향 집합 연관 방식이다.

### 보조기억장치

보조기억장치는 ==전원과 관계없이 데이터를 영구 보관==하는 대용량 저장장치다. 접근 방식에 따라 나뉜다.

| 장치               | 접근 방식 | 원리                                                            | 특징                                     |
| ------------------ | --------- | --------------------------------------------------------------- | ---------------------------------------- |
| 자기 테이프        | 순차 접근 | 긴 테이프의 자성 방향으로 기록. 원하는 위치까지 감아야 한다     | 용량당 가격이 가장 낮아 장기 백업·보관용 |
| HDD(자기 디스크)   | 직접 접근 | 회전하는 자성 원판 위로 헤드가 이동해 읽고 쓴다                 | 헤드 이동과 회전 대기로 수 ms가 걸린다   |
| 광 디스크          | 직접 접근 | 레이저로 원판 표면의 미세한 홈(pit)을 읽는다. CD, DVD, 블루레이 | 배포용 매체                              |
| SSD(플래시 메모리) | 직접 접근 | 플로팅 게이트 등에 전하를 가두는 비휘발성 반도체 메모리         | 기계 부품이 없어 빠르고 충격에 강하다    |

순차 접근과 직접 접근의 차이는 원하는 데이터까지 가는 방법에 있다. 테이프에서 1,000번째 기록을 읽으려면 앞의 999개를 지나가도록 테이프를 감아야 한다. 디스크는 헤드를 해당 트랙으로 옮기고 원판이 해당 섹터를 헤드 아래로 가져올 때까지 기다리면 되므로, 앞의 데이터를 거치지 않고 위치에 바로 접근한다.

![플로피디스크와 하드디스크 사진, 자기 디스크의 구조: 여러 장의 플래터가 축에 겹쳐 있고, 플래터 표면은 동심원 트랙으로, 트랙은 다시 부채꼴 섹터로 나뉜다. 여러 플래터에서 같은 반지름의 트랙을 묶은 것이 실린더다](./images/csintro-computer-architecture-disk.jpg '출처: 『컴퓨터 사이언스: 새내기를 위한 최신 컴퓨터 개론』(한빛아카데미) 그림 3-23, 3-24')

HDD 표면은 동심원 모양의 트랙(track)으로, 트랙은 다시 섹터(sector, 보통 512바이트 또는 4 KiB)로 나뉜다. 여러 장의 원판(플래터)에서 같은 반지름의 트랙을 묶어 실린더(cylinder)라고 한다. HDD에서 데이터 하나를 읽는 시간은 세 부분의 합이다.

| 구성                          | 뜻                                              | 7,200 RPM HDD의 예                       |
| ----------------------------- | ----------------------------------------------- | ---------------------------------------- |
| 탐색 시간(seek time)          | 헤드를 목표 트랙으로 옮기는 시간                | 평균 약 9 ms                             |
| 회전 지연(rotational latency) | 목표 섹터가 헤드 아래로 올 때까지 기다리는 시간 | 반 바퀴 평균: 60 s ÷ 7,200 ÷ 2 ≈ 4.17 ms |
| 전송 시간(transfer time)      | 섹터의 데이터를 읽어 내는 시간                  | 4 KiB 기준 0.1 ms 미만                   |

합치면 무작위 위치의 4 KiB를 읽는 데 약 13 ms가 걸린다. 같은 작업을 NVMe SSD는 약 0.1 ms 안에 끝내므로 100배 이상 빠르다. 연속된 위치를 읽을 때는 탐색과 회전 지연이 한 번만 들므로 HDD도 초당 200 MB 안팎의 전송량을 낸다. HDD에서는 흩어진 파일 조각을 연속된 위치로 재배치하는 조각 모음이 성능을 높이지만, SSD에서는 효과가 없는 이유가 이 차이다.

광 디스크는 기록면의 홈과 평면이 레이저를 반사하는 정도가 다른 점을 이용한다. CD는 780 nm 적외선 레이저로 약 700 MB, DVD는 650 nm 적색 레이저로 한 면 한 층에 4.7 GB, 블루레이는 405 nm 청자색 레이저로 한 층에 25 GB를 저장한다. 파장이 짧을수록 레이저 점을 작게 모을 수 있어 같은 면적에 더 많은 홈을 기록한다.

플래시 메모리는 셀 구성에 따라 NAND형과 NOR형으로 나뉜다. NAND형은 집적도가 높아 SSD와 USB 메모리처럼 대용량 데이터 저장에 쓰이고, NOR형은 바이트 단위로 빠르게 읽을 수 있어 펌웨어 같은 코드 저장에 쓰인다.

> [!WARNING] 삭제한 파일과 SSD
> 운영체제에서 파일을 삭제하면 보통 파일 시스템의 목록에서 항목만 지우고 데이터 자체는 남는다. HDD는 그 위치를 덮어쓰면 복구가 어렵지만, SSD는 수명 관리를 위해 쓰기를 다른 셀에 분산(웨어 레벨링)하므로 같은 파일을 덮어써도 원래 셀이 남을 수 있다. 저장장치를 폐기할 때는 제조사의 보안 삭제(Secure Erase) 기능이나 전체 디스크 암호화 후 키 폐기를 쓴다.

### 디스플레이 방식의 변화

![CRT 모니터의 원리 그림과 측면 사진. 음극 히터에서 나온 전자총의 전자 빔을 편향요크가 휘어 형광물질이 코팅된 화면에 쏘면 가시광선이 나온다](./images/csintro-computer-architecture-crt.jpg 'CRT 모니터의 원리. 출처: 『컴퓨터 사이언스』(한빛아카데미) 그림 3-34')

CRT는 ==전자 빔이 화면을 한 줄씩 훑으며 형광체를 발광시키는== 방식이라, 화면이 클수록 브라운관이 길고 무거워진다. 평판 디스플레이(LCD, PDP, OLED)가 이를 대체한 이유다.

모니터는 화면을 만드는 원리에 따라 다음처럼 바뀌어 왔다.

| 방식 | 원리                                                                        | 특징                                                       |
| ---- | --------------------------------------------------------------------------- | ---------------------------------------------------------- |
| CRT  | 전자총이 쏜 전자빔을 자기장으로 휘어 형광면을 한 줄씩 훑으며 빛나게 한다    | 두껍고 무겁다. 2000년대 중반 이후 LCD로 대체               |
| PDP  | 작은 셀에 가둔 기체를 방전시켜 나오는 자외선으로 형광체를 발광시킨다        | 대형 TV에 쓰였으나 전력 소비가 커서 2014년 무렵 생산 종료  |
| LCD  | 백라이트의 빛을 액정 분자의 배열과 편광 필터로 픽셀마다 통과시키거나 막는다 | 얇고 가볍다. 액정 자체는 빛을 내지 않는다                  |
| OLED | 유기 화합물에 전류를 흘리면 스스로 빛을 낸다                                | 백라이트가 없어 검은색이 완전히 꺼지고, 휘어지는 화면 가능 |

### 프린터의 분류

프린터는 종이에 물리적인 충격을 가하는지에 따라 나뉜다.

| 분류     | 방식          | 원리                                                          | 쓰임                                     |
| -------- | ------------- | ------------------------------------------------------------- | ---------------------------------------- |
| 충격식   | 도트 매트릭스 | 핀으로 잉크 리본을 종이에 때려 점을 찍는다                    | 여러 장 겹친 복사 용지 인쇄, 일부 영수증 |
| 비충격식 | 잉크젯        | 노즐에서 미세한 잉크 방울을 분사한다                          | 가정용 사진·문서 인쇄                    |
| 비충격식 | 레이저        | 레이저로 감광 드럼에 정전기 상을 만들고 토너를 붙여 열로 정착 | 사무실 대량 문서 인쇄                    |
| 비충격식 | 감열식        | 열에 반응해 색이 변하는 종이에 열을 가한다                    | 카드 결제 영수증                         |

3D 프린터는 3차원 설계 데이터(CAD)를 얇은 수평 층으로 나눈 뒤, 녹인 플라스틱을 노즐로 쌓거나(FDM) 액체 수지를 빛으로 굳히는(SLA) 방식으로 한 층씩 적층해 입체물을 만든다. 금형 없이 시제품을 만들 수 있어 제품 설계, 의료용 보형물, 건축 모형 제작에 쓰인다. 플로터는 펜이나 잉크 헤드를 움직여 건축·기계 도면처럼 큰 종이에 선을 정밀하게 그리는 출력장치이고, 햅틱 인터페이스는 진동이나 저항력으로 사용자에게 촉각을 전달하는 장치다. 게임 패드의 진동, 스마트폰 화면을 누를 때의 미세한 진동이 예다.

### CPU와 입출력장치의 데이터 교환

입출력장치는 CPU보다 훨씬 느리다. 사람이 1초에 키를 10번 누른다면, 3 GHz CPU는 키 입력 사이에 약 3억 클록을 보낸다. 그래서 ==CPU가 입출력을 기다리는 방식==이 중요하다.

| 방식                      | 동작                                                                             | 장단점                                                        |
| ------------------------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 프로그램 입출력(폴링)     | CPU가 장치의 상태 레지스터를 반복해서 읽어 준비되었는지 확인                     | 구현이 단순하지만 기다리는 동안 CPU가 다른 일을 못 한다       |
| 인터럽트 구동 입출력      | 장치가 준비되면 인터럽트로 알린다                                                | CPU가 그동안 다른 일을 한다. 데이터 이동은 여전히 CPU가 한다  |
| DMA(Direct Memory Access) | DMA 컨트롤러가 장치와 메모리 사이에서 블록 단위로 직접 전송하고, 끝나면 인터럽트 | 대량 전송에서 CPU 부담이 거의 없다. SSD, 네트워크 카드가 사용 |

예를 들어 SSD에서 1 MB 파일을 읽을 때 인터럽트 구동 방식이면 CPU가 몇 바이트씩 수십만 번 옮겨야 하지만, DMA 방식이면 CPU는 "이 주소에서 1 MB를 읽어 RAM의 이 위치에 써라"라고 한 번 지시하고 완료 인터럽트 한 번만 받는다.

입력장치도 공격 경로가 된다. USB 장치가 키보드인 것처럼 자신을 등록하고 미리 입력된 명령어를 빠르게 타이핑하는 공격(BadUSB 계열)이 있어, 출처를 모르는 USB 장치를 연결하지 않는 것이 기본 보안 수칙이다.

## 직접 해 보기

### 내 컴퓨터의 CPU와 캐시 확인하기

이 글의 수치를 실제 기기에서 확인할 수 있다.

```bash
# macOS
sysctl -n machdep.cpu.brand_string      # CPU 모델
sysctl hw.ncpu hw.l1dcachesize hw.l2cachesize hw.cachelinesize
# Linux
lscpu | grep -E 'Model name|L1d|L2|L3'
getconf LEVEL1_DCACHE_LINESIZE          # 캐시 라인 크기, 보통 64
```

Apple M 계열 Mac에서는 `hw.cachelinesize`가 128로 나온다. 캐시 라인 크기가 64바이트로 고정된 것은 아니고 CPU 설계마다 다르다는 뜻이다.

### 기계어 확인하기

C 코드를 컴파일한 결과를 어셈블리와 기계어 바이트로 확인할 수 있다.

```c
/* add.c */
int add(int a, int b) { return a + b; }
```

```bash
cc -O1 -c add.c -o add.o
objdump -d add.o            # Linux. macOS에서는 otool -tv add.o
```

x86-64 Linux에서의 출력은 대략 다음과 같다.

```text
0000000000000000 <add>:
   0:	8d 04 37             	lea    (%rdi,%rsi,1),%eax
   3:	c3                   	ret
```

`a`와 `b`는 함수 호출 규약에 따라 레지스터 rdi, rsi로 전달되고, 결과는 eax에 담겨 돌아간다. 메모리 접근 없이 레지스터만으로 계산이 끝난다. 왼쪽 숫자는 명령어의 주소(오프셋), 가운데가 기계어 바이트, 오른쪽이 어셈블리다.

## 정리

- 폰 노이만 구조는 CPU, 주기억장치, 입출력장치가 시스템 버스로 연결되고, 명령어와 데이터를 같은 메모리에 저장한다. 같은 버스를 공유하므로 폰 노이만 병목이 생긴다.
- 시스템 버스는 주소(어디를), 데이터(무엇을), 제어(읽기·쓰기 등 어떻게)로 나뉜다.
- CPU는 제어장치, ALU, 레지스터로 이루어지며, PC는 다음 명령어의 주소를, IR은 현재 명령어를, MAR과 MBR은 메모리와 주고받는 주소와 데이터를 보관한다.
- 명령어 사이클은 인출과 실행을 항상, 간접과 인터럽트를 조건에 따라 수행한다.
- 기억장치는 레지스터, 캐시(SRAM), 주기억장치(DRAM), 보조기억장치 순으로 느리고 커지며, 지역성 덕분에 대부분의 접근이 빠른 계층에서 끝난다.
