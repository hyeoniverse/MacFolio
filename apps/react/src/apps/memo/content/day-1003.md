이날 커밋은 30개다. 가장 중요한 변경은 화면에 보이지 않는다. 그전까지는 시험(`check`)이 실패해도 사이트에 배포될 수 있었다. Cloudflare가 시험과 관계없이 같은 코드를 별도로 빌드해 배포했기 때문이다. 이날부터는 **시험을 통과한 커밋만 배포**된다.

그 밖의 작업은 시스템 설정, GitHub 앱, Finder와 프로젝트 앱이다. 이 글은 시간 순이 아니라 주제별로 정리했다.

## 배포: 시험을 통과한 커밋만

### 문제

PR #80의 `Workers Builds: macfolio` 검사가 실패했다. 로그에는 `Initializing build environment...`가 5분 간격으로 두 번 기록된 뒤 `Build failed to initialize and was timed out`만 남아 있었다. 처음에는 빌드 한도를 초과했다고 판단했지만, 대시보드의 사용량을 확인해 보니 이번 달 빌드 시간은 3,000분 중 150분이었다. 한도 문제가 아니라 Cloudflare 측 빌드 환경이 시작되지 않은 것이다.

![Cloudflare Workers 사용량](./images/day-1003-workers-usage.jpg '빌드 실패 시각에 확인한 Workers 사용량. 빌드 시간 150/3,000분으로 한도와 관계없었다')

### 원인: 시험과 배포가 서로 독립적

빌드 실패 상태로 머지해도 되는지 검토하다가 더 큰 구조 문제를 확인했다. 시험(GitHub Actions)과 배포(Cloudflare Workers Builds)가 서로 독립적으로 실행되고 있었다.

| 항목               | 변경 전 (Cloudflare Git 연결)    | 변경 후 (GitHub Actions)                   |
| ------------------ | -------------------------------- | ------------------------------------------ |
| 빌드 실행 위치     | Cloudflare 빌드 서버             | GitHub Actions                             |
| 시험과의 관계      | 시험 결과와 관계없이 빌드·배포   | 배포 작업은 시험 작업이 통과한 뒤에만 실행 |
| 시험이 실패한 커밋 | 배포될 수 있음                   | 배포되지 않음                              |
| 빌드 환경 장애     | Cloudflare 빌드 서버 상태에 의존 | GitHub Actions 러너에서 빌드               |

### 조치

배포를 GitHub Actions로 이전했다([Workers Builds 대신 GitHub Actions와 wrangler로 시험을 통과한 커밋만 배포하기](/memo/deploy-github-actions), [#82](https://github.com/hyeoniverse/MacFolio/pull/82)).

1. 배포용 Cloudflare API 토큰을 기존 토큰과 별도로 새로 발급해 저장소 시크릿에 저장했다
2. Cloudflare의 Git 연결을 해제(Disconnect)했다
3. 배포 작업이 시험 작업 뒤에만 실행되도록 워크플로를 구성했다

절차는 [Cloudflare의 GitHub Actions 배포 문서](https://developers.cloudflare.com/workers/ci-cd/external-cicd/github-actions/)와 저장소의 [.github/workflows](https://github.com/hyeoniverse/MacFolio/tree/main/.github/workflows)에 있다. 같은 날 conventions 검사에 "Node.js 20 is deprecated" 경고가 표시되어, 액션 버전을 Node 24로 올리는 PR도 별도로 제출했다([#83](https://github.com/hyeoniverse/MacFolio/pull/83)).

이틀 뒤 API 자동 배포도 같은 방식으로 구성했다. 백엔드 설계도 이날 한 장으로 정리했다([요청 계층과 위험별 설계 결정으로 정리한 MacFolio 백엔드 구성도](/memo/backend-design), [#84](https://github.com/hyeoniverse/MacFolio/pull/84)).

## GitHub 앱: 서버에서 받은 실제 프로필

GitHub 앱이 서버가 받아 온 프로필과 README를 표시하고, 표시할 저장소는 시스템 설정에서 선택하게 했다([API 서버에서 GitHub API 응답을 캐시해 프로필을 실시간 조회하기](/memo/github-live-profile)). 9월 29일에 등록한 이슈 [#34](https://github.com/hyeoniverse/MacFolio/issues/34)의 작업이다.

공개 저장소이므로 다른 사람이 GitHub를 연결하지 않고 사용하는 경우도 고려했다. 서버가 없으면 `.ts` 파일에 기록한 기본값을 사용한다.

### 서버 반영 시의 시행착오

새 기능을 서버에 반영할 때 오류가 연달아 발생했다. 홈 폴더에서 안내대로 `pg_dump`, `git pull`, `docker compose up`을 실행했더니 다음 오류가 순서대로 표시되었다.

| 명령                | 오류                | 원인                                                      |
| ------------------- | ------------------- | --------------------------------------------------------- |
| `pg_dump`           | 명령을 찾을 수 없음 | 서버 호스트에는 `pg_dump`가 없고, DB 컨테이너 안에만 있다 |
| `git pull`          | 저장소 폴더가 아님  | 저장소는 `~/macfolio`에 있다                              |
| `docker compose up` | compose 파일이 없음 | compose 파일은 `~/deploy`에 있다                          |

올바른 순서로 다시 실행한 뒤 `docker compose logs -f api`로 확인하니 `Applying migration 20261002150000_wallpapers` 다음에 `All migrations have been successfully applied.`가 기록되고 Nest가 시작되었다. 화면에서 배경화면 추가가 동작하는 것까지 확인했다.

```bash
cd ~/deploy
docker compose exec -T db pg_dump -U macfolio macfolio > ~/backup-$(date +%F).sql
(cd ~/macfolio && git pull)
docker compose up -d --build api
docker compose logs -f api   # "All migrations have been successfully applied." 확인
```

마이그레이션을 컨테이너 시작 시점에 실행하는 방식은 [Prisma Migrate 배포 문서](https://www.prisma.io/docs/orm/prisma-client/deployment/deploy-database-changes-with-prisma-migrate)를 따랐다.

## Finder와 프로젝트 앱

밤에는 Finder를 만들었다. 문서·프로젝트·블로그·앱을 폴더와 파일처럼 탐색한다([openRequest store로 Finder에서 고른 항목을 다른 앱에서 열기](/memo/finder-app), [#86](https://github.com/hyeoniverse/MacFolio/pull/86)). 이슈 [#20](https://github.com/hyeoniverse/MacFolio/issues/20)(이력서·문서)의 첫 작업이다.

![현재의 Finder](./images/day-1003-finder.jpg 'Finder의 현재 화면')

배포한 프로젝트 사이트를 창 안에 표시하는 프로젝트 앱([PROJECTS 데이터에서 생성하는 iframe 앱과 ProjectAppName 브랜드 타입](/memo/project-apps), [#87](https://github.com/hyeoniverse/MacFolio/pull/87))과 MacFolio를 프로젝트 목록에 추가하는 작업([PROJECTS 단일 원본으로 GitHub 스냅샷과 프로젝트 목록 합치기](/memo/projects-one-list), [#88](https://github.com/hyeoniverse/MacFolio/pull/88))도 이날 밤 시작했다.

### 프로젝트 목록이 여러 곳에 있던 문제

처음에는 hyeoniverse 프로젝트가 Safari·Finder·앱 어디에도 없었고, MacFolio를 추가하자 한 화면에만 표시되었다. 프로젝트 목록을 한 곳에서 관리하지 않아 한 곳에만 추가된 것이다. 확인해 보니 GitHub 앱의 스냅샷만 프로젝트 목록을 별도로 기록하고 있었다. 스냅샷도 Safari·Finder·터미널과 같은 `PROJECTS`에서 생성하게 했다. 두 PR은 이틀 뒤에 머지했다.

## 돌아보며

**잘한 점**

- 시험을 통과한 커밋만 배포되게 했다. 시험이 실패한 커밋은 이제 사이트에 배포되지 않는다
- 프로젝트 목록을 `PROJECTS` 한 곳으로 통합했다. `PROJECTS`를 수정하면 모든 화면에 반영되고, 화면 사이에 불일치가 생기면 시험이 실패한다

**아쉬운 점**

- 화면 구성을 정하지 않고 구현을 시작했다. 저장소 선택 화면은 21분에 세 번, 아이콘은 20분에 네 번 변경했다. 처음에 참고 화면(macOS 설정의 그룹 목록)을 정했다면 한두 번에 끝났을 것이다
- 변경이 반복된 커밋이 모두 새벽 5시 전후에 집중되어 있다. 판단력이 떨어지는 시간대에 화면 구성을 결정했다
