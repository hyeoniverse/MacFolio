이슈에 "쓰지 않는 선택자 지우기 (Stylelint 도입 검토)"를 적어 두었다. 먼저 Stylelint로 할 수 있는 일인지 보았다.

## 배경

이 사이트의 CSS는 컴포넌트마다 파일을 따로 둔다. 지금 `apps/react/src` 아래 CSS 파일은 92개, 합쳐 5만 줄 가까이 된다. 화면을 여러 번 갈아엎으면서(프로젝트 페이지를 템플릿으로 바꾸고, Launchpad와 창 최소화를 다시 만들고, 메모 도구 막대를 다시 짜고) 옛 화면의 규칙이 그대로 남았다는 것은 짐작하고 있었다. 다만 어느 것이 남았는지는 몰랐다.

쓰지 않는 규칙은 화면에는 해가 없지만 두 가지 비용이 있다. 하나는 번들 크기다. 다른 하나는 읽는 사람이 헷갈린다는 점이다. 비슷한 이름의 규칙이 두 벌 있으면 어느 쪽을 고쳐야 화면이 바뀌는지 매번 확인해야 한다.

## Stylelint로는 안 된다

Stylelint는 CSS 파일만 읽는다. 어떤 클래스를 HTML이나 컴포넌트가 쓰는지는 모르므로 "쓰지 않는 선택자" 규칙이 없다. 그 일을 하는 도구(PurgeCSS 등)는 소스에서 클래스 이름을 글자로 찾는데, 이 사이트는 클래스 이름을 조립하는 곳이 많아 그대로 쓰면 쓰는 규칙까지 지운다. 그래서 한 번 직접 세어 보았다.

| 방법                           | 장점                         | 단점                                                               |
| ------------------------------ | ---------------------------- | ------------------------------------------------------------------ |
| Stylelint 도입                 | CSS 문법·순서 규칙은 잘 본다 | 쓰는지 여부는 모른다                                               |
| PurgeCSS를 빌드에 넣기         | 자동으로 매번 지운다         | 조립한 이름을 못 알아봐 쓰는 규칙까지 지운다. 예외 목록이 길어진다 |
| 브라우저 커버리지(개발자 도구) | 실제로 쓰인 규칙을 본다      | 모든 앱·모든 상태를 열어 봐야 한다. 휴대폰·다크 모드까지           |
| 한 번 직접 세고 사람이 확인    | 조립 규칙을 내가 안다        | 매번 자동은 아니다                                                 |

자동화를 버린 이유는 아래 그림 한 장이면 충분하다.

![CSS의 .sky-rain이 코드에서는 sky-와 값을 합쳐 만들어져, 글자 찾기가 놓치는 예](./images/unused-css-selectors-assembled.svg '조립한 이름은 글자로 찾을 수 없다')

## 1단계: 글자로 찾기

스크립트는 단순하다. CSS 파일에서 주석을 지우고, `{` 앞의 선택자에서 `.이름` 꼴을 모두 뽑는다. 그리고 소스 파일을 한 덩어리 글자로 합쳐 그 이름이 들어 있는지 본다.

```python
for sel in re.findall(r'([^{}]+)\{', css_text):
    for name in re.findall(r'\.(-?[_a-zA-Z][\w-]*)', sel):
        names.add(name)
missing = [n for n in names if n not in source_blob]
```

CSS의 모든 선택자에서 클래스 이름 2,761개를 뽑고, `.ts`·`.tsx`·`.md` 어디에도 그 글자가 없는 것을 골랐다. 150개가 나왔다.

## 2단계: 조립하는 이름 걸러 내기

150개 대부분은 코드가 이름을 조립해 붙이는 클래스였다.

| 종류                   | 예                                                          | 코드                               |
| ---------------------- | ----------------------------------------------------------- | ---------------------------------- |
| 앞부분 + 값            | `sky-rain`, `rank-1`, `view-gallery`                        | `` `weather sky-${weather.sky}` `` |
| 템플릿 접두사 + 뒷부분 | `mg-trouble`, `pp-member`                                   | `cx(prefix, 'trouble')`            |
| 라이브러리가 붙임      | `hljs-keyword`, `ProseMirror-selectednode`, `resize-cursor` | highlight.js, ProseMirror          |

`이름-${` 꼴과 `cx(prefix, '이름')` 꼴을 코드에서 모아 이것으로 만들 수 있는 클래스를 빼고, 라이브러리 클래스를 빼자 9개가 남았다. 9개는 하나씩 코드를 읽어 정말 쓰지 않는지 확인했다.

| 클래스                                    | 무엇이었나                                             |
| ----------------------------------------- | ------------------------------------------------------ |
| `sp-hero-main`, `sp-tiles`, `sp-timeline` | 프로젝트 페이지를 템플릿으로 바꾸기 전의 공통 레이아웃 |
| `minimized-container`, `dock-launchpad`   | 창 최소화 미리보기와 옛 Launchpad 버튼                 |
| `cd-lock`, `cd-voice-script`              | 데모의 옛 잠금 표시와 음성 대본                        |
| `tm-jump`                                 | DevCourse 터미널의 옛 바로 가기                        |
| `memo-toolbar-title`                      | 메모 도구 막대의 옛 제목                               |

![클래스 2,761개에서 150개, 9개로 줄이고 규칙 24개를 지운 단계](./images/unused-css-selectors-funnel.svg '단계마다 남은 수')

## 지우기

손으로 지우지 않고 CSS 파서(postcss)로 이 클래스만 쓰는 규칙 24개를 지우고, 다른 선택자와 함께 묶인 곳(`.minimized-container i, .dock-item i`)은 그 선택자만 뺐다. `minimized-container`만 쓰던 배경 그림(`imgs/minimize.JPG`, 58KB)도 지웠다.

손으로 지우지 않은 이유는 묶인 선택자 때문이다. `.minimized-container i, .dock-item i`에서 앞쪽만 지우려다 쉼표 하나를 잘못 남기면 규칙 전체가 무효가 되어 `.dock-item i`까지 깨진다. 파서는 선택자 목록을 배열로 다루니 이런 실수가 없다.

바뀐 파일과 지운 줄 수는 이렇다.

| 파일                                           | 지운 줄 |
| ---------------------------------------------- | ------- |
| `apps/safari/ProjectPage.css`                  | 78      |
| `apps/safari/project/creative/demos.css`       | 51      |
| `apps/safari/project/custom/DevCoursePage.css` | 16      |
| `desktop/dock/DockItem.css`                    | 11      |
| `apps/memo/styles/toolbar.css`                 | 10      |
| 합계                                           | 166     |

## 확인

- 지운 9개 클래스를 `.ts`·`.tsx`에서 다시 찾아 한 곳도 나오지 않는 것을 확인했다. 조립하는 곳(`` `sp-${` ``, `cx(prefix, …)`)에서도 이 뒷부분을 만드는 값이 없는지 따로 봤다.
- 단위 시험과 E2E는 그대로 통과했다. 이 일은 CSS만 지우므로 시험이 깨진다면 그 클래스를 어딘가 쓰고 있었다는 뜻이다.
- 공개 폴더에서 `imgs/minimize.JPG`(58,836바이트)가 빠졌다.

## 남은 것·배운 것

이 글을 쓰며 같은 방식으로 다시 세어 보니, 지금은 CSS 클래스가 2,850개이고 글자로 못 찾는 것이 169개다. 그사이 새 화면이 늘었으니 숫자가 늘어난 것은 자연스럽다. 이 169개도 대부분 조립하는 이름일 것이다. 그래도 1년에 한두 번은 같은 순서로 다시 볼 만하다.

- 쓰지 않는 규칙은 이름을 조립하는 곳 때문에 자동으로 찾기 어렵다. 새로 지울 때도 이 순서(글자로 찾기 → 조립하는 이름 걸러 내기 → 하나씩 읽기)를 다시 쓰면 된다.
- 이름을 조립하는 코드는 편하지만 검색을 어렵게 만든다. 값이 몇 개 안 되면 `{ rain: 'sky-rain', … }`처럼 이름을 통째로 적는 쪽이 나중에 찾기 쉽다.
- 도구를 들이기 전에 "이 도구가 정말 그 질문에 답하는가"를 먼저 본다. Stylelint는 좋은 도구지만 이번 질문의 답은 아니었다.
