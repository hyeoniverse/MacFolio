## 서버를 TypeScript로, 메모를 MySQL로

21일 밤 11시 26분 커밋 "FEAT: Memo app"은 이틀 작업의 기반이다. 서버를 Express 생성기의 JavaScript에서 TypeScript로 다시 썼다. `routes → controllers → models`로 나누고, `mysql2`의 연결 풀로 MySQL에 붙였다. 표는 `folders`와 `memos` 둘이다.

화면 쪽은 [일주일 전](/memo/day-20241015) 코드에 적어 둔 폴더·메모를 지우고, `MemoContext`가 axios로 서버를 부르게 했다. 메모를 고치면 목록의 제목도 바로 바뀌게 했다.

![메모 저장 흐름](./images/day-20241021-structure.svg '편집 권한이 사람이 아니라 메모에 붙어 있었다')

이 커밋에는 컴파일한 결과물 `server/dist/`와 환경 변수 파일 `server/.env`도 같이 들어갔다. `.env`는 닷새 뒤 추적에서 뺐다([2024년 10월 26~27일 회고](/memo/day-20241026)).

## 메모마다 비밀번호

로그인이 없었으니 고치고 지우는 사람을 가릴 방법은 메모에 비밀번호를 붙이는 것이었다. `memos.password`에 bcrypt 해시를 두고, 수정·삭제 경로 앞에 미들웨어를 두었다.

```ts
// 메모 수정 (비밀번호 검증 필요)
router.put('/:id', validatePassword, updateMemoController);
// 메모 삭제 (비밀번호 검증 필요)
router.delete('/:id', validatePassword, deleteMemoController);
```

`validatePassword`는 요청 몸통의 `password`를 `bcrypt.compare`로 그 메모의 해시와 비교한다. 없으면 400, 메모가 없으면 404, 틀리면 403이다. 22일 오전 9시 49분에 화면에 삭제를 붙이면서 비밀번호를 묻는 창을 띄웠다.

## 메모 화면: 컴포넌트 나누기와 "고정"

22일 0시 9분에 `Memo.tsx`에서 `FolderList`, `MemoItem`, `MemoTools`를 떼어 냈고, 새 메모에는 기본 제목과 내용을 넣었다. 2시 58분의 "고정"은 이랬다.

```ts
.sort((a, b) => {
	// 1번 폴더에서 id가 1인 메모를 상단 고정
	if (selectedFolder === 1) {
		if (a.id === 1) return -1;
		if (b.id === 1) return 1;
	}
	return b.id - a.id;
});
```

고정할 메모를 고르는 기능이 아니라, id가 1인 메모를 "모든 메모" 폴더 맨 위에 두는 규칙이었다. 4시 13분에는 쓰기 시작한 새 메모를 저장 전까지 임시 메모로 목록에 넣었다.

## 그 밖에: 시간대와 시작음

- **시간대**: 화면에서 `toLocaleString`에 `timeZone: 'Asia/Seoul'`을 붙이던 것을 삭제하고, DB 연결에 `timezone: '+09:00'`을 지정했다. 시간대 변환을 화면마다 하지 않고 DB 연결 한 곳에서 처리한다
- **시작음**: 로딩 화면에 Mac 시작음을 추가했다

## 돌아보며

비밀번호를 메모에 붙인 것은 "누가 고칠 수 있나"를 "무엇을 아나"로 바꾼 것이다. 로그인을 만들지 않고 쓸 수 있는 가장 가까운 답이었지만, 비밀번호를 아는 사람은 누구든 관리자가 된다. 2026년에 이 사이트가 고른 답은 [정적 사이트에서는 관리자를 가릴 수 없으니 먼저 잠그고](/memo/read-only-memo), 서버가 생긴 뒤 로그인으로 푸는 것이었다.

"고정"도 같은 모양이다. 고정하는 기능 대신 고정된 결과를 코드에 적었다. 기능이 필요한지 확인하기 전에는 이렇게 결과를 먼저 적는 것도 방법이지만, 이름이 기능처럼 남으면 나중에 읽는 사람이 헷갈린다.
