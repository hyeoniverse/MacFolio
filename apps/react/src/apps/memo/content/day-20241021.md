## 서버를 TypeScript로, 메모를 MySQL로

21일 밤 11시 26분 커밋 "FEAT: Memo app"은 이틀 작업의 기반이다. 서버를 Express 생성기의 JavaScript에서 TypeScript로 다시 썼다. `routes → controllers → models` 3계층으로 나누고, `mysql2`의 연결 풀로 MySQL에 연결했다. 테이블은 `folders`와 `memos` 두 개다.

| 계층        | 역할                                                                           |
| ----------- | ------------------------------------------------------------------------------ |
| routes      | 주소와 HTTP 메서드를 컨트롤러에 연결한다 (`PUT /:id` → `updateMemoController`) |
| controllers | 요청 값을 모델에 전달하고 응답을 반환한다                                      |
| models      | `mysql2` 연결 풀로 SQL을 실행한다                                              |

화면에서는 [일주일 전](/memo/day-20241015) 코드에 작성한 폴더·메모를 삭제하고, `MemoContext`가 axios로 서버를 호출하게 했다. 메모를 수정하면 목록의 제목도 즉시 갱신된다.

![메모 저장 흐름](./images/day-20241021-structure.svg '편집 권한이 사용자가 아니라 메모 단위로 정해졌다')

이 커밋에는 컴파일 결과물 `server/dist/`와 환경 변수 파일 `server/.env`도 함께 커밋되었다. `.env`는 닷새 뒤 git 추적에서 제외했다([2024년 10월 26~27일 회고](/memo/day-20241026)).

## 메모 단위 비밀번호

로그인 기능이 없어서, 수정·삭제 권한을 구분하는 방법으로 메모마다 비밀번호를 지정했다. `memos.password` 열에 bcrypt 해시를 저장하고, 수정·삭제 경로 앞에 검증 미들웨어를 배치했다.

```ts
// 메모 수정 (비밀번호 검증 필요)
router.put('/:id', validatePassword, updateMemoController);
// 메모 삭제 (비밀번호 검증 필요)
router.delete('/:id', validatePassword, deleteMemoController);
```

`validatePassword`는 요청 본문의 `password`를 `bcrypt.compare`로 해당 메모의 해시와 비교한다.

| 경우                   | 응답                 |
| ---------------------- | -------------------- |
| 요청에 비밀번호가 없음 | 400                  |
| 메모가 없음            | 404                  |
| 비밀번호 불일치        | 403                  |
| 일치                   | 다음 컨트롤러로 진행 |

22일 오전 9시 49분에 화면에 삭제 기능을 추가하면서, 비밀번호를 입력받는 창을 표시하게 했다.

## 메모 화면: 컴포넌트 분리와 "고정"

22일 0시 9분에 `Memo.tsx`에서 `FolderList`, `MemoItem`, `MemoTools`를 분리했고, 새 메모에는 기본 제목과 내용을 지정했다. 2시 58분 커밋의 "고정"은 다음과 같은 정렬 규칙이었다.

```ts
.sort((a, b) => {
	// 1번 폴더에서 id가 1인 메모를 상단 고정
	if (selectedFolder === 1) {
		if (a.id === 1) return -1;
		if (b.id === 1) return 1;
	}
	return b.id - a.id;
});
```

고정할 메모를 선택하는 기능이 아니라, id가 1인 메모를 "모든 메모" 폴더 맨 위에 배치하는 규칙이었다. 4시 13분에는 작성 중인 새 메모를 저장 전까지 임시 메모로 목록에 표시했다.

## 그 밖에: 시간대와 시작음

- **시간대**: 화면의 `toLocaleString`에 지정하던 `timeZone: 'Asia/Seoul'`을 삭제하고, DB 연결에 `timezone: '+09:00'`을 지정했다. 시간대 변환을 화면마다 처리하지 않고 DB 연결 한 곳에서 처리한다
- **시작음**: 로딩 화면에 Mac 시작음을 추가했다

## 돌아보며

메모마다 비밀번호를 지정한 것은 "누가 수정할 수 있는가"를 "무엇을 알고 있는가"로 바꾼 것이다. 로그인 없이 구현할 수 있는 가장 가까운 방법이었지만, 비밀번호를 아는 사람은 누구든 관리자 권한을 갖는다. 2026년에 이 사이트가 선택한 방법은 [정적 사이트에서는 관리자를 가릴 수 없으니 먼저 잠그고](/memo/read-only-memo), 서버가 생긴 뒤 로그인으로 잠금을 해제하는 것이었다.

"고정"도 같은 구조다. 고정 기능 대신 고정된 결과를 코드에 작성했다. 기능이 필요한지 확인하기 전에는 결과를 먼저 하드코딩하는 것도 방법이지만, 이름이 기능처럼 남으면 나중에 코드를 읽는 사람이 혼동한다.
