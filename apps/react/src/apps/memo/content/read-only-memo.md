메모 앱(이 블로그)에 폴더 만들기, 이름 바꾸기, 끌어서 옮기기, 글 고정을 차례로 넣었다. 처음에는 누구나 자기 브라우저에서 정리해 볼 수 있게 했는데, 생각해 보니 이상했다. 블로그 글의 폴더와 순서는 글쓴이가 정하는 것이다. 방문자가 바꿀 일이 아니다.

## 비밀번호를 넣으면 안 되나

가장 쉬운 방법은 비밀번호를 물어보는 것이다. 하지만 이 사이트는 정적 파일이다. 비밀번호를 확인하는 코드가 브라우저에서 돌면, 비밀번호나 그 해시가 자바스크립트 번들에 그대로 들어간다. 개발자 도구를 열면 누구나 볼 수 있다.

설령 확인을 우회하지 못하게 만들어도, 편집한 결과는 그 사람 브라우저의 `localStorage`에만 남는다. 관리자가 정리한 폴더를 다른 방문자에게 보여 줄 방법이 없다. 결국 두 가지가 필요하다.

1. 누가 관리자인지 **서버가** 판단한다.
2. 정리한 결과를 **서버에** 저장한다.

둘 다 백엔드가 있어야 한다.

## 그래서 지금은 잠가 둔다

편집 기능은 모두 한 hook 뒤에 두었다. 백엔드가 붙기 전까지는 늘 `false`다.

```ts
/**
 * 편집은 관리자만 할 수 있다. 이 사이트는 정적 파일이라 브라우저 코드만으로는 관리자를 가릴 수 없으므로
 * 백엔드의 관리자 로그인이 붙기 전까지는 늘 false다.
 */
export function useCanEditMemo(): boolean {
	return false;
}
```

화면은 이 값 하나로 갈린다. `false`면 새 폴더 단추와 ••• 메뉴가 없고, 끌어서 옮길 수도 없다. 예전에 방문자가 자기 브라우저에 만들어 둔 폴더와 순서도 더는 읽지 않고 지운다.

만들어 둔 편집 기능을 지우지 않은 이유도 있다. 관리자 로그인이 붙으면 이 hook이 서버의 로그인 상태를 돌려주기만 하면 된다. 편집 E2E 테스트도 지우지 않고 건너뛰기로 표시해 두었다가, 그때 다시 켠다.

## 다음 단계

백엔드에서 할 일은 이렇다.

- GitHub OAuth로 로그인하고, 정해 둔 계정만 관리자로 인정한다
- 폴더·순서·고정 상태를 서버에 저장하고, 쓰기 요청마다 서버가 권한을 다시 확인한다
- 같은 로그인으로 GitHub 앱에 보여 줄 고정 저장소도 설정에서 고른다

화면에서 단추를 숨기는 것은 보안이 아니라 안내일 뿐이다. 실제로 막는 일은 서버가 한다.
