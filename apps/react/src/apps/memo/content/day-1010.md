자정에 머지 버튼을 두 번 눌렀는데, 둘 다 main에 들어가지 않았다. 이날은 그것을 다시 올리는 것으로 시작했다. 그 뒤로 main에 PR 32개가 들어갔다. 새벽에는 서버 쪽 기능, 아침에는 보안 시험, 저녁에는 보안 설정과 의존성, 밤에는 날씨 앱이었다.

아래 PR(#143)이 30여 초 먼저 머지되어 브랜치의 역할이 끝난 뒤, 그 위에 쌓은 PR이 그 브랜치로 머지되었다. 전날 음악 PR은 순서가 반대라 무사히 main에 갔다. 그 뒤로는 PR을 쌓지 않고 늘 main을 base로 올린다.

휴지통은 처음에 이 사이트를 만들며 **버린 기능**을 모아 보여 주는 곳이었다가, #147에서 **실제로 비울 수 있는 것**만 담는 곳으로 바뀌었다. 방문자에게는 이 사이트가 브라우저에 남긴 설정·검색어, 관리자에게는 글에서 빠져 쓰는 곳이 없는 서버 파일이다([휴지통 앱](/memo/bin-app), [쓰는 곳이 없는 파일 찾기](/memo/server-files-cleanup)).

## 새벽: 정리를 마치고 서버를 보다

- **lint 경고 0개** — 마지막 경고 4개를 없애고, 경고로 낮춰 두었던 규칙을 에러로 올리고, 모든 패키지에 `--max-warnings 0`을 걸었다([#144](https://github.com/hyeoniverse/MacFolio/pull/144)). 같은 새벽에 리팩터링 이슈 [#15](https://github.com/hyeoniverse/MacFolio/issues/15), desktop-core 이슈 [#16](https://github.com/hyeoniverse/MacFolio/issues/16), 백엔드 API 이슈 [#9](https://github.com/hyeoniverse/MacFolio/issues/9)를 닫았다.
- **가끔 실패하던 시험의 원인은 코드였다** — 전체를 돌릴 때만 가끔 실패하던 메모 편집 시험 셋. 일부러 느리게 돌려 재현하니, 제목에서 Enter를 누를 때 따로 불러오는 편집기가 아직 없어서 그 뒤의 글자가 제목으로 들어가고 있었다. 느린 기기에서는 사람도 겪는 버그였다([#148](https://github.com/hyeoniverse/MacFolio/pull/148), [아직 없는 편집기로 옮긴 초점](/memo/lazy-editor-focus)).
- **서버 자원 감시** — Oracle Always Free 서버는 7일 동안 사용률이 낮으면 회수될 수 있다. API가 1분마다 CPU·메모리·네트워크를 재고, 위험하면 메일로 알린다([#151](https://github.com/hyeoniverse/MacFolio/pull/151)). 종량제라면 이번 달 요금과 예산 경고를, SDK 없이 Oracle 요청 서명을 직접 만들어 붙였다([#153](https://github.com/hyeoniverse/MacFolio/pull/153)). 메뉴 막대의 배터리는 관리자에게 서버 자원을, 방문자에게 방문 추이를 보여 준다([#155](https://github.com/hyeoniverse/MacFolio/pull/155)).
- **CI가 시작도 못 했다** — API e2e용 PostgreSQL 이미지를 로그인 없이 Docker Hub에서 받다가 받기 한도에 걸렸다. GitHub 러너는 IP를 여럿이 함께 쓰므로 다시 돌려도 같았다. 같은 이미지를 ECR Public에서 받게 했다([#154](https://github.com/hyeoniverse/MacFolio/pull/154)).

## 저녁: 설정으로 켜고 끄는 보안, 의존성

- 올린 사진의 EXIF·XMP를 지우고 방향만 남긴다. 휴대폰 사진의 위도·경도가 그대로 공개되고 있었다([#163](https://github.com/hyeoniverse/MacFolio/pull/163)).
- 너무 큰 몸통은 500이 아니라 413으로, 로그의 DB 비밀번호·API 키·쿠키·메일 주소는 가린다([#167](https://github.com/hyeoniverse/MacFolio/pull/167)).
- Apple 메뉴의 '이 Mac에 관하여'와 시스템 설정의 '정보'에 만든 사람의 프로필([#161](https://github.com/hyeoniverse/MacFolio/pull/161)), 메일 앱에서 주인 주소를 누르면 복사([#165](https://github.com/hyeoniverse/MacFolio/pull/165)).
- 시스템 설정의 '개인정보 보호 및 보안': 메일에만 걸려 있던 사람 확인(Turnstile)을 댓글·메시지에도, 관리자가 켜고 끈다([#168](https://github.com/hyeoniverse/MacFolio/pull/168)).
- 워크플로의 액션 9개를 커밋 SHA로 고정하고 Dependabot을 켰다([#169](https://github.com/hyeoniverse/MacFolio/pull/169)). 저장소 기록 전체를 gitleaks로 훑는 CI도 더했다([#170](https://github.com/hyeoniverse/MacFolio/pull/170)).

Dependabot을 켜자 PR 여섯 개가 한꺼번에 열렸다(vite 6→8, mermaid 12, lucide-react 1.x, `@types/node` 26 등, [#171](https://github.com/hyeoniverse/MacFolio/pull/171)~[#176](https://github.com/hyeoniverse/MacFolio/pull/176)). `@types/node` 26은 타입 검사를 깨뜨렸다. 프론트의 `lib`는 ES2020인데 코드는 ES2022의 `.at()`을 쓰고 있었고, 지금까지는 `@types/node` 22가 ES2022를 끌어와서 **우연히** 통과했던 것이다. `lib`를 ES2022로 올리고, Dependabot 브랜치에 사람이 커밋하면 규칙 검사에 걸리던 것을 고쳤다([#178](https://github.com/hyeoniverse/MacFolio/pull/178)). PR마다 미리보기가 올라가던 것은 프론트엔드가 바뀐 PR에만 올리게 했다([#179](https://github.com/hyeoniverse/MacFolio/pull/179)).

## 밤: 날씨

마지막은 macOS 날씨 앱이다([#177](https://github.com/hyeoniverse/MacFolio/pull/177), [macOS 날씨 앱 만들기](/memo/weather-app)). 데이터는 키 없이 쓰는 Open-Meteo에서 받는다. Open-Meteo의 장소 검색은 한국어 도시 이름을 잘 찾지 못하고 느려서, 자주 찾을 도시 211곳과 서울의 구는 사이트에 넣어 두었다.

머지 직전에 CI가 휴대폰 시험 하나에서 실패했다. 카드를 밀고 휴지통을 누르면 지워져야 하는데 지워지지 않았다. 처음에는 카드가 아직 휴지통을 덮고 있다고 짐작하고 고쳤는데, 다시 실패했다. 로컬(macOS)에서는 늘 통과했으므로 CI와 같은 리눅스 컨테이너에서 돌리며 이벤트를 찍었다. 누름은 휴지통에 닿아 `pointerdown`·`pointerup`까지 왔지만 `click`이 오지 않았다. 시험이 CDP로 보낸 터치가 끝나고 몇백 ms 안에 다시 누르면, 리눅스의 Chrome은 click을 만들지 않았다. 사람 손으로는 생기지 않는 간격이라 그 시험은 click으로 지우게 했다. 첫 짐작으로 고친 것 중 "미는 동안에는 애니메이션 없이 손가락을 따라오게"는 맞는 변경이라 남겼다.

## 돌아보며

이날 main을 깨뜨린 것은 셋이었다. 쌓아 올린 PR, 각자 통과한 두 PR의 조합, 바깥 서비스(Docker Hub)의 한도. 셋 다 PR 하나의 CI로는 보이지 않는다. PR을 하루에 서른 개 넘게 머지하면, PR 하나가 통과했다는 것과 main이 통과한다는 것은 다른 말이 된다. 머지한 뒤 main의 CI를 다시 보는 것까지가 머지다.

가끔 실패하는 시험 세 건은 원인이 모두 달랐다. 메모 편집기는 **코드의 버그**였고, 메시지 시험은 무작위 이름이 우연히 겹치는 **시험의 운**이었고([#164](https://github.com/hyeoniverse/MacFolio/pull/164)), 날씨 시험은 **브라우저 자동화의 성질**이었다. 겉모습은 같은 "가끔 실패"인데 고칠 곳은 코드, 시험, 시험 도구로 달랐다. 그래서 다시 돌려서 통과시키지 않고 원인을 찾는 것이 맞다. 날씨 시험에서는 첫 짐작이 틀렸는데, 그 짐작을 리눅스에서 확인하기 전에 올린 것이 아쉽다. 재현한 다음에 고쳤어야 했다.

보안 점검은 목록을 먼저 적고 하나씩 PR로 처리했다. 대부분 "이미 막혀 있지만 시험이 없던 것"(XSS, 경로 권한)이나 "한 겹만 막혀 있던 것"(iframe, 요청 제한)이었다. 막혀 있다는 것을 시험으로 고정해 두어야, 다음에 설정을 바꾸는 사람이 조용히 여는 일을 막을 수 있다.
