## Markdown 이력서와 텍스트 편집기

[#309](https://github.com/hyeoniverse/MacFolio/pull/309)로 진행했고, 터미널 앱의 `resume` 명령에서 시작했다. 이 명령은 원래 Finder의 이력서 폴더를 열었는데, 터미널 안에서 웃는 Mac 아스키 아트와 이력서를 출력하도록 바꿨다.

이어서 이력서의 데이터 구조를 바꿨다. 기존에는 시스템 설정에 입력한 프로필·프로젝트 값을 화면마다 따로 조합해 이력서를 만들었다. Finder 화면, PDF, 터미널이 각자 조합 코드를 갖고 있어서, 한 곳의 조합 순서나 문구를 고치면 다른 화면의 이력서와 내용이 달라졌다.

| 항목        | 변경 전                          | 변경 후                                              |
| ----------- | -------------------------------- | ---------------------------------------------------- |
| 원본        | 시스템 설정의 프로필·프로젝트 값 | **Markdown 문서 하나** (API `/site/resume`에 저장)   |
| 렌더링      | 화면마다 값을 조합해 각각 렌더링 | Finder 문서, PDF, 터미널 `resume`이 같은 문서를 읽음 |
| 설정값 반영 | 자동                             | "불러오기"로 문서에 삽입, 삽입 후에는 문서의 일부    |

![이력서 원본을 하나로 통일한 구조](./images/day-1021-resume-source.svg '변경 전에는 세 화면이 각자 조합 코드를 가졌다. 변경 후에는 세 화면이 GET /site/resume의 같은 Markdown을 읽고, 설정값은 불러오기로 문서에 삽입한다')

==원본을 하나로 통일해서, 화면마다 이력서 내용이 달라지는 문제가 구조적으로 발생하지 않는다.== 설정값이 자동으로 반영되지 않는 대신, "불러오기"를 누른 시점의 값이 문서에 들어가고 그 뒤로는 문서에서 자유롭게 고칠 수 있다.

### 텍스트 편집기

이 문서를 여는 앱으로 macOS 텍스트 편집기(TextEdit)를 만들었다. 처음에는 서식 막대와 미리보기를 분리한 방식이었다. 왼쪽에서 `**굵게**` 같은 Markdown 원문을 고치면 오른쪽에 결과가 나오는 구조다. 메모 앱처럼 서식이 적용된 상태에서 바로 편집하는 WYSIWYG(What You See Is What You Get) 편집기가 더 적합하다고 판단해, 메모 앱이 이미 쓰는 Milkdown으로 바꿨다. Milkdown은 ProseMirror 위에서 Markdown을 읽고 쓰는 편집기 프레임워크다. 실행 취소·다시 실행, ⌘S 저장, Markdown 원문 보기도 추가했다.

![텍스트 편집기에서 이력서를 고치는 화면](./images/day-1021-textedit.jpg#float-right '서식 막대와 눈금자 아래에서 서식이 적용된 상태로 편집한다. 오른쪽 위가 불러오기·변경 취소·저장')

이어서 영문 이력서(`/site/resume/en`)를 추가하고, Finder의 이력서 폴더에 `.md`와 `.pdf`를 함께 배치했다. PDF는 내려받지 않고 미리보기 앱에서 바로 열리며, 요청 시점의 Markdown으로 생성한다. 따라서 Markdown을 저장한 직후 PDF를 열면 고친 내용이 바로 반영되어 있다.

### 시행착오

| 증상                         | 원인                                                                                                                        | 수정                                                              |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 확장자가 PDF에만 표시        | `.md` 문서 이름에는 확장자를 붙이지 않았다                                                                                  | 문서 종류에 따라 확장자를 붙이는 함수 `withExtension` 하나로 생성 |
| 불러오기가 이전 내용을 읽음  | Milkdown은 변경 내용을 비동기로 늦게 전달한다. 방금 입력한 글자가 상태에 반영되기 전에 버튼을 누르면 이전 내용으로 덮어썼다 | 버튼을 누를 때 편집기에서 현재 내용을 직접 읽는다                 |
| 커밋 타입 `design`이 CI 거부 | 커밋 규칙에는 `design`이 없고, 브랜치 이름 규칙에만 `design/`이 있어 혼동했다                                               | 커밋 메시지를 `feat`/`fix` 등 허용 타입으로 고쳐 다시 push        |

두 번째 문제를 예로 들면, "경력" 절에 한 줄을 입력하자마자 저장을 누르면 저장된 문서에는 그 줄이 없었다. 화면에는 글자가 보이지만, React 상태로 전달되는 변경 알림이 아직 도착하지 않은 시점이었기 때문이다. 이 저장소의 커밋 타입은 `feat`·`fix`·`docs`·`refactor`·`test`·`style`·`perf`·`chore`·`ci` 아홉 가지이고, CI가 커밋 메시지마다 이 목록을 검사한다.

## 위젯

바탕화면과 휴대폰 홈 화면에 위젯 8종을 추가했다([#311](https://github.com/hyeoniverse/MacFolio/pull/311)). 위젯은 앱을 열지 않고 바탕화면에서 날씨·캘린더·음악 같은 정보를 바로 보여 주는 작은 판이다. macOS Sonoma부터 바탕화면에도 놓을 수 있게 되었다.

| 항목      | 바탕화면                                               | 휴대폰                   |
| --------- | ------------------------------------------------------ | ------------------------ |
| 배치      | 180px 격자, 바탕화면 아이콘을 피해 배치                | 홈 화면 페이지           |
| 추가·삭제 | 위젯 갤러리에서 선택하면 빈 칸으로 이동하는 애니메이션 | 홈 화면을 길게 눌러 편집 |

배경 스타일은 두 번 바꿨다.

1. 불투명한 패널
2. 배경화면이 비치는 유리 질감(`backdrop-filter: blur`)
3. 보는 위젯(사진·음악 등)은 유리, 읽는 위젯(캘린더·메모)은 불투명한 패널

==글자가 많은 위젯은 배경이 비치면 가독성이 떨어지기 때문이다.== 예를 들어 밝은 배경화면 위의 유리 메모 위젯은 흰 바탕에 회색 글자처럼 대비가 낮아져 제목을 읽기 어려웠다. 사진 위젯은 Finder › 그림의 폴더도 선택할 수 있다. 자세한 과정은 [180px 칸 격자 좌표로 바탕화면 위젯 배치하기](/memo/desktop-widgets)에 적었다.

## 첫 방문자를 위한 둘러보기와 팁 앱

첫 방문자는 Mac처럼 생긴 화면에서 어디부터 눌러야 할지 알기 어렵다. 그래서 Apple 팁 앱처럼 화면의 한 영역씩 강조하며 "여기를 눌러 보세요"라고 안내하는 둘러보기(온보딩 투어)를 만들었다([#313](https://github.com/hyeoniverse/MacFolio/pull/313)).

![둘러보기가 바탕화면의 이력서를 비추는 화면](./images/day-1021-tour.jpg '화면을 어둡게 덮고 이력서 폴더만 강조한다. 강조된 영역을 더블클릭하면 Finder가 열리고 다음 단계로 넘어간다')

- 로딩 화면이 사라진 뒤, 이 브라우저에서 첫 방문이면 환영 카드가 표시된다. 끝까지 보거나 닫으면 `localStorage`에 `macfolio:tour` 값을 저장해 다시 표시하지 않는다
- 어두운 덮개는 클릭을 그대로 통과시킨다(`pointer-events: none`). 강조된 영역을 누르면 실제 동작이 실행된 뒤 다음 단계로 넘어간다. 화면에 없는 대상(좁은 화면이라 Dock에 표시되지 않은 앱 등)은 건너뛴다
- 다시 보려면 도움말 › MacFolio 둘러보기, 또는 새로 추가한 **팁** 앱을 실행한다

`pointer-events: none`은 요소가 마우스·터치 이벤트의 대상이 되지 않게 하는 CSS 속성이다. 이 값을 준 요소 위를 클릭하면 브라우저는 그 아래에 있는 요소를 클릭 대상으로 삼는다. 덮개 전체에 이 값을 주고 안내 카드에만 `pointer-events: auto`를 다시 주면, 카드의 "다음" 버튼은 눌리고 나머지 화면은 덮개가 없는 것처럼 동작한다.

![둘러보기 덮개와 클릭이 지나가는 층](./images/day-1021-tour-layers.svg '비춘 칸 바깥은 큰 box-shadow로 어둡게 칠한다. 덮개는 pointer-events: none이라 더블클릭이 아래의 이력서 아이콘에 그대로 전달되고, 카드만 auto로 클릭을 받는다')

강조 영역은 구멍을 뚫는 대신 `box-shadow: 0 0 0 9999px`로 만든다. 그림자 번짐 반경(spread)을 9999px로 주면 강조 칸 바깥 전체가 그림자 색으로 칠해지고, 칸 안쪽만 원래 화면이 보인다. 다음 단계로 넘어가는 판단은 `document`에 캡처 단계로 등록한 `click` 리스너가 한다. 클릭 대상이 강조한 요소 안에 있으면, 원래 클릭 동작(Finder 열기)이 그대로 실행된 뒤 다음 단계로 이동한다.

팁 앱은 macOS 팁 앱의 레이아웃을 따랐다. 첫 화면에 검색, 팁 카드, 앱별 사용 설명서가 있다. 설명서는 처음에 짧은 팁 목록이었는데, 메모·Finder·Safari처럼 기능이 많은 앱은 Apple 사용 설명서처럼 큰 제목과 여러 문단, 실제 화면 캡처를 번갈아 배치하는 형식으로 바꿨다. 화면 캡처 20장은 빌드한 사이트에서 Playwright로 2배 해상도로 생성한다. 화면이 바뀌면 스크립트를 다시 실행해 캡처를 갱신할 수 있다.

![팁 앱 첫 화면](./images/day-1021-tips.jpg '검색, 둘러보기 카드와 세 줄 목록, 팁 카드. 카드에는 그림만 넣고 제목·설명은 카드 아래에 배치한다')

## 디자인 토큰 마무리와 다시 나온 정의되지 않은 CSS 변수

전날 세 층으로 재구성한 토큰 정리를 마무리했다. 스택 PR 문제로 main에 빠졌던 두 변경([#294](https://github.com/hyeoniverse/MacFolio/pull/294))을 다시 넣고, 토큰 단계에 없는 값을 정리했다.

| PR                                                       | 내용                                                                                                |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| [#296](https://github.com/hyeoniverse/MacFolio/pull/296) | 간격·모서리·글자의 단계 밖 값을 가까운 토큰으로, z-index를 전역 층 토큰과 컴포넌트 내부의 -1~10으로 |

#296은 전날 #280의 규칙을 반대 방향으로 바꿨다.

| 방식                      | 규칙                                         | 예: `border-radius: 13px`  |
| ------------------------- | -------------------------------------------- | -------------------------- |
| #280 차단 목록(denylist)  | 토큰 이름이 있는 값만 차단                   | 13px 토큰이 없으므로 통과  |
| #296 허용 목록(allowlist) | 토큰 범위 안의 숫자는 모두 차단, 예외만 허용 | 차단, 가까운 토큰으로 수정 |

허용하는 예외는 1~2px 미세값, 26px를 넘는 레이아웃 치수 등이다. 차단할 값의 목록보다 허용할 값의 목록이 더 짧았기 때문에 방향을 바꿨다.

그런데 같은 날 새로 만든 화면에서 토큰 이름을 잘못 썼다. 둘러보기 카드의 모서리가 직각으로 표시되어 확인해 보니, 모서리를 `--radius-16`, 글자를 `--text-caption1`로 썼는데 실제 토큰은 `--radius-14`·`--radius-18`과 `--text-caption`뿐이었다. ==정의되지 않은 변수는 오류 없이 무시되어 모서리 반경이 0이 된다.== 같은 실수가 같은 날 만든 텍스트 편집기 CSS에도 있었다.

[전날 회고](/memo/day-1020)에 "정의되지 않은 CSS 변수를 검출하는 규칙도 필요하다"고 적었는데, 바로 다음 날 같은 실수를 두 번 했다. 사용한 토큰이 실제로 정의된 이름인지 Stylelint가 검사하는 규칙이 필요하다. 검사 방법은 단순하다. 토큰 파일 세 개에서 `--`로 시작하는 정의 이름을 모아 집합을 만들고, 앱 CSS의 모든 `var(--…)` 참조가 그 집합에 있는지 확인하면 된다.

## 큰 파일 분리와 코드 정리

전날에 이어 커진 파일을 같은 기준으로 나눴다. 코드는 옮기기만 하고 내용은 바꾸지 않았다.

- [#293](https://github.com/hyeoniverse/MacFolio/pull/293): `Memo.tsx`에서 칸 배치·메모 선택·폴더 정리·글자 크기·버전 기록을 분리했다 (전날 올린 PR을 이날 머지)
- [#299](https://github.com/hyeoniverse/MacFolio/pull/299): 프로젝트 편집기의 항목 편집기 11개(718줄 파일 하나)를 `editors/` 폴더의 파일로 분리
- [#300](https://github.com/hyeoniverse/MacFolio/pull/300): `Weather.tsx` 682줄에서 훅 세 개와 장소 카드·상세 영역을 분리해 324줄로
- [#295](https://github.com/hyeoniverse/MacFolio/pull/295): `eslint-disable` 주석마다 사유를 기록하다가 `Modal`의 포커스 버그를 찾았다

#295의 버그는 `Modal`이 리렌더링될 때마다 포커스를 첫 입력 칸으로 되돌리는 문제였다. 포커스 이동과 Esc 키 처리가 의존성 `[onClose]`인 `useEffect` 하나에 있었다. 부모 컴포넌트가 렌더링할 때마다 `onClose`를 새 함수로 만들어 넘기면 effect가 다시 실행되고, 그때마다 포커스 이동 코드도 함께 실행됐다. 예를 들어 대화상자의 두 번째 입력 칸에 글자를 입력해 부모 상태가 바뀌면, 포커스가 첫 칸으로 이동할 수 있는 구조였다. 이 effect에는 "초점은 열 때 한 번만"이라는 주석과 함께 `react-hooks/exhaustive-deps` 규칙을 끄는 주석이 붙어 있었다. 포커스 이동(열 때 한 번)과 Esc 키 처리를 별도의 effect로 나눠, 린트 규칙을 비활성화하지 않고 고쳤다.

## Finder

전날 만든 Finder PR 세 개([#282](https://github.com/hyeoniverse/MacFolio/pull/282)·[#285](https://github.com/hyeoniverse/MacFolio/pull/285)·[#287](https://github.com/hyeoniverse/MacFolio/pull/287))를 머지하고 남은 문제를 고쳤다.

- [#297](https://github.com/hyeoniverse/MacFolio/pull/297): 열기 창에서 바탕화면 가상본의 화살표 표시가 아이콘 밖에 표시되던 문제. 화살표는 `position: absolute`인데 열기 창의 아이콘 영역에 기준 요소(`position: relative`)가 없었다. `absolute` 요소는 `position`이 지정된 가장 가까운 조상을 기준으로 배치되므로, 기준이 없으면 훨씬 바깥의 요소를 기준으로 위치가 정해진다
- [#308](https://github.com/hyeoniverse/MacFolio/pull/308): README의 라이트·다크 그림(`<picture>`)을 Finder의 문서 보기에서도 사이트의 화면 모드에 맞게 선택한다
- 이력서 문서 이름의 확장자는 위 「[Markdown 이력서와 텍스트 편집기](#markdown-이력서와-텍스트-편집기)」 절의 `withExtension`으로 해결했다

그리고 Finder › 그림에서 새 폴더 메뉴가 비활성화된 것을 찾았다. 관리자 폴더를 만들 수 있는 위치를 정한 규칙(`FINDER_BUILTIN_PARENT`)에 그림 폴더가 빠져 있었다. 이 규칙은 contracts 패키지(`packages/contracts`)에 있어 서버의 저장 검증과 화면이 함께 사용하므로, 한 곳에 추가하면 양쪽에 모두 반영된다. 그림 안의 앨범 폴더는 사진 앱이 프로젝트 사진으로 채우는 위치라 계속 차단했다([#314](https://github.com/hyeoniverse/MacFolio/pull/314)).

## 공유 카드와 RSS

공유 카드는 카카오톡·Slack·X 같은 서비스에 링크를 붙여 넣었을 때 제목·설명과 함께 표시되는 미리보기 그림이다. 서비스는 페이지 HTML의 Open Graph 메타 태그(`<meta property="og:image" …>`)를 읽어 이 그림을 가져온다. RSS는 사이트의 새 글 목록을 XML로 제공해, 피드 구독 앱이 주기적으로 읽어 새 글을 알려 주게 하는 형식이다.

| PR                                                       | 내용                                                                                                                   |
| -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| [#303](https://github.com/hyeoniverse/MacFolio/pull/303) | RSS 피드, 글마다 공유 이미지와 수정일, 없는 글 주소는 404. 사진이 없는 글은 빌드 시 제목으로 공유 카드를 생성한다      |
| [#306](https://github.com/hyeoniverse/MacFolio/pull/306) | 서버에서 작성한 글의 공유 카드는 API가 생성한다. 카드 생성 코드를 `packages/og-card`로 옮겨 빌드와 API가 함께 사용한다 |

공유 카드는 처음에 빌드 시에만 생성했는데(#303), 그러면 배포 후 관리자가 서버에서 작성한 글은 카드가 없다. 그래서 카드 생성 코드를 패키지로 분리해 빌드와 API가 같은 코드로 생성하게 했다(#306). 저장소 글과 서버 글의 카드가 같은 글꼴·배치로 만들어진다.

## 돌아보며

이날 추가한 세 기능은 모두 처음 구현한 형태에서 여러 번 바꿨다.

| 기능          | 변경 과정                                                      |
| ------------- | -------------------------------------------------------------- |
| 텍스트 편집기 | 미리보기 분리형 → WYSIWYG 편집기                               |
| 위젯          | 불투명한 패널 → 유리 → 유리와 패널 혼합                        |
| 팁 앱         | 목록 → macOS 팁 앱 레이아웃, 설명서는 짧은 팁 → 글과 실제 화면 |

처음부터 참고할 실제 앱(macOS 텍스트 편집기, 위젯, 팁 앱)을 정하고 시작했다면 변경 횟수를 줄일 수 있었다.
