## 낮: 이력서를 Markdown 한 장으로, 텍스트 편집기

낮의 일은 하나의 PR([#309](https://github.com/hyeoniverse/MacFolio/pull/309))로 이어졌다. 시작은 터미널의 `resume` 명령이었다. Finder를 여는 대신 웃는 Mac 아스키 아트와 이력서를 터미널에 그리게 했다(12시~14시).

그다음 이력서 자체를 바꿨다. 지금까지 이력서는 시스템 설정의 프로필·프로젝트 값을 조합해 화면마다 따로 그렸다. 이를 **Markdown 한 장**으로 바꾸고, 관리자가 고친 글을 API(`/site/resume`)에 저장하게 했다. Finder의 이력서 문서, PDF, 터미널 `resume`이 모두 같은 글을 읽는다. 설정의 프로필과 프로젝트는 "불러오기"로 글에 넣고, 넣은 뒤로는 그 글의 일부가 된다.

그 글을 여는 앱으로 macOS 텍스트 편집기를 만들었다(16시). 처음에는 서식 막대가 있는 미리보기 방식이었는데, 메모(노션)처럼 서식이 입혀진 그대로 고치는 편집기가 더 맞다고 보고 Milkdown으로 바꿨다. 실행 취소·다시 실행, ⌘S 저장, Markdown 원문 보기도 넣었다.

![텍스트 편집기에서 이력서를 고치는 화면](./images/day-1021-textedit.jpg '서식 막대와 눈금자 아래에서 서식이 입혀진 채 고친다. 오른쪽 위가 불러오기·변경 취소·저장')

이어서 영문 이력서(`/site/resume/en`)를 더하고, Finder의 이력서 폴더에 `.md`와 `.pdf`를 나란히 두었다. PDF는 내려받지 않고 미리보기에서 바로 열리며, 지금 Markdown으로 그때그때 만든다.

### 헛디딘 곳

- **확장자가 PDF에만 보였다.** `.md` 문서 이름에는 확장자가 없었다. 이름마다 손으로 붙이는 대신, 문서 종류로 확장자를 붙이는 함수(`withExtension`) 하나로 모든 문서 이름을 만들었다
- **불러오기가 옛 글을 읽었다.** Milkdown은 바뀐 글을 조금 늦게 알린다. 방금 친 글자가 아직 상태에 없는 채로 불러오기·저장을 누르면 옛 글로 덮었다. 버튼을 누를 때는 편집기에서 지금 글을 바로 읽게 했다
- **커밋 타입 `design`이 CI에서 걸렸다.** 이 저장소의 커밋 규칙에는 `design`이 없다(`feat`·`fix`·`docs`·`refactor`·`test`·`style`·`perf`·`chore`·`ci`). 브랜치 이름 규칙에는 `design/`이 있어서 헷갈렸다. 메시지를 고쳐 다시 올렸다

## 저녁: 위젯

18시부터는 바탕화면과 휴대폰 홈 화면에 위젯 8종을 두었다([#311](https://github.com/hyeoniverse/MacFolio/pull/311)). 바탕화면은 180px 칸 격자에 놓고, 휴대폰은 홈 화면을 길게 눌러 빼고 더한다. 처음에는 불투명한 판이었다가 배경화면이 비치는 유리로, 다시 "보는 위젯은 유리, 읽는 위젯(캘린더·메모)은 불투명한 판"으로 바꿨다. 갤러리에서 고른 위젯이 빈 칸으로 날아가 놓이고, 바탕화면 아이콘을 피해 자리를 잡는다. 자세한 과정은 [바탕화면과 홈 화면에 위젯](/memo/desktop-widgets)에 적었다.

## 저녁: 처음 온 사람을 위한 둘러보기와 팁 앱

위젯과 같은 시간에 둘러보기를 만들었다([#313](https://github.com/hyeoniverse/MacFolio/pull/313)). 처음 온 사람은 Mac처럼 생긴 화면에서 어디부터 눌러야 할지 모른다. 그래서 Apple 팁 앱처럼 화면의 한 곳씩 비추며 "이걸 눌러 보세요"라고 안내한다.

![둘러보기가 바탕화면의 이력서를 비추는 화면](./images/day-1021-tour.jpg '화면을 어둡게 덮고 이력서 폴더만 비춘다. 비춘 곳을 두 번 누르면 Finder가 열리고 다음 단계로 넘어간다')

- 로딩 화면이 걷힌 뒤, 이 브라우저에서 처음이면 환영 카드가 뜬다. 끝까지 보거나 닫으면 `macfolio:tour`를 남겨 다시 띄우지 않는다
- 덮개는 클릭을 그대로 통과시킨다. 비춘 곳을 누르면 그 동작을 한 뒤 다음 단계로 간다. 화면에 없는 곳(좁은 화면이라 Dock에 못 들어간 앱 등)은 건너뛴다
- 다시 보려면 도움말 › MacFolio 둘러보기, 또는 새 **팁** 앱

팁 앱은 macOS 팁 앱의 모양을 따랐다. 첫 화면에 찾기와 팁 카드, 앱마다의 사용 설명서가 있다. 설명서는 처음에 짧은 팁 목록이었는데, 메모·Finder·Safari처럼 기능이 많은 앱은 Apple 사용 설명서처럼 큰 제목과 여러 문단, 실제 화면 그림을 번갈아 두는 글 형식으로 바꿨다. 화면 그림 20장은 빌드한 사이트에서 Playwright로 2배 해상도로 찍는다.

![팁 앱 첫 화면](./images/day-1021-tips.jpg '찾기, 둘러보기 카드와 세 줄 목록, 팁 카드. 카드는 그림 칸만이고 제목·설명은 카드 밖 아래에 둔다')

### 또 정의되지 않은 CSS 변수

둘러보기 카드의 모서리가 직각으로 나왔다. 모서리를 `--radius-16`, 글자를 `--text-caption1`처럼 썼는데, 토큰에는 `--radius-14`·`--radius-18`과 `--text-caption`만 있다. 정의되지 않은 변수는 오류 없이 무시되어 모서리가 0이 된다. 같은 실수가 같은 날 만든 텍스트 편집기 CSS에도 있었다.

[전날 회고](/memo/day-1020)에 "정의되지 않은 CSS 변수를 막는 규칙도 있으면 좋겠다"고 적었는데, 바로 다음 날 같은 구멍에 두 번 빠졌다. 토큰이 실제로 있는 이름인지 Stylelint가 확인하는 규칙이 필요하다.

### 그림 폴더에서 새 폴더가 안 만들어졌다

밤에 Finder › 그림에서 새 폴더가 비활성화된 것을 봤다. 관리자 폴더를 둘 수 있는 자리를 정한 규칙(`FINDER_BUILTIN_PARENT`)에 그림이 빠져 있었다. 이 규칙은 서버의 저장 검사와 화면이 함께 쓰므로, 한 곳에 더하면 둘 다 열린다. 그림 안의 앨범 폴더는 사진 앱이 프로젝트 사진으로 채우는 곳이라 그대로 막았다([#314](https://github.com/hyeoniverse/MacFolio/pull/314)).

## 돌아보며

이날은 큰 기능 셋을 하루에 넣었다. 셋 다 처음 만든 모양에서 몇 번씩 다시 바꿨다. 텍스트 편집기는 미리보기에서 서식대로 고치는 편집기로, 위젯은 불투명한 판에서 유리로, 다시 유리와 판을 섞어서, 팁 앱은 목록에서 macOS 팁 앱 모양으로, 설명서는 짧은 팁에서 글과 실제 화면으로. 처음부터 참고할 실제 앱(macOS 텍스트 편집기, 위젯, 팁 앱)을 옆에 두고 시작했으면 바꾸는 횟수가 줄었을 것이다.

정의되지 않은 CSS 변수는 사람이 기억해서 막을 수 없다는 것이 이틀 연속으로 확인됐다. 다음에 할 일 첫 줄에 Stylelint 규칙을 둔다.
