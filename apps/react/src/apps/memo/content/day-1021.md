## Markdown 이력서와 텍스트 편집기

이 주제는 PR 하나([#309](https://github.com/hyeoniverse/MacFolio/pull/309))로 진행했다. 시작은 터미널의 `resume` 명령이었다. Finder를 여는 대신 웃는 Mac 아스키 아트와 이력서를 터미널에 출력하도록 변경했다.

이어서 이력서의 데이터 구조를 변경했다.

| 항목        | 변경 전                          | 변경 후                                              |
| ----------- | -------------------------------- | ---------------------------------------------------- |
| 원본        | 시스템 설정의 프로필·프로젝트 값 | **Markdown 문서 하나** (API `/site/resume`에 저장)   |
| 렌더링      | 화면마다 값을 조합해 각각 렌더링 | Finder 문서, PDF, 터미널 `resume`이 같은 문서를 읽음 |
| 설정값 반영 | 자동                             | "불러오기"로 문서에 삽입, 삽입 후에는 문서의 일부    |

원본을 하나로 통일해서, 화면마다 이력서 내용이 달라지는 문제가 구조적으로 발생하지 않는다.

이 문서를 여는 앱으로 macOS 텍스트 편집기를 만들었다. 처음에는 서식 막대와 미리보기를 분리한 방식이었는데, 메모 앱(Notion 방식)처럼 서식이 적용된 상태에서 바로 편집하는 WYSIWYG 편집기가 더 적합하다고 판단해 Milkdown으로 변경했다. 실행 취소·다시 실행, ⌘S 저장, Markdown 원문 보기도 추가했다.

![텍스트 편집기에서 이력서를 고치는 화면](./images/day-1021-textedit.jpg '서식 막대와 눈금자 아래에서 서식이 적용된 상태로 편집한다. 오른쪽 위가 불러오기·변경 취소·저장')

이어서 영문 이력서(`/site/resume/en`)를 추가하고, Finder의 이력서 폴더에 `.md`와 `.pdf`를 함께 배치했다. PDF는 내려받지 않고 미리보기 앱에서 바로 열리며, 요청 시점의 Markdown으로 생성한다.

### 시행착오

- **확장자가 PDF에만 표시됐다.** `.md` 문서 이름에는 확장자가 없었다. 이름마다 직접 붙이는 대신, 문서 종류에 따라 확장자를 붙이는 함수(`withExtension`) 하나로 모든 문서 이름을 생성했다
- **불러오기가 이전 내용을 읽었다.** Milkdown은 변경 내용을 비동기로 늦게 전달한다. 방금 입력한 글자가 아직 상태에 반영되지 않은 시점에 불러오기·저장을 누르면 이전 내용으로 덮어썼다. 버튼을 누를 때는 편집기에서 현재 내용을 직접 읽도록 수정했다
- **커밋 타입 `design`이 CI에서 거부됐다.** 이 저장소의 커밋 규칙에는 `design`이 없다(`feat`·`fix`·`docs`·`refactor`·`test`·`style`·`perf`·`chore`·`ci`). 브랜치 이름 규칙에는 `design/`이 있어서 혼동했다. 커밋 메시지를 수정해 다시 push했다

## 위젯

바탕화면과 휴대폰 홈 화면에 위젯 8종을 추가했다([#311](https://github.com/hyeoniverse/MacFolio/pull/311)).

| 항목      | 바탕화면                                               | 휴대폰                   |
| --------- | ------------------------------------------------------ | ------------------------ |
| 배치      | 180px 격자, 바탕화면 아이콘을 피해 배치                | 홈 화면 페이지           |
| 추가·삭제 | 위젯 갤러리에서 선택하면 빈 칸으로 이동하는 애니메이션 | 홈 화면을 길게 눌러 편집 |

배경 스타일은 두 번 변경했다. 처음에는 불투명한 패널이었다가 배경화면이 비치는 유리 질감으로, 다시 "보는 위젯은 유리, 읽는 위젯(캘린더·메모)은 불투명한 패널"로 정했다. 글자가 많은 위젯은 배경이 비치면 가독성이 떨어지기 때문이다. 사진 위젯은 Finder › 그림의 폴더도 선택할 수 있다. 자세한 과정은 [바탕화면과 홈 화면에 위젯](/memo/desktop-widgets)에 정리했다.

## 첫 방문자를 위한 둘러보기와 팁 앱

첫 방문자는 Mac처럼 생긴 화면에서 어디부터 눌러야 할지 알기 어렵다. 그래서 Apple 팁 앱처럼 화면의 한 영역씩 강조하며 "여기를 눌러 보세요"라고 안내하는 둘러보기(온보딩 투어)를 만들었다([#313](https://github.com/hyeoniverse/MacFolio/pull/313)).

![둘러보기가 바탕화면의 이력서를 비추는 화면](./images/day-1021-tour.jpg '화면을 어둡게 덮고 이력서 폴더만 강조한다. 강조된 영역을 더블클릭하면 Finder가 열리고 다음 단계로 넘어간다')

- 로딩 화면이 사라진 뒤, 이 브라우저에서 첫 방문이면 환영 카드가 표시된다. 끝까지 보거나 닫으면 `macfolio:tour` 값을 저장해 다시 표시하지 않는다
- 어두운 오버레이는 클릭을 그대로 통과시킨다(`pointer-events: none`). 강조된 영역을 누르면 실제 동작이 실행된 뒤 다음 단계로 넘어간다. 화면에 없는 대상(좁은 화면이라 Dock에 표시되지 않은 앱 등)은 건너뛴다
- 다시 보려면 도움말 › MacFolio 둘러보기, 또는 새로 추가한 **팁** 앱을 실행한다

팁 앱은 macOS 팁 앱의 레이아웃을 따랐다. 첫 화면에 검색, 팁 카드, 앱별 사용 설명서가 있다. 설명서는 처음에 짧은 팁 목록이었는데, 메모·Finder·Safari처럼 기능이 많은 앱은 Apple 사용 설명서처럼 큰 제목과 여러 문단, 실제 화면 캡처를 번갈아 배치하는 형식으로 변경했다. 화면 캡처 20장은 빌드한 사이트에서 Playwright로 2배 해상도로 생성한다.

![팁 앱 첫 화면](./images/day-1021-tips.jpg '검색, 둘러보기 카드와 세 줄 목록, 팁 카드. 카드에는 그림만 넣고 제목·설명은 카드 아래에 배치한다')

## 디자인 토큰 마무리와 다시 발생한 정의되지 않은 CSS 변수

전날 세 층으로 재구성한 토큰 정리를 마무리했다. 스택 PR 문제로 main에 반영되지 않았던 두 변경([#294](https://github.com/hyeoniverse/MacFolio/pull/294))을 다시 반영하고, 토큰 단계에 없는 값을 정리했다.

| PR                                                       | 내용                                                                                                           |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| [#296](https://github.com/hyeoniverse/MacFolio/pull/296) | 간격·모서리·글자의 단계 밖 값을 가까운 토큰으로, z-index를 전역 층 토큰과 컴포넌트 내부의 -1~10으로. 파일 74개 |

#296은 전날 #280의 규칙을 반대 방향으로 바꿨다. #280은 "토큰 이름이 있는 값만" 차단했는데, 이번에는 토큰 범위 안의 숫자는 모두 차단하고 예외(1~2px 미세값, 26px를 넘는 레이아웃 치수 등)만 허용했다. 차단 목록(denylist)보다 허용 목록(allowlist)이 더 짧았기 때문이다.

그런데 같은 날 새로 만든 화면에서 토큰 이름을 잘못 썼다. 둘러보기 카드의 모서리가 직각으로 표시되어 확인해 보니, 모서리를 `--radius-16`, 글자를 `--text-caption1`로 썼는데 실제 토큰은 `--radius-14`·`--radius-18`과 `--text-caption`뿐이었다. 정의되지 않은 변수는 오류 없이 무시되어 모서리 반경이 0이 된다. 같은 실수가 같은 날 만든 텍스트 편집기 CSS에도 있었다.

[전날 회고](/memo/day-1020)에 "정의되지 않은 CSS 변수를 검출하는 규칙도 필요하다"고 적었는데, 바로 다음 날 같은 문제가 두 번 발생했다. 사용한 토큰이 실제로 정의된 이름인지 Stylelint가 검사하는 규칙이 필요하다.

## Finder

전날 만든 Finder PR 세 개([#282](https://github.com/hyeoniverse/MacFolio/pull/282)·[#285](https://github.com/hyeoniverse/MacFolio/pull/285)·[#287](https://github.com/hyeoniverse/MacFolio/pull/287))을 머지했고, 이후 남은 문제를 수정했다.

- [#297](https://github.com/hyeoniverse/MacFolio/pull/297): 열기 창에서 바탕화면 가상본의 화살표 표시가 아이콘 밖에 표시되던 문제. 화살표는 `position: absolute`인데 열기 창의 아이콘 영역에 기준 요소(`position: relative`)가 없었다
- [#308](https://github.com/hyeoniverse/MacFolio/pull/308): README의 라이트·다크 그림(`<picture>`)을 Finder의 문서 보기에서도 사이트의 화면 모드에 맞게 선택한다
- 이력서 문서 이름의 확장자는 위 「Markdown 이력서와 텍스트 편집기」 절의 `withExtension`으로 해결했다

그리고 Finder › 그림에서 새 폴더 메뉴가 비활성화된 것을 발견했다. 관리자 폴더를 만들 수 있는 위치를 정한 규칙(`FINDER_BUILTIN_PARENT`)에 그림 폴더가 빠져 있었다. 이 규칙은 서버의 저장 검증과 화면이 함께 사용하므로, 한 곳에 추가하면 양쪽에 모두 반영된다. 그림 안의 앨범 폴더는 사진 앱이 프로젝트 사진으로 채우는 위치라 계속 차단했다([#314](https://github.com/hyeoniverse/MacFolio/pull/314)).

## 돌아보며

이날은 큰 기능 세 개를 하루에 추가했다. 세 기능 모두 처음 구현한 형태에서 여러 번 변경했다.

| 기능          | 변경 과정                                                      |
| ------------- | -------------------------------------------------------------- |
| 텍스트 편집기 | 미리보기 분리형 → WYSIWYG 편집기                               |
| 위젯          | 불투명한 패널 → 유리 → 유리와 패널 혼합                        |
| 팁 앱         | 목록 → macOS 팁 앱 레이아웃, 설명서는 짧은 팁 → 글과 실제 화면 |

처음부터 참고할 실제 앱(macOS 텍스트 편집기, 위젯, 팁 앱)을 정하고 시작했다면 변경 횟수를 줄일 수 있었다.

정의되지 않은 CSS 변수는 사람이 주의하는 것만으로는 막을 수 없다는 것이 이틀 연속으로 확인됐다. 다음 작업 목록의 첫 항목으로 Stylelint 규칙을 추가한다.
