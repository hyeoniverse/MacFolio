## 필기와 실기는 같은 범위를 다르게 묻는다

정보처리기사 실기는 필기와 시험 범위가 같다. 출제기준도 같은 NCS(국가직무능력표준) 응용 소프트웨어 엔지니어링 능력단위에서 나온다. NCS는 산업 현장의 직무를 능력단위로 나눠 국가가 정한 표준이고, 능력단위는 "SQL 응용"처럼 한 가지 업무를 해내는 데 필요한 지식과 기술의 묶음이다. 차이는 문제 형식이다. 필기는 보기 네 개 중 하나를 고르는 CBT(Computer Based Test, 컴퓨터로 치르는 시험) 객관식이고, 실기는 종이 시험지에 답을 직접 쓰는 필답형이다.

![같은 개념을 필기와 실기가 묻는 방식](./images/eip-practical-overview-question-forms.svg '필기는 보기에서 알아보면 되지만 실기는 용어와 순서를 직접 써야 한다')

보기가 없다는 차이는 생각보다 크다. 필기에서는 "자료 결합도"라는 이름을 보고 가장 약한 결합이라는 사실만 떠올리면 정답을 고를 수 있다. 실기에서는 결합도 여섯 가지의 이름을 모두 기억해 내고, 순서까지 맞게 써야 한다. 심리학에서는 앞의 능력을 재인(recognition), 뒤의 능력을 회상(recall)이라고 구분한다[^recall]. 회상은 재인보다 어렵고, 그 차이가 아래 합격률 통계에 그대로 나타난다.

| 구분        | 필기                             | 실기                                     |
| ----------- | -------------------------------- | ---------------------------------------- |
| 형식        | CBT 객관식 4지 택일              | 필답형 주관식                            |
| 과목        | 5과목                            | 정보처리 실무 1과목                      |
| 문항        | 100문항 (과목당 20)              | 20문항 안팎                              |
| 시간        | 2시간 30분                       | 2시간 30분                               |
| 합격 기준   | 과목당 40점 이상, 평균 60점 이상 | 100점 만점에 60점 이상                   |
| 필요한 능력 | 용어를 보고 뜻을 알아보는 능력   | 뜻을 보고 용어를 떠올려 정확히 쓰는 능력 |

실기는 과락이 없다. 20문항 중 12문항 정도를 맞히면 합격선에 닿는다. 그래서 모든 범위를 완벽하게 외우기보다, 출제 비중이 큰 유형에서 확실히 점수를 얻는 편이 효율적이다.

[^recall]: 재인은 제시된 자극이 이전에 본 것인지 판단하는 기억 인출 방식이고, 회상은 단서만으로 정보를 스스로 꺼내는 방식이다. 같은 내용이라도 회상 검사의 정답률이 재인 검사보다 낮게 나타난다.

## 실기 합격률이 필기보다 낮은 이유

한국산업인력공단이 Q-Net에 공개한 종목별 검정현황을 보면, 필기 합격률은 매년 60% 안팎인데 실기 합격률은 2020년부터 20~30%대에 머문다. 연도별 응시·합격 인원과 그래프는 [정보처리기사 시험 구조와 합격 기준](/memo/eip-overview)에 정리했다.

| 연도 | 필기 합격률 | 실기 합격률 |
| ---- | ----------: | ----------: |
| 2019 |       58.2% |       51.4% |
| 2020 |       57.3% |       17.7% |
| 2023 |         59% |         21% |

2019년까지는 필기와 실기 합격률이 비슷했다. NCS 기반 출제기준이 실기에 적용된 2020년에 실기 합격률이 17.7%로 떨어졌고, 그 뒤로 20~30%대에 머문다. 2023년에는 필기 응시자 10명 중 6명이 붙은 반면, 실기 응시자는 10명 중 2명만 붙었다. 수치로 확인할 수 있는 원인은 다음과 같다.

1. **보기가 없다.** 필기는 네 개 중 하나를 고르므로 정확히 몰라도 소거법으로 범위를 좁힐 수 있다. 실기는 용어 철자, 순서, 출력 공백까지 직접 써야 한다
2. **범위는 필기와 같은데 묻는 깊이가 다르다.** 필기에서 "이 설명에 맞는 것은?"으로 묻던 개념이 실기에서는 "이 설명에 해당하는 용어를 영문 약어로 쓰시오"로 바뀐다
3. **응시자가 누적된다.** 2023년 실기 응시는 58,088명으로 그해 필기 합격자 35,428명보다 많다. 필기 합격자는 발표일부터 2년 동안 필기가 면제되므로, 이전 연도 필기 합격자가 실기에 다시 응시한다. 같은 사람이 한 해에 여러 번 응시하면 응시 인원에 그만큼 더해지므로, 합격률은 사람 단위가 아니라 응시 단위의 비율이다
4. **회차마다 난이도 편차가 크다.** 2021년 30.8%와 2022년 20.8%처럼 연도별로 10%p씩 오르내린다. 어떤 회차에 응시해도 60점을 넘기려면 특정 유형에 기대지 말고 세 유형 모두에서 점수를 확보해야 한다

> [!NOTE] 합격률이 낮다는 것의 의미
> 실기 합격률 20%대는 문제가 풀 수 없을 만큼 어렵다는 뜻이 아니다. 필기를 공부한 방식(보기를 보고 알아보기) 그대로 실기에 응시하는 사람이 많다는 뜻이다. 이 글의 나머지 절은 유형마다 답을 직접 써 내는 연습 방법을 다룬다.

## 실기 출제기준과 12개 능력단위

실기 과목명은 "정보처리 실무" 하나다. Q-Net 출제경향은 지금 적용되는 출제기준(2023년 1월부터 2025년 12월까지)의 실기 범위를 12개 능력단위로 제시한다. 아래 표의 "주요 내용"은 Q-Net 출제경향의 괄호 안 설명이고, "주로 나오는 유형"은 이 연재에서 문제 형태로 분류한 결과다.

| 번호 | 능력단위                  | 주요 내용 (Q-Net 출제경향)                           | 주로 나오는 유형                        |
| ---: | ------------------------- | ---------------------------------------------------- | --------------------------------------- |
|    1 | 요구사항 확인             | 소프트웨어 공학의 요구사항 분석 기법 활용            | 설명 보고 용어 쓰기, 순서대로 쓰기      |
|    2 | 데이터 입출력 구현        | 논리·물리 데이터베이스 설계, 조작 프로시저           | 용어 쓰기(정규화·이상 현상), 관계대수   |
|    3 | 통합 구현                 | 연계 대상 모듈 간 특성과 연계 모듈 구현              | 약어 풀어 쓰기, 보기에서 골라 기호      |
|    4 | 서버 프로그램 구현        | 개발 환경 구축, 형상 관리, 공통 모듈, 테스트 수행    | 순서대로 쓰기(결합도·응집도), 용어 쓰기 |
|    5 | 인터페이스 구현           | 인터페이스 설계, 기능 구현, 구현 검증                | 약어 풀어 쓰기, 빈칸 채우기             |

|    7 | 애플리케이션 테스트 관리  | 테스트 케이스 설계, 통합 테스트, 성능 개선           | 보기에서 골라 기호, 빈칸 채우기         |
|    8 | SQL 응용                  | SQL 작성                                             | SQL 빈칸 채우기, 결과 행 수, 쿼리 작성  |
|    9 | 소프트웨어 개발 보안 구축 | SW 개발 보안 설계와 구현                             | 설명 보고 용어 쓰기, 약어 쓰기          |

|   11 | 응용 SW 기초 기술 활용    | 운영체제, 데이터베이스, 네트워크 활용, 개발환경 구축 | 설명 보고 용어 쓰기, 계산(서브네팅 등)  |

표에서 보이듯 능력단위 12개 중 10개가 용어 쓰기 중심이다. 반면 문항 수로 따지면 코드 읽기 하나(프로그래밍 언어 활용)가 회차마다 대체로 5~8문항, SQL이 2~3문항을 차지한다. 능력단위 수와 문항 수가 비례하지 않으므로, 공부 시간을 능력단위 개수대로 나누면 안 된다. 코드와 SQL은 능력단위 두 개로 전체 점수의 3분의 1 이상을 차지한다.

## 세 가지 출제 유형

실기 문제는 답의 형태에 따라 세 유형으로 나눌 수 있다.

| 유형      | 답의 형태                    | 회차당 비중    | 채점에서 갈리는 지점    |
| --------- | ---------------------------- | -------------- | ----------------------- |
| 용어 쓰기 | 단어, 약어, 기호, 순서       | 가장 많다      | 철자, 요구한 형태, 순서 |
| 코드 읽기 | 출력되는 문자열 그대로       | 대체로 5~8문항 | 공백, 줄바꿈, 계산 실수 |
| SQL       | SQL 문의 일부, 행 수, 결과값 | 대체로 2~3문항 | 키워드 철자, NULL 처리  |

아래 절에서는 유형마다 하위 형태를 나누고, 예제와 푸는 순서를 보인다. 개념 자체의 설명은 각론 글이 맡고, 이 글은 "문제를 받으면 무엇부터 하는가"를 다룬다.

## 용어 쓰기 유형

용어 쓰기는 회차마다 문항 수가 가장 많다. 같은 용어라도 문제가 답을 어떤 모양으로 요구하느냐에 따라 다섯 가지로 나뉜다.

![용어 쓰기 문제의 다섯 가지 하위 유형](./images/eip-practical-overview-term-subtypes.svg '하위 유형마다 답안에 쓰는 것의 모양이 다르다')

### 설명 보고 용어 쓰기

가장 기본 형태다. 개념을 설명하는 문장 한두 개를 주고 해당하는 용어를 쓰게 한다. 다음은 이 유형의 예제다.

> 다음 설명에 해당하는 테스트 기법을 쓰시오.
>
> 입력 조건의 중간값보다 경계에서 오류가 발생할 확률이 높다는 점을 이용해, 입력 범위의 최솟값·최댓값과 그 바로 바깥 값을 테스트 데이터로 선정하는 기법

<details>
<summary>정답</summary>

**경계값 분석**(Boundary Value Analysis)

</details>

이 유형에서는 비슷한 용어끼리 구분하는 능력이 중요하다. 동등 분할, 경계값 분석, 원인-결과 그래프, 결정 테이블, 상태 전이처럼 같은 분류(블랙박스 테스트)에 속한 용어들의 정의가 한 문장씩만 다르기 때문이다. 풀이 순서는 다음과 같다.

1. 설명에서 분류를 알려 주는 단어를 찾는다. 위 예제에서는 "테스트 기법"과 "입력 조건"이 블랙박스 테스트라는 분류를 알려 준다
2. 그 분류에 속한 용어 목록을 떠올린다
3. 목록 중 설명의 핵심 단어("경계", "바로 바깥 값")와 정의가 겹치는 하나를 고른다

### 빈칸 채우기

설명이나 표의 일부를 빈칸 ①②③으로 뚫어 두고 채우게 한다. 빈칸이 여러 개이면 앞뒤 빈칸이 서로 단서가 된다.

> 다음은 트랜잭션의 특성을 설명한 것이다. 빈칸에 들어갈 특성을 쓰시오.
>
> ( ① ): 트랜잭션의 연산은 데이터베이스에 모두 반영되거나 전혀 반영되지 않아야 한다.
> ( ② ): 트랜잭션이 실행을 완료하면 그 결과는 데이터베이스에 영구히 반영되어야 한다.

① 원자성(Atomicity) ② 지속성(Durability)

</details>

빈칸 문제는 빈칸의 개수와 짝이 정해져 있다는 점을 이용한다. ACID처럼 네 개짜리 묶음에서 두 개를 묻는다면, 나머지 일관성(Consistency)과 고립성(Isolation)의 정의를 먼저 지워 나가면 남는 두 개가 답이 된다. 묶음 전체를 외워 두어야 이 소거가 가능하다.

### 순서대로 쓰기

단계나 등급을 섞어 놓고 정해진 순서로 쓰게 한다. 순서가 하나라도 어긋나면 문항 전체가 틀린다.

> 다음 테스트 레벨을 수행 순서대로 기호로 쓰시오.
>
> ㄱ. 시스템 테스트 ㄴ. 인수 테스트 ㄷ. 단위 테스트 ㄹ. 통합 테스트

<details>
<summary>정답</summary>

ㄷ → ㄹ → ㄱ → ㄴ (단위 → 통합 → 시스템 → 인수)

</details>

순서 문제는 "무엇을 기준으로 한 순서인가"를 먼저 확인한다. 결합도는 "약한 것부터"와 "강한 것부터"가 정반대 답이 되고, OSI 7계층도 "하위 계층부터"인지 "상위 계층부터"인지에 따라 답이 뒤집힌다. 문제의 기준 단어에 밑줄을 긋고 답을 쓴다.

### 보기에서 골라 기호로 쓰기

설명 여러 개와 보기 목록을 주고, 해당하는 보기를 기호로 쓰게 한다. 필기와 비슷해 보이지만 보기 수가 설명 수보다 많고, "모두 고르시오"처럼 답의 개수를 알려 주지 않는 경우가 있다.

> 다음 GoF 디자인 패턴 중 생성 패턴에 해당하는 것을 모두 골라 기호로 쓰시오.
>
> ㄱ. Singleton ㄴ. Adapter ㄷ. Observer ㄹ. Builder ㅁ. Decorator ㅂ. Prototype

<details>
<summary>정답</summary>

ㄱ, ㄹ, ㅂ (Adapter와 Decorator는 구조 패턴, Observer는 행위 패턴)

</details>

"모두 고르시오"는 하나라도 빠지거나 더해지면 틀린다. 분류 묶음(생성 5개, 구조 7개, 행위 11개)을 외워 두면, 보기 하나하나를 묶음에 대조해 확실하게 고를 수 있다. 답안에는 용어가 아니라 기호만 쓴다.

### 약어 풀어 쓰기

약어를 주고 풀어 쓴 이름을 쓰게 하거나, 반대로 설명을 주고 영문 약어로 쓰게 한다.

> (1) ESB를 영문 Full-name으로 쓰시오.
>
> (2) 웹 서비스의 이름, 제공 위치, 호출 메시지 형식을 XML로 기술하는 언어를 영문 약어로 쓰시오.

<details>
<summary>정답</summary>

(1) Enterprise Service Bus (2) WSDL (Web Services Description Language의 약어)

</details>

약어 문제는 약어, 풀어 쓴 영문, 우리말 뜻 세 가지를 한 세트로 외워야 풀린다. 풀어 쓴 영문의 철자 하나만 틀려도 오답이므로, 눈으로 읽지 말고 손으로 써 보며 외운다.

### 헷갈리는 짝 비교

용어 쓰기에서 틀리는 답의 대부분은 전혀 모르는 용어가 아니라, 같은 분류 안의 이웃 용어다. 짝마다 둘을 가르는 기준을 한 단어로 잡아 두면 시험장에서 빠르게 구분된다.

| 짝                        | 가르는 기준              | 앞 용어                                 | 뒤 용어                                     |
| ------------------------- | ------------------------ | --------------------------------------- | ------------------------------------------- |
| 동등 분할 / 경계값 분석   | 어느 값을 고르는가       | 구간마다 대표값 하나                    | 구간의 경계와 바로 바깥 값                  |
| 드라이버 / 스텁           | 무엇을 대신하는가        | 상위 모듈 대신 하위 모듈을 호출(상향식) | 하위 모듈 대신 호출을 받음(하향식)          |
| 검증 / 확인               | 무엇과 비교하는가        | 명세대로 만들었는가(Verification)       | 사용자가 원하는 것을 만들었는가(Validation) |
| 알파 테스트 / 베타 테스트 | 어디서 하는가            | 개발자 환경에서 사용자가                | 사용자 환경에서 사용자가                    |
| DELETE / DROP             | 무엇이 사라지는가        | 행(테이블 구조는 남음)                  | 테이블 구조까지                             |
| WHERE / HAVING            | 무엇을 거르는가          | 그룹으로 묶기 전의 행                   | GROUP BY로 묶은 뒤의 그룹                   |
| 피싱 / 파밍               | 사용자를 어떻게 보내는가 | 가짜 링크를 눌러 이동하게 유도          | DNS나 hosts 파일을 바꿔 정상 주소도 가짜로  |
| 정적 분석 / 동적 분석     | 실행하는가               | 코드를 실행하지 않고 검사               | 프로그램을 실행하며 검사                    |

### 외우는 방법

용어는 필기 공부에서 이미 한 번 본 것이므로, 실기에서는 방향과 단위를 바꿔 반복한다.

**방향을 설명에서 용어로 바꾼다.** 용어를 보고 설명을 떠올리는 연습은 필기(재인) 수준에서 멈춘다. 실기는 설명을 보고 용어를 꺼내야 하므로 연습도 같은 방향이어야 한다.

1. 요약 노트의 용어 열을 종이로 가리고, 설명만 읽은 뒤 용어를 빈 종이에 쓴다
2. 가린 종이를 걷어 철자까지 대조한다. 틀리거나 떠오르지 않은 용어에 표시한다
3. 그날 끝에 표시한 용어만 다시 같은 방식으로 쓴다
4. 다음 날 시작할 시각에 전날 표시한 용어부터 다시 쓴다

**묶음 단위로 외운다.** 용어 하나를 따로 외우면 시험장에서 이웃 용어와 섞인다. 같은 분류의 용어를 한 표에 모으고, 표 전체를 한 번에 재현하는 연습을 한다.

| 묶음                 | 개수 | 재현 연습                                                |
| -------------------- | ---: | -------------------------------------------------------- |
| 결합도 (약한 것부터) |    6 | 자료, 스탬프, 제어, 외부, 공통, 내용을 순서대로 쓰기     |
| 응집도 (강한 것부터) |    7 | 기능, 순차, 교환, 절차, 시간, 논리, 우연을 순서대로 쓰기 |
| 블랙박스 테스트 기법 |    5 | 기법 이름과 고르는 값을 한 줄씩 쓰기                     |
| 트랜잭션 특성 ACID   |    4 | 영문 첫 글자, 영문, 우리말을 세 칸으로 쓰기              |
| GoF 생성 패턴        |    5 | 패턴 이름을 영문 철자로 쓰기                             |

순서가 있는 묶음은 첫 글자를 이어 읽는 방법이 유효하다. 결합도를 약한 것부터 "자스제외공내"(자료, 스탬프, 제어, 외부, 공통, 내용)로 외우면, 시험장에서 첫 글자만 떠올려도 여섯 개를 순서대로 복원할 수 있다. 각 묶음의 개념 설명은 [실기 요구사항·설계·테스트](/memo/eip-practical-design-test)와 [실기 보안·네트워크·신기술 용어](/memo/eip-practical-security-network)에 있다.

## 코드 읽기 유형

C, Java, Python 코드를 주고 출력값을 쓰게 하는 문제다. 코드를 작성하라는 문제는 거의 없고, 이미 작성된 코드를 실행했다고 가정하고 결과를 쓴다. 출력값은 하나의 숫자나 문자열이므로 채점 기준이 명확하고, 손으로 끝까지 추적하면 확실하게 맞힐 수 있는 문항이다.

### 변수 추적 표

코드 문제를 푸는 기본 방법은 ==변수 추적 표==를 그리는 것이다. 반복문 한 바퀴마다, 함수 호출 한 번마다 변수 값이 어떻게 바뀌는지 표에 한 줄씩 적는다.

![코드 문제는 변수 추적 표를 그려 푼다](./images/eip-practical-overview-trace.svg '반복마다 i, 조건, s를 한 줄씩 적으면 continue로 건너뛴 회차도 놓치지 않는다')

머릿속으로만 따라가면 `continue`로 건너뛴 회차나 후위 증감 연산자(`i++`)가 값을 바꾸는 시점을 놓치기 쉽다. 표를 그리면 시간이 조금 더 걸리지만 실수가 크게 줄어든다. 위 코드는 gcc로 컴파일해 실행하면 `10`을 출력한다.

추적 표를 그리는 순서는 언어와 상관없이 같다.

1. 코드에 등장하는 변수를 표의 열로 만든다. 반복 조건식도 열로 하나 둔다
2. 변수 초깃값을 첫 줄에 적는다
3. 한 줄을 실행할 때마다 값이 바뀐 변수만 새 값으로 적는다
4. 출력문을 만나면 출력되는 글자를 별도 칸에 공백과 줄바꿈까지 그대로 적는다
5. 반복 조건이 거짓이 되는 줄까지 적고 종료한다

### C: 후위 증감과 정수 나눗셈

```c
#include <stdio.h>

int main(void) {
    int a[5] = {3, 8, 5, 6, 1};
    int i = 0, s = 0, k;
    while (i < 5) {
        k = a[i++];
        if (k % 2 == 0) continue;
        s += k / 2;
    }
    printf("%d %d\n", s, i);
    printf("%d %.1f\n", s / 2, (double)s / 2);
    return 0;
}
```

함정은 두 군데다. `a[i++]`는 현재 `i`로 원소를 읽은 뒤에 `i`를 1 늘린다. 그리고 `k / 2`는 정수끼리의 나눗셈이므로 소수점 아래를 버린다. `continue`가 증감보다 뒤에 있어서 짝수 원소를 건너뛰어도 `i`는 이미 늘어나 있다.

| 회차 | 읽기 전 i | k = a[i++] | 읽은 뒤 i | k % 2 == 0   | k / 2 |   s |
| ---: | --------: | ---------: | --------: | ------------ | ----: | --: |
|    1 |         0 |          3 |         1 | 거짓         |     1 |   1 |
|    2 |         1 |          8 |         2 | 참, continue |       |   1 |
|    3 |         2 |          5 |         3 | 거짓         |     2 |   3 |
|    4 |         3 |          6 |         4 | 참, continue |       |   3 |
|    5 |         4 |          1 |         5 | 거짓         |     0 |   3 |

`i`가 5가 되어 `i < 5`가 거짓이므로 반복이 끝난다. 두 번째 `printf`에서 `s / 2`는 정수 나눗셈이라 `1`이고, `(double)s / 2`는 `s`를 실수로 바꾼 뒤 나누므로 `1.5`다. gcc로 실행한 출력은 다음과 같다.

```text
3 5
1 1.5
```

### C: 재귀 호출 추적

재귀 함수는 추적 표 대신 호출 그림을 그린다. 호출이 내려가는 방향과 값이 돌아오는 방향을 나눠 적어야 출력 순서가 보이기 때문이다.

```c
#include <stdio.h>

void bin(int n) {
    if (n > 1) bin(n / 2);
    printf("%d", n % 2);
}

int main(void) {
    bin(13);
    printf("\n");
    return 0;
}
```

`printf`가 재귀 호출 뒤에 있으므로, 가장 깊은 호출부터 출력한다. 13을 2로 나눈 몫을 따라 내려가면 `bin(13)`, `bin(6)`, `bin(3)`, `bin(1)` 순서로 호출이 쌓이고, `bin(1)`에서 더 내려가지 않는다. 그 뒤 쌓인 순서의 반대로 하나씩 돌아오며 나머지를 출력한다.

![bin(13) 재귀 호출 추적](./images/eip-practical-overview-recursion.svg '호출은 13, 6, 3, 1 순서로 내려가고, 출력은 1, 3, 6, 13의 나머지 순서로 나온다')

| 복귀 순서 | 실행 중인 호출 | n % 2 | 지금까지 출력 |
| --------: | -------------- | ----: | ------------- |
|         1 | bin(1)         |     1 | 1             |
|         2 | bin(3)         |     1 | 11            |
|         3 | bin(6)         |     0 | 110           |
|         4 | bin(13)        |     1 | 1101          |

실행 결과는 `1101`이고, 13을 2진수로 쓴 값과 같다. 만약 `printf`가 재귀 호출 앞에 있었다면 출력 순서가 뒤집혀 `1011`이 된다. 재귀 문제에서는 출력문이 재귀 호출의 앞인지 뒤인지를 가장 먼저 확인한다. 팩토리얼·피보나치처럼 반환값을 계산하는 재귀는 [실기 C 코드 읽기](/memo/eip-practical-c)에서 다룬다.

### Java: 동적 바인딩과 필드

```java
class Parent {
    int x = 10;
    int get() { return x; }
    void show() { System.out.print(get() + " "); }
}

class Child extends Parent {
    int x = 20;
    @Override
    int get() { return x * 2; }
}

public class Main {
    public static void main(String[] args) {
        Parent p = new Child();
        p.show();
        System.out.print(p.x + " ");
        System.out.println(((Child) p).x);
    }
}
```

Java 문제의 핵심 함정은 ==메서드는 실제 객체의 타입을, 필드는 변수의 선언 타입을 따른다==는 규칙이다. 메서드 호출 대상을 실행 중에 실제 객체 기준으로 정하는 방식을 동적 바인딩이라고 한다.

| 문장              | 변수의 선언 타입 | 실제 객체 | 결정 기준                    | 결과 |
| ----------------- | ---------------- | --------- | ---------------------------- | ---: |
| `p.show()`        | Parent           | Child     | show는 Parent에만 있음       |      |
| show 안의 `get()` | Parent           | Child     | 메서드: 실제 객체 Child.get  |   40 |
| `p.x`             | Parent           | Child     | 필드: 선언 타입 Parent.x     |   10 |
| `((Child) p).x`   | Child            | Child     | 필드: 형 변환한 타입 Child.x |   20 |

`show()`는 Parent에 정의되어 있지만, 그 안에서 부르는 `get()`은 실제 객체인 Child의 메서드가 실행된다. Child의 `get()` 안에 있는 `x`는 Child의 필드 20이므로 40을 반환한다. java로 실행한 출력은 다음과 같다.

```text
40 10 20
```

### Python: 슬라이싱 끝 인덱스와 나눗셈

```python
nums = [5, 2, 9, 4, 7, 1]
a = nums[1:4]
b = nums[::-2]
c = nums[-3:]
total = sum(a) // len(a)
print(a, b, c)
print(total, sum(a) / len(a))
s = "PROGRAM"
print(s[2:5], s[-1], s[::3])
```

슬라이싱 `[시작:끝:간격]`에서 끝 인덱스의 원소는 포함하지 않는다. 간격이 음수이면 시작과 끝을 생략하면 마지막 원소부터 거꾸로 간다. Python의 `/`는 정수끼리 나눠도 실수를 내고, `//`가 몫만 낸다.

| 식           | 고르는 인덱스 | 결과        |
| ------------ | ------------- | ----------- |
| `nums[1:4]`  | 1, 2, 3       | `[2, 9, 4]` |
| `nums[::-2]` | 5, 3, 1       | `[1, 4, 2]` |
| `nums[-3:]`  | 3, 4, 5       | `[4, 7, 1]` |
| `15 // 3`    |               | `5`         |
| `15 / 3`     |               | `5.0`       |
| `s[2:5]`     | 2, 3, 4       | `OGR`       |
| `s[-1]`      | 6             | `M`         |
| `s[::3]`     | 0, 3, 6       | `PGM`       |

python3로 실행한 출력은 다음과 같다. 리스트는 대괄호와 쉼표 뒤 공백까지 출력되고, `15 / 3`은 나누어떨어져도 `5.0`으로 출력된다.

```text
[2, 9, 4] [1, 4, 2] [4, 7, 1]
5 5.0
OGR M PGM
```

| 정수 나눗셈        | C·Java | `7 / 2`                   | `3`              | 수학의 3.5로 계산                     |
| 형 변환 뒤 나눗셈  | C      | `(double)3 / 2`           | `1.5`            | 괄호 위치를 확인하지 않음             |
| 동적 바인딩        | Java   | `Parent p = new Child();` | Child의 메서드   | 선언 타입의 메서드로 착각             |
| 필드는 정적 결정   | Java   | `p.x`                     | Parent의 x       | 메서드 규칙을 필드에도 적용           |
| 문자열 연결 순서   | Java   | `1 + 2 + "A"`             | `3A`             | 모두 문자열 연결로 착각               |
| 슬라이싱 끝 인덱스 | Python | `nums[1:4]`               | 인덱스 1~3       | 끝 인덱스까지 포함                    |
| 나눗셈 결과 타입   | Python | `4 / 2`                   | `2.0`            | C처럼 정수로 착각                     |
| 음수의 몫          | Python | `-7 // 2`                 | `-4`             | 0 쪽으로 버린다고 착각(Python은 내림) |

마지막 줄의 `-7 // 2`는 python3에서 실제로 `-4`를 출력한다. Python의 `//`는 소수점 아래를 버리는 것이 아니라 더 작은 정수로 내린다. 각 언어의 함정을 더 많은 예제로 확인하려면 [실기 C 코드 읽기](/memo/eip-practical-c)와 [실기 Java·Python 코드 읽기](/memo/eip-practical-java-python)를 본다.

### SQL 실행 순서

SQL 문은 SELECT부터 쓰지만, 데이터베이스는 FROM부터 처리한다. 결과 행 수를 묻는 문제는 실행 순서대로 각 단계가 끝난 뒤 남는 행 수를 적어 나가면 틀리지 않는다.

```sql
SELECT 부서, COUNT(*) AS 인원
FROM 사원
WHERE 급여 >= 300
GROUP BY 부서
HAVING COUNT(*) >= 2;
```

![SQL 실행 순서와 단계별 행 수](./images/eip-practical-overview-sql-order.svg 'FROM 6행, WHERE 4행, GROUP BY 3그룹, HAVING 1그룹을 거쳐 SELECT가 1행을 낸다')

| 실행 순서 | 절                   | 남는 것                              |
| --------: | -------------------- | ------------------------------------ |
|         1 | FROM 사원            | 6행                                  |
|         2 | WHERE 급여 >= 300    | 강민, 나래, 라희, 마루 4행           |
|         3 | GROUP BY 부서        | 개발 2명, 영업 1명, 인사 1명의 3그룹 |
|         4 | HAVING COUNT(*) >= 2 | 개발 1그룹                           |
|         5 | SELECT               | 부서와 인원 열만 남긴 1행            |
|         6 | ORDER BY             | 이 예제에는 없음                     |

sqlite3 실행 결과는 다음과 같다.

```text
부서  인원
----  ----
개발     2
```

실행 순서를 알면 "SELECT에서 붙인 별칭을 WHERE에서 쓸 수 없는 이유"도 설명된다. WHERE는 SELECT보다 먼저 실행되므로 그 시점에는 별칭이 아직 없다.

### 빈칸 채우기

> 다음 [학생] 테이블에서 학과별 학생 수가 3명 이상인 학과만 조회하는 SQL 문의 빈칸을 채우시오.
>
> `SELECT 학과, COUNT(*) FROM 학생 GROUP BY 학과 ( ① ) COUNT(*) >= 3;`

빈칸에 들어갈 키워드는 `HAVING`이다. `WHERE`는 그룹으로 묶기 전의 행을 거르고, `HAVING`은 `GROUP BY`로 묶은 뒤의 그룹을 거른다. 집계 함수(`COUNT`, `SUM`, `AVG`)가 조건에 들어 있으면 그룹이 만들어진 뒤에야 계산할 수 있으므로 `HAVING`이다. 빈칸 문제는 빈칸 앞뒤의 절을 보고 실행 순서상 어느 자리인지 판단하면 키워드가 정해진다.

| 빈칸 앞뒤의 모양                | 들어갈 키워드 |
| ------------------------------- | ------------- |
| `GROUP BY 열 ( ) 집계함수 조건` | `HAVING`      |
| `FROM 테이블 ( ) 행 조건`       | `WHERE`       |
| `( ) BY 열 DESC`                | `ORDER`       |
| `SELECT ( ) 열` (중복 제거)     | `DISTINCT`    |
| `UPDATE 테이블 ( ) 열 = 값`     | `SET`         |
| `INSERT ( ) 테이블 VALUES (…)`  | `INTO`        |

### 결과 행 수 쓰기

행 수 문제에서 가장 많이 틀리는 지점은 NULL이다. NULL은 "값이 없음"을 뜻하는 표시이고, 어떤 값과 비교해도 참이 되지 않는다.

```sql
SELECT DISTINCT 부서 FROM 사원;
SELECT COUNT(*) FROM 사원 WHERE 부서 <> '개발';
SELECT COUNT(*), COUNT(부서), COUNT(DISTINCT 부서) FROM 사원;
SELECT COUNT(*) FROM 사원 WHERE 부서 = NULL;
```

| 질의                   | 실행 결과 | 이유                                               |
| ---------------------- | --------- | -------------------------------------------------- |
| `SELECT DISTINCT 부서` | 4행       | 개발, 영업, 인사에 NULL도 한 행으로 나온다         |
| `WHERE 부서 <> '개발'` | 3         | 바다의 NULL은 `<>` 비교에서도 참이 아니어서 빠진다 |
| `COUNT(*)`             | 6         | 행 자체를 집계한다                                 |
| `COUNT(부서)`          | 5         | 열 값이 NULL인 행은 집계하지 않는다                |
| `COUNT(DISTINCT 부서)` | 3         | NULL을 빼고 서로 다른 값만 집계한다                |
| `WHERE 부서 = NULL`    | 0         | NULL 비교는 `IS NULL`로 써야 한다                  |

같은 NULL이 `DISTINCT`에서는 한 행으로 나오고 `COUNT(열)`에서는 빠진다. 행 수 문제에 NULL이 들어 있는 표가 나오면, NULL 행에 먼저 표시를 하고 각 절이 그 행을 어떻게 다루는지 따로 확인한다.

### 쿼리 직접 작성

요구사항을 문장으로 주고 SQL 문 전체를 쓰게 하는 형태다.

> 사원 테이블에서 부서가 없는 사원을 제외하고, 부서별 평균 급여를 평균 급여가 높은 순으로 조회하는 SQL 문을 작성하시오. 평균 급여 열의 별칭은 평균급여로 한다.

요구사항 문장을 절 단위로 쪼갠 뒤, SELECT를 마지막에 채우는 순서로 쓴다.

| 요구사항 조각               | 대응하는 절              |
| --------------------------- | ------------------------ |
| 사원 테이블에서             | `FROM 사원`              |
| 부서가 없는 사원을 제외하고 | `WHERE 부서 IS NOT NULL` |
| 부서별                      | `GROUP BY 부서`          |
| 평균 급여 (별칭 평균급여)   | `AVG(급여) AS 평균급여`  |
| 평균 급여가 높은 순으로     | `ORDER BY 평균급여 DESC` |

```sql
SELECT 부서, AVG(급여) AS 평균급여
FROM 사원
WHERE 부서 IS NOT NULL
GROUP BY 부서
ORDER BY 평균급여 DESC;
```

```text
부서  평균급여
----  --------
개발     365.0
영업     315.0
인사     300.0
```

ORDER BY는 SELECT 뒤에 실행되므로 별칭 `평균급여`를 쓸 수 있다. 직접 작성 문제는 문장 끝의 세미콜론, 문자열의 작은따옴표, `IS NOT NULL`의 철자처럼 문법 요소 하나만 빠져도 오답이 될 수 있으므로 다 쓴 뒤 절 순서와 기호를 다시 확인한다.

### 관계대수·정규화·이상 현상의 이름 묻기

SQL 묶음에는 SQL 문 대신 이론 용어의 이름을 묻는 문항도 들어간다. 형태는 용어 쓰기와 같고, 기호나 조건을 보고 이름을 쓴다.

| 문제가 주는 것                                              | 답                |
| ----------------------------------------------------------- | ----------------- |
| 기호 σ, 조건을 만족하는 튜플(행)만 고르는 연산              | 셀렉트(Select)    |
| 기호 π, 지정한 속성(열)만 남기는 연산                       | 프로젝트(Project) |
| 기호 ⋈, 공통 속성으로 두 릴레이션을 합치는 연산             | 조인(Join)        |
| 기호 ÷, 다른 릴레이션의 모든 값과 관련된 튜플을 고르는 연산 | 디비전(Division)  |
| 부분 함수 종속을 제거한 정규형                              | 제2정규형(2NF)    |
| 이행 함수 종속을 제거한 정규형                              | 제3정규형(3NF)    |
| 결정자이면서 후보 키가 아닌 것을 제거한 정규형              | BCNF              |
| 새 데이터를 넣으려면 원하지 않는 값도 함께 넣어야 하는 현상 | 삽입 이상         |
| 한 행을 삭제하면 필요한 정보까지 함께 사라지는 현상         | 삭제 이상         |
| 같은 정보가 여러 행에 있어 일부만 고치면 모순이 생기는 현상 | 갱신 이상         |

관계대수 기호는 생김새가 비슷하지 않으므로 기호와 이름을 짝으로 외우면 된다. 정규형은 "무엇을 제거하는가"가 단계마다 하나씩 다르므로, 정규형 이름과 제거 대상을 순서대로 쓰는 연습을 한다. 개념의 예제와 실행 결과는 [실기 SQL 응용](/memo/eip-practical-sql)에서 다룬다.

### 출력 형식 확인

코드 문제의 답은 화면에 찍히는 글자 그대로다. 출력문이 만드는 공백과 줄바꿈을 한 칸씩 확인한다.

![출력 형식에서 공백과 줄바꿈을 확인하는 방법](./images/eip-practical-overview-output-format.svg '숫자 뒤 공백, 쉼표 뒤 공백, 문자열 연결 순서까지 출력의 일부다')

아래 세 프로그램은 각각 gcc, java, python3로 실행했다.

```c
for (int i = 1; i <= 3; i++) printf("%d ", i);
printf("|\n");
for (int i = 1; i <= 3; i++) printf("%d\n", i);
printf("%3d|%-3d|%03d\n", 7, 7, 7);
```

```text
1 2 3 |
1
2
3
  7|7  |007
```

`%3d`는 세 칸 폭에서 오른쪽 정렬, `%-3d`는 왼쪽 정렬, `%03d`는 빈칸을 0으로 채운다. 첫 줄의 `3` 뒤에도 공백이 있다는 점을 `|`로 확인할 수 있다.

```java
System.out.println("A" + 1 + 2);
System.out.println(1 + 2 + "A");
System.out.println('A' + 1);
System.out.print("x");
System.out.print("y");
System.out.println();
System.out.println(7 / 2 + " " + 7 % 2 + " " + 7.0 / 2);
```

```text
A12
3A
66
xy
3 1 3.5
```

`+`는 왼쪽부터 계산한다. 문자열이 먼저 나오면 뒤의 숫자도 문자열로 이어 붙고, 숫자가 먼저 나오면 숫자끼리 더한 뒤 문자열을 붙인다. `'A' + 1`은 문자 A의 코드값 65에 1을 더한 정수 66이다. `print`는 줄을 바꾸지 않고 `println`만 줄을 바꾼다.

```python
print(1, 2, 3)
print([1, 2, 3])
print("a", "b", sep="")
print("x", end="")
print("y")
print(4 / 2, 7 // 2, -7 // 2)
print({"k": 1}, (1,))
print("%d-%s" % (5, "z"))
```

```text
1 2 3
[1, 2, 3]
ab
xy
2.0 3 -4
{'k': 1} (1,)
5-z
```

`print`는 인자 사이에 공백 하나(`sep`)를, 끝에 줄바꿈(`end`)을 넣는다. `sep=""`이나 `end=""`가 있으면 그 기본값이 바뀐다. 딕셔너리는 작은따옴표와 콜론 뒤 공백까지, 원소 하나짜리 튜플은 쉼표까지 출력된다.

> [!TIP] 부분 점수
> 답이 여러 개인 문항(예: 빈칸 ①②③을 모두 채우는 문항)은 맞힌 빈칸만큼 부분 점수를 주는 경우가 있다. 모르는 빈칸이 있어도 아는 빈칸은 끝까지 채운다.

## 시험장

### 준비물과 규칙

한국산업인력공단의 2024년도 국가기술자격 검정 시행계획 공고에 실린 필답형 실기 관련 규정은 다음과 같다.

| 항목        | 규정                                                                                                      |
| ----------- | --------------------------------------------------------------------------------------------------------- |
| 신분증      | 공단 인정 신분증을 지참하지 않으면 해당 시험이 정지(퇴실)되고 무효 처리된다                               |
| 필기구      | 주관식 답안은 검은색 필기구만 쓸 수 있다. 연필과 유색 필기구는 쓸 수 없다                                 |
| 지워지는 펜 | 지워지는 볼펜류는 답안 작성에 쓸 수 없다                                                                  |
| 답안 정정   | 필답형 답안을 고치려면 수정테이프를 쓸 수 있다                                                            |
| 시계        | 시험 중에는 통신 기능과 전자식 화면이 없는 아날로그 손목시계만 착용·소지할 수 있다                        |
| 전자기기    | 소지가 금지된 전자기기를 소지하거나 사용하면 부정행위로 처리되고 당해 시험이 무효가 된다                  |
| 입실 시각   | 필답형 시험실 입실은 시험 시작 30분 전이다. 기사 1부는 09:00 입실·09:30 시작, 2부는 13:00 입실·13:30 시작 |
| 시행일      | 기사 제1회 필답형 실기는 시행 기간이 시작되는 첫 토요일에 전국에서 동시에 치른다                          |

> [!CAUTION] 지워지는 볼펜
> 마찰열로 지워지는 볼펜은 검은색이어도 쓸 수 없다. 평소 공부에 쓰던 펜이 이 종류라면 시험용 검은색 볼펜을 따로 준비한다.

시험지를 받으면 표지의 수험자 유의사항부터 읽는다. 답을 쓰는 위치, 계산에 쓸 수 있는 공간, 정정 방법이 그 회차 기준으로 적혀 있다. 변수 추적 표와 SQL 단계별 행 수는 허용된 공간에 쓰고, 답란에는 최종 답만 옮겨 적는다.

### 시간 배분

2시간 30분 동안 20문항 안팎을 푸니 문항당 7분 정도가 주어진다. 용어 문제는 알면 1분, 모르면 아무리 고민해도 떠오르지 않는 경우가 많다. 반대로 코드 문제는 시간을 들이면 맞힐 수 있다. 그래서 확실한 점수를 먼저 확보하고, 시간이 드는 문제를 가운데에 둔다.

![실기 150분 시간 배분 예시](./images/eip-practical-overview-exam-timeline.svg '용어 1차와 SQL로 50분, 코드 읽기에 50분, 남은 용어와 점검에 45분을 쓴다')

| 구간     | 시간 | 하는 일                                                        |
| -------- | ---: | -------------------------------------------------------------- |
| 훑기     |  5분 | 전체 문항 수와 유형을 확인하고, 코드·SQL 문항 번호에 표시한다  |
| 용어 1차 | 25분 | 바로 쓸 수 있는 용어 문제만 답을 쓴다                          |
| SQL      | 25분 | 표가 작아서 실행 순서대로 직접 결과를 계산할 수 있다           |
| 코드     | 50분 | 여백에 변수 추적 표나 재귀 호출 그림을 그린다                  |
| 용어 2차 | 25분 | 비워 둔 용어 문제로 돌아가 떠오르는 용어를 쓴다                |
| 점검     | 20분 | 문항 번호, 약어 형태, 순서, 출력 공백과 줄바꿈을 다시 확인한다 |

용어 2차에서도 끝내 떠오르지 않는 문항은 비슷한 용어라도 쓴다. 빈칸으로 두면 0점이지만, 같은 분류의 용어를 쓰면 맞을 가능성이 남는다. 점검 구간에서는 코드 문항의 답을 다시 계산하지 말고, 출력 형식(공백, 줄바꿈, 대괄호, 소수점)만 확인한다. 계산을 처음부터 다시 하면 시간이 모자라고, 처음 계산과 다른 값이 나오면 어느 쪽이 맞는지 판단할 근거도 없다.

## 필기 합격 발표부터 실기까지

2024년 제1회 일정에서 필기 합격자 발표는 3월 13일, 실기 원서 접수는 3월 26일부터 29일까지, 실기 시험은 4월 27일(토)이다. 발표 다음 날부터 시험 전날까지 44일, 발표일부터 시험일까지 45일이다. 이 기간을 유형별로 나누면 다음과 같이 계획할 수 있다.

![필기 합격 발표부터 실기 시험까지 기간 활용 예시](./images/eip-practical-overview-prep-period.svg '코드 읽기와 SQL을 먼저 끝내고, 용어 암기에 가장 긴 기간을 둔 뒤 모의 시험으로 마무리한다')

| 단계      | 기간        | 일수 | 할 일                                                                                                 |
| --------- | ----------- | ---: | ----------------------------------------------------------------------------------------------------- |
| 코드 읽기 | 3.14 ~ 3.24 |   11 | C 5일, Java 3일, Python 3일. 언어마다 함정 유형을 정리하고 추적 표로 출력값 계산                      |
| SQL       | 3.25 ~ 3.31 |    7 | 실행 순서대로 행 수 적기, NULL 처리, 쿼리 작성, 관계대수 기호와 정규형 이름. 이 기간에 실기 원서 접수 |
| 용어 암기 | 4.1 ~ 4.17  |   17 | 12개 능력단위를 묶음으로 나눠 설명에서 용어 방향으로 반복                                             |
| 모의 시험 | 4.18 ~ 4.24 |    7 | 하루 한 회씩 150분을 재고 풀고, 틀린 답을 답안 작성 규칙 표와 대조                                    |
| 점검      | 4.25 ~ 4.26 |    2 | 헷갈리는 짝 비교 표와 출력 형식 규칙만 다시 확인                                                      |

코드 읽기와 SQL을 앞에 두는 이유는 한 번 익히면 잘 잊히지 않기 때문이다. 용어는 범위가 가장 넓고 잊기 쉬우므로 시험에 가까운 기간에 둔다. 용어 17일은 다시 묶음 단위로 나눌 수 있다.

| 기간        | 묶음                                     | 해당 능력단위                                    |
| ----------- | ---------------------------------------- | ------------------------------------------------ |
| 4.1 ~ 4.5   | 요구사항, UML, 화면 설계, 디자인 패턴    | 요구사항 확인, 화면 설계, 서버 프로그램 구현     |
| 4.6 ~ 4.9   | 테스트 기법, 통합 테스트, 형상·버전 관리 | 애플리케이션 테스트 관리, 제품 소프트웨어 패키징 |
| 4.10 ~ 4.11 | EAI, 인터페이스, 데이터베이스 이론       | 통합 구현, 인터페이스 구현, 데이터 입출력 구현   |
| 4.12 ~ 4.15 | 보안 공격, 보안 솔루션, 암호             | 소프트웨어 개발 보안 구축                        |
| 4.16 ~ 4.17 | 운영체제, 네트워크, 신기술               | 응용 SW 기초 기술 활용                           |

새 묶음을 시작하는 날에도 전날까지의 묶음에서 표시해 둔 용어를 먼저 다시 쓴다. 이 방식이면 앞쪽 묶음은 4월 17일까지 여러 번 반복된다.

> [!IMPORTANT] 기간이 짧은 경우
> 45일 계획은 기간을 넉넉히 쓰는 경우의 예시다. 기간이 1주일뿐이라면 단계의 순서는 그대로 두고 일수만 줄인다. 앞의 사흘에 코드와 SQL을, 나머지 나흘에 용어 반복을 두는 식이다. 필기를 1주일 동안 준비한 과정은 [필기 1주일 합격 후기](/memo/eip-written-review)에 있다.

## 공부 순서

필기를 막 합격하고 실기를 준비한다면 다음 순서를 추천한다.

| 순서 | 유형      | 이유                                                         |
| ---- | --------- | ------------------------------------------------------------ |
| 1    | 코드 읽기 | 한 번 익히면 잊지 않고, 문항 수가 많으며 확실히 맞힐 수 있다 |
| 2    | SQL       | 문법 범위가 좁아 짧은 시간에 끝낼 수 있다                    |
| 3    | 용어 쓰기 | 범위가 가장 넓고 잊기 쉬우므로 시험 직전까지 반복해서 외운다 |

용어는 필기 공부에서 이미 한 번 본 것이므로, 실기에서는 "설명을 보고 용어를 떠올리는" 방향으로 반복한다. 용어 목록을 보고 설명을 떠올리는 연습만 하면 필기 수준에서 멈춘다. 설명 문장을 가리고 용어를 쓰거나, 용어를 가리고 설명을 읽은 뒤 용어를 소리 내어 말하는 식으로 연습한다.
