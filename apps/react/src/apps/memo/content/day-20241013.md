이 글은 2026년 10월에 git 기록을 다시 읽으며 쓴 회고다. 그날의 커밋 18개와 그 코드를 근거로 썼고, 화면 대신 코드 구조를 그림으로 그렸다.

이날은 아침 8시 32분에 시작해 오후 5시 40분에 끝났다. 오전에는 창과 Dock, 낮에는 블로그 앱과 폴더 나누기, 오후에는 메일 앱을 했다.

## 오전: 앱 상태를 한곳에

첫 커밋 "Fix: music player"는 이름과 달리 `AppContext`와 `Container`를 처음 만든 커밋이다. 앱 13개마다 `{ isRunning, isMinimized, zIndex }`를 두고, 창 틀(제목 표시줄, 신호등, 끌기)은 `Container` 하나가 그린다. 그 위에 Safari 창, 열릴 때 애니메이션, 아이콘을 더했다.

10시 21분과 12시 48분에는 누른 창을 맨 앞으로 올렸다. 모든 앱을 `zIndex` 순으로 줄 세워 0부터 다시 번호를 매기고, 누른 앱에 가장 큰 번호를 준다.

```ts
const bringAppToFront = useCallback(
	(appName: AppName) => {
		const sortedApps = Object.entries(apps).sort(([, a], [, b]) => a.zIndex - b.zIndex);
		setApps((prevState) => {
			const updatedApps = { ...prevState };
			sortedApps.forEach(([name], index) => {
				updatedApps[name as AppName].zIndex = index;
			});
			updatedApps[appName].zIndex = sortedApps.length;
			return updatedApps;
		});
	},
	[apps]
);
```

지금 보면 두 가지가 걸린다. 줄 세우기는 `setApps` 밖의 `apps`로 하고, 바깥 객체만 복사한 채 안쪽 객체의 `zIndex`를 직접 바꾼다. 같은 렌더에서 두 번 부르면 앞의 결과를 모른다.

## 낮: 블로그 앱과 client/server

12시 25분에 블로그 앱을 더했다. 따로 운영하던 블로그(`codingkirby.github.io`)를 창 안에 iframe으로 띄운 것이다. 오후 2시 45분에는 React 앱을 `client/`로 옮기고, 3시 15분에 Express 생성기로 `server/`를 만들었다. 생성기가 만든 jade 템플릿과 `users.js` 경로가 그대로 들어갔다.

![10월 13일의 저장소 구조](./images/day-20241013-structure.svg 'client와 server로 나눴지만 둘은 아직 서로 부르지 않았다')

## 오후: 메일 앱

3시 43분에 Mail 앱을 만들었다. 받은편지함 모양이고, 메일 세 통은 코드에 적은 더미였다. 5시 5분에는 더미 메일을 환영 메일 한 통으로 줄이고, 쓰기 버튼을 `mailto:` 링크로 바꿨다. 5시 40분에 서버에 nodemailer로 Gmail SMTP를 쓰는 `POST /sendMail` 경로를 더했지만, 앱은 이 경로를 부르지 않았다. 이 경로는 이틀 뒤 지워진다([2024년 10월 15일 회고](/memo/day-20241015)).

같은 커밋에서 음악 재생 상태를 `MusicContext`로 꺼냈다. 창을 닫아도 음악은 계속 나와야 해서, 재생 상태를 창 컴포넌트 밖에 두어야 했다.

## 돌아보며

하루에 앱 둘과 서버 하나를 더했지만, 서버와 앱은 이날 한 번도 이어지지 않았다. 서버를 먼저 만들고 쓸 곳을 나중에 찾은 셈이다. 메일 앱이 결국 `mailto:`로 간 것을 보면, 그날 필요했던 것은 서버가 아니라 메일 앱의 모양이었다. 2026년에 메일을 서버로 보내게 한 것은 스팸 막기와 하루 상한까지 정한 뒤였다.
