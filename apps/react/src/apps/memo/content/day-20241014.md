이 글은 2026년 10월에 git 기록을 다시 읽으며 쓴 회고다. 그날의 커밋 8개와 그 코드를 근거로 썼고, 화면 대신 그때의 창 상태 구조를 그림으로 그렸다.

커밋은 새벽 2시 11분부터 6시 42분 사이에 있다. [전날](/memo/day-20241013) 저녁에 만든 `MusicContext`를 정리하는 것으로 시작해, 볼륨, 최소화, 최대화 순서로 갔다.

![2024년 10월 14일 작업 흐름](./images/day-20241014-timeline.svg '새벽 2시와 4~6시에 커밋이 있다')

## 음악을 창 밖으로

2시 11분 커밋은 `MusicPlayer.tsx`의 재생 로직을 `MusicContext`로 옮겼다. 세 파일에서 220줄을 지우고 144줄을 더했다. 재생·일시 정지, 이전·다음 곡, 재생 위치 옮기기, 버퍼링 표시가 모두 Context로 갔다. 창 컴포넌트는 그 값을 그리기만 한다. 곡은 둘(〈센과 치히로의 행방불명〉 OST)이고 주소는 `REACT_APP_MUSIC_URL`에서 받았다.

4시 26분에는 상태 막대의 스피커 아이콘을 누르면 볼륨 창(`VolumeModal`, 57줄)이 뜨게 했다. 볼륨은 `MusicContext`의 0~1 값이다.

## 최소화 애니메이션과 최대화

5시 48분에 최소화 애니메이션을 만들었다. 창의 가운데를 기준으로 `translate`와 `scale(0)`을 0.5초 동안 걸고, `setTimeout` 0.5초 뒤에 최소화 상태로 바꾼다. 창 위치는 `containerPosition_<앱>` 키로 localStorage에 남겨, 다시 열면 그 자리에 뜬다.

```ts
setIsMinimizing(true); // 애니메이션을 트리거
setTimeout(() => {
	minimizeApp(appName);
	setIsMinimizing(false);
	savePositionToStorage(position.x, position.y);
}, 500); // 애니메이션 시간과 맞춰서
```

6시 15분과 42분에는 최대화를 만들었다. 최대화하면 창을 상태 막대(25px) 아래부터 화면 끝까지 키우고, 이전 크기도 `containerSize_<앱>`으로 저장해 되돌릴 때 쓴다.

![10월 14일의 창 상태](./images/day-20241014-structure.svg '앱이 켜졌는지와 창이 보이는지가 isRunning 한 값에 들어 있었다')

## 지금과 비교하면

- **최대화**: 화면 끝까지 키워서 Dock을 덮었다. 2026년 9월 28일에 "최대화 시 Dock 영역 비우기"로 고쳤다([9월 28일 회고](/memo/day-0928)).
- **애니메이션 시간**: CSS 전환 0.5초와 `setTimeout` 500ms를 따로 적어 맞췄다. 지금 창 동작은 `desktop-core`의 순수 함수로 계산한다([창 관리를 core로](/memo/desktop-core-windows)).
- **`isRunning`**: 창을 닫으면 앱도 꺼진 것으로 쳤다. 그래서 배경 음악이 나오는 중에도 음악 창을 닫으면 음악 앱이 "꺼진" 상태였다. 이 구조는 2026년 10월 18일에야 창과 실행으로 나눴다([음악 앱 버그 세 가지](/memo/music-player-fixes), [10월 18일 회고](/memo/day-1018)).
- **음악**: 재생 목록과 셔플·반복은 core의 플레이어 store로 옮겼다([음악을 core로](/memo/desktop-core-music)).

## 돌아보며

음악을 창 밖의 Context로 옮긴 판단은 맞았다. 창을 닫아도 음악이 계속 나와야 했기 때문이다. 그런데 앱 상태 쪽은 그 판단을 따라가지 않았다. 음악은 창 밖에서 살아 있는데, 앱 상태는 여전히 "창이 열려 있다 = 실행 중"이었다. 이 어긋남은 2년 동안 남아 있다가 버그 셋으로 드러났다.
