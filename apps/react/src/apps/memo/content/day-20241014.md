## 음악 재생 상태를 창 컴포넌트 밖으로

2시 11분 커밋은 [전날](/memo/day-20241013) 만든 `MusicContext`에 `MusicPlayer.tsx`의 재생 로직을 옮겼다. 세 파일에서 220줄을 삭제하고 144줄을 추가했다. 재생·일시 정지, 이전·다음 곡, 재생 위치 이동, 버퍼링 표시가 모두 Context로 이동했고, 창 컴포넌트는 Context의 값을 렌더링만 한다. 곡은 두 개(〈센과 치히로의 행방불명〉 OST)이고, 파일 주소는 `REACT_APP_MUSIC_URL` 환경 변수에서 읽는다.

4시 26분에는 상태 막대의 스피커 아이콘을 클릭하면 볼륨 창(`VolumeModal`, 57줄)을 표시하게 했다. 볼륨은 `MusicContext`의 0~1 값이다.

## 창 동작: 최소화 애니메이션, 위치 저장, 최대화

5시 48분에 최소화 애니메이션을 만들었다. 창의 중심을 기준으로 `translate`와 `scale(0)`을 0.5초 동안 적용하고, `setTimeout` 0.5초 뒤에 최소화 상태로 전환한다. 창 위치는 `containerPosition_<앱>` 키로 localStorage에 저장해, 다시 열면 같은 위치에 표시한다.

```ts
setIsMinimizing(true); // 애니메이션을 트리거
setTimeout(() => {
	minimizeApp(appName);
	setIsMinimizing(false);
	savePositionToStorage(position.x, position.y);
}, 500); // 애니메이션 시간과 맞춰서
```

6시 15분과 42분에는 최대화를 구현했다. 최대화하면 창을 상태 막대(25px) 아래부터 화면 끝까지 확장하고, 이전 크기를 `containerSize_<앱>` 키로 저장해 복원할 때 사용한다.

| localStorage 키          | 저장 값        | 사용 시점            |
| ------------------------ | -------------- | -------------------- |
| `containerPosition_<앱>` | 창의 x, y      | 최소화 후 다시 열 때 |
| `containerSize_<앱>`     | 최대화 전 크기 | 최대화를 해제할 때   |

![10월 14일의 창 상태](./images/day-20241014-structure.svg '앱 실행 여부와 창 표시 여부가 isRunning 한 값에 함께 들어 있었다')

## 지금과 비교하면

- **최대화**: 화면 끝까지 확장해서 Dock을 가렸다. 2026년 9월 28일에 "최대화 시 Dock 영역 비우기"로 수정했다([9월 28일 회고](/memo/day-0928)).
- **애니메이션 시간**: CSS 전환 0.5초와 `setTimeout` 500ms를 각각 하드코딩해 일치시켰다. 지금 창 동작은 `desktop-core`의 순수 함수로 계산한다([창 관리를 core로](/memo/desktop-core-windows)).
- **`isRunning`**: 창을 닫으면 앱도 종료된 것으로 처리했다. 그래서 배경 음악이 재생되는 중에도 음악 창을 닫으면 음악 앱이 "종료" 상태였다. 이 구조는 2026년 10월 18일에야 창 표시와 앱 실행 상태로 분리했다([isRunning 정의와 React key·ref 함수 동일성이 일으킨 음악 앱 버그](/memo/music-player-fixes), [10월 18일 회고](/memo/day-1018)).
- **음악**: 재생 목록과 셔플·반복은 core의 플레이어 store로 옮겼다([음악을 core로](/memo/desktop-core-music)).

## 돌아보며

음악을 창 밖의 Context로 옮긴 판단은 적절했다. 창을 닫아도 음악은 계속 재생되어야 하기 때문이다. 그러나 앱 상태는 같은 기준으로 바뀌지 않았다. 음악은 창과 무관하게 재생되는데, 앱 상태는 여전히 "창이 열려 있다 = 실행 중"이었다. 이 불일치는 2년 동안 남아 있다가 버그 세 개로 드러났다.
