폴더는 글 하나가 한 곳에만 들어간다. 'CSS'와 '리팩터링'에 모두 걸치는 글은 폴더로는 묶을 수 없다. macOS 메모는 이럴 때 태그를 쓴다. 본문 아무 데나 `#태그`를 쓰면 그것이 태그가 되고, 사이드바 아래에 태그 묶음이 생긴다.

![태그로 보기](./images/memo-tags.jpg '사이드바 아래의 태그 묶음. 채운 칩은 포함, 테두리·취소선은 제외. 둘 이상 고르면 모두/일부 포함을 고른다')

## 저장하지 않는다

태그 칸을 따로 두지 않았다. 본문이 곧 태그의 출처다. 그래서 DB도, API도, 저장소의 Markdown 형식도 그대로다. 글을 고쳐서 `#태그`를 지우면 태그도 사라진다. 따로 맞춰 둘 것이 없다.

```ts
/** #태그: 줄 처음이나 공백·여는 괄호 뒤의 #, 바로 뒤에 이름 (# 뒤에 공백이 있으면 제목이다) */
export const TAG_PATTERN = /(^|[\s(（[])#([\p{L}\p{N}_-]+)/gu;
```

`\p{L}`(모든 글자)이라 한글 태그도 된다. `#` 바로 뒤에 공백이 있으면 Markdown 제목(`# 제목`)이므로 태그가 아니다.

## 태그가 아닌 `#`

규칙의 대부분은 "태그가 아닌 #"을 거르는 일이었다. 이 블로그에는 CSS 글이 많아서 `#edbb4d` 같은 색이 자주 나온다. 커밋 이야기에는 `#14` 같은 이슈 번호도 나온다.

| 쓴 것                                | 태그?  | 이유                                 |
| ------------------------------------ | ------ | ------------------------------------ |
| `#리팩터링`, `(#CSS)`                | 예     |                                      |
| `# 제목`                             | 아니오 | `#` 뒤에 공백 (제목)                 |
| 코드 블록·`인라인 코드` 안의 `#코드` | 아니오 | 코드                                 |
| `[글](#section)`, `https://a.b/#x`   | 아니오 | 링크 주소                            |
| `#14`                                | 아니오 | 숫자만 (이슈 번호)                   |
| `#115의`, `#96에서`, `#14로`         | 아니오 | 이슈 번호 + 조사                     |
| `#fff`, `#2b2100`, `#edbb4d`         | 아니오 | 색 (16진수 3·6·8자리)                |
| `C#언어`                             | 아니오 | 단어 가운데 (`#` 앞이 공백이 아니다) |

색을 거르는 규칙 때문에 `#cafe`나 `#face`처럼 16진수 글자로만 된 영어 태그는 쓸 수 없다. 블로그에 색이 나오는 일이 훨씬 많아서 그쪽을 골랐다.

이 규칙을 만든 뒤 지금까지 쓴 글 27편에 돌려 봤다. 태그로 읽힌 것은 하나도 없었다. 본문의 `#`은 모두 코드 블록 안의 색이었다.

### 이슈 번호에 붙은 조사

어느새 메모의 태그 목록에 `#115의`, `#116의`, `#96의`가 나타났다. "#115의 API 변경은…"처럼 이슈 번호 뒤에 조사를 바로 붙여 쓴 문장이었다. 숫자만인 이름은 거르지만, 한국어는 조사를 띄어 쓰지 않아서 `115의`가 이름 전체로 읽혔다.

숫자 뒤에 조사(의, 은, 는, 이, 가, 을, 를, 에, 에서, 으로, 로, 와, 과, 도, 만, 까지, 부터 …)만 붙은 이름도 거르게 했다. `#2026회고`처럼 숫자로 시작해도 뒤가 조사가 아니면 그대로 태그다. 시험에 `#115의 API, #96에서, #14로`를 더했고, 고치기 전 규칙으로 돌리면 세 개가 태그로 나오는 것을 확인했다.

## 세 곳에서 같은 규칙

태그는 세 곳에 보인다. 모두 같은 함수(`tagsInText`)로 찾는다.

- **사이드바의 태그 묶음**: 모든 글의 본문에서 태그를 모아, 글이 많은 태그부터 늘어놓는다. 맨 앞의 '모든 태그'는 태그가 하나라도 있는 글이다
- **읽기 화면**: remark 플러그인이 Markdown 문법 나무의 글자 마디를 쪼개 `<span class="memo-tag">`로 감싼다. 코드·링크 마디는 들어가지 않는다. 누르면 그 태그의 글만 본다
- **편집기**: ProseMirror 꾸밈(decoration)으로 칠하기만 한다. 편집기에서 태그를 누르면 그 자리에 커서가 가야 하므로 다른 화면으로 넘어가지 않는다

## 포함, 제외, 미선택

처음에는 태그를 누르면 그 태그의 글만, 한 번 더 누르면 모든 글로 돌아갔다. macOS 메모는 태그를 누를 때마다 상태가 셋을 돈다.

| 누른 횟수 | 칩 모양               | 뜻                            |
| --------- | --------------------- | ----------------------------- |
| 0         | 회색                  | 고르지 않음                   |
| 1         | 강조 색으로 채움      | 이 태그가 있는 글 (포함)      |
| 2         | 강조 색 테두리·취소선 | 이 태그가 있는 글은 뺌 (제외) |
| 3         | 회색                  | 다시 고르지 않음              |

태그를 둘 이상 고르면 '태그' 옆에 "선택된 태그 중 모두 포함"이 생기고, 누르면 "일부 포함"으로 바꿀 수 있다. 오른쪽의 위아래 chevron 한 쌍은 macOS 팝업 단추처럼 "누르면 고를 것이 펼쳐진다"는 표시다. 포함한 태그가 모두 있어야 하는지(그리고), 하나라도 있으면 되는지(또는)다. 제외한 태그는 어느 쪽이든 그 태그가 있는 글을 뺀다. 목록 위에는 무엇으로 걸렀는지 적는다.

- 하나만 포함: `선택된 태그(#디자인)와 일치하는 메모를 표시합니다.` 제목은 `#디자인`
- 여럿: `3개의 선택된 태그와 모두 일치하는 메모를 표시합니다.` 제목은 `3개의 태그`
- 제외만 있으면 안내 없이 제목만 `1개의 태그`

고른 상태는 `{ 태그: 'include' | 'exclude' }`와 모두/일부 하나로 둔다. 글이 맞는지 보는 함수는 이것뿐이다.

```ts
export function matchesTags(postTags: string[], selection: TagSelection): boolean {
	const has = (name: string) => postTags.some((tag) => sameTag(tag, name));
	if (selection.all) return postTags.length > 0;
	if (namesIn(selection, 'exclude').some(has)) return false;
	const included = namesIn(selection, 'include');
	if (included.length === 0) return true;
	return selection.match === 'all' ? included.every(has) : included.some(has);
}
```

태그로 보는 화면은 폴더로 보는 화면을 그대로 쓴다. 경로 자리에 `'\u0000tags'`를 넣고, 어떤 태그를 골랐는지는 따로 둔다. 폴더 이름에 쓸 수 없는 글자로 시작해서 사용자가 만든 폴더와 겹치지 않는다. 폴더를 고르면 태그 고르기는 풀린다.

본문의 `#디자인`처럼 줄 처음에 쓴 태그는 목록의 미리보기에서 `#`이 지워져 "디자인"으로 보였다. 미리보기를 만들 때 Markdown 제목 표시(`# `)를 걷어 내는 규칙이 `#` 뒤 공백 없이도 걸렸기 때문이다. `#` 뒤에 공백이 있을 때만 걷게 고쳤다.
