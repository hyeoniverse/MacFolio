폴더에는 글 하나가 한 곳에만 속한다. 'CSS'와 '리팩터링'에 모두 해당하는 글은 폴더로 묶을 수 없다. macOS 메모는 이런 경우 태그를 사용한다. 본문의 어느 위치에든 `#태그`를 입력하면 태그가 되고, 사이드바 아래에 태그 그룹이 표시된다. 같은 방식을 MacFolio 메모 앱에 구현했다([#67](https://github.com/hyeoniverse/MacFolio/pull/67)).

## 배경

블로그 글이 늘면서 폴더만으로는 글을 찾기 어려웠다. 예를 들어 [캐스케이드 레이어(`@layer`) 글](/memo/css-layer-reset)은 '프론트엔드' 폴더에 있지만 '리팩터링' 주제이기도 하다. 폴더를 더 세분하면 글의 분류 위치를 정하는 고민만 늘 뿐, 여러 폴더에 걸친 주제는 여전히 묶이지 않았다. 현재 이 블로그의 글 끝마다 `#MacFolio #리팩터링 #CSS` 같은 해시태그 줄을 넣는 규칙도 이 시점부터다.

태그는 10월 1일 저녁에 최근 삭제된 항목·잠금과 함께 작업 목록에 추가했다. 첫 구현 화면의 예시 태그에 개인적인 내용이 포함되어 있어 바로 개발 주제의 예시로 교체했다. 다음 날에는 "선택된 태그를 모두 포함 / 일부 포함" 선택 칸 오른쪽의 화살표를 다른 메뉴와 같은 chevron(⌄)으로 통일했다.

태그 저장 위치는 세 가지를 비교했다.

| 방법                                   | 장점                                    | 단점                                                                             |
| -------------------------------------- | --------------------------------------- | -------------------------------------------------------------------------------- |
| Markdown 머리말에 `tags:` 필드         | 명시적이다                              | 머리말 형식·검증·API·DB 열을 모두 추가해야 한다. 편집기에 별도 입력란이 필요하다 |
| DB에 태그 테이블과 글-태그 연결 테이블 | 쿼리가 빠르다                           | 저장소 Markdown 글은 DB에 없어서 두 출처를 동기화해야 한다                       |
| **본문의 `#태그`를 추출 (선택)**       | 저장 형식이 그대로다. macOS 메모와 같다 | 태그가 아닌 `#`을 제외하는 규칙이 필요하다                                       |

이 블로그 글의 상당수는 저장소의 Markdown 파일이고, 나머지는 서버 DB에 있다. 두 출처를 같은 방식으로 처리하려면 본문에서 추출하는 방법이 가장 단순했다. 그 비용은 제외 규칙이다.

![태그로 보기](./images/memo-tags.jpg '사이드바 아래의 태그 그룹. 채운 칩은 포함, 테두리·취소선은 제외. 둘 이상 선택하면 모두/일부 포함을 선택한다')

## 별도로 저장하지 않는다

태그 필드를 따로 만들지 않았다. 본문이 태그의 유일한 출처다. 그래서 DB, API, 저장소의 Markdown 형식이 모두 그대로다. 글을 수정해 `#태그`를 삭제하면 태그도 사라진다. 별도로 동기화할 데이터가 없다.

```ts
/** #태그: 줄 처음이나 공백·여는 괄호 뒤의 #, 바로 뒤에 이름 (# 뒤에 공백이 있으면 제목이다) */
export const TAG_PATTERN = /(^|[\s(（[])#([\p{L}\p{N}_-]+)/gu;
```

`\p{L}`은 모든 언어의 문자를 뜻하는 [유니코드 속성 이스케이프](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Regular_expressions/Unicode_character_class_escape)라 한글 태그도 인식한다. `#` 바로 뒤에 공백이 있으면 Markdown 제목(`# 제목`)이므로 태그가 아니다.

## 태그가 아닌 `#`

규칙의 대부분은 "태그가 아닌 #"을 제외하는 조건이었다. 이 블로그에는 CSS 글이 많아서 `#edbb4d` 같은 색 값이 자주 나온다. 커밋 기록에는 `#14` 같은 이슈 번호도 나온다.

| 입력                                 | 태그?  | 이유                                 |
| ------------------------------------ | ------ | ------------------------------------ |
| `#리팩터링`, `(#CSS)`                | 예     |                                      |
| `# 제목`                             | 아니오 | `#` 뒤에 공백 (제목)                 |
| 코드 블록·`인라인 코드` 안의 `#코드` | 아니오 | 코드                                 |
| `[글](#section)`, `https://a.b/#x`   | 아니오 | 링크 주소                            |
| `#14`                                | 아니오 | 숫자만 (이슈 번호)                   |
| `#115의`, `#96에서`, `#14로`         | 아니오 | 이슈 번호 + 조사                     |
| `#fff`, `#2b2100`, `#edbb4d`         | 아니오 | 색 (16진수 3·6·8자리)                |
| `C#언어`                             | 아니오 | 단어 가운데 (`#` 앞이 공백이 아니다) |

색을 제외하는 규칙 때문에 `#cafe`나 `#face`처럼 16진수 문자로만 된 영어 태그는 사용할 수 없다. 블로그에 색 값이 나오는 빈도가 훨씬 높아서 색 제외를 우선했다.

이 규칙을 만든 뒤 당시까지 작성한 글 27편에 실행했다. 태그로 인식된 항목은 하나도 없었다. 본문의 `#`은 모두 코드 블록 안의 색 값이었다.

### 이슈 번호에 붙은 조사

이후 메모의 태그 목록에 `#115의`, `#116의`, `#96의`가 표시됐다. "#115의 API 변경은…"처럼 이슈 번호 뒤에 조사를 붙여 쓴 문장이었다. 숫자로만 된 이름은 제외하지만, 한국어는 조사를 띄어 쓰지 않아서 `115의` 전체가 태그 이름으로 인식됐다.

숫자 뒤에 조사(의, 은, 는, 이, 가, 을, 를, 에, 에서, 으로, 로, 와, 과, 도, 만, 까지, 부터 …)만 붙은 이름도 제외하게 했다. `#2026회고`처럼 숫자로 시작해도 뒤가 조사가 아니면 태그로 인식한다. 시험에 `#115의 API, #96에서, #14로`를 추가했고, 수정 전 규칙으로 실행하면 세 개가 태그로 인식되는 것을 확인했다.

필터링은 두 단계다.

1. `tagsOf`: 본문에서 코드 블록, 인라인 코드, 링크 주소, HTML 태그를 공백으로 치환한다.
2. `isTagName`: 남은 텍스트에서 패턴으로 찾은 이름을 한 번 더 검사해 이슈 번호와 색 값을 제외한다.

```ts
const ISSUE_NUMBER = new RegExp(`^\\d+${PARTICLE}?$`);

export function isTagName(name: string): boolean {
	if (ISSUE_NUMBER.test(name)) return false;
	if (/^[0-9a-f]{3}([0-9a-f]{3})?([0-9a-f]{2})?$/i.test(name)) return false;
	return true;
}
```

## 세 곳에서 같은 규칙

![본문 → tagsInText → 세 화면](./images/memo-tags-pipeline.svg '색과 이슈 번호는 제외되고, 남은 태그가 사이드바·읽기 화면·편집기에 같은 규칙으로 표시된다')

태그는 세 곳에 표시된다. 모두 같은 함수(`tagsInText`)로 추출한다. 이 함수와 필터·정렬 함수는 처음에는 `apps/react`에 있었고, 현재는 React와 DOM에 의존하지 않는 순수 함수로 `packages/desktop-core/src/memo/tags.ts`로 옮겼다.

| 위치               | 구현                                                                                                                                                                          | 누르면                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| 사이드바 태그 그룹 | 모든 글의 본문에서 태그를 수집해 글 수가 많은 순으로 나열. 맨 앞의 '모든 태그'는 태그가 하나라도 있는 글                                                                      | 태그 필터 적용                      |
| 읽기 화면          | [remark](https://github.com/remarkjs/remark) 플러그인이 Markdown 구문 트리(mdast)의 텍스트 노드를 분할해 `<span class="memo-tag">`로 감싼다. 코드·링크 노드는 탐색하지 않는다 | 그 태그의 글만 표시                 |
| 편집기             | ProseMirror [데코레이션](https://prosemirror.net/docs/ref/#view.Decorations)으로 스타일만 적용                                                                                | 그 위치에 커서 이동(화면 전환 없음) |

## 포함, 제외, 미선택

처음 구현에서는 태그를 누르면 그 태그의 글만, 한 번 더 누르면 모든 글로 돌아갔다. macOS 메모는 태그를 누를 때마다 세 상태를 순환한다.

| 누른 횟수 | 칩 스타일             | 의미                            |
| --------- | --------------------- | ------------------------------- |
| 0         | 회색                  | 미선택                          |
| 1         | 강조 색으로 채움      | 이 태그가 있는 글 (포함)        |
| 2         | 강조 색 테두리·취소선 | 이 태그가 있는 글은 제외 (제외) |
| 3         | 회색                  | 다시 미선택                     |

태그를 둘 이상 선택하면 '태그' 옆에 "선택된 태그 중 모두 포함"이 표시되고, 누르면 "일부 포함"으로 바꿀 수 있다. 오른쪽의 위아래 chevron 한 쌍은 macOS 팝업 버튼처럼 "누르면 선택지가 펼쳐진다"는 표시다. 모두 포함은 AND(포함한 태그가 모두 있어야 함), 일부 포함은 OR(하나라도 있으면 됨)이다. 제외한 태그는 두 경우 모두 그 태그가 있는 글을 제외한다. 목록 상단에는 적용한 필터를 표시한다.

- 하나만 포함: `선택된 태그(#디자인)와 일치하는 메모를 표시합니다.` 제목은 `#디자인`
- 여럿: `3개의 선택된 태그와 모두 일치하는 메모를 표시합니다.` 제목은 `3개의 태그`
- 제외만 있으면 안내 없이 제목만 `1개의 태그`

선택 상태는 `{ 태그: 'include' | 'exclude' }` 객체와 모두/일부 값 하나로 저장한다. 글의 일치 여부를 판단하는 함수는 다음 하나뿐이다.

```ts
export function matchesTags(postTags: string[], selection: TagSelection): boolean {
	const has = (name: string) => postTags.some((tag) => sameTag(tag, name));
	if (selection.all) return postTags.length > 0;
	if (namesIn(selection, 'exclude').some(has)) return false;
	const included = namesIn(selection, 'include');
	if (included.length === 0) return true;
	return selection.match === 'all' ? included.every(has) : included.some(has);
}
```

태그 보기 화면은 폴더 보기 화면을 그대로 재사용한다. 경로 값으로 `'\u0000tags'`를 사용하고, 선택한 태그는 별도 상태로 저장한다. 폴더 이름에 쓸 수 없는 문자로 시작하므로 사용자가 만든 폴더와 충돌하지 않는다. 폴더를 선택하면 태그 선택은 해제된다.

본문의 `#디자인`처럼 줄 처음에 쓴 태그는 목록 미리보기에서 `#`이 삭제되어 "디자인"으로 표시됐다. 미리보기를 만들 때 Markdown 제목 기호(`# `)를 제거하는 정규식이 `#` 뒤에 공백이 없어도 일치했기 때문이다. `#` 뒤에 공백이 있을 때만 제거하도록 수정했다.

## 남은 것·정리

- 태그는 매번 모든 글의 본문을 탐색해 수집한다. 글 200편 정도에서는 문제없지만, 글이 훨씬 많아지면 목록을 불러올 때 한 번 수집해 캐시하는 방법을 검토해야 한다.
- `#cafe`처럼 16진수 문자로만 된 영어 태그는 사용할 수 없다. 이 블로그에서는 색 값이 훨씬 자주 나와서 이 제약을 허용했다.
- 별도로 저장하지 않는 설계 덕분에 API·DB·저장소 형식을 하나도 바꾸지 않았다. 대신 "무엇이 태그가 아닌가"를 시험 케이스로 계속 추가해야 했다. 조사가 붙은 이슈 번호처럼 한국어 글에서만 생기는 경우가 그 예다.
- 휴대폰 메모의 태그 화면은 이후 iOS 메모처럼 변경했다(`9d712f5bf`). 제목이 태그 이름이 되고, 상단에 가로 스크롤 칩 행이 추가됐다.
