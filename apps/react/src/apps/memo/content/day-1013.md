이날 #187 브랜치의 프로젝트 템플릿 코드는 3만 1천 줄이 늘고 3만 7천 줄이 줄었다. 더한 것보다 지운 것이 많았다. 전날 밤에 넣은 장식을 걷어 내는 것으로 시작해서, 열세 개의 모양을 네 개로 줄였다가, 다시 열 개로 늘렸다.

![10월 13일 작업 흐름](./images/day-1013-timeline.svg '새벽에는 #187의 템플릿과 main의 Sheet·메일, 오후와 밤에는 #187의 저장소 템플릿과 RPG 대화창. 커밋한 시각 기준')

## 템플릿 열셋이 넷이 되고, 다시 열이 되기까지

[#187](https://github.com/hyeoniverse/MacFolio/pull/187)은 시스템 설정에서 프로젝트를 고치는 PR이다. 새 프로젝트의 Safari 페이지는 고른 템플릿으로 그린다. 그 템플릿이 이날 이렇게 바뀌었다.

1. **장식 걷어 내기**: 전날 밤에 넣은 빛 번짐, 그라데이션 글자, 반사, 기울기, 유리 효과, 색 그림자, 떠다니는 카드를 모두 뺐다. 단색 바탕, 큰 글자, 강조색 하나, 얕은 그림자 한 벌만 남겼다. 라이트 테마에서도 어두운 바탕을 쓰던 것은 흰 바탕으로 바꿨다.
2. **열셋을 넷으로**: 모양마다 읽는 데이터가 달라서, 편집 화면에 넣은 칸이 어떤 모양에서는 보이고 어떤 모양에서는 안 보였다. 모든 템플릿이 같은 랜딩 내용(`landingOf`: 히어로, 숫자, 주요 기능, 화면 모음, 쓰는 법, 만든 방식 등)만 읽게 하고, 비어 있는 구역은 빠지게 했다. 그리고 열세 모양을 제품·카드·문서·벤토 네 템플릿으로 줄였다. 이 커밋 하나에서 2만 7천 줄이 줄었다.
3. **넷을 컨셉별로**: 네 템플릿에 각각 참고할 실제 제품을 정했다. 제품은 Apple 제품 페이지, 카드는 Stripe, 문서는 Notion, 벤토는 Framer·Raycast.
4. **다시 열로**: 키노트·매거진·개발자 도구·놀이를 더했고, 오후에는 GitHub 저장소 화면을 흉내 낸 저장소 템플릿을 되살렸다. RPG 대화창까지 열 개다.

예전 모양 이름은 버리지 않았다. 서버에 저장해 둔 값이 `cinema`라면 키노트로, `brutal`이라면 벤토로, 가장 가까운 새 템플릿으로 바꿔 읽는다(`LEGACY_LOOKS`).

![제품 템플릿](./images/day-1013-product.jpg '네 템플릿 중 제품. Apple 제품 페이지처럼 큰 제목과 가운데 정렬, 그 아래 창 틀의 큰 화면. 전날 밤의 랜딩 페이지와 같은 프로젝트다')

저장소 템플릿의 Languages 막대는 실제 GitHub 언어 비율을 그린다. 공개 경로 `GET /github/languages/:owner/:name`이 비율로 바꿔 주는데, 아무 저장소나 묻는 열린 프록시가 되지 않게 사이트 프로젝트가 가리키는 저장소만 받는다. 저장소마다 6시간 캐시하고, GitHub가 응답하지 않으면 이전 값을 쓴다.

## 지운 RPG 배경 테마

RPG 대화창은 이날 두 번 더 바뀌었다. 새벽에는 고전 RPG 화면으로, 밤에는 언더테일처럼 검은 무대에 흰 테두리 대화 상자 하나만 있는 화면으로. 밤의 커밋은 525줄을 더하고 5,027줄을 지웠다. 전날 만든 배경 테마 열네 개, CSS로 그린 픽셀 풍경, 그림 픽셀화, 편집 화면의 대화창 배경 칸과 데이터의 `backdrop`이 모두 빠졌다. 그림은 픽셀화하지 않고 원본 그대로 액자에 띄운다.

![단순해진 RPG 대화창](./images/day-1013-rpg.jpg '밤에 다시 그린 RPG 대화창. 검은 무대, 흰 테두리 액자의 원본 그림, 대화 상자 하나')

## Sheet: 두 번째 공통 부품

main에서는 전날 Modal에 이어 Sheet를 뽑았다. 메일 쓰기, 메일 동작, 음악 지금 재생 중 세 곳이 아래에서 올라오는 시트를 각자 만들고 있었다. 오버레이, 올라오고 내려가는 애니메이션, 닫기를 `Sheet` 하나로 모으고, 모양 차이는 `variant` 셋(page·card·cover)으로 나눴다([#220](https://github.com/hyeoniverse/MacFolio/pull/220), [휴대폰 시트 3곳의 공통 동작](/memo/ui-sheet)).

처음 올린 뒤에 두 가지를 더 고쳤다. 시트를 열 때 초점을 옮기면서 브라우저가 뒤의 앱 화면을 스크롤했고(`preventScroll`로), 시트가 가로로 밀려 음악 화면의 왼쪽 여백이 사라졌다(`overflow-x: hidden`으로). 고친 뒤에는 전후 화면이 픽셀 단위로 같았다.

같은 방식으로 SearchField([#223](https://github.com/hyeoniverse/MacFolio/pull/223))와 분석 앱의 여백 정리([#222](https://github.com/hyeoniverse/MacFolio/pull/222))도 PR을 올렸다. 둘 다 전후 화면을 픽셀로 비교했고, 아직 열려 있다.

## 두 번 찾은 CSS 층 순서

메일 앱의 불러오기 오류 문구가 작고 목록에 붙어 있다는 이야기를 듣고 여백을 보다가, 답장 버튼의 안쪽 여백이 0인 것을 찾았다. 빌드한 HTML에서 공통 컴포넌트 CSS가 든 파일이 먼저 붙어서, 층 순서가 `components, reset`으로 정해지고 reset의 `* { padding: 0 }`이 버튼 여백을 이기고 있었다. 층 순서 선언을 `index.html`의 인라인 스타일 맨 앞으로 옮겼다([#221](https://github.com/hyeoniverse/MacFolio/pull/221), [공통 버튼의 여백이 사라진 이유](/memo/css-layer-order-fix)).

이것은 전날 #187에서 이미 고친 버그다. 그 수정이 아직 머지하지 않은 브랜치에 있어서, main에서는 처음부터 다시 찾았다.

## 메일 칸 오류, 여섯 번

같은 PR에서 메일 쓰기 창의 칸 오류 표시도 바꿨다. 빈 칸으로 보내기를 누르면 칸마다 오류 문구가 한 줄씩 늘어 화면이 출렁였다. 30분 동안 다섯 가지를 차례로 해 보았다. 필수 배지, 칸 아래 줄의 안내 문구, 칸 밖 별도 줄의 흐린 문구, 칸 안의 안내 글자, 이름표만 빨갛게. 모두 칸 사이에 무언가가 끼어 산만했다.

여섯 번째에 macOS 메일처럼 칸 사이에는 아무것도 적지 않기로 했다. 네 칸이 다 차야 보내기 버튼이 눌리고, 형식이 틀리면 공통 경고창에 문구 하나를 띄운다.

## CI: 이번에는 ECR Public의 한도

Sheet를 머지한 뒤 main CI가 시험을 시작하지도 못했다. API e2e용 PostgreSQL 이미지를 받다가 `toomanyrequests: Data limit exceeded`가 났다. 10월 10일에 Docker Hub의 받기 한도를 피해 옮긴 곳이 ECR Public(`public.ecr.aws`)인데, 이번에는 그쪽 한도에 걸렸다. 다음 머지(#221)의 CI는 통과했다.

## 돌아보며

템플릿이 자리를 잡은 것은 두 가지를 정한 뒤였다. 하나는 모든 템플릿이 같은 내용을 읽는다는 것(`landingOf`), 다른 하나는 템플릿마다 참고할 실제 제품이다. 그 전의 사흘 동안은 모양마다 읽는 데이터도, 기준도 달랐다. 그래서 열세 개를 그릴 때마다 빈 곳을 메우는 일이 생겼고, 장식을 더했다가 걷어 냈다. 무엇을 보여 줄지를 먼저 정하고 모양을 그렸다면, 전날 밤에 넣고 이날 새벽에 뺀 장식은 처음부터 없었을 것이다.

메일 칸 오류도 같았다. 여섯 번을 바꾼 끝에 정한 방법은 macOS 메일이 이미 하고 있는 것이었다. 이 사이트는 macOS를 흉내 내는 사이트다. 처음부터 macOS 메일을 열어 보았다면 한 번에 끝났을 것이다.

반대로 Sheet와 Modal은 전날 세어 둔 목록대로 PR 하나씩으로 끝났다. 무엇을 만들지 먼저 정하면 다시 그리는 횟수가 줄어든다.

#187은 이날 끝에 커밋 61개, 4만 줄이 넘는다. 10월 4일에 PR 하나에 커밋 83개를 넣은 것을 반성하고, 10월 7일에는 트래픽 분석을 PR 네 개로 나눴다. 그런데 이번에도 한 PR이 사흘 동안 커졌다. 그 사이 main의 버그 수정 하나가 그 안에 묻혀, main에서 같은 버그를 다시 찾아야 했다. 편집 화면, 템플릿, 저장소 언어 API는 따로 머지할 수 있는 단위였다.
