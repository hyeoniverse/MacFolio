메모의 휴대폰 화면을 iOS 메모처럼(떠 있는 뒤로 가기, 큰 제목, 회색 바탕 위 흰 카드, 아래 떠 있는 단추) 바꾸고 나니, 홈 화면에서 다른 앱을 열 때마다 예전 모양("< 홈 | 앱 이름" 제목 막대, 흰 바탕에 바로 놓인 줄)이 나왔다. 같은 휴대폰 안에서 앱마다 모양이 다르면 어색하다.

![메일·메시지 전후](./images/mobile-apps-mail-messages.jpg '메일과 메시지의 전후: 뒤로 가기 옆의 큰 제목, 흰 카드 목록, 아래의 떠 있는 단추')

## 함께 쓰는 값

메모에서 쓰던 색과 그림자를 메모 안에만 두지 않고, 휴대폰 셸(`Window.css`)에 공통 값으로 뺐다. 앱은 이 값으로 바탕과 카드를 칠한다.

```css
.container.mobile[data-app] {
	--phone-page-bg: #f3f4f6;
	--phone-card-bg: #ffffff;
	--phone-float-shadow: 0 0 0 0.5px rgba(0, 0, 0, 0.06), 0 4px 14px rgba(0, 0, 0, 0.12);
	--phone-separator: rgba(60, 60, 67, 0.18);
}
```

다크 모드에서는 바탕이 카드보다 어둡다(#1e1e1e 위에 #2c2c2e). 떠 있는 뒤로 가기도 처음에는 창 바탕색이라 다크 모드에서 바탕에 묻혔는데, 카드 색으로 바꿔 구분되게 했다.

제목 막대를 띄우는 값(`floating`)은 메모 본문을 만들 때 셸에 더해 두었다. 앱은 `<MobileNavigation floating />` 한 줄로 제목 막대 대신 동그란 뒤로 가기를 쓴다. 바탕이 회색인 화면에서는 상태 막대 뒤와 홈 인디케이터 아래도 회색으로 잇고, 흰 바탕인 화면(메모 본문, 메일 읽기, 메시지, 음악)만 흰색으로 둔다.

## 큰 제목은 뒤로 가기 줄에

처음에는 큰 제목을 뒤로 가기 단추 아래 줄에 두었다. iOS 메모의 목록처럼 단추 줄과 제목 줄이 따로 있는 모양이다. 그런데 메일·메시지·설정처럼 오른쪽 위에 단추가 없는 화면에서는 뒤로 가기 하나만 있는 윗줄이 통째로 비어서, 목록이 그만큼 아래로 밀렸다. 큰 제목을 뒤로 가기와 같은 줄, 그 오른쪽에 두었다.

큰 제목의 모양은 공통 클래스(`phone-title`) 하나로 맞춘다. 줄 높이를 뒤로 가기(44px)에 맞추고, 뒤로 가기가 차지한 폭에 20px을 더 띄운다. 처음에는 12px만 띄웠더니 단추와 제목이 붙어 보였다. 화면은 위 여백을 뒤로 가기의 위 여백(`--phone-top`, 6px)만 둔다.

```css
.container.mobile .phone-title {
	display: flex;
	align-items: center;
	min-height: 44px;
	/* 뒤로 가기(왼쪽 16~60px) 오른쪽으로 20px, 화면 옆 여백 16px 안에서 */
	padding-left: 64px;
}
```

앱마다 따로 적어 두었던 제목 크기·여백(메일의 받은 편지함, 설정 안쪽 화면의 제목, 단축어의 제목)은 지우고 이 클래스를 붙였다. 제목과 단추가 같은 줄에 있는지는 E2E 시험에서 둘의 세로 가운데를 비교해 확인한다.

![설정·단축어](./images/mobile-apps-settings.jpg '설정은 위쪽 탭 대신 iOS 설정처럼 항목 목록에서 눌러 들어간다')

## 앱마다

- **메일**: 큰 제목 '받은 편지함'과 메일 수, 흰 카드 목록. 제목 옆의 쓰기 단추 대신 아래 오른쪽에 떠 있는 새로운 메시지
- **메시지**: iOS 메시지처럼 흰 바탕. 큰 제목 '메시지', 고정 대화는 큰 아바타만(고른 것을 칠하지 않는다), 대화 줄은 52px 아바타와 줄 끝의 ›. 빈 목록은 처음에 안내 한 줄만 고정 대화 바로 아래에 두었더니, 위의 큰 아바타에 붙어 보였다. iOS의 빈 화면처럼 한참 아래에 아이콘, 굵은 제목, 쓰기 단추 안내를 두었다. 위의 검색 칸과 쓰기 단추 대신 아래에 검색 알약과 새 피드백. 대화 화면의 이름·비밀번호는 입력 알약 위의 둥근 카드 하나로 묶었다. 처음에는 카드를 받은 말풍선 색(회색)으로 칠했더니 흰 입력 알약 옆에서 혼자 튀었다. 입력 알약과 같은 흰 바탕과 그림자로 바꿨다. 대화 머리의 아바타·이름 알약·설명 사이도 4px에서 10px로 띄웠고, 새 피드백의 설명은 떠 있는 단추 줄 아래로 내렸다. 입력 칸 글자는 16px 이상이다. iOS Safari는 16px보다 작은 입력 칸을 누르면 화면을 확대한다
- **암호·단축어**: 떠 있는 뒤로 가기와 큰 제목, 회색 바탕

시스템 설정은 휴대폰에서 항목(계정, 화면 모드, 배경화면, 사운드)을 위쪽 탭으로 늘어놓고 있었다. iOS 설정처럼 큰 제목 '설정' 아래 흰 카드 목록으로 바꾸고, 항목을 누르면 그 화면으로 넘어가 떠 있는 뒤로 가기로 돌아오게 했다. 항목 아이콘은 iOS처럼 색칠한 둥근 네모다. 넓은 창에서는 예전처럼 왼쪽 목록과 오른쪽 화면이 함께 보인다.

메시지의 아래 검색 알약은 대화 목록을 넘기는 칸 밖에 따로 그린다. 메모의 목록에서 겪은 것처럼, 넘기는 칸 안의 요소를 칸 밖 기준으로 띄우면 브라우저마다 다르게 그려질 수 있어서다. 검색어는 위의 검색 칸과 같은 상태를 써서, 넓은 창과 휴대폰 어느 쪽에서 찾아도 같다.

GitHub, Safari, 새싹 농장은 그대로 두었다. 셋 다 화면 위쪽을 자기 도구(탭, 주소 막대, 게임 화면)가 쓰는 앱이라, 동그란 뒤로 가기를 띄우면 그것을 가린다.

## 음악은 iOS 음악처럼

음악은 처음에 다른 앱처럼 회색 바탕에 재생 목록 줄을 흰 카드로 묶었다. 실제 iOS 음악을 옆에 두고 보니 짜임이 달랐다. iOS 음악은 흰 바탕이고, 보관함에서 재생 목록을 바로 늘어놓지 않는다. 보관함은 들어갈 곳의 목록이다.

![음악 전후](./images/mobile-apps-music.jpg '전: 보관함에 재생 목록이 바로 / 후: 지금 재생 중인 목록의 표지와 빨간 아이콘 줄, 플레이리스트, 곡 목록')

- **보관함**: 큰 제목 아래에 지금 재생 중인 목록의 표지와 이름. 누르면 그 목록으로 간다. 그 아래 빨간 아이콘 줄(플레이리스트, 아티스트, 앨범, 노래)과 줄 끝의 ›
- **플레이리스트**: 표지와 이름, 설명을 한 줄씩. 오른쪽 위의 정렬 단추로 격자·목록, 제목순·종류순을 고른다. '모든 노래'는 보관함의 '노래'로 따로 연다
- **앨범·아티스트**: 앨범은 두 칸 격자, 아티스트는 동그란 사진 줄
- **곡 목록**: 가운데 큰 표지, 이름과 설명, 곡 수와 길이. 그 아래 [셔플] 동그라미와 [재생] 알약. 재생 중인 곡은 표지 위에 막대를 겹친다
- **미니 플레이어**: 아래에 떠 있는 알약

![음악 목록 화면](./images/mobile-apps-music-lists.jpg '플레이리스트의 보기·정렬 메뉴, 앨범 격자, 아티스트 줄, 다크 모드의 곡 목록')

앨범과 아티스트는 따로 저장한 데이터가 없다. 곡마다 이미 앨범과 가수가 적혀 있어서, 곡을 앨범·가수로 묶어 재생 목록과 같은 모양(`Playlist`)으로 만든다. 재생 목록을 찾는 함수가 이 묶음도 찾게 해서, 재생·셔플·다음 재생이 고치지 않고 그대로 돈다.

```ts
export function groupTracks(tracks: Track[], by: 'album' | 'artist'): Playlist[] {
	const groups = new Map<string, Track[]>();
	for (const t of tracks) groups.set(t[by], [...(groups.get(t[by]) ?? []), t]);
	return [...groups].map(([name, members]) => ({ id: `${by}:${name}`, name, … }));
}
```

곡 목록에서 뒤로 가면 연 곳(보관함, 플레이리스트, 앨범, 아티스트)으로 돌아가고, 뒤로 가기의 화면 읽기 이름도 그곳의 이름이다.

iOS 음악 화면에서 데이터가 없는 것은 만들지 않았다. 아래 탭 막대(홈, 새로운 음악, 라디오)와 '최근 추가된 항목'(곡을 넣은 날짜가 없다), 플레이리스트 만들기, 내려받기, 공동 작업, 곡마다의 ••• 메뉴다. 정렬 메뉴의 추가된 날짜·최근 재생일·업데이트된 날짜도 같은 까닭으로 뺐다.

넓은 창은 예전 그대로 왼쪽 재생 목록과 가운데 곡 목록이다. 휴대폰 화면만 따로 그리는 것은 화면 폭으로 정하는 훅(`useIsMobile`)으로 나눴다.

## 남은 앱도 같은 막대로

메일·메모·설정·메시지·음악은 이렇게 바꿨지만, Safari·Finder·GitHub·API 문서·활동 상태 보기와 프로젝트 앱들(HYEONIVERSE, 새싹 농장, 뉴픽, QRU, WTD)은 예전 막대 그대로였다. 맨 위에 파란 "‹ 홈" 글자와 가운데 제목, 아래에 테두리가 있는 회색 막대다. 휴대폰에서 앱을 번갈아 열면 뒤로 가기 단추가 동그라미였다가 글자였다가 했다.

이 앱들은 내용이 웹 페이지(프로젝트 데모, 문서)이거나 자기 막대(Finder의 보기 단추, 활동 상태 보기의 탭)가 있어서 큰 제목을 얹을 자리가 없다. 그래서 큰 제목은 두지 않고, **막대만 같은 모양으로** 바꿨다. 모든 앱의 공통 막대(`MobileAppFrame`)에서 한 번에 고친다.

- 뒤로 가기는 떠 있는 막대와 같은 44px 동그라미(카드 색, 그림자). "홈", "받은 편지함" 같은 글자는 화면 읽기 프로그램에만 남긴다
- 막대 높이 56px, 테두리 없이 앱의 회색 바탕(`--phone-page-bg`)과 같은 색. 상태 표시줄 뒤까지 같은 색이 이어진다
- 가운데 제목은 17px 굵게

이제 어느 앱을 열어도 뒤로 가기가 같은 자리, 같은 모양이다. 큰 제목이 있는 앱은 막대 없이 동그라미만 떠 있고, 없는 앱은 그 동그라미 옆에 작은 제목이 붙는다.

## 재생과 일시 정지 사이의 1.25px

음악 앱에서 재생을 누를 때마다 옆의 이전·다음 단추가 미세하게 움찔했다. 재 보니 가운데 재생 단추의 폭이 일시 정지(⏸)일 때 20.5px, 재생(▶)일 때 23px였고, 그만큼 양옆 단추가 1.25px씩 밀렸다. Font Awesome의 두 아이콘은 글자 폭이 다르고, 단추는 아이콘 폭을 따라 늘었다 줄었다.

아이콘에 고정 폭(`fa-fw`)을 주어 어느 아이콘이든 같은 칸을 차지하게 했다. 음악 앱의 재생 단추, 좁은 창의 미니 플레이어, 메뉴 막대, 휴대폰 홈 화면의 음악 위젯 네 곳이다. 시험은 재생·일시 정지를 바꾸기 전후의 재생 단추 폭과 이전·다음·메뉴 막대 단추의 자리가 같은지 본다. 고치기 전에는 폭이 20.5에서 23으로 바뀌며 실패했다.

## 메시지 목록은 iOS 메시지처럼

메시지 목록도 실제 iOS 메시지 스크린샷과 나란히 놓고 맞췄다.

- 큰 제목 대신 떠 있는 뒤로 가기와 같은 줄 **가운데에 작은 제목** "메시지"
- 고정 대화(김정현)는 128px 큰 동그라미, 이름은 그 아래 회색
- 대화 줄: 62px 아바타, 굵은 이름, 오른쪽에 시간과 ›, 미리보기는 두 줄까지. 구분선은 아바타를 비켜 이름이 시작하는 자리부터
- 아래에 떠 있는 검색 알약과 새 피드백 단추가 마지막 대화를 가리지 않게, 목록 아래를 그만큼(120px) 비웠다

## 홈 화면은 스크롤하지 않고 페이지로

앱이 늘면서 홈 화면 격자가 한 화면을 넘었다. 격자에 `overflow-y: auto`를 줘 두어서 위젯 아래 칸 안에서 아이콘이 스크롤됐다. iOS 홈 화면은 스크롤하지 않는다. 다 들어가지 않는 앱은 **다음 페이지**로 가고, 옆으로 넘기며, 아래 점이 지금 페이지를 알려 준다.

- 몇 칸이 들어가는지는 화면에서 잰다. 첫 페이지는 위젯 아래 높이, 나머지 페이지는 전체 높이를 아이콘 한 줄 높이(실제 아이콘에서 잰다)와 줄 사이로 나누고, 격자의 열 수(세로 4열, 가로 6열)를 곱한다. 화면 크기가 바뀌면 `ResizeObserver`로 다시 잰다
- 나누는 계산(`rowsThatFit`, `pageApps`)은 순수 함수로 떼어 시험한다
- 페이지는 가로 스크롤에 `scroll-snap`을 걸어 한 페이지씩 멈추고, 스크롤 막대는 숨긴다. 점을 누르면 그 페이지로 간다(마우스로 볼 때)

375×667 휴대폰에서는 첫 페이지에 위젯과 아이콘 한 줄, 2쪽에 나머지가 놓인다. 390×844에서는 첫 페이지에 세 줄이 들어간다.

## 제목 막대와 홈 바가 자리를 차지하지 않게

앞에서 뒤로 가기를 동그라미로 바꿨지만, 구조는 그대로였다. 앱 위에는 여전히 **제목 막대 한 줄**이 있었고, 큰 제목이 있는 앱만 그 막대를 띄우는(`floating`) 예외를 두었다. 아래의 홈 바도 22px 띠로 앱 높이를 깎았다. 모양만 바꾼 것이라, 앱마다 위아래가 조금씩 잘려 보였다.

그래서 막대 자체를 없앴다.

- 뒤로 가기는 언제나 **앱 위에 떠 있는 44px 동그라미 하나**다. 막대도 제목도 없고, 앱은 상태 막대 바로 아래부터 끝까지 높이를 다 쓴다. 앱마다 붙이던 `floating`, `title` 옵션은 지웠다
- 동그라미가 떠 있는 자리에 앱의 첫 줄이 있으면 그 줄은 왼쪽을 64px 비운다 (Safari 주소창, Finder·GitHub·활동 상태 보기의 도구 막대)
- Finder는 자기 뒤로·앞으로 화살표를 숨기고, 떠 있는 뒤로 가기가 Finder의 뒤로가 된다. 처음 화면에서는 홈으로 간다
- 웹 페이지를 그대로 띄우는 앱(iframe)은 위가 남의 페이지라 비울 수 없다. 이런 앱은 뒤로 가기를 **왼쪽 아래**에 띄운다 (`placement: 'bottom'`)
- 홈 바도 앱 위에 겹쳐 그린다. 대신 아래에 떠 있는 것들(메일·메모의 글쓰기, 메시지 검색과 입력창, 음악 재생 막대)은 `--phone-bottom-inset`(22px + 안전 영역)만큼 올려 홈 바에 걸리지 않게 했다

## 홈 화면은 손으로 넘긴다

페이지를 나눈 뒤에도 홈 화면을 옆으로 쓸어 넘길 수가 없었다. 페이지는 가로 스크롤에 `scroll-snap`을 건 것이라 넘기기를 브라우저에 맡겼는데, 마우스로 끌면 아무 일도 없었고, 손가락 흉내(DevTools 프로토콜의 터치)로는 넘어가긴 해도 30px만 살짝 끌어도 다음 페이지로 튀었다.

그래서 넘기기를 직접 한다.

- 페이지를 스크롤하지 않고 **트랙을 옮긴다** (`translateX`). 손가락·마우스·펜을 모두 Pointer Events로 들어서, 끄는 동안은 페이지가 그대로 따라오고 첫·마지막 페이지 바깥으로는 1/3만 따라온다 (고무줄)
- 처음 8px로 가로인지 세로인지 정한다. 세로면 놓아주어 제어 센터 쓸기가 받는다. 그래서 `touch-action: pan-y`
- 놓을 때 폭의 20%를 넘게 끌었거나 빠르게(0.4px/ms) 튕겼으면 한 페이지 넘긴다. 이 판단(`pageAfterSwipe`)은 순수 함수로 떼어 시험한다
- 아이콘 위에서 시작한 쓸기는 그 앱을 열지 않는다. 트랙패드로 옆으로 밀어도 넘어간다

시험은 멈춘 뒤의 자리를 본다. 처음 쓴 시험은 고치기 전 코드에서도 통과했는데, 페이지가 넘어가는 도중의 점을 보고 판정했기 때문이다. 이제는 그 페이지가 화면 왼쪽 끝에 멈추고 0.5초 뒤에도 그대로인지 보고, 고치기 전 코드에서는 실패한다.

## Esc는 뒤로 가기

키보드가 있는 곳에서 휴대폰 화면을 볼 때는 Esc가 떠 있는 뒤로 가기와 같다. 본문에서 누르면 목록, 목록에서는 폴더, 첫 화면에서는 홈이다.

Esc를 이미 쓰는 곳이 많다. 팝오버, 확인 대화상자, 메일 쓰기, 이미지 크게 보기, 로그인 결과, 메시지의 새 피드백. 이들이 닫히면서 뒤로까지 가면 한 번에 두 단계가 넘어간다. 듣는 순서에 기대면 앱이 언제 듣기 시작했는지에 따라 달라지므로, 규칙을 하나로 정했다.

- Esc를 쓴 곳은 `preventDefault()`로 썼다고 남긴다
- 뒤로 가기는 그 키 이벤트가 다 돈 뒤에(`setTimeout 0`) 보고, 누가 썼으면 가지 않는다
- 입력 칸·글쓰기 칸 안의 Esc는 쓰기를 위한 것이라 뒤로 가지 않는다
- 제어 센터나 앱 전환기가 열려 있으면 Esc는 그것부터 닫는다. 맨 앞의 앱만 Esc를 듣는다

## 상태 표시줄도 앱 위에 겹친다

제목 막대를 없앤 뒤에도 앱 틀은 상태 표시줄 높이만큼 `padding-top`을 두어, 시계와 배터리가 있는 띠가 따로 자리를 차지했다. 앱 내용은 그 띠 아래에서 잘렸다.

앱 틀의 그 여백을 지우고, 상태 표시줄을 투명하게 앱 위에 겹쳤다. 대신 앱 안에서 그 높이를 비운다.

- 휴대폰 앱들은 이미 위쪽 여백을 한 변수 `--phone-top`(뒤로 가기의 위 여백 6px)으로 잡고 있었다. 이 값을 **상태 표시줄 높이 + 6px**로 바꾸었다. 스크롤 내용의 위 여백이 이 값이라, 처음에는 상태 표시줄 아래에서 시작하고 스크롤하면 그 밑으로 지나간다
- 떠 있는 뒤로 가기는 앱 맨 위(0)에서 `--phone-top`만큼 내려온다
- 이 변수를 안 쓰던 곳은 맞췄다. 메모와 메일 본문은 6px·60px·64px를 직접 써 두어서, 오른쪽 위 단추가 상태 표시줄 아이콘 위로 올라갔고 메일 보낸 사람 줄이 뒤로 가기 밑에 깔렸다. 이제 모두 `--phone-top`을 기준으로 한다
- 도구 막대가 첫 줄인 앱(Safari, Finder, GitHub, 활동 상태 보기)은 막대를 상태 표시줄 높이(`--phone-status`)만큼 키워, 막대 바탕이 상태 표시줄 뒤까지 이어진다
- 프로젝트 사이트와 API 문서처럼 웹 페이지를 통째로 띄우는 앱도 페이지를 상태 표시줄 밑까지 그린다. 처음에는 페이지를 그만큼 내렸는데, 그러면 이 앱들만 위에 띠가 남았다. 대신 페이지 맨 위의 메뉴가 상태 표시줄 글자와 겹친다. 처음에는 이 앱들 위에서만 상태 표시줄에 반투명한 흰 유리를 깔았는데, 상태 표시줄이 다시 막대처럼 보였다. 그래서 어느 앱에서나 상태 표시줄의 바탕은 투명하게 두고, 밑으로 지나가는 내용만 약하게 흐린다(`backdrop-filter: blur(6px)`). 페이지 맨 위 메뉴는 상태 표시줄 밑에 있어 누를 수 없다. 남의 페이지라 여기서 여백을 줄 수는 없다

## 설정의 계정 화면

계정 화면(설정, 암호 앱이 같이 쓴다)만 데스크톱 모양이었다. 폭이 520px까지로 묶여 있었고, 프로필 줄은 바탕이 없고, 단추는 글자 길이만큼, 정보 묶음은 회색 바탕에 테두리만 있었다. 그래서 폭이 제각각으로 보였다. 휴대폰에서는 다른 설정 화면처럼 폭을 꽉 채운 흰 카드(프로필, 로그인·로그아웃 단추, 정보)로 바꿨다.

## Safari는 iOS Safari처럼

휴대폰 Safari는 데스크톱 Safari를 좁힌 모양이었다. 위에 도구 막대(이전·다음, 주소창, 공유, 새 탭)와 탭 막대가 두 줄로 있었고, 페이지는 그 아래 남은 칸에 보였다. iOS Safari는 반대다. 페이지가 화면을 다 쓰고, 다루는 것은 아래에 떠 있는 막대 하나다. 그래서 사진 앱처럼 휴대폰 화면을 따로 짰다(`SafariMobile`). 탭 상태와 메뉴는 데스크톱과 같이 쓴다.

- 페이지는 화면 맨 위부터 끝까지 쓰고, 투명한 상태 표시줄 밑으로 스크롤된다
- 아래 막대: 왼쪽 뒤로 가기(홈), 가운데 주소 알약(탭 모음 단추와 주소), 오른쪽 •••(링크 공유, 새로운 탭, 탭 모두 보기, 탭 닫기). 주소를 누르면 데모(없으면 저장소)를 새 탭에서 연다
- 주소 알약을 옆으로 밀면 옆 탭으로 간다. 처음에는 마우스로 밀어도 넘어가지 않았는데, 브라우저가 주소 링크를 끌어 옮기기로 가져가며 pointer 이벤트를 취소했기 때문이다. 링크에 `draggable={false}`를 줬다
- 탭 모음은 탭을 두 줄 카드로 늘어놓는다. 미리보기는 실제 페이지를 휴대폰 폭(390px)으로 그려 카드 폭만큼 줄인 것이고, `inert`로 눌리지 않게 한다. 카드의 ×로 닫고, 카드를 누르면 그 탭으로 돌아온다. 아래에는 탭 수와 새로운 탭 단추가 있다

왼쪽 아래에 둔 뒤로 가기가 주소 알약보다 50px 위에 떠 있던 것도 고쳤다. 뒤로 가기 줄은 위에 둘 때를 위해 위아래로 `--phone-top`(상태 표시줄 + 6px)만큼 여백이 있는데, 아래에 둘 때도 그 여백이 붙어 있었다. 프로젝트 사이트를 띄우는 앱들의 뒤로 가기도 같은 이유로 떠 있었다.

## 홈 바가 있으니 홈 단추는 빼도 된다

앱의 첫 화면에 있는 뒤로 가기는 홈으로 간다. 그런데 화면 아래 홈 바도 같은 일을 한다. 아래에 막대가 있는 Safari와 웹 페이지 앱에서는 그 동그라미가 막대 옆 자리를 차지하거나 페이지를 가리기만 했다. 그래서 뒤로 가기에 `hideHome`을 두었다. 켜면 홈으로 가는 단추는 그리지 않고, 앱이 정한 뒤로 가기(Safari 탭 모음의 완료처럼 앱 안에서 한 단계 뒤로)가 있을 때만 그린다. Safari의 주소 알약은 그만큼 왼쪽으로 넓어졌다.

휴대폰 홈 화면의 파일 앱 아이콘도 Finder 아이콘을 빌려 쓰던 것을, iOS 파일처럼 흰 바탕에 파란 폴더를 그린 SVG(`files.svg`)로 바꿨다. 데스크톱 Dock은 그대로 Finder다.
