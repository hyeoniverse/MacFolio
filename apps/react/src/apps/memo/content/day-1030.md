메모 글에 주소 한 줄만 적으면 YouTube 같은 바깥 사이트의 재생기를 iframe으로 그리게 하고, 지원 사이트를 21곳으로 늘렸다. 재생기가 없는 영상·음악 파일은 브라우저 기본 재생기로 그리고, 글에 올린 첨부 파일은 사이트 안 앱으로 열게 했다. 뒤로·앞으로로 돌아온 글이 원래 스크롤 위치에서 시작하게 했고, 관리자가 글을 열기만 해도 임시 저장되던 편집기 문제를 고쳤다.

| 주제              | 핵심 내용                                                                          |
| ----------------- | ---------------------------------------------------------------------------------- |
| 링크 임베드       | 주소에서 ID만 뽑아 iframe 주소를 새로 만들고, 판별과 CSP `frame-src`가 같은 목록   |
| 영상·음악 재생기  | `<video controls>`·`<audio controls>`, CSP `media-src`에 `https:`                  |
| 첨부 파일 앱 열기 | 파일 이름의 확장자로 미리보기·텍스트 편집기·Safari를 고르고, HTML은 sandbox iframe |
| 내려받기 버튼     | 다른 출처에서 무시되는 `download` 속성을 `Blob` 임시 주소로 우회                   |
| 스크롤 위치       | 기록 칸에 위치를 저장하고, 늦게 그려지는 내용 때문에 0.6초 동안 매 프레임 맞춤     |

## 주소 한 줄을 iframe 임베드로 ([#405](https://github.com/hyeoniverse/MacFolio/pull/405))

### 배경: iframe 임베드와 CSP

`<iframe>`은 페이지 안에 다른 웹 페이지를 사각형 영역으로 넣는 HTML 요소다. YouTube·Vimeo 같은 사이트는 다른 페이지에 넣도록 만든 재생기 전용 주소(예: `https://www.youtube.com/embed/<영상 ID>`)를 제공하고, 이 주소를 iframe의 `src`로 지정하면 글 안에서 영상을 재생할 수 있다. 이렇게 바깥 콘텐츠를 페이지에 끼워 넣는 것을 임베드(embed)라고 한다.

CSP(Content Security Policy)는 서버가 응답 헤더로 "이 페이지는 이 출처의 자원만 불러올 수 있다"고 브라우저에 알리는 규칙이다. 예를 들어 `frame-src https://www.youtube-nocookie.com`이면 iframe은 그 출처의 페이지만 띄울 수 있고, 다른 출처의 iframe은 브라우저가 막는다. 임베드할 사이트를 늘리려면 CSP의 출처 목록도 함께 늘려야 한다.

### 판별 규칙

동영상을 소개하려면 화면을 캡처해 넣어야 했고, 읽는 사람은 사이트로 이동해야 재생할 수 있었다. 그래서 ==문단에 주소 링크 하나만 있고 링크 글자가 주소 그대로이면 임베드==하게 했다([f0692a858](https://github.com/hyeoniverse/MacFolio/commit/f0692a858)). 문장 속 링크나 `[발표 영상](https://youtu.be/…)`처럼 글자를 붙인 링크는 링크로 남긴다.

```markdown
https://www.youtube.com/watch?v=nYkdrAPrdcw ← 임베드

발표 영상은 https://youtu.be/nYkdrAPrdcw 에 있다. ← 링크
[발표 영상](https://youtu.be/nYkdrAPrdcw) ← 링크
```

![읽기 화면의 YouTube 임베드](./images/memo-link-embed-reader.jpg 'Flux 글에 주소 한 줄로 적은 F8 2014 발표 영상. 본문 폭의 16:9 재생기와 아래의 "YouTube에서 열기" 링크')

![임베드 판별 순서](./images/day-1030-embed-decision.svg '도식. 단독 링크 문단인지, 지원하는 https 호스트인지, ID가 안전한 문자로만 되어 있는지 차례로 확인하고, 모두 맞으면 ID로 iframe 주소를 새로 만든다')

처음에는 YouTube·Vimeo·Spotify·CodePen 등에서 시작했고, 이어서 SoundCloud·Twitch·TED·TikTok·Instagram·Apple Music·Google 문서 등 21곳으로 늘렸다([54592851d](https://github.com/hyeoniverse/MacFolio/commit/54592851d)). 공유 주소만으로 임베드 주소를 만들 수 있는 iframe 방식만 넣었다.

읽기 화면은 react-markdown의 `p`를 바꿔, 주소만 있는 문단을 `<figure class="memo-embed">`로 그린다. iframe은 `loading="lazy"`이고 아래에 "YouTube에서 열기" 링크를 붙인다. 저장소 글 가운데 주소만 한 줄로 적은 지원 사이트 링크는 없어 기존 글의 화면은 바뀌지 않았다.

| 결정               | 내용                                                                                                                                              |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 주소를 새로 만든다 | `embedOf(href)`가 공유 주소에서 ID만 뽑아 iframe 주소를 만든다. ID는 `[\w-]`만 받고, https가 아니면 임베드하지 않는다                             |
| CSP와 같은 목록    | `frame-src`에 `EMBED_ORIGINS`(출처 22개, Twitch는 재생기와 클립 출처가 다름)만 더한다. 판별과 CSP가 같은 목록이라 사이트를 더할 때 한 곳만 고친다 |
| YouTube            | 쿠키를 남기지 않는 `youtube-nocookie.com`, `referrerPolicy="strict-origin-when-cross-origin"`(Referer가 없으면 재생을 거부한다)                   |
| 넣지 않은 사이트   | X·GitHub Gist(스크립트 삽입 방식), Bandcamp·SlideShare(내부 ID를 알려면 API 요청), Dailymotion(Player ID 없이는 403)                              |

### 편집기의 임베드

관리자 편집기는 ProseMirror 위에 만든 Milkdown이다. ProseMirror의 장식(decoration)은 문서 내용을 바꾸지 않고 화면에만 덧그리는 기능이다. `Decoration.node`는 기존 노드에 class 같은 속성을 더하고, 위젯 장식은 문서 사이에 문서에 속하지 않는 DOM 요소를 끼워 넣는다. 그래서 장식으로 그린 iframe은 저장되는 Markdown에 들어가지 않는다.

편집기는 주소 문단을 높이 0으로 숨기고(`Decoration.node`로 `memo-embed-source`), 그 뒤에 ProseMirror 위젯 장식으로 같은 iframe을 붙인다. 글(Markdown)은 주소 한 줄 그대로다. 위젯 key를 iframe 주소로 정해 다른 곳에 입력해도 iframe을 다시 불러오지 않는다. 높이 0인 문단은 브라우저의 위·아래 화살표가 건너뛰어 `handleKeyDown`이 커서를 직접 넣는다.

마우스를 올리면 보이는 도구 버튼(주소 바꾸기, 링크로 바꾸기, 임베드 삭제)은 네 번 다듬었다. 둥근 반투명 버튼에서 YouTube 링크 복사 버튼과 같은 바탕 없는 24px 아이콘으로 바꾸고, 자리를 재생기 제목 줄 아래 왼쪽으로 옮긴 뒤 들여쓰기를 맞췄다.

`appendTransaction`은 ProseMirror 플러그인이 문서가 바뀐 직후 추가 변경을 덧붙이는 함수다. 예를 들어 링크 글자를 `https://youtu.be/abc`에서 `https://youtu.be/xyz`로 고치면, 링크 주소(href)도 같은 값으로 맞추는 변경을 덧붙인다.

| 편집기 증상                                      | 원인                                                                                     | 수정                                                                                   |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 주소 글자를 고치면 `[새 주소](예전 주소)`로 저장 | 링크 글자만 바뀌고 href는 그대로                                                         | `appendTransaction`이 https 주소 하나뿐인 문단의 링크를 글자 주소로 맞춘다             |
| 글을 열기만 해도 임시 저장                       | 위 맞추기가 표 칸 안 문단과 코드 글자(`` `https://…` ``)에도 링크를 걸어 문서가 바뀌었다 | 표는 건너뛰고 코드 글자에는 링크를 걸지 않는다. E2E가 글을 연 뒤 저장 0회인지 확인한다 |

> [!WARNING] 문서를 고치는 플러그인은 기존 글을 바꾼다
> `appendTransaction`은 사용자가 입력하지 않아도 편집기가 문서를 열 때 실행된다. 맞추기 규칙이 닿는 범위를 좁히지 않으면, 관리자가 글을 열기만 해도 서버에 임시 저장본이 생긴다.

## 영상·음악 재생기

`<video controls>`·`<audio controls>`는 브라우저가 재생·멈춤·음량·전체 화면 버튼을 그려 주는 기본 미디어 요소다. 임베드할 사이트 재생기가 없는 영상(`mp4`·`webm`·`mov` 등)·음악(`mp3`·`m4a`·`flac` 등) 파일은 `<video controls>`·`<audio controls>`로 그린다([ec6afd8cb](https://github.com/hyeoniverse/MacFolio/commit/ec6afd8cb)).

| 링크                  | 판별                                                  |
| --------------------- | ----------------------------------------------------- |
| 주소만 적은 바깥 파일 | https 주소 경로의 확장자                              |
| 편집기로 올린 파일    | 링크 제목 '첨부 파일' + 링크 글자(파일 이름)의 확장자 |

API는 바꾸지 않았다. `Content-Disposition`은 응답을 화면에 보일지 파일로 저장할지 알려 주는 헤더라 링크로 열 때만 적용되고 `<video src>` 재생에는 영향이 없다. 영상의 중간 지점으로 건너뛰면 브라우저는 `Range: bytes=1000000-`처럼 파일의 일부 바이트만 요청하는데, API는 이 Range 요청을 이미 지원한다. CSP `media-src`에는 바깥 파일을 재생하려고 `https:`를 더했다. 미디어는 스크립트를 실행하지 못해 그림(`img-src`)과 같은 수준으로 판단했다.

![영상·음악 재생기](./images/memo-link-embed-media.jpg '읽기 화면. 위는 주소만 적은 MP4 영상(본문 폭, 모서리는 본문 이미지와 같다), 아래는 MP3 음악(본문 폭의 재생 막대). 각 재생기 아래에 파일 이름 링크가 있다. MDN의 CC0 예제 파일')

마지막에 Playwright WebKit에서 재생기를 그려 위쪽 줄을 픽셀로 재고(모서리에서 6px 안쪽, 높이 46px) 자리를 정했다. 처음 재생하기 전에는 Safari가 위쪽 줄을 보이지 않으므로 왼쪽 위 모서리에 배치하고, `play` 이벤트 뒤에는 전체 화면·PiP 버튼과 겹치지 않게 왼쪽에서 100px로 비킨다.

재생기 주변에서 두 가지를 더 고쳤다.

- **올릴 때**: 영상·음악 파일을 올리면 링크를 따로 한 문단에 넣고 커서를 다음 줄로 옮긴다. 문장 중간에 넣으면 단독 링크 문단이 아니라서 재생기로 바뀌지 않았다.
- **파일 이름 자리**: 커서가 원래 링크 줄에 들어가면 그 줄이 재생기 위에 보이다가, 빠져나오면 아래 캡션으로 자리를 옮겼다. 재생기 위젯을 원래 문단의 앞에 붙이고(임베드는 뒤), 편집 중인 줄을 캡션과 같은 글자 크기·여백으로 가운데 정렬해 파일 이름이 늘 재생기 아래 가운데에 보인다.

## 첨부 파일을 사이트 안 앱으로 열기

글에 올린 첨부 파일은 누르면 Finder에서 파일을 열 때와 같은 사이트 안 앱으로 열게 했다([19ab24ad5](https://github.com/hyeoniverse/MacFolio/commit/19ab24ad5)).

| 파일                        | 여는 앱                       |
| --------------------------- | ----------------------------- |
| `pdf`, 그림                 | 미리보기                      |
| `md`                        | 텍스트 편집기 (Markdown 서식) |
| `txt`·`log`·`csv`·`json` 등 | 텍스트 편집기 (고정폭)        |
| `html`                      | Safari 새 탭                  |
| 그 밖 (`zip` 등)            | 새 탭 (내려받기)              |

올린 파일 주소에는 확장자가 없어 링크 글자(파일 이름)로 정한다(`shared/lib/fileApps.ts`). 예를 들어 링크 글자가 `notes.md`이면 텍스트 편집기를 Markdown 서식으로 연다.

HTML 파일은 그 안의 스크립트가 사이트의 쿠키나 저장소에 접근하지 못하게 격리해야 한다. iframe의 `sandbox` 속성은 iframe 안 문서의 권한을 기본으로 모두 빼고 적은 권한만 허락하며, `srcdoc`은 주소 대신 HTML 문자열을 iframe 내용으로 직접 넣는 속성이다. HTML은 `sandbox="allow-popups"` iframe의 `srcdoc`으로 그려 스크립트·양식 제출·같은 출처 접근을 막는다. 시험에서 파일 안의 `parent.hacked = 1`이 실행되지 않는 것을 확인했다.

![Safari로 연 HTML 파일](./images/memo-attachment-apps-safari.jpg 'demo.html을 연 Safari. 파일 이름의 탭이 새로 열리고, 주소창에는 파일 아이콘과 이름이 보인다. 파일 안의 <style>(초록 제목)은 적용된다')

시험 도구의 `addInitScript`는 모든 프레임에서 실행되어 sandbox iframe에서 `localStorage` 접근 오류를 냈고, 맨 바깥 창에서만 실행하게 했다.

### 내려받기 버튼

누르면 앱이 열리므로 파일 자체를 받는 버튼을 따로 만들었다. 버튼은 배지 안 파일 이름 오른쪽에 붙이고 재생기 캡션에도 같은 버튼을 넣었다. 아이콘은 받침대 위 화살표(`fa-download`)로 정하고, 이름과 버튼 사이에 세로 구분선을 넣었다.

`<a download>`는 링크를 열지 않고 파일로 저장하게 하는 속성이지만, 페이지와 같은 출처의 주소에서만 동작한다. `Blob`은 브라우저 메모리에 담은 파일 데이터이고, `URL.createObjectURL()`로 `blob:`으로 시작하는 임시 주소를 만들 수 있다. 이 임시 주소는 페이지와 같은 출처로 취급된다.

![Blob 임시 주소로 내려받기](./images/day-1030-download-blob.svg '도식. 다른 출처의 a download는 무시되므로, 파일을 받아 Blob으로 만든 뒤 같은 출처의 blob: 주소에 download를 붙인다. 받지 못하면 새 탭에서 연다')

> [!WARNING] 다른 출처 주소에는 적용되지 않는 download 속성
> 첨부 파일은 API 서버 출처라 `<a download>`가 무시된다. `fetchFileBlob`으로 받은 `Blob`의 임시 주소에 `download="<파일 이름>"`을 붙여 저장하고, 받지 못하면 새 탭에서 연다(API가 `Content-Disposition: attachment`로 응답한다).

| 문제                                | 처리                                                                                                                |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 링크 안에 버튼을 둘 수 없다         | 버튼을 링크 바로 뒤의 형제로 만들고, 배지의 오른쪽 여백(34px) 안으로 음수 여백(-28px)으로 당긴다                    |
| 편집 화면에서 커서가 버튼 뒤로 잡힘 | 위젯 장식에 `marks: []`를 주지 않으면 위젯이 `<a>` 안에 그려진다. 비워 두어 링크 밖에 그린다                        |
| 아이콘이 둘                         | [#406](https://github.com/hyeoniverse/MacFolio/pull/406)에서 본문 이미지의 내려받기 아이콘도 `fa-download`로 맞췄다 |

같은 PR에서 편집 중인 이미지에 삭제 버튼(크게 보기 왼쪽)을 더했다. 그 전에는 그림을 골라 Delete 키를 눌러야 지울 수 있었다.

## 돌아온 글의 스크롤 위치

27일에 만든 뒤로·앞으로는 돌아온 글을 항상 맨 위에서 시작했다. 기록 칸(`NavEntry`)에 `scroll`을 더하고([305a763f4](https://github.com/hyeoniverse/MacFolio/commit/305a763f4)), 다른 칸으로 가기 직전에 지금 위치를 적게 했다. 다른 글을 열면 본문이 맨 위로 가므로, 스크롤 이벤트에서 본문의 마지막 위치를 따로 보관해 그 값을 적는다. sessionStorage에서 읽은 값이 음수·10,000,000 초과·숫자가 아니면 기록을 버린다.

돌아온 뒤 한 번만 맞추면 위치가 밀렸다. 스크롤 앵커링(scroll anchoring)은 화면 위쪽의 내용 높이가 바뀌어도 보고 있던 문단이 같은 자리에 머물도록 브라우저가 스크롤 위치를 자동으로 고치는 기능이다. ==늦게 그려지는 편집기·목차가 높이를 바꾸고, 브라우저의 스크롤 앵커링이 위치를 옮긴다==(편집 화면에서 900 → 950px). 약 0.6초(40프레임) 동안 매 프레임 다시 맞추고, 그사이 휠·터치 입력이 있으면 멈춘다. 목록에서 새로 연 글은 지금처럼 맨 위에서 시작한다.

![스크롤 위치 맞추기](./images/day-1030-scroll-restore.svg '도식. 한 번만 맞추면 늦게 그려진 내용과 스크롤 앵커링 때문에 950px로 밀린다. 0.6초 동안 매 프레임 900px로 맞추고, 휠·터치 입력이 있으면 멈춘다')
