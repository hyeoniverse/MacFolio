정보처리기사 실기는 보기 없이 용어를 직접 쓰고, 코드의 출력값과 SQL 결과를 손으로 계산하는 필답형 시험이다. 이 글은 연재의 실기 각론 다섯 편에서 시험장에 들고 갈 만한 것만 골라 표로 압축한 요약본이다. 설명이 더 필요한 항목은 절 끝의 상세 글 링크를 따라간다.

## 답안 작성 체크리스트

채점은 정해진 정답과 비교해 이루어진다. 뜻이 맞아도 문제가 요구한 형태와 다르면 틀린다.

| 문제의 요구        | 맞는 답                   | 틀리는 답                            |
| ------------------ | ------------------------- | ------------------------------------ |
| 영문 약어로 쓰시오 | `EAI`                     | `Enterprise Application Integration` |
| 영문 Full-name으로 | `Enterprise Service Bus`  | `ESB`                                |
| 한 가지만 쓰시오   | `스텁`                    | `스텁, 드라이버`                     |
| 모두 골라 기호로   | `ㄱ, ㄹ, ㅂ`              | `ㄱ, ㄹ` (하나 누락), 용어로 씀      |
| 순서대로 쓰시오    | `ㄷ → ㄹ → ㄱ → ㄴ`       | 순서 무시                            |
| `printf("%d ", i)` | `1 2 3 ` (숫자 사이 공백) | `123`                                |
| Python 리스트 출력 | `[2, 9, 4]`               | `[2,9,4]`, `2 9 4`                   |
| 영문 철자          | `Singleton`, `HAVING`     | `Singletone`, `HAVEING`              |

- 후보를 두 개 쓰지 않는다. 하나가 정답이어도 오답 처리될 수 있다
- 빈칸이 여러 개인 문항은 맞힌 칸만큼 부분 점수가 있을 수 있으니 아는 칸은 끝까지 채운다
- 순서 문제는 "약한 것부터"인지 "강한 것부터"인지, "하위부터"인지 "상위부터"인지 기준 단어에 먼저 밑줄을 긋는다

## 요구사항·설계·테스트 용어

### 순서로 외우는 묶음

![순서를 외워야 하는 용어 묶음](./images/eip-practical-summary-order-map.svg '결합도·응집도·정규화는 첫 글자 연결로, 나머지는 단계 이름 그대로 외운다')

결합도(Coupling)는 모듈 사이의 의존 정도라서 낮을수록, 응집도(Cohesion)는 한 모듈 안 요소들의 관련 정도라서 높을수록 좋다. 그래서 두 표 모두 ==맨 왼쪽이 가장 좋은 설계==다.

| 묶음             | 순서                                                   | 외우는 말      |
| ---------------- | ------------------------------------------------------ | -------------- |
| 결합도 (약 → 강) | 자료, 스탬프, 제어, 외부, 공통, 내용                   | 자스제외공내   |
| 응집도 (강 → 약) | 기능적, 순차적, 교환적, 절차적, 시간적, 논리적, 우연적 | 기순교절시논우 |
| 요구사항 개발    | 도출, 분석, 명세, 확인                                 |                |
| 테스트 레벨      | 단위, 통합, 시스템, 인수                               |                |
| UI 기본 원칙     | 직관성, 유효성, 학습성, 유연성                         | 직유학유       |
| GoF 패턴 분류    | 생성 5개, 구조 7개, 행위 11개                          | 합계 23개      |

V 모델에서 개발 단계와 테스트 단계는 요구사항 분석 ↔ 인수, 시스템 설계 ↔ 시스템, 아키텍처 설계 ↔ 통합, 모듈 설계 ↔ 단위로 짝을 이룬다.

### 헷갈리는 짝

| 짝                          | 가르는 기준                                                                                      |
| --------------------------- | ------------------------------------------------------------------------------------------------ |
| 순차적 / 절차적 응집도      | 앞 단계 출력이 다음 단계 입력이면 순차적, 순서만 있고 데이터가 안 이어지면 절차적                |
| 논리적 응집도 / 제어 결합도 | 모듈 안에서 플래그로 기능을 고르면 논리적 응집도, 모듈 사이에 플래그를 넘기면 제어 결합도        |
| 집합 / 포함(합성)           | 부분이 독립적으로 남으면 집합(빈 마름모), 전체와 함께 사라지면 포함(채운 마름모)                 |
| 연관 / 의존                 | 멤버 변수로 계속 참조하면 연관(실선), 매개변수로 잠깐 쓰면 의존(점선)                            |
| 일반화 / 실체화             | 클래스 상속은 실선 + 빈 삼각형, 인터페이스 구현은 점선 + 빈 삼각형                               |
| 확인 / 검증                 | 확인(Validation)은 사용자 의도와 맞는가, 검증(Verification)은 명세대로 만들었는가                |
| 동등 분할 / 경계값 분석     | 구간마다 대표값 하나 / 경계와 바로 양옆 값                                                       |
| 드라이버 / 스텁             | 드라이버는 하위 모듈을 호출하는 임시 상위 모듈(상향식), 스텁은 호출당하는 임시 하위 모듈(하향식) |
| 알파 / 베타 테스트          | 개발자 장소에서 사용자가 / 사용자 장소에서 개발자 없이                                           |
| 오버로딩 / 오버라이딩       | 매개변수가 달라야 함(컴파일 시각 결정) / 같아야 함(실행 시각 결정)                               |

### 테스트 기법과 커버리지

| 블랙박스 (명세 기반)                                                                   | 화이트박스 (구조 기반)                                 |
| -------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| 동등 분할, 경계값 분석, 원인-결과 그래프, 결정 테이블, 상태 전이, 오류 예측, 비교 검사 | 기초 경로 검사, 조건 검사, 루프 검사, 데이터 흐름 검사 |

| 커버리지   | 만족 조건                                                |
| ---------- | -------------------------------------------------------- |
| 구문       | 모든 문장을 한 번 이상 실행                              |
| 결정(분기) | 전체 조건식이 참·거짓을 각각 한 번 이상                  |
| 조건       | 개별 조건이 참·거짓을 각각 한 번 이상                    |
| 조건/결정  | 결정과 조건을 동시에 만족                                |
| MC/DC      | 조건/결정 + 각 조건이 결과에 독립적으로 영향을 줌을 보임 |
| 다중 조건  | 모든 조건 조합                                           |

조건 커버리지를 만족해도 결정 커버리지는 만족하지 못할 수 있다. `A && B`에 (T, F), (F, T)를 넣으면 A와 B가 각각 참·거짓을 한 번씩 갖지만 결정은 두 번 다 거짓이다.

순환 복잡도는 제어 흐름 그래프의 간선 수 E와 노드 수 N으로 `V(G) = E - N + 2{:math}`, 또는 조건 노드 수 P로 `V(G) = P + 1{:math}`이다. 간선 7개, 노드 6개면 3이다.

## SQL

### 문법 뼈대

```sql
SELECT [DISTINCT] 열 FROM 테이블 [WHERE 행 조건] [GROUP BY 열] [HAVING 그룹 조건] [ORDER BY 열 [ASC | DESC]];
INSERT INTO 테이블 (열1, 열2) VALUES (값1, 값2);
UPDATE 테이블 SET 열 = 값 WHERE 조건;
DELETE FROM 테이블 WHERE 조건;
CREATE INDEX 인덱스명 ON 테이블(열);
GRANT SELECT ON 테이블 TO 사용자 WITH GRANT OPTION;
REVOKE SELECT ON 테이블 FROM 사용자 CASCADE;
```

| 분류 | 명령어                         | 다루는 대상           |
| ---- | ------------------------------ | --------------------- |
| DDL  | CREATE, ALTER, DROP, TRUNCATE  | 테이블·뷰·인덱스 구조 |
| DML  | SELECT, INSERT, UPDATE, DELETE | 행                    |
| DCL  | GRANT, REVOKE                  | 권한                  |
| TCL  | COMMIT, ROLLBACK, SAVEPOINT    | 트랜잭션              |

국내 수험서는 COMMIT과 ROLLBACK을 DCL에 넣는 세 분류 체계로 설명하는 경우가 많다. GRANT는 `TO`, REVOKE는 `FROM`이다.

### 처리 순서와 키워드 구분

![SQL 처리 순서와 절마다 쓸 수 있는 것](./images/eip-practical-summary-sql-order.svg '집계 함수 조건은 그룹이 생긴 뒤의 HAVING에 쓰고, SELECT에서 붙인 별칭은 WHERE에서 쓸 수 없다')

| 빈칸 앞뒤 모양                     | 키워드     |
| ---------------------------------- | ---------- |
| `GROUP BY 열 ( ) 집계함수 조건`    | `HAVING`   |
| `FROM 테이블 ( ) 행 조건`          | `WHERE`    |
| `SELECT ( ) 열` (중복 제거)        | `DISTINCT` |
| `UPDATE 테이블 ( ) 열 = 값`        | `SET`      |
| `INSERT ( ) 테이블 VALUES`         | `INTO`     |
| `CREATE INDEX 이름 ( ) 테이블(열)` | `ON`       |

| 짝                       | 구분                                                              |
| ------------------------ | ----------------------------------------------------------------- |
| DELETE / DROP / TRUNCATE | 행만 삭제(조건 가능) / 구조까지 삭제 / 구조는 남기고 모든 행 삭제 |
| `BETWEEN a AND b`        | a 이상 b 이하, 양 끝 포함                                         |
| `LIKE '_래'` / `'%서%'`  | `_`는 정확히 한 글자, `%`는 0글자 이상                            |
| `= NULL` / `IS NULL`     | `= NULL`은 항상 참이 아니어서 0행, NULL 비교는 `IS NULL`          |
| CASCADE / RESTRICT       | 참조하는 쪽까지 연쇄 처리 / 참조가 있으면 거부                    |

### NULL이 섞인 행 수

아래는 [실기 개요 글](/memo/eip-practical-overview)의 사원 테이블(6명, 그중 바다의 부서만 NULL)을 sqlite3로 실행한 결과다.

| 질의                                                   | 결과 | 이유                                 |
| ------------------------------------------------------ | ---: | ------------------------------------ |
| `COUNT(*)`                                             |    6 | 행 자체를 집계                       |
| `COUNT(부서)`                                          |    5 | NULL인 행은 집계하지 않음            |
| `COUNT(DISTINCT 부서)`                                 |    3 | NULL을 빼고 서로 다른 값만           |
| `SELECT DISTINCT 부서`                                 |  4행 | DISTINCT에서는 NULL도 한 행으로 나옴 |
| `WHERE 부서 <> '개발'`                                 |    3 | NULL은 `<>` 비교에서도 참이 아님     |
| `WHERE 부서 = NULL`                                    |    0 | `IS NULL`로 써야 함                  |
| `WHERE 급여 >= 300 GROUP BY 부서 HAVING COUNT(*) >= 2` |  1행 | 6행 → WHERE 4행 → 3그룹 → 1그룹      |

`NOT IN (서브쿼리)`의 결과에 NULL이 하나라도 있으면 결과가 0행이 된다. `x NOT IN (1, 2, NULL)`은 `x <> 1 AND x <> 2 AND x <> NULL`이고 마지막 항이 항상 UNKNOWN이기 때문이다. 서브쿼리에서 `IS NOT NULL`로 걸러 내거나 `NOT EXISTS`를 쓴다.

### 조인과 집합 연산

![조인과 집합 연산의 결과 행 수](./images/eip-practical-summary-join-set.svg '외부 조인은 짝 없는 행을 NULL로 채워 남기고, UNION ALL만 중복을 유지한다')

그림의 행 수는 값이 {1, 2, 3}인 테이블 A와 {2, 3, 4}인 테이블 B를 sqlite3로 실제 조인·연산해 얻었다.

| 연산                    | 결과                                                    |
| ----------------------- | ------------------------------------------------------- |
| INNER JOIN              | 짝이 있는 행만                                          |
| LEFT / RIGHT OUTER JOIN | 내부 조인 + 왼쪽(오른쪽)의 짝 없는 행, 반대쪽 열은 NULL |
| FULL OUTER JOIN         | 내부 조인 + 양쪽의 짝 없는 행                           |
| CROSS JOIN              | 모든 조합, 행 수 = 왼쪽 × 오른쪽                        |
| NATURAL JOIN            | 이름이 같은 열로 자동 동등 조인, 공통 열은 한 번만      |
| SELF JOIN               | 같은 테이블을 별칭 두 개로 조인                         |
| UNION / UNION ALL       | 합집합, 중복 제거 / 중복 유지                           |
| INTERSECT               | 교집합                                                  |
| EXCEPT                  | 차집합 (Oracle은 MINUS)                                 |

### 관계대수

| 기호    | 이름                           | SQL 대응                             |
| ------- | ------------------------------ | ------------------------------------ |
| σ       | 셀렉트 (Select)                | WHERE: ==행==을 고른다               |
| π       | 프로젝트 (Project)             | SELECT 열 목록: ==열==을 고른다      |
| ⋈       | 조인 (Join)                    | JOIN                                 |
| ÷       | 디비전 (Division)              | NOT EXISTS 이중 부정                 |
| ∪ ∩ − × | 합집합, 교집합, 차집합, 교차곱 | UNION, INTERSECT, EXCEPT, CROSS JOIN |

σ가 SQL의 SELECT가 아니라 WHERE에 해당한다는 점이 가장 많이 헷갈린다. 교차곱의 차수(열 수)는 두 릴레이션 차수의 합, 카디널리티(행 수)는 곱이다. 열 6개·행 7개와 열 3개·행 4개의 교차곱은 차수 9, 카디널리티 28이다. 관계대수는 절차적 언어, 관계해석은 비절차적 언어다.

### 정규화와 이상 현상

| 정규형 | 제거하는 것                               |
| ------ | ----------------------------------------- |
| 1NF    | 원자값이 아닌 도메인 (한 칸에 값 여러 개) |
| 2NF    | 부분 함수 종속                            |
| 3NF    | 이행 함수 종속                            |
| BCNF   | 결정자이면서 후보 키가 아닌 것            |
| 4NF    | 다치 종속                                 |
| 5NF    | 후보 키를 통하지 않는 조인 종속           |

| 이상 현상 | 뜻                                                       |
| --------- | -------------------------------------------------------- |
| 삽입 이상 | 원하지 않는 값까지 함께 넣어야 저장할 수 있다            |
| 삭제 이상 | 한 행을 삭제하면 남겨야 할 정보까지 사라진다             |
| 갱신 이상 | 같은 정보가 여러 행에 있어 일부만 고치면 불일치가 생긴다 |

| ACID           | 영문        | 한 줄 정의                                        |
| -------------- | ----------- | ------------------------------------------------- |
| 원자성         | Atomicity   | 모두 반영되거나 하나도 반영되지 않는다            |
| 일관성         | Consistency | 끝난 뒤에도 무결성 제약을 만족한다                |
| 격리성(독립성) | Isolation   | 동시에 실행되는 트랜잭션의 중간 결과를 볼 수 없다 |
| 영속성(지속성) | Durability  | COMMIT된 결과는 장애가 나도 남는다                |

뷰는 데이터를 보관하지 않는 가상 테이블이고, 시험 기준으로는 ALTER로 정의를 바꿀 수 없다.

<details>
<summary>switch 폴스루, static, 재귀 (실행 확인)</summary>

```c
int t = 0;
for (int k = 1; k <= 3; k++) {
    switch (k) {
    case 1: t += 1;
    case 2: t += 10; break;
    default: t += 100;
    }
}
printf("%d\n", t);           /* 121 */

int counter(void) { static int s = 0; int a = 0; s++; a++; return s * 10 + a; }
/* counter()를 세 번 호출하면 11 21 31 */

void show(int n) { if (n == 0) return; printf("%d ", n); show(n - 1); printf("%d ", n); }
/* show(3)은 3 2 1 1 2 3 */
```

k = 1은 break가 없어 case 2까지 실행해 11, k = 2는 10, k = 3은 100을 더한다. static 변수 s는 처음 한 번만 초기화되고, 재귀 호출 뒤의 출력문은 가장 깊은 호출부터 거꾸로 실행된다.

</details>

배열 이름이나 주소를 함수에 넘기면 원본이 바뀌고, 일반 변수의 값을 넘기면 원본은 그대로다.

### Java

아래는 `Parent p = new Child();`로 만든 객체를 포함해 java로 실행한 결과다. Parent와 Child는 각각 생성자에서 `P `와 `C `를 출력하고, 같은 이름의 필드 `x`(1과 2), 오버라이딩한 `show()`, static 메서드 `who()`를 가진다.

| 코드                                                              | 출력              | 함정                                  |
| ----------------------------------------------------------------- | ----------------- | ------------------------------------- |
| `new Child()`                                                     | `P C `            | 부모 생성자가 먼저 실행               |
| `p.show()`                                                        | `Child.show`      | 메서드는 실제 객체 기준(동적 바인딩)  |
| `p.x`, `((Child) p).x`                                            | `1 2`             | 필드는 변수 타입 기준                 |
| `p.who()` (static)                                                | `Parent.who`      | static 메서드도 변수 타입 기준        |
| `"A" + 1 + 2`, `1 + 2 + "A"`, `'A' + 1`                           | `A12`, `3A`, `66` | 왼쪽부터 계산, char + int는 정수      |
| `7 / 2`, `7 % 2`, `7.0 / 2`, `-7 / 2`                             | `3 1 3.5 -3`      | 정수끼리면 정수 나눗셈, 0 쪽으로 버림 |

| `try { print("try "); return 1; } finally { print("finally "); }` | `try finally 1`   | finally가 반환 직전에 실행            |
| `sum(1, 2)`, `sum(1.0, 2)` (int·double 오버로딩)                  | `3 3.0`           | 인자 타입에 맞는 메서드 선택          |
| `int[] b = arr; b[0] = 9;` 후 `arr[0]`                            | `9`               | 배열 변수는 같은 객체를 가리킴        |
| `i = 5; j = i++ + ++i;` 후 `i, j`                                 | `7 12`            | 5 + 7, i는 두 번 증가                 |

예외는 위에서부터 타입이 맞는 첫 catch 하나만 실행되고, finally는 예외 여부와 관계없이 실행된다. 배열 범위를 벗어나면 `ArithmeticException` catch는 건너뛰고 `Exception` catch로 간다.

### Python

아래 출력은 모두 python3로 실행한 값이다. `s = "PYTHON"`, `L = [10, 20, 30, 40, 50]`이다.

| 코드                                             | 출력                        | 함정                                 |

## 보안·네트워크·신기술 용어

### 공격 기법

| 용어                              | 한 줄 정의                                                               |
| --------------------------------- | ------------------------------------------------------------------------ |
| SQL 삽입 (SQL Injection)          | 입력값에 SQL 문법을 넣어 쿼리 조건을 바꿈                                |
| XSS (Cross-Site Scripting)        | 공격자 스크립트가 ==피해자 브라우저==에서 실행. 저장형, 반사형, DOM 기반 |
| CSRF (Cross-Site Request Forgery) | 피해자 권한으로 ==서버 기능==이 실행되게 요청을 위조                     |
| 스머핑 (Smurfing)                 | 출발지를 대상 IP로 위조한 ICMP 요청을 브로드캐스트로 보내 응답 집중      |
| 랜드 어택 (LAND Attack)           | 출발지 IP = 목적지 IP = 대상                                             |
| 티어드롭 (TearDrop)               | IP 조각의 오프셋을 겹치게 조작                                           |
| 죽음의 핑 (Ping of Death)         | 65,535바이트를 넘는 ICMP 패킷을 조각내 전송                              |
| SYN 플러딩                        | SYN만 보내고 ACK를 안 보내 대기 큐 고갈                                  |
| 피싱 / 파밍                       | 가짜 링크로 유인 / DNS·hosts를 변조해 정상 주소도 가짜로                 |
| 스미싱 / 큐싱 / 비싱              | 문자 메시지 / QR 코드 / 전화(음성)                                       |
| APT (Advanced Persistent Threat)  | 특정 조직에 침투해 오래 잠복하며 정보 유출                               |
| 바이러스 / 웜 / 트로이 목마       | 숙주 필요 / 스스로 전파 / 복제 없이 위장                                 |
| ARP 스푸핑                        | 가짜 ARP 응답으로 게이트웨이 IP에 자기 MAC을 대응시켜 가로챔             |
| 세션 하이재킹                     | 인증을 마친 세션 정보를 가로채 정상 사용자로 행세                        |
| MITM (Man-In-The-Middle)          | 통신 양쪽 사이에 끼어들어 중계하며 엿보거나 바꿈                         |

### 암호

| 알고리즘           | 핵심                                                                           |
| ------------------ | ------------------------------------------------------------------------------ |
| DES                | 블록 64비트, 키 56비트, 16라운드                                               |

IPv4 클래스는 첫 옥텟으로 A(0~127), B(128~191), C(192~223), D(224~239, 멀티캐스트), E(240~255, 실험용)로 나눈다. 서브네팅은 빌리는 비트 수 s와 남는 호스트 비트 수 h로 계산한다. 서브넷 수는 `2^s{:math}`, 블록 크기는 `2^h{:math}`, 할당 가능한 호스트 수는 `2^h - 2{:math}`(네트워크 주소와 브로드캐스트 주소 제외)다. 200.1.1.0/24를 /28로 나누면 블록 크기 16, 서브넷당 호스트 14개이고, 세 번째 서브넷은 200.1.1.32에서 시작해 브로드캐스트 주소가 200.1.1.47이다.
