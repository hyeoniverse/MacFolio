## DB를 Cloud SQL로, `.env`를 추적에서 제외

26일 8시 정각 커밋은 DB 연결을 Google Cloud SQL로 바꿨다. 코드에서 바뀐 것은 많지 않다. 연결 설정에 포트(`DB_PORT`, 기본 3306)를 더하고 주석을 달았을 뿐, 주소·사용자·비밀번호는 [닷새 전](/memo/day-20241021)처럼 환경 변수에서 읽는다. 바뀐 것은 그 환경 변수가 가리키는 곳이다.

이어서 1분 뒤 `.gitignore`에 `.env`를 넣고, 4분 뒤 `server/.env`를 저장소에서 지웠다. 마지막으로 `macbook.sql`(83줄)에 표 정의를 남겼다.

```sql
CREATE TABLE `memos` (
  `id` int NOT NULL AUTO_INCREMENT,
  `folder_id` int DEFAULT NULL,
  `title` varchar(300) DEFAULT NULL,
  `content` text,
  `password` varchar(60) NOT NULL DEFAULT '0000',
  ...
```

`password`의 기본값 `'0000'`은 bcrypt 해시가 아니다. `bcrypt.compare`는 해시가 아닌 값과는 맞지 않으니, 비밀번호 없이 만든 메모는 아무도 고치거나 지울 수 없었을 것이다.

## 지금과 비교하면

- **node_modules**: 2024년 12월 서버 폴더를 지울 때 1,478개, 2025년 3월 Vite로 옮길 때 340개로 줄었고, 2026년 9월 28일 0시 15분 커밋에서 모두 추적에서 뺐다([9월 28일 회고](/memo/day-0928)). 지금은 pnpm 잠금 파일만 커밋한다.
- **.env**: 지금은 비밀 값을 저장소에 두지 않고, 한 번 커밋했다 지운 값도 찾도록 기록 전체를 훑는 CI가 있다([비밀 값 검사](/memo/secret-scanning)).
- **DB**: Cloud SQL의 MySQL은 두 달 뒤 Firebase로, 지금은 Oracle Cloud VM의 PostgreSQL이다([백엔드 설계](/memo/backend-design), [서버 배포](/memo/deploy-api-oracle-tunnel)).
- **스키마**: 손으로 남긴 `.sql` 파일 대신, 지금은 API 서버의 Prisma 마이그레이션이 표를 만든다.

## 돌아보며

`.env`를 지운 날 바로 다음 날 `node_modules`를 넣었다. 하나는 저장소에 있으면 안 되는 것을 빼는 일이고, 하나는 없어도 되는 것을 넣는 일이었다. 둘 다 "무엇을 저장소에 두는가"라는 같은 질문인데, 이틀 동안 답이 반대로 갔다.

이 6만 개는 2년 동안 저장소 기록에 남았다. 지금도 이 저장소를 처음부터 받으면 그 파일들을 같이 받는다. 지운 파일도 기록에는 남는다는 것은 비밀 값만의 이야기가 아니다.
