## 관계 데이터 언어

연산(operation)은 시스템 관점의 표현이고, 데이터 언어(data language)는 사용자 관점의 표현이다. 관계 데이터 모델의 정형 언어(formal language)는 두 가지다.

|      | 관계 대수(relational algebra)         | 관계 해석(relational calculus)   |
| ---- | ------------------------------------- | -------------------------------- |
| 성격 | 절차 언어: 무엇을(what)과 어떻게(how) | 비절차 언어: 무엇을(what)만      |
| 종류 |                                       | 튜플 관계 해석, 도메인 관계 해석 |

==관계 대수와 관계 해석은 표현력과 기능이 동등하다.== 관계 대수식으로 쓸 수 있는 질의는 관계 해석으로도 쓸 수 있고, 그 반대도 성립한다.

## 관계 대수

관계 대수는 릴레이션(튜플의 집합)을 처리하는 연산의 집합이다.

| 분류             | 연산자                             | 기호 |
| ---------------- | ---------------------------------- | ---- |
| 일반 집합 연산자 | 합집합(UNION)                      | ∪    |
|                  | 교집합(INTERSECT)                  | ∩    |
|                  | 차집합(DIFFERENCE)                 | −    |
|                  | 카티션 프로덕트(CARTESIAN PRODUCT) | ×    |
| 순수 관계 연산자 | 실렉트(SELECT)                     | σ    |
|                  | 프로젝트(PROJECT)                  | π    |
|                  | 조인(JOIN)                         | ⋈    |
|                  | 디비전(DIVISION)                   | ÷    |

==**폐쇄 성질(closure property)**: 피연산자와 연산 결과가 모두 릴레이션이다.== 그래서 한 연산의 결과를 다른 연산의 피연산자로 넣는 중첩(nested) 수식을 쓸 수 있다.

## 일반 집합 연산자

| 연산            | 정의                                                        | 결과 카디널리티                                         |
| --------------- | ----------------------------------------------------------- | ------------------------------------------------------- |
| 합집합          | `R ∪ S = { t \| t ∈ R ∨ t ∈ S }`                            | `\|R ∪ S\| ≤ \|R\| + \|S\|` (중복 튜플은 하나만 남는다) |
| 교집합          | `R ∩ S = { t \| t ∈ R ∧ t ∈ S }`                            | `\|R ∩ S\| ≤ min{\|R\|, \|S\|}`                         |
| 차집합          | `R − S = { t \| t ∈ R ∧ t ∉ S }`                            | `\|R − S\| ≤ \|R\|`                                     |
| 카티션 프로덕트 | `R × S = { r·s \| r ∈ R ∧ s ∈ S }` (·는 접속 concatenation) | `\|R × S\| = \|R\| × \|S\|`, 차수는 R의 차수 + S의 차수 |

합집합·교집합·차집합의 피연산자는 **합병 가능(union-compatible)** 해야 한다.

1. 두 릴레이션의 차수가 같다.
2. 대응하는 애트리뷰트 쌍마다 도메인이 같다.

∪, ∩, ×는 결합적(associative)이고 교환적(commutative)이다. 차집합은 둘 다 아니다.

```text
R ∪ S ∪ T = (R ∪ S) ∪ T = R ∪ (S ∪ T)
R ∪ S = S ∪ R
```

## 순수 관계 연산자

![실렉트, 프로젝트, 자연 조인이 고르는 부분](./images/db-relational-algebra-operators.svg '실렉트는 행을, 프로젝트는 열을 고르고, 조인은 공통 열로 두 릴레이션을 잇는다')

릴레이션 `R(X) = R(A1, …, An)`의 튜플 r에서 애트리뷰트 Ai의 값을 `r.Ai` 또는 `r[Ai]`로 쓴다. 애트리뷰트 집합 X에 대한 값은 `r[X]`다.

### 실렉트(σ)

조건을 만족하는 튜플만 고른다. 결과는 릴레이션의 **수평적 부분집합(horizontal subset)** 이다.

```text
σ조건(R) = { r | r ∈ R ∧ 조건(r) }
조건: A θ v 또는 A θ B, θ ∈ { =, ≠, <, ≤, >, ≥ }, ∧ · ∨ · ¬ 로 결합 가능
```

`σ학과='컴퓨터'(학생)`의 결과는 다음과 같다.

| 학번 | 이름   | 학년 | 학과   |
| ---- | ------ | ---- | ------ |
| 100  | 나수영 | 4    | 컴퓨터 |
| 300  | 정기태 | 1    | 컴퓨터 |
| 400  | 송병길 | 4    | 컴퓨터 |

`σ학번=300 ∧ 과목번호='C312'(등록)`은 학번 300의 C312 등록 튜플 하나를, `σ중간성적<기말성적(등록)`은 기말성적이 중간성적보다 높은 등록 튜플을 반환한다. 조건에 애트리뷰트끼리의 비교도 쓸 수 있다.

### 프로젝트(π)

지정한 애트리뷰트만 남긴다. 결과는 릴레이션의 **수직적 부분집합(vertical subset)** 이다.

```text
Y ⊆ X, Y = {B1, …, Bm} 일 때
πY(R) = { <r.B1, …, r.Bm> | r ∈ R }
```

==결과도 릴레이션이므로 중복 튜플은 제거된다.== `π학과(학생)`은 다섯 튜플이 아니라 {컴퓨터, 전기, 산공} 세 튜플이다. 같은 릴레이션에 프로젝트를 겹쳐 쓰면 바깥쪽만 남는다(`πY(πX(R)) = πY(R)`, Y ⊆ X).

### 조인(⋈)

두 릴레이션의 튜플을 조건에 따라 연결한다. 조건에 쓰는 애트리뷰트를 조인 애트리뷰트(join attribute)라 한다.

| 종류                        | 정의                                                | 결과 애트리뷰트                                      |
| --------------------------- | --------------------------------------------------- | ---------------------------------------------------- |
| 세타 조인(theta join)       | `R ⋈A θ B S = { r·s \| r ∈ R ∧ s ∈ S ∧ r.A θ s.B }` | R의 차수 + S의 차수                                  |
| 동일 조인(equijoin)         | 세타 조인에서 θ가 `=`인 경우                        | R의 차수 + S의 차수 (조인 애트리뷰트가 두 번 나온다) |
| 자연 조인(natural join, ⋈N) | 동일 조인 결과에서 중복 조인 애트리뷰트를 제거      | R과 S의 애트리뷰트 합집합                            |

결과 릴레이션에서 이름이 같은 애트리뷰트는 원래 릴레이션 이름을 한정어로 붙여 `학생.학번`, `등록.학번`처럼 구분한다. 이름이 겹치지 않는 애트리뷰트는 이름만 쓴다.

자연 조인은 `R(X)`, `S(Y)`의 공통 애트리뷰트 `Z = X ∩ Y`로 연결한다.

```text
R ⋈N S = { <r·s>[X ∪ Y] | r ∈ R ∧ s ∈ S ∧ r[Z] = s[Z] }
       = πX∪Y(σZ=Z(R × S))
```

==보통 "조인"이라고 하면 자연 조인을 뜻한다.== `학생 ⋈N 등록`의 앞부분은 다음과 같다.

| 학번 | 이름   | 학년 | 학과   | 과목번호 | 성적 | 중간성적 | 기말성적 |
| ---- | ------ | ---- | ------ | -------- | ---- | -------- | -------- |
| 100  | 나수영 | 4    | 컴퓨터 | C413     | A    | 90       | 95       |
| 100  | 나수영 | 4    | 컴퓨터 | E412     | A    | 95       | 95       |
| 200  | 이찬수 | 3    | 전기   | C123     | B    | 85       | 80       |
| 300  | 정기태 | 1    | 컴퓨터 | C312     | A    | 90       | 95       |
| …    |        |      |        |          |      |          |          |

**조인을 쓰는 이유**: ==두 릴레이션을 조인할 수 있다는 것은 연결점이 있다는 뜻이고, 그 연결점은 대부분 기본 키와 외래 키의 조합이다.== 조인으로 여러 릴레이션을 하나로 합치면 한 릴레이션만으로는 알 수 없던 정보에 조건을 걸 수 있다. 위 결과에서는 "컴퓨터학과 학생의 C413 성적"처럼 학생과 등록에 흩어진 정보를 함께 조회할 수 있다.

### 디비전(÷)

`R(X)`, `S(Y)`에서 `Y ⊆ X`이고 `D = X − Y`일 때, S의 모든 튜플과 짝을 이루는 R의 D 부분을 구한다.

```text
R ÷ S = { t | t ∈ πD(R) ∧ t·s ∈ R for all s ∈ S }
(R ÷ S) × S ⊆ R
```

=="모든 과목을 수강한 학생"처럼 "모든"이 들어간 질의에 쓴다.==

```text
π학번,이름((π학번,과목번호(등록) ÷ π과목번호(과목)) ⋈N 학생)
```

### 개명 연산(ρ)

중간 결과 릴레이션에 이름을 붙이거나 애트리뷰트 이름을 바꾼다.

| 형식               | 의미                                                           |
| ------------------ | -------------------------------------------------------------- |
| `ρS(E)`            | 관계 대수식 E의 결과 릴레이션 이름을 S로 지정                  |
| `ρS(B1, …, Bm)(E)` | 결과 릴레이션 이름을 S로, 애트리뷰트 이름을 B1, …, Bm으로 지정 |
| `ρ(B1, …, Bm)(R)`  | 릴레이션 R의 애트리뷰트 이름만 B1, …, Bm으로 변경              |

## 기본 연산과 복합 연산

|        | 기본 연산(primitive)              | 복합 연산(composite)                  |
| ------ | --------------------------------- | ------------------------------------- |
| 정의   | 다른 연산으로 대체할 수 없는 연산 | 기본 연산 몇 개로 대체할 수 있는 연산 |
| 연산자 | ∪, −, ×, σ, π                     | ∩, ⋈, ÷                               |

```text
R ∩ S = R − (R − S)
R ⋈A θ B S = σA θ B(R × S)
R(Z, Y) ÷ S(Y) = R[Z] − ((R[Z] × S) − R)[Z]
```

==복합 연산은 연산력을 늘리지 않고 표현력을 늘린다.== 조인은 카티션 프로덕트 뒤에 실렉트를 적용한 것과 같지만, 질의를 훨씬 짧게 쓸 수 있다.

## 관계 대수의 확장

| 연산                     | 기호 | 정의                                                                                               | 용도                                                    |
| ------------------------ | ---- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------------- |
| 세미 조인(semijoin)      | ⋉    | S와 자연 조인할 수 있는 R의 튜플만 남긴다. `R ⋉ S = R ⋈N (πZ(S)) = πX(R ⋈N S)`                     | 분산 질의에서 전송할 데이터 양을 줄인다                 |
| 외부 조인(outer join)    | ⋈⁺   | 상대 릴레이션에 대응하는 튜플이 없으면 상대 쪽을 널로 채워 결과에 포함한다                         | 누락 정보 처리. 두 릴레이션의 튜플이 모두 결과에 남는다 |
| 외부 합집합(outer union) | ∪⁺   | 합병 가능하지 않은 두 릴레이션을 모든 애트리뷰트를 가진 릴레이션으로 합치고, 없는 값은 널로 채운다 | 구조가 다른 릴레이션 합치기                             |
| 집계(aggregation)        | 𝒢    | 그룹별로 집계 함수를 적용한다                                                                      | 평균, 개수 같은 통계                                    |

세미 조인은 교환 법칙이 성립하지 않는다(`R ⋉ S ≠ S ⋉ R`). 대신 `R ⋈N S = (R ⋉ S) ⋈N S`가 성립해, 먼저 R을 줄인 뒤 조인해도 같은 결과를 얻는다.

### 집계 연산

```text
{G A} F B (E)
E: 관계 대수식(릴레이션)
G: 그룹 함수 GROUP, A: 그룹을 나눌 애트리뷰트
F: 집계 함수(SUM, AVG, MAX, MIN, COUNT), B: 집계 함수를 적용할 애트리뷰트
```

| 식                            | 의미                                                  |
| ----------------------------- | ----------------------------------------------------- |
| `AVG성적(등록)`               | 등록 릴레이션 전체 성적의 평균                        |
| `GROUP학년(학생)`             | 학생 튜플을 학년별 그룹으로 나눈다                    |
| `GROUP과목번호 AVG성적(등록)` | 과목별 평균 성적. GROUP을 먼저, AVG를 다음에 실행한다 |
| `GROUP학번 AVG성적(등록)`     | 학생별 평균 성적                                      |

## 질의문을 관계 대수식으로 표현하기

질의를 관계 대수식으로 바꿀 때는 다음 순서로 판단한다.

1. 사용자가 최종적으로 알고 싶은 애트리뷰트(→ 프로젝트)와 조건(→ 실렉트)은 무엇인가
2. 필요한 애트리뷰트가 한 릴레이션에 다 있는가. 없으면 어떤 릴레이션끼리 조인해야 하는가
3. 두 릴레이션을 조인할 수 있는가. 조인 애트리뷰트는 무엇인가

| 질의                                      | 관계 대수식                                  |
| ----------------------------------------- | -------------------------------------------- |
| 모든 학생의 이름과 학과                   | `π이름,학과(학생)`                           |
| 과목번호 C413에 등록한 학생의 이름과 성적 | `π이름,성적(σ과목번호='C413'(학생 ⋈N 등록))` |
| 화일구조 과목의 담당교수                  | `π담당교수(σ과목이름='화일구조'(과목))`      |
| 학생 <600, 김영호, 4, 컴퓨터> 삽입        | `학생 ∪ {<600, '김영호', 4, '컴퓨터'>}`      |
| 데이터베이스 과목 삭제                    | `과목 − σ과목이름='데이터베이스'(과목)`      |

수업 실습에서 풀었던 "담당교수가 황수관인 과목을 수강한 학생의 학번과 중간성적"은 세 단계로 나눠 쓸 수 있다.

```text
A = σ담당교수='황수관'(과목)              -- C312 자료구조 한 튜플
B = 등록 ⋈과목번호=과목번호 A             -- C312를 수강한 등록 튜플 3개
C = π학번,중간성적(B)
```

| 학번 | 중간성적 |
| ---- | -------- |
| 300  | 90       |
| 400  | 90       |
| 500  | 85       |

같은 질의를 SQL로 쓰면 다음과 같다. SQL 문법은 [다음 글](/memo/db-sql-ddl-dml)에서 다룬다.

```sql
SELECT E.Sno, E.Midterm
FROM ENROL E JOIN COURSE C ON E.Cno = C.Cno
WHERE C.Prname = '황수관';
```

## 과제로 풀어 본 문제

**자연 조인을 기본 연산으로 풀기.** 5주차 과제에서 `학생 ⋈N 등록`을 카티션 프로덕트(×), 실렉트(σ), 프로젝트(π) 순서로 직접 계산했다.

![자연 조인을 카티션 프로덕트, 실렉트, 프로젝트로 나눈 식](./images/db-relational-algebra-natural-join.jpg '과제에서 계산 순서를 색으로 표시한 식. 파랑, 빨강, 초록 순서로 계산한다')

1. **파랑, `학생 × 등록`**: 학생 5튜플과 등록 튜플을 모두 짝지어 학생.학번과 등록.학번이 다른 조합까지 모두 만든다.
2. **빨강, `σ학생.학번=등록.학번`**: 두 학번이 같은 튜플만 남긴다. 등록 11튜플과 같은 수가 남는다.
3. **초록, `π합집합`**: 학생.학번과 등록.학번 가운데 하나만 남겨, 중복 조인 애트리뷰트를 제거한다.

세 단계를 거친 결과가 본문의 `학생 ⋈N 등록` 표와 같다. 조인이 복합 연산이라는 것을 계산으로 확인한 셈이다.

**연산 결과 릴레이션의 기본 키.** R의 기본 키를 A, S의 기본 키를 B라 할 때 결과의 기본 키는 다음과 같다.

| 연산     | 결과의 기본 키                        | 이유                                                           |
| -------- | ------------------------------------- | -------------------------------------------------------------- |
| σ조건(R) | A                                     | R의 튜플 일부만 남으므로 그대로 유일하다                       |
| πY(R)    | Y 전체 (Y가 A를 포함하면 A)           | 프로젝트는 중복을 제거하므로 Y 전체는 항상 유일하다            |
| R × S    | AB                                    | R의 튜플과 S의 튜플 짝마다 하나씩 생긴다                       |
| R ∪ S    | 모든 애트리뷰트                       | 두 릴레이션의 튜플이 섞이므로 A만으로는 유일하다는 보장이 없다 |
| R ∩ S    | A (또는 B)                            | 결과는 R의 부분집합이자 S의 부분집합이다                       |
| R − S    | A                                     | 결과는 R의 부분집합이다                                        |
| R ⋈A=B S | AB (A와 B가 같은 애트리뷰트면 A)      | 카티션 프로덕트의 부분집합이다                                 |
| R ÷ S    | R의 키에서 S의 애트리뷰트를 뺀 나머지 | 결과 애트리뷰트가 D = X − Y뿐이다                              |

**납품 데이터베이스 질의.** [관계 데이터 모델 글](/memo/db-relational-model-keys)의 S, P, SP로 관계 대수식을 썼다.

| 질의                               | 관계 대수식                            |
| ---------------------------------- | -------------------------------------- |
| 모든 납품업자의 Sname과 City       | `πSname,City(S)`                       |
| 제품 123을 발송한 납품업자의 Sname | `πSname(S ⋈Sno=Sno σPno=123(SP))`      |
| 색이 red인 제품의 Pname            | `πPname(σColour='red'(P))`             |
| Nut를 발송한 납품업자의 Sname      | `πSname(S ⋈N (SP ⋈N σPname='Nut'(P)))` |

마지막 질의는 과제를 제출한 시각에 `S ⋈ σPname='Nut'(P)`로 썼는데, S와 P에는 공통 애트리뷰트가 없어 조인 조건을 세울 수 없다. ==납품업자와 제품은 발송(SP)을 통해서만 연결되므로, SP와 P를 먼저 조인해 Nut의 발송 튜플을 구한 뒤 S와 조인해야 한다.==

```text
A = σPname='Nut'(P)
B = SP ⋈N A        -- Nut를 발송한 (Sno, Pno, Qty, …)
C = S ⋈N B
πSname(C)
```

## 정리

- 관계 대수는 절차 언어이고, 연산 결과가 다시 릴레이션인 폐쇄 성질 덕분에 연산을 중첩할 수 있다.
- 실렉트는 수평적 부분집합, 프로젝트는 수직적 부분집합을 만들고, 조인은 기본 키와 외래 키로 릴레이션을 연결한다.
- ∪, −, ×, σ, π가 기본 연산이고, ∩, ⋈, ÷는 기본 연산으로 표현할 수 있는 복합 연산이다.
