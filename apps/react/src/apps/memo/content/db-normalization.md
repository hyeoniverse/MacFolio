## 릴레이션 스키마 설계와 이상

논리적 데이터베이스 설계는 관계 모델로 실세계를 정확히 표현하는 작업이다.

1. 애트리뷰트, 개체, 관계를 파악한다.
2. 관련 애트리뷰트를 릴레이션으로 묶는다. 이때 애트리뷰트 사이의 관계(데이터 종속성), 처리 효율, 데이터 일관성을 고려한다.
3. 데이터를 변경할 때 생기는 이상(anomaly)을 예방한다.

이상은 다음 수강 릴레이션에서 확인할 수 있다. 기본 키는 {학번, 과목번호}다.

| 학번 | 과목번호 | 성적 | 학년 |
| ---- | -------- | ---- | ---- |
| 100  | C413     | A    | 4    |
| 100  | E412     | A    | 4    |
| 200  | C123     | B    | 3    |
| 300  | C312     | A    | 1    |
| 300  | C324     | C    | 1    |
| 300  | C413     | A    | 1    |
| 400  | C312     | A    | 4    |
| 400  | C324     | A    | 4    |
| 400  | C413     | B    | 4    |
| 400  | E412     | C    | 4    |
| 500  | C312     | B    | 2    |

| 이상                         | 상황                                        | 결과                                                                  |
| ---------------------------- | ------------------------------------------- | --------------------------------------------------------------------- |
| 삭제 이상(deletion anomaly)  | 200번 학생이 C123 등록을 취소해 튜플을 삭제 | 200번이 3학년이라는 정보도 함께 사라진다(연쇄 삭제에 의한 정보 손실)  |
| 삽입 이상(insertion anomaly) | 600번 학생이 2학년이라는 사실을 삽입        | 과목을 등록하지 않으면 기본 키의 과목번호가 널이 되어 삽입할 수 없다  |
| 갱신 이상(update anomaly)    | 400번 학생의 학년을 4에서 3으로 변경        | 학번 400인 튜플 네 개를 모두 바꿔야 하고, 일부만 바뀌면 모순이 생긴다 |

**원인**: 학년은 학번만으로 정해지는데, 기본 키 {학번, 과목번호}로 식별되는 릴레이션에 함께 들어 있다. ==하나의 릴레이션에 성격이 다른 여러 종속 관계를 함께 표현했기 때문이다.==

**해결**: ==애트리뷰트 사이의 종속 관계를 분해(decomposition)해, 하나의 종속성을 하나의 릴레이션으로 표현한다.== 이 과정이 **정규화(normalization)** 다.

![수강 릴레이션 표(학번·과목번호·성적·학년 11행, 학년이 학번마다 반복)](./images/db-normalization-note-01.jpg '수강 릴레이션 표(학번·과목번호·성적·학년 11행, 학년이 학번마다 반복) (강의 자료)')

### 스키마 변환의 원리

애트리뷰트와 제약조건(종속성)을 수집한 뒤 제약조건에 따라 여러 릴레이션으로 분할하는 것을 스키마 변환(schema transformation)이라 한다. 정규화의 원칙이기도 하다.

1. **정보 표현의 무손실(nonloss representation)**: 분해 후에도 같은 의미의 정보를 유지한다.
2. **최소의 데이터 중복(minimal redundancy)**
3. **분리의 원칙(principle of separation)**: 독립된 관계는 별도의 릴레이션으로 분리해, 각각 독립적으로 처리할 수 있게 한다.

## 함수 종속

어떤 릴레이션 R에서 애트리뷰트 X의 각 값에 대해 애트리뷰트 Y의 값이 시간에 관계없이 항상 하나만 연관되면, Y는 X에 **함수 종속(functional dependency, FD)** 이라 하고 `X → Y`로 쓴다. X를 결정자(determinant), Y를 종속자(dependent)라 한다. X와 Y는 각각 애트리뷰트 집합일 수 있다.

학생 릴레이션에서 학번 하나에 대응하는 이름, 학년, 학과는 하나뿐이므로 다음이 성립한다.

```text
학번 → 이름, 학번 → 학년, 학번 → 학과
학번 → (이름, 학년, 학과)
```

- X가 후보 키라면 R의 모든 애트리뷰트 Y에 대해 `X → Y`가 성립한다.
- 반대로 X가 반드시 후보 키여야 하는 것은 아니다. 수강 릴레이션의 `학번 → 학년`에서 학번 100인 튜플은 두 개지만, 학년은 둘 다 4다. X 값이 같으면 Y 값도 같아야 한다는 것이 조건이다.
- ==함수 종속은 데이터 값에서 우연히 관찰되는 성질이 아니라 데이터의 의미(semantics)다.== `학번 → 학년`은 "학생은 한 학년에만 속한다"는 의미적 제약조건이다. DBMS는 함수 종속을 스키마에 명세하고 보장하는 방법을 제공해야 한다.

### 완전 함수 종속과 부분 함수 종속

애트리뷰트 둘 이상으로 구성된 집합 X에 대해 `X → Y`가 성립할 때,

|                            | 정의                                      | 수강 릴레이션 예                                           |
| -------------------------- | ----------------------------------------- | ---------------------------------------------------------- |
| 완전 함수 종속(full FD)    | X의 진부분집합 X′ 중 `X′ → Y`인 것이 없다 | 성적은 {학번, 과목번호}에 완전 함수 종속                   |
| 부분 함수 종속(partial FD) | X의 진부분집합 X′ 중 `X′ → Y`인 것이 있다 | 학년은 {학번, 과목번호}에 부분 함수 종속 (학번만으로 결정) |

학년은 학번 하나에 대해서는 완전 함수 종속이다. 이 관계를 그림으로 그린 것이 함수 종속 다이어그램이며, 정규화의 단계별 분해 대상을 찾는 데 쓴다.

![{학번,과목번호}→성적, 학번→학년을 화살표로 그린 수강 릴레이션 함수 종속 다이어그램](./images/db-normalization-note-02.jpg '{학번,과목번호}→성적, 학번→학년을 화살표로 그린 수강 릴레이션 함수 종속 다이어그램 (강의 자료)')

### 함수 종속의 추론 규칙

| 규칙                   | 내용                        | 예                                               |
| ---------------------- | --------------------------- | ------------------------------------------------ |
| R1 반사(reflexive)     | A ⊇ B이면 A → B. 또한 A → A | {학번, 과목번호} → 과목번호                      |
| R2 첨가(augmentation)  | A → B이면 AC → BC, AC → B   | 학번 → 학년이면 {학번, 이름} → {학년, 이름}      |
| R3 이행(transitive)    | A → B이고 B → C이면 A → C   | 학번 → 학과이고 학과 → 학과장이면 학번 → 학과장  |
| R4 분해(decomposition) | A → BC이면 A → B            | 학번 → {이름, 학년}이면 학번 → 이름              |
| R5 결합(union)         | A → B이고 A → C이면 A → BC  | 학번 → 이름, 학번 → 학년이면 학번 → {이름, 학년} |

## 정규형

정규형(normal form)은 일련의 제약조건을 만족하는 릴레이션이다. 정규화는 스키마 변환 `S → S′`로 더 높은 정규형을 만든다.

![1NF에서 BCNF까지의 분해 과정](./images/db-normalization-steps.svg '각 단계에서 제거하는 종속과 분해 결과')

### 제1정규형(1NF)

**모든 도메인이 원자 값만으로 된 릴레이션**이다. 다음 수강지도 릴레이션은 1NF다. 기본 키는 {학번, 과목번호}다.

| 학번 | 지도교수 | 학과   | 과목번호 | 성적 |
| ---- | -------- | ------ | -------- | ---- |
| 100  | P1       | 컴퓨터 | C413     | A    |
| 100  | P1       | 컴퓨터 | E412     | A    |
| 200  | P2       | 전기   | C123     | B    |
| 300  | P3       | 컴퓨터 | C312     | A    |
| 300  | P3       | 컴퓨터 | C324     | C    |
| 300  | P3       | 컴퓨터 | C413     | A    |
| 400  | P1       | 컴퓨터 | C312     | A    |
| 400  | P1       | 컴퓨터 | C324     | A    |
| 400  | P1       | 컴퓨터 | C413     | B    |
| 400  | P1       | 컴퓨터 | E412     | C    |

함수 종속은 다음과 같다.

```text
{학번, 과목번호} → 성적     (완전 함수 종속)
학번 → 지도교수              모든 학생은 지도교수가 한 명이다
학번 → 학과                  모든 학생은 한 학과에만 속한다
지도교수 → 학과              모든 지도교수는 한 학과에만 속한다
```

지도교수와 학과는 기본 키 {학번, 과목번호}에 부분 함수 종속이다.

![수강지도 릴레이션의 함수 종속 다이어그램](./images/db-normalization-fd-diagram.svg '빨간 화살표가 2NF에서, 주황 화살표가 3NF에서 제거할 종속이다')

| 1NF의 이상 | 내용                                                                        |
| ---------- | --------------------------------------------------------------------------- |
| 삽입 이상  | 500번 학생의 지도교수가 P4라는 사실은 과목을 등록하기 전에는 삽입할 수 없다 |
| 삭제 이상  | 200번 학생이 C123 등록을 취소하면 지도교수가 P2라는 정보까지 사라진다       |
| 갱신 이상  | 400번 학생의 지도교수를 P1에서 P3로 바꾸면 튜플 네 개를 모두 바꿔야 한다    |

**원인**: 기본 키에 부분 함수 종속된 애트리뷰트가 있다. 기본 키로 식별되는 개체(수강)와 무관한 애트리뷰트(지도교수, 학과)가 섞여, 독립적인 두 정보가 한 릴레이션에 표현되었다.

**해결**: 프로젝션으로 분해해 부분 함수 종속을 제거한다 → 2NF

![수강지도 릴레이션 표(학번·지도교수·학과·과목번호·성적 10행)](./images/db-normalization-note-03.jpg '수강지도 릴레이션 표(학번·지도교수·학과·과목번호·성적 10행) (강의 자료)')

![수강지도의 함수 종속 다이어그램({학번,과목번호}→성적, 학번→지도교수·학과, 지도교수→학과)](./images/db-normalization-note-04.jpg '수강지도의 함수 종속 다이어그램({학번,과목번호}→성적, 학번→지도교수·학과, 지도교수→학과) (강의 자료)')

### 제2정규형(2NF)

==**1NF이고, 키에 속하지 않는 모든 애트리뷰트가 기본 키에 완전 함수 종속**==인 릴레이션이다. 수강지도를 다음 두 릴레이션으로 분해한다.

```text
지도 (학번, 지도교수, 학과)          기본 키: 학번
수강 (학번, 과목번호, 성적)          기본 키: {학번, 과목번호}, 외래 키: 학번 → 지도
```

이 분해는 **무손실 분해(nonloss decomposition)** 다. ==프로젝션으로 나눈 릴레이션을 자연 조인하면 원래 릴레이션으로 돌아간다.== 원래 릴레이션의 정보는 분해된 릴레이션에서 모두 얻을 수 있지만, 그 역은 성립하지 않는다. "500번 학생의 지도교수는 P4"는 수강지도에서는 표현할 수 없었지만 지도 릴레이션에는 넣을 수 있다.

> **Heath의 무손실 분해 정리**: R(A, B, C)에서 함수 종속 A → B가 성립하면, R은 R1(A, B)와 R2(A, C)로 정보 손실 없이 분해할 수 있다.

지도 릴레이션에도 이상이 남는다.

| 학번 | 지도교수 | 학과   |
| ---- | -------- | ------ |
| 100  | P1       | 컴퓨터 |
| 200  | P2       | 전기   |
| 300  | P3       | 컴퓨터 |
| 400  | P1       | 컴퓨터 |

| 2NF(지도)의 이상 | 내용                                                                          |
| ---------------- | ----------------------------------------------------------------------------- |
| 삽입 이상        | 지도할 학생이 없으면 어떤 교수가 어떤 학과에 속한다는 사실을 삽입할 수 없다   |
| 삭제 이상        | 300번 학생의 튜플을 삭제하면 P3가 컴퓨터학과라는 정보도 사라진다              |
| 갱신 이상        | P1의 소속을 컴퓨터에서 전기로 바꾸면 학번 100과 400의 튜플을 모두 바꿔야 한다 |

**원인**: 이행적 함수 종속이 있다. 릴레이션 R에서 A → B, B → C가 성립해 A → C가 되면, C는 A에 이행적 함수 종속(transitive dependency)이라 한다. 지도에서는 `학번 → 지도교수 → 학과`다.

**해결**: 프로젝션으로 분해해 이행적 함수 종속을 제거한다 → 3NF

![분해 후 지도(학번→지도교수→학과)와 수강({학번,과목번호}→성적) 함수 종속 다이어그램](./images/db-normalization-note-06.jpg '분해 후 지도(학번→지도교수→학과)와 수강({학번,과목번호}→성적) 함수 종속 다이어그램 (강의 자료)')

![2NF로 분해한 지도(4행)와 수강(10행) 릴레이션 표](./images/db-normalization-note-07.jpg '2NF로 분해한 지도(4행)와 수강(10행) 릴레이션 표 (강의 자료)')

### 제3정규형(3NF)

==**2NF이고, 키가 아닌 모든 애트리뷰트가 기본 키에 이행적 함수 종속이 아닌**== 릴레이션이다. 지도를 다음 두 릴레이션으로 분해한다.

```text
학생지도 (학번, 지도교수)           기본 키: 학번, 외래 키: 지도교수 → 지도교수학과
지도교수학과 (지도교수, 학과)       기본 키: 지도교수
```

이제 "지도교수 P4는 수학과 소속"을 학생 없이 넣을 수 있다. 3NF에서는 키가 아닌 애트리뷰트를 갱신해도 이상이 생기지 않는다. 애트리뷰트가 두 개뿐인 이원 릴레이션(binary relation)은 이행적 종속이 생길 여지가 없어 모두 3NF다.

![2NF→(프로젝션)→3NF, 3NF→(조인)→2NF 양방향 화살표](./images/db-normalization-note-08.jpg '2NF→(프로젝션)→3NF, 3NF→(조인)→2NF 양방향 화살표 (강의 자료)')

![분해 후 학번→지도교수, 지도교수→학과 두 함수 종속 다이어그램](./images/db-normalization-note-09.jpg '분해 후 학번→지도교수, 지도교수→학과 두 함수 종속 다이어그램 (강의 자료)')

![3NF로 분해한 학생지도(4행)와 지도교수학과(3행) 릴레이션 표](./images/db-normalization-note-10.jpg '3NF로 분해한 학생지도(4행)와 지도교수학과(3행) 릴레이션 표 (강의 자료)')

### 3NF의 약점

3NF는 다음 세 조건이 모두 성립하는 릴레이션에서 이상을 막지 못한다.

1. 후보 키가 여러 개다.
2. 후보 키들이 두 개 이상의 애트리뷰트로 구성된다.
3. 후보 키들의 애트리뷰트가 서로 겹친다.

수강과목(학번, 과목, 교수) 릴레이션의 제약조건은 다음과 같다.

- 한 학생은 과목마다 한 교수의 강의만 수강한다.
- 각 교수는 한 과목만 담당한다.
- 한 과목을 여러 교수가 담당할 수 있다.

| 학번 | 과목       | 교수 |
| ---- | ---------- | ---- |
| 100  | 프로그래밍 | P1   |
| 100  | 자료구조   | P2   |
| 200  | 프로그래밍 | P1   |
| 200  | 자료구조   | P3   |
| 300  | 자료구조   | P3   |
| 300  | 프로그래밍 | P4   |

후보 키는 {학번, 과목}과 {학번, 교수}이고, 기본 키는 {학번, 과목}이다. 함수 종속은 `{학번, 과목} → 교수`, `교수 → 과목`이다. 키가 아닌 애트리뷰트는 교수 하나뿐이고 기본 키에 이행적으로 종속되지 않으므로 3NF지만 이상이 생긴다.

| 3NF(수강과목)의 이상 | 내용                                                                      |
| -------------------- | ------------------------------------------------------------------------- |
| 삽입 이상            | 교수 P5가 자료구조를 담당한다는 사실은 수강 학생이 있어야 삽입할 수 있다  |
| 삭제 이상            | 100번 학생이 자료구조를 취소하면 P2가 자료구조 담당이라는 정보도 사라진다 |
| 갱신 이상            | P1이 담당 과목을 자료구조로 바꾸면 P1이 나오는 모든 튜플을 바꿔야 한다    |

**원인**: 교수는 결정자(교수 → 과목)지만 후보 키가 아니다.

![수강과목 릴레이션 표(학번·과목·교수 6행, P1~P4)](./images/db-normalization-note-11.jpg '수강과목 릴레이션 표(학번·과목·교수 6행, P1~P4) (강의 자료)')

![수강과목의 함수 종속 다이어그램({학번,과목}→교수, 교수→과목)](./images/db-normalization-note-12.jpg '수강과목의 함수 종속 다이어그램({학번,과목}→교수, 교수→과목) (강의 자료)')

### 보이스/코드 정규형(BCNF)

==**릴레이션 R의 모든 결정자가 후보 키**==이면 R은 BCNF(Boyce/Codd Normal Form)다. 강한 제3정규형(strong 3NF)이라고도 하며, BCNF인 릴레이션은 1NF, 2NF, 3NF에도 속한다. 수강과목을 다음 두 릴레이션으로 분해한다.

```text
수강교수 (학번, 교수)             기본 키: {학번, 교수}, 외래 키: 교수 → 과목교수
과목교수 (교수, 과목)             기본 키: 교수
```

과목교수의 결정자는 교수 하나이고 교수가 후보 키이므로 BCNF다. P5가 자료구조를 담당한다는 사실도 학생 없이 넣을 수 있다.

![BCNF로 분해한 수강교수(학번·교수 6행)와 과목교수(교수·과목 4행) 릴레이션 표](./images/db-normalization-note-13.jpg 'BCNF로 분해한 수강교수(학번·교수 6행)와 과목교수(교수·과목 4행) 릴레이션 표 (강의 자료)')

![분해 후 {학번,교수} 키 박스와 교수→과목 함수 종속 다이어그램](./images/db-normalization-note-14.jpg '분해 후 {학번,교수} 키 박스와 교수→과목 함수 종속 다이어그램 (강의 자료)')

## 정규형 사이의 관계

| 정규형 | 조건                                                           | 이전 단계에서 제거하는 것 |
| ------ | -------------------------------------------------------------- | ------------------------- |
| 1NF    | 모든 도메인이 원자 값                                          | 반복 그룹(다중 값)        |
| 2NF    | 1NF + 키가 아닌 애트리뷰트가 기본 키에 완전 함수 종속          | 부분 함수 종속            |
| 3NF    | 2NF + 키가 아닌 애트리뷰트가 기본 키에 이행적 함수 종속이 아님 | 이행적 함수 종속          |
| BCNF   | 모든 결정자가 후보 키                                          | 후보 키가 아닌 결정자     |

정규형은 포함 관계에 있다. BCNF ⊂ 3NF ⊂ 2NF ⊂ 1NF이며, 높은 정규형일수록 조건이 엄격하다.

- ==정규화는 실제 데이터 값이 아니라 의미(함수 종속)를 기준으로 판단해야 한다.== 지금 들어 있는 값이 우연히 종속처럼 보여도 의미상 제약이 아니면 함수 종속이 아니다.
- 실제 설계에서는 정규형 순서대로 한 단계씩 진행하지 않을 수도 있다.

![비정규 릴레이션→1NF→2NF→3NF→BCNF→4NF→5NF로 가며 각 단계에서 제거하는 종속(부분·이행·결정자·MVD·JD) 흐름도](./images/db-normalization-note-15.jpg '비정규 릴레이션→1NF→2NF→3NF→BCNF→4NF→5NF로 가며 각 단계에서 제거하는 종속(부분·이행·결정자·MVD·JD) 흐름도 (강의 자료)')

![정규/비정규 릴레이션 ⊃ 1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF ⊃ 4NF ⊃ 5NF(PJ/NF) 중첩 타원 포함 관계도](./images/db-normalization-note-16.jpg '정규/비정규 릴레이션 ⊃ 1NF ⊃ 2NF ⊃ 3NF ⊃ BCNF ⊃ 4NF ⊃ 5NF(PJ/NF) 중첩 타원 포함 관계도 (강의 자료)')

## 과제로 풀어 본 문제

### 직원 릴레이션 정규화

직원(직원번호, 직원이름, 봉급, 과장, 과이름) 릴레이션을 분석했다. 직원은 한 과에만 속하고, 각 과에는 과장이 한 명 있다.

| 직원번호 | 직원이름 | 봉급  | 과장   | 과이름 |
| -------- | -------- | ----- | ------ | ------ |
| 100      | 나수영   | 400만 | 박종화 | 인사과 |
| 200      | 이찬수   | 300만 | 박종화 | 인사과 |
| 300      | 정기태   | 200만 | 황수관 | 자재과 |
| 400      | 송병길   | 200만 | 이규찬 | 총무과 |

기본 키는 직원번호이고, 함수 종속은 직원번호 → 직원이름, 봉급, 과장, 과이름과 과이름 → 과장이다.

![직원 릴레이션의 함수 종속 다이어그램](./images/db-normalization-employee-fd.jpg '과제에서 그린 다이어그램. 과이름에서 과장으로 가는 화살표가 이행적 종속이다')

- **정규형**: 기본 키가 애트리뷰트 하나라 부분 함수 종속이 생길 수 없으므로 2NF다. 직원번호 → 과이름 → 과장의 이행적 함수 종속이 있어 3NF는 아니다.
- **이상**:
  - 삽입 이상: 직원이 없는 과의 과장 정보를 넣을 수 없다.
  - 삭제 이상: 100번과 200번을 모두 삭제하면 박종화가 인사과 과장이라는 정보도 사라진다.
  - 갱신 이상: 인사과 과장이 바뀌면 100번과 200번 튜플을 모두 바꿔야 한다.
- **분해**: 과이름 → 과장을 별도 릴레이션으로 분리하면 3NF다.

```text
직원 (직원번호, 직원이름, 봉급, 과이름)     외래 키: 과이름 → 과
과   (과이름, 과장)
```

### 참과 거짓

| 명제                                                     | 판정                                                                                    |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 모든 이원 릴레이션은 2NF, 3NF, BCNF다                    | 참. 애트리뷰트가 둘이면 부분 종속도 이행적 종속도 생길 수 없고, 결정자는 항상 후보 키다 |
| R(A, B, C)가 R1(A, B)와 R2(A, C)의 조인과 같으면 A → B다 | 거짓                                                                                    |
| A → B이고 B → C이면 A → C다                              | 참 (이행 규칙)                                                                          |
| A → B이고 A → C이면 A → {B, C}다                         | 참 (결합 규칙)                                                                          |
| B → A이고 C → A이면 {B, C} → A다                         | 참 (첨가 규칙으로 {B, C} → {A, C}, 분해 규칙으로 {B, C} → A)                            |

두 번째 명제는 과제를 제출한 시각에 참으로 답했다. Heath의 정리는 "A → B이면 무손실 분해할 수 있다"이고, 그 역은 성립하지 않는다. R(A, B, C) = {(1, x, p), (1, y, p)}는 R1 = {(1, x), (1, y)}와 R2 = {(1, p)}로 나누어 조인해도 원래대로 돌아오지만, A = 1에 B가 x와 y 두 개라 A → B가 아니다. ==무손실 조인이 보장하는 것은 이보다 약한 다치 종속(A →→ B)이다.==

### 함수 종속으로 정규형 판정하기

R(A, B, C, D)의 기본 키가 {A, B}이고 C, D가 모두 {A, B}에 함수 종속일 때, 다음 종속이 추가되면 정규형은 이렇게 된다.

| 추가 종속 | 정규형 | 이유                                                                                         |
| --------- | ------ | -------------------------------------------------------------------------------------------- |
| 없음      | BCNF   | 결정자가 기본 키뿐이다                                                                       |
| C → D     | 2NF    | {A, B} → C → D의 이행적 종속                                                                 |
| C → B     | 3NF    | {A, C}도 후보 키가 되어 B는 키 애트리뷰트다. C는 결정자지만 후보 키가 아니므로 BCNF는 아니다 |
| B → D     | 1NF    | D가 기본 키의 일부 B에 부분 함수 종속                                                        |

### 잘못된 분해

지도(학번, 지도교수, 학과)를 학생지도(학번, 지도교수)와 학번학과(학번, 학과)로 분해해도 두 릴레이션은 각각 3NF다. 그러나 지도교수 → 학과라는 함수 종속이 어느 릴레이션에도 남지 않아, 지도교수가 어느 학과 소속인지 학생 없이 저장할 수 없는 삽입 이상이 그대로 남는다. DBMS가 "지도교수는 한 학과에만 속한다"를 검사할 수도 없다. A → B, B → C에서 C가 A에 이행적으로 종속하면, {A, B}와 {B, C}로 분해해야 종속성이 보존된다.

### 단계별 정규화

R(A, B, C, D, E)에 {A, B} → C, A → D, A → E, D → E가 성립한다.

1. **1NF**: 모든 값이 원자 값이다. 기본 키는 {A, B}다.
2. **2NF**: D와 E는 키의 일부 A에 부분 종속이므로 분리한다. R1(A, B, C), R2(A, D, E)
3. **3NF**: R2에 A → D → E의 이행적 종속이 있으므로 분리한다. R1(A, B, C), R2(A, D), R3(D, E)

과제에서는 3단계를 R2(A, D), R3(A, E)로 나눴다. 이렇게 나누면 D → E가 어느 릴레이션에도 남지 않아, 앞 절의 잘못된 분해와 같은 문제가 생긴다. 최종 세 릴레이션은 결정자가 모두 각 릴레이션의 후보 키이므로 BCNF다.

## 정리

- 이상은 여러 종속 관계를 한 릴레이션에 표현해서 생기고, 종속 관계별로 릴레이션을 분해해 해결한다.
- 1NF → 2NF는 부분 함수 종속을, 2NF → 3NF는 이행적 함수 종속을, 3NF → BCNF는 후보 키가 아닌 결정자를 제거한다.
- 분해는 자연 조인으로 원래 릴레이션을 복원할 수 있는 무손실 분해여야 한다.
