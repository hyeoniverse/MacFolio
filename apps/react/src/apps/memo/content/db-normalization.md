데이터베이스 기초 연재의 일곱 번째 글로, 7장(데이터 종속성과 정규화)을 다룬다. [관계 데이터 모델 글](/memo/db-relational-model-keys)에서 원자 값만 갖는 릴레이션을 정규화 릴레이션이라 했는데, 이 글은 그보다 엄격한 정규형으로 릴레이션을 분해하는 방법을 정리한다.

## 릴레이션 스키마 설계와 이상

논리적 데이터베이스 설계는 관계 모델로 실세계를 정확히 표현하는 작업이다.

1. 애트리뷰트, 개체, 관계를 파악한다.
2. 관련 애트리뷰트를 릴레이션으로 묶는다. 이때 애트리뷰트 사이의 관계(데이터 종속성), 처리 효율, 데이터 일관성을 고려한다.
3. 데이터를 변경할 때 생기는 이상(anomaly)을 예방한다.

이상은 다음 수강 릴레이션에서 확인할 수 있다. 기본 키는 {학번, 과목번호}다.

| 학번 | 과목번호 | 성적 | 학년 |
| ---- | -------- | ---- | ---- |
| 100  | C413     | A    | 4    |
| 100  | E412     | A    | 4    |
| 200  | C123     | B    | 3    |
| 300  | C312     | A    | 1    |
| 300  | C324     | C    | 1    |
| 300  | C413     | A    | 1    |
| 400  | C312     | A    | 4    |
| 400  | C324     | A    | 4    |
| 400  | C413     | B    | 4    |
| 400  | E412     | C    | 4    |
| 500  | C312     | B    | 2    |

| 이상                         | 상황                                        | 결과                                                                                                                             |
| ---------------------------- | ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 삭제 이상(deletion anomaly)  | 200번 학생이 C123 등록을 취소해 튜플을 삭제 | 200번이 3학년이라는 정보도 함께 사라진다(연쇄 삭제에 의한 정보 손실)                                                             |
| 삽입 이상(insertion anomaly) | 600번 학생이 2학년이라는 사실을 삽입        | 과목을 등록하지 않으면 기본 키의 과목번호가 널이 되어 삽입할 수 없다. 임시 과목번호 같은 원하지 않는 정보를 강제로 삽입해야 한다 |
| 갱신 이상(update anomaly)    | 400번 학생의 학년을 4에서 3으로 변경        | 학번 400인 튜플 네 개를 모두 바꿔야 하고, 일부만 바뀌면 모순이 생긴다                                                            |

이상은 ==하나의 릴레이션에 성격이 다른 여러 종속 관계를 함께 표현해서 생긴다.== 학년은 학번만으로 정해지는데, 기본 키 {학번, 과목번호}로 식별되는 릴레이션에 함께 들어 있다. 이상을 없애려면 ==애트리뷰트 사이의 종속 관계를 분해(decomposition)해 하나의 종속성을 하나의 릴레이션으로 표현한다.== 이 과정이 **정규화(normalization)** 다.

![수강 릴레이션 표(학번·과목번호·성적·학년 11행, 학년이 학번마다 반복)](./images/db-normalization-note-01.jpg '수강 릴레이션 표(학번·과목번호·성적·학년 11행, 학년이 학번마다 반복) (강의 자료)')

### 스키마 변환의 원리

애트리뷰트와 제약조건(종속성)을 수집한 뒤 제약조건에 따라 여러 릴레이션으로 분할하는 것을 스키마 변환(schema transformation)이라 한다. 정규화의 원칙이기도 하다.

| 원리                                        | 내용                                                                           |
| ------------------------------------------- | ------------------------------------------------------------------------------ |
| 정보 표현의 무손실(nonloss representation)  | 분해 후에도 같은 의미의 정보를 유지한다                                        |
| 최소의 데이터 중복(minimal data redundancy) | 같은 사실을 여러 튜플에 반복 저장하지 않는다                                   |
| 분리의 원칙(principle of separation)        | 독립된 관계는 별도의 릴레이션으로 분리해 릴레이션마다 독립적으로 처리하게 한다 |

## 함수 종속

어떤 릴레이션 R에서 애트리뷰트 X의 각 값에 대해 애트리뷰트 Y의 값이 최대 하나만 연관되면, Y는 X에 **함수 종속(functional dependency, FD)** 이라 하고 `X → Y`로 쓴다. X가 Y를 (함수적으로) 결정한다고도 하며, X를 결정자(determinant), Y를 종속자(dependent)라 한다. X와 Y는 각각 애트리뷰트 집합일 수 있다.

학생 릴레이션에서 학번 하나에 대응하는 이름, 학년, 학과는 하나뿐이므로 다음이 성립한다.

```text
학번 → 이름, 학번 → 학년, 학번 → 학과
학번 → (이름, 학년, 학과)
```

- X가 후보 키라면 R의 모든 애트리뷰트 Y에 대해 `X → Y`가 성립한다.
- 반대로 X가 반드시 후보 키여야 하는 것은 아니다. 수강 릴레이션의 `학번 → 학년`에서 학번 100인 튜플은 두 개지만, 학년은 둘 다 4다. X 값이 같으면 Y 값도 같아야 한다는 것이 조건이다.
- ==함수 종속은 데이터 값에서 우연히 관찰되는 성질이 아니라 데이터의 의미(semantics)다.== `학번 → 학년`은 "학생은 한 학년에만 속한다"는 의미적 제약조건이다. DBMS는 함수 종속을 스키마에 명세하고 보장하는 방법을 제공해야 한다.

### 완전 함수 종속과 부분 함수 종속

애트리뷰트 둘 이상으로 구성된 집합 X에 대해 `X → Y`가 성립할 때,

|                            | 정의                                      | 수강 릴레이션 예                                           |
| -------------------------- | ----------------------------------------- | ---------------------------------------------------------- |
| 완전 함수 종속(full FD)    | X의 진부분집합 X′ 중 `X′ → Y`인 것이 없다 | 성적은 {학번, 과목번호}에 완전 함수 종속                   |
| 부분 함수 종속(partial FD) | X의 진부분집합 X′ 중 `X′ → Y`인 것이 있다 | 학년은 {학번, 과목번호}에 부분 함수 종속 (학번만으로 결정) |

학년은 학번 하나에 대해서는 완전 함수 종속이다. 이 관계를 그림으로 그린 것이 함수 종속 다이어그램이며, 정규화의 단계별 분해 대상을 찾는 데 쓴다.

![{학번,과목번호}→성적, 학번→학년을 화살표로 그린 수강 릴레이션 함수 종속 다이어그램](./images/db-normalization-note-02.jpg '{학번,과목번호}→성적, 학번→학년을 화살표로 그린 수강 릴레이션 함수 종속 다이어그램 (강의 자료)')

### 함수 종속의 추론 규칙

| 규칙                   | 내용                        | 예                                               |
| ---------------------- | --------------------------- | ------------------------------------------------ |
| R1 반사(reflexive)     | A ⊇ B이면 A → B. 또한 A → A | {학번, 과목번호} → 과목번호                      |
| R2 첨가(augmentation)  | A → B이면 AC → BC, AC → B   | 학번 → 학년이면 {학번, 이름} → {학년, 이름}      |
| R3 이행(transitive)    | A → B이고 B → C이면 A → C   | 학번 → 학과이고 학과 → 학과장이면 학번 → 학과장  |
| R4 분해(decomposition) | A → BC이면 A → B            | 학번 → {이름, 학년}이면 학번 → 이름              |
| R5 결합(union)         | A → B이고 A → C이면 A → BC  | 학번 → 이름, 학번 → 학년이면 학번 → {이름, 학년} |

## 정규형

정규형(normal form)은 일련의 제약조건을 만족하는 릴레이션이다. 정규화는 스키마 변환 `S → S′`로 더 높은 정규형을 만든다.

![1NF에서 BCNF까지의 분해 과정](./images/db-normalization-steps.svg '각 단계에서 제거하는 종속과 분해 결과')

### 제1정규형(1NF)

**모든 도메인이 원자 값만으로 된 릴레이션**이다. 다음 수강지도 릴레이션은 1NF다. 기본 키는 {학번, 과목번호}다.

| 학번 | 지도교수 | 학과   | 과목번호 | 성적 |
| ---- | -------- | ------ | -------- | ---- |
| 100  | P1       | 컴퓨터 | C413     | A    |
| 100  | P1       | 컴퓨터 | E412     | A    |
| 200  | P2       | 전기   | C123     | B    |
| 300  | P3       | 컴퓨터 | C312     | A    |
| 300  | P3       | 컴퓨터 | C324     | C    |
| 300  | P3       | 컴퓨터 | C413     | A    |
| 400  | P1       | 컴퓨터 | C312     | A    |
| 400  | P1       | 컴퓨터 | C324     | A    |
| 400  | P1       | 컴퓨터 | C413     | B    |
| 400  | P1       | 컴퓨터 | E412     | C    |

함수 종속은 다음과 같다.

```text
{학번, 과목번호} → 성적     (완전 함수 종속)
학번 → 지도교수              모든 학생은 지도교수가 한 명이다
학번 → 학과                  모든 학생은 한 학과에만 속한다
지도교수 → 학과              모든 지도교수는 한 학과에만 속한다
```

지도교수와 학과는 기본 키 {학번, 과목번호}에 부분 함수 종속이다.

![수강지도 릴레이션의 함수 종속 다이어그램](./images/db-normalization-fd-diagram.svg '빨간 화살표가 2NF에서, 주황 화살표가 3NF에서 제거할 종속이다')

| 1NF의 이상 | 내용                                                                        |
| ---------- | --------------------------------------------------------------------------- |
| 삽입 이상  | 500번 학생의 지도교수가 P4라는 사실은 과목을 등록하기 전에는 삽입할 수 없다 |
| 삭제 이상  | 200번 학생이 C123 등록을 취소하면 지도교수가 P2라는 정보까지 사라진다       |
| 갱신 이상  | 400번 학생의 지도교수를 P1에서 P3로 바꾸면 튜플 네 개를 모두 바꿔야 한다    |

1NF에서 이상이 생기는 원인은 기본 키에 부분 함수 종속된 애트리뷰트가 있기 때문이다. 기본 키로 식별되는 개체(수강)와 무관한 애트리뷰트(지도교수, 학과)가 섞여, 독립적인 두 정보가 한 릴레이션에 표현되었다. 프로젝션으로 분해해 부분 함수 종속을 제거하면 2NF가 된다.

![수강지도 릴레이션 표(학번·지도교수·학과·과목번호·성적 10행)](./images/db-normalization-note-03.jpg '수강지도 릴레이션 표(학번·지도교수·학과·과목번호·성적 10행) (강의 자료)')

![수강지도의 함수 종속 다이어그램({학번,과목번호}→성적, 학번→지도교수·학과, 지도교수→학과)](./images/db-normalization-note-04.jpg '수강지도의 함수 종속 다이어그램({학번,과목번호}→성적, 학번→지도교수·학과, 지도교수→학과) (강의 자료)')

### 제2정규형(2NF)

==**1NF이고, 키에 속하지 않는 모든 애트리뷰트가 기본 키에 완전 함수 종속**==인 릴레이션이다. 수강지도를 다음 두 릴레이션으로 분해한다.

```text
지도 (학번, 지도교수, 학과)          기본 키: 학번
수강 (학번, 과목번호, 성적)          기본 키: {학번, 과목번호}, 외래 키: 학번 → 지도
```

이 분해는 **무손실 분해(nonloss decomposition)** 다. ==프로젝션으로 나눈 릴레이션을 자연 조인하면 원래 릴레이션으로 돌아간다.== 원래 릴레이션의 정보는 분해된 릴레이션에서 모두 얻을 수 있지만, 그 역은 성립하지 않는다. "500번 학생의 지도교수는 P4"는 수강지도에서는 표현할 수 없었지만 지도 릴레이션에는 넣을 수 있다.

#### Heath의 무손실 분해 정리

R(A, B, C)에서 함수 종속 A → B가 성립하면, R은 R1(A, B)와 R2(A, C)로 정보 손실 없이 분해할 수 있다. 수강지도에서는 학번 → {지도교수, 학과}이므로 지도와 수강으로 나누어도 정보가 손실되지 않는다.

지도 릴레이션에도 이상이 남는다.

| 학번 | 지도교수 | 학과   |
| ---- | -------- | ------ |
| 100  | P1       | 컴퓨터 |
| 200  | P2       | 전기   |
| 300  | P3       | 컴퓨터 |
| 400  | P1       | 컴퓨터 |

| 2NF(지도)의 이상 | 내용                                                                          |
| ---------------- | ----------------------------------------------------------------------------- |
| 삽입 이상        | 지도할 학생이 없으면 어떤 교수가 어떤 학과에 속한다는 사실을 삽입할 수 없다   |
| 삭제 이상        | 300번 학생의 튜플을 삭제하면 P3가 컴퓨터학과라는 정보도 사라진다              |
| 갱신 이상        | P1의 소속을 컴퓨터에서 전기로 바꾸면 학번 100과 400의 튜플을 모두 바꿔야 한다 |

2NF에서 이상이 생기는 원인은 이행적 함수 종속이다. 릴레이션 R에서 A → B, B → C가 성립해 A → C가 되면, C는 A에 이행적 함수 종속(transitive dependency, TD)이라 한다. 지도에서는 `학번 → 지도교수 → 학과`다. 프로젝션으로 분해해 이행적 함수 종속을 제거하면 3NF가 된다.

![분해 후 지도(학번→지도교수→학과)와 수강({학번,과목번호}→성적) 함수 종속 다이어그램](./images/db-normalization-note-06.jpg '분해 후 지도(학번→지도교수→학과)와 수강({학번,과목번호}→성적) 함수 종속 다이어그램 (강의 자료)')

![2NF로 분해한 지도(4행)와 수강(10행) 릴레이션 표](./images/db-normalization-note-07.jpg '2NF로 분해한 지도(4행)와 수강(10행) 릴레이션 표 (강의 자료)')

### 제3정규형(3NF)

==**2NF이고, 키가 아닌 모든 애트리뷰트가 기본 키에 이행적 함수 종속이 아닌**== 릴레이션이다. 지도를 다음 두 릴레이션으로 분해한다.

```text
학생지도 (학번, 지도교수)           기본 키: 학번, 외래 키: 지도교수 → 지도교수학과
지도교수학과 (지도교수, 학과)       기본 키: 지도교수
```

이제 "지도교수 P4는 수학과 소속"을 학생 없이 넣을 수 있다. 3NF에서는 키가 아닌 애트리뷰트를 갱신해도 이상이 생기지 않는다. 애트리뷰트가 두 개뿐인 이원 릴레이션(binary relation)은 이행적 종속이 생길 여지가 없어 모두 3NF다.

![분해 후 학번→지도교수, 지도교수→학과 두 함수 종속 다이어그램](./images/db-normalization-note-09.jpg '분해 후 학번→지도교수, 지도교수→학과 두 함수 종속 다이어그램 (강의 자료)')

![3NF로 분해한 학생지도(4행)와 지도교수학과(3행) 릴레이션 표](./images/db-normalization-note-10.jpg '3NF로 분해한 학생지도(4행)와 지도교수학과(3행) 릴레이션 표 (강의 자료)')

### 3NF의 약점

3NF는 다음 세 조건이 모두 성립하는 릴레이션에서 이상을 막지 못한다.

1. 후보 키가 여러 개다.
2. 후보 키들이 두 개 이상의 애트리뷰트로 구성된다.
3. 후보 키들의 애트리뷰트가 서로 겹친다.

이 경우를 다루려고 더 일반적인 BCNF가 제안되었다.

수강과목(학번, 과목, 교수) 릴레이션의 제약조건은 다음과 같다.

- 한 학생은 과목마다 한 교수의 강의만 수강한다.
- 각 교수는 한 과목만 담당한다.
- 한 과목을 여러 교수가 담당할 수 있다.

| 학번 | 과목       | 교수 |
| ---- | ---------- | ---- |
| 100  | 프로그래밍 | P1   |
| 100  | 자료구조   | P2   |
| 200  | 프로그래밍 | P1   |
| 200  | 자료구조   | P3   |
| 300  | 자료구조   | P3   |
| 300  | 프로그래밍 | P4   |

후보 키는 {학번, 과목}과 {학번, 교수}이고, 기본 키는 {학번, 과목}이다. 함수 종속은 `{학번, 과목} → 교수`, `교수 → 과목`이다. 기본 키에 속하지 않는 애트리뷰트는 교수 하나뿐이고, 교수는 기본 키에 완전 함수 종속이며 이행적으로 종속되지 않으므로 3NF다. 교수는 다른 후보 키 {학번, 교수}에 속하는 키 애트리뷰트이기도 하다. 그런데도 이상이 생긴다.

| 3NF(수강과목)의 이상 | 내용                                                                      |
| -------------------- | ------------------------------------------------------------------------- |
| 삽입 이상            | 교수 P5가 자료구조를 담당한다는 사실은 수강 학생이 있어야 삽입할 수 있다  |
| 삭제 이상            | 100번 학생이 자료구조를 취소하면 P2가 자료구조 담당이라는 정보도 사라진다 |
| 갱신 이상            | P1이 담당 과목을 자료구조로 바꾸면 P1이 나오는 모든 튜플을 바꿔야 한다    |

이상의 원인은 교수가 결정자(교수 → 과목)인데 후보 키가 아니라는 데 있다.

![수강과목 릴레이션 표(학번·과목·교수 6행, P1~P4)](./images/db-normalization-note-11.jpg '수강과목 릴레이션 표(학번·과목·교수 6행, P1~P4) (강의 자료)')

![수강과목의 함수 종속 다이어그램({학번,과목}→교수, 교수→과목)](./images/db-normalization-note-12.jpg '수강과목의 함수 종속 다이어그램({학번,과목}→교수, 교수→과목) (강의 자료)')

### 보이스/코드 정규형(BCNF)

==**릴레이션 R의 모든 결정자가 후보 키**==이면 R은 BCNF(Boyce/Codd Normal Form)다. 강한 제3정규형(strong 3NF)이라고도 하며, BCNF인 릴레이션은 1NF, 2NF, 3NF에도 속한다. 수강과목을 다음 두 릴레이션으로 분해한다.

```text
수강교수 (학번, 교수)             기본 키: {학번, 교수}, 외래 키: 교수 → 과목교수
과목교수 (교수, 과목)             기본 키: 교수
```

과목교수의 결정자는 교수 하나이고 교수가 후보 키이므로 BCNF다. P5가 자료구조를 담당한다는 사실도 학생 없이 넣을 수 있다.

![BCNF로 분해한 수강교수(학번·교수 6행)와 과목교수(교수·과목 4행) 릴레이션 표](./images/db-normalization-note-13.jpg 'BCNF로 분해한 수강교수(학번·교수 6행)와 과목교수(교수·과목 4행) 릴레이션 표 (강의 자료)')

![분해 후 {학번,교수} 키 박스와 교수→과목 함수 종속 다이어그램](./images/db-normalization-note-14.jpg '분해 후 {학번,교수} 키 박스와 교수→과목 함수 종속 다이어그램 (강의 자료)')

### 다치 종속과 제4정규형(4NF)

BCNF여도 이상이 남는 릴레이션이 있다. 과목 목록(UCPT)은 과목마다 담당 교수의 집합과 교재의 집합을 보관하고, 과목을 담당하는 교수는 그 과목의 교재를 전부 사용한다.

| 과목         | 교수     | 교재         |
| ------------ | -------- | ------------ |
| 화일구조     | {P1, P2} | {T1, T2}     |
| 데이터베이스 | {P3}     | {T3, T4, T5} |

도메인이 원자 값이 아니므로 비정규 릴레이션이다. 값을 펼친 개설 과목(CPT) 릴레이션은 다음과 같다.

| 과목         | 교수 | 교재 |
| ------------ | ---- | ---- |
| 화일구조     | P1   | T1   |
| 화일구조     | P1   | T2   |
| 화일구조     | P2   | T1   |
| 화일구조     | P2   | T2   |
| 데이터베이스 | P3   | T3   |
| 데이터베이스 | P3   | T4   |
| 데이터베이스 | P3   | T5   |

CPT에는 함수 종속이 없어 기본 키는 (과목, 교수, 교재) 전체이고, 키에 속하지 않는 결정자가 없으므로 BCNF다. 그러나 튜플 <c1, p1, t1>과 <c1, p2, t2>가 있으면 <c1, p1, t2>와 <c1, p2, t1>도 있어야 한다는 제약조건이 있다. 그래서 P4가 데이터베이스를 담당한다는 사실을 삽입하려면 교재 T3, T4, T5에 대한 튜플 세 개를 삽입해야 한다. ==과목이 교수나 교재의 값 하나가 아니라 값의 집합(set of values)을 결정하기 때문이다.== 화일구조는 교수 집합 {P1, P2}와 교재 집합 {T1, T2}를 서로 독립적으로 결정한다.

#### 다치 종속(MVD)

A, B, C가 릴레이션 R의 애트리뷰트 부분 집합일 때, ==(A, C) 값 쌍에 대응하는 B 값의 집합이 A 값에만 종속되고 C 값과는 독립이면 B는 A에 다치 종속(multivalued dependency, MVD)이라 하고 `A ↠ B`로 쓴다.== "A multidetermines B", "B is multidependent on A"로 읽는다.

| 성질                     | 내용                                                                                            | CPT의 예                                           |
| ------------------------ | ----------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 쌍으로 성립 (Fagin)      | A ↠ B이면 A ↠ C도 성립하며, 둘을 묶어 `A ↠ B \| C`로 쓴다                                       | 과목 ↠ 교재이므로 과목 ↠ 교수                      |
| FD는 MVD의 특수한 경우   | A → B이면 A ↠ B다. B 값의 집합이 원소 하나인 경우다                                             |                                                    |
| 무손실 분해 (Fagin 정리) | R(A, B, C)가 `A ↠ B \| C`를 만족하면 R1(A, B)와 R2(A, C)로 무손실 분해할 수 있다. 역도 성립한다 | CPT를 (과목, 교수)와 (과목, 교재)로 분해할 수 있다 |

Fagin 정리는 FD 대신 MVD를 조건으로 한 Heath 정리의 일반형이다.

#### 4NF의 정의

릴레이션 R에 MVD A ↠ B를 만족하는 애트리뷰트 집합 A, B가 있을 때, R의 모든 애트리뷰트가 A에 함수 종속이면(A가 후보 키이면) R은 4NF(Fourth Normal Form)다. BCNF로 정의하면 ==R이 BCNF이고 모든 MVD가 FD이면 R은 4NF다.== 즉 4NF인 릴레이션에는 MVD가 없거나, MVD `A ↠ B | C`가 있더라도 A에 대응하는 B와 C의 값이 하나씩이고 A가 후보 키다.

CPT를 과목교수(CP)와 과목교재(CT)로 분해한다.

| 과목         | 교수 |
| ------------ | ---- |
| 화일구조     | P1   |
| 화일구조     | P2   |
| 데이터베이스 | P3   |

| 과목         | 교재 |
| ------------ | ---- |
| 화일구조     | T1   |
| 화일구조     | T2   |
| 데이터베이스 | T3   |
| 데이터베이스 | T4   |
| 데이터베이스 | T5   |

이제 P4가 데이터베이스를 담당한다는 사실은 과목교수에 튜플 (데이터베이스, P4) 하나로 삽입한다. 두 릴레이션을 과목으로 자연 조인하면 CPT의 튜플 7개가 그대로 돌아온다.

### 조인 종속과 제5정규형(5NF)

SCP(SN, CN, PN) 릴레이션은 공급자(SN)가 부품(CN)을 프로젝트(PN)에 공급한다는 사실을 표현한다.

| SN  | CN  | PN  |
| --- | --- | --- |
| S1  | C1  | P2  |
| S1  | C2  | P1  |
| S2  | C1  | P1  |
| S1  | C1  | P1  |

모든 애트리뷰트가 키에 속하고 FD나 MVD가 없으므로 SCP는 4NF다. SCP를 프로젝션해 SC(SN, CN), CP(CN, PN), PS(PN, SN) 세 릴레이션을 만들면, 어느 두 개를 조인해도 SCP가 되지 않고 세 개를 모두 조인해야 SCP가 재생성된다.

| 조인           | 결과 튜플 수 | 위조 튜플(spurious tuple)                          |
| -------------- | ------------ | -------------------------------------------------- |
| SC ⋈ CP        | 5            | (S2, C1, P2)                                       |
| CP ⋈ PS        | 5            | (S2, C2, P1)                                       |
| PS ⋈ SC        | 5            | (S1, C2, P2)                                       |
| (SC ⋈ CP) ⋈ PS | 4            | 없음. (P2, S2)가 PS에 없어 (S2, C1, P2)가 제거된다 |

==SCP가 세 프로젝션의 조인과 같다는 것은 다음 3원 순환 제약조건(3-way cyclic constraint)이 성립한다는 뜻이다.==

```text
(S1, C1) ∈ SC 이고 (C1, P1) ∈ CP 이고 (P1, S1) ∈ PS 이면 (S1, C1, P1) ∈ SCP
즉
(S1, C1, P2) ∈ SCP 이고 (S2, C1, P1) ∈ SCP 이고 (S1, C2, P1) ∈ SCP 이면 (S1, C1, P1) ∈ SCP
```

n원 순환 제약조건을 만족하는 릴레이션은 n-분해 릴레이션이다. n-분해 릴레이션(n > 2)은 n개의 프로젝션으로만 무손실 분해할 수 있고, m(< n)개의 프로젝션으로는 무손실 분해할 수 없다. SCP는 3-분해 릴레이션이다.

#### 조인 종속(JD)

A, B, …, Z가 R의 애트리뷰트의 진부분집합일 때, ==R이 프로젝션 A, B, …, Z의 조인과 같으면 R은 조인 종속(join dependency, JD) `*(A, B, …, Z)`를 만족한다.== SCP는 JD `*(SC, CP, PS)`를 만족한다.

- R(A, B, C)가 JD `*(AB, AC)`를 만족하면 MVD `A ↠ B | C`가 성립한다. MVD는 2-분해인 JD의 특별한 경우이고, JD는 MVD의 일반형이다.
- JD를 만족하는 n-분해 릴레이션은 n개의 프로젝션으로 분해해야 한다.

SCP에 남는 이상은 다음과 같다.

| 이상      | 내용                                                                                                                                                                            |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 삽입 이상 | (S1, C1, P2), (S1, C2, P1)만 있는 SCP′에 (S2, C1, P1)을 삽입하면 순환 제약조건 때문에 원하지 않는 (S1, C1, P1)도 삽입해야 한다. 역으로 (S2, C1, P1)의 삭제는 이상 없이 가능하다 |
| 삭제 이상 | SCP에서 (S1, C1, P1)을 삭제하면 나머지 세 튜플이 순환 제약조건을 어기므로 다른 튜플 하나를 함께 삭제해야 한다. (S2, C1, P1)의 삭제는 이상 없이 가능하다                         |

원인은 SCP가 3-분해 릴레이션이라는 데 있고, SCP를 SC, CP, PS로 3-분해하면 해결된다.

#### 5NF의 정의

==릴레이션 R에 존재하는 모든 조인 종속이 R의 후보 키를 통해 성립하면 R은 5NF(Fifth Normal Form)다.== 프로젝션-조인 정규형(PJ/NF, projection-join normal form)이라고도 한다. 후보 키를 통해 성립한다는 것은 JD에 포함된 애트리뷰트 부분 집합이 모두 R의 슈퍼 키라는 뜻이다.

| 예                                                | 조인 종속                                                                            | 판정                                                               |
| ------------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------ |
| SCP                                               | `*(SC, CP, PS)`                                                                      | SC, CP, PS가 후보 키 (SN, CN, PN)를 통하지 않으므로 5NF가 아니다   |
| SC, CP, PS                                        | 없음                                                                                 | 5NF                                                                |
| 학생(학번, 이름, 학과, 학년), 후보 키 학번과 이름 | `*((학번, 이름, 학과), (학번, 학년))`, `*((학번, 이름), (학번, 학년), (이름, 학과))` | 프로젝션 애트리뷰트가 모두 슈퍼 키라 후보 키를 통해 성립하므로 5NF |

JD를 만족한다는 것은 프로젝션으로 무손실 분해가 가능하다는 의미이지, 반드시 분해해야 한다는 의미는 아니다. 또한 한 릴레이션에 존재하는 모든 JD를 찾아내기는 쉽지 않다.

## 정규형 사이의 관계

| 정규형 | 조건                                                           | 이전 단계에서 제거하는 것       |
| ------ | -------------------------------------------------------------- | ------------------------------- |
| 1NF    | 모든 도메인이 원자 값                                          | 반복 그룹(다중 값)              |
| 2NF    | 1NF + 키가 아닌 애트리뷰트가 기본 키에 완전 함수 종속          | 부분 함수 종속                  |
| 3NF    | 2NF + 키가 아닌 애트리뷰트가 기본 키에 이행적 함수 종속이 아님 | 이행적 함수 종속                |
| BCNF   | 모든 결정자가 후보 키                                          | 후보 키가 아닌 결정자           |
| 4NF    | BCNF + 모든 MVD가 FD                                           | 함수 종속이 아닌 다치 종속      |
| 5NF    | 모든 JD가 후보 키를 통해 성립                                  | 후보 키를 통하지 않는 조인 종속 |

정규형은 포함 관계에 있다. 5NF ⊂ 4NF ⊂ BCNF ⊂ 3NF ⊂ 2NF ⊂ 1NF이며, 높은 정규형일수록 조건이 엄격하다.

- ==정규화는 실제 데이터 값이 아니라 의미(함수 종속)를 기준으로 판단해야 한다.== 지금 들어 있는 값이 우연히 종속처럼 보여도 의미상 제약이 아니면 함수 종속이 아니다.
- 실제 설계에서는 정규형 순서대로 한 단계씩 진행하지 않을 수도 있다.

<summary>1. 릴레이션 설계와 변경 이상</summary>

> 관계 데이터베이스 설계와 바람직하지 않은 변경 이상의 관계를 예를 들어 설명하라.

설계에서 애트리뷰트를 릴레이션으로 묶을 때 애트리뷰트 사이의 종속성을 고려하지 않으면 같은 값이 여러 튜플에 중복 저장되고, ==중복이 있는 릴레이션을 변경하면 이상이 생긴다.== 학생의 학년을 등록 릴레이션으로 옮겨 만든 수강(학번, 과목번호, 성적, 학년)에서는 학번이 나타날 때마다 학년이 중복된다. 세 이상의 예는 [릴레이션 스키마 설계와 이상](#릴레이션-스키마-설계와-이상) 절의 표와 같고, 이상이 생기는 이유는 다음과 같다.

| 이상      | 이유                                                                                                                                        |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 삭제 이상 | 기본 키 {학번, 과목번호}의 일부인 과목번호만 삭제할 수 없어 튜플 전체를 삭제하므로, 그 튜플이 학년을 보관한 유일한 튜플이면 학년도 사라진다 |
| 삽입 이상 | 기본 키의 일부인 과목번호를 널로 둘 수 없어(개체 무결성), 등록 과목이 없는 학생의 학년을 삽입하려면 임시 과목번호를 넣어야 한다             |
| 갱신 이상 | 같은 학년 값이 여러 튜플에 중복되어, 일부 튜플만 갱신하면 한 학생이 두 학년을 갖는 모순이 생긴다                                            |

</details>

<summary>2. 직원 릴레이션 분석</summary>

> 직원(직원번호, 직원이름, 봉급, 과장, 과이름) 릴레이션에서, 직원은 한 과에만 속하고 각 과에는 과장이 한 명 있다. 튜플 예, 기본 키, 함수 종속, 함수 종속 다이어그램, 정규형, 변경 이상과 그 원인, 무손실 분해를 구하라.

(1) 튜플 예 4개는 다음과 같다.

| 직원번호 | 직원이름 | 봉급  | 과장   | 과이름 |
| -------- | -------- | ----- | ------ | ------ |
| 100      | 나수영   | 400만 | 박종화 | 인사과 |
| 200      | 이찬수   | 300만 | 박종화 | 인사과 |
| 300      | 정기태   | 200만 | 황수관 | 자재과 |
| 400      | 송병길   | 200만 | 이규찬 | 총무과 |

(2) 기본 키는 직원번호다. 같은 과에 직원이 여럿이고 이름과 봉급은 중복될 수 있으므로 직원번호만 튜플을 유일하게 식별한다.

(3) 함수 종속은 다음과 같다. 직원번호 → 과장은 나머지 두 종속에서 이행 규칙으로 유도된다.

```text
직원번호 → 직원이름
직원번호 → 봉급
직원번호 → 과이름
과이름 → 과장
직원번호 → 과장      (직원번호 → 과이름 → 과장)
```

(4) 함수 종속 다이어그램은 다음과 같다.

![직원 릴레이션의 함수 종속 다이어그램](./images/db-normalization-employee-fd.jpg '과제에서 그린 다이어그램. 과이름에서 과장으로 가는 화살표가 이행적 종속이다')

(5) 기본 키가 애트리뷰트 하나라 부분 함수 종속이 생길 수 없으므로 2NF다. ==직원번호 → 과이름 → 과장의 이행적 함수 종속이 있어 3NF는 아니다.==

(6) 변경 이상의 원인은 과장이 직원번호에 과이름을 거쳐 이행적으로 종속되는 과이름 → 과장이다.

| 이상      | 예                                                                                                    |
| --------- | ----------------------------------------------------------------------------------------------------- |
| 삽입 이상 | 직원이 없는 과의 과장을 삽입하려면 기본 키 직원번호가 널이 되므로 삽입할 수 없다                      |
| 삭제 이상 | 300번 직원의 튜플을 삭제하면 황수관이 자재과 과장이라는 정보도 사라진다                               |
| 갱신 이상 | 인사과의 과장이 바뀌면 100번과 200번 튜플을 모두 바꿔야 하고, 하나만 바꾸면 인사과의 과장이 둘이 된다 |

과제를 제출한 시각에는 삭제 이상의 예로 100번 직원 튜플을 삭제하면 박종화가 인사과 과장이라는 정보까지 사라진다고 답했는데, 200번 튜플에 같은 정보가 남아 있어 100번만 삭제해서는 정보가 사라지지 않는다. 과의 유일한 직원인 300번이나 400번을 삭제하는 예가 맞다.

(7) 과이름 → 과장을 프로젝션으로 분리한다.

```text
직원 (직원번호, 직원이름, 봉급, 과이름)     기본 키: 직원번호, 외래 키: 과이름 → 과
과   (과이름, 과장)                         기본 키: 과이름
```

| 직원번호 | 직원이름 | 봉급  | 과이름 |
| -------- | -------- | ----- | ------ |
| 100      | 나수영   | 400만 | 인사과 |
| 200      | 이찬수   | 300만 | 인사과 |
| 300      | 정기태   | 200만 | 자재과 |
| 400      | 송병길   | 200만 | 총무과 |

| 과이름 | 과장   |
| ------ | ------ |
| 인사과 | 박종화 |
| 자재과 | 황수관 |
| 총무과 | 이규찬 |

공통 애트리뷰트 과이름이 과의 키이므로 Heath 정리에 따라 무손실 분해다. 이행적 함수 종속이 사라져 두 릴레이션은 3NF이고, 각 릴레이션의 결정자가 직원번호와 과이름 하나씩이며 모두 후보 키이므로 BCNF까지 만족한다.

<details>
<summary>3. 정규화의 목적과 정규형 사이의 관계</summary>

> 정규화의 목적과 정규형 간의 관계를 설명하라.

정규화의 목적은 애트리뷰트 사이의 종속성을 분석해 ==하나의 릴레이션에 하나의 종속성만 표현되도록 분해해서 이상을 없애는 데== 있다. 분해는 자연 조인으로 원래 릴레이션을 복원할 수 있는 무손실 분해여야 하고, 분해된 릴레이션에서는 원래 릴레이션의 정보를 모두 얻을 수 있지만 그 역은 성립하지 않는다.

정규형은 릴레이션이 만족하는 제약조건으로 정의한다. 2NF, 3NF, BCNF는 함수 종속, 4NF는 다치 종속, 5NF는 조인 종속을 제약조건으로 쓴다. 차수가 높을수록 제약조건이 엄격해져 5NF ⊂ 4NF ⊂ BCNF ⊂ 3NF ⊂ 2NF ⊂ 1NF의 포함 관계가 성립한다([정규형 사이의 관계](#정규형-사이의-관계) 절). 1NF이면서 2NF가 아닌 릴레이션은 항상 프로젝션으로 2NF 릴레이션들로 무손실 분해할 수 있고, 2NF이면서 3NF가 아닌 릴레이션도 같은 방법으로 3NF 릴레이션들로 분해할 수 있다.

과제를 제출한 시각에는 정규형의 제약조건이 보통 함수 종속이라고만 답했는데, 4NF와 5NF의 제약조건은 함수 종속이 아니라 다치 종속과 조인 종속이다.

</details>

<details>
<summary>4. 참과 거짓</summary>

> 다음 중 참인 것은 무엇인가? 참이 아닌 것은 예를 들어라.

| 명제                                                         | 판정                                                                                                       |
| ------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| (1) 모든 이원 릴레이션은 2NF다                               | 참. 키가 애트리뷰트 하나면 부분 종속이 생길 수 없고, 키가 두 애트리뷰트 전체면 키가 아닌 애트리뷰트가 없다 |
| (2) 모든 이원 릴레이션은 3NF다                               | 참. 애트리뷰트가 둘이라 A → B → C 형태의 이행적 종속이 생길 수 없다                                        |
| (3) 모든 이원 릴레이션은 BCNF다                              | 참. 자명하지 않은 FD A → B가 있으면 A가 곧 후보 키다                                                       |
| (4) R(A, B, C)가 R1(A, B)와 R2(A, C)의 조인과 같으면 A → B다 | 거짓                                                                                                       |
| (5) A → B이고 B → C이면 A → C다                              | 참 (이행 규칙)                                                                                             |
| (6) A → B이고 A → C이면 A → {B, C}다                         | 참 (결합 규칙)                                                                                             |
| (7) B → A이고 C → A이면 {B, C} → A다                         | 참 (첨가 규칙으로 {B, C} → {A, C}, 분해 규칙으로 {B, C} → A)                                               |

과제를 제출한 시각에는 (4)를 참으로 답했다. Heath의 정리는 "A → B이면 무손실 분해할 수 있다"이고, 그 역은 성립하지 않는다. R(A, B, C) = {(1, x, p), (1, y, p)}는 R1 = {(1, x), (1, y)}와 R2 = {(1, p)}로 나누어 조인해도 원래대로 돌아오지만, A = 1에 B가 x와 y 두 개라 A → B가 아니다. ==무손실 조인이 보장하는 것은 이보다 약한 다치 종속 `A ↠ B | C`다.== [다치 종속](#다치-종속mvd) 절의 Fagin 정리가 이 관계를 필요충분조건으로 말해 준다.

</details>

<details>
<summary>5. 추가 종속에 따른 정규형</summary>

> R(A, B, C, D)의 기본 키가 (A, B)이고 C, D가 (A, B)에 함수 종속일 때, (1) 다른 종속이 없을 때, (2) D가 C에 함수 종속일 때, (3) B가 C에 함수 종속일 때, (4) D가 B에 함수 종속일 때 정규형을 구하라.

"Y가 X에 함수 종속"은 X → Y다. 따라서 (2)는 C → D, (3)은 C → B, (4)는 B → D다.

| 문항 | 추가 종속 | 정규형 | 이유                                                                                                                                                      |
| ---- | --------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (1)  | 없음      | BCNF   | 결정자가 기본 키 {A, B}뿐이다                                                                                                                             |
| (2)  | C → D     | 2NF    | C, D는 {A, B}에 완전 함수 종속이지만 {A, B} → C → D의 이행적 종속이 있다                                                                                  |
| (3)  | C → B     | 3NF    | {A, C} → {A, B}이므로 {A, C}도 후보 키가 되어 B는 키 애트리뷰트다. 키가 아닌 D에는 부분·이행적 종속이 없지만, 결정자 C가 후보 키가 아니므로 BCNF는 아니다 |
| (4)  | B → D     | 1NF    | D가 기본 키의 일부 B에 부분 함수 종속이다                                                                                                                 |

</details>

<details>
<summary>6. 잘못된 분해</summary>

> 2NF인 지도 릴레이션을 학생지도(학번, 지도교수)와 학번학과(학번, 학과)로 분해하면 어떻게 되는지 비교하고, 일반적인 분해 방법을 제안하라.

공통 애트리뷰트 학번이 두 릴레이션의 키이므로 이 분해도 무손실이고, 두 릴레이션은 이원 릴레이션이라 각각 3NF다. 그러나 지도교수 → 학과라는 함수 종속이 어느 릴레이션에도 남지 않는다. ==분해한 릴레이션들의 함수 종속으로 원래 함수 종속을 모두 유도할 수 있어야 종속성이 보존(dependency preservation)되는데, 이 분해는 종속성을 보존하지 못한다.==

| 문제               | 내용                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| 삽입 이상          | 지도교수가 어느 학과 소속인지 학생 없이 저장할 수 없다                                                                     |
| 갱신 이상          | P1의 소속이 바뀌면 학번학과에서 학번 100과 400의 튜플을 모두 바꿔야 한다                                                   |
| 제약조건 검사 불가 | 학번학과에 (100, 컴퓨터), (400, 전기)를 넣어도 지도교수가 같은 P1인 두 학생의 학과가 다르다는 모순을 DBMS가 검사할 수 없다 |

A를 키로 하는 릴레이션에 A → B, B → C가 성립해 C가 A에 이행적으로 종속하면, {A, C}가 아니라 ==이행 경로를 따라 {A, B}와 {B, C}로 분해해야 종속성이 보존된다.== 책의 학생지도(학번, 지도교수)와 지도교수학과(지도교수, 학과)가 이 방법이다.

</details>

<details>
<summary>7. 단계별 정규화</summary>

> R(A, B, C, D, E)에 {A, B} → C, A → D, A → E, D → E가 성립한다. 단계별로 분해하고 각 단계의 이유와 정규형을 밝히고, 최종 릴레이션들이 속하는 모든 정규형을 설명하라.

{A, B}는 함수 종속을 따라 C, D, E를 모두 결정하고, A와 B는 어느 종속의 오른쪽에도 나오지 않으므로 기본 키는 {A, B} 하나다. A → E는 A → D, D → E에서 이행 규칙으로 유도된다.

| 단계 | 분해 이유                                                          | 결과                             | 정규형 |
| ---- | ------------------------------------------------------------------ | -------------------------------- | ------ |
| 1    | 모든 도메인이 원자 값이다                                          | R(A, B, C, D, E), 기본 키 {A, B} | 1NF    |
| 2    | D와 E가 기본 키의 일부 A에 부분 함수 종속이므로 A를 키로 분리      | R1(A, B, C), R2(A, D, E)         | 2NF    |
| 3    | R2에 A → D → E의 이행적 함수 종속이 있으므로 이행 경로를 따라 분리 | R1(A, B, C), R2(A, D), R3(D, E)  | 3NF    |

최종 세 릴레이션의 결정자는 R1의 {A, B}, R2의 A, R3의 D이고 각각 그 릴레이션의 후보 키이므로 ==세 릴레이션은 BCNF이며, 따라서 1NF, 2NF, 3NF에도 속한다.== 주어진 종속이 함수 종속뿐이라 FD가 아닌 MVD와 후보 키를 통하지 않는 JD가 없으므로 4NF와 5NF의 조건도 만족한다. 세 릴레이션을 자연 조인하면 R이 복원되고, 원래 함수 종속도 모두 남아 있다.

과제를 제출한 시각에는 3단계를 R2(A, D), R3(A, E)로 나눴다. 이렇게 나누면 D → E가 어느 릴레이션에도 남지 않아, 위 6번의 잘못된 분해와 같은 문제가 생긴다.

</details>

## 정리

- 이상은 여러 종속 관계를 한 릴레이션에 표현해서 생기고, 종속 관계별로 릴레이션을 분해해 해결한다.
- 1NF → 2NF는 부분 함수 종속을, 2NF → 3NF는 이행적 함수 종속을, 3NF → BCNF는 후보 키가 아닌 결정자를 제거한다.
- BCNF → 4NF는 함수 종속이 아닌 다치 종속을, 4NF → 5NF는 후보 키를 통하지 않는 조인 종속을 제거한다.
- 분해는 자연 조인으로 원래 릴레이션을 복원할 수 있는 무손실 분해여야 한다.
