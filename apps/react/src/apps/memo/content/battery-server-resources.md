메뉴 막대의 Wi-Fi 위치에는 이미 서버(API) 가동 여부가 표시된다([/health 응답 시간을 막대 수로 환산하고 no-cors 요청으로 CORS 차단을 구분하는 서버 상태 표시](/memo/server-status-wifi)). 그 옆 배터리는 3/4이 채워진 고정 이미지였다. 서버 자원 감시 기능을 구현한 뒤([Oracle Always Free 회수를 막는 /proc 사용률 측정과 위험 메일 알림](/memo/resource-monitor)) 이 배터리 아이콘에 데이터를 연결했다. 관리자에게는 서버 자원을, 방문자에게는 방문 추이를 표시한다. 사용률을 확인하려고 매번 '활동 상태 보기'를 여는 대신, 메뉴 막대만 보고 위험 여부를 판단할 수 있게 하는 것이 목적이었다.

같은 날 커밋 세 개로 구현했다(서버 자원 배터리, macOS 형태 SVG, 방문자용 방문 추이). 모두 PR [#162](https://github.com/hyeoniverse/MacFolio/pull/162)로 병합됐다. 메뉴는 `src/desktop/status-bar/BatteryMenu.tsx`(132줄), 값 계산은 `src/apps/activity/useServerResources.ts`(88줄)와 `useVisitTrend.ts`(75줄), 그림은 `src/shared/server/ServerBattery.tsx`다.

![배터리 단계](./images/battery-server-resources-levels.svg '왼쪽 관리자(유휴 회수 위험), 오른쪽 방문자(방문 추이). 같은 그림에 fill만 다르다')

## 배경: 배터리 아이콘에 담을 값

macOS 메뉴 막대의 배터리 아이콘은 테두리 안의 막대 길이로 남은 충전량을 표시한다. 막대가 짧아질수록 남은 시간이 적다는 뜻이고, 충전량이 낮아지면 막대 색이 바뀐다. 사용자는 숫자를 읽지 않고 막대 길이만 보고 상태를 판단한다.

MacFolio에서 이 형태에 맞는 값은 "기준까지 얼마나 남았는가"로 표현할 수 있는 값이다. 관리자에게는 서버가 회수 기준까지 얼마나 여유가 있는지, 방문자에게는 최근 방문이 직전 기간보다 얼마나 늘었는지를 정했다.

| 보는 사람 | 막대가 나타내는 값                    | 막대가 짧아지는 경우                      |
| --------- | ------------------------------------- | ----------------------------------------- |
| 관리자    | Always Free 유휴 회수 기준까지의 여유 | 서버 사용률이 회수 기준 20%에 가까워질 때 |
| 방문자    | 최근 7일 방문의 직전 7일 대비 증감률  | 방문 수가 직전 7일보다 줄었을 때          |

## 관리자: 서버 자원

### Always Free 인스턴스의 유휴 회수

MacFolio의 API 서버는 Oracle Cloud의 Always Free 인스턴스다. Always Free는 계정마다 정해진 크기의 VM을 기간 제한 없이 무료로 제공하는 요금제다. 대신 ==Oracle은 7일 동안 사용률이 기준보다 낮은 Always Free 인스턴스를 회수할 수 있다==([OCI Always Free 리소스 문서](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)). 문서에 적힌 기준은 7일 동안 아래 조건이 모두 성립하는 경우다.

| 조건                    | 기준     | 적용 대상 |
| ----------------------- | -------- | --------- |
| CPU 사용률의 95퍼센타일 | 20% 미만 | 모든 형태 |
| 네트워크 사용률         | 20% 미만 | 모든 형태 |
| 메모리 사용률           | 20% 미만 | A1 형태만 |

95퍼센타일은 측정값을 작은 순서로 늘어놓았을 때 95% 위치의 값이다. 7일 동안 1분마다 잰 값이 10,080개라면 작은 쪽에서 약 9,576번째(10,080 × 0.95) 값이 된다. 가장 높은 5%(약 504분, 8시간 남짓)는 결과에서 빠지므로, 배포나 백업으로 CPU를 잠깐 많이 쓴 시간은 결과를 끌어올리지 못한다.

### 위험 단계와 배터리

사용률이 낮을수록 회수 기준에 가까워지므로, 여유가 줄수록 배터리 충전량이 줄어든다. 서버의 `reclaimRisk` 함수는 모든 조건이 20% 미만이면 위험, 모든 조건이 30%(기준 + 여유 10%p) 미만이면 주의로 판정한다.

![회수 기준 20%와 주의 여유 30%를 표시한 수직선과, CPU·네트워크 값에 따라 위험·주의·안전이 정해지는 세 가지 예시](./images/battery-server-resources-reclaim-rule.svg '모든 조건이 함께 기준 아래여야 위험이다. CPU 하나만 30%를 넘어도 안전이다')

| 회수 위험 (서버 탭과 같은 계산)  | 배터리 `fill` | 색   |
| -------------------------------- | ------------- | ---- |
| 안전                             | 100 (가득)    | 기본 |
| 주의 (모든 기준이 30% 미만)      | 25            | 주황 |
| 회수 위험 (모든 기준이 20% 미만) | 10            | 빨강 |
| 아직 모름                        | 50 (절반)     | 기본 |

> [!NOTE]
> 종량제(`payg`)이거나 감시가 비활성화되어 있으면 회수 위험이 없으므로 기본 형태(3/4, `fill` 75)를 유지한다.

## 방문자: 방문 추이

방문자에게는 서버 자원을 공개하지 않는다(`/resources`는 관리자만 호출할 수 있고, 방문자 화면에서는 요청하지 않는다). 대신 누구나 조회할 수 있는 '활동 상태 보기' 개요와 같은 `GET /analytics/summary`로 **최근 7일 방문 수의 직전 7일 대비 증감률**을 배터리로 표시한다.

| 직전 7일 대비 | 배터리       |
| ------------- | ------------ |
| +100% 이상    | 가득         |
| +50%          | 3/4          |
| 같음          | 절반         |
| -50%          | 1/4          |
| -100%         | 거의 빔 (5%) |

계산식은 `50 + 증감률 / 2`를 5~100% 범위로 제한한 값이다.

```ts
const percent =
	trend.previous > 0 ? ((trend.visits - trend.previous) / trend.previous) * 100 : trend.visits > 0 ? 100 : 0;
const fill = Math.round(Math.min(100, Math.max(5, 50 + percent / 2)));
```

E2E 시험의 가짜 API 값으로 계산하면 다음과 같다.

```math
\begin{aligned}
\text{증감률} &= \frac{1{,}284 - 1{,}146}{1{,}146} \times 100 \approx 12.04\% \\
\text{fill} &= \operatorname{round}(50 + 12.04 / 2) = 56
\end{aligned}
```

![방문 추이와 배터리](./images/battery-server-resources-curve.svg '같음이 절반, 두 배가 가득. 아래는 5%에서 멈춰 빈 배터리처럼 보이지 않게 했다')

하한을 0이 아니라 5%로 둔 이유는, 거의 빈 배터리가 관리자 화면에서 "회수 위험" 상태의 형태이기 때문이다. ==방문 감소에 같은 경고 형태를 표시할 이유는 없다==. 직전 7일 방문이 0이면 증감률을 계산할 수 없어서, 최근 7일 방문이 있으면 가득, 없으면 절반으로 표시한다. 방문 감소는 경고 대상이 아니므로 색을 적용하지 않는다.

서버는 방문자에게 이 값을 1분 동안 캐시해 응답하고, 메뉴 막대는 10분마다 다시 요청한다. 방문자 수와 무관하게 집계는 1분에 한 번이다. 서버에 연결하지 못하면 기본 형태로 표시한다.

배터리를 클릭하면 다음 항목이 표시된다.

![메뉴 막대의 배터리 메뉴. 방문 (최근 7일), 1,284회 방문, 앞 7일(1,146회)보다 +12%, 오늘 224회, 활동 상태 보기에서 자세히](./images/battery-server-resources-menu.jpg 'E2E의 가짜 API 값으로 캡처한 방문자 메뉴. +12%라 배터리가 절반보다 조금 더(56%) 차 있다')

| 줄                            | 내용                      |
| ----------------------------- | ------------------------- |
| `1,284회 방문`                | 최근 7일 방문 수          |
| `앞 7일(1,146회)보다 +12% ▲`  | 직전 7일 방문 수와 증감률 |
| `오늘 224회`                  | 오늘 방문 수              |
| **활동 상태 보기에서 자세히** | 개요 탭을 연다            |

## 배터리 아이콘

처음에는 Font Awesome의 배터리 아이콘(`fa-battery-*`)을 사용했다. 그런데 단계마다 별도 아이콘이라 충전량을 임의로 지정할 수 없고, 테두리와 내부가 같은 두께의 검은 형태라 macOS 메뉴 막대의 배터리와 달랐다.

| 방법                            | 장점                         | 단점                                                   |
| ------------------------------- | ---------------------------- | ------------------------------------------------------ |
| Font Awesome `fa-battery-*` 5종 | 이미 사용 중인 아이콘 세트   | 0·25·50·75·100%만 있다. 테두리가 두꺼워 macOS와 다르다 |
| 이미지 파일(PNG·SVG) 여러 장    | 형태를 자유롭게 지정         | 충전량마다 파일이 필요하다                             |
| 컴포넌트 하나의 SVG (**채택**)  | `fill` 값 하나로 1~100% 표현 | 다크 모드 색을 직접 지정해야 한다                      |

그래서 Wi-Fi 위치의 서버 신호처럼 SVG로 직접 작성했다(`ServerBattery`). SVG는 도형을 좌표로 기술하는 이미지 형식이고, React 컴포넌트 안에 태그로 쓰면 속성 값을 변수로 바꿀 수 있다. `viewBox="0 0 26 12"`는 가로 26, 세로 12 단위의 좌표계를 뜻하고, 실제 화면 크기는 CSS(`width: 1.75em`)가 정한다. 글자 크기가 커지면 배터리도 같은 비율로 커진다.

![ServerBattery의 SVG를 14배 확대해 shell, cap, level 세 도형과 좌표를 표시하고, 아래에 fill 10·25·75·100의 실제 모양을 비교한 그림](./images/battery-server-resources-anatomy.svg '바뀌는 값은 .level의 폭 하나다. fill 56이면 19의 56%인 10.64')

| 도형     | SVG 요소 | 값                                               | CSS                            |
| -------- | -------- | ------------------------------------------------ | ------------------------------ |
| `.shell` | `rect`   | 22.3 × 10.8, 모서리 반지름 3.2                   | 채움 없음, 선 1.2, 투명도 0.45 |
| `.cap`   | `path`   | 오른쪽 단자                                      | 투명도 0.45                    |
| `.level` | `rect`   | x 2.2, 높이 7.6, 폭 `19 × fill ÷ 100` (최소 1.6) | `currentColor`로 진하게        |

옅은 테두리, 오른쪽의 작은 단자, `fill`(%)만큼 채워지는 진한 내부 막대로 구성된다. 색은 `currentColor`(요소의 글자색을 그대로 쓰는 CSS 값)라서 메뉴 막대 글자색을 따르고, 글자색이 바뀌면 배터리 색도 함께 바뀐다. 주의와 위험 상태에서는 내부 막대만 macOS의 주황(`--color-system-orange`)과 빨강(`--color-system-red`)으로 칠한다. 방문 추이와 기본 배터리(75%)도 같은 컴포넌트다. 메뉴 안의 '유휴 회수' 줄에는 같은 배터리를 아이콘 영역(14px)에 맞게 축소해 표시한다.

## 관리자 메뉴

macOS 배터리 메뉴처럼 짧은 항목으로 구성했다.

| 줄                                                   | 내용                                                                                                         |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `CPU 3.2% · 메모리 41% · 네트워크 0.6%`              | 가장 최근 측정값. 네트워크는 Mbps가 아니라 대역폭(기본 50Mbps) 대비 비율이라 다른 두 값과 같은 척도로 읽힌다 |
| `Always Free · VM.Standard.E2.1.Micro · 3분 전 측정` | 요금제, 인스턴스 형태, 측정 시각                                                                             |
| `유휴 회수: 위험`                                    | 7일치 데이터가 누적되기 전이면 `2일치로 미리 본 값`으로 표시                                                 |
| 방문 (최근 7일)                                      | 방문자 메뉴와 같은 줄                                                                                        |
| **활동 상태 보기에서 자세히**                        | 그래프와 기준 표가 있는 서버 탭을 바로 연다                                                                  |

네트워크 값은 예를 들어 최근 측정값이 0.3Mbps이고 인스턴스 대역폭이 50Mbps이면 `0.3 \div 50 \times 100 = 0.6\%{:math}`로 표시된다. Oracle의 회수 기준도 Mbps가 아니라 비율이므로 같은 척도로 비교할 수 있다.

메뉴 막대는 5분마다, 그리고 메뉴를 여는 시각에 한 번 더 요청한다. 서버는 1분마다 측정하므로 메뉴를 열면 항상 최신에 가까운 값이 표시된다.

## 앱을 특정 탭으로 열기

'활동 상태 보기'는 열 때마다 개요 탭으로 시작한다. 메뉴에서 서버 탭으로 바로 이동하려면 앱에 "이 탭으로 열어 달라"는 요청을 전달해야 했다. 주소로 앱 항목을 여는 방법(`/memo/<글>`)은 메모와 Safari에만 있고, 탭 하나를 선택하는 데 주소까지 변경할 필요는 없어서 작은 요청 저장소(`requestedTab`)를 추가했다.

저장소는 `desktop-core`의 `createStore`로 만든 값 하나다. 여러 컴포넌트가 같은 값을 읽고(`getState`), 바꾸고(`setState`), 바뀔 때 알림을 받을(`subscribe`) 수 있다. 메뉴와 앱은 서로를 import하지 않고 이 저장소만 공유한다.

![BatteryMenu가 requestedTab에 server를 기록하고 앱을 열면, Activity가 값을 읽어 서버 탭으로 전환한 뒤 값을 null로 비우는 순서도](./images/battery-server-resources-requested-tab.svg '요청 값은 한 번 읽으면 비운다. 다음에 Dock에서 열면 다시 개요 탭이다')

앱이 이미 열려 있어도 저장소를 구독하고 있으므로 같은 방식으로 전환된다. '이 Mac에 관하여' 창이 시스템 설정을 여는 방식과 같다([앱 목록에 등록하지 않고 데스크톱이 직접 렌더링하는 시스템 창](/memo/about-this-mac)).

## 휴대폰

휴대폰 상태 표시줄의 배터리도 같은 값으로 채워진다. 관리자에게는 서버 자원(회수 위험이면 빨간색으로 10%만), 방문자에게는 방문 추이를 표시한다. 상태 표시줄은 누르면 제어 센터가 열리는 위치라 별도 메뉴는 추가하지 않았다.

## 남은 과제와 정리

- 방문자 배터리는 "직전 7일 대비"라서, 방문 수가 일정하면 항상 절반이다. 하루 10회든 1,000회든 같은 형태다. 절대 수치는 메뉴를 열어야 확인할 수 있다.
- 관리자 배터리는 5분마다 요청한다. 그 사이 회수 기준을 넘어도 최대 5분 늦게 반영된다. 회수는 7일 단위로 판정되므로 이 지연은 문제가 되지 않는다.
- 새 아이콘을 추가하는 것보다 기존 아이콘에 데이터를 연결하는 방식이 메뉴 막대의 요소 수를 늘리지 않았다. 다만 같은 아이콘이 사용자에 따라 다른 의미를 가지므로, ==메뉴 첫 줄에 표시 대상(서버 자원 / 방문)을 반드시 명시==했다.
