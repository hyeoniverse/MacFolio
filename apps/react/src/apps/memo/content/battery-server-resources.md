메뉴 막대의 Wi-Fi 위치에는 이미 서버(API) 가동 여부가 표시된다([/health 응답 시간으로 메뉴 막대의 Wi-Fi 자리에 서버 상태 표시하기](/memo/server-status-wifi)). 그 옆 배터리는 3/4이 채워진 고정 이미지였다. 서버 자원 감시 기능을 구현한 뒤([Oracle Always Free 회수를 막는 /proc 사용률 측정과 위험 메일 알림](/memo/resource-monitor)) 이 배터리 아이콘에 데이터를 연결했다. 관리자에게는 서버 자원을, 방문자에게는 방문 추이를 표시한다. 사용률을 확인하려고 매번 '활동 상태 보기'를 여는 대신, 메뉴 막대만 보고 위험 여부를 판단할 수 있게 하는 것이 목적이었다.

같은 날 커밋 세 개로 구현했다(서버 자원 배터리, macOS 형태 SVG, 방문자용 방문 추이). 모두 PR [#162](https://github.com/hyeoniverse/MacFolio/pull/162)로 병합됐다. 메뉴는 `src/desktop/status-bar/BatteryMenu.tsx`(132줄), 값 계산은 `src/apps/activity/useServerResources.ts`(88줄)와 `useVisitTrend.ts`(75줄), 그림은 `src/shared/server/ServerBattery.tsx`다.

![배터리 단계](./images/battery-server-resources-levels.svg '왼쪽 관리자(유휴 회수 위험), 오른쪽 방문자(방문 추이). 같은 그림에 fill만 다르다')

## 관리자: 서버 자원

Always Free 서버이면 배터리는 **유휴 회수 기준까지 남은 여유**를 나타낸다. Oracle은 7일 동안 사용률이 기준보다 낮은 Always Free 인스턴스를 회수할 수 있다([OCI Always Free 리소스 문서](https://docs.oracle.com/en-us/iaas/Content/FreeTier/freetier_topic-Always_Free_Resources.htm)). 사용률이 낮을수록 회수 기준에 가까워지므로, 여유가 줄수록 배터리 충전량이 줄어든다.

| 회수 위험 (서버 탭과 같은 계산)  | 배터리          |
| -------------------------------- | --------------- |
| 안전                             | 가득            |
| 주의 (모든 기준이 30% 미만)      | 1/4, 주황       |
| 회수 위험 (모든 기준이 20% 미만) | 비어 있음, 빨강 |
| 아직 모름                        | 절반            |

종량제(`payg`)이거나 감시가 비활성화되어 있으면 회수 위험이 없으므로 기본 형태(3/4)를 유지한다.

## 방문자: 방문 추이

방문자에게는 서버 자원을 공개하지 않는다(`/resources`는 관리자만 호출할 수 있고, 방문자 화면에서는 요청하지 않는다). 대신 누구나 조회할 수 있는 '활동 상태 보기' 개요와 같은 `GET /analytics/summary`로 **최근 7일 방문 수의 직전 7일 대비 증감률**을 배터리로 표시한다.

| 직전 7일 대비 | 배터리       |
| ------------- | ------------ |
| +100% 이상    | 가득         |
| +50%          | 3/4          |
| 같음          | 절반         |
| -50%          | 1/4          |
| -100%         | 거의 빔 (5%) |

계산식은 `50 + 증감률 / 2`를 5~100% 범위로 제한한 값이다.

```ts
const percent =
	trend.previous > 0 ? ((trend.visits - trend.previous) / trend.previous) * 100 : trend.visits > 0 ? 100 : 0;
const fill = Math.round(Math.min(100, Math.max(5, 50 + percent / 2)));
```

![방문 추이와 배터리](./images/battery-server-resources-curve.svg '같음이 절반, 두 배가 가득. 아래는 5%에서 멈춰 빈 배터리처럼 보이지 않게 했다')

하한을 0이 아니라 5%로 둔 이유는, 빈 배터리가 관리자 화면에서 "회수 위험" 상태의 형태이기 때문이다. 방문 감소에 같은 경고 형태를 표시할 이유는 없다. 직전 7일 방문이 0이면 증감률을 계산할 수 없어서, 최근 7일 방문이 있으면 가득, 없으면 절반으로 표시한다. 방문 감소는 경고 대상이 아니므로 색을 적용하지 않는다.

서버는 방문자에게 이 값을 1분 동안 캐시해 응답하고, 메뉴 막대는 10분마다 다시 요청한다. 방문자 수와 무관하게 집계는 1분에 한 번이다. 서버에 연결하지 못하면 기본 형태로 표시한다.

배터리를 클릭하면 다음 항목이 표시된다.

![메뉴 막대의 배터리 메뉴. 방문 (최근 7일), 1,284회 방문, 앞 7일(1,146회)보다 +12%, 오늘 224회, 활동 상태 보기에서 자세히](./images/battery-server-resources-menu.jpg 'E2E의 가짜 API 값으로 캡처한 방문자 메뉴. +12%라 배터리가 절반보다 조금 더(56%) 차 있다')

| 줄                            | 내용                      |
| ----------------------------- | ------------------------- |
| `1,284회 방문`                | 최근 7일 방문 수          |
| `앞 7일(1,146회)보다 +12% ▲`  | 직전 7일 방문 수와 증감률 |
| `오늘 224회`                  | 오늘 방문 수              |
| **활동 상태 보기에서 자세히** | 개요 탭을 연다            |

관리자 메뉴에도 서버 자원 아래에 같은 방문 줄이 있다.

## 배터리 아이콘

처음에는 Font Awesome의 배터리 아이콘(`fa-battery-*`)을 사용했다. 그런데 단계마다 별도 아이콘이라 충전량을 임의로 지정할 수 없고, 테두리와 내부가 같은 두께의 검은 형태라 macOS 메뉴 막대의 배터리와 달랐다.

| 방법                            | 장점                         | 단점                                                   |
| ------------------------------- | ---------------------------- | ------------------------------------------------------ |
| Font Awesome `fa-battery-*` 5종 | 이미 사용 중인 아이콘 세트   | 0·25·50·75·100%만 있다. 테두리가 두꺼워 macOS와 다르다 |
| 이미지 파일(PNG·SVG) 여러 장    | 형태를 자유롭게 지정         | 충전량마다 파일이 필요하다                             |
| 컴포넌트 하나의 SVG (**채택**)  | `fill` 값 하나로 1~100% 표현 | 다크 모드 색을 직접 지정해야 한다                      |

그래서 Wi-Fi 위치의 서버 신호처럼 SVG로 직접 작성했다(`ServerBattery`). 옅은 테두리, 오른쪽의 작은 단자, `fill`(%)만큼 채워지는 진한 내부 막대로 구성된다. 주의와 위험 상태에서는 내부 막대만 macOS의 주황(`#ff9f0a`)과 빨강(`#ff453a`)으로 칠한다. 방문 추이와 기본 배터리(75%)도 같은 컴포넌트다. 메뉴 안의 '유휴 회수' 줄에는 같은 배터리를 아이콘 영역(14px)에 맞게 축소해 표시한다.

## 관리자 메뉴

macOS 배터리 메뉴처럼 짧은 항목으로 구성했다.

| 줄                                                   | 내용                                                                                                         |
| ---------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `CPU 3.2% · 메모리 41% · 네트워크 0.6%`              | 가장 최근 측정값. 네트워크는 Mbps가 아니라 대역폭(기본 50Mbps) 대비 비율이라 다른 두 값과 같은 척도로 읽힌다 |
| `Always Free · VM.Standard.E2.1.Micro · 3분 전 측정` | 요금제, 인스턴스 형태, 측정 시각                                                                             |
| `유휴 회수: 위험`                                    | 7일치 데이터가 누적되기 전이면 `2일치로 미리 본 값`으로 표시                                                 |
| 방문 (최근 7일)                                      | 방문자 메뉴와 같은 줄                                                                                        |
| **활동 상태 보기에서 자세히**                        | 그래프와 기준 표가 있는 서버 탭을 바로 연다                                                                  |

메뉴 막대는 5분마다, 그리고 메뉴를 여는 시각에 한 번 더 요청한다. 서버는 1분마다 측정하므로 메뉴를 열면 항상 최신에 가까운 값이 표시된다.

## 앱을 특정 탭으로 열기

'활동 상태 보기'는 열 때마다 개요 탭으로 시작한다. 메뉴에서 서버 탭으로 바로 이동하려면 앱에 "이 탭으로 열어 달라"는 요청을 전달해야 했다. 주소로 앱 항목을 여는 방법(`/memo/<글>`)은 메모와 Safari에만 있고, 탭 하나를 선택하는 데 주소까지 변경할 필요는 없어서 작은 요청 저장소(`requestedTab`)를 추가했다. 메뉴가 탭 이름을 기록하고 앱을 열면, 앱이 그 값을 읽어 해당 탭으로 전환하고 값을 초기화한다. 앱이 이미 열려 있어도 저장소를 구독하고 있으므로 같은 방식으로 전환된다. '이 Mac에 관하여' 창이 시스템 설정을 여는 방식과 같다([Apple 메뉴의 '이 Mac에 관하여'를 앱이 아닌 시스템 창으로 구현하기](/memo/about-this-mac)).

## 휴대폰

휴대폰 상태 표시줄의 배터리도 같은 값으로 채워진다. 관리자에게는 서버 자원(회수 위험이면 빨간색으로 조금만), 방문자에게는 방문 추이를 표시한다. 상태 표시줄은 누르면 제어 센터가 열리는 위치라 별도 메뉴는 추가하지 않았다.

## 남은 과제와 정리

- 방문자 배터리는 "직전 7일 대비"라서, 방문 수가 일정하면 항상 절반이다. 방문 수가 많든 적든 같은 형태다. 절대 수치는 메뉴를 열어야 확인할 수 있다.
- 관리자 배터리는 5분마다 요청한다. 그 사이 회수 기준을 넘어도 최대 5분 늦게 반영된다. 회수는 7일 단위로 판정되므로 이 지연은 문제가 되지 않는다.
- 새 아이콘을 추가하는 것보다 기존 아이콘에 데이터를 연결하는 방식이 메뉴 막대의 요소 수를 늘리지 않았다. 다만 같은 아이콘이 사용자에 따라 다른 의미를 가지므로, 메뉴 첫 줄에 표시 대상(서버 자원 / 방문)을 반드시 명시했다.
