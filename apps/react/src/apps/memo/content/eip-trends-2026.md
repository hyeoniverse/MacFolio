이 연재의 앞선 글들은 2024년 제1회 시험을 준비하던 시점에 쓴 글이다. 그 뒤로 실기는 여덟 번 더 시행되었고, 2027년부터 적용되는 새 출제기준이 공개되면서 필기 과목 구성도 바뀐다. 이 글은 2026년 11월 18일 기준으로 확인할 수 있는 자료를 바탕으로 두 가지 변화를 정리한다.

1. 2027년 1월 1일부터 필기가 5과목 100문항에서 4과목 80문항으로 바뀐다.
2. 실기는 2026년부터 SQL 문항이 3~4개로 늘고, Python 문항과 처음 보는 보안 용어가 많아졌다.

> [!NOTE] 자료의 성격
> 출제기준은 한국산업인력공단이 Q-Net에 공개하는 공식 문서다. 실기 문제는 공단이 공개하지 않기 때문에, 회차별 유형 구성과 주제는 수험생이 시험 직후 기억으로 복원해 공유한 자료를 서로 대조해 집계했다. 한 곳에서만 확인한 값은 따로 표시하고, 예제는 기출 문장을 옮기지 않고 직접 만들어 실행했다.

## 2027년부터 필기는 4과목 80문항

출제기준은 한국산업인력공단이 종목별로 시험 과목, 문항 수, 시험 시간, 세부 출제 범위를 정해 공개하는 문서다. Q-Net의 정보처리기사 출제기준 목록에는 2026년 한 해에 적용하는 기준과 2027년 1월 1일부터 2029년 12월 31일까지 적용하는 기준이 함께 올라와 있다. 2026년 시험까지는 이 연재가 다룬 5과목 체제가 이어지고, 2027년 제1회 필기부터 새 기준을 따른다.

아래 세부 내용은 새 출제기준을 정리한 2차 출처 두 곳(IT위키, 링커리어 자료실)의 내용이 서로 일치하는 부분만 옮긴 것이다. 응시 전에는 Q-Net에서 출제기준 원문(한글 파일)을 직접 내려받아 세목을 확인하는 편이 안전하다.

| 항목      | 2026년까지                       | 2027~2029년                                |
| --------- | -------------------------------- | ------------------------------------------ |
| 과목 수   | 5과목                            | 4과목                                      |
| 문항 수   | 100문항 (과목당 20)              | 80문항 (과목당 20)                         |
| 시험 시간 | 2시간 30분                       | 2시간                                      |
| 합격 기준 | 과목당 40점 이상, 평균 60점 이상 | 같음 (과목당 8문항 이상, 전체 48문항 이상) |

과목당 문항 수와 과락 기준이 그대로이므로, 한 과목에서 12문항 이상 틀리면 불합격이라는 계산도 같다. 전체 기준은 80문항의 60%인 48문항이다.

```math
80 \times 0.6 = 48,\qquad 20 \times 0.4 = 8
```

### 과목이 어떻게 합쳐지고 옮겨 갔나

![2026년까지의 필기 5과목과 2027년부터의 4과목 대응도](./images/eip-trends-2026-written-mapping.svg '1과목 설계가 소프트웨어 개발에 흡수되고, 자료구조와 개발 방법론이 다른 과목으로 옮겨 간다')

가장 큰 변화는 1과목 소프트웨어 설계가 독립 과목에서 빠지고 그 내용이 새 1과목 소프트웨어 개발에 흡수된 점이다. 세부 이동은 다음과 같다.

- 5과목에 있던 소프트웨어개발 방법론 활용 항목이 새 1과목 소프트웨어 개발로 옮겨 간다.
- 2과목 소프트웨어 개발에 있던 자료구조(스택, 큐, 트리, 그래프)가 새 3과목 프로그래밍 언어 활용의 기본문법 활용 아래로 옮겨 간다.
- '현행 시스템 분석'과 '데이터 입출력 구현' 항목이 삭제된다.
- 용어 표기가 바뀐다. 예를 들어 '네트워크 7계층'은 'OSI 계층형 모델'로 표기한다.

> [!IMPORTANT] 실기는 바뀌지 않는다
> 실기는 12개 능력단위, 필답형 2시간 30분 구성을 유지한다. 2024년 1월 정부가 발표한 제5차 국가기술자격 제도발전 기본계획에 필답형 실기의 CBT(컴퓨터 기반 시험) 전환 방향이 들어 있지만, 2026년 11월 현재 정보처리기사 실기에 적용한다는 공고는 확인되지 않는다.

> [!TIP] 기출 문제집을 쓸 때
> 2027년 이후 응시자가 2026년 이전 필기 기출로 공부한다면, 옛 1과목 기출은 새 1과목, 옛 2과목의 자료구조 기출은 새 3과목에 해당한다. 같은 주제가 다른 과목 번호로 나온다는 점만 기억하면 된다.

## 언어·영역별로 자주 나온 주제

### C: 포인터를 따라가는 문제

C는 최근 회차에서 다음 주제가 반복되었다.

| 주제                      | 묻는 내용                                         |
| ------------------------- | ------------------------------------------------- |
| 구조체 포인터·연결 리스트 | `next`를 바꿔 노드 순서를 재연결한 뒤 순회 출력   |
| 이중 포인터               | 함수 안에서 바깥의 포인터 자체를 바꾸는 코드      |
| 함수 포인터               | 함수 주소를 배열에 담아 호출 (2026년 1회, 3회)    |
| 구조체로 만든 트리 순회   | 자식 포인터를 재귀로 따라가는 전위·중위·후위 순회 |
| 원형 큐                   | `(rear + 1) % size`로 계산한 인덱스               |
| 비트 연산과 `unsigned`    | 부호 없는 정수의 시프트와 AND·OR·XOR 결과         |

함수 포인터는 수험생 후기에서 신유형으로 꼽힌 주제다. 함수 이름은 그 함수의 시작 주소로 변환되므로 `int (*op)(int, int)`로 선언한 변수에 담았다가 `op(3, 4)`처럼 호출할 수 있다.

```c
#include <stdio.h>

int add(int a, int b) { return a + b; }
int mul(int a, int b) { return a * b; }

int main(void) {
    int (*op[2])(int, int) = { add, mul };
    int r = 1;
    for (int i = 0; i < 4; i++) {
        r = op[i % 2](r, i + 1);
    }
    printf("%d\n", r);
    return 0;
}
```

`op`는 함수 포인터 두 개를 담은 배열이다. `i`가 짝수이면 `add`, 홀수이면 `mul`을 호출한다.

| `i` | 호출        | `r` |
| --- | ----------- | --- |
| 0   | `add(1, 1)` | 2   |
| 1   | `mul(2, 2)` | 4   |
| 2   | `add(4, 3)` | 7   |
| 3   | `mul(7, 4)` | 28  |

gcc로 컴파일해 실행한 출력은 `28`이다.

연결 리스트 문제는 대부분 노드의 `next`를 바꾼 뒤 처음부터 순회한 출력을 묻는다. 노드 1, 2, 3에서 `head`를 2번 노드로 옮기고 1번 노드를 3번 뒤에 붙이면 출력은 `2 3 1`이 된다. 노드를 상자로, `next`를 화살표로 그리면서 대입문을 한 줄씩 따라가면 실수가 줄어든다.

### Java: 컴파일 시각에 정해지는 것과 실행 시각에 정해지는 것

Java는 상속과 동적 바인딩이 거의 매회 나왔다. 동적 바인딩은 부모 타입 변수로 자식 객체를 가리킬 때, 오버라이딩된 메서드는 실제 객체(자식)의 것이 실행되는 규칙이다. 반대로 필드와 `static` 메서드는 변수의 선언 타입으로 정해진다. 함께 자주 나온 주제는 `static` 메서드 하이딩, `try`-`catch`-`finally` 실행 순서, 재귀, 오버로딩과 제네릭의 정적 결정, `enum`(2025년 3회), `implements`·`super` 빈칸, 2차원 배열에서 행 참조를 공유하는 코드다.

```java
class Parent {
    int x = 10;
    static String who() { return "P"; }
    int get() { return x; }
}

class Child extends Parent {
    int x = 20;
    static String who() { return "C"; }
    @Override
    int get() { return x; }
}

public class Main {
    public static void main(String[] args) {
        Parent p = new Child();
        System.out.println(p.x + " " + p.get() + " " + p.who());
    }
}
```

openjdk 25로 실행한 출력은 `10 20 P`다. 필드 `p.x`와 static 메서드 `p.who()`는 선언 타입 `Parent`를 따르고, 오버라이딩된 `p.get()`만 실제 객체 `Child`의 메서드가 실행된다. 세 값이 모두 `Child`의 것이라고 생각하면 `20 20 C`라고 쓰게 되는데, 이 차이를 노리는 문제가 반복해서 나왔다.

### Python: 같은 객체를 가리키는 변수

Python은 슬라이싱과 음수 인덱스, 딕셔너리 컴프리헨션, 집합의 `&`(교집합), `enumerate`, 클래스 상속이 나왔고, 2026년에는 객체 참조를 이해해야 풀리는 문제가 연달아 나왔다. 2026년 1회의 얕은 복사와 3회의 가변 기본 매개변수다.

얕은 복사(shallow copy)는 바깥 컨테이너만 새로 만들고 안에 든 원소는 원래 객체를 그대로 참조하는 복사다. `list.copy()`, `list[:]`, `copy.copy()`가 여기에 해당하고, 안쪽 리스트까지 새로 만들려면 `copy.deepcopy()`를 쓴다.

```python
a = [[1, 2], [3, 4]]
b = a.copy()
b[0].append(9)
b[1] = [0]
print(a)
print(b)
```

```text
[[1, 2, 9], [3, 4]]
[[1, 2, 9], [0]]
```

![Python 리스트 얕은 복사의 참조 구조](./images/eip-trends-2026-shallow-copy.svg 'b[0]은 a[0]과 같은 리스트라 append가 양쪽에 보이고, b[1]에 대입한 새 리스트는 a에 영향이 없다')

`b[0].append(9)`는 a와 b가 공유하는 안쪽 리스트를 수정하므로 양쪽 출력에 9가 나타난다. `b[1] = [0]`은 b의 칸에 새 리스트를 대입하는 연산이라 a는 바뀌지 않는다. 수정(메서드 호출)과 대입을 구분하는 문제다.

가변 기본 매개변수는 함수의 기본값으로 리스트 같은 가변 객체를 지정했을 때, 그 객체가 함수를 정의하는 시각에 한 번만 만들어지고 이후 호출이 같은 객체를 계속 사용하는 동작이다.

```python
def add(x, items=[]):
    items.append(x)
    return items

print(add(1))
print(add(2))
print(add(3, []))
print(add(4))
```

```text
[1]
[1, 2]
[3]
[1, 2, 4]
```

python3로 실행한 결과다. 세 번째 호출만 새 리스트를 넘겼고, 네 번째 호출은 다시 기본값 리스트를 써서 1, 2 뒤에 4가 붙는다.

### SQL: 결과 행 수와 DDL 빈칸

SQL은 결과 행 수나 집계 값을 묻는 문제가 중심이었다. 서브쿼리, 조인, `DISTINCT`, `COUNT`, 외부 조인 뒤의 `NULL` 처리가 자주 나왔고, 2024년 3회에는 서브쿼리를 3단으로 중첩한 문제가 나왔다. 관계대수의 디비전(÷)과 프로젝트(π)도 출제되었다.

2026년에는 조회 결과를 계산하는 문제 외에 테이블 정의(DDL) 문장의 빈칸을 채우는 문제가 늘었다.

| 회차       | 주제                              |
| ---------- | --------------------------------- |
| 2026년 1회 | `CREATE TABLE`과 외래키 정의 빈칸 |
| 2026년 2회 | `CHECK` 제약조건, `CREATE DOMAIN` |
| 2026년 3회 | `ORDER BY` 빈칸                   |

`CHECK` 제약조건은 열에 들어갈 값이 만족해야 하는 조건식을 정의하고, 조건을 어기는 `INSERT`나 `UPDATE`를 거부한다. `CREATE DOMAIN`은 자료형과 기본값, 제약조건을 묶어 이름을 붙인 사용자 정의 도메인을 만드는 표준 SQL 문장이다. PostgreSQL 등은 지원하지만 SQLite와 MySQL은 지원하지 않는다. 아래는 SQLite에서 실행한 `CHECK` 예제다.

```sql
CREATE TABLE 학생 (
    학번 INTEGER PRIMARY KEY,
    이름 TEXT NOT NULL,
    학년 INTEGER CHECK (학년 BETWEEN 1 AND 4)
);
INSERT INTO 학생 VALUES (1, '김', 2);
INSERT INTO 학생 VALUES (2, '이', 5);
SELECT COUNT(*) FROM 학생;
```

```text
Error near line 7: CHECK constraint failed: 학년 BETWEEN 1 AND 4
1
```

두 번째 `INSERT`는 학년 5가 조건을 어겨 거부되고, 테이블에는 한 행만 남는다. "몇 행이 저장되는가"를 묻는 문제라면 답은 1이다.

외부 조인 뒤에는 짝이 없는 행의 열이 `NULL`로 채워진다. 그래서 행 수를 집계하는 `COUNT(*)`와 `NULL`이 아닌 값만 집계하는 `COUNT(열)`이 다르게 나오는데, 이 차이를 노린 문제도 반복해서 나왔다.

### 이론: 디자인 패턴, 결합도·응집도, 서브네팅

이론 10문항 안에서 거의 매회 나온 주제는 다음과 같다.

| 영역     | 자주 나온 주제                                                                            |
| -------- | ----------------------------------------------------------------------------------------- |
| 설계     | 디자인 패턴(2026년은 매회), 결합도·응집도, UML, DB 설계 단계, 정규형, 키, 차수·카디널리티 |
| 테스트   | 테스트 커버리지, 동등 분할, 경계값 분석, 스텁·드라이버                                    |
| 운영체제 | CPU 스케줄링 SRT·RR, 페이지 교체 LRU                                                      |
| 네트워크 | 서브네팅(2025년 1회부터 2026년 3회까지 매회), 라우팅 프로토콜 OSPF·RIP                    |

디자인 패턴은 2026년 세 회차에 Bridge, Observer, Abstract Factory, Factory Method가 나왔고, 그 전에는 Proxy, Adapter, Iterator가 나왔다. 설명을 읽고 패턴 이름을 쓰는 형식이 대부분이므로 패턴마다 목적을 한 문장으로 구분해 두어야 한다.

| 패턴             | 분류 | 목적                                                               |
| ---------------- | ---- | ------------------------------------------------------------------ |
| Abstract Factory | 생성 | 서로 관련된 객체들을 구체 클래스를 지정하지 않고 한 묶음으로 생성  |
| Factory Method   | 생성 | 어떤 클래스의 객체를 만들지 서브클래스가 결정                      |
| Bridge           | 구조 | 추상(기능) 계층과 구현 계층을 분리해 각각 독립적으로 확장          |
| Adapter          | 구조 | 호환되지 않는 인터페이스를 클라이언트가 기대하는 인터페이스로 변환 |
| Proxy            | 구조 | 대리 객체가 실제 객체에 대한 접근을 제어                           |
| Observer         | 행위 | 한 객체의 상태가 바뀌면 등록된 객체들에 자동으로 통지              |
| Iterator         | 행위 | 내부 구조를 드러내지 않고 집합 객체의 원소를 순서대로 접근         |

Abstract Factory와 Factory Method는 이름이 비슷해서 자주 바꿔 쓰게 된다. 객체 여러 개를 한 묶음(제품군)으로 만들면 Abstract Factory, 객체 하나의 생성을 서브클래스에 맡기면 Factory Method다.

서브네팅은 다섯 회차 연속으로 나왔고, 프리픽스 길이를 구하거나, 같은 크기로 나눈 서브넷(FLSM, 고정 길이 서브넷 마스크)의 브로드캐스트 주소를 묻거나, 첫 번째 서브넷(Subnet-zero)을 사용하는지 여부를 따지는 형태였다. 2025년 3회는 서브네팅, 페이지 교체, 스케줄링 같은 계산형이 하나도 나오지 않은 예외적인 회차다.

예를 들어 `192.168.10.0/24`를 같은 크기의 서브넷 네 개로 나누는 경우를 계산해 보면 다음과 같다.

| 기호 | 뜻             | 값  |
| ---- | -------------- | --- |
| n    | 서브넷 수      | 4   |
| s    | 서브넷 비트 수 | 2   |
| h    | 호스트 비트 수 | 6   |

1. 서브넷 4개를 구분하려면 `2^{s} \ge 4{:math}`를 만족하는 최소 s가 필요하므로 s = 2다.
2. 새 프리픽스 길이와 호스트 비트 수를 구한다.

```math
24 + 2 = 26,\qquad h = 32 - 26 = 6
```

3. 서브넷 하나의 주소 수와 사용 가능한 호스트 수를 구한다. 네트워크 주소와 브로드캐스트 주소는 호스트에 할당하지 않으므로 2를 뺀다.

```math
2^{6} = 64,\qquad 2^{6} - 2 = 62
```

4. 주소를 64씩 끊으면 각 서브넷의 마지막 주소가 브로드캐스트 주소다.

![192.168.10.0/24를 /26 네 개로 나누는 FLSM 서브네팅](./images/eip-trends-2026-flsm.svg '마지막 옥텟을 64씩 끊으면 각 구간의 마지막 주소가 브로드캐스트 주소다')

| 서브넷 | 네트워크 주소  | 호스트 범위 | 브로드캐스트   |
| ------ | -------------- | ----------- | -------------- |
| 0      | 192.168.10.0   | .1 ~ .62    | 192.168.10.63  |
| 1      | 192.168.10.64  | .65 ~ .126  | 192.168.10.127 |
| 2      | 192.168.10.128 | .129 ~ .190 | 192.168.10.191 |
| 3      | 192.168.10.192 | .193 ~ .254 | 192.168.10.255 |

Subnet-zero는 서브넷 비트가 모두 0인 첫 서브넷(192.168.10.0/26)을 사용하는 설정이다. 사용하지 않는다는 조건이 붙으면 192.168.10.64가 첫 번째 서브넷이 된다.

> [!TIP] 시험에서는 이렇게 묻는다
> "`192.168.10.0/24`를 FLSM으로 4개 서브넷으로 나눌 때 세 번째 서브넷의 브로드캐스트 주소를 쓰시오"처럼 묻는다. Subnet-zero를 사용하면 답은 `192.168.10.191`이다. 서브넷 번호를 0부터 매기는지 1부터 매기는지 문제의 조건을 먼저 확인한다.

## 처음 나온 용어

회차마다 이론 한두 문항은 실기에 처음 나온 용어였다. 두 곳 이상의 복원 자료에서 일치하는 것만 모았고, 정의는 표준 문서와 공식 자료를 기준으로 직접 썼다.

| 회차       | 용어                     | 한 줄 정의                                                                                           |
| ---------- | ------------------------ | ---------------------------------------------------------------------------------------------------- |
| 2024년 3회 | URL 구성요소             | `scheme://host:port/path?query#fragment` 순서로 자원의 위치를 나타내는 문자열의 각 부분              |
| 2024년 3회 | 애드혹(Ad hoc) 네트워크  | 무선 AP 같은 기반 시설 없이 단말끼리 직접 연결해 구성하는 네트워크                                   |
| 2025년 1회 | 스케어웨어(Scareware)    | 가짜 감염 경고로 겁을 줘 가짜 보안 프로그램 결제나 악성코드 설치를 유도하는 악성 소프트웨어          |
| 2025년 1회 | CRC                      | 데이터를 생성 다항식으로 나눈 나머지를 덧붙여 전송 중 비트 오류를 검출하는 순환 중복 검사            |
| 2025년 3회 | OTP                      | 시간이나 횟수를 바탕으로 생성해 한 번만 쓰는 비밀번호                                                |
| 2025년 3회 | OAuth                    | 비밀번호를 넘기지 않고 제3자 애플리케이션에 제한된 접근 권한(액세스 토큰)을 위임하는 인가 프레임워크 |
| 2025년 3회 | 접근 통제 모델           | 접근 권한을 정하는 방식. 보안 등급 기준의 MAC, 소유자 재량의 DAC, 역할 기준의 RBAC                   |
| 2025년 3회 | UML 패키지 다이어그램    | 모델 요소를 패키지로 묶고 패키지 사이의 의존 관계를 표시하는 구조 다이어그램                         |
| 2025년 3회 | 셸 명령어                | 리눅스 셸에서 파일·권한·프로세스를 다루는 명령(예: 권한을 바꾸는 `chmod`)                            |
| 2026년 1회 | 심볼릭 링크 공격         | 권한이 높은 프로그램이 접근할 경로에 심볼릭 링크를 미리 만들어 다른 파일을 읽거나 덮어쓰게 하는 공격 |
| 2026년 1회 | 워터링 홀(Watering hole) | 표적 집단이 자주 방문하는 웹사이트를 감염시켜 방문자에게 악성코드를 유포하는 공격                    |
| 2026년 1회 | ISMS                     | 정보보호 관리체계. 국내에서는 KISA가 ISMS-P 인증을 운영한다                                          |
| 2026년 1회 | HDLC                     | 플래그 비트열 `01111110`으로 프레임 경계를 구분하는 비트 지향 데이터 링크 프로토콜                   |
| 2026년 1회 | 비기능 요구사항 분류     | 기능 외에 성능, 보안, 가용성, 유지보수성처럼 품질과 제약에 관한 요구사항을 나누는 기준               |
| 2026년 2회 | 해시                     | 임의 길이 입력을 고정 길이 값으로 바꾸고 원래 입력을 되돌릴 수 없는 단방향 함수(예: SHA-256)         |
| 2026년 3회 | SBOM                     | 소프트웨어를 구성하는 라이브러리·컴포넌트의 이름, 버전, 라이선스를 적은 소프트웨어 자재 명세서       |
| 2026년 3회 | 루트킷(Rootkit)          | 공격자가 관리자 권한을 유지하면서 자신의 프로세스와 파일을 숨기도록 하는 도구 모음                   |
| 2026년 3회 | IDEA                     | 64비트 블록과 128비트 키를 쓰는 블록 암호                                                            |
| 2026년 3회 | Skipjack                 | 미국 NSA가 설계한 64비트 블록, 80비트 키의 블록 암호                                                 |
| 2026년 3회 | RBAC                     | 사용자에게 직접 권한을 주지 않고 역할에 권한을 부여한 뒤 사용자를 역할에 배정하는 접근 통제          |

처음 나온 용어의 절반 이상이 보안 분야이고, IDEA·Skipjack·RBAC·OTP처럼 필기 5과목 정보시스템 구축 관리의 보안 범위에 있던 용어가 많다. 필기 CBT 문제는 공개되지 않아 필기 신출 용어 목록은 신뢰할 만하게 만들 수 없지만, 실기 신출 보안 용어가 필기 5과목 범위와 겹친다는 점은 확인된다. 필기를 공부하는 시점에 보안 용어를 영문 철자까지 정리하면 실기 준비에 그대로 쓰인다.

> [!TIP] 시험에서는 이렇게 묻는다
> "소프트웨어 공급망 보안을 위해 제품에 포함된 오픈소스 컴포넌트와 버전, 라이선스 정보를 목록으로 관리하는 문서를 영문 약어로 쓰시오"처럼 설명을 주고 용어를 쓰게 한다. 답은 SBOM이다. 약어 문제는 풀네임(Software Bill of Materials)을 함께 기억해 두면 보기 없이도 떠올리기 쉽다.

## 합격률

[개요 글](/memo/eip-overview)에서 2023년까지의 연도별 합격률을 정리했다. 그 뒤 두 해의 연간 통계와 회차별 실기 합격률은 다음과 같다.

| 연도 | 필기 응시 | 필기 합격 | 필기 합격률 | 실기 응시 | 실기 합격 | 실기 합격률 |
| ---- | --------- | --------- | ----------- | --------- | --------- | ----------- |
| 2024 | 65,986    | 40,097    | 60.8%       | 66,305    | 18,980    | 28.6%       |
| 2025 | 66,327    | 43,146    | 65.1%       | 73,858    | 16,326    | 22.1%       |

연간 수치는 Q-Net 수험자동향 자료이고, 원서 접수 기준으로 집계해 종목별 검정현황의 수치와 다를 수 있다. 회차별 실기 합격률은 공단 발표를 수험생 사이트(정처기 감자)가 회차별로 정리한 값이다.

![정보처리기사 실기 회차별 합격률](./images/eip-trends-2026-pass-rates.svg '회차별 실기 합격률은 15.1%에서 36.8% 사이를 오르내린다')

| 회차 | 2024년 | 2025년 | 2026년              |
| ---- | ------ | ------ | ------------------- |
| 1회  | 36.8%  | 15.1%  | 18.1%               |
| 2회  | 27.7%  | 27.8%  | 34.7%               |

필기 합격률은 두 해 모두 60%대로 2023년 이전과 비슷하다. 실기는 연간 22~29%이지만 회차별로는 최저 15.1%(2025년 1회)와 최고 36.8%(2024년 1회)가 2배 넘게 차이 나고, 같은 해 안에서도 10%p 이상 달라진다. 특정 회차가 쉬울 것이라는 예상으로 응시 시기를 고르기는 어렵다.

## 앞으로 준비한다면

위의 집계에서 근거를 찾을 수 있는 준비 방향만 정리한다.

| 근거                                       | 준비 방향                                                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 2026년 SQL 3~4문항, DDL 빈칸 출제          | `SELECT` 결과 계산과 함께 `CREATE TABLE`, `PRIMARY KEY`, `FOREIGN KEY`, `CHECK` 문법을 손으로 쓸 수 있게 연습 |
| 2026년 Python 2~3문항, 참조 관련 문제      | 얕은 복사와 깊은 복사, 가변 기본 매개변수, 슬라이싱 결과를 직접 실행해 확인                                   |
| 서브네팅 5회 연속, 디자인 패턴 2026년 매회 | FLSM 계산 절차와 GoF 패턴의 목적 한 문장을 암기                                                               |
| 처음 나온 용어 절반 이상이 보안            | 필기 5과목 보안 용어를 영문 철자와 약어 풀이까지 정리                                                         |

2027년 이후 응시자는 필기 범위가 줄어든 만큼 필기 준비 기간을 줄일 수 있지만, 실기 범위는 바뀌지 않는다. 필기에서 빠진 '현행 시스템 분석'과 '데이터 입출력 구현'에 해당하는 내용도 실기 12개 능력단위에는 남아 있으므로, 실기 준비 단계에서 다시 챙겨야 한다. 실기 CBT 전환 여부는 확정 공고가 없으니 원서 접수 전에 Q-Net 공지를 확인한다.

### 예제 1. 구조체 멤버로 담은 함수 포인터

> 출제: 2026년 실기 3회 · 구조체 배열 포인터와 멤버 함수 포인터

다음 C 프로그램의 실행 결과를 쓰시오.

```c
#include <stdio.h>

typedef struct {
    int v;
    int (*f)(int);
} Item;

int twice(int n) { return n * 2; }
int dec(int n) { return n - 1; }
int sq(int n) { return n * n; }

int main(void) {
    Item it[3] = { {3, twice}, {5, dec}, {4, sq} };
    Item *p = it;
    int sum = 0;
    sum += p->f(p->v);
    p += 2;
    sum += p->f(p->v);
    p--;
    sum += (*p).f(it[0].v);
    printf("%d\n", sum);
    return 0;
}
```

<details>
<summary>정답과 해설</summary>

정답: `24`

`Item`은 정수 `v`와 함수 포인터 `f`를 함께 담는 구조체다. `int (*f)(int)`는 "정수 하나를 받아 정수를 돌려주는 함수의 주소"를 보관하는 멤버이고, 초기화 목록에 함수 이름 `twice`를 쓰면 그 함수의 시작 주소가 들어간다. `p`는 구조체 배열의 원소를 가리키는 포인터라서 `p += 2`는 바이트 2개가 아니라 구조체 2개만큼 이동한다.

| 줄           | `p`가 가리키는 원소 | 호출       | 반환값 | `sum` |
| ------------ | ------------------- | ---------- | ------ | ----- |
| 첫 번째 `+=` | `it[0]` (3, twice)  | `twice(3)` | 6      | 6     |
| `p += 2` 뒤  | `it[2]` (4, sq)     | `sq(4)`    | 16     | 22    |
| `p--` 뒤     | `it[1]` (5, dec)    | `dec(3)`   | 2      | 24    |

세 번째 호출이 이 문제의 핵심이다. 호출할 함수는 `(*p).f`, 즉 `it[1]`의 `dec`이지만 인자는 `p->v`가 아니라 `it[0].v`인 3이다. 함수를 고르는 쪽과 값을 고르는 쪽이 서로 다른 원소에서 오도록 만든 함정이다.

> [!CAUTION] 시험에서 실수하는 지점
> `p->f`와 `(*p).f`는 같은 뜻이다. 표기가 바뀌었다고 다른 동작을 떠올리지 말고, 포인터 이동(`p += 2`, `p--`)이 끝난 시점에 `p`가 몇 번 원소인지 먼저 표에 적어 둔다. 세 번째 호출의 인자를 `p->v`로 착각하면 `dec(5) = 4`가 되어 26이라고 쓰게 된다.

</details>

> [!NOTE] 개념 요약
>
> - 함수 포인터 선언은 `반환형 (*이름)(매개변수형)`이다. 괄호를 빼고 `int *f(int)`로 쓰면 "int 포인터를 돌려주는 함수" 선언이 된다.
> - 함수 이름은 그 함수의 시작 주소로 변환되므로 `f = twice;`로 대입하고 `f(3)`이나 `(*f)(3)`으로 호출한다. 배열 `int (*op[2])(int, int)`나 구조체 멤버에 담아도 호출 방법은 같다.
> - 구조체 포인터에서 `p->m`과 `(*p).m`은 같은 뜻이고, `p + k`는 바이트가 아니라 구조체 k개 크기만큼 이동한다.
> - 풀이 순서: 포인터 이동이 끝난 시점의 원소 번호, 호출할 함수, 인자 값을 따로 표에 적는다.

### 예제 2. 구조체 포인터 트리의 후위 순회

> 출제: 2026년 실기 2회 · 트리 후위 순회, 2026년 실기 3회 · 트리 전위 순회

다음 C 프로그램의 실행 결과를 쓰시오.

```c
#include <stdio.h>

typedef struct Node {
    char name;
    struct Node *left;
    struct Node *right;
} Node;

int cnt = 0;
char found = '?';

void visit(Node *n, int k) {
    if (n == NULL) return;
    visit(n->left, k);
    visit(n->right, k);
    cnt++;
    if (cnt == k) found = n->name;
}

int main(void) {
    Node d = {'D', NULL, NULL};
    Node e = {'E', NULL, NULL};
    Node f = {'F', NULL, NULL};
    Node b = {'B', &d, &e};
    Node c = {'C', NULL, &f};
    Node a = {'A', &b, &c};
    visit(&a, 4);
    printf("%c %d\n", found, cnt);
    return 0;
}
```

<details>
<summary>정답과 해설</summary>

정답: `F 6`

먼저 `main`의 초기화 목록을 읽어 트리 모양을 그린다. 각 구조체의 두 번째 값이 `left`, 세 번째 값이 `right`다. `c`는 `left`가 `NULL`이고 `right`가 `f`이므로 F는 C의 ==오른쪽== 자식이다.

![구조체 포인터로 만든 트리와 후위 순회 순서](./images/eip-trends-2026-postorder-tree.svg 'C의 왼쪽은 비어 있고 F가 오른쪽 자식이라, 후위 순회에서 F가 C보다 먼저 방문된다')

`visit`는 왼쪽 자식, 오른쪽 자식을 모두 처리한 뒤에 `cnt`를 올리므로 후위 순회(왼쪽 → 오른쪽 → 자기 자신)다.

| 방문 순서 (`cnt`) | 1   | 2   | 3   | 4     | 5   | 6   |
| ----------------- | --- | --- | --- | ----- | --- | --- |
| 노드              | D   | E   | B   | **F** | C   | A   |

`cnt`가 4가 되는 시각의 노드는 F이고, 순회가 끝나면 `cnt`는 노드 개수인 6이다. `found`를 찾은 뒤에도 재귀는 멈추지 않으므로 `cnt`는 4에서 멈추지 않는다.

이 문제의 함정은 `cnt++`가 재귀 호출 두 줄 뒤에 있다는 점이다. 같은 코드에서 `cnt++`를 첫 줄로 옮기면 전위 순회(A B D E C F)가 되어 4번째는 E이고, 두 재귀 호출 사이로 옮기면 중위 순회(D B E A C F)가 되어 4번째는 A다. 노드 선언 순서(d, e, f, b, c, a)는 방문 순서와 관계가 없다.

> [!CAUTION] 시험에서 실수하는 지점
> 순회 문제는 출력문이나 카운터가 재귀 호출의 앞, 사이, 뒤 중 어디에 있는지로 전위·중위·후위가 정해진다. 함수 이름이 `preorder`처럼 붙어 있어도 코드 위치로 판단한다. 마지막 출력에서 `cnt`를 `k`와 같은 4로 쓰는 실수도 잦다.

</details>

| 순회 | 처리 코드의 위치  | 방문 순서            | 예제 트리   |
| ---- | ----------------- | -------------------- | ----------- |
| 전위 | 두 재귀 호출 앞   | 자신 → 왼쪽 → 오른쪽 | A B D E C F |
| 중위 | 두 재귀 호출 사이 | 왼쪽 → 자신 → 오른쪽 | D B E A C F |
| 후위 | 두 재귀 호출 뒤   | 왼쪽 → 오른쪽 → 자신 | D E B F C A |

개념 요약: 루트는 전위에서 처음, 후위에서 마지막에 방문하고, 중위에서는 왼쪽 서브트리와 오른쪽 서브트리 사이에 온다. 자식이 하나뿐인 노드는 그 자식이 `left`인지 `right`인지를 초기화 목록에서 먼저 확인한다.

### 예제 3. 필드 은닉과 오버로딩의 정적 결정

> 출제: 2026년 실기 3회 · 상속과 필드 은닉, 2026년 실기 1회 · 오버로딩과 char 타입 변환

다음 Java 프로그램의 실행 결과를 쓰시오.

```java
class Base {
    int n = 1;
    int show() { return n; }
    String pick(int x) { return "I"; }
    String pick(double x) { return "D"; }
}

class Sub extends Base {
    int n = 5;
    int total() { return n + super.n; }
    @Override
    String pick(int x) { return "i"; }
    String pick(char x) { return "c"; }
}

public class Main {
    public static void main(String[] args) {
        Sub s = new Sub();
        Base b = s;
        System.out.println(b.n + s.n + " " + s.show() + " " + s.total());
        char ch = 'A';
        System.out.println(b.pick(ch) + s.pick(ch) + b.pick(ch + 1) + s.pick(2L));
    }
}
```

<details>
<summary>정답과 해설</summary>

정답:

```text
6 1 6
iciD
```

Java에서 필드는 오버라이딩되지 않는다. `Sub`에 같은 이름의 `n`을 선언하면 `Base`의 `n`을 가리는 별도의 필드가 하나 더 생기고(필드 은닉, field hiding), 어느 `n`을 쓸지는 컴파일 시각에 변수나 코드가 속한 클래스로 정해진다. 오버로딩도 마찬가지로 컴파일러가 인자의 선언 타입을 보고 메서드 시그니처를 고르며, 그렇게 고른 메서드가 자식에서 오버라이딩되어 있으면 실행 시각에 자식 쪽이 실행된다.

첫 줄은 다음 순서로 계산한다.

| 식          | 결정 기준                                              | 값  |
| ----------- | ------------------------------------------------------ | --- |
| `b.n`       | 변수 `b`의 선언 타입 `Base`의 필드                     | 1   |
| `s.n`       | 선언 타입 `Sub`의 필드                                 | 5   |
| `b.n + s.n` | 문자열이 나오기 전이라 정수 덧셈                       | 6   |
| `s.show()`  | `show`는 `Base`에 정의되어 있어 그 안의 `n`은 `Base.n` | 1   |
| `s.total()` | `n`은 `Sub.n`, `super.n`은 `Base.n`                    | 6   |

`+` 연산은 왼쪽부터 계산하므로 `b.n + s.n`이 먼저 정수 6이 되고, 그다음 `" "`를 만나서부터 문자열 연결이 된다. `"15"`라고 쓰면 틀린다. `s.show()`는 `Sub` 객체에서 호출했지만 `show`의 본문은 `Base` 클래스 안에 있으므로 `Base`의 `n`을 읽는다.

둘째 줄은 호출마다 후보 시그니처를 먼저 고른다.

| 호출             | 컴파일 시각에 보는 후보              | 고른 시그니처  | 실행되는 메서드  | 결과 |
| ---------------- | ------------------------------------ | -------------- | ---------------- | ---- |
| `b.pick(ch)`     | `Base`의 `pick(int)`, `pick(double)` | `pick(int)`    | `Sub`의 재정의   | `i`  |
| `s.pick(ch)`     | 위 두 개 + `Sub`의 `pick(char)`      | `pick(char)`   | `Sub.pick(char)` | `c`  |
| `b.pick(ch + 1)` | `ch + 1`은 `int`                     | `pick(int)`    | `Sub`의 재정의   | `i`  |
| `s.pick(2L)`     | `long`은 `int`로 자동 변환되지 않음  | `pick(double)` | `Base`의 것      | `D`  |

`b.pick(ch)`가 핵심 함정이다. 실제 객체는 `Sub`이고 `Sub`에 `pick(char)`가 있지만, 컴파일러는 선언 타입 `Base`에 있는 메서드만 후보로 본다. `char`는 `int`로 넓히는 변환이 `double`보다 가까워 `pick(int)`가 선택되고, 그 메서드가 `Sub`에서 오버라이딩되어 있으므로 소문자 `i`가 나온다.

> [!CAUTION] 시험에서 실수하는 지점
> "실제 객체가 `Sub`이니 전부 `Sub` 것"이라고 생각하면 첫 줄을 `10 5 6`, 둘째 줄을 `cciD`로 쓰게 된다. 필드와 오버로딩은 컴파일 시각(선언 타입), 오버라이딩만 실행 시각(실제 객체)이라는 순서로 두 번 나눠 판단한다. 문자열 연결 앞의 정수 덧셈도 매번 확인한다.

</details>

| 대상                     | 결정 시각   | 기준                                                      |
| ------------------------ | ----------- | --------------------------------------------------------- |
| 필드                     | 컴파일 시각 | 변수의 선언 타입, 메서드 본문 안에서는 그 메서드의 클래스 |
| `static` 메서드          | 컴파일 시각 | 변수의 선언 타입 (하이딩)                                 |
| 오버로딩 시그니처 선택   | 컴파일 시각 | 선언 타입에 있는 후보와 인자의 선언 타입                  |
| 오버라이딩된 메서드 실행 | 실행 시각   | 실제 객체의 클래스                                        |

개념 요약: 오버로딩 후보는 정확히 일치하는 타입, 기본형 넓히기(`char`→`int`→`long`→`float`→`double`), 박싱, 가변 인자 순으로 고르고, `long`→`int` 같은 좁히는 변환은 자동으로 일어나지 않는다. 부모 필드는 `super.n`으로 읽는다.

### 예제 4. 슬라이싱 복사 뒤 `+=`와 `= +`

> 출제: 2026년 실기 1회 · 중첩 리스트의 얕은 복사

다음 Python 프로그램의 실행 결과를 쓰시오.

```python
a = [[1], [2, 3], [4]]
b = a[:]
b[0] += [5]
b[1] = b[1] + [6]
b[2].extend([7, 8])
print(sum(len(x) for x in a), sum(len(x) for x in b))
```

<details>
<summary>정답과 해설</summary>

정답: `7 8`

`a[:]`는 바깥 리스트만 새로 만드는 얕은 복사다. 복사 직후에는 `b[0]`, `b[1]`, `b[2]`가 `a`의 안쪽 리스트 세 개를 그대로 가리킨다. 이후 세 줄은 모두 리스트에 원소를 덧붙이는 것처럼 보이지만 동작이 다르다.

| 줄                    | 연산의 성격                                  | `a`                     | `b`                       |
| --------------------- | -------------------------------------------- | ----------------------- | ------------------------- |
| 복사 직후             |                                              | `[[1],[2,3],[4]]`       | `[[1],[2,3],[4]]`         |
| `b[0] += [5]`         | 리스트의 `+=`는 제자리 확장(`extend`와 같음) | `[[1,5],[2,3],[4]]`     | `[[1,5],[2,3],[4]]`       |
| `b[1] = b[1] + [6]`   | `+`가 새 리스트를 만든 뒤 `b[1]`에만 대입    | 변화 없음               | `[[1,5],[2,3,6],[4]]`     |
| `b[2].extend([7, 8])` | 공유하는 리스트를 제자리 확장                | `[[1,5],[2,3],[4,7,8]]` | `[[1,5],[2,3,6],[4,7,8]]` |

길이 합은 `a`가 2 + 2 + 3 = 7, `b`가 2 + 3 + 3 = 8이다.

이 문제의 함정은 `x += y`와 `x = x + y`가 리스트에서 다르게 동작한다는 점이다. 정수나 문자열처럼 바꿀 수 없는(immutable) 객체에서는 둘 다 새 객체를 만들지만, 리스트의 `+=`는 원래 리스트를 수정한다. 그래서 `b[0] += [5]`는 `a`에도 보이고, `b[1] = b[1] + [6]`은 `b`에만 보인다.

> [!CAUTION] 시험에서 실수하는 지점
> `+=`도 대입문 모양이라 `a`에 영향이 없다고 판단하기 쉽다. 그렇게 풀면 `a`의 합이 5가 된다. 리스트에서는 `+=`, `append`, `extend`, 인덱스 대입(`b[0][0] = …`)을 수정, `b[i] = 새 리스트`만 교체로 분류해 두면 된다.

</details>

> [!NOTE] 개념 요약
>
> - `b = a`는 복사가 아니라 같은 리스트에 이름을 하나 더 붙이는 대입이다. 얕은 복사(`a[:]`, `a.copy()`, `list(a)`, `copy.copy(a)`)는 바깥 리스트만 새로 만들고 안쪽 객체는 공유하며, 깊은 복사 `copy.deepcopy(a)`는 안쪽까지 새로 만든다.
> - 공유 객체를 수정해 원본에도 보이는 연산: `append`, `extend`, `insert`, `pop`, 리스트의 `+=`, `b[i][j] = 값`.
> - 칸을 교체해 복사본에만 보이는 연산: `b[i] = 새 객체`, `b[i] = b[i] + [...]`.
> - 정수, 문자열, 튜플은 변경할 수 없는(immutable) 객체라 `+=`도 새 객체를 만든다.

### 예제 5. 생성자의 가변 기본 매개변수

> 출제: 2026년 실기 3회 · 가변 기본 인수

다음 Python 프로그램의 실행 결과를 쓰시오.

```python
class Cart:
    def __init__(self, owner, items=[]):
        self.owner = owner
        self.items = items

    def put(self, x):
        self.items.append(x)
        return len(self.items)

c1 = Cart("A")
c2 = Cart("B")
c3 = Cart("C", [])
c1.put(10)
c2.put(20)
c3.put(30)
print(c1.put(40), len(c2.items), len(c3.items), c1.items is c2.items)
```

<details>
<summary>정답과 해설</summary>

정답: `3 3 1 True`

기본값 `items=[]`의 빈 리스트는 `def __init__` 문이 실행되는 시각, 즉 클래스를 정의하는 시각에 한 번만 만들어진다. 인자를 생략한 `c1`과 `c2`는 그 리스트 하나를 함께 `self.items`로 보관하고, 빈 리스트를 직접 넘긴 `c3`만 자기 리스트를 가진다.

| 줄           | 기본값 리스트 (c1, c2 공유) | `c3.items` |
| ------------ | --------------------------- | ---------- |
| `c1.put(10)` | `[10]`                      | `[]`       |
| `c2.put(20)` | `[10, 20]`                  | `[]`       |
| `c3.put(30)` | `[10, 20]`                  | `[30]`     |
| `c1.put(40)` | `[10, 20, 40]` → 반환 3     | `[30]`     |

`print`의 인자는 왼쪽부터 평가되므로 `c1.put(40)`이 먼저 실행되어 3을 돌려주고, 그 뒤에 읽는 `len(c2.items)`도 같은 리스트라 3이다. `is`는 두 변수가 같은 객체인지 검사하는 연산자이므로 `True`다.

이 문제의 함정은 객체를 따로 만들었으니 장바구니도 따로일 것이라는 직관이다. 인스턴스는 둘이어도 기본값 객체는 하나다. 실무에서는 `items=None`으로 받고 본문에서 `if items is None: items = []`로 새 리스트를 만들어 이 문제를 피한다.

> [!CAUTION] 시험에서 실수하는 지점
> `len(c2.items)`를 `c2.put(20)` 직후의 값인 2로 쓰는 실수가 잦다. 출력 시각에는 `c1.put(40)`이 이미 실행된 뒤다. `print` 안에 값을 바꾸는 호출이 섞여 있으면 인자를 왼쪽부터 하나씩 실행한다.

</details>

> [!NOTE] 개념 요약
>
> - 기본값 식은 `def` 문이 실행되는 시각(함수나 클래스를 정의하는 시각)에 한 번만 평가된다. 리스트, 딕셔너리, 집합 같은 가변 기본값은 인자를 생략한 모든 호출이 같은 객체를 공유한다.
> - 인자를 직접 넘긴 호출만 자기 객체를 쓴다. `__init__`도 같아서 인스턴스가 여러 개여도 기본값 객체는 하나다.
> - 피하는 관용구: `def f(x, items=None):`로 받고 본문에서 `if items is None: items = []`.
> - `is`는 같은 객체인지, `==`는 값이 같은지를 비교한다. 함수 인자는 왼쪽부터 차례로 평가된다.

### 예제 6. 외래키 정의 빈칸과 연쇄 삭제

> 출제: 2026년 실기 1회 · 외래키 DDL, 2026년 실기 2회 · CREATE DOMAIN과 CHECK

다음은 학과에 소속된 수강생을 저장하는 테이블 정의다. 물음에 답하시오.

```sql
CREATE TABLE 학과 (
    학과코드 TEXT PRIMARY KEY,
    학과명 TEXT NOT NULL
);
CREATE TABLE 수강생 (
    번호 INTEGER PRIMARY KEY,
    이름 TEXT,
    학과코드 TEXT,
    ( ① ) fk_dept ( ② ) (학과코드) ( ③ ) 학과 (학과코드) ON DELETE CASCADE
);
INSERT INTO 학과 VALUES ('CS', '컴퓨터'), ('EE', '전자');
INSERT INTO 수강생 VALUES (1, '가', 'CS'), (2, '나', 'EE'), (3, '다', 'CS'), (4, '라', NULL);
INSERT INTO 수강생 VALUES (5, '마', 'ME');
DELETE FROM 학과 WHERE 학과코드 = 'CS';
SELECT COUNT(*) FROM 수강생;
```

1. ①~③에 들어갈 키워드를 쓰시오.
2. 마지막 `SELECT`의 결과를 쓰시오. (외래키 검사가 켜진 DBMS라고 가정한다)

<details>
<summary>정답과 해설</summary>

정답: ① `CONSTRAINT` ② `FOREIGN KEY` ③ `REFERENCES`, 결과 `2`

제약조건에 이름을 붙이는 문법은 `CONSTRAINT 이름 제약종류 (…)` 순서다. 외래키는 `FOREIGN KEY (자식 열) REFERENCES 부모테이블 (부모 열)`로 쓰고, `ON DELETE CASCADE`는 부모 행이 삭제되면 그 행을 참조하는 자식 행도 함께 삭제하라는 참조 동작이다. SQLite는 외래키 검사가 기본으로 꺼져 있어 `PRAGMA foreign_keys = ON;`을 먼저 실행해 확인했다.

| 단계                 | 결과                                               | 수강생 행 수 |
| -------------------- | -------------------------------------------------- | ------------ |
| 첫 `INSERT` (4행)    | 모두 성공. 4번의 `NULL`은 외래키 검사 대상이 아님  | 4            |
| `('ME')` 행 `INSERT` | 학과에 없는 코드라 `FOREIGN KEY constraint failed` | 4            |
| `DELETE … 'CS'`      | 연쇄 삭제로 1번(가), 3번(다) 삭제                  | 2            |

남는 행은 2번(나, EE)과 4번(라, NULL)이다.

이 문제의 함정은 두 가지다. 외래키 열의 `NULL`은 "아직 소속이 없음"을 뜻해 참조 무결성 위반이 아니고, `ON DELETE CASCADE`가 붙으면 부모 삭제가 거부되지 않고 자식까지 삭제된다. 참조 동작을 지정하지 않으면 기본값(`NO ACTION`)에 따라 자식이 남아 있는 부모 행의 `DELETE`가 실패한다.

2026년 2회에 나온 `CREATE DOMAIN`도 같은 빈칸 형식이다. `CREATE DOMAIN 학년_T AS INTEGER CHECK (VALUE BETWEEN 1 AND 4);`처럼 도메인에 붙는 조건에는 열 이름 대신 `VALUE`를 쓰고, 조건 키워드는 테이블 정의와 같은 `CHECK`다. SQLite는 `CREATE DOMAIN`을 지원하지 않아 이 문장은 실행 결과 없이 문법만 소개한다.

> [!CAUTION] 시험에서 실수하는 지점
> ③에 `REFERENCE`(s 빠짐)나 `FOREIGN`만 쓰면 오답이다. 필답형은 키워드 철자가 틀리면 오답으로 처리된다. 행 수 문제에서는 실패한 `INSERT`를 행 수에 넣거나, `NULL` 행도 연쇄 삭제된다고 생각하는 실수가 잦다.

</details>

> [!NOTE] 개념 요약
>
> - 제약조건 문법: `CONSTRAINT 이름 PRIMARY KEY (열)`, `CONSTRAINT 이름 FOREIGN KEY (열) REFERENCES 부모테이블 (열)`, `CONSTRAINT 이름 CHECK (조건)`, `CONSTRAINT 이름 UNIQUE (열)`.
> - 참조 동작은 `ON DELETE`·`ON UPDATE` 뒤에 붙인다. `CASCADE`는 자식도 함께 삭제·변경, `SET NULL`은 자식 열을 `NULL`로, `SET DEFAULT`는 기본값으로 바꾸고, `RESTRICT`와 `NO ACTION`(지정하지 않을 때의 기본)은 자식이 있으면 거부한다. `RESTRICT`는 문장을 실행하는 즉시, `NO ACTION`은 문장이 끝난 뒤(제약을 지연시켰다면 커밋 시각) 검사한다는 점만 다르다.
> - 외래키 열의 `NULL`은 참조 무결성 검사 대상이 아니고, 부모에 없는 값을 넣는 `INSERT`는 거부된다.
> - 도메인 정의: `CREATE DOMAIN 이름 AS 자료형 DEFAULT 값 CHECK (VALUE 조건);` 조건에는 열 이름 대신 `VALUE`를 쓴다.

### 예제 7. 왼쪽 외부 조인 뒤의 행 수

> 출제: 2026년 실기 3회 · LEFT JOIN과 IS NULL 행 수, 2026년 실기 2회 · RIGHT OUTER JOIN 뒤 행 수

[회원] 테이블과 [주문] 테이블이 다음과 같을 때, 두 SQL 문의 결과를 각각 쓰시오.

| 회원.id | 이름 |
| ------- | ---- |
| 1       | 가   |
| 2       | 나   |
| 3       | 다   |
| 4       | 라   |

| 주문.oid | 주문.id | 금액 |
| -------- | ------- | ---- |
| 10       | 1       | 500  |
| 11       | 1       | 300  |
| 12       | 3       | 700  |
| 13       | 5       | 200  |

```sql
-- (1)
SELECT COUNT(*), COUNT(주문.oid)
FROM 회원 LEFT OUTER JOIN 주문 ON 회원.id = 주문.id;

-- (2)
SELECT COUNT(*)
FROM 회원 LEFT OUTER JOIN 주문 ON 회원.id = 주문.id
WHERE 주문.oid IS NULL;
```

<details>
<summary>정답과 해설</summary>

정답: (1) `5`, `3` (2) `2`

왼쪽 외부 조인(LEFT OUTER JOIN)은 왼쪽 테이블의 모든 행을 결과에 남기고, 조건에 맞는 오른쪽 행이 없으면 오른쪽 열을 `NULL`로 채운다. 먼저 조인 결과 전체를 표로 만든다.

| 회원.id | 이름 | oid    | 금액   | 설명                 |
| ------- | ---- | ------ | ------ | -------------------- |
| 1       | 가   | 10     | 500    | 주문 두 건이라 두 행 |
| 1       | 가   | 11     | 300    |                      |
| 2       | 나   | `NULL` | `NULL` | 짝 없음              |
| 3       | 다   | 12     | 700    |                      |
| 4       | 라   | `NULL` | `NULL` | 짝 없음              |

(1)에서 `COUNT(*)`는 행 수 5, `COUNT(주문.oid)`는 `NULL`이 아닌 값 3이다. (2)는 위 표에서 `oid`가 `NULL`인 행, 즉 주문이 없는 회원 2명만 남는다. 주문 13은 회원 5를 가리키지만 왼쪽 테이블에 5가 없어 결과에 나타나지 않는다.

이 문제의 함정은 "회원이 4명이니 행도 4개"라는 직관이다. 회원 1의 주문이 두 건이라 그 회원은 두 행으로 늘어난다. 외부 조인 결과의 행 수는 짝이 있는 조합 수에 짝 없는 왼쪽 행 수를 더한 값이다.

```math
3 + 2 = 5
```

> [!CAUTION] 시험에서 실수하는 지점
> 오른쪽에만 있는 주문 13을 결과에 넣어 6이라고 쓰거나, `COUNT(*)`와 `COUNT(열)`을 같은 값으로 쓰는 실수가 잦다. `RIGHT OUTER JOIN` 문제라면 남기는 쪽이 오른쪽 테이블로 바뀌므로, 어느 테이블의 행이 모두 남는지부터 표시한다.

</details>

| 조인               | 결과에 모두 남는 행 | 짝 없는 행의 반대쪽 열 |
| ------------------ | ------------------- | ---------------------- |
| `INNER JOIN`       | 조건에 맞는 조합만  | 행 자체가 빠짐         |
| `LEFT OUTER JOIN`  | 왼쪽 테이블 전체    | `NULL`                 |
| `RIGHT OUTER JOIN` | 오른쪽 테이블 전체  | `NULL`                 |
| `FULL OUTER JOIN`  | 양쪽 테이블 전체    | `NULL`                 |

개념 요약: 외부 조인의 행 수는 짝이 맞는 조합 수(한 행이 여러 행과 맞으면 그만큼 늘어난다)에 짝 없는 보존 쪽 행 수를 더한 값이다. `COUNT(*)`는 `NULL`이 있는 행도 집계하고 `COUNT(열)`은 `NULL`을 빼며, `WHERE 반대쪽.열 IS NULL`은 짝이 없는 행만 남긴다.

### 예제 8. 설명을 읽고 디자인 패턴 쓰기

> 출제: 2026년 실기 1회 · Bridge와 Observer

다음 설명에 해당하는 디자인 패턴을 〈보기〉에서 골라 쓰시오.

1. 주식 시세 객체의 가격이 바뀌면 차트 화면, 알림 모듈, 기록 모듈이 각자 자동으로 새 가격을 전달받는다. 시세 객체는 자신을 구독한 객체의 목록만 보관하고, 그 객체들이 구체적으로 무엇인지 알지 못한다.
2. 도형(원, 사각형)의 종류와 그리는 방식(화면 출력, PDF 출력)을 각각 독립된 클래스 계층으로 나누고, 도형 객체가 그리기 객체를 참조하도록 연결한다. 그래서 도형 3종과 출력 방식 4종을 조합할 때 12개가 아니라 3 + 4개의 클래스로 충분하다.

〈보기〉 Adapter, Bridge, Decorator, Factory Method, Mediator, Observer, Proxy, Strategy

<details>
<summary>정답과 해설</summary>

정답: 1. Observer 2. Bridge

1번의 단서는 "상태가 바뀌면 등록된 객체들이 자동으로 전달받는다"이다. 관찰 대상(Subject)이 관찰자(Observer) 목록을 보관하고 상태 변경 시 모두에게 통지하는 일대다 의존 관계가 Observer 패턴이다. 2번의 단서는 "두 계층을 독립적으로 나누고 참조로 연결한다"이다. 기능(도형) 계층과 구현(출력 방식) 계층을 분리해 각각 확장하는 구조가 Bridge 패턴이다.

헷갈리는 오답 후보와 구별법은 다음과 같다.

| 오답 후보 | 비슷해 보이는 이유             | 구별법                                                           |
| --------- | ------------------------------ | ---------------------------------------------------------------- |
| Mediator  | 여러 객체 사이의 통신을 다룬다 | 중재자가 객체끼리의 상호작용을 대신 조정. 일방향 통지는 Observer |
| Strategy  | 동작을 별도 객체로 분리한다    | 알고리즘 하나를 실행 중에 교체. 두 계층 조합이 핵심이면 Bridge   |
| Adapter   | 두 클래스를 연결한다           | 이미 있는 맞지 않는 인터페이스를 변환. 설계 단계 분리는 Bridge   |

이 문제의 함정은 "연결한다"는 말만 보고 Adapter를 고르는 것이다. Adapter는 호환되지 않는 기존 코드를 나중에 맞추는 패턴이고, Bridge는 처음부터 두 축을 분리해 클래스 수가 곱으로 늘어나는 것을 막는 패턴이다.

> [!CAUTION] 시험에서 실수하는 지점
> 패턴 이름은 영문 철자로 쓰라는 조건이 붙는 경우가 많다. Observer를 `Observe`, Bridge를 `Bridges`처럼 쓰면 오답 처리될 수 있다. 같은 계열에서 2026년 2회는 Abstract Factory, 3회는 Factory Method가 나왔으니 생성 패턴 두 개의 차이(제품군 생성인지, 객체 하나의 생성을 서브클래스에 맡기는지)도 함께 정리해 둔다.

</details>

> [!NOTE] 개념 요약
>
> - GoF 패턴 23개는 생성 5개(Abstract Factory, Builder, Factory Method, Prototype, Singleton), 구조 7개(Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy), 행위 11개(Chain of Responsibility, Command, Interpreter, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor)로 나뉜다.
> - 설명의 단서로 고른다. 상태 변화 자동 통지는 Observer, 두 계층 분리는 Bridge, 인터페이스 변환은 Adapter, 기능 덧붙이기는 Decorator, 접근 대리는 Proxy, 알고리즘 교체는 Strategy, 상호작용 중재는 Mediator, 인스턴스 하나 보장은 Singleton이다.
> - Abstract Factory는 관련 객체 묶음(제품군)을 생성하고, Factory Method는 생성할 클래스를 서브클래스가 결정한다.

### 예제 9. Subnet-zero를 쓰지 않는 FLSM 브로드캐스트 주소

> 출제: 2026년 실기 3회 · FLSM 서브넷의 브로드캐스트 주소

`172.16.8.0/24` 네트워크를 FLSM 방식으로 6개 이상의 서브넷으로 나누려고 한다. 서브넷 비트는 필요한 최소 개수만 사용하고 Subnet-zero는 사용하지 않는다. 세 번째로 할당하는 서브넷의 브로드캐스트 주소를 쓰시오.

<details>
<summary>정답과 해설</summary>

정답: `172.16.8.127`

| 기호 | 뜻                    | 값  |
| ---- | --------------------- | --- |
| n    | 필요한 서브넷 수      | 6   |
| s    | 서브넷 비트 수        | 3   |
| p    | 새 프리픽스 길이      | 27  |
| B    | 서브넷 하나의 주소 수 | 32  |

1. `2^{s} \ge 6{:math}`을 만족하는 최소 s를 구한다. `2^{2} = 4{:math}`는 부족하고 `2^{3} = 8{:math}`이므로 s = 3이다.
2. 새 프리픽스 길이와 서브넷 하나의 주소 수를 구한다.

```math
p = 24 + 3 = 27,\qquad B = 2^{32 - 27} = 2^{5} = 32
```

3. 마지막 옥텟을 32씩 끊어 서브넷 8개를 만든다. Subnet-zero를 쓰지 않으므로 서브넷 비트가 `000`인 첫 구간(.0~.31)은 할당하지 않고, `001`인 .32부터 첫 번째로 센다.

| 서브넷 비트 | 범위       | Subnet-zero 사용 시 | 사용하지 않을 시 | 브로드캐스트 |
| ----------- | ---------- | ------------------- | ---------------- | ------------ |
| 000         | .0 ~ .31   | 1번째               | 할당 안 함       | 172.16.8.31  |
| 001         | .32 ~ .63  | 2번째               | 1번째            | 172.16.8.63  |
| 010         | .64 ~ .95  | 3번째               | 2번째            | 172.16.8.95  |
| 011         | .96 ~ .127 | 4번째               | **3번째**        | 172.16.8.127 |

4. 세 번째 서브넷은 `172.16.8.96/27`이고, 브로드캐스트 주소는 범위의 마지막 주소다.

```math
96 + 32 - 1 = 127
```

Python의 `ipaddress` 모듈로 `/24`를 `/27`로 나눈 결과도 같은 범위를 돌려준다. 서브넷 비트를 3개 쓰면 8개가 생겨 Subnet-zero를 빼도 7개가 남으므로 6개 조건을 만족한다.

이 문제의 함정은 Subnet-zero 조건 하나로 답이 한 칸씩 밀린다는 점이다. 조건을 놓치면 `172.16.8.95`라고 쓰게 된다.

> [!CAUTION] 시험에서 실수하는 지점
> 브로드캐스트 주소를 다음 서브넷의 시작 주소(.128)로 쓰거나, 사용 가능한 마지막 호스트 주소(.126)로 쓰는 실수가 잦다. 브로드캐스트는 범위의 마지막 주소, 마지막 호스트는 그보다 1 작은 주소다.

</details>

> [!NOTE] 개념 요약
>
> - 순서: 서브넷 n개에 필요한 최소 서브넷 비트 s(`2^{s} \ge n{:math}`) → 새 프리픽스 = 기존 프리픽스 + s → 블록 크기 = 2^(32 − 새 프리픽스) → 마지막 옥텟을 블록 크기씩 끊는다.
> - 각 구간의 첫 주소가 네트워크 주소, 마지막 주소가 브로드캐스트 주소이고, 사용 가능한 호스트 수는 블록 크기 − 2다.
> - Subnet-zero를 쓰지 않으면 서브넷 비트가 모두 0인 첫 구간을 빼므로 쓸 수 있는 서브넷이 `2^{s} - 1{:math}`개로 줄고, k번째 서브넷이 한 칸 뒤로 밀린다.
> - 프리픽스별 블록 크기: /25는 128, /26은 64, /27은 32, /28은 16, /29는 8, /30은 4.

### 예제 10. 설명을 읽고 보안 용어 쓰기

> 출제: 2026년 실기 3회 · 루트킷, 2025년 실기 1회 · 스케어웨어

다음 설명에 해당하는 용어를 영문으로 쓰시오.

1. 공격자가 침입한 시스템에서 관리자 권한을 계속 유지하려고 설치하는 도구 모음이다. 운영체제의 프로세스 목록이나 파일 목록을 보여 주는 기능을 변조해, 공격자의 프로세스와 파일이 관리자 화면에도 나타나지 않게 숨긴다.
2. 웹 페이지를 열면 "PC에서 바이러스 37개가 발견되었습니다" 같은 가짜 경고 창을 띄워 사용자를 불안하게 만들고, 치료 프로그램이라며 유료 결제나 실제로는 악성인 프로그램 설치를 유도한다.

<details>
<summary>정답과 해설</summary>

정답: 1. 루트킷(Rootkit) 2. 스케어웨어(Scareware)

1번의 단서는 "관리자 권한 유지"와 "자신을 숨긴다" 두 가지다. 유닉스 계열에서 관리자 계정을 root라 부르는 데서 온 이름으로, 시스템 명령이나 커널 모듈을 바꿔치기해 탐지를 피한다. 2번의 단서는 "공포(scare)를 이용한 가짜 경고"다.

| 오답 후보            | 비슷해 보이는 이유         | 구별법                                                             |
| -------------------- | -------------------------- | ------------------------------------------------------------------ |
| 백도어(Backdoor)     | 재침입 경로를 남긴다       | 인증을 우회하는 통로 자체. 흔적을 숨기는 도구 모음이면 루트킷      |
| 트로이 목마(Trojan)  | 정상 프로그램으로 위장한다 | 유용한 프로그램으로 위장해 실행 유도. 은닉·권한 유지는 루트킷      |
| 랜섬웨어(Ransomware) | 돈을 요구한다              | 실제로 파일을 암호화한 뒤 복호화 대가 요구. 가짜 경고는 스케어웨어 |
| 애드웨어(Adware)     | 원치 않는 창을 띄운다      | 광고 노출이 목적. 공포를 주어 결제를 유도하면 스케어웨어           |

이 문제의 함정은 "돈을 요구한다"는 공통점이다. 스케어웨어는 실제 피해 없이 겁만 주고, 랜섬웨어는 파일을 실제로 암호화한다.

> [!CAUTION] 시험에서 실수하는 지점
> 영문으로 쓰라는 조건에서 한글로만 쓰거나 `Rootkits`, `Scareware program`처럼 덧붙이면 감점될 수 있다. 같은 3회에 나온 SBOM처럼 약어로 답하는 용어는 풀네임(Software Bill of Materials)까지 함께 외워 두면 설명만 보고도 떠올리기 쉽다.

</details>

> [!NOTE] 개념 요약
>
> - 악성 소프트웨어는 목적과 동작으로 구별한다. 루트킷은 권한 유지와 은닉, 백도어는 인증 우회 통로, 트로이 목마는 정상 프로그램 위장, 랜섬웨어는 파일 암호화 후 금전 요구, 스케어웨어는 가짜 경고로 결제 유도, 스파이웨어는 정보 몰래 수집, 애드웨어는 광고 노출이 목적이다.
> - 바이러스는 다른 파일에 붙어야 퍼지고, 웜은 숙주 파일 없이 네트워크로 스스로 전파된다.
> - 최근 함께 나온 보안 용어: SBOM(소프트웨어 자재 명세서), 워터링 홀(표적이 자주 찾는 사이트 감염), 심볼릭 링크 공격.
> - 답은 조건에 맞춰 영문 철자로 쓰고, 약어는 풀네임까지 외워 둔다.
