## 메모 앱 첫판

2시 43분 커밋의 메시지는 "fix: app state"인데, 실제 내용은 메모 앱 첫판(`Memo.tsx` 133줄, `Memo.css` 161줄)이다. macOS 메모처럼 왼쪽에 폴더, 가운데에 메모 목록, 오른쪽에 본문을 배치했다. `Button`, `Input`, `ScrollArea` 같은 작은 공통 컴포넌트도 이 커밋에서 생겼다.

데이터는 모두 코드에 있었다. 폴더 다섯 개(모든 iCloud 메모, 메모, 공부, 아이디어, 스케치)와 메모 세 개(파스타 레시피, 책 읽기, 프로그래밍 공부)를 `useState`의 초깃값으로 정의했다. 새로고침하면 처음 상태로 돌아간다.

같은 커밋에서 서버에 `routes/memo.js`(24줄)를 추가했다. `let memos = []`인 메모리 배열에 GET·POST 경로를 연결한 것이고, 화면은 이 경로를 호출하지 않았다. 반대로 이틀 전 만든 메일 경로 `routes/mail.js` 39줄은 이 커밋에서 삭제되었다.

![10월 15일의 메모 앱 구조](./images/day-20241015-structure.svg '화면과 서버 모두 메모를 메모리에만 보관했다')

오전 11시대의 커밋 셋은 메모 앱 정리다.

- **스타일**: `Memo.tsx`와 `Memo.css`의 화면 스타일을 조정했다(154줄 추가, 80줄 삭제)
- **`Input` 삭제**: 새벽에 만든 `Input` 컴포넌트(12줄)를 사용하는 곳이 없어 삭제했다
- **"모든 iCloud 메모"**: 이 폴더를 선택하면 모든 메모를 표시한다. 폴더 id가 `'1'`이면 폴더 필터링을 건너뛰는 한 줄이다

## GitHub 앱

7시 27분에 GitHub 앱을 추가했다. 프로필 사진·이름·링크, GitHub README에 있던 배지와 통계 그림, 고정 저장소 목록을 JSX로 옮겨 작성했다. 통계 그림은 외부 서비스(github-readme-stats 등)의 이미지 주소를 그대로 사용했다. 값은 모두 직접 작성한 것이라, GitHub의 실제 프로필이 바뀌어도 화면은 바뀌지 않는다.

## 음악: 첫 클릭에 재생, 곡 7개

7시 38분에는 배경 음악을 첫 클릭에 재생하게 했다. 브라우저는 사용자가 페이지와 상호작용하기 전에는 소리가 있는 자동 재생을 차단한다. 그래서 `window`에 클릭 리스너를 한 번 등록하고, 첫 클릭에서 재생한 뒤 리스너를 제거한다.

7시 42분에는 볼륨 창을 상태 막대 쪽 `VolumeModal`에서 음악 플레이어 쪽 `MusicPlayerVolume`으로 옮기고, 스타일도 `MusicPlayer.css`로 합쳤다. 같은 커밋에서 `Profile.tsx`의 이름을 `GithubProfile.tsx`로 변경했다.

11시 37분 커밋은 `MusicContext`의 곡 목록을 2개에서 7개로 늘렸다. 〈센과 치히로의 행방불명〉 두 곡에 〈하울의 움직이는 성〉, 이루마 두 곡 등 다섯 곡을 더하고, 곡 이름·앨범·표지 배열도 7개로 맞췄다. 음악 파일 4개(`4.mp3`~`7.mp3`, 약 12.8MB)와 앨범 그림 4장은 `client/public/`에 직접 커밋되었다.

## 창과 기타 정리

나머지 짧은 커밋 넷은 정리 작업이다.

- **더블클릭 처리**: 제목 표시줄의 더블클릭 최대화(`onDoubleClick={handleMaximize}`) 줄을 정리했다(1줄)
- **불필요한 호출 삭제**: Blog 앱에 남아 있던 `bringAppToFront` 호출 하나를 삭제했다. 창을 맨 앞으로 올리는 처리는 이틀 전 `Container`가 담당하게 되었기 때문이다
- **빈 줄 삭제·그림자**: 메일 앱 JSX의 빈 줄 두 개를 삭제하고, 메일 앱의 `box-shadow` 값을 한 줄 수정했다

## 돌아보며

메모 앱은 이날 "메모처럼 생긴 화면"으로 시작했다. 어떤 내용을 담을지는 정하지 않아서, 내용은 파스타 레시피 같은 예시였다. 1주일 뒤에는 서버와 DB를 연결했고([2024년 10월 21~22일 회고](/memo/day-20241021)), 2년 뒤에는 이 앱이 사이트의 블로그가 되었다. 화면을 먼저 만든 앱이 나중에 가장 많은 역할을 맡게 되었다.

커밋 메시지는 이날 가장 아쉬운 부분이다. 메모 앱 첫판의 메시지가 "fix: app state"였고, 메일 경로 삭제도 같은 커밋에 섞였다. 이런 커밋은 메시지만으로 실제 변경을 알 수 없어서, 나중에 변경 이력을 추적할 때 코드를 직접 대조해야 한다. 지금은 커밋 형식을 CI가 검사하고, 한 커밋에는 한 가지 변경만 담는다([커밋 규칙을 문서 대신 CI로 지키기](/memo/commit-conventions-ci)).
