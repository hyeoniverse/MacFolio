Dock 오른쪽 끝의 휴지통 아이콘은 처음부터 있었지만 `onClick={() => {}}`였다. 눌러도 아무 일이 없는 아이콘은 macOS를 흉내 낸 화면에서 가장 먼저 티가 나는 곳이다.

## 처음 생각: 버린 기능 모음

macOS의 휴지통에는 지운 파일이 있다. 이 사이트에서 "지운 것"이 무엇일까 생각하다가, 만들면서 버린 기능을 모으기로 했다. CRA → Vite, Firebase → 직접 만든 API 서버, 방명록이던 메모 앱 → 블로그, 이름·비밀번호 칸 → 방문자 쿠키 같은 11가지다. 항목마다 왜 바꿨는지, 그 커밋에서 지운 코드 줄 수, 바꾸기 전 화면을 붙였다.

바꾸기 전 화면은 사진이 남아 있지 않아서, 바꾸기 직전 커밋을 다시 빌드해 찍었다.

```bash
git worktree add --detach old df07a4bf^   # Blog 앱을 지우기 직전
cd old && pnpm install --frozen-lockfile && pnpm --filter @macfolio/react build
npx vite preview --port 4801
```

Playwright로 그 화면을 열고 시계를 그날로 맞춘 뒤 앱을 열어 찍었다.

![방명록이던 메모 앱](./images/bin-app-old-memo.jpg '바꾸기 직전 커밋을 빌드해 찍은 화면. 닉네임과 내용을 적어 남기는 방명록이었다')

줄 수를 셀 때도 배운 것이 있다. Firebase를 걷어 낸 커밋은 그대로 세면 −1,139줄인데 대부분이 `pnpm-lock.yaml`이었고, 빼면 −105줄이다. CRA에서 Vite로 옮긴 커밋은 −93,819줄이 나왔는데, 그때 저장소에 실수로 들어가 있던 `node_modules`를 지운 것이었다.

## 그리고 뺐다

만들고 보니 걸리는 것이 있었다.

- 내용 대부분이 개발 일지에 이미 있다. 휴지통은 일부러 열어 봐야 하는 곳이라, 같은 이야기를 한 번 더 보는 사람은 많지 않다.
- 개발이 끝나면 더할 것이 없다. 휴지통이 "실제로 무언가를 지우는 곳"이 아니라 전시장이 된다.

그래서 휴지통은 **실제로 비울 수 있는 것**만 담기로 했다. 바꾸기 전 화면은 이 글에 남겼다.

## 지금: 내 브라우저 데이터

방문자가 비울 수 있는 것은 이 사이트가 그 브라우저에 남긴 것이다.

| 항목                                  | 저장 위치        | 비우면                               |
| ------------------------------------- | ---------------- | ------------------------------------ |
| 설정 (화면 모드, 배경화면, 딸깍 소리) | `localStorage`   | 바로 처음 설정으로                   |
| 메모 보기 설정                        | `localStorage`   | 메모 앱을 다음에 열 때부터 처음 설정 |
| 메모 최근 검색어                      | `localStorage`   | 찾기 칸의 최근 목록이 빈다           |
| 로그인하러 떠날 때 켜 둔 앱           | `sessionStorage` | 돌아왔을 때 창이 처음 상태로         |

남아 있는 것만 보여 주고, 하나씩 또는 "휴지통 비우기"로 한 번에 지운다. 설정은 앱이 들고 있는 값도 함께 처음으로 돌린다. 이때 순서가 중요했다. 설정 저장소는 값이 바뀌면 `localStorage`에 다시 쓰므로, 처음 설정으로 돌린 **뒤에** 키를 지워야 키가 남지 않는다.

목록은 코드 안의 배열인데, 새 키를 쓰고 여기에 더하는 것을 잊으면 휴지통이 그 데이터를 모른 채 "남긴 것이 없습니다"라고 말하게 된다. 그래서 단위 시험이 소스 전체에서 `localStorage`·`sessionStorage`를 쓰는 파일의 `macfolio:` 키를 모아, 모두 목록에 있는지 확인한다.

방문자 이름 쿠키(`macfolio_visitor`)는 다르게 다룬다. 서버가 주는 httpOnly 쿠키라 사이트의 자바스크립트가 읽거나 지울 수 없다. 그래서 무엇인지와 브라우저 설정에서 지우는 방법만 적었다. 쿠키가 있는지 알아보려고 서버의 `GET /visitor`를 부르지도 않는다. 그 요청이 쿠키가 없는 방문자에게 새 쿠키를 만들기 때문이다.

서버에 무엇을 얼마나 보관하는지는 개인정보 문서(`docs/privacy.md`)에 따로 적어 두었다. 목록 아래의 링크를 누르면 Finder가 그 문서를 연다.

## 관리자에게는 서버 파일

관리자로 로그인하면 사이드바에 "서버 파일"이 하나 더 생긴다. 글에서 빼도 서버에 남는 이미지·첨부 중 쓰는 곳이 없는 것을 지운다. 이야기는 [글에서 지운 이미지는 서버에 남는다](/memo/server-files-cleanup)에 따로 적었다.

## 휴대폰에는 두지 않는다

iOS에는 휴지통 앱이 없다. 그래서 앱 정보에 `desktopOnly`를 두고 휴대폰 홈 화면에서는 뺐다.
