Dock 오른쪽 끝의 휴지통 아이콘은 처음부터 있었지만 `onClick={() => {}}`였다. 눌러도 아무 일이 없는 아이콘은 macOS를 흉내 낸 화면에서 가장 먼저 티가 나는 곳이다.

## 무엇을 버렸는지 보여 주는 휴지통

macOS의 휴지통에는 지운 파일이 있다. 이 사이트에서 "지운 것"이 무엇일까 생각하다가, 만들면서 버린 기능과 기술을 모으기로 했다.

| 버린 것                          | 대신                                    |
| -------------------------------- | --------------------------------------- |
| Create React App                 | Vite                                    |
| Firebase (방명록 저장, 호스팅)   | 직접 만든 API 서버와 Cloudflare Workers |
| 방명록이던 메모 앱, Blog 앱      | Markdown 블로그 (메모 앱)               |
| 방문자가 정리하는 메모 폴더      | 관리자만 정리하고 서버에 저장           |
| 메시지·댓글의 이름과 비밀번호 칸 | 방문자 쿠키로 정하는 이름               |
| 손으로 옮겨 적은 GitHub 프로필   | 서버가 GitHub에서 받아 오는 프로필      |
| Cloudflare의 빌드 서버           | GitHub Actions                          |
| !important 72개, 메뉴 다섯 벌    | CSS @layer, 공통 Menu                   |
| 새 탭으로 여는 Swagger 문서      | 사이트 안의 API 문서 앱                 |

항목을 고르면 오른쪽에 무엇으로 바꿨고 언제 왜 바꿨는지가 나오고, "개발 일지 읽기"를 누르면 메모 앱이 그 이야기를 쓴 글을 연다. 결과만 보면 지금의 기술 목록이지만, 무엇을 버리고 왜 바꿨는지가 판단을 더 잘 보여 준다고 생각했다.

목록은 코드 안의 배열(`apps/bin/removed.ts`)이다. 각 항목에는 근거가 되는 글이나 커밋이 있는 것만 넣었다. 단위 시험이 항목마다 이어 주는 글 파일이 실제로 있는지 확인해서, 글 주소를 바꾸면 시험이 먼저 알려 준다.

## 지운 코드와 커밋

항목마다 그 변경의 커밋과, 그 커밋에서 더하고 지운 코드 줄 수를 붙였다. 커밋 이름을 누르면 GitHub에서 그 변경을 바로 본다.

줄 수는 `git show --numstat`으로 셌는데, 그대로 세면 숫자가 부풀었다. 처음 센 Firebase 제거는 −1,139줄이었는데, 대부분 `pnpm-lock.yaml`이었다. CRA에서 Vite로 옮긴 커밋은 −93,819줄이 나왔다. 들여다보니 그때 저장소에 실수로 들어가 있던 `node_modules`(lodash 등 1,139개 파일)를 지운 것이었다. 잠금 파일, `node_modules`, 코드에서 만드는 `openapi.json`, 글(.md)을 빼고 다시 세니 Firebase는 −105줄, CRA → Vite는 −2,247줄이다.

| 버린 것                     | 지운 줄 | 더한 줄 |
| --------------------------- | ------- | ------- |
| Create React App            | 2,247   | 2,693   |
| 방명록이던 메모 앱          | 1,253   | 663     |
| 메시지·댓글의 이름·비밀번호 | 563     | 643     |
| 메뉴 다섯 벌                | 428     | 403     |
| Firebase                    | 105     | 8       |

더한 줄이 지운 줄보다 많은 것도 있다. GitHub 프로필을 서버에서 받아 오게 바꾼 커밋은 294줄을 지우고 2,650줄을 더했다. 손으로 적은 값 대신 API, 캐시, 설정 화면이 생겼기 때문이다.

## 바꾸기 전 모습

말로 "예전에는 방명록이었다"고 쓰는 것보다 그때 화면을 보여 주는 편이 낫다. 그런데 예전 화면을 찍어 둔 사진이 없었다. 그래서 바꾸기 직전 커밋을 다시 빌드해서 찍었다.

```bash
git worktree add --detach old df07a4bf^   # Blog 앱을 지우기 직전
cd old && pnpm install --frozen-lockfile && pnpm --filter @macfolio/react build
npx vite preview --port 4801
```

Playwright로 그 화면을 열고, 시계를 그날(2026년 9월 28일)로 맞춘 뒤 앱을 열어 찍었다.

![방명록이던 메모 앱](./images/bin-app-old-memo.jpg '바꾸기 직전 커밋을 빌드해 찍은 화면. 닉네임과 내용을 적어 남기는 방명록이었다')

이렇게 찍은 것이 세 장이다. 방명록 메모, 방문자도 폴더를 만들 수 있던 메모, Blog 앱이다. Blog 앱은 창에 띄우던 예전 블로그 주소가 이미 404를 내고 있었는데, 지운 이유를 이보다 잘 보여 주는 화면은 없어서 그대로 썼다. 나머지는 개발 일지에 이미 있던 전후 그림(이름·비밀번호 칸, 손으로 적은 GitHub 프로필)과, 지금도 서버에 있는 Swagger 화면이다.

정보 칸의 작은 그림을 누르거나 목록에서 스페이스를 누르면 창 가득 크게 본다. Finder의 훑어보기와 같은 키다.

## 지운 메모는 메모 앱에

처음에는 관리자가 지운 메모(메모 앱의 "최근 삭제된 항목")도 휴지통에 함께 보여 주었다. 그런데 macOS도 메모 앱에서 지운 메모는 메모 앱 안에만 두고 Finder 휴지통에는 넣지 않는다. 같은 일을 두 곳에서 하면, 두 앱이 같은 서버 목록을 따로 들고 있다가 어긋나지 않게 맞추는 코드도 따로 필요했다. 그래서 휴지통은 방문자와 관리자 모두에게 "지운 기능"만 보여 주게 했다.

## 휴대폰에는 두지 않는다

iOS에는 휴지통 앱이 없다. 사진과 파일 앱 안에 "최근 삭제된 항목"이 있을 뿐이다. 그래서 앱 정보에 `desktopOnly`를 두고 휴대폰 홈 화면에서는 뺐다.
