메모 편집기에 이미지를 끌어 놓으면 파일은 서버의 `Upload` 테이블에 들어가고, 글 본문에는 `![](https://<API 주소>/files/<id>)` 한 줄이 들어간다. 글과 파일은 이 주소 문자열로만 이어져 있다.

그래서 글에서 그 줄을 지워도 파일은 지워지지 않는다. 글을 영구히 지워도 마찬가지다. 사용자 입장에서는 이미지를 지웠는데, 서버에는 그대로 남아 DB를 차지한다.

## 지울 때 파일도 함께 지우면 안 될까

처음 떠오른 방법은 글을 저장할 때 빠진 이미지를 찾아 바로 지우는 것이다. 하지만 이 사이트에는 그럴 수 없는 이유가 두 가지 있다.

- **예전 버전.** 게시할 때마다 버전이 남고, 예전 버전으로 되돌릴 수 있다. 지금 글에서 뺀 이미지도 예전 버전에는 들어 있다.
- **최근 삭제된 항목.** 지운 글은 30일 동안 되살릴 수 있다.

바로 지우면 이 둘이 깨진다. 그래서 자동으로 지우지 않고, 파일마다 **어디에서 쓰는지**를 보여 주고 관리자가 고르게 했다.

## 쓰는 곳 찾기

파일과 글은 문자열로만 이어져 있으니, 글의 문자열에서 파일 주소를 찾는다.

```ts
export function uploadIdsIn(text: string | null | undefined): string[] {
	if (!text) return [];
	return [...new Set([...text.matchAll(/\/files\/([\w-]{16})(?![\w-])/g)].map((match) => match[1]))];
}
```

파일 id는 16자라서, 뒤에 글자가 더 붙으면 다른 주소로 본다. 서버의 `GET /files`(관리자만)는 모든 글의 게시한 내용, 임시 저장, 예전 버전을 이 함수로 훑고, 파일마다 쓰는 곳을 세 가지로 알려 준다.

| 쓰는 곳         | 뜻                                                | 지울 수 있나                             |
| --------------- | ------------------------------------------------- | ---------------------------------------- |
| 지금 글         | 게시한 내용이나 임시 저장 (최근 삭제된 글도 포함) | 아니요 (409)                             |
| 배경화면        | 관리자가 올린 배경화면의 원본·썸네일              | 아니요 (배경화면 설정에서 지운다)        |
| 예전 버전에서만 | 지금 글에서는 뺐지만 예전 버전에 남아 있다        | 예 (그 버전으로 되돌리면 그 자리가 빈다) |
| 없음            |                                                   | 예                                       |

`DELETE /files/:id`도 같은 규칙으로 막는다. 화면에서 지우기 단추를 감추는 것만으로는 부족하다. 화면을 거치지 않은 요청도 있고, 화면이 목록을 읽은 뒤에 누가 그 파일을 글에 넣었을 수도 있다.

목록을 읽을 때 파일 내용(`data`, 바이트)은 읽지 않는다. 한 파일이 10MB까지라, 목록에서 내용까지 읽으면 그만큼 DB에서 끌어온다.

## 서버가 모르는 글

이 블로그의 글 대부분은 저장소의 Markdown 파일이다. 서버 DB에는 관리자가 고친 글만 있다. 저장소 글이 서버의 이미지를 가리키면 서버는 그것을 모른다.

그래서 화면이 한 번 더 본다. 휴지통은 저장소 글의 본문에서도 같은 주소를 찾아, 하나라도 있으면 "글에서 쓰는 파일"로 보고 지우기 단추를 감춘다.

## 휴지통에서

관리자로 로그인하면 휴지통 사이드바에 "서버 파일"이 생긴다. 맨 위에 쓰는 곳이 없는 파일의 수와 크기가 나오고, 하나씩 또는 한 번에 지운다. 되돌릴 수 없어서 지우기 전에 묻는다.

[휴지통](/memo/bin-app)이 "이 사이트에서 버린 기능"을 모아 두는 곳이라면, 서버 파일은 "글에서 버렸지만 서버에 남은 것"이다. macOS 휴지통이 지운 파일을 모아 두는 것과도 맞다.

## 시험

- API 단위 시험: 주소 찾기 (전체 주소·경로, 같은 id는 한 번, 16자보다 긴 주소)
- API e2e: 지금 글·예전 버전·배경화면을 구별하는지, 안 쓰는 파일과 예전 버전만 쓰는 파일은 지우고 나머지는 409, 관리자가 아니면 401
- 화면 E2E: 가짜 서버에 네 가지 파일을 두고, 쓰는 파일에는 지우기 단추가 없고 나머지를 하나씩·한 번에 지우는지
