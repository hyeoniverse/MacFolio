## #187의 마지막 밤: RPG를 걸어 다니는 마을로

[전날](/memo/day-1016)은 "메뉴가 어디서 어디로 진행되는지 모르겠다"는 말을 듣고 끝났다. 자정 직후부터 그 말에 답했다.

| 시각  | 바꾼 것                                                                                                              |
| ----- | -------------------------------------------------------------------------------------------------------------------- |
| 00:29 | 게임 화면을 360×208로 낮추고 전체 화면에서 세 배(글자 33px)로 키움. 맨 위 길잡이 줄(메뉴 ▸ 주제 ▸ 단계), 읽음 ✓·NEXT |
| 01:27 | Safari 페이지 전체를 게임 화면으로. 높이에 맞춘 정수배, 반투명 어두운 창, 금색 강조 하나                             |
| 02:16 | 40×24 타일 마을을 방향키·WASD로 걷는다. 게시판·풀숲의 버그·상점·여관 앞에서 Z를 누르면 그 주제가 열린다              |
| 03:18 | 마을과 장면을 Pixel-Boy의 Ninja Adventure 에셋(CC0)으로 다시 그림. 자동 타일 흙길·물, 걷기 프레임이 있는 주인공      |
| 04:09 | 한글 입력 상태에서 Z·X·WASD가 먹지 않던 것을 고침                                                                    |

마지막 버그는 한글 자판 때문이었다. 한글 입력 상태에서 Z를 누르면 `event.key`가 `'z'`가 아니라 `'ㅋ'`로 오고, 크롬의 입력기는 `'Process'`를 보내기도 한다. 게임 키는 글자 대신 자판 위치(`event.code`)로 읽게 했다.

```ts
const CODE_KEYS = { KeyZ: 'z', KeyX: 'x', KeyW: 'w', KeyA: 'a', KeyS: 's', KeyD: 'd' };

export function gameKey(event: KeyboardEvent): string {
	const byCode = CODE_KEYS[event.code];
	if (byCode) return byCode;
	return event.key.length === 1 ? event.key.toLowerCase() : event.key;
}
```

## 22분 만에 되돌린 템플릿 구조

4시 59분에는 템플릿마다 페이지 구조를 아예 다르게 만들었다. 제품은 스크롤 이야기, 키노트는 16:9 슬라이드 덱, 문서는 페이지 트리 사이드바, 매거진은 표지·차례·펼침면이다. 49개 파일에 15,013줄을 더한 커밋이었다. 5시 21분에 그대로 되돌렸다.

## CI: Postgres 이미지와 25분 한도

전날 회고에 "이미지를 캐시하거나 받는 곳을 바꾸는 일을 할 때가 되었다"고 적었다. 이날 아침 [#240](https://github.com/hyeoniverse/MacFolio/pull/240)으로 했다. ECR Public이 한도에 걸리면 mirror.gcr.io, 그다음 Docker Hub에서 받는다. Postgres를 `services`가 아니라 단계로 띄워서, 이미지를 끝내 받지 못해도 형식 검사 같은 다른 검사는 돈다.

같은 아침 #187을 머지하기 직전에 화면 E2E도 `check` 작업에서 떼어 세 칸으로 나눠 동시에 돌렸다. 시험이 늘어 한 작업의 25분 한도에 걸렸기 때문이다. API 이미지와 배포는 E2E까지 통과해야 진행한다. 이틀 뒤 이것을 다시 여섯 칸으로 나눴다([머지하고 배포까지 15분에서 5분으로](/memo/faster-e2e-ci)).

| 이날 끝                 | 숫자 | 전날보다 |
| ----------------------- | ---: | -------: |
| 브라우저 E2E            |  443 |      +68 |
| 단위 시험 (화면 + core) |  615 |     +131 |
| contracts 단위 시험     |   42 |       +9 |
| API 단위 시험           |  166 |       +9 |
| API e2e                 |  128 |       +4 |
| main에 머지한 PR        |   17 |          |

숫자는 그날 마지막 main 커밋(#244 머지)에서 `test(`·`it(` 호출을 센 값이고, 전날 값도 같은 방법으로 셌다. 늘어난 시험 대부분은 #187에 들어 있었다.

## 돌아보며

#187은 일주일 동안 열려 있었고, 그동안 main이 계속 움직여 이날 새벽에도 main을 한 번 더 합쳐야 했다. 그 PR을 닫은 것은 새 기능이 아니라 빼기였다. RPG 대화창을 다른 브랜치로 옮기자 바로 머지할 수 있었다. 끝나지 않은 실험을 PR 안에 두면 PR 전체가 그 실험을 기다린다.

새벽 다섯 시의 템플릿 구조 바꿈은 1만 5천 줄짜리였고 22분 만에 되돌렸다. 머지를 앞둔 PR에 그 크기의 바꿈을 넣은 것부터가 잘못이었다. 범위를 첫 화면과 구역 머리로 좁힌 두 번째 시도는 남았다.

아침의 정리 PR 열 개는 서로 다른 방법으로 "화면이 그대로인지"를 확인했다. 값을 그대로 두거나, 빌드한 CSS를 바이트로 비교하거나, 계산된 스타일을 요소마다 비교했다. 정리는 무엇이 같아야 하는지를 먼저 정하면 빨리 끝난다.
