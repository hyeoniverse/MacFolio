## Finder를 실제 파일 시스템으로

19일부터 Finder에서 Cloudflare R2에 저장한 실제 파일을 다뤘다. 관리자가 업로드하면 API가 5분 동안 유효한 서명 URL을 발급하고, 파일 본문은 API 서버를 거치지 않고 R2로 직접 전송된다. 폴더 구조는 `/finder/layout`에 저장해 방문자도 같은 구조를 보고, PDF는 pdf.js로 렌더링하는 미리보기 앱에서, 영상은 HTTP Range 요청에 응답하는 QuickTime 앱에서 연다. 20일에는 열기 창에서 바탕화면의 포트폴리오 가상본이 빈 폴더로 열리는 버그를 계기로, 12곳이 각자 구현하던 "가상본이면 원본으로 이동" 규칙을 별도 노드 종류(`kind: 'alias'`)로 분리했다. ==이제 가상본 처리를 빠뜨린 코드는 타입 검사에서 오류가 난다.== 같은 날 Macintosh HD › 사용자 › hyeoniverse 아래 단일 트리로 재구성했고, 서버에 저장된 폴더 id는 그대로 유지했다.

## 디자인 토큰 세 층과 Stylelint

`theme.css` 한 파일에서 기본 글자색 하나에 이름 다섯 개, 값 네 가지가 쓰이고 있었다. 20일 [#286](https://github.com/hyeoniverse/MacFolio/pull/286)에서 토큰을 원시값(`primitives.css`), 의미(`semantic.css`), 컴포넌트(`components.css`) 세 층으로 나누고 참조 방향을 컴포넌트 → 의미 → 원시 한 방향으로 정했다. 앞뒤 PR에서 속성에 직접 쓴 이름 없는 색을 161곳에서 6곳으로 줄였고, Stylelint로 토큰 범위의 숫자를 직접 쓰지 못하게 했다. 21일 [#296](https://github.com/hyeoniverse/MacFolio/pull/296)에서는 차단 목록보다 허용 목록이 짧아 규칙을 반대로 바꿨다. 남은 문제는 ==정의되지 않은 CSS 변수는 오류 없이 무시된다==는 점이다. 같은 날 Finder 작업에서 방금 이름을 바꾼 `--radius-xs`를 써서 모서리가 사라졌고, 다음 날 둘러보기 카드와 텍스트 편집기에서도 없는 토큰 이름을 썼다.

## Markdown 이력서, 위젯, 둘러보기

21일에는 큰 기능 세 개를 추가했다. 이력서는 시스템 설정의 값을 화면마다 조합하던 방식에서 Markdown 문서 하나(`/site/resume`)로 바꿔, Finder 문서, PDF, 터미널 `resume`이 같은 원본을 읽는다. 이 문서를 여는 앱으로 Milkdown 기반의 WYSIWYG 텍스트 편집기를 만들었다. 바탕화면과 휴대폰 홈 화면에는 180px 격자에 배치하는 위젯 8종을 추가했고, 첫 방문자에게는 화면의 한 영역씩 강조하며 실제로 누르게 하는 둘러보기와 팁 앱을 보여 준다. 세 기능 모두 처음 구현한 형태에서 여러 번 바꿨다(미리보기 분리형 편집기 → WYSIWYG, 불투명 패널 → 유리 → 혼합).

## 첫 방문 성능과 CI 성능 예산

22일 Lighthouse로 측정한 첫 방문은 휴대폰 55점(LCP 25.7초), 데스크톱 62점(LCP 5.8초)이었고 첫 방문마다 4.9MB·9MB를 내려받았다. 세 차례 개선으로 휴대폰은 LCP 3.2초·483KB, 데스크톱은 98점·771KB가 됐다. 본문 글꼴 TTF(압축 1.7MB)를 `unicode-range`로 나눈 woff2 두 조각(149KB)으로 바꾸고, 모든 앱을 `lazy`로 분리해 첫 번들을 250KB에서 47KB(brotli)로 줄이고, 로딩 화면을 누르기 전에는 바탕화면을 렌더링하지 않았다. 같은 날 명언 위젯이 데이터를 첫 번들에 넣어 `boot`가 65KB로 늘었고, 23일 운영 사이트 재측정에서 이 회귀를 찾았다. 같은 날 [#367](https://github.com/hyeoniverse/MacFolio/pull/367)에서 `boot` 55KB, 첫 방문 합계 265KB의 brotli 상한을 CI에 걸었다.

## 배포 시간과 머지 뒤 CI 실패

19일에는 머지부터 배포까지 약 15분 중 8~9분이 화면 E2E였다. E2E를 여섯 작업으로 나누고 PR에서 통과한 커밋과 트리가 같은 main 커밋은 E2E를 생략해 5분으로 줄였다. 24일에는 [#368](https://github.com/hyeoniverse/MacFolio/pull/368)을 머지한 뒤 CI가 서로 다른 원인으로 네 번 실패했다. E2E 세 건은 macOS에서 반복해도 재현되지 않아 CI가 남긴 Playwright trace로 원인을 확인했다. 홈 아이콘 이름의 `line-height: normal`이 Linux에서 웹 글꼴 적용 전후 2px 달라졌고, 약 2MB의 저장소 글 청크가 늦게 도착하는 사이 메모 목록이 재정렬됐다. 두 원인 모두 방문자 기기에서도 생기는 동작이라 시험이 아니라 앱을 고쳤다. 나머지 E2E 한 건은 시험의 scroll 이벤트 순서 문제였다. 의존성 검사는 코드와 무관하게 새로 공개된 body-parser 권고로 실패했고, 그 수정을 머지한 뒤 multer 권고로 다시 실패했다.

## 돌아보며

- 파일이 겹치지 않아도 같은 이름을 사용하면 겹치는 작업이다. 토큰 이름 변경과 Finder 작업이 한 줄에서 두 번 충돌했다.
- 사람이 기억해야 하는 규칙은 언젠가 누락된다. 가상본은 타입 검사로, 숫자 값은 Stylelint로 옮겼고, 정의되지 않은 CSS 변수 검사가 다음 차례로 남았다.
- 오류 문구보다 요청과 기록을 직접 확인한다. R2 업로드 오류는 CORS를 가리켰지만 원인은 서명 키였고, 재현되지 않는 E2E는 trace로만 원인이 드러났다.
- 회귀를 찾은 날 그 회귀를 막는 검사를 넣었다. 다만 전송 크기 예산은 같은 CSS를 두 번 받는 요청 중복을 잡지 못해, 24일에 요청 횟수를 확인하는 E2E를 보완했다.
- CORP, 아이폰 음악 위젯 모서리, CSS preload 경고는 모두 Chromium과 Playwright WebKit에서 재현되지 않았다. 배포 후 실제 Safari 확인을 점검 항목에 포함한다.
