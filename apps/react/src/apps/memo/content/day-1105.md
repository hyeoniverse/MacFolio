## 의존성 업데이트와 오류 응답 ([#411](https://github.com/hyeoniverse/MacFolio/pull/411))

| 커밋                                                                  | 문제                                                                                                                                                                 | 수정                                                                    |
| --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| [e11d3b5f8](https://github.com/hyeoniverse/MacFolio/commit/e11d3b5f8) | scalar 문서 앱의 `@scalar/agent-chat`이 쓰는 `ai` 7은 `@ai-sdk/provider-utils` 5를 요구하는데, low 취약점 때문에 넣은 override `^4.0.33`이 4로 고정했다              | override 삭제. 5.0.61이 설치된다                                        |

전역 예외 필터는 http-errors를 직접 받는 경우만 우리말로 바꾸고 있었다. ==마이너 업데이트가 예외의 모양을 바꿔 그 분기를 건너뛰었다==. 필터 단위 시험에 감싼 413 오류(`new HttpException('request entity too large', 413, { cause })`)를 더했다.

## 메모 글 표기 ([#412](https://github.com/hyeoniverse/MacFolio/pull/412))

긴 개념 글에서 핵심 문장이 굵게만으로는 눈에 띄지 않았고, 정의와 주의할 점이 본문과 구분되지 않았으며, 관계 대수식의 아래 첨자는 코드 글자로만 적을 수 있었다. 그래서 표기 다섯 가지를 더했다. 모두 GitHub·Obsidian 등에서 쓰는 표기를 따라, 저장소의 Markdown을 다른 뷰어에서 열어도 의미가 유지되게 했다.

| 표기                   | 결과                    | 따른 표기                         |
| ---------------------- | ----------------------- | --------------------------------- |
| `==글자==`             | 형광펜                  | Obsidian·Typora                   |
| `[제목](#제목-주소)`   | 그 절로 이동            | GitHub 제목 id 규칙               |
| `` `SELECT 1{:sql}` `` | 인라인 코드 문법 강조   | rehype-pretty-code                |
| ` ```math `            | KaTeX 블록 수식         | GitHub                            |
| `` `식{:math}` ``      | KaTeX 인라인 수식       | rehype-pretty-code의 언어 꼬리표  |
| `> [!NOTE] 제목`       | 콜아웃 상자 (다섯 종류) | GitHub 경고, 제목은 Obsidian 확장 |

### 형광펜

![형광펜](./images/week-1102-highlight.jpg '글자 아래 55%만 칠하고, 줄이 바뀌어도 줄마다 끝이 둥글다')

읽기 화면은 remark 플러그인(`remarkHighlight`)이 한 문단 안에서 `==`를 짝지어 `<mark class="memo-highlight">`로 그린다. `a == b`처럼 여는 `==` 뒤나 닫는 `==` 앞이 공백이면, 짝이 없거나 코드 안이면 글자 그대로 남긴다. 기존 글 248편을 렌더링해 `<mark>`가 하나도 생기지 않는 것을 확인했다.

편집기는 같은 remark 플러그인으로 읽고 저장할 때 remark-stringify 확장 handler로 `==`를 되돌린다. 서식 막대 버튼, 도구 막대의 빠른 버튼, ⌘⇧H, `==글자==` 입력 규칙으로 켜고 끈다. 모양은 macOS 메모의 노란 강조처럼 글자 아래 55%만 칠하고(`--memo-highlight`, 라이트 45%·다크 32% 불투명도), `box-decoration-break: clone`으로 줄마다 끝을 둥글게 한다.

### 제목의 글 안 주소

제목에 id가 없어, 글에 적은 `[다시 보일 때의 규칙](#다시-보일-때의-규칙)` 같은 링크가 눌러도 움직이지 않았다. `remarkHeadingIds`가 GitHub와 같은 규칙(소문자, 글자·숫자·공백·`-`·`_`만 남기고 공백을 `-`로, 같은 제목은 `-1`, `-2`)으로 id를 만든다. 각주·접기 블록처럼 `user-content-`를 앞에 붙여 사이트의 다른 id와 겹치지 않게 하고, `MarkdownLink`가 짧은 이름으로도 찾는다.

> [!IMPORTANT] 깨진 글 안 링크를 시험으로 막는다
> `content.test.ts`가 모든 글의 `#주소` 링크가 그 글의 제목·각주·접기 블록을 가리키는지 검사한다. 257편 전체가 통과하고, 깨져 있던 기존 링크도 이제 동작한다.

편집 화면에서는 처음에 글 안 링크를 누르면 바로 그 제목으로 이동하게 했다가 곧 바꿨다. 누르기만 해도 이동하면 링크 글자를 고칠 수 없고, 다른 링크는 누르면 그 자리에 커서가 놓이기 때문이다. 이제 글 안 링크도 마우스를 올리면 뜨는 툴팁의 "그 자리로 이동" 버튼이나 ⌘·Ctrl 누르기로 이동하고, 툴팁에는 `#데이터와-정보`처럼 주소를 풀어 보인다. 이동은 `anchors.ts`가 받는 이벤트로 하고, 제목은 읽기 화면과 같은 주소 규칙(`headingSlug`)으로 찾는다.

접기 블록의 요약이 두 줄이면 › 가 두 줄의 가운데에 오던 것도 함께 고쳤다. 요약을 `align-items: flex-start`로 바꾸고 › 를 `margin-top: calc((1lh - 0.45em) / 2)`로 첫 줄 가운데에 맞춘다.

### 인라인 코드 문법 강조와 등록하지 않았던 언어

코드 블록은 ` ```언어 `로 언어를 받지만 인라인 코드에는 언어를 적을 자리가 없었다. 끝에 `{:언어}`를 달면 꼬리표를 떼고 코드 블록과 같은 lowlight 규칙으로 강조한다. 꼬리표가 없거나 모르는 언어면 그대로 둔다.

![SQL 문법 강조](./images/week-1102-sql-highlight.jpg 'SQL 코드 블록 강조. 전에는 SQL이 등록되지 않아 글자색 하나였다')

이 작업 중에 SQL 코드 블록에 강조가 없던 것도 찾아, 꼬리표 기능보다 먼저 고쳤다. `highlight.ts`는 블로그에 쓰는 언어만 등록하는데, 글 전체에 ` ```sql ` 블록이 80개 있는데도 SQL이 빠져 있었다. SQL·C·diff·Python을 등록하고 `jsonc`는 JSON, `console`은 Bash 별칭으로 받는다.

### 수식과 KaTeX 지연 로딩

![수식](./images/week-1102-math.jpg '블록 수식과 인라인 수식. 아래 첨자에 한글을 쓴 관계 대수식')

rehype 단계에서 수식 자리만 `<memo-math>`로 표시하고, KaTeX(`katex` 0.18.10)와 CSS는 수식이 있는 글을 처음 열 때 동적 `import()`로 불러온다. ==KaTeX는 첫 화면과 메모 앱 청크에 들어가지 않아==, 첫 방문 번들은 263.6KB / 265KB로 예산 안에 있다. 불러오기 전과 식이 틀렸을 때는 원문을 코드로 보인다. 두 표기 모두 편집기에서는 코드라 LaTeX 원문 그대로 보이고, 저장할 때 깨지지 않는다.

| 항목   | 처리                                                                                          |
| ------ | --------------------------------------------------------------------------------------------- |
| 보안   | `trust` 없이 그려 `\href` 같은 명령을 막는다                                                  |
| CSP    | KaTeX의 인라인 style과 자체 글꼴은 기존 `style-src 'unsafe-inline'`, `font-src 'self'`로 허용 |
| 접근성 | 화면 낭독기를 위해 MathML을 함께 넣는다                                                       |
| 검증   | 수식 249개를 `strict: 'error'`로 그려 오류가 없는 것을 스크립트로 확인                        |

KaTeX는 Milkdown 수식 플러그인 때문에 이미 루트 `overrides`에 `^0.18.2`(프로토타입 오염으로 trust 제한 우회, low)로 지정되어 있었다. 메모 앱 의존성에 `^0.18.10`으로 더하자 lockfile의 specifier가 overrides 범위와 달라져 CI의 `pnpm install --frozen-lockfile`이 실패했다. lockfile에 overrides 범위를 기록해 통과시켰다.

### 콜아웃

![콜아웃 다섯 종류](./images/week-1102-callout-types.jpg '참고·팁·중요·주의·경고. 선 없는 둥근 카드에 종류 색을 7% 섞은 바탕, 아이콘만 종류 색')

| 표기           | 제목 | 색     | 쓰는 곳          |
| -------------- | ---- | ------ | ---------------- |
| `[!NOTE]`      | 참고 | 링크색 | 보충 설명        |

| `[!IMPORTANT]` | 중요 | 남색   | 핵심 정의·정리   |

처음 모양은 왼쪽 선이었고, 곧 Apple 개발자 문서의 Note 상자처럼 선 없는 둥근 카드(`--radius-14`)로 바꿨다. 편집 화면(`writer/callouts.ts`)은 인용 블록과 `[!NOTE]` 글자를 그대로 남기고 class만 덧씌워 같은 색 상자로 보인다.

> [!WARNING] 편집기가 저장할 때 콜아웃 표시를 이스케이프했다
> 편집기가 저장할 때 `> [!NOTE]`를 `> \[!NOTE]`로 이스케이프해, 관리자가 글을 한 번 저장하면 콜아웃이 인용문이 되었다. `unescapeTags`가 인용 블록 첫머리의 콜아웃 표시만 되돌리게 하고, `writer.test.ts`와 E2E가 저장 형식을 검사한다.

### 경로와 같은 계층의 제목

막대 가운데는 지금 절과 읽는 자리까지의 하위 제목을 `절 › ### › ####`로 잇는다. `toc.ts`의 `tocPosition`이 읽는 제목에서 거슬러 올라가며 더 얕은 단계만 모으므로, 같은 단계의 앞 제목은 경로에 들지 않는다. 경로의 각 제목은 단추이고, 마우스를 올리면 `tocSiblings`가 고른 같은 계층의 제목 목록이 바로 아래에 뜬다.

![경로와 같은 계층의 제목](./images/week-1102-toc-trail.svg '도식. 읽는 제목에서 거슬러 올라가 경로를 만들고, 경로의 제목마다 부모가 같은 제목을 펼친다')

처음 펼침 규칙([c01cb2d48](https://github.com/hyeoniverse/MacFolio/commit/c01cb2d48))은 경로의 상위 제목에는 하위 제목을, 지금 읽는 제목에는 같은 계층을 펼쳤다. ==같은 막대 안에서 마우스를 올린 제목에 따라 목록의 기준이 달라져==, 모두 같은 계층의 제목으로 맞췄다([d651c3c82](https://github.com/hyeoniverse/MacFolio/commit/d651c3c82)).

### 붙는 막대의 구현 세부

| 문제                             | 처리                                                                                                                                                                                        |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 막대가 나타나는 시각             | 막대가 원래 놓일 자리가 붙는 선(스크롤 칸 위 여백 + 막대의 `top`)을 지나면 `data-stuck`. 그 전에는 `visibility: hidden` + `inert`, 아래 여백을 막대 높이만큼 음수로 잡아 본문을 밀지 않는다 |
| 제목이 막대에 가림               | 스크롤 칸 `scroll-padding-top`에 막대 아래 끝 + 8px. 읽는 중 기준선은 막대 아래 끝 + 48px                                                                                                   |
| 마우스로 누른 버튼이 본문을 넘김 | 초점을 받은 버튼을 `scroll-padding` 아래로 보이려고 브라우저가 본문을 넘긴다. 막대에서 `mousedown` 기본 동작을 막아 누르기만으로는 초점을 옮기지 않는다(키보드 초점은 그대로)               |
| Safari에서 목록 끝의 뒤가 비침   | Safari는 넘기는 상자 끝에서 튕길 때 그 상자의 바탕까지 민다. 바탕·모서리·그림자는 넘기지 않는 바깥 카드(`overflow: clip`)로 옮기고 안의 목록만 넘긴다                                       |
| 휴대폰                           | 막대를 `position: static`·높이 0으로 만들고 버튼만 `position: absolute`로 `.memo-reader`에 맞춰, 본문을 넘겨도 뒤로 버튼과 같은 줄에 있다                                                   |
| 절이 바뀔 때                     | 바뀐 절·하위 제목만 `key`로 새로 그려 읽는 방향으로 미끄러진다. 움직임 줄이기 설정에서는 움직이지 않는다                                                                                    |

이전·다음 절 이름은 평소에 화살표만 보이고, 마우스를 올리거나 키보드 초점이 오면 `max-width`·투명도를 함께 바꿔 화살표 옆으로 밀려 나온다. 칸(1fr) 안에서 펼쳐 가운데 글자가 밀리지 않는다. 처음 목차를 만든 과정은 [목차 글](/memo/memo-toc-image-layout)에 있다.

## 돌아보며

NestJS 12.3은 마이너 업데이트로 Express 오류를 감싸기 시작했고, 전역 필터의 분기를 건너뛰어 응답 설명이 영어가 됐다. 마이너 업데이트도 예외의 모양을 바꿀 수 있다는 것을 놓쳤다. 오류 응답의 언어와 모양은 사용자에게 보이는 계약이라, 필터 단위 시험에 프레임워크가 감싼 형태를 함께 넣었다.

형광펜·콜아웃·수식·제목 id는 모두 GitHub·Obsidian·rehype-pretty-code의 표기를 따랐다. 그래서 저장소의 Markdown을 GitHub에서 열어도 콜아웃 종류와 글 안 링크가 같게 동작한다. 편집기가 이 표기를 이스케이프하지 않는지는 저장 형식 시험으로 확인한다.

KaTeX는 수식이 있는 글을 열 때만 불러와 첫 방문 번들이 263.6KB / 265KB로 예산 안에 머물렀다. 새 기능의 비용을 기존 예산으로 바로 확인할 수 있었다. 앞으로도 기능을 더할 때마다 첫 화면 예산과 메모 앱 청크에 들어가는지를 같은 측정으로 확인한다.

목차 막대는 두 시간 반 동안 여섯 번 바꿨다. 막대 한 줄, 이전·다음 절, 블록 되살리기, 하위 제목 경로, 같은 계층 펼침으로 이어졌고, 펼침 규칙은 만든 지 30분 만에 다시 바꿨다. [10월 23일 회고](/memo/day-1023)에 적은 "기준 화면을 먼저 정한다"는 다짐을 이번에도 지키지 못했다. 다음에는 막대의 상태(맨 위, 붙음, 펼침, 휴대폰)별 화면을 먼저 그린 뒤 구현한다.
