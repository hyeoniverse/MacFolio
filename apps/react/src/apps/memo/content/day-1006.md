커밋 12개, 일한 시간 세 시간 남짓. 열흘 중 가장 짧은 날이다. 새 글도 없고, 고친 내용은 모두 있던 글에 더했다. 이날 메뉴 막대의 메뉴가 실제로 동작하게 되었다. 열흘 동안 만든 것 중 macOS와 가장 비슷하게 동작하는 기능이다.

![10월 6일 작업 흐름](./images/day-1006-timeline.svg '오전 세 시간 동안 메뉴 막대, 밤에 정리 하나')

## 앱마다 다른 메뉴

전날 메뉴 막대의 파일·보기·윈도우·도움말이 열리게만 해 두었다. 이날 그 안을 앱마다 채웠다. 메모·Safari·Finder·음악이 먼저 자기 메뉴를 등록하고([#111](https://github.com/hyeoniverse/MacFolio/pull/111)), 메일·터미널·시스템 설정·iframe 앱(프로젝트 앱, API 문서)이 뒤따랐다([#113](https://github.com/hyeoniverse/MacFolio/pull/113)).

![지금의 메뉴 막대 메뉴](./images/day-1006-menu.jpg '메모 앞에서 메뉴 막대의 메뉴를 연 지금 모습')

그 전에 작은 버그 두 개를 고쳤다. 메모 글 안의 다른 글 링크는 새 탭이 아니라 사이트 안에서 열리고([#109](https://github.com/hyeoniverse/MacFolio/pull/109), [앱 안의 화면에 주소 붙이기](/memo/app-links)), 메뉴 막대를 눌러도 지금 앱이 Finder로 바뀌지 않는다([#110](https://github.com/hyeoniverse/MacFolio/pull/110), [메뉴 막대의 앱 이름이 맨 앞 창을 따른다](/memo/menu-bar-app-name)).

## 단축키는 ⌘ 대신 ⌥

macOS 앱은 ⌘N·⌘T·⌘W를 쓰지만, 브라우저 안의 페이지는 이 키를 받지 못한다. 브라우저가 먼저 새 창·새 탭·탭 닫기를 해 버린다. 페이지에서 이 동작을 막을 방법도 없다. 그래서 같은 글자에 ⌥를 붙였다([#112](https://github.com/hyeoniverse/MacFolio/pull/112)).

| 키               | 하는 일                                    |
| ---------------- | ------------------------------------------ |
| ⌥N               | 새로운 메모(관리자) · 새로운 Finder 윈도우 |
| ⌥T · ⌥W          | 새로운 탭 · 탭 닫기 (Safari)               |
| ⌥[ · ⌥] · ⌥↑     | 뒤로 · 앞으로 · 상위 폴더 (Finder)         |
| ⌥Space · ⌥← · ⌥→ | 재생/일시정지 · 이전 곡 · 다음 곡 (음악)   |
| ⌥W · ⌥M          | 윈도우 닫기 · 최소화 (공통)                |

도움말에 키보드 단축키 목록을 넣고 띄워 보니, Safari에 '탭 닫기 ⌥W'와 '윈도우 닫기 ⌥W'가 함께 있었다. 같은 키는 앞쪽 항목만 들어서, 윈도우 닫기는 단축키가 있다고 보이는데 실제로는 되지 않았다. macOS Safari처럼 앱이 ⌥W를 쓰면 공통 '윈도우 닫기'는 ⌥⇧W로 바꿨다. 목록을 띄우지 않았으면 몰랐을 것이다.

![지금의 키보드 단축키 목록](./images/day-1006-shortcuts.jpg '도움말 → 키보드 단축키의 지금 모습')

## 맨 앞 앱의 메뉴만

밤에는 메뉴 구성을 정리했다. 윈도우 메뉴에 다른 앱 목록이, 보기 메뉴에 다크 모드가 들어 있었다. macOS에서 메뉴 막대는 맨 앞 앱의 것이다. 이것들을 빼고, 굵은 앱 이름을 앱 메뉴(가리기, 종료)로 만들고, Safari에는 책갈피, 메일에는 사서함 메뉴를 넣었다([#114](https://github.com/hyeoniverse/MacFolio/pull/114)). 이 이야기는 모두 [메뉴 막대의 파일·보기·윈도우가 실제로 열린다](/memo/menubar-menus)에 더했다.

![10월 6일 영역별 변경](./images/day-1006-areas.svg '데스크톱(메뉴 막대)과 E2E가 대부분')

![열흘 동안의 커밋과 E2E](./images/day-1006-days.svg '커밋 12개, E2E는 235개')

하루가 끝날 때 브라우저 E2E는 235개, 단위 시험은 311개였다. API는 바꾸지 않았다.

## 돌아보며

브라우저가 가로채는 키를 쓰지 않고 ⌥로 바꾼 것은 잘한 결정이다. 화면에 보이는 단축키와 실제로 동작하는 단축키가 항상 같다. 겹친 ⌥W는 단축키 목록을 화면에 띄워서 찾았다.

아쉬운 점은 메뉴 막대 작업을 여섯 번에 나눠 했다는 것이다. 전날 저녁, 이날 오전, 이날 밤, 다음 날 새벽 두 번, 다음 날 밤. "그 앱의 것만"이라는 원칙을 처음에 정했으면 정리하는 커밋이 따로 필요 없었다. 다음 날 새벽에는 main에서만 실패하는 메뉴 시험까지 나왔다([10월 7일](/memo/day-1007)).

이 작업은 이슈 [#96](https://github.com/hyeoniverse/MacFolio/issues/96)(메뉴 막대를 맨 앞 앱에 맞게)이고, 다음 날 [#113](https://github.com/hyeoniverse/MacFolio/pull/113)이 머지되면서 닫혔다. 전날 저녁의 자동 배포를 서버에서 한 번에 설정하게 한 문서([#108](https://github.com/hyeoniverse/MacFolio/pull/108))도 이날 아침 머지했다.
