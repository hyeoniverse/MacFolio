## 글꼴: OS와 관계없이 같은 글꼴로

### 교체 ([#384](https://github.com/hyeoniverse/MacFolio/pull/384))

같은 화면이 macOS·iOS와 Windows·Android·Linux에서 다른 글꼴로 그려졌다. 글꼴 지정이 `-apple-system`으로 시작해 Apple 기기는 시스템 글꼴(SF Pro, Apple SD Gothic Neo)을, 그 밖의 기기는 `public/fonts/`에서 배포하던 Apple SD Gothic Neo **Regular 한 굵기**를 받았다. 굵은 글씨 약 500곳은 Apple 기기가 아니면 브라우저가 합성한 굵기였다. 그리고 Apple 글꼴은 웹 배포 허락이 없다.

![고치기 전: macOS와 Linux](./images/open-fonts-before-os.jpg '고치기 전. 같은 빌드를 macOS Chromium과 Linux Chromium에서 열었다. 영문·숫자·고정폭·굵은 글씨가 다르다')

![고친 뒤: macOS와 Linux](./images/open-fonts-after-os.jpg '고친 뒤. 두 OS가 같은 글꼴을 받는다')

| 용도       | 고치기 전 (Apple 기기 / 그 밖)                 | 고친 뒤 (모두 SIL OFL 1.1)                                 |
| ---------- | ---------------------------------------------- | ---------------------------------------------------------- |
| 본문       | SF Pro + Apple SD Gothic Neo / Regular 웹 글꼴 | Pretendard Variable (굵기 45~920)                          |
| 고정폭     | SF Mono / Consolas·DejaVu Sans Mono 등         | JetBrains Mono Variable                                    |
| 명조       | AppleMyungjo / 기기마다 다름                   | Noto Serif KR Variable                                     |
| PDF 이력서 | Apple SD Gothic Neo                            | Pretendard OTF (react-pdf가 woff를 풀려면 `Buffer`가 필요) |
| 공유 카드  | Apple SD Gothic Neo                            | Pretendard woff (satori는 woff2를 읽지 못함)               |

CSS 34개 파일의 글꼴 지정을 `src/styles/fonts.css`의 변수 셋(`--font-sans`·`--font-mono`·`--font-serif`)으로 바꾸고, Apple 글꼴 파일 11개를 저장소에서 삭제했다. 입력 칸·버튼은 브라우저 기본값이 시스템 글꼴이라 `reset` 층에 `font-family: inherit`를 넣었다.

<details>
<summary>Pretendard 동적 서브셋(92조각)을 쓰지 않은 이유</summary>

처음에는 Pretendard가 제공하는 동적 서브셋을 시도했다. 메모 앱 첫 화면은 글 234편의 제목·요약을 한 화면에 그려 92조각 거의 전부(약 1.7MB)를 받았고, `@font-face` CSS 14.6KB 때문에 첫 방문 번들이 271.4KB로 상한 265KB를 넘었다. `scripts/subset-font.py`로 core(영문·문장 부호·자모·KS X 1001 2,350자) 하나와 나머지 한글 ext 8조각으로 직접 나눴다. 저장소 전체에서 KS X 1001 밖 한글은 '긂·똠·햏' 세 글자뿐이었다.

### 전송량 줄이기와 예산 ([#385](https://github.com/hyeoniverse/MacFolio/pull/385))

같은 글꼴을 그리는 대가로 데스크톱 첫 화면의 글꼴 전송량이 397KB(Chromium)에서 1,187KB로 늘었다. 교체 PR 본문에 이 수치를 기록했고, 같은 날 밤 후속 PR로 줄였다.

| 화면 (`vite preview`, 글꼴 응답 합계) |          교체 전 | #384 직후 | #385 적용 |
| ------------------------------------- | ---------------: | --------: | --------: |
| 데스크톱 첫 화면                      | 397KB (Chromium) |   1,187KB | **568KB** |
| 휴대폰 홈 (iPhone 15, WebKit)         |   136KB (WebKit) |     591KB | **382KB** |

1. **한글 명조는 Safari 창에 사용자 입력이 있는 시각에 받는다.** 바탕화면은 Safari 창이 처음부터 열려 있어 `ProjectPage.css`의 정적 `@import`로 첫 방문자 모두가 명조 한글 약 440KB를 받았다. 창 안을 누르거나 스크롤하는 등 사용자 입력이 있으면 `import()`로 불러온다. 그 전에는 같은 Pretendard 파일에 `size-adjust: 111.8%`(한글 폭 Noto Serif KR 0.966em ÷ Pretendard 0.864em)를 준 대체 글꼴로 그려, 명조로 바뀌는 시각에 제목 상자가 571×87px로 같다.
2. **Pretendard core를 이 사이트가 쓰는 글자로 줄였다.** 저장소의 글·화면 문구에 나오는 KS X 1001 1,093자만 core(456KB → 246KB)에 남기고, 나머지 1,257자는 `ksx` 조각(253KB)으로 분리했다.
3. **첫 화면 글꼴 예산.** 글꼴은 그린 글자에 따라 받아 빌드 결과만으로 크기를 알 수 없다. 그래서 `budget.mjs`가 아니라 E2E에 실제 브라우저 시험 3개를 넣었다: 데스크톱 첫 화면 600KB, 휴대폰 홈 410KB 상한, 데스크톱 첫 화면에 명조 한글 조각이 없는지.

![명조를 받기 전과 후](./images/open-fonts-serif-swap.jpg '첫 화면의 Safari 창. 왼쪽은 명조를 받기 전(폭을 맞춘 Pretendard), 오른쪽은 창을 누른 뒤의 Noto Serif KR. 제목의 줄바꿈과 높이가 같다')

대체 글꼴의 처음 이름 `'Serif Fallback'`은 동작하지 않았다. CSS 압축이 `font-family` 값의 따옴표를 제거하자 첫 낱말이 일반 글꼴 키워드 `serif`로 해석되어 규칙 전체가 무효가 되었다. 이름을 `'Pretendard Serif Fallback'`으로 바꿨다. 과정 전체는 [OS마다 다르던 글꼴을 하나로](/memo/open-fonts)에 적었다.

## 저장소 글의 폴더 변경과 서버의 정리 내용 ([#389](https://github.com/hyeoniverse/MacFolio/pull/389))

블로그 폴더 구성을 바꾸면서 저장소 글의 `category`를 고쳤다. 화면은 저장소 `category`에 관리자가 메모 앱에서 바꾼 폴더 이름·글 지정(서버의 `GET /memo/organization`)을 차례로 적용하므로, 배포 API를 조회만 해서 영향을 확인했다.

| 항목                     | 값                                     | 영향                                                                               |
| ------------------------ | -------------------------------------- | ---------------------------------------------------------------------------------- |
| `moves` (폴더 이름 변경) | `개발기` → `개발 기록`                 | 저장소 이름을 `개발 기록`으로 바꿔도 표시는 같다                                   |
| `posts` (글별 폴더 지정) | `notes-polish`가 `…/프론트엔드`로 지정 | 그대로 두면 없어진 `프론트엔드` 폴더가 글 하나로 다시 생긴다. 관리자 화면에서 이동 |
| `order` (폴더 순서)      | 비어 있음                              | 가나다순                                                                           |

글 주소(slug)는 파일 이름이라 `category`를 바꿔도 링크는 깨지지 않는다. 폴더 이름에는 경로 구분자 `/`를 쓸 수 없어(`CI/CD`는 4단이 되어 `MAX_FOLDER_DEPTH` 3을 넘는다) `CI·CD`처럼 가운뎃점을 썼다.

#389는 마지막 삭제 커밋을 머지 뒤에 push해 main에 반영되지 않았다. 다음 날 #392로 같은 변경을 다시 반영했다.

## 의존성: 편집기를 막은 패치 버전 ([#382](https://github.com/hyeoniverse/MacFolio/pull/382), [#383](https://github.com/hyeoniverse/MacFolio/pull/383))

오전에 Dependabot이 PR 두 개를 올렸다. #382(`docker/login-action` 4.6.0 → 4.7.0)는 그대로 머지했고, #383(15개 패키지 업데이트)은 메모 편집기 E2E가 실패했다.

| 항목        | 내용                                                                                                                                                                                     |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 원인 버전   | `remark-cjk-friendly` 2.3.2 → 2.3.3 (함께 올라온 `mdast-util-to-markdown-cjk-friendly` 1.0.1)                                                                                            |
| 증상        | Milkdown 편집기가 글을 Markdown으로 직렬화하는 `containerPhrasing`에서 강조 처리기가 `TypeError: Cannot read properties of undefined (reading 'length')`. 관리자 편집 화면이 열리지 않음 |
| 영향 범위   | 방문자 읽기 화면은 Markdown을 직렬화하지 않아 영향 없음                                                                                                                                  |
| 배제한 원인 | `mdast-util-to-markdown`이 2.1.3·2.2.0 두 사본으로 나뉜 것. 2.2.0 하나로 맞춰도 같은 오류                                                                                                |
| 수정        | `package.json`에서 2.3.2로 고정, `dependabot.yml`에서 2.3.3 제외. 나머지 14개 업데이트는 반영                                                                                            |

`dependabot.yml`의 제외 항목에는 해제 조건을 주석으로 남겼다: 다음 버전이 나오면 편집기 E2E로 확인한 뒤 이 줄을 삭제한다.

## 돌아보며

**화면을 통일한 대가를 수치로 기록해, 같은 날 줄일 수 있었다.** #384 본문에 화면별 글꼴 전송량(397KB → 1,187KB)을 기록했기 때문에, 후속 PR의 목표와 결과(568KB)를 같은 측정 방법으로 비교할 수 있었다. 번들 예산(`budget.mjs`)은 빌드 결과만 검사해 글꼴 전송량 증가를 잡지 못했다. 그린 글자에 따라 달라지는 자원은 실제 브라우저 시험으로 예산을 걸어야 한다.

**PR에 커밋을 더하기 전에 머지 여부를 확인한다.** #389의 삭제 커밋은 머지 뒤에 올라가 main에 빠졌고, 다음 날 별도 PR이 필요했다. push 직전에 `gh pr view --json state`로 PR 상태를 확인하는 단계를 넣는다.

**패치 버전 하나가 관리자 편집 화면을 막았다.** 읽기 화면만 시험했다면 배포 후에야 발견했을 오류를 편집기 E2E가 잡았다. 고정한 버전은 `dependabot.yml`에 해제 조건과 함께 기록해, 다음 버전에서 다시 확인하도록 했다.
