메뉴 막대의 `File Edit View Go Window Help`는 글자였다. 눌러도 아무 일이 없었다. 이번에 진짜 메뉴로 바꿨다 (#96의 첫 단계).

![메모를 쓰는 중에 연 윈도우 메뉴](./images/menubar-window.jpg '열린 창 목록에서 지금 쓰는 창(메모)에 체크')

## 무엇이 들어 있나

| 메뉴   | 항목                                                                         |
| ------ | ---------------------------------------------------------------------------- |
| 파일   | 링크 복사(메모의 글처럼 주소가 있는 화면), 윈도우 닫기                       |
| 보기   | 다크 모드 (지금 상태에 체크)                                                 |
| 윈도우 | 최소화, 확대/축소, 열린 창 목록 (지금 쓰는 창에 체크, 고르면 그 창이 앞으로) |
| 도움말 | API 문서, GitHub 저장소, 문제 알리기                                         |

제목은 앱 이름(메모, 음악…)처럼 macOS 한국어판을 따라 **파일·편집·보기·이동·윈도우·도움말**로 바꿨다. 항목이 하나도 없는 제목은 감춘다. macOS도 앱마다 메뉴 막대의 제목이 다르다. 지금은 편집·이동을 쓰는 앱이 없어서 `파일 보기 윈도우 도움말`만 보이고, 창 밖을 눌러 Finder가 되면 창이 없으니 `보기 윈도우 도움말`만 남는다.

## 앱 안의 동작을 바깥에서 부르기

어려운 점은 메뉴 막대가 앱 바깥에 있다는 것이다. 메모의 "새 글", Safari의 "새 탭" 같은 동작은 거의 다 앱 컴포넌트 안의 상태에 있다. 상태를 모두 바깥으로 꺼내면 앱마다 크게 고쳐야 한다.

그래서 **앱이 열려 있는 동안 자기 메뉴를 등록**하게 했다.

```ts
useAppMenus('memo', [
	{ title: '파일', items: [{ label: '새로운 메모', onSelect: startNewDraft }] },
	{ title: '보기', items: [{ label: '갤러리로 보기', checked: view === 'gallery', onSelect: … }] },
]);
```

등록한 항목은 앱 안의 함수와 상태를 그대로 들고 있다. 메뉴 막대는 지금 쓰는 앱이 등록한 메뉴와 공통 메뉴를 합쳐 그린다. 합치는 일은 순수 함수(`buildMenuBar`) 하나가 한다. 앱의 항목을 같은 제목의 공통 항목 위에 두고, 앱만의 메뉴(음악의 '제어' 같은)는 이동 뒤·윈도우 앞에 두고, 빈 제목은 뺀다. 이 규칙은 단위 테스트로 확인한다. 앱마다의 메뉴는 다음 단계에서 붙인다.

## 창 닫기는 창이 한다

'윈도우 닫기'·'최소화'는 메뉴 막대가 `closeApp`을 바로 부르면 된다. 그런데 그러면 창이 닫히는 애니메이션(Dock으로 빨려 들어가는)이 없다. 애니메이션은 창 컴포넌트 안에 있다.

메뉴는 **명령만 보내고**, 창이 자기 앱으로 온 명령을 받아 신호등 단추와 같은 함수로 처리한다. 다른 앱에 "이 글을 열어 줘"를 보낼 때 쓰던 방식(`openRequest`)과 같은 모양이다. 나중에 단축키(⌥W 같은)도 같은 명령을 보내면 된다.

## 메뉴 제목을 누르면 Finder가 되던 문제

바로 전에 "창 밖(바탕화면·메뉴 막대·Dock)을 누르면 메뉴 막대 이름이 Finder가 된다"를 만들었다. 메뉴 제목도 메뉴 막대 안이라, 메모를 쓰다가 '파일'을 누르면 먼저 Finder가 되고 Finder의 메뉴가 열렸다. 메모의 파일 메뉴를 열 방법이 없었다.

macOS에서도 메뉴 제목과 그 메뉴는 지금 앱의 것이다. 메뉴 제목 묶음과 거기서 연 메뉴에 `data-app-menu`를 붙이고, 바탕화면 판은 이것을 누른 경우만 건너뛰게 했다. (그 뒤 메뉴 막대 전체로 넓혔다: Apple 메뉴, 서버 상태, 음량, 빈 곳을 눌러도 지금 앱이 그대로다. [메뉴 막대의 앱 이름](/memo/menu-bar-app-name) 참고)

## macOS처럼 옮겨 다니기

- 메뉴가 열린 채 다른 제목에 마우스를 올리면 그 메뉴로 넘어간다
- ←·→로 옆 메뉴, ↓로 첫 항목, Esc로 닫기

화면 테스트를 쓰다가 ←·→가 마우스로 연 메뉴에서는 듣지 않는 것을 알았다. 키 입력은 초점이 있는 곳으로 가는데, 마우스로 열면 초점이 메뉴 밖에 남아 있었다. 메뉴 막대 메뉴는 열릴 때 메뉴 자체가 초점을 받게 했다(항목은 칠하지 않는다).

## 앱마다 메뉴

이어서 앱 넷이 자기 메뉴를 등록했다. 앱 안에 이미 있던 함수를 그대로 메뉴 항목으로 내놓았을 뿐, 상태를 바깥으로 꺼낸 앱은 없다.

| 앱     | 메뉴                                                                                            |
| ------ | ----------------------------------------------------------------------------------------------- |
| 메모   | 파일: 새로운 메모(관리자만) · 편집: 찾기… · 보기: 목록/갤러리, 사이드바, 정렬과 그룹화          |
| Safari | 파일: 새로운 탭, 탭 닫기 · 이동: 이전 탭, 다음 탭 (끝에서는 비활성)                             |
| Finder | 파일: 새로운 Finder 윈도우 · 보기: 아이콘/목록 · 이동: 뒤로, 앞으로, 상위 폴더, 즐겨찾기 위치들 |
| 음악   | 제어(앱만의 메뉴): 재생/일시정지, 다음·이전 곡, 셔플, 반복                                      |

- 메모의 정렬 항목은 도구 막대의 '정렬과 그룹화' 메뉴가 쓰던 목록(`sortMenuItems`)을 그대로 붙였다. 같은 체크 상태가 두 곳에 보인다
- 찾기는 글을 열었을 때만 된다. 열린 글이 없으면 비활성으로 두고 이유를 마우스를 올리면 보여 준다
- 음악의 '제어'는 공통 제목이 아니라서 '이동' 뒤, '윈도우' 앞에 온다 (macOS 음악 앱도 그 자리에 '제어'가 있다)
- Finder는 바탕화면을 눌러 Finder가 되었을 때도 메뉴가 보인다. 그때는 Finder 창이 닫혀 있을 수 있어서, 항목을 고르면 먼저 Finder 창을 연 뒤에 그 일을 한다. 바탕화면에서 이동 → 블로그를 고르면 Finder가 블로그 폴더로 열린다

처음 앞에 떠 있는 Safari에 '이동' 메뉴가 생기면서, 메뉴 막대 첫 화면의 제목이 `파일 보기 이동 윈도우 도움말`이 되었다. 제목이 앱마다 달라지는 것이 이번에야 눈에 보였다.

## 단축키

메뉴 항목 오른쪽에 단축키를 보여 주고, 누르면 그 항목을 실행한다. 지금 쓰는 앱의 메뉴(와 공통 메뉴)에 있는 항목만 듣는다. Finder가 앞이면 Safari의 '새로운 탭'은 눌러도 아무 일이 없다.

**⌘ 대신 ⌥.** macOS 앱은 ⌘N·⌘T·⌘W를 쓰지만, 브라우저 안의 페이지는 이 키를 받지 못한다. 브라우저가 먼저 새 창·새 탭·탭 닫기를 해 버린다(사이트가 탭 닫기를 막지 못하게 하는 장치라 우회할 수 없다). 그래서 같은 글자에 ⌥를 붙였다.

| 단축키           | 동작                                                    |
| ---------------- | ------------------------------------------------------- |
| ⌥N               | 새로운 메모(관리자) · 새로운 Finder 윈도우              |
| ⌥T · ⌥W          | 새로운 탭 · 탭 닫기 (Safari)                            |
| ⌥⇧[ · ⌥⇧]        | 이전 탭 · 다음 탭 (Safari)                              |
| ⌥[ · ⌥] · ⌥↑     | 뒤로 · 앞으로 · 상위 폴더 (Finder)                      |
| ⌥1 · ⌥2          | 목록/아이콘 · 갤러리/목록 보기 (메모 · Finder)          |
| ⌥Space · ⌥← · ⌥→ | 재생/일시정지 · 이전 곡 · 다음 곡 (음악)                |
| ⌥W · ⌥M          | 윈도우 닫기 · 최소화 (공통)                             |
| ⌘F               | 열린 글 안에서 찾기 (메모, 브라우저의 페이지 찾기 대신) |

몇 가지를 정했다.

- **키는 `code`로 본다.** 맥에서 ⌥를 누른 채 N을 치면 `event.key`가 `n`이 아니라 `˜` 같은 특수 문자가 된다. 자판의 자리(`KeyN`)로 맞춘다
- **⌘·Ctrl을 나눈다.** 단축키의 '⌘'는 맥에서는 ⌘(metaKey), Windows·Linux에서는 Ctrl이다. 표시도 맥은 `⌥⇧⌘N` 기호, 그 밖은 `Ctrl+Alt+N`이다
- **같은 키는 앞쪽 메뉴가 먼저.** Safari의 '탭 닫기'(⌥W)와 공통 '윈도우 닫기'(⌥W)가 겹친다. 앱 항목이 공통 항목보다 앞에 있으니 Safari에서는 탭이 닫힌다. macOS Safari에서 ⌘W가 탭을 닫는 것과 같다
- **글자를 쓰는 중에는 ⌥만 쓰는 단축키를 듣지 않는다.** 맥에서 ⌥는 특수 문자를 입력하는 데 쓴다. 찾기 칸에 글자를 쓰다 ⌥2를 눌러도 갤러리로 바뀌지 않는다. ⌘F처럼 ⌘가 들어간 것은 입력 중에도 된다

메모 앱은 원래 ⌘F를 자기 안에서 따로 듣고 있었다. 이제 메뉴의 '찾기…'에 단축키를 붙였으니 그 코드를 지웠다. 같은 키를 두 곳에서 들으면 어느 쪽이 먼저 받을지 알 수 없다.
