음악 앱에서 버그 세 가지를 고쳤다. 셋 다 화면만 보면 이상한데, 원인은 한 줄씩이었다.

## 배경 음악이 나오는데 음악 앱은 꺼져 있다

데스크톱은 로딩 화면을 넘기면 `startMusic` 이벤트로 배경 음악을 튼다. 그런데 음악 앱은 `runningAtStart`가 없어 Dock에 켜짐 표시가 없었다. macOS에서 소리를 내는 앱은 실행 중이다.

처음에는 Safari처럼 `runningAtStart: true`를 주었더니 음악 창이 Safari 위로 열려, 처음 화면과 메뉴 막대의 앱 이름이 모두 바뀌었다. 그래서 `runningAtStart`에 `'minimized'`를 더했다. desktop-core의 `initialWindows`가 이 앱을 켜 두되 창은 내려 둔다. Dock에는 켜짐 표시가 있고, 맨 앞은 그대로 Safari, Dock을 누르면 음악 창이 올라온다. 모바일은 배경 음악을 틀지 않으므로 그대로 꺼진 채 시작한다.

## 셔플을 누르면 재생 막대에 표지가 쌓인다

재생 막대의 '지금 곡' 버튼 안에 표지 `img`와 제목 `span`이 있고, 곡이 바뀔 때 새로 나타나게 둘 다 `key={track.id}`를 주었다. 형제끼리 key가 같으면 React가 어느 요소를 지울지 맞추지 못해, 곡이 바뀔 때마다 옛 요소가 남는다. 셔플 버튼은 아무 곡이나 고르므로 누를 때마다 표지와 제목이 하나씩 쌓였다.

key에 자리 이름을 붙여 `art-<곡>`, `title-<곡>`처럼 형제끼리 다르게 했다. 휴대폰의 지금 재생 중 시트도 표지와 곡 정보가 같은 key를 쓰고 있어 함께 고쳤다.

## 지금 재생 중을 열면 시트가 끝없이 내려간다

`Sheet`는 닫힐 때 복사본이 아래로 내려가며 사라지게, ref 함수에서 `useExitMotion`의 정리 함수를 돌려준다. 그런데 이 ref 함수를 그릴 때마다 새로 만들었다. React 19는 ref 함수가 바뀌면 옛 ref를 정리하고 새 ref를 거는데, 이때 정리 함수가 사라지는 움직임을 돌린다. 재생 중에는 재생 시간이 바뀔 때마다 시트가 다시 그려지므로, 열려 있는 시트 위로 복사본이 끝없이 내려갔다.

ref 함수를 `useCallback`으로 한 번만 만들어, 시트가 정말 빠질 때만 움직임이 돈다.

## 시험

- desktop-core 단위 시험: `runningAtStart`가 `'minimized'`면 켜 두되 창은 내려 둔다.
- E2E: 처음부터 Dock에 음악 켜짐 표시가 있고 창은 내려가 있다. 셔플을 다섯 번 눌러도 재생 막대에 표지와 제목이 하나씩이다. 지금 재생 중을 열고 다시 그려도 사라지는 움직임의 복사본이 하나도 생기지 않는다.

마지막 시험은 처음에 고치기 전에도 통과했다. Playwright 설정이 움직임 줄이기를 켜 두어 `playExit`가 아예 돌지 않았기 때문이다. 그 시험만 움직임 줄이기를 끄고, 복사본은 금방 지워지므로 `MutationObserver`로 생기는 순간을 세게 했다.
