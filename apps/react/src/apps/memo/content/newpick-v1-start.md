뉴픽(NewPick)은 2024년 12월 26일부터 2025년 2월 6일까지 프로그래머스 데브코스에서 5명(프론트엔드 2, 백엔드 3)이 만든 뉴스레터 서비스다. 이 글은 팀 프로젝트 시기의 첫 글로, 주제를 정하고 기술 스택을 바꾸기까지의 첫 2주를 정리한다. 당시 노션 회의록·자료실과 레포의 커밋 기록을 다시 읽으며 썼다. 1년 8개월 뒤 혼자 다시 연 이야기는 [v2 시리즈](/memo/newpick-v2-start)에 있다.

## 첫 회의: 아이디어 다섯 개

12월 26일 첫 회의에서 다섯 명이 각자 아이디어를 하나씩 가져왔다.

| 아이디어                                  | 내용                                                             |
| ----------------------------------------- | ---------------------------------------------------------------- |
| 창작자를 위한 플랫폼                      | 감정 분석, 역사적 인물과 대화하는 AI                             |
| **AI를 활용한 뉴스레터 생성기** (내 제안) | 관심 분야의 뉴스를 크롤링해 AI로 요약하고 주기적으로 메일로 보냄 |
| AI 여행 플래너                            | 선호도 설문으로 일정표를 만들고 드래그로 수정                    |
| AI 건강검진                               | 증상을 입력하면 유행 중인 질병과 관련 질병을 설명                |
| 운동 루틴·노트북 추천 등                  | 사용자 맞춤 추천 서비스 여러 개                                  |

뉴스레터 생성기가 선택됐고, 이름은 News와 Pick을 합친 "뉴픽"이 됐다. 회의록에 선택 이유는 남아 있지 않다. 돌아보면 크롤링·AI 요약·메일 발송·스케줄러로 백엔드 세 명의 일이 나뉘고, 프론트에는 관심사 설정·미리보기·목록 화면이 있어 다섯 명이 동시에 일하기 좋은 주제였다.

## 첫 기획안과 실제로 만든 것

첫 기획안은 "기간 1개월, 4주 일정"이었다. 실제로 만든 것과 비교하면 이렇다.

| 항목      | 첫 기획안 (12/26)                                          | 실제 (2/6)                                                        |
| --------- | ---------------------------------------------------------- | ----------------------------------------------------------------- |
| 프론트    | React + TypeScript, styled-components 또는 Chakra UI       | **Next.js** + TypeScript, styled-components, Zustand, React Query |
| 백엔드    | Node.js(Express), 크롤링은 Python(BeautifulSoup, Selenium) | **NestJS**, 크롤링은 puppeteer                                    |
| DB        | "???"                                                      | MySQL(GCP) + MongoDB Atlas                                        |
| AI        | OpenAI API 또는 Hugging Face                               | OpenAI `gpt-4o-mini`                                              |
| 배포      | "???"                                                      | 프론트 Vercel, 백엔드 AWS EC2 + Nginx                             |
| 발송 주기 | 일간·주간·월간                                             | 매일 아침 (관리자가 주기 변경)                                    |
| 역할      | "AI/크롤링 담당 1명 / ??"                                  | 백엔드 세 명이 크롤링·AI·메일·인증을 나눔                         |

물음표로 남겨 둔 칸이 많았다. 처음부터 정답을 정하기보다 첫 주에 스택을 정하기로 했고, 일정표에도 "기술 스택 결정 및 역할 분담"을 1주 차 일로 넣었다.

## React? Next.js? Vue?

프론트는 내가 12월 31일에 React + TypeScript + Vite로 초기 설정을 만들었다. 그런데 첫 멘토링에서 멘토가 Next.js 이야기를 꺼냈고, 1월 3일 자료실에 "React? Next.js? Vue.js?"라는 조사 문서를 만들었다.

조사 방법은 단순했다. 가고 싶은 회사들의 프론트엔드 채용 공고를 모아 기술 스택을 표로 정리했다.

| 회사           | 코어                                  | 상태 관리                   |
| -------------- | ------------------------------------- | --------------------------- |
| 네이버         | JavaScript/TypeScript, React          | Redux                       |
| 우아한형제들   | React, Vue.js, TypeScript             | Jotai, Zustand, React Query |
| 비바리퍼블리카 | React, TypeScript, **Next.js**        | React Query, Jotai          |
| 카카오         | JavaScript, TypeScript, Preact, React |                             |
| 당근마켓       | React, TypeScript, ReScript           | Redux, Recoil               |

잡코리아 공고 수로는 React가 가장 많고 Next.js가 가장 적었다. 그래도 Next.js를 고른 이유를 문서에 이렇게 적었다.

- React 공식 문서가 새 프로젝트에 Next.js 같은 프레임워크를 권장한다.
- Next.js 공고는 적어 보여도, React 공고의 우대 사항에 들어 있는 경우가 많다.
- 뉴스레터는 검색에 노출될수록 좋은 서비스라 SSR이 의미가 있다.

1월 6~7일, 팀원이 Vite 설정을 Next.js(App Router)로 옮겼다(`refactor: React.js > Next.js로 변경`). 레포를 만든 지 열이틀 만의 전환이었다. 기능 개발 전이라 비용이 거의 없었다.

## 협업 방식

| 항목   | 방식                                                               |
| ------ | ------------------------------------------------------------------ |
| 회의   | 매일 오전 11시 데일리 스크럼, 주 1회 팀 회의, 수·토 멘토링         |
| 문서   | 노션: 회의록, 자료실(기획안·컨벤션·참고 자료), 트러블슈팅 DB, 칸반 |
| 코드   | GitHub 이슈·PR 템플릿, 브랜치·커밋 컨벤션, front·back 레포 분리    |
| 디자인 | Figma 와이어프레임 (프론트 팀원이 UI 디자인 담당)                  |
| 소통   | Slack, 카카오톡, Zep                                               |

트러블슈팅 DB에는 6주 동안 28건이 쌓였다(프론트 12, 백엔드 16). 프론트 12건 중 절반 가까이가 Next.js의 서버·클라이언트 렌더링 차이에서 나온 문제였다. 그 이야기는 [다음 글](/memo/newpick-v1-nextjs)에 있다.

## 남은 것·배운 것

- 스택을 첫 주에 정하기로 하고 물음표를 남겨 둔 것이 결과적으로 맞았다. 백엔드도 Express와 Python 대신 NestJS 하나로 정리됐다.
- 기술 선택을 채용 공고로 조사한 방식은 지금 보면 얕다. 프로젝트에 필요한 것(SEO, 서버에서 읽는 로그인 쿠키)보다 "쓰는 회사가 있는가"를 먼저 봤다. 그 결과 Next.js의 서버 렌더링을 제대로 이해하지 못한 채 시작했고, 그 비용은 마감 주에 한꺼번에 나왔다.
- 일정표의 "4주 차: 테스트"는 지켜지지 않았다. 마감까지 프론트 테스트는 0개, 백엔드는 한 번도 통과하지 않은 스캐폴드 테스트뿐이었고, v2에서 [기준선을 잴 때](/memo/newpick-v2-start) 그대로 숫자로 남았다.
