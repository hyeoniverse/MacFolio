## Safari를 포트폴리오로

Safari를 프로젝트 포트폴리오로 바꿨다. 프로젝트 목록을 GitHub 고정 저장소와 일치시키고, 프로젝트마다 탭이 하나씩 열리게 하고, 소개 페이지는 Apple 제품 페이지와 같은 구성으로 작성했다. 새싹 농장은 게임을 창 안에서 바로 실행하는 앱으로 추가했다([Unity WebGL 게임을 창 안에 넣기](/memo/game-in-iframe)).

![지금의 Safari](./images/day-0929-safari.jpg '프로젝트마다 탭이 열린 Safari의 현재 모습. 페이지 내용은 10월 4일에 대부분 재작성했다')

전날 만든 휴대폰 셸도 이날 머지했고([#33](https://github.com/hyeoniverse/MacFolio/pull/33)), 그동안 미뤄 둔 글 네 편을 한 번에 게시했다.

필수 항목(제목·날짜·폴더·본문)은 세 계층에서 검증한다.

| 계층 | 검증 방법              | 막는 경우               |
| ---- | ---------------------- | ----------------------- |
| 화면 | 저장 전 입력 검사      | 일반적인 입력 실수      |
| API  | 같은 규칙으로 400 응답 | 화면을 거치지 않은 요청 |
| DB   | CHECK 제약             | API를 거치지 않은 쓰기  |

API e2e는 GitHub만 가짜 응답으로 대체하고 실제 PostgreSQL에 연결해 실행한다. 관리자가 아닌 계정이 차단되는지, 위조한 요청이 거절되는지까지 확인한다. 첫날 30개로 시작했다.

## 관리자 로그인: 아이디 대신 숫자 ID

로그인을 처음 구현하고 세 시간 만에 다시 수정했다. 관리자 여부를 GitHub **아이디(login)**로 판단하고 있었는데, 아이디는 변경할 수 있다. 관리자가 아이디를 변경하면 이전 아이디를 다른 사람이 등록할 수 있고, 그 사람이 로그인하면 관리자로 인식된다.

| 기준             | 변경 가능 | 위험                                           |
| ---------------- | --------- | ---------------------------------------------- |
| 아이디 (`login`) | 가능      | 이전 아이디를 등록한 다른 사람이 관리자가 된다 |
| 숫자 ID (`id`)   | 불가능    | 계정마다 고정                                  |

변경되지 않는 **숫자 ID**로 판단하도록 수정하고, 로그인 요청에는 IP별 횟수 제한을 적용했다.
