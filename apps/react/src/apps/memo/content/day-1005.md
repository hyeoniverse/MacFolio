이날 커밋은 77개다(글 작업 커밋 32개 포함). 전날의 프로젝트 페이지 PR([#88](https://github.com/hyeoniverse/MacFolio/pull/88))을 새벽 3시에 머지한 뒤로는 주로 서버 관련 작업을 했다. 이날의 작업은 대부분 하나의 질문에서 출발했다. **서버가 중단되면 이 기능도 함께 사라지는가?**

| 주제           | 이 질문에 대한 답                                    |
| -------------- | ---------------------------------------------------- |
| 서버 상태 메뉴 | 서버가 중단되면 메뉴 막대에서 바로 알 수 있게 한다   |
| API 문서       | 서버가 중단되어도 열리도록 문서를 사이트에 포함한다  |
| DB 백업        | 서버가 회수되어도 글이 남도록 서버 밖(R2)에 백업한다 |
| API 자동 배포  | 배포가 실패하면 이전 컨테이너로 되돌린다             |

이 글은 시간 순이 아니라 주제별로 정리했다.

## 메뉴 막대: 서버 상태와 실제 메뉴

### 서버 상태 표시

장식용이던 메뉴 막대의 Wi-Fi 아이콘 자리에 API 서버 상태를 표시했다. `/health`를 주기적으로 호출해 응답 시간과 DB 상태를 막대 개수로 표시하고, 누르면 상세 정보를 보여 준다([/health 응답 시간과 DB 상태를 막대 수로 환산하는 서버 상태 표시](/memo/server-status-wifi), [#90](https://github.com/hyeoniverse/MacFolio/pull/90)).

![현재의 서버 메뉴](./images/day-1005-server-menu.jpg '메뉴 막대 오른쪽 위의 서버 메뉴. 현재 화면이고, 시험용 가짜 API에 연결되어 있다')

메뉴를 만들면서 주변 요소의 문제도 발견해 함께 수정했다.

- 화면 끝에서 잘리는 메뉴
- 고정 위치로 표시되던 음량 창
- 높이가 서로 다른 재생·음량 버튼

### 앱 이름과 메뉴

- 메뉴 막대의 앱 이름이 맨 앞 창의 앱을 따르게 했다([#97](https://github.com/hyeoniverse/MacFolio/pull/97), [#101](https://github.com/hyeoniverse/MacFolio/pull/101), [글](/memo/menu-bar-app-name))
- 파일·보기·윈도우·도움말이 실제 메뉴로 열리게 했다([#105](https://github.com/hyeoniverse/MacFolio/pull/105), [글](/memo/menubar-menus)). 이 작업을 위해 이슈 [#96](https://github.com/hyeoniverse/MacFolio/issues/96)을 등록했다

## API 문서를 서버 없이 열기

### 첫 구현: 서버의 `/docs`를 iframe으로

서버 메뉴의 'API 문서 열기'는 처음에 서버의 `/docs`를 iframe으로 표시했다. 이를 위해 서버의 보안 헤더(`X-Frame-Options`, `frame-ancestors`)에 `/docs` 경로만 예외를 추가했다.

### 43분 뒤 방식 변경

이 문서는 **서버 상태 메뉴에서 여는 문서**다. 서버가 중단되면 iframe은 빈 창이 된다. 즉 서버에 문제가 있어 문서가 가장 필요한 시점에 문서를 볼 수 없다.

| 항목               | iframe 방식                     | 사이트 포함 방식                                                                     |
| ------------------ | ------------------------------- | ------------------------------------------------------------------------------------ |
| 문서 출처          | 서버의 `/docs`                  | API 코드에서 생성한 `openapi.json`을 사이트에 포함                                   |
| 렌더링             | 서버의 Swagger UI               | 사이트 안에서 Scalar로 렌더링                                                        |
| 서버 중단 시       | 빈 창                           | 정상 표시                                                                            |
| 보안 헤더          | `/docs`만 iframe 허용 예외 필요 | 예외 불필요 (예외를 원래대로 복원)                                                   |
| 문서와 코드의 일치 | 항상 일치                       | 단위 시험이 코드와 파일을 비교. API를 변경하고 파일을 다시 생성하지 않으면 CI가 실패 |

자세한 내용은 [Vite 두 번째 진입점과 iframe으로 Scalar API 문서 격리하기](/memo/api-docs-app)([#95](https://github.com/hyeoniverse/MacFolio/pull/95))에 정리했다.

![현재의 API 문서 앱](./images/day-1005-apidocs.jpg 'API 문서 앱의 현재 화면. 서버 없이도 열린다')

앱이 늘어나면서 Dock이 Launchpad와 겹치는 문제를 수정했고([글](/memo/dock-layout)), API 문서 아이콘은 6분 동안 세 번 변경했다가 처음 모양인 `{ API }`로 되돌렸다.

## DB 백업

### 왜 필요했나

블로그 글과 이미지가 모두 1GB 무료 서버의 DB에만 저장되어 있었다. 무료 서버가 회수되면 글도 함께 사라진다. 매일 DB를 덤프해 서버 밖(Cloudflare R2)에 보관하고, 복원까지 스크립트로 검증하게 했다([pg_dump와 R2로 하는 DB 백업과 복원 시험](/memo/db-backup), [#94](https://github.com/hyeoniverse/MacFolio/pull/94)).

### 서버 적용 절차

자세한 내용은 [ops/backup.sh](https://github.com/hyeoniverse/MacFolio/blob/main/ops/backup.sh), [ops/restore.sh](https://github.com/hyeoniverse/MacFolio/blob/main/ops/restore.sh), [docs/deployment.md](https://github.com/hyeoniverse/MacFolio/blob/main/docs/deployment.md)에 있고, R2 설정은 [Cloudflare R2 문서](https://developers.cloudflare.com/r2/)와 [rclone 설치 문서](https://rclone.org/install/)를 따랐다.

```bash
sudo -v ; curl https://rclone.org/install.sh | sudo bash   # apt 버전은 R2를 지원하지 않는다
rclone config                                            # R2 원격 저장소 생성
~/macfolio/ops/backup.sh                                 # 한 번 실행해 확인
rclone ls <원격>:<버킷>                                    # 업로드된 파일 확인
```

### 적용 중 발생한 문제

| 문제                                                                                             | 조치                                                      | PR                                                     |
| ------------------------------------------------------------------------------------------------ | --------------------------------------------------------- | ------------------------------------------------------ |
| R2 무료 한도를 초과할 수 있음                                                                    | 무료 한도에 도달하기 전에 백업을 중단                     | [#98](https://github.com/hyeoniverse/MacFolio/pull/98) |
| apt의 rclone 1.53은 R2 공급자를 지원하지 않음                                                    | 공식 설치 스크립트로 최신 버전 설치                       | -                                                      |
| 버킷 목록 조회(`rclone lsd r2:`)는 계정 전체 요청이라, 버킷 하나에만 권한이 있는 키로는 항상 403 | 연결 확인을 버킷 크기 조회와 시험 파일 업로드·삭제로 변경 | [#99](https://github.com/hyeoniverse/MacFolio/pull/99) |

서버에서 처음 실행한 백업 파일은 1,007KB였고, 복원한 DB의 글 수가 원본과 같았다([rclone과 UTC cron으로 R2에 DB 백업 걸기](/memo/r2-backup-setup)).

## 10월 2일 오류의 근본 원인

10월 2일에 "배포 직후 메모가 열리지 않던" 문제를 경고 대화상자로 처리하고 넘어갔다. 이날 근본 원인을 찾았다.

| 조건                                                             | 결과                                                 |
| ---------------------------------------------------------------- | ---------------------------------------------------- |
| 사이트가 존재하지 않는 주소에도 항상 `index.html`을 200으로 반환 | 없는 코드 파일 요청에도 HTML이 200으로 응답됨        |
| `/assets/*`에는 1년 동안 재요청하지 않는 `immutable` 캐시 헤더   | 위 HTML 응답이 그 코드 파일 이름으로 1년 동안 캐시됨 |

새벽 4시 반에 #90을 머지했는데 사이트에 반영되지 않은 일도 배포 과정을 다시 점검하는 계기가 되었다.

배포 중에 삭제된 이전 코드 파일 주소를 요청한 브라우저는 **그 파일 이름으로 HTML을 1년 동안 캐시**하게 된다. 존재하지 않는 파일 주소는 404를, 앱 주소만 첫 화면을 반환하도록 분리했다([not_found_handling 뒤 Worker 함수로 SPA 주소와 없는 자산의 404 나누기](/memo/asset-404), [#103](https://github.com/hyeoniverse/MacFolio/pull/103)).

## API 자동 배포

### 구조

main에서 API가 변경되면 GitHub Actions가 이미지를 빌드해 GHCR에 업로드하고, 서버는 다음 순서로 배포한다([command= 제한 SSH 키와 GHCR 이미지로 하는 API 자동 배포와 롤백](/memo/api-auto-deploy), [#104](https://github.com/hyeoniverse/MacFolio/pull/104)). 이슈 [#100](https://github.com/hyeoniverse/MacFolio/issues/100)의 작업이다.

```text
GitHub Actions: 이미지 빌드 → GHCR 업로드
서버:          DB 백업 → 컨테이너 교체 → 헬스 체크 → 실패 시 이전 이미지로 롤백
```

1GB 메모리 서버가 직접 이미지를 빌드하던 작업이 사라졌다.

### 적용 중 발생한 문제

실제 서버에 적용하면서 문제가 다섯 번 발생했다([자동 배포를 실제 서버에 걸기 - 막힌 곳 다섯](/memo/api-auto-deploy-setup)). 그중 하나는 첫 배포에서 바로 발생했다. 서버의 compose 파일은 이미지 태그(`API_TAG`)가 없으면 중단하도록 작성했는데, 첫 배포에는 태그가 아직 없어서 배포 전 백업 단계가 중단되었다([#107](https://github.com/hyeoniverse/MacFolio/pull/107)). 로컬 시험용 compose 파일에는 이 검사가 없어 시험에서 발견하지 못했다.

## 돌아보며

**"서버가 중단되면?"이라는 질문은 효과가 있었다.** API 문서, 백업, 자동 배포의 방식이 모두 이 질문으로 정해졌다. 아쉬운 점은 이 질문을 **구현한 뒤에** 했다는 것이다. iframe 방식은 서버 헤더에 예외까지 추가하고 43분 만에 되돌렸다. 구현 전에 확인했다면 헤더 예외는 만들 필요가 없었다.

**시험 환경과 운영 환경의 설정 파일이 달랐다.** `API_TAG` 검사가 서버의 compose 파일에만 있어서 로컬 시험에서 발견하지 못했다. 시험은 운영과 같은 설정 파일로 진행해야 한다.
