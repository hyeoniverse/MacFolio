전날의 프로젝트 페이지 PR([#88](https://github.com/hyeoniverse/MacFolio/pull/88))이 새벽 3시에 머지된 뒤로는 주로 서버 작업을 했다. 서버 상태 확인, API 문서, DB 백업, 배포 자동화다. 커밋 77개 중 32개가 글이었다.

돌아보면 이날 한 일은 거의 모두 같은 질문에서 나왔다. **서버가 꺼지면 이것도 같이 사라지는가?**

![10월 5일 작업 흐름](./images/day-1005-timeline.svg '새벽에는 HYEONIVERSE 마무리와 메뉴 막대·서버, 낮에는 백업, 저녁에는 자동 배포')

## 메뉴 막대에 서버 상태 표시

장식용이던 메뉴 막대의 Wi-Fi 아이콘 자리에 API 서버 상태를 띄웠다. `/health`를 주기적으로 불러 응답 시간과 DB 상태를 막대 수로 보여 주고, 누르면 자세히 나온다([메뉴 막대의 Wi-Fi 자리에 서버 상태 띄우기](/memo/server-status-wifi), [#90](https://github.com/hyeoniverse/MacFolio/pull/90)).

![지금의 서버 메뉴](./images/day-1005-server-menu.jpg '메뉴 막대 오른쪽 위의 서버 메뉴. 지금 모습이고, 시험용 가짜 API에 붙어 있다')

메뉴를 만들면서 주변 요소의 문제도 발견했다. 화면 끝에서 잘리는 메뉴, 고정 위치였던 음량 창, 높이가 다른 재생·음량 단추. 하나씩 고쳤다.

## API 문서를 서버 없이 보기

서버 메뉴의 'API 문서 열기'는 처음에 서버의 `/docs`를 iframe으로 띄웠다. 그러려고 서버의 보안 헤더(`X-Frame-Options`, `frame-ancestors`)에 `/docs`만 예외도 만들었다.

43분 뒤에 방법을 바꿨다. 이 문서는 **서버 상태 메뉴에서 여는 것**인데, 서버가 꺼지면 빈 창이 된다. 서버에 문제가 있을 때 정작 문서를 볼 수 없다. 그래서 API 코드에서 `openapi.json`을 뽑아 사이트에 넣고 Scalar로 그리게 하고, 보안 헤더 예외는 되돌렸다. 단위 시험이 코드와 파일을 비교하므로 API를 바꾸고 파일을 다시 만들지 않으면 CI가 깨진다([API 문서를 사이트 안의 앱으로](/memo/api-docs-app), [#95](https://github.com/hyeoniverse/MacFolio/pull/95)).

![지금의 API 문서 앱](./images/day-1005-apidocs.jpg 'API 문서 앱의 지금 모습. 서버 없이도 열린다')

앱이 늘자 Dock이 Launchpad와 겹쳤고([글](/memo/dock-layout)), API 문서 아이콘은 6분 동안 세 번 바뀌었다가 처음 모양 `{ API }`로 돌아왔다.

## DB 백업

블로그 글과 이미지가 모두 1GB 무료 서버의 DB에만 있게 되었다. 서버가 회수되면 글도 같이 사라진다. 매일 덤프해 서버 밖(R2)에 남기고, 되살려 보는 것까지 스크립트로 했다([글이 DB에만 있게 되어서 백업을 붙였다](/memo/db-backup), [#94](https://github.com/hyeoniverse/MacFolio/pull/94)).

실제 서버에 적용할 때 생긴 문제:

- R2 무료 한도에 닿기 전에 백업이 멈추게 ([#98](https://github.com/hyeoniverse/MacFolio/pull/98))
- apt의 rclone 1.53에는 R2가 없어서 공식 설치 스크립트로
- 버킷 하나짜리 키로는 버킷 목록이 늘 403이라 연결 확인 방법을 바꿔서 ([#99](https://github.com/hyeoniverse/MacFolio/pull/99))

서버에서 처음 돌린 백업은 1,007KB였고, 되살린 글 수가 원본과 같았다([R2에 DB 백업 걸기](/memo/r2-backup-setup)).

## 10월 2일 오류의 원인

10월 2일에 "배포 직후 메모가 안 열리던" 일을 경고창으로 막고 끝냈었다. 이날 근본 원인을 찾았다. 사이트가 없는 주소에 늘 `index.html`을 200으로 줬는데, `/assets/*`에는 "1년 동안 다시 묻지 말라"(`immutable`) 헤더가 걸려 있었다. 배포 중에 사라진 옛 코드 파일 주소를 받은 브라우저는 **그 이름으로 HTML을 1년 동안 캐시하게** 된다. 없는 파일 주소는 404, 앱 주소만 첫 화면을 주게 나눴다([없는 코드 파일에 index.html을 주던 문제](/memo/asset-404), [#103](https://github.com/hyeoniverse/MacFolio/pull/103)).

## API 자동 배포

API 자동 배포를 만들었다. main에서 API가 바뀌면 Actions가 이미지를 GHCR에 올리고, 서버는 백업 → 컨테이너 교체 → 건강 확인을 하고 실패하면 되돌린다([API 자동 배포](/memo/api-auto-deploy), [#104](https://github.com/hyeoniverse/MacFolio/pull/104)). 1GB 서버가 직접 빌드하던 일이 사라졌다.

실제 서버에 적용하면서 문제가 다섯 번 생겼다([자동 배포를 실제 서버에 걸기 - 막힌 곳 다섯](/memo/api-auto-deploy-setup)). 그중 하나는 첫 배포에서 바로 나왔다. 서버 compose 파일은 이미지 태그(`API_TAG`)가 없으면 멈추게 썼는데, 첫 배포에는 태그가 아직 없어서 배포 전 백업이 멈췄다([#107](https://github.com/hyeoniverse/MacFolio/pull/107)). 로컬 시험의 compose 파일에는 이 검사가 없었다.

중간중간 메뉴 막대도 고쳤다. 앱 이름이 맨 앞 창을 따르고([#97](https://github.com/hyeoniverse/MacFolio/pull/97), [#101](https://github.com/hyeoniverse/MacFolio/pull/101), [글](/memo/menu-bar-app-name)), 파일·보기·윈도우·도움말이 실제 메뉴로 열린다([#105](https://github.com/hyeoniverse/MacFolio/pull/105), [글](/memo/menubar-menus)). AI 요약 데모의 기본 공급자는 Groq로 바꿨다([#106](https://github.com/hyeoniverse/MacFolio/pull/106), [글](/memo/groq-summary)).

## 돌아보며

"서버가 꺼지면?"이라는 질문은 도움이 되었다. API 문서, 백업, 자동 배포의 방식이 모두 이 질문으로 정해졌다. 아쉬운 점은 이 질문을 **만든 뒤에** 했다는 것이다. iframe은 서버 헤더에 예외까지 만들고 43분 만에 되돌렸다. 넣기 전에 물었으면 헤더 예외는 만들 일이 없었다.

또 하나는 시험에 쓰는 파일과 실제 서버에서 쓰는 파일이 달랐다는 점이다. `API_TAG` 검사가 서버의 compose 파일에만 있어서 로컬 시험에서 잡지 못했다. 시험은 실제와 같은 파일로 해야 한다.
