## 들어가기 전에

방화벽과 백신을 설치했다고 기업이 안전해지지는 않는다. 퇴사자의 계정이 그대로 남아 있거나, 패치 담당자가 정해져 있지 않거나, 사고가 났을 때 누구에게 보고해야 하는지 모르면 장비가 탐지한 경보도 쓸모가 없다. 기업의 정보보호는 여러 겹의 보안 장비(기술 대책)와, 그 장비를 운영하는 정책·조직·절차(관리 대책)를 함께 갖춰야 한다.

이 글은 앞부분에서 금융권 IT 기업의 보안 인프라를 예로 들어 기술 대책이 실제로 어떻게 배치되는지 따라가고, 뒷부분에서 이를 운영하는 관리체계와 법적 의무를 정리한다.

## 산업 인프라와 보안 인프라의 변화

### 산업혁명과 IT 인프라

| 구분         | 시기                | 핵심 기술                                        | 변화                      |
| ------------ | ------------------- | ------------------------------------------------ | ------------------------- |
| 1차 산업혁명 | 18세기 중~19세기 초 | 증기기관(영국)                                   | 생산의 기계화             |
| 2차 산업혁명 | 19세기 중·후반      | 전기, 화학, 석유, 철강                           | 소비재의 대량생산         |
| 3차 산업혁명 | 20세기 후반         | 컴퓨터, 인터넷, 재생 에너지, 분산 전력망         | 정보화·자동화             |
| 4차 산업혁명 | 21세기 초~현재      | 인공지능, 사물인터넷, 빅데이터, 모바일, 클라우드 | 정보통신·경제·사회의 융합 |

4차 산업혁명이라는 말은 2016년 세계경제포럼에서 클라우스 슈바프가 널리 퍼뜨린 표현이다. 기업 업무가 모두 네트워크로 연결된 IT 시스템 위에서 돌아가면서, 시스템이 멈추거나 데이터가 유출되면 곧바로 업무 중단과 금전 손실로 이어진다. ==보안이 IT 부서의 부가 기능이 아니라 사업 연속성의 조건이 된 배경이다==.

## 시스템 보안

### 정의와 6대 항목

시스템 보안은 ==허가받지 않은 사용자가 파일, 폴더, 시스템에 접근하는 것을 제한하는 일이다==. 이를 위해 다루는 주제를 여섯 가지로 나눈다.

![계정 관리, 세션 관리, 접근 통제, 권한 관리, 로그 관리, 취약점 관리의 여섯 항목과 각 항목의 대표 솔루션](./images/csintro-security-in-organizations-six-items.svg '시스템 보안 6대 항목')

| 항목        | 내용                                               | 대표 보안 솔루션                                                |
| ----------- | -------------------------------------------------- | --------------------------------------------------------------- |
| 계정 관리   | ID·비밀번호, 추가 인증(OTP 등 다중 인증)           | 접근통제 시스템, 추가 인증 시스템                               |
| 세션 관리   | 로그인 상태의 유지 시간 통제(유휴 시 자동 종료)    | 방화벽·VPN의 세션 시간 설정, 시스템 세션 관리                   |
| 접근 통제   | 누가 어느 네트워크·서버·DB에 접근할 수 있는지 통제 | 네트워크 접근 제어(NAC), 서버 접근 제어(SAC), DB 접근 제어(DAC) |
| 권한 관리   | 사용자별 접근 수준 관리, 최소 권한                 | 계정·권한 관리 시스템(IAM)                                      |
| 로그 관리   | 접근 기록, 시스템 로그, 감사 증적 보관             | 통합 로그 시스템                                                |
| 취약점 관리 | 운영체제·애플리케이션의 취약점 점검과 조치         | 패치 관리, 진단 도구, 모의 해킹, 시큐어 코딩, 디지털 포렌식     |

여기서 NAC·SAC·DAC는 기업 보안 실무에서 쓰는 장비 분류다.

- **NAC**(Network Access Control): 사내 네트워크에 연결하려는 단말이 허가된 장치인지, 백신과 보안 패치가 최신인지 검사한 뒤 접속을 허용한다.
- **SAC**(Server Access Control): 서버에 접속할 때 반드시 접근제어 게이트웨이를 거치게 해, 누가 어느 서버에서 어떤 명령을 실행했는지 기록하고 위험한 명령을 차단한다.
- **DAC**(Database Access Control): DB 접근을 중계해 사용자별로 조회할 수 있는 테이블과 쿼리를 제한하고 실행한 SQL을 기록한다.

==운영체제 이론에서 DAC는 임의적 접근 통제(Discretionary Access Control)를 뜻하므로==, 문맥에 따라 구분해 읽어야 한다. 계정·권한·로그의 운영체제 수준 원리는 [시스템 보안: 계정·접근 제어·권한·로그·취약점 관리와 버퍼 오버플로](/memo/csintro-system-security)에서 다룬다.

### 인프라 영역별 시스템 보안

기업망에서는 이 여섯 항목이 장비 하나에 모이지 않고 영역마다 나뉘어 적용된다. 인터넷에서 들어온 트래픽은 1차 방화벽, DDoS 차단 시스템, 침입 탐지(TMS·IDS), 2차 방화벽을 지나고, 내부 서버 앞에서 NAC·SAC·DAC 접근 통제를 다시 거친다. 계정·세션·권한·로그·취약점 관리는 이 경로에 있는 모든 서버와 장비에 공통으로 적용된다. TMS(Threat Management System)는 국내 공공·금융권에서 쓰는 이름으로, 네트워크 트래픽에서 위협을 탐지해 관제 센터에 알리는 IDS 계열 장비다.

![인터넷에서 DDoS 차단 시스템, 1차 방화벽, 2차 방화벽, TMS·IDS를 지나 내부 서버로 가는 경로 위에 접근 통제와 계정·세션·권한·로그 관리가 표시되고, 모든 장비가 취약점 관리로 연결된다](./images/csintro-security-in-organizations-infra-areas.jpg '인프라 영역별로 적용되는 시스템 보안 6대 항목. 출처: 코스콤 정보보호 실무 자료(2020)')

## 네트워크 보안

### 정의와 역할

네트워크 보안은 인프라 구조에서 가장 앞단에 놓이는 보안 수단이다. ==주로 OSI 7계층 가운데 4계층(전송 계층)까지==, 즉 IP 주소·포트·프로토콜 수준에서 동작하며 방화벽, VPN, Anti-DDoS처럼 차단 중심의 시스템이다.

| 역할                                | 담당 장비                |
| ----------------------------------- | ------------------------ |
| 규칙(Rule) 등 정책에 의한 허용·거부 | 라우터 ACL, 방화벽       |
| 패턴에 의한 통제                    | IDS·IPS(TMS)             |
| DoS·DDoS 공격 방어                  | DDoS 차단 시스템, 대피소 |
| 공용망에서 암호화와 사설 터널 제공  | VPN                      |
| 무선망을 통한 공격 대응             | 무선 침입 방지(WIPS)     |
| 물리적인 망 분리                    | 업무망·인터넷망 분리     |

망 분리는 업무용 내부망과 인터넷용 망을 물리적으로(또는 가상화로) 나누는 방식이다. 국내에서는 공공기관이 먼저 도입했고, 금융권은 2013년 3·20 사이버 테러 뒤 같은 해 7월 「금융전산 보안 강화 종합대책」으로 의무화되어, 직원이 업무용 PC와 인터넷용 PC를 따로 쓰는 경우가 많다. 2024년 이후 금융 분야와 공공 분야 모두 클라우드·생성형 AI 활용을 위해 망 분리 규제를 단계적으로 완화하고 있다.

### 라우터 ACL

라우터는 인터넷과 연결되는 첫 장비이며, 접근 목록(ACL, Access Control List)으로 들어오는(inbound) 트래픽과 나가는(outbound) 트래픽을 IP 주소, 포트, 프로토콜 기준으로 허용하거나 차단한다. 원칙은 다음과 같다.

- ==필요한 최소한의 IP 대역만 정의해 허용한다==.
- 웜·바이러스가 전파에 쓰는 포트(예: SMB 445, NetBIOS 137~139)를 차단한다.
- 사설 IP 대역이나 자기 조직 대역을 출발지로 단 외부 패킷을 버린다.

```text
access-list 110 deny   tcp any any eq 445
access-list 110 deny   ip 10.0.0.0 0.255.255.255 any
access-list 110 permit tcp any host 198.51.100.10 eq 443
access-list 110 deny   ip any any
interface GigabitEthernet0/0
 ip access-group 110 in
```

위 시스코 IOS 설정은 445번 포트와 사설 대역 출발지를 막고, 웹 서버의 443번 포트만 허용한 뒤 나머지를 모두 거부하는 규칙을 외부 인터페이스의 들어오는 방향에 적용한다.

### VPN

VPN(가상 사설망)은 인터넷 같은 공용망을 쓰면서도 보호 대상 단말끼리 암호화된 터널로 통신하게 해 사설망처럼 쓰게 하는 기술이다. IPsec(3계층)이나 SSL/TLS(전송 계층 위)로 데이터를 암호화한다. 지사와 본사를 연결하거나, 재택 근무자가 사내망에 접속할 때 쓴다. 터널의 구조는 [VPN과 터널링: IPsec과 TLS VPN](/memo/net-vpn)에서 다룬다.

### Anti-DDoS

DDoS 공격은 노리는 계층에 따라 나뉘며, 계층마다 막는 방법이 다르다.

![L7은 HTTP GET 플러딩처럼 웹 서버 처리 능력을, L4는 SYN 플러딩처럼 연결 테이블을, L3는 ICMP·UDP 플러딩과 반사 공격으로 회선 대역폭을 고갈시킨다](./images/csintro-security-in-organizations-ddos-layers.svg 'DDoS 공격의 계층별 분류')

| 계층             | 공격 대상                                     | 예                                                     |
| ---------------- | --------------------------------------------- | ------------------------------------------------------ |
| 애플리케이션(L7) | 사용자가 접근하는 특정 서비스                 | HTTP GET 플러딩, 캐시 제어(CC) 공격, SQL·RPC 요청 남용 |
| 전송(L4)         | 특정 목적지의 시스템이나 네트워크 서비스 전체 | TCP SYN·SYN-ACK·RST 플러딩, UDP 플러딩                 |
| 네트워크(L3)     | 네트워크 기능 자체(회선)                      | UDP·ICMP 플러딩                                        |

캐시 제어 공격은 HTTP 요청 헤더에 `Cache-Control: no-cache`를 넣어 중간 캐시 서버를 우회하고 원본 웹 서버가 매번 응답을 만들게 하는 L7 공격이다. ==L7 공격은 요청 하나하나가 정상 사용자와 똑같아 트래픽 양이 적어도 효과가 크다==. DDoS 차단 시스템은 출발지별 요청 빈도, 비정상 헤더, 자바스크립트 실행 여부 확인(챌린지) 등으로 봇을 걸러 낸다. 회선 자체를 넘치게 하는 대규모 공격은 KISA의 사이버 대피소나 통신사·CDN의 세척 서비스로 트래픽을 우회시킨다.

### 1차·2차 방화벽

기업망은 방화벽을 두 겹으로 둔다.

![인터넷에서 DDoS 차단 시스템과 1차 방화벽을 지나면 웹 방화벽 뒤의 웹 서버(DMZ)와 VPN이 있고, 2차 방화벽과 NAC·SAC·DAC 접근 통제, TMS·IDS를 지나야 내부 서버와 단말에 닿는다](./images/csintro-security-in-organizations-firewall-zones.jpg '1차·2차 방화벽과 접근 통제 배치. 출처: 코스콤 정보보호 실무 자료(2020)')

| 구분       | 보호 구간                        | 정책                                                                                       |
| ---------- | -------------------------------- | ------------------------------------------------------------------------------------------ |
| 1차 방화벽 | 외부에 노출된 구간(Untrust Zone) | 최소한의 허용 규칙, NAT·PAT·프록시로 내부 IP 숨김, 외부에서 접근할 수 있는 곳은 DMZ로 제한 |
| 2차 방화벽 | 내부(Trust Zone)                 | 외부에서 내부로 오는 경로 차단, 업무별 분리(단말·업무·DB·WAS), 내부 접근용 별도 접속 서버  |

NAT(Network Address Translation)는 내부의 사설 IP를 공인 IP로 바꿔 내보내는 기능이고, PAT(Port Address Translation)는 공인 IP 하나를 여러 내부 호스트가 포트 번호로 나눠 쓰게 한다. 외부에서는 내부 호스트의 실제 주소를 알 수 없다. DMZ(비무장 지대)는 외부 사용자가 접근해야 하는 웹·메일 서버를 두는 중간 구간으로, ==여기 있는 서버가 뚫려도 2차 방화벽이 내부망을 한 번 더 막는다==. 내부 서버에 접근할 때도 관리자 PC에서 바로 접속하지 않고 접근통제 게이트웨이(점프 서버)를 거치게 해 모든 작업을 기록한다.

## 웹 보안

### 정의와 중요성

웹 보안은 누구나 접근할 수 있는 웹 서버 애플리케이션을 보호하고, 웹에 접속하는 클라이언트 기기의 유해한 접근에 대응하는 일이다. 네트워크·시스템·애플리케이션 3계층이 모두 관여하므로 보안 정책의 집합체라 할 만하다.

- 네트워크 보안, 시스템 보안, 애플리케이션 보안이 체인처럼 연결된 계층 구조다. 접근 통제, 운영체제 보안, 계정 관리 등 대부분의 보안 정책이 웹 서버에 모인다.
- 웹 사이트는 기업의 얼굴이라, 첫 화면 변조(디페이스)나 개인정보 유출이 곧바로 기업 이미지 손상으로 이어진다.
- ==누구나 접근할 수 있는 DMZ에 있어 공격자의 첫 번째 목표가 된다==. 웹 애플리케이션은 침해사고의 가장 흔한 최초 침투 경로로 꼽힌다.

![네트워크 보안(Anti-DDoS, 방화벽, TMS·IDS)이 바깥을, 시스템 보안(서버 보안, 접근 통제)이 가운데를, 애플리케이션 보안(웹 방화벽, 웹셸 탐지, 시큐어 코딩)이 웹 서버를 감싼다](./images/csintro-security-in-organizations-web-layers.svg '웹 서버를 감싸는 3계층 보안')

| 계층         | 솔루션                            | 막는 것                                           |
| ------------ | --------------------------------- | ------------------------------------------------- |
| 네트워크     | Anti-DDoS, 방화벽, TMS·IDS        | 대량 트래픽, 허용하지 않은 포트, 알려진 공격 패턴 |
| 시스템       | 서버 보안(Secure OS), NAC·SAC·DAC | 서버 권한 탈취 후 확산, 비인가 접근               |
| 애플리케이션 | 웹 방화벽, 웹셸 탐지, 시큐어 코딩 | SQL 삽입, XSS, 웹셸 업로드                        |

웹셸(web shell)은 공격자가 파일 업로드 취약점 등으로 웹 서버에 올리는 스크립트 파일(`.php`, `.jsp`)로, 브라우저로 접속해 서버에서 임의 명령을 실행하게 해 준다. 웹셸 탐지 솔루션은 웹 디렉터리의 파일 변경과 위험한 함수 호출 패턴을 감시한다. Secure OS는 운영체제 커널에 강제적 접근 통제를 덧붙여 관리자 계정이 탈취되어도 정해진 파일·명령만 쓰게 하는 서버 보안 제품이다.

### 웹 취약점 분석 절차

기업은 정기적으로 웹 애플리케이션 취약점 분석(모의 해킹)을 수행한다.

![수행 전 대상 범위 선정, 정보 수집, 목록화를 거쳐 모의침투에서 취약점 분석, 공격 시도, 결과 분석을 하고, 수행 후 대응 방안 마련, 보고서 작성, 흔적 제거로 끝낸다](./images/csintro-security-in-organizations-web-assessment.svg '웹 취약점 분석 절차')

| 단계     | 작업                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| 수행 전  | 점검 대상 URL·서버와 기간을 정하고(범위 선정), 사용 기술과 공개 정보를 수집하고, 페이지·입력값·기능을 목록화 |
| 모의침투 | 목록의 각 항목에 취약점이 있는지 분석하고, 실제로 공격을 시도해 영향도를 확인하고, 결과를 분석               |
| 수행 후  | 취약점별 대응 방안을 마련하고 보고서를 작성한 뒤, 점검 중 만든 계정·파일 등 흔적을 제거하고 종료             |

==모의 해킹은 공격과 같은 행위이므로 대상 범위와 일정을 시작 전에 서면으로 합의한 뒤에만 수행한다==. 범위 밖의 시스템을 건드리면 정보통신망법 위반이 될 수 있다.

### OWASP Top 10

OWASP(Open Worldwide Application Security Project)는 웹 애플리케이션의 정보 노출, 악성 파일, 보안 취약점을 연구하는 국제 비영리 단체다. 실제 취약점 데이터를 모아 가장 위험한 10가지 항목을 몇 년마다 발표하며, 이 목록(OWASP Top 10)이 웹 취약점 진단의 사실상 기준으로 쓰인다. ==판마다 순위와 항목이 바뀌므로== 최신판을 [owasp.org/Top10](https://owasp.org/Top10/)에서 확인해야 한다.

![2013년판의 인젝션과 XSS는 2021년판 A03 인젝션으로, 직접 객체 참조와 기능 수준 접근 통제 누락은 A01 접근 통제 실패로 합쳐졌고, 설계·무결성·로깅·SSRF가 새로 들어왔다](./images/csintro-security-in-organizations-owasp.svg 'OWASP Top 10 2013년판과 2021년판의 대응')

| 2013년판                              | 뜻                                                          | 2021년판에서                 |
| ------------------------------------- | ----------------------------------------------------------- | ---------------------------- |
| A1 인젝션                             | 입력값이 SQL·OS 명령으로 해석되어 실행                      | A03 인젝션                   |
| A2 인증·세션 관리 취약점              | 세션 탈취, 약한 비밀번호 정책                               | A07 식별·인증 실패           |
| A3 XSS(크로스 사이트 스크립팅)        | 입력값이 다른 사용자의 브라우저에서 스크립트로 실행         | A03 인젝션에 통합            |
| A4 취약한 직접 객체 참조              | URL의 `id=1001`을 `1002`로 바꾸면 남의 데이터가 보임        | A01 접근 통제 실패에 통합    |
| A5 보안 설정 오류                     | 기본 계정, 디렉터리 목록 노출, 상세 오류 메시지             | A05 보안 설정 오류           |
| A6 민감 데이터 노출                   | 암호화하지 않은 개인정보·비밀번호 저장·전송                 | A02 암호화 실패              |
| A7 기능 수준 접근 통제 누락           | 관리자 URL을 일반 사용자가 직접 호출 가능                   | A01 접근 통제 실패에 통합    |
| A8 CSRF(크로스 사이트 요청 변조)      | 로그인한 사용자의 브라우저가 의도하지 않은 요청을 보내게 함 | 독립 항목에서 제외           |
| A9 알려진 취약점이 있는 컴포넌트 사용 | 패치되지 않은 라이브러리·프레임워크                         | A06 취약하고 오래된 컴포넌트 |
| A10 검증되지 않은 리다이렉트·포워드   | 정상 도메인을 거쳐 피싱 사이트로 이동시킴                   | 독립 항목에서 제외           |

2021년판은 접근 통제 실패(Broken Access Control)를 1위로 올렸고, 안전하지 않은 설계(A04), 소프트웨어·데이터 무결성 실패(A08), 보안 로깅·모니터링 실패(A09), 서버 측 요청 위조(SSRF, A10)를 새로 넣었다. CSRF와 검증되지 않은 리다이렉트는 이미 2017년판에서 빠졌다. 대부분의 웹 프레임워크가 CSRF 방어를 기본으로 갖추면서 CSRF가 발견된 애플리케이션 비율이 5% 수준으로 낮아졌고, 리다이렉트 취약점도 약 8%로 목록 기준에 못 미쳤기 때문이다.

## 보안관제와 사이버 침해대응

### 배경

- IT 환경이 빠르게 발전하면서 접속과 데이터가 대량으로 발생한다.
- 해킹 기술이 지능화되고 사이버 침해가 급격히 늘었다.
- 방화벽, DDoS 차단, 침입 탐지 등 요소별로 다양한 정보보호 시스템을 운영하지만, 대부분 악성코드와 알려진 침해 패턴 위주로 탐지·대응한다.

그래서 정보보호 시스템과 단말에서 발생하는 대량의 로그를 활용해 침해 징후를 미리 파악하고, 사고가 나기 전에 대응하는 능동적 체계를 만드는 것이 목표가 되었다.

### 개별 모니터링에서 통합 모니터링으로

![왼쪽은 장비마다 다른 관리 화면을 따로 보는 개별 모니터링, 오른쪽은 DDoS·방화벽·웹 방화벽·스팸 차단·단말·서버 로그를 수집·저장, 처리·분석, 시각화 단계로 모아 대시보드 하나로 보는 통합 모니터링](./images/csintro-security-in-organizations-monitoring.jpg '개별 모니터링 구조와 통합 모니터링 구조. 출처: 코스콤 정보보호 실무 자료(2020)')

| 구조          | 방식                                                        | 한계·장점                                         |
| ------------- | ----------------------------------------------------------- | ------------------------------------------------- |
| 개별 모니터링 | 정보보호 시스템마다 자체 관리 화면으로 이벤트 위주 관제     | 한 공격이 여러 장비에 남긴 흔적을 연결하기 어려움 |
| 통합 모니터링 | 모든 로그를 한곳에 모아 시간순(시계열)으로 한 화면에서 관제 | 장비 간 연관 분석 가능                            |

통합 모니터링은 로그를 수집·저장하고, 형식을 맞춰 처리·분석하고, 대시보드로 시각화하는 세 단계로 이루어진다. 이 역할의 시스템을 SIEM(Security Information and Event Management)이라 하며, 오픈소스로는 Elastic Stack(Elasticsearch, Logstash, Kibana)으로 구성하는 경우가 많다.

연관 분석의 예를 들면 다음과 같다. 웹 방화벽 로그에 "203.0.113.7에서 SQL 삽입 시도 탐지(차단)"가 있고, 10분 뒤 같은 IP가 웹 서버 로그에서 다른 URL로 정상 응답(200)을 받았고, 다시 몇 분 뒤 DB 접근 제어 로그에 대량 조회가 기록되었다면, 차단을 우회한 공격이 성공했을 가능성이 높다. ==세 로그를 따로 보면 각각은 흔한 이벤트일 뿐이다==.

### 공격 단계별로 남는 로그

공격자는 여러 단계를 거쳐 침투하며, 단계마다 다른 장비에 흔적이 남는다.

![인터넷, DMZ, 내부 단말망, 내부 네트워크에 놓인 장비마다 Ⓐ~Ⓝ 로그 기호가 붙어 있고, 아래 표에 취약점 파악부터 기타 침해 행위까지 단계별로 남는 로그가 정리되어 있다](./images/csintro-security-in-organizations-attack-logs.jpg '공격 유형별로 빅데이터 분석에 쓰이는 시스템 로그. 그림의 Scannig는 Scanning, CnS는 C&C(명령 제어)를 뜻한다. 출처: 코스콤 정보보호 실무 자료(2020)')

| 공격 단계                   | 예                                            | 흔적이 남는 로그                                    |
| --------------------------- | --------------------------------------------- | --------------------------------------------------- |
| ① 취약점 파악               | 포트 스캐닝, IP 스캐닝                        | 트래픽, 방화벽, 침입 탐지 로그                      |
| ② 유해 사이트로 접근 유도   | 피싱, 파밍, DNS 변조                          | 단말, 스팸 차단, 네트워크 로그                      |
| ③ 악성코드 감염             | 감염 사이트 접속, 악성코드 다운로드, C&C 접속 | 백신, 단말, 방화벽, 침입 탐지 로그                  |
| ④ 악성코드 실행과 내부 침투 | 권한 획득, 내부 서버 접속, SQL 삽입           | 서버 시스템, 서버 보안, 웹셸, 데이터 유출 탐지 로그 |
| ⑤⑥ 악의적 공격              | DoS·DDoS, XSS                                 | DDoS 탐지, 웹 방화벽, 트래픽 로그                   |

### 악성코드의 수명 주기

![해킹 목표 단말이 감염 사이트에서 드로퍼 사이트로 전환되어 악성코드를 내려받고, 업데이트 사이트와 C&C 1번 서버를 거쳐 암호화된 악성코드를 설치한 뒤 C&C 2번 서버로 데이터를 탈취한다. 현재 탐지는 마지막 단계에, 향후 탐지는 앞 단계에 둔다](./images/csintro-security-in-organizations-malware-lifecycle.jpg '악성코드 수명 주기와 탐지 시점. 출처: 코스콤 정보보호 실무 자료(2020)')

1. 해킹 목표 단말이 웹 서핑이나 이메일 링크(피싱)로 감염 사이트에 접속한다.
2. 감염 사이트가 악성코드 배포 서버(드로퍼 사이트)로 접속을 전환한다.
3. 단말로 악성코드가 다운로드된다.
4. 다운로드된 악성코드가 실행된다.
5. 악성코드가 업데이트 사이트에 접속한다.
6. 업데이트로 C&C 서버 접속 기능을 내려받는다.
7. 감염 단말의 권한으로 C&C 1번 서버에 접속한다.
8. C&C 서버가 암호화된 본 악성코드를 보낸다.
9. 악성코드를 복호화·설치하고 접속 관련 로그 등 증거를 삭제한다.
10. 설치된 악성코드가 C&C 2번 서버에 접속해 비밀번호와 중요 데이터를 탈취하거나 파괴한다.

기존 탐지 체계는 10단계처럼 피해가 드러난 뒤에 대응(사후 대응)하는 경우가 많았다. 빅데이터 기반 관제는 ==1~7단계에서 생기는 비정상 접속==(처음 보는 도메인 접속, 업무 시간 외 외부 통신, 알려진 유해 IP와의 통신)을 찾아 피해 전에 대응하는 것을 목표로 한다. 이 단계 구분은 록히드 마틴의 사이버 킬 체인(정찰 → 무기화 → 전달 → 익스플로잇 → 설치 → 명령 제어 → 목적 달성)과 같은 발상이다. 악성코드의 분류와 감염 경로는 [악성코드의 분류와 감염 경로, 탐지와 대응](/memo/csintro-malware)에서 다룬다.

### 빅데이터 분석 구조와 유해 IP 자동 차단

금융권 관제 센터의 예를 보면, 인터넷용 단말 약 1,200대, 방화벽 약 500대, 웹 방화벽, DDoS 차단 장비, TMS(센서 수십 대), 데이터 유출 방지(DLP) 장비, 업무별 서버 수십~수백 대가 로그를 보낸다. 이 로그를 수집 시스템이 모아 빅데이터 저장소에 인덱싱하고, 분석 엔진이 실시간 상관 분석, 과거 이력 분석, 포렌식 조회를 수행하며, 결과를 장비별 대시보드와 통합 대시보드로 보여 준다.

외부 위협 정보도 함께 쓴다. 금융보안원(금융기관이 탐지한 유해 IP)과 KISA(민간이 탐지한 유해 IP)가 API로 제공하는 목록을 매일 정해진 시각에 수집하고, 자기 조직의 DDoS 차단·웹 방화벽·방화벽·TMS 로그와 실시간으로 대조한다. 유해 IP가 실제로 유입되었으면 대시보드에 지역별 발신지 분포와 시간대별 탐지 이력을 표시하고, 차단 정책을 장비에 자동 반영한다. 이렇게 외부 위협 정보와 내부 로그를 자동으로 결합하는 방식을 위협 인텔리전스(threat intelligence) 연동이라 한다.

## 정보보호 관리체계

### 관리체계의 개념

앞에서 본 장비와 관제 체계는 사람이 정책을 정하고, 담당자가 운영하고, 누군가 점검해야 제대로 동작한다. 정보보호 관리체계(ISMS, Information Security Management System)는 조직이 보호할 자산을 정하고, 위험을 평가해 대책을 고르고, 그 대책이 제대로 운영되는지 점검해 개선하는 과정을 문서와 절차로 정한 것이다. 국제 표준은 ISO/IEC 27001이며, 계획(Plan) → 실행(Do) → 점검(Check) → 개선(Act)을 반복하는 구조로 흔히 설명한다.

![계획에서 정책·범위·위험 평가를, 실행에서 대책 구현을, 점검에서 감사와 심사를, 개선에서 결함 시정을 하고 다시 계획으로 돌아간다](./images/csintro-security-in-organizations-pdca.svg '관리체계의 PDCA 순환')

### ISMS-P 인증

국내에서는 과학기술정보통신부와 개인정보보호위원회가 공동으로 고시한 「정보보호 및 개인정보보호 관리체계 인증 등에 관한 고시」에 따라 KISA가 인증을 운영한다. 2018년 11월 기존의 정보보호 관리체계(ISMS) 인증과 개인정보보호 관리체계(PIMS) 인증을 통합해 ISMS-P가 만들어졌다.

| 구분      | ISMS                          | ISMS-P                                         |
| --------- | ----------------------------- | ---------------------------------------------- |
| 범위      | 정보보호 관리체계             | 정보보호 + 개인정보 처리 전 과정               |
| 인증기준  | 80개                          | 101개                                          |
| 법적 근거 | 정보통신망법 제47조           | 정보통신망법 제47조, 개인정보 보호법 제32조의2 |
| 의무 여부 | 기준에 해당하는 사업자는 의무 | 자율 신청                                      |

![ISMS-P 인증기준은 관리체계 수립 및 운영 16개, 보호대책 요구사항 64개, 개인정보 처리 단계별 요구사항 21개로 구성된다](./images/csintro-security-in-organizations-ismsp.svg 'ISMS는 1·2 영역 80개, ISMS-P는 세 영역 101개를 심사한다')

**ISMS 인증 의무 대상**은 정보통신망법 시행령이 정한다. 주요 기준은 다음과 같다.

- 전기통신사업법에 따라 등록한 기간통신사업자로서 서울과 모든 광역시에서 정보통신망 서비스를 제공하는 자(ISP)
- 집적정보통신시설(IDC) 사업자
- 연간 매출액 또는 세입이 1,500억 원 이상인 상급종합병원, 재학생 1만 명 이상인 고등교육기관
- 전년도 정보통신서비스 부문 매출액 100억 원 이상이거나, 직전 3개월 일평균 이용자 수 100만 명 이상인 정보통신서비스 제공자

인증의 유효 기간은 3년이며, 그동안 매년 사후 심사를 받고 3년마다 갱신 심사를 받는다. 금융 분야는 금융보안원도 인증 기관으로 지정되어 있다.

앞에서 본 기술 대책은 인증기준의 보호대책 요구사항에 대응한다. 예를 들어 시스템 보안 6대 항목은 2.5(인증 및 권한관리), 2.6(접근통제), 2.9(시스템 및 서비스 운영관리), 2.11(사고 예방 및 대응)에 해당한다. "로그 관리"는 접속 기록을 생성하는 데 그치지 않고 위·변조되지 않게 별도 서버에 보관하고 정기적으로 검토해야 충족된다.

==인증은 특정 시점에 기준을 충족했음을 보여 줄 뿐 사고가 나지 않는다는 보증은 아니다==. 인증을 받은 기업에서도 대규모 유출 사고가 일어나, 인증 이후 실제 운영 수준을 점검하는 사후 관리 강화가 꾸준히 논의된다.

## 위험 관리

위험 관리는 관리체계의 중심이다. ==모든 자산을 같은 수준으로 보호할 수는 없으므로==, 어떤 자산이 어떤 위협에 얼마나 노출되어 있는지 평가해 한정된 예산을 우선순위에 따라 배분한다.

| 용어   | 뜻                                                    | 예시                              |
| ------ | ----------------------------------------------------- | --------------------------------- |
| 자산   | 조직이 가치를 두는 정보, 시스템, 인력, 시설           | 고객 DB 서버                      |
| 위협   | 자산에 손실을 줄 수 있는 원인                         | 외부 해커의 SQL 삽입 공격         |
| 취약점 | 위협이 이용할 수 있는 약점                            | 입력값 검증이 없는 로그인 페이지  |
| 위험   | 위협이 취약점을 이용해 손실을 일으킬 가능성과 그 영향 | DB 유출로 인한 과징금과 신뢰 하락 |

![자산 식별, 위협 식별, 취약점 진단, 위험 평가, 위험 처리 순서로 진행하고, 위험 처리 방법은 감소·회피·전가·수용 네 가지다](./images/csintro-security-in-organizations-risk.svg '위험 관리 절차와 위험 처리 방법')

위험 평가에서는 흔히 다음과 같이 위험도를 산정한다.

```math
\text{위험도} = \text{자산 가치} \times \text{위협 발생 가능성} \times \text{취약성 정도}
```

각 항목을 1~3점으로 매긴 예는 다음과 같다.

| 자산                           | 자산 가치 | 위협 | 취약성 | 위험도 | 판단(허용 수준 9점) |
| ------------------------------ | --------- | ---- | ------ | ------ | ------------------- |
| 인터넷 노출 고객 DB, 패치 지연 | 3         | 3    | 3      | 27     | 즉시 대책           |
| 사내 그룹웨어                  | 2         | 2    | 2      | 8      | 허용 범위, 모니터링 |
| 내부망 테스트 서버             | 1         | 1    | 2      | 2      | 수용                |

조직은 허용할 수 있는 위험 수준(DoA, Degree of Assurance)을 정하고, 이를 넘는 위험부터 대책을 세운다.

| 처리 방법 | 뜻                                    | 예시                                         |
| --------- | ------------------------------------- | -------------------------------------------- |
| 감소      | 보호대책을 도입해 위험을 낮춤         | 웹 방화벽 도입, 시큐어 코딩, 패치            |
| 회피      | 위험의 원인이 되는 업무를 하지 않음   | 필요 없는 주민등록번호 수집 중단             |
| 전가      | 손실을 제3자에게 넘김                 | 사이버 보험 가입, 전문 업체에 운영 위탁      |
| 수용      | 대책 비용이 손실보다 크면 그대로 감수 | 허용 수준 이하의 위험, 경영진 승인 후 문서화 |

대책을 적용한 뒤에도 ==남는 위험(잔여 위험)은 경영진이 승인하고==, 위험 평가는 연 1회 이상 또는 시스템이 크게 바뀔 때마다 다시 수행한다.

## 보안 정책과 조직

### 정책 체계

보안 정책은 상위 문서에서 하위 문서로 갈수록 구체적이다.

| 문서            | 내용                                   | 예시                                                            |
| --------------- | -------------------------------------- | --------------------------------------------------------------- |
| 정책(policy)    | 경영진이 승인한 정보보호의 목표와 원칙 | "모든 개인정보는 암호화해 저장한다"                             |
| 지침(standard)  | 정책을 지키기 위한 구체적 기준         | "비밀번호는 영문·숫자·특수문자 조합 8자 이상"                   |
| 절차(procedure) | 담당자가 따라 하는 단계별 방법         | "퇴사자 발생 시 인사팀 통보 후 24시간 이내 전 시스템 계정 삭제" |

정책은 경영진의 승인을 받아 전 직원에게 알리고, 법령이나 조직이 바뀌면 개정한다. ==정책이 있어도 절차가 없으면 실무자가 무엇을 해야 하는지 알 수 없어 운영되지 않는다==.

### 조직과 인력

| 직책                      | 근거                     | 역할                                                |
| ------------------------- | ------------------------ | --------------------------------------------------- |
| 정보보호 최고책임자(CISO) | 정보통신망법 제45조의3   | 정보보호 계획 수립, 취약점 분석, 침해사고 대응 총괄 |
| 개인정보 보호책임자(CPO)  | 개인정보 보호법 제31조   | 개인정보 처리 업무 총괄, 정보주체 고충 처리         |
| 정보보호 실무 조직        | ISMS-P 인증기준 1.1.3 등 | 보안관제, 취약점 점검, 교육, 감사                   |

정보통신서비스 제공자는 CISO를 지정해 과학기술정보통신부에 신고해야 하며, 직전 사업연도 말 자산총액 5조 원 이상이거나, ISMS 인증 의무 대상자 가운데 자산총액 5천억 원 이상이면 CISO가 정보보호 외의 업무를 겸할 수 없다. 인적 보안으로는 입사 시 보안 서약, 정기 보안 교육, 직무 분리, 퇴사 시 계정 회수와 자산 반납을 관리한다.

## 침해사고 대응

### 대응 절차

NIST SP 800-61은 침해사고 대응을 다음 단계로 나눈다[^sp80061].

| 단계           | 내용                                                                 |
| -------------- | -------------------------------------------------------------------- |
| 준비           | 대응 조직(CERT)과 연락망, 절차서, 분석 도구, 백업 마련, 모의 훈련    |
| 탐지·분석      | 경보와 로그로 사고 여부를 판단하고 범위·심각도 분류                  |
| 봉쇄·근절·복구 | 감염 시스템 격리, 악성코드·백도어 제거, 패치 후 백업으로 서비스 복구 |
| 사후 활동      | 원인 분석 보고서 작성, 재발 방지 대책 반영, 절차 개선                |

봉쇄 단계에서는 증거 보존이 중요하다. ==감염 서버를 바로 포맷하면 공격 경로와 유출 범위를 확인할 수 없으므로==, 메모리와 디스크 이미지를 먼저 확보하는 디지털 포렌식 절차를 따른다. 앞의 악성코드 수명 주기 9단계처럼 공격자가 로그를 지우는 경우가 많아, ==로그를 별도 서버로 실시간 전송해 두는 것이 사후 분석의 전제가 된다==.

### 신고 의무

| 사고                    | 근거                                  | 신고 기한                                   | 신고처                                      |
| ----------------------- | ------------------------------------- | ------------------------------------------- | ------------------------------------------- |
| 침해사고(해킹, DDoS 등) | 정보통신망법 제48조의3                | ==침해사고를 알게 된 시각부터 24시간 이내== | 과학기술정보통신부 또는 KISA                |
| 개인정보 유출           | 개인정보 보호법 제34조, 시행령 제40조 | ==유출을 알게 된 시각부터 72시간 이내==     | 개인정보보호위원회 또는 KISA, 정보주체 통지 |

개인정보 유출 신고는 1천 명 이상 유출, 민감정보·고유식별정보 유출, 외부 불법 접근에 의한 유출 가운데 하나에 해당하면 의무다. 이 밖에 일정 규모 이상의 기업은 「정보보호산업법」 제13조에 따라 정보보호 투자액과 인력 현황을 매년 공시한다.
