## 들어가기 전에

네트워크로 주고받는 데이터는 수많은 장비와 회선을 거쳐 목적지에 도착한다. 같은 회선을 쓰는 다른 호스트, 중간의 라우터, 무선 구간의 누군가가 그 데이터를 엿보거나 바꾸거나 막을 수 있다. 네트워크 보안은 이런 위협을 유형별로 구분하고, 각 유형에 맞는 방어 장비를 망의 적절한 위치에 배치하는 일이다.

이 글은 개괄을 목표로 한다. 각 공격과 방어 기술의 동작 원리, 패킷 수준의 분석, 실습 코드는 [네트워크 보안](/memo/net-tcpip-model) 연재에서 자세히 다루므로, 여기서는 전체 지도를 그리고 해당 글로 연결한다.

## 위협의 분류

보안 공격은 공격자가 통신에 개입하는 방식에 따라 두 가지로 나뉜다[^x800].

- **수동적 공격**(passive attack): 통신 내용을 관찰만 하고 바꾸지 않는다. 도청과 트래픽 분석이 여기에 속한다. 데이터가 변하지 않으므로 탐지하기 어렵고, 암호화로 예방하는 것이 기본 대책이다.
- **능동적 공격**(active attack): 데이터를 위조·변조·재전송하거나 서비스를 방해한다. 신분 위장, 메시지 변조, 서비스 거부가 여기에 속한다. 완전히 막기 어려워 탐지와 복구가 중요하다.

![스니핑은 기밀성, 스푸핑은 무결성과 인증, DoS는 가용성을 침해한다](./images/csintro-network-security-attacks.svg '세 가지 대표 공격과 각각이 침해하는 보안 속성')

## 스니핑

스니핑(sniffing)은 네트워크를 지나는 패킷을 가로채 내용을 확인하는 도청 공격이다. 패킷을 바꾸지 않으므로 수동적 공격에 해당한다.

일반적인 네트워크 인터페이스 카드(NIC)는 목적지 MAC 주소가 자기 주소이거나 브로드캐스트인 프레임만 운영체제로 올리고 나머지는 버린다. NIC를 **무차별 모드**(promiscuous mode)로 바꾸면 목적지와 관계없이 수신한 모든 프레임을 올린다. Wireshark나 tcpdump 같은 패킷 캡처 도구가 이 모드를 사용하며, 두 도구 모두 리눅스·macOS·윈도우에서 동작한다(tcpdump의 윈도우 판은 WinDump).

무차별 모드만으로 모든 트래픽을 볼 수 있는 환경은 허브처럼 모든 포트로 프레임을 복제하는 공유 매체다. 스위치는 MAC 주소 테이블을 보고 목적지 포트로만 프레임을 전달하므로, 다른 호스트끼리의 트래픽은 공격자 포트에 도착하지 않는다. 그래서 스위치 환경의 공격자는 먼저 스푸핑으로 트래픽이 자기에게 오도록 만든다.

예를 들어 HTTP로 로그인하면 아이디와 비밀번호가 평문으로 전송되어 캡처 화면에 그대로 나타난다. HTTPS(TLS)를 쓰면 캡처는 되지만 내용은 암호문이다. 실제 캡처 과정은 [Wireshark로 HTTP 트래픽과 TCP 핸드셰이크 분석하기](/memo/net-wireshark-http)에, pcap 라이브러리로 스니퍼를 직접 만드는 방법은 [패킷 스니핑과 스푸핑, pcap과 원시 소켓의 이해](/memo/net-sniffing-spoofing)에 정리했다.

## 스푸핑

스푸핑(spoofing)은 주소나 신원을 위조해 상대를 속이는 공격이다. 위조 대상에 따라 IP 스푸핑, ARP 스푸핑, DNS 스푸핑 등으로 부른다.

### ARP 스푸핑

같은 LAN 안에서 IP 주소를 MAC 주소로 바꿀 때 ARP(Address Resolution Protocol)를 쓴다. ARP에는 인증이 없어, 요청하지 않은 ARP 응답도 수신 호스트가 캐시에 반영한다. 공격자가 "게이트웨이 IP 192.168.0.1의 MAC 주소는 공격자의 MAC이다"라는 위조 응답을 반복해서 보내면, 피해 호스트는 외부로 나가는 모든 프레임을 공격자에게 보낸다. 공격자는 받은 프레임을 진짜 게이트웨이로 다시 전달(relay)해 통신이 끊기지 않게 하면서 내용을 확인하거나 바꾼다. 이 상태를 중간자(man-in-the-middle) 공격이라 한다.

ARP 캐시는 다음 명령으로 확인한다.

```bash
arp -a
```

게이트웨이 IP에 대응하는 MAC 주소가 실제 라우터 MAC과 다르거나, 서로 다른 IP 두 개가 같은 MAC을 가리키면 스푸핑을 의심한다. 대책으로는 중요한 항목을 정적 항목으로 고정하는 방법(`arp -s <IP> <MAC>`)이 있으나 호스트마다 관리해야 하므로 규모가 커지면 운영이 어렵다. 기업망에서는 스위치의 DHCP 스누핑과 동적 ARP 검사(DAI)로 위조 응답을 차단한다. ARP의 동작은 [IP 헤더와 서브넷, ARP 주소 변환](/memo/net-ip-arp)에서 다룬다.

### DNS 스푸핑

DNS는 `example.com` 같은 도메인 이름을 IP 주소로 변환한다. DNS 스푸핑은 클라이언트가 보낸 질의에 대해 진짜 DNS 서버보다 먼저 위조 응답을 보내, 클라이언트가 공격자의 서버로 접속하게 만든다. 같은 LAN에 있는 공격자라면 ARP 스푸핑으로 질의를 먼저 확인한 뒤 응답을 위조한다. 재귀 DNS 서버의 캐시에 위조 레코드를 넣는 캐시 오염(cache poisoning)은 그 서버를 쓰는 모든 사용자에게 영향을 준다.

운영체제는 DNS 질의 전에 hosts 파일(리눅스·macOS의 `/etc/hosts`, 윈도우의 `C:\Windows\System32\drivers\etc\hosts`)을 먼저 확인한다. 중요한 도메인을 hosts 파일에 고정하면 그 도메인은 DNS 응답의 영향을 받지 않지만, 모든 도메인을 등록할 수는 없고 IP가 바뀌면 직접 갱신해야 한다. 거꾸로 악성코드가 hosts 파일을 바꿔 은행 도메인을 피싱 서버로 연결하는 공격도 있어, 이 파일은 관리자 권한으로만 수정할 수 있다.

근본 대책은 DNS 응답에 전자서명을 붙여 위조 여부를 검증하는 DNSSEC과, 질의의 출발지 포트와 트랜잭션 ID를 무작위로 골라 위조 응답을 맞히기 어렵게 하는 방법이다. 자세한 공격 과정과 DNSSEC은 [DNS의 계층 구조와 캐시 오염 공격, DNSSEC 방어](/memo/net-dns-attack)에 있다.

## 서비스 거부 공격

서비스 거부(DoS, Denial of Service) 공격은 대상의 CPU·메모리·연결 테이블·네트워크 대역폭 같은 자원을 고갈시켜 정상 사용자가 서비스를 쓰지 못하게 한다. 가용성을 침해하는 공격이다.

| 공격            | 고갈시키는 자원       | 방식                                                                                            |
| --------------- | --------------------- | ----------------------------------------------------------------------------------------------- |
| Ping of Death   | 운영체제의 패킷 처리  | IP 최대 길이(65,535바이트)를 넘는 ICMP 패킷을 단편으로 나눠 보내 재조립 시 버퍼 오버플로를 유발 |
| SYN 플러딩      | 서버의 반개방 연결 큐 | SYN만 대량으로 보내고 마지막 ACK를 보내지 않아 연결 대기 큐(backlog)를 채움                     |
| UDP·ICMP 플러딩 | 네트워크 대역폭       | 대량의 패킷으로 회선 용량을 소진                                                                |
| HTTP GET 플러딩 | 웹 서버의 처리 능력   | 정상처럼 보이는 요청을 대량으로 보냄                                                            |

Ping of Death는 1996년에 널리 알려진 운영체제 버그를 노린 공격으로, 당시 패치 이후 현재 운영체제에서는 통하지 않는다. 패킷이 단편화되는 이유는 링크마다 한 번에 보낼 수 있는 최대 길이(MTU)가 달라서이며, IPv4에서 단편은 최종 목적지에서만 재조립된다.

SYN 플러딩은 TCP 3-way 핸드셰이크의 구조를 이용한다. 서버는 SYN을 받으면 SYN-ACK를 보내고 연결 정보를 큐에 보관한 채 ACK를 기다린다. 출발지 IP를 위조한 SYN이 대량으로 오면 큐가 가득 차 정상 연결을 받지 못한다. 대표 대책인 SYN 쿠키는 큐에 상태를 보관하지 않고 연결 정보를 초기 순서 번호에 담아 보낸다. 리눅스에서는 `net.ipv4.tcp_syncookies` 커널 매개변수로 켠다. 공격과 대책의 상세는 [TCP 프로토콜을 겨냥한 공격과 방어](/memo/net-tcp-attacks)에 있다.

### DDoS

분산 서비스 거부(DDoS) 공격은 악성코드에 감염된 다수의 PC·서버·IoT 기기(좀비, 봇)가 동시에 한 대상을 공격한다. 공격자는 명령 제어(C&C) 서버를 통해 봇 전체에 명령을 내리며, 이 봇의 집합을 봇넷이라 한다. 공격 트래픽이 수많은 정상 IP에서 오므로 출발지 IP로 차단하기 어렵다.

국내 사례로 2009년 7월 7일부터 사흘간 정부·포털·금융 사이트를 노린 7·7 DDoS 공격이 있다. 이 공격에 쓰인 악성코드는 정해진 날짜가 되면 감염 PC의 하드디스크를 손상시키도록 만들어져 있었다[^ahn77]. 2016년에는 IoT 기기를 감염시킨 Mirai 봇넷이 DNS 서비스 업체 Dyn을 공격해 미국 동부의 여러 대형 사이트 접속이 장애를 겪었다.

DDoS 대응은 한 장비로 해결되지 않는다. 회선 앞단의 DDoS 차단 장비, 통신사나 CDN의 트래픽 세척(scrubbing) 서비스, 서비스별 대역폭 제한, 공공의 사이버 대피소 같은 우회 경로를 함께 운영한다.

## 방어 장비: 방화벽, IDS, IPS, VPN

![인터넷과 내부망 사이에 IPS와 방화벽이 직렬로 놓이고, IDS는 사본 트래픽을 받으며, 원격 PC는 VPN 터널로 내부망에 접속한다](./images/csintro-network-security-defense.svg '경계 보안 장비의 배치 예. 실제 구성은 조직마다 다르다')

| 장비                   | 역할                                                    | 위치·동작                                      | 한계                                         |
| ---------------------- | ------------------------------------------------------- | ---------------------------------------------- | -------------------------------------------- |
| 방화벽                 | 출발지·목적지 IP, 포트, 프로토콜, 연결 상태로 허용·거부 | 내부망과 외부망의 경계, 트래픽 경로 위(인라인) | 허용된 포트 안에 담긴 공격은 구분하지 못함   |
| IDS (침입 탐지 시스템) | 공격 시그니처나 이상 행위를 탐지해 경보                 | 스위치 미러 포트로 사본을 받음(경로 밖)        | 탐지만 하고 차단하지 않음                    |
| IPS (침입 방지 시스템) | IDS의 탐지 기능에 더해 해당 패킷·세션을 차단            | 트래픽 경로 위(인라인)                         | 오탐 시 정상 트래픽까지 차단, 장애점이 됨    |
| VPN                    | 공용망 위에 암호화 터널을 만들어 사설망처럼 사용        | 지사 간 또는 원격 사용자와 본사 사이           | 터널 끝 단말이 감염되면 내부망에 그대로 노출 |

방화벽 정책의 기본은 "명시적으로 허용한 서비스 외에는 모두 거부"하는 기본 거부(default deny)다. 쓰지 않는 포트는 닫고, 외부에서 들어온 패킷의 출발지 IP가 내부망 대역이면 위조로 보고 버린다(진입 필터링). 기업망은 외부에 공개하는 웹·메일 서버를 DMZ라는 별도 구간에 두고, 외부 방화벽과 내부 방화벽 두 겹으로 내부망을 보호하는 구성을 흔히 쓴다. 웹 애플리케이션 공격(SQL 삽입, XSS 등)은 HTTP 내용을 해석해야 막을 수 있어 웹 방화벽(WAF)을 따로 둔다.

IDS의 탐지 방식은 두 가지다. 알려진 공격의 패턴과 비교하는 **오용 탐지**(시그니처 기반)는 정확하지만 새로운 공격을 놓치고, 평소 트래픽의 통계적 기준선에서 벗어난 행위를 찾는 **이상 탐지**는 새 공격을 잡을 수 있지만 오탐이 많다. 시그니처는 새 공격이 알려질 때마다 갱신해야 한다.

방화벽 종류와 iptables 규칙은 [방화벽의 종류와 iptables 규칙](/memo/net-firewall)에서, IPsec·TLS VPN의 터널 구조는 [VPN과 터널링: IPsec과 TLS VPN](/memo/net-vpn)에서 이어서 다룬다.

```text
? (192.168.0.1) at 0:c:29:44:2c:ea on en0 ifscope [ethernet]
? (192.168.0.23) at 0:c:29:ad:25:88 on en0 ifscope [ethernet]
```

첫 줄이 기본 게이트웨이다. `netstat -rn | grep default`로 게이트웨이 IP를 확인하고, 그 IP의 MAC 주소가 라우터 라벨이나 관리 화면의 MAC과 같은지 비교한다.

### hosts 파일로 이름 해석 바꾸기

hosts 파일에 항목을 추가하면 DNS 질의 없이 그 IP로 접속한다. 테스트용 도메인으로 확인한다.

```bash
sudo sh -c 'echo "127.0.0.1 test.local" >> /etc/hosts'
ping -c 1 test.local
```

`ping`이 DNS 질의 없이 hosts 파일에 적은 127.0.0.1(자기 자신)로 패킷을 보낸다. 같은 원리로 악성코드가 hosts 파일을 바꾸면 사용자가 주소창에 정상 도메인을 입력해도 다른 서버로 접속하므로, 확인이 끝나면 추가한 줄을 삭제한다.
