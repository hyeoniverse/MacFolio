사진 위젯은 고른 앨범이나 Finder › 그림 폴더의 사진을 10초마다 넘긴다. 위젯을 누르면 사진 앱이 열렸지만, 항상 보관함 격자로 열렸다. 위젯에서 본 사진을 다시 보려면 앨범을 고르고 격자에서 그 사진을 찾아야 했다. iOS와 macOS의 사진 위젯은 누르면 그 사진을 바로 연다. 이 사이트도 그렇게 바꾸었다.

![데스크톱 전후](./images/photo-widget-open-current-desktop.jpg '왼쪽은 고치기 전(보관함 격자), 오른쪽은 고친 뒤. 왼쪽 위 위젯이 표시 중인 QRU 다크 테마 화면이 QRU 앨범의 4/9로 열린다')

## 동작

| 상황                                   | 고치기 전        | 고친 뒤                                                  |
| -------------------------------------- | ---------------- | -------------------------------------------------------- |
| 위젯의 사진을 누름                     | 사진 앱 › 보관함 | 사진 앱 › 그 사진의 앨범 › 그 사진의 크게 보기           |
| 크게 보기에서 ←·→, 사진 띠             | -                | 같은 앨범(프로젝트 앨범 또는 그림 폴더 앨범) 안에서 이동 |
| 크게 보기를 닫음                       | -                | 그 앨범의 격자                                           |
| 사진 앱이 이미 열려 다른 곳을 봄       | 창만 앞으로      | 창을 앞으로 가져오고 그 사진으로 이동                    |
| 일시 정지·소리 단추, 끌기, 오른쪽 클릭 | 앱을 열지 않음   | 그대로 (앱을 열지 않음)                                  |

휴대폰 홈 화면의 위젯도 같다. 화면 전체를 쓰는 사진 앱이 열리고, iOS 사진의 크게 보기(위의 제목 알약, 아래의 사진 띠)가 그 앨범의 사진으로 채워진다.

![휴대폰 전후](./images/photo-widget-open-current-mobile.jpg '왼쪽부터 사진 위젯이 표시 중인 홈 화면, 고치기 전(보관함), 고친 뒤(QRU 앨범 안의 크게 보기). iPhone 13 크기, 사진 띠도 QRU 앨범의 9장이다')

## 앱 사이의 요청: openRequest 재사용

다른 앱의 항목 하나를 여는 방법은 이미 있었다. Finder에서 글을 열면 메모가 그 글을 연다. `shared/lib/openRequest.ts`의 저장소에 `{ app, id }` 요청 하나를 보관하고, 받는 앱이 `useOpenRequest`로 꺼낸다. 받는 앱이 아직 마운트 전이면 요청이 남아 있다가 마운트 시각에 처리된다. 자세한 구조는 [Finder 앱 글](/memo/finder-app)에 있다.

사진 위젯도 이 경로를 쓴다. 바꾼 점은 둘이다.

- **받는 앱 타입:** 요청을 받는 앱은 주소(`/memo/<글>`, `/safari/<프로젝트>`)가 있는 앱(`LinkedApp`)으로 한정되어 있었다. `LINKED_APPS`에 `photos`를 넣으면 `/photos/…` 딥 링크까지 생기므로, 요청 전용 타입 `RequestApp = LinkedApp | 'photos'`를 따로 정의했다
- **요청 id:** 사진 하나를 가리키려면 앨범 id와 파일 주소가 함께 필요하다. 같은 파일이 두 앨범에 있을 수 있어서다. 구분 문자를 정해 이어 붙이면 앨범 id(`finder:folder:…`)나 주소의 문자와 충돌할 수 있어, `JSON.stringify([album, src])`로 직렬화한다. 되돌리는 `parsePhotoTarget`은 형식이 다르면 `null`을 반환한다

![흐름](./images/photo-widget-open-current-flow.svg '위젯이 표시 중인 사진을 ref에 보관하고, 누르면 요청을 남긴 뒤 앱을 연다. 사진 앱은 보관함에서 그 사진을 찾아 크게 보기로 연다')

## 위젯의 앨범 id와 사진 앱의 앨범 id

위젯이 고르는 곳(`PhotoSource`)과 사진 앱의 앨범(`Album`)은 같은 자료에서 나오지만 id가 다르다.

| 곳                  | 위젯의 id         | 사진 앱의 앨범 id        |
| ------------------- | ----------------- | ------------------------ |
| 프로젝트 앨범       | `qru`             | `qru`                    |
| 그림 폴더 바로 안   | `pictures`        | `finder:pictures`        |
| 그림 안에 만든 폴더 | `folder:widget01` | `finder:folder:widget01` |

사진 앱은 프로젝트 id와 겹치지 않도록 폴더 앨범에 `finder:` 접두사를 붙인다. 이 규칙은 `usePhotoLibrary.ts` 안의 지역 함수였다. 위젯도 같은 규칙이 필요해, `photoSources.ts`의 `libraryAlbumId(source)`로 옮기고 두 곳이 함께 쓴다. 위젯의 `photosOf`는 사진마다 `albumId`를 덧붙인다.

위젯이 '모든 앨범'을 넘기는 중이어도 사진마다 원래 앨범의 id가 붙어 있으므로, 누르면 보관함이 아니라 그 사진의 앨범이 열린다.

<details>
<summary>위젯 쪽 코드: 표시 중인 사진을 ref에 보관</summary>

`PhotoWidget`은 사진이 바뀔 때마다 `onShow`로 알린다. `Widget`은 이 값을 상태가 아닌 ref에 보관한다. 렌더링에 쓰지 않는 값이어서 10초마다 위젯 전체를 다시 그릴 이유가 없다.

```tsx
const shownPhoto = useRef<PhotoTarget | null>(null);
const showPhoto = useCallback((target: PhotoTarget | null) => {
	shownPhoto.current = target;
}, []);

// 위젯의 빈 곳을 누르면
if (kind === 'photos' && shownPhoto.current) requestOpen('photos', photoTargetId(shownPhoto.current));
open(app);
```

누름 처리는 기존 위젯 공통 경로(`button, a, [role="slider"], input`이 아닌 곳)를 그대로 쓴다. 일시 정지·소리 단추는 `button`이라 앱을 열지 않고, 끌기 직후의 클릭은 바탕화면 쪽 `onClickCapture`가 이미 막는다.

</details>

## 사진 앱 쪽: 늦게 생기는 앨범과 두 화면

`useOpenPhoto(albums, onOpen, enabled)` 훅이 요청을 받는다. 처리 순서는 이렇다.

1. 요청 id를 `parsePhotoTarget`으로 되돌려 ref에 보관한다
2. `locatePhoto(albums, target)`로 앨범과 앨범 안의 순번을 찾는다. 앨범 id와 `src`가 모두 맞아야 한다
3. 찾으면 `onOpen(album, index)`을 호출하고 보관한 요청을 삭제한다. 못 찾으면 보관한 채로 두고, `albums`가 바뀔 때 다시 찾는다

3의 재시도가 필요한 까닭은 그림 폴더 앨범이 비동기로 생기기 때문이다. 폴더 앨범은 `loadDocuments()`로 파일 목록을 받은 뒤에 `folderSources`가 만든다. 위젯이 폴더 사진을 표시 중이라면 파일 목록은 이미 공유 저장소에 있지만, 사진 앱이 처음 마운트되는 순서에 따라 첫 렌더링의 보관함에 그 앨범이 없을 수 있다.

> 처음 구현은 보관한 요청을 `useState`에 두고 effect에서 `setState(null)`을 호출했다. eslint-plugin-react-hooks의 `set-state-in-effect` 규칙이 연쇄 렌더링 가능성으로 오류를 냈다. 렌더링에 쓰지 않는 값이므로 ref로 바꾸었다.

사진 앱에는 화면이 둘 있다. `Photos`가 데스크톱 화면을 그리고, 휴대폰이면 그 안에서 `PhotosMobile`을 그린다. 두 컴포넌트가 모두 `useOpenRequest('photos')`를 구독하면 먼저 꺼낸 쪽만 요청을 받는다. 그래서 `useOpenRequest`에 `enabled` 인자를 더해, `Photos`는 `!mobile`일 때만 받고 `PhotosMobile`은 마운트된 동안 받는다.

| 화면                    | 찾은 뒤의 상태                                                                       |
| ----------------------- | ------------------------------------------------------------------------------------ |
| 데스크톱 (`Photos`)     | `place = { kind: 'album', id }`, `viewing = index`. 격자 위에 뜬 사이드바는 접는다   |
| 휴대폰 (`PhotosMobile`) | 보관함 탭, 검색 닫음, `opened = 그 앨범`, `viewing = { photos: 앨범의 사진, index }` |

크게 보기는 원래 '보는 곳의 사진 목록과 순번'으로 동작하므로, 보는 곳을 그 앨범으로 정하면 좌우 넘기기와 사진 띠가 자동으로 그 앨범 기준이 된다.

## 홈 화면 편집 중에 남던 요청

휴대폰 홈 화면은 위젯을 길게 누르면 편집 상태가 된다. 편집 중에는 `MobileHome`의 `open`이 아무것도 하지 않는다. 그런데 요청을 남기는 일은 `open` 호출보다 먼저 일어난다. 편집 중에 사진 위젯을 누르면 사진 앱은 열리지 않고 요청만 저장소에 남았다. 나중에 홈 화면의 사진 아이콘으로 앱을 열면, 보관함 대신 편집 중에 눌렀던 사진이 크게 보기로 열렸다.

`MobileHome`의 `onClickCapture`에서 편집 중 위젯 안의 누름(단추·링크·슬라이더·입력 칸 제외)을 캡처 단계에서 막도록 고쳤다. 바탕화면 위젯은 이미 같은 방식으로 편집 중 누름을 막고 있었다. 이 동작은 E2E 시험으로 확인하며, 수정 전 코드에서는 실패한다(보관함 제목 대신 크게 보기가 보인다). 메모 위젯의 글 목록처럼 단추로 된 항목은 이번 범위에서 제외했다.

## 시험

- **단위 시험:** 요청 id 직렬화와 복원(쌍점·물음표·따옴표가 든 값), 형식이 다른 id, 보관함에서 앨범과 순번 찾기, 같은 파일이어도 다른 앨범이면 찾지 않음, 위젯 사진의 `albumId`(프로젝트 앨범은 그대로, 그림 폴더는 `finder:`)
- **E2E 시험(데스크톱):** Playwright의 `page.clock`으로 시계를 10초 앞당겨 첫 사진이 아닌 사진을 표시하게 하고 누른다. 크게 보기의 사진 주소가 위젯과 같고, 순번이 `n/3`, ←·→가 같은 앨범을 돌고, 닫으면 그 앨범 격자다. 사진 앱이 보관함을 보는 중에 위젯을 다시 눌러도 그 사진으로 이동한다. 일시 정지·소리 단추는 앱을 열지 않는다
- **E2E 시험(휴대폰, iPhone):** 위젯을 누르면 그 사진이 QRU 앨범(9장) 안에서 열리고 사진 띠가 9장이다. 편집 중에 누르면 앱이 열리지 않고, 나중에 사진 앱을 열어도 보관함이 보인다
