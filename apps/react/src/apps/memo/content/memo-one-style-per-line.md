메모 편집기에서 목록 항목에 커서를 두고 서식 메뉴의 '머리말'을 누르면 아무 일도 일어나지 않았다. 머리말에서 '토글 목록'을 누르면 머리말은 그대로 두고 빈 토글이 아래에 하나 더 생겼다. 토글 제목에서 '제목'을 눌러도 그대로였다. [토글 목록을 더한](/memo/memo-editor-toggle-footnote) 다음 날 고쳤다. 같이 눈에 띈 구분선 모양까지 한 PR([#227](https://github.com/hyeoniverse/MacFolio/pull/227))로 고쳤다.

## 노션처럼, 아니면 macOS 메모처럼

노션은 목록 안에 제목을 넣을 수 있고, 제목 자체를 토글로 만들 수도 있다. macOS 메모는 줄마다 모양이 하나다. 제목·머리말·부머리말·본문·모노 스타일·목록 셋 가운데 하나를 고르면, 앞의 모양은 사라진다.

| 방법                                         | 좋은 점                                              | 걸리는 점                                                                                  |
| -------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 노션처럼 겹쳐 쓰기 (목록 안 제목, 제목 토글) | 표현이 넓다                                          | Markdown에서 `- ## 제목`, `<summary>` 안의 서식이 되어 읽기 화면이 어색하거나 그릴 수 없다 |
| 지금처럼 두기 (아무 일도 없음)               | 할 일이 없다                                         | 누른 버튼이 반응하지 않는다. 버그로 보인다                                                 |
| **macOS 메모처럼 한 줄에 모양 하나**         | 서식 메뉴가 이미 그 모양, 저장한 Markdown이 깔끔하다 | 노션에 익숙한 사람에게는 제약으로 보인다                                                   |

macOS 메모처럼 하기로 했다.

- 서식 메뉴가 처음부터 macOS 메모의 모양 목록을 그대로 따른다. 항목도 하나만 고르는 라디오 버튼(`menuitemradio`)이다.
- 글은 Markdown으로 저장된다. 목록 안의 제목은 `- ## 제목`이 되는데, 읽기 화면에서는 목록 점 옆에 큰 제목이 붙어 어색하다.
- 토글 제목을 머리말로 만들려면 `<summary>` 안에 서식을 넣어야 한다. 읽기 화면은 본문의 HTML을 그리지 않고, 토글 제목도 안전하게 글자로만 넣는다.

## 고른 모양으로 그 줄을 바꾼다

정했으면 그대로 동작해야 한다. 아무 일도 없던 곳에서, 고른 모양으로 그 줄을 바꾼다.

| 지금 줄   | 고른 것               | 결과                                                       |
| --------- | --------------------- | ---------------------------------------------------------- |
| 목록 항목 | 제목·머리말·본문·모노 | 목록에서 꺼내 그 모양으로 (남은 항목은 목록 그대로)        |
| 목록 항목 | 토글 목록             | 목록에서 꺼내 그 글자를 제목으로 한 토글                   |
| 머리말    | 토글 목록             | 머리말 글자가 토글 제목 (빈 토글을 새로 만들지 않는다)     |
| 머리말    | 목록                  | 본문으로 바꿔 목록에 넣는다 (목록 항목의 첫 줄은 본문이다) |
| 토글 제목 | 제목·목록·인용        | 토글을 풀고 그 줄을 그 모양으로 (내용은 아래에 그대로)     |

![목록 항목과 토글 제목에서 모양을 바꾸는 순서](./images/memo-one-style-per-line-convert.svg '먼저 목록이나 토글에서 꺼낸 다음 고른 모양으로 바꾼다')

편집기의 목록 항목은 첫 줄이 늘 문단이어야 한다(`paragraph block*`). 그래서 목록 항목 안에서 문단을 머리말로 바꾸는 명령은 아무 일도 하지 않고 실패했다. 이제 목록에서 먼저 꺼낸 다음 바꾼다.

```ts
case 'block': {
	// macOS 메모처럼 한 줄에 모양은 하나: 목록이나 토글 제목에서 고르면 그 줄을 꺼내 고른 모양으로 바꾼다
	const converted = current.summary || current.list !== null;
	if (current.summary) toggleDetails(view);
	else if (current.list) leaveList(ctx);
	// …
}
```

토글 제목에 커서가 있으면 서식 메뉴에서 '본문'이 아니라 '토글 목록'이 골라져 보이게 했다. 커서 자리의 서식에 `summary`(토글 제목 줄인지)를 더했다.

## 구분선

구분선(`---`)은 스타일이 없어서 브라우저 기본값으로 그려졌다. 회색 2px 입체 선이었고, 위 여백만 있고 아래 여백은 0이었다. 다크 모드에서는 밝고 굵은 선이 됐다.

테두리색 1px 선에, 위아래 1.8em 같은 여백으로 바꿨다. 편집기도 `.memo-markdown`이라 읽기 화면과 같은 규칙을 쓴다. 편집기에서 구분선을 고르면 강조색 테두리가 보인다.

편집기는 구분선을 `***`로 저장하고 있었다(remark-stringify 기본값). 지금 글들은 `---`를 쓰니, 목록 기호(`bullet: '-'`)처럼 `rule: '-'`을 줬다. 그대로 두면 저장소 글을 편집기에서 한 번 고칠 때마다 `---`가 `***`로 바뀌어 고친 줄과 상관없는 차이가 생긴다.

```css
.memo-markdown hr {
	height: 1px;
	margin: 1.8em 0;
	border: none;
	background-color: var(--memo-border);
}

/* 편집기에서 구분선을 고르면 (눌러서, 또는 화살표로) 강조색 테두리 */
.memo-inline-editor hr.ProseMirror-selectednode {
	outline: 2px solid var(--memo-accent);
	outline-offset: 4px;
}
```

![구분선 전후](./images/memo-one-style-per-line-hr.svg '브라우저 기본 입체 선 대신 1px 테두리색 선, 위아래 같은 여백, ---로 저장')

## 확인

`e2e/memo-editor.spec.ts`에 시험 둘을 더했다(78줄).

- "목록 항목·토글 제목에서 머리말을 고르면 그 줄을 꺼내 머리말로, 머리말에서 토글을 고르면 그 글자가 토글 제목…": 위 표의 바꾸기를 차례로 하고, 저장된 Markdown을 본다.
- "구분선은 가는 테두리색 선에 위아래 같은 여백, 편집기에서 고쳐도 --- 그대로 저장한다": 계산된 높이·위아래 여백이 같은지, 저장한 본문에 `---`가 남는지 본다.

PR은 8개 파일, 177줄 더하기, 8줄 지우기다. 편집기 코드에서 바뀐 것은 `formatCommands.ts`의 `'block'` 처리(19줄)와 커서 자리 서식에 `summary`를 더한 것이 거의 전부다.

## 남은 것·배운 것

- 기능을 고를 때 "무엇이 더 강력한가"보다 "저장한 글이 어떻게 보이는가"를 기준으로 삼았다. 이 편집기의 결과물은 Markdown 파일이고, 그 파일은 저장소와 GitHub에서도 읽힌다.
- 라이브러리 기본값(`***`, 회색 입체 선)은 우리 글의 규칙과 다를 수 있다. 처음 쓰는 요소는 기본값을 한 번 확인한다.
