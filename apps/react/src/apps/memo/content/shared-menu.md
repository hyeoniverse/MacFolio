공통 컴포넌트로 옮기는 두 번째 단계다. 앱을 훑어보니 **떠 있는 창**(메뉴, 팝오버)을 다섯 군데에서 따로 만들고 있었다.

| 어디                      | 그리는 곳 | 자리 잡기                      | 닫기                             |
| ------------------------- | --------- | ------------------------------ | -------------------------------- |
| 메모 우클릭·정렬·••• 메뉴 | body      | 화면 안으로 (가로·세로)        | document의 pointerdown·keydown   |
| 메모 서식 창·표 손잡이    | body      | 아래 가운데·오른쪽, 가로만     | 같은 코드를 다시                 |
| 날짜 고르기 달력          | body      | 아래 왼쪽, 오른쪽 끝만         | 같은 코드를 또                   |
| Apple 메뉴                | body      | 로고 아래, 당기지 않음         | 같은 코드를 또                   |
| 메시지 우클릭             | **창 안** | 대화 칸 기준 좌표, 당기지 않음 | **window**의 pointerdown·keydown |

"바깥을 누르거나 Esc를 누르면 닫는다"는 열댓 줄을 네 번 거의 그대로 썼다. 메시지만 window에 달았다. 자리 잡기는 다섯 곳이 다 조금씩 달랐다. 어떤 것은 화면 밖으로 넘쳐도 그대로 두었다.

## 셋으로 나눴다

![메뉴·팝오버 다섯 벌이 쓰는 공통 부품](./images/shared-menu-structure.svg '자리 잡기와 닫기는 메뉴가 아닌 작은 창도 쓴다. 메뉴 모양은 Menu 하나로')

**`placement.ts`: 자리 잡기.** 순수 함수 셋이다. 창 크기와 기준 자리를 받아 `left`·`top`을 돌려준다. DOM을 건드리지 않아서 단위 테스트로 가장자리를 다 시험할 수 있다.

```ts
placeAtPoint(point, size); // 우클릭한 자리에 왼쪽 위를 맞춘다. 넘치면 안으로
placeBelow(rect, size, { align, gap }); // 단추 아래 (왼쪽 맞춤 또는 가운데)
placeRight(rect, size); // 단추 오른쪽 (표 손잡이 메뉴)
```

**`useDismiss`: 닫기.** 바깥을 누르거나 Esc를 누르면 닫는다. "안쪽"으로 칠 요소들을 받는다.

```ts
useDismiss(open, () => setOpen(false), [panelRef, buttonRef], { keepOpenInside: '.ProseMirror table' });
```

여는 단추를 안쪽으로 넣는 것이 중요하다. 안 넣으면 열린 메뉴의 단추를 다시 눌렀을 때 일이 이렇게 된다.

1. `pointerdown`이 "바깥 누름"으로 메뉴를 닫는다
2. 이어지는 `click`이 다시 연다

닫히지 않는 메뉴가 된다. 예전 코드는 여는 단추마다 `onPointerDown`에서 `stopPropagation`을 따로 불러 이걸 막고 있었다. 공통 메뉴는 여는 단추를 `trigger`로 받아 안쪽으로 친다. Apple 메뉴부터 이렇게 바꿨다.

리스너는 열릴 때 한 번만 단다. 넘겨받는 `onDismiss`와 `inside` 배열은 렌더링할 때마다 새로 만들어진다. 이걸 의존성으로 걸면 렌더링마다 리스너를 뗐다 다시 단다. 그래서 최신 값만 ref에 담아 두고 리스너 안에서 읽는다.

**`Menu`: macOS 메뉴.** 항목은 네 가지다.

```ts
type MenuItem =
	| { label; icon?; onSelect; disabled?; hint?; checked?; destructive? } // 누르는 항목
	| { heading: string } // 묶음 이름 (정렬 기준, 순서)
	| { note: string } // 안내 한 줄 ("○○(으)로 로그인됨")
	| 'separator';
```

아이콘이나 체크 표시가 하나라도 있으면 모든 항목에 아이콘 자리를 두어 글자를 맞춘다. 새로 ↑·↓·Home·End로 항목을 옮겨 다닐 수 있게 했다. 다섯 벌 어디에도 없던 기능이다.

## 옮기며 생긴 일

### 메시지 메뉴는 창 밖으로 꺼냈다

메시지의 우클릭 메뉴만 창 안에 `position: absolute`로 그려져 있었다. 대화 칸 기준 좌표를 쓰고 안쪽으로 당기지도 않아서, 창의 오른쪽·아래 끝에서 우클릭하면 메뉴가 대화 칸 밖으로 넘칠 수 있었다. 공통 메뉴는 body에 그리고 화면 좌표를 쓰므로 그 계산을 지웠다.

```ts
// 전: 대화 칸 기준
const box = event.currentTarget.closest('.messages-chat').getBoundingClientRect();
setMenu({ x: event.clientX - box.left, y: event.clientY - box.top });
// 후: 화면 기준 그대로
setMenu({ x: event.clientX, y: event.clientY });
```

E2E도 고쳤다. 메시지와 팝업 시험이 메뉴를 메시지 창 안에서 찾고 있어서, 처음 돌렸을 때 둘이 실패했다. 페이지 전체에서 찾게 했다.

### 첫 항목에 초점을 줄까

메시지 메뉴는 열자마자 첫 항목에 초점을 주었다. 키보드로 바로 고를 수 있어 좋다. 하지만 메모의 메뉴들은 그러지 않았다. 공통 메뉴가 이걸 기본으로 하면, 메모 메뉴를 열 때마다 초점이 옮겨 간다. 메뉴를 닫은 뒤에는 초점이 원래 자리(검색 칸 등)로 돌아오지 않는다.

이번 단계는 모양과 동작을 바꾸지 않고 코드만 합치는 것이 목표다. 그래서 `autoFocus`는 기본으로 끄고, 원래 그렇게 하던 메시지 메뉴에서만 켰다. ↑·↓로 옮겨 다니기는 메뉴 안에 초점이 있을 때만 움직이므로 어디서나 켜 두었다.

### 전후 화면 비교

1단계에서 만든 화면 40장 비교를 다시 돌렸다. 바뀐 것은 메뉴 넷뿐이었다.

- **Apple 메뉴 (0.4%)**: 모서리 10px → 12px, 항목 여백이 메모 메뉴와 같아졌다. 같은 macOS 메뉴인데 두 모양이던 것이 하나로 맞았다

![Apple 메뉴](./images/shared-menu-apple.jpg '전: 혼자 다른 모서리와 여백. 후: 메모의 메뉴와 같은 모양')

- **메모 정렬·•••·폴더 고르기 메뉴 (0.2~0.4%)**: 줄 간격이 1~2px 좁아졌다
  - 원인을 찾아보니 예전 메모 메뉴의 항목(`<button>`)이 메뉴의 글꼴을 물려받지 않고 있었다
  - 메뉴는 body에 그려서 앱의 `.memo button { font: inherit }`이 닿지 않는다. 항목 규칙에도 `font-size`만 있고 `font-family`가 없었다
  - 그래서 브라우저 기본 단추 글꼴로 그려져 줄 높이가 조금 달랐다
  - 공통 메뉴는 항목이 `font: inherit`로 메뉴의 글꼴을 따른다

![메모 정렬 메뉴](./images/shared-menu-sort.jpg '전: 브라우저 기본 단추 글꼴. 후: 메뉴의 글꼴 (줄 간격이 조금 좁아졌다)')

메모 우클릭 메뉴처럼 묶음 이름이 없는 메뉴는 0%였다. 서식 창, 달력, 표 손잡이 메뉴도 0%였다. 창 안의 내용은 그대로 두고 닫기와 자리 잡기만 바꿨기 때문이다.

## 남은 것

- 메모 메뉴는 아직 마우스를 올리면 파란색(전역 강조색)이다. 메모 앱의 노란색이 아니다. 메뉴는 body에 그려서 앱 창에 정한 색 변수(`--memo-*`)가 닿지 않는다. 앱마다 메뉴 색을 다르게 하려면 메뉴를 그리는 자리에도 그 앱의 색 변수를 걸어야 한다. 단추를 공통 컴포넌트로 옮기는 다음 단계에서 같이 정한다
- 서식 창의 서식 단추, 달력의 날짜 칸은 그대로다. 다음 단계에서 단추를 정리할 때 함께 옮긴다
