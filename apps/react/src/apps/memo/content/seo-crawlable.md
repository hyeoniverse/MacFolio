이 사이트는 macOS 데스크톱을 웹으로 옮긴 것이라, 화면 전체를 React가 그린다. 서버가 주는 HTML에는 `<div id="root"></div>` 하나뿐이고, 글도 프로젝트 소개도 스크립트가 돈 뒤에야 생긴다. 사람에게는 문제가 없지만 검색엔진에는 문제가 된다. Google은 스크립트를 돌려 보기도 하지만 늦고 확실하지 않으며, 네이버나 링크 미리보기(카카오톡·Slack·X)는 대부분 스크립트를 돌리지 않는다. 그래서 어떤 주소를 가져가도 제목은 늘 "김정현의 Mac"이고 본문은 비어 있었다. 글이 180편을 넘었는데 검색으로는 하나도 찾을 수 없었다.

## 무엇을 했나

### 빌드: 글 목록과 sitemap

Vite 플러그인이 빌드할 때 저장소의 Markdown 글을 모두 읽는다. 머리말을 읽는 규칙은 메모 앱과 같은 코드(desktop-core)를 쓰고, 본문은 react-markdown으로 HTML 문자열을 만든다. 화면과 같은 Markdown 규칙(GFM, 한국어 굵게)이라 표나 목록도 그대로 나온다. 결과는 두 파일이다.

- `seo/posts.json`: 글마다 주소, 제목, 날짜, 요약, 카테고리, 태그, 본문 HTML
- `sitemap.xml`: 첫 화면, 모든 글(`lastmod`는 글 날짜), 모든 프로젝트 주소

`robots.txt`에는 sitemap 주소를 한 줄 더했다.

### Worker: 주소마다 다른 첫 화면

`/memo/<글>`이나 `/safari/<프로젝트>` 같은 앱 주소는 원래도 Cloudflare Worker가 index.html을 내준다. 여기에 한 단계를 더했다. Worker가 `posts.json`을 한 번 받아 두고, 주소에 맞는 페이지를 HTML에 넣는다.

| 주소                 | 제목·설명                 | 구조화 데이터   | 본문                         |
| -------------------- | ------------------------- | --------------- | ---------------------------- |
| `/`                  | 사이트 이름과 소개        | Person, WebSite | 소개와 모든 글·프로젝트 링크 |
| `/memo/<글>`         | 글 제목, 글 요약          | BlogPosting     | 제목, 날짜, 글 본문          |
| `/safari/<프로젝트>` | 프로젝트 이름, 한 줄 소개 | CreativeWork    | 소개, 기술, 저장소·데모 링크 |

`<head>`에는 canonical, Open Graph(`og:title`, `og:image` 등), Twitter 카드도 넣는다. 원래 있던 `<title>`과 description은 덧붙이지 않고 바꾼다. 같은 태그가 두 개 있으면 검색엔진이 어느 쪽을 쓸지 모르기 때문이다. 공유 카드의 그림은 데스크톱 화면을 1200×630으로 찍어 `og-image.jpg`로 두었다.

없는 글이나 프로젝트 주소에는 `noindex`를 단다. PR 미리보기 주소(`*.workers.dev`)는 응답 헤더에 `X-Robots-Tag: noindex`를 붙여 실제 사이트와 겹쳐 색인되지 않게 했다.

### 본문은 숨기되, 같은 내용으로

본문을 `#root` 안에 넣으면 스크립트를 받는 동안 글자가 잠깐 비칠 수 있다. 그래서 index.html의 인라인 스타일로 1px 크기에 잘라 숨긴다(화면 읽기 프로그램이 쓰는 방식과 같다). 앱이 그리기 시작하면 React가 `#root` 안을 통째로 바꾸므로 앱에는 영향이 없다.

검색엔진에만 다른 내용을 보여 주는 것은 클로킹이라 불이익을 받는다. 여기서 넣는 내용은 앱이 보여 주는 글·프로젝트와 같은 데이터에서 나온다. 관리자가 시스템 설정에서 고친 프로필과 프로젝트도 Worker가 이미 받아 오던 사이트 콘텐츠를 합쳐서 쓴다(숨긴 프로젝트는 빠진다).

모든 글자는 HTML로 이스케이프하고, JSON-LD 안의 `<`는 `<`로 바꿔 `</script>`로 빠져나가지 못하게 했다.

## 어떻게 확인했나

- Worker 단위 시험: 주소마다 제목·설명·canonical·og·JSON-LD, 제목과 description이 하나씩만 있는지, 없는 글의 `noindex`, 미리보기의 `X-Robots-Tag`, 제목에 `<`, `&`, `"`, `</script>`가 들어간 글의 이스케이프
- 빌드 시험: 저장소의 모든 글과 프로젝트가 sitemap에 있는지, 본문의 HTML이 그려지지 않는지
- 빌드 결과에 `seo/posts.json`과 `sitemap.xml`이 생기는지

화면 E2E는 `vite preview`로 돌아서 Worker를 거치지 않는다. 그래서 이 부분은 단위 시험으로만 확인한다.

## 배포한 뒤 할 일

코드만으로는 검색에 바로 나오지 않는다. 검색엔진에 사이트를 알려야 한다.

1. **Google Search Console**에 `https://macfolio.hyeoniverse.com`을 등록한다. 도메인 속성이면 Cloudflare DNS에 TXT 레코드를 더해 소유를 확인한다.
2. Search Console의 Sitemaps에 `sitemap.xml`을 제출하고, URL 검사로 글 주소 하나를 넣어 "페이지 색인 생성 요청"을 누른다. 실제 HTML 보기에서 제목과 본문이 보이면 된다.
3. **네이버 서치어드바이저**에 사이트를 등록하고(HTML 태그나 파일로 소유 확인), 요청 › 사이트맵 제출에 같은 주소를 넣는다.
4. 카카오톡이나 Slack에 글 주소를 붙여 공유 카드에 제목·요약·그림이 나오는지 본다.

## 남은 것

관리자가 API로 쓴 글(저장소에 Markdown 파일이 없는 글)은 빌드 때 모르는 글이라 `posts.json`과 sitemap에 없다. 그런 글의 주소는 지금은 `noindex`가 붙는다. 서버 글도 Worker가 API에서 받아 넣는 것은 다음에 할 일이다.
