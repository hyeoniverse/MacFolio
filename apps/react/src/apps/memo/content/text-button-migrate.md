아이콘 버튼 45곳을 `IconButton`으로 옮긴 다음 차례는 글자 버튼이다. `docs/ui.md`의 버튼 표에는 "`Button`으로 옮길 수 있음 약 33곳"이 있었다. 휴지통 비우기, 찾기의 완료, 글쓰기의 게시처럼 `<button>`에 글자를 직접 적은 버튼들이다. 이번에 이 가운데 30곳을 공통 `Button`으로 옮겼다. 목표는 지난번과 같다. **화면은 하나도 바뀌지 않는다.**

## 무엇을 옮겼나

| 앱     | 곳  | 버튼                                                                                                                       |
| ------ | --- | -------------------------------------------------------------------------------------------------------------------------- |
| 메모   | 13  | 찾기 완료·모두·대치, 휴대폰 목록 완료·이동·삭제, 버전 되돌리기, 잠금 풀기, 이미지 창 다시 고르기·찾기·더 보기, 게시·버리기 |
| 설정   | 11  | 정보·GitHub·프로젝트의 취소·완료·편집 9, 정보의 기본값으로 되돌리기, 개인정보의 더 알아보기                                |
| 휴지통 | 2   | 휴지통 비우기, 항목마다 비우기                                                                                             |
| 그 밖  | 4   | 메시지 새 피드백 취소, 날씨 다시 시도, 이 Mac에 관하여 추가 정보, 활동 상태 보기의 관리자 로그인                           |

처음 표에는 설정의 취소·완료·편집이 7곳(정보·GitHub)으로 적혀 있었다. 프로젝트 항목에도 같은 클래스(`showcase-text-button`)를 쓰는 버튼 3곳이 있어 함께 옮겼다.

옮기는 방법은 단순하다. `<button>`을 `<Button>`으로 바꾸고, `Button`의 기본값과 같은 `type="button"`만 뺀다. 앱의 `className`, `type="submit"`·`form`, `disabled`, `title`, 처리기는 그대로 둔다. `tone`은 쓰지 않았다. 색은 지금처럼 앱의 CSS가 정한다. 보이는 글자가 곧 이름이라, 역할과 이름으로 버튼을 찾는 E2E는 고칠 것이 없었다.

## 공통 CSS가 더하는 값

`Button`의 CSS는 `components` 층에 있고, 앱의 CSS는 층 밖에 있어 늘 이긴다. 문제는 앱이 적지 않은 값이다. `.ui-button`은 다음을 더한다.

- `display: inline-flex`, 가운데 정렬, `gap: 6px`
- 나타날 때 `fade-in` 애니메이션
- 안쪽 여백, 둥근 모서리 8px, 옅은 바탕, `font: inherit`
- 비활성일 때 `opacity: 0.45`

앱의 reset 층(예: `.memo button { font: inherit }`)은 `components` 층에 지므로, 앱이 클래스로 덮지 않은 값은 그대로 바뀐다. 그래서 앱마다 규칙을 하나 더했다.

```css
:where(.bin-empty-button):where(.ui-button) {
	display: inline-block;
	align-items: normal;
	justify-content: normal;
	gap: normal;
	animation: none;
}
```

`:where()`라 점수가 0이다. 층 밖에 있으니 공통 CSS는 이기고, 점수가 0이니 앱이 원래 적은 규칙에는 진다. 앱의 규칙을 하나하나 고치지 않고, 공통 CSS가 더한 값만 지울 수 있다. 앱마다 더 지운 값은 다음과 같다.

- 설정: 둥근 모서리(`border-radius: 0`). 취소·완료·편집은 글꼴을 브라우저 기본값으로 되돌렸다(`font-family: revert`). 원래 글꼴을 물려받지 않던 버튼이라, `font: inherit`가 붙으면 글꼴이 바뀌어 폭이 26px에서 22.5px로 줄었다
- 메모: 게시·버리기와 휴대폰 목록의 이동·삭제는 비활성일 때 흐려지지 않는다(`opacity: 1`). 이미지 창의 다시 고르기·더 보기는 바탕이 없다

## 모양이 같은 것을 어떻게 확인했나

지난번과 같은 방법을 썼다. E2E를 돌릴 때 페이지에 작은 스크립트를 넣는다. 화면에 보이는 `.ui-button`마다 계산된 스타일을 모두 읽고, 공통 클래스(`ui-button`)를 잠깐 떼고 다시 읽어 비교한다. 클래스를 뗀 상태가 곧 옮기기 전의 `<button>`이다. 위에서 더한 규칙도 `.ui-button`에 걸려 있으므로 함께 빠진다. 데스크톱과 휴대폰(iPhone·Android) 프로젝트에서, 시험이 지나가는 기본·마우스를 올린 상태·비활성 상태가 모두 기록된다.

처음 돌렸을 때는 옮긴 버튼의 기록이 모두 달랐다. 대부분은 `display`·정렬·`gap`이었고, 위에 적은 모서리·글꼴·바탕·비활성의 흐림이 더해졌다. 규칙을 더하고 다시 돌린 뒤에는 기록된 64가지(버튼·상태·화면 폭)가 모두 같았다. 애니메이션은 시험이 움직임을 끄고 돌아서 비교에 잡히지 않으므로, 따로 `animation: none`으로 지웠다.

마지막으로 옮기기 전과 뒤를 각각 빌드해, 이 Mac에 관하여 창을 찍어 비교했다. 두 그림은 한 화소도 다르지 않았다.

## 옮기지 않은 것

없다. 표에 적은 버튼은 모두 옮겼다. `<button>`을 직접 쓰는 곳은 85파일 250곳에서 81파일 220곳이 되었다. 남은 곳은 Safari 프로젝트 데모 페이지와, 목록 줄·탭·카드처럼 그 앱에만 있는 모양의 버튼이다.
