[아이콘 버튼 45곳을 `IconButton`으로 옮긴 작업](/memo/icon-button-migrate)에 이어 글자 버튼을 옮겼다([#246](https://github.com/hyeoniverse/MacFolio/pull/246)). [`docs/ui.md`](https://github.com/hyeoniverse/MacFolio/blob/main/docs/ui.md)의 버튼 표에는 "`Button`으로 옮길 수 있음 약 33곳"이 기록되어 있었다. 휴지통 비우기, 찾기의 완료, 글쓰기의 게시처럼 `<button>`에 글자를 직접 작성한 버튼들이다. 이번에 이 가운데 30곳을 공통 `Button`으로 옮겼다. 목표는 이전 작업과 같다. **화면은 한 픽셀도 바뀌지 않는다.**

## 옮긴 버튼

| 앱     | 곳  | 버튼                                                                                                                       |
| ------ | --- | -------------------------------------------------------------------------------------------------------------------------- |
| 메모   | 13  | 찾기 완료·모두·대치, 휴대폰 목록 완료·이동·삭제, 버전 되돌리기, 잠금 풀기, 이미지 창 다시 고르기·찾기·더 보기, 게시·버리기 |
| 설정   | 11  | 정보·GitHub·프로젝트의 취소·완료·편집 9, 정보의 기본값으로 되돌리기, 개인정보의 더 알아보기                                |
| 휴지통 | 2   | 휴지통 비우기, 항목마다 비우기                                                                                             |
| 그 밖  | 4   | 메시지 새 피드백 취소, 날씨 다시 시도, 이 Mac에 관하여 추가 정보, 활동 상태 보기의 관리자 로그인                           |

처음 표에는 설정의 취소·완료·편집이 7곳(정보·GitHub)으로 기록되어 있었다. 프로젝트 항목에도 같은 클래스(`showcase-text-button`)를 사용하는 버튼 3곳이 있어 함께 옮겼다.

변경 방법은 단순하다. 휴지통의 '비우기' 버튼의 변경은 다음과 같다.

```diff
+import Button from '@/shared/ui/button/Button';
-				<button
-					type="button"
+				<Button
 					className="bin-empty-button"
 					onClick={…}
 				>
 					휴지통 비우기
-				</button>
+				</Button>
```

`<button>`을 `<Button>`으로 바꾸고, `Button`의 기본값과 같은 `type="button"`만 제거한다. 앱의 `className`, `type="submit"`·`form`, `disabled`, `title`, 처리기는 유지한다. `tone` 속성은 사용하지 않았다. 색은 기존처럼 앱의 CSS가 지정한다. 표시되는 글자가 곧 접근 가능한 이름이라, 역할과 이름으로 버튼을 찾는 E2E(`getByRole('button', { name })`)는 수정할 필요가 없었다.

## 검토한 방법

컴포넌트 교체보다 "모양을 유지하는 일"이 어려웠다. 검토한 방법은 세 가지다.

| 방법                                           | 장점                                    | 단점                                                                      |
| ---------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------------- |
| 앱 CSS에서 버튼마다 덮어쓸 값을 직접 작성한다  | 변경 내용이 그 위치에서 바로 보인다     | 30곳마다 `display`·`gap`·모서리를 작성해야 하고, 명시도 경쟁이 생긴다     |
| `Button`에 스타일이 없는 `variant="bare"` 추가 | 앱 CSS를 수정하지 않는다                | 공통 컴포넌트에 "공통 모양을 사용하지 않는" 옵션이 생겨 역할이 모호해진다 |
| 앱마다 `:where()` 규칙 하나로 되돌린다         | 앱의 기존 규칙은 유지, 앱마다 규칙 하나 | 나중에 앱 모양을 공통 모양으로 맞출 때 이 규칙을 삭제해야 한다            |

세 번째 방법을 선택했다. 이번 작업의 목표는 "컴포넌트는 통일하고 화면은 유지"다. 화면을 공통 모양으로 맞추는 작업은 별도로 진행하고, 그 시점에 `:where()` 규칙이 삭제 대상 목록이 된다.

## 공통 CSS가 추가하는 값

`Button`의 CSS는 [캐스케이드 레이어(`@layer`)](https://developer.mozilla.org/en-US/docs/Web/CSS/@layer)[^1]의 `components` 레이어에 있고, 앱의 CSS는 레이어 밖에 있어 항상 우선 적용된다. 문제는 앱 CSS가 지정하지 않은 속성이다. `.ui-button`은 다음 값을 추가한다.

- `display: inline-flex`, 가운데 정렬, `gap: 6px`
- 표시될 때 `fade-in` 애니메이션
- 안쪽 여백, 둥근 모서리 8px, 옅은 배경색, `font: inherit`
- 비활성일 때 `opacity: 0.45`

앱의 reset 레이어(예: `.memo button { font: inherit }`)는 `components` 레이어보다 먼저 선언되어 우선순위가 낮다. 따라서 앱이 클래스로 덮어쓰지 않은 속성은 공통 CSS의 값으로 바뀐다. 그래서 앱마다 규칙을 하나 추가했다.

```css
:where(.bin-empty-button):where(.ui-button) {
	display: inline-block;
	align-items: normal;
	justify-content: normal;
	gap: normal;
	animation: none;
}
```

[`:where()`](https://developer.mozilla.org/en-US/docs/Web/CSS/:where) 안의 선택자는 [명시도(specificity)](https://developer.mozilla.org/en-US/docs/Web/CSS/Specificity)가 0이다. 레이어 밖에 있으므로 공통 CSS보다 우선하고, 명시도가 0이므로 앱이 원래 작성한 규칙보다는 우선순위가 낮다. 앱의 규칙을 하나씩 수정하지 않고 공통 CSS가 추가한 값만 되돌릴 수 있다.

| 규칙                                          | 위치         | 명시도 | 결과                     |
| --------------------------------------------- | ------------ | ------ | ------------------------ |
| `.bin-empty-button` (앱 규칙)                 | 레이어 밖    | 0-1-0  | 가장 우선                |
| `:where(.bin-empty-button):where(.ui-button)` | 레이어 밖    | 0-0-0  | 공통 CSS보다 우선        |
| `.ui-button`                                  | `components` | 0-1-0  | 위 두 규칙이 없는 속성만 |
| `.memo button` (앱 reset)                     | reset 레이어 | 0-1-1  | 가장 낮음                |

앱마다 추가로 되돌린 값은 다음과 같다.

- 설정: 둥근 모서리(`border-radius: 0`). 취소·완료·편집은 글꼴을 브라우저 기본값으로 되돌렸다(`font-family: revert`). 원래 글꼴을 상속하지 않던 버튼이라, `font: inherit`가 적용되면 글꼴이 바뀌어 너비가 26px에서 22.5px로 줄었다
- 메모: 게시·버리기와 휴대폰 목록의 이동·삭제는 비활성일 때 투명도를 낮추지 않는다(`opacity: 1`). 이미지 창의 다시 고르기·더 보기는 배경색이 없다

![앱 CSS, :where 규칙, components 층의 .ui-button, 앱 reset 층이 이기는 순서](./images/text-button-migrate-cascade.svg ':where() 규칙은 공통 CSS보다 세고 앱 규칙보다 약하다')

## 모양이 같은지 확인한 방법

이전 작업과 같은 방법을 사용했다. E2E 실행 중 페이지에 작은 스크립트를 삽입한다. 화면에 표시된 `.ui-button`마다 [계산된 스타일](https://developer.mozilla.org/en-US/docs/Web/API/Window/getComputedStyle)을 모두 읽고, 공통 클래스(`ui-button`)를 잠시 제거한 뒤 다시 읽어 비교한다. 클래스를 제거한 상태가 곧 옮기기 전의 `<button>`이다. 위에서 추가한 `:where()` 규칙도 `.ui-button`을 조건으로 하므로 함께 빠진다. 데스크톱과 휴대폰(iPhone·Android) 프로젝트에서, 시험이 거치는 기본·hover·비활성 상태가 모두 기록된다.

처음 실행했을 때는 옮긴 버튼의 기록이 모두 달랐다. 대부분 `display`·정렬·`gap` 차이였고, 위에 적은 모서리·글꼴·배경색·비활성 투명도 차이가 추가로 있었다. 규칙을 추가하고 다시 실행한 뒤에는 기록된 64가지 조합(버튼·상태·화면 너비)이 모두 같았다. 애니메이션은 시험이 애니메이션을 끈 상태(`reducedMotion`)로 실행되어 비교에 잡히지 않으므로, 별도로 `animation: none`을 지정했다.

![E2E 중에 ui-button을 떼고 붙인 계산된 스타일을 비교하는 방법](./images/text-button-migrate-compare.svg '클래스를 떼어 보고 비교한다')

이 방법은 화면을 하나씩 캡처하지 않아도 E2E가 거치는 모든 상태를 자동으로 비교한다. 다만 시험이 거치지 않는 상태(예: 시험이 클릭하지 않는 버튼의 hover)는 기록되지 않는다.

마지막으로 변경 전과 후를 각각 빌드해 '이 Mac에 관하여' 창을 캡처하고 비교했다. 두 이미지는 픽셀 단위로 동일했다.

## 변경 규모

- 변경 파일 24개, 247줄 추가와 103줄 삭제. 추가된 줄의 대부분은 앱마다 추가한 `:where()` 규칙과 주석이다.
- 옮긴 버튼 30곳: 메모 13, 설정 11, 휴지통 2, 그 밖 4

## 옮기지 않은 것

표에 기록한 버튼은 모두 옮겼다. `<button>`을 직접 사용하는 곳은 85개 파일 250곳에서 81개 파일 220곳으로 줄었다. 남은 곳은 Safari 프로젝트 데모 페이지와, 목록 행·탭·카드처럼 그 앱에만 있는 모양의 버튼이다.

## 남은 것·배운 것

- 앱마다 추가한 `:where()` 규칙은 "공통 모양과 다른 곳"의 목록이기도 하다. 버튼 모양을 공통으로 맞출 때 이 규칙을 하나씩 삭제하면서 화면을 바꾸면 된다.
- 설정의 버튼처럼 원래 글꼴을 상속하지 않던 버튼이 있었다. `font: inherit` 한 줄이 너비를 26px에서 22.5px로 바꿨다. 계산된 스타일 비교가 없었다면 육안으로는 발견하기 어려운 차이다.
- 캐스케이드 레이어(`@layer`) 밖의 규칙은 레이어 안의 규칙보다 항상 우선한다. 그리고 `:where()`는 명시도를 0으로 만든다. 이 둘을 함께 사용하면 "공통 CSS보다 우선하고 앱 규칙보다는 낮은" 규칙을 만들 수 있다.
