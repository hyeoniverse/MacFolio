시스템 설정에서 내용 끝까지 내렸는데, 한 번 더 굴리면 창 전체가 또 스크롤됐다. 스크롤되는 상자가 두 개였다.

재현은 간단했다. 화면 1280×800에서 시스템 설정을 열고 '정보'를 고른 뒤 끝까지 굴리면, 패널이 멈춘 다음 창의 콘텐츠 칸이 한 번 더 스크롤됐다. 관리자로 로그인하면 항목이 일곱 개로 늘어 패널이 더 눌렸다.

## 무엇이 스크롤되나

설정 창 안의 요소마다 `scrollHeight`와 `clientHeight`를 재서, 넘치면서 `overflow`가 `auto`·`scroll`인 것을 모았다.

| 창                        | 정보                                   | 개인정보 보호 및 보안 |
| ------------------------- | -------------------------------------- | --------------------- |
| 기본 크기 (화면 1280×800) | 창의 콘텐츠 칸 + 패널 (패널 높이 79px) | 패널                  |
| 넓은 화면 (1600×1000)     | 창의 콘텐츠 칸 + 패널                  | 패널                  |

창의 콘텐츠 칸(`.content`)은 앱 공통 틀이라 `overflow: scroll`이고, 설정은 안에서 패널(`.settings-panel`)이 따로 스크롤한다. 콘텐츠 칸이 넘치면 둘이 겹친다.

## 원인 1: 위쪽 탭이 패널을 밀어냈다

설정 창은 기본 폭이 좁아서, 폭이 520px 이하면 왼쪽 항목 목록을 위쪽 탭 줄로 바꾼다. 탭은 `flex: 1`로 폭을 나눠 가졌는데, 관리자에게는 항목이 일곱 개라 한 칸이 좁아졌다. 그러자 '화면 모드', '개인정보 보호 및 보안' 같은 이름이 한 글자씩 세로로 꺾이며 탭 줄이 창 높이의 대부분을 차지했다. 패널은 79px로 눌렸고, 넘친 만큼 창 전체가 스크롤됐다.

처음에는 탭을 한 줄로 두고 옆으로 넘기게 고쳤다. 그런데 진짜 macOS의 시스템 설정은 좁은 창에서 모양을 바꾸지 않는다. 사이드바와 패널이 함께 들어가는 크기보다 작게 **줄어들지 않을** 뿐이다. 그래서 그 방식으로 바꿨다.

고칠 방법을 견줘 보면 이렇다.

| 방법                                    | 좋은 점                                      | 걸린 점                                                                |
| --------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------- |
| 위쪽 탭을 한 줄로 두고 옆으로 넘기기    | 좁은 창도 그대로 쓴다                        | macOS 시스템 설정에 없는 모양이고, 탭이 많으면 무엇이 있는지 안 보인다 |
| 창의 콘텐츠 칸을 `overflow: hidden`으로 | 한 줄로 스크롤이 하나가 된다                 | 다른 앱이 쓰는 공통 틀이라 그 앱들의 스크롤이 막힌다                   |
| 앱마다 가장 작은 창 크기 (고름)         | macOS와 같은 동작, 좁은 모양이 필요 없어진다 | 화면이 아주 작으면 창이 화면보다 작아질 수는 없다(그때는 화면 크기)    |

- 앱마다 가장 작은 창 크기를 정할 수 있게 했다(`apps/manifest.ts`의 `minSize`). 창을 처음 열 때, 옮길 때, 모서리를 끌어 줄일 때 모두 이 크기 아래로 내려가지 않는다(`desktop/window/geometry.ts`). 정하지 않은 앱은 전처럼 360×200이다.
- 시스템 설정은 처음 780×540, 가장 작게는 680×420이다. 이 폭에서는 늘 왼쪽에 사이드바가 있으므로, 좁은 창용 위쪽 탭 모양은 지웠다.
- 넓은 창의 왼쪽 목록도 창보다 길어지면(관리자는 항목이 늘어난다) 목록만 스크롤한다.
- 설정 전체(`.settings`)는 창 높이에 딱 맞추고(`min-height: 0`, `overflow: hidden`), 패널도 `min-height: 0`으로 줄어들 수 있게 했다.

```ts
// apps/react/src/apps/manifest.ts
// 사이드바와 패널이 함께 들어가는 크기보다 작게 줄이지 않는다 (macOS 시스템 설정처럼)
settings: {
	label: '시스템 설정',
	icon: 'settings.png',
	inDock: true,
	windowSize: { width: 780, height: 540 },
	minSize: { width: 680, height: 420 },
},
```

창 크기를 정하는 함수들(`defaultRect`, `clampRect`, `moveRect`, `resizeRect`)이 모두 `min`을 받게 했다. 전에는 상수 `MIN_SIZE`를 함수 안에서 바로 읽었다.

```ts
// apps/react/src/desktop/window/geometry.ts
export function clampRect(rect: Rect, viewport: Viewport, min: MinSize = MIN_SIZE): Rect {
	const maxWidth = viewport.width;
	const maxHeight = viewport.height - STATUSBAR_HEIGHT;
	const width = clamp(rect.width, Math.min(min.width, maxWidth), maxWidth);
	const height = clamp(rect.height, Math.min(min.height, maxHeight), maxHeight);
	// …
}
```

`Math.min(min.width, maxWidth)`가 화면이 더 작을 때의 안전장치다. 680px보다 좁은 화면에서는 화면 폭이 가장 작은 크기가 된다.

`min-height: 0`이 빠지면 안 되는 까닭이 있다. 세로 flex 안의 자식은 기본으로 `min-height: auto`라 자기 내용보다 작아지지 않는다. 패널 안 내용이 길면 패널이 그만큼 커지고, 넘친 만큼 부모가 스크롤된다. `min-height: 0`이어야 패널이 창 높이에 맞춰 줄고 자기 안에서 스크롤한다.

## 원인 2: 숨은 글자가 창을 늘렸다

탭을 고친 뒤에도 정보 항목에서만 창이 넘쳤다. 콘텐츠 칸의 자식들은 모두 창 높이 안에 있는데, 콘텐츠 칸의 `scrollHeight`만 736px였다.

패널 안에서 `position: absolute`인 요소를 찾으니 셋이 나왔다. 링크 옆의 화면 읽기용 숨은 글자 "(메일 앱에서 쓰기)", "(새 탭)"이다(`.visually-hidden`). 절대 위치 요소는 가장 가까운 `position`이 있는 조상을 기준으로 놓인다. 설정의 패널과 그 위 상자에는 `position`이 없어서, 이 글자들은 창의 콘텐츠 칸(`position: relative`)을 기준으로 놓였다. 그래서 패널의 스크롤이나 `overflow: hidden`에 묶이지 않고, 패널 아래쪽 링크 자리만큼 콘텐츠 칸을 늘렸다.

패널을 `position: relative`로 해서 숨은 글자의 기준을 패널로 바꿨다. 이제 숨은 글자도 패널 안에서 함께 스크롤된다.

```css
/* apps/react/src/apps/settings/Settings.css (.settings-panel) */
min-width: 0;
min-height: 0;
/* 패널 끝에 닿아도 창(바깥)으로 스크롤이 이어지지 않게 */
overscroll-behavior: contain;
/* 안의 position: absolute 요소(화면 읽기용 숨은 글자 등)도 패널을 기준으로 */
position: relative;
```

`overscroll-behavior: contain`도 함께 넣었다. 패널 끝에 닿은 뒤의 굴림이 바깥 상자로 넘어가지 않게 하는 속성이다. 바깥에 스크롤할 것이 없어진 지금은 덤이지만, 나중에 다른 원인으로 바깥이 넘쳐도 굴림이 새지 않는다.

## 시험

- 단위: 앱이 정한 최소 크기보다 작게 만들지 않고(화면이 더 작으면 화면 크기), 모서리·변을 끌어 줄여도 그 크기에서 멈추고 반대쪽 변은 그대로다.
- E2E: 설정 창에서 정보·개인정보 보호 및 보안·배경화면을 차례로 열고, 창의 콘텐츠 칸이 넘치지 않는지(`scrollHeight - clientHeight ≤ 1`)와 패널 높이가 200px보다 큰지 본다. 화면 1280×800과 1600×1000에서 돌리고, 고치기 전의 CSS로는 두 크기 모두 실패하는 것을 확인했다.
- E2E: 설정 창의 오른쪽 아래 모서리를 왼쪽 위로 한참 끌어도 680×420에서 멈추고, 사이드바는 패널 왼쪽에 그대로 있다.

미리보기 빌드에서 같은 순서로 다시 재 보았다. 처음 크기는 780×540, 모서리를 600·500px 끌자 680×420에서 멈췄다. 그 크기에서 '정보'의 패널은 내용 724px을 389px 높이로 보여 주며 스스로 스크롤하고, 창의 콘텐츠 칸은 `scrollHeight - clientHeight`가 0이었다.

![가장 작은 크기 680×420의 시스템 설정](./images/settings-double-scroll-min.jpg '가장 작게 줄여도 사이드바가 왼쪽에 남고, 패널만 스크롤된다')

## 덤: 가끔 실패하던 댓글 사람 확인 시험

전체 E2E를 돌리다가 관계없는 시험 하나가 가끔 실패했다. 댓글에 사람 확인(Turnstile)을 켜고 댓글 두 개를 잇달아 쓰는 시험이다. 사람 확인 토큰은 한 번만 쓸 수 있어서, 댓글을 쓰고 나면 새 토큰을 받는다. 그 사이(시험의 가짜 위젯은 50ms)에 등록을 누르면 "사람인지 확인하는 칸이 끝날 때까지 기다려 주세요."만 뜨고 댓글은 올라가지 않았다. 시험은 그것을 모르고 댓글이 보이기를 기다리다 실패했다.

시험의 타이밍 문제이지만, 사람도 빠르게 누르면 똑같이 겪는다. 그래서 시험을 늦추지 않고 화면을 고쳤다. 토큰이 올 때까지 등록 버튼을 끄고 '확인 중…'으로 보여 준다.

```tsx
// apps/react/src/apps/memo/comments/Comments.tsx
{
	/* 사람 확인을 켰으면 토큰이 올 때까지 끈다: 댓글을 쓴 직후 새 토큰을 받는 사이에 누르면 보내지 못한다 */
}
<Button tone="primary" type="submit" disabled={sending || !human.ready}>
	{sending ? '등록 중…' : human.ready ? '등록' : '확인 중…'}
</Button>;
```

이 시험만 30번씩 열 개를 동시에 돌려 보니, 고치기 전에는 60번 중 2번 실패했고 고친 뒤에는 60번 모두 통과했다.

## 배운 것

- **스크롤 문제는 재서 찾는다.** 넘치는 상자를 눈으로 찾기는 어렵다. 요소마다 `scrollHeight`와 `clientHeight`를 재서 넘치는 것을 모으니 원인 둘이 바로 갈렸다.
- **숨은 글자도 자리를 차지한다.** 화면 읽기용 글자는 1px로 줄여 둘 뿐 레이아웃에 남는다. 절대 위치 요소의 기준 상자가 어디인지가 중요했다.
- **줄어들지 않는 것도 답이다.** 좁은 창에 맞는 두 번째 모양을 만드는 대신, macOS처럼 그보다 작아지지 않게 하니 지울 코드가 생겼다. 위쪽 탭 CSS 한 덩어리가 사라졌다.
- **가끔 실패하는 시험은 화면 버그일 수 있다.** 사람도 빨리 누르면 같은 일을 겪는다. 시험에 기다림을 더하는 대신 화면을 고쳤다.
