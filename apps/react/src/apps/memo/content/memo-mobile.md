메모 앱은 넓은 창을 기준으로 만들고, 좁아지면 한 칸씩 넘기는 화면(폴더 → 목록 → 본문)으로 바뀐다. 데스크톱에서 창을 줄여 가며 확인했는데, 휴대폰에서 관리자로 열어 보니 어색한 곳이 몇 군데 있었다.

![본문 전후](./images/memo-mobile-tools.jpg '전: 제목 막대 아래 두 줄로 흩어진 도구 / 후: 떠 있는 단추, ••• 메뉴')

## 본문은 iOS 메모처럼

전에는 휴대폰 셸의 제목 막대("< 모든 글 | 메모") 아래에 새 메모, 서식(가가), 삭제, 고정, 공유가 한 줄로 있었다. 고정과 공유만 크기와 위 여백이 달라 들쭉날쭉했고, 게시 단추는 공유 아이콘 밑에 혼자 떠 있었다. 처음에는 단추 크기와 줄만 맞췄는데, 실제 iOS 메모를 옆에 두고 보니 구조가 달랐다. iOS 메모의 본문에는 제목 막대가 없다.

- **왼쪽 위**: 뒤로 가기 동그란 단추 하나
- **오른쪽 위**: 공유와 •••를 담은 알약
- **••• 메뉴**: 맨 위에 아이콘 줄(메모 고정, 잠그기), 그 아래 메모에서 찾기와 빨간 삭제
- **아래 왼쪽**: 글자 꾸밈 알약 (가가, 체크리스트, 표, 이미지, 첨부)
- **아래 오른쪽**: 새로 쓰기 동그란 단추

처음 옮겼을 때는 게시 단추가 날짜 줄 위에 따로 한 줄을 차지해서, 날짜·폴더 줄이 떠 있는 단추보다 한참 아래로 밀렸다. 글자도 넓은 창 그대로 12px라 휴대폰에서는 작았다. 게시 단추(와 저장 상태)를 떠 있는 단추 줄로 올려 오른쪽 알약 왼쪽에 알약 하나로 띄우고, 날짜 줄은 가운데 그대로 단추 아래에 14px로 두었다. 처음에는 넓은 창의 노란 채운 단추를 그대로 알약에 넣었더니 혼자 튀었다. 옆 알약의 공유·••• 단추처럼 채우지 않은 글자 단추로 바꾸고, 게시할 것이 없으면 회색으로 둔다. 저장 상태 글("임시 저장됨" 등)도 처음에는 알약 안에 넣었는데, 글이 붙으면 알약이 길어져 좁은 화면에 맞지 않았다. 알약에는 단추만 두고, 저장 상태는 화면 읽기 프로그램에만 알린다. 변경 사항 버리기도 글 대신 되돌리기 아이콘이다.

제목 막대는 모든 앱이 함께 쓰는 휴대폰 셸의 것이라, 앱이 "이 화면에서는 막대를 띄워 달라"고 알리는 값(`floating`)을 하나 더했다. 앱이 뒤로 가기 글자를 바꿀 때 쓰던 `MobileNavigation`에 같이 넘긴다. 셸은 막대를 본문 위에 겹치고(`position: absolute`), 배경을 비우고, 뒤로 가기만 동그랗게 그린다. 뒤로 가기 글자("모든 글")는 화면 읽기 프로그램에만 남긴다.

```tsx
<MobileNavigation backLabel={categoryName} onBack={() => setPane('list')} floating />
```

••• 메뉴의 맨 위 아이콘 줄은 공용 메뉴(`Menu`)에 `{ row: [...] }` 항목을 더해서 만들었다. 데스크톱 메뉴도 같은 부품이라, 휴대폰에서는 `touch` 모양만 덧붙여 글자와 여백을 키운다.

아래 알약의 가가를 누르면 서식 창이 단추 아래로 열려서 화면 밖으로 나갔다. 떠 있는 창을 단추 아래에 두는 함수(`placeBelow`)가 가로로만 화면 안으로 당겼기 때문이다. 아래로 넘치는데 위에 자리가 있으면 단추 위에 두게 고쳤다.

처음에는 "휴대폰인가"를 셸이 내려 주는 Context로 알아내려 했는데, 단추가 하나도 그려지지 않았다. Context는 Provider의 **자식**에만 닿는다. 메모 컴포넌트는 창(`AppWindow`)을 그리는 쪽이라 Provider 바깥에 있다. 화면 폭으로 정하는 기존 훅(`useIsMobile`)을 썼다.

## 목록과 폴더도 iOS 메모처럼

본문을 바꾸고 나니 목록과 폴더 화면만 예전 모양(제목 막대 "< 폴더 | 메모", 그 아래 검색 칸, 회색 바탕에 바로 놓인 줄)으로 남았다. 실제 iOS 메모의 목록·폴더 화면도 본문과 같은 짜임이다.

![목록·폴더 전후](./images/memo-mobile-lists.jpg '목록과 폴더 화면의 전후: 큰 제목, 흰 카드 묶음, 떠 있는 단추, 아래 검색 알약')

- **위**: 본문처럼 제목 막대 없이 동그란 뒤로 가기. 목록은 오른쪽 위에 정렬, 폴더 화면은 새로운 폴더 (관리자)
- **큰 제목**: 목록은 폴더 이름과 "N개의 메모", 폴더 화면은 "폴더"
- **카드 묶음**: 회색 바탕 위에 흰 카드. 목록은 오늘·어제 같은 묶음마다, 폴더는 '블로그' 묶음 하나. 줄 사이 선은 글자가 시작하는 곳부터 긋는다
- **'블로그' 옆의 ⌄**: 누르면 묶음을 접는다
- **아래**: 검색 알약과 새 메모 (관리자). 폴더 화면의 검색 알약을 누르면 모든 글로 가서 검색 칸에 커서를 둔다

한 칸씩 보는 화면이라 고른 폴더·메모를 노랗게 칠하지 않는다. 대신 폴더 줄 끝에 ›를 붙여 누르면 넘어간다는 것을 보인다.

검색 칸과 정렬·새 메모 단추는 원래 목록 맨 위의 한 줄(`.memo-compact-tools`)에 함께 있다. 처음에는 이 줄을 `display: contents`로 풀어 단추마다 `position: absolute`로 띄웠다. 감싼 상자가 그려지지 않으니 기준이 목록 칸이 되어 데스크톱 Chrome에서는 잘 보였는데, 실제 휴대폰에서는 검색 알약이 보이지 않았다. 그 줄이 목록을 넘기는 칸(`overflow: auto`) **안**에 있었기 때문이다. 넘기는 칸 안의 요소를 칸 밖 기준으로 띄우는 것은 브라우저마다 다르게 그려질 여지가 있다.

그래서 휴대폰에서는 그 줄을 숨기고, 정렬과 검색 알약·새 메모를 넘기는 칸 **밖**(목록 칸의 바로 아래 자식)에 따로 그린다. 본문의 떠 있는 단추도 처음부터 이렇게 두었다.

```tsx
<section className="memo-list">
	<div className="memo-scroll">{/* 큰 제목, 묶음 카드 */}</div>
	{phone && compact && (
		<>
			<div className="memo-phone-list-top">{sortMenu()}</div>
			<div className="memo-phone-bottom memo-list-bottom">
				{searchBox()}
				{canEdit && <IconButton label="새 메모" … />}
			</div>
		</>
	)}
</section>
```

방문자에게는 새 메모가 없으니 `:has()`로 검색 알약을 오른쪽 끝까지 늘린다.

회색 바탕은 상태 막대 뒤와 홈 인디케이터 아래까지 이어져야 한다. 둘 다 메모 칸 밖(모바일 셸)에 있어서 메모 칸의 `@container` 규칙 안에 넣으면 걸리지 않는다. 컨테이너 쿼리는 조건을 재는 컨테이너의 자손에만 적용되기 때문이다. 그래서 그 규칙만 `@container` 밖에 두었다.

## 좁은 화면의 표

본문의 표는 폭 100%로 화면에 맞춘다. 휴대폰처럼 좁으면 칸이 줄어들면서 한국어 낱말 가운데서 줄이 바뀌었다('그리 / 는 곳').

![표 전후](./images/memo-mobile-table.jpg '전: 낱말 가운데서 줄이 바뀐다 / 후: 낱말은 그대로, 넘치면 옆으로 민다')

```css
.memo-reader-body > .memo-markdown table {
	display: block;
	overflow-x: auto;
}

.memo-reader-body > .memo-markdown :is(th, td) {
	min-width: 7.5em;
	word-break: keep-all;
}
```

`word-break: keep-all`로 낱말 가운데서는 바꾸지 않고, 칸마다 최소 폭을 두어 넘치면 표만 옆으로 밀리게 했다. 처음에는 최소 폭을 4.5em으로 했더니 칸이 오히려 더 좁아져 줄이 더 많이 바뀌었다. 스크린샷을 전후로 나란히 놓고 보고 나서야 알았다.

처음에는 `.memo-markdown table`로 걸었더니, 넓은 창의 편집기에서 표 편집 시험이 깨졌다. 이 규칙은 `@container (max-width: 700px)` 안에 있는데, 컨테이너 쿼리는 **가장 가까운** 컨테이너를 잰다. 편집기(`.memo-writer`)도 날짜 줄 배치 때문에 컨테이너로 만들어 두었고, 본문 칸은 넓은 창에서도 700px보다 좁다. 그래서 휴대폰이 아닌데도 편집기 안의 표가 `display: block`이 되었고, 시험은 표 칸을 누르지 못한 채 시간이 다 됐다. 읽기 화면의 본문(`.memo-reader-body > .memo-markdown`)으로만 좁혀서 고쳤다.
