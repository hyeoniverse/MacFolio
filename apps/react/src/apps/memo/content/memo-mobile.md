메모 앱은 넓은 창을 기준으로 만들고, 좁아지면 한 칸씩 넘기는 화면(폴더 → 목록 → 본문)으로 바뀐다. 데스크톱에서 창을 줄여 가며 확인했는데, 휴대폰에서 관리자로 열어 보니 어색한 곳이 몇 군데 있었다.

![도구 자리 전후](./images/memo-mobile-tools.jpg '왼쪽 둘: 본문 위 도구 줄 / 오른쪽 둘: 목록 위 새 메모')

## 본문 위 도구가 두 줄이었다

본문 위에는 새 메모, 서식(가가), 삭제, 고정, 공유가 있다. 고정과 공유에만 `font-size: 17px`과 위 여백이 붙어 있어서, 같은 줄인데 아이콘 크기와 높이가 제각각이었다. 게시 단추는 편집기 쪽의 날짜 줄에 들어 있는데, 좁은 편집기에서는 날짜 위의 따로 한 줄로 올라가 공유 아이콘 바로 밑에 혼자 떠 있었다.

- 도구 줄의 단추는 모두 같은 크기로 (36×34, 아이콘 17px). 서식, 삭제, 고정은 왼쪽, 공유는 오른쪽 끝
- 휴대폰에서는 날짜·폴더를 왼쪽에, 저장 상태와 게시를 같은 줄 오른쪽에 둔다. 게시 단추는 손가락으로 누를 만하게 키웠다

같은 줄에 있는지는 E2E에서 단추들의 세로 가운데를 재서 확인한다. 서식 단추만 높이가 달라서(30px) 위쪽 끝이 아니라 가운데를 비교했다.

```ts
const middles = await bar.locator('.ui-icon-button:visible').evaluateAll((buttons) =>
	buttons.map((button) => {
		const box = button.getBoundingClientRect();
		return Math.round(box.top + box.height / 2);
	})
);
expect(new Set(middles).size).toBe(1);
```

## 새 메모와 새로운 폴더의 자리

넓은 창에서 새 메모와 새로운 폴더는 사이드바 위쪽에 있다. 한 칸씩 볼 때는 그 막대(신호등 자리, 사이드바 여닫기)를 통째로 숨겼는데, 그 바람에 휴대폰에서는 새로운 폴더를 만들 수 없었다. 새 메모는 본문 위에만 있어서, 새 글을 쓰려면 아무 글이나 먼저 열어야 했다.

- **새 메모**: 목록 위 검색 칸 옆 (정렬 단추 다음). iOS 메모처럼 목록에서 바로 쓴다
- **새로운 폴더**: 폴더 화면 오른쪽 위. 사이드바 막대를 관리자에게만 다시 보이게 하고, 신호등 자리와 여닫기는 숨긴다

```css
.memo .memo-sidebar-bar:has(.memo-new-folder-button) {
	display: flex;
}
```

방문자에게는 단추가 없으니 `:has()`로 막대가 빈 줄로 남지 않게 했다.

폴더 화면은 회색인데 홈 인디케이터 줄은 흰색이라 화면 아래에 흰 띠가 보였다. 홈 인디케이터는 메모 칸 밖(모바일 셸)에 있어서 메모 칸의 `@container` 규칙 안에 넣으면 걸리지 않는다. 컨테이너 쿼리는 조건을 재는 컨테이너의 자손에만 적용되기 때문이다. 그래서 그 규칙만 `@container` 밖에 두었다.

## 좁은 화면의 표

본문의 표는 폭 100%로 화면에 맞춘다. 휴대폰처럼 좁으면 칸이 줄어들면서 한국어 낱말 가운데서 줄이 바뀌었다('그리 / 는 곳').

![표 전후](./images/memo-mobile-table.jpg '전: 낱말 가운데서 줄이 바뀐다 / 후: 낱말은 그대로, 넘치면 옆으로 민다')

```css
.memo-reader-body > .memo-markdown table {
	display: block;
	overflow-x: auto;
}

.memo-reader-body > .memo-markdown :is(th, td) {
	min-width: 7.5em;
	word-break: keep-all;
}
```

`word-break: keep-all`로 낱말 가운데서는 바꾸지 않고, 칸마다 최소 폭을 두어 넘치면 표만 옆으로 밀리게 했다. 처음에는 최소 폭을 4.5em으로 했더니 칸이 오히려 더 좁아져 줄이 더 많이 바뀌었다. 스크린샷을 전후로 나란히 놓고 보고 나서야 알았다.

처음에는 `.memo-markdown table`로 걸었더니, 넓은 창의 편집기에서 표 편집 시험이 깨졌다. 이 규칙은 `@container (max-width: 700px)` 안에 있는데, 컨테이너 쿼리는 **가장 가까운** 컨테이너를 잰다. 편집기(`.memo-writer`)도 날짜 줄 배치 때문에 컨테이너로 만들어 두었고, 본문 칸은 넓은 창에서도 700px보다 좁다. 그래서 휴대폰이 아닌데도 편집기 안의 표가 `display: block`이 되었고, 시험은 표 칸을 누르지 못한 채 시간이 다 됐다. 읽기 화면의 본문(`.memo-reader-body > .memo-markdown`)으로만 좁혀서 고쳤다.
