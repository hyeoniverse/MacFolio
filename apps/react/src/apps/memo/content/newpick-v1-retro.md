뉴픽 팀 프로젝트는 2025년 2월 6일 최종 발표로 끝났다. 이 글은 발표에서 무엇을 보여 줬는지, 그 뒤 팀이 무엇을 하려 했는지, 그리고 그때의 기록을 1년 8개월 뒤 [v2 리팩토링](/memo/newpick-v2-start)에서 고친 것과 나란히 놓으면 무엇이 보이는지를 정리한다. 팀 시절의 다른 글은 [첫 2주](/memo/newpick-v1-start), [Next.js](/memo/newpick-v1-nextjs), [로그인](/memo/newpick-v1-auth)에 있다.

## 최종 발표

발표는 프론트(나)와 백엔드(팀장)가 나눠 맡았다. 서비스 개요 → 핵심 기능 → 기획과 일정 → 기술 스택과 구조 → 트러블슈팅 → 시연 순서였다.

| 영역    | 발표한 구조                                                                                              |
| ------- | -------------------------------------------------------------------------------------------------------- |
| 프론트  | Next.js(App Router), TypeScript, Zustand, React Query, styled-components, Vercel                         |
| 백엔드  | NestJS, Prisma + MySQL(GCP), Mongoose + MongoDB Atlas, AWS EC2 + Nginx, GitHub Actions 자동 배포, Sentry |
| AI·메일 | OpenAI `gpt-4o-mini`로 요약·제목·HTML 생성, Nodemailer(Gmail)로 발송                                     |
| 데이터  | MySQL 10개 테이블(사용자·구독·뉴스레터), MongoDB 1개 컬렉션(크롤링 원문)                                 |

시연 시나리오는 비로그인(메인의 AI 요약 체험, 오늘의 트렌드, 목록 정렬, 상세의 조회수·관련 뉴스)과 로그인(북마크, 구독 설정, 일시정지·재시작, 실제로 받은 메일) 두 갈래였다. 시연 메모 맨 위에는 "프리티어 서버라 조금 느릴 수 있다"고 적어 두었다.

## 백엔드가 발표한 트러블슈팅

| 문제                  | 당시 해결                                                                                                         |
| --------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 크롤링이 느림         | `for...of` 순차 → `Promise.all` 병렬 → 메모리 급증 → `p-queue`로 동시 실행 제한 → 섹션은 순차, 기사는 병렬로 타협 |
| 봇 차단               | User-Agent 세 개(Windows·iPhone·Mac) 중 무작위, 1~3초 무작위 지연                                                 |
| 요약 요청이 400       | 하루 치 기사 197건을 한 번에 넣어 183,151토큰. 모델 한도 128,000토큰 초과                                         |
| 요약 결과 저장 실패   | AI가 고른 카테고리 이름이 DB와 달라 `categoryId: undefined`                                                       |
| Prisma로 MongoDB 저장 | MongoDB는 Mongoose, MySQL은 Prisma로 나눔                                                                         |
| 도메인·HTTPS·OAuth    | Nginx + certbot, Google 콘솔 리디렉션 URI·앱 게시 ([로그인 글](/memo/newpick-v1-auth))                            |

요약 저장 실패 로그를 다시 보면, 저장하려던 HTML이 ` ```html ` 코드 블록으로 감싸여 있었다. 코드 블록을 벗겨 내는 처리는 팀 프로젝트가 끝날 때까지 없었다.

팀은 한 달 정도 더 이어 가기로 했다. 회의록에 남은 계획은 이렇다.

| 회의 | 계획                                                                                                                                                              |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2/7  | 시연 영상 편집. 각자 할 일: 커뮤니티·댓글, 보안, 다국어, 서버·도메인 유지 / 노션 정리, README, styled-components → CSS, 받은 뉴스레터 내역, access token 수정(나) |
| 2/12 | 다음 주부터 한 달 진행, 주 1회 화상 회의, "테스트는 무조건 로컬에서". 댓글·커뮤니티, 카카오 등 로그인 추가, 날씨·지역 뉴스, 네이버 API로 크롤링, 키워드·검색      |
| 2/21 | "AI 뉴스레터가 새로 생성되지 않는 원인 파악", "카테고리별 목록이 최신순으로 안 나오는 문제". 다음 회의 3월 1일                                                    |

3월 1일 회의록은 없다. 기록은 2월 21일에서 멈췄다. 서버와 도메인은 "계속 열어 두기"로 했지만 결국 만료됐다.

## 1년 8개월 뒤 나란히 놓기

v2를 하면서 고친 것들 중 상당수는 팀 시절 기록에 이미 증상으로 남아 있었다. 원인을 몰랐거나, 알았지만 마감 안에 손대지 못한 것들이다.

| 팀 시절 기록                              | v2에서 찾은 원인과 수정                                                                                                                                                                           |
| ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 봇 차단을 피하려고 iPhone User-Agent 추가 | iPhone으로 받은 페이지에는 날짜 속성이 없는 요소가 먼저 나와, 기사 18%가 날짜 없이 수집됨 ([인프라 글](/memo/newpick-infra-simplify))                                                             |
| 2/21 "AI 뉴스레터가 새로 생성되지 않음"   | 당시 원인은 기록에 없다. v2에서 같은 증상을 낼 수 있는 원인 두 가지를 찾았다: 카테고리 하나가 실패하면 루프 전체가 멈추는 구조, 9시간 밀린 날짜 범위 ([스케줄러 글](/memo/newpick-kst-scheduler)) |
| 요약 저장 실패 `categoryId: undefined`    | 분류 응답을 DB의 카테고리 이름으로 제한 (JSON 스키마 enum) ([Claude 전환 글](/memo/newpick-claude-api))                                                                                           |
| HTML이 코드 블록으로 감싸여 저장          | "코드 블록 없이" 지시 + 감싸 오면 벗겨 내기 (같은 글)                                                                                                                                             |
| 197건을 한 번에 넣어 토큰 한도 초과       | 아직 남음. 카테고리별로 나눠 요약하지만, 입력 길이를 제한하는 코드는 지금도 없다                                                                                                                  |
| 2/7 "access token 받는 것 수정"(내 할 일) | `apiFetch`와 middleware로 갱신 경로를 처음부터 다시 ([요청 경로 글](/memo/newpick-api-client))                                                                                                    |
| 2/7 "styled-components → CSS"(내 할 일)   | v2 4단계 이슈(#10, Tailwind 전환)로 남아 있음                                                                                                                                                     |
| 2/7 "서버·도메인은 계속 열어 두기"        | 만료. v2는 작은 서버 한 대에 다시 배포하는 것을 목표로 함(#12)                                                                                                                                    |
| 2/7·2/12 "댓글·커뮤니티"                  | 목업만 남아, v2 개선 이슈(#22)에서 구현하거나 지우기로 정함                                                                                                                                       |

## 남은 것·배운 것

- 증상은 기록했지만 원인은 기록하지 않았다. 노션 트러블슈팅 DB 28건 중 상당수는 에러 메시지와 참고 링크뿐이다. 그래서 2월 21일의 "생성되지 않는 원인 파악"은 다음 회의로 넘어갔고, 그 회의는 열리지 않았다.
- "한 달 더"는 할 일 목록이 아니라 "누가, 언제까지, 무엇을 끝낸다"가 있어야 이어진다. 회의록의 액션 아이템 칸은 대부분 비어 있다.
- 그래도 이 기록 덕분에 v2를 시작할 수 있었다. 무엇이 어디서 깨졌는지 추측할 단서가 노션과 커밋에 남아 있었다. v2에서는 같은 이유로 단계마다 이슈에 완료 조건을, PR에 확인한 방법을 적고 있다.
