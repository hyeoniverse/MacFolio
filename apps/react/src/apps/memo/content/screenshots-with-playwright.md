README를 새로 쓰고 예전 블로그 글에도 이미지를 넣기로 했다. 필요한 장면은 이런 것들이었다.

- 관리자로 로그인한 계정 화면
- 예약한 글, 고치는 중인 글, 한 번도 게시하지 않은 글이 목록에 함께 있는 모습
- 표 손잡이로 열을 고르고 메뉴를 연 순간

손으로 찍으려면 실제 서버에 로그인해서 가짜 글을 만들고, 메뉴를 열어 둔 채 캡처해야 한다. 끝나면 가짜 글을 지워야 하고, 화면이 바뀌면 처음부터 다시 해야 한다. 그래서 **스크린샷도 테스트처럼 코드로 찍기로 했다.**

## E2E의 가짜 API를 그대로 쓴다

E2E에는 이미 `page.route`로 만든 가짜 API가 있다. 로그인, 글쓰기, 게시, 예약, 댓글을 서버 없이 흉내 낸다. 스크린샷용 테스트 파일을 하나 만들어, 테스트처럼 장면을 만든 뒤 테스트 대신 사진을 찍었다.

```ts
test.use({ viewport: { width: 1600, height: 1000 }, deviceScaleFactor: 2, reducedMotion: 'no-preference' });

test('임시 저장·게시 상태', async ({ page }) => {
	await fakeApi(page, { signedIn: true }); // 관리자로 들어온다
	const memo = await openMemo(page);
	// 게시한 글을 고치고, 새 메모를 쓰고, 다음 달로 예약한다
	// …
	await shot(page, memo, 'drafts-status.jpg');
});
```

- `deviceScaleFactor: 2`로 레티나 화면처럼 선명하게 찍는다
- E2E는 움직임을 끈 채(`reducedMotion: 'reduce'`) 돌리지만, 사진은 실제 모습이어야 해서 켠다
- 이 파일은 저장소에 넣지 않았다. CI에서 돌 필요가 없고, 찍은 이미지만 커밋한다

## 막힌 곳

### Dock 아이콘을 못 찾았다

처음에는 Dock에서 `'메모'`라는 이름의 단추를 눌렀는데 30초 동안 찾지 못하고 끝났다. 화면에는 "메모"라고 보이지만, Dock 단추의 접근성 이름은 앱 id(`memo`, `settings`)였다. 테스트 도우미(`dockItem(page, 'memo')`)가 이미 id로 찾고 있었는데, 스크린샷 코드를 새로 쓰면서 화면 글자로 찾은 게 잘못이었다.

### 계정 화면의 아바타가 깨졌다

로그인한 계정 화면을 찍었더니 아바타 자리에 깨진 이미지 표시가 떴다. 아바타는 `https://github.com/<계정>.png`에서 받는데, 사진을 찍는 환경에서는 바깥 요청이 막혀 있었다. 가짜 API처럼 이 주소도 가로채서, 미리 받아 둔 프로필 사진을 돌려주게 했다.

```ts
await page.route('https://github.com/*.png*', (route) =>
	route.fulfill({ path: 'avatar.png', contentType: 'image/png' })
);
```

### 메뉴가 창 밖에서 잘렸다

표 손잡이를 눌러 메뉴를 연 장면을 찍었더니 메뉴 오른쪽이 잘려 있었다. 메모 창의 기본 크기(900×600)에서는 열 메뉴가 창 오른쪽 끝을 넘는다. 실제로 쓸 때는 창을 키우면 그만이지만, 사진에서는 잘린 메뉴가 버그처럼 보인다.

찍기 전에 창 크기를 키우고, 창 전체 대신 **보여 주려는 부분만** 잘라서 찍었다.

```ts
await memo.evaluate((el) => {
	el.style.width = '1400px';
	el.style.height = '820px';
});
// 창 전체 대신 본문 쪽만, 아래 빈 곳은 잘라서
await shot(page, memo.locator('.memo-reader'), 'notes-table-handles.jpg', 300);
```

반대로 **넓어지는 검색 칸**은 창이 좁아야 의미가 있다. 넓은 창에서는 도구가 접히지 않아 보여 줄 게 없다. 그 사진만 기본 크기로 찍었다.

![표 손잡이](./images/notes-table-handles.jpg '창을 넓혀서 메뉴가 표를 가리지 않는 자리에 다 보이게 찍었다')

### 보여 줘야 할 표시가 목록 밖에 있었다

게시 상태 사진에는 "예약", 점, "임시 저장" 표시가 한 화면에 다 보여야 한다. 처음에는 오래된 글(9월 28일)을 고쳤더니, 그 글을 고르는 순간 목록이 그 글까지 스크롤되어 새 메모의 표시가 화면 밖으로 나갔다. **목록 맨 위의 오늘 글을 고치도록** 순서를 바꾸고, 찍기 직전에 목록을 맨 위로 올렸다.

### 이미지가 떴는지 확인하기

찍은 이미지를 글에 넣고, 빌드한 사이트에서 그 글을 열어 모든 `<img>`의 `naturalWidth`를 읽어 봤다. 첫 이미지만 값이 있고 나머지는 0이었다. 깨진 게 아니라 **지연 로딩**이었다. 화면 밖 이미지는 스크롤해서 가까워져야 불러온다. 이미지마다 `scrollIntoViewIfNeeded()`로 불러온 뒤 다시 읽으니 모두 제 크기가 나왔다.

### 브라우저 버전이 달랐다

사진을 찍는 환경에 설치된 Chromium이 Playwright가 기대하는 버전보다 오래됐다. `playwright install`로 받는 대신, 설정을 한 겹 덮어 이미 있는 브라우저를 쓰게 했다.

```ts
import base from './playwright.config';
export default {
	...base,
	use: { ...base.use, launchOptions: { ...base.use?.launchOptions, executablePath: '/opt/pw-browsers/chromium' } },
};
```

원래 설정은 그대로 두고 경로만 바꾸니, 사진을 찍고 나서 이 파일만 지우면 된다.

## 찍은 것

README의 데스크톱 화면, 로그인 전후 계정 화면, Swagger, 그리고 예전 글 네 편에 넣은 표 손잡이·찾기 막대·넓어지는 검색 칸·Safari 탭·게시 상태·폴더 메뉴·가가 메뉴까지 모두 같은 방법으로 찍었다.

좋았던 점은 세 가지다.

- **다시 찍기 쉽다.** 화면이 바뀌면 명령 한 번이면 된다
- **실제 데이터가 나오지 않는다.** 가짜 서버의 글과 댓글만 보인다
- **장면이 곧 사용 흐름이다.** 사진 한 장을 만들려고 적은 순서(글 고치기 → 새 메모 → 예약)가 그대로 관리자가 쓰는 순서라, 찍다가 어색한 곳이 보이면 그게 고칠 곳이다
