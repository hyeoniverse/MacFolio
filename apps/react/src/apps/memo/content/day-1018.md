## 보안 점검, UTM 집계, 롤백 훈련

기능 개발이 아닌 작업 세 가지를 진행했다. 공통점은 "문제가 없다고 가정하던 것"을 수치로 확인했다는 점이다.

| PR                                                       | 작업          | 결과                                                                       |
| -------------------------------------------------------- | ------------- | -------------------------------------------------------------------------- |
| [#252](https://github.com/hyeoniverse/MacFolio/pull/252) | SAST·SCA 점검 | Semgrep 7건 중 오탐 4건, 영향 없음 3건. ERROR 등급만 차단하는 CI 작업 추가 |
| [#253](https://github.com/hyeoniverse/MacFolio/pull/253) | UTM 집계      | 매체 표, 출처·매체·캠페인 조합 표, 조합별 일별 추이, 링크 생성기           |
| [#254](https://github.com/hyeoniverse/MacFolio/pull/254) | 롤백 훈련     | 헬스 체크에 실패하는 이미지를 배포하자 41초 만에 이전 버전으로 복구        |

### 보안 점검 ([#252](https://github.com/hyeoniverse/MacFolio/pull/252))

Semgrep(SAST, 코드 정적 분석), pnpm audit과 osv-scanner(SCA, 의존성 취약점 분석)를 실행했다. Semgrep이 보고한 7건 중 4건은 오탐, 3건은 실제 영향이 없는 코드였다. 영향이 없는 3건 중 2건은 `__proto__` 같은 이름을 폴더 이름으로 그대로 따라가던 코드여서, 해당 이름을 제외하도록 수정했다. ERROR 등급만 차단하는 Semgrep CI 작업을 추가했다([Semgrep과 SCA 도구로 점검하기](/memo/security-scan)).

osv-scanner와 함께 사용하려던 NVD API 키는 발급받지 못했다. 신청 양식을 제출해도 확인 메일이 오지 않고 화면이 멈췄으며, 알려진 해결 방법을 모두 시도해도 결과가 같았다. NVD 키 발급은 중단하고 해당 항목을 닫았다.

### UTM 집계 ([#253](https://github.com/hyeoniverse/MacFolio/pull/253))

활동 상태 보기에 매체 표, 출처·매체·캠페인 조합 표와 조합별 일별 추이, 관리자용 UTM 링크 생성기를 추가했다. 방문 시 읽은 `utm_*` 값은 `history.replaceState`로 주소창에서 삭제한다. 방문자가 UTM이 붙은 주소를 복사해 공유하면 같은 캠페인 방문이 중복 집계되고 링크를 배포한 곳도 함께 전달되기 때문이다([UTM 조합 표와 링크 생성기](/memo/utm-analytics)).

### 롤백 훈련 ([#254](https://github.com/hyeoniverse/MacFolio/pull/254))

배포 스크립트는 새 이미지가 헬스 체크를 통과하지 못하면 이전 버전으로 되돌리도록 작성되어 있었지만, 실제로 동작하는지 확인한 적은 없었다. 헬스 체크에 항상 실패하는 훈련용 이미지를 운영 서버에 배포해 확인했다([롤백 훈련](/memo/rollback-drill)).

훈련은 서버에서 수동으로 진행했다. 순서는 다음과 같다.

1. **훈련 전 상태 기록:** 현재 태그는 `sha-7e7eac0`, 컨테이너는 healthy, `/health`도 같은 버전을 응답했다. 이미 서버에 접속한 상태에서 `ssh <서버 접속 명령>` 줄까지 함께 붙여 넣어 문법 오류가 한 줄 출력됐지만, 나머지 명령은 정상 실행됐다

![훈련 전 서버 상태](./images/rollback-drill-server-before.jpg '훈련 전. API_TAG와 컨테이너 상태, /health 응답을 먼저 기록했다. 접속 주소는 마스킹했다')

2. **훈련용 이미지 배포:** 헬스 체크에 항상 실패하는 `sha-dead000` 이미지를 빌드해 올리고, GitHub Actions의 "API 배포" 워크플로를 그 태그로 수동 실행했다
3. **롤백 확인:** 워크플로는 3분 만에 실패로 종료됐고, 서버 로그에는 `09:04:53 이전 버전으로 되돌린다: sha-7e7eac0` 다음에 `09:05:34 배포 실패, 되돌림: sha-7e7eac0가 다시 떠 있다`가 기록됐다. 롤백에 걸린 시간은 41초다

![서버 로그의 되돌림](./images/rollback-drill-server-log.jpg '훈련 중 서버 로그. 새 이미지가 헬스 체크를 통과하지 못하자 41초 만에 이전 태그로 복구됐다')

4. **최종 상태 확인:** `watch docker compose ps`로 `sha-7e7eac0` 컨테이너가 healthy 상태로 유지되는 것을 확인하고 종료했다

```bash
cd ~/deploy
grep '^API_TAG=' .env                 # 훈련 전 태그 기록
docker compose ps api                 # (healthy) 확인
curl -s https://<API 주소>/health; echo
# 훈련용 이미지를 배포한 뒤
watch docker compose ps               # 이전 태그가 healthy로 유지되는지 확인
```

자세한 절차와 복구 방법은 [docs/rollback-drill.md](https://github.com/hyeoniverse/MacFolio/blob/main/docs/rollback-drill.md)와 [ops/deploy.sh](https://github.com/hyeoniverse/MacFolio/blob/main/ops/deploy.sh)에 있고, 헬스 체크는 [Docker의 HEALTHCHECK 문서](https://docs.docker.com/reference/dockerfile/#healthcheck)를 따랐다.

## Finder의 문서 폴더와 미리보기 앱

18시부터 Finder 작업을 시작했다. 이슈 [#8](https://github.com/hyeoniverse/MacFolio/issues/8)을 정리하며 설계를 정했다.

| 결정 사항      | 내용                                                                             |
| -------------- | -------------------------------------------------------------------------------- |
| 파일 저장 위치 | 저장소가 아니라 Cloudflare R2. 사이트 Worker가 같은 출처의 `/files/` 경로로 제공 |
| 폴더 구조      | 기존 저장소 Markdown 문서와 별도로 이력서·포트폴리오·자격증 폴더                 |
| 파일 열기      | PDF와 그림은 Finder 안이 아니라 별도의 미리보기 앱에서 연다                      |

그때까지 Finder의 문서 폴더에는 저장소의 Markdown 문서만 있었다. 이날 그 아래에 이력서·포트폴리오·자격증 폴더를 추가했다.

![Finder의 문서 폴더](./images/day-1018-finder-docs.jpg 'Finder의 문서 폴더. 이력서·포트폴리오·자격증 폴더를 이날 추가했다. 사이드바의 데스크탑·블로그는 다음 날 화면')

처음에는 PDF와 그림을 Finder 창 안에서 표시했다. 결과 화면을 보고 macOS처럼 별도의 미리보기 앱을 두기로 결정했고, 실제 미리보기 앱 수준으로 구현하는 데 필요한 범위를 검토한 뒤 착수했다.

- **18시 37분:** macOS처럼 별도 창으로 실행되는 미리보기 앱으로 이동
- **18시 53분:** 브라우저 내장 PDF 뷰어 대신 pdf.js로 페이지를 직접 렌더링. 페이지 썸네일, 검색, 텍스트 선택, 배율을 앱에서 직접 제어하기 위해서다

관리자의 파일 업로드 경로도 구현했다. 파일이 API 서버를 거치지 않고 R2로 직접 전송된다([Cloudflare R2 파일을 Worker가 같은 출처 /files/로 제공하기](/memo/finder-files)).

```text
브라우저 ── 폴더·이름·크기 ──▶ API: 관리자 세션, 파일 종류, 20MB 이하 확인
브라우저 ◀── 5분 유효한 서명 URL ── API
브라우저 ── 파일 본문 ──▶ R2 (API 서버를 거치지 않음)
```

이 작업은 [#255](https://github.com/hyeoniverse/MacFolio/pull/255)로 올렸고, 다음 날 새벽에 미리보기 앱을 보완한 뒤 머지했다.

## 음악 앱 버그 세 가지

마지막으로 음악 앱 버그 세 가지를 [#257](https://github.com/hyeoniverse/MacFolio/pull/257)로 수정했다([isRunning 정의와 React key·ref 함수 동일성이 일으킨 음악 앱 버그](/memo/music-player-fixes)).

| 증상                                                          |
| ------------------------------------------------------------- |
| 배경 음악이 재생 중인데 Dock의 음악 아이콘에 실행 표시가 없음 |
| 셔플을 누르면 재생 막대의 앨범 표지가 겹쳐 쌓임               |
| '지금 재생 중' 시트를 끝없이 아래로 스크롤할 수 있음          |

첫째 버그는 오래된 구조에서 비롯됐다. 창이 열려 있는지와 앱이 실행 중인지를 하나의 값으로 관리하는 구조가 2024년 10월의 첫 React 코드부터 있었다([2024년 10월 14일 회고](/memo/day-20241014)). 음악은 창이 없어도 배경 음악으로 재생될 수 있으므로 두 상태가 달라질 수 있는데, 값(`isRunning`)이 하나뿐이라 구분하지 못했다. 이날 두 상태를 별도의 값으로 분리했다.

| 하루 끝 main 기준       | 수치 | 전날 대비 |
| ----------------------- | ---: | --------: |
| 브라우저 E2E            |  446 |        +3 |
| 단위 시험 (화면 + core) |  625 |       +10 |
| contracts 단위 시험     |   46 |        +4 |
| API 단위 시험           |  167 |        +1 |
| API e2e                 |  129 |        +1 |
| main에 머지한 PR        |   10 |           |

수치는 그날 마지막 main 커밋(#254 머지)에서 `test(`·`it(` 호출을 집계한 값이다. 저녁의 Finder·음악 작업은 다음 날 머지되어 포함되지 않았다.

## 돌아보며

이날은 진행 중이던 작업을 마무리하는 날이었다. 열흘 동안 진행한 계획을 완료하고, 그동안 미뤄 둔 점검과 훈련을 진행했다. 리팩터링 PR은 화면을 변경하지 않아 검토할 항목이 적었고, 그래서 PR 여섯 개를 네 시간 남짓 만에 머지할 수 있었다.

저녁의 Finder 작업은 반대로 새 작업의 시작이었다. 첫 커밋은 Finder 창 안에서 PDF를 표시하는 방식이었는데, 37분 뒤 미리보기 앱으로 옮겼다. 이 사이트의 기준은 "macOS처럼"이다. macOS에서는 PDF를 Finder 안에서 읽지 않는다는 점을 먼저 확인했다면 첫 커밋부터 미리보기 앱으로 구현했을 것이다.
