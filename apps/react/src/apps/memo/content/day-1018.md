## 점검, 집계, 훈련

오후에는 기능이 아닌 일을 셋 했다.

- **SAST·SCA 점검** ([#252](https://github.com/hyeoniverse/MacFolio/pull/252)): Semgrep, pnpm audit, osv-scanner를 돌렸다. Semgrep의 7건은 오탐 4, 영향 없음 3이었다. 영향 없음 중 둘은 `__proto__` 같은 이름을 폴더 이름으로 따라가던 곳이라 걸러 냈다. ERROR만 막는 Semgrep CI 작업을 더했다([Semgrep과 SCA 도구로 점검하기](/memo/security-scan)).
- **UTM 집계** ([#253](https://github.com/hyeoniverse/MacFolio/pull/253)): 매체 표, 출처·매체·캠페인 조합 표와 조합별 일별 추이, 관리자용 링크 생성기를 더했다. 읽은 utm은 주소창에서 지운다([UTM 조합 표와 링크 생성기](/memo/utm-analytics)).
- **되돌리기 훈련** ([#254](https://github.com/hyeoniverse/MacFolio/pull/254)): 헬스 체크가 늘 실패하는 훈련용 이미지를 진짜 서버에 배포했다. 자동 배포는 41초 만에 이전 버전으로 돌아왔다([되돌리기 훈련](/memo/rollback-drill)).

### 되돌리기 훈련을 직접 해 보기

훈련은 서버에서 손으로 했다. 문서의 "훈련을 일으키는 방법"이 너무 짧아서 더 자세히 풀어 쓴 뒤, 그 순서대로 했다. 먼저 지금 상태를 적어 두었다. 서버에 이미 접속한 채로 `ssh <평소 쓰는 서버 접속>`까지 붙여 넣어 문법 오류가 한 줄 났지만, 나머지 명령은 돌았다. 지금 태그는 `sha-7e7eac0`, 컨테이너는 healthy, `/health`도 같은 버전을 돌려줬다.

![훈련 전 서버 상태](./images/rollback-drill-server-before.jpg '훈련 전. API_TAG와 컨테이너 상태, /health 응답을 먼저 적어 두었다. 접속 주소는 가렸다')

그다음 헬스 체크가 늘 실패하는 `sha-dead000` 이미지를 만들어 올리고, Actions의 "API 배포"를 그 태그로 수동 실행했다. 워크플로는 3분 만에 실패로 끝났고, 서버 로그에는 `09:04:53 이전 버전으로 되돌린다: sha-7e7eac0` 뒤에 `09:05:34 배포 실패, 되돌림: sha-7e7eac0가 다시 떠 있다`가 찍혔다. 41초다.

![서버 로그의 되돌림](./images/rollback-drill-server-log.jpg '훈련 중 서버 로그. 새 이미지가 건강 확인을 통과하지 못하자 41초 만에 이전 태그로 돌아왔다')

마지막으로 `watch docker compose ps`로 `sha-7e7eac0`이 healthy로 남아 있는 것을 보고 끝냈다.

```bash
cd ~/deploy
grep '^API_TAG=' .env                 # 훈련 전 태그 적어 두기
docker compose ps api                 # (healthy) 확인
curl -s https://<API 주소>/health; echo
# 훈련용 이미지를 배포한 뒤
watch docker compose ps               # 이전 태그가 healthy로 남는지
```

자세한 절차와 되돌리는 법은 [docs/rollback-drill.md](https://github.com/hyeoniverse/MacFolio/blob/main/docs/rollback-drill.md)와 [ops/deploy.sh](https://github.com/hyeoniverse/MacFolio/blob/main/ops/deploy.sh)에 있고, 헬스 체크는 [Docker의 HEALTHCHECK 문서](https://docs.docker.com/reference/dockerfile/#healthcheck)를 따랐다.

SCA 점검 중에는 osv-scanner와 함께 쓰려던 NVD API 키를 받으려 했는데, 신청 폼을 채우고 제출해도 메일이 오지 않고 화면이 멈췄다. 찾아본 방법을 다 해 봐도 안 돼서, NVD 키를 받는 일은 그만두고 그 항목은 닫았다.

셋 다 "있다고 믿던 것"을 확인하는 일이었다. 보안 문제가 없다고 믿었고, 배포가 실패하면 되돌아간다고 믿었다. 이날 숫자로 확인했다.

## Finder의 문서 폴더

저녁 여섯 시부터는 Finder를 손봤다. 이슈 [#8](https://github.com/hyeoniverse/MacFolio/issues/8)을 정리하며 정할 것을 골랐다. 파일은 R2에, 폴더는 문서와 따로, 그림은 Finder 미리보기로 열기로. 그때까지 Finder의 문서는 저장소의 Markdown 문서뿐이었다. 그 아래에 이력서·포트폴리오·자격증 폴더를 두고, 파일은 저장소가 아니라 Cloudflare R2에 두기로 했다. 사이트 Worker가 같은 주소(`/files/`)로 내준다.

![Finder의 문서 폴더](./images/day-1018-finder-docs.jpg 'Finder의 문서. 이력서·포트폴리오·자격증 폴더가 이날 생겼다. 사이드바의 데스크탑·블로그는 다음 날 모습')

PDF와 그림은 처음에는 Finder 안에서 보여 줬다. Finder 안에서 보이는 것을 보고 진짜 Mac처럼 미리보기 앱을 따로 두기로 했고, 진짜 미리보기 앱처럼 만드는 게 얼마나 어려운지 따져 본 뒤 범위를 정했다. 18시 37분에 macOS처럼 따로 뜨는 미리보기 앱으로 옮겼고, 18시 53분에는 브라우저의 PDF 보기 대신 pdf.js로 쪽을 직접 그리게 했다. 쪽 그림, 찾기, 글자 고르기, 배율을 앱이 직접 다루기 위해서다.

관리자가 파일을 올리는 길도 만들었다. 브라우저가 API에 폴더·이름·크기를 묻고, API가 관리자 세션과 종류, 20MB 이하를 확인한 뒤 R2에 바로 올릴 5분짜리 서명 주소를 준다. 파일이 API 서버를 거치지 않는다([Finder의 이력서 PDF와 그림을 미리보기 앱으로](/memo/finder-files)). 이 작업은 [#255](https://github.com/hyeoniverse/MacFolio/pull/255)로 올렸고, 다음 날 새벽에 미리보기를 더 다듬은 뒤 머지했다.

## 음악 앱 버그 셋

마지막으로 음악 앱 버그 셋을 [#257](https://github.com/hyeoniverse/MacFolio/pull/257)로 고쳤다. 배경 음악이 나오는데 음악 앱이 꺼진 것으로 보였고, 셔플을 누르면 재생 막대의 표지가 쌓였고, 지금 재생 중 시트가 끝없이 내려갔다([음악 앱 버그 세 가지](/memo/music-player-fixes)).

첫째 버그의 뿌리는 오래되었다. 창이 열려 있는지와 앱이 실행 중인지를 한 값에 담는 구조는 2024년 10월의 첫 React 코드부터 있었다([2024년 10월 14일 회고](/memo/day-20241014)). 이날 둘을 나눴다.

| 이날 끝                 | 숫자 | 전날보다 |
| ----------------------- | ---: | -------: |
| 브라우저 E2E            |  446 |       +3 |
| 단위 시험 (화면 + core) |  625 |      +10 |
| contracts 단위 시험     |   46 |       +4 |
| API 단위 시험           |  167 |       +1 |
| API e2e                 |  129 |       +1 |
| main에 머지한 PR        |   10 |          |

숫자는 그날 마지막 main 커밋(#254 머지)에서 `test(`·`it(` 호출을 센 값이다. 저녁의 Finder·음악 작업은 다음 날 머지되어 여기에 들어 있지 않다.

## 돌아보며

이날은 닫는 날이었다. 열흘짜리 계획을 닫고, 그동안 미뤄 둔 점검과 훈련을 했다. 정리 PR은 화면을 바꾸지 않으니 리뷰할 것이 적었고, 그래서 PR 일곱 개가 네 시간 남짓 만에 들어갔다.

저녁의 Finder는 반대로 여는 일이었다. 첫 커밋은 Finder 안에서 PDF를 보여 주는 것이었는데, 37분 뒤에 미리보기 앱으로 옮겼다. 이 사이트는 "macOS처럼"이 기준이다. macOS에서 PDF를 Finder 안에서 읽지 않는다는 것을 먼저 떠올렸다면 첫 커밋부터 미리보기 앱이었을 것이다.
