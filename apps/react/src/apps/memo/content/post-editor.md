폴더 정리를 붙이고 나니 "글쓰기 버튼은 어디 있냐"는 말을 들었다. 맞는 말이었다. 관리자로 로그인했는데 글을 쓸 수도, 오타 하나 고칠 수도 없었다.

![관리자가 보는 글](./images/memo-editor.jpg '관리자로 로그인하면 글이 곧 편집기다. 제목도 본문도 보이는 그대로 고친다')

## 파일은 그대로, 서버 글을 겹친다

지금까지의 글은 저장소의 Markdown 파일이다. 이걸 DB로 옮기지 않고, 정리 내용과 같은 방식으로 **겹치기로** 했다.

- 새로 쓴 글은 서버에만 있다. 주소는 날짜와 짧은 무작위 문자(`2026-09-29-a1b2c3`)라 한글 제목도 주소가 깨지지 않는다
- 저장소의 글을 고치면 **같은 주소로** 서버에 저장된다. 목록에서는 서버 글이 파일을 대신한다
- 저장소의 글을 지우면 파일은 남아 있으니 **지운 표시**를 서버에 남긴다. 표시가 있으면 목록에서 뺀다

```ts
for (const item of server) {
	if (item.deleted)
		bySlug.delete(item.slug); // 지운 글은 가린다
	else bySlug.set(item.slug, toPost(item)); // 고친 글은 대신하고, 새 글은 더한다
}
```

이렇게 하면 서버가 내려가 있어도 저장소의 글은 그대로 보인다. 서버는 "무엇이 바뀌었는지"만 들고 있다.

## API

```text
GET    /posts         누구나: 서버의 글과 지운 표시
POST   /posts         관리자: 새 글
PUT    /posts/:slug   관리자: 고치기 (서버에 없던 저장소 글이면 새로 만든다)
DELETE /posts/:slug   관리자: 지운 표시
```

제목 1~100자, 실제로 있는 날짜(2월 30일은 거절), 폴더 3단까지, 요약 200자, 본문 5만 자까지를 서버에서 검사한다. 어긴 규칙은 모두 모아 돌려주고, 편집 화면은 그대로 보여 준다.

## 편집 단추 없이, 보이는 그대로

처음에는 편집 단추를 누르면 제목·날짜·폴더·요약·본문 칸이 있는 편집 화면으로 바뀌고, 저장 단추를 누르는 방식이었다. 동작은 했지만 메모 앱답지 않았다. macOS 메모에는 편집 단추도 저장 단추도 없다. 보고 있는 글을 누르면 그대로 고쳐지고, 알아서 저장된다.

그래서 관리자에게는 **글이 곧 편집기**가 되게 바꿨다.

- 제목은 제목 자리에서, 본문은 제목·굵게·목록·코드·표가 **보이는 모양 그대로** 고친다. 편집기는 [Milkdown](https://milkdown.dev)을 쓰고, 저장은 지금처럼 Markdown으로 한다
- 날짜와 폴더는 제목 위 한 줄에서 누르면 바뀐다. 달력은 브라우저 기본 달력 대신 사이트 모양으로 만들었다
- 고치고 0.8초 멈추면 저장한다. 제목이나 본문이 비면 저장하지 않고 그 이유를 같은 줄에 보여 준다
- 새 메모는 누르자마자 빈 메모가 열리고 제목에 커서가 간다. 제목에서 Enter를 누르면 본문으로 넘어간다. 처음 저장할 때 주소가 생기고, 그 뒤로는 같은 글을 고친다

편집기는 관리자에게만 필요하므로 처음 쓸 때 따로 불러온다(`React.lazy`). 방문자가 받는 파일 크기는 그대로다.

### 보이는 그대로 고칠 때 신경 쓴 것

- **열기만 해서는 저장하지 않는다.** 편집기가 Markdown을 다시 쓰면 공백이나 기호가 조금 달라질 수 있어서, 실제로 고쳤을 때만 저장한다
- **이미지 경로.** 저장소 글의 이미지는 `./images/a.jpg`처럼 글 파일 기준 경로라 편집기 안에서는 보이지 않는다. 편집기에 넣을 때 빌드된 주소로 바꾸고, 저장할 때 원래 경로로 되돌린다
- **새 메모가 처음 저장될 때 편집기가 다시 그려지지 않게.** 새 메모에는 주소가 없다가 저장하면서 생긴다. 주소로 편집기를 구분하면 그 순간 편집기가 새로 그려져 커서가 날아간다. 새 메모의 편집기 이름을 기억해 두고 주소가 생긴 뒤에도 그 이름을 쓴다
- **저장은 차례로.** 빠르게 고치면 요청이 뒤바뀌어 도착해 예전 내용이 이길 수 있어서 한 줄로 세워 보낸다. 다른 글로 옮겨 가면 남은 편집을 바로 보낸다

필수 항목(제목·날짜·폴더·본문)은 화면에서 먼저 막고, API도 같은 규칙으로 400을 돌려주고, DB에도 CHECK 제약을 걸어 둘을 거치지 않은 쓰기까지 막는다.

## 로그인했는지 보이게

"로그인했는데 단추가 안 보인다"는 것이 로그인 문제인지 기능이 없는 것인지 헷갈렸다. 그래서 관리자로 로그인하면 메모 도구 막대에 **관리자** 표시가 붙게 했다. 표시가 없으면 로그인 쪽을, 있으면 기능 쪽을 보면 된다.
