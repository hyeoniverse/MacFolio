폴더 정리를 붙이고 나니 "글쓰기 버튼은 어디 있냐"는 말을 들었다. 맞는 말이었다. 관리자로 로그인했는데 글을 쓸 수도, 오타 하나 고칠 수도 없었다.

![관리자가 보는 글](./images/memo-editor.jpg '관리자로 로그인하면 글이 곧 편집기다. 제목도 본문도 보이는 그대로 고친다')

## 파일은 그대로, 서버 글을 겹친다

지금까지의 글은 저장소의 Markdown 파일이다. 이걸 DB로 옮기지 않고, 정리 내용과 같은 방식으로 **겹치기로** 했다.

- 새로 쓴 글은 서버에만 있다. 주소는 날짜와 짧은 무작위 문자(`2026-09-29-a1b2c3`)라 한글 제목도 주소가 깨지지 않는다
- 저장소의 글을 고치면 **같은 주소로** 서버에 저장된다. 목록에서는 서버 글이 파일을 대신한다
- 저장소의 글을 지우면 파일은 남아 있으니 **지운 표시**를 서버에 남긴다. 표시가 있으면 목록에서 뺀다

```ts
for (const item of server) {
	if (item.deleted)
		bySlug.delete(item.slug); // 지운 글은 가린다
	else bySlug.set(item.slug, toPost(item)); // 고친 글은 대신하고, 새 글은 더한다
}
```

이렇게 하면 서버가 내려가 있어도 저장소의 글은 그대로 보인다. 서버는 "무엇이 바뀌었는지"만 들고 있다.

## API

```text
GET    /posts         누구나: 서버의 글과 지운 표시
POST   /posts         관리자: 새 글
PUT    /posts/:slug   관리자: 고치기 (서버에 없던 저장소 글이면 새로 만든다)
DELETE /posts/:slug   관리자: 지운 표시
```

> 이 API는 뒤에 임시 저장·게시·버전 기록으로 바뀌었다. 저장하면 바로 공개되던 문제를 풀면서다 ('바로 고치는 블로그에 임시 저장과 버전 기록 붙이기').

제목 1~100자, 실제로 있는 날짜(2월 30일은 거절), 폴더 3단까지, 요약 200자, 본문 5만 자까지를 서버에서 검사한다. 어긴 규칙은 모두 모아 돌려주고, 편집 화면은 그대로 보여 준다.

## 편집 단추 없이, 보이는 그대로

처음에는 편집 단추를 누르면 제목·날짜·폴더·요약·본문 칸이 있는 편집 화면으로 바뀌고, 저장 단추를 누르는 방식이었다. 동작은 했지만 메모 앱답지 않았다. macOS 메모에는 편집 단추도 저장 단추도 없다. 보고 있는 글을 누르면 그대로 고쳐지고, 알아서 저장된다.

그래서 관리자에게는 **글이 곧 편집기**가 되게 바꿨다.

- 제목은 제목 자리에서, 본문은 제목·굵게·목록·코드·표가 **보이는 모양 그대로** 고친다. 편집기는 [Milkdown](https://milkdown.dev)을 쓰고, 저장은 지금처럼 Markdown으로 한다
- 날짜와 폴더는 제목 위 한 줄에서 누르면 바뀐다. 달력은 브라우저 기본 달력 대신 사이트 모양으로 만들었다. 화살표만 있으면 몇 년 전 날짜로 가기가 번거로워서, 위의 '2026년 9월'을 누르면 월을, 한 번 더 누르면 연도(12년씩)를 한 번에 고르게 했다
- 고치고 0.8초 멈추면 저장한다(지금은 임시 저장). 제목이나 본문이 비면 저장하지 않고 그 이유를 같은 줄에 보여 준다
- 새 메모는 누르자마자 빈 메모가 열리고 제목에 커서가 간다. 제목에서 Enter를 누르면 본문으로 넘어간다. 처음 저장할 때 주소가 생기고, 그 뒤로는 같은 글을 고친다

편집기는 관리자에게만 필요하므로 처음 쓸 때 따로 불러온다(`React.lazy`). 방문자가 받는 파일 크기는 그대로다.

### 보이는 그대로 고칠 때 신경 쓴 것

- **열기만 해서는 저장하지 않는다.** 편집기가 Markdown을 다시 쓰면 공백이나 기호가 조금 달라질 수 있어서, 실제로 고쳤을 때만 저장한다
- **이미지 경로.** 저장소 글의 이미지는 `./images/a.jpg`처럼 글 파일 기준 경로라 편집기 안에서는 보이지 않는다. 편집기에 넣을 때 빌드된 주소로 바꾸고, 저장할 때 원래 경로로 되돌린다
- **새 메모가 처음 저장될 때 편집기가 다시 그려지지 않게.** 새 메모에는 주소가 없다가 저장하면서 생긴다. 주소로 편집기를 구분하면 그 순간 편집기가 새로 그려져 커서가 날아간다. 새 메모의 편집기 이름을 기억해 두고 주소가 생긴 뒤에도 그 이름을 쓴다
- **저장은 차례로.** 빠르게 고치면 요청이 뒤바뀌어 도착해 예전 내용이 이길 수 있어서 한 줄로 세워 보낸다. 다른 글로 옮겨 가면 남은 편집을 바로 보낸다

### 서식 도구 막대

단축키(⌘B 등)만으로는 머리말이나 체크리스트를 넣는 법이 보이지 않는다. macOS 메모의 도구 막대처럼 **가가**(서식) 단추와 체크리스트·표·이미지 단추를 메모 도구 막대에 두었다.

- 가가 메뉴에는 굵게·기울임·취소선·코드와 제목·머리말·부머리말·본문·모노 스타일, 목록 세 가지, 블록 인용, 표 넣기, 이미지 넣기가 있다. 커서가 있는 곳의 서식에 체크가 붙는다
- 메뉴를 누를 때 편집기의 커서를 빼앗지 않게 `pointerdown`의 기본 동작을 막는다. 그래야 서식이 커서 자리에 바로 들어간다
- 창이 좁으면 체크리스트·표·이미지 단추는 숨고 가가 메뉴 하나에 모인다
- 체크리스트 항목은 앞의 동그라미를 누르면 체크된다. 저장하면 `- [x] 할 일`이 된다

![가가 메뉴](./images/editor-format-menu.jpg '가가 메뉴. 커서가 체크리스트 안에 있어서 체크리스트에 표시가 붙었다')

도구 막대는 편집기 바깥(창 위)에 있어서, 둘을 작은 저장소로 이었다. 편집기는 커서 자리의 서식과 명령을 실행할 함수를 알리고, 도구 막대는 그걸 보고 그린다.

처음에는 머리말을 골라도 메뉴의 체크가 '본문'에 머물렀다. 편집기가 명령 함수를 알리는 `useEffect`가 `useEditor`의 `get`에 걸려 있었는데, `get`이 렌더링마다 새 함수라 effect가 매번 다시 돌았다. 정리 함수가 서식 상태를 빈 값으로 되돌리니, 알린 서식이 곧바로 지워졌다. 명령 함수는 처음 한 번만 알리고 `get`은 ref로 읽게 고쳤다.

### 표 고치기

표는 넣을 수는 있었지만 고치기가 어려웠다. 편집기의 기본 동작 몇 가지가 걸렸다.

- 표를 넣으면 커서가 표 **앞 문단에** 남았다. 바로 글자를 치면 표 밖에 써지고, Tab을 누르면 편집기 밖으로 나갔다. 넣은 뒤 머리글 첫 칸으로 커서를 옮긴다
- 칸 안에서 Enter를 누르면 **표를 빠져나갔다.** Markdown 표의 칸에는 줄을 바꿀 수 없으니, 스프레드시트처럼 아래 칸으로 가게 하고 마지막 행이면 행을 하나 넣는다. 마지막 칸에서 Tab을 눌러도 행이 생긴다
- 행·열을 넣고 지울 단추가 없었다. 커서가 표 안에 있으면 표 단추가 **표 편집** 메뉴가 된다. 위·아래 행 추가, 왼쪽·오른쪽 열 추가, 행·열 삭제, 열 정렬, 표 삭제가 있고, 메뉴를 연 채로 다른 칸을 눌러 가며 고칠 수 있다

Markdown 표는 머리글 한 행과 본문 한 행 이상이 있어야 한다. 그래서 머리글 행, 마지막 남은 본문 행, 마지막 열은 지울 수 없게 메뉴에서 꺼 둔다. 표를 없애려면 표 삭제를 쓴다.

### 이미지 올리기와 파일 첨부

이미지는 주소로만 넣을 수 있었다. 이제 **파일에서 고르거나, 붙여넣거나(스크린샷), 끌어다 놓으면** API에 올리고 그 자리에 넣는다. 클립 단추로는 아무 파일이나 첨부한다. 첨부 파일은 파일 이름을 글자로 한 링크가 되고, 링크 제목(`"첨부 파일 · 2 KB"`)으로 알아봐서 읽기·편집 화면 모두 같은 카드 모양으로 그린다.

올린 파일은 DB에 바로 둔다. 배포할 곳이 정해지지 않았고, 서버 디스크는 배포 환경에 따라 다시 시작하면 사라질 수 있어서다. 한 파일은 10MB까지이고, API·DB CHECK 제약 둘 다에서 막는다.

올린 파일은 누구나 받을 수 있으니, 받는 쪽에서 스크립트로 실행되지 않게 했다.

- **이미지인지는 파일 앞부분(매직 넘버)으로 판단한다.** 브라우저가 보낸 형식 이름은 믿지 않는다. PNG·JPEG·GIF·WebP만 이미지로 보고, SVG는 스크립트를 담을 수 있어서 이미지로 보지 않는다
- 이미지가 아닌 파일은 `Content-Disposition: attachment`로 내려받게만 하고, `X-Content-Type-Options: nosniff`와 `Content-Security-Policy: sandbox`를 붙인다. HTML 파일을 올려도 API 주소에서 열리지 않는다
- helmet의 기본값 `Cross-Origin-Resource-Policy: same-origin`이면 다른 주소(사이트)의 `<img>`가 이미지를 못 불러온다. 파일 응답에만 `cross-origin`으로 연다
- multer는 파일 이름을 latin1로 읽어서 한글 이름이 깨진다. UTF-8로 다시 읽고, 내려받을 때는 `filename*=UTF-8''…`로 돌려준다

### 이미지를 블록으로, 표에 손잡이를

써 보니 둘 다 아직 불편했다.

- **이미지 옆에 이상한 입력 자리가 생겼다.** Markdown에서 이미지는 글줄 안의 요소라, 이미지만 있는 문단에도 이미지 앞뒤로 커서 자리가 있었다. 이미지를 누르고 →를 눌러 글을 쓰면 **앞 문단**에 써지기도 했고, 글이 이미지로 끝나면 그 아래에 이어 쓸 수 없었다. 이미지 하나만 있는 문단은 편집기 안에서 **이미지 블록**으로 바꿔 다루고, 저장할 때는 다시 `![설명](주소 "캡션")` 한 줄로 쓴다. Milkdown에도 이미지 블록이 있지만 비율을 설명(alt) 자리에 저장해서 쓰지 않았다. 글 끝에는 늘 빈 문단을 둬서 이어 쓸 수 있다
- **파일로 고른 이미지에 설명을 쓸 수 없었다.** 고르자마자 올려서 넣었기 때문이다. 이제 어디서 가져오든(내 파일, 주소, Unsplash, Pexels) 먼저 미리 보고 설명과 캡션을 쓴 뒤 넣는다. 넣은 이미지를 고르면 이미지 단추가 '이미지 편집'이 되어 설명·캡션을 고칠 수 있다
- **표는 어느 칸에 있는지 보이지 않았다.** 읽기 화면처럼 가로줄만 있어서 빈 칸이 보이지 않았다. 커서가 있는 표에만 칸 선과 지금 칸의 옅은 배경을 그리고, macOS 메모처럼 지금 열 위와 지금 행 왼쪽에 **손잡이**를 둔다. 손잡이를 누르면 그 열·행만 고치는 메뉴가 열린다. 선은 자리를 차지하지 않는 그림자로 그려서 표 크기는 읽기 화면과 같다

표를 고치면 편집기가 모든 열을 왼쪽 정렬(`:--`)로 써서 목록 미리 보기에 `:`가 남았다. 왼쪽 정렬은 정렬 없음과 똑같이 보이니 저장할 때 `---`로 되돌린다.

### Unsplash, Pexels에서 사진 찾기

이미지 넣기 창에서 Unsplash와 Pexels를 바로 찾는다. 두 API 키는 서버(API)에만 두고, 화면은 API에 검색을 부탁한다. 키가 없으면 그 서비스 탭에 어떤 환경 변수를 채우면 되는지 보여 준다.

두 서비스의 API 가이드라인에 맞췄다.

- 사진가와 서비스를 밝힌다. 캡션을 `사진: [이름](주소), [Unsplash](주소)`로 채워 두는데, 캡션 안의 `[글자](https://…)`는 두 화면 모두 링크로 그린다
- Unsplash는 사진 주소를 그대로 쓰고(핫링크), 링크에 `utm_source`를 붙이고, 사진을 넣으면 '내려받음'을 알린다

### 코드 복사 단추

코드 블록 오른쪽 위에 복사 단추를 달았다. 읽기 화면과 편집기 모두 같은 자리, 같은 모양이다. 올리면 보이고, 터치 기기에서는 늘 보인다.

### 편집 화면과 읽기 화면을 똑같이

관리자는 편집기로, 방문자는 읽기 화면으로 같은 글을 본다. 둘이 다르게 보이면 "보이는 그대로 고친다"는 말이 틀린 게 된다. 눈으로 비교하는 대신 두 화면에서 **문단마다 위치와 높이를 재서** 비교했다.

- **문단 사이 간격이 달랐다.** 읽기 화면은 `.memo-markdown > * + *`로 간격을 주는데, 편집기의 문단은 한 단계 안쪽(`.ProseMirror`)에 있어서 이 규칙을 받지 못했다. 같은 규칙을 편집기에도 걸었더니 이번엔 머리말 위 간격이 줄었다. 새 규칙의 우선순위(클래스 2개)가 `.memo-markdown h2`(클래스 1개 + 태그)보다 높아서 머리말의 큰 간격을 덮은 것이다. `:where(.ProseMirror)`로 우선순위를 읽기 화면 규칙과 같게 맞췄다
- **이미지 문단이 80px 더 높았다.** 편집기는 커서를 놓을 자리로 이미지 앞뒤에 빈 요소를 넣는데, 이게 빈 줄을 두 개 만들었다. 이미지 문단에서는 숨긴다. 이미지 모양(가운데, 둥근 모서리, 아래 캡션)도 읽기 화면과 같은 구조로 그린다
- 코드 블록 강조는 읽기 화면과 같은 lowlight로 칠하고, 체크 항목은 읽기 화면도 편집기와 같은 동그라미로 바꿨다. 제목 위 '날짜 · 폴더' 줄도 저장 상태를 오른쪽 끝으로 빼서 가운데가 밀리지 않게 했다

지금은 네 글에서 모든 문단의 위치와 높이가 두 화면에서 같다.

필수 항목(제목·날짜·폴더·본문)은 화면에서 먼저 막고, API도 같은 규칙으로 400을 돌려주고, DB에도 CHECK 제약을 걸어 둘을 거치지 않은 쓰기까지 막는다.

## 로그인했는지 보이게

"로그인했는데 단추가 안 보인다"는 것이 로그인 문제인지 기능이 없는 것인지 헷갈렸다. 그래서 관리자로 로그인하면 메모 도구 막대에 **관리자** 표시가 붙게 했다. 표시가 없으면 로그인 쪽을, 있으면 기능 쪽을 보면 된다.
