데이터베이스 기초 연재의 두 번째 글로, 3장(데이터베이스 시스템의 구성)을 다룬다. [앞 글](/memo/db-dbms-data-independence)에서 DBMS의 목적이 사상(mapping)으로 구현하는 데이터 독립성이라고 했는데, 이 글은 그 구조를 구체적으로 정리한다.

## 데이터베이스 시스템의 구성 요소

데이터베이스 시스템(database system)은 데이터를 데이터베이스로 저장·관리해 정보를 생성하는 컴퓨터 중심 시스템이다. 구성 요소는 여섯 가지다.

| 구성 요소           | 내용                                                      |
| ------------------- | --------------------------------------------------------- |
| 3단계 데이터베이스  | 외부·개념·내부 단계로 표현한 데이터베이스                 |
| 데이터 언어         | DDL, DML, DCL                                             |
| 사용자              | 일반 사용자, 응용 프로그래머, DBA                         |
| DBMS                | 데이터베이스를 관리하고 사용자 요청을 수행하는 소프트웨어 |
| DBA                 | 데이터베이스 시스템 전체를 책임지는 특수한 사용자         |
| 데이터베이스 컴퓨터 | 데이터베이스 처리 전용 하드웨어(선택)                     |

## 3단계 데이터베이스와 스키마

데이터베이스는 보는 관점에 따라 세 단계로 표현한다.

| 단계                        | 관점                       | 스키마                  | 내용                                                                                |
| --------------------------- | -------------------------- | ----------------------- | ----------------------------------------------------------------------------------- |
| 외부 단계(external level)   | 개별 사용자(응용 프로그램) | 외부 스키마(서브스키마) | 사용자 관점에서 정의한 전체 데이터베이스의 논리적 일부. 응용마다 여러 개            |
| 개념 단계(conceptual level) | 기관 전체                  | 개념 스키마(스키마)     | 모든 응용에 대한 통합 데이터 구조. 시스템 전체에 하나                               |
| 내부 단계(internal level)   | 저장 장치                  | 내부 스키마             | 개념 스키마의 저장 구조(storage structure). 저장 장치가 필요로 하는 정보를 추가한다 |

**스키마(schema)** 는 데이터베이스의 구조(개체, 관계)와 제약조건(constraints)을 명세한 것이다.

![3단계 데이터베이스 구조와 두 사상](./images/db-three-level-schema-mapping.svg '외부 스키마는 응용마다, 개념·내부 스키마는 하나씩 있다')

학생 데이터베이스를 예로 들면, 성적 처리 프로그램의 외부 스키마는 학번·이름·성적만, 학적 프로그램의 외부 스키마는 학번·이름·학과만 가져간다. 개념 스키마에는 학생 개체의 모든 애트리뷰트가 정의되고, 내부 스키마에는 레코드 길이, 필드 오프셋, 인덱스 같은 저장 정보가 더해진다. ==세 스키마는 달라 보이지만 모두 "학생"이라는 하나의 개체를 위해 정의된 것이며, 사상으로 연결된다.==

### 단계 간의 사상

| 사상           | 정의하는 것                           | 다른 이름                              | 제공하는 독립성      |
| -------------- | ------------------------------------- | -------------------------------------- | -------------------- |
| 외부/개념 사상 | 외부 스키마와 개념 스키마의 대응 관계 | 응용 인터페이스(application interface) | 논리적 데이터 독립성 |
| 개념/내부 사상 | 개념 스키마와 내부 스키마의 대응 관계 | 저장 인터페이스(storage interface)     | 물리적 데이터 독립성 |

개념 스키마에 애트리뷰트를 추가해도 외부/개념 사상만 고치면 외부 스키마와 응용 프로그램은 그대로다(논리적 독립성). 인덱스를 추가하거나 저장 장치를 바꿔도 개념/내부 사상만 고치면 개념 스키마는 그대로다(물리적 독립성).

### 카탈로그와 데이터 디렉터리

스키마는 컴파일되어 카탈로그에 저장된다. 스키마를 그림으로 표현한 것을 스키마 다이어그램(schema diagram)이라 한다.

|           | 카탈로그(catalog)                                                    | 데이터 디렉터리(data directory)              |
| --------- | -------------------------------------------------------------------- | -------------------------------------------- |
| 저장 내용 | 시스템 안의 모든 객체에 대한 정의와 명세                             | 저장된 데이터를 참조하는 데 필요한 위치 정보 |
| 다른 이름 | 시스템 데이터베이스, 메타 데이터베이스, 데이터 사전(data dictionary) |                                              |
| 사용 주체 | 사용자와 시스템 모두. DBA의 관리 도구                                | 시스템만                                     |

==카탈로그는 "데이터에 관한 데이터"인 메타데이터를 저장한다.== 카탈로그 자체도 테이블이라 사용자가 SQL로 조회할 수 있다.

## 데이터 언어

데이터 언어는 데이터베이스를 정의·조작·제어하기 위해 시스템과 통신하는 수단이다.

### 데이터 정의어(DDL)

DDL(Data Definition Language)은 데이터베이스 구조를 정의하고 변경한다. 정의하는 내용은 다음과 같다.

- 논리적 데이터 구조: 개념 스키마와 외부 스키마
- 물리적 데이터 구조: 내부 스키마. 이 부분을 정의하는 언어를 데이터 저장 정의어(Data Storage Definition Language)라 한다
- 논리적 구조와 물리적 구조 사이의 사상

### 데이터 조작어(DML)

DML(Data Manipulation Language)은 사용자(응용 프로그램)와 DBMS 사이의 통신 수단으로, 검색·삽입·삭제·변경 연산의 집합이다.

|           | 절차적 DML                                                  | 비절차적 DML                                     |
| --------- | ----------------------------------------------------------- | ------------------------------------------------ |
| 수준      | 저급 데이터 언어                                            | 고급 데이터 언어                                 |
| 명세      | 무엇을(what)과 어떻게(how)                                  | 무엇을(what)만. 어떻게는 시스템에 맡긴다(선언적) |
| 처리 단위 | 한 번에 레코드 하나(one record at a time)                   | 한 번에 레코드 집합(set of records at a time)    |
| 사용 방식 | 응용 프로그램에 삽입(embedded)되어 DML 예비 컴파일러가 처리 | 독립적·대화식으로 쓰는 질의어(query language)    |

호스트 프로그램 속에 삽입되어 쓰이는 DML을 데이터 부속어(DSL, Data Sublanguage)라 하며, 절차적일 수도 비절차적일 수도 있다. 사용자가 원하는 어떤 객체든 추출하고 어떤 관계든 표현할 수 있는 능력을 데이터 언어의 완전성(completeness)이라 한다.

### 데이터 제어어(DCL)

DCL(Data Control Language)은 공용 데이터베이스를 관리하기 위해 데이터 제어를 정의한다. 여러 사용자가 함께 써도 각자 혼자 쓰는 것처럼 정확하게 동작하게 하는 것이 목적이며, 주로 DBA가 사용한다.

- 데이터 보안(security): 로그인과 권한 검사
- 데이터 무결성(integrity): 검색 결과의 정확성
- 데이터 회복(recovery)
- 병행 수행(concurrency): 여러 사용자의 동시 접근

## 사용자

| 사용자                | 사용하는 언어          | 접근 방식                                                            |
| --------------------- | ---------------------- | -------------------------------------------------------------------- |
| 일반 사용자(end user) | 비절차적 DML(질의어)   | 메뉴, 폼, 그래픽 인터페이스로 삽입·삭제·갱신·검색                    |
| 응용 프로그래머       | 호스트 언어 + DML(DSL) | PL/I, COBOL, Pascal, C, Java 같은 호스트 언어로 작성한 응용 프로그램 |
| DBA                   | DDL, DCL               | 데이터베이스를 정의하고 제어                                         |

## DBMS의 처리 과정과 구성 요소

DBMS는 사용자 요청을 다음 순서로 처리한다.

1. 사용자의 접근 요청(access request)을 접수하고 분석한다.
2. 요청을 시스템이 이해하는 형태로 변환(transform)한다.
3. 외부·개념·내부·저장 구조 사이의 사상을 수행해 저장 데이터에 접근한다.
4. 저장 데이터베이스에 필요한 연산을 실행한다.

| 구성 요소                      | 역할                                                                                                                                                                  |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DDL 컴파일러                   | DDL로 명세한 스키마를 내부 형태로 변환해 카탈로그에 저장                                                                                                              |
| 질의어 처리기(query processor) | 질의문을 파싱·분석·컴파일해 목적 코드(object code)를 생성                                                                                                             |
| 예비 컴파일러(precompiler)     | 응용 프로그램에 삽입된 DML을 추출해 DML 컴파일러로 보내고, 그 자리를 프로시저 호출로 바꾼 프로그램을 호스트 언어 컴파일러로 보낸다                                    |
| DML 컴파일러                   | DML 명령을 목적 코드로 변환                                                                                                                                           |
| 런타임 데이터베이스 처리기     | 실행 시각에 저장 데이터 관리자를 통해 데이터베이스 연산을 수행                                                                                                        |
| 트랜잭션 관리자                | 트랜잭션 단위로 작업을 수행하며, 무결성·권한 제어와 병행 제어·회복을 담당. 계좌 이체처럼 여러 연산이 모두 성공하거나 모두 취소되어야 하는 작업을 보장한다             |
| 저장 데이터 관리자             | 디스크의 사용자 데이터베이스와 카탈로그 접근을 제어. 운영체제의 파일 관리자(페이지 결정)와 디스크 관리자(데이터 전송)를 이용하고, 메모리에서는 버퍼 관리자가 관리한다 |

사용자 유형별로 요청이 지나는 경로를 정리하면 다음과 같다.

![사용자 유형별 요청이 DBMS 모듈을 지나는 경로](./images/db-three-level-schema-dbms-flow.svg '세 경로 모두 저장 데이터 관리자를 거쳐 디스크에 접근한다')

| 사용자          | 경로                                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------------------- |
| DBA             | DDL → DDL 컴파일러(오류 검사, 내부 형태 변환) → 저장 데이터 관리자 → 카탈로그                                        |
| 응용 프로그래머 | 응용 프로그램 → 예비 컴파일러 → DML 컴파일러 → 런타임 데이터베이스 처리기 → 저장 데이터 관리자 → 저장 데이터베이스   |
| 일반 사용자     | 질의어 → 질의어 처리기 → 런타임 데이터베이스 처리기(트랜잭션 관리자와 협력) → 저장 데이터 관리자 → 저장 데이터베이스 |

## 데이터베이스 관리자(DBA)

DBA(Database Administrator)는 데이터베이스 시스템의 관리와 운영에 대한 모든 책임을 진다.

- **데이터베이스 설계와 운영** (가장 중요한 업무)
  - 데이터베이스의 구성 요소 결정과 스키마 정의
  - 저장 구조와 접근 방법 설정
  - 보안 정책 수립, 권한 부여, 유효성 검사
  - 백업·회복 절차 수립과 무결성 유지
  - 성능 향상과 새 요구에 맞춘 재구성
  - 카탈로그 유지 관리
- **행정과 불평 해결**: 데이터 표현과 문서화 표준 설정, 사용자 요구 처리
- **시스템 감시와 성능 분석**: 자원 이용도, 병목(bottleneck), 장비 성능, 데이터 사용 추세 분석

## 데이터베이스 컴퓨터

데이터베이스 기능만 효율적으로 수행하는 특수 목적 하드웨어로, 필수 요소는 아니다. 데이터베이스가 GB(1024MB), TB(1024GB), PB(1024TB), EB(1024PB) 단위로 커지는 대규모 데이터베이스(VLDB)에서 성능을 높이려고 쓴다. 범용 컴퓨터 뒤에 후위 컴퓨터(backend computer)로 두며, 지능형 저장 장치, 내용 주소화 메모리(associative memory), 병렬 처리(parallel processing) 같은 기술을 사용한다.

## 과제로 풀어 본 문제

**데이터베이스, DBMS, 데이터베이스 시스템의 구별.**

| 용어                | 정의                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------- |
| 데이터베이스        | 한 조직의 여러 응용 시스템이 공용할 수 있도록 통합·저장한 운영 데이터의 집합                                  |
| DBMS                | 응용 프로그램과 데이터 사이의 중재자로, 모든 응용 프로그램이 데이터베이스를 공용하게 관리하는 범용 소프트웨어 |
| 데이터베이스 시스템 | 데이터를 데이터베이스로 저장·관리해 정보를 생성하는 컴퓨터 중심 시스템. 데이터베이스와 DBMS는 그 구성 요소다  |

**외부 스키마와 저장 구조의 관계.** 사용자와 응용 프로그램은 저장 구조가 아니라 외부 스키마로 데이터에 접근한다. 둘 사이는 외부/개념 사상과 개념/내부 사상 두 단계로 연결되며, DBMS가 이 사상을 자동으로 수행하므로 사용자는 저장 구조가 바뀐 사실을 의식하지 않는다.

**응용 프로그램과 질의어로 접근하는 방식의 차이.** 응용 프로그램은 호스트 언어에 DML(DSL)을 삽입해 접근하므로 프로그래밍 능력이 필요하다. 질의어는 컴퓨터에 대한 특별한 지식 없이 검색·삽입·삭제·갱신을 할 수 있고, 일반 사용자를 위해 메뉴, 폼, 그래픽 인터페이스를 함께 제공한다.

**절차적 DML과 비절차적 DML의 장단점.**

|          | 장점                                                                                 | 단점                                                                                                                |
| -------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| 절차적   | 처리 순서를 프로그래머가 정하므로 접근 경로를 직접 제어할 수 있다                    | 한 번에 레코드 하나를 호스트 언어와 함께 처리해 독자적으로 쓸 수 없고, 호스트 언어와 데이터 언어를 모두 알아야 한다 |
| 비절차적 | 원하는 데이터만 명세하면 되고, 여러 레코드를 한 번에 처리하며, 대화식으로 쓸 수 있다 | 접근 경로를 시스템이 정하므로, 같은 결과를 내는 질의라도 쓰는 방식에 따라 성능이 달라질 수 있다                     |

과제를 제출한 시각에는 비절차적 DML의 단점을 "순서와 상관없이 실행되어 이해하기 어렵다"고 적었는데, 비절차적 질의도 결과의 의미는 명확하다. 실제 단점은 처리 방법을 시스템의 질의 최적화기에 맡긴다는 점이라 위 표처럼 고쳤다.

**DBMS 구성 요소의 상호 관계.** 고급 DBMS일수록 사용자가 시스템 내부를 몰라도 편리하게 데이터 요구를 표현할 수 있다. 컴파일러, 처리기, 관리자 모듈이 요구를 단계적으로 변환해, 사용자를 소프트웨어와 하드웨어의 세부 사항으로부터 독립시킨다.

## 정리

- 스키마는 외부·개념·내부 세 단계로 정의하고, 외부/개념 사상이 논리적 데이터 독립성을, 개념/내부 사상이 물리적 데이터 독립성을 제공한다.
- 데이터 언어는 DDL(정의), DML(조작), DCL(제어)로 나뉘고, DML은 절차적·비절차적으로 나뉜다.
- DBMS는 컴파일러와 처리기들이 요청을 목적 코드로 변환한 뒤 저장 데이터 관리자를 통해 저장 데이터베이스에 접근한다.
