데이터베이스 기초 연재의 두 번째 글로, 3장(데이터베이스 시스템의 구성)을 다룬다. [앞 글](/memo/db-dbms-data-independence)에서 DBMS의 목적이 사상(mapping)으로 구현하는 데이터 독립성이라고 했는데, 이 글은 그 구조를 구체적으로 정리한다.

## 데이터베이스 시스템의 구성 요소

데이터베이스 시스템(database system)은 데이터를 데이터베이스로 저장·관리해 정보를 생성하는 컴퓨터 중심 시스템이다. 구성 요소는 여섯 가지다.

| 구성 요소           | 내용                                                      |
| ------------------- | --------------------------------------------------------- |
| 3단계 데이터베이스  | 외부·개념·내부 단계로 표현한 데이터베이스                 |
| 데이터 언어         | DDL, DML, DCL                                             |
| 사용자              | 일반 사용자, 응용 프로그래머, DBA                         |
| DBMS                | 데이터베이스를 관리하고 사용자 요청을 수행하는 소프트웨어 |
| DBA                 | 데이터베이스 시스템 전체를 책임지는 특수한 사용자         |
| 데이터베이스 컴퓨터 | 데이터베이스 처리 전용 하드웨어(선택)                     |

![사용자 1~n(질의어·DML)→외부 스키마→개념 스키마→내부 스키마→저장 DB, 그리고 각 단계와 연결된 DBMS를 그린 데이터베이스 시스템 전체 구성도](./images/db-three-level-schema-note-05.jpg '사용자 1~n(질의어·DML)→외부 스키마→개념 스키마→내부 스키마→저장 DB, 그리고 각 단계와 연결된 DBMS를 그린 데이터베이스 시스템 전체 구성도 (강의 자료)')

## 3단계 데이터베이스와 스키마

데이터베이스는 보는 관점에 따라 세 단계로 표현한다.

| 단계                        | 관점                       | 스키마                  | 내용                                                                                |
| --------------------------- | -------------------------- | ----------------------- | ----------------------------------------------------------------------------------- |
| 외부 단계(external level)   | 개별 사용자(응용 프로그램) | 외부 스키마(서브스키마) | 사용자 관점에서 정의한 전체 데이터베이스의 논리적 일부. 응용마다 여러 개            |
| 개념 단계(conceptual level) | 기관 전체                  | 개념 스키마(스키마)     | 모든 응용에 대한 통합 데이터 구조. 시스템 전체에 하나                               |
| 내부 단계(internal level)   | 저장 장치                  | 내부 스키마             | 개념 스키마의 저장 구조(storage structure). 저장 장치가 필요로 하는 정보를 추가한다 |

==**스키마(schema)** 는 데이터베이스의 구조(개체, 관계)와 제약조건(constraints)을 명세한 것이다.==

![3단계 데이터베이스 구조와 두 사상](./images/db-three-level-schema-mapping.svg '외부 스키마는 응용마다, 개념·내부 스키마는 하나씩 있다')

학생 데이터베이스를 예로 들면, 성적 처리 프로그램의 외부 스키마는 학번·이름·성적만, 학적 프로그램의 외부 스키마는 학번·이름·학과만 가져간다. 개념 스키마에는 학생 개체의 모든 애트리뷰트가 정의되고, 내부 스키마에는 레코드 길이, 필드 오프셋, 인덱스 같은 저장 정보가 더해진다. ==세 스키마는 달라 보이지만 모두 "학생"이라는 하나의 개체를 위해 정의된 것이며, 사상으로 연결된다.==

![학적과·학생과 외부 스키마 2개, STUDENT 개념 스키마, STORED-STUDENT 내부 스키마(BYTE·OFFSET)가 화살표로 연결된 3단계 예시](./images/db-three-level-schema-note-01.jpg '학적과·학생과 외부 스키마 2개, STUDENT 개념 스키마, STORED-STUDENT 내부 스키마(BYTE·OFFSET)가 화살표로 연결된 3단계 예시 (강의 자료)')

### 단계 간의 사상

| 사상           | 정의하는 것                           | 다른 이름                              | 제공하는 독립성      |
| -------------- | ------------------------------------- | -------------------------------------- | -------------------- |
| 외부/개념 사상 | 외부 스키마와 개념 스키마의 대응 관계 | 응용 인터페이스(application interface) | 논리적 데이터 독립성 |
| 개념/내부 사상 | 개념 스키마와 내부 스키마의 대응 관계 | 저장 인터페이스(storage interface)     | 물리적 데이터 독립성 |

==개념 스키마에 애트리뷰트를 추가해도 외부/개념 사상만 고치면 외부 스키마와 응용 프로그램은 그대로다(논리적 독립성).== ==인덱스를 추가하거나 저장 장치를 바꿔도 개념/내부 사상만 고치면 개념 스키마는 그대로다(물리적 독립성).==

![외부 스키마 1~n→외부/개념 사상(응용 인터페이스)→개념 스키마→개념/내부 사상(저장 인터페이스)→내부 스키마→저장 DB 3단계 구조도](./images/db-three-level-schema-note-02.jpg '외부 스키마 1~n→외부/개념 사상(응용 인터페이스)→개념 스키마→개념/내부 사상(저장 인터페이스)→내부 스키마→저장 DB 3단계 구조도 (강의 자료)')

### 카탈로그와 데이터 디렉터리

==스키마는 컴파일되어 카탈로그에 저장된다.== 스키마를 그림으로 표현한 것을 스키마 다이어그램(schema diagram)이라 한다.

|           | 카탈로그(catalog)                                                    | 데이터 디렉터리(data directory)         |
| --------- | -------------------------------------------------------------------- | --------------------------------------- |
| 저장 내용 | 시스템 안의 모든 객체에 대한 정의와 명세                             | 저장된 데이터를 참조하는 데 필요한 정보 |
| 다른 이름 | 시스템 데이터베이스, 메타 데이터베이스, 데이터 사전(data dictionary) |                                         |
| 사용 주체 | 사용자와 시스템 모두. DBA의 관리 도구                                | 시스템만                                |

==카탈로그는 "데이터에 관한 데이터"인 메타데이터를 저장한다.== 관계 DBMS에서는 카탈로그도 테이블로 저장되므로 사용자가 SQL로 조회할 수 있다.

## 데이터 언어

데이터 언어는 데이터베이스를 정의·조작·제어하기 위해 시스템과 통신하는 수단이다.

### 데이터 정의어(DDL)

DDL(Data Definition Language)은 데이터베이스 구조를 정의하고 변경한다. 정의하는 내용은 다음과 같다.

- 논리적 데이터 구조: 개념 스키마와 외부 스키마
- 물리적 데이터 구조: 내부 스키마. 이 부분을 정의하는 언어를 데이터 저장 정의어(Data Storage Definition Language)라 한다
- 논리적 구조와 물리적 구조 사이의 사상

### 데이터 조작어(DML)

DML(Data Manipulation Language)은 사용자(응용 프로그램)와 DBMS 사이의 통신 수단으로, 검색·삽입·삭제·변경 연산의 집합이다.

|           | 절차적 DML                                                  | 비절차적 DML                                     |
| --------- | ----------------------------------------------------------- | ------------------------------------------------ |
| 수준      | 저급 데이터 언어                                            | 고급 데이터 언어                                 |
| 명세      | 무엇을(what)과 어떻게(how)                                  | 무엇을(what)만. 어떻게는 시스템에 맡긴다(선언적) |
| 처리 단위 | 한 번에 레코드 하나(one record at a time)                   | 한 번에 레코드 집합(set of records at a time)    |
| 사용 방식 | 응용 프로그램에 삽입(embedded)되어 DML 예비 컴파일러가 처리 | 독립적·대화식으로 쓰는 질의어(query language)    |

비절차적 DML인 질의어는 단말에서 명령(command) 형태로 독자적·대화식으로 실행하며, 질의문 하나가 레코드 집합을 처리하는 프로그램을 추상적으로 표현한다.

호스트 프로그램 속에 삽입되어 쓰이는 DML을 데이터 부속어(DSL, Data Sublanguage)라 하며, 절차적일 수도 비절차적일 수도 있다. 사용자가 원하는 어떤 객체든 추출하고 어떤 관계든 표현할 수 있는 능력을 데이터 언어의 완전성(completeness)이라 한다.

### 데이터 제어어(DCL)

DCL(Data Control Language)은 공용 데이터베이스를 관리하기 위해 데이터 제어를 정의하고 기술한다. ==여러 사용자가 공용하는 데이터베이스의 정확성과 안전성을 유지하는 것이 목적이며, 데이터베이스 관리를 위해 주로 DBA가 사용한다.==

| 제어 내용                | 목적                                                               |
| ------------------------ | ------------------------------------------------------------------ |
| 데이터 보안(security)    | 불법 사용자의 접근을 막고 사용자별 권한을 검사                     |
| 데이터 무결성(integrity) | 저장된 데이터의 정확성과 유효성 유지                               |
| 데이터 회복(recovery)    | 장애가 발생하면 데이터베이스를 장애 이전의 일관된 상태로 복구      |
| 병행 수행(concurrency)   | 여러 사용자가 동시에 접근해도 각자 혼자 쓰는 것과 같은 결과를 보장 |

## 사용자

사용자는 데이터베이스를 이용하려고 접근하는 사람으로, 사용하는 데이터 언어에 따라 세 유형으로 나뉜다.

| 사용자                | 사용하는 언어          | 접근 방식                                                            |
| --------------------- | ---------------------- | -------------------------------------------------------------------- |
| 일반 사용자(end user) | 비절차적 DML(질의어)   | 메뉴, 폼, 그래픽 인터페이스로 삽입·삭제·갱신·검색                    |
| 응용 프로그래머       | 호스트 언어 + DML(DSL) | PL/I, COBOL, Pascal, C, Java 같은 호스트 언어로 작성한 응용 프로그램 |
| DBA                   | DDL, DCL               | 데이터베이스를 정의하고 제어                                         |

## DBMS의 처리 과정과 구성 요소

DBMS는 사용자 요청을 다음 순서로 처리한다.

1. 사용자의 접근 요청(access request)을 접수하고 분석한다.
2. 요청을 시스템이 이해하는 형태로 변환(transform)한다.
3. 외부·개념·내부·저장 구조 사이의 사상을 수행해 저장 데이터에 접근한다.
4. 저장 데이터베이스에 필요한 연산을 실행한다.

| 구성 요소                      | 역할                                                                                                                                                                  |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| DDL 컴파일러                   | DDL로 명세한 스키마를 내부 형태로 변환해 카탈로그(메타 데이터베이스, 데이터의 데이터)에 저장                                                                          |
| 질의어 처리기(query processor) | 질의문을 파싱·분석·컴파일해 목적 코드(object code)를 생성                                                                                                             |
| 예비 컴파일러(precompiler)     | 응용 프로그램에 삽입된 DML을 추출해 DML 컴파일러로 보내고, 그 자리를 프로시저 호출로 바꾼 프로그램을 호스트 언어 컴파일러로 보낸다                                    |
| DML 컴파일러                   | DML 명령을 목적 코드로 변환                                                                                                                                           |
| 런타임 데이터베이스 처리기     | 프로그램 실행 중에 저장 데이터 관리자를 통해 데이터베이스 연산을 수행                                                                                                 |
| 트랜잭션 관리자                | 트랜잭션 단위로 작업을 수행하며, 무결성·권한 제어와 병행 제어·회복을 담당. 계좌 이체처럼 여러 연산이 모두 성공하거나 모두 취소되어야 하는 작업을 보장한다             |
| 저장 데이터 관리자             | 디스크의 사용자 데이터베이스와 카탈로그 접근을 제어. 운영체제의 파일 관리자(페이지 결정)와 디스크 관리자(데이터 전송)를 이용하고, 메모리에서는 버퍼 관리자가 관리한다 |

사용자 유형별로 요청이 지나는 경로를 정리하면 다음과 같다.

![사용자 유형별 요청이 DBMS 모듈을 지나는 경로](./images/db-three-level-schema-dbms-flow.svg '세 경로 모두 저장 데이터 관리자를 거쳐 디스크에 접근한다')

| 사용자          | 경로                                                                                                                 |
| --------------- | -------------------------------------------------------------------------------------------------------------------- |
| DBA             | DDL → DDL 컴파일러(오류 검사, 내부 형태 변환) → 저장 데이터 관리자 → 카탈로그                                        |
| 응용 프로그래머 | 응용 프로그램 → 예비 컴파일러 → DML 컴파일러 → 런타임 데이터베이스 처리기 → 저장 데이터 관리자 → 저장 데이터베이스   |
| 일반 사용자     | 질의어 → 질의어 처리기 → 런타임 데이터베이스 처리기(트랜잭션 관리자와 협력) → 저장 데이터 관리자 → 저장 데이터베이스 |

![일반사용자·응용프로그래머·DBA의 요청이 질의어 처리기·DML 예비컴파일러·DDL 컴파일러·런타임 처리기·트랜잭션 관리자·저장 데이터 관리자를 거쳐 저장 DB와 카탈로그에 닿는 DBMS 구성도](./images/db-three-level-schema-note-03.jpg '일반사용자·응용프로그래머·DBA의 요청이 질의어 처리기·DML 예비컴파일러·DDL 컴파일러·런타임 처리기·트랜잭션 관리자·저장 데이터 관리자를 거쳐 저장 DB와 카탈로그에 닿는 DBMS 구성도 (강의 자료)')

## 데이터베이스 관리자(DBA)

DBA(Database Administrator)는 데이터베이스 시스템의 관리와 운영에 대한 모든 책임을 진다. 업무는 세 갈래로 나뉜다.

| 업무                     | 내용                                                                                                                                                                                   |
| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 데이터베이스 설계와 운영 | 구성 요소 결정, 스키마 정의, 저장 구조와 접근 방법 설정, 보안 정책 수립·권한 부여·유효성 검사, 백업·회복 절차 수립, 무결성 유지, 성능 향상과 새 요구에 맞춘 재구성, 카탈로그 유지 관리 |
| 행정과 불평 해결         | 데이터 표현과 시스템 문서화의 표준 설정, 사용자의 요구와 불평 해결                                                                                                                     |
| 시스템 감시와 성능 분석  | 시스템 성능 감시(monitoring), 자원 이용도·병목(bottleneck)·장비 성능 분석, 사용자 요구의 변화·데이터 사용 추세·각종 통계의 종합 분석                                                   |

설계와 운영의 세부 업무는 아래 연습문제 4번에 적었다.

## 데이터베이스 컴퓨터

데이터베이스 기능만 효율적으로 수행하는 특수 목적 하드웨어로, 필수 요소는 아니다. 데이터베이스가 GB(1024MB), TB(1024GB), PB(1024TB), EB(1024PB) 단위로 커지는 대규모 데이터베이스(VLDB)에서 성능을 높이려고 쓴다. 범용 컴퓨터 뒤에 후위 컴퓨터(backend computer)로 두며, 지능형 저장 장치, 내용 주소화 메모리(associative memory), 병렬 처리(parallel processing) 같은 기술을 사용한다.

## 연습문제 풀이

<details>
<summary>1. 스키마의 정의와 유형</summary>

> 스키마란 무엇이며, 그 유형에는 어떤 것이 있는지 설명해 보라.

스키마는 데이터베이스의 논리적 정의로, 데이터베이스 구조(개체, 관계)와 제약조건에 대한 명세다. 3단계 데이터베이스 구조에 따라 외부 스키마(서브스키마), 개념 스키마(스키마), 내부 스키마로 나뉜다. 각 스키마의 관점과 개수는 [3단계 데이터베이스와 스키마](#3단계-데이터베이스와-스키마) 절의 표와 같다.

</details>

<details>
<summary>2. 3단계 데이터베이스 구조와 데이터 독립성</summary>

> 3단계 데이터베이스 구조란 무엇이며 이것은 데이터 독립성과 어떻게 연관되는지 설명해 보라.

3단계 데이터베이스 구조는 하나의 데이터베이스를 개별 사용자의 관점(외부 스키마), 모든 사용자 관점을 통합한 기관 전체의 관점(개념 스키마), 저장 장치의 관점(내부 스키마)으로 나누어 기술하는 구조다.

==세 단계 사이에 사상을 두므로 한 단계의 스키마를 바꿔도 사상만 고치면 상위 단계는 바뀌지 않는다.== 외부/개념 사상이 논리적 데이터 독립성을, 개념/내부 사상이 물리적 데이터 독립성을 제공한다.

</details>

<details>
<summary>3. 데이터 정의어</summary>

> 데이터 정의어를 설명하라.

==데이터 정의어(DDL)는 데이터베이스 구조를 정의하고 변경하는 데 사용하는 언어다.== 정의 대상은 다음 세 가지다.

| 정의 대상           | 명세하는 스키마                        |
| ------------------- | -------------------------------------- |
| 논리적 데이터 구조  | 개념 스키마, 외부 스키마               |
| 물리적 데이터 구조  | 내부 스키마(데이터 저장 정의어로 명세) |
| 두 구조 사이의 사상 | 논리적 구조와 물리적 구조의 대응 관계  |

DBA가 주로 사용하며, DDL로 명세한 스키마는 DDL 컴파일러가 내부 형태로 변환해 카탈로그에 저장한다. SQL의 `CREATE TABLE{:sql}`, `ALTER TABLE{:sql}`, `DROP TABLE{:sql}`이 DDL이다.

</details>

<details>
<summary>4. 데이터베이스 관리자의 기능</summary>

> 데이터베이스 관리자의 기능을 설명하라.

DBA의 업무는 [데이터베이스 관리자](#데이터베이스-관리자dba) 절의 표처럼 설계와 운영, 행정과 불평 해결, 시스템 감시와 성능 분석으로 나뉜다. 설계와 운영의 세부 업무는 다음과 같다.

| 세부 업무                              | 내용                                                                                                        |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 구성 요소 결정                         | 개체, 개체를 기술하는 애트리뷰트, 개체 사이의 관계를 선정                                                   |
| 스키마 정의                            | 구성 요소로 데이터베이스를 설계하고 DBMS가 이해하는 스키마로 기술                                           |
| 저장 구조와 접근 방법 설정             | 레코드의 물리적 표현, 저장 레코드 사이의 순서, 인덱스와 포인터 같은 접근 방법 결정                          |
| 보안 정책 수립, 권한 부여, 유효성 검사 | 불법 사용을 막고 정당한 사용자에게 알맞은 권한을 부여하며, 저장 데이터의 유효성과 처리 작업의 합법성을 검사 |
| 백업·회복 절차 수립                    | 서비스 중단에 대비한 예비 시설과, 데이터베이스가 손상되면 즉시 복구하는 절차 수립                           |
| 무결성 유지                            | 무결성 규정을 만들고 이를 위반하지 않게 데이터베이스를 제어해 정확성과 유효성 유지                          |
| 성능 향상과 재구성                     | 시간이 지나거나 기술 환경이 바뀔 때 새 요구에 맞춰 데이터베이스를 재구성                                    |
| 카탈로그 유지 관리                     | 설계·구현·운영·확장 단계에서 사용하는 카탈로그를 최신 상태로 유지                                           |

</details>

<summary>5. 데이터베이스, DBMS, 데이터베이스 시스템의 구별</summary>

> 데이터베이스, 데이터베이스 관리 시스템, 데이터베이스 시스템을 구별해서 설명해 보라.

| 용어                | 정의                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------- |
| 데이터베이스        | 한 조직의 여러 응용 시스템이 공용할 수 있도록 통합·저장한 운영 데이터의 집합                                  |
| DBMS                | 응용 프로그램과 데이터 사이의 중재자로, 모든 응용 프로그램이 데이터베이스를 공용하게 관리하는 범용 소프트웨어 |
| 데이터베이스 시스템 | 데이터를 데이터베이스로 저장·관리해 정보를 생성하는 컴퓨터 중심 시스템. 데이터베이스와 DBMS는 그 구성 요소다  |

</details>

<summary>6. 사상과 데이터 독립성의 관계</summary>

> 데이터베이스 시스템에서 사상(mapping)과 데이터 독립성의 관계를 설명하라.

| 사상           | 스키마가 바뀌는 경우                             | 결과                                                                     |
| -------------- | ------------------------------------------------ | ------------------------------------------------------------------------ |
| 외부/개념 사상 | 개념 스키마 변경(애트리뷰트·레코드 추가 등)      | 사상만 고치면 외부 스키마와 응용 프로그램은 그대로(논리적 데이터 독립성) |
| 개념/내부 사상 | 내부 스키마 변경(인덱스 추가, 저장 장치 교체 등) | 사상만 고치면 개념 스키마와 응용 프로그램은 그대로(물리적 데이터 독립성) |

==데이터 독립성은 사상으로 구현되며, 사상이 스키마 변경의 영향을 흡수한다.==

<details>
<summary>7. 데이터 조작어의 연산</summary>

> 데이터 조작어를 수행하는 데이터베이스 연산을 설명하라.

DML은 검색(retrieval), 삽입(insertion), 삭제(deletion), 변경(update)의 네 연산을 제공한다. SQL로 예제 데이터에 적용하면 다음과 같다.

```sql
SELECT Sname FROM STUDENT WHERE Dept = '컴퓨터';       -- 검색
INSERT INTO ENROL (Sno, Cno) VALUES (500, 'C413');      -- 삽입: 박종화가 데이터베이스 과목에 등록
UPDATE STUDENT SET Year = 2 WHERE Sno = 300;            -- 변경: 정기태의 학년을 2로
DELETE FROM ENROL WHERE Sno = 200 AND Cno = 'C123';     -- 삭제: 이찬수의 프로그래밍 등록 취소
```

검색문의 결과는 학과가 컴퓨터인 학생 세 명이다.

| Sname  |
| ------ |
| 나수영 |
| 정기태 |
| 송병길 |

삽입문은 ENROL에 (500, C413, NULL, NULL, NULL) 튜플을 추가하고, 변경문은 STUDENT 튜플 하나의 Year를 바꾸며, 삭제문은 ENROL 튜플 하나를 삭제한다.

</details>

<details>
<summary>8. 데이터 제어어의 연산</summary>

> 데이터 제어어에 포함되는 연산들을 설명하라.

DCL은 보안, 무결성, 회복, 병행 수행을 제어한다. 각 항목의 목적은 [데이터 제어어](#데이터-제어어dcl) 절의 표와 같다. SQL에서는 권한을 부여하는 `GRANT{:sql}`와 회수하는 `REVOKE{:sql}`가 보안을 담당하고, 트랜잭션을 끝내는 `COMMIT`과 취소하는 `ROLLBACK`이 회복과 병행 제어의 단위를 지정한다.

```sql
GRANT SELECT, UPDATE ON STUDENT TO user1;
REVOKE UPDATE ON STUDENT FROM user1;
```

</details>

<details>
<summary>9. 응용 프로그램 접근과 질의어 접근의 비교</summary>

> 응용 프로그램으로 데이터베이스를 접근하는 것과 질의어로 데이터베이스를 접근하는 것을 비교 설명해 보라.

|             | 응용 프로그램                                        | 질의어                                           |
| ----------- | ---------------------------------------------------- | ------------------------------------------------ |
| 사용자      | 응용 프로그래머                                      | 일반 사용자(단말 사용자)                         |
| 언어        | 호스트 언어 + DML(DSL)                               | 비절차적 DML                                     |
| 필요한 지식 | 프로그래밍 능력과 데이터 언어 지식                   | 컴퓨터에 대한 특별한 지식 없이 사용              |
| 처리 방식   | 예비 컴파일러와 DML 컴파일러를 거쳐 목적 코드로 실행 | 질의어 처리기가 질의문을 즉시 해석·컴파일해 실행 |
| 인터페이스  | 응용 프로그램 자체                                   | 메뉴, 폼, 그래픽 같은 사용자 인터페이스          |

두 방식 모두 검색뿐 아니라 삽입, 삭제, 갱신을 수행할 수 있다.

</details>

<details>
<summary>10. 외부 스키마와 저장 데이터베이스 구조의 관계</summary>

> 외부 스키마와 저장 데이터베이스 구조와의 관계를 설명하라.

==외부 스키마와 저장 데이터베이스 구조는 직접 연결되지 않고, 외부/개념 사상과 개념/내부 사상의 두 단계 사상으로 연결된다.== 사용자의 요청은 외부 스키마로 표현되고, DBMS가 외부/개념 사상으로 개념 스키마의 요청으로, 다시 개념/내부 사상으로 내부 스키마의 저장 구조에 대한 접근으로 변환한다. DBMS가 이 변환을 자동으로 수행하므로 저장 구조가 바뀌어도 개념/내부 사상만 고치면 외부 스키마와 응용 프로그램은 그대로다.

</details>

<details>
<summary>11. 절차적 DML과 비절차적 DML의 장단점</summary>

> 절차적 조작어와 비절차적 조작어의 장단점을 설명하라.

|          | 장점                                                                                        | 단점                                                                                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 절차적   | 처리 순서와 접근 경로를 프로그래머가 정하므로 레코드 단위로 세밀하게 제어할 수 있다         | 한 번에 레코드 하나를 호스트 언어와 함께 처리해 독자적으로 쓸 수 없고, 호스트 언어와 데이터 언어를 모두 알아야 한다                                                          |
| 비절차적 | 원하는 데이터만 명세하면 되고, 여러 레코드를 한 번에 처리하며, 독자적·대화식으로 쓸 수 있다 | 접근 경로를 시스템(질의 최적화기)이 정하므로 사용자가 처리 방법과 성능을 직접 제어할 수 없고, 레코드 단위로 처리하는 호스트 언어와 연결하려면 커서 같은 별도 장치가 필요하다 |

</details>

<details>
<summary>12. DBMS 구성 요소의 기능과 상호 관계</summary>

> DBMS를 구성하는 소프트웨어 모듈, 즉 구성 요소의 기능과 이들 간의 상호 관계를 설명해 보라.

각 모듈의 기능은 [DBMS의 처리 과정과 구성 요소](#dbms의-처리-과정과-구성-요소) 절의 표와 같다. 모듈 사이에서는 다음 순서로 결과가 전달된다.

| 단계 | 모듈                         | 넘겨받는 것                | 넘기는 것                                       |
| ---- | ---------------------------- | -------------------------- | ----------------------------------------------- |
| 1    | DDL 컴파일러                 | DBA가 작성한 DDL           | 내부 형태의 스키마를 카탈로그에 저장            |
| 2    | 질의어 처리기                | 일반 사용자의 질의문       | 카탈로그를 참조해 만든 목적 코드                |
| 2    | 예비 컴파일러 → DML 컴파일러 | 응용 프로그램에 삽입된 DML | 목적 코드, 프로시저 호출로 바뀐 호스트 프로그램 |
| 3    | 런타임 데이터베이스 처리기   | 목적 코드                  | 데이터베이스 연산 요청                          |
| 3    | 트랜잭션 관리자              | 런타임 처리기의 연산       | 무결성·권한 검사, 병행 제어와 회복을 거친 연산  |
| 4    | 저장 데이터 관리자           | 데이터베이스 연산 요청     | 파일 관리자·디스크 관리자를 통한 디스크 접근    |

==컴파일러와 처리기가 사용자 요청을 단계적으로 변환하고 저장 데이터 관리자만 디스크에 접근하므로, 사용자는 시스템 내부와 하드웨어의 세부 사항을 몰라도 데이터 요구를 표현할 수 있다.== 사용자 유형별 경로는 [DBMS](#dbms의-처리-과정과-구성-요소) 절의 경로 표와 그림에 있다.

</details>

## 정리

- 스키마는 외부·개념·내부 세 단계로 정의하고, 외부/개념 사상이 논리적 데이터 독립성을, 개념/내부 사상이 물리적 데이터 독립성을 제공한다.
- 데이터 언어는 DDL(정의), DML(조작), DCL(제어)로 나뉘고, DML은 절차적·비절차적으로 나뉜다.
- DBMS는 컴파일러와 처리기들이 요청을 목적 코드로 변환한 뒤 저장 데이터 관리자를 통해 저장 데이터베이스에 접근한다.
