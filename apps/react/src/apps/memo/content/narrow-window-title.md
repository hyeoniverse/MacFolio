앱마다 창 너비가 640px 아래로 내려가면 컨테이너 쿼리(`@container (max-width: 640px)`)로 휴대폰과 같은 화면을 쓴다. 휴대폰에서는 창 맨 위에 제목 막대가 따로 있지만, 데스크톱 창에서는 그대로 왼쪽 위에 신호등 버튼(닫기·최소화·확대)이 떠 있다. 음악 앱은 이 차이를 생각하지 않아서, 창을 좁히면 보관함 제목이 버튼 밑에 깔렸다.

## 배경

데스크톱에서 창 오른쪽 아래 모서리를 끌어 음악 창을 좁혀 보면 바로 보였다. 560px쯤에서 화면이 휴대폰 모양으로 바뀌고, 보관함의 큰 제목이 빨강·노랑·초록 동그라미 밑으로 들어갔다. 곡 목록으로 들어가면 돌아갈 버튼이 없어서, 창을 다시 넓히는 것 말고는 보관함으로 돌아올 방법이 없었다. Safari는 더 좁혀야 보였다. 380px 이하에서 뒤로·앞으로 버튼이 신호등 아래로 들어가 누를 수 없었다.

![좁은 창 전후](./images/narrow-window-title.jpg '위: 전 / 아래: 후')

## 원인

좁은 창의 앱이 휴대폰 화면을 그대로 쓰는데, 휴대폰과 데스크톱 창은 위쪽 사정이 다르다.

|           | 휴대폰                              | 좁은 데스크톱 창                            |
| --------- | ----------------------------------- | ------------------------------------------- |
| 맨 위     | 상태 표시줄, 그 아래 셸의 뒤로 가기 | 앱 안 왼쪽 위에 신호등 버튼이 겹쳐 떠 있다  |
| 위 여백   | `--phone-top`                       | 앱이 정한 값 (음악은 16px)                  |
| 뒤로 가기 | `MobileNavigation`이 그린다         | `MobileNavigation`은 아무것도 그리지 않는다 |

음악은 좁은 화면에서 사이드바(보관함)의 위 여백을 0으로, 본문의 위 여백을 16px로 두었다. 휴대폰에서는 그 위에 셸이 자리를 잡아 주니 문제가 없었지만, 데스크톱 창에서는 신호등이 그 자리에 있었다.

Safari는 다른 원인이었다. 도구 막대 맨 왼쪽에 신호등 자리로 64px짜리 빈 칸(`.safari-lights-space`)을 두었는데, flex 항목의 기본값 `flex-shrink: 1` 때문에 자리가 모자라면 이 칸부터 줄었다.

## 고를 수 있는 방법

| 방법                                                                  | 문제                                                         |
| --------------------------------------------------------------------- | ------------------------------------------------------------ |
| 좁은 창에서는 신호등 버튼을 숨긴다                                    | 창을 닫거나 최소화할 길이 없어진다. macOS도 신호등은 늘 있다 |
| 좁은 창도 휴대폰처럼 셸이 제목 막대를 그린다                          | 데스크톱 창 전체 구조를 바꿔야 한다                          |
| 앱이 신호등 줄 높이만큼 위를 비우고, 돌아가는 버튼을 직접 단다 (고름) | 앱마다 챙겨야 한다. 그래서 시험으로 훑는다                   |

메일·메모·메시지는 이미 세 번째 방식으로 위를 비우고 있었다. 음악과 Safari만 따라오지 않았다.

## 음악

좁은 창의 보관함과 곡 목록 위쪽을 신호등 버튼 줄 높이(44px)만큼 비웠다. 휴대폰은 원래 쓰던 `--phone-top`이 이 값을 덮어쓰므로 바뀌지 않는다.

```css
@container (max-width: 640px) {
	/* 위쪽은 신호등 버튼 줄 높이만큼 비운다. 휴대폰은 --phone-top으로 덮어쓴다 */
	.music-sidebar {
		padding: 44px 16px 16px; /* 전: 0 16px 16px */
	}
	.music-main {
		padding: 44px 16px 24px; /* 전: 16px 16px 24px */
	}
	.music-back {
		display: flex;
	}
}
```

곡 목록에는 돌아가는 버튼이 없었다. 휴대폰에서는 제목 막대의 뒤로 가기(`MobileNavigation`)가 그 일을 하는데, 이 부품은 데스크톱에서 아무 일도 하지 않는다. 그래서 좁은 데스크톱 창에서는 곡 목록으로 들어가면 보관함으로 돌아올 수 없었다. 메일의 받은 편지함 버튼처럼 곡 목록 위에 `‹ 보관함` 버튼(`.music-back`)을 두고, 넓은 창과 휴대폰에서는 숨긴다.

## Safari

빈 칸에 `flex: none`을 주고, 대신 주소 막대가 줄어들도록 `min-width: 0`을 줬다.

```css
.safari-lights-space {
	flex: none; /* 줄어들면 뒤로·앞으로 버튼이 신호등 아래로 들어간다 */
	width: 64px;
}
.safari-address {
	min-width: 0; /* 대신 주소 막대가 줄어든다 */
	max-width: 520px;
}
```

`min-width: 0`이 필요한 것은 flex 항목의 기본 최소 너비가 `auto`(내용 너비)라서다. 빈 칸만 고정하면 주소 막대도 줄지 않아 도구 막대가 창 밖으로 넘친다.

## 다른 앱도 훑기

![신호등과 겹치는지 보는 시험](./images/narrow-window-title-check.svg '보이는 버튼·링크·입력·제목·탭의 상자가 신호등 상자와 겹치면 실패')

같은 일이 다른 앱에도 있는지 E2E 시험(`e2e/narrow-window.spec.ts`)으로 찾았다. 앱마다 창을 700, 560, 460, 380, 320px로 바꾸고, 보이는 버튼·링크·입력·제목·탭 가운데 신호등 버튼과 겹치는 것이 있는지 본다. 앱 9개(음악·메시지·메일·메모·설정·GitHub·Safari·터미널·게임)에 폭 5가지라 45번 확인한다.

```ts
const covered = await win.evaluate((frame) => {
	const lights = frame.querySelector('.traffic-lights')!.getBoundingClientRect();
	return [...frame.querySelectorAll<HTMLElement>('button, a, input, h1, h2, h3, [role="tab"]')]
		.filter((el) => !el.closest('.traffic-lights'))
		.filter((el) => {
			const box = el.getBoundingClientRect();
			// 보이지 않는 것은 빼고, 두 상자가 가로·세로 모두 겹치면
			return box.right > lights.left && box.left < lights.right && box.bottom > lights.top && box.top < lights.bottom;
		})
		.map((el) => (el.textContent || el.getAttribute('aria-label') || el.tagName).trim().slice(0, 20));
});
expect(covered, `${width}px`).toEqual([]);
```

폭을 바꾼 뒤에는 `requestAnimationFrame`을 한 번 기다린다. 컨테이너 쿼리는 스타일을 다시 계산해야 적용되기 때문이다. 실패하면 겹친 요소의 글자와 폭이 메시지에 나와서 어디를 고칠지 바로 알 수 있다.

고치기 전에는 음악(560px 이하)과 Safari(380px 이하)만 걸렸고, 메일·메모·메시지·설정·GitHub·터미널·게임은 이미 버튼 아래에 자리를 두고 있었다. 음악은 따로 `e2e/music.spec.ts`의 "좁은 창에서는 제목이 신호등 버튼 아래에 있고, 곡 목록에서 보관함으로 돌아온다"로 돌아가는 버튼까지 확인한다([PR #77](https://github.com/hyeoniverse/MacFolio/pull/77)).

## 남은 것·배운 것

- 이 시험은 상자가 겹치는지만 본다. 버튼 바로 옆에 붙어 답답해 보이는 것은 잡지 못한다.
- 뒤에 앱마다 가장 작은 창 크기(`minSize`)를 두었다. 예를 들어 시스템 설정은 사이드바가 늘 보이는 680×420 아래로 줄지 않는다. 너무 좁은 창을 막는 것도 같은 문제를 줄이는 방법이다.
- "휴대폰 화면을 그대로 쓴다"는 말에는 "휴대폰 셸이 해 주던 일"이 빠져 있었다. 화면을 재사용할 때는 그 화면이 기대던 바깥 환경(위 여백, 뒤로 가기)까지 같이 따져야 한다.
- 특정 앱에서 찾은 버그를 모든 앱에 대고 훑는 시험으로 바꾸면, 새 앱을 더할 때도 같은 실수를 잡아 준다. 이번 시험은 앱 이름 목록에 하나만 더하면 된다.
