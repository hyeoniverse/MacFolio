[트래픽 분석 1](/memo/analytics-api)에서 API를, [2](/memo/analytics-collect)에서 사이트의 수집을 만들었다. 마지막은 숫자를 보는 화면이다. 하루에 몇 명이 왔는지, 어떤 글을 많이 읽는지를 사이트 안에서 바로 보고 싶었다.

작업은 PR [#162](https://github.com/hyeoniverse/MacFolio/pull/162)다. 첫 커밋 하나에 14개 파일, 1,336줄이 들어갔다(CSS 430줄, 화면 300줄, 숫자 다듬기 156줄, 표 99줄, 그래프 47줄, 시험).

## 왜 활동 상태 보기인가

통계 화면은 보통 웹 대시보드 모양이다. 이 사이트는 macOS 데스크톱이라, 그 안에 어울리는 앱을 찾았다. macOS의 **활동 상태 보기(Activity Monitor)** 는 위에 CPU·메모리·네트워크 탭이 있고, 가운데 표는 머리를 눌러 정렬하고, 아래에 작은 그래프가 있다. 통계를 보여 주기에 딱 맞는 모양이라 그대로 빌렸다. 아이콘도 어두운 화면에 초록 선 그래프다.

![활동 상태 보기 화면 구성](./images/analytics-activity-monitor-layout.svg '탭 다섯과 기간, 숫자 칸 넷, SVG 그래프, 정렬되는 표. 서버 없이는 캡처할 수 없어 구성만 그렸다')

## 탭 다섯

| 탭        | 보여 주는 것                                                                                                                              |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 개요      | 방문, 순방문자, 앱 열기, 평균 머문 시간 (앞의 같은 길이 기간과 비교해 ▲▼). 일별 방문 그래프. 가장 많이 연 앱 5개, 가장 많이 들어온 곳 5개 |
| 유입 경로 | 검색·소셜·직접·링크로 묶어 보기, 들어온 곳, `utm_campaign`, `utm_source`                                                                  |
| 앱·글     | 앱 열기, 글·프로젝트 보기, 바깥 링크 누름                                                                                                 |
| 지역·기기 | 나라, 기기, 브라우저, OS, 언어                                                                                                            |
| 실시간    | 최근 30분의 방문. 10초마다 다시 묻는다. 행을 누르면 그 방문의 흐름(들어옴 → 메모 열기 → 글 보기 → 링크 누름)                              |

기간은 오늘, 7일, 30일, 90일에서 고른다. 메뉴 막대의 '보기' 메뉴에도 탭과 기간을 두었다.

순방문자 칸에는 "날마다 센 순방문자의 합"이라는 설명을 달았다. 쿠키 없이 하루 해시로 세기 때문에, 월요일과 화요일에 온 같은 사람은 두 명이다([1편](/memo/analytics-api)).

## 차트 라이브러리를 쓸까

| 방법                      | 좋은 점                      | 문제                                                          |
| ------------------------- | ---------------------------- | ------------------------------------------------------------- |
| Recharts 같은 라이브러리  | 축, 툴팁, 범례가 다 있다     | 그래프 하나를 위해 의존성과 번들이 는다. 모양을 맞추기 어렵다 |
| 표만 두고 그래프 없음     | 가장 쉽다                    | 날마다 늘고 주는 흐름이 안 보인다                             |
| 직접 그린 SVG (고른 방법) | 선 둘, 면 하나라 코드가 짧다 | 축 눈금과 툴팁이 없다                                         |

필요한 그래프는 "날짜별 방문" 하나였다. 축 눈금은 시작·끝 날짜와 최댓값만 글자로 적으면 충분했다. 그래서 직접 그렸다.

## 표: 정렬과 비율 막대

표는 하나의 컴포넌트(`StatTable`)를 모든 탭이 쓴다. 머리(이름, 방문)를 누르면 그 열로 정렬하고, 다시 누르면 반대로 한다. 숫자 열은 처음에 많은 순, 이름 열은 처음에 가나다순이다. 이름은 `localeCompare(…, 'ko')`로 비교해서 한글이 영문보다 먼저 온다. 정렬 상태는 `aria-sort`로 알린다.

```ts
const sorted = [...named].sort((a, b) => {
	const order = sort.key === 'value' ? a.value - b.value : a.name.localeCompare(b.name, 'ko');
	return sort.descending ? -order : order;
});
```

머리를 누를 때 같은 열이면 방향만 뒤집고, 다른 열로 옮기면 숫자 열은 내림차순, 이름 열은 오름차순부터 시작한다.

![표의 정렬 순서](./images/analytics-activity-monitor-sort.svg '방문 열과 이름 열은 처음 방향이 다르다')

행마다 전체에서 차지하는 비율을 막대로 그린다. 이름은 화면에 맞게 바꾼다.

- 빈 들어온 곳 → "직접 들어옴"
- 나라 코드 → `Intl.DisplayNames`로 "대한민국 (KR)"
- 앱 이름 → 앱 목록(`manifest.ts`)의 이름 ("메모")
- `memo/cra-to-vite` → "메모 › cra-to-vite"

"유입 경로"의 묶어 보기는 호스트를 규칙으로 나눈다. google·naver·daum 같은 검색 엔진은 '검색', linkedin·x·kakao·velog 같은 곳은 '소셜', 빈 값은 '직접', 나머지는 '링크'다.

## 그래프: SVG 하나

![그래프를 그리는 순서](./images/analytics-activity-monitor-chart.svg '날짜 배열을 좌표로 바꾸고 path 세 개를 그린다')

```ts
const x = (index: number) => (days.length === 1 ? WIDTH / 2 : (index / (days.length - 1)) * WIDTH);
const y = (value: number) => HEIGHT - (value / max) * (HEIGHT - 12) - 2;
```

`<svg>`에 선 두 개를 그렸다. 방문은 아래를 옅게 채운 초록 선, 순방문자는 파란 점선이다. 창 폭에 맞춰 늘어나도록 `preserveAspectRatio="none"`을 주고, 그러면 선도 같이 늘어나 두꺼워지므로 `vector-effect: non-scaling-stroke`로 두께를 지킨다. 화면 읽기 프로그램에는 날짜별 숫자를 `aria-label`로 읽어 준다.

## 관리자에게만 (처음 설계)

앱 정보(`manifest.ts`)에 `adminOnly`를 더했다. Launchpad, 휴대폰 홈 화면, Finder의 '앱' 폴더는 관리자로 로그인했을 때만 이 앱을 보여 준다. 그래도 터미널의 `open activity`처럼 열 길은 남는다. 그때는 잠긴 화면("관리자만 볼 수 있습니다")과 관리자 로그인 버튼만 보인다. 화면에서 감추는 것과 별개로 숫자는 **서버가** 관리자 세션을 확인하고 내준다(`AdminGuard`). 방문자가 화면을 고쳐도 숫자는 받을 수 없다.

### 같은 날 바꾼 것: 누구나 연다

이 설계로 커밋한 지 세 시간이 안 되어, 같은 PR에서 방향을 바꿨다. 방문 수, 많이 연 앱, 나라·기기 같은 숫자는 숨길 이유가 없었다. 오히려 방문자가 "이 사이트를 몇 명이 보는지" 볼 수 있는 편이 포트폴리오로서 낫다. 그래서 `adminOnly`를 걷고, 서버가 방문자에게는 공개용 숫자만 주도록 했다(`scope: 'public'`). 자세한 내용은 [트래픽 분석 4](/memo/analytics-public)에 적었다.

| 자리               | 방문자                     | 관리자               |
| ------------------ | -------------------------- | -------------------- |
| 개요의 숫자·그래프 | 보인다                     | 보인다               |
| 들어온 곳          | 검색·소셜·직접·링크 묶음만 | 주소까지             |
| 캠페인(`utm_*`)    | 잠김                       | 보인다               |
| 실시간             | 잠김 (이유와 로그인 버튼)  | 10초마다 다시 묻는다 |

잠긴 자리에는 빈 칸 대신 "관리자만 볼 수 있습니다"와 이유, 관리자 로그인 버튼을 둔다. 묶어 보기 규칙(검색·소셜·직접·링크)도 이때 화면에서 서버(`apps/api/src/analytics/rules.ts`의 `referrerGroup`)로 옮겼다. 방문자에게 주소를 보내지 않고 묶음만 보내려면 서버가 묶어야 한다.

## 다크 모드와 좁은 창

색은 사이트의 테마 변수만 쓴다. 다크 모드는 따로 손대지 않아도 바뀐다. 초록과 빨강(▲▼)만 앱 안의 변수로 두었다.

좁은 창과 휴대폰에서는 숫자 칸이 두 줄, 표가 한 줄씩 쌓인다. 화면 폭이 아니라 **창 폭**을 봐야 해서, 미디어 질의 대신 컨테이너 질의(`@container`)를 썼다. 데스크톱에서 창을 좁혀도 휴대폰과 같은 배치가 된다.

```css
.activity {
	container-type: inline-size;
}
@container (max-width: 640px) {
	/* 숫자 칸 두 줄, 표 한 줄씩 */
}
```

`@media (max-width: 640px)`였다면 1440px 화면에서 창을 500px로 좁혀도 넓은 배치가 그대로였을 것이다. 이 사이트의 앱은 모두 창 안에 있으니, 앱 안의 배치는 창 폭을 기준으로 하는 편이 맞다.

스크린샷으로 밝은 화면, 다크 모드, 휴대폰을 확인했다. 처음에는 표의 글자가 가운데로 몰렸다. 창이 글을 가운데로 정렬하고 있어서, 앱에서 왼쪽 정렬로 되돌렸다. 실시간의 시각은 "오후 12:02:00"이 칸을 넘쳐서 24시간 표기로 바꿨다.

## 시험

- 단위(`src/apps/activity/model.test.ts`, 처음엔 `data.test.ts`): 기간(한국 시간 오늘까지), 앞 기간이 없으면 비교하지 않기, 머문 시간 표기, 표의 이름(앱 이름, 나라 이름, 빈 값), 실시간 흐름의 한 줄
- 화면(`e2e/activity.spec.ts`, 가짜 API `e2e/fakeApi.ts`): 처음 버전은 "방문자에게는 Launchpad에 없고 터미널로 열어도 잠긴 화면, 서버에 묻지도 않는다"를 확인했다. 공개로 바꾼 뒤에는 **방문자도 Launchpad에서 열어 공개 숫자를 본다. 들어온 곳의 주소·캠페인과 실시간은 관리자만**으로 바뀌었다. 관리자 쪽은 **개요(앞 기간 대비, 그래프, 많이 연 앱·들어온 곳) → 탭과 기간을 바꾸고 표를 정렬한다**와 **실시간에서 방문을 누르면 흐름이 펼쳐진다**가 그대로 지킨다.

## 그 뒤에 더한 것

- **서버 탭**: Oracle 서버의 CPU·메모리 사용률과 유휴 회수 위험, 종량제 요금을 같은 앱에서 본다([서버 자원 보기](/memo/resource-monitor)). 탭은 여섯이 됐다.
- **UTM 조합 표와 링크 만들기**(PR [#211](https://github.com/hyeoniverse/MacFolio/pull/211), [UTM 분석](/memo/utm-analytics)): `LineChart`에 `visitors`가 없으면 방문 선만 그리게 해서, 조합별 일별 추이에도 같은 그래프를 쓴다.
- **블로그 글 조회수**: 메모의 글 머리와 이 앱의 글별 표에 전체 기간 조회수를 보인다.

## 남은 것, 배운 것

- 그래프에 툴팁이 없다. 특정 날의 숫자는 표나 화면 읽기용 `aria-label`로만 알 수 있다. 마우스를 올리면 그날 숫자를 보이는 정도는 더할 만하다.
- 실시간은 10초마다 다시 묻는다(폴링). 관리자 한 명만 보므로 서버 부담은 작지만, 창을 띄워 둔 채 두면 계속 요청한다.
- "관리자 전용"으로 시작했다가 몇 시간 만에 열었다. 처음부터 "어떤 숫자가 정말 비밀인가"를 나눠 봤다면 잠금 화면을 두 번 만들지 않았을 것이다. 감출 것은 주소·캠페인·실시간 흐름처럼 사람을 짐작할 수 있는 값뿐이었다.

## 직접 열어 보기

활동 상태 보기는 서버 없이도 가짜 데이터로 열린다. E2E가 쓰는 가짜 API(`apps/react/e2e/fakeApi.ts`)가 요약 응답을 돌려준다.

```bash
cd apps/react
npx playwright test e2e/activity.spec.ts --project=desktop-chromium
```

실제 사이트에서는 Launchpad(또는 휴대폰 홈)에서 '활동 상태 보기'를 연다. 같은 숫자를 API로 직접 볼 수도 있다. 방문자로 부르면 묶음만, 관리자 쿠키가 있으면 호스트와 UTM 표까지 온다.

```bash
curl -s "https://macfolio-api.hyeoniverse.com/analytics/summary?from=2026-10-01&to=2026-10-07" | head -c 300; echo
```

그래프 숫자가 맞는지는 표의 합계와 탭 위 합계가 같은지로 본다. 화면 규칙(정렬·비율 막대)은 `src/apps/activity/model.test.ts`가 맡는다(`npx vitest run src/apps/activity`). API 문서는 [Swagger](https://macfolio-api.hyeoniverse.com/docs)의 analytics 묶음에 있다.
