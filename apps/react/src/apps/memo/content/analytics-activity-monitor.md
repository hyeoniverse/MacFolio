[트래픽 분석 1](/memo/analytics-api)에서 API를, [2](/memo/analytics-collect)에서 사이트의 수집을 만들었다. 마지막은 숫자를 보는 화면이다.

## 왜 활동 상태 보기인가

통계 화면은 보통 웹 대시보드 모양이다. 이 사이트는 macOS 데스크톱이라, 그 안에 어울리는 앱을 찾았다. macOS의 **활동 상태 보기(Activity Monitor)** 는 위에 CPU·메모리·네트워크 탭이 있고, 가운데 표는 머리를 눌러 정렬하고, 아래에 작은 그래프가 있다. 통계를 보여 주기에 딱 맞는 모양이라 그대로 빌렸다. 아이콘도 어두운 화면에 초록 선 그래프다.

## 탭 다섯

| 탭        | 보여 주는 것                                                                                                                              |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 개요      | 방문, 순방문자, 앱 열기, 평균 머문 시간 (앞의 같은 길이 기간과 비교해 ▲▼). 일별 방문 그래프. 가장 많이 연 앱 5개, 가장 많이 들어온 곳 5개 |
| 유입 경로 | 검색·소셜·직접·링크로 묶어 보기, 들어온 곳, `utm_campaign`, `utm_source`                                                                  |
| 앱·글     | 앱 열기, 글·프로젝트 보기, 바깥 링크 누름                                                                                                 |
| 지역·기기 | 나라, 기기, 브라우저, OS, 언어                                                                                                            |
| 실시간    | 최근 30분의 방문. 10초마다 다시 묻는다. 행을 누르면 그 방문의 흐름(들어옴 → 메모 열기 → 글 보기 → 링크 누름)                              |

기간은 오늘, 7일, 30일, 90일에서 고른다. 메뉴 막대의 '보기' 메뉴에도 탭과 기간을 두었다.

순방문자 칸에는 "날마다 센 순방문자의 합"이라는 설명을 달았다. 쿠키 없이 하루 해시로 세기 때문에, 월요일과 화요일에 온 같은 사람은 두 명이다([1편](/memo/analytics-api)).

## 표: 정렬과 비율 막대

표는 하나의 컴포넌트(`StatTable`)를 모든 탭이 쓴다. 머리(이름, 방문)를 누르면 그 열로 정렬하고, 다시 누르면 반대로 한다. 숫자 열은 처음에 많은 순, 이름 열은 처음에 가나다순이다. 이름은 `localeCompare(…, 'ko')`로 비교해서 한글이 영문보다 먼저 온다. 정렬 상태는 `aria-sort`로 알린다.

행마다 전체에서 차지하는 비율을 막대로 그린다. 이름은 화면에 맞게 바꾼다.

- 빈 들어온 곳 → "직접 들어옴"
- 나라 코드 → `Intl.DisplayNames`로 "대한민국 (KR)"
- 앱 이름 → 앱 목록(`manifest.ts`)의 이름 ("메모")
- `memo/cra-to-vite` → "메모 › cra-to-vite"

"유입 경로"의 묶어 보기는 호스트를 규칙으로 나눈다. google·naver·daum 같은 검색 엔진은 '검색', linkedin·x·kakao·velog 같은 곳은 '소셜', 빈 값은 '직접', 나머지는 '링크'다.

## 그래프: SVG 하나

차트 라이브러리를 들이지 않고 `<svg>`에 선 두 개를 그렸다. 방문은 아래를 옅게 채운 초록 선, 순방문자는 파란 점선이다. 창 폭에 맞춰 늘어나도록 `preserveAspectRatio="none"`을 주고, 그러면 선도 같이 늘어나 두꺼워지므로 `vector-effect: non-scaling-stroke`로 두께를 지킨다. 화면 읽기 프로그램에는 날짜별 숫자를 `aria-label`로 읽어 준다.

## 관리자에게만

앱 정보(`manifest.ts`)에 `adminOnly`를 더했다. Launchpad, 휴대폰 홈 화면, Finder의 '앱' 폴더는 관리자로 로그인했을 때만 이 앱을 보여 준다. 그래도 터미널의 `open activity`처럼 열 길은 남는다. 그때는 잠긴 화면("관리자만 볼 수 있습니다")과 관리자 로그인 단추만 보인다. 화면에서 감추는 것과 별개로 숫자는 **서버가** 관리자 세션을 확인하고 내준다(`AdminGuard`). 방문자가 화면을 고쳐도 숫자는 받을 수 없다.

## 다크 모드와 좁은 창

색은 사이트의 테마 변수만 쓴다. 다크 모드는 따로 손대지 않아도 바뀐다. 초록과 빨강(▲▼)만 앱 안의 변수로 두었다.

좁은 창과 휴대폰에서는 숫자 칸이 두 줄, 표가 한 줄씩 쌓인다. 화면 폭이 아니라 **창 폭**을 봐야 해서, 미디어 질의 대신 컨테이너 질의(`@container`)를 썼다. 데스크톱에서 창을 좁혀도 휴대폰과 같은 배치가 된다.

스크린샷으로 밝은 화면, 다크 모드, 휴대폰을 확인했다. 처음에는 표의 글자가 가운데로 몰렸다. 창이 글을 가운데로 정렬하고 있어서, 앱에서 왼쪽 정렬로 되돌렸다. 실시간의 시각은 "오후 12:02:00"이 칸을 넘쳐서 24시간 표기로 바꿨다.

## 시험

- 단위: 기간(한국 시간 오늘까지), 앞 기간 대비, 머문 시간 표기, 들어온 곳 묶기, 표의 이름, 흐름의 한 줄
- 화면(가짜 API): 방문자에게는 Launchpad에 없고 터미널로 열어도 잠긴 화면, 서버에 묻지도 않는다. 관리자는 개요의 숫자와 ▲▼, 그래프, 기간을 바꾸면 다시 묻기, 묶어 보기, 이름 정렬과 반대 정렬, 앱·글과 나라·기기, 실시간 흐름 펼치기
