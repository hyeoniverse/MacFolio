이 글은 2026년 10월에 git 기록을 다시 읽으며 쓴 회고다. 22일 밤과 23일 새벽에 커밋이 하나씩이라 한 편으로 묶었고, 날짜가 아니라 주제별로 정리했다. [11월 4일](/memo/day-20241104) 뒤 7주 만의 커밋이다. 화면 대신 이전 전후의 구조를 도식으로 그렸다.

![2024년 12월 22~23일 작업 흐름](./images/day-20241222-timeline.svg '22일 밤 9시 39분과 23일 새벽 2시 36분')

## 코드 형식 정리: 포매터 적용

22일 밤의 "fix: update UI/UX" 커밋은 메모·GitHub 앱과 창·음악 CSS 여섯 파일에서 1,611줄을 추가하고 1,498줄을 삭제했다. 공백 차이를 제외하면(`git diff -w`) 243줄 추가, 130줄 삭제다. 변경된 줄 대부분은 스페이스 들여쓰기를 탭으로 바꾸고, 한 줄에 나열한 구조 분해 할당을 한 줄에 하나씩 나눈 것이다. 코드 포매터를 처음 적용한 커밋으로 보인다.

| 기준           |  추가 |  삭제 |
| -------------- | ----: | ----: |
| 전체 diff      | 1,611 | 1,498 |
| 공백 차이 제외 |   243 |   130 |

## 서버 삭제와 Firebase 이전

23일 새벽 2시 36분 커밋은 59,588개 파일을 변경했다. 작업 내용은 세 가지다.

1. `server/`를 삭제했다. Express, TypeScript 컨트롤러, MySQL 연결이 모두 제거되었다.
2. `client/` 안의 앱을 저장소 루트로 옮겼다. `client/src`가 `src`가 되었고, React를 18.3에서 19.0으로 업그레이드했다.
3. Firebase를 연동했다. 호스팅은 `build` 폴더를 배포하고 모든 경로를 `index.html`로 재작성(rewrite)한다. 메모는 Realtime Database의 `memos/<폴더>/<id>` 경로에 저장한다.

추적하던 `node_modules` 파일은 60,798개에서 1,478개로 줄었다. 서버와 `client/`의 `node_modules`가 함께 제거되었기 때문이다.

![Firebase 전후 구조](./images/day-20241222-structure.svg '서버를 제거하고 브라우저가 데이터베이스를 직접 읽고 쓴다')

## 서버가 담당하던 권한 확인의 공백

서버를 제거하면서 서버가 담당하던 권한 확인도 함께 사라졌다. 이 커밋의 데이터베이스 보안 규칙은 다음과 같았다.

```json
{
	"rules": {
		".read": true,
		".write": true
	}
}
```

이 규칙에서는 누구나 모든 메모를 읽고 쓸 수 있다. 메모 비밀번호는 [두 달 전](/memo/day-20241021)에는 서버가 bcrypt 해시로 비교했는데, 이 커밋부터는 브라우저가 메모의 `password` 값을 그대로 읽어 `memo.password === password`로 비교한다. 비밀번호가 평문으로 데이터베이스에 저장되고, 그 데이터베이스는 누구나 읽을 수 있었다.

| 항목             | 서버 시절 (10월 21일~) | Firebase 이전 후 (12월 23일~) |
| ---------------- | ---------------------- | ----------------------------- |
| 비밀번호 저장    | bcrypt 해시            | 평문                          |
| 비교 위치        | 서버 미들웨어          | 브라우저                      |
| 데이터 읽기·쓰기 | 서버 경로만            | 규칙상 누구나                 |

## 지금과 비교하면

- **데이터베이스 규칙**: 2026년 9월 28일 새벽 1시 15분에 Realtime Database 규칙을 전체 차단으로 변경하고, 24분 뒤 Firebase 코드를 삭제했다([9월 28일 회고](/memo/day-0928)).
- **편집 권한**: 메모 편집은 먼저 아무도 할 수 없게 잠갔다가([관리자만 편집](/memo/read-only-memo)), API 서버와 GitHub 로그인이 생긴 뒤 관리자만 하게 했다([관리자 로그인](/memo/admin-login-github-oauth)).
- **호스팅**: Firebase Hosting에서 Cloudflare Workers로 이전했다. 지금 화면은 Worker가 정적 파일로 제공하고, API는 별도로 운영하는 NestJS 서버가 담당한다([백엔드 설계](/memo/backend-design)).

## 돌아보며

서버를 삭제한 이유는 커밋에 기록되어 있지 않다. 코드로 보면 Express 서버와 Cloud SQL을 별도로 운영하는 대신, 정적 호스팅과 관리형 데이터베이스로 전환하는 선택이었다. 그 과정에서 서버가 담당하던 "누가 쓸 수 있는가"의 확인은 아무 곳에서도 하지 않게 되었다. 서버를 제거할 때는 서버의 역할을 목록으로 정리하고, 각 역할을 어디로 옮길지 하나씩 정해야 했다.

2026년에 다시 서버를 구축할 때는 반대 순서로 진행했다. 먼저 데이터베이스를 차단하고 편집을 잠근 뒤, 서버에 로그인과 권한 확인을 구현하고 나서 편집을 허용했다.
