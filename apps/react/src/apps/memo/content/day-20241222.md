이 글은 2026년 10월에 git 기록을 다시 읽으며 쓴 회고다. 22일 밤과 23일 새벽에 커밋이 하나씩이라 한 편으로 묶었다. [11월 4일](/memo/day-20241104) 뒤 7주 만의 커밋이다. 화면 대신 옮기기 전후의 구조를 그림으로 그렸다.

![2024년 12월 22~23일 작업 흐름](./images/day-20241222-timeline.svg '22일 밤 9시 39분과 23일 새벽 2시 36분')

## 22일: 화면 손보기

"fix: update UI/UX" 커밋은 메모·GitHub 앱과 창·음악 CSS 여섯 파일에서 1,611줄을 더하고 1,498줄을 지웠다. 공백 차이를 빼고 보면 243줄 더하기, 130줄 지우기다. 바뀐 줄 대부분은 스페이스 들여쓰기를 탭으로 바꾸고, 한 줄에 몰아 쓴 구조 분해를 한 줄에 하나씩 펼친 것이다. 포매터를 처음 돌린 커밋으로 보인다.

## 23일: Firebase

새벽 2시 36분 커밋은 59,588개 파일을 바꿨다. 한 일은 셋이다.

1. `server/`를 지웠다. Express, TypeScript 컨트롤러, MySQL 연결이 모두 빠졌다.
2. `client/` 안의 앱을 저장소 루트로 올렸다. `client/src`가 `src`가 되었고, React는 18.3에서 19.0으로 올렸다.
3. Firebase를 붙였다. 호스팅은 `build` 폴더를 올리고 모든 주소를 `index.html`로 돌린다. 메모는 Realtime Database의 `memos/<폴더>/<id>`에 둔다.

추적하던 `node_modules` 파일은 60,798개에서 1,478개로 줄었다. 서버와 `client/` 쪽이 빠졌기 때문이다.

![Firebase 전후 구조](./images/day-20241222-structure.svg '서버를 없애고 브라우저가 데이터베이스를 바로 읽고 쓴다')

## 서버가 하던 일은 어디로 갔나

서버가 없으니 서버가 하던 확인도 같이 사라졌다. 이 커밋의 데이터베이스 규칙은 이랬다.

```json
{
	"rules": {
		".read": true,
		".write": true
	}
}
```

이 규칙대로라면 누구나 모든 메모를 읽고 쓸 수 있다. 메모 비밀번호는 [두 달 전](/memo/day-20241021)에는 서버가 bcrypt 해시로 비교했는데, 이제는 브라우저가 메모의 `password` 값을 그대로 읽어 `memo.password === password`로 비교한다. 비밀번호가 평문으로 데이터베이스에 있고, 그 데이터베이스는 누구나 읽을 수 있었다.

## 지금과 비교하면

- **데이터베이스 규칙**: 2026년 9월 28일 새벽 1시 15분에 Realtime Database 규칙을 전체 차단으로 바꾸고, 24분 뒤 Firebase를 지웠다([9월 28일 회고](/memo/day-0928)).
- **누가 고치나**: 메모 편집은 먼저 아무도 못 하게 잠갔다가([관리자만 편집](/memo/read-only-memo)), API 서버와 GitHub 로그인이 생긴 뒤 관리자만 하게 했다([관리자 로그인](/memo/admin-login-github-oauth)).
- **호스팅**: Firebase Hosting에서 Cloudflare Workers로 옮겼다. 지금 화면은 Worker가 정적 파일로 내주고, API는 따로 띄운 NestJS 서버가 맡는다([백엔드 설계](/memo/backend-design)).

## 돌아보며

서버를 지운 이유는 커밋에 적혀 있지 않다. 코드로 보면 Express 서버와 Cloud SQL을 따로 운영하는 대신, 정적 호스팅과 관리형 데이터베이스로 가는 길이었다. 그 길에서 서버가 맡던 "누가 쓸 수 있나"는 아무도 맡지 않게 되었다. 서버를 없앨 때는 서버가 하던 일을 목록으로 적고 하나씩 새 자리를 정해야 했다.

2026년에 다시 서버를 세울 때는 반대 순서로 갔다. 먼저 데이터베이스를 닫고 편집을 잠근 뒤, 로그인과 권한을 서버에 만들고 나서 편집을 열었다.
