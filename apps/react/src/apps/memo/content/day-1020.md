## 디자인 토큰을 세 층으로

전날까지 색·모서리·그림자에 이름(토큰)을 붙여 왔는데, `theme.css` 한 파일 안에서 이름 짓는 방식이 섞여 있었다. 기본 글자색 하나에 `--color-text`·`text-strong`·`label`·`popover-text`·`menubar-text` 다섯 이름이 있었고 값도 `#333`·`#000`·`#1d1d1f`·`#111` 네 가지였다. 빨강은 `red`·`danger`·`error`가 저마다 다른 값이었다. 모서리는 크기 이름(`xs`~`xl`)과 쓰임새 이름(`panel`·`window`)이 한 줄에 섞였다.

저녁에 이것을 세 층으로 다시 세웠다([#286](https://github.com/hyeoniverse/MacFolio/pull/286)).

| 1 원시값   | `primitives.css` | `--palette-*` 색 값, 숫자 이름의 `--radius-4…22`, 높이 단계 `--shadow-1…`      | 색은 쓰지 않음, 숫자 이름은 씀 |

## Finder를 진짜 OS처럼

### 열기 창의 빈 포트폴리오

저녁에 미리보기의 열기 창에서 **데스크탑 › 포트폴리오**를 열면 "비어 있음"이 뜨는데, **문서 › 포트폴리오**로 가면 프로젝트가 다 있는 것을 봤다.

| 고치기 전                                                                                             | 고친 뒤                                                                                              |
| ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| ![고치기 전](./images/finder-home-tree-openpanel-before.jpg '바탕화면의 포트폴리오를 열면 비어 있음') | ![고친 뒤](./images/finder-home-tree-openpanel-after.jpg '같은 동작으로 문서 › 포트폴리오가 열린다') |

바탕화면의 포트폴리오는 진짜 폴더가 아니라 가상본인데, 가상본을 "안이 빈 폴더에 원래 폴더 id를 붙인 것"으로 표현하고 있었다. Finder는 그 id를 따라갔지만 열기 창만 그 빈 폴더 자체로 들어갔다. 한 줄로 고칠 수 있었는데, "이런 거면 구조 자체에 허점이 있는 것 아니냐"고 물었다. 찾아보니 가상본을 만나는 곳 12곳이 "가상본이면 따라가라"를 저마다 기억해서 지키고 있었다. git 기록에서는 전날(19일) 새벽 열기 창이 트리를 쓰기 시작한 지 두 시간 뒤에 가상본이 들어오면서 열기 창만 빠졌고, 그날 오전 같은 파일을 고칠 때도 또 빠졌다. 그래서 가상본을 폴더의 변형이 아니라 따로 된 종류(`kind: 'alias'`)로 나눴다([#282](https://github.com/hyeoniverse/MacFolio/pull/282)).

### 루트가 하나인 트리

그다음 내 Mac의 Finder 화면을 보내며 "진짜 OS처럼 루트가 따로 있고 거기에 폴더가 있는 구조가 맞지 않을까" 물었다. 이 사이트의 Finder는 데스크탑·문서·블로그·응용 프로그램이 서로 따로 된 꼭대기였다. Macintosh HD › 사용자 › hyeoniverse 아래에 데스크탑·문서·블로그와 macOS 기본 폴더(공용·그림·다운로드·동영상·음악)를 두고, 사이드바의 즐겨찾기를 그 안 폴더로 가는 바로가기로 바꿨다. 블로그를 어디에 둘지, 빈 기본 폴더를 만들지, 홈 이름은 무엇으로 할지는 내가 정했다(홈 안, 만든다, `hyeoniverse`). 서버에 저장한 폴더 id는 그대로 두고 그 위에 노드만 얹어서 서버는 바뀌지 않는다([#285](https://github.com/hyeoniverse/MacFolio/pull/285), [바탕화면의 포트폴리오만 비어 있었다](/memo/finder-home-tree)).

![홈 폴더](./images/finder-home-tree-home.jpg 'Macintosh HD › 사용자 › hyeoniverse. 기본 폴더 앞면에 macOS처럼 문양을 넣었다')

### 그림과 음악

빈 기본 폴더를 보니 채우고 싶어졌다. "음악 폴더에 음악 앱의 곡을, 그림에는 사진 앱의 사진을" 넣자고 했고, 구조상 맞다면 프로젝트 폴더 안에 있던 사진 폴더를 그림으로 옮기라고 했다. 같은 사진이 두 곳에 있으면 원래 자리가 흐려지기 때문이다. 음악은 아티스트 › 앨범 › 곡으로 두고, 곡을 열면 음악 앱이 그 앨범을 재생 목록 삼아 그 곡부터 재생한다([#287](https://github.com/hyeoniverse/MacFolio/pull/287)). 곡이라는 새 종류를 더하자, #282에서 Finder의 열기 끝에 넣어 둔 `never` 검사가 "여는 법을 정하라"는 컴파일 오류를 냈다. 빠뜨릴 수 없게 만든 장치가 바로 다음 PR에서 일했다.

## 같은 저녁, 두 작업이 부딪힌 곳

토큰 정리와 Finder 작업은 같은 저녁에 따로 진행했다. 서로 겹치는 파일이 거의 없어서 괜찮을 줄 알았는데, 한 줄에서 두 번 만났다.

![같은 저녁, 두 작업이 만난 곳](./images/day-1020-collision.svg '#280이 숫자 4px를 막자 Finder 쪽 커밋이 CI에서 걸렸고, #286이 --radius-xs를 --radius-4로 바꾸자 방금 고친 줄이 정의되지 않은 이름을 가리키게 되었다')

1. 20시 47분, 음악 앱의 앨범 그림 모서리를 `border-radius: 4px`로 적은 커밋이 CI의 린트에서 걸렸다. 19시 21분에 머지한 #280이 이름 있는 값(4px = `--radius-xs`)을 숫자로 쓰지 못하게 막았기 때문이다. 5분 뒤 `var(--radius-xs)`로 고쳤다
2. 21시 13분에 #286이 모서리 이름을 숫자 이름으로 바꾸면서 `--radius-xs`가 사라졌다. 방금 고친 줄은 정의되지 않은 변수를 가리키게 되었다. 이번에는 린트도 CI도 아무 말이 없었다. 정의되지 않은 CSS 변수는 오류 없이 무시되고, 모서리 둥글림만 조용히 사라진다. 22시 46분에 `var(--radius-4)`로 다시 고쳤다

숫자를 막는 규칙은 첫 번째를 잡았지만, 이름이 바뀐 두 번째는 사람이 찾아야 했다. 다음 날 아침에는 "토큰을 대대적으로 고쳤는데 스타일이 어긋난 데가 없냐"고 물어, main과 Finder 브랜치를 같은 장면에서 찍어 픽셀로 비교했다. 같아야 하는 장면 14장(라이트·다크)이 모두 차이 0이었다.

## 서버 접속과 개발 환경

낮의 빈 시간은 여기에 썼다. 로컬 API의 `.env`를 잃어버려 서버의 배포 값을 가져오려 했는데, 새 Mac에 서버 SSH 키가 없었다. 비밀번호 계정이 없는 Ubuntu 서버라 시리얼 콘솔로도 못 들어가서, 원래 서버 디스크를 떼어 임시 VM에 붙이고 새 키를 넣기로 했다.

![임시 VM이 원래 서버 디스크로 부팅된 과정](./images/oracle-ssh-key-recovery-boot.svg '두 디스크의 루트 이름표가 같아, 디스크를 붙인 임시 VM이 원래 서버 디스크로 부팅되었다')

그런데 디스크를 붙인 임시 VM이 17시 54분에 재부팅되면서 **원래 서버 디스크로** 떠 있었다. cloud-init이 새 VM의 첫 부팅으로 보고 임시 VM에 넣은 공개 키를 원래 서버의 `authorized_keys`에 대신 넣어 둔 상태였다. 되돌려 켜자 18시 13분에 API가 돌아왔고, 바뀐 호스트 키로 배포 secret(`DEPLOY_KNOWN_HOSTS`)을 고치고 잃어버린 옛 키 줄을 지웠다. 그 사이 키 암호와 공개 키를 헷갈리고, `lsblk`를 Cloud Shell에서, `scp`를 서버 안에서 치는 시행착오가 있었다([SSH 키를 잃어버린 Oracle 서버 되살리기](/memo/oracle-ssh-key-recovery), [#278](https://github.com/hyeoniverse/MacFolio/pull/278)).

로컬도 맞췄다. pnpm이 없어 급하게 `npm install`부터 쳤다가 루트 패키지만 깔리고 `package-lock.json`이 생겼다. Node 25부터 corepack이 빠진 탓이었다([zsh: command not found: pnpm](/memo/pnpm-command-not-found)). 서버에서 받은 배포 값으로 로컬 `.env`를 만들 때는 `DATABASE_URL`·`CORS_ORIGINS`처럼 로컬에 맞지 않는 키만 고쳤고, GitHub OAuth는 콜백 주소가 다르니 개발용 앱 값을 새로 받기로 했다. Docker Desktop은 설치만 하고 한 번도 켜지 않아 `docker` 명령조차 없었다.

## 돌아보며

[10월 19일](/memo/day-1019)에는 겹치는 일을 나란히 하지 말자고 적었다. 이날은 겹치지 않는다고 생각한 두 일이 이름 하나에서 만났다. 토큰 쪽은 이름을 바꾸고, Finder 쪽은 그 이름을 새로 썼다. 파일이 겹치지 않아도 **같은 이름을 쓰면** 겹치는 일이다. 이름을 바꾸는 작업은 다른 작업을 다 머지한 뒤에 하거나, 바꾸는 쪽이 옛 이름을 쓰는 곳을 끝까지 찾아야 한다. 정의되지 않은 CSS 변수를 막는 규칙도 있으면 좋겠다.

가상본 버그와 CSS 변수 이름은 같은 모양의 문제였다. "가상본이면 따라가라", "이 이름은 이제 없다" 같은 규칙을 사람이 기억해야 하면 언젠가 빠진다. 가상본은 따로 된 종류로 나눠 컴파일러가 잡게 했고, 숫자 값은 Stylelint가 잡게 했다. 아직 사람이 기억해야 하는 것(사라진 CSS 변수, 스택 PR의 base)이 남아 있다.

서버 키를 잃은 일은 새 Mac으로 옮기며 `~/.ssh`를 챙기지 않아서였다. 새 키와 그 암호는 Mac 밖에도 따로 두고, Mac을 바꿀 때 옮길 목록에 `~/.ssh`를 넣어야 한다.
