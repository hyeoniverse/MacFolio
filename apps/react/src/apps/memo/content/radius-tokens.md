[z-index에 이름을 붙인](/memo/z-index-layers) 다음 대상은 모서리 둥글기(`border-radius`)다. 새 카드나 버튼을 만들 때마다 "다른 카드는 몇 px였지?"를 기존 CSS에서 검색해야 했다([#232](https://github.com/hyeoniverse/MacFolio/pull/232)).

계기는 10월 12일이었다. 메모 편집기에 추가한 접기 토글의 모서리가 다른 요소와 같은 둥글기인지 확인하려 했는데, 비교할 기준 값이 없었다. 같은 확인이 버튼·카드마다 반복되므로 값에 이름을 붙이기로 했다.

## border-radius가 무엇인가

상자 모서리의 곡률 반경을 지정하는 CSS 속성이다([MDN `border-radius`](https://developer.mozilla.org/en-US/docs/Web/CSS/border-radius)). 값이 클수록 더 둥글다. 높이의 절반보다 큰 값을 지정하면 양 끝이 반원인 알약 모양이 되고, `50%`를 지정하면 정사각형이 원이 된다.

## 사용 현황 집계

`src` 아래 CSS에서 `border-radius`는 576곳이었다. 값은 마흔 가지가 넘었다.

| 값                         | 사용 수      | 용도                     |
| -------------------------- | ------------ | ------------------------ |
| 50%                        | 84           | 원 (아바타, 동그란 버튼) |
| 999px                      | 73           | 알약 (검색 칸, 배지)     |
| 6px                        | 46           | 작은 버튼, 입력 칸       |
| 8px                        | 42           | 버튼, 메뉴               |
| 14px                       | 34           | 카드                     |
| 10px                       | 29           | 목록 상자                |
| 4px                        | 15           | 작은 표시, 코드 조각     |
| 12 · 22 · 18 · 20 · 16px … | 각 20곳 아래 | 앱마다 다른 모양         |

원(50%)을 제외한 위의 여섯 값만으로 239곳, 전체의 40%가 넘는다.

![border-radius 값별 사용 횟수 막대 그래프](./images/radius-tokens-counts.svg '색칠한 여섯 값에 이름을 붙였다. 원은 이미 뜻이 분명해 그대로 두었다')

## 이름을 붙이는 방법 비교

| 방법                                           | 장점                                         | 단점                                      |
| ---------------------------------------------- | -------------------------------------------- | ----------------------------------------- |
| 값을 하나로 통합한다 (예: 버튼은 모두 8px)     | 이름 수가 적다                               | 화면이 바뀐다. 앱마다 맞춘 모양이 깨진다  |
| Sass 변수나 Tailwind 설정에 정의한다           | 빌드 시각에 값이 치환된다                    | 이 저장소는 Sass도 Tailwind도 쓰지 않는다 |
| CSS 변수로 이름만 붙이고 같은 값만 교체 (채택) | 화면이 그대로다. 개발자 도구에서 값이 보인다 | 이름 없이 숫자를 쓰는 것을 막지는 못한다  |

## 이름 붙이기

`styles/theme.css`에 [CSS 사용자 지정 속성](https://developer.mozilla.org/en-US/docs/Web/CSS/Using_CSS_custom_properties)[^custom] 여섯 개를 정의했다.

```css
:root {
	--radius-xs: 4px;
	--radius-sm: 6px;
	--radius-md: 8px;
	--radius-lg: 10px;
	--radius-xl: 14px;
	--radius-full: 999px; /* 알약 */
}
```

![여섯 이름이 가리키는 둥글기](./images/radius-tokens-shapes.svg '같은 상자에 4·6·8·10·14·999px를 적용한 모양과 이름, 주요 용도')

그리고 34개 CSS 파일에서 `border-radius: 8px;`처럼 이 값 하나만 지정된 239곳을 `border-radius: var(--radius-md);`로 교체했다. 값이 같으므로 화면은 1px도 달라지지 않는다. 커밋(`ef26f3e67`)은 36개 파일에서 302줄을 추가하고 239줄을 삭제했다. 삭제한 줄 수가 교체한 위치 수와 같다.

```css
/* 전 */
.memo-search {
	border-radius: 999px;
}
/* 후 */
.memo-search {
	border-radius: var(--radius-full);
}
```

교체한 날 다시 집계하면 `border-radius: 6px;`·`8px;`·`999px;`처럼 이름이 있는 값을 숫자로 작성한 줄은 0곳이었다.

## 교체하지 않은 값

| 값                                                  | 유지한 이유                                                                                                              |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| 원(`50%`)                                           | 크기와 관계없이 원을 뜻하므로 값 자체가 의미를 드러낸다                                                                  |
| 모서리마다 다른 값 (`14px 14px 0 0` 같은 하단 시트) | 단일 값이 아니다                                                                                                         |
| 나머지 값 (12·22·18px 등)                           | 앱마다 iOS·macOS 모양에 맞춰 고른 값이 많다. 가까운 이름으로 통합하면 모양이 바뀌므로 디자인을 맞출 시각에 개별 결정한다 |

이제 새 카드는 `var(--radius-xl)`, 새 알약은 `var(--radius-full)`로 작성하면 다른 요소와 같은 둥글기가 된다.

## 사흘 뒤 재집계

이 글을 수정한 10월 19일에 같은 방법으로 다시 집계했다.

![이름 쓰는 곳과 다시 생긴 숫자](./images/radius-tokens-after.svg '이름은 그대로 쓰이지만, 뒤에 더한 코드는 숫자로 적었다')

|                                               | 10월 16일 (바꾼 날) | 10월 19일 |
| --------------------------------------------- | ------------------- | --------- |
| `border-radius` 줄                            | 576                 | 921       |
| `var(--radius-*)`                             | 239                 | 246       |
| 이름이 있는 값을 숫자로 (`6px`·`8px`·`999px`) | 0                   | 115       |

`border-radius` 줄이 사흘 만에 345줄 늘었는데, 이름을 쓴 줄은 7줄만 늘었다. 숫자로 다시 생긴 115줄은 대부분 그 사이 크게 늘어난 Safari 프로젝트 페이지 템플릿(`apps/safari`)에 있다. 이름을 정의하는 것만으로는 새 코드가 이름을 사용하도록 강제되지 않았다.

## 남은 것·배운 것

- 이름 사용을 유지하려면 자동 검사가 필요하다. 이 글을 쓴 시각에는 그런 규칙이 없었고, 이후 [#280](https://github.com/hyeoniverse/MacFolio/pull/280)의 Stylelint 규칙이 그 역할을 맡았다.
- 12·22·18px처럼 이름 없는 값은 디자인을 맞출 시각에 개별 결정하기로 하고 유지했다.
- 화면을 바꾸지 않는 리팩터링은 "같은 값만 교체한다"는 규칙 하나로 리뷰가 단순해진다. 삭제한 줄 수와 교체한 위치 수가 같은지만 확인하면 된다.
