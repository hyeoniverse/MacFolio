[z-index에 이름을 붙인](/memo/z-index-layers) 다음 차례는 모서리 둥글기(`border-radius`)다. 새 카드나 버튼을 만들 때마다 "다른 카드는 몇 px였지?"를 찾아야 했다([PR #232](https://github.com/hyeoniverse/MacFolio/pull/232)).

## border-radius가 무엇인가

상자의 모서리를 얼마나 둥글게 깎을지 정하는 CSS 속성이다. 값이 클수록 더 둥글다. 높이의 절반보다 크게 주면 양 끝이 반원인 알약 모양이 되고, `50%`를 주면 정사각형이 원이 된다.

## 세어 보기

`src` 아래 CSS에서 `border-radius`는 576곳이었다. 값은 마흔 가지가 넘었다.

| 값                         | 곳           | 무엇                     |
| -------------------------- | ------------ | ------------------------ |
| 50%                        | 84           | 원 (아바타, 동그란 버튼) |
| 999px                      | 73           | 알약 (검색 칸, 배지)     |
| 6px                        | 46           | 작은 버튼, 입력 칸       |
| 8px                        | 42           | 버튼, 메뉴               |
| 14px                       | 34           | 카드                     |
| 10px                       | 29           | 목록 상자                |
| 4px                        | 15           | 작은 표시, 코드 조각     |
| 12 · 22 · 18 · 20 · 16px … | 각 20곳 아래 | 앱마다 다른 모양         |

원(50%)을 뺀 위의 여섯 값만으로 239곳, 전체의 40%가 넘는다.

![border-radius 값별 사용 횟수 막대 그래프](./images/radius-tokens-counts.svg '색칠한 여섯 값에 이름을 붙였다. 원은 이미 뜻이 분명해 그대로 두었다')

## 어떻게 이름을 붙일까

| 방법                                             | 좋은 점                                   | 문제                                      |
| ------------------------------------------------ | ----------------------------------------- | ----------------------------------------- |
| 값을 하나로 합친다 (예: 버튼은 모두 8px)         | 이름이 적다                               | 화면이 바뀐다. 앱마다 맞춘 모양이 깨진다  |
| Sass 변수나 Tailwind 설정에 둔다                 | 빌드 때 값이 들어간다                     | 이 저장소는 Sass도 Tailwind도 쓰지 않는다 |
| CSS 변수로 이름만 붙이고 같은 값만 바꾼다 (고름) | 화면이 그대로다. 브라우저에서 값이 보인다 | 이름 없이 숫자를 쓰는 것을 막지는 못한다  |

## 이름 붙이기

`styles/theme.css`에 여섯 이름을 두었다.

```css
:root {
	--radius-xs: 4px;
	--radius-sm: 6px;
	--radius-md: 8px;
	--radius-lg: 10px;
	--radius-xl: 14px;
	--radius-full: 999px; /* 알약 */
}
```

그리고 34개 CSS 파일에서 `border-radius: 8px;`처럼 이 값 하나만 적힌 239곳을 `border-radius: var(--radius-md);`로 바꿨다. 값이 같으니 화면은 1px도 달라지지 않는다. 커밋(`ef26f3e67`)은 36개 파일, 302줄을 더하고 239줄을 지웠다. 지운 줄 수가 바꾼 곳 수와 같다.

```css
/* 전 */
.memo-search {
	border-radius: 999px;
}
/* 후 */
.memo-search {
	border-radius: var(--radius-full);
}
```

바꾼 날 다시 세어 보면 `border-radius: 6px;`·`8px;`·`999px;`처럼 이름이 있는 값을 숫자로 적은 줄은 0곳이었다.

## 바꾸지 않은 것

- **원(50%)**: 크기와 상관없이 원이라는 뜻이라 이미 이름이나 다름없다.
- **모서리마다 다른 값**(`14px 14px 0 0` 같은 위쪽만 둥근 시트): 한 값이 아니라 그대로 두었다.
- **나머지 값(12·22·18px 등)**: 앱마다 iOS·macOS 모양을 따라 고른 값이 많다. 여섯 이름 중 가까운 것으로 합치면 모양이 바뀌므로, 디자인을 맞출 때 하나씩 정한다.

이제 새 카드는 `var(--radius-xl)`, 새 알약은 `var(--radius-full)`로 시작하면 다른 곳과 같은 둥글기가 된다.

## 사흘 뒤 다시 세어 보니

이 글을 고치는 10월 19일에 같은 방법으로 다시 셌다.

![이름 쓰는 곳과 다시 생긴 숫자](./images/radius-tokens-after.svg '이름은 그대로 쓰이지만, 뒤에 더한 코드는 숫자로 적었다')

|                                               | 10월 16일 (바꾼 날) | 10월 19일 |
| --------------------------------------------- | ------------------- | --------- |
| `border-radius` 줄                            | 576                 | 921       |
| `var(--radius-*)`                             | 239                 | 246       |
| 이름이 있는 값을 숫자로 (`6px`·`8px`·`999px`) | 0                   | 115       |

`border-radius` 줄이 사흘 만에 345줄 늘었는데, 이름을 쓴 줄은 7줄만 늘었다. 숫자로 다시 생긴 115줄이 있는 파일은 대부분 그 사이 크게 늘어난 Safari 프로젝트 페이지 템플릿(`apps/safari`)이다. 이름을 붙이는 것만으로는 새 코드가 이름을 쓰게 되지 않았다.

## 남은 것·배운 것

- 이름을 지키게 하려면 검사가 있어야 한다. 예를 들어 stylelint로 `border-radius`에 이름이 있는 값을 숫자로 적으면 경고하게 하는 것이 다음 할 일이다. 지금은 그런 규칙이 없다.
- 12·22·18px처럼 이름 없는 값은 디자인을 맞출 때 하나씩 정하기로 하고 그대로 두었다.
- 화면을 바꾸지 않는 리팩터링은 "같은 값만 바꾼다"는 규칙 하나로 리뷰가 쉬워진다. 지운 줄 수와 바꾼 곳 수가 같은지만 보면 된다.
