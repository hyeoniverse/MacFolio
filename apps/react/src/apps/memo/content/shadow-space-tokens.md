z-index, 모서리 둥글기, 글자 크기에 이어 그림자와 간격에도 이름을 붙였다([#248](https://github.com/hyeoniverse/MacFolio/pull/248)). 색은 다음 작업으로 미뤘다. 리팩터링 계획([#150](https://github.com/hyeoniverse/MacFolio/issues/150))의 5단계(스타일) 중 하나다.

## 배경

간격은 CSS에서 가장 많이 작성하는 값이다. 숫자로만 작성되어 있으면 인접 화면이 어떤 간격을 썼는지 파일을 열어야 알 수 있다. 이름이 있으면 같은 용도의 위치에 같은 이름을 쓰게 되고, 이후 간격 체계를 바꿀 때 수정할 위치가 한 곳이 된다.

그림자는 반대 문제였다. 같은 요소(휴대폰 화면의 플로팅 버튼)의 그림자를 여섯 곳이 같은 값으로 각각 정의하고 있었다. 하나를 수정하면 나머지 다섯 곳과 어긋난다.

## 채택한 방법과 제외한 방법

| 방법                                        | 장점                                | 단점                                                                |
| ------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------- |
| 4px 격자로 맞추고 6·10·14px을 가까운 값으로 | 간격 체계가 단순해진다              | 수백 곳이 1~2px씩 이동한다. 이번 단계의 "화면 유지" 규칙에 어긋난다 |
| `--space-sm`·`--space-md` 같은 의미 이름    | 값을 바꿔도 이름이 유효하다         | 열 단계를 구분할 이름이 부족하고, 이름만으로는 크기를 알 수 없다    |
| 자주 쓰는 열 값에 px 숫자 이름 (채택)       | 값이 같으므로 자동 비교로 확인 가능 | 이름이 값을 나타내므로, 값을 바꾸려면 이름도 바꿔야 한다            |

## 그림자 집계

`src` 아래 CSS에서 [`box-shadow`](https://developer.mozilla.org/en-US/docs/Web/CSS/box-shadow)는 305곳이었다. 그런데 대부분은 이미 앱별로 정의한 변수(`--phone-float-shadow`, `--qc-shadow` 등)를 사용하거나, 테두리 대신 쓰는 `0 0 0 1px` 한 줄이거나, 한두 곳에만 나오는 값이었다. 같은 값이 세 곳 이상 반복된 것은 다섯 가지뿐이다.

| 이름             | 값                                                        | 사용 수 | 용도                             |
| ---------------- | --------------------------------------------------------- | ------- | -------------------------------- |
| `--shadow-float` | `0 0 0 0.5px rgba(0,0,0,.06), 0 4px 14px rgba(0,0,0,.12)` | 6       | 휴대폰 화면의 플로팅 버튼        |
| `--shadow-menu`  | `0 0 0 0.5px rgba(0,0,0,.15), 0 10px 30px rgba(0,0,0,.2)` | 3       | 메뉴, 날짜 선택기, 설정의 팝오버 |
| `--shadow-md`    | `0 6px 18px rgba(0,0,0,.18)`                              | 3       | 작은 카드                        |
| `--shadow-lg`    | `0 8px 30px rgba(0,0,0,.18)`                              | 3       | 휴대폰 홈 위젯, 날씨 카드        |
| `--shadow-xl`    | `0 18px 40px rgba(0,0,0,.12)`                             | 4       | Safari 프로젝트 소개의 큰 카드   |

![그림자 다섯 이름](./images/shadow-space-tokens-shadows.svg '같은 카드에 다섯 그림자를 걸어 본 모양')

이 값들은 라이트와 다크에서 같은 값을 사용하므로 테마별 값을 따로 정의하지 않았다. 창과 팝오버처럼 테마마다 값이 다른 그림자는 이미 `--shadow-window`·`--shadow-popover`가 담당하고 있다.

## 간격 집계

`padding`·`margin`·`gap`은 모두 3,657곳이었다. 값 하나만 지정된 선언에서 자주 나온 값은 다음과 같다.

| 값   | 사용 수 |
| ---- | ------- |
| 8px  | 252     |
| 6px  | 181     |
| 10px | 176     |
| 12px | 129     |
| 4px  | 125     |
| 16px | 104     |
| 14px | 101     |
| 2px  | 82      |
| 20px | 76      |
| 24px | 68      |
| 18px | 63      |

24px까지는 2px 단위로 촘촘하게 사용하고, 그 위로는 빈도가 낮아진다. 그래서 2·4·6·8·10·12·14·16·20·24px 열 값을 선택하고, 이름에 px 값을 그대로 넣었다(`--space-8`은 8px). `sm`·`md` 같은 이름으로는 열 단계를 구분하기에 부족하고, 숫자를 보면 바로 크기를 알 수 있기 때문이다.

토큰은 `src/styles/theme.css`의 `:root`에 정의했다.

```css
/* apps/react/src/styles/theme.css */
--space-2: 2px;
--space-4: 4px;
--space-6: 6px;
--space-8: 8px;
--space-10: 10px;
--space-12: 12px;
--space-14: 14px;
--space-16: 16px;
--space-20: 20px;
--space-24: 24px;

--shadow-float: 0 0 0 0.5px rgba(0, 0, 0, 0.06), 0 4px 14px rgba(0, 0, 0, 0.12); /* 휴대폰 떠 있는 버튼 */
--shadow-menu: 0 0 0 0.5px rgba(0, 0, 0, 0.15), 0 10px 30px rgba(0, 0, 0, 0.2); /* 메뉴·날짜 고르기 */
```

교체 기준은 하나다. **선언의 값이 모두 이 열 값일 때만** 교체했다.

| 선언                | 교체 여부 | 이유                     |
| ------------------- | --------- | ------------------------ |
| `gap: 8px`          | 교체      | 열 값                    |
| `padding: 6px 10px` | 교체      | 모두 열 값               |
| `padding: 0 12px`   | 유지      | 0이 섞임                 |
| `margin: auto 8px`  | 유지      | `auto`가 섞임            |
| 음수·`calc()` 포함  | 유지      | 열 값이 아닌 요소가 섞임 |

이 기준으로 1,543곳을 교체했다.

| 이름         | 값   | 교체한 값의 수 |
| ------------ | ---- | -------------- |
| `--space-2`  | 2px  | 113            |
| `--space-4`  | 4px  | 201            |
| `--space-6`  | 6px  | 235            |
| `--space-8`  | 8px  | 321            |
| `--space-10` | 10px | 254            |
| `--space-12` | 12px | 214            |
| `--space-14` | 14px | 165            |
| `--space-16` | 16px | 163            |
| `--space-20` | 20px | 103            |
| `--space-24` | 24px | 88             |

![--space-2부터 --space-24까지 바꾼 곳의 수 막대. 8px이 321곳으로 가장 많다](./images/shadow-space-tokens-counts.svg '이름으로 바꾼 간격 값의 수')

## 이름을 붙이지 않은 값

- **18px(63곳)·28px(47곳)과 그 밖의 값**: 열 값 사이에 있거나 앱 하나에 집중된 값이다. 가까운 이름으로 통합하면 화면이 1~2px 이동하므로, 화면을 보며 하나씩 결정한다.
- **0이 섞인 단축 속성 표기**: `padding: 0 12px`의 0은 이름을 붙일 값이 아니고, 12px만 교체하면 한 줄에 숫자와 이름이 섞여 가독성이 떨어진다.
- **한두 곳에만 나오는 그림자, 앱 변수로 정의한 그림자**: 이름을 붙여도 재사용할 곳이 없다.

교체 결과는 다음과 같다. 메모의 버전 목록 버튼에서 `6px 10px`은 이름으로 바뀌고, 열 값에 없는 `gap: 1px`은 그대로 남았다.

```css
/* apps/react/src/apps/memo/styles/note.css */
.memo-format-panel .memo-revision-list button {
	gap: 1px;
	padding: var(--space-6) var(--space-10);
	border-radius: var(--radius-md);
}
```

## 확인

PR 하나에서 70개 파일, 1,656줄을 추가하고 1,576줄을 삭제했다. 이 정도 변경량은 육안으로 확인할 수 없다. 교체 전후의 빌드를 각각 실행해, 데스크톱과 iPhone 크기, 라이트와 다크에서 여러 앱 화면의 모든 요소의 계산된 스타일을 비교했다. 차이는 없었다. `var()`는 계산된 값에서 원래 숫자로 치환되므로 브라우저가 적용하는 값은 같다.

| 비교 축   | 조합                     |
| --------- | ------------------------ |
| 뷰포트    | 데스크톱, iPhone         |
| 테마      | 라이트, 다크             |
| 비교 대상 | 여러 앱 화면의 모든 요소 |
| 결과      | 계산된 스타일 차이 0     |

## 이후 변경

이 글을 쓴 시각에 CSS에서 `--space-*`는 1,908곳에 사용됐다. 교체한 1,543곳보다 365곳 많다. 이후에 만든 화면도 숫자 대신 이름을 쓰고 있다는 의미다. 가장 많이 사용되는 것은 여전히 `--space-8`(333곳)이었다. 그림자 다섯 값은 19곳에서 21곳으로 늘었다.

그 뒤 토큰 구조가 두 번 바뀌었다.

| 병합일    | PR                                                       | 변경                                                                                                                                                         |
| --------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 10월 20일 | [#280](https://github.com/hyeoniverse/MacFolio/pull/280) | Stylelint 규칙 추가. `gap`·`padding`·`margin`에 2~24px 열 값을 단일 값으로 작성하면 `pnpm lint`가 실패한다                                                   |
| 10월 20일 | [#294](https://github.com/hyeoniverse/MacFolio/pull/294) | 그림자를 높이 단계(`--shadow-1`~`--shadow-7`, `styles/tokens/primitives.css`)와 용도 이름(`raised`·`float`·`card`·`menu`·`modal`, `semantic.css`)으로 재구성 |

## 남은 것과 배운 것

- **18px·28px은 화면을 보며 결정한다.** 값 하나만 지정된 선언만 집계해도 둘을 합쳐 110곳이 1~2px씩 이동한다. 값 수정 작업이므로 이름 부여와 분리한다.
- **토큰 사용 강제는 별도 작업이었다.** 이 글을 쓴 시각에는 장치가 없었고, 이후 #280에서 "이름이 있는 값만 차단"하는 방식으로 예외 목록 없이 해결했다.
- **세 곳 이상만 이름을 붙인다.** 그림자는 305곳 중 다섯 값 19곳만 이름이 됐다. 한두 곳에만 쓰는 값에 이름을 붙이면 이름 목록만 길어진다.
- **이름에 값을 넣는 것도 방법이다.** `--space-8`은 8px이라는 것이 이름에 드러난다. 체계를 바꾸는 시각에는 이름도 바꿔야 하지만, 그전까지는 값을 기억할 필요가 없다.
