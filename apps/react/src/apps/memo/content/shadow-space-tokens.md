z-index, 모서리 둥글기, 글자 크기에 이어 그림자와 간격에도 이름을 붙였다. 색은 다음 차례로 미룬다. 리팩터링 계획([#150](https://github.com/hyeoniverse/MacFolio/issues/150))의 5단계(스타일) 중 하나다.

## 왜

간격은 CSS에서 가장 많이 적는 값이다. 숫자로만 적혀 있으면 이웃 화면이 어떤 간격을 썼는지 파일을 열어 봐야 안다. 이름이 있으면 같은 뜻의 자리에 같은 이름을 쓰게 되고, 나중에 간격 체계를 바꿀 때 찾을 곳이 한 군데가 된다.

그림자는 반대 문제였다. 같은 모양(휴대폰 화면의 떠 있는 버튼)을 여섯 곳이 같은 값으로 따로 적고 있었다. 하나를 고치면 나머지 다섯이 어긋난다.

## 고른 방법과 버린 방법

| 방법                                        | 좋은 점                             | 걸린 점                                                             |
| ------------------------------------------- | ----------------------------------- | ------------------------------------------------------------------- |
| 4px 격자로 맞추고 6·10·14px을 가까운 값으로 | 간격 체계가 깔끔해진다              | 수백 곳이 1~2px씩 움직인다. 이번 단계의 "화면 그대로" 규칙을 어긴다 |
| `--space-sm`·`--space-md` 같은 뜻 이름      | 값을 바꿔도 이름이 맞는다           | 열 값을 나눌 이름이 모자라고, 이름만 봐서는 크기를 모른다           |
| 자주 쓰는 열 값에 px 숫자 이름 (고름)       | 값이 그대로라 기계로 확인할 수 있다 | 이름이 값을 말하므로, 값을 바꾸려면 이름도 바꿔야 한다              |

## 그림자 세어 보기

`src` 아래 CSS에서 `box-shadow`는 305곳이었다. 그런데 대부분은 이미 앱마다 둔 변수(`--phone-float-shadow`, `--qc-shadow` 등)를 쓰거나, 테두리 대신 그리는 `0 0 0 1px` 한 줄이거나, 한두 곳에만 나오는 값이었다. 똑같은 값이 세 곳 이상 되풀이된 것은 다섯 가지뿐이다.

| 이름             | 값                                                        | 곳  | 쓰임                             |
| ---------------- | --------------------------------------------------------- | --- | -------------------------------- |
| `--shadow-float` | `0 0 0 0.5px rgba(0,0,0,.06), 0 4px 14px rgba(0,0,0,.12)` | 6   | 휴대폰 화면의 떠 있는 버튼       |
| `--shadow-menu`  | `0 0 0 0.5px rgba(0,0,0,.15), 0 10px 30px rgba(0,0,0,.2)` | 3   | 메뉴, 날짜 고르기, 설정의 팝오버 |
| `--shadow-md`    | `0 6px 18px rgba(0,0,0,.18)`                              | 3   | 작은 카드                        |
| `--shadow-lg`    | `0 8px 30px rgba(0,0,0,.18)`                              | 3   | 휴대폰 홈 위젯, 날씨 카드        |
| `--shadow-xl`    | `0 18px 40px rgba(0,0,0,.12)`                             | 4   | Safari 프로젝트 소개의 큰 카드   |

![그림자 다섯 이름](./images/shadow-space-tokens-shadows.svg '같은 카드에 다섯 그림자를 걸어 본 모양')

이 값들은 라이트와 다크에서 똑같이 쓰고 있어서 테마별 값을 따로 두지 않았다. 창과 팝오버처럼 테마마다 값이 다른 그림자는 이미 `--shadow-window`·`--shadow-popover`가 맡고 있다.

## 간격 세어 보기

`padding`·`margin`·`gap`은 모두 3,657곳이었다. 값 하나만 적힌 선언에서 자주 나온 값은 이렇다.

| 값   | 곳  |
| ---- | --- |
| 8px  | 252 |
| 6px  | 181 |
| 10px | 176 |
| 12px | 129 |
| 4px  | 125 |
| 16px | 104 |
| 14px | 101 |
| 2px  | 82  |
| 20px | 76  |
| 24px | 68  |
| 18px | 63  |

24px까지는 2px 간격으로 촘촘하게 쓰고, 그 위로는 드물어진다. 그래서 2·4·6·8·10·12·14·16·20·24px 열 값을 고르고, 이름에 px 숫자를 그대로 넣었다(`--space-8`은 8px). `sm`·`md` 같은 이름은 열 칸을 나누기에 모자라고, 숫자를 보면 바로 크기를 알 수 있기 때문이다.

토큰은 `src/styles/theme.css`의 `:root`에 둔다.

```css
/* apps/react/src/styles/theme.css */
--space-2: 2px;
--space-4: 4px;
--space-6: 6px;
--space-8: 8px;
--space-10: 10px;
--space-12: 12px;
--space-14: 14px;
--space-16: 16px;
--space-20: 20px;
--space-24: 24px;

--shadow-float: 0 0 0 0.5px rgba(0, 0, 0, 0.06), 0 4px 14px rgba(0, 0, 0, 0.12); /* 휴대폰 떠 있는 버튼 */
--shadow-menu: 0 0 0 0.5px rgba(0, 0, 0, 0.15), 0 10px 30px rgba(0, 0, 0, 0.2); /* 메뉴·날짜 고르기 */
```

바꾼 기준은 하나다. **선언의 값이 모두 이 열 값일 때만** 바꿨다. `gap: 8px`이나 `padding: 6px 10px`은 바꾸고, `padding: 0 12px`처럼 0이 섞이거나 `auto`·음수·`calc()`가 섞인 선언은 그대로 두었다. 이렇게 1,543곳을 바꿨다.

| 이름         | 값   | 바꾼 값의 수 |
| ------------ | ---- | ------------ |
| `--space-2`  | 2px  | 113          |
| `--space-4`  | 4px  | 201          |
| `--space-6`  | 6px  | 235          |
| `--space-8`  | 8px  | 321          |
| `--space-10` | 10px | 254          |
| `--space-12` | 12px | 214          |
| `--space-14` | 14px | 165          |
| `--space-16` | 16px | 163          |
| `--space-20` | 20px | 103          |
| `--space-24` | 24px | 88           |

![--space-2부터 --space-24까지 바꾼 곳의 수 막대. 8px이 321곳으로 가장 많다](./images/shadow-space-tokens-counts.svg '이름으로 바꾼 간격 값의 수')

## 이름을 붙이지 않은 값

- **18px(63곳)·28px(47곳)과 그 밖의 값**: 열 값 사이에 끼거나 앱 하나에 몰린 값이다. 가까운 이름으로 합치면 화면이 1~2px 움직이므로, 화면을 보며 하나씩 정한다.
- **0이 섞인 줄임 표기**: `padding: 0 12px`의 0은 이름을 붙일 값이 아니고, 12px만 바꾸면 한 줄에 숫자와 이름이 섞여 오히려 읽기 어렵다.
- **한두 곳에만 나오는 그림자, 앱 변수로 둔 그림자**: 이름을 붙여도 다시 쓰일 곳이 없다.

바꾼 모습은 이렇다. 메모의 버전 목록 버튼에서 `6px 10px`은 이름이 되고, 열 값에 없는 `gap: 1px`은 그대로 남았다.

```css
/* apps/react/src/apps/memo/styles/note.css */
.memo-format-panel .memo-revision-list button {
	gap: 1px;
	padding: var(--space-6) var(--space-10);
	border-radius: var(--radius-md);
}
```

## 확인

PR 하나에 70개 파일, 1,656줄을 더하고 1,576줄을 지웠다. 줄 수가 이만큼 바뀌면 눈으로 확인할 수 없다. 바꾸기 전과 뒤의 빌드를 띄워, 데스크톱과 iPhone 크기, 라이트와 다크에서 여러 앱 화면의 모든 요소에 계산된 스타일을 비교했다. 차이는 없었다. `var()`는 계산된 값에서 원래 숫자로 풀리므로 브라우저가 보는 값은 같다.

## 그 뒤

지금 CSS에서 `--space-*`는 1,908곳에 쓰인다. 바꾼 1,543곳보다 365곳 많다. 그 뒤에 만든 화면도 숫자 대신 이름을 쓰고 있다는 뜻이다. 가장 많이 쓰는 것은 여전히 `--space-8`(333곳)이다. 그림자 다섯은 19곳에서 21곳이 되었다.

## 남은 것과 배운 것

- **18px·28px은 화면을 보며 정한다.** 값 하나만 적힌 선언만 세어도 둘을 합쳐 110곳이 1~2px씩 움직인다. 값을 고치는 일이라 이름 붙이기와 따로 한다.
- **토큰을 쓰지 않은 새 값을 막는 장치는 없다.** Stylelint 규칙으로 막을 수 있지만, 일부러 남긴 값(0이 섞인 줄임 표기, 앱 고유의 값)이 많아 예외 목록부터 정해야 한다.
- **세 곳 이상만.** 그림자는 305곳 중 다섯 값 19곳만 이름이 됐다. 한두 곳에만 쓰는 값에 이름을 붙이면 이름 목록만 길어진다.
- **이름에 값을 넣는 것도 방법이다.** `--space-8`은 8px이라는 것이 이름에 드러난다. 체계를 바꿀 날이 오면 이름을 바꿔야 하지만, 그날까지는 숫자를 외울 필요가 없다.
