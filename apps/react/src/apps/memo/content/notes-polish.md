편집기가 돌아가기 시작하자, 쓰다 보면 걸리는 곳이 하나씩 보였다. macOS 메모를 옆에 띄워 두고 하나씩 맞췄다.

## 배경

9월 말에 메모 앱에서 블로그 글을 직접 쓰기 시작했다. 글을 몇 편 쓰자 걸리는 곳이 한꺼번에 드러났다.

| 걸린 곳   | 재현                                                                                                   |
| --------- | ------------------------------------------------------------------------------------------------------ |
| 표        | 표를 넣고 열을 더하거나 옮기려면 Markdown 원문을 고쳐야 했다. 글 맨 앞의 표 앞에는 글을 쓸 수 없었다   |
| 찾기      | 긴 글에서 낱말 하나를 바꾸려면 눈으로 찾아야 했다. 브라우저의 ⌘F는 편집기 안의 고치기를 해 주지 않는다 |
| 검색 칸   | 관리자로 로그인하면 도구가 늘어 검색 칸이 도구 막대 밖으로 22px 넘쳐 잘렸다                            |
| 이미지    | 넣은 뒤에는 캡션을 고치기 어려웠고, 내려받기가 다른 주소의 그림에서 듣지 않았다                        |
| Safari 탭 | 좁은 창에서 탭이 가로로 넘쳐 밀어야 보였다                                                             |

9월 30일과 10월 1일 이틀에 걸쳐 기능마다 커밋을 나눠 고쳤고, 일부는 [PR #55](https://github.com/hyeoniverse/MacFolio/pull/55)로 묶였다.

## 표 손잡이

커서가 표 안에 있으면 지금 열 위와 지금 행 왼쪽에 작은 둥근 손잡이가 생긴다.

- 손잡이를 누르면 그 **열·행 전체를 고르고**, 손잡이는 열 폭만큼 펼쳐진 막대(⌄)가 되어 고른 테두리 위에 붙는다. 메뉴는 '앞에 열 추가', '뒤에 열 추가', 'N개의 열 삭제'처럼 macOS 메모와 같은 말을 쓴다
- 고른 채로 **Backspace**를 누르면 칸이 빈다
- 고른 범위의 **대각선 꼭짓점**을 끌면 맞은편 꼭짓점을 기준으로 범위가 늘고 준다
- 고른 행·열의 손잡이를 **끌면 옮긴다.** 놓을 자리에 선이 보이고, 고른 범위가 손가락을 따라온다

![표 손잡이로 열을 고른 모습](./images/notes-table-handles.jpg '열 손잡이를 누르면 열 전체를 고르고, 손잡이가 열 폭만큼 펼쳐진 막대가 된다. 메뉴는 표를 가리지 않는 자리에 뜬다')

Markdown 표는 첫 행이 늘 머리글이다. 그래서 행을 맨 위로 옮기면 표를 다시 짜서, 새로 첫 행이 된 행을 머리글 칸으로, 밀려난 머리글을 보통 칸으로 바꾼다.

### 고른 칸이 보이지 않았다

10월 1일 저녁, 표에서 칸을 골라도 아무 표시가 없다는 것을 알아챘다. 같은 표를 macOS 메모에 만들어 칸을 골라 보니 고른 범위에 노란 테두리가 둘리고 대각선 꼭짓점에 둥근 점이 붙었다. 이 화면을 기준으로 고른 범위의 테두리와 꼭짓점을 다시 그렸다.

![macOS 메모에서 표의 첫 행을 고른 화면](./images/notes-polish-table-selection-request.jpg '참고한 macOS 메모 화면. 고른 범위에 노란 테두리, 대각선 꼭짓점에 둥근 점이 붙는다')

고치고 다시 써 보니 두 가지가 더 걸렸다. 표 양옆을 눌러도 커서가 가지 않았고, 커서가 있어도 보이지 않았다. 표 뒤에서 Backspace를 두 번 눌러야 표가 지워졌다. 아래 두 절이 그 두 가지를 고친 이야기다.

### 손잡이가 엉뚱한 자리에 붙었다

처음 만든 손잡이는 열 위가 아니라 머리글 칸을 덮고 있었다. 계산한 자리와 그려진 자리가 13px쯤 어긋났다. 처음에는 자리를 잰 뒤에 레이아웃이 바뀐 줄 알고 다음 프레임에 한 번 더 재게 했는데, 그대로였다.

원인은 **본문의 문단 간격 규칙**이었다. 읽기 화면과 모양을 맞추려고 `.memo-markdown > * + * { margin-top: 0.9em }`를 걸어 두었는데, 손잡이를 편집기 바로 아래에 그리다 보니 손잡이도 '본문의 두 번째 요소'가 되어 0.9em(약 13px)을 받았다. 손잡이와 테두리에 `margin: 0`을 주자 맞았다.

### 표 앞에 커서를 둘 수 없었다

본문 맨 앞에 넣은 표는 앞에 문단이 없어서 표 앞에 글을 쓸 방법이 없었다. 표 뒤에서 Backspace로 표를 지울 수도 없었다. 편집기의 기본 Backspace는 표 뒤의 빈 문단을 지우는데, 글 끝에 늘 빈 문단을 두는 플러그인이 그 문단을 바로 다시 만들었다. 지우고 다시 생기기를 되풀이할 뿐이었다.

- 표·이미지 앞뒤처럼 글자를 쓸 수 없는 자리에도 커서(틈 커서)를 둔다. 첫 행에서 ↑, 마지막 행에서 ↓로 간다
- 표 바로 뒤 문단의 맨 앞에서 Backspace를 누르면 먼저 **표를 고르고**, 한 번 더 누르면 지운다

## 글 안에서 찾기·대치

⌘F를 누르면 글 위에 찾기 막대가 열린다. ‹ ›나 Enter로 찾은 곳을 옮겨 다니고, 편집할 때는 '대치'를 켜서 하나씩 또는 모두 바꾼다. ⌄ 메뉴에는 영문 대/소문자 무시, 순환 검색, 다음을 포함·다음으로 시작·전체 단어, 최근 검색이 있다.

![글 안에서 찾기](./images/notes-find-bar.jpg '찾은 곳은 옅게, 지금 찾은 곳은 진하게 칠한다. ⌄ 메뉴에서 옵션과 최근 검색을 고른다')

![찾기 규칙 하나, 칠하기 두 벌](./images/notes-polish-find.svg '편집기와 읽기 화면이 같은 findInBlocks 결과를 각자 방식으로 칠한다')

찾기 규칙은 순수 함수 하나로 두고, 칠하는 곳만 두 벌이다. 이 함수는 지금 `packages/desktop-core/src/memo/find.ts`에 있다.

```ts
export function findMatches(text: string, query: string, options: FindOptions): [number, number][] {
	if (!query) return [];
	const haystack = options.ignoreCase ? text.toLowerCase() : text;
	const needle = options.ignoreCase ? query.toLowerCase() : query;
	const matches: [number, number][] = [];
	let from = 0;
	while (from <= haystack.length - needle.length) {
		const at = haystack.indexOf(needle, from);
		if (at === -1) break;
		const end = at + needle.length;
		const startsWord = !isWordChar(text[at - 1]);
		const endsWord = !isWordChar(text[end]);
		const ok = options.mode === 'contains' || (startsWord && (options.mode === 'startsWith' || endsWord));
		if (ok) {
			matches.push([at, end]);
			from = end;
		} else from = at + 1;
	}
	return matches;
}
```

단어 글자는 `[\p{L}\p{N}_]`라 한글도 단어 경계를 안다. 덩어리(문단, 표의 칸, 제목)를 넘는 자리는 찾지 않는다.

- **편집기**: ProseMirror 장식으로 칠하고, 대치는 트랜잭션으로 한다. 뒤에서부터 바꿔야 앞 자리가 밀리지 않는다
- **읽기 화면**: DOM을 바꾸지 않고 CSS Custom Highlight API(`::highlight()`)로 칠한다. 글을 문단·칸 단위로 모아 찾고, 찾은 자리를 DOM 범위로 되돌린다

읽기 화면을 칠하는 방법은 둘을 놓고 골랐다.

| 방법                            | 문제                                                                                             |
| ------------------------------- | ------------------------------------------------------------------------------------------------ |
| 찾은 자리를 `<mark>`로 감싼다   | React가 그린 DOM을 바깥에서 바꾸게 된다. 다음 렌더링에서 React가 모르는 노드가 생기거나 사라진다 |
| CSS Custom Highlight API (고름) | 지원하지 않는 브라우저에서는 칠해지지 않는다. 그때도 개수와 옮겨 다니기는 된다                   |

```ts
registry.set('memo-find', new Highlight(...ranges.filter((_, i) => i !== current)));
registry.set('memo-find-current', new Highlight(...(current >= 0 ? [ranges[current]] : [])));
```

⌘F는 처음에 메모 창 요소에 걸었는데, 본문 글자를 눌러도 초점이 창 안으로 들어가지 않아 동작하지 않았다. 메모가 맨 앞 창일 때 window에서 받게 바꿨다.

## 넓어지는 검색 칸

관리자 도구가 늘면서 검색 칸이 점점 작아졌다. 재 보니 이미 도구 막대 밖으로 22px 넘쳐 잘리고 있었다(검색 칸의 최소 폭 때문).

검색 칸은 자리가 모자라면 돋보기만 남을 때까지 줄어들고, 초점이 가면 다른 도구가 **•••** 로 접히면서 오른쪽 끝을 둔 채 왼쪽으로 넓어진다. 도구 묶음은 `grid-template-columns: 1fr → 0fr`로, 검색 칸은 `flex-basis`로 움직인다. ••• 를 누르는 순간 검색 칸의 초점이 빠져 도구가 다시 펼쳐지면 안 되므로, 그 버튼은 누를 때 초점을 가져가지 않게 했다.

![넓어진 검색 칸과 ••• 메뉴](./images/notes-search-expanded.jpg '검색 칸에 초점이 가면 도구가 ••• 로 접힌다. 접힌 도구는 ••• 메뉴에 모여 있다')

⌄ 메뉴에서는 체크리스트·표·이미지·코드·첨부 파일이 있는 메모만 거를 수 있다. 고른 조건은 검색 칸 안에 작은 표로 붙는다.

## 이미지: 캡션 고치기, 내려받기, 놓을 자리

- **캡션은 누르면 그 자리에서 고친다.** 처음 넣을 때만 캡션을 쓸 수 있고, 뒤에는 이미지를 골라 메뉴를 열어야 했다. 이제 편집기에서 캡션을 누르면 입력칸이 되고 Enter로 저장, Esc로 취소한다. 캡션이 없으면 이미지를 골랐을 때 '캡션 추가'가 보인다
- **내려받기 버튼.** 이미지에 올리면 오른쪽 위에 보인다. 올린 파일은 API 주소, 찾은 사진은 Unsplash·Pexels 주소라 `<a download>`가 듣지 않는다(다른 주소면 브라우저가 파일 이름을 무시하고 연다). 그림을 받아 와서 파일로 저장하고, 받지 못하면 새 탭에서 연다
- **끌어다 놓을 자리.** 편집기에 놓을 자리 표시가 있었지만 색이 없어서 보이지 않았다. 강조 색으로 칠하고, `position: fixed`라 컨테이너 쿼리를 쓰는 메모 창 안에서는 창 기준이 되므로 body로 옮겼다

## Safari 탭

좁은 창에서 탭이 가로로 넘쳐 밀어야 보였다. macOS Safari처럼 **지금 탭은 넉넉하게, 나머지는 짧게** 나눴다. 모든 탭이 같은 몫(`flex-grow: 1`)에서 시작하고 지금 탭만 몫을 크게 가진다. 탭을 바꾸면 `flex-grow`가 옮겨 가면서 폭이 부드럽게 바뀌고, 다른 탭 제목은 말줄임으로 앞부분만 보인다.

![좁은 창의 Safari 탭](./images/safari-tabs.jpg '지금 탭은 제목이 다 보이고, 다른 탭은 짧게 줄어든다. 좁아도 주소창은 그대로 있다')

처음에는 좁은 창에서만 이 모양을 쓰고 주소창을 숨겼는데, 두 모양이 따로 놀고 좁을 때 주소를 볼 수 없었다. 이제 어느 폭에서나 같은 탭 모양(둥근 막대 안의 알약)을 쓰고, 주소창도 늘 있다. 닫기 버튼은 탭 왼쪽에 제 자리를 갖고 제목 쪽은 오른쪽에 같은 폭을 비워, 제목과 겹치지 않고 가운데도 맞는다. 자리는 지금 탭과 올린 탭에서만 펴서, 좁을 때 다른 탭은 그만큼 제목을 더 보인다.

## 남은 것·배운 것

- 손잡이가 13px 어긋난 것처럼, "본문의 모든 형제에 간격" 같은 넓은 선택자는 나중에 끼워 넣는 요소까지 잡는다. 편집기 위에 그리는 장식은 본문 흐름 밖(포털이나 절대 위치)에 두는 편이 안전하다.
- `position: fixed`는 `container-type`을 가진 조상 안에서 창 기준이 된다. 끌어다 놓을 자리 표시를 body로 옮긴 것도 이 때문이었다. 컨테이너 쿼리를 쓰는 앱 안에 고정 위치 요소를 둘 때는 늘 확인해야 한다.
- ⌘F는 뒤에 [메뉴 막대의 메뉴](/memo/menubar-menus)에서 메뉴의 '찾기…' 단축키로 옮겼고, 메모 안에서 따로 듣던 코드는 지웠다.
