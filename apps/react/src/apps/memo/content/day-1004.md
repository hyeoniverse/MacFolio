커밋 83개. 열흘 중 가장 많다. 그런데 이날 main에 들어간 PR은 하나도 없다. 83개가 모두 [#88](https://github.com/hyeoniverse/MacFolio/pull/88) 하나에 쌓였고, 그 PR은 다음 날 새벽 3시 3분에 머지되었다. 첫 커밋부터 머지까지 27시간이다.

![10월 4일 작업 흐름](./images/day-1004-timeline.svg '자정부터 아침 9시까지 쉬지 않고, 오후 3시부터 다시 자정까지')

## 색만 다르던 페이지를 프로젝트마다

전에는 프로젝트 페이지가 색만 다르고 짜임은 같았다. 이날 프로젝트마다 읽는 방법을 따로 만들었다. 게임은 걸으면서, 터미널 과정은 명령을 치면서, 뉴스 서비스는 지면처럼 읽는다.

| 프로젝트    | 이날 생긴 것                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------- |
| 새싹 농장   | 게임 에셋으로 만든 페이지, 흙길 지도 위를 걷는 주인공, 아침에서 밤으로 바뀌는 하늘, 엔딩 크레딧 |
| DevCourse   | 터미널 화면만 두고, 명령을 쳐야 내용이 나온다 (`ls`·`cd`·`tree`·`cat`)                          |
| 큐알유      | 실제 앱 분위기, 스크롤에 맞춰 펼치는 묻고 답하기, 데이터베이스 구조                             |
| 뉴픽        | 신문 지면처럼 머리 사진 기사·사진 기사·단신                                                     |
| MacFolio    | 커지는 노트북, 화면 크기 시뮬레이터, 벤토 그리드                                                |
| HYEONIVERSE | 마스코트 몽이, 라이트·다크 밀대, 레이아웃 바꿔 보기                                             |

![지금의 새싹 농장 페이지](./images/day-1004-sproutfarm.jpg 'Safari의 새싹 농장 페이지 지금 모습. 개발 일지가 흙길 지도다')

움직이는 것은 여러 번 고쳤다. 새싹 농장의 소는 걸음과 발끝을 세 번, 개발 일지의 주인공은 일정한 걸음 → 걷는 방향의 앞·뒤·옆 모습 → 멀어지면 뛰어서 따라오기로 세 번 고쳤다. 모두 새벽 4시에서 7시 사이다.

HYEONIVERSE·뉴픽·WTD·큐알유 페이지의 숫자는 저장소를 근거로 바로잡았다. 9월 29일에 NewPick 팀 구성을 잘못 적었던 일과 같은 종류다.

## 데모는 진짜로, 대신 제한부터

HYEONIVERSE 페이지의 CMS 장은 설명 대신 직접 해 보는 데모로 바꿨다. 발표 갤러리, 음성, 파형 편집, 문서 변환, 번역, 요약. 데모가 진짜로 돌게 API도 붙였는데, 실제 AI 공급자를 부르는 일이라 대체 순서와 횟수 제한을 처음부터 같이 넣었다.

| 데모        | 공급자 (실패하면 다음) | 제한                             |
| ----------- | ---------------------- | -------------------------------- |
| 음성 만들기 | Fish → Google → Edge   | 80자, IP마다 하루 3번, 전체 50번 |
| 번역·요약   | 실제 공급자            | IP마다 하루 3번, 전체 50번       |
| AI 커버     | 실제 공급자            | IP마다 하루 3번, 전체 10번       |

마스코트 몽이는 화면에 보이는 데모 곁으로 따라가 해 보라고 권하고, 결과에 반응한다.

![지금의 HYEONIVERSE 페이지](./images/day-1004-hyeoniverse.jpg 'Safari의 HYEONIVERSE 페이지 지금 모습. 페이지 짜임은 다음 날 새벽까지 더 바뀌었다')

## 자정에 처음 연 Safari

밤 11시 31분과 48분에 커밋이 두 개 들어갔다. **Safari에서 멈춘 스크롤 장면**과 **Safari에서 사라지던 몽이**. 하루 종일 Chrome에서 만들고 자정 무렵에야 Safari에서 열어 봤다. 페이지에 `overflow: clip`을 걸면 Safari에서 sticky가 멈췄고, 높이 0인 몽이 층에 걸면 몽이가 사라졌다.

Safari 영역이 1만 9천 줄 늘고 6천 줄 줄었다. 나머지를 다 합쳐도 Safari 막대 하나만 못하다.

## 돌아보며

커밋은 83개인데 E2E는 6개 늘었다. 이 두 숫자가 이날을 요약한다. 만든 것은 많았지만 하나하나 끝맺지 않고 다음으로 넘어갔다.

프로젝트마다 읽는 방법을 다르게 한 건 잘한 결정이었다. 색만 바꾼 페이지보다 프로젝트를 훨씬 잘 보여 준다. 데모에 제한부터 건 것도 맞았다. 문제는 크기였다. 프로젝트 페이지마다 PR을 나눴으면 리뷰도, 되돌리기도, Safari에서 확인하는 일도 그때그때 했을 것이다. 같은 일을 사흘 뒤 트래픽 분석에서는 PR 네 개로 나눠 했다([10월 7일](/memo/day-1007)).

그리고 0시부터 9시까지 쉬지 않았다. 걸음 애니메이션을 여러 번 다시 고친 것도, Safari를 자정에야 연 것도 이 하루의 길이와 무관하지 않다.
