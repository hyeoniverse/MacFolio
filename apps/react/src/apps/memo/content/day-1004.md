이날은 프로젝트마다 페이지 구성을 다르게 만들었고, 실제로 동작하는 AI 데모에 사용 제한을 걸었고, Safari에서만 생긴 문제를 고쳤다. 이 작업을 모두 PR [#88](https://github.com/hyeoniverse/MacFolio/pull/88) 하나에 담았고, 이 PR은 다음 날 새벽에 머지했다.

이 PR과 연결된 이슈는 GitHub 고정 저장소 선택 [#34](https://github.com/hyeoniverse/MacFolio/issues/34)와 Vite 전환 성능 정리 [#3](https://github.com/hyeoniverse/MacFolio/issues/3)이고, 둘 다 다음 날 새벽 머지와 함께 닫았다. 같은 밤에 연 [#87](https://github.com/hyeoniverse/MacFolio/pull/87)(프로젝트 앱)과 [#89](https://github.com/hyeoniverse/MacFolio/pull/89)(GitHub 활동)도 그때 함께 머지했다.

## 프로젝트마다 다른 페이지

### 무엇을 바꿨나

그전에는 프로젝트 페이지가 색만 다르고 구성은 같았다. 프로젝트마다 내용을 전달하는 방식을 따로 만들었다. 게임은 캐릭터를 움직이며 보고, 터미널 과정은 명령어를 입력하며 보고, 뉴스 서비스는 신문 지면 형태로 본다.

| 프로젝트    | 페이지 구성                                                                                     |
| ----------- | ----------------------------------------------------------------------------------------------- |
| 새싹 농장   | 게임 에셋으로 만든 페이지, 흙길 지도 위를 걷는 주인공, 아침에서 밤으로 바뀌는 하늘, 엔딩 크레딧 |
| DevCourse   | 터미널 화면만 배치하고, 명령(`ls`·`cd`·`tree`·`cat`)을 입력해야 내용이 표시된다                 |
| 큐알유      | 실제 앱의 분위기, 스크롤에 맞춰 펼쳐지는 질의응답, 데이터베이스 구조                            |
| 뉴픽        | 신문 지면처럼 헤드라인 사진 기사·사진 기사·단신                                                 |
| MacFolio    | 확대되는 노트북, 화면 크기 시뮬레이터, 벤토 그리드                                              |
| HYEONIVERSE | 마스코트 몽이, 라이트·다크 전환 슬라이더, 레이아웃 전환                                         |

![현재의 새싹 농장 페이지](./images/day-1004-sproutfarm.jpg 'Safari의 새싹 농장 페이지 현재 화면. 개발 일지를 흙길 지도로 표현했다')

### 애니메이션 수정

움직이는 요소는 여러 번 고쳤다. 모두 아홉 시간 연속 작업의 중반 이후에 몰린 커밋이다.

| 대상                      | 수정 과정                                                                                                                                         |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 새싹 농장의 소            | 걸음과 발끝 위치를 세 번 수정. 이미지 두 장이 번갈아 바뀌는 것처럼 보였고, 걸을 때 옆모습이 어색했다                                              |
| 개발 일지의 주인공        | 일정한 걸음 → 진행 방향에 따른 앞·뒤·옆 모습 → 멀어지면 뛰어서 따라오기                                                                           |
| 첫 화면의 소와 닭         | 나무 위를 밟고 지나갔다. 요소의 앞뒤 순서(z-index)를 발끝(요소의 가장 아래) 높이로 정하도록 수정했고, 한 번 수정한 뒤에도 남아 있어 다시 확인했다 |
| 노을에서 밤으로 가는 하늘 | 경계가 너무 뚜렷해 인벤토리 위 여백을 늘리고, 맨 아래 풀밭에만 밝게 남아 있던 영역에 밤 조명을 적용했다                                           |

### 그 밖의 페이지 수정

- **큐알유:** "어떻게 만들었나요?"는 눌러야 내용이 보이는 방식이었다. 스크롤에 맞춰 차례로 펼쳐지고, 위로 스크롤하면 다시 접히게 했다. 처음에는 펼쳐지는 순간이 잘 보이지 않았는데, 펼치는 시점(trigger)이 너무 일렀기 때문이다
- **수치 검증:** HYEONIVERSE·뉴픽·WTD·큐알유 페이지의 수치를 각 저장소를 근거로 바로잡았다. 9월 29일에 NewPick 팀 구성을 잘못 기재한 것과 같은 유형의 오류다

## 실제로 동작하는 AI 데모와 사용 제한

HYEONIVERSE 페이지의 CMS 장은 설명 대신 직접 사용해 보는 데모(발표 갤러리, 음성 생성, 파형 편집, 문서 변환, 번역, 요약)로 바꿨다. 데모가 실제로 동작하도록 API도 만들었다. 실제 AI 공급자를 호출해서 비용이 들고 남용될 수 있으므로, 공급자 대체 순서와 호출 횟수 제한을 처음부터 함께 구현했다.

| 데모      | 공급자 (실패하면 다음 공급자) | 제한                           |
| --------- | ----------------------------- | ------------------------------ |
| 음성 생성 | Fish → Google → Edge          | 80자, IP당 하루 3회, 전체 50회 |
| 번역·요약 | 실제 공급자                   | IP당 하루 3회, 전체 50회       |
| AI 커버   | 실제 공급자                   | IP당 하루 3회, 전체 10회       |

### 음성 데모의 시행착오

- 처음에는 브라우저 내장 음성 합성으로 만들었다. 목소리 종류를 보여 줄 수 없고 Fish보다 부자연스러워서 Fish를 우선 사용하게 바꿨다
- 직접 사용해 보니 소리가 나지 않았고, 클립 끌기도 동작하지 않았다. 클립 순서는 핸들 없이 길게 눌러 끌도록 변경했다
- 데모 API 키는 서버의 `api.env`에 `FISH_AUDIO_API_KEY`, `GOOGLE_TTS_API_KEY`를 추가하고 API를 다시 배포해 활성화했다. 배포한 뒤 "서버에 닿지 못했습니다"가 표시되어 설정을 다시 확인했다

마스코트 몽이는 화면에 보이는 데모 옆으로 이동해 사용을 권하고, 결과에 반응한다.

![현재의 HYEONIVERSE 페이지](./images/day-1004-hyeoniverse.jpg 'Safari의 HYEONIVERSE 페이지 현재 화면. 페이지 구성은 다음 날 새벽까지 더 변경되었다')

## Safari에서만 발생한 문제

**Safari에서 멈춘 스크롤 장면**과 **Safari에서 사라지던 몽이**는 하루 작업의 맨 끝에야 고쳤다. ==Chrome에서만 개발하고 Safari 확인을 작업 마지막으로 미뤘기 때문이다.==

| 증상                                                                      | 원인                                                                                   |
| ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| "스크롤하면 화면이 따라 움직입니다" 장면이 멈춤 (한 번 고친 뒤 다시 발생) | 페이지에 `overflow: clip`을 적용하면 Safari에서 `position: sticky`가 동작하지 않았다   |
| 몽이가 화면에서 사라지고, 마우스를 올리면 깜빡임                          | 높이가 0인 몽이 레이어에 `overflow: clip`을 적용하면 Safari에서 몽이가 표시되지 않았다 |

## 돌아보며

**기능 수에 비해 시험이 적었다.** ==프로젝트 페이지 여섯 개와 AI 데모 여섯 개를 만들었는데 E2E는 6개만 늘었다.== 기능 하나를 마무리하면 시험을 추가하기 전에 다음 기능으로 넘어갔다.

**잘한 결정도 두 가지 있었다.** 프로젝트마다 내용을 전달하는 방식을 다르게 해서, 색만 바꾼 페이지보다 프로젝트의 성격이 훨씬 잘 드러났다. 데모에 사용 제한부터 적용한 것도 맞았다. ==실제 공급자를 호출하는 API는 공개되는 순간부터 비용이 발생한다.==

**PR 하나가 너무 컸다.** 프로젝트 페이지마다 PR을 나눴다면 리뷰, 되돌리기, Safari 확인을 페이지 단위로 그때그때 했을 것이다. 사흘 뒤 트래픽 분석은 이 판단에 따라 PR 네 개로 나눠 진행했다([10월 7일](/memo/day-1007)).

**작업 시간이 너무 길었다.** 자정부터 아홉 시간을 쉬지 않고 작업했다. 걸음 애니메이션을 여러 번 다시 고친 것과 Safari 확인이 늦어진 것에는 이렇게 길게 작업한 영향도 있다.
