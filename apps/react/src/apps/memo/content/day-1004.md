## 프로젝트마다 다른 페이지

전에는 프로젝트 페이지가 색만 다르고 짜임은 같았다. 이날 프로젝트마다 읽는 방법을 따로 만들었다. 게임은 캐릭터를 움직이며 보고, 터미널 과정은 명령어를 입력하며 보고, 뉴스 서비스는 신문 지면 형태로 본다.

| 프로젝트    | 이날 생긴 것                                                                                    |
| ----------- | ----------------------------------------------------------------------------------------------- |
| 새싹 농장   | 게임 에셋으로 만든 페이지, 흙길 지도 위를 걷는 주인공, 아침에서 밤으로 바뀌는 하늘, 엔딩 크레딧 |
| DevCourse   | 터미널 화면만 두고, 명령을 쳐야 내용이 나온다 (`ls`·`cd`·`tree`·`cat`)                          |
| 큐알유      | 실제 앱 분위기, 스크롤에 맞춰 펼치는 묻고 답하기, 데이터베이스 구조                             |
| 뉴픽        | 신문 지면처럼 머리 사진 기사·사진 기사·단신                                                     |
| MacFolio    | 커지는 노트북, 화면 크기 시뮬레이터, 벤토 그리드                                                |
| HYEONIVERSE | 마스코트 몽이, 라이트·다크 밀대, 레이아웃 바꿔 보기                                             |

![지금의 새싹 농장 페이지](./images/day-1004-sproutfarm.jpg 'Safari의 새싹 농장 페이지 지금 모습. 개발 일지가 흙길 지도다')

움직이는 것은 여러 번 고쳤다. 새싹 농장의 소는 걸음과 발끝을 세 번, 개발 일지의 주인공은 일정한 걸음 → 걷는 방향의 앞·뒤·옆 모습 → 멀어지면 뛰어서 따라오기로 세 번 고쳤다. 모두 새벽 4시에서 7시 사이다.

고친 계기는 화면에서 본 어긋남이었다. 소는 이미지 두 장이 번갈아 바뀌는 것처럼 보였고, 걸어갈 때 옆모습이 어색했다. 첫 화면에서는 소와 닭이 나무 위를 밟고 지나갔다. 요소의 앞뒤를 발끝(요소의 가장 아래) 높이로 정해야 하는데, 한 번 고쳤다는데도 그대로라 다시 확인했다. 노을에서 밤으로 넘어가는 하늘은 경계가 너무 또렷해서 인벤토리 위 여백을 늘리고, 맨 아래 풀밭에만 밝게 남아 있던 곳에 밤 조명을 입혔다. 개발 일지에서는 누워 있는 나무와 물 위에 놓인 바위를 찾아 고치고 식물을 더 깔았다. 첫 화면 문구는 여러 후보를 받아 고르다가 번역투가 계속 남아서, 끝내 "농장에 작은 소동이 생겼어요. 얼른 잡아 주세요!"를 직접 정했고, 엔딩 문구는 마무리 인사로 바꿨다.

큐알유의 "어떻게 만들었나요?"는 눌러야 내용이 보이는 게 별로여서 스크롤에 맞춰 차례로 펼쳐지고, 위로 올리면 다시 접히게 했다. 처음에는 펼쳐지는 순간이 잘 안 보였는데, 펼치는 시점(trigger)이 너무 일러서였다. 뉴픽에서는 뜻 모를 "스크랩 0"과 속보 띠를 가리는 글자를 지웠고, "펼쳐 읽기"는 다른 UI로 바꿨다. MacFolio 로고는 사과 모양으로 바꾸다 메탈릭 띠와 금속 글씨가 촌스러워서 걷어 냈다.

HYEONIVERSE·뉴픽·WTD·큐알유 페이지의 숫자는 저장소를 근거로 바로잡았다. 9월 29일에 NewPick 팀 구성을 잘못 적었던 일과 같은 종류다.

## 실제로 동작하는 데모와 사용 제한

HYEONIVERSE 페이지의 CMS 장은 설명 대신 직접 해 보는 데모로 바꿨다. 발표 갤러리, 음성, 파형 편집, 문서 변환, 번역, 요약. 데모가 실제로 동작하도록 API도 만들었는데, 실제 AI 공급자를 부르는 일이라 대체 순서와 횟수 제한을 처음부터 같이 넣었다.

| 데모        | 공급자 (실패하면 다음) | 제한                             |
| ----------- | ---------------------- | -------------------------------- |
| 음성 만들기 | Fish → Google → Edge   | 80자, IP마다 하루 3번, 전체 50번 |
| 번역·요약   | 실제 공급자            | IP마다 하루 3번, 전체 50번       |
| AI 커버     | 실제 공급자            | IP마다 하루 3번, 전체 10번       |

음성 데모는 처음에 브라우저 음성으로 만들었는데, 목소리 종류를 보여 주지도 못하고 Fish보다 부자연스러워서 Fish를 먼저 쓰게 바꿨다. 소리가 나지 않고 클립 끌기도 안 되는 것을 직접 눌러 보고 찾았고, 클립 순서는 손잡이 없이 길게 눌러 끌게 했다. 데모 API 키는 서버의 `api.env`에 `FISH_AUDIO_API_KEY`, `GOOGLE_TTS_API_KEY`를 넣고 API를 다시 배포해서 켰다. 배포 뒤 "서버에 닿지 못했습니다"가 떠서 다시 확인했다. 상태에 따라 레이아웃이 움직이지 않게 하는 것, 현재 메뉴가 늘 보이게 하는 것도 이때 요청했다.

마스코트 몽이는 화면에 보이는 데모 곁으로 따라가 해 보라고 권하고, 결과에 반응한다.

![지금의 HYEONIVERSE 페이지](./images/day-1004-hyeoniverse.jpg 'Safari의 HYEONIVERSE 페이지 지금 모습. 페이지 짜임은 다음 날 새벽까지 더 바뀌었다')

## 자정에야 확인한 Safari

밤 11시 31분과 48분에 커밋이 두 개 들어갔다. **Safari에서 멈춘 스크롤 장면**과 **Safari에서 사라지던 몽이**. 하루 종일 Chrome에서 만들고 자정 무렵에야 Safari에서 열어 봤다. "스크롤하면 화면이 따라 움직입니다" 장면이 저녁에 한 번 고쳤는데도 밤 11시에 다시 멈췄고, 몽이는 계속 사라졌으며, 마우스를 올리면 깜빡였다. 페이지에 `overflow: clip`을 걸면 Safari에서 sticky가 멈췄고, 높이 0인 몽이 층에 걸면 몽이가 사라졌다.

Safari 코드가 1만 9천 줄 늘고 6천 줄 줄었다. 다른 영역의 변경을 모두 합쳐도 Safari보다 적다.

## 돌아보며

커밋은 83개인데 E2E는 6개만 늘었다. 만든 기능은 많았지만, 하나를 마무리하고 시험을 붙이기 전에 다음 기능으로 넘어갔다.

프로젝트마다 읽는 방법을 다르게 한 건 잘한 결정이었다. 색만 바꾼 페이지보다 프로젝트를 훨씬 잘 보여 준다. 데모에 제한부터 건 것도 맞았다. 아쉬운 점은 PR 하나가 너무 컸다는 것이다. 프로젝트 페이지마다 PR을 나눴으면 리뷰도, 되돌리기도, Safari에서 확인하는 일도 그때그때 했을 것이다. 같은 일을 사흘 뒤 트래픽 분석에서는 PR 네 개로 나눠 했다([10월 7일](/memo/day-1007)).

그리고 0시부터 9시까지 쉬지 않고 일했다. 걸음 애니메이션을 여러 번 다시 고친 것과 Safari 확인이 늦어진 것은 너무 길게 일한 탓도 있다.

이 PR과 연결된 이슈는 GitHub 고정 저장소 고르기 [#34](https://github.com/hyeoniverse/MacFolio/issues/34)와 Vite 전환 성능 정리 [#3](https://github.com/hyeoniverse/MacFolio/issues/3)이고, 둘 다 다음 날 새벽 머지와 함께 닫혔다. 같은 밤에 연 [#87](https://github.com/hyeoniverse/MacFolio/pull/87)(프로젝트 앱)과 [#89](https://github.com/hyeoniverse/MacFolio/pull/89)(GitHub 활동)도 그때 함께 들어갔다.
