블로그 폴더는 글 파일 머리말의 `category`로 정해진다. 10월 9일 [폴더 재분류](/memo/memo-folders-reorg)에서 `개발기/MacFolio`를 백엔드·인프라·프론트엔드·회고로 나눴고, 10월 26일 코드 구조 글 22편을 모은 설계 폴더를 더했다. 글이 238편이 되자 이 구조로는 원하는 글을 찾기 어려워졌다.

| 폴더                                   | 글 수 | 문제                                                                                    |
| -------------------------------------- | ----- | --------------------------------------------------------------------------------------- |
| `개발기/MacFolio/프론트엔드`           | 104   | 앱 기능, CSS 토큰·공통 컴포넌트, 성능 측정이 한 폴더에 있다                             |
| `개발기/MacFolio/인프라`               | 42    | 배포·운영, 보안, 테스트·CI, 빌드 도구가 섞여 있다. '인프라'와 맞지 않는 글이 절반쯤이다 |
| `개발기/MacFolio/백엔드`               | 26    | 트래픽 분석 연재 1~6 중 1~4는 백엔드, 5·6은 프론트엔드에 있다                           |
| `기술 노트/Git`, `/React`, `/브라우저` | 각 1  | 글 하나짜리 폴더가 셋이다. 폴더 이름이 기술 하나를 가리켜 다음 글을 둘 곳이 애매하다    |

## 새 구조

![새 폴더 구조](./images/blog-categories-structure.svg '도식. 맨 위 네 폴더와 하위 폴더. 숫자는 저장소 글 수, 회색은 아직 글이 없는 폴더')

맨 위 네 폴더는 글의 목적으로 나눈다.

| 맨 위 폴더  | 담는 글                                   | 하위 기준                        |
| ----------- | ----------------------------------------- | -------------------------------- |
| 개발 기록   | 프로젝트를 만든 기록                      | 프로젝트 › 작업의 종류           |
| 기술 노트   | 프로젝트와 상관없이 다시 찾아볼 실무 지식 | 분야 › 세부 분야 (3단)           |
| 학습        | CS·언어처럼 교과서 지식을 정리한 글       | 관리자 화면에서 만든 폴더 그대로 |
| 코딩 테스트 | 문제 풀이                                 | 관리자 화면에서 만든 폴더 그대로 |

- `개발기`는 사이트에서 이미 `개발 기록`으로 보이고 있었다. 관리자 화면에서 바꾼 폴더 이름은 서버의 정리 내용(`moves`)에 저장되는데, 저장소 글의 `category`도 같은 이름으로 맞췄다.
- 폴더 이름에는 `/`를 쓸 수 없다. `/`는 경로 구분자라 `CI/CD`는 4단 경로가 되어 [3단 제한](/memo/desktop-core-shared-rules)에 걸린다. 그래서 `CI·CD`, `테스트·CI`처럼 가운뎃점을 쓴다.

<details>
<summary>설계 폴더의 기준 (같은 날 먼저 만든 폴더)</summary>

설계 폴더는 MacFolio의 [store 설계](/memo/macfolio-store-design) 글이 프론트엔드 폴더에 맞지 않는다는 지적에서 시작했다. 코드의 경계와 공유를 다루는 글을 둔다.

- 패키지·모듈 경계: 로직을 어느 패키지에 둘지(desktop-core), 파일을 어떻게 나눌지
- 화면과 서버가 함께 쓰는 타입·스키마·규칙(`@macfolio/contracts`, desktop-core의 메모 규칙)
- 의존 방향과 그것을 지키는 장치(순환 의존 검사, 브랜드 타입, 공통 클라이언트)

먼저 프론트엔드 6편(desktop-core 분리 3편, 리팩터링 1~3단계), 인프라 13편(contracts 8편, 브랜드 타입, 순환 의존, 공통 API 클라이언트, 프로필·앱 파일 분할), 백엔드 3편(공유 규칙·스키마)을 옮겼고, 이번 재구성에서 공통 모듈·파일 분할 4편을 더해 27편이 되었다.

같은 단어(리팩터링, 스키마, 구조)가 들어가도 주제가 한 영역의 작업이면 설계에 두지 않았다. 리팩터링 4·5단계(컴포넌트·스타일)는 디자인 시스템, 6단계는 서버, 7단계는 보안, [백엔드 구성도](/memo/backend-design)는 서버, CSS 층 글은 디자인 시스템, TypeScript 7 글은 테스트·CI에 있다. 리팩터링 연재는 각 글의 앞뒤 단계 링크로 이어진다.

## 서버 정리 내용과의 관계

관리자 화면에서 폴더를 옮기거나 만들면 서버의 정리 내용(`GET /memo/organization`)에 저장되고, 저장소 `category`보다 먼저 적용된다([글은 Markdown에 두고 정리만 서버에](/memo/memo-organization-api)). 배포 API에서 읽은 값과 이번 변경의 관계는 다음과 같다.

| 정리 내용                                                            | 영향                                                                                                                               |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| 폴더 이름 바꾸기 `개발기` → `개발 기록`                              | 저장소도 `개발 기록`이 되어 바꿀 경로가 없다. 사이트 표시는 같다                                                                   |
| 폴더 이름 바꾸기 `기술 노트/브라우저` → `기술 노트/프론트엔드`       | Safari 글이 `기술 노트/프론트엔드/브라우저`가 되어 해당 경로가 없다                                                                |
| 글 하나의 폴더 지정 `notes-polish` → `개발 기록/MacFolio/프론트엔드` | 이 지정이 남아 있으면 사라진 `프론트엔드` 폴더가 이 글 하나로 다시 보인다. 관리자 화면에서 이 글을 `기능`으로 옮기면 지정이 바뀐다 |
| 학습·코딩 테스트 폴더                                                | 저장소 글과 관계없이 그대로 보인다                                                                                                 |

기술 노트의 빈 세부 폴더는 저장소 글로는 만들 수 없다. 폴더는 글의 `category`에서 만들어지기 때문이다. 글이 생기면 그 글과 함께 나타나고, 미리 보이게 하려면 메모 앱의 폴더 편집에서 만든다.
