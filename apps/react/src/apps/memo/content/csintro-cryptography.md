## 들어가기 전에

암호는 정해진 사람만 내용을 읽을 수 있도록 데이터를 바꾸는 기술이다. 인터넷 뱅킹, 메신저, 웹 사이트 주소창의 자물쇠 표시(HTTPS), 스마트폰 저장소 암호화가 모두 이 글에서 다루는 알고리즘을 조합해 동작한다.

| 순서 | 내용                                                         |
| ---- | ------------------------------------------------------------ |
| 1    | 용어, 암호 체계의 구성, 케르크호프스 원칙                    |
| 2    | 고전 암호: 전치, 치환(시저 암호), 빈도 분석                  |
| 3    | 대칭키 암호: DES의 구조와 S-박스, 3DES, AES, SEED, IDEA, RC5 |
| 4    | 블록 암호 운용 방식: ECB, CBC, GCM                           |
| 5    | 공개키 암호: RSA 키 생성과 계산, 기밀성과 부인 방지          |
| 6    | 해시 함수: 성질, MD 계열, SHA 계열, 비밀번호 저장            |
| 7    | 전자서명, PKI, 하이브리드 암호                               |
| 8    | 직접 해 보기: C로 만든 시저 암호, MD5 해시값 비교            |

필요한 배경은 정보보호의 목표인 기밀성·무결성·가용성, 비트와 바이트, 그리고 나머지 연산이다. `a mod n{:math}`은 a를 n으로 나눈 나머지로, 예를 들어 `29 mod 26 = 3{:math}`이다. 시계에서 11시의 3시간 뒤가 14시가 아니라 2시가 되는 계산과 같다. 비트 연산 XOR(배타적 논리합, ⊕)은 두 비트가 다르면 1, 같으면 0을 내며, ==같은 값을 두 번 XOR하면 원래 값으로 돌아온다==(`(a ⊕ k) ⊕ k = a{:math}`). 이 성질 때문에 XOR는 거의 모든 대칭키 암호에 쓰인다.

## 용어와 기본 가정

### 암호학의 용어

| 용어                     | 뜻                                                          |
| ------------------------ | ----------------------------------------------------------- |
| 암호학(cryptology)       | 비밀 코드를 만들거나 해독하는 학문 전체                     |
| 암호 설계(cryptography)  | 비밀 코드를 만드는 분야. 넓게는 암호학 전체를 가리키기도 함 |
| 암호 분석(cryptanalysis) | 키 없이 암호문을 해독하거나 알고리즘의 약점을 찾는 분야     |
| crypto                   | 위의 것을 모두 아우르는 줄임말                              |
| 평문(plaintext)          | 누구나 읽을 수 있는 원래 데이터. 암호화의 대상              |
| 암호문(ciphertext)       | 당사자만 알 수 있게 바꾼 데이터                             |
| 암호화(encryption)       | 평문을 암호문으로 바꾸는 작업                               |
| 복호화(decryption)       | 암호문을 평문으로 되돌리는 작업                             |
| 암호 알고리즘            | 암호화·복호화에 쓰는 절차(수단)                             |
| 키(key)                  | 알고리즘에 넣는 비밀 값. 양쪽이 약속한 규칙                 |

암호화와 복호화를 수행하려면 양쪽이 알고 있어야 하는 것이 두 가지다. 하나는 어떤 방식으로 바꾸는지(알고리즘), 다른 하나는 그 방식에 넣을 비밀 값(키)이다. 예를 들어 =="알파벳을 몇 칸 민다"가 알고리즘이고 "3칸"이 키다==.

### 케르크호프스 원칙

현대 암호는 1883년 오귀스트 케르크호프스(Auguste Kerckhoffs)가 제시한 원칙을 따른다. 암호 체계(알고리즘)는 공격자에게 완전히 알려져 있다고 가정하고, ==키만이 유일한 비밀이어도 안전해야 한다==는 원칙이다. 이렇게 가정하는 이유는 다음과 같다.

- 경험적으로 비밀 알고리즘은 공개되었을 때 알고리즘 자체가 강력하지 않은 경우가 많았다. 공개 검증을 거치지 않은 설계에는 결함이 남는다.
- 비밀 알고리즘은 역공학, 내부자 유출, 장비 탈취로 결국 공개된다. 1990년대 DVD 복제 방지용 비공개 암호 CSS와 휴대전화 암호 A5/1이 모두 역공학으로 공개된 뒤 곧바로 깨졌다.
- ==알고리즘이 노출되면 바꾸기 어렵지만, 키는 노출되어도 새로 만들면 된다==.

그래서 AES와 SHA-3는 공개 공모와 수년간의 공개 분석을 거쳐 표준이 되었다.

## 고전 암호

컴퓨터 이전의 암호는 글자를 다루었다. 방식은 크게 두 가지다.

![전치 암호는 apple의 글자 위치를 바꿔 palpe를 만들고, 치환 암호는 각 글자를 세 칸 밀어 dssoh를 만든다](./images/csintro-cryptography-transposition-substitution.svg '전치 암호와 치환 암호의 차이')

### 전치 암호

전치(transposition) 암호는 글자는 그대로 두고 위치만 미리 정한 규칙으로 바꾼다. 규칙이 "앞에서부터 두 글자씩 묶어 순서를 바꾼다"라면 다음과 같다.

| 평문     | 두 글자씩 묶기 | 암호문   |
| -------- | -------------- | -------- |
| `apple`  | `ap` `pl` `e`  | `palpe`  |
| `orange` | `or` `an` `ge` | `roneag` |

규칙이 "글자 순서를 뒤집기"라면 `orange`는 `egnaro`가 된다. 고대 그리스의 스키테일(scytale)은 막대에 가죽 띠를 감고 글을 쓴 뒤 풀어서 보내는 전치 암호였다. 같은 굵기의 막대가 키였다. 전치 암호는 글자 자체가 바뀌지 않으므로 ==글자 빈도가 평문과 같다==. 영어라면 e·t·a가 여전히 많이 나오므로, 암호문이 영어 철자 빈도를 그대로 가지고 있다는 사실만으로 전치 암호임을 추정할 수 있다.

![palpe와 aroegn의 원래 단어를 맞혀 보라는 문제](./images/csintro-cryptography-slide-challenge.jpg '전치 암호 해독 문제. palpe는 apple, aroegn은 orange의 글자 위치를 바꾼 것이다')

`aroegn`은 `orange`를 세 글자씩 `ora` `nge`로 나눈 뒤 각 묶음의 순서를 뒤집어 `aro` `egn`을 만든 결과다. 같은 전치 암호라도 규칙(키)에 따라 결과가 달라진다.

### 치환 암호와 시저 암호

치환(substitution) 암호는 각 글자를 다른 글자로 바꾼다. 시저 암호(Caesar cipher)는 알파벳을 정해진 칸 수만큼 밀어 바꾸는 가장 단순한 치환 암호로, 율리우스 카이사르가 3칸 이동을 썼다고 수에토니우스가 기록했다.

![평문 A~Z가 세 칸씩 밀려 D~C에 대응하고, X·Y·Z는 처음으로 돌아가 A·B·C가 된다](./images/csintro-cryptography-caesar.svg '키가 3인 시저 암호의 대응표')

글자를 A=0, B=1, …, Z=25로 번호 매기고 이동 칸 수를 키 k라 하면 다음과 같다.

```math
E(x) = (x + k) \bmod 26, \qquad D(y) = (y - k) \bmod 26
```

k = 3일 때 계산 예는 다음과 같다.

| 평문 글자 | 번호 x | `x + 3{:math}` | `mod 26{:math}` | 암호문 글자 |
| --------- | ------ | -------------- | --------------- | ----------- |
| H         | 7      | 10             | 10              | K           |
| E         | 4      | 7              | 7               | H           |
| L         | 11     | 14             | 14              | O           |
| X         | 23     | 26             | 0               | A           |
| Z         | 25     | 28             | 2               | C           |

같은 방식으로 `fourscoreandsevenyearsago`는 `IRXUVFRUHDQGVHYHQBHDUVDJR`가 된다(암호문은 관례상 대문자로 쓴다).

![소문자 알파벳 a~z 각각에서 화살표가 세 칸 뒤의 대문자 D~C로 이어진다](./images/csintro-cryptography-slide-caesar.jpg '시저 암호의 글자 대응. 위가 평문, 아래가 암호문 알파벳이다. 출처: 양대일, 『정보 보안 개론』, 한빛아카데미')

시저 암호는 ==키가 될 수 있는 값이 25개뿐이어서==, 모든 키를 대입해 보는 전수 조사(brute force)로 곧바로 해독된다. 이동 칸 수가 아니라 26글자를 임의로 섞은 대응표를 키로 쓰는 단일 치환 암호는 키의 경우의 수가 `26! \approx 4 \times 10^{26}{:math}`이라 전수 조사는 불가능하다. 그래도 같은 평문 글자가 항상 같은 암호문 글자로 바뀌므로, 암호문에서 가장 많이 나온 글자를 e, 다음을 t로 맞춰 보는 **빈도 분석**으로 해독된다. 9세기 아랍의 학자 알킨디가 이 방법을 기록했다. ==키 공간이 커도 평문의 통계적 성질이 암호문에 남으면 안전하지 않다==는 점이 현대 암호 설계의 출발점이 되었다.

현대 블록 암호는 치환(혼돈, confusion)과 전치(확산, diffusion)를 비트 단위로 여러 번 반복해 이 통계적 흔적을 지운다. 클로드 섀넌(Claude Shannon)이 1949년 논문에서 정리한 개념이다.

## 대칭키 암호

대칭키 암호는 암호화와 복호화에 같은 키를 쓴다. 연산이 빨라 대용량 데이터 암호화에 쓰지만, 통신 전에 두 사람이 같은 키를 안전하게 나눠 가져야 하는 **키 분배 문제**가 있다. n명이 서로 다른 키로 통신하려면 키가 `n(n-1)/2{:math}`개 필요해, 100명이면 4,950개, 1,000명이면 499,500개다.

![대칭키 암호는 같은 키 K로 암호화·복호화하고, 공개키 암호는 수신자의 공개키로 암호화하고 개인키로 복호화한다](./images/csintro-cryptography-keys.svg '대칭키와 공개키 암호의 키 사용 방식')

평문을 일정 크기 블록으로 나눠 처리하는 블록 암호가 대표적이다.

| 알고리즘 | 블록 크기          | 키 길이           | 라운드       | 개발·현재 상태                                              |
| -------- | ------------------ | ----------------- | ------------ | ----------------------------------------------------------- |
| DES      | 64비트             | 56비트            | 16           | 1977년 미국 표준(FIPS 46). 2005년 표준 철회                 |
| 3DES     | 64비트             | 112 또는 168비트  | 48(DES 3회)  | NIST가 2023년 이후 암호화 용도 사용 금지                    |
| AES      | 128비트            | 128, 192, 256비트 | 10, 12, 14   | 2001년 미국 표준(FIPS 197). 현재 가장 널리 쓰는 대칭키 암호 |
| SEED     | 128비트            | 128비트           | 16           | 1999년 KISA 개발, 국내 표준(TTA), ISO/IEC 18033-3           |
| IDEA     | 64비트             | 128비트           | 8.5          | 1991년 라이·매시 설계, PGP 초기 판에서 사용                 |
| RC5      | 32·64·128비트 가변 | 0~2,040비트 가변  | 가변 (0~255) | 1994년 리베스트 설계, 매개변수형 블록 암호                  |

### DES의 역사

1973년 미국 상무부 산하 표준국(NBS, 현재의 NIST)이 정부의 비밀이 아닌 정보를 보호할 암호 알고리즘을 공모했고, IBM이 제출한 루시퍼(Lucifer)를 고친 알고리즘이 1977년 1월 연방 표준 DES(Data Encryption Standard)로 확정되었다. DES는 이후 20여 년간 은행 ATM, 금융 결제망, 유닉스 비밀번호 저장(`crypt`)에 널리 쓰였다. 1990년대 후반 키 길이가 너무 짧다는 사실이 실증되면서 1998년 11월 이후 미국 정부의 신규 사용 권고에서 빠졌고 2005년에 표준이 철회되었다. 지금도 오래된 금융 장비와 응용 프로그램에서 3DES 형태로 남아 있는 경우가 있다.

### DES의 구조

| 항목          | 값                                                                          |
| ------------- | --------------------------------------------------------------------------- |
| 블록 길이     | 64비트                                                                      |
| 키 길이       | 56비트 (입력은 64비트이지만 바이트마다 1비트는 패리티), `2^{56}{:math}`가지 |
| 라운드        | 16회                                                                        |
| 안전성의 핵심 | S-박스 8개. 각각 6비트를 4비트로 바꾸는 표                                  |

DES는 페이스텔(Feistel) 구조를 쓴다. 64비트 블록을 왼쪽(L) 32비트와 오른쪽(R) 32비트로 나눈 뒤 매 라운드 다음을 수행한다.

1. 오른쪽 절반 R을 F 함수에 넣는다. F 함수는 R을 48비트로 확장하고, 라운드 키 K와 XOR한 뒤, S-박스 8개로 다시 32비트로 줄이고, 비트 순서를 섞는다(순열 P).
2. F의 출력을 왼쪽 절반 L과 XOR한다.
3. 좌우를 바꾼다. 새 L은 이전 R, 새 R은 `L ⊕ F(R, K)`다.

```math
L_i = R_{i-1}, \qquad R_i = L_{i-1} \oplus F(R_{i-1}, K_i)
```

![DES 한 라운드: 오른쪽 32비트가 확장, 라운드 키 XOR, S-박스, 순열을 거쳐 왼쪽과 XOR되고 좌우가 바뀐다](./images/csintro-cryptography-feistel.svg 'DES의 페이스텔 라운드')

페이스텔 구조의 장점은 ==복호화가 암호화와 같은 회로로 된다==는 점이다. 라운드 키를 역순(K16 → K1)으로 넣고 같은 과정을 거치면 XOR가 두 번 적용되어 원래 값이 나온다. F 함수 자체는 되돌릴 수 없어도 된다.

![L3·R3에서 출발해 좌우를 바꾸고 S-박스 출력과 XOR해 L1·R1로 돌아가는 DES 복호화 과정](./images/csintro-cryptography-des-decrypt.jpg 'DES 복호화 과정. 암호화와 같은 구조를 거꾸로 따라간다. 출처: 양대일, 『정보 보안 개론』, 한빛아카데미')

### 확장과 S-박스 계산

확장 E는 32비트를 4비트씩 8묶음으로 나눈 뒤, 각 묶음 앞뒤에 이웃 묶음의 끝 비트를 하나씩 붙여 6비트로 만든다. 예를 들어 이웃한 세 묶음이 `1010 1100 0111`이면 가운데 묶음 `1100`은 앞 묶음의 마지막 비트 `0`과 뒤 묶음의 첫 비트 `0`을 붙여 `0 1100 0`이 된다. 이렇게 이웃 비트가 두 S-박스에 동시에 들어가 한 비트의 변화가 여러 S-박스로 퍼진다.

S-박스는 6비트 입력을 4비트로 바꾸는 4행 16열의 표다. 입력의 첫 비트와 마지막 비트를 붙인 2비트가 행 번호, 가운데 4비트가 열 번호다. 입력이 `111000`일 때 S-박스 S1을 따라가 보자.

| 단계    | 계산                                   | 값         |
| ------- | -------------------------------------- | ---------- |
| 입력    | 6비트                                  | `1 1100 0` |
| 행      | 첫 비트와 마지막 비트 `1`, `0` → `10₂` | 2          |
| 열      | 가운데 4비트 `1100₂`                   | 12         |
| 표 조회 | S1의 2행 12열                          | 3          |
| 출력    | 4비트                                  | `0011`     |

S1의 2행은 `4 1 14 8 13 6 2 11 15 12 9 7 3 10 5 0`이고, 0부터 세어 12번째 값이 3이다. ==S-박스는 DES에서 유일한 비선형 연산이다==. 나머지 연산(XOR, 비트 이동)은 모두 선형이라 S-박스가 없으면 연립 방정식으로 키를 구할 수 있다. 1990년 비함(Biham)과 샤미르(Shamir)가 공개한 차분 분석이 S-박스 설계에 이미 대비되어 있었다는 사실이 나중에 밝혀졌다. IBM과 NSA가 1970년대에 이 공격을 알고 S-박스를 설계했던 것이다.

### DES가 폐기된 이유

==DES가 폐기된 이유는 구조가 아니라 키 길이다==. 56비트 키의 경우의 수는 `2^{56} \approx 7.2 \times 10^{16}{:math}`개다. 1998년 전자 프런티어 재단(EFF)이 약 25만 달러로 만든 전용 장비 Deep Crack이 56시간 만에 키를 찾았고, 1999년에는 인터넷의 PC 수만 대와 함께 22시간 15분으로 줄었다.

### 3DES

3DES(트리플 DES)는 DES가 깨진 뒤 AES가 나오기 전까지 기존 DES 장비를 그대로 활용하기 위해 쓴 방식이다. DES를 암호화(K1) → 복호화(K2) → 암호화(K3) 순서로 세 번 적용한다. 가운데를 복호화로 두는 EDE 구성은 세 키를 모두 같게 하면 단일 DES와 결과가 같아져 옛 장비와 호환되게 하려는 설계다. 복호화는 반대로 복호화(K3) → 암호화(K2) → 복호화(K1)다.

![평문이 K1 DES 암호화, K2 DES 복호화, K3 DES 암호화를 차례로 거쳐 암호문이 된다](./images/csintro-cryptography-3des.svg '3DES의 EDE 구성')

| 방식     | 키               | 키 길이 | 실제 보안 강도 |
| -------- | ---------------- | ------- | -------------- |
| 2키 3DES | K1, K2 (K3 = K1) | 112비트 | 약 80비트 이하 |
| 3키 3DES | K1, K2, K3       | 168비트 | 약 112비트     |

==키 길이가 두 배, 세 배가 되어도 보안 강도는 그만큼 늘지 않는다==. 중간 일치 공격(meet-in-the-middle)은 평문에서 한 단계 암호화한 결과와 암호문에서 한 단계 복호화한 결과를 표로 만들어 가운데에서 일치하는 값을 찾으므로, 키를 두 번 쓴 2DES는 `2^{57}{:math}`번 정도의 계산으로 깨진다. 3키 3DES도 같은 이유로 168비트가 아니라 112비트 강도로 평가한다[^sp800-57]. 게다가 DES보다 세 배 느리고 블록이 64비트로 작아, 같은 키로 수십 GB를 암호화하면 블록 충돌을 이용한 공격(Sweet32, 2016)에 노출된다. 그래서 AES로 대체되었다.

### AES

AES(Advanced Encryption Standard)는 DES의 후속 표준을 정하기 위해 NIST가 1997년 공개 공모를 열어 선정한 알고리즘이다. 공모 조건은 128비트 블록, 128·192·256비트의 다양한 키 길이, 향후 30년 이상 쓸 수 있는 보안성, 하드웨어와 소프트웨어 모두에서의 효율이었다. 15개 후보 가운데 벨기에의 다먼(Daemen)과 레이먼(Rijmen)이 설계한 Rijndael이 2000년에 선정되어 2001년 FIPS 197로 발표되었다.

AES는 페이스텔 구조가 아니라 SPN(치환·순열 네트워크) 구조로, 128비트 블록 전체를 4×4 바이트 행렬(상태, state)로 보고 매 라운드 네 단계를 거친다.

![4×4 바이트 상태에 SubBytes, ShiftRows, MixColumns, AddRoundKey를 차례로 적용한다](./images/csintro-cryptography-aes-round.svg 'AES 한 라운드의 네 단계')

| 단계        | 동작                                                   | 역할           |
| ----------- | ------------------------------------------------------ | -------------- |
| SubBytes    | 각 바이트를 S-박스(256개 항목 표)로 바꿈               | 비선형성(혼돈) |
| ShiftRows   | 0행은 그대로, 1·2·3행은 각각 1·2·3바이트 왼쪽으로 회전 | 열 사이 확산   |
| MixColumns  | 각 열(4바이트)을 고정 행렬과 곱함(GF(2⁸) 연산)         | 열 안의 확산   |
| AddRoundKey | 라운드 키와 XOR                                        | 키 결합        |

라운드 수는 키 길이 128·192·256비트에 따라 10·12·14이며, 마지막 라운드는 MixColumns를 생략한다. 대부분의 CPU가 AES 전용 명령어(x86의 AES-NI, ARMv8 Crypto Extensions)를 제공해 코어 하나로 초당 수 GB를 처리한다. HTTPS, 디스크 암호화(FileVault, BitLocker), 와이파이(WPA2·WPA3), 메신저가 모두 AES를 쓴다. 공개 후 20년 넘게 분석되었지만 전수 조사보다 의미 있게 빠른 공격은 나오지 않았다.

### SEED

SEED는 전자상거래, 금융, 무선 통신에서 전송되는 중요 정보를 보호하기 위해 1999년 한국인터넷진흥원(당시 한국정보보호센터)과 국내 암호 전문가들이 개발한 128비트 블록 암호다. 128비트 키, 16라운드 페이스텔 구조다. 1990년대 후반 미국이 128비트 암호의 수출을 제한하던 시기에, 국내 인터넷 뱅킹과 전자상거래가 강한 암호를 쓸 수 있도록 만들었다. 2000년대 국내 금융권 보안 프로그램과 공인인증서 체계에 널리 쓰였고, TTA 표준과 ISO/IEC 18033-3 국제 표준에 등록되었다. 이후 국내에서는 경량 환경을 위한 ARIA(2004, 국가 표준 KS X 1213)와 LEA(2013)가 추가로 개발되었다.

### IDEA

IDEA(International Data Encryption Algorithm)는 1991년 스위스의 라이(Lai)와 매시(Massey)가 발표한 64비트 블록, 128비트 키의 암호다. 8라운드와 마지막 출력 변환(반 라운드)으로 구성되어 흔히 8.5라운드라 한다. XOR, `2^{16}{:math}`을 법으로 한 덧셈, `2^{16} + 1{:math}`을 법으로 한 곱셈이라는 서로 다른 세 연산을 섞는 것이 특징이며, 모든 연산이 16비트 단위라 당시의 16비트 프로세서에서도 구현이 쉬웠다. 이메일 암호화 프로그램 PGP의 초기 판(2.x)이 IDEA를 기본 대칭키 암호로 써서 널리 알려졌다. 특허 문제로 이후 쓰임이 줄었다.

### RC5

RC5(Ron's Code 5)는 1994년 RSA의 R인 로널드 리베스트(Ronald Rivest)가 설계한 블록 암호다. 블록 크기(32·64·128비트), 키 길이(0~2,040비트), 라운드 수(0~255)를 모두 매개변수로 정하는 것이 특징이라 RC5-w/r/b(워드 크기 w비트, 라운드 r, 키 b바이트)처럼 표기한다. 덧셈, XOR, 데이터에 따라 회전량이 달라지는 비트 회전만으로 이루어져 구조가 단순하고 소프트웨어에서 빠르다. RC5-32/12/16(64비트 블록, 12라운드, 128비트 키)이 대표 설정이다.

## 블록 암호 운용 방식

블록 암호는 한 번에 블록 하나(AES는 16바이트)만 처리한다. 그보다 긴 메시지를 암호화하려면 블록을 어떻게 이어 붙일지 정해야 하는데, 이를 운용 방식(mode of operation)이라 한다. 같은 AES라도 운용 방식에 따라 안전성이 크게 달라진다.

| 방식 | 동작                                                          | 특징                                                              |
| ---- | ------------------------------------------------------------- | ----------------------------------------------------------------- |
| ECB  | 블록마다 독립적으로 암호화                                    | 같은 평문 블록은 같은 암호문 블록이 되어 패턴이 드러남. 사용 금지 |
| CBC  | 이전 암호문 블록과 XOR한 뒤 암호화. 첫 블록은 무작위 IV와 XOR | 패턴은 숨기지만 무결성 검증이 없어 패딩 오라클 공격에 취약        |
| CTR  | 카운터를 암호화한 값을 평문과 XOR                             | 병렬 처리 가능, 스트림 암호처럼 동작                              |
| GCM  | CTR 암호화에 인증 태그(GHASH)를 더함                          | 기밀성과 무결성을 함께 제공(AEAD). TLS 1.3의 기본                 |

==ECB로 비트맵 이미지를 암호화하면 같은 색 영역이 같은 암호문이 되어 그림의 윤곽이 그대로 보인다==. 실무에서는 AES-GCM이나 ChaCha20-Poly1305처럼 암호화와 변조 검증을 한 번에 하는 방식(AEAD)을 쓴다.

## 공개키 암호

공개키 암호(비대칭키 암호)는 수학적으로 연결된 키 한 쌍을 쓴다. **공개키**는 누구에게나 공개하고, **개인키**는 소유자만 보관한다. 한 키로 암호화한 것은 짝이 되는 다른 키로만 풀린다. 항상 한 쌍의 개인키와 공개키로 암호화와 복호화가 이루어진다. 1976년 디피(Diffie)와 헬먼(Hellman)이 개념과 키 합의 방법을 발표했고, 1977년 리베스트(Rivest), 샤미르(Shamir), 애들먼(Adleman)이 처음으로 실용적인 공개키 암호 알고리즘 RSA를 만들었다. 이름은 세 사람의 성 첫 글자다.

공개키 암호는 키 분배 문제를 해결한다. n명이 통신해도 각자 키 쌍 하나씩, 모두 n쌍이면 된다.

### 기밀성과 부인 방지

공개키 암호는 어느 키로 암호화하느냐에 따라 두 가지 기능을 제공한다. 철수와 영희의 예로 보자.

| 기능      | 철수가 쓰는 키         | 영희가 쓰는 키         | 보장하는 것                                   |
| --------- | ---------------------- | ---------------------- | --------------------------------------------- |
| 기밀성    | 영희의 공개키로 암호화 | 영희의 개인키로 복호화 | 영희만 읽을 수 있음                           |
| 부인 방지 | 철수의 개인키로 암호화 | 철수의 공개키로 복호화 | 철수가 만들었음. 철수는 나중에 부인할 수 없음 |

- **기밀성**: 영희의 공개키로 암호화한 메시지는 영희의 개인키를 가진 영희만 읽는다. 사전에 비밀 키를 나눌 필요가 없다.
- **부인 방지**(nonrepudiation): 쉽게 말해 '발뺌 방지'다. 철수가 자기 개인키로 암호화한 메시지는 철수의 공개키로 누구나 풀어 볼 수 있으므로 비밀은 아니다. 대신 철수의 공개키로 풀린다는 사실이 그 메시지를 철수의 개인키로 만들었다는 증거가 된다. 개인키는 철수만 가지므로 철수는 나중에 보낸 적이 없다고 부인할 수 없다. ==대칭키 암호는 두 사람이 같은 키를 가지므로, 메시지를 둘 중 누가 만들었는지 제3자에게 증명할 수 없어== 이 기능을 제공하지 못한다.

부인 방지 방식이 바로 뒤에서 다룰 전자서명의 원리다. 실제 RSA 구현에서는 '개인키로 암호화'라는 표현 대신 '개인키로 서명'이라 하고, 메시지 전체가 아니라 해시값에 서명하며, 패딩 방식(RSA-PSS)도 암호화와 다르다.

![왼쪽은 철수가 영희의 공개키로 암호화하고 영희가 개인키로 복호화하는 과정, 오른쪽은 철수가 자기 개인키로 암호화하고 영희가 철수의 공개키로 복호화하는 과정](./images/csintro-cryptography-slide-pk-functions.jpg '공개키로 암호화하면 기밀성, 개인키로 암호화하면 부인 방지를 얻는다. 출처: 양대일, 『정보 보안 개론』, 한빛아카데미')

### RSA의 원리

RSA의 안전성은 큰 두 소수의 곱은 쉽게 계산되지만, 그 곱을 다시 두 소수로 인수분해하기는 매우 어렵다는 사실에 기반한다. 계산을 따라갈 수 있도록 아주 작은 수로 예를 든다.

| 기호   | 뜻                                 | 예시 값  |
| ------ | ---------------------------------- | -------- |
| p, q   | 비밀로 고르는 두 소수              | 5, 11    |
| n      | 법(modulus), `p × q`, 공개         | 55       |
| φ(n)   | 오일러 함수 `(p − 1)(q − 1)`, 비밀 | 40       |
| e      | 공개 지수, φ(n)과 서로소           | 3        |
| d      | 개인 지수, `e × d mod φ(n) = 1`    | 27       |
| 공개키 | (e, n)                             | (3, 55)  |
| 개인키 | (d, n)                             | (27, 55) |

1. 키 생성: p = 5, q = 11에서 n = 55, φ(n) = 4 × 10 = 40이다. 40과 공약수가 없는 e = 3을 고른다. `3 × d{:math}`를 40으로 나눈 나머지가 1이 되는 d를 찾으면 `3 × 27 = 81 = 2 × 40 + 1{:math}`이므로 d = 27이다(확장 유클리드 알고리즘으로 계산한다).
2. 암호화: 평문 m = 7을 공개키로 암호화한다.

   ```math
   c = m^e \bmod n = 7^3 \bmod 55 = 343 \bmod 55 = 13
   ```

3. 복호화: 암호문 13을 개인키로 복호화한다.

   ```math
   m = c^d \bmod n = 13^{27} \bmod 55 = 7
   ```

| 단계   | 입력 | 사용한 키 | 출력 |
| ------ | ---- | --------- | ---- |
| 암호화 | 7    | (3, 55)   | 13   |
| 복호화 | 13   | (27, 55)  | 7    |

`13^{27}{:math}`은 30자리가 넘는 수이지만, 지수를 2진수로 나눠 제곱을 반복하며 매 단계 55로 나눈 나머지만 남기는 고속 거듭제곱으로 몇 번의 곱셈만에 구한다. 이 계산이 성립하는 근거는 오일러 정리다. `ed = 1 + kφ(n){:math}`이므로 `m^{ed} = m \cdot (m^{φ(n)})^k \equiv m \pmod n{:math}`이 된다.

n = 55는 바로 5 × 11로 분해되므로 이 예제는 안전하지 않다. ==공격자가 n을 인수분해하면 φ(n)을 계산해 d를 구할 수 있기 때문이다==. 실제로는 n을 2,048비트(10진수 약 617자리) 이상으로 쓰며, 현재 공개된 최대 인수분해 기록은 829비트(RSA-250, 2020년)다. 공개키 연산은 대칭키보다 수백~수천 배 느려서 데이터 자체를 RSA로 암호화하지는 않는다. 오늘날에는 같은 보안 강도를 더 짧은 키로 내는 타원 곡선 암호(ECDH, ECDSA, Ed25519)도 널리 쓰인다.

### 하이브리드 암호

실제 프로토콜은 두 방식의 장점을 합친다. ==공개키 방식으로 대칭키(세션 키)를 안전하게 합의한 뒤, 데이터는 빠른 AES로 암호화한다==. HTTPS(TLS 1.3)는 ECDHE 키 합의로 세션 키를 만들고 AES-GCM이나 ChaCha20-Poly1305로 데이터를 암호화한다.

![클라이언트와 서버가 공개키 방식으로 세션 키를 합의하고, 이후 데이터는 같은 세션 키의 AES-GCM으로 암호화한다](./images/csintro-cryptography-hybrid.svg '하이브리드 암호의 흐름')

## 해시 함수

### 해시의 개념

해시 함수는 임의 길이의 문자열을 더 짧은 고정 길이의 값(해시값, 다이제스트)으로 바꾸는 함수다. 원래 해시는 데이터베이스와 해시 테이블에서 검색을 효과적으로 구현하기 위해 만들어졌다. 보안에서는 완전히 똑같은 데이터만 해시값이 같고, 조금만 달라도 해시값이 전혀 달라진다는 점을 이용한다. ==암호화가 정보를 숨기는 기술이라면 해시는 정보의 위조·변조를 확인하는 기술==, 즉 **무결성**을 확인하는 도구다. 해시를 이용하면 전자서명, 전자봉투, 전자화폐 같은 전자상거래 기능을 구현할 수 있다.

![hello와 hellp의 MD5 해시값은 공통점이 없고, 출력 길이는 입력과 관계없이 고정이다](./images/csintro-cryptography-hash-avalanche.svg '한 글자 차이가 만드는 해시값 차이')

### 해시 함수의 성질

암호학적 해시 함수 h가 갖춰야 할 성질은 다음과 같다.

| 성질                              | 뜻                                                                     |
| --------------------------------- | ---------------------------------------------------------------------- |
| 압축(compression)                 | 입력 길이와 관계없이 출력 길이가 작고 고정됨                           |
| 효율성(efficiency)                | 어떤 입력 x든 `h(x)`를 쉽게 계산                                       |
| 일방향성(one-way, 역상 저항성)    | 해시값 y가 주어져도 `h(x) = y`인 x를 찾기 어려움                       |
| 약한 충돌 저항성(제2 역상 저항성) | x와 `h(x)`가 주어졌을 때 `h(y) = h(x)`이면서 `y ≠ x`인 y를 찾기 어려움 |
| 강한 충돌 저항성                  | `h(x) = h(y)`이면서 `x ≠ y`인 x, y 쌍을 아무거나 찾기 어려움           |

출력 길이가 유한하므로 충돌은 반드시 많이 존재한다. 요구 조건은 ==충돌을 "찾기가 계산상 어려워야" 한다는 것==이다. 강한 충돌 저항성은 생일 역설 때문에 출력 길이의 절반 정도만큼의 강도를 갖는다. 출력이 n비트이면 약 `2^{n/2}{:math}`개의 입력만 해시해 봐도 충돌 하나를 찾을 확률이 높아진다. 사람 23명만 모여도 생일이 같은 두 사람이 있을 확률이 50%를 넘는 것과 같은 원리다. 그래서 ==128비트인 MD5의 충돌 저항성은 많아야 64비트 수준이다==.

### MD 계열

MD(Message Digest) 알고리즘은 로널드 리베스트가 개발했다.

| 알고리즘 | 발표 | 출력    | 특징                                                             | 현재 상태                        |
| -------- | ---- | ------- | ---------------------------------------------------------------- | -------------------------------- |
| MD2      | 1989 | 128비트 | 8비트 컴퓨터에 맞춘 설계                                         | 폐기                             |
| MD4      | 1990 | 128비트 | 32비트 컴퓨터에 맞춘 빠른 설계                                   | 1995년 충돌 발견, 폐기           |
| MD5      | 1991 | 128비트 | MD4를 강화. MD4보다 느리지만 안전성을 높임. 512비트 블록, 64단계 | 2004년 충돌 발견, 보안 용도 금지 |

2004년 왕샤오윈(Wang Xiaoyun) 연구팀이 MD5 충돌을 실제로 찾았고, 2008년에는 MD5 충돌로 위조한 CA 인증서가 시연되었다. 2012년 악성코드 Flame은 MD5 충돌로 마이크로소프트의 코드 서명을 위조해 윈도우 업데이트로 위장했다. 지금 MD5는 파일이 전송 중 우연히 손상되었는지 확인하는 체크섬 정도로만 쓰고, 서명·인증서·비밀번호에는 쓰지 않는다.

### SHA 계열

SHA(Secure Hash Algorithm)는 미국 NSA가 설계하고 NIST가 표준으로 발표한 해시 함수 계열이다.

| 알고리즘 | 발표 | 출력 길이              | 블록         | 상태                                                                  |
| -------- | ---- | ---------------------- | ------------ | --------------------------------------------------------------------- |
| SHA-0    | 1993 | 160비트                | 512비트      | 발표 직후 결함으로 철회                                               |
| SHA-1    | 1995 | 160비트                | 512비트      | MD4 구조를 발전시킨 형태. 2017년 실제 충돌(SHAttered), 서명 용도 폐기 |
| SHA-2    | 2001 | 224, 256, 384, 512비트 | 512·1024비트 | 현재 표준. SHA-256이 가장 널리 쓰임                                   |
| SHA-3    | 2015 | 224, 256, 384, 512비트 | 가변         | 공모로 선정된 Keccak. SHA-2와 내부 구조(스펀지)가 다름                |

SHA-1은 MD5보다 조금 느리지만 더 안전한 해시로 2000년대에 표준처럼 쓰였다. 2017년 구글과 CWI 연구팀이 내용이 다르고 SHA-1 값이 같은 PDF 파일 두 개를 공개(SHAttered)하면서 서명 용도에서 완전히 퇴출되었다. Git도 SHA-1에서 SHA-256으로 옮겨 가는 중이다. SHA-2 계열에서 SHA-256은 비트코인, TLS 인증서 서명, 소프트웨어 배포 파일 검증에 쓰인다.

![SHA-1, SHA-256, SHA-384, SHA-512의 최대 메시지 크기, 블록 크기, 해시 길이, 상대 강도를 비교한 표](./images/csintro-cryptography-slide-sha.jpg 'SHA 계열의 매개변수. SHA-256과 SHA-512의 블록은 각각 512비트, 1,024비트다. 출처: 양대일, 『정보 보안 개론』, 한빛아카데미')

### 비밀번호 저장

비밀번호를 데이터베이스에 저장할 때는 평문 대신 해시값을 저장하고, 로그인 시 입력값의 해시를 비교한다. 다만 SHA-256 같은 범용 해시를 그대로 쓰지 않는다. 범용 해시는 빨라서 GPU로 초당 수십억 개를 대입할 수 있고, 같은 비밀번호는 같은 해시값이 되어 미리 계산해 둔 표(레인보 테이블)로 역추적되기 때문이다. 사용자마다 다른 무작위 값(솔트)을 붙이고 일부러 느리게 만든 bcrypt, scrypt, Argon2, PBKDF2를 쓴다.

## 전자서명과 PKI

### 전자서명

전자서명은 해시와 공개키 암호를 조합해 문서의 무결성, 서명자 인증, 부인 방지를 제공한다. ==긴 문서 전체를 공개키 연산으로 처리하면 느리므로 문서의 해시값에 서명한다==.

![A는 문서의 해시값을 개인키로 서명해 문서와 함께 보내고, B는 문서를 직접 해시한 값과 서명을 A의 공개키로 검증한 값을 비교한다](./images/csintro-cryptography-signature.svg '해시와 개인키로 만드는 전자서명과 검증')

문서가 한 글자라도 바뀌면 B가 계산한 해시값이 달라 검증에 실패한다. A의 개인키 없이는 올바른 서명을 만들 수 없으므로, 서명이 검증되면 A가 서명했다는 사실도 확인된다.

### PKI와 인증서

남은 문제는 =="이 공개키가 정말 A의 것인가"==다. 공격자가 자기 공개키를 A의 것이라고 속여 배포하면 서명 검증 자체가 무의미해진다. 공개키 기반 구조(PKI, Public Key Infrastructure)는 신뢰하는 제3자인 **인증 기관**(CA, Certificate Authority)이 "이 공개키의 주인은 A다"라는 내용에 전자서명한 **인증서**(X.509 형식)를 발급해 이 문제를 해결한다.

| 구성 요소                   | 역할                                                              |
| --------------------------- | ----------------------------------------------------------------- |
| 인증 기관(CA)               | 신원을 확인하고 인증서를 발급·폐지                                |
| 등록 기관(RA)               | 신청자의 신원 확인을 대행                                         |
| 인증서                      | 소유자 정보, 공개키, 유효 기간, 발급 CA의 서명                    |
| 인증서 폐지 목록(CRL), OCSP | 유효 기간 전에 폐지된 인증서를 확인                               |
| 루트 인증서                 | 운영체제·브라우저에 미리 저장된 최상위 CA의 인증서. 신뢰의 출발점 |

웹 브라우저는 서버 인증서에서 출발해 중간 CA, 루트 CA 순서로 서명을 검증하고, 루트 인증서가 운영체제나 브라우저의 신뢰 저장소에 있으면 연결을 신뢰한다. 국내에서는 2020년 12월 개정 「전자서명법」 시행으로 공인인증서 제도가 폐지되어, 과거 공인인증서는 '공동인증서'라는 이름으로 여러 민간 전자서명 수단과 같은 지위에서 쓰인다.

## 직접 해 보기

### C로 만든 시저 암호

영문 평문을 입력받아 3칸 이동한 암호문을 출력하는 프로그램을 처음에는 다음과 같이 작성했다.

```c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

void main()
{
    char plaintext[30];  // 평문을 담을 배열
    char *ciphertext;    // 암호문을 담을 포인터, 길이에 맞춰 동적 할당
    int length = 0;

    printf("Plaintext (only english) ==> ");
    gets(plaintext);
    length = strlen(plaintext);
    ciphertext = calloc(length + 1, sizeof(char));

    int i = 0;
    while (i < length)
    {
        if (('A' <= plaintext[i] && plaintext[i] <= 'Z') || ('a' <= plaintext[i] && plaintext[i] <= 'z'))
        {
            if (('X' <= plaintext[i] && plaintext[i] <= 'Z') || ('x' <= plaintext[i] && plaintext[i] <= 'z'))
                ciphertext[i] = plaintext[i] - 23;  // X~Z는 A~C로 돌아감
            else
                ciphertext[i] = plaintext[i] + 3;
        }
        else
            ciphertext[i] = plaintext[i];           // 알파벳이 아니면 그대로
        i++;
    }
    printf("Caesar encryption ==> %s\n", ciphertext);
}
```

macOS의 clang으로 컴파일해 `Hello, World!`를 입력한 결과는 다음과 같다. Xcode에서 실행하면 마지막 줄이 `Program ended with exit code: 36`으로 표시된다.

```text
$ cc -w -o caesar ceaser.c
$ echo 'Hello, World!' | ./caesar; echo "exit $?"
warning: this program uses gets(), which is unsafe.
Plaintext (only english) ==> Caesar encryption ==> Khoor, Zruog!
exit 36
```

암호화 결과는 맞지만 두 가지가 눈에 띈다.

- **`gets` 경고**: macOS의 C 라이브러리는 `gets`를 호출하는 프로그램이 실행될 때 경고를 출력한다. `gets`는 입력 길이를 검사하지 않아 30자를 넘게 입력하면 배열 뒤의 스택 메모리(반환 주소 포함)를 덮어쓴다. 1988년 모리스 웜이 `fingerd`의 `gets` 호출을 이용해 퍼졌고, C11 표준에서 삭제되었다. ==암호 프로그램이라도 입력 처리가 안전하지 않으면 그 자체가 공격 경로가 된다==.
- **종료 코드 36**: `main`의 반환형을 `void`로 두어 반환값이 정해지지 않았다. 그래서 반환값 레지스터에 마지막으로 남아 있던 `printf`의 반환값, 즉 출력한 글자 수 `"Caesar encryption ==> Khoor, Zruog!\n"`의 36바이트가 종료 코드로 보인 것이다. 입력 길이가 바뀌면 종료 코드도 바뀐다. C 표준이 정한 `main`의 반환형은 `int`다.

이 문제들을 고친 판은 다음과 같다.

```c
#include <ctype.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* 알파벳만 key칸 밀고, 나머지 문자는 그대로 둔다 */
static char shift(char c, int key)
{
	if (isupper((unsigned char)c))
		return (char)('A' + (c - 'A' + key) % 26);
	if (islower((unsigned char)c))
		return (char)('a' + (c - 'a' + key) % 26);
	return c;
}

int main(void)
{
	char plaintext[256];
	int key = 3;

	printf("Plaintext (only english) ==> ");
	if (fgets(plaintext, sizeof plaintext, stdin) == NULL)
		return 1;
	plaintext[strcspn(plaintext, "\n")] = '\0';

	size_t length = strlen(plaintext);
	char *ciphertext = calloc(length + 1, sizeof(char));
	if (ciphertext == NULL)
		return 1;

	for (size_t i = 0; i < length; i++)
		ciphertext[i] = shift(plaintext[i], key);

	printf("Caesar encryption ==> %s\n", ciphertext);
	free(ciphertext);
	return 0;
}
```

```text
$ cc -Wall -Wextra -o caesar caesar.c
$ ./caesar
Plaintext (only english) ==> Hello, xyz World
Caesar encryption ==> Khoor, abc Zruog
$ echo $?
0
```

| 처음 코드                           | 문제                                                    | 고친 코드                                  |
| ----------------------------------- | ------------------------------------------------------- | ------------------------------------------ |
| `gets(plaintext)` (배열 30바이트)   | 입력 길이 검사 없음, 스택 버퍼 오버플로. C11에서 삭제됨 | `fgets`로 버퍼 크기만큼만 읽고 줄바꿈 제거 |
| `void main()`                       | 종료 코드가 정해지지 않음(위 실행에서 36)               | `int main(void)`, `return 0`               |
| X~Z는 `-23`, 나머지는 `+3`으로 분기 | 3칸 이동에만 맞는 상수라 키를 바꾸면 다시 계산해야 함   | `(c - 'A' + key) % 26`으로 일반화          |
| `calloc` 결과 미확인, `free` 없음   | 할당 실패 시 널 포인터 역참조, 메모리 해제 누락         | 반환값 확인, `free` 호출                   |

복호화는 `key`를 `26 - 3 = 23`으로 바꿔 같은 함수에 넣으면 된다. 25개 키를 모두 넣어 출력하는 반복문 하나면 이 암호가 전수 조사로 바로 풀린다는 사실도 확인할 수 있다.

### MD5 해시값 비교

웹의 MD5 생성기나 터미널에서, 마지막 한 글자만 다른 두 문자열의 해시를 비교한다.

```bash
echo -n hello1 | md5          # 리눅스는 md5sum
echo -n hello2 | md5
echo -n hello | shasum -a 256 # 리눅스는 sha256sum
```

```text
203ad5ffa1d7c650ad681fdff3965cd2
6e809cbda0732ac4845916a59016f954
2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
```

| 입력     | 알고리즘 | 해시값(앞 8자리) | 길이(16진수) |
| -------- | -------- | ---------------- | ------------ |
| `hello1` | MD5      | `203ad5ff`       | 32자         |
| `hello2` | MD5      | `6e809cbd`       | 32자         |
| `hello`  | SHA-256  | `2cf24dba`       | 64자         |

끝의 숫자 하나만 다른데 두 MD5 값에 공통된 패턴이 없다. 웹 생성기는 결과를 대문자로 보여 주기도 하지만 16진수 표기의 대소문자 차이일 뿐 값은 같다. `-n`을 빼면 `echo`가 줄바꿈 문자까지 입력에 넣어 다른 값이 나온다. 내려받은 파일의 무결성을 확인할 때는 배포처가 공개한 SHA-256 값과 `shasum -a 256 <파일>`의 결과를 비교한다.
