## 들어가기 전에

암호는 정해진 사람만 내용을 읽을 수 있도록 데이터를 바꾸는 기술이다. 인터넷 뱅킹, 메신저, 웹 사이트의 자물쇠 표시(HTTPS)가 모두 이 글에서 다루는 알고리즘을 조합해 동작한다.

| 순서 | 내용                                      |
| ---- | ----------------------------------------- |
| 1    | 용어와 케르크호프스 원칙                  |
| 2    | 고전 암호: 전치, 치환(시저 암호)과 C 구현 |
| 3    | 대칭키 암호: DES, 3DES, AES, SEED         |
| 4    | 공개키 암호: RSA와 작은 수 예제           |
| 5    | 해시 함수: MD5, SHA 계열과 충돌           |
| 6    | 전자서명과 PKI                            |

필요한 배경은 정보보호의 목표인 기밀성·무결성·가용성과, 비트·바이트와 나머지 연산(`a mod n{:math}`, a를 n으로 나눈 나머지)이다.

## 용어와 기본 가정

| 용어               | 뜻                                                                 |
| ------------------ | ------------------------------------------------------------------ |
| 평문(plaintext)    | 누구나 읽을 수 있는 원래 데이터                                    |
| 암호문(ciphertext) | 키 없이는 뜻을 알 수 없게 바꾼 데이터                              |
| 암호화(encryption) | 평문을 암호문으로 바꾸는 과정                                      |
| 복호화(decryption) | 암호문을 평문으로 되돌리는 과정                                    |
| 키(key)            | 암호화·복호화 알고리즘에 넣는 비밀 값                              |
| 암호학(cryptology) | 암호 설계(cryptography)와 암호 분석(cryptanalysis)을 아우르는 학문 |

현대 암호는 **케르크호프스 원칙**(Kerckhoffs's principle)을 따른다. 알고리즘은 공격자에게 모두 알려져 있다고 가정하고, 키만 비밀로 유지해도 안전해야 한다는 원칙이다. 비공개 알고리즘은 역공학이나 유출로 결국 공개되고, 공개 검증을 거치지 않은 알고리즘에는 설계 결함이 남아 있는 경우가 많기 때문이다. AES와 SHA-3도 공개 공모와 수년간의 공개 분석을 거쳐 표준이 되었다.

## 고전 암호

### 전치 암호

전치(transposition) 암호는 글자는 그대로 두고 위치만 정해진 규칙으로 바꾼다. 규칙이 "앞에서부터 두 글자씩 묶어 순서를 바꾼다"라면 `apple`은 `pa` `lp` `e`가 되어 `palpe`, `orange`는 `ro` `na` `eg`가 되어 `ronaeg`이 된다. 규칙이 "뒤집기"라면 `orange`는 `egnaro`다. 글자 빈도가 평문과 같아서, 영어라면 e·t·a가 여전히 많이 나온다는 점이 분석의 단서가 된다.

### 치환 암호와 시저 암호

치환(substitution) 암호는 각 글자를 다른 글자로 바꾼다. 시저 암호(Caesar cipher)는 알파벳을 정해진 칸 수만큼 밀어 바꾸는 가장 단순한 치환 암호로, 율리우스 카이사르가 3칸 이동을 썼다고 전해진다.

글자를 A=0, B=1, …, Z=25로 번호 매기고 이동 칸 수를 키 k라 하면 다음과 같다.

```math
E(x) = (x + k) \bmod 26, \qquad D(y) = (y - k) \bmod 26
```

k = 3일 때 `HELLO`는 `KHOOR`가 되고, 알파벳 끝의 `X`·`Y`·`Z`는 처음으로 돌아가 `A`·`B`·`C`가 된다. 키가 될 수 있는 값이 25개뿐이라 모두 대입해 보는 전수 조사(brute force)로 곧바로 해독된다. 키 공간이 작은 암호는 알고리즘을 숨겨도 안전하지 않다는 대표적인 예다.

### C로 구현한 시저 암호

다음은 영문 평문을 입력받아 3칸 이동한 암호문을 출력하는 프로그램이다.

```c
#include <ctype.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

/* 알파벳만 key칸 밀고, 나머지 문자는 그대로 둔다 */
static char shift(char c, int key)
{
	if (isupper((unsigned char)c))
		return (char)('A' + (c - 'A' + key) % 26);
	if (islower((unsigned char)c))
		return (char)('a' + (c - 'a' + key) % 26);
	return c;
}

int main(void)
{
	char plaintext[256];
	int key = 3;

	printf("Plaintext (only english) ==> ");
	if (fgets(plaintext, sizeof plaintext, stdin) == NULL)
		return 1;
	plaintext[strcspn(plaintext, "\n")] = '\0';

	size_t length = strlen(plaintext);
	char *ciphertext = calloc(length + 1, sizeof(char));
	if (ciphertext == NULL)
		return 1;

	for (size_t i = 0; i < length; i++)
		ciphertext[i] = shift(plaintext[i], key);

	printf("Caesar encryption ==> %s\n", ciphertext);
	free(ciphertext);
	return 0;
}
```

```text
$ cc -Wall -Wextra -o caesar caesar.c
$ ./caesar
Plaintext (only english) ==> Hello, xyz World
Caesar encryption ==> Khoor, abc Zruog
```

이 코드는 처음 작성한 판에서 다음을 고친 결과다.

| 처음 코드                           | 문제                                                                                     | 고친 코드                                  |
| ----------------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------ |
| `gets(plaintext)` (배열 30바이트)   | 입력 길이를 검사하지 않아 30자를 넘으면 스택 버퍼 오버플로. C11에서 표준에서 삭제된 함수 | `fgets`로 버퍼 크기만큼만 읽고 줄바꿈 제거 |
| `void main()`                       | C 표준이 정한 `main`의 반환형은 `int`                                                    | `int main(void)`, `return 0`               |
| X~Z는 `-23`, 나머지는 `+3`으로 분기 | 3칸 이동에만 맞는 상수라 키를 바꾸면 다시 계산해야 함                                    | `(c - 'A' + key) % 26`으로 일반화          |
| `calloc` 결과 미확인, `free` 없음   | 할당 실패 시 널 포인터 역참조, 메모리 해제 누락                                          | 반환값 확인, `free` 호출                   |

`gets`는 이 프로그램에서 가장 위험한 부분이다. 입력이 배열 크기를 넘으면 스택의 반환 주소까지 덮어쓸 수 있어, 1988년 모리스 웜이 `fingerd`의 `gets` 호출을 이용해 퍼졌다. 암호 프로그램이라도 입력 처리가 안전하지 않으면 그 자체가 공격 경로가 된다.

## 대칭키 암호

대칭키 암호는 암호화와 복호화에 같은 키를 쓴다. 연산이 빨라 대용량 데이터 암호화에 쓰지만, 통신 전에 두 사람이 같은 키를 안전하게 나눠 가져야 하는 **키 분배 문제**가 있다. n명이 서로 다른 키로 통신하려면 키가 `n(n-1)/2{:math}`개 필요해, 100명이면 4,950개다.

![대칭키 암호는 같은 키 K로 암호화·복호화하고, 공개키 암호는 수신자의 공개키로 암호화하고 개인키로 복호화한다](./images/csintro-cryptography-keys.svg '대칭키와 공개키 암호의 키 사용 방식')

평문을 일정 크기 블록으로 나눠 처리하는 블록 암호가 대표적이다.

| 알고리즘 | 블록 크기          | 키 길이           | 라운드       | 현재 상태                                                   |
| -------- | ------------------ | ----------------- | ------------ | ----------------------------------------------------------- |
| DES      | 64비트             | 56비트            | 16           | 1977년 미국 표준(FIPS 46). 2005년 표준 철회, 사용 금지      |
| 3DES     | 64비트             | 112 또는 168비트  | 48(DES 3회)  | NIST가 2023년 이후 암호화 용도 사용 금지                    |
| AES      | 128비트            | 128, 192, 256비트 | 10, 12, 14   | 2001년 미국 표준(FIPS 197). 현재 가장 널리 쓰는 대칭키 암호 |
| SEED     | 128비트            | 128비트           | 16           | 1999년 KISA 개발, 국내 표준(TTA)                            |
| IDEA     | 64비트             | 128비트           | 8.5          | PGP 초기 판에서 사용                                        |
| RC5      | 32·64·128비트 가변 | 0~2,040비트 가변  | 가변 (1~255) | 1994년 리베스트 설계, 매개변수형 블록 암호                  |

### DES와 3DES

DES는 64비트 블록을 좌우 32비트로 나누고, 오른쪽 절반을 확장(32→48비트)한 뒤 라운드 키와 XOR하고 S-박스 8개로 다시 32비트로 줄여 왼쪽과 섞는 과정을 16번 반복한다. 이 구조를 페이스텔(Feistel) 구조라 한다. 각 S-박스는 6비트 입력을 4비트로 바꾸는 표이며, 이 비선형 변환이 DES 안전성의 핵심이다.

DES가 폐기된 이유는 구조가 아니라 키 길이다. 56비트 키의 경우의 수는 `2^{56} \approx 7.2 \times 10^{16}{:math}`개로, 1998년 전자 프런티어 재단(EFF)이 만든 전용 장비 Deep Crack이 56시간 만에 키를 찾았다.

3DES는 DES를 `암호화(K1) → 복호화(K2) → 암호화(K3)` 순서로 세 번 적용한다. 키 두 개(K1 = K3)를 쓰면 키 길이는 112비트지만, 중간 일치 공격 등을 고려한 실제 보안 강도는 약 80비트로 평가된다. 키 세 개를 쓰면 키 길이 168비트, 보안 강도 112비트다[^sp800-57]. DES보다 세 배 느리고 블록이 64비트로 작아 대량 데이터에서 충돌을 이용한 공격(Sweet32)에 취약해, AES로 대체되었다.

### AES

AES는 1997년 NIST의 공개 공모에서 15개 후보 가운데 벨기에의 다먼(Daemen)과 레이먼(Rijmen)이 설계한 Rijndael이 선정된 것이다. 128비트 블록을 4×4 바이트 행렬로 보고 바이트 치환(SubBytes), 행 이동(ShiftRows), 열 혼합(MixColumns), 라운드 키 더하기(AddRoundKey)를 키 길이에 따라 10·12·14라운드 반복한다. 대부분의 CPU가 AES 전용 명령어(x86의 AES-NI, ARMv8 Crypto Extensions)를 제공해 초당 수 GB를 처리한다. HTTPS, 디스크 암호화(FileVault, BitLocker), 와이파이(WPA2·WPA3)가 모두 AES를 쓴다.

## 공개키 암호

공개키 암호(비대칭키 암호)는 수학적으로 연결된 키 한 쌍을 쓴다. **공개키**는 누구에게나 공개하고, **개인키**는 소유자만 보관한다. 한 키로 암호화한 것은 짝이 되는 다른 키로만 풀린다. 1976년 디피(Diffie)와 헬먼(Hellman)이 개념을 발표했고, 1977년 리베스트(Rivest), 샤미르(Shamir), 애들먼(Adleman)이 처음으로 실용적인 알고리즘 RSA를 만들었다.

- **기밀성**: B의 공개키로 암호화하면 B의 개인키를 가진 B만 읽는다. 사전에 비밀 키를 나눌 필요가 없다.
- **부인 방지**: A가 자기 개인키로 서명하면 A의 공개키로 누구나 검증할 수 있고, 개인키는 A만 가지므로 A가 나중에 서명 사실을 부인할 수 없다. 대칭키 암호는 두 사람이 같은 키를 가지므로 누가 만들었는지 구분할 수 없다.

### RSA의 원리

RSA의 안전성은 큰 두 소수의 곱은 쉽게 계산되지만, 그 곱을 다시 두 소수로 인수분해하기는 매우 어렵다는 사실에 기반한다. 계산을 따라갈 수 있도록 아주 작은 수로 예를 든다.

| 기호   | 뜻                              | 예시 값  |
| ------ | ------------------------------- | -------- |
| p, q   | 비밀로 고르는 두 소수           | 5, 11    |
| n      | 법(modulus), `p × q`, 공개      | 55       |
| φ(n)   | `(p − 1)(q − 1)`, 비밀          | 40       |
| e      | 공개 지수, φ(n)과 서로소        | 3        |
| d      | 개인 지수, `e × d mod φ(n) = 1` | 27       |
| 공개키 | (e, n)                          | (3, 55)  |
| 개인키 | (d, n)                          | (27, 55) |

1. 키 생성: p = 5, q = 11에서 n = 55, φ(n) = 40이다. e = 3을 고르면 `3 × 27 = 81 = 2 × 40 + 1`이므로 d = 27이다.
2. 암호화: 평문 m = 7을 공개키로 암호화한다.

   ```math
   c = m^e \bmod n = 7^3 \bmod 55 = 343 \bmod 55 = 13
   ```

3. 복호화: 암호문 13을 개인키로 복호화한다.

   ```math
   m = c^d \bmod n = 13^{27} \bmod 55 = 7
   ```

| 단계   | 입력 | 사용한 키 | 출력 |
| ------ | ---- | --------- | ---- |
| 암호화 | 7    | (3, 55)   | 13   |
| 복호화 | 13   | (27, 55)  | 7    |

n = 55는 바로 5 × 11로 분해되므로 이 예제는 안전하지 않다. 실제로는 n을 2,048비트(10진수 약 617자리) 이상으로 쓴다. 공개키 연산은 대칭키보다 수백~수천 배 느려서, 실제 프로토콜(TLS 등)은 공개키 방식으로 대칭키를 안전하게 합의한 뒤 데이터는 AES로 암호화하는 하이브리드 방식을 쓴다.

## 해시 함수

해시 함수는 임의 길이의 입력을 고정 길이의 값(해시값, 다이제스트)으로 바꾸는 함수다. 암호화가 내용을 숨기는 기술이라면, 해시는 내용이 바뀌었는지 확인하는 **무결성** 검증 기술이다. 원래는 데이터베이스와 해시 테이블에서 빠른 검색을 위해 쓰였고, 보안에서는 입력이 1비트만 달라도 해시값이 전혀 달라진다는 성질을 이용한다.

암호학적 해시 함수 h가 갖춰야 할 성질은 다음과 같다.

| 성질                              | 뜻                                                       |
| --------------------------------- | -------------------------------------------------------- |
| 압축                              | 입력 길이와 관계없이 출력은 고정 길이                    |
| 효율성                            | 어떤 입력 x든 `h(x)`를 빠르게 계산                       |
| 역상 저항성(일방향성)             | 해시값 y가 주어져도 `h(x) = y`인 x를 찾기 어려움         |
| 제2 역상 저항성(약한 충돌 저항성) | x가 주어졌을 때 `h(y) = h(x)`인 다른 y를 찾기 어려움     |
| 충돌 저항성(강한 충돌 저항성)     | `h(x) = h(y)`인 서로 다른 x, y 쌍을 아무거나 찾기 어려움 |

출력 길이가 유한하므로 충돌은 반드시 존재한다. 요구 조건은 충돌을 "찾기가 계산상 어려워야" 한다는 것이다.

| 알고리즘 | 출력 길이              | 발표           | 상태                                                                |
| -------- | ---------------------- | -------------- | ------------------------------------------------------------------- |
| MD5      | 128비트                | 1991, 리베스트 | 2004년 충돌 발견. 보안 용도 사용 금지(파일 손상 확인 정도로만 사용) |
| SHA-1    | 160비트                | 1995, NSA·NIST | 2017년 실제 충돌(SHAttered) 공개. 전자서명 용도 폐기                |
| SHA-2    | 224, 256, 384, 512비트 | 2001           | 현재 표준. SHA-256이 가장 널리 쓰임                                 |
| SHA-3    | 224, 256, 384, 512비트 | 2015           | 공모로 선정된 Keccak, SHA-2와 내부 구조가 다른 예비 표준            |

비밀번호 저장에는 SHA-256 같은 범용 해시를 그대로 쓰지 않는다. 범용 해시는 빨라서 GPU로 초당 수십억 개를 대입할 수 있기 때문이다. 사용자마다 다른 무작위 값(솔트)을 붙이고 일부러 느리게 만든 bcrypt, scrypt, Argon2, PBKDF2를 쓴다.

## 전자서명과 PKI

### 전자서명

전자서명은 해시와 공개키 암호를 조합해 문서의 무결성, 서명자 인증, 부인 방지를 제공한다. 긴 문서 전체를 공개키 연산으로 처리하면 느리므로 문서의 해시값에 서명한다.

![A는 문서의 해시값을 개인키로 서명해 문서와 함께 보내고, B는 문서를 직접 해시한 값과 서명을 A의 공개키로 검증한 값을 비교한다](./images/csintro-cryptography-signature.svg '해시와 개인키로 만드는 전자서명과 검증')

문서가 한 글자라도 바뀌면 B가 계산한 해시값이 달라 검증에 실패한다. A의 개인키 없이는 올바른 서명을 만들 수 없으므로 서명이 검증되면 A가 서명했다는 사실도 확인된다.

### PKI와 인증서

남은 문제는 "이 공개키가 정말 A의 것인가"다. 공격자가 자기 공개키를 A의 것이라고 속여 배포하면 서명 검증 자체가 무의미해진다. 공개키 기반 구조(PKI, Public Key Infrastructure)는 신뢰하는 제3자인 **인증 기관**(CA, Certificate Authority)이 "이 공개키의 주인은 A다"라는 내용에 전자서명한 **인증서**(X.509 형식)를 발급해 이 문제를 해결한다.

| 구성 요소                   | 역할                                                              |
| --------------------------- | ----------------------------------------------------------------- |
| 인증 기관(CA)               | 신원을 확인하고 인증서를 발급·폐지                                |
| 등록 기관(RA)               | 신청자의 신원 확인을 대행                                         |
| 인증서                      | 소유자 정보, 공개키, 유효 기간, 발급 CA의 서명                    |
| 인증서 폐지 목록(CRL), OCSP | 유효 기간 전에 폐지된 인증서를 확인                               |
| 루트 인증서                 | 운영체제·브라우저에 미리 저장된 최상위 CA의 인증서. 신뢰의 출발점 |

웹 브라우저는 서버 인증서에서 출발해 중간 CA, 루트 CA 순서로 서명을 검증하고, 루트 인증서가 운영체제나 브라우저의 신뢰 저장소에 있으면 연결을 신뢰한다. 국내에서는 2020년 12월 개정 「전자서명법」 시행으로 공인인증서 제도가 폐지되어, 과거 공인인증서는 '공동인증서'라는 이름으로 여러 민간 전자서명 수단과 같은 지위에서 쓰인다.

## 직접 해 보기

macOS와 리눅스에는 해시 계산 명령이 기본으로 들어 있다. 입력이 한 글자만 달라도 해시값이 완전히 달라지는지 확인한다.

```bash
echo -n hello | md5          # 리눅스는 md5sum
echo -n hellp | md5
echo -n hello | shasum -a 256 # 리눅스는 sha256sum
```

```text
5d41402abc4b2a76b9719d911017c592
c983190483df167d2a3841463c2a9341
2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
```

| 입력    | 알고리즘 | 해시값(앞 8자리) |
| ------- | -------- | ---------------- |
| `hello` | MD5      | `5d41402a`       |
| `hellp` | MD5      | `c9831904`       |
| `hello` | SHA-256  | `2cf24dba`       |

마지막 글자 o를 p로 바꿨을 뿐인데 MD5 값에 공통된 부분이 없다. `-n`을 빼면 `echo`가 줄바꿈 문자까지 입력에 넣어 다른 값이 나온다. 내려받은 파일의 무결성을 확인할 때는 배포처가 공개한 SHA-256 값과 `shasum -a 256 <파일>`의 결과를 비교한다.
