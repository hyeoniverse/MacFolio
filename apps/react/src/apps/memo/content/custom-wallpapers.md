시스템 설정 → 배경화면에는 macOS 배경화면 6장과 iOS 배경화면 6장이 있다. 모두 `public/imgs/wallpapers`에 파일로 포함되어 있어서, 하나를 추가하려면 이미지를 축소하고 썸네일을 생성해 커밋하고 배포해야 했다. 라이트·다크 두 벌과 썸네일까지 그 폴더만 현재 7.7MB다. 사진 한 장을 바꾸려고 저장소에 MB 단위 파일을 누적하고 배포를 기다리는 방식은 적합하지 않았다. PR은 [#75](https://github.com/hyeoniverse/MacFolio/pull/75)다.

이제 배경화면 화면 위쪽에 '추가한 배경화면' 그룹이 별도로 있다. macOS 설정에서 '사용자의 사진'이 기본 배경화면과 분리된 구성과 같다. 관리자로 로그인하면 그 그룹 맨 앞에 '사진 추가…' 칸이 표시된다. 회색 배경 칸 안에 사진 아이콘(+)과 문구가 있다. 사진을 선택하면 즉시 업로드되고, 바로 그 배경화면으로 바뀐다. 업로드한 배경화면은 그 칸 뒤에 추가되고, 모든 방문자에게 표시된다. 업로드한 배경화면이 없으면 방문자에게는 이 그룹이 표시되지 않는다.

![데스크톱 전후](./images/custom-wallpapers-desktop.jpg '추가한 배경화면과 기본 배경화면을 따로, 묶음마다 간략히 보기(가로 한 줄)와 모두 보기')

## 표시 대상 결정

처음에 두 방식을 비교했다.

| 방식                                    | 표시 대상   | 저장 위치                 |
| --------------------------------------- | ----------- | ------------------------- |
| 방문자가 자기 사진을 추가               | 해당 방문자 | 해당 브라우저 (IndexedDB) |
| **관리자가 업로드하면 모든 방문자에게** | 모든 방문자 | 서버                      |

포트폴리오의 배경화면은 사이트 주인이 정하는 것이라 두 번째 방식을 채택했다. 방문자는 기존처럼 선택만 한다.

## 화면 종류별 배경화면 표시

처음에는 설정에 macOS 그룹과 iOS 그룹을 모두 표시했다. 그런데 데스크톱 방문자가 휴대폰 배경화면을 선택할 이유는 없다. 이제 데스크톱에는 macOS 배경화면만, 휴대폰에는 iOS 배경화면만 표시된다.

그러면 관리자가 데스크톱에서 휴대폰 배경화면을 업로드할 수 없다. 두 종류를 한 장으로 통합하는 방법도 검토했지만, 가로(16:10)와 세로(9:19.5)의 비율 차이가 커서 기본 배경화면을 다른 쪽에 사용하면 크게 잘린다. 그래서 기본 배경화면은 화면 종류별로 분리하고, **추가한 배경화면은 구분 없이 양쪽에 모두 표시**했다. 데스크톱에서 한 번 업로드하면 휴대폰에서도 선택할 수 있다. 비율이 다르면 가운데 기준으로 잘리지만, 관리자가 직접 선택한 사진이라 허용 범위로 판단했다. 선택한 배경화면은 데스크톱용과 휴대폰용을 별도로 저장한다.

| 항목            | 데스크톱                                                          | 휴대폰                  |
| --------------- | ----------------------------------------------------------------- | ----------------------- |
| 기본 배경화면   | macOS 6장                                                         | iOS 6장                 |
| 추가한 배경화면 | 표시                                                              | 표시                    |
| 배치            | 그룹마다 가로 한 줄(간략히 보기), '모두 보기(n)'로 여러 줄 펼치기 | 화면 폭에 맞춘 3열 격자 |
| 지우기(×) 버튼  | 마우스를 올렸을 때 표시                                           | 항상 표시               |
| 선택 저장       | 데스크톱용 값                                                     | 휴대폰용 값             |

썸네일은 macOS 설정처럼 테두리 없이 둥근 사진만 표시하고, 선택한 항목에는 약간 떨어진 파란 테두리를 표시한다(`outline-offset`). 데스크톱의 한 줄 보기에서는 열자마자 선택한 배경화면이 보이는 위치로 스크롤해 둔다.

칸 단위로 스크롤이 멈추게([`scroll-snap`](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_scroll_snap)) 했더니 처음에 첫 칸이 8px 잘려 있었다. 왼쪽 위로 걸친 ×가 잘리지 않도록 한 줄에 안쪽 여백을 두었는데, 스냅 정렬 기준은 그 여백을 반영하지 않고 스크롤 컨테이너의 가장자리에 첫 칸을 정렬했기 때문이다. [`scroll-padding-inline`](https://developer.mozilla.org/en-US/docs/Web/CSS/scroll-padding-inline)으로 정렬 기준도 같은 만큼 안쪽으로 이동했다.

## 서버: 기존 파일 저장소 활용

![사진 고르기 → 브라우저에서 2560px·640px JPEG → POST /wallpapers → Upload 두 줄과 Wallpaper 한 줄 → GET /wallpapers로 모든 방문자에게](./images/custom-wallpapers-upload-flow.svg '이미지 처리는 브라우저가, 저장과 권한은 서버가 맡는다')

메모 글에 넣는 이미지를 업로드하는 API(`POST /files`)가 이미 있다. 파일은 DB의 `Upload` 테이블에 저장하고 `/files/:id`로 응답한다. 배경화면은 그 위에 테이블 하나(`Wallpaper`)만 추가했다. 이름과 원본·썸네일의 `Upload` id를 저장한다.

| API                      | 권한   | 동작                                           |
| ------------------------ | ------ | ---------------------------------------------- |
| `GET /wallpapers`        | 모두   | 목록 조회                                      |
| `POST /wallpapers`       | 관리자 | 원본·썸네일 이미지와 이름으로 생성             |
| `PATCH /wallpapers/:id`  | 관리자 | 이름 변경 (아래 '삭제와 이름 변경' 참고)       |
| `DELETE /wallpapers/:id` | 관리자 | 삭제. 이미지 두 장도 한 트랜잭션에서 함께 삭제 |

이미지는 MIME 형식 이름을 신뢰하지 않고 파일 앞부분의 바이트(매직 바이트)로 PNG·JPEG·GIF·WebP 여부를 확인한다. 파일 API와 같은 규칙이다. 이름 길이는 DB의 CHECK 제약으로도 제한한다. 업로드한 이미지의 EXIF는 이후 서버에서 제거하도록 바뀌었다([JPEG·PNG·WebP 세그먼트를 순회해 EXIF를 지우고 방향 값만 남기기](/memo/upload-strip-exif)).

테이블을 별도로 둔 이유는 "어떤 업로드 파일이 배경화면인가"를 식별해야 하기 때문이다. `Upload`만 있으면 글에 넣은 이미지와 배경화면을 구분할 수 없다. 삭제 시 이미지 두 장을 함께 삭제하는 처리, 휴지통에서 "배경화면으로 사용 중인 파일은 삭제하지 않는다"고 표시하는 처리 모두 이 테이블을 기준으로 한다. 마이그레이션 파일(`20261002150000_wallpapers/migration.sql`)은 22줄이다.

## 브라우저에서 축소해 전송

휴대폰으로 촬영한 사진은 10MB를 넘기 쉽고, 업로드 한도도 10MB다. 서버에서 축소하려면 이미지 처리 라이브러리가 필요한데, 소형 서버(E2.1.Micro, RAM 1GB)에서 실행하기에는 부담이 크다. 그래서 브라우저가 캔버스로 축소한 뒤 JPEG 두 장을 전송한다([`createImageBitmap`](https://developer.mozilla.org/en-US/docs/Web/API/Window/createImageBitmap), [`canvas.toBlob`](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob)).

```ts
const bitmap = await createImageBitmap(file);
const scale = Math.min(1, max / Math.max(bitmap.width, bitmap.height));
canvas.width = Math.round(bitmap.width * scale);
canvas.height = Math.round(bitmap.height * scale);
context.drawImage(bitmap, 0, 0, canvas.width, canvas.height);
canvas.toBlob(resolve, 'image/jpeg', quality);
```

| 파일   | 긴 변  | JPEG 품질 | 기준                                  |
| ------ | ------ | --------- | ------------------------------------- |
| 원본   | 2560px | 0.86      | 기본 배경화면과 같은 크기             |
| 썸네일 | 640px  | 0.8       | 설정 화면 썸네일(320px)의 2배(레티나) |

두 장은 `Promise.all`로 병렬 생성한다. 썸네일이 별도로 있어서 설정 화면이 원본 수 MB를 내려받지 않는다.

| 방법                                   | 장점                               | 단점                                                                       |
| -------------------------------------- | ---------------------------------- | -------------------------------------------------------------------------- |
| 원본을 업로드하고 서버가 축소          | 브라우저 처리가 없다               | 이미지 라이브러리(sharp 등)를 1GB 서버에 설치해야 한다. 10MB 한도를 넘는다 |
| 원본을 업로드하고 그대로 사용          | 가장 단순                          | 설정 화면 썸네일마다 수 MB를 내려받는다                                    |
| **브라우저가 두 장으로 축소해 업로드** | 서버는 저장만 한다. 한도 안에 든다 | 캔버스를 거치며 EXIF·색 프로필이 제거된다(배경화면에는 오히려 적합하다)    |

## 선택한 배경화면 저장

설정은 현재도 브라우저(localStorage)에 저장한다. 기본 배경화면은 id(`sonoma`)만 저장하면 되지만, 추가한 배경화면은 id(`custom:…`)와 함께 이미지 주소도 저장한다. 그래야 다음 접속 시 서버에 목록을 요청하기 전에 즉시 렌더링할 수 있다.

이 주소는 CSS `url('…')`에 삽입된다. 저장된 값이 변조되어도 CSS 구문을 깨뜨리지 못하도록, 따옴표·괄호·공백이 없는 `http(s)` 주소만 허용한다.

관리자가 배경화면을 삭제하면, 그 배경화면을 선택한 방문자는 다음 접속 시 목록을 조회한 뒤 기본 배경화면으로 돌아간다. 앱 시작 시각의 목록 요청은 추가한 배경화면을 선택한 방문자만 보낸다. 설정의 배경화면 화면을 열면 모든 방문자가 목록을 요청한다.

![휴대폰 전후](./images/custom-wallpapers-mobile.jpg '휴대폰에는 추가한 배경화면과 iOS 배경화면. 지우기(×)가 늘 보인다')

## 삭제와 이름 변경

macOS 설정처럼 추가한 배경화면의 왼쪽 위 모서리에 × 버튼을 걸쳐 배치했다. 어두운 원의 테두리를 배경(창은 흰색, 휴대폰은 회색)과 같은 색으로 칠해서, 썸네일 모서리를 원형으로 파낸 것처럼 보인다. 데스크톱에서는 마우스를 올렸을 때만 표시되고, 휴대폰은 마우스가 없으므로 항상 표시된다. 표시되는 원은 22px이지만 터치 영역은 손가락 크기(44px)로 넓혔다.

```css
.wallpaper-remove::before {
	position: absolute;
	inset: -11px;
	content: '';
}
```

이름은 처음에 파일 이름을 사용한다. 휴대폰 사진은 `IMG_4021` 같은 이름이라, 오른쪽 클릭 메뉴에 '이름 바꾸기…'를 추가했다(API는 `PATCH /wallpapers/:id`). 휴대폰에는 오른쪽 클릭이 없어서 길게 누르면(0.5초) 같은 메뉴가 표시된다. 메뉴를 연 터치를 뗄 때는 선택으로 처리하지 않는다.

이름은 40자까지 허용하지만 썸네일 아래에서는 썸네일 폭에 맞춰 말줄임(…)으로 한 줄 표시하고, 마우스를 올리면 전체 이름이 표시된다. 썸네일은 API 서버에서 내려받으므로, 로딩 중에 빈 테두리만 보이지 않도록 영역을 회색으로 채운다.

삭제 전에는 "모든 방문자의 목록에서 사라집니다"라는 확인 대화상자를 표시한다. 기본 배경화면은 코드에 정의된 목록이라 삭제할 수 없다.

서버에 연결하지 못하면 추가한 배경화면 없이 기본 배경화면(데스크톱 6장, 휴대폰 6장)만 표시된다.

## 구현 순서

PR 안의 커밋 다섯 개가 구현 순서와 같다.

1. 관리자의 배경화면 추가·삭제 (서버 테이블·API, 화면의 업로드)
2. 이름 변경, macOS처럼 '사진 추가' 칸과 왼쪽 위 삭제 버튼
3. 화면 종류별 기본 배경화면 분리, 데스크톱은 가로 한 줄과 모두 보기, 추가한 배경화면은 양쪽에 표시
4. 추가한 배경화면과 기본 배경화면을 그룹으로 분리
5. 썸네일 테두리 제거, 휴대폰은 3열 격자로 확대

기능(1)을 먼저 완성하고, 나머지는 실제로 업로드해 보며 macOS 설정과 비교해 수정했다. PR 전체는 파일 25개, +1,756/−82줄이다.

## 실제 업로드로 검토한 과정

10월 2일 오후, 시스템 설정에서 배경화면을 추가할 수 있게 하기로 정했다. 기본 배경화면은 삭제할 수 없게 했다. 중간에 이 기능을 제외하는 방안도 검토했다. 하지만 저장소가 공개되어 있어 이 사이트를 가져다 쓰는 사람도 자신의 배경화면을 추가하려 할 것이라, 관리자 추가 기능으로 유지했다.

## 남은 과제와 정리

- 추가한 배경화면에는 라이트·다크 두 벌이 없다. 기본 배경화면은 다크 모드에서 어두운 버전으로 바뀌지만, 업로드한 사진은 한 장 그대로다.
- 데스크톱과 휴대폰에 같은 사진을 사용하면 비율 차이만큼 잘린다. 잘리는 위치를 선택하는 기능(초점 지정)은 아직 없다.
- 이후 [움직이는 배경화면 - MP4와 GIF를 바탕화면에 깔기](/memo/video-wallpaper)에서 MP4와 GIF를 추가했다. 위 코드의 `shrink`는 GIF이면 원본을 그대로 두고 썸네일만 생성한다.

"누가 보는가"를 먼저 정하자 저장 위치(브라우저 또는 서버)와 권한이 함께 결정됐다. 또 소형 서버에서는 이미지 처리를 브라우저에 맡기는 것이 비용이 가장 낮은 선택이었다. 브라우저에는 이미 이미지 디코더와 캔버스가 있다.
