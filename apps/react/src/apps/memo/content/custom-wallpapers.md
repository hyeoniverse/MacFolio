시스템 설정 → 배경화면에는 macOS 배경화면 6장과 iOS 배경화면 6장이 있다. 모두 `public/imgs/wallpapers`에 파일로 들어 있어서, 하나를 더하려면 이미지를 줄이고 썸네일을 만들어 커밋하고 배포해야 했다.

이제 배경화면 화면 위쪽에 '추가한 배경화면' 묶음이 따로 있다. macOS 설정에서 '사용자의 사진'이 기본 배경화면과 나뉘어 있는 것과 같다. 관리자로 로그인하면 그 묶음 맨 앞에 '사진 추가…' 칸이 생긴다. 회색으로 채운 칸 안에 사진 아이콘(+)과 글자가 있다. 사진을 고르면 그 자리에서 올라가고, 바로 그 배경화면으로 바뀐다. 올린 배경화면은 그 칸 뒤로 이어 붙고, 모든 방문자에게 보인다. 올린 것이 없으면 방문자에게는 이 묶음이 보이지 않는다.

![데스크톱 전후](./images/custom-wallpapers-desktop.jpg '추가한 배경화면과 기본 배경화면을 따로, 묶음마다 간략히 보기(가로 한 줄)와 모두 보기')

## 누구에게 보일까

처음에 두 가지를 견줬다.

| 방식                         | 보이는 사람 | 저장하는 곳             |
| ---------------------------- | ----------- | ----------------------- |
| 방문자가 자기 사진을 더한다  | 그 사람만   | 그 브라우저 (IndexedDB) |
| **관리자가 올리면 모두에게** | 모든 방문자 | 서버                    |

포트폴리오의 배경화면은 사이트 주인이 고르는 것이라 두 번째로 정했다. 방문자는 지금처럼 고르기만 한다.

## 화면마다 자기 배경화면만

처음에는 설정에 macOS 묶음과 iOS 묶음을 둘 다 보여 줬다. 그런데 데스크톱 방문자에게 휴대폰 배경화면은 고를 이유가 없다. 이제 데스크톱에는 macOS 배경화면만, 휴대폰에는 iOS 배경화면만 보인다.

그러면 관리자가 데스크톱에서는 휴대폰 배경화면을 올릴 수 없다. 둘을 한 장으로 합치는 방법도 생각했지만, 가로(16:10)와 세로(9:19.5)는 비율이 너무 달라서 기본 배경화면을 한쪽에 쓰면 크게 잘린다. 그래서 기본 배경화면은 화면마다 따로 두고, **더한 배경화면은 구분 없이 양쪽에 다 보이게** 했다. 데스크톱에서 한 번 올리면 휴대폰에서도 고른다. 비율이 다르면 가운데 기준으로 잘리는데, 직접 고른 사진이라 괜찮다고 봤다. 고른 배경화면은 데스크톱용과 휴대폰용을 따로 기억한다.

썸네일은 macOS 설정처럼 테두리 없이 사진만 둥글게 보이고, 고른 것에는 조금 떨어진 파란 고리를 두른다(`outline-offset`). 휴대폰은 썸네일을 화면 폭에 맞춰 세 칸으로 크게 늘어놓는다. 데스크톱에서는 묶음마다(추가한 배경화면, macOS) 한 줄로 두고 가로로 넘긴다(간략히 보기). 제목 오른쪽의 '모두 보기(n)'를 누르면 그 묶음만 그 자리에서 여러 줄로 펼치고, '간략히 보기'로 다시 접는다. 한 줄일 때는 열자마자 고른 배경화면이 보이는 자리로 넘겨 둔다. 칸 단위로 멈추게(`scroll-snap`) 했더니 처음에 첫 칸이 8px 잘려 있었다. 왼쪽 위로 걸친 ×가 잘리지 않게 한 줄에 안쪽 여백을 뒀는데, 칸을 맞추는 기준은 그 여백을 모르고 스크롤 칸의 가장자리에 첫 칸을 붙였기 때문이다. `scroll-padding-inline`으로 맞추는 기준도 같은 만큼 들였다. 휴대폰은 처음부터 격자로 둔다.

## 서버: 기존 파일 저장소에 얹기

메모 글에 넣는 이미지를 올리는 API(`POST /files`)가 이미 있다. 파일은 DB의 `Upload` 테이블에 두고 `/files/:id`로 내려준다. 배경화면은 이 위에 표 하나(`Wallpaper`)만 더했다. 이름과 원본·썸네일의 `Upload` id다.

- `GET /wallpapers`: 누구나 목록을 받는다
- `POST /wallpapers`: 관리자만. 원본·썸네일 이미지와 이름
- `DELETE /wallpapers/:id`: 관리자만. 이미지 두 장도 한 트랜잭션에서 함께 지운다

이미지는 형식 이름을 믿지 않고 파일 앞부분으로 PNG·JPEG·GIF·WebP인지 본다. 파일 API와 같은 규칙이다. 이름 길이는 DB의 CHECK 제약으로도 막는다.

## 브라우저에서 줄여 보내기

휴대폰으로 찍은 사진은 10MB를 넘기 쉽고, 업로드 한도도 10MB다. 서버에서 줄이려면 이미지 처리 라이브러리가 필요한데, 작은 서버(E2.1.Micro)에서 돌리기는 부담이다. 그래서 브라우저가 캔버스로 줄인 뒤 JPEG 두 장을 보낸다.

```ts
const bitmap = await createImageBitmap(file);
const scale = Math.min(1, max / Math.max(bitmap.width, bitmap.height));
canvas.width = Math.round(bitmap.width * scale);
canvas.height = Math.round(bitmap.height * scale);
context.drawImage(bitmap, 0, 0, canvas.width, canvas.height);
canvas.toBlob(resolve, 'image/jpeg', quality);
```

원본은 긴 변 2560px(기본 배경화면과 같다), 썸네일은 640px이다. 썸네일이 따로 있어서 설정 화면이 원본 수 MB를 받지 않는다.

## 고른 배경화면 기억하기

설정은 지금도 브라우저(localStorage)에 저장한다. 기본 배경화면은 id(`sonoma`)만 두면 되지만, 더한 배경화면은 id(`custom:…`)와 함께 이미지 주소도 둔다. 그래야 다음에 열 때 서버에 목록을 묻기 전에 바로 그린다.

이 주소는 CSS `url('…')`에 들어간다. 저장된 값을 누가 고쳐도 CSS를 깨지 못하게, 따옴표·괄호·공백이 없는 `http(s)` 주소만 읽는다.

관리자가 배경화면을 지우면, 그것을 골라 둔 방문자는 다음에 열 때 목록을 받아 보고 기본 배경화면으로 돌아간다. 목록은 더한 배경화면을 골라 둔 사람만 앱을 열 때 받는다. 설정의 배경화면 화면을 열면 누구나 받는다.

![휴대폰 전후](./images/custom-wallpapers-mobile.jpg '휴대폰에는 추가한 배경화면과 iOS 배경화면. 지우기(×)가 늘 보인다')

## 지우기와 이름 바꾸기

macOS 설정처럼 더한 배경화면의 왼쪽 위 모서리에 × 단추를 걸쳤다. 어두운 동그라미의 테두리를 바탕(창은 흰색, 휴대폰은 회색)과 같은 색으로 칠해서, 썸네일 모서리를 동그랗게 파낸 것처럼 보인다. 데스크톱에서는 마우스를 올렸을 때만 보이고, 휴대폰은 올릴 마우스가 없어서 늘 보인다. 보이는 동그라미는 22px이지만 누르는 자리는 손가락 크기(44px)로 넓혔다.

```css
.wallpaper-remove::before {
	position: absolute;
	inset: -11px;
	content: '';
}
```

이름은 처음에 파일 이름을 쓴다. 휴대폰 사진은 `IMG_4021` 같은 이름이라, 오른쪽 클릭 메뉴에 '이름 바꾸기…'를 두었다(API는 `PATCH /wallpapers/:id`). 휴대폰은 오른쪽 클릭이 없어서 길게 누르면(0.5초) 같은 메뉴가 뜬다. 메뉴를 연 손가락을 떼는 것은 고르기로 치지 않는다.

이름은 40자까지 받지만 썸네일 아래에서는 썸네일 폭에서 잘라(…) 한 줄로 두고, 마우스를 올리면 다 보인다. 썸네일은 API 서버에서 받으므로, 받는 동안 빈 테두리만 보이지 않게 자리를 회색으로 칠해 둔다.

지우기 전에는 "모든 방문자의 목록에서 사라집니다"라고 묻는다. 기본 배경화면은 코드에 있는 목록이라 지울 수 없다.

서버에 닿지 못하면 더한 배경화면 없이 기본 배경화면(데스크톱 6장, 휴대폰 6장)만 보인다.
