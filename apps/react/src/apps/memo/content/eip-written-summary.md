이 글은 필기 다섯 과목 글에서 시험에 자주 나오는 내용만 뽑아 표와 목록으로 압축한 요약본이다. 시험 직전에 위에서부터 훑어보고, 기억나지 않는 항목은 과목 절 끝의 링크로 상세 글을 열어 확인하면 된다. 과목당 20문항이고, ==모든 과목 40점 이상, 다섯 과목 평균 60점 이상==이어야 합격한다.

## 1과목 소프트웨어 설계

### 외울 순서

| 대상                | 순서                                                                              |
| ------------------- | --------------------------------------------------------------------------------- |
| 생명주기 단계       | 요구 분석 → 설계 → 구현 → 시험 → 유지보수                                         |
| 나선형 모형 (Boehm) | 계획 수립 → 위험 분석 → 개발 및 검증 → 고객 평가, 여러 바퀴 반복                  |
| 요구사항 개발       | 도출 → 분석 → 명세 → 확인                                                         |
| 럼바우 OMT          | 객체 모델링(객체 다이어그램) → 동적 모델링(상태) → 기능 모델링(DFD)               |
| 결합도 (약 → 강)    | 자료 → 스탬프 → 제어 → 외부 → 공통 → 내용 (==자스제외공내==)                      |
| 응집도 (강 → 약)    | 기능적 → 순차적 → 교환적 → 절차적 → 시간적 → 논리적 → 우연적 (==기순교절시논우==) |

### 생명주기 모형과 애자일

- **모형 키워드**: 폭포수는 고전적·선형 순차(되돌아가지 않음), 프로토타입은 견본, 나선형은 Boehm·위험 분석, 애자일은 짧은 주기·변화 대응
- **애자일 선언**: 개인과 상호작용, 작동하는 소프트웨어, 고객과의 협력, 변화에 대응하기를 더 중시한다
- **XP 5가치**: 의사소통, 단순성, 피드백, 용기, 존중. 대표 실천 사항은 짝 프로그래밍, TDD, 리팩토링, 지속적인 통합
- **스크럼**: 역할은 제품 책임자(PO, 백로그 우선순위), 스크럼 마스터(장애 요소 제거), 개발자. 스프린트는 1개월 이하, 일일 스크럼은 15분, 진척은 번다운 차트

### 분석 도구와 UML

- **DFD 4요소**: 프로세스(원), 자료 흐름(화살표), 자료 저장소(평행선), 단말(사각형)
- **자료 사전 기호**: `=` 정의, `+` 연결, `[ | ]` 선택, `{ }` 반복, `( )` 생략 가능, `** **` 주석
- **UML 구조 다이어그램 6**: 클래스, 객체, 컴포넌트, 배치, 복합체 구조, 패키지
- **UML 행위 다이어그램 7**: 유스케이스, 시퀀스, 커뮤니케이션, 상태, 활동, 상호작용 개요, 타이밍
- **가시성**: `+` public, `-` private, `#` protected, `~` package

### 인터페이스

- **MOM**: 메시지 큐로 비동기 전달. **TP-Monitor**: 항공 예약·은행처럼 빠른 응답이 필요한 온라인 트랜잭션 관리. **ORB**: 분산 객체 요청 중개(CORBA). **RPC**: 원격 프로시저를 로컬 함수처럼 호출. **WAS**: 동적 웹 콘텐츠 처리

## 2과목 소프트웨어 개발

### 자료구조와 손으로 푸는 계산

- **스택**은 후입선출(LIFO). 함수 호출과 복귀, 인터럽트 처리, 후위식 계산, DFS, Undo에 쓴다. **큐**는 선입선출(FIFO). 작업 스케줄링, BFS에 쓴다. 데크는 양쪽 끝에서 삽입·삭제
- **그래프 최대 간선 수**: 무방향 `n(n-1)/2{:math}`, 방향 `n(n-1){:math}`. 예: 정점 5개면 10개와 20개
- **트리 순회**: 전위는 루트를 맨 앞, 중위는 가운데, 후위는 맨 뒤에 방문한다. 전위의 첫 글자와 후위의 마지막 글자는 항상 근 노드다
- **수식 변환**: 연산 순서대로 괄호를 치고 연산자를 닫는 괄호(후위) 또는 여는 괄호(전위) 자리로 옮긴 뒤 괄호를 지운다. `(A+B)*C-D/E`의 후위식은 `AB+C*DE/-`, 전위식은 `-*+ABC/DE`
- **순환 복잡도**: 간선 11개, 노드 9개, 분기 노드 3개인 제어 흐름 그래프라면 다음과 같다.

```math
V(G) = E - N + 2 = 11 - 9 + 2 = 4,\qquad V(G) = D + 1 = 3 + 1 = 4
```

| 정렬           | 평균        | 최악       | 한 줄 요약                         |
| -------------- | ----------- | ---------- | ---------------------------------- |
| 선택·버블·삽입 | O(n²)       | O(n²)      | 삽입 정렬만 최선 O(n)              |
| 셸             | 약 O(n^1.5) | O(n²)      | 간격을 두고 삽입 정렬, 간격을 줄임 |
| 퀵             | O(n log n)  | ==O(n²)==  | 피벗 기준 분할 후 재귀             |
| 힙·합병        | O(n log n)  | O(n log n) | 최악도 n log n                     |
| 기수           | O(dn)       | O(dn)      | 비교하지 않고 자릿수별 분배        |

이진 검색은 O(log₂n), 해싱은 O(1)이다.

## 3과목 데이터베이스 구축

### 설계 순서와 스키마

| 대상          | 순서와 내용                                                                                                                                         |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 설계 5단계    | 요구 조건 분석 → 개념적 설계(E-R 다이어그램, DBMS 무관) → 논리적 설계(==정규화==, 릴레이션 스키마) → 물리적 설계(==인덱스==, 접근 경로) → 구현(DDL) |
| 스키마 3단계  | 외부(사용자 관점, 여러 개) → 개념(조직 전체, 하나) → 내부(물리적 저장 구조)                                                                         |
| 데이터 독립성 | 내부를 바꿔도 개념이 그대로면 물리적 독립성, 개념을 바꿔도 외부가 그대로면 논리적 독립성                                                            |

### 관계 데이터 모델

- **차수**(degree)는 속성(열)의 수, **카디널리티**(cardinality)는 튜플(행)의 수
- **키**: 슈퍼키(유일성만), 후보키(유일성 + 최소성), 기본키(후보키 중 대표, NULL·중복 불가), 대체키(나머지 후보키), 외래키(다른 릴레이션의 기본키 참조)
- **무결성**: 개체(기본키는 NULL·중복 불가), 참조(외래키는 참조 대상의 기본키 값이거나 NULL), 도메인(정의된 값 범위)

| 관계대수 연산자 | 기호    | 뜻                                  |
| --------------- | ------- | ----------------------------------- |
| 실렉트          | σ       | 조건에 맞는 행(수평)                |
| 프로젝트        | π       | 지정한 열(수직), 중복 제거          |
| 조인            | ⋈       | 공통 속성으로 연결                  |
| 디비전          | ÷       | 오른쪽 값을 ==모두== 가진 왼쪽 튜플 |
| 합·교·차·교차곱 | ∪ ∩ − × | 일반 집합 연산                      |

관계대수는 절차적, 관계해석은 비절차적이다.

### 정규화

![비정규 릴레이션에서 5NF까지 내려가며 단계마다 제거하는 종속이 적혀 있다](./images/eip-written-summary-normalization.svg '화살표마다 제거하는 것의 첫 글자를 이으면 도부이결다조')

- **이상 현상**: 삽입 이상(기본키 일부가 없으면 행을 넣을 수 없음), 삭제 이상(다른 정보까지 함께 사라짐), 갱신 이상(일부만 고쳐 값이 모순됨)
- **함수 종속**: `{회원번호, 도서번호} → 대여일`은 완전, `회원번호 → 이름`은 부분, `회원번호 → 등급 → 대여한도`는 이행적
- **반정규화**: 성능을 위해 테이블 통합, 수평·수직 분할, 중복 테이블·중복 속성 추가

| 헷갈리는 짝       | 구분                                          |
| ----------------- | --------------------------------------------- |
| 2NF / 3NF         | 부분 함수 종속 제거 / 이행적 함수 종속 제거   |
| 3NF / BCNF        | 키가 아닌 속성만 검사 / 모든 결정자가 후보키  |
| 정규화 / 반정규화 | 이상 제거를 위한 분해 / 성능을 위한 통합·중복 |

### SQL과 물리 설계

- **DDL**: `CREATE`, `ALTER`, `DROP`, `TRUNCATE`. **DML**: `SELECT`, `INSERT`, `UPDATE`, `DELETE`. **DCL**: `GRANT`, `REVOKE`, `COMMIT`, `ROLLBACK`
- **인덱스**: 클러스터드는 행 자체를 키 순서로 정렬해 테이블당 하나, 넌클러스터드는 여러 개
- **분산 DB 투명성**: 위치, 중복, 병행, 장애

### 트랜잭션

| ACID          | 뜻                             | 보장하는 구성 요소      |
| ------------- | ------------------------------ | ----------------------- |
| 원자성        | 전부 반영 또는 전혀 반영 안 함 | 회복 관리자(로그, UNDO) |
| 일관성        | 실행 전후 무결성 유지          | 무결성 제약 검사        |
| 독립성·격리성 | 중간 결과를 남이 볼 수 없음    | 병행 제어(로킹)         |
| 영속성·지속성 | 완료 결과는 장애에도 유지      | 회복 관리자(로그, REDO) |

- **상태**: 활동 → 부분 완료 → 완료. 활동 중 오류나 부분 완료에서 반영 중 장애가 나면 실패 → 철회. ==부분 완료==는 마지막 연산까지 실행했지만 COMMIT 직전인 상태
- **병행 제어 없을 때의 문제**: 갱신 분실, 비완료 의존성(오손 읽기), 모순성, 연쇄 복귀
- **병행 제어 기법**: 로킹, 2단계 로킹(확장 단계와 축소 단계, 직렬 가능성 보장, 교착 상태 가능), 타임스탬프 순서(교착 상태 없음), 낙관적 검증, 다중 버전(MVCC)
- **로킹 단위**가 크면 lock 수가 적고 병행성이 낮으며 관리가 쉽다. 작으면 반대
- **회복**: REDO는 COMMIT 기록이 있는 트랜잭션을 다시 반영, UNDO는 COMMIT 기록이 없는 트랜잭션을 되돌린다. 즉시 갱신은 REDO·UNDO 모두, 지연 갱신은 REDO만 필요하다. 검사점은 조사 범위를 줄이고, 그림자 페이징은 로그 없이 페이지 테이블 두 개를 쓴다

| 격리 수준        | 오손 읽기 | 반복 불가능 읽기 | 팬텀 읽기 |
| ---------------- | --------- | ---------------- | --------- |
| READ UNCOMMITTED | 발생      | 발생             | 발생      |
| READ COMMITTED   | 방지      | 발생             | 발생      |
| REPEATABLE READ  | 방지      | 방지             | 발생      |
| SERIALIZABLE     | 방지      | 방지             | 방지      |

## 4과목 프로그래밍 언어 활용

### C·Java·Python에서 자주 틀리는 것

- **연산자 우선순위**: 단항 → 산술(`* / %` → `+ -`) → 시프트 → 관계 → 비트(`&` → `^` → `|`) → 논리(`&&` → `||`) → 조건 → 대입 → 순서. 단항·조건·대입은 오른쪽에서 왼쪽으로 결합한다
- **전위·후위 증감**: `++a`는 증가 후 사용, `a++`는 사용 후 증가. `a = 10`일 때 `c = a++ * 2`는 20이고 a는 11이 된다
- **포인터**: `*p + 1`은 가리키는 값에 1을 더하고, `*(p + 1)`은 다음 원소의 값이다. `p[3]`은 `*(p + 3)`
- **나눗셈**: C·Java는 정수끼리면 몫만 남아 `7 / 2`가 3이다. Python의 `/`는 항상 실수 나눗셈(3.5)이고, `//`는 음의 무한대 방향으로 내려 `-7 // 2`가 −4다
- **Java 상속**: `Animal a = new Dog()`에서 오버라이딩한 메서드는 실제 객체(Dog)의 것을, 필드와 static 메서드는 선언 타입(Animal)의 것을 쓴다
- **오버로딩 / 오버라이딩**: 같은 클래스에서 매개변수만 다르게 / 상속받은 메서드를 같은 시그니처로 다시 정의

### CPU 스케줄링

| 구분   | 기법                                                                                       |
| ------ | ------------------------------------------------------------------------------------------ |
| 비선점 | FCFS(도착 순), SJF(실행 시간 짧은 순), HRN(응답률 높은 순)                                 |
| 선점   | SRT(남은 시간 짧은 순, SJF의 선점형), RR(할당량만큼 돌아가며), 다단계 큐, 다단계 피드백 큐 |
| 둘 다  | 우선순위. 기아 현상은 에이징으로 막는다                                                    |

```math
\text{반환 시간} = \text{완료} - \text{도착},\quad \text{대기 시간} = \text{반환 시간} - \text{실행 시간},\quad \text{HRN 응답률} = \frac{\text{대기 시간} + \text{실행 시간}}{\text{실행 시간}}
```

예: P1(도착 0, 실행 6), P2(1, 3), P3(2, 8), P4(3, 2)를 처리하면 다음과 같다. SJF는 시각 6에 가장 짧은 P4, 다음 P2, 마지막 P3를 실행하므로 대기 시간은 0, 7, 9, 3이고 평균은 `(0 + 7 + 9 + 3) / 4 = 4.75{:math}`다.

| 기법     | 실행 순서              | 평균 대기 시간 |
| -------- | ---------------------- | -------------- |
| FCFS     | P1 → P2 → P3 → P4      | 6.5            |
| SJF      | P1 → P4 → P2 → P3      | 4.75           |
| HRN      | P1 → P2 → P4 → P3      | 5.0            |
| SRT      | P1 → P2 → P4 → P1 → P3 | ==3.75==       |
| RR (q=2) | 할당량 2씩 돌아가며    | 7.5            |

### 프로세스, 교착 상태, 기억장치

- **상태 전이**: 준비 → 실행(디스패치), 실행 → 준비(타이머 런아웃), 실행 → 대기(블록), 대기 → 준비(웨이크업). 대기에서 실행으로 바로 가지 않는다
- **교착 상태 필요 조건 4**: 상호 배제, 점유와 대기, 비선점, 환형 대기
- **교착 상태 해결 4**: 예방(조건 하나를 부정), 회피(==은행원 알고리즘==), 발견(자원 할당 그래프의 순환 검사), 회복(종료하거나 자원을 빼앗음)
- **배치 전략**: 최초 적합(처음 만나는 충분한 공간), 최적 적합(남는 공간이 가장 작은 곳), 최악 적합(가장 큰 곳)
- **스래싱**: 프로세스 실행 시간보다 페이지 교체 시간이 더 많아지는 현상. 워킹 셋을 주기억장치에 상주시키면 부재가 줄어든다
- **단편화**: 내부는 할당한 영역 안에 남는 공간, 외부는 영역 사이에 남는 작은 빈 공간. 페이징은 같은 크기, 세그먼테이션은 논리적 단위로 다른 크기로 나눈다

## 5과목 정보시스템 구축 관리

### 개발 방법론과 비용 산정

방법론은 구조적(기능, DFD), 정보공학(데이터, ERD), 객체지향, CBD(컴포넌트 조립), 애자일(스크럼은 관리 방식, XP는 개발 기술 실천)로 구분한다.

비용 산정은 하향식(전문가 감정, 델파이)과 상향식(LOC, 개발 단계별 인월수, 수학적 산정)으로 나뉜다. 수학적 산정 기법에는 COCOMO, Putnam, FP가 있다.

**LOC 기법**: 낙관치 a, 기대치 m, 비관치 b를 1:4:1로 가중 평균한다. 예: a = 30,000, m = 36,000, b = 42,000줄, 1인 월 생산성 300줄, 인건비 600만 원, 10명이면 다음과 같다.

```math
\text{LOC} = \frac{a + 4m + b}{6} = 36{,}000,\quad \text{노력} = \frac{36{,}000}{300} = 120\ \text{MM},\quad \text{비용} = 120 \times 600\text{만} = 7.2\text{억},\quad \text{기간} = \frac{120}{10} = 12\ \text{개월}
```

**COCOMO** (Boehm): 규모 KDSI(인도된 코드 1,000줄 단위)로 노력 `E = a \times \text{KDSI}^{b}{:math}`, 기간 `D = 2.5 \times E^{d}{:math}`를 구한다. 예: 조직형 30KDSI면 `E = 2.4 \times 30^{1.05} \approx 85.3{:math}`MM, `D \approx 13.5{:math}`개월, 평균 인원 `E / D \approx 6.3{:math}`명.

| COCOMO 유형 | 규모 기준             | a, b      | d    | 예                       |
| ----------- | --------------------- | --------- | ---- | ------------------------ |
| 조직형      | 5만 줄(50KDSI) 이하   | 2.4, 1.05 | 0.38 | 사무 처리, 업무용        |
| 반분리형    | 30만 줄(300KDSI) 이하 | 3.0, 1.12 | 0.35 | 운영체제, DBMS, 컴파일러 |
| 내장형      | 30만 줄 초과          | 3.6, 1.20 | 0.32 | 신호기 제어, 미사일 유도 |

COCOMO는 기본형 → 중간형(15가지 비용 승수) → 발전형(단계별 승수) 순으로 정밀해진다.

- **Putnam**: Rayleigh-Norden 곡선으로 생명 주기 전체의 노력 분포를 예측한다. 자동화 도구는 SLIM
- **FP**: 기능 유형 EI(외부 입력), EO(외부 출력, 가공 있음), EQ(외부 조회, 가공 없음), ILF(내부 논리 파일), EIF(외부 연계 파일, 참조만)에 가중치를 곱해 합한다. `\text{VAF} = 0.65 + 0.01 \times \text{TDI}{:math}`, `\text{AFP} = \text{UFP} \times \text{VAF}{:math}`. 자동화 도구는 ESTIMACS

### 일정 관리와 프로세스 표준

**PERT 기대 시간**: 낙관치 o, 기대치 m, 비관치 p로 계산한다. o = 4, m = 6, p = 14일이면 다음과 같다.

```math
t_e = \frac{o + 4m + p}{6} = \frac{4 + 24 + 14}{6} = 7\ \text{일},\qquad \sigma = \frac{p - o}{6} \approx 1.67
```

**CPM 임계 경로**: 시작에서 끝까지 가능한 경로의 기간을 모두 더해 가장 긴 경로를 고른다. 여유(LS − ES)가 0인 작업이 임계 경로다. 경로가 A-C-E-F(16일), A-D-F(13일), B-D-F(12일)이면 답은 A-C-E-F, 16일이다.

| 단계 | CMMI        | SPICE    |
| ---- | ----------- | -------- |
| 0    | 없음        | 불완전   |
| 1    | 초기        | 수행     |
| 2    | 관리        | 관리     |
| 3    | ==정의==    | ==확립== |
| 4    | 정량적 관리 | ==예측== |
| 5    | 최적화      | 최적화   |

ISO/IEC 12207은 생명 주기 프로세스를 기본·지원·조직으로 나누고, ISO/IEC 15504(SPICE)는 프로세스 능력을 평가한다.
