메뉴 막대, 창, Dock까지 macOS를 흉내 냈는데 바탕화면에는 배경화면만 있었다. 진짜 Mac을 켜면 오른쪽 위에 폴더 몇 개가 늘 보인다. Finder에 이미 문서 폴더(이력서, 포트폴리오, 자격증)와 프로젝트 폴더가 있으니, 그 넷을 바탕화면에 꺼내 두었다.

> 나중에 프로젝트 위치는 문서 › 포트폴리오 안으로 합쳤다. 그래서 지금 바탕화면의 기본 폴더는 이력서·포트폴리오·자격증 셋이고, 모두 원래 폴더를 여는 가상본(작은 화살표)이다.

## 자리는 픽셀이 아니라 칸

macOS의 바탕화면 아이콘은 오른쪽 위에서 시작해 아래로 한 열을 채우고, 다 차면 왼쪽 열로 넘어간다. 그래서 자리를 픽셀로 두지 않고 "오른쪽에서 몇째 열, 위에서 몇째 줄"인 칸으로 두었다.

```ts
export function cellToPoint({ col, row }: Cell, viewport: Viewport): Point {
	return { x: viewport.width - MARGIN.right - (col + 1) * CELL.width, y: MARGIN.top + row * CELL.height };
}
```

칸은 오른쪽 끝을 기준으로 하므로 창 크기가 바뀌어도 아이콘이 오른쪽에 붙어 있다. 끌어 옮긴 자리도 칸으로 `localStorage`에 남긴다. 저장한 칸이 화면 밖이거나 다른 아이콘과 겹치면 버리고 차례대로 빈 칸에 둔다.

## 끌어 놓기는 가까운 빈 칸으로

아이콘을 놓으면 놓인 자리에서 가장 가까운 칸으로 맞춘다. 그 칸에 다른 아이콘이 있으면 가장 가까운 빈 칸으로 간다. 여럿을 함께 끌어도 서로 겹치지 않는다. 이 계산은 DOM 없이 순수 함수(`layout.ts`)로 두고 단위 테스트로 확인했다.

## 고르기

- 누르면 하나만 고르고, ⌘는 넣고 빼고, ⇧는 더한다
- 빈 곳에서 끌면 옅은 사각형이 생기고, 거기 걸린 아이콘을 고른다
- ⌘A는 모두, Esc는 해제, ⌘O·⌘↓는 연다
- 여럿을 고른 채 하나를 그냥 누르면 바로 풀지 않는다. 떼었을 때 끌지 않았으면 그때 그것만 남긴다. 그래야 고른 것을 한꺼번에 끌 수 있다 (macOS도 같다)

## 두 번 누르기와 포인터 붙잡기

처음에는 누르자마자 `setPointerCapture`로 포인터를 붙잡았다. 그러자 두 번 눌러도 폴더가 열리지 않았다. 포인터를 붙잡으면 `click`·`dblclick`도 붙잡은 요소(아이콘 층)로 가서, 아이콘의 `onDoubleClick`에 닿지 않는다. 그래서 빈 곳에서 사각형을 그릴 때는 바로 붙잡고, 아이콘은 4px 넘게 움직여 끌기가 시작될 때 붙잡는다.

## 포털로 띄운 메뉴

오른쪽 클릭 메뉴는 기존 `Menu`를 썼다. 메뉴는 `body`에 그려지지만(포털) React 이벤트는 React 트리를 따라 아이콘 층까지 올라온다. 메뉴 항목을 누르는 순간 층이 "빈 곳을 눌렀다"고 보고 사각형 고르기를 시작해 포인터를 붙잡았고, 항목의 클릭이 사라졌다. 층의 핸들러는 이벤트가 정말 층 DOM 안에서 났을 때만 받게 했다.

빈 곳의 메뉴에는 정리하기, 이름순으로 정리, 배경화면 변경…이 있고, 배경화면 변경…은 시스템 설정의 배경화면 항목을 연다. 아이콘의 메뉴는 열기와 Finder에서 보기다.

## 층

아이콘 층은 배경화면 바로 위, 창·Dock·메뉴 막대 아래에 둔다. 창이 덮으면 가려지고, 아이콘을 누르면 메뉴 막대의 앱 이름이 Finder가 된다. 휴대폰 화면에는 넣지 않았다.
