메뉴 막대, 창, Dock까지 macOS를 흉내 냈는데 바탕화면에는 배경화면만 있었다. 진짜 Mac을 켜면 오른쪽 위에 폴더 몇 개가 늘 보인다. Finder에 이미 문서 폴더(이력서, 포트폴리오, 자격증)와 프로젝트 폴더가 있으니, 그 넷을 바탕화면에 꺼내 두었다.

![바탕화면 오른쪽 위의 폴더 아이콘과 사각형 고르기](./images/desktop-icons-select.jpg '빈 곳에서 끌면 옅은 사각형이 생기고, 걸린 아이콘이 골라진다')

> 나중에 프로젝트 위치는 문서 › 포트폴리오 안으로 합쳤다. 그래서 지금 바탕화면의 기본 폴더는 이력서·포트폴리오·자격증 셋이고, 모두 원래 폴더를 여는 가상본(작은 화살표)이다.

## 자리는 픽셀이 아니라 칸

자리를 어떻게 둘지 먼저 정해야 했다.

| 방법                                 | 좋은 점                                                     | 나쁜 점                                                               |
| ------------------------------------ | ----------------------------------------------------------- | --------------------------------------------------------------------- |
| 픽셀 좌표 (`x`, `y`)                 | 놓은 자리 그대로                                            | 창 폭이 바뀌면 오른쪽 아이콘이 화면 밖으로 나간다. 겹침을 막기 어렵다 |
| CSS 그리드에 순서대로                | 계산이 없다                                                 | 사용자가 놓은 자리를 기억할 수 없다. 빈 칸을 둘 수 없다               |
| **오른쪽 위 기준 칸 (`col`, `row`)** | 창 폭이 바뀌어도 오른쪽에 붙는다. 겹침은 "같은 칸"으로 판단 | 칸과 픽셀을 오가는 계산이 필요하다                                    |

macOS의 바탕화면 아이콘은 오른쪽 위에서 시작해 아래로 한 열을 채우고, 다 차면 왼쪽 열로 넘어간다. 그래서 자리를 픽셀로 두지 않고 "오른쪽에서 몇째 열, 위에서 몇째 줄"인 칸으로 두었다.

```ts
export function cellToPoint({ col, row }: Cell, viewport: Viewport): Point {
	return { x: viewport.width - MARGIN.right - (col + 1) * CELL.width, y: MARGIN.top + row * CELL.height };
}
```

칸 하나는 가로 96px, 세로 100px이고, 위 34px(메뉴 막대), 오른쪽 12px, 아래 96px(Dock)을 비운다. 그래서 1440×900 화면이면 한 열에 7줄이 들어간다(`(900 − 34 − 96) / 100`의 내림). 칸은 오른쪽 끝을 기준으로 하므로 창 크기가 바뀌어도 아이콘이 오른쪽에 붙어 있다. 끌어 옮긴 자리도 칸으로 `localStorage`에 남긴다. 저장한 칸이 화면 밖이거나 다른 아이콘과 겹치면 버리고 차례대로 빈 칸에 둔다.

![오른쪽 위에서 세는 칸](./images/desktop-icons-grid.svg '자리는 픽셀이 아니라 (col, row) 칸. 창 폭이 바뀌어도 오른쪽에 붙어 있다')

## 끌어 놓기는 가까운 빈 칸으로

아이콘을 놓으면 놓인 자리에서 가장 가까운 칸으로 맞춘다. 그 칸에 다른 아이콘이 있으면 가장 가까운 빈 칸으로 간다. 여럿을 함께 끌어도 서로 겹치지 않는다. 이 계산은 DOM 없이 순수 함수(`layout.ts`)로 두고 단위 테스트로 확인했다.

```ts
// apps/react/src/desktop/icons/layout.ts
export function nearestFree(want: Cell, taken: ReadonlySet<string>, rows: number, cols: number): Cell {
	// 화면이 꽉 차면 화면 밖 열에도 둔다 (아이콘을 잃지 않게)
	const limit = Math.max(cols, Math.ceil((taken.size + 1) / rows) + 1);
	for (let col = 0; col < limit; col++)
		for (let row = 0; row < rows; row++) {
			if (taken.has(keyOf({ col, row }))) continue;
			const distance = (col - want.col) ** 2 + (row - want.row) ** 2;
			if (distance < bestDistance) {
				best = { col, row };
				bestDistance = distance;
			}
		}
	return best ?? { col: limit, row: 0 };
}
```

거리가 같은 칸이 여럿이면 채우는 차례(오른쪽 열 위부터)가 앞선 칸을 고른다. `<` 비교라 먼저 본 칸이 남기 때문이다. 화면이 아이콘으로 꽉 찬 경우에도 아이콘을 잃지 않도록 화면 밖 열까지 찾는다. 여럿을 함께 끌면 하나씩 놓으면서 놓은 칸을 `taken`에 더하므로, 함께 끈 아이콘끼리도 겹치지 않는다.

![놓은 칸에 다른 아이콘이 있으면 가장 가까운 빈 칸으로 간다](./images/desktop-icons-drop.svg '거리는 칸 단위 유클리드 거리. 같으면 채우는 차례가 앞선 칸')

## 고르기

- 누르면 하나만 고르고, ⌘는 넣고 빼고, ⇧는 더한다
- 빈 곳에서 끌면 옅은 사각형이 생기고, 거기 걸린 아이콘을 고른다
- ⌘A는 모두, Esc는 해제, ⌘O·⌘↓는 연다
- 여럿을 고른 채 하나를 그냥 누르면 바로 풀지 않는다. 떼었을 때 끌지 않았으면 그때 그것만 남긴다. 그래야 고른 것을 한꺼번에 끌 수 있다 (macOS도 같다)

## 두 번 누르기와 포인터 붙잡기

처음에는 누르자마자 `setPointerCapture`로 포인터를 붙잡았다. 그러자 두 번 눌러도 폴더가 열리지 않았다. 포인터를 붙잡으면 `click`·`dblclick`도 붙잡은 요소(아이콘 층)로 가서, 아이콘의 `onDoubleClick`에 닿지 않는다. 그래서 빈 곳에서 사각형을 그릴 때는 바로 붙잡고, 아이콘은 4px 넘게 움직여 끌기가 시작될 때 붙잡는다.

## 포털로 띄운 메뉴

오른쪽 클릭 메뉴는 기존 `Menu`를 썼다. 메뉴는 `body`에 그려지지만(포털) React 이벤트는 React 트리를 따라 아이콘 층까지 올라온다. 메뉴 항목을 누르는 순간 층이 "빈 곳을 눌렀다"고 보고 사각형 고르기를 시작해 포인터를 붙잡았고, 항목의 클릭이 사라졌다. 층의 핸들러는 이벤트가 정말 층 DOM 안에서 났을 때만 받게 했다.

![바탕화면 빈 곳의 오른쪽 클릭 메뉴: 새 폴더, 정리하기, 이름순으로 정리, 배경화면 변경…](./images/desktop-icons-context-menu.jpg '빈 곳의 메뉴. 새 폴더는 뒤에 더한 항목이다')

빈 곳의 메뉴에는 정리하기, 이름순으로 정리, 배경화면 변경…이 있고, 배경화면 변경…은 시스템 설정의 배경화면 항목을 연다. 아이콘의 메뉴는 열기와 Finder에서 보기다.

## 층

아이콘 층은 배경화면 바로 위, 창·Dock·메뉴 막대 아래에 둔다. 창이 덮으면 가려지고, 아이콘을 누르면 메뉴 막대의 앱 이름이 Finder가 된다. 휴대폰 화면에는 넣지 않았다. 휴대폰은 iOS 홈 화면을 흉내 내고 있어서 바탕화면 폴더라는 개념이 없다.

## 남은 것과 배운 것

- 키보드로 아이콘 사이를 옮겨 다니는 것(화살표 키)은 아직 없다. ⌘A·Esc·⌘O만 된다.
- 끌어 옮긴 자리는 `localStorage`에만 남는다. 다른 기기에서는 처음 자리로 보인다. 방문자마다 다른 것이 맞다고 보고 서버에 두지 않았다.

배운 것: `setPointerCapture`는 끌기를 편하게 해 주지만, 붙잡은 동안 `click`·`dblclick`까지 붙잡은 요소로 보낸다. 누르기와 끌기를 같은 요소에서 받을 때는 "끌기가 시작된 뒤에" 붙잡아야 한다. 그리고 포털로 띄운 메뉴의 이벤트는 DOM이 아니라 React 트리를 따라 올라온다는 것을 다시 한 번 겪었다. 이벤트를 받는 쪽에서 `currentTarget.contains(target)`로 진짜 출처를 확인하는 습관이 필요하다.
