## 배경: macOS 바탕화면의 아이콘

macOS의 바탕화면(Desktop)은 창 뒤에 깔린 배경화면 영역이자, 파일과 폴더를 둘 수 있는 폴더이기도 하다. 바탕화면에 둔 항목은 화면 오른쪽 위부터 아이콘으로 표시되고, 다음 동작을 지원한다.

| 동작           | 결과                                                      |
| -------------- | --------------------------------------------------------- |
| 클릭           | 아이콘 하나를 선택(파란 배경으로 강조)                    |
| 빈 곳에서 끌기 | 반투명 사각형이 생기고, 사각형과 겹친 아이콘을 모두 선택  |
| 아이콘 끌기    | 선택한 아이콘을 다른 위치로 옮김. 놓은 위치는 그대로 유지 |
| 더블 클릭      | 폴더를 Finder 창으로 열기                                 |
| 오른쪽 클릭    | 열기, 정리하기 같은 메뉴                                  |

MacFolio는 메뉴 막대, 창, Dock까지 macOS와 같게 구현했지만 바탕화면에는 배경화면만 있었다. Finder에 이미 문서 폴더(이력서, 포트폴리오, 자격증)와 프로젝트 폴더가 있어서, [#259](https://github.com/hyeoniverse/MacFolio/pull/259)에서 이 네 폴더를 바탕화면에 배치하고 위 동작을 구현했다.

![바탕화면 오른쪽 위의 폴더 아이콘과 사각형 고르기](./images/desktop-icons-select.jpg '빈 곳에서 끌면 반투명 사각형이 생기고, 사각형과 겹친 아이콘이 선택된다')

> [!NOTE] 현재의 바탕화면 폴더
> 이후 프로젝트 폴더는 문서 › 포트폴리오 안으로 합쳤다. 그래서 현재 바탕화면의 기본 폴더는 이력서·포트폴리오·자격증 세 개이고, 모두 원래 폴더를 여는 가상본(아이콘 왼쪽 아래의 작은 화살표)[^alias]이다.

10월 18일 미리보기 앱([#255](https://github.com/hyeoniverse/MacFolio/pull/255))을 마친 뒤 이 작업을 시작했다. 처음 구현에는 문서 폴더만 있어서 프로젝트 폴더도 바탕화면에 배치했다. 이후 사진이 별도 최상위 폴더로 표시되는 구조가 Mac과 달라 프로젝트 폴더의 하위 폴더로 옮겼고([#261](https://github.com/hyeoniverse/MacFolio/pull/261)), 실행하는 앱은 실제 Mac처럼 응용 프로그램 폴더에만 두고 프로젝트는 포트폴리오 폴더 하나로 합쳤다.

## 위치는 픽셀이 아니라 칸

먼저 아이콘 위치를 어떤 단위로 저장할지 정했다.

| 방법                                 | 좋은 점                                                     | 나쁜 점                                                               |
| ------------------------------------ | ----------------------------------------------------------- | --------------------------------------------------------------------- |
| 픽셀 좌표 (`x`, `y`)                 | 놓은 위치를 그대로 보관                                     | 창 폭이 바뀌면 오른쪽 아이콘이 화면 밖으로 나간다. 겹침을 막기 어렵다 |
| CSS 그리드에 순서대로                | 계산이 없다                                                 | 사용자가 놓은 위치를 저장할 수 없다. 빈 칸을 둘 수 없다               |
| **오른쪽 위 기준 칸 (`col`, `row`)** | 창 폭이 바뀌어도 오른쪽에 붙는다. 겹침은 "같은 칸"으로 판단 | 칸과 픽셀을 오가는 계산이 필요하다                                    |

픽셀 좌표의 문제를 예로 들면, 1440px 폭 창에서 x = 1332에 둔 아이콘(폭 96px, 1332~1428)은 창 폭을 1280px로 줄이면 전체가 화면 밖에 놓인다. macOS의 바탕화면 아이콘은 오른쪽 위에서 시작해 아래로 한 열을 채우고, 다 차면 왼쪽 열로 넘어간다. 그래서 위치를 픽셀이 아니라 "오른쪽에서 몇째 열, 위에서 몇째 줄"인 칸으로 저장했다.

```ts
export function cellToPoint({ col, row }: Cell, viewport: Viewport): Point {
	return { x: viewport.width - MARGIN.right - (col + 1) * CELL.width, y: MARGIN.top + row * CELL.height };
}
```

칸 하나는 가로 96px, 세로 100px이고, 위 34px(메뉴 막대), 오른쪽 12px, 아래 96px(Dock)을 여백으로 확보한다. 1440×900 화면에서 계산하면 다음과 같다.

| 값                        | 계산                                         | 결과        |
| ------------------------- | -------------------------------------------- | ----------- |
| 한 열의 줄 수 (`rowsFor`) | `floor((900 − 34 − 96) / 100)`               | 7줄         |
| 열 수 (`colsFor`)         | `floor((1440 − 12) / 96)`                    | 14열        |
| 칸 (0, 0)의 왼쪽 위       | `x = 1440 − 12 − 96`, `y = 34`               | (1332, 34)  |
| 칸 (1, 2)의 왼쪽 위       | `x = 1440 − 12 − 2 × 96`, `y = 34 + 2 × 100` | (1236, 234) |

==칸은 오른쪽 끝을 기준으로 계산하므로 창 크기가 바뀌어도 아이콘이 오른쪽 끝에 정렬된다.== 창 폭이 1280px로 바뀌면 칸 (0, 0)은 `1280 − 12 − 96 = 1172`로 다시 계산된다. 끌어 옮긴 위치도 칸 단위로 `localStorage`에 저장한다. 저장한 칸이 화면 밖이거나 다른 아이콘과 겹치면 그 값은 버리고 채우는 순서대로 빈 칸에 배치한다.

![오른쪽 위에서 세는 칸](./images/desktop-icons-grid.svg '위치는 픽셀이 아니라 (col, row) 칸. 창 폭이 바뀌어도 오른쪽 끝에 정렬된다')

## 끌어 놓기는 가까운 빈 칸으로

아이콘을 놓으면 놓은 위치에서 가장 가까운 칸으로 맞춘다. 픽셀 위치를 칸으로 바꾸는 계산은 `cellToPoint`의 역산이다. 예를 들어 1440×900 화면에서 아이콘의 왼쪽 위를 (1250, 150)에 놓으면 `col = round((1440 − 12 − 96 − 1250) / 96) = round(0.85) = 1`, `row = round((150 − 34) / 100) = round(1.16) = 1`이라 칸 (1, 1)이 된다.

그 칸에 다른 아이콘이 있으면 가장 가까운 빈 칸으로 이동한다. 여러 아이콘을 함께 끌어도 서로 겹치지 않는다. 이 계산은 DOM 없이 순수 함수(`layout.ts`)로 구현하고 단위 시험으로 확인했다.

```ts
// apps/react/src/desktop/icons/layout.ts
export function nearestFree(want: Cell, taken: ReadonlySet<string>, rows: number, cols: number): Cell {
	// 화면이 꽉 차면 화면 밖 열에도 둔다 (아이콘을 잃지 않게)
	const limit = Math.max(cols, Math.ceil((taken.size + 1) / rows) + 1);
	for (let col = 0; col < limit; col++)
		for (let row = 0; row < rows; row++) {
			if (taken.has(keyOf({ col, row }))) continue;
			const distance = (col - want.col) ** 2 + (row - want.row) ** 2;
			if (distance < bestDistance) {
				best = { col, row };
				bestDistance = distance;
			}
		}
	return best ?? { col: limit, row: 0 };
}
```

거리는 칸 단위 유클리드 거리의 제곱(`Δcol² + Δrow²`)이다. 제곱근을 계산하지 않아도 크기 비교 결과는 같다. 예를 들어 칸 (0, 1)에 놓으려는데 그 칸이 차 있으면, (0, 0)·(0, 2)·(1, 1)이 모두 거리 1로 같다. 거리가 같은 칸이 여러 개면 채우는 순서(오른쪽 열 위부터)가 앞선 칸을 선택한다. `<` 비교라 먼저 검사한 칸이 남기 때문이다. 이 예에서는 (0, 0)이 비어 있으면 (0, 0)이 선택된다.

화면이 아이콘으로 가득 찬 경우에도 아이콘이 사라지지 않도록 화면 밖 열까지 검색한다. 여러 아이콘을 함께 끌면 하나씩 배치하면서 배치한 칸을 `taken`에 추가하므로, 함께 끈 아이콘끼리도 겹치지 않는다.

![놓은 칸에 다른 아이콘이 있으면 가장 가까운 빈 칸으로 간다](./images/desktop-icons-drop.svg '거리는 칸 단위 유클리드 거리. 같으면 채우는 차례가 앞선 칸')

## 선택 규칙

| 입력                           | 결과                                                |
| ------------------------------ | --------------------------------------------------- |
| 클릭                           | 그 아이콘 하나만 선택                               |
| ⌘ + 클릭                       | 선택에 추가하거나 선택에서 제외 (토글)              |
| ⇧ + 클릭                       | 선택에 추가                                         |
| 빈 곳에서 끌기                 | 반투명 사각형과 겹친 아이콘을 선택                  |
| ⌘A / Esc                       | 모두 선택 / 선택 해제                               |
| ⌘O, ⌘↓, 더블 클릭              | 선택한 폴더 열기                                    |
| 여러 개를 선택한 상태에서 클릭 | 버튼을 뗀 시각에 끌기가 없었으면 그 아이콘만 남긴다 |

마지막 규칙은 macOS와 같다. ==누르는 시각에 바로 선택을 해제하면 선택한 아이콘을 한꺼번에 끌 수 없기== 때문이다. 예를 들어 이력서와 포트폴리오를 선택한 상태에서 이력서를 누르고 끌면 두 아이콘이 함께 이동한다. 끌지 않고 그대로 떼면, 그 시각에 선택이 이력서 하나로 줄어든다.

빈 곳에서 끌어 만든 사각형은 끄는 방향과 관계없이 같은 형태로 계산한다. 시작점과 현재 점의 좌표에서 작은 값을 왼쪽·위, 큰 값을 오른쪽·아래로 삼는다(`rectFrom`). 그다음 각 아이콘에서 실제로 보이는 영역(칸 96px에서 좌우 14px씩을 뺀 그림과 이름 부분)과 겹치는지 확인한다. 테두리만 닿아도 겹친 것으로 본다.

![1440×900 화면에서 (1430,180)부터 (1300,250)까지 왼쪽 아래로 끌면 두 번째·세 번째 아이콘이 선택된다](./images/desktop-icons-marquee.svg '오른쪽 위에서 왼쪽 아래로 끌어도 rectFrom은 left·top이 작은 값인 같은 사각형을 만든다')

## 더블 클릭과 포인터 캡처

**포인터 캡처**[^capture]는 이후의 포인터 이벤트를 포인터 위치와 관계없이 지정한 요소로 보내는 기능이다. 끌기 구현에 쓰면, 마우스를 빠르게 움직여 포인터가 아이콘 밖으로 나가도 아이콘이 `pointermove`를 계속 받는다.

처음에는 `pointerdown` 시각에 바로 [`setPointerCapture`](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture)로 포인터를 캡처했다. 그러자 더블 클릭해도 폴더가 열리지 않았다. 포인터를 캡처하면 이어지는 `click`·`dblclick`도 캡처한 요소(아이콘 레이어)로 전달되어, 아이콘의 `onDoubleClick`이 호출되지 않는다. 그래서 빈 곳에서 사각형을 그리는 경우에는 바로 캡처하고, ==아이콘은 4px 이상 움직여 끌기가 시작된 시각에 캡처한다.==

| 캡처 시각                             | 더블 클릭 시 `dblclick` 대상 | 결과                 |
| ------------------------------------- | ---------------------------- | -------------------- |
| `pointerdown` 즉시                    | 아이콘 레이어                | 아이콘 처리기 미호출 |
| 4px 이상 움직인 뒤 (`DRAG_THRESHOLD`) | 아이콘                       | 폴더가 열린다        |

이동 거리는 `Math.hypot(dx, dy)`로 계산한다. 더블 클릭하는 동안 마우스가 1~2px 흔들려도 4px에 미치지 않으므로 캡처가 일어나지 않는다.

![pointerdown 시각에 캡처하면 dblclick이 레이어로 가고, 4px 이동 후 캡처하면 아이콘에 전달된다](./images/desktop-icons-capture.svg '포인터 캡처 시각에 따라 dblclick을 받는 요소가 달라진다')

## 포털로 렌더링한 메뉴

오른쪽 클릭 메뉴는 공통 `Menu` 컴포넌트를 썼다. 메뉴는 [포털](https://react.dev/reference/react-dom/createPortal)로 `body`에 렌더링된다. 포털은 React 컴포넌트를 부모 컴포넌트의 DOM 안이 아닌 다른 DOM 위치(여기서는 `body` 바로 아래)에 그리는 기능이다. 메뉴·대화상자가 부모 요소의 `overflow: hidden`에 잘리거나 다른 요소 뒤에 가려지지 않게 하는 용도로 주로 쓴다.

포털에는 한 가지 특성이 있다. ==React 이벤트는 DOM이 아니라 React 트리를 따라 아이콘 레이어까지 전파된다.== DOM에서 메뉴는 아이콘 레이어 밖에 있지만, React 트리에서는 여전히 레이어의 자식이다.

![React 트리에서는 메뉴 항목의 이벤트가 아이콘 레이어까지 전파되지만, DOM 트리에서는 메뉴가 body 아래에 있어 레이어 밖이다](./images/desktop-icons-portal-tree.svg '왼쪽은 React가 이벤트를 전파하는 경로, 오른쪽은 실제 DOM 위치. 두 트리가 다르다')

메뉴 항목을 누르는 시각에 레이어가 이 이벤트를 "빈 곳 클릭"으로 처리해 사각형 선택을 시작하고 포인터를 캡처했고, 그 결과 항목의 `click`이 발생하지 않았다. 레이어의 처리기는 이벤트 대상이 레이어 DOM 안에 있을 때(`currentTarget.contains(target)`)만 처리하도록 수정했다. `currentTarget`은 처리기를 등록한 요소(레이어), `target`은 실제로 누른 요소(메뉴 항목)다. `contains()`는 DOM 기준으로 판단하므로 메뉴 항목에 대해 `false`를 돌려준다.

![바탕화면 빈 곳의 오른쪽 클릭 메뉴: 새 폴더, 정리하기, 이름순으로 정리, 배경화면 변경…](./images/desktop-icons-context-menu.jpg '빈 곳의 메뉴. 새 폴더는 이후에 추가한 항목이다')

빈 곳의 메뉴에는 정리하기, 이름순으로 정리, 배경화면 변경…이 있고, 배경화면 변경…은 시스템 설정의 배경화면 항목을 연다. 아이콘의 메뉴 항목은 열기와 Finder에서 보기다.

## 레이어 순서

아이콘 레이어는 배경화면 바로 위, 창·Dock·메뉴 막대 아래에 배치한다. 창이 덮으면 아이콘이 가려지고, 아이콘을 누르면 메뉴 막대의 앱 이름이 Finder로 바뀐다. 휴대폰 화면에는 넣지 않았다. 휴대폰 화면은 iOS 홈 화면을 재현하므로 바탕화면 폴더라는 개념이 없다.

## 남은 과제

- 화살표 키로 아이콘 사이를 이동하는 기능은 아직 없다. ⌘A·Esc·⌘O만 지원한다.
- 끌어 옮긴 위치는 `localStorage`에만 저장된다. 다른 기기에서는 기본 위치로 표시된다. 방문자마다 위치가 다른 것이 맞다고 판단해 서버에 저장하지 않았다.

> [!IMPORTANT] 배운 것
> `setPointerCapture`는 끌기 구현을 단순하게 하지만, 캡처한 동안 `click`·`dblclick`까지 캡처한 요소로 보낸다. 클릭과 끌기를 같은 요소에서 처리한다면 끌기가 시작된 시각에 캡처해야 한다. 그리고 포털로 렌더링한 메뉴의 이벤트는 DOM이 아니라 React 트리를 따라 전파된다([React 문서](https://react.dev/reference/react-dom/createPortal#caveats)). 이벤트를 처리하는 쪽에서 `currentTarget.contains(target)`로 실제 발생 위치를 확인해야 한다.
