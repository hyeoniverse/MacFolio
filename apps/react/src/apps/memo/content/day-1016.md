## 날씨 앱: 경계에 걸린 휴대폰 화면

휴대폰 화면인데 날씨 앱이 넓은 창 모양으로 나와, 위쪽이 흐려지고 사이드바 버튼이 상태 표시줄에 가렸다. 사이트는 폭 767px까지(눕힌 휴대폰은 더 넓어도) 휴대폰 화면으로 보는데, 날씨 앱은 640px 이하일 때만 iOS 모양으로 바뀌었다. 641~767px이 그 사이에 걸렸다. 메모 앱처럼 휴대폰 화면이면 폭과 상관없이 iOS 모양을 쓰게 했다([#226](https://github.com/hyeoniverse/MacFolio/pull/226), [날씨 앱의 세 가지 어긋남](/memo/weather-layout-fixes)).

![날씨 앱 744px](./images/day-1016-weather.jpg '744px 세로 화면. 왼쪽은 넓은 창 모양의 사이드바가 남은 수정 전')

같은 PR에서 두 가지를 더 고쳤다. 넓은 창에서는 사이드바 버튼을 누르게 하려고 사이드바 전체를 위로 올려 두었는데, 그 사이드바가 신호등을 덮었다. 휴대폰의 목록 버튼은 장소가 하나뿐이면 왼쪽으로 밀려 있었다.

## 메모: 구분선과 한 줄에 모양 하나

구분선에는 스타일이 아예 없어서 브라우저 기본값(회색 2px 입체 선, 위 여백만)이 나왔다. 테두리 색 1px 선과 같은 위아래 여백으로 바꿨다. 편집기가 `---`를 `***`로 바꿔 저장하던 것도 고쳤다([#227](https://github.com/hyeoniverse/MacFolio/pull/227)).

![구분선](./images/day-1016-hr.jpg '다크 모드 읽기 화면. 수정 전에는 밝고 굵은 선이 튀었다')

목록 안의 제목, 토글 제목의 머리말은 노션처럼 지원할지 iOS 메모처럼 지원하지 않을지 정해야 했다. iOS·macOS 메모 방식으로 정했다. 서식 메뉴가 원래 macOS 메모의 모양 목록(하나만 고른다)을 따르고, 노션 방식으로 저장하면 읽기 화면에서 목록 점 옆에 큰 제목이 붙어 어색했기 때문이다. 이제 목록 항목에서 머리말을 고르면 그 줄이 목록에서 빠져 머리말이 된다([한 줄에 모양은 하나](/memo/memo-one-style-per-line)).

## 상태 표시줄과 홈 인디케이터: 밑의 그림을 읽는다

홈 화면의 상태 표시줄은 배경화면과 상관없이 늘 흰색이었다. 밝은 배경화면에서는 흰 바탕에 흰 글씨였다. 이제 상태 표시줄과 홈 인디케이터 바로 밑에 그려진 화면을 읽어(배경화면, 사진 같은 그림 포함), 흰색과 검은색 중 바탕과 대비가 더 큰 쪽을 고른다. 시계 쪽과 아이콘 쪽은 따로 읽는다([#228](https://github.com/hyeoniverse/MacFolio/pull/228), [상태 표시줄과 홈 인디케이터를 어떤 배경에서도 보이게](/memo/mobile-bars-contrast)).

![상태 표시줄](./images/day-1016-bars.jpg 'iOS 18 라이트 배경화면. 수정 후에는 시계와 아이콘이 검은색이다')

처음에는 섞인 바탕을 위해 글자 둘레에 반대 색의 옅은 빛을 두었다. 리뷰에서 "구린 것 같다"는 말을 듣고 뺐다. 실제 iOS는 한 가지 색만 쓰고 빛을 두지 않는다. 빛이 꼭 필요한 곳도 배경화면 하나의 아이콘 자리뿐이었다.

빛을 뺀 뒤 Kaleidoscope 배경화면에서 홈 인디케이터가 검은색으로 나오는 버그도 찾았다. 인디케이터의 누르는 자리는 화면 폭 전체인데, 그 양 끝(밝은 청록)까지 읽고 있었다. 보이는 막대(134px) 바로 밑만 읽게 고쳤다.

## 활동 상태 보기: 없앤 < 버튼

휴대폰의 활동 상태 보기 첫 화면에는 홈으로 가는 < 버튼이 떠 있었다. 그 자리를 비우느라 탭 줄 전체가 왼쪽에서 64px 안쪽으로 들어가 있었다. iOS에서 탭으로 나눈 앱의 첫 화면에는 뒤로 가기가 없고, 이 사이트의 날씨·사진도 이미 그렇다. 버튼을 없애고, 탭 줄과 기간 줄을 카드와 같은 선에 맞췄다. 기간 고르기는 넓은 창과 같은 오른쪽 끝으로 옮겼다([#229](https://github.com/hyeoniverse/MacFolio/pull/229)).

## 키보드 위 서식 막대와 문단 도구

휴대폰에서 메모를 쓰다 키보드가 올라오면 화면 아래의 서식 알약이 키보드 뒤에 깔렸다. iOS Safari는 키보드가 올라와도 화면 크기(`innerHeight`)를 줄이지 않고, 보이는 영역(`visualViewport`)만 줄이기 때문이다. 키보드가 가린 높이를 재서 서식 막대를 키보드 바로 위에 폭 가득 띄웠다. 주소창이 접힐 때처럼 120px보다 적게 줄면 키보드로 보지 않는다([#230](https://github.com/hyeoniverse/MacFolio/pull/230)).

![키보드 위 서식 막대](./images/day-1016-keyboard.jpg '시험 브라우저에는 화면 키보드가 없어서 visualViewport만 줄이고 그 자리를 회색으로 칠했다')

같은 PR에 iOS 메모의 문단 도구도 더했다. 서식 막대 끝의 문단 버튼을 누르면 막대가 내어쓰기·들여쓰기, 위·아래로 옮기기, 인용, 목록 버튼으로 바뀐다. 이 PR은 실제 아이폰에서 확인하지 못해 아직 열려 있다.

## 사흘 기다린 #222·#223과 z-index 층 이름

10월 13일에 올린 분석 앱 여백 정리([#222](https://github.com/hyeoniverse/MacFolio/pull/222))와 SearchField 추출([#223](https://github.com/hyeoniverse/MacFolio/pull/223))이 이날 머지되었다. #223에는 머지 전에 휴대폰 검색 문제 넷을 더 고쳤다. 사진 검색 칸이 줄어들지 않아 닫기(×)가 화면 밖으로 잘렸고, 메시지는 검색 중에도 오른쪽 버튼이 '새 피드백'이었다. 이제 검색 중에는 그 버튼이 검색 닫기(×)가 된다.

오후에는 공통 정리 계획(#150)의 다음 항목인 z-index도 정리했다. 13개 파일 20곳에 1000, 9999, 15000 같은 숫자로 흩어져 있던 값을 `theme.css`의 층 이름 15개(`--z-dock`, `--z-menubar`, `--z-login` …)로 모았다. 값은 하나도 바꾸지 않아 화면은 그대로다([#231](https://github.com/hyeoniverse/MacFolio/pull/231), [z-index를 층 이름으로](/memo/z-index-layers)). 이 PR은 다음 날 0시에 머지되었다.

## #187: RPG를 네 번 그리다

이틀 전 멈춘 2단계를 처음부터 다시 했다. 먼저 아홉 템플릿의 새 구역을 다듬었다. 팀원 카드의 GitHub 주소가 카드 밖으로 넘치던 것을 짧은 주소(`github.com/아이디`)로 고쳤고, 그림이 없는 트러블슈팅은 문제·원인·해결·결과를 2×2로 놓았다.

그리고 RPG 대화창을 네 번 그렸다. 매번 화면을 보고 받은 말에 따라 다시 그렸다.

## CI: ECR Public 한도, 다섯 번

이날 CI 실패는 모두 같은 이유였다. 시험에 쓸 Postgres 이미지를 `public.ecr.aws`에서 받다가 `toomanyrequests: Data limit exceeded`로 거절당해, 형식 검사도 시험도 시작하지 못했다.

| 언제            | 어디              |
| --------------- | ----------------- |
| 10월 13일       | #220 머지 뒤 main |
| 10월 15일 23:14 | #225              |
| 10월 16일 00:19 | #225 머지 뒤 main |
| 10월 16일 14:28 | #223              |
| 10월 16일 14:48 | #229              |

10월 10일에 Docker Hub의 받기 한도를 피해 ECR Public으로 옮겼는데, 이번에는 그쪽 한도에 걸렸다. 매번 실패한 작업만 다시 돌려 통과시켰다. 받는 곳은 아직 그대로다.

## 돌아보며

낮의 PR 다섯 개는 같은 모양으로 진행했다. main에서 브랜치를 새로 만들고, 수정 전후 화면을 같은 시나리오로 찍고, 개발기 글 하나를 붙여 올렸다. PR끼리 겹치는 파일이 없어서 어떤 순서로 머지해도 충돌하지 않았다. 다섯 개 중 넷이 올린 지 27분에서 70분 사이에 머지되었다. 작게 나누면 검토도 빠르다.

밤의 RPG는 반대였다. 네 번을 그리는 동안 받은 말은 "못생겼다", "칙칙하다", "안 예쁘다"였고, 그때마다 한 가지 축만 바꿨다. 해상도, 그다음 색, 그다음 타일이다. 10월 13일 회고에서 "템플릿마다 참고할 실제 제품을 먼저 정한 뒤에야 자리를 잡았다"고 적었다. RPG에는 그런 기준이 없었다. 참고할 게임 화면 하나를 먼저 정했다면 네 번 중 몇 번은 줄었을 것이다.

ECR 한도는 이제 우연이 아니다. 나흘 동안 다섯 번 걸렸고, 매번 사람이 다시 돌렸다. 다시 돌리면 통과하니 미뤄 왔지만, 이미지를 캐시하거나 받는 곳을 바꾸는 일을 할 때가 되었다.
