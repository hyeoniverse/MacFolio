이 글은 2026년 10월에 git 기록을 다시 읽으며 쓴 회고다. 그날의 커밋 6개와 그 코드를 근거로 썼다. 커밋은 새벽 4시 37분부터 5시 54분 사이에 있다. 기능 커밋은 클릭 소리와 로딩 화면 스타일 둘이고, 나머지 넷은 설치와 캐시 정리, 그 과정에서 생긴 문제를 처리한 커밋이다.

![2024년 11월 4일 작업 흐름](./images/day-20241104-timeline.svg '기능 커밋 둘, 나머지 넷은 설치·캐시·.gitignore')

## 클릭 소리

4시 37분 커밋은 화면 어디를 클릭하든 마우스 버튼을 누르는 시점과 떼는 시점에 소리를 재생했다. `App.tsx`에 `Audio` 객체 두 개를 생성하고, `document`의 `mousedown`·`mouseup` 이벤트에서 `play()`를 호출했다.

```ts
const mouseDownSound = new Audio(`${mp3Url}/mouse-down.mp3`);
const mouseUpSound = new Audio(`${mp3Url}/mouse-up.mp3`);

const handleMouseDown = useCallback(() => {
	mouseDownSound.play();
}, []);

useEffect(() => {
	document.addEventListener('mousedown', handleMouseDown);
	document.addEventListener('mouseup', handleMouseUp);
	// ...
}, [handleMouseDown, handleMouseUp]);
```

같은 커밋에서 시작음 파일(`mac-startup.mp3`)을 클릭 소리와 같은 `sounds/` 폴더로 옮기고, 로딩 화면이 그 경로를 사용하게 했다. 5시에는 로딩 화면 컴포넌트의 인라인 스타일을 `Loading.css`(36줄)로 분리했다.

## 커밋에 섞인 캐시

5시 2분 "Chore: npm install" 커밋의 실제 내용은 패키지가 아니라 `client/node_modules/.cache/` 아래의 webpack 캐시였다. `index.pack` 하나가 3.3MB다. [일주일 전](/memo/day-20241026)에 `node_modules` 전체를 추적하기 시작했기 때문에, CRA 개발 서버가 `node_modules` 안에 생성하는 캐시도 함께 추적되었다.

5시 49분 "Chore: remove cache"는 babel-loader 캐시 1,732개를 포함해 1,820개 파일을 변경했다. 그런데 같은 커밋에 `client/build/` 빌드 결과물 72개가 새로 추가되었다. 5시 54분에 `.gitignore`에 `client/node_modules/.cache` 한 줄을 추가해 정리를 마쳤다. 캐시만 제외했고, `node_modules`와 `build`는 계속 추적했다.

## 지금과 비교하면

- **클릭 소리**: 2026년에 다시 구현할 때 `<audio>` 대신 Web Audio를 사용했다. `<audio>`는 재생할 때마다 파일을 준비해 지연이 생기고, 연속으로 클릭하면 앞 소리가 끊긴다. 지금은 0.08초 길이의 소리를 한 번 디코딩해 메모리에 보관하고, 클릭할 때마다 새 `AudioBufferSourceNode`로 재생한다([Web Audio로 클릭 소리 내기](/memo/click-sound)).
- **캐시와 빌드 결과물**: 2026년 9월 28일에 빌드 결과물과 `node_modules`를 모두 추적에서 제외했다([9월 28일 회고](/memo/day-0928)).

## 돌아보며

이날 커밋 여섯 개 중 넷은 앞 커밋이 만든 문제를 처리한 것이다. 근본 원인은 일주일 전 `.gitignore`에서 삭제한 `node_modules` 한 줄이었고, 이날은 그 하위의 `.cache`만 다시 제외했다. 증상을 하나씩 막으면 같은 원인이 다른 형태로 다시 나타난다. 같은 날 `client/build`가 커밋된 것이 그 예다.

커밋 메시지도 실제 내용과 일치하지 않았다. "npm install" 메시지의 커밋 두 개 중 하나는 캐시였다. 커밋 전에 `git status`로 변경 파일 목록을 확인했다면 두 커밋 모두 생기지 않았을 것이다.
