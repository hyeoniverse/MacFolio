이 글은 2026년 10월에 git 기록을 다시 읽으며 쓴 회고다. 그날의 커밋 6개와 그 코드를 근거로 썼다. 커밋은 새벽 4시 37분부터 5시 54분 사이에 있다. 기능은 처음 하나이고, 나머지는 그것을 정리하거나 정리하다 생긴 일을 치운 것이다.

![2024년 11월 4일 작업 흐름](./images/day-20241104-timeline.svg '기능 커밋 둘, 나머지 넷은 설치·캐시·.gitignore')

## 클릭 소리

4시 37분 커밋은 화면 어디를 누르든 누를 때와 뗄 때 소리를 냈다. `App.tsx`에 `Audio` 객체 둘을 만들어 두고, `document`의 `mousedown`·`mouseup`에서 `play()`했다.

```ts
const mouseDownSound = new Audio(`${mp3Url}/mouse-down.mp3`);
const mouseUpSound = new Audio(`${mp3Url}/mouse-up.mp3`);

const handleMouseDown = useCallback(() => {
	mouseDownSound.play();
}, []);

useEffect(() => {
	document.addEventListener('mousedown', handleMouseDown);
	document.addEventListener('mouseup', handleMouseUp);
	// ...
}, [handleMouseDown, handleMouseUp]);
```

같은 커밋에서 시작음 파일(`mac-startup.mp3`)을 클릭 소리와 같은 `sounds/` 폴더에 넣고, 로딩 화면이 그 파일을 쓰게 했다. 5시에는 로딩 화면 컴포넌트의 인라인 스타일을 `Loading.css`(36줄)로 옮겼다.

## 커밋에 섞인 캐시

5시 2분 "Chore: npm install" 커밋은 패키지가 아니라 `client/node_modules/.cache/` 아래의 webpack 캐시였다. `index.pack` 하나가 3.3MB다. [일주일 전](/memo/day-20241026)에 `node_modules`를 통째로 추적하기 시작했기 때문에, CRA 개발 서버가 `node_modules` 안에 쓰는 캐시도 같이 추적되었다.

5시 49분 "Chore: remove cache"는 babel-loader 캐시 1,732개를 포함해 1,820개 파일을 바꿨다. 그런데 같은 커밋에 `client/build/` 빌드 결과물 72개가 새로 들어갔다. 5시 54분에 `.gitignore`에 `client/node_modules/.cache` 한 줄을 더해 마무리했다. 캐시만 막았고, `node_modules`와 `build`는 그대로 추적했다.

## 지금과 비교하면

- **클릭 소리**: 2026년에 다시 만들 때 `<audio>`를 버리고 Web Audio를 썼다. `<audio>`는 재생할 때마다 파일을 준비해 늦게 나고, 연달아 누르면 앞 소리가 잘린다. 지금은 0.08초짜리 소리를 한 번 디코딩해 두고 누를 때마다 새 재생기로 튼다([Web Audio로 클릭 소리 내기](/memo/click-sound)).
- **캐시와 빌드 결과물**: 2026년 9월 28일에 빌드 결과물과 `node_modules`를 모두 추적에서 뺐다([9월 28일 회고](/memo/day-0928)).

## 돌아보며

이날 커밋 여섯 중 넷은 앞 커밋이 만든 일을 치운 것이다. 근본 원인은 일주일 전 `.gitignore`에서 지운 `node_modules` 한 줄이었고, 이날은 그 아래의 `.cache`만 다시 막았다. 증상을 하나씩 막으면 같은 원인이 다른 모양으로 또 나온다. 같은 날 `client/build`가 들어온 것이 그 예다.

커밋 메시지도 내용과 어긋났다. "npm install"이라는 메시지 둘 중 하나는 캐시였다. 커밋하기 전에 바뀐 파일 목록을 한 번 보았다면 두 커밋 모두 생기지 않았을 것이다.
