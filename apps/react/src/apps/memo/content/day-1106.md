## 머지 뒤 배포를 막은 검색 성능 시험 ([#414](https://github.com/hyeoniverse/MacFolio/pull/414))

### 증상

전날 [#412](https://github.com/hyeoniverse/MacFolio/pull/412)를 머지한 뒤 CI의 `check` 작업이 desktop-core 검색 성능 시험 한 건에서 실패했다. `deploy`가 `check`에 걸려 있어 사이트에 배포되지 않았다. 같은 커밋을 다시 돌리면 통과했다.

```
FAIL src/memo/search.test.ts > 성능 > 글 240편(본문 8,600자씩)에서 검색어를 한 글자씩 칠 때 한 번에 평균 5ms 안
AssertionError: expected 5.458333333333333 to be less than 5
```

#412는 검색 코드를 바꾸지 않았다. 실패한 시험은 [10월 27일](/memo/day-1027)에 검색 순위를 만들며 더한 것이다.

### 원인

시험은 절대 시간(검색 한 번 평균 5ms 미만)을 기준으로 삼았다. 같은 코드가 Mac에서는 0.2ms, GitHub 공유 러너에서는 5ms 안팎이고, 러너가 느린 순간에는 기준을 넘는다.

> [!IMPORTANT] 시험이 지키려던 것은 속도가 아니라 캐시
> 검색용 글자는 글마다 처음 한 번만 만들고(`searchIndexOf`의 `WeakMap`), 글자를 칠 때마다 다시 만들지 않는다. 절대 시간으로 이 성질을 확인하면 ==러너 속도까지 함께 시험하게 된다==.

### 고친 방법

시험 하나를 둘로 나눴다.

| 시험               | 확인하는 것                                                                                                                                   | 러너 속도의 영향              |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| 검색용 글자 재사용 | 검색어를 10번 반복해 친 뒤에도 글 240편의 `searchIndexOf(post)`가 처음 만든 객체와 같다(`===`)                                                | 없음 (시간을 재지 않는다)     |
| 상대 비교          | 새 글 객체 240개의 검색용 글자를 처음부터 만드는 시간(`build`)과 검색 한 번의 평균 시간(`perQuery`)을 같은 실행에서 재 `perQuery < build / 5` | 두 값에 같이 걸려 비율은 유지 |

캐시가 깨져 검색마다 검색용 글자를 다시 만들면 `perQuery`가 `build`와 비슷해져 두 번째 시험이 실패한다. Mac에서 잰 값은 `build` 10~14ms, `perQuery` 0.21~0.23ms로 비율이 48~62배라 5배 기준에 여유가 있다. desktop-core의 tsconfig에는 DOM lib가 없어 `performance.now()` 대신 원래처럼 `Date.now()`를 쓴다. `search.test.ts` 24건이 5회 반복 모두 통과했다.

## 돌아보며

캐시를 지키려고 만든 시험이 절대 시간을 재는 바람에 러너 속도까지 함께 시험했다. 시험이 확인하려는 성질은 시간 대신 직접 검사해야 했다. 앞으로는 객체 동일성(`===`)처럼 성질을 직접 확인하고, 시간이 꼭 필요하면 같은 실행 안의 두 값을 비교한다.

`deploy`가 `check`에 걸려 있어, 코드와 무관한 시험 한 건의 실패가 그날 머지한 기능 전체의 배포를 막았다. 흔들리는 시험의 비용은 배포 구조에 따라 커진다. 10월 30일·31일의 임베드 편집 시험과 스크롤 복원 시험에 이어, 시간과 순서에 기대는 시험을 또 고쳤다.
