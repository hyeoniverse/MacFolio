관리자 글쓰기를 메모 앱처럼 바꿨다. 편집 단추 없이 글을 누르면 바로 고치고, 멈추면 알아서 저장한다. 쓰기는 편해졌는데 곧 두 가지가 걸렸다.

- **저장하는 순간 방문자에게 보인다.** 쓰다 만 글도, 반쯤 고친 문장도 그대로 공개된다
- **되돌릴 수 없다.** 잘못 지운 문단은 저장되는 순간 사라진다

따로 편집 모드를 두는 쪽으로 돌아갈까도 생각했지만, 바로 고치는 편함은 그대로 두고 **저장과 공개를 나누기로** 했다.

## 임시 저장과 게시

글 하나에 내용을 두 벌 둔다.

- **게시한 내용**: 방문자가 보는 것
- **임시 저장**: 관리자가 고치고 있는 것

자동 저장은 임시 저장에만 쓴다. 날짜 줄 오른쪽의 **게시**를 눌러야 임시 저장이 게시한 내용이 되고, 그때 방문자에게 보인다. 게시하지 않은 편집은 **변경 사항 버리기**로 버리고 게시한 내용으로 돌아갈 수 있다.

새 메모는 임시 저장으로 시작한다. 게시하기 전에는 아무에게도 보이지 않으니 며칠에 걸쳐 써도 된다.

관리자 목록에는 상태를 붙였다.

- **임시 저장**: 한 번도 게시하지 않은 글
- **점**: 게시한 글에 게시하지 않은 편집이 있다
- **예약**: 게시했지만 날짜가 아직 안 된 글

![관리자 목록의 게시 상태](./images/drafts-status.jpg '예약한 글은 예정 묶음에, 게시하지 않은 편집은 제목 옆 점으로, 새 메모는 임시 저장 표시로 보인다')

저장소의 Markdown 글도 같다. 고치면 임시 저장만 생기고, 방문자는 게시할 때까지 원래 파일 내용을 본다.

## 버전 기록

게시할 때마다 그 내용을 버전으로 남긴다(글마다 최근 50개). 도구 막대의 시계 단추를 누르면 버전 목록이 열리고, 고르면 미리 보고, **이 버전으로 되돌리기**를 누르면 그 내용이 편집기에 들어간다. 되돌려도 바로 공개되지는 않는다. 임시 저장으로 들어가서, 확인하고 게시하면 된다. 저장소 글이면 목록 맨 아래에 **원본**이 있어서 처음 파일 내용으로도 돌아갈 수 있다.

![버전 기록](./images/memo-versions.jpg '게시할 때마다 남은 버전과 저장소 원본. 고르면 미리 보고 되돌릴 수 있다')

되돌리기는 편집기를 새로 그리는 대신 **편집기 스스로 내용을 바꾸게** 했다. 바깥에서 새 내용으로 편집기를 다시 그리면, 사라지는 편집기가 마지막 편집을 저장하는 요청과 되돌린 내용을 저장하는 요청이 경쟁한다. 늦게 도착한 쪽이 이기므로 되돌린 내용이 덮일 수 있다. 편집기 안의 저장 줄에 되돌린 내용을 세우면 차례가 지켜진다.

## 예약 발행

날짜를 미래로 고르면 게시 단추가 **예약**으로 바뀐다. 누르면 게시는 되지만, 방문자에게는 그 날짜부터 보인다.

예약을 위해 따로 도는 작업(스케줄러)은 두지 않았다. 방문자가 글 목록을 받을 때 서버가 **게시한 날짜가 오늘(서울 기준) 이후인 글을 뺀다.** 날짜가 지나면 다음 요청부터 저절로 보인다. 저장소 글을 미래 날짜로 다시 게시했다면, 원래 파일 내용도 그날까지 가린다.

관리자 목록에서는 미래 날짜 글이 '오늘'로 묶이던 문제도 고쳤다. 날짜로 묶을 때 미래는 **예정**으로 따로 모은다.

## 서버: 두 벌의 내용과 CHECK 제약

`Post` 테이블에 게시한 내용(`title`…`body`, `publishedAt`)과 임시 저장(`draftTitle`…`draftBody`, `draftUpdatedAt`)을 나란히 두고, 버전은 `PostRevision`에 쌓는다.

```text
GET    /posts                    누구나: 게시한 글 중 날짜가 된 것, 가릴 표시
GET    /posts/admin              관리자: 게시한 내용과 임시 저장
POST   /posts                    새 글 (임시 저장으로)
PUT    /posts/:slug/draft        임시 저장 (자동 저장)
DELETE /posts/:slug/draft        변경 사항 버리기
POST   /posts/:slug/publish      게시 (버전이 하나 남는다)
GET    /posts/:slug/revisions    버전 목록, /:id 로 내용
```

DB에는 "두 벌 모두 **다 비었거나, 다 규칙에 맞는다**"는 CHECK 제약을 걸었다. 여기서 한 번 틀렸다. 처음에는 이렇게 썼다.

```sql
("title" IS NULL AND ... ) OR (length(btrim("title")) BETWEEN 1 AND 100 AND length(btrim("body")) > 0 ...)
```

제목만 있고 본문이 `NULL`인 행을 넣어 보는 테스트가 **통과해 버렸다.** `btrim(NULL)`은 `NULL`이고, `NULL > 0`도 `NULL`이라 뒤쪽 식 전체가 `NULL`이 된다. 그런데 CHECK 제약은 결과가 `false`일 때만 거절하고 **`NULL`이면 통과시킨다.** 각 칸이 `IS NOT NULL`인지 먼저 따지게 고쳤다.

이미 있던 글은 마이그레이션에서 옮겼다. 지운 표시는 내용을 비우고, 나머지는 게시한 글로 보고 지금 내용을 첫 버전으로 남긴다. 옛 모양의 행을 넣은 빈 DB에 마이그레이션을 차례로 적용해서 결과를 확인했다.
