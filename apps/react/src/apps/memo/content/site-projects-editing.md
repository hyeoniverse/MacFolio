프로필에 이어 프로젝트도 코드에서 꺼냈다. 프로젝트는 Safari 탭, Finder의 프로젝트 폴더, 터미널 `projects`, 사진 앨범, 그리고 데모를 창 안에 띄우는 **프로젝트 앱**(Dock·Launchpad)이 함께 쓰는 목록이다. 이제 관리자가 **시스템 설정 › 프로젝트**에서 순서를 바꾸고, 숨기고, 고치고, 새 프로젝트를 더한다.

## 서버에는 덮어쓸 값만

코드의 프로젝트 하나는 길다. 주요 기능, 장, 화면 모음, 출처까지 들어 있다. 이것을 통째로 서버에 옮기지 않고, 코드를 **기본값**으로 두고 서버에는 바꾼 것만 둔다.

```ts
interface ProjectEntry {
	id: string;
	hidden?: boolean;
	/** 코드의 기본값에 덮어쓸 맨 위 필드. null은 고를 수 있는 필드를 지운다 (예: 앱을 끈다) */
	override?: { [K in keyof Project]?: Project[K] | null };
}
```

- 서버 목록의 순서대로 보이고, 서버 목록에 없는 코드의 프로젝트는 끝에 붙는다. 나중에 코드에 프로젝트를 더해도 보인다.
- 코드에 없는 id는 새 프로젝트다. 빈 바탕에 덮어쓸 값을 채운다.
- 저장할 때는 기본값과 **다른 필드만** 남긴다(`overrideOf`). 이름 하나만 바꾸면 `{ id: 'macfolio', override: { name: '…' } }` 한 줄이다.

## 검사: 링크는 https만

이 값은 링크(`<a href>`)와 iframe 주소, 그림 주소가 된다. 서버와 화면이 함께 쓰는 `parseProjects()`(desktop-core)가 작은 스키마로 모든 필드를 검사한다.

- 저장소·데모·출처 링크는 `https:` 주소만. `javascript:` 같은 주소는 여기서 걸린다.
- 그림·영상은 사이트 안 경로(`/imgs/…`)나 https만. 따옴표·괄호·공백은 받지 않는다.
- 앱 아이콘은 이미지 폴더 기준 경로(`..` 없이)나 https, 색은 `#rrggbb`·`rgb()`만.
- id는 영어 소문자·숫자·`-`이고, 이 사이트의 앱 이름(`safari`, `finder`…)과 겹치면 안 된다. 프로젝트 앱의 이름이 곧 id이기 때문이다.
- 틀린 곳은 `프로젝트 newpick.url: https:// 주소여야 합니다.`처럼 경로와 함께 모두 돌려준다.

규칙을 만들고 나서 코드의 프로젝트를 모두 이 검사에 넣어 보는 시험을 더했더니, 바로 하나가 걸렸다. 한 장의 테마 팔레트가 18개라 처음 정한 한도 12개를 넘었다. 고급 JSON으로 그대로 저장할 수 있어야 하므로 한도를 30개로 올렸다.

## 앱 목록은 시작할 때 한 번 정해진다

어려운 것은 서버가 아니라 화면이었다. 프로필은 컴포넌트가 `useProfile()`로 읽으면 끝이었는데, 프로젝트는 여러 모듈이 **불러올 때** 계산해 둔다.

```ts
// apps/manifest.ts: 모듈을 불러올 때 한 번
export const PROJECT_APPS = PROJECTS.filter((project) => project.app && project.demo);
export const APP_NAMES = [...BUILTIN, ...PROJECT_APPS.map((project) => project.id), ...];
```

앱 목록, Dock, 창 컴포넌트 표, 사진 앨범이 모두 이렇다. 이것을 모두 반응형으로 바꾸는 대신, **이 모듈들을 불러오기 전에** 서버의 내용을 합치게 했다.

```ts
// main.tsx
void loadSiteContent().finally(() => import('./boot'));
```

`main.tsx`는 사이트 콘텐츠만 읽고, 앱은 `boot.tsx`에서 동적으로 불러온다. `PROJECTS` 배열은 바꾸지 않고 **안을 채운다**(`splice`). 혹시 먼저 읽어 간 모듈이 있어도 같은 배열을 본다. 그래서 저장한 내용은 새로고침하면 적용된다. 설정 화면도 저장한 뒤 "지금 새로고침" 단추를 보여 준다.

## 기다리지 않게: Worker가 HTML에 넣는다

앱을 그리기 전에 API를 기다리면 첫 화면이 그만큼 늦어진다. 배포한 사이트에서는 Cloudflare Worker가 첫 화면(index.html)을 줄 때 API의 `GET /site`를 받아 HTML에 넣는다.

```html
<script type="application/json" id="site-content">
	{"profile":null,"projects":{…}}
</script>
```

- `type="application/json"`이라 실행되지 않는 데이터다. CSP가 인라인 스크립트를 막아도 상관없다.
- 글 안의 `</script>`로 빠져나가지 못하게 `<`를 `<`로 바꾼다.
- 화면은 이 태그가 있으면 바로 쓰고, 없으면(로컬·E2E) API에 2.5초까지 묻는다. 그래도 안 되면 코드의 기본값으로 연다.
- Worker는 받은 값을 1분 동안 다시 쓰고, API에 닿지 않으면 1.5초 만에 포기하고 콘텐츠 없이 준다.

첫 화면은 원래 Worker를 거치지 않는 정적 파일이었다. `run_worker_first: ["/", "/index.html"]`로 첫 화면만 Worker를 먼저 거치게 했다. 그림·코드 같은 나머지 파일은 그대로 Worker를 거치지 않는다.

## 새 데모 주소와 CSP

사이트의 CSP는 빌드할 때 코드의 데모 주소로 `frame-src`를 만들었다. 그런데 관리자가 새 프로젝트 앱을 더하면 그 데모 주소는 빌드에 없으니 iframe이 막힌다.

같은 Worker가 첫 화면을 줄 때, 받은 콘텐츠의 데모 주소를 더해 CSP를 다시 만든다. CSP는 문서(HTML) 응답에 붙은 것이 그 페이지에 적용되므로, 첫 화면만 맞추면 된다. `wrangler dev`에 가짜 API를 붙여 보니, 콘텐츠가 HTML에 들어가고 가짜 데모 주소가 `frame-src`에 더해졌다.

```
frame-src 'self' https://challenges.cloudflare.com https://newpick-tan.vercel.app … https://stub-demo.example.com …
```

## 편집 화면

**시스템 설정 › 프로젝트**는 관리자에게만 보인다.

- 목록: 줄마다 위·아래, 숨기기·보이기, 편집. 이름 아래에 `id · 앱 · 고침 · 숨김` 같은 표시가 붙는다. 새로 더한 프로젝트만 지울 수 있고, 코드의 프로젝트는 숨길 수만 있다.
- 편집 › **기본**: 이름, 소개, 큰 제목, 기간, 페이지 모양, 저장소·데모 주소, 주 언어, 기술, 화면 캡처.
- 편집 › **앱**: "이 사이트 안에서 창으로 열기"를 켜면 프로젝트 앱이 된다. 앱 이름, 아이콘, Dock에 고정, 게임('여기서 플레이'), 뜨기 전 창 바탕, 창 크기. 앱은 데모 주소가 있어야 한다.
- 편집 › **고급 (JSON)**: 프로젝트 전체를 JSON으로 고친다. 폼에 없는 주요 기능, 장, 화면 모음도 여기서 고친다. 기본으로 돌아가면 JSON에서 고친 값이 폼에 보인다.
- **완료**는 서버와 같은 규칙으로 검사하고 목록으로 돌아간다. 실제 저장은 목록의 **저장**이 한 번에 한다.

## 시험

- 단위(desktop-core): 다듬기와 모르는 필드 버리기, `javascript:`·`data:`·http 거절, id 규칙, 안쪽 필수·열거·숫자·색, `null` 지우기, 길이·개수, 합치기 순서, 기본값과 다른 필드만, 데모 출처
- 단위(화면): 코드의 프로젝트가 모두 검사를 통과, 이 사이트의 앱 이름이 모두 막힌 id에 있음, `PROJECTS` 배열은 그대로 두고 안만 바뀜
- 단위(Worker): 콘텐츠 넣기와 `</script>` 막기, 새 데모 주소가 frame-src에, API가 없거나 실패하면 콘텐츠 없이, 1분 캐시, 옛 코드 파일은 404
- API e2e: 401·400과 이유, 저장·읽기·지우기, 경로 표에 두 경로
- E2E: 서버에 둔 순서·숨김·새 프로젝트 앱이 Safari·Dock에 보임 / 관리자가 폼·JSON으로 고치고 순서·숨김을 저장하면 새로고침 뒤 적용 / 새 프로젝트를 앱으로 더하고 기본값으로 되돌리기
