Finder는 사이트에 있는 것(문서, 프로젝트, 블로그 글, 앱)을 파일처럼 보여 주지만, 지금까지는 보기만 했다. 폴더를 만들 수도, 파일을 옮길 수도 없었다. 바탕화면의 이력서·포트폴리오·자격증 아이콘도 코드에 박힌 목록이었다. 이번에 실제 Mac처럼 폴더를 다루게 했다. 단, 바꾸는 것은 관리자만 하고, 바꾼 구조는 서버에 저장해 모든 방문자가 같은 구조를 본다. PR은 [#263](https://github.com/hyeoniverse/MacFolio/pull/263)이고, 커밋 22개, 파일 82개, +4,255/−386이다.

## 무엇을 옮길 수 있나

모든 것을 옮길 수 있게 하면 사이트가 망가진다. 프로젝트 폴더를 지우면 Safari의 프로젝트 탭이 갈 곳을 잃는다. 그래서 항목마다 종류를 나눴다(`finder/edit.ts`의 `editKind`).

- **관리자가 만든 폴더**: 이름 변경, 이동, 휴지통 모두 된다
- **올린 파일(R2)**: 이름 변경(확장자는 그대로), 이동, 휴지통
- **블로그 글과 블로그 폴더**: 블로그 안에서만 옮긴다. 폴더 이름도 바꾼다
- **시스템 항목**: 위치(데스크탑, 문서, 블로그, 응용 프로그램), 이력서·포트폴리오·자격증, 포트폴리오 안의 프로젝트마다의 폴더와 그 안의 사진 폴더, 저장소 문서, 앱. 끌리지 않고 메뉴도 흐리다

방문자에게는 같은 메뉴가 흐리게 보이고, 항목도 끌리지 않는다. 화면에서 막는 것은 보기 위해서이고, 실제로 막는 것은 서버다. 저장 요청은 관리자 세션이 없으면 401이다.

## 파일을 옮겨도 R2는 그대로

올린 파일은 R2에 `resume/<무작위>.pdf`처럼 폴더별 키로 들어 있고, 문서 표(Document)의 폴더 값과 키 앞부분이 맞는지 DB의 CHECK 제약이 본다. 파일을 옮길 때마다 R2 객체를 복사하고 지우는 방법도 있지만, 실패하면 파일이 둘이 되거나 사라질 수 있다.

그래서 R2와 문서 표는 건드리지 않고 "보이는 자리"만 따로 적었다. 새 표 `FinderLayout`은 메모 정리(`MemoOrganization`)처럼 한 행짜리 JSON이다.

```json
{
	"folders": [{ "id": "folder:k3x9a1", "name": "발표 자료", "parent": "docs" }],
	"files": { "file:resume/abc123.pdf": "folder:k3x9a1" },
	"aliases": ["docs:이력서", "docs:포트폴리오", "docs:자격증"]
}
```

파일의 주소(`/files/<키>`)는 바뀌지 않으니 이미 공유한 링크도 그대로 열린다. 원래 올린 폴더로 다시 옮기면 적어 둔 자리를 지운다. 규칙은 `packages/contracts`의 zod 스키마 하나로 서버와 화면이 함께 쓴다. 상위 폴더가 있어야 하고, 폴더가 자기 안으로 들어가는 고리는 안 되며, 같은 폴더 안에서 이름이 겹치면 안 된다. 블로그·응용 프로그램·사진 폴더에는 만든 폴더를 둘 수 없다.

구조를 어디에 둘지는 세 가지를 견줬다.

| 방법                                    | 좋은 점                           | 나쁜 점                                                            |
| --------------------------------------- | --------------------------------- | ------------------------------------------------------------------ |
| 브라우저(`localStorage`)에 저장         | 서버가 필요 없다                  | 관리자가 정리한 구조를 방문자가 볼 수 없다                         |
| 옮길 때마다 R2 키와 문서 표를 바꾼다    | "진짜" 이동                       | 복사·지우기 중 실패하면 파일이 둘이거나 없다. 공유한 주소가 깨진다 |
| **보이는 자리만 한 행 JSON으로 서버에** | 파일·주소는 그대로. 되돌리기 쉽다 | 기본 트리에 겹치는 계산이 필요하다                                 |

![FinderLayout을 기본 트리에 겹치는 구조](./images/finder-filesystem-layout.svg 'R2 키와 문서 표는 그대로 두고 보이는 자리만 따로 적는다')

트리를 만드는 함수(`buildLocations`)는 여전히 순수 함수다. 기본 트리를 만든 뒤 이 구조를 겹친다. 프로젝트를 지워서 상위 폴더가 사라졌거나 지운 파일을 가리키는 자리는 조용히 건너뛴다.

## 컴퓨터의 파일도 어느 폴더에나 놓는다

처음에는 이력서·포트폴리오·자격증과 프로젝트 폴더에만 파일을 놓아 올릴 수 있었다. 새로 만든 폴더나 바탕화면에 놓으면 아무 일도 없어서, 진짜 폴더처럼 보이지 않았다. 이제는 파일을 받을 수 있는 폴더면 어디에 놓아도 올라간다.

R2에 올릴 문서 폴더는 놓은 폴더에서 위로 올라가며 처음 만나는 이력서·포트폴리오·자격증·프로젝트 폴더로 정한다. 그런 폴더가 없으면(바탕화면, 문서 맨 위) 포트폴리오에 올린다. 놓은 곳이 그 폴더가 아니면 다 올린 뒤 Finder 구조에 `file:<키> → 놓은 폴더`를 적는다. 끌어서 옮길 때와 같은 방법이라, 올린 파일은 놓은 자리에 바로 보인다. 바탕화면의 가상본 위에 놓으면 원래 폴더로, 파일 아이콘 위에 놓으면 바탕화면으로 올라간다. 받을 수 없는 곳에 놓아도 브라우저가 파일을 열어 사이트를 떠나지 않게 막는다. Finder 사이드바에는 문서 아래에 이력서·포트폴리오·자격증을 두어, 그 위에 바로 놓을 수도 있다.

## 더 많은 파일 종류, 방문자는 내 화면에만

처음에는 PDF·PNG·JPG·WebP만 받았다. 이제 GIF·AVIF 그림과 문서(txt, md, docx, xlsx, pptx, hwp, key …), 영상·소리(mp4, mov, mp3 …), ZIP도 받는다. 목록은 contracts의 `DOCUMENT_EXTENSIONS` 하나이고, 사이트 Worker가 내주는 종류와 같은지 시험으로 맞춘다. PDF·그림은 미리보기로 열고, 그 밖의 파일은 회색 확장자 딱지를 단 종이 아이콘으로 보이며 열면 받는다. SVG·HTML은 사이트 주소에서 스크립트가 돌 수 있어 받지 않고, 글자·영상·소리가 아닌 파일은 Worker가 늘 받기(attachment)로 내준다.

관리자가 아닌 방문자가 파일을 놓으면 서버에는 올리지 않는다. 대신 브라우저의 blob 주소로 그 폴더에 넣어, 진짜 Finder처럼 놓은 자리에 보이고 미리보기로 열린다. 처음 한 번 "내 화면에만 추가됨" 알림을 띄우고, 새로고침하면 사라진다.

그림은 오른쪽 클릭 › 데스크탑 사진 설정으로 바로 바탕화면이 된다. 바탕화면에서 띄운 휴지통 경고창은 창 안이 아니라 화면 한가운데, 모든 창 위에 뜬다(예전에는 바탕화면 층 안에 그려져 Safari 같은 창 아래에 깔렸다).

## 휴지통은 진짜 휴지통

처음에는 휴지통으로 이동하면 확인을 받고 바로 지웠다. 그래서 휴지통을 열어도 아무것도 없었다. 이제는 macOS처럼 묻지 않고 휴지통에 넣는다. 만든 폴더는 상위를 `trash`로, 올린 파일은 `files`에 `trash`로 적고, 원래 자리는 구조의 `trash`(항목 → 보내기 전 폴더)에 남긴다. 서버(R2)의 파일은 아직 그대로다.

![휴지통으로 보내기 → 되돌려 놓기 또는 즉시 삭제·비우기. 영구 삭제할 때만 묻고 서버에서도 지운다](./images/finder-filesystem-trash.svg '휴지통에 있는 동안은 구조의 trash에 원래 자리만 적어 둔다')

Dock의 휴지통 › 버린 항목에서 오른쪽 클릭으로 되돌려 놓거나(원래 폴더, 없어졌으면 올린 폴더) 즉시 삭제하고, 비우기로 모두 영구 삭제한다. 영구 삭제할 때만 확인을 받고 서버에서도 지운다. 버린 항목이 있으면 Dock의 휴지통에 종이가 담긴다.

바탕화면에 바로 놓은 파일은 처음에 포트폴리오에 올리고 자리만 바탕화면으로 적었다. 그래서 휴지통에 넣으면 `portfolio/…` 키가 보여 헷갈렸다. 이제는 **데스크탑** 폴더(키 `desktop/…`)에 올라가 바탕화면이 그 파일의 원래 자리가 된다. 휴지통은 Dock의 휴지통 칸에 끌어다 놓아도 된다(Finder 창은 HTML 끌어 놓기, 바탕화면 아이콘은 놓는 자리의 `data-dock-trash`를 찾는다).

## 동영상은 QuickTime Player로

mp4를 올려도 회색 종이 아이콘이었고, 열면 그냥 받기만 했다. macOS처럼 **QuickTime Player** 앱을 더했다. 동영상·소리(mp4·mov·webm·mp3·m4a·wav)를 열면 이 앱이 검은 바탕에서 재생하고, 파일 없이 열면 올린 동영상·소리 파일을 골라 연다. Finder 아이콘은 동영상의 0.5초 장면(`#t=0.5`)에 재생 표시를 얹고, 휴대폰 파일 앱은 그 자리에서 재생한다.

재생 막대는 브라우저 기본 막대 대신 macOS QuickTime처럼 영상 아래에 떠 있는 반투명 판으로 그렸다. 소리, 10초 뒤로·재생·10초 앞으로, PIP·공유(받기)·재생 속도가 위에, 지난 시간·위치 막대·전체 시간이 아래에 있고, 재생 중 마우스를 2.5초 움직이지 않으면 사라진다.

`<video>`는 파일을 나눠 받는다. 사이트 Worker의 `/files/*`가 Range 요청에 206(`content-range`)으로 답하지 않으면 Safari는 재생하지 않고 Chrome도 앞뒤로 옮길 수 없어서, R2의 범위 읽기(`get(key, { range })`)로 그 부분만 내준다.

## 블로그 폴더는 메모와 같은 데이터

블로그 폴더는 원래 메모의 정리 내용(만든 폴더, 옮긴 글, 옮긴 폴더)으로 만든다. Finder에서 블로그 폴더를 옮기거나 이름을 바꾸면 Finder 구조가 아니라 이 정리 내용을 바꾼다. 메모가 쓰는 함수(`movePost`, `moveFolder`, `renameFolder`)를 그대로 불러서 3단 제한 같은 메모 규칙도 같이 지킨다.

열려 있는 메모도 새로고침 없이 따라가게, 정리 내용을 저장하면 작은 알림 저장소(`organizationEvents`)로 알린다. Finder가 저장하면 메모 사이드바가 바뀌고, 메모에서 폴더를 옮기면 Finder의 블로그 폴더가 바뀐다.

## 바탕화면도 같은 파일 시스템

macOS에서 바탕화면은 사용자 폴더 안의 "데스크탑" 폴더다. Finder 사이드바 맨 위에 **데스크탑** 위치를 두고, 바탕화면 아이콘은 이 폴더의 내용을 그린다. 처음 있던 이력서·포트폴리오·자격증은 다른 곳에 있는 시스템 폴더라서 가상본(alias)으로 두고, macOS처럼 왼쪽 아래에 작은 화살표를 붙였다. 가상본을 열면 원래 폴더로 간다.

![Finder의 데스크탑 위치와 바탕화면](./images/finder-filesystem-desktop.jpg 'Finder 사이드바 맨 위의 데스크탑과 바탕화면 아이콘은 같은 폴더다. 기본 셋은 화살표가 붙은 가상본')

관리자는 바탕화면을 오른쪽 클릭해 새 폴더를 만들고, Finder의 파일을 바탕화면에 끌어 놓고, 바탕화면 폴더를 Finder 창의 폴더(아이콘, 사이드바, 경로 막대)로 끌어 넣는다. Finder 안에서는 HTML 끌어 놓기를 쓰지만, 바탕화면 아이콘은 원래 포인터로 칸을 옮기는 방식이라, 놓는 순간 `elementsFromPoint`로 포인터 아래에 Finder 폴더가 있는지 본다. 있으면 자리를 바꾸지 않고 그 폴더로 옮긴다. 아이콘의 위치는 예전처럼 브라우저마다 따로 저장한다.

## macOS처럼 하려고 맞춘 것

- 새 폴더 이름은 "이름 없는 폴더", 겹치면 "이름 없는 폴더 2". 만들자마자 이름을 고치는 칸이 열린다
- Enter는 이름 변경, Esc는 취소. 이미 고른 항목의 이름을 한 번 더 누르면 잠시 뒤 고치는 칸이 열린다(두 번 누르기와 겹치지 않게)
- 파일 이름을 고칠 때는 확장자 앞까지만 골라 둔다
- 같은 이름이 있으면 "이미 사용 중입니다" 경고창을 띄운다
- 폴더를 휴지통으로 보내면 안의 것도 함께 간다. 올린 파일이 들어 있으면 저장소에서도 지워진다고 묻는다
- ⇧⌘N은 브라우저가 가져가는 단축키라, 다른 메뉴처럼 ⌘ 대신 ⌥를 쓴 ⌥⇧N으로 했다

## 프로젝트는 포트폴리오 안으로

사이드바에 있던 **프로젝트** 위치를 없애고, 프로젝트마다의 폴더를 **문서 › 포트폴리오** 안으로 옮겼다. 포트폴리오를 열면 프로젝트 폴더(MacFolio, HYEONIVERSE …)가 위에 이름순으로, 그 아래에 포트폴리오 파일이 있다. 실제 Mac에서도 프로젝트 자료는 문서 폴더 안에 두는 편이 자연스럽다.

옮긴 것은 트리 위의 자리뿐이다. 폴더 id(`projects/<id>`), 올릴 때의 폴더 값(`project:<id>`), R2 키(`projects/<id>/…`)는 그대로라 서버 데이터를 고칠 일이 없었다. 바탕화면의 기본 가상본도 이력서·포트폴리오·자격증 셋이 되었다. 예전에 저장한 구조에 프로젝트 가상본이 남아 있어도 없는 폴더라 조용히 건너뛴다.

휴대폰의 파일 앱은 같은 트리를 읽기만 한다. 데스크탑 위치도 보이고, 가상본을 누르면 원래 폴더가 열린다.

## 실제로 써 보며 고친 순서

10월 18일 저녁부터 다음 날 새벽까지, 로컬과 배포 사이트에서 직접 끌어 보며 고쳤다.

1. 미리보기의 열기 창에 폴더가 3개만 보였다. 파일 구조가 진짜 데스크톱처럼 이어져야 해서 Finder 트리를 그대로 쓰게 했다.
2. 블로그의 빈 폴더가 Finder에 안 보였다. 메모 사이드바처럼 빈 폴더도 보이게 고쳤다.
3. 바탕화면에 파일을 끌어 놓아도 안 올라갔다. 로그인을 안 한 상태였다. 로그인하고 `chill.gif`를 놓자 "PDF, PNG, JPG, WebP 파일만 올릴 수 있습니다"가 떠서 받는 종류를 늘렸다. 늘린 뒤에도 같은 문구가 떴는데, 종류를 허용하는 마이그레이션과 `packages/contracts` 빌드가 서버에 아직 반영되지 않아서였다.
4. 그림을 휴지통으로 옮길 때 뜨는 확인창이 Safari 창보다 아래에 깔렸다. 바탕화면 층 안에 그려지고 있어서, 화면 한가운데 모든 창 위에 뜨게 바꿨다.
5. 휴지통으로 옮긴 파일이 휴지통에 안 보였다. 바탕화면에 올린 파일이 "파일을 둘 폴더가 없습니다: portfolio/…"로 실패했고, 바탕화면에 올렸는데 왜 portfolio 아래에 있는지도 이상했다. 바탕화면용 키(`desktop/…`)를 따로 두었다.
6. Dock의 휴지통으로 끌어 놓기가 안 돼서 되게 했고, 끄는 동안 아이템이 휴지통 아래로 들어가 보이던 겹침 순서도 고쳤다.
7. MP4는 미리보기도 재생도 안 됐다. 동영상을 여는 QuickTime Player를 더했다.

## 확인

- 규칙: `packages/contracts/src/finder.test.ts`. "빈 몸통은 빈 구조", "기본 폴더와 만든 폴더 아래에 폴더·파일을 둔다", "없는 상위 폴더, 블로그·응용 프로그램, 고리, 겹친 이름은 거절", "이름: 비었거나 / 가 있거나 너무 길면 안 된다". 서버와 화면이 이 스키마 하나를 쓴다.
- 서버: `apps/api/src/finder/finder.service.test.ts`. "저장한 적 없으면 빈 구조", "관리자가 저장하면 누구나 같은 구조를 읽는다", "고리·없는 상위 폴더·블로그 아래는 400". 서비스는 36줄이다. 검사는 contracts가, 저장은 한 행 upsert가 한다.
- 화면: `apps/react/e2e/finder-filesystem.spec.ts`. "문서에 새 폴더를 만들고 이름을 바꾼 뒤 PDF를 끌어 넣는다", "바탕화면에서 새 폴더를 만들고 Finder 폴더로 끌어 넣는다 (가상본은 화살표)", "블로그 폴더 이름을 Finder에서 바꾸면 메모도 그 이름을 쓴다", 방문자는 "같은 구조를 보지만 새 폴더·이름 변경·옮기기는 할 수 없다". E2E는 가짜 `/finder/layout`으로 돈다.
- 화면의 편집 규칙은 `finder/edit.ts`(333줄)에 모았다. 무엇을 옮길 수 있는지(`editKind`, `canMove`, `canTrash`)와 어디에 놓을 수 있는지(`containerKind`)가 순수 함수다.

## 남은 것과 배운 것

- 휴지통에 든 R2 파일은 비우기 전까지 서버에 남는다. 관리자가 오래 비우지 않으면 쓰지 않는 파일이 R2에 쌓인다. 지금 양은 작다.
- 여러 관리자가 동시에 구조를 고치면 나중 저장이 이긴다. 관리자가 한 명이라 버전 검사는 두지 않았다.
- 방문자가 놓은 파일은 새로 고침하면 사라진다. 일부러 그렇게 했다. 방문자 파일을 서버에 두는 순간 공개 업로드 창구가 된다.

배운 것: "옮기기"를 실제 데이터 이동으로 만들면 실패 경우가 늘고 이미 나간 주소가 깨진다. 데이터는 그대로 두고 "보이는 자리"만 겹쳐 적으면, 실패해도 잃는 것이 없고 되돌리기도 쉽다. 메모 앱의 정리 내용(`MemoOrganization`)에서 쓴 방법을 Finder에 그대로 가져왔다. 같은 문제를 같은 모양으로 풀면 두 앱이 서로를 따라가게 만들기도 쉬웠다.
