Finder는 사이트의 데이터(문서, 프로젝트, 블로그 글, 앱)를 파일 형태로 표시하지만, 지금까지는 조회만 가능했다. 폴더를 만들거나 파일을 옮길 수 없었다. 바탕화면의 이력서·포트폴리오·자격증 아이콘도 코드에 고정된 목록이었다. 이번에 실제 Mac처럼 폴더를 편집할 수 있게 했다. 단, 편집은 관리자만 할 수 있고, 편집한 구조는 서버에 저장해 모든 방문자가 같은 구조를 조회한다. PR은 [#263](https://github.com/hyeoniverse/MacFolio/pull/263)이고, 커밋 22개, 파일 82개, +4,255/−386이다.

## 편집 가능한 항목

모든 항목을 옮길 수 있게 하면 사이트 기능이 깨진다. 예를 들어 프로젝트 폴더를 삭제하면 Safari의 프로젝트 탭이 가리킬 대상이 사라진다. 그래서 항목마다 종류를 나눴다(`finder/edit.ts`의 `editKind`).

| 종류                    | 허용 동작                                                                                                                                                             |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 관리자가 만든 폴더      | 이름 변경, 이동, 휴지통                                                                                                                                               |
| 업로드한 파일(R2)       | 이름 변경(확장자 유지), 이동, 휴지통                                                                                                                                  |
| 블로그 글과 블로그 폴더 | 블로그 안에서만 이동. 폴더 이름 변경                                                                                                                                  |
| 시스템 항목             | 위치(데스크탑, 문서, 블로그, 응용 프로그램), 이력서·포트폴리오·자격증, 포트폴리오 안의 프로젝트별 폴더와 그 안의 사진 폴더, 저장소 문서, 앱. 끌 수 없고 메뉴도 비활성 |

방문자에게는 같은 메뉴가 비활성으로 표시되고, 항목도 끌리지 않는다. 화면의 제한은 안내용이고, 실제 차단은 서버가 한다. 저장 요청에 관리자 세션이 없으면 401을 반환한다.

## 파일을 옮겨도 R2 객체는 그대로

업로드한 파일은 R2에 `resume/<무작위>.pdf`처럼 폴더별 키로 저장되어 있고, 문서 테이블(Document)의 폴더 값과 키 접두사가 일치하는지 DB의 CHECK 제약이 검사한다. 파일을 옮길 때마다 R2 객체를 복사하고 삭제하는 방법도 있지만, 중간에 실패하면 파일이 두 개가 되거나 사라질 수 있다.

그래서 R2와 문서 테이블은 수정하지 않고 "표시 위치"만 별도로 기록했다. 새 테이블 `FinderLayout`은 메모 정리(`MemoOrganization`)처럼 JSON 한 행이다.

```json
{
	"folders": [{ "id": "folder:k3x9a1", "name": "발표 자료", "parent": "docs" }],
	"files": { "file:resume/abc123.pdf": "folder:k3x9a1" },
	"aliases": ["docs:이력서", "docs:포트폴리오", "docs:자격증"]
}
```

파일 주소(`/files/<키>`)는 바뀌지 않으므로 이미 공유한 링크도 그대로 열린다. 원래 업로드한 폴더로 다시 옮기면 기록한 위치를 삭제한다. 규칙은 `packages/contracts`의 [zod](https://zod.dev/) 스키마 하나를 서버와 화면이 함께 쓴다.

- 상위 폴더가 존재해야 한다
- 폴더가 자기 자신의 하위로 들어가는 순환 구조는 허용하지 않는다
- 같은 폴더 안에서 이름이 중복되면 안 된다
- 블로그·응용 프로그램·사진 폴더에는 만든 폴더를 둘 수 없다

구조의 저장 위치는 세 가지를 비교했다.

| 방법                                   | 장점                              | 단점                                                                       |
| -------------------------------------- | --------------------------------- | -------------------------------------------------------------------------- |
| 브라우저(`localStorage`)에 저장        | 서버가 필요 없다                  | 관리자가 정리한 구조를 방문자가 조회할 수 없다                             |
| 이동할 때마다 R2 키와 문서 테이블 변경 | 실제 이동                         | 복사·삭제 중 실패하면 파일이 두 개가 되거나 사라진다. 공유한 주소가 깨진다 |
| **표시 위치만 JSON 한 행으로 서버에**  | 파일·주소는 그대로. 되돌리기 쉽다 | 기본 트리 위에 덮어쓰는 계산이 필요하다                                    |

![FinderLayout을 기본 트리 위에 덮어쓰는 구조](./images/finder-filesystem-layout.svg 'R2 키와 문서 테이블은 그대로 두고 표시 위치만 별도로 기록한다')

트리를 생성하는 함수(`buildLocations`)는 여전히 순수 함수다. 기본 트리를 생성한 뒤 이 구조를 덮어쓴다. 프로젝트 삭제로 상위 폴더가 사라졌거나 삭제된 파일을 가리키는 항목은 오류 없이 건너뛴다.

## 컴퓨터의 파일을 어느 폴더에나 업로드

처음에는 이력서·포트폴리오·자격증과 프로젝트 폴더에만 파일을 놓아 업로드할 수 있었다. 새로 만든 폴더나 바탕화면에 놓으면 반응이 없어서 실제 폴더처럼 동작하지 않았다. 이제는 파일을 받을 수 있는 폴더라면 어디에 놓아도 업로드된다.

R2에 업로드할 문서 폴더는 놓은 폴더에서 상위로 올라가며 처음 만나는 이력서·포트폴리오·자격증·프로젝트 폴더로 정한다.

| 놓은 위치                              | R2 문서 폴더                    | Finder 구조에 기록      |
| -------------------------------------- | ------------------------------- | ----------------------- |
| 이력서·포트폴리오·자격증·프로젝트 폴더 | 그 폴더                         | 없음                    |
| 그 하위에 만든 폴더                    | 가장 가까운 상위의 위 폴더      | `file:<키> → 놓은 폴더` |
| 바탕화면                               | 데스크탑(`desktop/…`)[^desktop] | 없음                    |
| 바탕화면의 가상본 위                   | 가상본이 가리키는 원래 폴더     | 없음                    |
| 문서 맨 위처럼 해당 폴더가 없는 곳     | 포트폴리오                      | `file:<키> → 놓은 폴더` |

Finder 구조에 기록하는 방식은 끌어서 옮길 때와 같아서, 업로드한 파일은 놓은 위치에 바로 표시된다. 받을 수 없는 위치에 놓아도 브라우저가 파일을 열어 사이트를 벗어나지 않도록 기본 동작을 막는다. Finder 사이드바에는 문서 아래에 이력서·포트폴리오·자격증을 배치해, 사이드바 항목 위에 바로 놓을 수도 있다.

## 파일 종류 확대, 방문자 파일은 본인 화면에만

처음에는 PDF·PNG·JPG·WebP만 허용했다. 이제 GIF·AVIF 그림과 문서(txt, md, docx, xlsx, pptx, hwp, key …), 영상·소리(mp4, mov, mp3 …), ZIP도 허용한다. 목록은 contracts의 `DOCUMENT_EXTENSIONS` 하나이고, 사이트 Worker가 제공하는 종류와 같은지 시험으로 확인한다.

- PDF·그림은 미리보기로 열고, 그 밖의 파일은 회색 확장자 라벨이 붙은 문서 아이콘으로 표시하며 열면 내려받는다
- SVG·HTML은 사이트 출처에서 스크립트가 실행될 수 있어 허용하지 않는다
- 텍스트·영상·소리가 아닌 파일은 Worker가 항상 내려받기(`Content-Disposition: attachment`)로 응답한다

관리자가 아닌 방문자가 파일을 놓으면 서버에 업로드하지 않는다. 대신 브라우저의 [blob URL](https://developer.mozilla.org/ko/docs/Web/API/URL/createObjectURL_static)로 그 폴더에 추가해, 실제 Finder처럼 놓은 위치에 표시되고 미리보기로 열린다. 처음 한 번 "내 화면에만 추가됨" 알림을 표시하고, 새로고침하면 사라진다.

그림은 오른쪽 클릭 › 데스크탑 사진 설정으로 바로 배경화면이 된다. 바탕화면에서 실행한 휴지통 경고창은 창 안이 아니라 화면 중앙, 모든 창 위에 표시된다(이전에는 바탕화면 레이어 안에 렌더링되어 Safari 같은 창 아래에 가려졌다).

## macOS와 같은 휴지통

처음에는 휴지통으로 이동하면 확인을 받고 바로 삭제했다. 그래서 휴지통을 열어도 항목이 없었다. 이제는 macOS처럼 확인 없이 휴지통으로 이동한다. 만든 폴더는 상위를 `trash`로, 업로드한 파일은 `files`에 `trash`로 기록하고, 원래 위치는 구조의 `trash`(항목 → 이동 전 폴더)에 보관한다. 서버(R2)의 파일은 이 시점에는 삭제하지 않는다.

![휴지통으로 이동 → 되돌려 놓기 또는 즉시 삭제·비우기. 영구 삭제할 때만 확인하고 서버에서도 삭제한다](./images/finder-filesystem-trash.svg '휴지통에 있는 동안은 구조의 trash에 원래 위치만 기록한다')

Dock의 휴지통 › 버린 항목에서 오른쪽 클릭으로 되돌려 놓거나(원래 폴더, 삭제됐으면 업로드한 폴더) 즉시 삭제하고, 비우기로 모두 영구 삭제한다. 영구 삭제할 때만 확인을 받고 서버에서도 삭제한다. 버린 항목이 있으면 Dock의 휴지통 아이콘에 종이가 담긴 모양으로 바뀐다.

바탕화면에 직접 놓은 파일은 처음에 포트폴리오에 업로드하고 위치만 바탕화면으로 기록했다. 그래서 휴지통에 넣으면 `portfolio/…` 키가 표시되어 혼동을 주었다. 이제는 **데스크탑** 폴더(키 `desktop/…`)에 업로드되어 바탕화면이 그 파일의 원래 위치가 된다. Dock의 휴지통 칸에 끌어다 놓아도 휴지통으로 이동한다(Finder 창은 [HTML 끌어 놓기](https://developer.mozilla.org/ko/docs/Web/API/HTML_Drag_and_Drop_API), 바탕화면 아이콘은 놓는 위치의 `data-dock-trash` 요소를 찾는다).

## 동영상은 QuickTime Player로

mp4를 업로드해도 회색 문서 아이콘이었고, 열면 내려받기만 했다. macOS처럼 **QuickTime Player** 앱을 추가했다.

- 동영상·소리(mp4·mov·webm·mp3·m4a·wav)를 열면 검은 배경에서 재생하고, 파일 없이 실행하면 업로드한 동영상·소리 파일을 선택해 연다
- Finder 아이콘은 동영상의 0.5초 시점 프레임([`#t=0.5`](https://developer.mozilla.org/ko/docs/Web/HTML/Element/video) 미디어 프래그먼트)에 재생 표시를 겹치고, 휴대폰 파일 앱은 그 자리에서 재생한다
- 재생 막대는 브라우저 기본 컨트롤 대신 macOS QuickTime처럼 영상 아래에 떠 있는 반투명 패널로 구현했다. 위 줄에 소리, 10초 뒤로·재생·10초 앞으로, PIP·공유(내려받기)·재생 속도가 있고, 아래 줄에 경과 시간·탐색 막대·전체 시간이 있다. 재생 중 마우스를 2.5초 움직이지 않으면 숨긴다

`<video>`는 파일을 구간 단위로 요청한다. 사이트 Worker의 `/files/*`가 [Range 요청](https://developer.mozilla.org/ko/docs/Web/HTTP/Range_requests)에 206(`content-range`)으로 응답하지 않으면 Safari는 재생하지 않고 Chrome도 탐색할 수 없어서, R2의 범위 읽기(`get(key, { range })`)로 요청한 구간만 응답한다.

## 블로그 폴더는 메모와 같은 데이터

블로그 폴더는 원래 메모의 정리 내용(만든 폴더, 옮긴 글, 옮긴 폴더)으로 생성한다. Finder에서 블로그 폴더를 옮기거나 이름을 바꾸면 Finder 구조가 아니라 이 정리 내용을 수정한다. 메모가 쓰는 함수(`movePost`, `moveFolder`, `renameFolder`)를 그대로 호출해서 3단계 깊이 제한 같은 메모 규칙도 함께 적용된다.

열려 있는 메모도 새로고침 없이 반영되도록, 정리 내용을 저장하면 작은 알림 store(`organizationEvents`)로 변경을 알린다. Finder가 저장하면 메모 사이드바가 갱신되고, 메모에서 폴더를 옮기면 Finder의 블로그 폴더가 갱신된다.

## 바탕화면도 같은 파일 시스템

macOS에서 바탕화면은 사용자 폴더 안의 "데스크탑" 폴더다. Finder 사이드바 맨 위에 **데스크탑** 위치를 추가하고, 바탕화면 아이콘은 이 폴더의 내용을 렌더링한다. 기존의 이력서·포트폴리오·자격증은 다른 위치에 있는 시스템 폴더라서 가상본(alias)으로 표시하고, macOS처럼 왼쪽 아래에 작은 화살표를 붙였다. 가상본을 열면 원래 폴더로 이동한다.

![Finder의 데스크탑 위치와 바탕화면](./images/finder-filesystem-desktop.jpg 'Finder 사이드바 맨 위의 데스크탑과 바탕화면 아이콘은 같은 폴더다. 기본 세 항목은 화살표가 붙은 가상본')

관리자는 바탕화면을 오른쪽 클릭해 새 폴더를 만들고, Finder의 파일을 바탕화면에 끌어 놓고, 바탕화면 폴더를 Finder 창의 폴더(아이콘, 사이드바, 경로 막대)로 끌어 넣을 수 있다. Finder 안에서는 HTML 끌어 놓기를 쓰지만, 바탕화면 아이콘은 포인터 이벤트로 칸을 이동하는 방식이라 놓는 시각에 [`document.elementsFromPoint`](https://developer.mozilla.org/en-US/docs/Web/API/Document/elementsFromPoint)로 포인터 아래에 Finder 폴더가 있는지 확인한다. 있으면 칸 위치를 바꾸지 않고 그 폴더로 이동한다. 아이콘 위치는 기존처럼 브라우저마다 별도로 저장한다.

## macOS와 같게 맞춘 세부 동작

- 새 폴더 이름은 "이름 없는 폴더", 중복되면 "이름 없는 폴더 2". 생성 직후 이름 입력 칸이 열린다
- Enter는 이름 변경, Esc는 취소. 이미 선택한 항목의 이름을 한 번 더 클릭하면 잠시 후 입력 칸이 열린다(더블 클릭과 구분하기 위한 지연)
- 파일 이름을 변경할 때는 확장자 앞까지만 선택된다
- 같은 이름이 있으면 "이미 사용 중입니다" 경고창을 표시한다
- 폴더를 휴지통으로 이동하면 하위 항목도 함께 이동한다. 업로드한 파일이 포함되어 있으면 저장소에서도 삭제된다고 확인한다
- ⇧⌘N은 브라우저가 처리하는 단축키라서, 다른 메뉴처럼 ⌘ 대신 ⌥를 쓴 ⌥⇧N으로 정했다

## 프로젝트는 포트폴리오 안으로

사이드바의 **프로젝트** 위치를 제거하고, 프로젝트별 폴더를 **문서 › 포트폴리오** 안으로 옮겼다. 포트폴리오를 열면 프로젝트 폴더(MacFolio, HYEONIVERSE …)가 위에 이름순으로, 그 아래에 포트폴리오 파일이 표시된다. 실제 Mac에서도 프로젝트 자료는 문서 폴더 안에 보관하는 편이 일반적이다.

옮긴 것은 트리상의 위치뿐이다. 폴더 id(`projects/<id>`), 업로드 시 폴더 값(`project:<id>`), R2 키(`projects/<id>/…`)는 그대로라 서버 데이터를 수정할 필요가 없었다. 바탕화면의 기본 가상본도 이력서·포트폴리오·자격증 세 개가 되었다. 이전에 저장한 구조에 프로젝트 가상본이 남아 있어도 존재하지 않는 폴더라 오류 없이 건너뛴다.

휴대폰 파일 앱은 같은 트리를 읽기 전용으로 표시한다. 데스크탑 위치도 표시되고, 가상본을 누르면 원래 폴더가 열린다. (이후 [위젯 작업](/memo/desktop-widgets)에서 휴대폰 파일 앱에도 편집 기능을 추가했다.)

## 남은 것과 배운 것

- 휴지통의 R2 파일은 비우기 전까지 서버에 남는다. 관리자가 오래 비우지 않으면 사용하지 않는 파일이 R2에 누적된다. 현재 용량은 작다.
- 여러 관리자가 동시에 구조를 수정하면 마지막 저장이 적용된다(last write wins). 관리자가 한 명이라 버전 검사는 넣지 않았다.
- 방문자가 놓은 파일은 새로고침하면 사라진다. 의도한 동작이다. 방문자 파일을 서버에 저장하면 공개 업로드 경로가 생긴다.

배운 것: "이동"을 실제 데이터 이동으로 구현하면 실패 경우가 늘고 이미 공유한 주소가 깨진다. 데이터는 그대로 두고 "표시 위치"만 덮어써 기록하면, 실패해도 데이터가 손실되지 않고 되돌리기도 쉽다. 메모 앱의 정리 내용(`MemoOrganization`)에서 쓴 방법을 Finder에 그대로 적용했다. 같은 문제를 같은 구조로 해결하자 두 앱을 서로 동기화하기도 쉬웠다.
