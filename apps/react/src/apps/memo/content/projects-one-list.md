GitHub 앱의 고정 저장소에 MacFolio를 넣었더니, Safari 탭에도 Finder의 프로젝트 폴더에도 MacFolio가 없었다. 같은 프로젝트 이야기인데 한쪽에만 생긴 것이다.

![Safari와 GitHub 앱](./images/projects-one-list.jpg '왼쪽: Safari의 HYEONIVERSE 페이지 / 오른쪽: 같은 목록에서 만든 GitHub 앱의 고정 저장소')

## 목록이 두 개였다

프로젝트 정보는 `shared/profile.ts`의 `PROJECTS`에 모여 있다. Safari 탭, Finder의 프로젝트 폴더, 터미널의 `projects` 명령이 모두 이 목록을 읽는다. 그런데 GitHub 앱의 스냅샷(서버에 닿지 않을 때 보여 주는 값)은 이 목록을 읽지 않고, 저장소 이름과 설명을 따로 적어 두고 있었다. 처음에는 GitHub 화면을 그대로 옮겨 적은 값이라 따로 두는 게 맞아 보였지만, 결국 같은 프로젝트를 두 군데에 적은 셈이었다.

그래서 스냅샷의 고정 저장소를 `PROJECTS`에서 만들게 했다. 프로젝트의 GitHub 주소에서 `owner/이름`을 나누고, 설명은 프로젝트 소개 한 줄, 홈페이지는 데모 주소를 쓴다. 이제 프로젝트를 더하거나 빼는 곳은 `PROJECTS` 한 곳이고, 순서도 모든 화면에서 같다.

이 약속이 깨지지 않게 시험도 하나 두었다. 스냅샷의 저장소 주소 목록이 `PROJECTS`의 주소 목록과 같은 순서로 같아야 통과한다.

## 따로 두는 것도 있다

서버가 GitHub에서 받아 보여 주는 고정 저장소는 관리자가 시스템 설정에서 고른다. 이것은 화면 코드가 아니라 서버 DB에 저장되는 값이라 `PROJECTS`와 묶지 않았다. 묶으면 배포 없이 저장소를 바꾸는 기능이 사라진다. 스냅샷은 서버를 못 쓸 때의 대비책이니 코드 안의 목록을 따르고, 실제 화면은 관리자가 고른 값을 따른다.

## 두 프로젝트의 페이지

Safari의 프로젝트 페이지는 프로젝트마다 모양(look)이 다르다. 두 프로젝트에도 각자 모양을 정했다.

- **MacFolio**: macOS를 흉내 낸 사이트라서, 따로 꾸미지 않은 Apple 제품 페이지 모양(`product`)을 그대로 쓴다. 아이콘은 사이트 로고(`logo512.png`)를 그대로 쓰고 바탕만 새로 칠했다. 노을빛 세로 그라데이션 위에 로고 모양을 하얗게 채우고, 아래로 그림자를 깔았다. 처음에는 사과를 직접 그리고 그 안에 창까지 넣어 봤는데, 사이트가 이미 쓰는 로고만 못했다. 지금 보고 있는 화면이 곧 데모라서 "데모 보기" 단추는 두지 않고, 주소창에는 저장소 주소가 보인다. 서버 쪽 이야기는 [MacFolio 백엔드 한 장으로 보기](/memo/backend-design)에 있다.
- **HYEONIVERSE**: Next.js와 Supabase로 만든 포트폴리오 사이트다. 그 사이트처럼 큰 세리프 제목과 마젠타(#d40063)를 쓰는 모양(`creative`)을 새로 만들었다. 다크 모드에서는 그 사이트의 어두운 바탕을 쓴다.

## 탭이 일곱 개가 되자

프로젝트가 일곱 개가 되니 좁은 Safari 창에서 지금 탭의 제목까지 잘렸다. 탭 폭은 몫(flex-grow)으로 나누는데, 탭 수가 늘면 지금 탭이 많이 가져가도 모자랐다. 그래서 지금 탭은 제목 길이보다 작아지지 않게(`min-width: max-content`) 하고, 나머지 탭이 그만큼 더 줄어들게 했다.

## 색만 다른 같은 페이지

프로젝트마다 모양(look)을 정해 두었지만, 실제로는 모든 페이지가 같은 순서로 쌓여 있었다. 큰 제목과 화면 캡처, 숫자 띠, 기능, 어두운 띠의 만든 방식, 맡은 일, 기술 사양 표. 색과 테두리를 바꿔도 스크롤을 내리면 같은 페이지를 다시 읽는 느낌이었다.

그래서 모양마다 페이지를 따로 짰다. 데이터(`PROJECTS`)는 그대로 두고, 그 프로젝트가 무엇인지에 맞춰 짜임과 읽는 순서를 정했다.

짜임을 나눈 뒤에는 페이지마다 그 프로젝트다운 동작도 하나씩 넣었다. 새싹 농장은 게임에 쓴 Sprout Lands 에셋(Cup Nooble)에서 풀밭 타일, 집과 나무, 걸어 다니는 소와 병아리, 대화창을 잘라 와 타이틀 화면과 대화창을 꾸미고, PRESS START를 누르면 화면이 번쩍이며 퀘스트로 내려간다. 개발 일지는 풀밭 위 흙길을 따라 표지판이 서는 지도이고, 스크롤하면 주인공이 그 길을 따라 걷는다. 화면 가운데 높이와 같은 길 위의 점을 SVG 경로에서 찾고(`getPointAtLength`를 이분 탐색), 주인공은 그 점까지 초당 150px쯤의 걸음으로 길을 따라 걸어간다. 처음에는 그 점에 바로 세웠더니 스크롤하는 만큼 순간이동하듯 너무 빨랐다. 지도 바탕은 풀 타일 조각을 정해진 씨앗의 난수로 섞어 만든 넓은 풀밭에 나무·덤불·꽃·돌과 작은 연못을 흩어 두었다. 연못이 놓인 칸에도 똑같이 흩다 보니 바위가 물 위에 떠 있었다. 연못 칸에는 아무것도 흩지 않고 연못 위 둑에 작은 꽃 몇 송이만 두고, 나무와 꽃의 몫을 늘려 칸마다 일고여덟 개씩 심었다. 돌은 땅 위에 조금씩 남기고, 보라 버섯은 농장에 더 어울리는 빨간 버섯으로 바꿨다. 기술 사양은 아이템 칸과 설명 창이 있는 인벤토리이고, 커서는 게임의 고양이 발 스프라이트가 톡톡 두드리는 그림이다. 말풍선 그림을 상자 테두리로 늘리면 꼬리까지 늘어나 뭉개져서, 꼬리 없는 상자 그림을 따로 만들고 꼬리는 대화창에만 따로 붙였다.

새싹 농장 페이지는 내려가는 만큼 하루가 흐른다. 타이틀은 아침, 하루(게임 화면) 구역은 낮, 개발 일지 가운데는 노을, 인벤토리는 해 질 녘, 크레딧은 별이 뜬 밤이다. 화면 가운데가 어느 두 구역 사이에 있는지로 바탕색과 풀밭 그림 위에 얹는 빛을 섞는다. 처음에는 페이지 전체 높이로 나눴더니 긴 개발 일지가 거의 다 차지해 노을과 밤이 잘 보이지 않아, 구역마다 때를 정했다. 그래도 노을에서 밤으로 넘어가는 곳이 끊겨 보였다. 개발 일지 풀밭이 끝나는 줄과 크레딧 상자의 윗변에서 색이 딱 바뀌었기 때문이다. 개발 일지 끝에 붉은 저녁을 하나 더 끼우고, 풀밭의 위아래 끝과 크레딧의 윗부분은 지금의 하늘색에서 시작해 스며들게 했다. 그래도 경계가 선명해서, 인벤토리 위에 하늘만 넘어가는 여백(180px)을 두고, 크레딧은 360px에 걸쳐 천천히 밤으로 짙어지게 했다. 별과 달도 하늘이 어두워진 다음부터 뜬다. 맨 아래 풀밭만 혼자 대낮처럼 밝아서 남색 그늘을 덮고, 윗줄에만 달빛을 얹고, 지나가는 주인공과 병아리도 어둡게 했다. 풀밭 위에는 반딧불이가 깜빡인다(처음 그늘은 너무 어두워서 절반쯤 걷었다). 빠르게 스크롤하면 주인공이 걸음 속도로 따라오느라 한참 화면 밖에 있었다. 이제 멀어질수록 빨리 뛰어오고, 화면 높이의 60%보다 멀면 화면 가장자리 바로 바깥까지 먼저 옮겨 둔다. 맨 끝까지 스크롤해 튕기면 탭 화면의 흰 바탕이 드러나서, 이 페이지에서는 튕기지 않게 하고 탭 화면 아래쪽에 밤 색을 깔았다. 그리고 스크롤할 때마다 경계가 잠깐씩 진해졌는데, 바탕색에만 0.4초 전환이 걸려 있어서였다. 지도·크레딧 가장자리는 같은 하늘색을 바로 쓰는데 바탕만 늦게 따라오니 그 사이가 어긋났다. 색은 어차피 스크롤 프레임마다 다시 칠하므로 전환을 뺐다. 크레딧은 엔딩처럼 맡은 일을 점선으로 이름까지 잇고, 에셋 출처는 나무 표지판에 담고, 맨 아래 풀밭으로 주인공과 병아리가 지나간다.

HYEONIVERSE 페이지에는 그 사이트의 마스코트 몽이를 세웠다. 지금 읽는 장에 따라 손을 흔들고, 반짝이고, 웃고, 놀라고, 맺음말에서는 잠든다. 화면 테두리와 차례의 표시 막대만 은색 그라데이션으로 칠했다. 아이콘 테와 몽이 받침, 장 번호에도 금속 효과를 넣어 봤는데 오히려 지저분해 보여서 뺐다.

MacFolio 페이지는 원래의 제품 페이지 흐름을 그대로 두었더니 너무 단조로웠다. 그래서 Apple 제품 페이지가 실제로 쓰는 장면 세 개를 넣었다. 첫 화면은 높이를 창 두 배 남짓으로 잡고 그 안의 무대를 멈춰 세워(`position: sticky`), 스크롤하는 동안 제목은 옅어지고 아래 작게 보이던 노트북이 무대 가운데로 올라오며 커진다. 진행도는 스크롤할 때마다 한 프레임에 한 번 재서 `--p`(0~1)로 넣고, 위치와 크기는 CSS가 그 값으로 계산한다. React는 다시 그리지 않는다. 좁은 창이나 움직임 줄이기 설정에서는 무대를 세우지 않고 처음부터 다 보인다. 끝에 나오는 "브라우저 안에, Mac 하나."는 처음에 회색 작은 글씨로 화면 맨 아래에 따로 떠 있어 묻혀 보였다. 이제 노트북 바로 아래에 붙여 노트북과 한 덩어리로 올라오고, 노트북이 거의 다 커졌을 때 흐림이 걷히며 떠오른다. 글씨는 크고 굵게, 뒷말은 강조색 그라데이션이다. 창이 낮으면 한 줄이 무대 아래로 잘려서, 노트북과 한 줄이 끝에 화면 높이 안에 다 들어오는 비율을 재어 그만큼만 키운다. 노트북 화면도 흐릿한 960px 캡처 대신 1440px 화면을 1.5배로 찍은 그림으로 바꿨다. 그래도 한 줄이 노트북 아래에 따로 붙어 나오는 게 밋밋해서, 이제 노트북이 거의 다 올라오면 화면 가운데에 작게 떠올라 앞으로 튀어나오듯 커지며 노트북 아래 제자리로 내려온다(화면 가운데까지의 거리를 재서 `--rise`로 넣는다). 끝에는 한 줄 아래로 숨 쉴 자리를 남기도록 노트북을 조금 위에 세우고 크기를 160px만큼 덜 키운다. 낮은 창에서는 처음 작게 놓인 노트북이 GitHub 링크를 가렸다. 제목과 링크가 끝나는 자리를 재서, 노트북이 그보다 24px 아래에서 출발하게 했다. Safari 창을 끌어 크기를 바꾸면 브라우저 창(window)의 resize가 오지 않아 무대 높이가 옛 값에 머물렀다. 공통 스크롤 도우미가 스크롤 상자의 크기도 `ResizeObserver`로 지켜보게 고쳤다.

그다음은 화면 크기 시뮬레이터다. 처음에는 데스크톱과 휴대폰 화면을 나란히 두었는데, 이 사이트가 화면 크기에 따라 어떻게 바뀌는지는 두 장으로 다 보이지 않았다. 그래서 모니터(1920px), 노트북(1440px), 태블릿(820px), 휴대폰(390px)에서 메모·메시지·Safari를 실제 브라우저로 찍고(모니터는 1배, 노트북 1.5배, 태블릿 2배, 휴대폰 3배), 이 구역에 들어오면 시뮬레이터가 화면에 고정되고, 스크롤하는 만큼 모니터 → 노트북 → 태블릿 → 휴대폰으로 넘어간다. 처음에는 시간에 맞춰 저절로 돌렸는데, 스크롤이 그냥 지나가 버려 넘어가는 모습을 끝까지 보기 어려웠다. 기기 틀은 폭과 높이, 테두리, 모서리를 바꾸며 다음 기기로 모양을 바꾸고, 틀이 반쯤 바뀌었을 때 그 크기에서 찍은 화면이 나타난다. 아래의 자는 틀 폭을 따라 늘고 줄며 1920px → 1440px처럼 숫자가 굴러가고, 단계 칸은 영상의 챕터처럼 지나온 만큼 아래 막대가 차고, 누르면 그 단계 자리로 스크롤한다. 휴대폰까지 보고 나면 아래로 내려가지 않고 다음 앱으로 이어진다. 메모의 모니터 → … → 휴대폰, 메시지의 모니터 → … → 휴대폰, Safari까지 열두 장면을 고정된 채 넘기고, 위의 앱 단추도 지금 앱을 따라 바뀐다. 설명에는 실제 기준을 적었다. 767px 이하이거나, 가로로 눕혀 높이가 499px 이하인 휴대폰이면 iOS 홈 화면이 되고(`desktop/layout.ts`), 그보다 넓으면 태블릿이라도 데스크톱이다.

만든 방식에는 요청이 지나는 길(브라우저 → Workers, Tunnel → NestJS → PostgreSQL, GitHub Actions → Workers)을 SVG로 그렸다. 선마다 길이를 1로 두고(`pathLength`) 단계 번호를 붙여, 진행도에서 단계 번호를 뺀 값으로 상자가 켜지고 선이 그려진다. 화살촉은 선마다 따로 두어야 그 선이 다 그려진 다음에 나타난다. 처음에는 진행도를 스크롤 위치에 바로 묶었더니, 그림 윗부분이 화면에 들어오자마자 그려지기 시작해 그림이 다 보이기 전에 끝나 버렸다. 그다음에는 그림이 다 보이면 시간에 맞춰 그렸는데, 스크롤과 상관없이 저절로 지나가 버렸다. 결국 그림도 화면에 고정해 두고, 고정된 동안 스크롤하는 만큼 상자가 켜지고 화살표가 이어지게 했다. 글자만 있던 상자에는 아이콘(Font Awesome 글자)을 넣고, 브라우저는 위에 점 세 개가 있는 창, PostgreSQL은 원통 모양으로 그렸다.

나머지 요소도 가만히 있지 않는다. 섹션 제목은 스크롤에 맞춰 낱말마다 흐림이 걷히며 밝아지고, 숫자 띠·기능 타일·만든 방식·맡은 일·기술 사양 줄은 화면에 들어오면 아래에서 떠오르고 벗어나면 다시 사라진다(`IntersectionObserver`로 `data-shown`을 붙였다 뗀다). 주요 기능은 처음에 아이콘 달린 타일 네 장이었고, 다음에는 MacBook Pro 페이지의 '주요 특징 살펴보기'처럼 옆으로 넘기는 큰 카드로 바꿨는데 둘 다 마음에 들지 않았다. 지금은 Apple 페이지의 벤토 그리드처럼 크기가 다른 타일로 여섯 칸 격자를 채운다. 첫 줄은 검은 큰 타일(진짜 같은 데스크톱)과 작은 타일, 둘째 줄은 작은 타일과 큰 타일로 엇갈리고, 타일마다 한 줄 제목과 설명 아래로 실제 화면이 걸쳐 놓인다. 작은 타일의 화면은 오른쪽으로 비켜 잘리고, 마우스를 올리면 화면이 살짝 커진다.

큐알유의 명함이 오가는 순서와 묻고 답하기는 칸의 머리가 화면 60% 선을 지나면 위 칸부터 차례로 펼쳐지고, 다시 올리면 아래 칸부터 접힌다. 처음에는 화면에 들어오자마자 열어서 정작 열리는 모습이 화면 아래쪽에서 지나가 버렸는데, 기준선을 읽는 눈높이로 올리자 펼쳐지는 게 보였다. WTD는 저장소 커밋 날짜로 2주 스프린트를 그리고, DevCourse는 주차별 기록과 직접 만든 실습 프로젝트 다섯 개를 터미널 출력으로 보여 준다. 터미널 출력의 한글 문장은 고정폭이 아니라 본문 글꼴로 바꿔 읽기 쉽게 했다. 브라우저 안에 창을 또 그리면 Safari 창과 겹쳐 보여서, DevCourse 페이지는 창 테두리 없이 페이지 전체를 터미널 화면으로 두었다. 처음에는 위에 미리 쳐 둔 명령과 결과를 늘어놓고 맨 아래에서 같은 명령을 다시 쳐 보게 했는데, 이미 본 내용을 또 보여 줄 뿐이라 칠 이유가 없었다. 그래서 페이지에는 소개와 `help`만 두고, 숫자·주차별 기록·프로젝트·기술 사양은 명령을 쳐야 나오게 했다. 대신 실제 저장소를 `ls`·`cd`·`tree`·`cat`으로 돌아볼 수 있다. `cd Week02/03` 하고 `cat Readme.md` 하면 그날 쓴 강의 노트가 나온다. 저장소 내용은 스크립트로 한 파일(폴더는 객체, 글 파일은 앞 100줄, 그림은 이름만)에 묶어 두고 페이지를 열 때 받으며, 코드에 적힌 DB 비밀번호 같은 값은 가렸다. 목록의 이름을 누르면 들어가거나 읽고, Tab은 명령과 경로를 채운다.

나머지 네 페이지에도 만질 거리와 스크롤 연출을 하나씩 넣었다. 나타나는 기준과 사라지는 기준을 같게 두었더니, 숨은 요소는 조금 내려가 있어서 화면 경계에 걸린 WTD 숫자 띠가 나타났다 사라졌다를 되풀이하며 떨었다. 이제 12% 넘게 보이면 나타나고, 화면에서 다 벗어나야 사라진다. 화면에 들어오면 나타나고 벗어나면 사라지는 것은 모든 페이지가 같은 훅(`useReveal`)을 쓰고, 나타나는 모양만 페이지마다 다르다. 신문은 잉크가 번지듯 흐림이 걷히고, 칸반 카드는 위에서 떨어져 붙은 뒤 살짝 흔들리고, 큐알유와 포트폴리오는 아래나 왼쪽에서 밀려 들어온다. 숫자 띠의 숫자는 화면에 들어올 때마다 0부터 세어 올라간다(앞뒤 글자는 두고 숫자만, 보조 기술에는 처음부터 다 읽힌다).

- **뉴픽**: 제호 아래에 기능과 만든 방식의 제목이 흘러가는 속보 띠를 두었다. 흐르는 글이 "속보" 라벨 위로 지나가 가려서, 글은 라벨 옆 창 안에서만 보이게 했다. 기사 꼭지에는 처음에 가위 단추를 달아 오려 두면 수가 느는 놀이를 넣었는데, 오려 둔다고 얻는 것이 없어 쓸모가 없었다. 그래서 "기사 펼쳐 읽기"로 바꿔 누르면 줄 아래에 자세한 설명과 화면이 펼쳐지게 했는데, 눌러야만 보이는 것도 답답했다. 이제 펼치는 단추 없이 처음부터 신문 지면으로 짠다. 첫 꼭지는 큰 제목과 첫 글자를 키운 본문, 실제 서비스 화면 사진이 놓인 머리 사진 기사, 사진이 있는 꼭지는 세로 괘선으로 나뉜 사진 기사, 사진이 없는 꼭지는 이중 괘선 상자의 단신으로 모았다. 사진은 신문 사진처럼 살짝 바랜 색이다가 마우스를 올리면 제 색이 돌아오고, 아래에 "▲ 실제 서비스 화면" 설명을 단다(뉴픽 저장소의 소개 그림).
- **WTD**: 칸반 카드를 진짜로 끌어 다른 열에 놓을 수 있다. 끌고 있는 동안 놓을 열이 그 열의 색으로 밝아지고, 열의 카드 수가 톡 튀며 바뀐다. 마우스 없이도 카드 오른쪽 위 화살표로 다음 열로 보낼 수 있고, "처음대로"로 되돌린다. 옮긴 카드가 다른 열에서 새로 그려지면 지켜볼 목록에 없어 보이지 않아서, 훅이 나중에 생긴 요소도 지켜보게 했다(`MutationObserver`).
- **큐알유**: 명함 두 장에 마우스를 올리면 그쪽으로 기울고, 빛이 마우스를 따라 명함 위를 비춘다. 처음 모습은 차분한 청록뿐이라 너무 심심해서, 실제 앱의 분위기를 그대로 가져왔다. 바탕은 앱의 민트→분홍 그라데이션(다크 모드는 앱의 청회색→자줏빛), 상자는 앱처럼 두툼한 그림자를 쓰고, 앞면 명함은 앱 첫 화면의 로고 카드다. 처음에는 앱처럼 비스듬히 눕혔는데 너무 기울어 보여 반듯하게 두고, 마우스를 올리면 아주 살짝만 기운다. 로고의 3×3 칸은 처음에 한 칸씩 튀어 오르며 놓이고, 마우스를 올리면 청록 칸이 물결처럼 들린다. 처음에는 명함에 일련번호 칩과 셔플 단추로 새 번호를 슬롯처럼 굴려 뽑는 장치, 번호를 옮겨 적듯 넣어 보는 칸도 두었는데, 모두 해 봐야 얻는 것이 없는 장식이라 뺐다. 그 자리에는 명함 한 장이 Firestore에 저장되는 모습을 그렸다. 공개 문서 `cards/{id}`, 소유자만 읽는 `private/card`, 사진만 떼어 둔 `photo/data`, 번호로 한 번만 읽는 `serials/{번호}` 네 문서가 필드 칩과 누가 읽을 수 있는지와 함께 나오고, 하위 문서는 부모 안에 이어 그린다. 필드 칩은 문서가 화면에 들어오면 하나씩 톡 놓인다. 명함이 오가는 순서 옆에는 앱 창을 두고, 단계가 펼쳐질 때마다 그 단계의 실제 앱 화면(만들기 모달, 사진 맞추기, 명함 보기, 셔플, 내 명함)으로 겹쳐 바뀐다. 앱 화면은 앱 저장소의 README 캡처(예시 명함은 모두 가짜 데이터)를 썼다. 화면 모음은 그 구역에 들어오면 화면에 고정되고, 세로로 스크롤하는 만큼 띠가 옆으로 넘어가 끝에 닿아야 다음 구역으로 내려간다. 고정된 동안 내려갈 길이는 화면 높이에 띠가 넘치는 폭을 더한 만큼이고, 그림이 늦게 불러와져 띠 폭이 바뀌면 다시 잰다(`ResizeObserver`). 좁은 창과 움직임 줄이기에서는 고정하지 않고 손으로 옆으로 넘긴다. 숫자 띠의 숫자가 설명 글씨만큼 작아 보이던 것은 공통 규칙(`.sp-facts span`)이 세어 올라가는 숫자 안의 글자에도 걸렸기 때문이라, 바로 아래 설명에만 걸리게 좁혔다.
- **HYEONIVERSE**: 차례의 각 장 아래 줄이 그 장을 읽은 만큼 차오른다. 왼쪽 칸이 화면보다 길어 차례 아래가 가려졌다. 처음에는 왼쪽 칸이 함께 스크롤되다가 아랫변에서 멈추게 했는데, 그러면 위의 아이콘과 몽이가 화면 밖으로 밀려났다. 아이콘과 몽이는 늘 보여야 해서, 장을 읽기 시작하면 소개 글과 링크를 접고 제목을 줄여 차례까지 한 화면에 들어오게 했다. 지금 장을 알리던 금속 막대는 읽은 만큼 차는 줄이 대신해서 뺐고, 몽이가 뛸 때 머리가 잘리지 않게 조금 내렸다. 몽이를 누르면 한 번 뛰고 하트가 퐁퐁 솟는다. 처음에는 하트가 한자리에 겹쳐 하나만 보였는데, 기울기를 `px × deg`로 계산해 변환 전체가 무시됐기 때문이었다. 단위 없는 숫자로 넘기고 쓰는 곳에서 단위를 붙였다.

페이지는 `apps/safari/project/`에 하나씩 두고, `ProjectPage`는 모양에 맞는 페이지를 고르기만 한다. 구역 이름(주요 기능, 만든 방식, 맡은 일, 기술 사양)은 모든 페이지가 같게 붙여서, 보조 기술이나 시험은 짜임이 달라도 같은 이름으로 찾는다.

새로 그린 MacFolio와 HYEONIVERSE 아이콘은 Dock의 다른 아이콘 옆에서 납작해 보였다. 위는 밝고 아래는 어두운 세로 그라데이션, 왼쪽 위의 은은한 빛, 아래 가장자리 그림자를 넣고, 사과·별 모양 아래에 그림자를 깔아 다른 아이콘과 깊이를 맞췄다.

## 내용이 너무 적었다

모양은 갖췄는데 HYEONIVERSE는 기능 네 줄과 만든 방식 네 줄이 전부였고, 다른 팀 프로젝트도 README 몇 줄에 머물렀다. 그래서 각 저장소의 문서와 커밋을 다시 읽고, 근거가 있는 것만 더했다.

데이터에는 `chapters`(장: 제목, 첫머리, 숫자, 글 묶음, 그림)를 더했다. 기능과 만든 방식으로 다 담기지 않는 이야기를 장으로 묶고, 페이지마다 제 모양으로 그린다. 신문은 번호 붙은 기획 기사, 칸반은 압정으로 꽂은 에픽 붙임쪽지(마우스를 올리면 바로 서며 들린다), 명함은 두툼한 타일, 포트폴리오는 차례에 장이 하나씩 더 붙는다.

- **HYEONIVERSE**: 관리자와 CMS(편집기, 자동 저장과 리비전, 409로 알아채는 동시 저장, pg_cron 예약 발행과 휴지통, 멤버 초대), 디자인 시스템(세 층 토큰, 결정 기록 D1~D33, Tailwind를 되돌린 이유), 성능, 보안과 데이터, 진행 과정과 품질(여덟 단계와 PR마다 거치는 관문)을 장으로 더했다. 진행 과정의 세로줄은 그 장을 읽는 만큼 차오른다. 숫자도 바로잡았다. 예전의 "98점(LCP 1.9초)"은 날짜와 조건이 없는 표에서 왔는데, 작업물 문서에 운영 사이트를 데스크톱 Lighthouse로 세 번 잰 중앙값(성능 97, 접근성 100, SEO 100, LCP 0.7초)이 있어 그 값을 쓴다. 그래도 글만 가득하고 볼거리가 없어서, 기능마다 그 사이트의 실제 화면을 붙이고 직접 만져 볼 수 있게 했다. 첫 화면은 "스크롤에 반응한다"면서 정작 스크롤에 반응하는 모습은 없어서, 그 사이트의 홈을 위에서 아래로 내려가며 찍은 화면 셋(첫 화면 → 토러스가 지나가는 소개 → What I do)을 겹쳐 두고 이 그림이 화면을 지나가는 동안 스크롤한 만큼 다음 화면으로 넘어가게 했다(오른쪽 스크롤 막대도 함께 내려간다). 그 아래에는 라이트와 다크 캡처를 겹쳐 두고 가운데 손잡이를 끌면 나뉘는 밀대를 두었는데, 끌 수 있다는 걸 알아채기 어려워서 화면에 보이는 동안 손잡이가 혼자 좌우로 흔들리며 "끌어서 비교해 보세요" 말풍선을 띄운다(한 번이라도 직접 만지면 멈춘다). 작업물 레이아웃 여섯 가지는 처음에 단추를 누르면 그 캡처로 바뀌게 했는데, 캡처만으로는 레이아웃의 차이가 잘 드러나지 않았다. 지금은 레이아웃마다 실제로 어떻게 움직이는지를 CSS로만 그린 작은 도식으로 보여 준다(가로로 흐르는 Flow, 칸이 차례로 밝아지는 벤토 Grid, 카드 여덟 장이 도는 Cylinder, 배경이 겹쳐 바뀌고 네 귀퉁이에 HUD가 뜨는 Fullscreen, 층마다 다른 속도로 흐르는 Cinematic, 왼쪽은 멈추고 오른쪽만 흐르는 Split). 스크롤 장면은 About 페이지를 녹화한 영상을 화면에 보일 때만 돌게 했다(H.264를 못 트는 브라우저를 위해 첫 화면 그림을 깔아 둔다). 성능 장에서는 개선 전 막대 아래로 개선 뒤 막대가 화면에 들어올 때 줄어들며 몇 % 줄었는지 붙는다. 관리자와 CMS 장은 짧은 글 여덟 줄로는 무엇을 만들었는지 다 보이지 않아, 글 한 편의 길을 따라 다시 썼다. 편집기, 요소마다 떠 있는 도구 막대, 세 겹 자동 저장과 버전 확인, 초안에서 영구 삭제까지 글 한 편의 일생, 글 목록의 일괄 처리, 네 단계 권한, 대시보드, 코드 배포 없는 사이트 설정마다 그 사이트의 실제 화면이나 도식을 붙이고, 글과 그림을 좌우로 엇갈려 놓았다. 그림은 누르면 화면 가득 크게 보인다(`<dialog>`).

디자인 시스템 장은 토큰 층과 결정 기록을 설명하는 글이라 방문자에게 와닿지 않았다. 대신 그 사이트에서 직접 고를 수 있는 테마를 보여 주는 장으로 바꿨다. 관리자 설정의 프리셋 18개(강조색, 라이트·다크의 바탕과 글자 다섯 색)를 그대로 옮겨, 견본을 누르거나 라이트·다크를 바꾸면 작은 홈 화면의 색이 그 테마로 바뀐다. 화면에 보이는 동안에는 프리셋이 혼자 넘어간다. 대비도 그 사이트의 규칙대로 계산한다. 강조 글자는 바탕 위 대비가 4.5에 못 미치면 OKLCH 명도만 바탕 반대쪽으로 옮기고(기본 테마 다크에서 `#d40063` → `#e62771`), 강조색 면 위 글자는 그 모드의 바탕 → 글자 → 반대 모드 순으로 처음 4.5를 넘는 색을 고른다. 처음에는 보정 없이 계산해서 Twilight 다크의 강조색이 "부족"으로 나왔는데, 실제 사이트는 그렇게 보이지 않으니 틀린 표시였다. 3D 토러스는 프리셋을 바꿔도 그대로이고 라이트·다크 재질만 바뀐다.

CMS에는 할 이야기가 더 있어서 장을 둘 더했다. **발표 갤러리와 음성**에서는 작업물 발표 자료(모두의 키오스크)가 원근으로 기운 갤러리에서 대본을 읽는 만큼 넘어가고(음성 파일 → 브라우저 음성 → 4초 순서), TTS 공급자(Fish → Google → Edge)를 눌러 막아 두고 음성을 만들면 다음 공급자로 넘어가는 모습, 녹음 파형을 끌어 고르고 잘라내기·붙여넣기·나누기·되돌리기(50단계)를 하는 편집기, PPTX를 끌어 놓으면 장마다 그림으로 그려지고 발표자 노트가 대본으로 들어가는 과정을 직접 해 볼 수 있다. **자동 번역과 AI 요약**에서는 편집 언어를 EN으로 바꾸면 빈 칸이 DeepL 번역으로 채워지고, 발행하면 AI 요약 상자가 붙는다. 이 화면들은 로그인이 필요한 관리자 화면이라, 먼저 같은 규칙으로 움직이는 데모로 만들었다. 이후 그 사이트 README에 관리자·CMS 절이 생기며 실제 캡처 18장과 영상 5개가 올라와서, 데모마다 아래에 "실제 화면" 줄을 두고 붙였다. 캡처는 관리자 머리줄(로그인한 계정이 보이는 줄)을 잘라 내고 그 기능이 보이는 영역만 남겼고, 영상도 같은 높이를 잘라 H.264로 다시 만들었다. 테마 장에는 Arctic·Rosewood·Meadow로 바꿔 본 홈을 라이트·다크로 쌓은 그림을, 글과 작업물 잇기와 SEO 점검에도 실제 화면을 붙였다. 글도 README에 맞춰 고쳤다(재번역 범위 고르기, 번역은 저장해야 남는다는 점, 강조색끼리 ΔE 20 이상, 이미지 색 뽑기는 브라우저 안에서만).

발표 갤러리 데모는 처음에 다른 작업물(모두의 키오스크) 발표 자료를 썼는데, HYEONIVERSE 장이니 HYEONIVERSE 발표 자료(19쪽 PDF) 가운데 7장으로 바꿨다. 소리도 실제로 나게 했다. 브라우저는 소리 자동 재생을 막으므로, 그 사이트처럼 "음성과 함께 보기 / 음성 없이 보기"를 먼저 묻는다. 1장은 그 사이트가 실제로 트는 TTS 음성(README 시연 영상에서 음성만 떼어 낸 26초 MP3)을 틀고, 2~6장은 대본만 있는 장이라 방문자 브라우저의 음성 합성(`speechSynthesis`)이 읽고, 7장은 대본이 없어 4초 뒤 넘어간다. 그 사이트의 재생 규칙(음성 파일 → 브라우저 음성 → 4초)과 같다. 음성이 끝나야 다음 장으로 넘어가고, 화면 밖으로 나가면 멈춘다. 자막은 문단 전체가 아니라 문장 하나씩, 글자 수 비율로 시간을 나눠 바꿔 보여 준다. "대본을 목소리로" 데모도 실제 소리가 나게 했다. 대본을 HYEONIVERSE 발표 1장 대본의 앞 두 문장으로 바꾸고(읽기 사전의 실제 짝 Hyeoniverse → 허니버스), Fish로 만들어지면 그 사이트의 실제 Fish 음성에서 두 문장만 잘라 낸 9.5초 파일을 튼다. 재생을 따라 대본이 가사처럼 채워지고, 재생 막대를 끌어 옮길 수 있다. 세 곳 모두 막으면 그 사이트처럼 브라우저 음성 합성이 읽고, Google·Edge로 넘어간 경우에는 그 공급자의 실제 파일이 없어 소리 없이 결과만 보여 준다고 밝힌다. 녹음 파형 편집기도 가짜 파형과 소리 없는 재생 막대뿐이었고, 클립을 끌어 옮길 수도 없었다. 이제 같은 실제 Fish 음성(9.5초)을 0.1초 칸으로 나눠, 파형은 그 음성의 실제 세기로 그리고, 재생하면 편집한 순서대로 원래 녹음의 조각들을 Web Audio로 이어 튼다. 클립 번호 손잡이를 끌면 클립이 손을 따라오고 놓일 자리에 선이 그어지며, 놓으면 순서가 바뀐다(되돌리기 가능). 손잡이를 잡은 뒤로는 창 전체에서 움직임을 받아, 클립이 손잡이째 움직여도 끌기를 놓치지 않는다. 갤러리의 브라우저 음성은 자연스럽지 않아서, 그 사이트 갤러리가 실제로 트는 Fish 음성 파일(발표 2·3·4·5·8·11쪽)을 받아 슬라이드를 그 쪽들로 맞췄다. 이제 1장부터 7장까지 모두 실제 음성이 나오고, 12쪽은 대본이 없는 장이라 4초 뒤 넘어간다. 2장부터는 대본을 아직 옮기지 않아 자막 없이 음성만 나온다. 장이 열한 개로 늘자 붙어 있는 왼쪽 칸이 화면보다 길어져, 아래로 내려가면 차례 아래쪽이 가려졌다. 왼쪽 칸 높이를 스크롤하는 칸 높이 안으로 묶고 차례만 그 안에서 스크롤되게 했으며, 지금 읽는 장이 차례 칸 밖에 있으면 보이는 곳으로 당긴다. "대본을 목소리로" 데모는 실제로 음성을 만드는 것처럼 보여서, 대체 순서 시연이라는 설명을 위에 붙이고 단추 이름도 "대체 순서 돌려 보기"로 바꿨다. KO/EN 토글만 칸 폭만큼 늘어나 있던 것도 글자 폭으로 줄였다. 결국 "대본을 목소리로"는 흉내 대신 실제로 음성을 만드는 데모로 바꿨다. MacFolio API에 `POST /speech`를 두고, 그 사이트와 같은 차례(Fish → Google → Edge)와 같은 목소리로 만든다. 화면에서 공급자를 눌러 막아 두면 그 공급자는 건너뛰어, 실패했을 때 다음으로 넘어가는 모습을 실제 결과로 본다. 비용 때문에 한 번에 80자까지, 해시한 IP마다 하루 3번, 사이트 전체 하루 50번만 받고(서버 메모리로 센다), 세 곳 모두 실패하면 쓴 횟수를 돌려준다. 주소·메일과 욕설 몇 가지는 읽지 않는다. 파형 편집기의 클립은 손잡이 대신 클립을 길게(0.4초) 눌러 끌게 했다. 도구 단추가 듣지 않는 것처럼 보인 건 단추 탓이 아니라, 위쪽 "실제 화면" 그림이 늦게 불러와지며 높이가 바뀌어 누르려던 자리가 120px쯤 밀렸기 때문이었다. 그림 칸을 16:10으로 미리 잡아 두어 밀리지 않게 했다. AI 장에는 커버 이미지 이야기도 더했다: 커버 없이 발행하면 Unsplash → Pexels에서 키워드로 찾아 채우고, 선택창에서 NanoBanana(Gemini)·Hugging Face FLUX로 그릴 수 있다.

장이 열한 개가 되자 모든 장이 "번호 · 제목 · 첫머리 · 숫자 · 두 칸 글 묶음"으로 똑같이 반복돼 심심했다. 장 데이터에 `look`을 두고 장마다 짜임을 바꿨다. Apple 제품 페이지처럼 테두리 없는 둥근 타일과 넉넉한 안쪽 여백, 큰 제목을 지켰다. 관리자와 CMS는 왼쪽 항목을 고르면 설명이 펼쳐지고 오른쪽 큰 화면이 그 항목의 실제 화면으로 바뀌는 쇼케이스, 발표 갤러리와 음성은 데모마다 큰 무대 타일, AI 장은 크기가 다른 벤토 타일, 트래픽은 숫자 타일과 큰 화면 아래 아이콘 카드, 성능은 Lighthouse 같은 점수 고리와 큰 번호 목록, 보안은 요청이 들어와 DB에 닿기까지 지나는 방어를 바깥부터 안으로 한 칸씩 들여 쌓은 층, 테마는 아이콘이 붙은 작은 타일이다. 좁은 창에서는 왼쪽 차례가 위로 지나가 버려 지금 읽는 장을 알 수 없어서, 내용 위에 붙는 가로 차례 줄을 두고 지금 장 칩을 가운데로 민다. 음성 데모는 결과에 따라 대본 줄·플레이어가 나타났다 사라지며 아래가 움직였는데, 자리를 늘 잡아 두고 내용만 바꾸게 했다. 녹음 파형 편집기도 가짜 파형과 소리 없는 재생 막대뿐이었고, 클립을 끌어 옮길 수도 없었다. 이제 같은 실제 Fish 음성(9.5초)을 0.1초 칸으로 나눠, 파형은 그 음성의 실제 세기로 그리고, 재생하면 편집한 순서대로 원래 녹음의 조각들을 Web Audio로 이어 튼다. 클립 번호 손잡이를 끌면 클립이 손을 따라오고 놓일 자리에 선이 그어지며, 놓으면 순서가 바뀐다(되돌리기 가능). 손잡이를 잡은 뒤로는 창 전체에서 움직임을 받아, 클립이 손잡이째 움직여도 끌기를 놓치지 않는다.

"스크롤하면 화면이 따라 움직입니다"는 동작은 했지만, 그림이 화면 아래에서 올라오는 동안(스크롤 200px 남짓) 세 장면이 다 넘어가 버려서 정작 그림이 다 보일 때는 이미 멈춰 있었다. 그림이 든 상자에 `overflow: hidden`과 나타나는 효과의 `transform`이 걸려 있어 그 안에서는 `position: sticky`가 듣지 않으므로, 장면을 따로 긴 트랙에 넣고 그 안에서 그림을 화면 가운데에 붙였다. 그림이 붙어 있는 동안 장마다 화면 절반만큼 스크롤해야 다음 장면으로 넘어간다.

트래픽 분석 장도 더했다. 방문은 페이지를 처음 열 때 한 번 보내고 서버가 (IP, 날짜)로 하루 한 행만 남기며, 관리자와 "내 IP"는 세지 않는다. 봇은 버리지 않고 표시를 붙여 따로 남겨 두고, 유입은 검색·소셜·커뮤니티·개발·직접·기타 여섯 갈래로 나눈다. 관리자 화면에도 가린 IP와 HMAC 키만 내려가고, 90일이 지나면 pg_cron이 IP를 익명화한다. 대시보드에 붙어 있던 트래픽 페이지 캡처는 실제로는 트래픽 페이지라 이 장으로 옮겼다.

데모와 실제 화면이 늘면서 왼쪽 차례 칸이 오른쪽 내용을 눌러 작아 보였다. 왼쪽은 220~280px로 좁혀 붙여 두고 전체 폭을 1320px까지 넓혀, 오른쪽 내용 칸이 590px 남짓에서 880px 안팎으로 커졌다. 제목 글자도 좁아진 칸에 맞춰 줄였다.

그래도 장마다 짜임만 바꿨을 뿐 페이지는 여전히 "왼쪽 차례, 오른쪽 내용" 두 칸이라 내용이 좁고 답답했다. 페이지 전체를 Apple 제품 페이지처럼 다시 그렸다. 위에는 이름·차례·데모 단추가 한 줄로 늘 붙어 있는 로컬 내비가 뒤 내용을 흐리게 비추며, 지금 읽는 장이 진해지고 읽은 만큼 밑줄이 찬다(차례가 창보다 길면 지금 장이 가운데 오게 옆으로 민다). 그 아래는 몽이와 큰 제목, 소개, 링크를 가운데로 모은 첫머리, 금속 테를 두른 첫 화면, 큰 숫자 셋이 이어지고, 장마다 화면 폭을 다 쓰는 띠가 번갈아 바탕을 바꾸며 가운데 1080px 안에 작은 번호·큰 제목·첫머리 글을 가운데 정렬로 둔다. 띠가 어두워지면 그 위 타일은 떠 보이는 밝은 색으로 바꾼다. 관리자와 CMS 쇼케이스는 하나씩 눌러 봐야 해서 기능을 훑기 어려웠다. 열 가지 기능을 모두 화면이 붙은 타일 두 줄로 펼쳤고, 화면 캡처가 없는 대시보드는 같은 자리를 아이콘으로 채워 타일 높이를 맞췄다. 녹음 파형 편집기 아래의 "녹음 → 구간 선택 → 나누기" 영상은 편집 화면 전체를 찍어 파형이 아래쪽 얇은 띠로만 보여서, 편집이 잘 드러나지 않았다. 잘라도 조용한 녹음의 납작한 파형이라 나아지지 않아 영상은 빼고, 그 위에서 실제 음성으로 직접 나누고 옮겨 보는 편집기가 그 역할을 맡게 했다.

위에 붙은 차례 막대는 결국 뺐다. 장이 큰 띠로 나뉘어 있어 차례 없이도 어디쯤인지 알 수 있었고, 막대는 화면 위를 가리기만 했다. 대신 첫머리에만 서 있던 몽이가 늘 따라다닌다. 처음에는 장마다 정해 둔 가장자리로 옮겨 다니게 했는데, 옮겨 다닐 까닭이 없으니 그냥 산만했다. 그래서 몽이에게 일을 줬다. 화면에 가장 크게 보이는 데모 곁(내용 칸 오른쪽 가장자리, 데모 머리 높이)으로 통통 튀어 가 "EN을 누르면 진짜로 번역해요"처럼 그 데모를 해 보라고 말풍선으로 권하고, 데모와 함께 스크롤된다. 데모는 지금 하는 일을 페이지에 알리고(`cr-demo` 이벤트), 몽이는 만드는 중이면 기다리고, 끝나면 반짝이며 "됐어요!", 실패하면 놀라며 아래 이유를 보라고 한다. 보이는 데모가 없으면 오른쪽 아래에서 쉬고, 좁은 창에서는 가장자리 밖으로 몸 반쯤 내밀고 엿본다. 마우스를 올리면 깜빡이던 것은, 웃는 얼굴로 바뀌며 그림 크기와 위치가 달라져 마우스가 몽이 밖으로 나갔다 들어왔다를 되풀이했기 때문이다. 몽이 칸 크기를 못 박고 그림은 마우스를 받지 않게 했다. 녹음 파형 편집기는 클립을 나눈 뒤 잘라내기·복사가 듣지 않았다. 클립을 아무 데나 길게 누르면 끌기가 시작되게 했더니, 파형을 누른 채 잠깐 멈췄다가 끄는 평범한 구간 고르기가 클립 옮기기로 바뀌어 구간이 골라지지 않았던 것이다(클립이 하나일 때는 옮길 일이 없어 드러나지 않았다). 길게 눌러 옮기기는 클립 위 번호 띠에서만 받고, 파형 쪽은 늘 구간 고르기로 나눴다.

그 사이트 README에 운영 화면 캡처(대시보드, 일별 조회, 트래픽, IP 분석, 알림, 서비스 호출 기록 …)가 새로 올라와, 관리자 머리줄을 잘라 내고 붙였다. 아이콘으로 채워 두었던 대시보드 타일에 실제 화면이 들어갔고, 알림과 댓글, 서비스 호출 기록 타일을 더해 CMS 장은 열두 칸이 됐다. 트래픽 장에는 트래픽, IP 분석, 일별 조회 화면을 나란히 두었다. 알림 화면을 보다가 그 사이트의 AI 요약이 "gemini-2.0-flash는 더 이상 쓸 수 없다"는 404로 실패하고 있는 걸 봤다. 요약 데모도 같은 모델을 쓰고 있어서, 기본을 늘 최신 Flash를 가리키는 `gemini-flash-latest`로 바꾸고, 그래도 내려간 모델이라는 404가 오면 응답이 권하는 모델로 한 번 다시 묻고 그 뒤로는 그 모델을 쓰게 했다. "스크롤하면 화면이 따라 움직입니다" 장면이 다시 멈춘 것은 몽이가 가장자리 밖으로 내밀 때 옆 스크롤이 생기지 않게 페이지 전체에 건 `overflow-x: clip` 탓으로 보였다. Chromium에서는 멀쩡했지만 Safari에서는 그 안의 sticky가 붙지 않아, 자르기를 몽이 층에만 걸었다. 그랬더니 이번에는 Safari에서 몽이가 사라졌다. 몽이 층은 높이가 0이라, 옆만 자르라는 설정을 Safari가 세로까지 잘라 버린 것이다. 자르기는 어느 층에도 걸지 않고, 몽이는 늘 화면 안에 두고, 옆 스크롤은 스크롤 상자(Safari 창의 페이지 칸) 자신에서 막았다. 스크롤 상자 자신의 overflow는 그 안의 sticky를 깨지 않는다.

모든 장을 큰 띠로 바꾸고 나니 이번에는 장 안이 단조로웠다. 관리자와 CMS는 열두 칸이 같은 크기로 줄지어 있었고, AI·트래픽·테마 장도 비슷한 타일의 반복이었다. 장마다 다른 짜임을 다시 줬다. 관리자와 CMS는 항목에 묶음(쓰기, 발행과 정리, 운영, 권한과 설정)을 달고, 묶음마다 첫 항목은 화면과 글을 좌우로 놓은 큰 칸, 나머지는 작은 칸 둘이나 셋으로 짜며 큰 칸의 좌우를 묶음마다 바꿨다. AI 장은 글과 데모가 좌우로 엇갈리는 큰 줄로, 글은 줄 안에서 붙어 데모를 따라온다. 트래픽 장은 숫자를 어두운 계기판 띠에 두고, 트래픽·IP 분석·일별 조회 화면을 큰 화면 하나에 작은 둘이 비스듬히 얹힌 콜라주로, 나머지 이야기는 옆으로 넘기는 카드로 바꿨다. 테마 장은 왼쪽 글을 읽어 내려가면 오른쪽에 붙은 화면이 지금 읽는 항목의 화면으로 바뀐다(누르지 않아도 글은 모두 보인다). 그러다 사이트 설정 캡처의 이메일 칸에 개인 메일이 남아 있는 걸 봐서, 새 캡처처럼 admin@example.com으로 가리고 관리자 머리줄을 잘라 냈다. 발표 갤러리에는 일시정지를 더하고(Space로도), 자막 자리는 늘 세 줄 높이로 두어 문장 길이나 자막 켜고 끄기에 따라 아래가 움직이지 않게 했다.

발표 갤러리의 자막은 1장에만 있었다. 2장부터는 대본을 받아 문장 자막을 넣었는데, 맞춰 보니 음성과 그림이 5장부터 한 쪽씩 어긋나 있었다. 그 사이트 갤러리의 쪽 번호(음성 파일 이름)와 발표 PDF의 쪽 번호가 5쪽부터 하나씩 차이 났던 것이다. 장마다 갤러리 쪽(음성)과 PDF 쪽(그림)을 따로 적어 맞췄고, 마지막 대본 없는 장은 맺음말 쪽으로 바꿨다. 자막은 원래 어림 시간으로 도는 CSS 애니메이션이라 음성과 따로 놀았다. 이제 음성이 나오면 그 재생 위치를, 아니면 흐른 시간을 매 프레임 재서 지금 문장만 보이고 읽은 낱말이 강조색으로 바뀐다(일시정지·장 넘기기에도 그대로 맞는다. 처음엔 회색에서 검정으로 진해지게 했는데 둘이 잘 갈리지 않았다). 재생·음성·자막 단추는 아이콘 폭을 고정해 눌러도 크기가 바뀌지 않고, 음성 출처 글은 길어지면 말줄임으로 한 줄에 둔다. 음성 만들기 줄의 안내 글만 아래로 처져 있던 것은, 장 타일의 글에 건 여백 규칙(`.cr-tile p`)이 타일 안에 든 데모의 문단에까지 번졌기 때문이라 타일 자신의 글에만 걸리게 좁혔다. 아이콘도 Apple 제품 페이지처럼 상자 없이 강조색의 큰 기호를 칸 왼쪽 위에 두는 모양으로 통일했고, 보안 장은 한 칸씩 들여 쌓던 층을 같은 모양의 카드 격자로 바꾸고 바깥부터 몇 겹째인지 머리말로 남겼다. 구조도는 처음에 그 사이트 문서의 그림을 그대로 붙였는데, 그림 한 장으로는 무엇이 무엇을 부르는지 읽기 어려웠다. 그래서 "한눈에 보는 구조" 장에 직접 그렸다. 사용자 → 앱(Next.js) → 데이터와 바깥 서비스 세 단에 상자를 두고, 상자 사이 선은 스크립트가 상자 자리를 재서 긋는다(창 크기나 줄바꿈이 바뀌면 다시 긋는다). 상자에 마우스를 올리거나 초점을 두면 이어진 선과 상자만 강조색으로 남고 선 위로 흐름이 지나가며, 배포·검사 같은 곁가지는 점선이다. 좁은 창에서는 세 단을 위아래로 쌓는다. 테마 미리보기의 토러스는 CSS 그라데이션으로 흉내 낸 고리가 쉬지 않고 돌아 산만했다. 실제 홈 캡처에서 3D 토러스를 오려 내 라이트·다크 그림을 모드마다 바꿔 끼우고 돌리지 않는다. NewPick 로고와 아이콘은 작은 PNG(324×62, 76×76)를 늘려 써서 흐렸다. 로고는 같은 꼴의 글꼴(Abril Fatface)에서 글자 윤곽을 뽑고, 아이콘은 원본 픽셀을 재서 N의 사선이 P의 기둥으로 이어지는 모양을 도형으로 다시 그려 둘 다 SVG로 바꿨다.

관리자와 CMS 장은 묶음 앞에 "01–03" 같은 번호를 달았는데 쓸모없이 딱딱해서 빼고, 묶음 이름 아래 한 줄 소개를 달았다. 그리고 묶음마다 맨 앞 큰 칸을 그림 대신 직접 만져 보는 도식으로 바꿨다. "세 겹 자동 저장"은 글을 고치면 브라우저 저장 줄이 바로 반짝이고, 손을 떼면 3초 막대가 차오른 뒤 서버 수정본 수가 오르고, 떠나기를 누르면 sendBeacon 줄이 켜진다. "다른 화면에서 먼저 저장"을 켜고 저장하면 열 때 받은 버전과 서버 버전이 달라 409로 막힌다. "글 한 편의 일생"은 초안을 예약하고, pg_cron이 발행하고, 고쳐 저장할 때마다 버전이 오르고, 지우면 휴지통에서 30일(인기 글은 90일) 뒤 정리 작업이 지우는 동안 published·scheduled_at·version·deleted_at·purge_after 칼럼 값이 바뀌는 모습을 보여 준다. 이야기도 더했다. 소통 묶음에는 로그인 없는 댓글(닉네임 섞기, 이모지 반응 여덟 가지, 같은 브라우저는 저장된 식별자로·다른 기기는 비밀번호로 확인, 지워도 원문을 보존해 관리자가 되살림)과 Resend 메일(답글 알림, 초대, 새 기기 확인, DB가 직접 보내는 예약 발행 알림)이 화면에 들어오면 하나씩 도착하는 메일함을, 권한 묶음에는 GitHub 로그인과 초대를 두었다. 초대받은 사람·모르는 사람·소유자 가운데 하나를 고르면 /auth/callback이 소유자 메일인지, 이미 역할이 있는지, 초대 행이 있는지 차례로 보고, 하나도 아니면 계정을 지운다. 칸에 마우스를 올리면 살짝 떠오른다. "누가 무엇을 할 수 있나"도 표 그림 대신 직접 해 보게 했다. 역할(소유자·관리자·저자·방문자)을 고르면 그 칸이 강조되고 할 수 없는 줄은 옅어지며, 동작을 누르면 RLS가 app_metadata의 역할을 읽어 허용하거나, API가 확인을 빠뜨려도 DB가 막는다는 판정이 붙는다. "글 한 편의 일생"은 휴지통 정리 같은 설명 줄이 뜰 때마다 카드 키가 바뀌어, 설명 줄 자리를 늘 비워 두게 했다. 그리고 그 사이트에 있지만 빠져 있던 두 가지를 더했다. 소통 묶음의 이모지 키친은 설정의 "조합" 창처럼 이모지 두 개를 골라 Google Gboard가 섞어 둔 그림을 보여 준다. 조합 목록은 그 사이트가 빌드 때 만든 meta.json·pairs.bin(이모지 619개)에서 데모용 여덟 개의 짝만 뽑아 넣었다. AI 장의 "공급자 고르기와 대체, 사용량"은 기능마다 공급자 차례를 바꾸고, 대체를 켜고 끄고, 공급자를 세 번 실패시켜 꺼 본 뒤 요청을 보내 어느 공급자가 받는지 본다. 이번 달 사용량은 무료 한도가 알려진 공급자만 막대로 견준다(Google 번역 50만 자, Google TTS는 무료 100만 바이트 가운데 앱 상한 80만). 공급자 데모는 처음에 "실패" 단추로만 공급자를 끌 수 있어 실제와 달랐다. 이제 요청을 보내면 공급자마다 그 사이트처럼 확률로 성공하거나 시간 초과·서버 오류·키 오류로 실패하고, 한도를 넘을 요청은 한도 초과로 막힌다. 성공하면 그 공급자의 이번 달 사용량이 오르고, 지나간 길(DeepL 한도 초과 → Google Translate +1,800자)이 남는다. 실패는 원인별로 세어 키·한도 문제는 3번, 일시 오류는 5번 이어지면 꺼진다. "한눈에 보는 구조"는 상자를 세 단으로 늘어놓은 그림이라 요청이 어디로 가는지 보이지 않았다. MacFolio 페이지의 "요청이 지나는 길"처럼 SVG로 다시 그려, 그림이 화면에 멈춘 동안 스크롤한 만큼 방문자·관리자 → Next.js → Auth·PostgreSQL·AI·Resend 차례로 상자가 켜지고 화살표가 이어진다. 데이터베이스는 원통, 사람이 쓰는 화면은 브라우저 창 모양이고, DB가 pg_cron으로 직접 보내는 메일과 GitHub Actions의 배포는 옅은 곁가지 선으로 그렸다. 몽이는 마우스를 올리면 아직 깜빡였는데, 표정 그림을 바꿀 때 나가는 그림과 들어오는 그림이 함께 옅어져 그 사이가 비쳤기 때문이었다. 들어오는 표정이 다 보인 뒤에 나가는 표정이 사라지게 하고, 올렸을 때는 튀지 않게 했다. 말풍선은 몽이가 화면 위쪽에 설 때 위로 잘렸고 긴 문장은 옆으로 넘쳤다. 몽이가 말풍선 키만큼 아래에 서게 하고, 왼쪽에 남은 폭을 넘으면 줄을 바꾼다. 그래도 무작위만으로는 겪을 수 있는 경우가 들쭉날쭉해서, 공급자마다 성향을 미리 정해 두었다. DeepL은 무료 한도 직전이라 열 번쯤 보내면 한도 초과로 막히고, Google 번역은 자주 429·503을 내 다섯 번 이어지면 꺼지며, Claude는 크레딧이 바닥나 결제 필요로, OpenAI는 한도 초과·키 만료로 실패한다. NanoBanana는 무료 한도가 없는 유료 공급자라 키를 넣지 않은 상태로 두어 실패로 세지 않고 건너뛰고, Google TTS는 앱 상한 80만 바이트 직전이라 한 번 더 쓰면 그다음부터 보내지 않는다. "다음 달로 넘기기"를 누르면 사용량이 0부터 다시 시작하고 한도·일시 오류로 꺼진 공급자는 다시 시도하지만, 키·결제 문제로 꺼진 공급자는 그대로 남아 직접 다시 켜야 한다. Safari 주소창은 모서리를 캡슐 모양으로 둥글렸다.

Safari 탭은 처음에 만든 순서대로였는데, 보는 사람이 가장 먼저 봐야 할 것부터 놓았다: 혼자 설계하고 운영 중인 HYEONIVERSE, 이 사이트 MacFolio, 팀 프로젝트 뉴픽·큐알유·WTD·새싹 농장, 교육 과정 순이다. GitHub 앱의 고정 저장소, Finder, 터미널의 `project` 번호도 같은 목록을 따른다.

번역·요약·커버 데모도 정해 둔 결과를 보여 주는 흉내였다. 음성 만들기처럼 실제로 돌게 바꿨다. MacFolio API에 `/translate`(DeepL → Google), `/summary`(Gemini, 한국어·영어 요약), `/cover`(NanoBanana → Hugging Face FLUX, 16:9)를 두고, 그 사이트와 같은 공급자 차례와 같은 키 이름을 쓴다. 번역은 방문자가 한국어 칸 세 개를 고쳐(합쳐 200자) EN을 누르면 어느 공급자가 번역했는지와 함께 채워지고, 요약은 본문(800자)을 고쳐 발행하면 두 언어 요약이 붙고, 커버는 제목(60자)과 스타일을 골라 그린다. 번역과 커버는 음성처럼 공급자를 눌러 막아 두면 다음 공급자로 넘어가는 모습을 실제 결과로 본다. 비용 때문에 데모마다 해시한 IP당 하루 3번, 사이트 전체 하루 50번(커버는 10번)만 받고, 모든 공급자가 실패하면 쓴 횟수를 돌려준다. 하루 횟수 세기, 막는 말, 공급자 실패 사유는 음성과 함께 쓰는 한 곳(`common/demo.ts`)으로 모았다. 그 뒤 커버 데모에서는 NanoBanana를 뺐다. 그림 한 장마다 값을 치르고 매달 다시 채워지는 무료 한도가 없어서다. 대신 이미 프론트엔드와 터널에 쓰는 Cloudflare의 Workers AI(매일 무료 할당이 다시 채워진다)로 같은 FLUX.1 schnell을 먼저 부르고, 실패하면 Hugging Face로 넘긴다. 두 곳을 이어 시도해도 터널의 100초 안에 끝나게 각각 45초에서 끊고, 상한은 IP마다 하루 1번, 사이트 전체 5번으로 낮췄다.

- **뉴픽**: 로그인 없이 해 보는 AI 체험, 요약에 쓴 원문 기사 카드, 팝업에서 리다이렉트로 바꾼 로그인, 첫 화면 데이터를 서버에서 먼저 받는 구조, Hydration 오류 다섯 번을 더했다. "(protected) 경로로 묶어 로그인한 사람만 들어온다"는 문장은 그 가드를 나중에 지웠으므로 실제 동작(로그아웃하면 홈으로)에 맞게 고쳤다.
- **WTD**: 맡은 일이 "백엔드 연동, 드래그 앤 드롭"에 머물러 있었지만, 커밋을 보면 114개 중 94개로 뼈대, 상태 관리, 로그인, 비회원 할 일 옮기기, 루틴 전체를 맡았다. 로그인과 동기화, 루틴을 에픽으로 더하고, 폴더 구조도 실제 파일(taskApi·routineApi, utils, AuthContext)에 맞췄다.
- **큐알유**: 서버 없이 지키는 데이터(목록을 열지 않는 길잡이 문서, 복합 색인 0개, 드롭다운 값과 색인 라벨이 어긋났던 버그, 사진 150KB 상한)를 장으로 더하고, 앱 화면 모음을 옆으로 넘겨 본다. 앞으로 할 일(다음 단계)은 포트폴리오에서 보여 줄 내용이 아니라서 모든 페이지에서 뺐다.

장이 여덟 개로 늘자 시험이 하나 깨졌다. 마지막 장(기술 사양)을 눌러 내려가도 차례에 "읽는 중"이 켜지지 않았다. 지금 읽는 장은 `IntersectionObserver`로 화면 가운데 띠에 걸린 장을 찾는데, 기준을 페이지 전체 화면으로 두어서 창이 작으면 그 띠가 Safari의 스크롤 칸 바깥에 놓였다. 기준을 스크롤 칸으로 바꾸고, 맺음말까지 내려와도 차례에서는 마지막 장을 읽는 중으로 둔다.
