[트래픽 분석 3](/memo/analytics-activity-monitor)까지는 '활동 상태 보기'가 관리자 전용이었다. 방문자가 열면 잠긴 화면만 보였다. 써 보니 아까웠다. 포트폴리오를 보러 온 사람에게 "직접 만든 분석이 이렇게 돈다"를 보여 줄 수 있는 앱인데, 정작 그 사람은 볼 수 없었다.

## 무엇을 공개하나

전부 공개할 수는 없었다. 걸린 것은 둘이었다.

- **캠페인(`utm_campaign`):** 이력서나 지원서에 붙이는 링크에 보통 회사 이름을 넣는다. 그대로 공개하면 어디에 지원했는지가 드러난다. 들어온 곳의 주소(호스트)도 비슷하다
- **실시간:** 방문 하나하나의 흐름과 가린 IP가 있다. 합계가 아니라 사람 단위다

그래서 이렇게 나눴다.

| 누구나                                                                                                                                                  | 관리자만                                              |
| ------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 개요(방문·순방문자·앱 열기·머문 시간, 그래프), 앱·글·바깥 링크, 나라·기기·브라우저·OS·언어, 들어온 곳의 **묶음**(검색·소셜·직접·링크), 블로그 글 조회수 | 들어온 곳의 주소, `utm_source`·`utm_campaign`, 실시간 |

## 서버가 나눈다

화면에서 감추는 것으로는 부족하다. 숫자는 이미 브라우저에 와 있으니 개발자 도구로 볼 수 있다. 그래서 요약 경로(`GET /analytics/summary`)를 누구나 부르게 열되, **서버가** 관리자 세션을 보고 줄 표를 정한다. 관리자가 아니면 들어온 곳의 주소와 utm 표를 빈 목록으로 주고, 응답에 `scope: 'public'`을 적는다. 실시간(`/analytics/live`)은 그대로 관리자만 부른다.

들어온 곳의 묶음(검색·소셜·직접·링크)은 화면에서 나누던 것을 서버로 옮겼다. 방문자에게 주소를 주지 않으니 묶는 일도 서버가 해야 한다. 규칙이 한 곳에만 있게 되었다. 지난 날의 집계는 주소별로 저장돼 있어서, 요약을 낼 때 주소를 묶음으로 바꿔 더한다. 저장된 집계를 다시 만들 필요가 없다.

누구나 부르는 경로가 되니 부하도 생각했다. 1년치를 계속 요청해도 DB를 매번 읽지 않게, 방문자용 요약은 같은 기간이면 1분 동안 같은 값을 준다. 요약을 열 때 지난 날을 모으는 일도 방문자 요청에서는 5분에 한 번만 한다(날이 바뀌었으면 바로). 관리자는 드물게 여니 열 때마다 모은다.

화면은 서버가 준 `scope`를 보고 그린다. 방문자에게는 개요의 '가장 많이 들어온 곳' 대신 묶음 표를, 유입 경로 탭에는 묶음 표와 "관리자만 볼 수 있습니다" 안내를, 실시간 탭에는 안내와 로그인 단추만 보여 준다. 실시간은 서버에 묻지도 않는다. 앱 정보의 `adminOnly`와 Launchpad·홈 화면·Finder에서 감추던 코드는 걷어 냈다.

## 블로그 글 조회수

글을 볼 때마다 `item` 이벤트(`memo/<글 주소>`)가 이미 가고 있었다. 숫자를 세는 규칙 하나와 경로 하나를 더했다.

- **한 방문에서 같은 글은 한 번.** 메모에서 글 사이를 오가면 같은 글을 여러 번 고르게 된다. 하루치를 모을 때 (방문, 글) 쌍마다 한 번만 센다
- **`GET /analytics/views?app=memo`:** 글마다 전체 기간 조회수. 지난 날은 날마다 모은 숫자의 합, 오늘은 이벤트에서 바로 센다. 누구나 부르고 1분 동안 같은 값을 준다

메모는 앱을 열 때 이 값을 한 번 받아, 글 머리의 날짜 옆에 "조회 42"를 붙인다. 서버가 없으면 붙이지 않는다. '활동 상태 보기'의 앱·글 탭에는 "블로그 글 조회수 (전체 기간)" 표를 더하고, 글 주소 대신 제목을 보여 준다. 기간별 "글·프로젝트" 표도 메모 글은 제목으로 바꿨다.

## 탭을 바꾸면 정렬이 따라왔다

화면 테스트를 고치다가 버그를 하나 찾았다. 유입 경로 탭에서 표를 이름순으로 바꾼 뒤 앱·글 탭으로 가면, 블로그 글 조회수 표가 많은 순이 아니라 이름 역순으로 나왔다.

탭마다 표가 다르지만, React가 보기에는 **같은 자리의 같은 컴포넌트**였다. 그래서 표 안의 정렬 상태를 그대로 두고 내용만 바꿨다. 탭 본문에 `key={tab}`을 주어 탭이 바뀌면 새로 그리게 했다. 시험은 원래 있던 것이 그대로 잡는다: 이름순으로 바꾼 뒤 앱·글 탭에서 많은 순인지 본다.

## 시험

- API 단위: 한 방문에서 같은 글은 한 번, 들어온 곳 묶음
- API e2e: 방문자 요약에 주소·utm이 없고 묶음은 있는지(응답 전체에 `kakao-2026` 같은 값이 없는지), 관리자 요약에는 있는지, 실시간은 관리자만, 글 조회수(지난 날의 합 + 오늘, 같은 방문의 같은 글은 한 번)
- 화면: 방문자가 Launchpad에서 열어 개요·묶음을 보고 유입 경로 상세와 실시간은 안내만, 관리자의 글별 조회수 표(제목), 메모 글 머리의 "조회 42"와 서버가 없을 때 감추기
