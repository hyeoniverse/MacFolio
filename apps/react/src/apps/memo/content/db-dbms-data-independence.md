2023년 봄 학기 데이터베이스기초 강의 노트와 과제를 장별로 정리한 연재의 첫 글이다. 각 글 끝의 "과제로 풀어 본 문제"에는 연습문제와 실습에서 쓴 답을 옮기고, 다시 확인해 틀린 답은 고쳐 적었다. 1장(정보 환경)과 2장(데이터베이스 관리 시스템)을 다룬다. 교재는 "데이타"라는 표기를 쓰지만 이 연재에서는 "데이터"로 적는다.

## 데이터와 정보

| 용어              | 뜻                                                                                                             |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| 데이터(data)      | 관찰이나 측정으로 수집한 사실(fact)이나 값(value: 수치, 문자열)                                                |
| 정보(information) | 의사결정에 쓸 수 있도록 데이터를 해석하거나 데이터 사이의 관계를 밝힌 결과. 데이터에 의미(meaning)가 더해진 것 |

==데이터를 처리(P)한 결과가 정보(I)이므로== `P(D) = I`로 쓴다. 데이터에서 정보를 추출하는 방법을 정보 처리 또는 자료 처리라고 한다.

**정보 시스템(information system)** 은 한 기관을 위해 데이터를 수집·조직·저장하고 정보를 생성·분배하는 수단이다. 수많은 데이터 가운데 그 기관의 의사결정에 필요한 데이터만 추출해 처리한다는 점이 핵심이다. 정보 시스템 안에서 한 부서를 위한 서브 시스템을 응용 시스템(application system)이라 하고, 응용 시스템은 응용 프로그램(application program)으로 구성된다. 대학의 종합정보시스템 안에 학사·수강신청·성적 같은 응용 시스템이 있는 구조가 그 예다.

정보 시스템은 용도에 따라 다음처럼 나뉜다.

- **경영 정보 시스템(MIS)**: 기획(planning), 운영(operation), 통제(control)를 지원한다.
- **의사 결정 지원 시스템(DSS)**: 넓은 의미의 정보 시스템으로, 다음을 포함한다.
  - 데이터 웨어하우스(data warehouse): 정보 저장소(information repository)
  - 데이터 마이닝(data mining): 데이터에서 규칙이나 패턴을 찾는 지식 발견
  - 지식 관리 시스템(knowledge management system)

## 데이터 처리 시스템

데이터를 처리하는 방식은 시간 관점에서 일괄 처리와 온라인(실시간) 처리로, 지리 관점에서 분산 처리로 나눈다.

|                        | 일괄 처리(batch)                                                   | 온라인 처리(online)                                |
| ---------------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 처리 시각              | 원시 데이터(raw data)를 수집·분류해 파일에 저장한 뒤 한꺼번에 처리 | 요청이 들어온 즉시 처리                            |
| 중심                   | 시스템 중심                                                        | 사용자 중심                                        |
| 시스템 성능            | 높다                                                               | 낮다                                               |
| 처리 비용              | 낮다                                                               | 높다                                               |
| 사용자가 기다리는 시간 | 길다                                                               | 짧다                                               |
| 필요한 장치            |                                                                    | 통신 제어기(communication controller)              |
| 적합한 업무            | 순차 접근 업무 (예: 은행 일일 정산)                                | 즉시 응답이 필요한 업무 (예: 인터넷뱅킹 계좌 이체) |

온라인 처리는 보수·유지·회복에 드는 오버헤드도 크다.

**분산 처리(distributed processing)** 는 지리적으로 떨어진 여러 컴퓨터 시스템(분산 처리기)이 통신 네트워크로 연결되어 분산 데이터베이스를 함께 처리하는 방식이다. 보통 요청하는 쪽(클라이언트)과 요청을 받아 처리하는 쪽(서버)으로 나뉜 클라이언트/서버 형태로 운영한다.

"데이터베이스"라는 용어는 1963년 6월 미국 SDC(System Development Corporation)가 연 제1차 심포지엄 "Development and Management of a Computer-centered Data Base"에서 처음 쓰였고, 1965년 9월 제2차 심포지엄 "Computer-centered Data Base Systems"에서 데이터베이스 시스템이라는 말로 이어졌다.

## 파일 시스템의 한계

DBMS(DataBase Management System)는 데이터베이스를 통제·운영하는 소프트웨어다. DBMS가 등장하기 전에는 운영체제가 지원하는 파일 시스템으로 데이터를 처리했다. 파일 중심 데이터 처리 시스템의 특징은 다음과 같다.

1. 각 응용 프로그램이 논리적 파일 구조를 정의하고, 그 구조를 직접 물리적 파일 구조로 구현한다.
2. 각 응용 프로그램이 물리적 데이터 구조에 접근하는 방법을 직접 구현한다.
3. 각 사용자가 데이터와 그 데이터를 처리하는 프로그램을 모두 관리한다.
4. 응용 프로그램끼리 데이터를 공유할 수 없다.

응용 프로그램과 파일이 1:1로 대응하므로, 인사 프로그램과 급여 프로그램이 각자 "사원" 파일을 가진다. 데이터가 적을 때는 문제가 없지만, 프로그램과 파일의 수가 늘면 두 가지 문제가 생긴다.

### 데이터 종속성(data dependency)

응용 프로그램과 데이터가 서로 의존하는 관계다. 데이터의 구성 방법이나 접근 방법을 바꾸면 그 데이터를 쓰는 응용 프로그램도 함께 고쳐야 한다. 예를 들어 사원 파일에 필드 하나를 추가하면 그 파일을 읽는 모든 프로그램의 레코드 구조 정의를 수정해야 하므로, 프로그램 관리가 어려워진다.

### 데이터 중복성(data redundancy)

한 시스템 안에서 같은 내용의 데이터가 여러 파일에 중복 저장되는 상태다. 중복은 다음 네 가지 문제를 낳는다.

| 문제                | 내용                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------- |
| 일관성(consistency) | 한 파일의 값만 바뀌고 다른 파일의 값은 그대로 남아, 같은 데이터가 서로 다른 값을 가진다 |
| 보안성(security)    | 같은 데이터가 여러 곳에 있어 모든 사본에 같은 수준의 보안을 적용하기 어렵다             |
| 경제성(economics)   | 같은 데이터를 여러 번 저장해 저장 공간과 갱신 비용이 늘어난다                           |
| 무결성(integrity)   | 데이터가 정확하다는 보장이 약해진다                                                     |

여러 응용 프로그램이 공동으로 쓰는 접근 루틴을 둔 파일 관리 시스템(file management system)이 이 문제를 줄이려고 등장했지만, 데이터 구조 정의가 여전히 프로그램 안에 있어 근본적인 해결이 되지 못했다. DBMS는 이 종속성과 중복성을 해결하기 위해 등장했다.

![파일 시스템과 DBMS의 데이터 접근 구조 비교](./images/db-dbms-data-independence-filesystem.svg '파일 시스템은 프로그램마다 파일을 갖고, DBMS는 통합 데이터베이스를 중재한다')

## DBMS의 정의와 필수 기능

DBMS는 ==**응용 프로그램과 데이터 사이의 중재자로서, 모든 응용 프로그램(사용자)이 데이터베이스를 공유할 수 있게 관리하는 범용 소프트웨어 시스템**==이다. 응용 프로그램은 파일에 직접 접근하지 않고 DBMS에 요청한다.

DBMS는 세 가지 필수 기능을 제공한다.

### 1. 정의(definition) 기능

하나의 저장 구조(storage structure)로 여러 사용자의 요구를 지원할 수 있도록 데이터를 조직(organize)하는 기능이다. 다음 세 가지를 명세해야 한다.

- 데이터의 **논리적 구조**(logical structure): 데이터 모델에 맞춘 구조
- 데이터의 **물리적 구조**(physical structure): 저장 장치에 저장되는 구조
- 논리적 구조와 물리적 구조 사이의 **사상(mapping)**

==이 사상이 뒤에서 설명할 데이터 독립성을 구현하는 수단이다.==

### 2. 조작(manipulation) 기능

사용자와 데이터베이스 사이의 인터페이스다. 검색(retrieve), 갱신(update), 삽입(insert), 삭제(delete)를 체계적으로 수행하며, 데이터 언어로 표현한다. 데이터 언어는 다음 조건을 갖춰야 한다.

- 사람이 이해하기 쉽고 자연스럽게 쓸 수 있다.
- 원하는 연산을 명세할 수 있다.
- 효율적으로 처리된다.

### 3. 제어(control) 기능

데이터의 정확성(correctness)과 보안성(security)을 유지하는 기능이다.

| 요건                                | 내용                                                               |
| ----------------------------------- | ------------------------------------------------------------------ |
| 무결성(integrity) 유지              | 언제 어디서 검색하든 내용이 정확해야 한다                          |
| 보안(security)·권한(authority) 검사 | 권한이 없는 사용자의 접근을 막아 데이터베이스가 오염되지 않게 한다 |
| 병행 수행 제어(concurrency control) | 여러 사용자가 동시에 접근해도 결과가 정확하다                      |
| 복구(recovery)                      | 장애가 발생해도 백업과 로그로 정확한 상태를 빠르게 회복한다        |

## DBMS의 장단점

| 장점                       | 내용                                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 데이터 중복 최소화         | 데이터를 통합해 중복을 사전에 통제한다. 중복을 완전히 없애는 것이 아니라, 성능 때문에 필요한 중복은 최소한으로 두고 DBMS가 제어한다(제어된 중복)             |
| 데이터 공유                | 같은 데이터를 여러 구조로 제공하므로, 새 응용 프로그램은 데이터 구성에 신경 쓰지 않고 응용 자체만 개발할 수 있다                                             |
| 일관성 유지                | 중복을 제어해 같은 데이터가 서로 다른 값을 갖지 않게 한다                                                                                                    |
| 무결성 유지                | 중복이 없더라도 허용되지 않는 값이 들어올 수 있으므로, 접근할 때마다 유효성을 검사한다                                                                       |
| 보안 보장                  | 데이터베이스를 중앙에서 관리해 정당한 사용자와 허용된 연산만 통과시킨다. 같은 데이터가 여러 파일에 흩어진 파일 시스템보다 보안 수준을 일정하게 유지하기 쉽다 |
| 표준화                     | 데이터 형식, 처리 방식, 문서화 양식의 표준을 기관 전체에 적용하기 쉽다                                                                                       |
| 기관 전체 데이터 요구 조정 | 모든 응용 시스템의 데이터 요구를 통합 분석해, 상충하는 요구를 조정한 구조로 조직한다                                                                         |

| 단점                        | 내용                                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------- |
| 운영비 오버헤드             | 소프트웨어 구매비, 하드웨어, 운영 인력의 인건비가 든다                                 |
| 특정 응용 프로그램의 복잡화 | 응용 프로그램이 데이터 구조를 직접 다루지 않고 DBMS를 거쳐야 한다                      |
| 복잡한 백업과 복구          | 구조가 복잡하고 여러 사용자가 동시에 쓰므로, 장애 원인과 상태를 파악하기 어렵다        |
| 시스템 취약성               | 통합 시스템이라 일부 장애가 전체 시스템 정지로 이어져 신뢰성과 가용성이 떨어질 수 있다 |

## DBMS의 궁극적 목적: 데이터 독립성

DBMS가 논리적 구조와 물리적 구조 사이의 사상을 정의하는 이유는 **데이터 독립성(data independence)** 을 얻기 위해서다. 데이터 독립성은 데이터 종속성의 반대 개념이다.

| 종류                 | 정의                                                                                    | 효과                                |
| -------------------- | --------------------------------------------------------------------------------------- | ----------------------------------- |
| 논리적 데이터 독립성 | 응용 프로그램에 영향을 주지 않고 논리적 데이터 구조를 바꿀 수 있다                      | 응용 프로그램을 효율적으로 개발한다 |
| 물리적 데이터 독립성 | 응용 프로그램과 논리적 데이터 구조에 영향을 주지 않고 물리적 데이터 구조를 바꿀 수 있다 | 저장 장치를 효율적으로 개선한다     |

데이터베이스에는 데이터가 최소한의 중복으로 저장되고, 기관 전체 관점에서 각 개체(entity)는 하나의 통합된 논리적 구조를 가진다. 각 응용 프로그램은 그중 자기가 필요한 일부만 다르게 보지만, 사상으로 연결되어 있어 본질적으로 같은 데이터다. 그래서 논리적 구조 사상은 논리적 데이터 독립성을, 물리적 구조 사상은 물리적 데이터 독립성을 지원한다. ==구조를 바꿔도 사상만 고치면 응용 프로그램은 그대로 동작한다.== 이 구조는 다음 글의 3단계 스키마에서 구체화된다.

## DBMS의 발전 과정

모든 DBMS는 개체와 관계를 정의하는 데서 설계를 시작하고, 구축 전에 데이터 모델로 논리적 구조를 확정한다. 어떤 데이터 모델을 쓰느냐에 따라 논리적 구조가 달라지며, 세대 구분도 데이터 모델을 기준으로 한다.

| 세대  | 시기           | 데이터 모델         | 대표 시스템                                                                                 |
| ----- | -------------- | ------------------- | ------------------------------------------------------------------------------------------- |
| 1세대 | 1960년대       | 네트워크, 계층      | IDS(GE, Charles Bachman 설계, 최초의 범용 DBMS), IMS(IBM)                                   |
| 2세대 | 1970\~1980년대 | 관계                | DB2, Oracle, Ingres, Sybase, Informix. PC 기반은 Access, FoxPro, dBase, Paradox, SQL Server |
| 3세대 | 1990년대 이후  | 객체지향, 객체-관계 | OODBMS, O-RDBMS                                                                             |

- **1세대**: 데이터베이스 구조와 DBMS의 필수 기능이 정의된 시기다. 표준이 없어 대형 컴퓨터 회사가 DBMS를 자체 제작해 판매했다. Bachman은 IDS를 설계하며 네트워크 데이터 모델의 기초를 놓았고, 레코드 사이의 관계를 그리는 데이터 구조도(data structure diagram)도 제안했다. IBM의 IMS는 계층 데이터 모델의 기초가 되었다.
- **2세대**: 1970년 IBM의 E. F. Codd가 관계 데이터 모델을 제안했다. 1980년대에 DBMS의 주류가 되었고, 기본 형태를 유지하며 지금까지 확장되고 있다. IBM이 관계 DBMS의 일부로 개발한 SQL(Structured Query Language)은 세계 표준 데이터베이스 언어가 되었다.
- **3세대**: 공학 설계, 이미지, 동영상, 공간 데이터, 시계열, 데이터 마이닝처럼 응용이 복잡해지면서 객체지향 프로그래밍에 기반한 객체지향 DBMS가 등장했다. 현재는 관계 모델에 객체 개념을 더한 객체-관계 DBMS가 함께 쓰인다.

## 과제로 풀어 본 문제

1장과 2장 연습문제에서 답을 정리해 둔 문항 가운데, 본문을 보충하는 것만 옮긴다.

**데이터베이스의 정의.** 데이터베이스는 한 조직(enterprise)의 여러 응용 시스템이 공용(shared)하기 위해 통합(integrated)·저장(stored)한 운영 데이터(operational data)의 집합이다. 정의에 들어 있는 네 단어가 각각 조건이다.

| 조건        | 뜻                                             |
| ----------- | ---------------------------------------------- |
| 통합 데이터 | 중복을 최소화하고, 중복이 있더라도 통제한다    |
| 저장 데이터 | 컴퓨터가 접근할 수 있는 저장 매체에 저장한다   |
| 운영 데이터 | 조직의 고유 기능을 수행하는 데 필요한 데이터다 |
| 공용 데이터 | 여러 응용 시스템이 공동으로 소유·유지·이용한다 |

**데이터베이스의 특성.** 실시간 접근성(질의에 실시간으로 응답), 계속적인 변화(삽입·삭제·갱신으로 상태가 바뀌는 동적 특성), 동시 공용(여러 사용자가 동시에 사용), 내용에 의한 참조(위치나 주소가 아니라 값으로 참조) 네 가지다. 사용자 입장에서는 레코드의 주소를 알 필요 없이 "학과가 컴퓨터인 학생"처럼 값으로 찾을 수 있다는 마지막 특성이 가장 중요하다.

**레코드 타입과 레코드 인스턴스.** `학생<학번, 이름, 학과>`처럼 필드 이름으로만 표현한 정의가 레코드 타입이고, `<1234, 홍길동, 컴퓨터>`처럼 실제 값으로 표현한 것이 레코드 인스턴스다. 학생을 기술하는 학번·이름·학과 사이의 관계는 개체 안의 속성 관계(묵시적), 학생과 교수 사이의 "지도"는 개체 사이의 개체 관계(명시적)다.

**데이터 중복은 완전히 제거해야 하는가.** 그렇지 않다. 성능 때문에 중복이 불가피한 경우가 있으므로 목표는 중복의 최소화다. 어떤 데이터가 어디에 중복되어 있는지 시스템이 알고 통제하는 제어된 중복이면 일관성을 유지할 수 있다.

**현재 DBMS의 세 기능.** 과제에서는 Oracle과 SQL Server를 예로 정리했다.

| 기능 | Oracle                             | SQL Server                               |
| ---- | ---------------------------------- | ---------------------------------------- |
| 정의 | 데이터베이스·테이블·인덱스 생성    | 데이터베이스·테이블·인덱스 생성          |
| 조작 | SELECT, INSERT, UPDATE, DELETE     | SELECT, INSERT, UPDATE, DELETE           |
| 제어 | 사용자 계정과 권한 관리, 성능 튜닝 | 사용자 계정과 권한 관리, 백업·복원, 복제 |

## 정리

- 파일 시스템에서는 응용 프로그램이 데이터 구조를 직접 정의해, 데이터 종속성과 중복성이 생긴다.
- DBMS는 응용 프로그램과 데이터 사이의 중재자로, 정의·조작·제어 세 기능을 제공한다.
- DBMS의 궁극적 목적은 데이터 독립성이고, 구현 수단은 논리적·물리적 구조 사이의 사상이다.
