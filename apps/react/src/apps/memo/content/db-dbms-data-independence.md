## 들어가기 전에

회사의 인사 프로그램과 급여 프로그램이 각자 "사원" 파일을 갖고 있다고 하자. 두 파일에는 같은 사원의 이름과 주소가 따로 저장되어 있다. 사원이 이사해 인사 담당자가 인사 파일의 주소를 고쳐도 급여 파일의 주소는 그대로 남고, 급여 명세서는 옛 주소로 발송된다. 사원 파일에 전화번호 필드 하나를 추가하는 작업도 간단하지 않다. 그 파일을 읽는 프로그램마다 레코드 형식을 직접 정의해 두었기 때문에, 프로그램을 모두 찾아 고치고 다시 컴파일해야 한다.

데이터베이스 관리 시스템(DBMS, DataBase Management System)은 이 두 문제를 해결하려고 등장한 소프트웨어다. 데이터를 한 곳에 통합해 저장하고, 응용 프로그램은 파일을 직접 읽는 대신 DBMS에 "사번이 E01인 사원의 주소"처럼 필요한 데이터를 요청한다. 저장 형식이 바뀌어도 DBMS가 요청과 저장 형식 사이의 대응 관계만 고치면 응용 프로그램은 그대로 동작한다. 이 성질이 데이터 독립성이다.

이 글이 답하려는 질문은 세 가지다. 데이터베이스는 단순한 파일 묶음과 무엇이 다른가. 파일 시스템에서 데이터 종속성과 중복성은 왜 생기고 어떤 문제를 낳는가. DBMS는 어떤 기능으로 데이터 독립성을 제공하는가.

| 순서 | 내용                                                             |
| ---- | ---------------------------------------------------------------- |
| 1    | 데이터와 정보, 정보 시스템, 일괄·온라인·분산 처리                |
| 2    | 데이터베이스의 정의, 특성, 논리적 구성 요소와 구조               |
| 3    | 파일 시스템의 데이터 종속성과 데이터 중복성                      |
| 4    | DBMS의 정의, 정의·조작·제어 기능, 장단점                         |
| 5    | 사상으로 구현하는 데이터 독립성, DBMS의 세대별 발전              |
| 6    | 연습문제 풀이(정보 환경 22문항, 데이터베이스 관리 시스템 11문항) |

국내 데이터베이스 교재 가운데에는 "데이타", "화일"로 표기하는 책이 있지만 이 글에서는 "데이터", "파일"로 적는다.

## 데이터와 정보

| 용어              | 뜻                                                                                                             |
| ----------------- | -------------------------------------------------------------------------------------------------------------- |
| 데이터(data)      | 관찰이나 측정으로 수집한 사실(fact)이나 값(value: 수치, 문자열)                                                |
| 정보(information) | 의사결정에 쓸 수 있도록 데이터를 해석하거나 데이터 사이의 관계를 밝힌 결과. 데이터에 의미(meaning)가 더해진 것 |

"학번 100, 데이터베이스, 95점"이라는 성적 레코드는 데이터다. 이런 레코드 수천 개를 과목별로 모아 "데이터베이스 과목의 평균은 82점이고 작년보다 6점 낮다"고 계산한 결과는 교과 과정을 조정할지 판단하는 근거가 되므로 정보다. ==데이터를 처리(P)한 결과가 정보(I)이므로== `P(D) = I{:math}`로 쓴다. 데이터에서 정보를 추출하는 방법을 정보 처리 또는 자료 처리라고 한다.

### 정보 시스템

정보 시스템(information system)은 한 기관을 위해 데이터를 수집·조직·저장하고 정보를 생성·분배하는 수단이다. ==수많은 데이터 가운데 그 기관의 의사결정에 필요한 데이터만 추출해 처리한다는 점이 핵심이다.== 정보 시스템 안에서 한 부서를 위한 서브 시스템을 응용 시스템(application system)이라 하고, 응용 시스템은 응용 프로그램(application program)으로 구성된다. 대학의 종합정보시스템 안에 학사·수강신청·성적 같은 응용 시스템이 있고, 성적 응용 시스템 안에 성적 입력·성적표 출력 프로그램이 있는 구조가 그 예다.

정보 시스템은 용도에 따라 다음처럼 나뉜다.

| 종류                       | 용도                                                                                                                                                                                                                                 |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 경영 정보 시스템(MIS)      | 기획(planning), 운영(operation), 통제(control)를 지원한다                                                                                                                                                                            |
| 의사 결정 지원 시스템(DSS) | 넓은 의미의 정보 시스템으로, 데이터 웨어하우스(data warehouse: 정보 저장소, information repository), 데이터 마이닝(data mining: 데이터에서 규칙이나 패턴을 찾는 지식 발견), 지식 관리 시스템(knowledge management system)을 포함한다 |

![현실세계→데이터→처리기(저장 데이터)→정보→의사결정으로 이어지는 정보 시스템 구성도](./images/db-dbms-data-independence-note-02.jpg '현실 세계에서 수집한 데이터가 저장 데이터로 처리되어 의사결정에 쓰이는 정보가 된다')

## 데이터 처리 시스템

데이터를 처리하는 방식은 시간 관점에서 일괄 처리와 온라인(실시간) 처리로, 지리 관점에서 분산 처리로 나눈다. 은행을 예로 들면, 하루 동안 쌓인 거래를 영업 종료 후 한꺼번에 정산하는 작업은 일괄 처리이고, 고객이 인터넷뱅킹에서 이체 버튼을 누르는 즉시 잔액을 바꾸는 작업은 온라인 처리다.

|                        | 일괄 처리(batch)                                                   | 온라인 처리(online)                                |
| ---------------------- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 처리 시각              | 원시 데이터(raw data)를 수집·분류해 파일에 저장한 뒤 한꺼번에 처리 | 요청이 들어온 즉시 처리                            |
| 중심                   | 시스템 중심                                                        | 사용자 중심                                        |
| 시스템 성능            | 높다                                                               | 낮다                                               |
| 처리 비용              | 낮다                                                               | 높다                                               |
| 사용자가 기다리는 시간 | 길다                                                               | 짧다                                               |
| 필요한 장치            |                                                                    | 통신 제어기(communication controller)              |
| 적합한 업무            | 순차 접근 업무 (예: 은행 일일 정산)                                | 즉시 응답이 필요한 업무 (예: 인터넷뱅킹 계좌 이체) |

일괄 처리는 원시 데이터를 수집하고 분류·정리해 파일에 수록하는 사전 준비 작업이 필요하다. 온라인 처리는 단말기와 컴퓨터를 상시 연결해 두어야 하므로 보수·유지·회복에 드는 오버헤드가 크다.

분산 처리(distributed processing)는 지리적으로 떨어진 여러 컴퓨터 시스템(분산 처리기, dispersed processor)이 통신 네트워크(communication network)로 연결되어 분산 데이터베이스(distributed database)를 함께 처리하는 방식이다. 서울 본사와 부산 지사가 각자 서버와 데이터베이스를 운영하면서 서로의 데이터를 조회하는 구성이 그 예다. 보통 요청하는 쪽(클라이언트)과 요청을 받아 처리하는 쪽(서버)으로 나뉜 클라이언트/서버 형태로 운영한다.

## 데이터베이스

"데이터베이스"라는 용어는 1963년 6월 미국 SDC(System Development Corporation)가 연 제1차 심포지엄 "Development and Management of a Computer-centered Data Base"에서 처음 쓰였고, 1965년 9월 제2차 심포지엄 "Computer-centered Data Base Systems"에서 데이터베이스 시스템이라는 말로 이어졌다.

### 정의

> [!IMPORTANT]
> ==데이터베이스는 한 조직(enterprise)의 여러 응용 시스템이 공용(shared)하기 위해 통합(integrated)·저장(stored)한 운영 데이터(operational data)의 집합이다.==

정의에 들어 있는 네 단어가 각각 조건이다.

| 조건        | 뜻                                             | 대학의 예                                                    |
| ----------- | ---------------------------------------------- | ------------------------------------------------------------ |
| 통합 데이터 | 중복을 최소화하고, 중복이 있더라도 통제한다    | 학생 주소를 학사·장학·기숙사 업무가 따로 저장하지 않는다     |
| 저장 데이터 | 컴퓨터가 접근할 수 있는 저장 매체에 저장한다   | 종이 학적부가 아니라 디스크에 저장한 학생 레코드             |
| 운영 데이터 | 조직의 고유 기능을 수행하는 데 필요한 데이터다 | 수강 신청, 성적. 화면 출력용 임시 데이터는 포함하지 않는다   |
| 공용 데이터 | 여러 응용 시스템이 공동으로 소유·유지·이용한다 | 수강 신청 시스템과 성적 시스템이 같은 수강 데이터를 사용한다 |

### 특성

| 특성                                   | 내용                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------ |
| 실시간 접근성(real-time accessibility) | 질의를 실시간으로 처리(real-time processing)하고 응답한다                |
| 계속적인 변화(continuous evolution)    | 갱신(update)·삽입(insert)·삭제(delete)로 상태가 계속 바뀌는 동적 특성    |
| 동시 공용(concurrent sharing)          | 여러 사용자(multi-user)가 동시에 사용한다                                |
| 내용에 의한 참조(content reference)    | 데이터의 위치(location)나 주소(address)가 아니라 내용(contents)으로 참조 |

내용에 의한 참조는 "디스크 3번 블록의 7번째 레코드"가 아니라 "학과가 컴퓨터인 학생"처럼 값으로 데이터를 찾는다는 뜻이다. 수강 신청 기간에 수천 명이 같은 과목 데이터를 동시에 읽고 고치는 상황이 동시 공용과 계속적인 변화가 함께 일어나는 예다.

### 논리적 구성 요소

사용자 입장에서 데이터베이스는 개체와 관계의 집합이다.

```math
\text{데이터베이스} = \{\, \text{개체(entities)},\ \text{관계(relationships)} \,\}
```

개체(entity)는 표현하려는 유무형 정보의 객체(object)로, 정보의 단위(unit)다. 학생 한 명, 과목 하나가 개체다. 개체는 하나 이상의 속성(attribute)으로 구성되고, ==속성은 데이터의 가장 작은 논리적 단위(logical unit)다.== 학생의 학번·이름·학과가 속성이다. 같은 속성으로 기술되는 개체들의 모임이 개체 집합(entity set)이다. 속성 이름으로만 기술한 개체의 정의를 개체 타입(entity type), 속성마다 실제 값을 가진 개체 하나를 개체 인스턴스(entity instance)라 하며, 이 둘은 파일의 레코드 타입(record type)과 레코드 인스턴스(record instance)에 대응한다.

| 구분             | 학번 | 이름   | 학과   |
| ---------------- | ---- | ------ | ------ |
| 개체 타입 `학생` | 학번 | 이름   | 학과   |
| 개체 인스턴스    | 1234 | 홍길동 | 컴퓨터 |
| 개체 인스턴스    | 1235 | 김철수 | 전자   |

개체 인스턴스들을 모은 위 표의 아래 두 행이 `학생` 개체 집합이다.

관계(relationship)는 두 가지다.

| 관계                              | 범위                  | 표현   | 예                                  |
| --------------------------------- | --------------------- | ------ | ----------------------------------- |
| 속성 관계(attribute relationship) | 개체 내(intra-entity) | 묵시적 | 학생을 기술하는 학번·이름·학과 사이 |
| 개체 관계(entity relationship)    | 개체 간(inter-entity) | 명시적 | 학생과 교수 사이의 "지도"           |

속성 관계는 한 개체의 특성(properties)을 기술한다. 학번 1234와 이름 홍길동이 같은 행에 있다는 사실만으로 "1234번 학생의 이름은 홍길동"이 표현되므로 따로 적지 않아도 된다. 반면 "1234번 학생의 지도교수는 P1"은 두 개체 사이의 사실이라 지도 관계로 명시해야 한다.

### 논리적 구조와 물리적 구조

|           | 논리적 구조(logical organization)                                           | 물리적 구조(physical organization)                                               |
| --------- | --------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 관점      | 사용자                                                                      | 저장 장치(시스템)                                                                |
| 내용      | 데이터의 개념적 구조(conceptual structure), 논리적 배치(logical allocation) | 저장 장치에 저장된 실제 구조(actual structure), 물리적 배치(physical allocation) |
| 추가 정보 | 없음                                                                        | 인덱스, 포인터 체인, 오버플로 구역                                               |
| 단위      | 논리적 레코드(logical record)                                               | 저장 레코드(stored record)                                                       |

사용자는 학생 데이터를 "학번 순서로 늘어선 표"로 이해하지만, 디스크에서는 레코드가 입력된 순서대로 여러 블록에 흩어져 있고 학번 순서는 별도의 인덱스가 보관한다. 인덱스는 책 뒤의 찾아보기처럼 키 값과 그 레코드의 저장 위치를 짝지어 보관하는 구조다. ==하나의 데이터베이스를 표현하는 두 구조는 서로 대응해야 하며, 이 대응이 뒤에서 설명할 사상(mapping)이다.==

> [!NOTE]
> 논리적 구조에서 인접한 레코드도 물리적 구조에서는 위치와 순서가 전혀 다를 수 있다.

## 파일 시스템의 한계

DBMS가 등장하기 전에는 운영체제가 지원하는 파일 시스템으로 데이터를 처리했다. 파일 중심 데이터 처리 시스템의 특징은 다음과 같다.

1. 각 응용 프로그램이 논리적 파일 구조를 정의하고, 그 구조를 직접 물리적 파일 구조로 구현한다.
2. 각 응용 프로그램이 물리적 데이터 구조에 접근하는 방법을 직접 구현한다.
3. 각 사용자가 데이터와 그 데이터를 처리하는 프로그램을 모두 관리한다.
4. 응용 프로그램끼리 데이터를 공유할 수 없다.

응용 프로그램과 파일이 1:1로 대응하므로, 인사 프로그램과 급여 프로그램이 각자 "사원" 파일을 가진다. 데이터가 적을 때는 문제가 없지만, 프로그램과 파일의 수가 늘면 두 가지 문제가 생긴다.

![응용 프로그램 1~n이 급여·세금 정산·퇴직금·인사 데이터 파일과 각각 1:1로 연결된 파일 시스템 구조도](./images/db-dbms-data-independence-note-06.jpg '파일 시스템: 응용 프로그램마다 자기 데이터 파일을 1:1로 가진다')

### 데이터 종속성(data dependency)

응용 프로그램과 데이터가 서로 의존하는 관계다. ==데이터의 구성 방법이나 접근 방법을 바꾸면 그 데이터를 쓰는 응용 프로그램도 함께 고쳐야 한다.== 파일 시스템에서는 각 프로그램이 "앞 6바이트는 사번, 다음 10바이트는 이름"처럼 레코드 형식을 코드 안에 정의해 두기 때문이다.

![사원 레코드에 전화번호 필드를 추가할 때 파일 시스템은 프로그램 3개의 레코드 정의를 모두 고치고, DBMS는 사상만 갱신하는 비교도](./images/db-dbms-data-independence-field-change.svg '필드 하나를 추가할 때 고쳐야 하는 범위: 파일 시스템은 모든 프로그램, DBMS는 사상')

사원 파일에 전화번호 필드를 추가하는 경우를 비교하면 위 그림과 같다. 파일 시스템에서는 사원 파일을 읽는 인사·급여·퇴직금 프로그램이 모두 옛 레코드 길이를 기준으로 필드를 잘라 읽으므로, 전화번호를 쓰지 않는 프로그램까지 레코드 정의를 고치고 다시 컴파일해야 한다. DBMS에서는 저장 레코드가 바뀌어도 DBMS가 저장 구조와 프로그램 요청 사이의 사상만 갱신하므로, 사번·이름·부서만 요청하는 기존 프로그램은 수정할 필요가 없다.

### 데이터 중복성(data redundancy)

==한 시스템 안에서 같은 내용의 데이터가 여러 파일에 중복 저장되는 상태다.== 인사 파일과 급여 파일이 모두 사원 주소를 보관하는 경우가 그 예다.

![인사 파일만 주소를 갱신해 급여 파일과 값이 달라진 파일 시스템과, 사원 릴레이션 한 곳에 주소를 저장한 DBMS 비교도](./images/db-dbms-data-independence-redundancy.svg '중복 저장된 주소는 한쪽만 갱신되면 두 값으로 갈린다')

중복은 다음 네 가지 문제를 낳는다.

| 문제                | 내용                                                                                    | 위 그림의 예                                          |
| ------------------- | --------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| 일관성(consistency) | 한 파일의 값만 바뀌고 다른 파일의 값은 그대로 남아, 같은 데이터가 서로 다른 값을 가진다 | E01의 주소가 인사 파일과 급여 파일에서 다르다         |
| 보안성(security)    | 같은 데이터가 여러 곳에 있어 모든 사본에 같은 수준의 보안을 적용하기 어렵다             | 인사 파일만 접근 권한을 제한해도 급여 파일로 노출된다 |
| 경제성(economics)   | 같은 데이터를 여러 번 저장해 저장 공간과 갱신 비용이 늘어난다                           | 주소 변경 한 건에 파일 두 개를 갱신해야 한다          |
| 무결성(integrity)   | 데이터가 정확하다는 보장이 약해진다                                                     | 어느 주소가 맞는지 시스템이 판단할 수 없다            |

여러 응용 프로그램이 공동으로 쓰는 접근 루틴을 갖춘 파일 관리 시스템(file management system)이 이 문제를 줄이려고 등장했지만, 데이터 구조 정의가 여전히 프로그램 안에 있어 근본적인 해결이 되지 못했다. ==DBMS는 이 종속성과 중복성을 해결하기 위해 등장했다.==

![파일 시스템과 DBMS의 데이터 접근 구조 비교](./images/db-dbms-data-independence-filesystem.svg '파일 시스템은 프로그램마다 파일을 갖고, DBMS는 통합 데이터베이스를 중재한다')

![응용 프로그램들과 데이터 파일들 사이에 파일 관리 시스템(공동 접근 루틴)이 끼어 있는 구조도](./images/db-dbms-data-independence-note-07.jpg '파일 관리 시스템: 공동 접근 루틴을 두었지만 데이터 구조 정의는 여전히 프로그램 안에 있다')

## DBMS의 정의와 필수 기능

> [!IMPORTANT]
> DBMS는 ==**응용 프로그램과 데이터 사이의 중재자로서, 모든 응용 프로그램(사용자)이 데이터베이스를 공유할 수 있게 관리하는 범용 소프트웨어 시스템**==이다.

응용 프로그램은 파일에 직접 접근하지 않고 DBMS에 요청한다. 오늘날 널리 쓰이는 Oracle, MySQL, PostgreSQL, SQL Server가 DBMS이고, 응용 프로그램은 이들에게 SQL 문장을 보내 데이터를 요청한다.

![응용 프로그램들이 DBMS를 거쳐 하나의 데이터베이스(겹쳐진 데이터 파일들)에 접근하는 구조도](./images/db-dbms-data-independence-note-08.jpg '응용 프로그램은 DBMS를 거쳐 하나의 데이터베이스에 접근한다')

DBMS는 세 가지 필수 기능을 제공한다.

### 1. 정의(definition) 기능

하나의 저장 구조(storage structure)로 여러 사용자의 요구를 지원할 수 있도록 데이터를 조직(organize)하는 기능이다. 다음 세 가지를 명세해야 한다.

| 명세 대상                       | 내용                                                    | SQL의 예                                  |
| ------------------------------- | ------------------------------------------------------- | ----------------------------------------- |
| 논리적 구조(logical structure)  | DBMS가 지원하는 데이터 모델에 맞춘 데이터의 구조와 특성 | `CREATE TABLE{:sql}`로 열과 타입을 정의   |
| 물리적 구조(physical structure) | 저장 장치에 저장되는 구조                               | `CREATE INDEX{:sql}`, 테이블스페이스 지정 |
| 사상(mapping)                   | 논리적 구조와 물리적 구조 사이의 대응                   | DBMS가 카탈로그에 보관해 자동으로 유지    |

==이 사상이 뒤에서 설명할 데이터 독립성을 구현하는 수단이다.==

### 2. 조작(manipulation) 기능

사용자와 데이터베이스 사이의 인터페이스다. 검색(retrieve), 갱신(update), 삽입(insert), 삭제(delete)를 체계적으로 수행하며, 데이터 언어로 표현한다. 데이터 언어는 다음 조건을 갖춰야 한다.

- 사람이 이해하기 쉽고 자연스럽게 쓸 수 있다.
- 원하는 연산을 명세할 수 있다.
- 효율적으로 처리된다.

SQL의 `SELECT{:sql}`, `UPDATE{:sql}`, `INSERT{:sql}`, `DELETE{:sql}`이 네 조작에 대응한다.

### 3. 제어(control) 기능

데이터의 정확성(correctness)과 보안성(security)을 유지하는 기능이다.

| 요건                                | 내용                                                               | 예                                                            |
| ----------------------------------- | ------------------------------------------------------------------ | ------------------------------------------------------------- |
| 무결성(integrity) 유지              | 언제 어디서 검색하든 내용이 정확해야 한다                          | 성적에 A~F 외의 값이 들어오면 거부한다                        |
| 보안(security)·권한(authority) 검사 | 권한이 없는 사용자의 접근을 막아 데이터베이스가 오염되지 않게 한다 | 학생 계정은 자기 성적만 조회하고 수정할 수 없다               |
| 병행 수행 제어(concurrency control) | 여러 사용자가 동시에 접근해도 결과가 정확하다                      | 정원 1명 남은 과목에 두 명이 동시에 신청해도 한 명만 등록된다 |
| 복구(recovery)                      | 장애가 발생해도 백업과 로그로 정확한 상태를 빠르게 회복한다        | 이체 도중 서버가 꺼지면 출금만 된 상태를 로그로 되돌린다      |

## DBMS의 장단점

| 장점                       | 내용                                                                                                                                                         |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 데이터 중복 최소화         | 데이터를 통합해 중복을 사전에 통제한다. 중복을 완전히 없애지 않고, 성능 때문에 필요한 중복만 최소한으로 유지해 DBMS가 제어한다(제어된 중복)                  |
| 데이터 공유                | 같은 데이터를 여러 구조로 제공하므로, 새 응용 프로그램은 데이터 구성에 신경 쓰지 않고 응용 자체만 개발할 수 있다                                             |
| 일관성 유지                | 중복을 제어해 같은 데이터가 서로 다른 값을 갖지 않게 한다                                                                                                    |
| 무결성 유지                | 중복이 없더라도 허용되지 않는 값이 들어올 수 있으므로, 접근할 때마다 유효성을 검사한다                                                                       |
| 보안 보장                  | 데이터베이스를 중앙에서 관리해 정당한 사용자와 허용된 연산만 통과시킨다. 같은 데이터가 여러 파일에 흩어진 파일 시스템보다 보안 수준을 일정하게 유지하기 쉽다 |
| 표준화                     | 데이터 형식, 처리 방식, 문서화 양식의 표준을 기관 전체에 적용하기 쉽다                                                                                       |
| 기관 전체 데이터 요구 조정 | 모든 응용 시스템의 데이터 요구를 통합 분석해, 상충하는 요구를 조정한 구조로 조직한다                                                                         |

| 단점                        | 내용                                                                                   |
| --------------------------- | -------------------------------------------------------------------------------------- |
| 운영비 오버헤드             | 소프트웨어 구매비, 하드웨어, 운영 인력의 인건비가 든다                                 |
| 특정 응용 프로그램의 복잡화 | 응용 프로그램이 데이터 구조를 직접 다루지 않고 DBMS를 거쳐야 한다                      |
| 복잡한 백업과 복구          | 구조가 복잡하고 여러 사용자가 동시에 쓰므로, 장애 원인과 상태를 파악하기 어렵다        |
| 시스템 취약성               | 통합 시스템이라 일부 장애가 전체 시스템 정지로 이어져 신뢰성과 가용성이 떨어질 수 있다 |

## DBMS의 궁극적 목적: 데이터 독립성

DBMS가 논리적 구조와 물리적 구조 사이의 사상을 정의하는 이유는 **데이터 독립성(data independence)** 을 얻기 위해서다. ==데이터 독립성은 데이터 종속성의 반대 개념이다.==

| 종류                 | 정의                                                                                    | 효과                                | 예                                                             |
| -------------------- | --------------------------------------------------------------------------------------- | ----------------------------------- | -------------------------------------------------------------- |
| 논리적 데이터 독립성 | 응용 프로그램에 영향을 주지 않고 논리적 데이터 구조를 바꿀 수 있다                      | 응용 프로그램을 효율적으로 개발한다 | 사원 테이블에 전화번호 열을 추가해도 급여 프로그램은 그대로다  |
| 물리적 데이터 독립성 | 응용 프로그램과 논리적 데이터 구조에 영향을 주지 않고 물리적 데이터 구조를 바꿀 수 있다 | 저장 장치를 효율적으로 개선한다     | 학번에 인덱스를 추가하거나 더 빠른 디스크로 옮겨도 질의는 같다 |

데이터베이스에는 데이터가 최소한의 중복으로 저장되고, 기관 전체 관점에서 각 개체(entity)는 하나의 통합된 논리적 구조를 가진다. 각 응용 프로그램은 그중 자기가 필요한 일부만 다르게 보지만, 사상으로 연결되어 있어 본질적으로 같은 데이터다. ==그래서 논리적 구조 사상은 논리적 데이터 독립성을, 물리적 구조 사상은 물리적 데이터 독립성을 지원한다.==

![프로그램의 데이터 구조(ABCD·BEF·GAD)→논리적 구조 사상→DB 논리적 구조→물리적 구조 사상→물리적 구조로 내려가는 사상 계층도](./images/db-dbms-data-independence-note-09.jpg '프로그램마다 다른 데이터 구조가 두 단계 사상을 거쳐 하나의 물리적 구조에 대응한다')

위 그림에서 세 프로그램은 각각 ABCD, BEF, GAD라는 서로 다른 필드 조합을 사용한다. 이 조합은 논리적 구조 사상으로 데이터베이스 전체의 논리적 구조(A~G)에 대응하고, 논리적 구조는 다시 물리적 구조 사상으로 저장 장치의 레코드에 대응한다. 저장 레코드의 배치를 바꾸면 물리적 구조 사상만, 논리적 구조에 필드 H를 더하면 논리적 구조 사상만 고치면 된다.

> [!IMPORTANT]
> ==구조를 바꿔도 사상만 고치면 응용 프로그램은 그대로 동작한다.==

이 구조는 다음 글의 3단계 스키마에서 구체화된다.

## DBMS의 발전 과정

모든 DBMS는 개체와 관계를 정의하는 데서 설계를 시작하고, 구축 전에 데이터 모델로 논리적 구조를 확정한다. 데이터 모델은 데이터의 구조, 그 구조에 적용하는 연산, 지켜야 할 제약조건을 정한 규칙의 묶음이다. ==어떤 데이터 모델을 쓰느냐에 따라 논리적 구조가 달라지며, 세대 구분도 데이터 모델을 기준으로 한다.==

| 세대  | 시기           | 데이터 모델         | 대표 시스템                                                                                 |
| ----- | -------------- | ------------------- | ------------------------------------------------------------------------------------------- |
| 1세대 | 1960년대       | 네트워크, 계층      | IDS(GE, Charles Bachman 설계, 최초의 범용 DBMS), IMS(IBM)                                   |
| 2세대 | 1970\~1980년대 | 관계                | DB2, Oracle, Ingres, Sybase, Informix. PC 기반은 Access, FoxPro, dBase, Paradox, SQL Server |
| 3세대 | 1990년대 이후  | 객체지향, 객체-관계 | OODBMS, O-RDBMS                                                                             |

![2012년 ACM 튜링상 100주년 행사에서 촬영한 Charles Bachman](./images/db-dbms-data-independence-bachman.jpg#float-right '최초의 범용 DBMS인 IDS를 설계한 Charles Bachman(2012년)')

1세대에는 데이터베이스 구조와 DBMS의 필수 기능이 정의되었다. 1960년대 초 General Electric의 Bachman이 설계한 IDS(Integrated Data Store)는 네트워크 데이터 모델의 기초가 되었고, Bachman은 레코드 사이의 관계를 그리는 데이터 구조도(data structure diagram)도 제안했다. Bachman은 이 업적으로 1973년 ACM 튜링상을 받았다. 1960년대 후반 IBM이 개발한 IMS(Information Management System)는 계층 데이터 모델의 기초가 되었다. 1970년대 초에는 대형 컴퓨터 회사들이 DBMS를 자체 제작해 판매했다.

2세대는 1970년 IBM의 E. F. Codd가 논문 "A Relational Model of Data for Large Shared Data Banks"로 제안한 관계 데이터 모델에서 시작한다. 관계 모델은 데이터를 행과 열로 된 표(릴레이션)로만 표현하고, 레코드 사이의 연결을 포인터가 아니라 값으로 표현한다. 관계 DBMS는 1980년대에 DBMS의 주류가 되었고, 기본 형태를 유지하며 지금까지 확장되고 있다. IBM이 관계 DBMS의 일부로 개발한 SQL(Structured Query Language)은 세계 표준 데이터베이스 언어가 되었다.

3세대는 공학 설계, 이미지, 동영상, 공간 데이터, 시계열, 데이터 마이닝처럼 응용의 복잡성(complexity)이 커지면서, 객체지향 프로그래밍에 기반한 새 데이터 모델로 만든 객체지향 DBMS에서 시작한다. 현재는 2세대와 3세대 DBMS가 함께 쓰이며, 관계 모델에 객체 개념을 더한 객체-관계 DBMS가 그 예다.

데이터는 관찰이나 측정으로 수집한 가공 전의 사실이나 값이고, 정보는 의사결정에 쓸 수 있도록 데이터를 처리·해석한 결과다([데이터와 정보](#데이터와-정보) 절). 학생별 성적 레코드는 데이터이고, 이 레코드를 학과별로 집계한 평균 성적은 교과 과정 개편을 판단하는 정보다. ==같은 데이터도 처리 목적에 따라 다른 정보가 된다.==

<summary>2. 정보 시스템과 유용성의 조건</summary>

> 정보 시스템이란 무엇이며, 유용성을 유지하기 위해서는 어떤 성질을 가지고 있어야 하는가?

정보 시스템은 한 기관의 의사결정에 필요한 데이터를 수집·조직·저장했다가, 필요한 시각에 처리해 정보를 생성·분배하는 수단이다. 정보 시스템이 유용하려면 정보가 정확하고(정확성), 의사결정 시각에 맞춰 제공되며(적시성), 그 의사결정에 관련된 내용이어야 한다(관련성). 이를 위해 저장 데이터를 계속 갱신해 현재 상태를 반영해야 한다.

==응용 시스템은 정보 시스템 안에서 한 부서의 업무를 위한 서브 시스템이고, 응용 프로그램으로 구성된다.== 포함 관계는 `\text{정보 시스템} \supset \text{응용 시스템} \supset \text{응용 프로그램}{:math}`이다. 대학 종합정보시스템의 성적 응용 시스템은 성적 입력·성적표 출력·평점 계산 같은 응용 프로그램으로 구성된다.

<summary>5. 데이터 처리 시스템과 정보 처리 시스템</summary>

| 구분                          | 범위                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------ |
| 정보 처리 시스템(정보 시스템) | 데이터 수집에서 정보 생성·분배와 의사결정 지원까지 전 과정. 사람, 절차, 수작업도 포함한다  |
| 데이터 처리 시스템            | 정보 시스템의 서브 시스템으로, 컴퓨터를 이용해 정보 시스템이 필요로 하는 데이터를 처리한다 |

==데이터 처리 시스템은 정보 시스템의 핵심 서브 시스템이고, 정보 처리 시스템은 그 처리 결과를 의사결정에 연결하는 전체 시스템이다.==

<summary>6. 데이터 처리 시스템의 유형</summary>

> 데이터가 조직되고 접근되는 방법에 따른 데이터 처리 시스템의 유형을 설명하라.

| 유형        | 구분 기준 | 처리 방법                                                                                               |
| ----------- | --------- | ------------------------------------------------------------------------------------------------------- |
| 일괄 처리   | 시간      | 원시 데이터를 일정 기간 수집·분류해 한꺼번에 처리하는 시스템 중심 방법                                  |
| 온라인 처리 | 시간      | 데이터가 발생하거나 요청이 들어온 즉시 처리하는 사용자 중심 방법                                        |
| 분산 처리   | 지리      | 지리적으로 분산된 처리기와 데이터베이스를 네트워크로 연결해, 논리적으로 하나의 시스템처럼 처리하는 방법 |

각 방식의 비교는 [데이터 처리 시스템](#데이터-처리-시스템) 절의 표와 같다.

</details>

<details>
<summary>7. 온라인 처리 시스템의 장단점</summary>

> 온라인 처리 시스템은 무엇이고, 그 장단점은 무엇인지 설명해 보라.

온라인 처리 시스템은 사전 준비 작업 없이 단말기에서 들어온 데이터를 통신 회선으로 컴퓨터에 보내 곧바로 처리하는 방식이다.

| 장점                                                            | 단점                                                    |
| --------------------------------------------------------------- | ------------------------------------------------------- |
| 처리 대기 시간이 없어 사용자가 편리하다                         | 시스템 성능이 낮고 처리 비용이 높다                     |
| 데이터의 분류·정리 작업이 필요 없다                             | 통신 제어기가 필요하고 보수·유지·회복의 오버헤드가 크다 |
| 입력 오류를 즉시 발견·교정해 데이터 처리의 회전 주기를 단축한다 |                                                         |
| 질의·검색·갱신을 수시로 수행해 데이터의 현재성을 유지한다       |                                                         |

</details>

<details>
<summary>8. 일괄 처리 시스템의 장단점</summary>

> 일괄 처리 시스템은 무엇이고, 그 장단점은 무엇인지 설명해 보라.

일괄 처리 시스템은 응용의 특성상 데이터를 일정 기간 수집해 분류·정렬한 다음 한꺼번에 처리하는 방식이다.

| 장점                                  | 단점                                                           |
| ------------------------------------- | -------------------------------------------------------------- |
| 시스템 성능이 높고 처리 비용이 낮다   | 사용자 개인의 처리 결과는 일괄 처리 시각까지 대기해야 한다     |
| 순차 접근 방법을 쓰는 업무에 유리하다 | 원시 데이터를 한곳에 수집해 분류하는 사전 준비 작업이 필요하다 |

</details>

<details>
<summary>9. 분산 처리 시스템에서 데이터베이스의 중요성</summary>

> 분산 처리 시스템에서 데이터베이스의 중요성을 설명하라.

분산 데이터베이스의 데이터는 그 데이터를 가장 많이 쓰는 사이트에 저장되지만, ==사용자에게는 네트워크 전체의 데이터가 논리적으로 하나의 데이터베이스로 보여 어느 노드에서나 접근할 수 있어야 한다.== 데이터베이스가 없으면 사이트마다 독립된 파일을 보관하게 되어, 같은 데이터가 여러 사이트에 중복되고 값이 서로 달라진다. 분산 처리기들이 공용하는 데이터를 하나의 논리적 구조로 통합하고 일관성을 유지하는 수단이 분산 데이터베이스다.

</details>

<details>
<summary>10. 데이터 처리 시스템에서 데이터베이스의 중요성</summary>

> 데이터 처리 시스템에서 데이터베이스의 중요성을 설명해 보라.

==데이터베이스는 같은 데이터를 목적이 서로 다른 여러 응용이 중복 없이 공용하게 한다.== 위 온라인 처리와 분산 처리 구성도에서 컴퓨터가 처리하는 저장 데이터가 데이터베이스이며, 정보를 생성하는 원천 데이터를 통합해 일관되게 유지하므로 데이터 처리 결과의 정확성이 데이터베이스에 달려 있다.

</details>

<details>
<summary>11. 분산 시스템의 장단점</summary>

> 분산 시스템의 장단점을 설명해 보라.

| 장점                                                                | 단점                                                      |
| ------------------------------------------------------------------- | --------------------------------------------------------- |
| 지역에서 발생한 문제에 신속하게 대응한다                            | 구현과 유지보수가 복잡하다                                |
| 지역 업무의 책임을 구분할 수 있다                                   | 여러 노드가 같은 데이터를 처리하므로 일관성 문제가 생긴다 |
| 새 응용을 모듈 단위로 구축하기 쉽다                                 | 노드 사이의 통신으로 네트워크 오버헤드가 생긴다           |
| 지역 처리 능력과 자원의 다원적 재편성으로 장애에 대한 신뢰성이 높다 |                                                           |
| 시스템 운영에 큰 영향 없이 노드를 폐쇄하거나 확장할 수 있다         |                                                           |

</details>

<summary>12. 전산화·사무 자동화·정보의 관계</summary>

> 전산화, 사무 자동화, 정보를 각각 설명하고, 이들이 서로 어떻게 연관되는가를 논의해 보라.

| 용어                           | 뜻                                                                                                      |
| ------------------------------ | ------------------------------------------------------------------------------------------------------- |
| 전산화(computerization)        | 사람이 수작업으로 처리하던 업무와 데이터를 컴퓨터가 처리하도록 옮기는 것. 데이터 처리 시스템을 구축한다 |
| 사무 자동화(office automation) | 문서 작성·전달·보관, 일정 관리 같은 사무실 업무 전반을 컴퓨터와 통신 기술로 자동화하는 것               |
| 정보                           | 의사결정에 쓸 수 있도록 데이터를 처리·해석한 결과                                                       |

전산화로 업무 데이터가 컴퓨터가 처리할 수 있는 형태로 저장되고, 사무 자동화는 전산화의 범위를 개별 업무에서 사무 전반으로 넓힌다. ==두 활동의 목적은 데이터를 처리해 의사결정에 필요한 정보를 적시에 생성하는 데 있다.== 전산화와 사무 자동화가 데이터를 생성·저장하는 수단이라면, 정보는 그 결과물이다.

<details>
<summary>16. 개체와 속성</summary>

> 개체(entity)와 속성(attribute)을 구분해서 설명하라.

개체는 표현하려는 유무형 정보의 객체로, 서로 구별되는 정보의 단위이며 하나 이상의 속성으로 구성된다. 속성은 개체의 특성이나 상태를 기술하는 데이터의 가장 작은 논리적 단위다. ==속성은 그 자체만으로는 의미 있는 정보를 표현하지 못해 개체에 속해서만 존재한다.== "컴퓨터"라는 값은 학생 개체의 학과 속성일 때 의미를 가진다.

</details>

<details>
<summary>17. 레코드 타입과 레코드 인스턴스</summary>

> 레코드 타입(record type)과 레코드 인스턴스(record instance)를 설명하고 그 예를 들어 보라.

레코드 타입은 필드 이름으로만 표현한 레코드 정의이고, 레코드 인스턴스는 실제 필드 값으로 표현한 레코드다. `학생(학번, 이름, 학과)`가 레코드 타입이고, `<1234, 홍길동, 컴퓨터>`가 그 타입의 레코드 인스턴스다. 예제 데이터 STUDENT에서는 `STUDENT(Sno, Sname, Year, Dept)`가 레코드 타입이고 `<100, 나수영, 4, 컴퓨터>`가 레코드 인스턴스다.

</details>

<details>
<summary>18. 개체 관계와 속성 관계</summary>

> 개체 관계와 속성 관계의 차이점을 설명하고 그 예를 들어 보라.

속성 관계는 한 개체를 기술하는 속성 사이의 개체 내 관계로 묵시적으로 취급하고, 개체 관계는 개체 집합 사이의 개체 간 관계로 명시적으로 표현한다([논리적 구성 요소](#논리적-구성-요소) 절의 표). 학생의 학번·이름·학과 사이는 속성 관계이고, 학생과 교수 사이의 "지도"나 STUDENT와 COURSE 사이의 "등록(ENROL)"은 개체 관계다.

</details>

<details>
<summary>19. 논리적 구조와 물리적 구조의 관계</summary>

> 데이터베이스의 논리적 구조와 물리적 구조를 설명하고 이들의 관계를 설명하라.

논리적 구조는 사용자 관점에서 본 데이터의 개념적 구조이고, 물리적 구조는 인덱스·포인터 체인 같은 추가 정보를 포함해 저장 장치에 저장된 실제 구조다([논리적 구조와 물리적 구조](#논리적-구조와-물리적-구조) 절). 두 구조는 같은 데이터베이스를 사용자 관점과 시스템 관점에서 표현한 것이므로 서로 대응해야 하고, DBMS는 이 대응을 사상으로 정의해 두 구조의 동등성을 유지한다.

</details>

<details>
<summary>20. 내용에 의한 참조와 주소에 의한 참조</summary>

> 데이터베이스에 대한 내용에 의한 참조와 주소에 의한 참조를 설명하고 일반 사용자의 입장에서 평가해 보라.

| 참조 방식        | 기준                                            |
| ---------------- | ----------------------------------------------- |
| 내용에 의한 참조 | 사용자가 요구하는 데이터의 내용, 즉 데이터의 값 |
| 주소에 의한 참조 | 데이터 레코드의 주소나 저장 위치                |

내용에 의한 참조에서는 레코드가 어디에 저장되었는지 몰라도 조건만으로 데이터를 찾는다. 예제 데이터에서 컴퓨터 학과 학생을 찾는 질의는 다음과 같다.

```sql
SELECT Sno, Sname
FROM STUDENT
WHERE Dept = '컴퓨터';
```

| Sno | Sname  |
| --- | ------ |
| 100 | 나수영 |
| 300 | 정기태 |
| 400 | 송병길 |

==일반 사용자에게는 저장 위치를 알 필요가 없는 내용에 의한 참조가 편리하다.== 주소에 의한 참조는 레코드의 저장 위치가 바뀌면 참조하는 프로그램도 고쳐야 하므로 데이터 종속성을 낳는다.

</details>

<details>
<summary>21. 논리적·물리적 데이터베이스를 구분하는 이점</summary>

> 물리적 데이터베이스와 논리적 데이터베이스를 구분하여 고려할 때 얻을 수 있는 이점은 무엇인가?

==두 구조를 구분하면 데이터 독립성을 얻는다.== 사용자와 응용 프로그램은 논리적 구조만 다루므로 저장 위치·인덱스·레코드 순서를 몰라도 된다. 시스템은 응용 프로그램을 고치지 않고 물리적 구조를 성능 기준으로 재조직할 수 있고, 같은 물리적 데이터 위에 응용마다 다른 논리적 구조를 제공할 수 있다.

</details>

<summary>22. 데이터 공용의 이점·단점과 보완책</summary>

> 데이터 공용(data sharing)을 할 때 얻는 이점과 단점을 설명하고, 단점을 보완하기 위한 대책을 설명해 보라.

| 이점                                                | 단점                                                                   | 보완책(DBMS 기능)                                  |
| --------------------------------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------- |
| 데이터를 한 번만 저장해 중복과 저장 비용이 줄어든다 | 여러 사용자가 같은 데이터를 동시에 갱신하면 결과가 틀어질 수 있다      | 병행 수행 제어(잠금, 트랜잭션)                     |
| 한 곳에서 갱신하므로 일관성을 유지한다              | 권한이 없는 사용자가 데이터에 접근하거나 오염시킬 수 있다              | 보안·권한 검사(사용자 계정, 권한 부여)             |
| 새 응용 프로그램이 기존 데이터를 그대로 사용한다    | 한 응용의 잘못된 입력이 그 데이터를 쓰는 모든 응용에 퍼진다            | 무결성 제약 검사                                   |
| 사용자 측면에서 이용이 편리하다                     | 장애 하나가 데이터를 공용하는 모든 응용을 멈추고, 관리·조직이 복잡하다 | 복구(백업과 로그), 데이터베이스 관리자의 중앙 관리 |

</details>

<details>
<summary>1. 파일 시스템의 장단점</summary>

> 파일 시스템의 장단점을 설명하라.

| 장점                                                                                            | 단점                                                                    |
| ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 응용 프로그램 안에 파일 접근·관리 코드가 있어 DBMS 같은 별도 소프트웨어의 설치·구성이 필요 없다 | 데이터 구조가 프로그램에 묶여 데이터 종속성이 생긴다                    |
| 구조가 단순해 작은 규모의 시스템에서는 효율적이다                                               | 응용 사이의 데이터 공용이 불가능해 같은 데이터가 여러 파일에 중복된다   |
|                                                                                                 | 각 사용자가 데이터와 그 데이터를 처리하는 프로그램을 모두 관리해야 한다 |

<details>
<summary>2. 데이터 종속성의 문제점과 해결책</summary>

> 데이터 종속성을 설명하고, 그 문제점과 해결책을 설명해 보라.

데이터 종속성은 응용 프로그램과 데이터 사이의 상호 의존 관계로, 각 프로그램이 자기 파일의 구조를 직접 정의하기 때문에 생긴다([데이터 종속성](#데이터-종속성data-dependency) 절). 데이터의 구성 방법이나 접근 방법을 바꾸면 관련 프로그램도 모두 고쳐야 해 프로그램 관리가 어렵다. ==DBMS가 데이터 구조를 프로그램 밖에서 정의하고 논리적·물리적 구조 사이의 사상으로 데이터 독립성을 제공해 종속성을 해결한다.==

</details>

<details>
<summary>3. 데이터 중복성의 문제점과 해결책</summary>

> 데이터의 중복성이 문제가 되는 이유를 설명하고 그 해결책을 설명해 보라.

같은 데이터가 여러 파일에 중복 저장되면 일관성, 보안성, 경제성, 무결성을 유지하기 어렵다([데이터 중복성](#데이터-중복성data-redundancy) 절의 표). DBMS로 데이터를 하나의 데이터베이스에 통합해 중복을 해결하고, 성능 때문에 필요한 중복은 DBMS가 위치를 알고 갱신을 함께 반영하는 제어된 중복으로 관리한다.

</details>

<details>
<summary>4. DBMS의 필수 기능</summary>

> DBMS가 갖추어야 될 필수 기능은 어떤 것인가를 설명하라.

정의, 조작, 제어 세 기능이다([DBMS의 정의와 필수 기능](#dbms의-정의와-필수-기능) 절). ==제어 기능의 요건은 무결성 유지, 보안·권한 검사, 병행 수행 제어, 복구 네 가지다.==

</details>

<details>
<summary>5. DBMS의 장단점</summary>

> DBMS를 사용할 때의 장단점을 설명하라.

장점은 데이터 중복 최소화, 데이터 공용, 일관성 유지, 무결성 유지, 보안 보장, 표준화 용이, 기관 전체 데이터 요구의 조정이고, 단점은 운영비 오버헤드, 특정 응용 프로그램의 복잡화, 복잡한 백업과 복구, 시스템 취약성이다. 각 항목의 내용은 [DBMS의 장단점](#dbms의-장단점) 절의 표와 같다.

</details>

<details>
<summary>6. 데이터 중복의 완전한 제거</summary>

> 데이터의 중복성은 완전히 제거되어야 하는가? 그렇지 않다면 그 이유는 무엇인가?

완전히 제거할 필요는 없다. 성능 때문에 중복이 불가피한 경우가 있으므로 목표는 중복의 최소화다. 예를 들어 ENROL에 학생 이름 Sname을 함께 저장하면 성적 조회마다 STUDENT와 조인하지 않아도 된다. ==어떤 데이터가 어디에 중복되어 있는지 시스템이 알고 통제하는 제어된 중복이면 일관성을 유지할 수 있다.==

</details>

<details>
<summary>7. 무결성이 깨졌을 때의 파급 효과</summary>

> 데이터의 무결성이 유지되지 않았을 경우의 파급 효과를 설명하라.

무결성이 깨지면 사용자에게 부정확한 데이터를 제공하고, 그 데이터로 생성한 정보에 근거한 의사결정도 잘못된다. ==데이터베이스는 여러 응용이 공용하므로 한 곳의 오류가 그 데이터를 쓰는 모든 응용으로 퍼진다.== 예를 들어 ENROL에 STUDENT에 없는 학번 600의 등록 레코드가 들어가면, 과목별 수강 인원과 성적 통계에 존재하지 않는 학생이 집계된다. 오류가 발견된 뒤에는 데이터베이스를 신뢰할 수 없게 되고, 잘못된 값을 추적해 수정하는 비용이 든다.

</details>

<details>
<summary>8. 데이터 독립성과 그 중요성</summary>

> 데이터 독립성을 설명하고, 왜 중요한 것인가를 설명하라.

데이터 독립성은 데이터의 논리적 구조나 물리적 구조를 바꿔도 응용 프로그램이 영향을 받지 않는 성질이며, 논리적 데이터 독립성과 물리적 데이터 독립성으로 나뉜다([데이터 독립성](#dbms의-궁극적-목적-데이터-독립성) 절의 표). DBMS의 궁극적 목적으로, 구조를 바꿀 때마다 응용 프로그램을 고치지 않아도 되므로 응용 프로그램과 저장 장치를 각각 효율적으로 개발·개선할 수 있다.

</details>

<details>
<summary>9. 데이터베이스 관리 시스템과 파일 관리 시스템</summary>

> 데이터베이스 관리 시스템과 파일 관리 시스템을 비교 설명하라.

|                  | 파일 관리 시스템                                | 데이터베이스 관리 시스템                    |
| ---------------- | ----------------------------------------------- | ------------------------------------------- |
| 데이터 구조 정의 | 각 응용 프로그램 안                             | DBMS가 프로그램 밖에서 통합 정의            |
| 접근 방법        | 여러 프로그램이 공동 접근 루틴을 사용           | 데이터 언어로 DBMS에 요청                   |
| 데이터 독립성    | 없다. 파일 구조를 바꾸면 프로그램도 고쳐야 한다 | 논리적·물리적 구조 사이의 사상으로 제공한다 |
| 중복             | 응용마다 파일을 보관해 중복이 남는다            | 데이터를 통합하고 필요한 중복만 제어한다    |
| 제어 기능        | 없다                                            | 무결성, 보안·권한, 병행 수행 제어, 복구     |

</details>

<details>
<summary>10. DBMS의 정의와 필요성</summary>

> DBMS는 무엇이며 왜 필요한가?

DBMS는 응용 프로그램과 데이터 사이의 중재자로서 모든 응용 프로그램(사용자)이 데이터베이스를 공용할 수 있게 관리하는 범용 소프트웨어 시스템이다. 파일 시스템의 데이터 종속성과 중복성을 해결하고, 궁극적으로 데이터 독립성을 제공해 응용 프로그램과 저장 장치를 효율적으로 개발할 수 있게 하려고 필요하다.

</details>

<details>
<summary>11. 현재 DBMS의 정의·조작·제어 기능</summary>

> 현재 사용되고 있는 DBMS들을 살펴보고, 각각 정의 기능, 조작 기능, 제어 기능에 대해 알아보라.

현재는 2세대 관계 DBMS와 객체 개념을 더한 객체-관계 DBMS가 함께 쓰인다. 널리 쓰이는 Oracle과 SQL Server를 제어 기능의 네 요건에 맞춰 비교하면 다음과 같다.

| 기능                 | Oracle                                                                         | SQL Server                                                                       |
| -------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 정의                 | `CREATE{:sql}`·`ALTER{:sql}`·`DROP{:sql}`으로 테이블·인덱스·뷰 정의            | `CREATE{:sql}`·`ALTER{:sql}`·`DROP{:sql}`으로 데이터베이스·테이블·인덱스·뷰 정의 |
| 조작                 | `SELECT{:sql}`, `INSERT{:sql}`, `UPDATE{:sql}`, `DELETE{:sql}`, `MERGE`        | `SELECT{:sql}`, `INSERT{:sql}`, `UPDATE{:sql}`, `DELETE{:sql}`, `MERGE`          |
| 제어: 무결성         | `PRIMARY KEY{:sql}`, `FOREIGN KEY{:sql}`, `CHECK{:sql}`, `NOT NULL{:sql}` 제약 | `PRIMARY KEY{:sql}`, `FOREIGN KEY{:sql}`, `CHECK{:sql}`, `NOT NULL{:sql}` 제약   |
| 제어: 보안·권한      | 사용자 계정, 롤(role), `GRANT{:sql}`/`REVOKE{:sql}`                            | 로그인·사용자, 롤, `GRANT{:sql}`/`REVOKE{:sql}`/`DENY`                           |
| 제어: 병행 수행 제어 | 트랜잭션(`COMMIT`/`ROLLBACK`), 행 수준 잠금, 다중 버전 읽기 일관성             | 트랜잭션, 잠금, 격리 수준(스냅숏 격리 포함)                                      |
| 제어: 복구           | 리두 로그와 언두, RMAN 백업·복구                                               | 트랜잭션 로그, `BACKUP DATABASE`/`RESTORE DATABASE`                              |

</details>

## 정리

- 파일 시스템에서는 응용 프로그램이 데이터 구조를 직접 정의해, 데이터 종속성과 중복성이 생긴다.
- DBMS는 응용 프로그램과 데이터 사이의 중재자로, 정의·조작·제어 세 기능을 제공한다.
- DBMS의 궁극적 목적은 데이터 독립성이고, 구현 수단은 논리적·물리적 구조 사이의 사상이다.
