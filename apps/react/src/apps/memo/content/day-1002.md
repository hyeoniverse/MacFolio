하루 동안 커밋 53개가 main에 들어갔다. 새벽 2시에 멈췄다가 오전 10시에 다시 시작해 자정 직전까지 이어졌다. 크게 보면 휴대폰 앱 맞추기, 방문자 이름, 그리고 배포 뒤에 드러난 오류다.

![10월 2일 작업 흐름](./images/day-1002-timeline.svg '새벽에는 메모 마무리, 낮에는 휴대폰 앱, 저녁에는 방문자 이름과 오류 안내')

## 새벽: 전날 일의 마무리

전날 밤부터 이어진 최근 삭제된 항목을 마저 다듬었다(안내 상자, 되돌려 놓기·즉시 삭제, 휴지통 비우기, 창 안 경고창). 태그에는 미선택·포함·제외 세 상태와 "모두·일부 포함"을 넣고, 휴대폰 본문을 iOS 메모처럼 바꿨다.

## 낮: 휴대폰 앱을 하나의 모양으로

오전에는 휴대폰 메모를 iOS 메모처럼 다시 짰다. 큰 제목, 카드로 묶은 목록, 넘기는 칸 밖에 떠 있는 단추, 아래 검색 칸이다. 폴더 편집에는 ≡ 손잡이로 순서를 바꾸는 기능을 넣고, API는 폴더 순서를 받게 했다.

![지금의 휴대폰 메모](./images/day-1002-mobile-memo.jpg '이날 만든 휴대폰 메모 목록의 지금 모습. 큰 제목이 뒤로 가기 줄에 있다')

오후 1시 32분에는 메모에서 만든 바탕·카드·떠 있는 단추를 공통 모양으로 빼서 음악·설정·암호·단축어·메일·메시지에 한 번에 입혔다. 오후 2시 53분에는 휴대폰 음악을 iOS 음악처럼 보관함·플레이리스트·앨범·아티스트로 나눴다.

![지금의 휴대폰 음악](./images/day-1002-mobile-music.jpg '휴대폰 음악의 지금 모습. 보관함에서 플레이리스트·아티스트·앨범·노래로 들어간다')

## 저녁: 이름과 비밀번호 칸을 없애다

휴대폰 메시지는 오후 내내 다듬었다. 오후 3시 49분, 4시 6분, 6시 6분, 7시 9분, 네 번이었다. 그중 하나는 이름·비밀번호 칸을 입력창과 맞추는 일이었는데, 아무리 맞춰도 두 칸이 입력창보다 더 눈에 띄었다.

그래서 저녁 7시 36분에 칸을 없앴다. 서버가 처음 온 브라우저에 쿠키를 주고, 그 값으로 "🦊 날쌘 여우" 같은 이름을 정한다. 같은 브라우저면 언제 와도 같은 이름이고, 자기 글은 그 브라우저에서 지운다. 메시지도 이때 처음으로 서버에 저장했다. 서버에 닿지 못하면 메시지 앱을 열지 않게 했다.

| 한 일                                          | 글                                        |
| ---------------------------------------------- | ----------------------------------------- |
| 방문자 쿠키로 이름, 메시지 서버 저장           | 이름·비밀번호 없이 쓰는 메시지와 댓글     |
| 서버가 없으면 메시지 앱을 열지 않기            | 서버가 없으면 메시지 앱을 열지 않기       |
| 앱 코드를 못 불러오면 새로고침을 권하는 경고창 | 배포 직후 메모가 안 열리던 까닭           |
| 계정 사진이 늦게 올 때 자리 채우기             | 프로필 사진이 늦게 올 때 비어 보이지 않게 |
| 관리자가 배경화면을 더하기                     | 관리자가 배경화면을 더하기                |

밤 9시 38분의 경고창은 배포 뒤에 본 오류였다. 메모를 열 때 가끔 "문제가 발생했습니다"가 떴고, 다시 열어도 같았다. 배포로 메모 코드 파일 이름이 바뀌었는데 열려 있던 페이지가 옛 이름을 찾고 있었다. 이날은 새로고침을 권하는 경고창으로 막았다. 뿌리는 사흘 뒤 10월 5일에 찾았다. 사이트가 없는 코드 파일에도 첫 화면(index.html)을 200으로 주고 있었다.

## 돌아보며

- **잘한 것: 한 앱에서 맞춘 모양을 공통으로 뺐다.** 메모에서 먼저 맞추고, 바탕·카드·떠 있는 단추를 뽑아 여섯 앱에 한 번에 입혔다. 앱마다 따로 맞췄으면 여섯 번 했을 일이다.
- **잘한 것: 다듬어도 안 되는 칸은 없앴다.** 이름·비밀번호 칸을 네 번 다듬다가, 칸이 문제라는 걸 알고 없앴다. 쓰는 사람도 덜 번거롭다.
- **아쉬운 것: 다듬기를 네 번 하고서야 없앴다.** 칸이 왜 필요한지(자기 글 지우기) 먼저 물었으면 처음부터 쿠키를 떠올렸을 것이다.
- **아쉬운 것: 오류를 증상에서 멈췄다.** 경고창으로 막은 뒤 뿌리(없는 파일에 HTML을 주는 서버 설정)는 사흘 뒤에야 찾았다.
