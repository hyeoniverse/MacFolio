macOS의 Apple 메뉴 맨 위에는 항상 **이 Mac에 관하여**가 있다. 선택하면 화면 가운데에 작은 창이 표시되고, Mac 이미지, 모델 이름(MacBook Pro), 칩·메모리·일련 번호·macOS 버전, '추가 정보…' 버튼이 나타난다. 이 사이트의 Apple 메뉴에는 이 항목이 없어서, 메뉴를 열면 macOS와 달리 첫 항목 위치가 비어 있었다.

포트폴리오 사이트에서 "이 Mac"에 해당하는 것은 사이트를 만든 사람이다. 그래서 같은 창 형태를 사용하고, 사양 위치에 프로필을 표시했다. 작업은 PR [#168](https://github.com/hyeoniverse/MacFolio/pull/168) 하나에 포함되어 있다. 첫 커밋이 창을 구현했고, 같은 날 세 차례 수정했다('역할'을 '직무'로 변경, 추가 정보…와 링크의 이동 대상 변경, 이메일 링크 스타일 변경).

## 표시 항목

| macOS               | 이 사이트                                   |
| ------------------- | ------------------------------------------- |
| Mac 그림            | GitHub 프로필 사진 (동그랗게)               |
| MacBook Pro         | 김정현, 아래에 Kim Jeong Hyeon              |
| 칩·메모리·일련 번호 | 직무·학교·위치·이메일·GitHub·주요 기술      |
| 추가 정보…          | 시스템 설정의 '정보'를 연다                 |
| 규제 인증서         | 개인정보 처리 방침                          |
| ™ & © Apple Inc.    | ™ & © 올해 Kim Jeong Hyeon. 모든 권리 보유. |

![이 Mac에 관하여 창](./images/about-this-mac-window.jpg '미리보기 서버(API 없음)에서 연 창. GitHub 사진을 받지 못해 이름 끝 두 글자를 회색 동그라미에 썼다')

처음에는 값을 `shared/profile.ts`의 상수 `PROFILE`과 `SKILLS`에서 직접 읽었다. 현재는 관리자가 시스템 설정에서 프로필을 수정할 수 있게 되어([코드를 고치지 않고 프로필 바꾸기](/memo/site-profile-editing)), `shared/site/profileStore.ts`의 `useProfile()`로 읽는다. 사양 줄을 생성하는 함수는 시스템 설정의 '정보'와 공유하려고 `desktop/about/profileInfo.ts`로 분리했다.

```ts
export const profileRows = (profile: SiteProfile): ProfileRow[] =>
	[
		{ label: '직무', value: profile.role },
		{ label: '학교', value: profile.school },
		{ label: '위치', value: profile.location },
		{ label: '이메일', value: profile.email, href: `mailto:${profile.email}` },
		{ label: 'GitHub', value: githubLogin(profile), href: profile.github },
		{ label: '주요 기술', value: profile.skills.frontend.slice(0, 3).join(' · ') },
	].filter((row) => row.value);
```

값이 비어 있는 항목은 줄 전체를 제외한다. 학교를 비우면 다섯 줄만 남고, 창 높이도 그만큼 줄어든다. 주요 기술은 프론트엔드 기술의 앞 세 개만 표시하고, 나머지는 '추가 정보…'에서 확인한다.

사진은 GitHub 주소에서 생성한 프로필 사진 주소를 사용한다. 이미지를 불러오지 못하면(미리보기 서버처럼 외부 네트워크에 접근할 수 없거나 주소가 잘못된 경우) 이름 끝 두 글자를 회색 원 안에 표시한다. 실패한 주소를 상태로 보관해 두고, 프로필의 GitHub 주소가 바뀌면 다시 시도한다.

## 앱과 시스템 창 중 구현 방식 선택

이 사이트에서 창을 표시하는 가장 간단한 방법은 앱을 하나 더 등록하는 것이다. 그러면 창 관리(끌기, 앞으로 가져오기, 최소화)를 추가 구현 없이 사용할 수 있다. 하지만 macOS에서 이 창은 앱이 아니다. 두 방법을 비교했다.

| 방법                                     | 장점                                                 | 단점                                                                                              |
| ---------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 앱으로 등록                              | 창 관리, 메뉴 막대의 앱 이름 표시를 그대로 사용      | Dock 아이콘, Finder의 응용 프로그램, 터미널 `open` 목록에 모두 추가된다. 최소화·확대도 활성화된다 |
| 데스크톱이 직접 렌더링하는 창 (**채택**) | macOS처럼 Dock·Finder에 표시되지 않는다. 코드가 작다 | 끌기, 초점, Esc 처리를 직접 구현해야 한다                                                         |

앱 목록에 등록하고 Dock·Finder에서만 숨기는 방법도 검토했지만, 앱 목록을 읽는 모든 위치에 예외 처리가 필요해 채택하지 않았다. 직접 렌더링하는 방식은 최초 구현이 `AboutThisMac.tsx` 124줄, CSS 163줄, 저장소 9줄이었다.

![열림 상태와 위치](./images/about-this-mac-state.svg '열림은 작은 저장소가, 옮긴 거리는 컴포넌트가 갖는다')

열림 상태는 `aboutStore` 하나가 관리한다. Apple 메뉴는 이 저장소의 `openAbout`만 호출하고, 창 컴포넌트는 `Desktop.tsx`에 항상 배치되어 있다가 `open`이 참일 때만 렌더링한다.

```ts
export const aboutStore = createStore<{ open: boolean }>({ open: false });
export const openAbout = () => aboutStore.setState({ open: true });
export const closeAbout = () => aboutStore.setState({ open: false });
```

직접 구현한 동작은 다음과 같다.

| 동작        | 구현                                                                                                                                                                                                                                                             |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 창 버튼     | macOS처럼 닫기 버튼만 빨간색이고, 최소화·확대 버튼은 회색 비활성 상태                                                                                                                                                                                            |
| 끌어 옮기기 | 창의 빈 영역을 끌면 이동한다. 시작 위치에서 이동한 거리를 `offset`에 저장하고 CSS `translate`로 적용한다. [`setPointerCapture`](https://developer.mozilla.org/en-US/docs/Web/API/Element/setPointerCapture)로 포인터를 고정해 빠르게 끌어도 추적이 끊기지 않는다 |
| 끌기 제외   | 버튼·링크·값(`dd`) 위에서는 끌기를 시작하지 않는다. 이메일 주소를 드래그해 선택·복사할 수 있어야 하기 때문이다                                                                                                                                                   |
| 초점·키보드 | 열리면 닫기 버튼에 초점을 두고, 열려 있는 동안에만 Esc 키 입력을 처리한다                                                                                                                                                                                        |
| 휴대폰      | 휴대폰 화면에는 Apple 메뉴가 없으므로 이 창도 없다                                                                                                                                                                                                               |

## 창에서 다른 앱을 여는 세 경로

창 안의 링크 세 개는 모두 다른 앱을 연다. 창이 대상 앱의 내부 구현에 의존하지 않도록 세 링크가 같은 방식을 사용한다. 작은 요청 저장소에 "이 대상을 열어 달라"는 값을 기록하고 `openApp`만 호출한다. 대상 앱은 그 저장소를 구독하다가 값을 읽고 초기화한다.

![요청 저장소 세 개](./images/about-this-mac-requests.svg '추가 정보…, 이메일, 개인정보 처리 방침이 각각 저장소 하나씩을 쓴다')

시스템 설정은 이렇게 받는다(`apps/settings/Settings.tsx`).

```ts
useEffect(() => {
	const take = ({ section: requested }: { section: string | null }) => {
		const match = SECTIONS.find((item) => item.id === requested);
		if (!match) return;
		setSection(match.id);
		setPhoneOpen(true);
		requestedSection.setState({ section: null });
	};
	take(requestedSection.getState());
	return requestedSection.subscribe(take);
}, []);
```

마운트 시각에 현재 값을 한 번 읽고(`take(getState())`), 이후에는 구독한다. 그래서 시스템 설정이 닫혀 있어도, 이미 열려 있어도 정보 항목으로 이동한다. 값을 읽은 즉시 초기화하므로 다음에 설정을 열 때 정보 항목으로 다시 이동하지 않는다.

| 경우                     | 동작                                                               |
| ------------------------ | ------------------------------------------------------------------ |
| 대상 앱이 닫혀 있음      | `openApp`으로 앱이 마운트되면서 `take(getState())`가 요청을 읽는다 |
| 대상 앱이 이미 열려 있음 | 구독 중인 `take`가 새 요청을 즉시 읽는다                           |
| 요청을 처리한 뒤         | 저장소 값을 `null`로 초기화해 다음 실행에 영향을 주지 않는다       |

**추가 정보…** 처음에는 Safari(자기소개가 있는 첫 화면)를 열게 했다. 사용해 보니 작은 창보다 상세한 화면으로 이동한다는 흐름이 드러나지 않았다. macOS에서 이 버튼은 시스템 설정의 **일반 › 정보**를 연다. 그래서 시스템 설정에 **정보** 항목(`AboutPane.tsx`)을 추가하고 그 항목을 열게 했다. 정보 항목에는 작은 창보다 자세한 내용이 그룹별로 있다.

- 프로필: 이름(한글·영문), 직무, 학교, 위치
- 연락처: 이메일, GitHub
- 기술: 프론트엔드·백엔드·인터랙션 전부
- 이 사이트(MacFolio): 만든 기술, 저장소

**이메일.** `mailto:`로 기기의 메일 앱을 여는 대신, 이 사이트의 **메일 앱**에서 '새로운 메시지'를 바로 연다(`ProfileLink.tsx`, [메일 앱에서 진짜로 메일 보내기 - Resend와 Turnstile](/memo/contact-mail)). 받는 사람이 항상 사이트 주인으로 고정된 작성 화면이라, 방문자는 사이트를 벗어나지 않고 메일을 보낸다. 휴대폰에서는 아래에서 올라오는 작성 시트가 열린다. `href`에는 계속 `mailto:`를 지정해, 새 탭으로 열기나 주소 복사 같은 브라우저 기능은 그대로 사용할 수 있다. 처음에는 이메일을 검은색 글자로 표시했는데, 클릭할 수 있는 요소로 인식하기 어려웠다. 그래서 GitHub 링크처럼 파란색 글자와 ↗ 표시를 추가했다.

**GitHub.** 외부 링크라 새 탭으로 연다. `openExternal`로 열어 이탈 링크 클릭으로 집계한다([트래픽 분석 2 - 사이트에서 모아 보내기](/memo/analytics-collect)).

**개인정보 처리 방침.** macOS의 이 창에는 저작권 줄 바로 위에 **규제 인증서** 링크가 있다. 이 사이트에서 그 위치에 해당하는 문서는 개인정보 처리 방침이다(방문 분석, 방문자 쿠키, 메일 처리를 설명한다). 같은 위치에 같은 형태의 링크를 배치하고, Apple 메뉴의 '개인정보 처리 방침'처럼 Finder에서 `docs/privacy.md`를 연다.

세 링크 모두 클릭하면 먼저 이 창을 닫는다. 이 창은 다른 창보다 위에 표시되어, 열어 둔 채로 두면 새로 연 앱을 가린다.

## 확인

`apps/react/e2e/about-this-mac.spec.ts`에 E2E 시험 4개를 작성했다.

| 시험                                                                                 | 확인 내용                                                                                                                                                          |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Apple 메뉴 맨 위에서 열면 만든 사람의 프로필이 보이고, 닫기·Esc로 닫는다             | 첫 메뉴 항목, 이름·영문 이름, 사양 줄 6개, GitHub의 ↗와 새 탭, 열면 메뉴가 닫히고 닫기 버튼에 초점                                                                 |
| 빈 곳을 잡아 옮기고, 추가 정보…는 macOS처럼 시스템 설정의 정보를 연다                | 끈 거리만큼 이동하는지, 설정이 이미 열려 있어도 정보 항목으로 이동하는지                                                                                           |
| 저작권 줄 위의 개인정보 처리 방침(macOS의 규제 인증서 자리)은 Finder에서 문서를 연다 | Finder에서 `docs/privacy.md`가 열리는지                                                                                                                            |
| 이메일을 누르면 기기의 메일 앱이 아니라 이 사이트의 메일 앱에서 새로운 메시지를 연다 | 받는 사람 줄에 사이트 주인의 이름과 이메일이 표시되는지. 작성을 취소해 메일 앱을 열어 둔 상태에서 시스템 설정의 정보에서 이메일을 다시 눌러도 작성 화면이 열리는지 |

마지막 시험의 후반부가 요청 저장소 구조의 핵심을 검증한다. 요청 저장소를 마운트 시각에만 읽었다면, 이미 열려 있는 메일 앱은 두 번째 요청을 처리하지 못한다.

## 남은 과제와 정리

- 창 위치는 저장하지 않는다. 닫았다 다시 열면 화면 가운데에 표시된다. macOS도 같은 방식으로 동작해 그대로 두었다.
- 창을 화면 밖으로 끌어내는 것을 제한하지 않는다. 닫고 다시 열면 가운데로 돌아오므로 현재까지 문제가 되지 않았다.
- "다른 앱을 열어 달라"는 요청은 앱끼리 직접 호출하지 않고 작은 저장소에 기록하는 방식이 적합하다. 대상 앱이 닫혀 있든 열려 있든 같은 코드로 처리하고, 요청하는 쪽은 대상 앱의 내부 구현에 의존하지 않는다. 이후 바탕화면 폴더 아이콘(`finderFolderRequest`)도 같은 방식으로 구현했다.
