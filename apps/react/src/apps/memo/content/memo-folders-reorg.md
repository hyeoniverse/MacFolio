블로그(메모 앱)의 폴더는 글 파일 머리말의 `category`로 정해진다. 10월 9일([#143](https://github.com/hyeoniverse/MacFolio/pull/143)) 이전의 구조와 폴더별 글 수는 다음과 같았다.

```text
개발기/MacFolio/
  데스크톱 15 · 메모 13 · 회고 10 · 백엔드 10 · 배포·운영 10
  프로젝트·GitHub 8 · 빌드·테스트 6 · 공통 UI 6 · 트래픽 분석 4 · 휴대폰 2
```

폴더 구조는 한 번에 정해지지 않았다.

| 날짜  | 변경                                                                                           |
| ----- | ---------------------------------------------------------------------------------------------- |
| 10/3  | 백엔드 설계 문서를 작성하면서 '백엔드' 폴더를 새로 만들고, 이전에 쓴 백엔드 글을 이동          |
| 10/8  | 회고 글에 폴더와 태그를 붙이면서 다른 글에도 태그와 폴더 분류를 추가                           |
| 10/12 | [병합 방식 글](/memo/merge-strategies)은 MacFolio가 아닌 일반론이라 개발기 밖에 새 폴더를 생성 |

이렇게 폴더가 하나씩 추가되면서 앱 이름 기준 폴더와 주제 기준 폴더가 섞였고, 아래와 같이 재분류했다.

## 기존 구조의 문제

- **상위 두 단계가 항상 같다.** 이 블로그의 글은 모두 MacFolio 개발 기록이라서, `개발기/MacFolio`는 글을 구분하는 역할을 하지 않는다. 폴더는 최대 3단계인데 그중 두 단계를 이 이름이 차지한다.
- **분류 기준이 섞였다.** `메모`는 앱, `휴대폰`은 화면 크기, `백엔드`는 계층, `회고`는 글 종류다. [게시 버튼 글자가 흐렸던 원인](/memo/memo-button-specificity) 글은 `메모`에, 비슷한 CSS 문제인 [시계 글자가 바뀔 때마다 흔들리던 메뉴 막대](/memo/menubar-clock-width)는 `데스크톱`에 있었다. 같은 종류의 문제와 해결 방법을 한 폴더에서 조회할 수 없다.
- **프로젝트 글이 별도 폴더에 있었다.** 프로젝트를 창으로 표시하거나 GitHub 앱을 만든 글도 결국 화면 구현 기록이다.

## 변경한 구조

```text
프론트엔드/
  기능          24  Finder·사진·API 문서 앱, 프로젝트 앱, GitHub 앱, 메모 태그·잠금,
                    표 다듬기, 메뉴 막대 메뉴, 앱 주소, 배경화면 올리기 …
  트러블슈팅     8  한국어 굵게, 선택자 우선순위, sticky와 stacking context,
                    Dock 겹침, 시계 폭, 좁은 창 제목 …
  구조·리팩터링  9  공통 메뉴·버튼, CSS 층, 인라인 스타일, 퇴장 애니메이션,
                    desktop-core, 이 글
  모바일         3  제어 센터 쓸기, iOS 모양 앱, 휴대폰 메모
백엔드          15  API, 로그인, 댓글, 메일, 트래픽 분석, AI 요약
인프라/
  배포·운영     10
  빌드·테스트    6
회고            10
```

![폴더 구조 전과 후](./images/memo-folders-reorg-tree.svg '앱·화면 크기·계층이 섞였던 10개 폴더를 영역과 작업의 종류로 나눴다')

최상위는 개발 영역으로 나눴다. 채용 담당자나 다른 개발자가 "백엔드는 어떻게 구현했나"를 찾아 들어오기 쉽게 하기 위해서다.

프론트엔드 하위는 어느 앱의 기록인지가 아니라 어떤 종류의 작업이었는지로 나눴다.

| 폴더          | 해당하는 글                                                   |
| ------------- | ------------------------------------------------------------- |
| 기능          | 새 기능을 구현한 글. 표 편집·찾기 같은 편집기 기능도 포함     |
| 트러블슈팅    | 잘못 표시되거나 동작하던 문제의 원인을 찾아 수정한 글         |
| 구조·리팩터링 | 화면은 유지하고 코드 구조를 바꾼 글. `!important` 정리도 포함 |
| 모바일        | 작은 화면 전용으로 구현한 기능                                |

처음에는 편집기 폴더를 별도로 만드는 안도 있었다. 하지만 편집기 글 넷 중 셋은 기능을 추가한 글이고 하나(한국어 굵게)는 원인을 찾은 글이라, 기준을 하나로 유지하려면 기능과 트러블슈팅으로 나누는 편이 맞았다. `!important`를 삭제한 글도 같은 이유로, CSS 주제지만 트러블슈팅이 아니라 구조·리팩터링에 분류했다. 화면에 드러난 문제가 없었고 코드 구조만 바꿨기 때문이다.

## 시험

폴더 이름에 의존하던 E2E 시험을 새 구조에 맞춰 수정했다.

- 1단 폴더 `개발기` → `프론트엔드`, 2단 폴더 `MacFolio` → `기능`
- 3단 제한 시험은 `프론트엔드/기능/초안`으로
- 휴대폰의 폴더 순서 바꾸기 시험은 가짜 폴더 두 개를 추가하던 코드를 삭제하고, 저장소 폴더 네 개(백엔드·인프라·프론트엔드·회고)로
- 새 메모가 저장될 폴더를 확인하던 시험의 목적은 "최근 삭제된 항목이 아니다"를 확인하는 것이었다. 그런데 "가장 최근 글의 폴더 이름"을 문자열로 기록해 두어서, 글을 하나 추가할 때마다 실패할 수 있었다. 목적대로 `최근 삭제`가 아닌지만 확인하도록 수정했다.

서버에서 수정한 글은 서버의 분류가 우선하므로 이 변경으로 이동하지 않는다. 해당하는 글이 하나 있어서 관리자 화면에서 별도로 이동한다.

글 91편의 `category`를 변경했고, 커밋의 변경 규모는 91개 파일, 198줄 추가, 133줄 삭제였다.

## 이틀 뒤: 최상위 폴더 복원

10월 11일([#192](https://github.com/hyeoniverse/MacFolio/pull/192))에 최상위의 '개발기 › MacFolio'를 복원했다. 제거한 뒤에는 이 블로그가 무엇의 기록인지 폴더에 드러나지 않았고, 앞으로 다른 프로젝트의 글이 생기면 '개발기' 아래에 나란히 배치할 위치도 필요했다.

![폴더 구조의 세 번의 변경](./images/memo-folders-reorg-history.svg '영역으로 나눈 기준은 유지하고, 프론트엔드 하위의 작업 종류 폴더는 3단계 제한 때문에 통합했다')

폴더는 최대 3단계다. 이 규칙은 화면과 서버가 함께 사용한다(desktop-core의 메모 규칙). 상위 두 단계를 복원하면 남는 단계는 하나뿐이라, 이 글에서 만든 프론트엔드 하위의 기능·트러블슈팅·구조·리팩터링·모바일 폴더와 인프라 하위의 배포·운영·빌드·테스트 폴더는 통합했다. 규칙을 4단계로 늘리는 방법도 있었지만, 사이드바의 깊이가 늘어나고 휴대폰 화면에서 들여쓰기 폭이 부족해진다. 글 탐색은 하위 폴더 대신 [태그](/memo/memo-tags)와 검색이 담당한다.

| 선택지                              | 장점                                                | 포기한 것                                    |
| ----------------------------------- | --------------------------------------------------- | -------------------------------------------- |
| 10/9 영역 + 작업 종류 (최상위 없음) | 같은 종류의 문제를 한 폴더에서 조회한다             | 이 블로그가 무엇의 기록인지 드러나지 않는다  |
| 10/11 개발기 › MacFolio › 영역      | 최상위가 의미를 가진다, 다른 프로젝트를 배치할 위치 | 작업 종류 폴더                               |
| (기각) 4단계로 늘리기               | 두 장점을 모두 유지한다                             | 사이드바가 깊어지고 휴대폰에서 폭이 부족하다 |

10월 19일 기준 이 저장소의 글은 프론트엔드 91편, 인프라 50편, 회고 33편, 백엔드 27편이다. 이 글의 `category`도 10월 11일 변경에서 `개발기/MacFolio/프론트엔드`로 바뀌었다.

## 정리

- 분류 체계는 한 번에 확정하기 어렵다. 이틀 만에 일부를 되돌렸지만, "앱 이름이 아니라 영역으로"라는 기준은 유지됐다. 되돌린 것은 폴더 깊이였고 분류 기준이 아니었다.
- 폴더 이름을 문자열로 기록한 시험은 분류를 바꿀 때마다 실패한다. "가장 최근 글의 폴더 이름"처럼 데이터에 따라 바뀌는 값을 시험에 기록하지 않고, 시험이 확인하려는 조건(여기서는 "최근 삭제가 아니다")만 검사하면 데이터가 바뀌어도 유지된다.
- 3단계 제한처럼 화면과 서버가 함께 지키는 규칙을 한 곳(desktop-core)에 정의해 두었기 때문에, 분류를 바꿔도 두 쪽의 검증 결과가 어긋나지 않았다.
