블로그(메모 앱)의 폴더는 글 파일 머리말의 `category`로 정해진다. 지금까지는 이랬다.

```
개발기/MacFolio/
  데스크톱 15 · 메모 13 · 회고 10 · 백엔드 10 · 배포·운영 10
  프로젝트·GitHub 8 · 빌드·테스트 6 · 공통 UI 6 · 트래픽 분석 4 · 휴대폰 2
```

## 무엇이 불편했나

- **두 단이 늘 같다.** 이 블로그의 글은 모두 MacFolio를 만든 이야기라서, `개발기/MacFolio`는 아무것도 가르지 않는다. 폴더는 3단까지인데 그중 두 단을 이 이름이 쓴다.
- **기준이 섞였다.** `메모`는 앱, `휴대폰`은 화면 크기, `백엔드`는 계층, `회고`는 글 종류다. "선택자 우선순위에 진 색" 글은 `메모`에, 비슷한 CSS 문제인 "시간이 바뀔 때 움찔하던 메뉴 막대"는 `데스크톱`에 있었다. 같은 종류의 문제를 어떻게 풀었는지 모아 보기 어렵다.
- **프로젝트 글이 따로 있었다.** 프로젝트를 창으로 띄우거나 GitHub 앱을 만든 글은 결국 화면을 만든 이야기다.

## 바꾼 구조

```
프론트엔드/
  기능          24  Finder·사진·API 문서 앱, 프로젝트 앱, GitHub 앱, 메모 태그·잠금,
                    표 다듬기, 메뉴 막대 메뉴, 앱 주소, 배경화면 올리기 …
  트러블슈팅     8  한국어 굵게, 선택자 우선순위, sticky와 stacking context,
                    Dock 겹침, 시계 폭, 좁은 창 제목 …
  구조·리팩터링  9  공통 메뉴·단추, CSS 층, 인라인 스타일, 퇴장 애니메이션,
                    desktop-core, 이 글
  모바일         3  제어 센터 쓸기, iOS 모양 앱, 휴대폰 메모
백엔드          15  API, 로그인, 댓글, 메일, 트래픽 분석, AI 요약
인프라/
  배포·운영     10
  빌드·테스트    6
회고            10
```

맨 위는 일하는 영역으로 나눴다. 채용 담당자나 다른 개발자가 "백엔드는 어떻게 했나"를 찾아 들어오기 쉽게 하려는 것이다.

프론트엔드 안은 어느 앱의 이야기인지가 아니라 어떤 종류의 일이었는지로 나눴다.

| 폴더          | 들어가는 글                                                     |
| ------------- | --------------------------------------------------------------- |
| 기능          | 없던 것을 만든 글. 표 다듬기·찾기 같은 편집기 기능도 여기       |
| 트러블슈팅    | 이상하게 보이거나 동작하던 것의 원인을 찾아 고친 글             |
| 구조·리팩터링 | 겉모습은 그대로 두고 코드를 정리한 글. `!important` 정리도 여기 |
| 모바일        | 작은 화면을 위해 따로 만든 것                                   |

처음에는 편집기를 따로 두는 안도 있었다. 하지만 편집기 글 넷 중 셋은 기능을 더한 글이고 하나(한국어 굵게)는 원인을 찾은 글이라, 기준을 하나로 맞추려면 나누는 편이 맞았다. `!important`를 지운 글도 같은 이유로 CSS 문제지만 트러블슈팅이 아니라 구조·리팩터링에 들어갔다. 보이던 문제가 없었고 코드만 정리했기 때문이다.

## 시험

폴더 이름에 기대던 E2E 시험을 새 구조에 맞췄다.

- 1단 폴더 `개발기` → `프론트엔드`, 2단 폴더 `MacFolio` → `기능`
- 3단 제한 시험은 `프론트엔드/기능/초안`으로
- 휴대폰의 폴더 순서 바꾸기 시험은 가짜 폴더 둘을 더하던 것을 빼고, 저장소 폴더 넷(백엔드·인프라·프론트엔드·회고)으로
- 새 메모가 들어갈 폴더를 확인하던 시험은 원래 "최근 삭제된 항목이 아니다"를 확인하려던 것이다. 그런데 "가장 최근 글의 폴더 이름"을 그대로 적어 두어서, 글을 하나 쓸 때마다 깨질 수 있었다. 뜻대로 `최근 삭제`가 아닌지만 보게 고쳤다.

서버에서 고친 글은 서버의 분류가 우선이라 이 변경으로 옮겨지지 않는다. 그런 글이 하나 있어서 관리자 화면에서 따로 옮긴다.
