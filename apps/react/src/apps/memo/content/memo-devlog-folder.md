10월 9일에 블로그 폴더를 다시 나눴다([블로그 폴더 다시 나누기](/memo/memo-folders-reorg)). 그때 맨 위의 '개발기 › MacFolio'를 뺐다. 모든 글이 그 아래에 있어서, 3단까지인 폴더 중 두 단을 늘 같은 이름이 차지했기 때문이다.

그런데 빼고 보니 이 블로그가 무엇의 기록인지가 폴더에서 보이지 않았다. 앞으로 다른 프로젝트의 글이 생기면 '개발기' 아래에 나란히 둘 자리도 필요하다. 그래서 다시 맨 위에 둔다.

## 3단 안에 맞추기

폴더는 3단까지다. 이 규칙은 화면과 서버가 함께 쓴다(desktop-core의 메모 규칙). '개발기 › MacFolio' 두 단을 다시 붙이면 남는 것은 한 단이다.

| 전                                                | 후                             |
| ------------------------------------------------- | ------------------------------ |
| 프론트엔드 › 기능·모바일·트러블슈팅·구조·리팩터링 | 개발기 › MacFolio › 프론트엔드 |
| 인프라 › 배포·운영·빌드·테스트                    | 개발기 › MacFolio › 인프라     |
| 백엔드                                            | 개발기 › MacFolio › 백엔드     |
| 회고                                              | 개발기 › MacFolio › 회고       |

규칙을 4단으로 늘리는 방법도 있었지만, 사이드바가 그만큼 깊어지고 휴대폰 화면에서 들여쓰기가 좁아진다. 3단을 지키고 프론트엔드·인프라의 하위 폴더를 합쳤다. 글 111편의 `category`를 바꿨고, 글을 찾는 것은 하위 폴더 대신 태그와 검색이 맡는다.

## 시험

폴더 이름과 깊이에 기대던 E2E를 새 구조에 맞췄다.

- 3단 규칙: 이제 '개발기(1) › MacFolio(2) › 회고(3)'가 이미 3단이라, 회고를 고르면 새 폴더를 만들 수 없고, 3단 높이인 '개발기'는 다른 폴더 안으로 옮길 수 없다.
- 폴더 순서(휴대폰 ≡ 손잡이): 맨 위 층 대신 'MacFolio' 아래 네 폴더의 순서를 바꾸고, 정리 내용에 그 경로들이 저장되는지 본다.
- Finder의 블로그: 맨 위에는 '개발기' 폴더 하나가 보이고, Enter로 들어간다.
