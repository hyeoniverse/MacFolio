미리보기 앱의 열기 창에서 **데스크탑 › 포트폴리오**를 두 번 누르면 "비어 있음"이 떴다. 같은 창에서 **문서 › 포트폴리오**로 가면 프로젝트 폴더가 다 보였다. 같은 폴더인데 들어가는 길에 따라 내용이 달랐다.

![고치기 전: 데스크탑 › 포트폴리오가 비어 있다](./images/finder-home-tree-openpanel-before.jpg '고치기 전. 바탕화면의 포트폴리오를 열면 비어 있음이 뜨고, 사이드바는 데스크탑을 칠한다')

![고친 뒤: 프로젝트 폴더가 보인다](./images/finder-home-tree-openpanel-after.jpg '고친 뒤. 같은 동작으로 문서 › 포트폴리오가 열리고, 사이드바도 문서를 칠한다')

## 증상의 원인: 가상본은 비어 있다

바탕화면의 포트폴리오·이력서·자격증은 진짜 폴더가 아니다. macOS의 가상본(alias)처럼 문서 안의 폴더를 가리키는 바로가기다. Finder 트리를 만드는 코드에서 가상본은 이렇게 생겼다.

```ts
desktop.children.push({ kind: 'folder', id: `alias:${target}`, name: real.name, aliasOf: target, children: [] });
```

`kind`는 `'folder'`인데 안에 든 것(`children`)은 늘 비어 있고, 진짜 폴더 id가 `aliasOf`에 들어 있다. Finder는 폴더를 열 때 이 값을 따라간다.

```ts
case 'folder':
	// 바탕화면의 가상본은 원래 폴더로
	go({ folder: item.aliasOf ?? item.id });
```

그런데 미리보기의 열기 창은 그 항목 자체로 들어갔다.

```ts
if (item.kind === 'folder') go(item.id);
```

빈 `children`을 그리니 "비어 있음"이다. Finder처럼 `item.aliasOf ?? item.id`로 바꾸면 고쳐진다. 한 줄이다.

## 한 줄로 끝내도 될까

"이런 거면 구조 자체에 허점이 있는 것 아니냐"는 물음이 나왔다. 가상본을 만나는 곳을 전부 찾아봤다.

| 쓰는 곳                           | 가상본 처리                                |
| --------------------------------- | ------------------------------------------ |
| Finder 열기                       | `aliasOf ?? id`                            |
| 휴대폰 파일 앱 열기·항목 수       | 직접 확인                                  |
| 바탕화면 아이콘 열기·위치 저장    | 직접 확인                                  |
| 끌어서 옮기기, 컴퓨터 파일 올리기 | `resolveAlias`                             |
| 편집 종류·휴지통·영구 삭제        | 직접 확인                                  |
| 찾기, 수정일 계산                 | 건너뜀                                     |
| 최근 항목, 미리보기 폴더          | 확인 안 함 (빈 안을 돌 뿐이라 결과는 맞음) |
| 열기 창의 파일 모으기             | 건너뜀                                     |
| **열기 창의 폴더 열기**           | **없음 → 버그**                            |

12곳이 "가상본이면 `aliasOf`를 따라가라"는 같은 규칙을 **각자 기억해서** 지키고 있었다. 잊으면 오류도 경고도 없이 빈 폴더처럼 동작한다. 타입으로 보면 가상본도 `children`이 있는 멀쩡한 폴더라 TypeScript가 잡아 줄 수도 없다. 최근 항목처럼 확인하지 않았는데 우연히 맞는 곳도 있었다.

git 기록을 보면 어떻게 새었는지 보인다 (한국 시간).

| 시각        | 일                                                                                               |
| ----------- | ------------------------------------------------------------------------------------------------ |
| 10-19 03:55 | 열기 창이 Finder와 같은 트리를 쓰기 시작. 폴더 열기는 `go(item.id)`                              |
| 10-19 05:41 | 두 시간 뒤 가상본 도입. Finder·휴대폰·바탕화면·편집 규칙에는 처리를 넣었지만 **열기 창은 빠짐**  |
| 10-19 10:40 | 열기 창을 고치며 파일 모으기에는 가상본 건너뛰기를 넣었지만, **같은 파일의 폴더 열기는 또 빠짐** |

같은 파일 안에서도 한 곳은 고치고 한 곳은 놓쳤다. 사람이 기억해야 하는 규칙은 이렇게 샌다. 그래서 한 줄 수정에 더해 구조를 바꿨다.

![가상본을 어떻게 표현했나: 전과 후](./images/finder-home-tree-model.svg '위: 폴더의 한 변형이던 가상본을 따로 된 종류로. 아래: 따로 된 꼭대기 넷을 디스크 하나 아래 트리로')

## 가상본을 따로 된 종류로

가상본을 폴더의 변형이 아니라 따로 된 종류로 나눴다. 안에 든 것이 없으니 `children`도 없다.

```ts
export interface AliasItem extends ItemBase {
	kind: 'alias';
	/** 원래 폴더의 id (예: docs:포트폴리오) */
	target: string;
}
```

이제 `kind === 'folder'`로 고르는 코드에 가상본이 섞이지 않는다. 폴더처럼 다루려면 `resolveAlias`로 원래 폴더를 찾아야 하고, 찾지 않으면 "빈 폴더"가 아니라 아예 폴더가 아니다. 새 종류를 빠뜨렸을 때 컴파일러가 잡는 곳도 만들었다.

- 목록 보기의 종류 이름표는 `Record<FinderItem['kind'], string>`이라, 새 종류의 이름이 없으면 컴파일 오류가 난다
- Finder의 열기는 `switch`의 끝에 `never` 검사를 두었다. 여는 법을 정하지 않은 종류가 생기면 컴파일 오류가 난다

```ts
default: {
	// 새 종류를 더하면 여기서 컴파일 오류가 난다 (여는 법을 정하게)
	const unhandled: never = item;
	return unhandled;
}
```

모든 실수를 컴파일러가 잡지는 않는다. 앞으로 누가 `if (item.kind === 'folder')`만 쓰고 가상본을 빠뜨리면, 오류 없이 "아무 일도 일어나지 않는" 쪽으로 실패한다. 그래도 빈 폴더가 정상처럼 보이던 것보다는 훨씬 눈에 띈다.

12곳을 새 종류로 맞췄다. 화면 쪽 타입만 바뀌고, 서버에 저장하는 구조(`layout.aliases`는 원래 폴더 id 목록)와 API는 그대로다.

## 그런데 진짜 Mac은 루트가 하나다

다음 물음은 "진짜 OS처럼 루트가 있고 그 안에 폴더가 있는 구조가 맞지 않나"였다. 실제 macOS의 Finder를 열면 홈 폴더 안에 데스크탑·문서·다운로드가 있고, 사이드바의 즐겨찾기는 그 폴더들로 가는 바로가기다. 이 사이트의 Finder는 데스크탑·문서·블로그·응용 프로그램이 **서로 따로 된 꼭대기**였고, 사이드바는 그 목록을 그대로 그렸다.

트리를 macOS처럼 바꿨다.

```text
Macintosh HD
├─ 사용자 › hyeoniverse
│  ├─ 공용 · 그림 · 다운로드 · 동영상 · 음악   (비어 있고, 열면 안내)
│  ├─ 데스크탑
│  ├─ 문서 › 이력서 · 포트폴리오(› 프로젝트들) · 자격증
│  └─ 블로그
└─ 응용 프로그램
```

![홈 폴더](./images/finder-home-tree-home.jpg '사이드바에 위치 칸(hyeoniverse, Macintosh HD)이 생기고, 경로 막대는 디스크부터 이어진다')

- 사이드바의 즐겨찾기는 트리 안 폴더로 가는 바로가기가 되고, 그 아래 **위치** 칸에 홈과 디스크가 생겼다
- 경로 막대는 `Macintosh HD › 사용자 › hyeoniverse › 문서`처럼 디스크부터 이어진다
- 사이드바에서 칠할 곳은 "경로에서 가장 안쪽의 사이드바 항목"이다. 문서 › 이력서 안이면 이력서, 홈의 다운로드 안이면 홈
- 블로그는 macOS에 없는 폴더라 홈 안에 두었다
- macOS 기본 폴더는 담을 것이 없어 비어 있다. 열면 "다운로드한 파일이 없습니다."처럼 폴더마다 안내를 띄운다
- 홈 폴더 이름은 GitHub 계정과 같은 `hyeoniverse`
- 미리보기 열기 창과 휴대폰 파일 앱은 지금처럼 즐겨찾기 목록만 보인다

### 서버는 건드리지 않았다

관리자가 만든 폴더와 옮긴 파일은 서버에 저장되는데, 그 기록은 `desktop`, `docs`, `docs:포트폴리오`, `projects/<id>` 같은 **폴더 id**로 적혀 있다. 서버도 이 id 모양을 정규식으로 검사한다.

```ts
export const FINDER_BUILTIN_PARENT =
	/^(trash|desktop|docs|docs:(이력서|포트폴리오|자격증)|projects\/[a-z0-9][a-z0-9-]{0,39})$/;
```

id를 `/Users/hyeoniverse/Documents`처럼 경로로 바꾸면 저장된 데이터를 옮기고 서버 검사도 고쳐야 한다. 그래서 **id는 그대로 두고 그 위에 `mac`·`users`·`home` 노드만 얹었다.** 화면 쪽 트리 만들기, 사이드바, 경로 막대, 열기 창, 휴대폰 파일 앱만 바뀐다. 대신 새 기본 폴더와 홈·디스크에는 관리자가 폴더를 만들거나 파일을 놓을 수 없다. 서버 규칙 밖이라서다.

꼭대기 목록에 기대던 곳은 세 군데였다. Finder의 사이드바·이동 메뉴·좁은 창의 위치 칩, 열기 창의 사이드바와 강조, 휴대폰 파일 앱의 즐겨찾기다. 모두 즐겨찾기 id 목록으로 트리에서 폴더를 찾아 그리게 바꿨다.

```ts
export const FAVORITE_IDS = ['desktop', 'docs', 'blog', 'apps'] as const;

/** ids의 폴더들 (트리에 없는 것은 건너뛴다) */
export const foldersOf = (roots: FinderItem[], ids: readonly string[]): FolderItem[] =>
	ids.map((id) => find(roots, id)).filter((item): item is FolderItem => item?.kind === 'folder');
```

### 폴더 문양

macOS의 기본 폴더는 앞면에 문양이 눌려 있다. 다운로드는 화살표, 음악은 음표, 응용 프로그램은 A다. 폴더 아이콘은 SVG 하나를 모든 폴더가 같이 쓰고 있어서, 폴더 id마다 앞면 가운데에 진한 파랑 선을 얹게 했다. Macintosh HD는 폴더 대신 디스크 아이콘이다.

## 확인한 것

- 열기 창에서 데스크탑 › 포트폴리오를 열면 MacFolio 프로젝트 폴더가 보이는지 확인하는 E2E를 먼저 더했다. **고치기 전 빌드에서 실패**하고 고친 뒤 통과하는 것을 보고 나서 구조를 바꿨다. 시험이 정말 이 버그를 잡는지 확인한 것이다
- 홈과 디스크를 탐색하는 E2E를 더했다. 홈의 폴더 순서, 문서로 들어갔을 때의 사이드바 강조와 경로 막대, 다운로드의 안내, 디스크의 응용 프로그램을 본다
- 단위 테스트 781개, E2E 566개(데스크톱 Chrome, iPhone, Android)가 통과했다

## 정리

- 바탕화면의 가상본을 `kind: 'folder'`에 빈 `children`과 `aliasOf`를 붙여 표현했더니, 12곳이 "가상본이면 따라가라"를 각자 기억해야 했다. 열기 창 한 곳이 빠져 빈 폴더가 열렸다
- 기억해야 하는 규칙은 샌다. 가상본을 `kind: 'alias'`로 나눠 폴더에 섞이지 않게 하고, `Record`와 `never` 검사로 새 종류를 빠뜨리면 컴파일 오류가 나게 했다
- 따로 놀던 꼭대기 넷을 macOS처럼 Macintosh HD › 사용자 › 홈 아래 한 트리로 묶고, 사이드바 즐겨찾기를 그 안 폴더로 가는 바로가기로 바꿨다
- 서버에 저장된 폴더 id는 그대로 두고 그 위에 노드만 얹어, 서버·API·저장된 데이터는 바꾸지 않았다
