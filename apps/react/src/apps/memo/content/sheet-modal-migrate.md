버튼 다음은 시트와 모달이다([#247](https://github.com/hyeoniverse/MacFolio/pull/247)). 리팩터링 계획 4단계의 마지막 항목은 "앱마다 따로 만든 버튼·시트·목록을 공통 컴포넌트로 바꾸기"다. 버튼은 `IconButton` 45곳과 `Button` 30곳을 교체해 완료했다. 이번에는 아래에서 올라오는 시트(`Sheet`)와 화면 가운데 표시되는 모달(`Modal`)을 조사한다.

## 조사 방법

`apps/react/src/apps`에서 [`aria-modal`](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-modal), `role="dialog"`, 바깥 클릭 시 닫히는 오버레이, `key === 'Escape'` 처리를 검색했다. 메일의 시트와 음악의 지금 재생 중 화면은 이미 `Sheet`를 사용하고, 단축키 창·로그인 결과·Launchpad는 이미 `Modal`을 사용한다. 그 밖에 검색된 것은 다음과 같다.

| 위치                             | 특징                                       | 결정           |
| -------------------------------- | ------------------------------------------ | -------------- |
| 메모 이미지 크게 보기            | 화면 전체 오버레이, Esc·바깥 클릭으로 닫힘 | `Modal`로 교체 |
| 설정 프로젝트 그림 크게 보기     | 오버레이, ←·→ 이동, Esc 전파 차단          | 유지           |
| 설정 프로젝트 시트               | 데스크톱 창 안의 시트, 배경 `inert`        | 유지           |
| 사진 크게 보기 (데스크톱·휴대폰) | 오버레이 없는 전체 화면 보기               | 유지           |
| 메모 버전 기록·서식·표 패널      | 팝오버                                     | 대상 아님      |
| Safari 데모 페이지의 창          | 다른 사이트를 재현하는 데모                | 대상 아님      |

계획 작성 시각에는 메일·메시지·음악·설정·휴지통이 각자 시트와 모달을 구현했다고 기록했다. 그 가운데 메일과 음악, 설정의 창들은 `Sheet`·`Modal`을 추출할 때 이미 교체했고, 메시지와 휴지통에는 별도 구현이 남아 있지 않았다. 교체 대상이 적다는 것도 조사 결과다. 의미가 다른 것을 무리하게 통합하지 않았다.

## 메모 이미지 크게 보기

본문 이미지를 클릭하면 화면 전체에 어두운 오버레이를 표시하고 가운데에 이미지를 크게 표시한다. 오버레이가 `role="dialog"`였고, Esc 처리와 닫힐 때의 페이드아웃을 직접 구현했다. `Modal`의 `scope="screen"`과 동작이 같다.

![교체 후 메모의 이미지 크게 보기](./images/sheet-modal-migrate-lightbox.jpg 'Modal scope="screen"으로 연 이미지 크게 보기. 화면 전체를 rgba(0, 0, 0, 0.75) 오버레이가 덮고 가운데에 이미지를 표시한다')

직접 구현하던 포털·Esc 처리·퇴장 애니메이션이 `Modal` 하나로 바뀌었다(`apps/react/src/apps/memo/components/MarkdownImage.tsx`).

```tsx
// 전
return createPortal(
	<div
		ref={lightbox}
		className="memo-lightbox"
		role="dialog"
		aria-modal="true"
		aria-label={alt || '이미지'}
		onClick={onClose}
	>
		<img src={src} alt={alt} />
	</div>,
	document.body
);

// 후
return (
	<Modal
		label={alt || '이미지'}
		onClose={onClose}
		scope="screen"
		overlayClassName="memo-lightbox"
		className="memo-lightbox-box"
	>
		<img src={src} alt={alt} onClick={onClose} />
	</Modal>
);
```

닫힐 때 포커스 복원은 effect 하나로 처리했다. 열리는 시각의 포커스 요소(연 버튼)를 저장해 두었다가 cleanup에서 복원한다.

```ts
useEffect(() => {
	const opener = document.activeElement as HTMLElement | null;
	return () => opener?.focus({ preventScroll: true });
}, []);
```

교체하면서 맞춘 것은 세 가지다.

| 항목                 | 기존 동작                                      | 교체 후 처리                                                                                                                                                                                                     |
| -------------------- | ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 오버레이 색과 레이어 | 앱 CSS에 직접 지정                             | `--ui-modal-dim`을 `rgba(0, 0, 0, 0.75)`로, `--ui-modal-z`를 메뉴와 같은 레이어로 지정. 안쪽 여백과 `zoom-out` 커서는 오버레이에 유지                                                                            |
| 이미지 클릭 시 닫힘  | 오버레이 전체가 클릭을 받아 이미지 클릭도 닫힘 | `Modal`은 오버레이만 클릭을 받으므로, 상자는 오버레이 안쪽을 채우되 [`pointer-events: none`](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/pointer-events)으로 두고 이미지에서 닫기 호출 |
| 포커스               | 포커스를 옮기지 않아 연 버튼에 유지            | `Modal`이 열 때 상자에 포커스를 두므로, 닫히면 연 버튼으로 포커스 복원                                                                                                                                           |

달라진 것은 닫힘 애니메이션 하나다. 전체가 함께 페이드아웃되던 것이, 다른 모달과 같이 오버레이는 페이드아웃되고 이미지는 축소되며 사라진다.

![전에는 덮개 하나가 모든 누름을 받았고, 후에는 덮개가 바깥 누름을, 이미지가 자기 누름을 받는다](./images/sheet-modal-migrate-hit.svg '옮기기 전과 뒤에 누름을 받는 곳')

## 교체하지 않은 것

설정 프로젝트의 그림 크게 보기는 외형만 보면 같다. 그러나 Esc를 자기 요소에서 받아 [이벤트 전파](https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Scripting/Events)를 차단한다. 뒤에 프로젝트 시트가 열려 있고, 그 시트도 Esc로 닫히기 때문이다. `Modal`의 Esc는 `window`에서 받으므로 교체하면 Esc 한 번에 둘이 함께 닫힌다. ←·→ 버튼과 닫기 버튼도 그림 상자 바깥에 있어 DOM 구조를 바꿔야 한다. 그래서 유지했다.

![그림 보기가 Esc를 자기 요소에서 받을 때와 Modal처럼 window에서 받을 때의 차이](./images/sheet-modal-migrate-escape.svg 'Esc를 어디서 받느냐가 갈랐다')

설정의 프로젝트 시트는 데스크톱 창 안에서 열리는 시트다. 배경을 [`inert`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/inert)로 비활성화하고 포커스를 시트 안에 가둔다. 휴대폰 전용인 `Sheet`와 의미가 다르다. 사진의 크게 보기는 오버레이가 없는 전체 화면이고 Esc나 바깥 클릭으로 닫지 않는다. 대화상자라기보다 화면 전환이다.

## 확인

E2E를 실행하며 이미지 크게 보기를 연 상태에서 오버레이와 이미지의 계산된 스타일(위치, 레이어, 여백, 배경색, 커서, 크기, 둥근 모서리, 그림자)을 교체 전후에 기록해 비교했다. 값은 모두 같았고, 스크린샷도 픽셀 단위로 같았다. 접근 가능한 이름(이미지 설명)과 `aria-modal`도 같다.

## 채택한 방법과 제외한 방법

교체하지 않은 세 곳을 무리하게 통합하는 방법도 있었다.

| 방법                                          | 결과                                                                         |
| --------------------------------------------- | ---------------------------------------------------------------------------- |
| `Modal`에 `escapeScope="self"` 같은 옵션 추가 | 한 곳을 위한 옵션이 공통 컴포넌트에 생긴다                                   |
| 설정 그림 보기의 구조를 바꿔 맞추기           | 상자 밖의 ←·→·닫기 버튼 배치를 다시 구현해야 하고, 화면이 바뀐다             |
| 유지하고 이유를 `docs/ui.md`에 기록 (채택)    | 공통 컴포넌트는 단순하게 유지되고, 다음 작업자가 같은 검토를 반복하지 않는다 |

이번 작업의 원칙은 "화면은 유지하고, 의미가 같은 것만 교체한다"였다. 그래서 세 번째 방법을 선택했다.

## 버튼 수 재집계

`docs/ui.md`의 "직접 쓴 `<button>` 220곳"은 다시 집계했다. 처음 89개 파일 295곳을 집계한 방법은 `apps/react/src`의 `.tsx`에서 `<button`이 있는 행을 세되, 시험 파일과 공통 컴포넌트 `shared/ui`를 제외하는 것이었다. 같은 방법으로 현재를 집계하면 91개 파일 265곳이다.

| 시점             | 집계 값 | 계산 방법                                 |
| ---------------- | ------- | ----------------------------------------- |
| 첫 집계          | 295곳   | 위 방법                                   |
| 교체 직전 (실제) | 340곳   | 그사이 Safari 프로젝트 페이지와 앱이 증가 |
| 문서의 값        | 220곳   | 첫 집계에서 교체한 수만 뺌 (오류)         |
| 재집계           | 265곳   | 위 방법을 현재 코드에 다시 적용           |

265곳 가운데 91곳은 Safari 프로젝트 데모 페이지다.

## 숫자

- 변경 파일 4개, 98줄 추가와 47줄 삭제. 그중 코드는 `MarkdownImage.tsx`(42줄 변경)와 `markdown.css`(21줄 변경)이고 나머지는 `docs/ui.md`와 이 글이다.
- 이로써 `Modal`을 사용하는 다이얼로그는 여섯 개가 됐다(경고창, 이름 변경, 단축키, 로그인 결과, Launchpad, 메모 이미지 크게 보기).

## 남은 것·배운 것

- 계획에 "앱마다 따로 만든 시트·창"이라고 기록했던 것의 대부분은 이미 앞선 PR에서 교체되어 있었다. 계획 문서의 목록은 실행 직전에 다시 집계해야 한다([공통 부품 목록을 먼저 적고, 아홉 후보를 다시 쟀다](/memo/ui-inventory)).
- 외형이 같아도 키 처리(Esc를 어디서 받는가)가 다르면 같은 컴포넌트가 아니다. 공통 컴포넌트로 교체할지 결정할 때는 키보드 동작부터 확인한다.
- 버튼 수는 집계 방법을 문서에 함께 기록한다. 이번에 수가 맞지 않았던 원인이 "첫 집계에서 교체한 수만 뺀" 계산이었다.
