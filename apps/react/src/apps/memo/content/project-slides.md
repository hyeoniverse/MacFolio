미리보기 앱으로 이력서 PDF를 열 수 있게 되자, 프로젝트마다 만들어 둔 발표 자료도 같은 길로 보이고 싶어졌다. 발표 자료는 스크롤해서 읽는 문서가 아니라 한 장씩 넘겨 보는 것이라, macOS 미리보기의 슬라이드쇼부터 만들었다.

## 슬라이드쇼

macOS 미리보기에서 보기 › 슬라이드쇼(⇧⌘F)를 고르면 화면이 검게 바뀌고 쪽 하나가 화면 가득 뜬다. 여기서도 같다.

- 지금 보던 쪽부터 시작한다.
- 쪽은 pdf.js로 화면 크기에 맞춰 그린다. 캔버스는 기기 픽셀 비율만큼 촘촘하게 그려 레티나 화면에서도 글자가 흐리지 않다.
- → ↓ 스페이스 PageDown은 다음, ← ↑ PageUp은 이전, Home·End는 처음과 끝, Esc는 끝내기. 화면을 누르면 다음 쪽이다.
- 마우스를 움직이면 아래에 작은 조절 막대(이전 / 3 / 27 / 다음 / 닫기)가 뜨고, 2초 동안 가만히 있으면 커서와 함께 사라진다.
- 브라우저가 허락하면 전체 화면으로 띄운다. 브라우저 쪽에서 전체 화면을 빠져나와도 슬라이드쇼가 같이 끝난다.

키는 창 전체에서 먼저(capture) 받는다. 그러지 않으면 뒤에 있는 미리보기 창의 ←→ 쪽 넘기기나 메뉴 막대 단축키가 같이 움직인다.

끝내면 미리보기 창이 끝낸 쪽으로 스크롤한다. 발표를 하다 멈춘 자리에서 바로 문서를 이어 읽을 수 있다.

## 프로젝트에 발표 자료 붙이기

프로젝트 정보에 `slides` 필드를 더했다. 값은 Finder 문서(R2)에 올린 PDF의 키다(예: `portfolio/abc123.pdf`).

관리자는 시스템 설정 › 프로젝트에서 프로젝트를 편집하고, 주소와 기술의 "발표 자료"에서 PDF를 고른다. 목록에는 문서 폴더의 PDF만 나온다. 고른 파일을 나중에 지우면 "찾을 수 없는 파일"로 남겨 두어, 저장할 때 몰래 사라지지 않는다.

서버와 화면은 같은 검사(`parseProjects`)를 쓴다. 키는 문서 폴더(이력서·포트폴리오·자격증) 안의 `.pdf` 하나만 받는다. 주소나 `../` 같은 값은 거절한다.

## 프로젝트 페이지의 버튼

발표 자료가 있고 그 파일이 문서 목록에 있으면, 프로젝트 페이지의 링크 묶음(여기서 열기, 데모, GitHub) 끝에 "발표 자료 보기" 버튼이 생긴다. 직접 짠 페이지와 템플릿 페이지(카드, 키노트, 벤토, 개발자 도구 등)가 모두 같은 버튼을 쓴다.

누르면 미리보기 앱이 맨 앞으로 오고 그 PDF가 열린다. 거기서 ⇧⌘F를 누르면 바로 발표 화면이다. 휴대폰에서는 창이 없으니 PDF를 새 탭으로 연다.
