폴더는 같은 계층끼리 항상 가나다순으로 정렬됐다. '개발기'와 '회고'처럼 자주 여는 폴더를 위에 배치하려면 이름을 바꾸는 방법밖에 없었다. iOS 메모는 폴더 화면의 편집 모드에서 행 오른쪽의 ≡ 핸들을 드래그해 순서를 바꾼다.

![폴더 순서 바꾸기](./images/memo-folder-order.jpg '편집 모드에서는 행마다 ≡ 핸들이 표시된다. 드래그하는 동안 잡은 폴더가 떠오르고, 지나간 폴더는 자리를 비킨다')

PR([#68](https://github.com/hyeoniverse/MacFolio/pull/68))은 서버(정리 내용 검증), 화면(정렬·드래그), 시험을 함께 수정했다. 변경 규모는 15개 파일, 301줄 추가, 13줄 삭제다.

10월 2일 오전, 휴대폰 메모의 폴더 화면을 iOS 메모 편집 화면의 스크린샷과 비교하며 맞추고 있었다. 새 폴더·편집 버튼을 복원하고 나니 iOS에는 편집 모드에서 행마다 ≡ 핸들이 있었다. 이름을 바꾸지 않고 순서를 정하려면 이 핸들이 필요해서 함께 구현했다.

## 저장: 경로 목록 하나

저장 방식은 세 가지를 비교해 선택했다.

| 방법                                            | 장점                                            | 단점                                                                                      |
| ----------------------------------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------- |
| 폴더마다 순번 숫자                              | 정렬이 쉽다                                     | 폴더는 글의 `category`에서 생기기도 해서 별도의 "폴더 객체"가 없다. 숫자를 붙일 곳이 없다 |
| 계층마다 배열 (`{ '개발기': ['MacFolio', …] }`) | 계층 구분이 명확하다                            | 폴더 이름을 바꾸면 키와 값을 모두 수정해야 한다                                           |
| **전체 경로를 한 목록으로**                     | 구조가 단순하고, 정렬은 "목록 안의 위치"로 결정 | 목록에 없는 폴더의 위치를 정해야 한다                                                     |

폴더 정리 내용(만든 폴더, 옮긴 글, 옮긴 폴더, 고정, 잠금)은 서버에 JSON 하나로 저장한다. 여기에 `order`를 추가했다.

```ts
/** 폴더 순서: 폴더 경로를 보일 순서대로. 같은 층끼리 이 순서를 따르고, 없는 폴더는 뒤에 가나다순 */
order: string[];
```

계층마다 따로 저장하지 않고 전체 경로를 한 목록으로 나열했다. 트리를 만들 때 같은 계층의 폴더를 이 목록 안의 위치로 정렬하고, 목록에 없는 폴더(새로 생긴 글의 폴더 등)는 그 뒤에 가나다순으로 배치한다. 따라서 순서를 한 번도 바꾸지 않았으면 기존 정렬과 같다.

```ts
const rank = (path: string) => {
	const index = order.indexOf(path);
	return index === -1 ? Infinity : index;
};
nodes.sort((a, b) => rank(a.path) - rank(b.path) || a.name.localeCompare(b.name));
```

두 폴더가 모두 목록에 없으면 `Infinity - Infinity`가 `NaN`이 되고, `NaN`은 falsy[^falsy]이므로 `||` 뒤의 가나다순 비교로 넘어간다.

| `a` 위치 | `b` 위치 | `rank(a) - rank(b)` | 결과                       |
| -------- | -------- | ------------------- | -------------------------- |
| 0        | 2        | `-2`                | `a`가 앞                   |
| 1        | 없음     | `-Infinity`         | 목록에 있는 `a`가 앞       |
| 없음     | 없음     | `NaN`               | `localeCompare`로 가나다순 |

순서를 바꾸면 해당 계층의 경로만 목록에서 제거하고 새 순서로 다시 추가한다. 다른 계층의 순서는 변경하지 않는다.

```ts
export function reorderFolders(organization: Organization, siblings: string[]): Organization {
	return { ...organization, order: [...organization.order.filter((path) => !siblings.includes(path)), ...siblings] };
}
```

경로로 저장하므로 폴더 이름을 바꾸거나 다른 폴더 안으로 이동하면 목록의 경로도 갱신해야 한다. 이름 바꾸기와 이동은 이미 같은 함수(`relocate`)로 글과 하위 폴더의 경로를 바꾸고 있어서, 그 함수에 `order` 갱신을 한 줄 추가했다. 폴더를 삭제하면 목록에서도 제거한다. 서버도 같은 규칙(최대 3단계, 이름 길이, 중복 금지)으로 `order`를 검증한다(`apps/api/src/memo/organization.ts`). 이전 형식의 JSON에는 `order`가 없으므로, 값이 없으면 빈 배열로 읽는다.

## 드래그: 잡은 폴더만 따라오게

![드래그하는 동안의 세 단계](./images/memo-folder-order-drag.svg '누를 때 위치를 측정하고, 드래그하는 동안은 transform만, 놓을 때 저장한다')

1. **누름**(`pointerdown`): 같은 계층 행들의 위치를 한 번 측정해 보관한다.
2. **이동**(`pointermove`): 포인터가 움직인 만큼 잡은 행을 `translateY`로 이동한다. 잡은 행의 중심이 다른 행의 중심을 넘으면, 그 행은 잡은 행의 높이만큼 반대쪽으로 이동한다.
3. **놓음**(`pointerup`·`pointercancel`): 그 시각의 순서를 저장하고 `transform`을 제거한다.

드래그하는 동안에는 React 상태를 바꾸지 않고 스타일만 바꾸므로 컴포넌트를 다시 렌더링하지 않는다.

- **같은 계층만**: 다른 폴더 안으로 넣는 동작은 '이 폴더 이동' 메뉴나 넓은 창의 드래그 앤 드롭으로 한다. 순서 바꾸기와 섞으면 포인터가 행 경계에 있을 때 사용자의 의도를 판별할 수 없다
- **하위 폴더가 펼쳐진 폴더**: 하위 폴더까지 한 덩어리(`li`)로 함께 이동한다
- **스크롤 방지**: 핸들에 [`touch-action: none`](https://developer.mozilla.org/en-US/docs/Web/CSS/touch-action)을 지정해, 드래그하는 동안 폴더 목록이 스크롤되지 않는다
- **키보드**: 핸들에 포커스를 두고 ↑·↓를 누르면 한 칸씩 이동한다

드래그 라이브러리(dnd-kit 등)는 사용하지 않았다. 같은 계층의 세로 목록 하나만 다루면 되고, 다른 폴더 안으로 넣는 드래그 앤 드롭은 이미 별도로 구현되어 있었다. 필요한 것은 [포인터 이벤트](https://developer.mozilla.org/en-US/docs/Web/API/Pointer_events) 세 개와 `transform`뿐이라 직접 구현했다. 이 코드는 직후에 만든 GitHub 저장소 선택 화면에도 같은 핸들이 필요해서 `shared/ui/reorder/pointerReorder.ts`로 옮겼다. 현재는 메모 폴더, 시스템 설정의 GitHub 저장소와 프로젝트 편집이 함께 사용한다.

## 남은 것·정리

- 다른 계층으로 이동하면서 순서까지 정하는 기능은 없다. 이동한 뒤 그 계층에서 다시 드래그한다.
- 경로를 키로 쓰는 데이터는 "경로가 바뀌는 모든 곳"을 찾아 함께 수정해야 한다. 이번에는 이름 바꾸기와 이동이 이미 `relocate` 하나를 거치고 있어서 한 줄 추가로 끝났다. 경로를 바꾸는 코드 경로를 함수 하나로 모아 두면 이런 변경의 범위가 줄어든다.
