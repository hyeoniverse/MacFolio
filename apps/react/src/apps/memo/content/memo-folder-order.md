폴더는 같은 층끼리 늘 가나다순이었다. '개발기'와 '회고'처럼 자주 여는 폴더를 위에 두고 싶어도 이름을 바꾸는 수밖에 없었다. iOS 메모는 폴더 화면의 편집에서 줄 오른쪽 ≡ 손잡이를 끌어 순서를 바꾼다.

![폴더 순서 바꾸기](./images/memo-folder-order.jpg '편집하면 줄마다 ≡ 손잡이. 끄는 동안 잡은 폴더가 떠오르고, 지나간 폴더는 비켜 준다')

PR([#68](https://github.com/hyeoniverse/MacFolio/pull/68))은 서버(정리 내용 검사), 화면(정렬·끌기), 시험을 함께 바꿨다. 15개 파일, 301줄 더하기, 13줄 지우기다.

## 저장: 경로 목록 하나

어떻게 저장할지 셋을 놓고 골랐다.

| 방법                                          | 좋은 점                                       | 걸리는 점                                                                               |
| --------------------------------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------- |
| 폴더마다 순번 숫자                            | 정렬이 쉽다                                   | 폴더는 글의 `category`에서 생기기도 해서 "폴더 객체"가 따로 없다. 숫자를 붙일 곳이 없다 |
| 층마다 배열 (`{ '개발기': ['MacFolio', …] }`) | 층이 분명하다                                 | 폴더 이름을 바꾸면 키와 값 둘 다 고쳐야 한다                                            |
| **전체 경로를 한 줄로**                       | 구조가 단순하고, 정렬은 "목록 안의 자리"로 끝 | 목록에 없는 폴더를 어떻게 둘지 정해야 한다                                              |

폴더 정리 내용(만든 폴더, 옮긴 글, 옮긴 폴더, 고정, 잠금)은 서버에 JSON 하나로 저장한다. 여기에 `order`를 더했다.

```ts
/** 폴더 순서: 폴더 경로를 보일 순서대로. 같은 층끼리 이 순서를 따르고, 없는 폴더는 뒤에 가나다순 */
order: string[];
```

층마다 따로 두지 않고 전체 경로를 한 줄로 늘어놓았다. 트리를 만들 때 같은 층의 폴더를 이 목록에서의 자리로 정렬하고, 목록에 없는 폴더(새로 생긴 글의 폴더 등)는 그 뒤에 가나다순으로 둔다. 그래서 순서를 한 번도 바꾸지 않았으면 예전과 똑같다.

```ts
const rank = (path: string) => {
	const index = order.indexOf(path);
	return index === -1 ? Infinity : index;
};
nodes.sort((a, b) => rank(a.path) - rank(b.path) || a.name.localeCompare(b.name));
```

둘 다 목록에 없으면 `Infinity - Infinity`가 `NaN`이 되는데, `NaN`은 거짓으로 치니 `||` 뒤의 가나다순으로 넘어간다.

순서를 바꾸면 그 층의 경로만 빼고 새 순서로 다시 붙인다. 다른 층의 순서는 건드리지 않는다.

```ts
export function reorderFolders(organization: Organization, siblings: string[]): Organization {
	return { ...organization, order: [...organization.order.filter((path) => !siblings.includes(path)), ...siblings] };
}
```

경로로 저장했으니 폴더 이름을 바꾸거나 다른 폴더 안으로 옮기면 목록의 경로도 바꿔야 한다. 이름 바꾸기와 옮기기는 이미 같은 함수(`relocate`)로 글과 하위 폴더의 경로를 바꾸고 있어서, 거기에 `order`도 한 줄 더했다. 폴더를 지우면 목록에서도 뺀다. 서버도 같은 규칙(3단, 이름 길이, 겹치지 않음)으로 `order`를 검사한다(`apps/api/src/memo/organization.ts`). 정리 내용을 처음 저장하는 사람(예전 JSON)에게는 `order`가 없으니, 없으면 빈 배열로 읽는다.

## 끌기: 잡은 폴더만 따라오게

![끄는 동안의 세 단계](./images/memo-folder-order-drag.svg '누를 때 자리를 재고, 끄는 동안은 transform만, 뗄 때 저장한다')

손잡이를 누르면 같은 층 줄들의 자리를 한 번 재 두고, 손가락이 움직이는 만큼 잡은 줄을 `translateY`로 옮긴다. 잡은 줄의 가운데가 다른 줄의 가운데를 넘으면 그 줄은 잡은 줄의 높이만큼 비켜 준다. 손을 떼면 그때의 순서를 저장하고 `transform`을 지운다. 끄는 동안에는 상태를 바꾸지 않고 스타일만 바꾸므로 다시 그리지 않는다.

- **같은 층만**: 다른 폴더 안으로 넣는 것은 '이 폴더 이동'이나 넓은 창의 끌어 놓기로 한다. 순서 바꾸기와 섞으면 손가락이 줄 경계에 있을 때 무엇을 하려는지 알 수 없다
- **하위 폴더가 펼쳐진 폴더**: 하위 폴더까지 한 덩어리(`li`)로 함께 움직인다
- **화면이 넘어가지 않게**: 손잡이에 `touch-action: none`을 주어, 끄는 동안 폴더 목록이 스크롤되지 않는다
- **키보드**: 손잡이에 초점을 두고 ↑·↓를 누르면 한 칸씩 움직인다

끌기 라이브러리(dnd-kit 등)는 쓰지 않았다. 같은 층의 세로 목록 하나만 다루면 되고, 다른 폴더 안으로 넣는 끌어 놓기는 이미 따로 있었다. 필요한 것은 포인터 이벤트 세 개와 `transform`뿐이라 직접 짰다. 이 코드는 곧이어 만든 GitHub 저장소 고르기에서도 같은 손잡이가 필요해서 `shared/ui/reorder/pointerReorder.ts`로 옮겼다. 지금은 메모 폴더, 시스템 설정의 GitHub 저장소와 프로젝트 편집이 함께 쓴다.

## 확인

- 서버 단위: `organization.test.ts`의 "폴더 순서: 없으면 빈 값, 있으면 폴더 경로 배열 (겹치거나 규칙에 어긋나면 거절)". 서버 E2E(`memo.e2e.test.ts`)의 빈 정리 내용 시험에도 `order`를 더했다.
- 화면 단위: `organize.test.ts`의 "폴더 순서: 같은 층만 새 순서로 바꾸고, 이름을 바꾸거나 옮기거나 지우면 순서도 따라간다", `posts.test.ts`의 "같은 층은 정한 순서를 따르고, 순서에 없는 폴더는 뒤에 가나다순".
- 화면 E2E: `e2e/mobile.spec.ts`의 "폴더 편집의 ≡ 손잡이로 같은 층 폴더 순서를 바꾸고, 정리 내용에 저장한다". 휴대폰 화면에서 손잡이를 끌고, 가짜 서버가 받은 `order`를 본다.

## 남은 것·배운 것

- 다른 층으로 옮기며 순서까지 정하는 것은 안 된다. 옮긴 뒤 그 층에서 다시 끈다.
- 경로를 열쇠로 쓰는 데이터는 "경로가 바뀌는 모든 곳"을 찾아 함께 고쳐야 한다. 이번에는 이름 바꾸기와 옮기기가 이미 `relocate` 하나를 지나고 있어서 한 줄이면 됐다. 경로를 바꾸는 길을 한 함수로 모아 두는 것이 이런 때 값을 한다.
