### R2 버킷 설정과 로컬 확인

파일 업로드를 확인하려면 R2 버킷이 필요해서 Cloudflare에서 직접 설정했다. 설정 중 발생한 문제와 원인은 다음과 같다.

| 증상                                               | 원인                                                | 조치                         |
| -------------------------------------------------- | --------------------------------------------------- | ---------------------------- |
| `macfolio-files` 이름을 사용할 수 없음             | 이미 생성해 둔 버킷                                 | 기존 버킷 사용               |
| 문서의 `CLOUDFLARE_API_TOKEN` 화면을 찾을 수 없음  | R2 접근 키는 별도 화면에서 발급                     | R2 API 토큰 화면에서 키 발급 |
| 로컬 E2E 두 개가 `Executable doesn't exist`로 실패 | Playwright를 업데이트한 뒤 브라우저를 설치하지 않음 | `npx playwright install`     |
| 업로드 후 미리보기가 "열 수 없습니다" 표시         | 목록 API·파일 경로 중 어디서 실패하는지 확인 필요   | 아래 `curl`로 단계별 확인    |

E2E는 가짜 API로 실행되므로, 실제 드래그 앤 드롭 업로드를 확인하려면 로컬 API에 R2 설정값을 넣고 실행해야 했다. 업로드 후 미리보기가 실패해서 요청 경로를 단계별로 확인했다.

```bash
curl -v http://localhost:4000/documents        # 목록에 key가 있는지 (200, JSON)
curl -sI "http://localhost:5173/files/<key>"   # 사이트가 해당 파일을 제공하는지
```

처음 `curl -s`는 아무것도 출력하지 않았지만, `-v`로 확인하니 목록은 200으로 정상 응답했다. 버킷 설정은 [Cloudflare R2 문서](https://developers.cloudflare.com/r2/buckets/)와 [R2 CORS 문서](https://developers.cloudflare.com/r2/buckets/cors/), 로컬 브라우저 설치는 [Playwright 설치 문서](https://playwright.dev/docs/browsers)를 따랐다.

### Finder를 실제 파일 시스템처럼 ([#263](https://github.com/hyeoniverse/MacFolio/pull/263))

5시부터 9시까지 Finder가 실제 파일 시스템처럼 동작하도록 구현했다([Finder 폴더를 진짜 데스크탑처럼](/memo/finder-filesystem)).

- **폴더 구조를 서버에 저장:** 관리자가 폴더를 만들고, 이름을 변경하고, 파일과 폴더를 드래그로 이동한다. 구조는 `/finder/layout` API에 저장해 방문자도 같은 구조를 본다. 블로그 폴더는 메모 앱의 분류와 연결되어, Finder에서 글을 이동하면 메모 앱에서도 이동된다
- **어디에 놓아도 업로드:** 컴퓨터의 파일을 폴더, 바탕화면, 파일 아이콘 위 어디에 놓아도 업로드된다. 허용 형식에 문서·영상·ZIP을 추가했다. 방문자가 놓은 파일은 서버에 업로드하지 않고 그 방문자의 화면에만 표시한다. 방문자가 놓은 PDF를 pdf.js가 읽을 수 있도록 CSP의 `connect-src`에 `blob:`을 추가했다
- **휴지통:** 휴지통으로 이동한 파일은 복원하거나 영구 삭제한다. 바탕화면 파일은 Dock의 휴지통으로 드래그해도 삭제된다

로컬과 운영 서버에서 직접 확인하며 발견한 문제는 다음과 같다.

| 증상                                                                                    | 원인·조치                                                                          |
| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| 바탕화면에 파일을 놓아도 업로드되지 않음                                                | 관리자로 로그인하지 않은 상태였음                                                  |
| `chill.gif` 업로드가 "PDF, PNG, JPG, WebP 파일만…"으로 거부됨                           | 허용 형식이 적었음. 형식을 추가한 뒤에도 같은 문구가 표시되어 재확인               |
| 새 형식을 허용하는 마이그레이션이 `No such file or directory`로 실패                    | 서버의 `~/deploy`, 로컬의 다른 폴더에서 실행함. 저장소 루트에서 실행해야 하는 명령 |
| 휴지통 확인 창이 Safari 창보다 아래에 표시됨                                            | 확인 창의 z-index 수정                                                             |
| 휴지통으로 이동한 파일이 휴지통에 표시되지 않음                                         | 휴지통 목록 수정                                                                   |
| 바탕화면에 올린 파일이 `portfolio/` 아래 키로 저장되어 "파일을 둘 폴더가 없습니다" 표시 | 바탕화면용 저장 경로 수정                                                          |

같은 시간대에 HYEONIVERSE 구조도의 아이콘이 사각형으로 깨진 문제도 수정했다. Font Awesome을 7로 업데이트했는데, SVG 텍스트로 렌더링하는 아이콘의 CSS에 6 버전의 글꼴 이름이 남아 있었다([#262](https://github.com/hyeoniverse/MacFolio/pull/262), [구조도 아이콘이 깨진 까닭](/memo/font-awesome-7-icons)).

### 41분 만에 바꾼 발표 자료 저장 방식

4시 22분, 프로젝트 발표 자료(PPT)를 사이트에 올리는 방법을 검토했다. 4시 45분에 미리보기 앱에 보기 › 슬라이드쇼(⇧⌘F)를 추가하고, 프로젝트 정보에 `slides` 필드를 두어 발표 자료 PDF를 선택하게 했다. 프로젝트 페이지에는 발표 자료 보기 버튼이 표시된다.

그런데 결과 화면을 보니, 필드로 파일을 선택하는 것보다 실제 OS처럼 프로젝트마다 폴더가 있는 방식이 더 자연스러웠다. 그 사이 프로젝트마다 Finder 폴더를 만드는 작업([#261](https://github.com/hyeoniverse/MacFolio/pull/261))도 진행 중이었다. 41분 뒤인 5시 26분에 `slides` 필드와 시스템 설정의 선택 칸을 삭제했다.

| 방식                     | 발표 자료를 정하는 곳         | 결과 |
| ------------------------ | ----------------------------- | ---- |
| `slides` 필드 (4시 45분) | 시스템 설정에서 PDF 선택      | 삭제 |
| 프로젝트 폴더 (5시 26분) | 프로젝트 폴더의 이름순 첫 PDF | 채택 |

같은 정보를 두 곳에 기록하지 않도록 한 결정이다([미리보기 슬라이드쇼와 프로젝트 발표 자료](/memo/project-slides), [#258](https://github.com/hyeoniverse/MacFolio/pull/258)).

## 동영상 배경화면과 QuickTime

7시 55분에 MP4와 GIF 애니메이션을 배경화면으로 사용할 수 있게 했다([#264](https://github.com/hyeoniverse/MacFolio/pull/264)). 동영상은 음소거 상태로 반복 재생하고, 동작 줄이기 설정이 켜져 있거나 탭이 백그라운드로 전환되면 정지한다([움직이는 배경화면](/memo/video-wallpaper)).

MP4를 업로드해 보니 미리보기도 재생도 되지 않았다. Finder에서는 회색 문서 아이콘으로 표시됐고, 열면 내려받기만 실행됐다. 8시 55분에 QuickTime Player 앱을 추가했다. `/files` 경로가 HTTP Range 요청에 응답하도록 해서, 긴 영상도 전체를 내려받지 않고 원하는 위치부터 재생한다.

![QuickTime의 열기 창](./images/day-1019-quicktime.jpg 'QuickTime을 파일 없이 실행하면 미리보기와 같은 열기 창이 표시된다. 사이드바는 Finder와 같은 트리')

### 배포 후 발견한 R2 키 오류 ([#268](https://github.com/hyeoniverse/MacFolio/pull/268))

배포 후 운영 사이트에서 업로드를 직접 시도하며 원인을 단계별로 좁혔다.

| 단계 | 확인한 것                         | 결과                                                             |
| ---- | --------------------------------- | ---------------------------------------------------------------- |
| 1    | 업로드 시도                       | "서버에 파일 저장소(R2)가 설정되지 않았습니다"                   |
| 2    | 서버에 R2 설정값 입력 후 재시도   | "저장소에 연결하지 못했습니다. 버킷의 CORS 설정을 확인해 주세요" |
| 3    | CORS 사전 요청(OPTIONS) 직접 전송 | `204`와 `Access-Control-Allow-Origin` 정상 응답                  |
| 4    | 서버 시각 확인                    | 정상 (서명 만료 문제 아님)                                       |
| 5    | 서명한 PUT 요청 직접 전송         | `SignatureDoesNotMatch`                                          |

오류 문구는 CORS를 가리켰지만, 실제 원인은 서버에 입력한 R2 키 값이었다. 이 과정에서 발견한 문제도 함께 수정했다([배경화면이 새로고침하면 사라지던 문제](/memo/finder-wallpaper-persist)).

- Finder의 '데스크탑 사진 설정'으로 선택한 배경화면이 새로고침하면 기본값으로 돌아감
- MP4를 배경화면으로 설정할 수 없음
- 관리자 휴지통에 서버 파일이 표시되지 않음
- QuickTime도 미리보기와 같은 열기 창으로 파일을 선택하도록 변경

### 검색 로봇용 본문 ([#269](https://github.com/hyeoniverse/MacFolio/pull/269))

이 사이트는 화면 전체를 JavaScript로 렌더링한다(CSR). 그래서 검색 로봇이 받는 HTML은 어느 주소든 제목이 같고 본문이 비어 있다. 블로그 글과 프로젝트가 검색 결과에 노출되지 않고, 링크를 공유해도 미리보기 카드가 표시되지 않았다.

| 항목             | 변경 전            | 변경 후                               |
| ---------------- | ------------------ | ------------------------------------- |
| `<title>`, 설명  | 모든 주소에서 동일 | 주소마다 다름                         |
| og 태그, JSON-LD | 없음               | 주소마다 삽입                         |
| 본문             | 비어 있음          | 화면에는 보이지 않는 로봇용 본문 삽입 |
| `sitemap.xml`    | 고정 목록          | 빌드 시 생성한 글 목록 + API 글       |

## 돌아보며

[10월 16일](/memo/day-1016)의 PR 다섯 개는 서로 겹치는 파일이 없어 어떤 순서로 머지해도 됐다. 이날은 반대였다. 미리보기, 바탕화면, 프로젝트 폴더, 파일 시스템이 모두 Finder의 같은 트리를 변경했고, 그래서 PR이 서로를 기다렸다. 오전 11시까지의 커밋 69개 중 10개가 다른 브랜치나 main을 병합하는 커밋이었다.

발표 자료 필드를 41분 만에 삭제한 것도 같은 이유다. 기능을 병렬로 개발하다 보니 한쪽에서 만든 필드가 다른 쪽에서 만든 폴더와 역할이 겹쳤다. 겹치는 작업을 한 브랜치에서 순서대로 진행했다면 병합 커밋도, 삭제한 필드도 없었을 것이다. 병렬로 진행할 작업은 서로 겹치지 않는 것으로 한정해야 한다.

R2 업로드 오류에서는 오류 문구가 실제 원인과 달랐다. 문구는 CORS를 가리켰지만 원인은 서명 키였다. 요청을 단계별로 직접 보내 확인하는 방법이 문구를 믿고 설정을 바꾸는 것보다 빨랐다.
