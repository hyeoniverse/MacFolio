### R2와 로컬 확인

이 작업에는 R2 버킷이 필요해서 Cloudflare에서 직접 설정했다. `macfolio-files` 이름을 못 쓴다고 해서 보니 이미 만들어 둔 버킷이었고, 문서에 나온 `CLOUDFLARE_API_TOKEN`은 화면에서 찾을 수 없어 R2 API 토큰 화면에서 따로 키를 만들었다. 로컬에서는 E2E 두 개가 `Executable doesn't exist`로 실패했는데, Playwright를 올린 뒤 브라우저를 받지 않아서였다(`npx playwright install`). E2E는 가짜 API로 도니, 내가 직접 끌어다 놓아 올리는 것을 보려면 로컬 API에 R2 값을 넣고 띄워야 했다. 올린 뒤 미리보기가 "열 수 없습니다"를 띄워서 `curl`로 하나씩 짚었다.

```bash
curl -v http://localhost:4000/documents        # 목록에 key가 있는지 (200, JSON)
curl -sI "http://localhost:5173/files/<key>"   # 사이트가 그 파일을 내주는지
```

처음 `curl -s`는 아무것도 찍지 않았지만 `-v`로 보니 목록은 200으로 제대로 나왔다. 버킷 설정은 [Cloudflare R2 문서](https://developers.cloudflare.com/r2/buckets/)와 [R2 CORS 문서](https://developers.cloudflare.com/r2/buckets/cors/), 로컬 브라우저 설치는 [Playwright 설치 문서](https://playwright.dev/docs/browsers)를 따랐다.

#255는 5시 14분에 머지되었다. 올린 지 11시간 만이고, 더한 줄이 4,897줄이다. 그 사이에 음악 앱 버그 셋을 고친 [#257](https://github.com/hyeoniverse/MacFolio/pull/257)이 2시 15분에 먼저 들어갔다([음악 앱 버그 세 가지](/memo/music-player-fixes)).

## 41분 만에 바꾼 발표 자료 자리

4시 22분에 프로젝트 발표 자료(PPT)도 올리고 싶어서 어떤 형태가 좋을지 따져 봤다. 4시 45분에 미리보기에 보기 › 슬라이드쇼(⇧⌘F)를 더하고, 프로젝트 정보에 `slides` 칸을 두어 발표 자료 PDF를 고르게 했다. 프로젝트 페이지에는 발표 자료 보기 버튼이 생긴다.

그런데 화면을 보니 칸으로 고르는 것보다 진짜 OS처럼 프로젝트마다 폴더가 있는 게 맞았다. 41분 뒤인 5시 26분에 `slides` 칸과 시스템 설정의 고르기 칸을 지웠다. 그 사이에 프로젝트마다 Finder 폴더를 만들었기 때문이다([#261](https://github.com/hyeoniverse/MacFolio/pull/261)). 이제 프로젝트 폴더에 PDF를 넣으면 이름순 첫 PDF가 발표 자료가 된다. 같은 사실을 두 곳에 적지 않게 했다([미리보기 슬라이드쇼와 프로젝트 발표 자료](/memo/project-slides), [#258](https://github.com/hyeoniverse/MacFolio/pull/258)).

## Finder를 파일 시스템으로

5시부터 9시까지는 Finder가 진짜 파일 시스템처럼 움직이게 했다.

- **폴더 구조를 서버에** ([#263](https://github.com/hyeoniverse/MacFolio/pull/263)): 관리자가 새 폴더를 만들고, 이름을 바꾸고, 파일과 폴더를 끌어 옮긴다. 구조는 `/finder/layout` API에 저장해 방문자도 같은 구조를 본다. 블로그 폴더는 메모 앱의 정리 내용을 바꾸므로, Finder에서 글을 옮기면 메모에서도 옮겨진다([Finder 폴더를 진짜 데스크탑처럼](/memo/finder-filesystem)).
- **어디에 놓아도 올리기**: 컴퓨터의 파일을 만든 폴더, 바탕화면, 파일 아이콘 위 어디에 놓아도 올라간다. 문서·영상·ZIP 같은 종류를 늘렸고, 방문자가 놓은 파일은 서버에 올리지 않고 그 사람 화면에만 둔다. 방문자가 놓은 PDF를 pdf.js가 읽도록 CSP의 `connect-src`에 `blob:`을 더했다.
- **로컬과 서버에서 직접 해 본 것**: 처음엔 바탕화면에 끌어 놓아도 안 올라갔는데 로그인을 안 해서였다. 로그인하자 `chill.gif`가 "PDF, PNG, JPG, WebP 파일만 올릴 수 있습니다"로 막혀 종류를 늘렸고, 늘린 뒤에도 같은 문구가 떠서 다시 확인했다. 새 종류를 받는 마이그레이션은 서버의 `~/deploy`나 내 Mac의 엉뚱한 폴더에서 치다 `No such file or directory`가 났다. 저장소 루트에서 쳐야 하는 명령이다.
- **휴지통**: 이미지를 휴지통으로 옮기려 하자 확인창이 Safari 같은 창보다 아래에 깔렸고, 옮겨도 휴지통에 보이지 않았고, 바탕화면에 올린 파일이 `portfolio/` 아래 키로 저장되어 "파일을 둘 폴더가 없습니다"가 떴다. 끌어 놓을 때 아이템의 z-index도 어긋났다. 이것들을 고친 결과가 아래다. 휴지통으로 옮긴 파일은 휴지통에서 되돌려 놓거나 영구 삭제한다. 바탕화면 파일은 Dock의 휴지통으로 끌어다 놓아도 된다.

그 사이에 HYEONIVERSE 구조도의 아이콘이 네모로 깨진 것도 고쳤다. Font Awesome을 7로 올렸는데 SVG 글자로 그리는 아이콘의 CSS에는 6의 글꼴 이름이 남아 있었다([#262](https://github.com/hyeoniverse/MacFolio/pull/262), [구조도 아이콘이 깨진 까닭](/memo/font-awesome-7-icons)).

## 움직이는 배경화면과 QuickTime

7시 55분에 MP4와 움직이는 GIF를 배경화면으로 쓰게 했다([#264](https://github.com/hyeoniverse/MacFolio/pull/264)). 동영상은 소리 없이 반복하고, 움직임 줄이기를 켜거나 탭이 가려지면 멈춘다([움직이는 배경화면](/memo/video-wallpaper)).

mp4를 올려 보니 미리보기도 재생도 안 됐다. Finder에서 회색 종이 아이콘이었고, 열면 내려받기만 했다. 8시 55분에 QuickTime Player 앱을 더했다. `/files`가 Range 요청에 응답하게 해서 긴 영상도 처음부터 다 받지 않고 원하는 곳부터 재생한다.

10시 40분에는 Finder의 '데스크탑 사진 설정'으로 고른 배경화면이 새로고침하면 기본값으로 돌아가던 버그를 고쳤고, QuickTime도 미리보기와 같은 열기 창으로 파일을 고르게 했다. 고친 계기는 배포 뒤 직접 해 본 것이다. 처음엔 업로드가 "서버에 파일 저장소(R2)가 설정되지 않았습니다"로, 값을 넣은 뒤에는 "저장소에 연결하지 못했습니다. 버킷의 CORS 설정을 확인해 주세요"로 막혔다. 서버에서 확인해 보니 CORS 사전 요청은 `204`와 `Access-Control-Allow-Origin`이 제대로 돌아왔고, 시계도 맞았다. 서명한 PUT을 직접 보내 보자 `SignatureDoesNotMatch`가 나서, 문제가 CORS가 아니라 서버에 넣은 R2 키 값이라는 것이 드러났다. 그 김에 mp4를 바탕화면으로 설정할 수 없는 것, 설정해도 새로고침하면 돌아가는 것, 관리자 휴지통의 서버 파일이 비어 있는 것을 찾아 함께 고쳤다([#268](https://github.com/hyeoniverse/MacFolio/pull/268), [배경화면이 새로고침하면 사라지던 문제](/memo/finder-wallpaper-persist)).

![QuickTime의 열기 창](./images/day-1019-quicktime.jpg 'QuickTime을 파일 없이 열면 미리보기와 같은 열기 창이 뜬다. 사이드바는 Finder와 같은 트리')

## CI: 15분에서 5분으로

시작은 9시 39분, #263을 머지했는데 한참 지나도 배포가 안 된 것이었다. 원래 몇 분 걸리는지 따져 보니 E2E가 너무 오래 걸렸다.

PR을 머지하고 사이트에 반영되기까지 15분쯤 걸렸고, 그중 8~9분이 화면 E2E였다. 이틀 전 세 칸으로 나눈 E2E를 여섯 칸으로 늘리고, PR에서 이미 통과한 것과 트리가 같은 main 커밋은 E2E를 다시 돌리지 않고 바로 배포하게 했다([#266](https://github.com/hyeoniverse/MacFolio/pull/266), [머지하고 배포까지 15분에서 5분으로](/memo/faster-e2e-ci)). 같은 시각에 Dependabot의 패키지 24개 묶음 업데이트([#265](https://github.com/hyeoniverse/MacFolio/pull/265))도 머지했다.

## 검색 로봇이 읽을 수 있게

이 사이트는 화면 전체를 자바스크립트로 그린다. 그래서 검색 로봇이 받는 HTML은 어느 주소든 제목이 같고 본문이 비어 있다. 블로그 글과 프로젝트가 검색에 걸리지 않고, 링크를 공유해도 미리보기가 뜨지 않는다.

[#269](https://github.com/hyeoniverse/MacFolio/pull/269)에서는 Worker가 주소마다 제목·설명·og 태그·JSON-LD와, 화면에는 보이지 않는 로봇용 본문을 넣는다. 앱이 뜨면 React가 그 자리를 덮는다. 빌드할 때 글 목록을 JSON으로 만들고, 관리자가 API로 쓴 글은 Worker가 1분 동안 기억해 두고 합친다. `sitemap.xml`도 그 목록으로 만든다. 11시 19분에 머지했다.

숫자는 오전 11시의 마지막 main 커밋(#268 머지)에서 `test(`·`it(` 호출을 센 값이다.

## 오후: 글 다시 쓰기, 회고 13편

11시 35분부터 오후 1시 반까지는 블로그를 손봤다([#270](https://github.com/hyeoniverse/MacFolio/pull/270), 더한 줄 21,289줄).

- **빠진 회고 13편**: 하루 회고가 9월 28일 ~ 10월 16일에만 있었다. 10월 17 ~ 19일 세 편과, 2024년 8월 ~ 2025년 3월의 초기 기록 열 편을 썼다. 커밋이 적은 날은 묶었고, 초기 기록은 `git show`로 그때 코드를 보고 썼다
- **글 본문 보강**: 회고를 뺀 168편을 대부분 1.5 ~ 3배로 늘렸다. 배경과 원인, 고른 방법과 버린 방법의 비교 표, 고치기 전후 코드, 확인한 방법과 직접 잰 수치를 넣고, 그림을 글마다 2 ~ 5개 넣었다
- **실제 개발 과정**: 작업하며 직접 찍은 화면을 관련 글에 넣었다. 되돌리기 훈련은 훈련 전 상태부터 41초 만에 되돌린 로그까지 다섯 장이다. 공인 IP·사용자명·키 경로·이메일은 가리거나 잘라 냈다
- **따라 하기**: 운영·배포·설정·백엔드 글 77편에 준비물·명령·기대 출력·되돌리는 법을 담은 절을 넣었다. 저장소 문서 링크 약 130개, 공식 문서 링크 약 140개
- **표현**: "~다는 말을 듣고"처럼 내 판단을 남에게 들은 것처럼 쓴 표현을 1인칭 관찰로 고쳤다

글이 늘자 실제 글 내용에 기대던 메모 E2E가 깨졌다. 표와 캡션이 여러 개가 되고, 검색어가 다른 글에도 걸렸기 때문이다. 찾는 글과 요소를 더 정확히 가리키게 고쳤다.

## 오후: 메모 읽기 다듬기

글이 길어지니 읽는 화면이 눈에 걸렸다.

- **저장소 문서 링크는 Finder에서**([#272](https://github.com/hyeoniverse/MacFolio/pull/272)): 글 속 `docs/rollback-drill.md` 같은 링크를 누르면 GitHub 새 탭이 열렸다. 그 문서들은 이미 Finder의 문서 폴더에 묶여 있어서, 사이트 안에서 바로 열게 했다. ⌘·Ctrl·Shift를 누르면 지금처럼 새 탭에 연다
- **글자 크기 조절**([#273](https://github.com/hyeoniverse/MacFolio/pull/273)): 본문이 14px로 고정이라 브라우저를 통째로 확대해야 했다. 본문만 0.85 ~ 1.5배 다섯 단계로 바꾸고, 고른 크기는 그 브라우저에만 남는다. 처음에는 도구 막대에 버튼을 두었다가, 14시 14분에 본문 오른쪽 아래에 떠 있는 알약으로 옮겼다
- **관리자 화면의 공유 버튼**([#271](https://github.com/hyeoniverse/MacFolio/pull/271)): 관리자로 로그인하면 편집 화면이라 공유 버튼을 빼 두었는데, 대신 쓸 ••• 메뉴는 검색할 때만 보여서 글 주소를 복사할 곳이 없었다. 버튼을 되살리고, 좁은 본문 칸(480px 이하)에서만 도구 사이 간격을 줄여 다 들어오게 했다

## 오후: 최대화한 창의 크기 조절

창을 최대화하면 가장자리에 크기 조절 커서는 뜨는데 끌어도 움직이지 않았다([#274](https://github.com/hyeoniverse/MacFolio/pull/274)). 최대화 중에는 옮기기를 막는 조건이 같은 함수를 쓰는 크기 조절까지 막고 있었다. macOS처럼 가장자리를 끌면 최대화가 풀리고 꽉 찬 크기에서부터 조절되게 했다.

마지막 커밋(14시 36분)은 라이트·다크 짝이 거의 맞던 메일·메시지·터미널·설정의 색 일곱 개를 기존 색 이름으로 옮긴 것이다. 이 작업이 다음 날 디자인 토큰을 세 층으로 다시 세우는 일의 시작이 되었다([10월 20일](/memo/day-1020)).

## 돌아보며

[10월 16일](/memo/day-1016)의 PR 다섯 개는 서로 겹치는 파일이 없어 어떤 순서로 머지해도 됐다. 이날은 반대였다. 미리보기, 바탕화면, 프로젝트 폴더, 파일 시스템이 모두 Finder의 같은 트리를 만졌고, 그래서 PR이 서로를 기다렸다. 이날 커밋 69개 중 열 개가 다른 브랜치나 main을 합치는 커밋이다.

발표 자료 칸을 41분 만에 지운 것도 같은 이유다. 기능을 나란히 만들다 보니 한쪽에서 만든 칸이 다른 쪽에서 만든 폴더와 겹쳤다. 겹치는 일을 한 브랜치에서 차례로 했다면 합치는 커밋도, 지운 칸도 없었을 것이다. 서로 겹치지 않는 일만 나란히 하는 것이 맞다.
