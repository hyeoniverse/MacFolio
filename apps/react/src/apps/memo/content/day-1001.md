## 새벽: 문서와 규칙

| 한 일                                    | 글                                            |
| ---------------------------------------- | --------------------------------------------- |
| 커밋 규칙과 규칙 검사 CI, main 필수 검사 | 커밋 규칙을 문서 대신 CI로 지키기             |
| 레이아웃에 따라 실패하던 이미지 끌기 E2E | 글 한 편 추가했더니 E2E가 깨졌다              |

## 낮: 따로 놀던 것을 하나로

오전에는 편집기의 작은 것들을 고쳤다. 게시 단추 글자가 흐리던 것, 코드 복사와 이미지 내려받기 단추가 서로 다르던 것, 캡션 칸, 표 칸 끌어 고르기와 표 양옆 커서. 메모 글과 Safari 프로젝트에는 주소를 붙이고 공유 단추를 달았다.

정오부터는 공통 컴포넌트 작업이었다. 고치다 보니 같은 일을 하는 코드가 앱마다 따로 있었다.

| 순서 | 한 일                                                | 글                                                   |
| ---- | ---------------------------------------------------- | ---------------------------------------------------- |
| 1    | 앱 루트의 단추·링크 기본값을 `@layer reset`으로      | !important 72개의 뿌리                               |
| 2    | 메뉴 다섯 벌을 `Menu`, `useDismiss`, `placement`로   | 메뉴 다섯 벌을 하나로                                |
| 3    | `!important`를 지우고 아이콘 단추를 `IconButton`으로 | !important 66개 지우기와 공통 아이콘 단추            |
| 4    | 글자 단추를 `Button`으로 (만들지 않은 후보도 적음)   | 글자 단추 하나로 합치기, 그리고 만들지 않은 컴포넌트 |

순서가 중요했다. `!important`가 72개나 있었던 건 앱 루트의 기본값(`.memo button { color: inherit }` 등)이 단추마다 적은 클래스보다 점수가 높아서, 단추마다 `!important`로 덮어 왔기 때문이다. 기본값을 CSS 층으로 먼저 내리자 남은 66개를 모두 지울 수 있었다(움직임 줄이기 설정의 2개만 남김). 지우며 생긴 차이는 화면을 전후로 찍어 비교해서 찾았다.

## 돌아보며

- **잘한 것: 공통 컴포넌트를 바닥부터 합쳤다.** 기본값(층) → 메뉴 → 아이콘 단추 → 글자 단추 순서로 했다. 뿌리를 먼저 뽑으니 `!important`를 0개로 만들 수 있었다.
- **잘한 것: 고친 것마다 글을 남겼다.** 19편이다. 무엇을 왜 그렇게 했는지 그날 적어 두었다.
- **아쉬운 것: 최근 삭제된 항목을 화면 보며 정했다.** 안내 상자를 뺐다가 50분 만에 문구를 되살리고, 다시 1시간 뒤에 상자째 되살렸다. macOS 메모의 실제 화면을 처음부터 옆에 두고 맞췄으면 되돌리는 커밋은 없었을 것이다.
- **아쉬운 것: 자정을 넘겼다.** 되돌림이 많았던 시간이 밤 11시부터 새벽 1시였다. 지친 시간에 하는 화면 결정은 다음 날 다시 보게 된다.
