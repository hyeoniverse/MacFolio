## 공통 컴포넌트: !important 72개를 0개로

### 문제

코드에 `!important`가 72개 있었다. 버튼 색이나 아이콘 크기가 적용되지 않을 때마다 하나씩 추가한 것이었다. 계기는 메모 앱의 작은 불일치였다. 코드 블록의 복사 버튼과 이미지의 다운로드 버튼이 같은 역할인데 모양과 스타일이 서로 달랐고, 공유 아이콘도 macOS의 "상자에서 화살표가 나오는" 모양이 아니었다. 이를 수정하려고 클래스와 스타일 구조를 도식으로 정리해 보니, 공통 버튼 컴포넌트가 없고 앱마다 같은 버튼을 따로 구현하고 있었다.

### 원인

72개의 원인은 하나였다. 앱 루트에 지정한 기본값이 버튼마다 지정한 클래스보다 명시도(specificity)가 높았다.

```css
/* 앱 루트의 기본값: 명시도 (0,1,1) */
.memo button {
	color: inherit;
}

/* 버튼 클래스: 명시도 (0,1,0) → 위 규칙에 밀려 적용되지 않는다 */
.memo-copy-button {
	color: var(--ui-accent);
}
```

그래서 버튼마다 `!important`로 기본값을 덮어쓰고 있었다.

### 조치

순서를 정해 네 개의 PR로 나눴다. 기본값을 먼저 CSS 캐스케이드 레이어(`@layer reset`)로 옮기면, 레이어 안의 규칙은 레이어 밖의 규칙보다 우선순위가 낮아져 명시도와 상관없이 버튼 클래스가 적용된다. 그 뒤로는 필요 없어진 `!important`를 삭제하기만 하면 된다. 삭제하면서 생긴 화면 차이는 변경 전후 스크린샷을 비교해 찾았다.

### 결과

남은 `!important`는 동작 줄이기(`prefers-reduced-motion`) 설정의 2개뿐이다. 이 2개는 사용자의 접근성 설정이 모든 애니메이션 규칙보다 우선해야 하는 경우다. 이 작업은 이슈 [#15](https://github.com/hyeoniverse/MacFolio/issues/15)(기능·UI 개선과 리팩터링)의 한 갈래이고, 같은 날 연 [#58](https://github.com/hyeoniverse/MacFolio/pull/58)은 범위를 다시 나눠 [#59](https://github.com/hyeoniverse/MacFolio/pull/59)로 제출했다.

### 표 다듬기

표를 사용하다가 macOS 메모와의 차이 네 가지를 발견했다.

| 증상                                                              | macOS 메모                              |
| ----------------------------------------------------------------- | --------------------------------------- |
| 셀을 선택해도 선택 표시가 없다                                    | 노란 테두리와 크기 조절 핸들이 표시된다 |
| 표 양옆의 여백을 클릭해 커서를 놓을 수 없고, 커서가 보이지 않는다 | 표 앞뒤에 커서를 놓을 수 있다           |
| 표를 삭제하려면 삭제 키를 두 번 눌러야 한다                       | 한 번에 삭제된다                        |
| 게시 버튼의 위쪽이 일부 잘린다                                    | -                                       |

![macOS 메모에서 셀을 선택한 화면](./images/table-polish-macos-selection.jpg '참고한 macOS 화면. 셀을 선택하면 노란 테두리와 핸들이 표시된다. MacFolio 메모에는 이 표시가 없었다')

네 가지를 [표 다듬기](/memo/table-polish)에서 함께 수정하고, 수정 후 실제로 셀을 선택해 테두리가 표시되는지, 삭제 키 한 번으로 표가 삭제되는지 확인했다.

### 최근 삭제된 항목: 되돌린 결정 세 번

최근 삭제된 항목은 22시 39분부터 다음 날 1시 8분까지 커밋 8개로 완성했고, 그중 일부는 앞의 결정을 되돌린 커밋이다.

| 시각        | 최근 삭제된 메모 화면의 변경                             |
| ----------- | -------------------------------------------------------- |
| 22:39       | 화면 정리, 끌어 놓기로 삭제·복구                         |
| 23:18       | 날짜는 항상 맨 위, **안내 상자를 빼고** 도구 막대로 대체 |
| 23:47       | 게시 줄을 **다시** 날짜 위로, 복구는 아이콘 버튼으로     |
| 23:58       | 목록 위 안내 문구 **복원**                               |
| 00:33 (2일) | **안내 상자 복원**, 되돌려 놓기·즉시 삭제, 휴지통 비우기 |
| 01:08 (2일) | 즉시 삭제는 창 안의 경고 대화상자로 확인                 |

되돌린 이유는 매번 화면을 열어 확인하면서 발견했다.

- **23:18 버전:** "게시하지 않은 변경 사항", "변경 사항 버리기" 표시를 찾을 수 없었다. 게시 줄을 이전 위치로 되돌렸다
- **23:47 버전:** "삭제한 메모는 30일 동안 여기에 보관된 후 영구 삭제됩니다. 폴더로 끌어 놓으면 복구됩니다." 안내 문구까지 사라졌다. 문구를 복원했고, 이어서 안내 상자도 복원했다

## 돌아보며

**원인부터 순서대로 진행한 작업은 되돌린 커밋이 없었다.** 공통 컴포넌트 작업은 원인(명시도)을 먼저 확인하고, 레이어 이동 → 메뉴 → 아이콘 버튼 → 글자 버튼 순서로 진행해 되돌린 커밋이 0개였다.

**화면을 보면서 결정한 작업은 같은 결정을 여러 번 되돌렸다.** 최근 삭제된 항목은 안내 상자를 뺐다가 40분 뒤 문구를 복원하고, 다시 35분 뒤 상자째 복원했다. macOS 메모의 실제 화면을 처음부터 옆에 두고 비교했다면 되돌리는 커밋은 필요 없었다. 되돌린 커밋이 23시부터 1시 사이에 몰린 것도, 집중력이 떨어진 시간대에 화면 구성을 결정했기 때문이라고 판단한다. UI를 바꿀 때는 참고할 실제 화면을 먼저 확보한 뒤 시작해야 한다.
