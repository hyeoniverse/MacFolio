코드에 `!important`가 72개 있었다. 각각은 단추 색이나 아이콘 크기가 적용되지 않아서 붙인 것이었는데, 원인은 모두 같았다. 앱 루트에 적은 기본값(`.memo button { color: inherit }` 같은 것)이 단추마다 적은 클래스보다 우선순위가 높아서, 단추마다 `!important`로 덮어쓰고 있었다.

이날의 주된 작업은 이 원인을 없애는 것이었다. 하루 커밋 51개 중 22개는 글이었고, 새 글이 19편으로 열흘 중 가장 많았다.

![10월 1일 작업 흐름](./images/day-1001-timeline.svg '새벽에는 문서와 규칙, 낮에는 공통 컴포넌트, 밤에는 메모 기능')

## !important 72개를 0개로

순서가 중요했다. 기본값을 먼저 CSS 층(`@layer reset`)으로 옮기자 단추마다 적은 클래스가 우선 적용되었고, 그 뒤로는 필요 없어진 `!important`를 지우기만 하면 됐다. 지우며 생긴 차이는 화면을 전후로 찍어 비교해서 찾았다.

1. 앱 루트의 단추·링크 기본값을 `@layer reset`으로 ([!important 72개의 뿌리](/memo/css-layer-reset), [#57](https://github.com/hyeoniverse/MacFolio/pull/57))
2. 앱마다 따로 있던 메뉴 다섯 벌을 `Menu`, `useDismiss`, `placement`로 ([메뉴 다섯 벌을 하나로](/memo/shared-menu), [#59](https://github.com/hyeoniverse/MacFolio/pull/59))
3. `!important`를 지우고 아이콘 단추를 `IconButton`으로 ([!important 66개 지우기와 공통 아이콘 단추](/memo/shared-button), [#60](https://github.com/hyeoniverse/MacFolio/pull/60))
4. 글자 단추를 `Button`으로, 만들지 않은 후보도 적어 두기 ([글자 단추 하나로 합치기](/memo/shared-text-button), [#61](https://github.com/hyeoniverse/MacFolio/pull/61))

남은 `!important`는 움직임 줄이기 설정의 2개뿐이다.

## 돌아보며

낮과 밤의 작업 결과가 달랐다. 낮의 공통 컴포넌트 작업은 원인부터 순서대로 했고, 되돌린 커밋이 없다. 밤의 최근 삭제된 항목은 화면을 보며 정했고, 안내 상자를 뺐다가 50분 만에 문구를 되살리고 다시 한 시간 뒤에 상자째 되살렸다. macOS 메모의 실제 화면을 처음부터 옆에 두고 맞췄으면 되돌리는 커밋은 없었다. 되돌린 커밋이 밤 11시부터 새벽 1시 사이에 몰린 것도 피곤한 시간에 화면을 결정했기 때문이라고 본다.

공통 컴포넌트 작업은 이슈 [#15](https://github.com/hyeoniverse/MacFolio/issues/15)(기능·UI 개선과 리팩터링)의 한 갈래로, 이날 PR 네 개로 나눠 냈다. 같은 날 연 [#58](https://github.com/hyeoniverse/MacFolio/pull/58)은 [#59](https://github.com/hyeoniverse/MacFolio/pull/59)로 다시 냈다.

고친 것마다 글을 쓰는 것은 이날도 지켰다. 19편이다. 무엇을 왜 그렇게 했는지 그날 적어 두어서, 열흘 뒤 이 회고를 쓸 때도 커밋보다 글을 먼저 참고했다.
