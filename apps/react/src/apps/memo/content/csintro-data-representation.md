## 진법과 자릿값

### 왜 2진법인가

진법은 수를 몇 개의 숫자 기호로 표현하는지를 정하는 규칙이다. 사람은 손가락 수와 같은 10진법을 주로 쓰지만, 역사적으로 다른 진법도 쓰였다. 바빌로니아는 60진법을 썼고 그 흔적이 1시간 = 60분, 원 한 바퀴 = 360°에 남아 있다. 마야 문명은 20진법을 썼다.

디지털 컴퓨터는 2진법을 쓴다. 전자 회로에서 전압이 높은 상태와 낮은 상태 두 가지만 구분하면, 전압이 약간 흔들려도 0과 1을 혼동하지 않는다. 10단계를 구분하는 회로보다 잡음에 강하고 만들기 쉽다.

### 자릿값

r진법에서 각 자리의 값은 r의 거듭제곱이다. 소수점 왼쪽 첫 자리가 `r^0{:math}`, 그 왼쪽이 `r^1{:math}`, 소수점 오른쪽 첫 자리가 `r^{-1}{:math}`이다.

```math
d_{n-1} \cdots d_1 d_0 . d_{-1} d_{-2} \cdots_{(r)} = \sum_{i} d_i \times r^{i}
```

| 진법   | 사용하는 숫자   | 자릿값(정수부, 오른쪽부터) | 주 용도                                        |
| ------ | --------------- | -------------------------- | ---------------------------------------------- |
| 2진수  | 0, 1            | 1, 2, 4, 8, 16, …          | 컴퓨터 내부 표현                               |
| 8진수  | 0~7             | 1, 8, 64, 512, …           | 유닉스 파일 권한(`chmod 755`)                  |
| 10진수 | 0~9             | 1, 10, 100, 1000, …        | 사람이 읽는 값                                 |
| 16진수 | 0~9, A~F(10~15) | 1, 16, 256, 4096, …        | 메모리 주소, 색상 코드(`#0A84FF`), 바이트 덤프 |

같은 숫자열 `111`도 진법에 따라 값이 다르다.

| 표기      | 계산                                                   | 10진수 값 |
| --------- | ------------------------------------------------------ | --------- |
| `111(2)`  | `1 \times 2^2 + 1 \times 2^1 + 1 \times 2^0{:math}`    | 7         |
| `111(8)`  | `1 \times 8^2 + 1 \times 8^1 + 1 \times 8^0{:math}`    | 73        |
| `111(16)` | `1 \times 16^2 + 1 \times 16^1 + 1 \times 16^0{:math}` | 273       |

## 진법 변환

### r진수에서 10진수로

각 자리 숫자에 자릿값을 곱해 모두 더한다. 소수부도 같은 방법으로 음의 거듭제곱을 곱한다.

| 수          | 계산                                                                                            | 결과     |
| ----------- | ----------------------------------------------------------------------------------------------- | -------- |
| `110101(2)` | `2^5 + 2^4 + 2^2 + 2^0 = 32 + 16 + 4 + 1{:math}`                                                | 53       |
| `1.1(2)`    | `1 + 1 \times 2^{-1}{:math}`                                                                    | 1.5      |
| `235.24(8)` | `2 \times 64 + 3 \times 8 + 5 + 2 \times 8^{-1} + 4 \times 8^{-2} = 157 + 0.25 + 0.0625{:math}` | 157.3125 |
| `7BC1(16)`  | `7 \times 4096 + 11 \times 256 + 12 \times 16 + 1{:math}`                                       | 31681    |

### 10진수에서 r진수로

정수부와 소수부를 따로 변환한다.

1. 정수부: r로 나눈 나머지를 기록하고, 몫이 0이 될 때까지 몫을 다시 r로 나눈다. 나머지를 마지막에 구한 것부터 역순으로 읽는다.
2. 소수부: r을 곱해 생긴 정수부(0 또는 자리올림 숫자)를 기록하고, 남은 소수부에 다시 r을 곱한다. 소수부가 0이 되거나 원하는 자릿수에 이르면 멈추고, 기록한 숫자를 순서대로 읽는다.

19를 2진수로, 0.625를 2진수로 변환하는 과정은 다음과 같다.

| 단계 | 19 ÷ 2 | 나머지 |     | 단계 | 소수부 × 2   | 정수부 |
| ---- | ------ | ------ | --- | ---- | ------------ | ------ |
| 1    | 19 → 9 | 1      |     | 1    | 0.625 → 1.25 | 1      |
| 2    | 9 → 4  | 1      |     | 2    | 0.25 → 0.5   | 0      |
| 3    | 4 → 2  | 0      |     | 3    | 0.5 → 1.0    | 1      |
| 4    | 2 → 1  | 0      |     |      |              |        |
| 5    | 1 → 0  | 1      |     |      |              |        |

나머지를 아래에서 위로 읽으면 `19 = 10011(2)`, 정수부를 위에서 아래로 읽으면 `0.625 = 0.101(2)`이다. 같은 방법으로 19를 16으로 나누면 몫 1, 나머지 3이므로 `19 = 13(16)`이고, 52.375를 8진수로 바꾸면 52 = 6 × 8 + 4, 0.375 × 8 = 3.0이므로 `64.3(8)`이다.

> [!WARNING] 유한한 10진 소수가 2진수에서는 무한 소수가 된다
> 0.1을 2진수로 바꾸면 0.1 → 0.2 → 0.4 → 0.8 → 1.6 → 1.2 → 0.4 …로 `0.000110011001100…(2)`가 끝없이 반복된다. 컴퓨터는 이 수를 유한한 비트에서 잘라 저장하므로 오차가 생긴다. JavaScript에서 `0.1 + 0.2 === 0.3`이 `false`인 이유다. 금액처럼 정확해야 하는 값은 원 단위 정수로 저장하거나 10진 소수 자료형(`decimal`)을 쓴다.

### 2진수와 8진수·16진수 사이의 변환

`8 = 2^3{:math}`, `16 = 2^4{:math}`이므로 2진수를 오른쪽부터 3자리씩 묶으면 8진수 한 자리, 4자리씩 묶으면 16진수 한 자리가 된다. 10진수를 거칠 필요가 없다.

| 2진수 `101100110111` | 묶음              | 결과      |
| -------------------- | ----------------- | --------- |
| 3자리씩              | `101 100 110 111` | `5467(8)` |
| 4자리씩              | `1011 0011 0111`  | `B37(16)` |

16진수 두 자리가 정확히 1바이트(8비트)이므로, 메모리 덤프와 패킷 분석 도구는 바이트를 16진수로 표시한다.

## 비트, 바이트, 워드

| 단위         | 크기                            | 설명                                                                         |
| ------------ | ------------------------------- | ---------------------------------------------------------------------------- |
| 비트(bit)    | 0 또는 1                        | binary digit의 줄임말. 정보의 최소 단위. n비트로 `2^n{:math}`가지를 구분한다 |
| 니블(nibble) | 4비트                           | 16진수 한 자리                                                               |
| 바이트(byte) | 8비트                           | 메모리 주소를 부여하는 기본 단위. 256가지 값                                 |
| 워드(word)   | CPU마다 다름(32비트, 64비트 등) | CPU가 한 번에 처리하는 데이터 크기. 레지스터 크기와 같다                     |

예를 들어 3비트로는 `000`부터 `111`까지 `2^3 = 8{:math}`가지를 구분하므로, 요일 7개를 모두 표현할 수 있다. 오늘날 PC와 스마트폰의 CPU는 대부분 64비트이므로 워드는 8바이트다. 다만 x86 계열의 어셈블리 문서는 역사적인 이유로 16비트를 word, 32비트를 dword(double word)라고 부르므로 문맥을 확인해야 한다.

기억 용량 단위에는 두 체계가 있다. 저장장치 제조사는 10의 거듭제곱(1 KB = 1,000바이트)을, 운영체제의 상당수는 2의 거듭제곱을 쓴다. IEC는 혼동을 막기 위해 2의 거듭제곱 단위에 KiB(키비바이트) 같은 별도 이름을 정했다.

| 10진 접두사 | 값               | 2진 접두사(IEC) | 값                     |
| ----------- | ---------------- | --------------- | ---------------------- |
| KB          | `10^3{:math}`    | KiB             | `2^{10} = 1024{:math}` |
| MB          | `10^6{:math}`    | MiB             | `2^{20}{:math}`        |
| GB          | `10^9{:math}`    | GiB             | `2^{30}{:math}`        |
| TB          | `10^{12}{:math}` | TiB             | `2^{40}{:math}`        |

1 TB로 판매된 SSD를 Windows에서 연결하면 약 931 GB로 표시되는 이유가 이 차이다. `10^{12} \div 2^{30} \approx 931{:math}`이다.

## 정수의 표현

### 부호 없는 정수

n비트를 모두 크기에 쓰면 0부터 `2^n - 1{:math}`까지 표현한다. 8비트면 0~255다. 255에 1을 더하면 `1 0000 0000`이 되는데 9번째 비트를 저장할 자리가 없으므로 0이 된다. 이렇게 표현 범위를 넘는 현상을 오버플로(overflow)라고 한다.

### 음수를 표현하는 세 방법

음수를 표현하려면 비트 하나를 부호에 써야 한다. 맨 앞(최상위) 비트를 부호 비트로 쓰는 방법이 세 가지 있다. +10과 -10을 8비트로 표현하면 다음과 같다.

| 방식        | 음수 만드는 법             | +10        | -10        | 8비트 범위  | 0의 표현     |
| ----------- | -------------------------- | ---------- | ---------- | ----------- | ------------ |
| 부호-절댓값 | 부호 비트만 1로            | `00001010` | `10001010` | -127 ~ +127 | +0, -0 두 개 |
| 1의 보수    | 모든 비트 반전             | `00001010` | `11110101` | -127 ~ +127 | +0, -0 두 개 |
| 2의 보수    | 모든 비트 반전 후 1을 더함 | `00001010` | `11110110` | -128 ~ +127 | 하나         |

같은 방법으로 ±38은 부호-절댓값 `00100110`/`10100110`, 1의 보수 `00100110`/`11011001`, 2의 보수 `00100110`/`11011010`이다.

보수(complement)의 일반적인 정의는 다음과 같다. r진수 n자리 수 N에 대해 (r-1)의 보수는 각 자리를 r-1에서 뺀 값 `(r^n - 1) - N{:math}`이고, r의 보수는 여기에 1을 더한 `r^n - N{:math}`이다. 10진수 534의 9의 보수는 999 - 534 = 465, 10의 보수는 466이다. 2진수 1010의 1의 보수는 0101, 2의 보수는 0110이다.

### 2의 보수를 쓰는 이유

오늘날 거의 모든 CPU가 2의 보수로 정수를 표현한다. 이유는 두 가지다.

1. 0이 하나뿐이다. 부호-절댓값과 1의 보수에는 `00000000`(+0)과 `10000000` 또는 `11111111`(-0)이 따로 있어 비교 회로가 복잡해진다.
2. 뺄셈을 덧셈 회로로 처리한다. A - B는 A + (B의 2의 보수)로 계산하고, 맨 앞에서 넘친 자리올림은 버린다. 부호를 따로 확인할 필요가 없으므로 덧셈기 하나로 덧셈과 뺄셈을 모두 처리한다.

![4비트 2의 보수 수 원: 0000부터 0111까지는 0~+7, 1000부터 1111까지는 -8~-1에 대응한다. 시계 방향으로 한 칸 이동하면 1을 더한 것이고, +7(0111)에서 한 칸 더 가면 -8(1000)이 되는 오버플로 경계가 있다. 오른쪽에는 +3을 반전하고 1을 더해 -3(1101)을 구하는 과정과 0101 + 1101 = 1 0010에서 넘친 자리올림을 버려 2를 얻는 계산이 있다](./images/csintro-data-representation-twos-complement.svg '4비트 2의 보수는 수직선을 원으로 말아 놓은 것과 같다')

n비트 2의 보수의 표현 범위는 `-2^{n-1}{:math}`부터 `2^{n-1} - 1{:math}`까지다. 32비트 정수(C의 `int`)는 -2,147,483,648부터 2,147,483,647까지다.

> [!CAUTION] 정수 오버플로와 보안
> 2,147,483,647에 1을 더하면 -2,147,483,648이 된다. 프로그램이 `if (len + 1 > MAX)`처럼 검사할 때 `len`이 최댓값이면 합이 음수가 되어 검사를 통과하고, 그 값으로 메모리를 할당하면 버퍼 오버플로로 이어질 수 있다. 정수 오버플로는 CWE-190으로 분류된 취약점이다.

## 실수의 표현

### 고정소수점

고정소수점(fixed-point)은 소수점의 위치를 미리 정해 두는 방식이다. 예를 들어 16비트 중 앞 8비트를 정수부, 뒤 8비트를 소수부로 정하면 소수부는 `1/256{:math}` 단위로만 표현된다. 회로가 단순하지만, 같은 비트 수로 표현할 수 있는 범위가 좁아 매우 큰 수(천문학적 거리)와 매우 작은 수(원자 크기)를 함께 다루지 못한다. 정수는 소수점이 맨 오른쪽에 고정된 고정소수점으로 볼 수 있다.

### 부동소수점과 정규화

부동소수점(floating-point)은 수를 과학적 표기법처럼 가수와 지수로 나눠 저장한다. 10진수 123,000을 `1.23 \times 10^5{:math}`로 쓰듯, 2진수를 `1.xxx \times 2^e{:math}` 형태로 바꾸는 과정을 정규화라고 한다.

```math
10110.11011_{(2)} = 1.011011011_{(2)} \times 2^{4}
```

소수점이 지수에 따라 떠다니므로(floating) 같은 비트 수로 넓은 범위를 표현한다. 현재 거의 모든 CPU와 프로그래밍 언어는 IEEE 754 표준을 따른다.

| 형식               | 전체   | 부호 | 지수 | 가수 | 바이어스 | 10진 유효 자릿수 | C 자료형 |
| ------------------ | ------ | ---- | ---- | ---- | -------- | ---------------- | -------- |
| 단정밀도(binary32) | 32비트 | 1    | 8    | 23   | 127      | 약 7자리         | `float`  |
| 배정밀도(binary64) | 64비트 | 1    | 11   | 52   | 1023     | 약 15~16자리     | `double` |

![IEEE 754 단정밀도 형식: 31번 비트는 부호 S, 30~23번은 지수 E 8비트, 22~0번은 가수 M 23비트이고 값은 (-1)^S × 1.M × 2^(E-127)이다. -6.75는 110.11(2) = 1.1011 × 2^2이므로 S = 1, E = 129 = 10000001, M = 1011 뒤에 0을 채운 값이 되어 16진수 0xC0D80000이다](./images/csintro-data-representation-ieee754.svg '정규화된 수의 맨 앞 1은 저장하지 않는다')

- 부호(S): 0이면 양수, 1이면 음수
- 지수(E): 실제 지수에 바이어스(단정밀도 127)를 더해 부호 없는 수로 저장한다. 지수가 -2이면 125를, 3이면 130을 저장한다. 음의 지수를 따로 부호 처리하지 않아도 되고, 지수 필드를 정수처럼 크기 비교할 수 있다.
- 가수(M): 정규화하면 소수점 앞은 항상 1이므로 이 1은 저장하지 않고(hidden bit), 소수점 뒤 비트만 왼쪽부터 채우고 나머지를 0으로 채운다. 그래서 23비트로 24비트 정밀도를 얻는다.

계산 예를 기호, 단계, 결과 순서로 정리하면 다음과 같다.

| 2진수           | 정규화                        | S   | E(10진) | E(2진)     | M(앞부분) |
| --------------- | ----------------------------- | --- | ------- | ---------- | --------- |
| `1010.011`      | `1.010011 \times 2^3{:math}`  | 0   | 130     | `10000010` | `010011`  |
| `0.011001`      | `1.1001 \times 2^{-2}{:math}` | 0   | 125     | `01111101` | `1001`    |
| `110.11`(-6.75) | `1.1011 \times 2^2{:math}`    | 1   | 129     | `10000001` | `1011`    |

`1010.011(2)`의 단정밀도 표현은 `0 10000010 01001100000000000000000`이다.

> [!NOTE] 특수한 값
> 지수 필드가 모두 1이면 무한대(가수가 0)나 NaN(Not a Number, 가수가 0이 아님)을 뜻한다. `1.0 / 0.0`은 무한대, `0.0 / 0.0`은 NaN이다. 지수 필드가 모두 0이면 0 또는 정규화하지 않은 아주 작은 수(비정규 수)를 뜻한다.

## 문자의 표현

문자는 숫자로 바꿔 저장한다. 어떤 문자에 어떤 번호를 붙이는지 정한 표를 문자 집합(character set), 그 번호를 바이트열로 바꾸는 규칙을 문자 인코딩(character encoding)이라고 한다.

### BCD와 EBCDIC

- BCD(Binary Coded Decimal, 2진화 10진 코드): 10진수 한 자리를 4비트 2진수로 표현한다. 각 비트의 가중치가 8, 4, 2, 1이어서 8421 코드라고도 한다. 10진수 59는 `0101 1001`이다. 2진수 변환 없이 10진수 자릿수를 그대로 다룰 수 있어 전자계산기, 금융 시스템에서 쓰였다. 여기에 존(zone) 비트 2개를 더해 6비트로 64개 문자를 표현한 코드를 BCD 문자 코드(BCDIC)라고 한다.
- EBCDIC(Extended BCD Interchange Code): IBM이 1960년대 System/360 메인프레임에 도입한 8비트 문자 코드로, 256개 문자를 표현한다. 지금도 IBM 메인프레임에서 쓰인다. 알파벳이 연속된 번호가 아니어서(`I`는 0xC9, `J`는 0xD1) ASCII와 변환할 때 표가 필요하다.

### ASCII

ASCII(American Standard Code for Information Interchange)는 미국표준협회(ASA, 현재 ANSI)가 1963년 제정한 7비트 문자 코드다. 0~127, 128개 번호를 쓴다.

| 범위      | 내용                                             | 예                                                 |
| --------- | ------------------------------------------------ | -------------------------------------------------- |
| 0~31, 127 | 제어 문자: 화면에 표시되지 않고 장치 동작을 지시 | 9 = 탭(HT), 10 = 줄 바꿈(LF), 13 = 캐리지 리턴(CR) |
| 32        | 공백                                             |                                                    |
| 48~57     | 숫자                                             | `'0'` = 48(0x30), `'9'` = 57(0x39)                 |
| 65~90     | 영문 대문자                                      | `'A'` = 65(0x41)                                   |
| 97~122    | 영문 소문자                                      | `'a'` = 97(0x61)                                   |
| 그 외     | 특수 문자                                        | `'!'` = 33, `'@'` = 64                             |

배치에는 규칙이 있다. 대문자와 소문자는 정확히 32(0x20) 차이 나므로, 6번째 비트(0x20) 하나만 바꾸면 대소문자가 바뀐다. 숫자 문자에서 48을 빼면 숫자 값이 된다.

컴퓨터는 1바이트(8비트) 단위로 데이터를 다루므로 ASCII 문자도 1바이트에 저장하고, 남는 최상위 비트는 0이다. 직렬 통신에서는 이 비트를 전송 오류 검사용 패리티 비트로 쓰기도 했다. 128~255를 각 나라 문자에 배정한 8비트 확장 코드(ISO 8859-1 등)도 만들어졌지만, 나라마다 128~255의 의미가 달라 서로 호환되지 않았다. 한국어 환경에서 쓰던 EUC-KR(완성형)은 한글 한 글자를 2바이트로 표현해 2,350자를 담았다.

### 유니코드

유니코드(Unicode)는 전 세계 문자를 하나의 문자 집합에 모으기 위해 유니코드 컨소시엄이 관리하는 표준이다. 각 문자에 코드 포인트라는 번호를 붙이고 `U+` 뒤에 16진수로 표기한다. `A`는 U+0041, `가`는 U+AC00, 웃는 얼굴 이모지는 U+1F600이다.

유니코드 초기(1991년 1.0)에는 16비트로 65,536자를 모두 담을 계획이었지만, 한자와 역사 문자를 모두 담기에 부족했다. 1996년 유니코드 2.0부터 코드 포인트 범위가 U+0000~U+10FFFF, 약 111만 개로 넓어졌다. 2023년의 유니코드 15.1은 약 15만 자를 정의한다. 현대 한글 완성형 11,172자(초성 19 × 중성 21 × 종성 28)는 U+AC00~U+D7A3에 순서대로 배치되어 있어, 코드 포인트를 계산으로 구할 수 있다.

```math
\text{코드 포인트} = \text{0xAC00} + (\text{초성} \times 21 + \text{중성}) \times 28 + \text{종성}
```

`가`는 초성·중성·종성 번호가 모두 0이므로 0xAC00이고, `각`은 종성 ㄱ이 1번이므로 0xAC01이다.

### UTF-8, UTF-16, UTF-32

유니코드는 번호를 정할 뿐이고, 그 번호를 바이트로 저장하는 방식은 여러 가지다. UTF 뒤의 숫자는 인코딩의 기본 단위(코드 유닛) 크기를 비트로 나타낸 것이며, 문자 하나의 크기가 아니다.

| 인코딩 | 코드 유닛 | 문자 하나의 크기 | 특징                                                                                  |
| ------ | --------- | ---------------- | ------------------------------------------------------------------------------------- |
| UTF-8  | 8비트     | 1~4바이트        | ASCII와 완전 호환. 웹 페이지의 98% 이상이 사용                                        |
| UTF-16 | 16비트    | 2 또는 4바이트   | U+FFFF를 넘는 문자는 서로게이트 쌍(4바이트). Windows API, Java·JavaScript 문자열 내부 |
| UTF-32 | 32비트    | 4바이트 고정     | n번째 문자 위치를 바로 계산할 수 있지만 용량이 크다                                   |

![UTF-8 바이트 구성: U+0000~U+007F는 0xxxxxxx 1바이트, U+0080~U+07FF는 110xxxxx 10xxxxxx 2바이트, U+0800~U+FFFF는 1110xxxx 10xxxxxx 10xxxxxx 3바이트, U+10000~U+10FFFF는 4바이트다. '가'(U+AC00)의 16비트 1010 110000 000000을 세 바이트의 x 자리에 나눠 넣으면 11101010 10110000 10000000, 즉 EA B0 80이 된다](./images/csintro-data-representation-utf8.svg '첫 바이트의 접두사가 문자의 바이트 수를 알려 준다')

UTF-8의 인코딩 규칙은 RFC 3629에 정의되어 있다. `가`(U+AC00)를 인코딩하는 단계는 다음과 같다.

1. U+AC00은 U+0800~U+FFFF 범위이므로 3바이트 형식 `1110xxxx 10xxxxxx 10xxxxxx`를 쓴다.
2. 0xAC00을 16비트 2진수로 쓰면 `1010 1100 0000 0000`이다.
3. 앞에서부터 4비트, 6비트, 6비트로 나눈다: `1010` / `110000` / `000000`
4. x 자리에 채우면 `11101010 10110000 10000000` = `EA B0 80`이다.

그래서 UTF-8에서 한글 한 글자는 3바이트, 영문은 1바이트다. "Hello"는 5바이트, "안녕"은 6바이트다. 터미널에서 직접 확인할 수 있다.

```bash
$ printf '가' | xxd
00000000: eab0 80                                  ...
$ printf 'A가' | wc -c
       4
```

> [!IMPORTANT] 인코딩과 보안
> 같은 문자를 여러 바이트열로 표현할 수 있으면 필터를 우회할 수 있다. 예를 들어 `/`(0x2F)를 규칙에 어긋나는 2바이트 `C0 AF`로 표현하는 과도 표현(overlong encoding)은 과거 웹 서버의 디렉터리 이동 공격(`../`) 필터를 우회하는 데 쓰였다. RFC 3629는 디코더가 이런 바이트열을 거부하도록 요구한다. 웹 보안 필터는 입력을 한 번 정규화한 뒤에 검사해야 한다.

## 소리와 이미지의 디지털화

자연의 소리와 빛은 연속적인 아날로그 신호다. 컴퓨터에 저장하려면 일정한 간격으로 값을 측정하고(표본화), 그 값을 정해진 단계 중 하나로 반올림한 뒤(양자화), 2진수로 부호화한다.

### 소리

| 단계   | 하는 일                                      | 예(음악 CD)                         |
| ------ | -------------------------------------------- | ----------------------------------- |
| 표본화 | 1초에 몇 번 진폭을 측정할지 정한다(표본화율) | 44,100 Hz: 1초에 44,100번 측정      |
| 양자화 | 측정값을 몇 단계로 나눌지 정한다(비트 깊이)  | 16비트: `2^{16} = 65536{:math}`단계 |
| 부호화 | 단계 번호를 2진수로 저장한다                 | 스테레오 2채널                      |

나이퀴스트-섀넌 표본화 정리에 따르면 원래 신호의 최고 주파수의 2배보다 높은 비율로 표본화해야 원래 신호를 복원할 수 있다. 사람의 가청 주파수 상한이 약 20 kHz이므로 CD는 그 2배를 조금 넘는 44.1 kHz를 쓴다. 압축하지 않은 CD 음질 1초의 크기는 다음과 같다.

```math
44100 \times 16\,\text{bit} \times 2\,\text{채널} = 1{,}411{,}200\,\text{bit/s} \approx 176\,\text{KB/s}
```

3분짜리 곡이면 약 31.8 MB다. MP3와 AAC는 사람이 잘 듣지 못하는 성분을 제거하는 손실 압축으로 이 크기를 약 10분의 1로 줄인다.

### 이미지

비트맵 이미지는 화면을 격자 모양의 픽셀로 나누고, 픽셀마다 색을 숫자로 저장한다. 가장 흔한 24비트 트루컬러는 빨강(R), 초록(G), 파랑(B) 각각을 8비트(0~255)로 표현해 약 1,677만 색(`2^{24}{:math}`)을 나타낸다. 웹 색상 코드 `#0A84FF`는 R = 0x0A(10), G = 0x84(132), B = 0xFF(255)다.

| 해상도               | 픽셀 수   | 24비트 비압축 크기 |
| -------------------- | --------- | ------------------ |
| 1920 × 1080 (FHD)    | 2,073,600 | 약 6.2 MB          |
| 3840 × 2160 (4K UHD) | 8,294,400 | 약 24.9 MB         |

비압축 이미지가 크기 때문에 사진은 JPEG(손실 압축), 스크린샷과 아이콘은 PNG(무손실 압축)로 저장하는 경우가 많다. 이와 달리 SVG 같은 벡터 이미지는 픽셀 대신 "원점 (10, 10)에서 (100, 50)까지 직선"처럼 도형을 수식으로 저장하므로 확대해도 계단 현상이 생기지 않는다.

## 정리

- r진법의 각 자리는 r의 거듭제곱을 자릿값으로 가진다. 10진수로 바꿀 때는 자릿값을 곱해 더하고, 10진수에서 바꿀 때는 정수부는 나눗셈의 나머지를 역순으로, 소수부는 곱셈의 정수부를 순서대로 읽는다.
- 2진수 3자리는 8진수 1자리, 4자리는 16진수 1자리에 대응한다.
- 정수는 2의 보수로 표현한다. 0이 하나뿐이고 뺄셈을 덧셈 회로로 처리하며, n비트 범위는 `-2^{n-1}{:math}` ~ `2^{n-1} - 1{:math}`이다.
- 실수는 IEEE 754 부동소수점으로 부호, 바이어스를 더한 지수, 맨 앞 1을 생략한 가수로 저장한다. 0.1처럼 2진수로 유한하게 표현되지 않는 수에는 오차가 생긴다.
- 문자는 문자 집합(유니코드)이 번호를 정하고 인코딩(UTF-8)이 바이트열을 정한다. UTF-8에서 영문은 1바이트, 한글은 3바이트다.
- 소리와 이미지는 표본화, 양자화, 부호화를 거쳐 숫자로 저장된다.
