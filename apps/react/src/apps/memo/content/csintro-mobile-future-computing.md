지금은 컴퓨터라고 하면 책상 위의 PC보다 주머니 속 스마트폰을 먼저 떠올리는 사람이 많다. 한발 더 나아가 냉장고, 손목시계, 자동차, 교통카드에도 작은 프로세서와 통신 모듈이 들어가 있다. 이 글은 이런 변화를 두 갈래로 나누어 설명한다.

필요한 배경은 두 가지다. 운영체제(OS)는 하드웨어를 관리하고 응용 프로그램이 하드웨어를 쓸 수 있도록 공통 기능을 제공하는 소프트웨어다. 네트워크는 기기끼리 데이터를 주고받는 통로이고, 인터넷은 그 네트워크들을 TCP/IP라는 공통 규약으로 연결한 것이다. TCP/IP의 계층 구조는 [TCP/IP 계층 모델과 캡슐화](/memo/net-tcpip-model)에서 자세히 다룬다.

## 모바일 기술

### 모바일과 스마트폰의 등장

모바일(mobile)은 '고정되어 있지 않고 이동할 수 있는'이라는 뜻이다. 정보통신 분야에서는 이동하면서 쓰는 통신 기기를 통틀어 모바일 기기라고 부른다. 휴대전화, 태블릿, 스마트워치가 모두 여기에 속한다.

스마트폰은 전화 기능에 범용 운영체제를 얹어 사용자가 응용 프로그램(앱)을 직접 설치할 수 있게 만든 휴대전화다. 주요 사건을 시간순으로 놓으면 다음과 같다.

| 연도 | 사건                                                                 |
| ---- | -------------------------------------------------------------------- |
| 1999 | RIM(현 BlackBerry Ltd.)이 이메일 단말기 BlackBerry를 출시            |
| 2007 | 애플이 첫 iPhone을 출시. 구글 주도로 Open Handset Alliance(OHA) 결성 |
| 2008 | 첫 안드로이드폰(HTC Dream) 출시, App Store 개장                      |
| 2010 | 삼성전자가 안드로이드 기반 갤럭시 S를 출시                           |

iPhone 이전에도 스마트폰은 있었지만, 키보드 대신 손가락으로 조작하는 정전식 터치스크린과 앱 마켓이라는 유통 구조가 함께 등장하면서 시장이 급격히 커졌다. BlackBerry는 2000년대 중반 북미에서 업무용 스마트폰의 대명사였고, 2007년 iPhone(국내에서는 흔히 '아이폰 2G'라고 부르는 1세대)과 2010년 갤럭시 S가 나오면서 일반 소비자 수요가 폭발적으로 늘었다.

![2009년 4분기부터 2018년 4분기까지 분기별 제조사 점유율 누적 막대그래프. 초기에는 노키아와 RIM 비중이 크고, 이후 삼성과 애플이 커지며 2010년대 후반에는 화웨이, 샤오미, OPPO, vivo가 늘어난다](./images/csintro-mobile-future-computing-vendor-share.jpg '분기별 세계 스마트폰 제조사 점유율. 출처: Statista')

그래프에서 2009년에는 초록색 노키아와 분홍색 RIM(BlackBerry)이 절반 가까이를 차지하지만, 2012년 무렵에는 거의 사라지고 파란색 삼성과 회색 애플이 그 자리를 채운다. 2010년대 후반에는 화웨이, 샤오미, OPPO, vivo 같은 중국 제조사가 빠르게 늘어난다. 휴대전화 시장의 1위 기업이었던 노키아가 3~4년 만에 밀려난 것은 ==하드웨어보다 플랫폼(운영체제와 앱 생태계)이 경쟁력을 좌우하게 되었음을 보여 준다==.

![2009년부터 2018년까지 모바일 운영체제 판매 점유율 꺾은선 그래프. Symbian은 50%에서 0으로 떨어지고 Android는 2%에서 85% 이상으로 오르며 iOS는 15~20% 사이를 유지한다](./images/csintro-mobile-future-computing-os-share.jpg '모바일 운영체제별 판매 점유율. 출처: pcskull.com (Gartner 자료 인용)')

운영체제별로 보면 변화가 더 뚜렷하다. 2009년 1분기에 약 50%였던 Symbian은 2013년에 사실상 0이 되었고, 안드로이드는 같은 기간 한 자릿수에서 80% 이상으로 올라갔다. iOS는 비싼 고급 기기 중심이라 판매 대수 점유율은 15~20%에 머물지만, 앱 매출에서는 안드로이드보다 큰 비중을 차지한다. 2010년대 중반 이후로는 안드로이드와 iOS 두 플랫폼이 시장의 거의 전부를 차지한다.

### 모바일 플랫폼

모바일 플랫폼은 모바일 운영체제를 중심으로, ==단말기 하드웨어가 달라도 같은 앱이 실행되도록 지원하는 소프트웨어 환경이다==. 운영체제 커널, 하드웨어 추상화 계층, 앱이 호출하는 API(application programming interface), 개발 도구, 앱 마켓까지 포함하는 개념이다. 예를 들어 카메라 앱 개발자는 제조사마다 다른 카메라 칩을 직접 제어하지 않고, 플랫폼이 제공하는 카메라 API만 호출하면 된다.

플랫폼을 공개하는 방식은 두 가지로 나뉜다.

- **공개형**: 소스 코드는 공개하지 않고 API와 SDK(software development kit)만 개발자에게 제공한다. iOS가 대표적이다.
- **오픈 소스형**: 플랫폼의 소스 코드 자체를 공개한다. 안드로이드의 기반인 AOSP(Android Open Source Project)가 대표적이다. 자체 플랫폼이 없는 제조사도 소스를 받아 자사 기기에 맞게 수정해 탑재할 수 있다.

| 플랫폼        | 개발 주체                  | 특징                                                             | 현재 상태                                |
| ------------- | -------------------------- | ---------------------------------------------------------------- | ---------------------------------------- |
| Android       | 구글, OHA                  | 리눅스 커널 기반 오픈 소스. 여러 제조사가 탑재                   | 세계 점유율 1위                          |
| iOS           | 애플                       | iPhone·iPad에 같은 SDK로 개발. 하드웨어와 소프트웨어를 함께 설계 | 점유율 2위                               |
| Windows Phone | 마이크로소프트             | 2015년 Windows 10 Mobile로 통합(대표 기기 Lumia 950)             | 2020년 1월 지원 종료                     |
| Symbian       | 노키아, Symbian Foundation | 2000년대 점유율 1위. 2010년 오픈 소스로 전환                     | 2013년 노키아의 마지막 출하 후 개발 중단 |
| BlackBerry OS | RIM                        | 사내 메일 서버와 연동, 업무용으로 인기                           | 2022년 1월 서비스 종료                   |

OHA(Open Handset Alliance)는 2007년 11월 구글이 이동통신사, 단말기 제조사, 반도체 회사 등 34개 회사와 함께 결성한 개방형 휴대전화 동맹이고, 이후 참여사가 계속 늘었다. 안드로이드가 빠르게 퍼진 이유 중 하나는 ==제조사가 라이선스 비용 없이 플랫폼을 탑재할 수 있었다==는 점이다. 같은 시기 리눅스 기반 오픈 소스 플랫폼으로 LiMo(리모)도 있었지만 시장에서 자리를 잡지 못하고 Tizen으로 흡수되었다.

플랫폼마다 개발자에게 SDK를 제공한다. SDK에는 앱을 컴파일하는 도구, 플랫폼 API를 쓰기 위한 라이브러리, 컴퓨터에서 스마트폰을 흉내 내는 에뮬레이터, 디버거가 들어 있다. 안드로이드는 Android Studio와 Android SDK를, iOS는 Xcode와 iOS SDK를 쓴다. iOS는 iPhone, iPod touch, iPad가 같은 운영체제를 쓰므로 하나의 SDK로 세 기기의 앱을 만들 수 있다.

### 안드로이드의 구조와 앱 보안

안드로이드는 여러 계층이 쌓인 소프트웨어 스택으로 이루어진다.

![안드로이드 소프트웨어 스택. 맨 아래 리눅스 커널 위에 하드웨어 추상화 계층, 그 위에 네이티브 라이브러리와 안드로이드 런타임, 자바 API 프레임워크, 맨 위에 앱이 있다](./images/csintro-mobile-future-computing-android-stack.svg '아래 계층일수록 하드웨어에 가깝고, 앱은 프레임워크 API만 호출한다')

| 계층                     | 하는 일                                                                                 |
| ------------------------ | --------------------------------------------------------------------------------------- |
| 리눅스 커널              | 프로세스·메모리 관리, 장치 드라이버, 보안 모듈(SELinux)                                 |
| 하드웨어 추상화 계층     | 제조사마다 다른 카메라·센서 칩을 같은 인터페이스로 감싼다                               |
| 네이티브 라이브러리, ART | 그래픽(OpenGL), 데이터베이스(SQLite) 같은 C/C++ 라이브러리와, 앱 코드를 실행하는 런타임 |
| 자바 API 프레임워크      | 화면 전환, 알림, 위치, 권한 확인 같은 기능을 앱에 API로 제공                            |
| 앱                       | 기본 앱과 사용자가 설치한 앱                                                            |

보안 관점에서 중요한 것은 앱 샌드박스(sandbox)다. 안드로이드는 앱을 설치할 때마다 서로 다른 리눅스 사용자 번호(UID)를 붙이고, 각 앱의 파일을 그 UID만 읽을 수 있게 만든다. ==리눅스의 사용자별 파일 권한을 앱 격리에 그대로 쓰는 것이다==. 그래서 메모 앱이 은행 앱의 파일을 몰래 읽을 수 없다. 앱이 연락처, 위치, 카메라처럼 민감한 자원을 쓰려면 권한(permission)을 선언하고, 실행 중에 사용자에게 허용을 받아야 한다. iOS도 앱마다 격리된 컨테이너를 두고, 애플이 서명한 앱만 실행하도록 강제한다. 리눅스 권한의 원리는 [시스템 보안: 계정·접근 제어·권한·로그·취약점 관리와 버퍼 오버플로](/memo/csintro-system-security)에서 다룬다.

> [!CAUTION] 공식 마켓 밖에서 받은 앱
> 문자 메시지의 링크로 받은 `.apk` 파일을 설치하는 것을 사이드로딩(sideloading)이라고 한다. 공식 마켓의 검사를 거치지 않으므로, 택배 조회나 청첩장으로 위장한 스미싱 앱이 이 경로로 설치되어 문자와 연락처를 빼낸다. 설정의 "출처를 알 수 없는 앱 설치" 허용은 꺼 두고, 설치할 때 요구하는 권한이 앱의 기능에 맞는지 확인한다.

### 모바일 웹과 HTML5

모바일 웹은 스마트폰 같은 모바일 단말기에서 웹 서비스를 이용하는 기술이다. 화면이 작고 터치로 조작하며 통신 환경이 자주 바뀐다는 조건에 맞춰, 위치 기반 서비스처럼 모바일에 특화된 기능이 더해졌다.

HTML5는 웹 문서의 구조를 기술하는 마크업 언어 HTML의 다섯 번째 주요 개정판이다. 개발 배경에는 두 언어의 한계가 있었다. HTML4는 단순하지만 새 기능을 넣기 어려웠고, HTML을 XML 문법으로 다시 정의한 XHTML은 확장은 쉽지만 문법이 엄격해 태그 하나만 틀려도 페이지 전체가 표시되지 않을 만큼 다루기 어려웠다. HTML5는 다음 네 가지 설계 원칙을 내걸었다.

| 원칙      | 뜻                                                                                           |
| --------- | -------------------------------------------------------------------------------------------- |
| 호환성    | 기존 웹 페이지가 새 브라우저에서도 그대로 동작해야 한다                                      |
| 독립성    | 특정 기기나 플러그인에 의존하지 않고 PC·모바일 어디서나 같은 기능을 제공한다                 |
| 오류 처리 | 잘못 쓴 문서를 브라우저마다 다르게 해석하지 않도록, 오류를 처리하는 방법까지 표준으로 정한다 |
| 접근성    | 시각 장애인이 쓰는 화면 낭독기 등 보조 기술이 문서 구조를 이해할 수 있게 한다                | 이전에는 동영상을 재생하거나 그래픽을 그리려면 Adobe Flash 같은 브라우저 플러그인이 필요했는데, 모바일 브라우저는 대부분 플러그인을 지원하지 않았다. HTML5는 ==이런 기능을 표준 안으로 가져왔다==. 지금은 WHATWG가 버전 번호 없이 계속 갱신하는 HTML Living Standard로 이어지고 있다. |

| 기능              | HTML5 이전                | HTML5 이후                                       |
| ----------------- | ------------------------- | ------------------------------------------------ |
| 동영상·음성 재생  | Flash 같은 플러그인 필요  | `<video>`, `<audio>` 태그 하나로 재생            |
| 동적 그래픽       | 플러그인 또는 이미지 교체 | `<canvas>`에 자바스크립트로 그리기, SVG 내장     |
| 다른 출처 간 통신 | 사실상 불가               | `postMessage`로 다른 도메인 창과 메시지 송수신   |
| 오프라인 동작     | 불가                      | 웹 스토리지, (현재는) 서비스 워커로 캐시 후 사용 |
| 파일 다루기       | 파일 선택 창만 가능       | 드래그 앤드 드롭, File API                       |

예를 들어 다음 몇 줄만으로 플러그인 없이 동영상을 재생하고, 캔버스에 사각형과 글자를 그릴 수 있다.

```html
<video src="intro.mp4" controls width="320"></video>

<canvas id="board" width="200" height="80"></canvas>
<script>
	const ctx = document.getElementById('board').getContext('2d');
	ctx.fillStyle = '#0a84ff';
	ctx.fillRect(10, 10, 80, 60); // x, y, 너비, 높이
	ctx.fillText('HTML5', 110, 45); // 캔버스에 글자 쓰기
</script>
```

Flash는 보안 취약점이 끊이지 않아 악성코드 유포 경로로 자주 쓰였고, HTML5가 그 기능을 대체하면서 2020년 12월 31일 지원이 종료되었다.

### 소셜 네트워크 서비스

소셜 네트워크 서비스(SNS)는 사용자가 프로필을 만들고 다른 사용자와 관계(친구, 팔로우)를 맺어 콘텐츠를 공유하는 온라인 서비스다. 페이스북은 친구 관계를 서로 승인해야 맺어지는 양방향 구조이고, 트위터(현 X)는 한쪽이 일방적으로 팔로우할 수 있는 단방향 구조다. 트위터는 처음에 휴대전화 문자 메시지 길이에 맞춰 게시물을 140자로 제한했다가 2017년에 280자로 늘렸다.

SNS라는 이름의 세 단어는 각각 공동체(social), 서로 연결된 관계망(network), 이 관계가 가능하도록 기반을 마련해 주는 것(service)을 뜻한다. 2015년 3분기 기준으로 페이스북 이용자는 15억 명, 트위터는 3억 700만 명을 넘었고, 페이스북은 76개 언어를 지원했다. SNS의 특징은 다음과 같다.

1. 서버 중심으로 실행되고, 포털·운영자가 정한 정책에 따라 사용 방식이 결정된다.
2. 사용자가 올린 콘텐츠의 소유권은 이용 약관에 따라 제한적으로만 인정된다. 대부분의 약관은 운영자에게 콘텐츠를 사용할 수 있는 폭넓은 라이선스를 준다.
3. 카페·동호회 같은 온라인 커뮤니티를 개인 단위 관계망으로 확장한 형태로 볼 수 있다.
4. 미리 정한 취미와 친밀도를 기반으로 관계를 맺는다.
5. 웹에서 모바일 앱으로 중심이 옮겨 가고 있다.

SNS는 서비스 운영자의 서버에서 실행되고, 운영자가 정한 정책에 따라 사용 방식과 콘텐츠의 노출 범위가 결정된다. 보안 관점에서는 사용자가 올린 사진의 위치 정보(EXIF), 출신 학교, 생일 같은 개인 정보가 비밀번호 재설정 질문이나 표적형 피싱(스피어 피싱)의 재료가 된다는 점이 문제다.

### 모바일 기기의 사회적 영향

- **디지털 치매**: 전화번호나 길을 기억하는 일을 기기에 맡기면서 기억력과 계산 능력이 떨어진다고 느끼는 현상을 가리키는 대중적인 용어다. ==의학적으로 정의된 질병명은 아니며==, 실제 치매와의 인과 관계도 확립되지 않았다.
  예방법으로는 길을 직접 찾아보기, 자주 거는 전화번호 외우기, 손을 쓰는 취미 활동처럼 뇌에 꾸준히 지적 자극을 주는 일이 권장된다.
- **스마트폰 과의존**: 사용 시간을 스스로 조절하지 못하고, 사용하지 못하면 불안이나 금단 증상이 나타나 일상생활에 지장이 생기는 상태다. 스마트폰이 없으면 아무것도 할 수 없을 것 같은 불안을 느끼기도 한다. 한국지능정보사회진흥원은 매년 「스마트폰 과의존 실태조사」로 위험군 비율을 집계하며, 조사는 조절 실패, 현저성(스마트폰이 생활에서 가장 중요한 활동이 됨), 문제적 결과의 세 요인으로 판정한다.

## 유비쿼터스 컴퓨팅

### 개념

유비쿼터스(ubiquitous)는 라틴어에서 온 말로 '어디에나 존재하는'이라는 뜻이다. 제록스 팰로앨토 연구소(PARC)의 마크 와이저(Mark Weiser)는 1991년 논문 "The Computer for the 21st Century"에서 다음과 같이 썼다.

> The most profound technologies are those that disappear. They weave themselves into the fabric of everyday life until they are indistinguishable from it.
>
> 가장 심오한 기술은 사라지는 기술이다. 그런 기술은 일상생활 속에 스며들어 생활과 구별할 수 없게 된다.

와이저는 이 비전을 두 가지 표현으로 설명했다.

- **보이지 않는 컴퓨터(invisible computer)**: 센서, 디스플레이, 프로세서를 벽, 가구, 옷 같은 사물 속에 내장하고 네트워크로 연결해, 컴퓨터가 눈에 띄는 물건으로 존재하지 않게 한다.
- **조용한 컴퓨터(calm computing)**: 사람이 자기 일에 집중할 수 있도록 컴퓨터가 존재를 드러내지 않고 필요한 순간에만 조용히 돕는다. 알림을 쏟아내 주의를 빼앗는 지금의 스마트폰과는 반대 방향이다.

유비쿼터스 컴퓨팅은 일상의 사물에 프로세서와 통신 기능을 넣어, ==사람이 컴퓨터를 의식하지 않고도 언제 어디서나 컴퓨팅 서비스를 이용하게 하는 개념이다==. 사용자가 컴퓨터 앞에 앉아 명령을 입력하는 대신, 사물에 내장된 컴퓨터가 상황을 감지해 필요한 일을 처리한다. 예를 들어 사람이 방에 들어오면 조명이 저절로 켜지고 실내 온도가 그 사람이 선호하는 값으로 조절된다.

이런 시스템이 갖추어야 할 특징은 다음 네 가지로 요약된다.

1. 네트워크에 항상 연결되어 있다.
2. 인터페이스가 사용자에게 드러나지 않는다.
3. 현실 공간 어디에서나 쓸 수 있다.
4. 사용자의 상황(위치, 시간, 활동)에 따라 제공하는 서비스가 바뀐다. 이를 상황 인지(context awareness)라고 한다.

### RFID

RFID(radio frequency identification)는 ==전파를 이용해 태그에 저장된 식별 정보를 접촉 없이 읽는 기술이다==. 태그(tag), 리더(reader), 그리고 리더가 읽은 정보를 처리하는 서버로 구성된다.

![RFID 동작 순서: 리더가 태그에 질의 전파를 보내면 태그가 칩의 정보로 응답하고, 리더가 이를 네트워크로 서버에 보내 관리자 화면에 표시](./images/csintro-mobile-future-computing-rfid.svg 'RFID 태그는 리더의 전파를 받아 응답한다')

![RFID 태그, 안테나, RFID 리더, 서버로 이어지는 구성도. ① 리더가 RF 신호를 보내고 ② 태그가 정보를 보내며 ③ 리더가 서버로 전송하고 ④ 서버가 관리자에게 제공한다](./images/csintro-mobile-future-computing-rfid-flow.jpg 'RFID 시스템의 동작 원리. 출처: 『컴퓨터 사이언스』, 한빛아카데미')

1. 리더가 안테나로 질의 신호를 담은 전파를 보낸다.
2. 태그가 그 전파를 받아 칩에 저장된 정보를 실어 응답한다. 전지가 없는 수동형(passive) 태그는 ==리더가 보낸 전파에서 동작에 필요한 전력을 얻는다==.
3. 리더는 받은 신호를 복조해 디지털 데이터로 바꾸고 네트워크로 서버에 보낸다.
4. 서버는 태그 번호로 데이터베이스를 조회해 상품 정보를 관리자 화면에 보여 준다.

| 항목         | 바코드                               | RFID                                                                         |
| ------------ | ------------------------------------ | ---------------------------------------------------------------------------- |
| 읽는 방식    | 빛(레이저, 카메라)으로 스캔          | 전파로 송수신                                                                |
| 시야(가시선) | 필요                                 | 불필요. 상자 안의 태그도 읽음                                                |
| 동시 인식    | 한 번에 하나                         | 여러 태그를 한 번에                                                          |
| 데이터 변경  | 불가(인쇄)                           | 쓰기 가능한 태그는 갱신 가능                                                 |
| 저장 용량    | 상품 번호 수준(EAN-13은 13자리 숫자) | 수백 비트에서 수 킬로바이트. 생산 일자, 유통 기한, 입출고 이력까지 기록 가능 |
| 인식 거리    | 수십 센티미터 이내                   | 수동형 수 센티미터~약 10미터, 전지를 단 능동형은 100미터 이상                |
| 단가         | 매우 낮음                            | 바코드보다 높음                                                              |

RFID는 쓰는 주파수에 따라 성격이 크게 달라진다.

| 대역          | 주파수        | 인식 거리(수동형) | 특징과 용도                                   |
| ------------- | ------------- | ----------------- | --------------------------------------------- |
| 저주파(LF)    | 125~134 kHz   | 10cm 이하         | 물과 몸을 잘 통과. 동물 등록 칩, 자동차 키    |
| 고주파(HF)    | 13.56 MHz     | 10cm 이하         | 교통카드, 사원증, 전자여권, NFC 결제          |
| 극초단파(UHF) | 860~960 MHz   | 수 미터~10m       | 물류 상자·의류 재고 관리, 여러 태그 동시 인식 |
| 마이크로파    | 2.45 GHz 이상 | 수 미터           | 능동형 태그와 함께 고속도로 통행료 징수 등    |

교통카드, 사원증 출입 통제, 고속도로 하이패스, 전자여권, 반려동물 등록용 내장 칩, 마라톤 기록 측정용 칩이 모두 RFID 또는 그 일종인 NFC(near field communication)를 쓴다. 다만 태그는 소유자가 모르는 사이에 근처의 리더에 응답할 수 있으므로, 전자여권처럼 개인 정보를 담은 태그는 암호화와 접근 통제(예: 여권 정보면을 광학적으로 읽어야 얻는 키로 통신을 여는 BAC 방식)를 함께 적용한다.

### 유비쿼터스 센서 네트워크

![센서 필드 안의 여러 센서 노드가 서로 데이터를 전달해 싱크 노드로 모으고, 싱크 노드가 USN 게이트웨이를 거쳐 인터넷 너머의 미들웨어와 응용 서비스로 보낸다](./images/csintro-mobile-future-computing-usn.svg '센서 노드는 멀리 있는 싱크 노드까지 이웃 노드를 거쳐 데이터를 전달한다')

유비쿼터스 센서 네트워크(USN)는 온도, 습도, 진동, 빛 같은 물리량을 측정하는 수많은 센서 노드를 무선으로 연결해 주변 상황을 자동으로 수집하는 네트워크다. 구성 요소는 다음과 같다.

- **센서 노드**: 센서, 저전력 프로세서, 무선 통신 모듈, 전지로 이루어진 작은 장치
- **싱크 노드**: 여러 센서 노드가 보낸 데이터를 모으는 집결 지점
- **USN 게이트웨이(라우터)**: 센서 네트워크와 인터넷 같은 외부 네트워크를 연결
- **USN 미들웨어**: 수집된 원시 데이터를 걸러 의미 있는 정보로 가공해 응용 서비스에 전달

예를 들어 산불 감시 시스템은 숲 곳곳에 온도·연기 센서를 설치하고, 이상 값이 측정되면 미들웨어가 위치와 함께 관제 센터에 경보를 보낸다.

센서 노드는 전지 하나로 몇 년을 버텨야 하므로, 통신 거리를 짧게 하고 대부분의 시간 동안 잠들어 있다가 주기적으로 깨어나 측정값을 보낸다. 멀리 있는 싱크 노드까지 직접 전파를 보내면 전력 소모가 크므로 이웃 노드를 징검다리 삼아 여러 번 건너 전달하는데, 이를 다중 홉(multi-hop) 전송이라고 한다. 보안 측면에서는 노드가 야외에 노출되어 있어 공격자가 노드를 가져가 저장된 암호 키를 빼내거나 가짜 측정값을 보내는 노드를 끼워 넣을 수 있다는 점이 문제다.

### 증강 현실

증강 현실(AR, augmented reality)은 카메라로 비친 현실 세계의 영상 위에 컴퓨터가 만든 가상의 정보를 겹쳐 보여 주는 기술이다. ==화면 전체를 가상 세계로 채우는 가상 현실(VR)과 달리 현실을 기반으로 한다==. 스마트폰 카메라를 거리에 비추면 상점 이름과 평점이 겹쳐 보이는 지도 앱, 가구를 방에 미리 배치해 보는 쇼핑 앱이 예다. 스마트폰은 카메라, GPS, 가속도 센서, 자이로스코프를 모두 갖추고 있어 모바일 AR에 적합하다.

증강 현실이 가상 정보를 붙일 위치를 정하는 방법은 크게 세 가지다.

| 방식                | 원리                                                                        | 예                                                |
| ------------------- | --------------------------------------------------------------------------- | ------------------------------------------------- |
| 마커 기반           | 카메라가 인쇄된 표식(QR 코드 비슷한 무늬)을 인식해 그 위에 3D 모델을 띄운다 | 그림책 페이지를 비추면 입체 캐릭터가 나오는 AR 북 |
| 위치 기반           | GPS와 나침반으로 현재 위치와 바라보는 방향을 계산                           | 2016년 포켓몬 GO, 길 안내 화살표                  |
| 마커 없는 공간 인식 | 카메라 영상에서 바닥·벽의 특징점을 찾아 공간 형태를 추정                    | 가구 배치 앱(ARKit, ARCore)                       |

### 생체 인식

생체 인식(biometrics)은 사람의 신체적 특징이나 행동적 특징으로 신원을 확인하는 기술이다. 비밀번호처럼 잊어버리거나 카드처럼 잃어버릴 일이 없다는 장점이 있지만, ==한번 유출되면 바꿀 수 없다는 단점이 있다==. 인증 방식으로서의 생체 인식은 [시스템 보안: 계정·접근 제어·권한·로그·취약점 관리와 버퍼 오버플로](/memo/csintro-system-security)에서 다시 다룬다.

| 구분   | 방식       | 원리                                                    | 특징                                     |
| ------ | ---------- | ------------------------------------------------------- | ---------------------------------------- |
| 신체적 | 지문       | 융선의 끝점·분기점 같은 특징점(minutiae) 비교           | 센서가 저렴하고 빠름. 가장 널리 쓰임     |
| 신체적 | 홍채       | 동공과 흰자위 사이 홍채의 무늬                          | 정확도가 매우 높음. 출입 통제, ATM       |
| 신체적 | 망막       | 안구 뒤쪽 망막의 혈관 배치                              | 정확하지만 측정 장비가 크고 불편         |
| 신체적 | 정맥       | 손바닥·손가락 정맥 패턴을 근적외선으로 촬영             | 피부 안쪽이라 위조가 어려움. 장비가 비쌈 |
| 신체적 | 손 모양    | 손가락 길이, 손 폭 같은 기하 정보                       | 처리가 빠르지만 구별력이 낮음            |
| 신체적 | 얼굴       | 2D 영상 또는 적외선 깊이 정보로 얼굴 형상 비교          | 비접촉. 사진·마스크 위조 대책 필요       |
| 행동적 | 음성(성문) | 목소리의 주파수 특성 분석                               | 녹음·음성 합성으로 위조 가능             |
| 행동적 | 서명       | 오프라인: 완성된 서명 모양. 온라인: 쓰는 속도·압력·순서 | 온라인 방식이 위조에 강함                |

각 방식의 장단점을 정리하면 다음과 같다.

| 정보    | 장점                            | 단점                                                   |
| ------- | ------------------------------- | ------------------------------------------------------ |
| 홍채    | 위조가 어렵고 정확도가 높다     | 등록·비교를 위해 대용량 홍채 정보를 저장해야 한다      |
| 망막    | 안전성이 우수하다               | 눈에 빛을 비추는 측정 방식이라 사용할 때 거부감이 있다 |
| 손 모양 | 간편하고 실시간 처리가 가능하다 | 정확도가 떨어진다                                      |
| 정맥    | 위조가 어렵다                   | 특징 추출이 어렵고 장비가 비싸다                       |
| 지문    | 장비 비용이 낮다                | 지문이 닳거나 다친 사람에게는 쓸 수 없다               |
| 얼굴    | 인식이 빠르고 접촉이 없다       | 조명과 자세에 따라 정확도가 떨어진다                   |
| 음성    | 비용이 낮고 멀리서도 인식된다   | 감기 같은 몸 상태의 영향을 받고, 처리 지연이 있다      |
| 서명    | 비용이 낮다                     | 컨디션에 따라 서명이 달라져 잘못 인식될 확률이 높다    |

생체 인식 시스템은 대부분 같은 단계를 거친다. 홍채 인식을 예로 들면 다음과 같다.

![얼굴 사진에서 눈 영상을 얻는 이미지 획득 단계, 동공과 흰자위 사이의 홍채만 잘라 내는 홍채 추출 단계, 홍채 DB에 저장된 패턴과 비교하는 패턴 비교 단계를 거쳐 신원을 결정한다](./images/csintro-mobile-future-computing-iris.jpg '홍채 인식 과정. 출처: 『컴퓨터 사이언스』, 한빛아카데미')

1. **획득**: 근적외선 카메라로 눈을 촬영한다. 근적외선은 홍채 색이 짙어도 무늬를 선명하게 비춘다.
2. **추출**: 영상에서 동공 경계와 홍채 바깥 경계를 찾아 도넛 모양의 홍채 영역만 잘라 내고, 직사각형으로 펼쳐 정규화한다.
3. **부호화**: 무늬를 필터로 분석해 2,048비트 같은 고정 길이의 홍채 코드로 바꾼다. ==원본 사진이 아니라 이 코드를 저장한다==.
4. **비교**: 새로 얻은 코드와 저장된 코드에서 서로 다른 비트의 비율(해밍 거리)을 계산해, 문턱값(예: 0.32)보다 작으면 같은 사람으로 판정한다.

예를 들어 2,048비트 중 410비트가 다르면 해밍 거리는 `410 / 2048 \approx 0.20{:math}`이므로 본인으로 판정하고, 1,000비트가 다르면 `\approx 0.49{:math}`로 다른 사람이다. 서로 무관한 두 홍채는 무작위 비트열처럼 절반 정도가 다르기 때문에 0.5 근처의 값이 나온다.

생체 인식의 정확도는 다른 사람을 본인으로 잘못 받아들이는 비율(FAR, false acceptance rate)과 본인을 잘못 거부하는 비율(FRR, false rejection rate)로 측정한다. ==판정 기준을 엄격하게 하면 FAR은 줄지만 FRR이 늘어나므로==, 용도에 맞게 균형점을 정한다.

![판정 문턱값을 느슨한 쪽에서 엄격한 쪽으로 옮기면 FAR 곡선은 높은 값에서 0으로 내려가고 FRR 곡선은 0에서 올라가며, 두 곡선이 만나는 점이 EER이다](./images/csintro-mobile-future-computing-far-frr.svg 'EER이 낮을수록 정확한 시스템이다')

두 곡선이 만나는 점의 오류율을 동일 오류율(EER, equal error rate)이라고 하며, 서로 다른 생체 인식 시스템의 정확도를 비교하는 기준으로 쓴다. 은행 금고 출입처럼 남이 들어오면 안 되는 곳은 FAR을 낮추는 쪽(엄격)으로, 스마트폰 잠금 해제처럼 본인이 자주 거부당하면 불편한 곳은 그보다 느슨한 쪽으로 문턱값을 정한다. Apple은 Touch ID의 FAR을 1/50,000, Face ID를 1/1,000,000으로 공개했다. 6자리 숫자 비밀번호를 무작위로 맞힐 확률 1/1,000,000과 같은 수준이다.

### 유비쿼터스 컴퓨팅의 응용

- **홈 네트워크**: 집 안의 가전, 조명, 도어록, 보일러를 네트워크로 연결해 밖에서 스마트폰으로 상태를 확인하고 제어한다.
- **원격 헬스케어(U-헬스케어)**: 유무선 통신 인프라를 기반으로, 혈압계, 혈당계, 웨어러블 기기가 측정한 생체 신호를 의료진에게 전송해, 만성 질환자나 노인이 병원에 가지 않고도 건강 상태를 관리받는다.

![가정의 센서가 혈당, 혈압, 심전도, 콜레스테롤, 체중을 감지하는 생체 정보 감지 기술, 무선·유선 네트워크와 서버로 이루어진 생체 정보 인터페이스 기술, 병원·연구소·제약회사가 데이터를 쓰는 생체 정보 처리 기술의 세 영역](./images/csintro-mobile-future-computing-uhealth.jpg 'U-헬스케어를 이루는 세 가지 기술. 출처: 『컴퓨터 사이언스』, 한빛아카데미')

감지 기술은 몸에 붙이거나 집에 두는 측정 기기, 인터페이스 기술은 측정값을 병원 서버로 안전하게 보내는 통신, 처리 기술은 의료진의 진단과 연구에 쓰는 분석이다. 건강 정보는 개인정보 보호법상 민감 정보이므로 전송 구간 암호화와 접근 통제가 필수다.

- **스마트 시티(U-시티)**: 도시 전역에 센서와 통신망을 깔아 교통 신호 제어, 방범 CCTV, 대중교통 도착 안내, 상하수도 관리 같은 공공 서비스를 통합 운영한다. 제공하는 서비스는 도시의 목표에 따라 다음과 같이 나뉜다.

| 분류        | 서비스 예                                                  |
| ----------- | ---------------------------------------------------------- |
| 편리한 도시 | 교통 정보·신호 제어, 물류, 전자 행정, 원격 교육, 원격 근무 |
| 건강한 도시 | 보건·복지, 응급 구조, 건강 관리                            |
| 안전한 도시 | 방범·화재 감시, 다리·터널 같은 공공 시설물 관리            |
| 쾌적한 도시 | 대기·토양·수질 오염 감시, 주거 단지 관리                   |

## 사물인터넷

### 등장 배경과 개념

사물인터넷(IoT, Internet of Things)은 사물에 센서와 통신 기능을 내장해 인터넷에 연결하고, 사물이 수집한 데이터를 바탕으로 서비스를 제공하는 기술이다. 같은 종류의 기기끼리 통신하는 사물지능통신(M2M, machine to machine)에서 출발해, 서로 다른 기기와 사람, 클라우드 서비스가 인터넷 프로토콜(IP)로 직접 연결되는 형태로 확장되었다. ==유비쿼터스 컴퓨팅이 제시한 비전을 인터넷 표준 기술로 구현한 것==이라고 볼 수 있다.

### 구조

![사물인터넷의 네 단계 구조: 스마트 팜의 온도 센서가 값을 측정하고, 무선 통신으로 전달하고, 클라우드에서 임계값과 비교하고, 환기창 개방과 알림 서비스를 제공](./images/csintro-mobile-future-computing-iot.svg '센서 값이 네트워크와 클라우드를 거쳐 서비스와 제어 명령이 된다')

| 단계          | 하는 일                                                         | 관련 핵심 기술                                          |
| ------------- | --------------------------------------------------------------- | ------------------------------------------------------- |
| 데이터 생성   | 센서가 온도·습도·가속도 같은 물리량을 측정해 디지털 값으로 변환 | 센싱 기술                                               |
| 네트워크 연결 | 측정값을 무선 또는 유선 네트워크로 전달                         | 네트워킹 기술(Wi-Fi, Bluetooth LE, Zigbee, LTE-M, LoRa) |
| 데이터 처리   | 수집·저장·분석·가공                                             | 인터페이스 기술(API, MQTT 같은 메시지 프로토콜)         |
| 서비스 제공   | 분석 결과를 사람이나 다른 기기가 쓸 수 있는 형태로 제공         | 디바이스 기술(소형 저전력 하드웨어, 구동기)             |

네 가지 핵심 기술을 조금 더 풀면 다음과 같다.

- **센싱 기술**: 가속도, 중력, 온도, 습도, 열, 가스, 조도, 초음파 같은 현상을 감지하는 센서. 여러 센서 값을 조합해 "사람이 넘어졌다"처럼 더 높은 수준의 정보를 만드는 가상 센서도 포함한다.
- **네트워킹 기술**: 사람, 사물, 서비스 같은 분산된 자원을 연결하는 유무선 네트워크. 전력을 아껴야 하는 기기는 Bluetooth LE나 Zigbee처럼 속도는 느려도 전력을 적게 쓰는 방식을, 멀리 떨어진 기기는 LoRa나 LTE-M 같은 저전력 광역 통신을 쓴다.
- **인터페이스 기술**: 센싱 정보를 응용 서비스와 연동하는 기술. 작은 기기에 맞게 만든 메시지 프로토콜 MQTT는 기기가 "온도/온실1" 같은 주제(topic)로 값을 올리면, 그 주제를 구독한 서비스가 받아 가는 방식으로 동작한다.
- **디바이스 기술**: 작은 크기와 낮은 전력으로 동작하는 프로세서, 모터·밸브 같은 구동기(actuator).

> [!WARNING] 사물인터넷의 보안 문제
> IoT 기기는 값이 싸고 성능이 낮아 보안 기능이 빈약한 경우가 많다. 2016년의 Mirai 봇넷은 ==공장 출하 시의 기본 아이디·비밀번호를 그대로 쓰는== IP 카메라와 공유기 수십만 대를 감염시켜 대규모 분산 서비스 거부(DDoS) 공격에 동원했다. 기본 비밀번호 변경, 펌웨어 업데이트, 불필요한 원격 접속 포트 차단이 기본 대책이다. 봇과 웜의 동작은 [악성코드의 분류와 감염 경로, 탐지와 대응](/memo/csintro-malware)에서 다룬다.

## 클라우드 컴퓨팅

### 정의

![위에는 PC, 노트북, 스마트폰, 태블릿, 자동차, 게임기 같은 클라이언트 디바이스, 가운데는 웹 검색, 오피스, 전자상거래, SNS, 데이터 마이닝 같은 클라우드 서비스, 아래는 여러 지역 클라우드가 연결된 클라우드 플랫폼이 있다](./images/csintro-mobile-future-computing-cloud-concept.jpg '어떤 기기로든, 언제 어디서나 같은 서비스에 접근한다. 출처: 『컴퓨터 사이언스』, 한빛아카데미')

클라우드 컴퓨팅은 서버, 스토리지, 네트워크, 소프트웨어 같은 컴퓨팅 자원을 직접 구매해 보유하는 대신, ==인터넷을 통해 필요한 만큼 빌려 쓰는 방식이다==. 미국 국립표준기술연구소(NIST)는 SP 800-145에서 다음과 같이 정의한다.

> 설정 가능한 컴퓨팅 자원(네트워크, 서버, 스토리지, 응용 프로그램, 서비스)의 공유 풀에 언제 어디서나 편리하게 필요에 따라 네트워크로 접근할 수 있게 하는 모델로, 최소한의 관리 노력이나 서비스 제공자와의 상호 작용만으로 자원을 신속하게 할당하고 반납할 수 있다.

같은 문서는 클라우드가 갖추어야 할 다섯 가지 특성을 제시한다.

1. **주문형 셀프서비스**: 사용자가 사업자 직원을 거치지 않고 웹 콘솔에서 직접 서버를 만든다.
2. **광대역 네트워크 접근**: PC, 스마트폰 등 다양한 단말에서 네트워크로 접근한다.
3. **자원 풀링**: 여러 사용자가 같은 물리 서버를 가상화로 나누어 쓴다.
4. **신속한 탄력성**: 접속자가 몰리면 서버를 늘리고, 줄면 다시 줄인다.
5. **측정되는 서비스**: 사용한 CPU 시간, 저장 용량, 전송량을 측정해 그만큼 요금을 매긴다.

예를 들어 온라인 쇼핑몰이 연말 할인 행사 기간에만 접속자가 열 배로 늘어난다면, 자체 서버로는 최대 부하에 맞춘 장비를 1년 내내 보유해야 한다. 클라우드에서는 행사 기간에만 서버를 늘렸다가 끝나면 반납하고, 쓴 시간만큼만 비용을 낸다.

숫자로 계산해 보자. 평소에는 서버 2대면 충분하고 연말 2주(336시간) 동안만 20대가 필요하며, 클라우드 서버 1대의 요금이 시간당 100원이라고 가정한다. 1년은 8,760시간이다.

```math
\begin{aligned}
\text{자체 보유(20대 상시)} &= 20 \times 8760 \times 100 = 17{,}520{,}000\text{원} \\
\text{클라우드} &= 2 \times 8760 \times 100 + 18 \times 336 \times 100 = 1{,}752{,}000 + 604{,}800 = 2{,}356{,}800\text{원}
\end{aligned}
```

같은 요금으로 비교해도 사용량이 들쭉날쭉한 서비스는 클라우드 비용이 7분의 1 수준이다. 반대로 1년 내내 20대를 꽉 채워 쓰는 서비스라면 장기 약정 할인이 없는 클라우드가 더 비쌀 수 있다.

==이 탄력성을 가능하게 하는 기술이 가상화(virtualization)다==. 하이퍼바이저(hypervisor)라는 소프트웨어가 물리 서버 한 대의 CPU, 메모리, 디스크를 나누어 여러 개의 가상 머신(VM)을 만들고, 각 가상 머신은 자기만의 운영체제를 가진 독립된 컴퓨터처럼 동작한다. 사용자가 콘솔에서 "서버 만들기"를 누르면 실제로는 데이터 센터의 어느 물리 서버 위에 가상 머신 하나가 몇십 초 만에 만들어진다. 같은 물리 서버를 다른 회사와 나누어 쓰므로, 가상 머신 사이의 격리가 깨지는 취약점은 클라우드에서 가장 심각한 문제로 다루어진다.

### 서비스 모델과 배치 모델

서비스 모델은 사업자가 어느 계층까지 관리해 주는지에 따라 나뉜다.

![온프레미스, IaaS, PaaS, SaaS에서 응용 프로그램부터 스토리지·네트워크까지 각 계층을 사용자와 클라우드 사업자 중 누가 관리하는지 비교](./images/csintro-mobile-future-computing-cloud.svg '오른쪽으로 갈수록 사업자가 관리하는 계층이 늘어난다')

| 모델                              | 사업자가 제공하는 것           | 사용자가 관리하는 것  | 예                                |
| --------------------------------- | ------------------------------ | --------------------- | --------------------------------- |
| IaaS(Infrastructure as a Service) | 가상 서버, 스토리지, 네트워크  | 운영체제부터 응용까지 | Amazon EC2, Google Compute Engine |
| PaaS(Platform as a Service)       | 운영체제, 런타임, 미들웨어까지 | 응용 코드와 데이터    | Heroku, Google App Engine         |
| SaaS(Software as a Service)       | 완성된 응용 프로그램           | 계정과 입력한 데이터  | Gmail, Microsoft 365              |

배치 모델은 누가 그 인프라를 쓰는지에 따라 퍼블릭(불특정 다수에게 공개), 프라이빗(한 조직 전용), 커뮤니티(이해관계가 같은 여러 조직이 공유), 하이브리드(둘 이상을 조합)로 나뉜다.

> [!NOTE] 공동 책임 모델
> 클라우드로 옮겨도 ==보안 책임이 모두 사업자에게 넘어가지 않는다==. 사업자는 데이터 센터와 하드웨어, 가상화 계층을 보호하고, 사용자는 자신이 관리하는 계층(IaaS라면 운영체제 패치, 방화벽 규칙, 계정 권한)을 보호한다. 저장소 버킷을 공개로 잘못 설정해 데이터가 유출되는 사고는 대부분 사용자 쪽 책임 영역에서 일어난다.

## 빅데이터

### 등장 배경

![1970년 메인프레임, 1990년 PC, 2000년 인터넷·모바일, 2010년대 빅데이터 시대, 2020년 이후 인공지능·사물인터넷으로 이어지며 디지털 정보량이 급증하는 그래프와, 데이터 규모가 엑사바이트에서 제타바이트로, 유형이 정형에서 비정형·사물 정보로, 특성이 구조화에서 다양성·실시간성으로 바뀌는 표](./images/csintro-mobile-future-computing-data-growth.jpg '전 세계 디지털 정보량 증가 추이. 출처: 『컴퓨터 사이언스』, 한빛아카데미')

컴퓨터의 중심이 메인프레임에서 PC, 인터넷과 모바일로 옮겨 갈 때마다 데이터를 만드는 주체가 늘었다. 메인프레임 시대에는 기업의 전산실만 데이터를 만들었지만, 스마트폰과 SNS 시대에는 모든 사람이, 사물인터넷 시대에는 모든 사물이 데이터를 만든다. 데이터의 단위로 보면 다음과 같다.

| 단위           | 크기                    | 감각적 예                                                    |
| -------------- | ----------------------- | ------------------------------------------------------------ |
| 기가바이트(GB) | `10^{9}{:math}` 바이트  | 고화질 영화 한 편                                            |
| 테라바이트(TB) | `10^{12}{:math}` 바이트 | 일반 PC 하드디스크 하나                                      |
| 페타바이트(PB) | `10^{15}{:math}` 바이트 | 대형 인터넷 기업이 하루에 처리하는 로그                      |
| 엑사바이트(EB) | `10^{18}{:math}` 바이트 | 1990년대 말 전 세계 디지털 정보 총량 수준                    |
| 제타바이트(ZB) | `10^{21}{:math}` 바이트 | 2011년 전 세계 정보량 약 1.8ZB, 2020년대에는 연간 100ZB 이상 |

### 개념

빅데이터는 기존 데이터베이스 관리 도구로 수집·저장·분석하기 어려울 만큼 큰 규모의 데이터와, 그 데이터에서 가치를 추출하는 기술을 함께 가리킨다. 스마트폰, SNS, IoT 센서가 쉬지 않고 데이터를 생성하면서 등장한 개념이다.

| 구분        | 기존 데이터                                    | 빅데이터                                                         |
| ----------- | ---------------------------------------------- | ---------------------------------------------------------------- |
| 데이터 양   | 테라바이트 수준                                | 테라바이트~제타바이트 수준                                       |
| 데이터 유형 | 정형 데이터(표 형태) 위주                      | 정형과 비정형 모두. 텍스트·이미지·로그 같은 비정형의 비중이 높음 |
| 처리 과정   | 단순. 원인과 결과의 인과 관계를 밝히는 데 중점 | 복잡해 분산 처리가 필요. ==변수 사이의 상관관계를 찾는 데 중점== |

흔히 세 가지 V로 특징을 설명한다.

- **규모(Volume)**: 테라바이트(TB)를 넘어 페타바이트(PB) 단위의 데이터
- **속도(Velocity)**: 센서나 클릭 로그처럼 실시간으로 쏟아지는 데이터
- **다양성(Variety)**: 표 형태의 정형 데이터뿐 아니라 텍스트, 이미지, 동영상 같은 비정형 데이터

### 처리 과정과 분석 기술

처리 과정은 다음 순서로 진행된다.

| 단계 | 내용                                         | 대표 기술                            |
| ---- | -------------------------------------------- | ------------------------------------ |
| 생성 | 사람과 기기가 데이터를 만든다                | 웹 서버 로그, 결제 기록, 센서        |
| 수집 | 로그, 센서, 웹 크롤링으로 원시 데이터를 수집 | Apache Kafka, Flume                  |
| 저장 | 여러 서버에 나누어 저장                      | HDFS(Hadoop 분산 파일 시스템), NoSQL |
| 처리 | 여러 서버에서 병렬로 계산                    | MapReduce, Apache Spark              |
| 분석 | 통계, 텍스트 마이닝, 기계 학습으로 패턴 추출 | SQL 엔진, 기계 학습 라이브러리       |
| 표현 | 결과를 차트나 대시보드로 시각화              | BI 도구                              |

분산 처리의 대표적인 방식인 MapReduce를 단어 세기로 살펴보자. 문서 세 개에 나오는 단어 수를 세는 일을 서버 세 대에 나누어 맡긴다.

![세 문서 조각을 Map 단계에서 서버마다 (단어, 1) 쌍으로 바꾸고, 셔플 단계에서 같은 단어끼리 모아 보안 [1,1,1], 클라우드 [1,1,1], 빅데이터 [1]을 만들고, Reduce 단계에서 합산해 보안 3, 클라우드 3, 빅데이터 1을 얻는다](./images/csintro-mobile-future-computing-mapreduce.svg '문서가 수억 개여도 ==서버만 늘리면 같은 방식으로 처리할 수 있다==')

1. **Map**: 각 서버가 맡은 문서를 읽어 단어마다 `(단어, 1)` 쌍을 만든다. 서버끼리 주고받을 것이 없어 동시에 실행된다.
2. **셔플**: 같은 단어의 쌍을 같은 서버로 모은다.
3. **Reduce**: 각 서버가 모인 값을 더한다.

분석 단계에서는 여러 기술을 함께 쓴다. 텍스트 마이닝은 리뷰나 뉴스 같은 글에서 자주 함께 나오는 단어와 감정을 뽑아내고, 자연어 처리는 문장 구조와 뜻을 해석하며, 기계 학습은 과거 데이터에서 규칙을 학습해 새 데이터를 분류·예측한다. 이 밖에 통계 분석, 웹 페이지를 자동으로 모으는 크롤링, 정보 검색, 의미 관계를 다루는 시맨틱 기술, 결과를 그림으로 보여 주는 시각화가 쓰이고, 이 모든 계산은 주로 클라우드 위에서 실행된다.

예를 들어 지도 앱은 수많은 스마트폰이 보낸 위치·속도 데이터를 실시간으로 집계해 도로별 정체 구간을 계산하고, 이를 경로 안내에 반영한다. 이때 개별 이동 경로는 개인 정보이므로, 집계 전에 ==식별 정보를 제거하는 가명 처리와 익명 처리가 필수다==.

## 정리

| 기술              | 핵심 아이디어                             | 대표 보안 쟁점                         |
| ----------------- | ----------------------------------------- | -------------------------------------- |
| 모바일 플랫폼     | 하드웨어가 달라도 같은 API로 앱 실행      | 악성 앱, 과도한 권한 요구              |
| 유비쿼터스 컴퓨팅 | 사물에 컴퓨터를 내장해 의식하지 않고 사용 | 상황 정보 수집에 따른 사생활 침해      |
| RFID·생체 인식    | 비접촉 식별, 신체 특징으로 인증           | 무단 판독, 바꿀 수 없는 생체 정보 유출 |
| 사물인터넷        | 센서 → 네트워크 → 처리 → 서비스           | 기본 비밀번호, 패치되지 않는 펌웨어    |
| 클라우드          | 자원을 필요한 만큼 빌려 쓰고 쓴 만큼 지불 | 공동 책임 모델, 설정 오류              |
| 빅데이터          | 대량·고속·다양한 데이터를 분산 처리       | 개인 정보 재식별                       |
