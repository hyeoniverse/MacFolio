## 빌드 도구를 CRA에서 Vite로

23일 밤의 커밋 "chore: vite로 변경"은 1,190개 파일을 변경했다. 대부분은 추적하던 `node_modules`가 제거된 것이다(1,478개 → 340개). 앱 코드의 변경은 다음과 같다.

| 항목      | 전 (CRA)                  | 후 (Vite)                             |
| --------- | ------------------------- | ------------------------------------- |
| 빌드      | `react-scripts` 5.0.1     | `vite` 6.2.1 + `@vitejs/plugin-react` |
| 스크립트  | `start`, `build`, `eject` | `dev`, `build`, `preview`             |
| HTML      | `public/index.html`       | 루트의 `index.html`                   |
| 진입 파일 | `src/index.tsx`           | `src/main.tsx`                        |
| 환경 변수 | `process.env.REACT_APP_*` | `import.meta.env.VITE_APP_*` (11개)   |
| 설정 파일 | 없음 (CRA가 숨김)         | 없음 (`vite.config` 없이 기본값)      |

![CRA에서 Vite로 바뀐 자리](./images/day-20250323-cra-vite.svg 'HTML 위치, 진입 파일, 환경 변수 접두사, 스크립트 네 곳이 변경되었다')

환경 변수 11개 중 8개가 Firebase 설정이고, 나머지 셋은 그림·음악·효과음 주소다. 접두사가 바뀌면 배포 환경에 등록한 변수 이름도 함께 변경해야 한다. 이 커밋에서는 코드만 변경했다.

```ts
// 전 (CRA): src/components/common/Dock.tsx
const imgUrl = process.env.REACT_APP_IMAGE_URL;
// 후 (Vite): VITE_ 접두사가 있는 변수만 브라우저 코드에 노출된다
const imgUrl = import.meta.env.VITE_APP_IMAGE_URL;
```

한 곳은 접두사 변경이 빠졌다. `Github.tsx`는 `import.meta.env.REACT_APP_IMAGE_URL`로 바뀌어, `import.meta.env`로 읽는 방식은 바뀌었지만 이름은 `REACT_APP_`로 남았다. Vite는 `VITE_` 접두사가 없는 변수를 브라우저 코드에 노출하지 않으므로 이 값은 `undefined`이고, GitHub 앱의 프로필 사진 주소가 `undefined/me.png`가 된다. 이튿날 Prettier 커밋 뒤에도 그대로였다. 변경 결과를 확인할 시험이 없어서 발견되지 않은 사례다.

같은 커밋에서 컴포넌트와 CSS 대부분도 함께 변경되었다. 변경 줄 수는 창(`Container.tsx`) 572줄, 음악(`MusicPlayer.tsx`) 431줄, `MusicContext` 387줄 등이다.

## Prettier로 코드 형식 정리

24일 아침 10시 8분 커밋은 음악 플레이어·음악 Context·창·Dock CSS 여섯 파일에 Prettier를 적용했다. 972줄을 추가하고 887줄을 삭제했지만, 공백 차이를 제외하면 197줄과 112줄이다. 변경 내용은 대부분 들여쓰기와 줄바꿈이다.

## 돌아보며

이전 작업은 하룻밤 커밋 하나로 끝났다. React 앱은 빌드 도구에 크게 의존하지 않아서, 변경할 곳이 HTML 위치, 진입 파일, 환경 변수 접두사 정도였다. 그러나 변경 결과를 확인할 시험이 없었다. `App.test.tsx` 파일은 남아 있었지만 `package.json`에 `test` 스크립트가 없었다. 1년 반 뒤 작업을 재개했을 때 가장 먼저 한 일이 시험을 추가하는 것이었고, 그 과정에서 [한 번도 동작한 적 없던 기능](/memo/bugs-found-by-tests)이 나왔다.
