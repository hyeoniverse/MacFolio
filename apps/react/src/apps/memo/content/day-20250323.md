## 3월 23일 - 빌드 도구를 CRA에서 Vite로

### 빌드 도구가 하는 일

React 코드는 브라우저가 그대로 실행할 수 없다. JSX(`<Dock />` 같은 태그 문법)와 TypeScript를 JavaScript로 변환하고, 수백 개의 파일과 `node_modules`의 라이브러리를 브라우저가 내려받을 파일로 묶어야 한다. 이 변환·묶음과 개발 중의 자동 새로고침을 맡는 프로그램이 빌드 도구다.

2024년 10월부터 이 저장소는 Create React App(CRA)을 썼다. CRA는 webpack·Babel·ESLint 설정을 `react-scripts` 패키지 안에 숨겨 두고, `npm start` 한 줄로 개발 서버를 띄우게 해 주는 도구다. Vite는 개발 중에는 앱 코드를 미리 묶지 않고, 브라우저가 ES 모듈 `import`로 요청한 파일만 그때 변환해 보내는 방식의 빌드 도구다. 프로덕션 빌드에서는 두 도구 모두 파일을 묶은 번들을 만든다.

![번들 기반 개발 서버와 Vite 개발 서버](./images/day-20250323-dev-server.svg 'CRA는 서버를 띄우기 전에 앱 전체를 묶고, Vite는 의존성만 미리 묶은 뒤 요청받은 파일을 그때 변환한다')

### 바꾼 자리

23일의 커밋 "chore: vite로 변경"은 1,190개 파일을 변경했다. 대부분은 git이 추적하던 `node_modules`를 제거한 것이다(1,478개 → 340개). 앱 코드의 변경은 다음과 같다.

| 항목      | 전 (CRA)                  | 후 (Vite)                             |
| --------- | ------------------------- | ------------------------------------- |
| 빌드      | `react-scripts` 5.0.1     | `vite` 6.2.1 + `@vitejs/plugin-react` |
| 스크립트  | `start`, `build`, `eject` | `dev`, `build`, `preview`             |
| HTML      | `public/index.html`       | 루트의 `index.html`                   |
| 진입 파일 | `src/index.tsx`           | `src/main.tsx`                        |
| 환경 변수 | `process.env.REACT_APP_*` | `import.meta.env.VITE_APP_*` (11개)   |
| 설정 파일 | 없음 (CRA가 숨김)         | 없음 (`vite.config` 없이 기본값)      |

![CRA에서 Vite로 바뀐 자리](./images/day-20250323-cra-vite.svg 'HTML 위치, 진입 파일, 환경 변수 접두사, 스크립트 네 곳을 변경했다')

HTML 위치가 바뀐 이유는 두 도구가 HTML을 다루는 방식이 다르기 때문이다. CRA는 `public/index.html`을 틀로 쓰고 빌드한 스크립트 태그를 그 안에 넣는다. Vite는 루트의 `index.html`을 앱의 진입점으로 읽고, 그 안의 `<script type="module" src="/src/main.tsx">`에서 출발해 import를 따라간다. 스크립트 이름의 `eject`는 CRA가 숨긴 설정을 프로젝트로 꺼내는 명령이고, Vite에는 숨긴 설정이 없어 해당 명령이 없다. 대신 빌드 결과를 로컬에서 띄워 보는 `preview`가 있다.

### 환경 변수 접두사

환경 변수는 코드 밖에서 주입하는 설정 값이다. 같은 코드를 개발용과 배포용으로 빌드할 때 그림 주소나 Firebase 프로젝트 키처럼 환경마다 다른 값을 넣는 데 쓴다. 환경 변수 11개 중 8개가 Firebase 설정이고, 나머지 셋은 그림·음악·효과음 주소다.

두 도구 모두 빌드 시각에 환경 변수를 코드 안의 문자열로 치환한다. 이때 서버 비밀번호 같은 값이 브라우저 코드에 들어가지 않도록, 정해진 접두사가 붙은 변수만 치환한다. CRA는 `REACT_APP_`, Vite는 `VITE_`가 그 접두사다. `VITE_APP_IMAGE_URL`은 `VITE_`로 시작하므로 Vite가 치환한다.

```ts
// 전 (CRA): src/components/common/Dock.tsx
const imgUrl = process.env.REACT_APP_IMAGE_URL;
// 후 (Vite): VITE_ 접두사가 있는 변수만 브라우저 코드에 노출된다
const imgUrl = import.meta.env.VITE_APP_IMAGE_URL;
```

접두사가 바뀌면 배포 환경에 등록한 변수 이름도 함께 변경해야 한다. 이 커밋에서는 코드만 변경했다.

![Vite가 VITE_ 접두사 변수만 치환하는 과정](./images/day-20250323-env-prefix.svg '이름이 VITE_로 시작하지 않는 변수는 import.meta.env에 들어가지 않아 undefined가 된다')

> [!WARNING] 접두사 변경이 빠진 변수
> 한 곳은 접두사 변경이 빠졌다. `Github.tsx`는 `import.meta.env.REACT_APP_IMAGE_URL`로 바뀌어, 읽는 방식(`import.meta.env`)은 바뀌었지만 이름은 `REACT_APP_`로 남았다. Vite는 `VITE_` 접두사가 없는 변수를 브라우저 코드에 노출하지 않으므로 이 값은 `undefined`이고, GitHub 앱의 프로필 사진 주소가 `undefined/me.png`가 된다. 이튿날 Prettier 커밋 뒤에도 그대로였다. ==빌드는 오류 없이 끝나고 화면에서만 사진이 깨지는 종류의 문제==라, 변경 결과를 확인할 시험이 없으면 드러나지 않는다.

같은 커밋에서 창(`Container.tsx`), 음악(`MusicPlayer.tsx`, `MusicContext`) 등 컴포넌트와 CSS 대부분도 함께 변경했다.

## 3월 24일 - Prettier로 코드 형식 정리

Prettier는 코드를 읽어 정해진 규칙(들여쓰기, 줄 길이, 따옴표 등)대로 다시 출력하는 코드 포매터다. 사람마다 다른 형식을 하나로 맞춰, 리뷰에서 형식 차이 대신 내용 차이만 보이게 하는 데 쓴다. 이날 커밋(`13e58b843`)의 `MusicPlayer.tsx` 일부를 보면, 탭 들여쓰기가 공백 두 칸으로, 작은따옴표가 큰따옴표로 바뀌고, 줄 길이 제한(기본 80자)을 넘는 객체는 속성마다 한 줄로 나뉘었다.

```diff
-	const [position, setPosition] = useState({ x: window.innerWidth - 450, y: 80 });
+  const [position, setPosition] = useState({
+    x: window.innerWidth - 450,
+    y: 80,
+  });
-		bringAppToFront('music');
+    bringAppToFront("music");
```

24일에는 음악 플레이어·음악 Context·창·Dock CSS 등 여섯 파일에 Prettier를 적용했다. `git diff`로는 972줄 추가, 887줄 삭제였지만, 공백 차이를 무시하는 `git diff -w`로 다시 집계하면 197줄 추가, 112줄 삭제다. 위 예시에서 `bringAppToFront` 줄은 따옴표가 바뀌어 `-w`에서도 변경으로 집계되고, 들여쓰기만 바뀐 줄은 집계에서 빠진다.

| 집계 방법     | 추가 | 삭제 |
| ------------- | ---: | ---: |
| `git diff`    |  972 |  887 |
| `git diff -w` |  197 |  112 |

==추가한 줄의 약 80%는 공백만 바뀐 줄==이다.

## 돌아보며

1. Vite 이전은 커밋 하나로 끝났다.
   - 앱 코드가 빌드 도구에 거의 의존하지 않아, 바꿀 곳은 HTML 위치, 진입 파일, 환경 변수 접두사 정도였다.
2. 결과를 확인할 시험은 없었다.
   - `App.test.tsx`는 남아 있었지만 `package.json`에 `test` 스크립트가 없었다.
   - 1년 반 뒤 작업을 재개하며 가장 먼저 시험을 추가했고, 그 과정에서 [한 번도 동작한 적 없던 기능](/memo/bugs-found-by-tests)이 나왔다.
