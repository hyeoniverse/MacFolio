메모 앱에서 글을 읽다가 한 문장만 모양이 이상한 걸 봤다.

```text
이번엔 실패가 아니라 **취소(cancelled)**가 떴다.
```

다른 곳의 `**굵게**`는 잘 되는데, 이 문장만 별표가 글자 그대로 보였다. 오타도 아니고 별표 개수도 맞았다.

## 규칙대로라면 굵게가 아니다

CommonMark는 `**`가 강조를 **여는지·닫는지**를 앞뒤 글자로 정한다. 닫는 `**`가 되려면 "오른쪽에 붙은(right-flanking)" 구분자여야 하는데, 조건은 이렇다.

- 바로 앞이 공백이 아니고,
- 바로 앞이 문장부호라면, 바로 뒤는 **공백이나 문장부호**여야 한다

`**취소(cancelled)**가`에서 닫는 `**`의 앞은 `)`(문장부호), 뒤는 `가`(글자)다. 두 번째 조건에 걸려 닫는 구분자가 되지 못하고, 짝을 못 찾은 `**`는 글자로 남는다.

영어라면 `**done (really)** now`처럼 닫는 별표 뒤에 공백이 오니 문제가 없다. 한국어는 조사를 바로 붙여 쓰니 **괄호·따옴표·코드로 끝나는 굵게** 뒤에서 자주 깨진다.

```markdown
**`dragover`**를 ← 코드로 끝남
*“기울임”*은 ← 따옴표로 끝남
```

저장소의 글을 모두 Markdown 트리로 읽어서, 강조가 되지 못하고 글자로 남은 `*`를 찾아봤다. 저장소 글에는 이 한 곳뿐이었다. 하지만 편집기로 쓴 글은 서버에 있어 이렇게 세어 볼 수 없고, 앞으로 쓸 글도 똑같이 깨질 수 있다. 글을 고쳐 피하는 대신 **읽는 규칙을 고치기로 했다.**

## 읽기 화면: remark 플러그인 하나

[remark-cjk-friendly](https://github.com/tats-u/markdown-cjk-friendly)는 한중일 글자 옆에서는 위 조건을 풀어 주는 플러그인이다. 영어 글에서는 CommonMark와 똑같이 동작한다. 글을 그리는 곳이 세 군데(읽기 화면, 편집 중 미리보기, 버전 기록)여서 목록을 한 파일에 모았다.

```ts
// markdownPlugins.ts
export const REMARK_PLUGINS: Options['remarkPlugins'] = [remarkGfm, remarkCjkFriendly];
```

## 편집기: 읽을 때와 쓸 때 모두

편집기(Milkdown)도 안에서 remark로 Markdown을 읽고 쓴다. 읽기 화면만 고치면 편집기에서는 여전히 별표가 보인다. 그리고 더 조용한 문제가 하나 있었다.

플러그인 없이 편집기에서 이 글을 열어 한 글자만 고쳐 저장하면, 편집기가 문서를 다시 Markdown으로 쓸 때 **"이대로 쓰면 굵게가 안 된다"는 걸 알고** 뒤 글자를 문자 참조로 바꿔 버린다.

```markdown
**취소(cancelled)**&#xAC00; 떴다.
```

화면에는 똑같이 보이지만 저장된 글이 망가진다. remark-cjk-friendly는 쓰는 쪽 규칙(`mdast-util-to-markdown`)도 함께 고쳐서, 편집기에 `$remark`로 걸면 읽기와 쓰기가 같이 맞춰진다.

```ts
const cjkFriendly = $remark('cjkFriendly', () => remarkCjkFriendly);

Editor.make().use(commonmark).use(gfm).use(cjkFriendly);
```

## 테스트

- **단위 테스트**: `**취소(cancelled)**가`, ``**`dragover`**를``, `*“기울임”*은`이 `<strong>`/`<em>`으로 그려지는지, 영어 글과 취소선은 그대로인지 본다. 플러그인을 빼고 돌리면 실패하는 것도 확인했다
- **E2E**: 읽기 화면에서 굵게로 보이는지, 관리자로 편집기에서 열어 그 문단에 이어 써도 저장된 Markdown에 `**취소(cancelled)**가`가 그대로 있고 `&#x`가 없는지 본다. 편집기 쪽 플러그인만 빼면 이 테스트가 실패한다

테스트를 쓰다 하나 더 배웠다. 처음엔 글 맨 끝 빈 줄에 `' 끝.'`을 쳤더니 저장된 글에 `&#x20;끝.`이 들어가 테스트가 실패했다. 줄 맨 앞의 공백은 Markdown에서 사라지니 편집기가 문자 참조로 지킨 것이다. 이번 문제와는 상관없는, 올바른 동작이었다. 굵게가 있는 문단 끝에 이어 쓰도록 테스트를 고쳤다.
