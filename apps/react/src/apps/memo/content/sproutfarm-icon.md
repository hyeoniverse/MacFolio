새싹 농장(SproutFarm) 앱 아이콘을 게임 캐릭터의 픽셀 그림(32×32칸)으로 다시 그렸다([#85](https://github.com/hyeoniverse/MacFolio/pull/85)). 픽셀 그림은 한 칸이 곧 한 색이라, 확대하는 방식에 따라 결과가 크게 달라진다. 지켜야 할 것은 두 가지다. **색을 섞지 않는 보간**과 **정수 배율**이다.

![아이콘 전후](./images/sproutfarm-icon.jpg '위: 게임 화면을 그대로 축소한 예전 아이콘. Dock 크기에서 캐릭터가 점으로 보인다 / 아래: 픽셀 그림을 정수 배율로 확대한 새 아이콘')

## 보간 방식: 최근접 이웃과 이중 선형

이미지를 확대하면 원본에 없던 픽셀을 채워야 한다. 이 값을 정하는 방법이 보간(interpolation)이다.

| 보간                           | 새 픽셀의 색                                 | 픽셀 그림에서                           |
| ------------------------------ | -------------------------------------------- | --------------------------------------- |
| 최근접 이웃 (nearest neighbor) | 원본에서 가장 가까운 픽셀의 색을 그대로 복사 | 칸의 각진 경계가 유지된다               |
| 이중 선형 (bilinear)           | 가까운 네 픽셀의 색을 거리에 따라 섞음       | 칸 사이에 중간색이 생겨 경계가 흐려진다 |

사진은 이중 선형(또는 그보다 부드러운 bicubic)으로 확대해야 계단이 보이지 않는다. 픽셀 그림은 반대로, 계단 모양의 경계 자체가 그림이라 섞으면 안 된다.

![같은 48칸 원본을 최근접 이웃 10배, 이중 선형 10배, 최근접 이웃 10.67배로 확대한 비교](./images/sproutfarm-icon-scaling.jpg '아이콘 원본(48칸)의 얼굴 부분 24칸. 왼쪽: 최근접 이웃 10배, 칸이 모두 10px이다 / 가운데: 이중 선형 10배, 칸 경계에 중간색이 생긴다 / 오른쪽: 최근접 이웃 10.67배(512 ÷ 48), 칸 폭이 10px과 11px로 섞여 같은 굵기의 선이 다르게 보인다')

## 배율: 정수가 아니면 칸 폭이 섞인다

최근접 이웃으로 확대해도 배율이 정수가 아니면 문제가 남는다. 원본 한 칸이 차지할 픽셀 수가 소수가 되어, 반올림 결과에 따라 어떤 칸은 10픽셀, 어떤 칸은 11픽셀이 된다. 같은 굵기의 선이 위치마다 다른 굵기로 보인다(위 그림 오른쪽, 10.67배).

그래서 출력 크기를 배율에 맞췄다.

- 캔버스는 48×48칸이다. 32칸 캐릭터를 아래 끝에 두고 위와 옆에 풀밭을 남겨, 작은 크기에서도 캐릭터와 배경이 함께 식별되게 했다.
- 배율은 정수 10배로 정했다. 48칸 × 10 = 480px이라 한 칸이 정확히 10×10 픽셀이다.
- 흔히 쓰는 512px에 맞추면 배율이 10.67배가 되어 칸 폭이 10px과 11px로 섞인다. 아이콘은 화면에서 축소해 표시하므로 원본이 512px일 필요가 없다.

![48×48칸 캔버스와 정수 10배·10.67배 확대 비교](./images/sproutfarm-icon-grid.svg '캔버스 구성과 배율. 10.67배로 확대하면 칸 폭이 10px과 11px로 섞인다 (도식)')

## 축소해서 보여 줄 때

480px 아이콘은 Dock에서 48~64px로 축소되어 표시된다. 축소에는 브라우저 기본 보간을 그대로 둔다. 작은 크기에서는 칸 하나가 1픽셀보다 작아져, 최근접 이웃으로 축소하면 일부 칸이 통째로 빠지며 선이 끊긴다. **확대는 최근접 이웃, 축소는 기본 보간**이 원칙이다.

처음 게임 화면을 그대로 축소한 아이콘이 알아볼 수 없었던 이유도 여기에 있다. 큰 장면을 작게 줄이면 칸들이 평균색으로 뭉개진다. 작게 보일 그림은 작은 칸 수(48칸)로 다시 그리고, 그것을 정수 배율로 키운 뒤 표시 크기로 줄이는 편이 결과가 선명하다.

## CSS에서는 image-rendering: pixelated

같은 원칙을 프로젝트 페이지(Safari의 새싹 농장 페이지)의 CSS에도 적용했다. 게임 에셋(Sprout Lands)의 스프라이트와 상자 테두리를 화면에서 키워 쓰는데, 브라우저 기본값은 이중 선형에 가까운 보간이라 그대로 두면 흐려진다.

```css
/* 상자 테두리(border-image)까지 픽셀 그대로 키운다. 게임 캡처 사진만 따로 auto */
.gm,
.gm * {
	image-rendering: pixelated;
}

.gm-day img {
	image-rendering: auto; /* 사진은 부드럽게 */
}
```

- [`image-rendering: pixelated`](https://developer.mozilla.org/en-US/docs/Web/CSS/image-rendering)는 확대할 때 최근접 이웃으로 그린다.
- 페이지 전체에 적용하고, 게임 화면 캡처처럼 사진에 가까운 그림만 `auto`로 되돌렸다.
- 파일 첫머리 주석에 "픽셀 그림은 정수 배로 키우고 색을 섞지 않는다"는 규칙을 적어 두었다. 말풍선 꼬리는 늘어나는 상자와 함께 늘리면 뭉개져서, 별도 요소(`::before`)로 따로 붙였다.

## 결과

| 항목        | 값                                               |
| ----------- | ------------------------------------------------ |
| 아이콘 원본 | 48×48칸, 정수 10배 → 480×480px                   |
| 파일 크기   | 15,627바이트(게임 장면 축소본) → 3,950바이트     |
| 확대 보간   | 최근접 이웃 (CSS는 `image-rendering: pixelated`) |
| 축소 보간   | 브라우저 기본                                    |

색 수가 적은 픽셀 그림은 같은 색이 길게 이어져 PNG의 무손실 압축이 잘 된다. 크기가 더 큰데도 파일은 4분의 1로 줄었다.
