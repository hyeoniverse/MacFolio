## 공통 컴포넌트: 사용처를 먼저 집계하고 Modal 추출

4단계의 첫 항목은 코드 변경이 아니라 사용처 집계였다.

1. `shared/ui`의 컴포넌트 15개의 props와 사용처를 `docs/ui.md`에 기록
2. 직접 작성한 `<button>` 295곳을 분류. 그중 공통 Button으로 옮길 수 있는 곳은 93곳
3. 계획의 후보 9개가 현재 코드에서 몇 번 반복되는지 다시 측정

([#210](https://github.com/hyeoniverse/MacFolio/pull/210), [공통 부품 목록을 먼저 적고](/memo/ui-inventory))

결과는 Sheet·Modal·SearchField 3개였다. 나머지 6개는 사용처는 많아도 형태나 역할이 서로 달라서, 하나로 통합하면 옵션만 늘어난다고 판단해 보류했다.

그중 Modal을 먼저 추출했다. 경고창, 배경화면 이름 변경, 키보드 단축키, 로그인 결과, Launchpad 5곳이 같은 동작을 각자 구현하고 있었다.

| 동작                | 전                | 후                     |
| ------------------- | ----------------- | ---------------------- |
| 오버레이(배경 덮개) | 5곳에서 각자 구현 | `Modal`                |
| 포커스 트랩         | 5곳에서 각자 구현 | `Modal`                |
| Esc로 닫기          | 5곳에서 각자 구현 | `Modal`                |
| 바깥 클릭으로 닫기  | 5곳에서 각자 구현 | `Modal`                |
| 닫힘 애니메이션     | 5곳에서 각자 구현 | `Modal`                |
| 내용과 패널 스타일  | 각 다이얼로그     | 각 다이얼로그 (그대로) |

'이 Mac에 관하여'는 오버레이 없이 끌어서 옮기는 창이라 대상에서 제외했다([#212](https://github.com/hyeoniverse/MacFolio/pull/212), [모달 다이얼로그 5개의 공통 동작](/memo/ui-modal)).

Modal 글을 추가한 커밋에서 시험이 다시 실패했다. 요약에 쓴 '이동'이라는 단어가 휴대폰 메모 E2E의 '이동' 버튼 탐색에 함께 잡혔다. 블로그 글이 시험 데이터로 작용한 것은 전날에 이어 두 번째다.

## TypeScript 7 업그레이드

전날 활성화한 Dependabot이 의존성 PR을 열었다. 작은 업데이트 묶음([#214](https://github.com/hyeoniverse/MacFolio/pull/214)), vitest 5([#216](https://github.com/hyeoniverse/MacFolio/pull/216)), Font Awesome 7([#217](https://github.com/hyeoniverse/MacFolio/pull/217))은 그대로 머지했다.

TypeScript 5.9에서 7.0으로 올리는 PR([#215](https://github.com/hyeoniverse/MacFolio/pull/215))은 린트 단계에서 실패했다. TypeScript 7은 Go로 다시 작성한 컴파일러라 아직 JavaScript API가 없고, typescript-eslint는 그 API를 호출한다. PR을 닫지 않고 공식 안내에 따라 두 버전을 함께 설치했다.

| 패키지 이름          | 실제 버전        | 사용처                   |
| -------------------- | ---------------- | ------------------------ |
| `typescript`         | TS 6 호환 패키지 | typescript-eslint (린트) |
| `@typescript/native` | TS 7             | 타입 검사, 빌드          |

TS 7에서 제거된 `baseUrl` 옵션도 tsconfig에서 삭제했다([npm 별칭으로 TypeScript 7 tsc와 TypeScript 6 typescript-eslint 함께 쓰기](/memo/typescript-7-side-by-side)).

## 메모 각주와 접기 블록

용어가 많은 글은 본문에 용어 설명을 모두 넣으면 흐름이 끊긴다. 그래서 메모 앱에 두 가지 기능을 추가했다([#218](https://github.com/hyeoniverse/MacFolio/pull/218), 적용한 글: [GitHub 병합 방식 세 가지](/memo/merge-strategies)).

- **각주:** 본문의 번호와 글 끝의 설명을 서로 링크한다
- **접기 블록(`details`):** "먼저 알아 둘 용어"를 › 토글로 접어 둔다. 모서리 반경이 다른 블록과 같은지 화면에서 확인했다

메모의 칸 너비도 조절할 수 있게 했다. 사이드바와 글 목록의 너비가 고정되어 긴 폴더 이름과 글 제목이 잘렸다. 처음에는 사이드바만 조절하게 했는데, 사용해 보니 목록과 본문 사이도 조절할 수 있어야 했다. 두 경계를 끌거나 키보드로 이동하고, 더블클릭하면 기본 너비로 돌아간다([#219](https://github.com/hyeoniverse/MacFolio/pull/219), [CSS 그리드 경계 위에 절대 위치로 둔 리사이즈 핸들로 메모 칸 너비 조절하기](/memo/memo-pane-resize)).

## UTM으로 유입 경로 확인

지원서에 첨부할 링크로 어느 지원처에서 방문했는지 확인하려고 UTM 매개변수를 검토했다. 트래픽 분석은 이미 `utm_source` 등을 읽고 있어서, 별도 생성기 없이 링크에 매개변수만 붙이면 집계된다. 첫 화면 주소에 붙여 실제로 방문해 집계되는 것을 확인했다.

```text
https://macfolio.hyeoniverse.com/?utm_source=<지원처>&utm_medium=resume&utm_campaign=<공고>
```

| 매개변수       | 의미      | 예          |
| -------------- | --------- | ----------- |
| `utm_source`   | 유입 출처 | 지원 회사명 |
| `utm_medium`   | 매체      | `resume`    |
| `utm_campaign` | 캠페인    | 공고 이름   |

UTM 생성기는 바로 만들지 않고 이슈에 계획만 기록했다. 확인 중에 발견한 활동 상태 보기의 여백 불일치도 같은 계획에 넣었다. 매개변수의 정의는 [Google 애널리틱스 도움말](https://support.google.com/analytics/answer/10917952)을 참고했다.

### main의 버그를 #187 안에서 수정한 일

템플릿 필드를 조정하다가 설정 창 확인 다이얼로그의 여백이 0인 것을 발견했다. 빌드한 CSS에서 cascade layer 순서가 뒤집혀, reset 레이어가 공통 컴포넌트 스타일보다 우선하고 있었다. main에도 있는 버그였는데 #187 안에서 수정했고, 이 수정은 다른 커밋 메시지의 뒷부분에 한 줄로만 기록됐다.

## 돌아보며

Modal 추출은 순조롭게 끝났다. 사용처 집계를 먼저 했기 때문이다. 후보 9개를 모두 만들었다면, 형태가 서로 다른 것을 하나로 묶느라 옵션이 늘어난 컴포넌트가 6개 더 생겼을 것이다. 집계해 보니 통합할 대상은 3개였고, 그중 하나를 PR 하나로 이전했다.

#187의 템플릿 작업은 반대였다. 무엇을 기준으로 다시 만드는지 정하지 않은 채 작업했다. RPG 대화창은 새벽에만 세 번 바뀌었고, 템플릿 전체도 저녁과 밤에 두 번 다시 디자인했다. "빈 곳 없이 꽉 차 보이게", "제품 랜딩 페이지처럼"은 방문자가 무엇을 읽어야 하는지가 아니라 화면이 어떻게 보이는지에 대한 기준이었다. 그래서 다음 날 새벽에 대부분 제거했다.

그리고 CSS 레이어 순서 수정이 #187 안에 묻혔다. main에도 있는 버그인데, 아직 머지하지 않은 큰 브랜치의 스타일 커밋에 한 줄로 들어갔다. 다음 날 main에서 같은 버그를 처음부터 다시 찾게 된다. 큰 브랜치에서 발견한 main의 버그는 그 시점에 별도 PR로 main에 보내야 했다.
