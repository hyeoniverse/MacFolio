전날 1~3단계를 끝낸 리팩터링 계획([#150](https://github.com/hyeoniverse/MacFolio/issues/150))은 4단계, 공통 컴포넌트로 넘어갔다. 계획에는 새로 뽑을 부품이 아홉 개 적혀 있었다. 이날 실제로 뽑은 것은 하나다.

main에 들어간 PR은 8개로 전날보다 훨씬 적다. 이날 커밋의 절반 넘게는 아직 열려 있는 [#187](https://github.com/hyeoniverse/MacFolio/pull/187) 브랜치에 있다.

![10월 12일 작업 흐름](./images/day-1012-timeline.svg '새벽에는 #187의 RPG 대화창과 main의 Modal, 오후에는 의존성과 블로그, 밤에는 다시 #187의 템플릿. 커밋한 시각 기준')

## 세고 나서 뽑기: 아홉 후보 중 셋, 그중 Modal

4단계의 첫 항목은 코드를 바꾸는 일이 아니라 세는 일이었다. `shared/ui`에 있는 부품 열다섯 개의 props와 쓰는 곳을 `docs/ui.md`에 적고, 직접 쓴 `<button>` 295곳을 분류했다. 그중 공통 단추로 옮길 수 있는 곳은 93곳이었다. 계획의 후보 아홉도 지금 코드에서 몇 번 나오는지 다시 쟀다([#210](https://github.com/hyeoniverse/MacFolio/pull/210), [공통 부품 목록을 먼저 적고](/memo/ui-inventory)).

결과는 Sheet·Modal·SearchField 셋이었다. 나머지 여섯은 수는 많아도 모양이나 뜻이 서로 달라서 하나로 묶으면 옵션만 늘어날 것 같아 보류했다.

그중 Modal을 먼저 뽑았다. 경고창, 배경화면 이름 바꾸기, 키보드 단축키, 로그인 결과, Launchpad 다섯이 오버레이·포커스·Esc·바깥 누르기·사라지는 애니메이션을 각자 만들고 있었다. 이 동작을 `Modal` 하나로 모으고, 다섯 다이얼로그에는 내용과 패널 모양만 남겼다. '이 Mac에 관하여'는 오버레이 없이 끌 수 있는 창이라 넣지 않았다([#212](https://github.com/hyeoniverse/MacFolio/pull/212), [모달 다이얼로그 5개의 공통 동작](/memo/ui-modal)).

Modal 글에서도 시험이 깨졌다. 요약에 쓴 '이동'이라는 말이 휴대폰 메모 E2E의 '이동' 단추 검색에 같이 걸렸다. 전날에 이어 두 번째다.

## Dependabot이 연 TypeScript 7

전날 켠 Dependabot이 의존성 PR을 열었다. 작은 업데이트 묶음([#214](https://github.com/hyeoniverse/MacFolio/pull/214)), vitest 5([#216](https://github.com/hyeoniverse/MacFolio/pull/216)), Font Awesome 7([#217](https://github.com/hyeoniverse/MacFolio/pull/217))은 그대로 머지했다.

TypeScript 5.9에서 7.0으로 올리는 PR([#215](https://github.com/hyeoniverse/MacFolio/pull/215))은 린트 단계에서 멈췄다. TypeScript 7은 Go로 새로 쓴 컴파일러라 JavaScript API가 아직 없고, typescript-eslint는 그 API를 부른다. PR을 닫지 않고, 공식 안내대로 `typescript`라는 이름에는 TS 6 호환 패키지를, `@typescript/native`에는 TS 7을 설치했다. 타입 검사와 빌드는 7로, 린트는 6 API로 돈다. 7에서 사라진 `baseUrl`도 tsconfig에서 지웠다([TypeScript 7로 올리기](/memo/typescript-7-side-by-side)).

## 글을 쓰다가 생긴 기능

오후에는 GitHub의 병합 방식 세 가지를 비교하는 글을 썼다([#218](https://github.com/hyeoniverse/MacFolio/pull/218), [GitHub 병합 방식 세 가지](/memo/merge-strategies)). MacFolio 이야기가 아닌 첫 글이라 '기술 노트/Git'이라는 새 폴더에 넣었다.

이 글은 Git 용어가 많아서, 본문에 풀이를 다 넣으면 흐름이 끊겼다. 그래서 메모 앱에 각주(같은 글 안에서 오가는 번호)와 접기 블록(`details`)을 더하고, 용어 풀이를 그쪽으로 옮겼다. 글이 필요로 해서 블로그 기능이 생긴 셈이다.

같은 흐름으로 메모의 칸 너비도 조절할 수 있게 했다. 사이드바와 글 목록의 너비가 고정되어 있어서 긴 폴더 이름과 글 제목이 잘렸다. 두 경계를 끌거나 키보드로 옮기고, 두 번 누르면 기본 너비로 돌아온다([#219](https://github.com/hyeoniverse/MacFolio/pull/219), [메모 칸 너비 조절](/memo/memo-pane-resize)).

## #187: RPG 대화창과 템플릿을 다시 그리다

#187 브랜치에서는 프로젝트 페이지의 모양을 계속 다시 그렸다.

- **RPG 대화창**(dialogue): 프로젝트 소개를 게임 대화로 읽는 모양이다. 새벽에만 세 번 다시 그렸다. 비주얼 노벨 화면, 아늑한 픽셀 RPG 화면, 그리고 낮 하늘의 장면. 한글 픽셀 글꼴(갈무리11)을 이 모양이 열릴 때만 받게 하고, 프로젝트마다 다른 배경 테마를 열네 개까지 만들었다.
- **편집 화면**: macOS 시스템 설정처럼 도구 막대, 탭, 라벨과 컨트롤이 한 줄인 그룹 상자로 다시 짰다. 저장하면 새로고침 없이 Safari와 Finder에 바로 적용된다.
- **템플릿 전체**: 저녁에는 템플릿이 쓰는 칸을 편집 화면에 모두 더하고, 모양마다 가상 예시 프로젝트 13개를 만들어 빈 곳이 없게 손봤다. 밤에는 '랜딩 키트'를 만들어 모든 템플릿을 브랜드 제품 랜딩 페이지처럼 다시 꾸몄다. 히어로의 빛 번짐, 숫자 띠, 기술 로고 줄이 이때 들어갔다.

![RPG 대화창](./images/day-1012-dialogue.jpg '이날 #187 브랜치의 RPG 대화창. 크림색 대화 상자, 나무판 숫자, 액자의 화면 모음. 이 모습은 13일 밤에 거의 지워졌다')

![랜딩 키트로 다시 꾸민 기본 템플릿](./images/day-1012-landing.jpg '밤에 랜딩 키트로 다시 꾸민 기본 템플릿. 오른쪽 위의 빛 번짐과 기울어진 기기 틀은 다음 날 새벽에 걷어 냈다')

템플릿 칸을 손보다가 설정 창 확인창의 여백이 0인 것을 찾았다. 빌드한 CSS에서 층 순서가 뒤집혀 reset이 공통 컴포넌트를 이기고 있었다. #187 안에서 고쳤는데, 이 수정은 커밋 메시지의 뒷부분에 한 줄로만 들어갔다.

## 돌아보며

Modal은 쉽게 끝났다. 세는 일을 먼저 했기 때문이다. 후보 아홉을 그대로 다 만들었다면, 모양이 서로 다른 것을 하나로 묶느라 옵션이 늘어난 부품이 여섯 개 더 생겼을 것이다. 세어 보니 묶을 만한 것은 셋이었고, 그중 하나를 PR 하나로 옮겼다.

#187의 템플릿 작업은 반대였다. 무엇을 기준으로 다시 그리는지 정하지 않은 채 그렸다. RPG 대화창은 새벽에만 세 번 바뀌었고, 템플릿 전체도 저녁과 밤에 두 번 다시 꾸몄다. "빈 곳 없이 꽉 차 보이게", "브랜드 랜딩 페이지처럼"은 방문자가 무엇을 읽어야 하는지가 아니라 화면이 어떻게 보이는지에 대한 기준이었다. 그래서 다음 날 새벽에 대부분 다시 걷어 냈다.

그리고 CSS 층 순서 수정이 #187에 묻혔다. main에도 있는 버그인데, 아직 머지하지 않은 큰 브랜치의 스타일 커밋 안에 한 줄로 들어갔다. 다음 날 main에서 같은 버그를 처음부터 다시 찾게 된다. 큰 브랜치에서 찾은 main의 버그는 그 자리에서 main으로 따로 보내야 했다.
