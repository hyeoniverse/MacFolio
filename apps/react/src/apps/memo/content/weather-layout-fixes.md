날씨 앱에서 걸린 것 세 가지를 고쳤다. 셋 다 두 규칙이 서로 다른 기준을 쓰던 곳이었다.

| 증상                                | 어긋난 두 기준                                   | 고친 곳                              |
| ----------------------------------- | ------------------------------------------------ | ------------------------------------ |
| 신호등이 어두운 사이드바에 가려진다 | 신호등 줄(z 3)과 사이드바(z 4)                   | 사이드바는 내리고 버튼만 따로 올린다 |
| 휴대폰 화면 안에 넓은 창 모양       | 사이트의 휴대폰 기준(767px)과 날씨의 기준(640px) | JS의 `data-compact`로 하나로 정한다  |
| 장소가 하나면 목록 버튼이 밀린다    | 그리드 칸 순서와 실제로 그린 자식 수             | `grid-column: 3`, 여백 28px          |

세 가지 모두 날씨 앱 하나만의 일이라 한 커밋에 담았다. 바뀐 파일은 `Weather.tsx`, `Weather.css`, `e2e/weather.spec.ts` 세 개다(294줄 추가, 202줄 삭제). CSS 변경이 큰 것은 컨테이너 질의 안의 규칙을 모두 밖으로 꺼내 선택자를 바꿨기 때문이다.

## 사이드바가 신호등을 덮었다

날씨 창은 제목 표시줄 없이 신호등 버튼이 내용 위에 떠 있다(`chrome="unified"`). 신호등 줄은 창을 끄는 자리이기도 해서 `z-index: 3`으로 내용 위에 있다.

떠 있는 사이드바의 오른쪽 위에는 사이드바 버튼이 있는데, 이 버튼도 신호등 줄 안에 있다. 그대로 두면 끌기 자리가 위에 있어서 버튼이 눌리지 않는다. 사이드바는 흐림(`backdrop-filter`) 때문에 새 층을 만들어서, 안의 버튼만 `z-index`를 올려도 소용이 없다. 그래서 사이드바째 `z-index: 4`로 올려 두었고, 그 바람에 어두운 사이드바가 신호등을 덮었다.

이것은 메모 도구 막대에서 겪은 쌓임 맥락 문제(/memo/sticky-stacking-context)와 같은 구조다. 그때는 sticky가, 이번에는 `backdrop-filter`가 새 층을 만들었다.

사이드바는 내리고, 사이드바 버튼만 사이드바 밖에 따로 두어 올렸다. 자리는 사이드바의 크기로 계산한다.

```css
/* 자리 = 사이드바 바깥 여백 8 + 너비 250 - 안쪽 여백 10 - 버튼 30, 위로는 8 + (36 - 26) / 2 */
.weather-sidebar-toggle {
	position: absolute;
	top: 13px;
	left: 218px;
	z-index: 4;
}
```

## 휴대폰 화면 안에 넓은 창 모양이 그려졌다

사이트는 폭 767px까지 휴대폰 화면으로 본다. 눕힌 휴대폰(높이 499px 이하)은 1023px까지도 휴대폰이다. 그런데 날씨 앱은 날씨 칸이 640px 이하일 때만 iOS 모양으로 바꿨다(`@container weather (max-width: 640px)`).

그래서 641~767px의 세운 화면과 눕힌 휴대폰에서는 넓은 창 모양(떠 있는 사이드바)이 휴대폰 화면 안에 그려졌다. 사이드바의 흐림이 화면 위쪽을 덮었고, 사이드바 버튼은 상태 표시줄 밑에 깔려 눌리지 않았다.

고칠 방법은 셋 정도였다.

| 방법                                    | 장점                        | 단점                                                                            |
| --------------------------------------- | --------------------------- | ------------------------------------------------------------------------------- |
| 컨테이너 질의 값을 767px로 올린다       | 한 줄                       | 눕힌 휴대폰(1023px까지)은 여전히 어긋난다. 데스크톱의 좁은 창도 iOS 모양이 된다 |
| 미디어 질의를 컨테이너 질의와 함께 쓴다 | CSS만으로 된다              | 사이트의 휴대폰 판단(JS, 높이 조건 포함)을 CSS에 다시 적어야 한다               |
| JS가 `data-compact`를 정한다            | 사이트와 같은 `useIsMobile` | `ResizeObserver` 하나가 더 돈다                                                 |

메모 앱도 같은 문제를 겪어서 JS가 정한 `data-compact`로 바꾼 적이 있다. 날씨도 그렇게 했다. 휴대폰 화면이면 폭과 상관없이 iOS 모양이고, 데스크톱에서는 날씨 칸이 640px(`COMPACT_WIDTH`) 이하일 때만 iOS 모양이다.

```ts
function useCompact(ref: React.RefObject<HTMLElement | null>) {
	const phone = useIsMobile();
	const [width, setWidth] = useState(Infinity);
	useEffect(() => {
		const element = ref.current;
		if (!element) return;
		const observer = new ResizeObserver(([entry]) => setWidth(entry.contentRect.width));
		observer.observe(element);
		return () => observer.disconnect();
	}, [ref]);
	return phone || width <= COMPACT_WIDTH;
}
```

CSS는 컨테이너 질의 안에 있던 규칙마다 앞에 `.weather[data-compact]`를 붙였다.

## 장소가 하나면 목록 버튼이 왼쪽으로 밀려났다

iOS 모양의 아래 막대는 세 칸 그리드다(`48px 1fr 48px`). 왼쪽은 빈 칸, 가운데는 장소 점, 오른쪽은 목록 버튼이다. 장소가 하나면 넘길 곳이 없어서 장소 점을 그리지 않는다. 그러면 목록 버튼이 비어 있는 가운데 칸으로 들어가, 가운데 칸 왼쪽 끝에 붙었다.

![아래 막대 그리드에서 목록 버튼이 두 번째 칸으로 밀렸다가 세 번째 칸에 고정된 모습](./images/weather-layout-fixes-bottom-bar.svg '빈 칸이 있어도 자리를 지키게')

목록 버튼에 `grid-column: 3`을 줘서 늘 오른쪽 칸에 둔다. 아래 막대의 좌우 여백도 날씨 칸과 다르게 16px였는데, 날씨 칸과 같은 28px(`--weather-gutter`)로 맞췄다. 이제 목록 버튼의 바깥 끝이 카드의 끝과 같은 선에 있다.

## 확인

`apps/react/e2e/weather.spec.ts`에 시험 셋을 더했다(79줄).

- "신호등은 떠 있는 사이드바 위에 보인다 (사이드바가 덮지 않는다)": 신호등 자리에서 맨 위에 그려진 것이 신호등 버튼인지 `document.elementFromPoint`로 본다
- "폭과 상관없이 iOS 모양 (목록은 덮어 열고, 사이드바 버튼이 상태 표시줄 밑에 깔리지 않는다)": 744px 세운 화면과 844×390 눕힌 화면 두 경우를 같은 시험으로 돌린다
- "아래 막대의 목록 버튼은 장소가 하나여도 오른쪽, 날씨 칸들과 같은 좌우 여백에 맞춘다": 목록 버튼의 오른쪽 끝이 날씨 칸의 오른쪽 끝과 같은지 좌표로 비교한다

첫 시험은 눈으로 보는 것과 같은 것을 확인한다. 화면에는 신호등이 보이는데 눌리지 않는 문제는, 요소가 "있는지"만 보는 시험으로는 잡히지 않는다. 그 좌표에서 맨 위에 무엇이 있는지를 봐야 한다.

## 남은 것·배운 것

- 반응형 기준이 둘 이상 있으면 그 사이에 반드시 틈이 생긴다. 이번의 641~767px이 그랬다. 앱 안의 "작은 모양" 판단은 사이트의 휴대폰 판단을 먼저 따르고, 그다음에 자기 폭을 본다.
- 컨테이너 질의는 앱 칸의 폭만 안다. 그 칸이 휴대폰 화면 안에 있는지는 모른다. 이 둘을 함께 봐야 하는 곳은 JS가 정한 속성으로 넘기는 편이 낫다.
- 그리드에서 자식이 조건에 따라 빠지면 나머지가 앞 칸으로 당겨진다. 자리가 정해진 자식은 `grid-column`으로 칸을 못 박는다.
- 같은 사이트의 다른 앱(메모)에서 이미 겪은 문제였다. 다음에 새 앱을 만들 때는 처음부터 `data-compact` 방식으로 시작한다.
