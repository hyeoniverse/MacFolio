데이터베이스 기초 연재의 여덟 번째 글로, 8장(데이터 모델링)을 다룬다. 앞의 글들이 관계 데이터 모델 안에서 릴레이션을 다뤘다면, 이 글은 현실 세계를 어떤 과정으로 릴레이션까지 옮기는지 정리한다.

## 데이터의 세 세계와 데이터베이스 설계

데이터는 세 세계에 걸쳐 표현된다.

| 세계                        | 표현 대상                   | 표현 단위                      |
| --------------------------- | --------------------------- | ------------------------------ |
| 현실 세계(real world)       | 실제로 존재하는 사물과 사건 | 개체, 속성, 관계               |
| 개념 세계(conceptual world) | 사람이 이해하는 추상적 구조 | 개체 타입, 관계 타입           |
| 컴퓨터 세계(computer world) | 컴퓨터가 처리하는 구조      | 레코드 타입, 필드, 저장 레코드 |

현실 세계를 구조적으로 표현하는 과정이 데이터베이스 설계(database design)다.

| 단계                                  | 입력 → 결과                                                                             | 설계 이름   |
| ------------------------------------- | --------------------------------------------------------------------------------------- | ----------- |
| 1. 개념적 모델링(conceptual modeling) | 현실 세계 → 개념적 구조. 추상적 개념인 개체 타입(entity type)으로 표현                  | 개념적 설계 |
| 2. 데이터 모델링(logical modeling)    | 개념적 구조 → 논리적 구조(데이터 모델). 논리적 개념인 레코드 타입(record type)으로 표현 | 논리적 설계 |
| 3. 데이터 구조화(data structuring)    | 논리적 구조 → 물리적 구조. 저장 장치에서의 데이터 표현                                  | 물리적 설계 |

==설계의 핵심은 개념적 구조와 논리적 구조를 거쳐 실제로 저장할 수 있는 물리적 구조로 변환하는 것이다.==

|           | 개념적 데이터 모델링                                  | 논리적 데이터 모델링                                       |
| --------- | ----------------------------------------------------- | ---------------------------------------------------------- |
| 표현 단위 | 애트리뷰트로 기술한 개체 타입과 개체 타입 사이의 관계 | 데이터 필드로 기술한 레코드 타입과 레코드 타입 사이의 관계 |
| 대표 모델 | 개체-관계 모델(E-R model)                             | 관계, 네트워크, 계층, 객체지향, 객체-관계 데이터 모델      |

![현실 세계(개체·특성·값)↔개념 세계(개체 타입·속성·값)↔컴퓨터 세계(레코드 타입·필드·값)와 개념적 모델링·데이터 모델링 흐름도](./images/db-er-model-note-01.jpg '현실 세계(개체·특성·값)↔개념 세계(개체 타입·속성·값)↔컴퓨터 세계(레코드 타입·필드·값)와 개념적 모델링·데이터 모델링 흐름도 (강의 자료)')

## 데이터 모델

데이터 모델 D는 세 요소로 정의한다.

```text
D = <S, O, C>
```

| 요소                    | 내용                                                                                                                  |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------- |
| S 구조(structure)       | 데이터의 정적 성질. 개체 타입과 그 사이의 관계를 명세한다                                                             |
| O 연산(operation)       | 데이터의 동적 성질. 개체 인스턴스를 처리하는 연산(데이터 조작 기법)을 명세한다                                        |
| C 제약조건(constraints) | 개체 인스턴스가 존재하기 위한 논리적 제약. 구조에서 파생되는 제약과 의미상 제약이 있으며, 데이터 조작의 한계를 정한다 |

관계 데이터 모델에 대입하면 S는 릴레이션, O는 [관계 대수](/memo/db-relational-algebra), C는 키와 [무결성 제약](/memo/db-relational-model-keys)이다.

논리적 데이터 모델 가운데 가장 많이 쓰이는 것은 관계 데이터 모델이다. 그 이전에는 네트워크 모델과 계층 모델이 많이 쓰였고, 최근에는 객체지향 모델과 객체-관계 모델도 쓰인다. ==하나의 DBMS는 하나의 논리적 데이터 모델만 구현하며==, ==모델 사이의 주요 차이는 데이터 요소 사이의 관계(relationship)를 표현하는 방식이다.==

## 개체 타입

**개체(entity)** 는 단독으로 존재할 수 있고 다른 것과 구별되는 객체(object)다. **개체 타입(entity type)** 은 이름과 애트리뷰트들로 정의하며, 같은 애트리뷰트로 구성된 개체들의 공통된 논리적 구조를 나타낸다. 한 개체 타입에 속하는 개체 인스턴스(instance)들의 집합을 개체 집합(entity set)이라 한다.

### 애트리뷰트의 유형

| 유형                              | 정의                                                                       | 예                               |
| --------------------------------- | -------------------------------------------------------------------------- | -------------------------------- |
| 단순 애트리뷰트(simple)           | 더 작은 구성 요소로 분해할 수 없다                                         | 학년                             |
| 복합 애트리뷰트(composite)        | 기본적인 단순 애트리뷰트 몇 개로 분해할 수 있다                            | 주소(시, 구, 동), 이름(성, 이름) |
| 단일 값 애트리뷰트(single-valued) | 개체마다 값이 하나다                                                       | 학생의 이름                      |
| 다중 값 애트리뷰트(multivalued)   | 개체마다 값이 여러 개일 수 있다. 실제로는 값의 최대 개수를 제한하기도 한다 | 학생의 취미                      |
| 유도 애트리뷰트(derived)          | 다른 애트리뷰트나 개체의 값에서 계산되어 정해진다                          | 과목-성적 개체의 평균 성적       |
| 저장 애트리뷰트(stored)           | 유도 애트리뷰트를 계산하는 데 쓰인 애트리뷰트                              | 등록 개체의 성적                 |
| 널 애트리뷰트(null)               | 널 값을 가질 수 있다                                                       | 휴대전화가 없는 사원의 전화번호  |

널 값은 개체 인스턴스가 어떤 애트리뷰트의 값을 갖지 않는다는 사실을 명시적으로 표시한다. 그 값이 개체에 해당하지 않는 경우(not applicable)와 알 수 없는 경우(unknown)가 있고, 알 수 없는 경우는 다시 값은 있지만 누락된 경우(missing)와 값이 있는지조차 모르는 경우(not known)로 나뉜다.

![주소를 도·시(군,읍)·동(면)번지·우편번호로, 동(면)번지를 다시 동(면)·번지·아파트번호로 나눈 복합 애트리뷰트 트리](./images/db-er-model-note-03.jpg '주소를 도·시(군,읍)·동(면)번지·우편번호로, 동(면)번지를 다시 동(면)·번지·아파트번호로 나눈 복합 애트리뷰트 트리 (강의 자료)')

## 관계 타입

**관계 타입(relationship type)** 은 개체 집합 사이의 대응, 즉 사상(mapping)이다. 학생 개체 집합과 과목 개체 집합 사이의 "등록"이 관계 타입이며, 관계는 개체 없이 단독으로 존재할 수 없다. 두 개체 집합 사이에 실제로 나타난 관계 인스턴스들의 집합을 관계 집합이라 한다.

![학생-등록(마름모)-과목으로 그린 등록 relationship type E-R 도식](./images/db-er-model-note-04.jpg '학생-등록(마름모)-과목으로 그린 등록 relationship type E-R 도식 (강의 자료)')

![학생 개체 집합·등록 관계 집합·과목 개체 집합의 원소를 선으로 이은 등록 관계 인스턴스 그림](./images/db-er-model-note-05.jpg '학생 개체 집합·등록 관계 집합·과목 개체 집합의 원소를 선으로 이은 등록 관계 인스턴스 그림 (강의 자료)')

### 사상 원소 수

관계 타입의 원소 수 제약조건(cardinality ratio)은 사상의 함수성으로 구분한다.

![관계 타입의 사상 원소 수 네 가지](./images/db-er-model-cardinality.svg '한쪽 개체가 상대 개체 몇 개와 연결되는지로 나눈다') 사상 f: X → Y와 g: Y → X에 대해,

| 원소 수      | 함수성              | 예                       |
| ------------ | ------------------- | ------------------------ |
| 1:1 (일대일) | f와 g 모두 함수적   | 결혼: 신랑 ↔ 신부        |
| 1:n (일대다) | g만 함수적          | 모자 관계: 어머니 ← 자녀 |
| n:1 (다대일) | f만 함수적          | 소속: 교수 → 학과        |
| n:m (다대다) | 둘 다 함수적이 아님 | 등록: 학생 ↔ 과목        |

사상 원소 수는 시간과 관계없이 항상 유지되는 정적인 관계다.

![두 집합 원소를 선으로 이어 1:1·1:n·n:1·n:n 사상 원소 수를 비교한 4개 그림](./images/db-er-model-note-06.jpg '두 집합 원소를 선으로 이어 1:1·1:n·n:1·n:n 사상 원소 수를 비교한 4개 그림 (강의 자료)')

### 참여 제약과 존재 종속

| 개념                             | 정의                                                                                                             | 예                              |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------- |
| 전체 참여(total participation)   | 개체 집합 A의 모든 개체가 A-B 관계에 참여한다                                                                    | 모든 교수는 학과에 소속된다     |
| 부분 참여(partial participation) | A의 일부 개체만 A-B 관계에 참여한다                                                                              | 휴학생은 과목에 등록하지 않는다 |
| 존재 종속(existence dependence)  | 개체 b의 존재가 개체 a의 존재에 종속된다. a를 주 개체(dominant entity), b를 종속 개체(subordinate entity)라 한다 | 대출이 있어야 상환이 존재한다   |

![교수-강의-과목 관계에 시간·장소 애트리뷰트가 붙은 attributes를 가진 relationship type 도식](./images/db-er-model-note-07.jpg '교수-강의-과목 관계에 시간·장소 애트리뷰트가 붙은 attributes를 가진 relationship type 도식 (강의 자료)')

![대출(대출번호·대출금액)-대출상환-상환(상환번호·상환일자·상환금액) 존재 종속 예시(주 개체: 대출, 종속 개체: 상환)](./images/db-er-model-note-08.jpg '대출(대출번호·대출금액)-대출상환-상환(상환번호·상환일자·상환금액) 존재 종속 예시(주 개체: 대출, 종속 개체: 상환) (강의 자료)')

## E-R 모델

개체-관계 모델(Entity-Relationship model)은 개체 타입과 관계 타입을 기본 개념으로 현실 세계를 개념적으로 표현하는 개념적 데이터 모델이다. 1976년 Peter Chen이 제안했고, 이를 그림으로 표현한 것이 E-R 다이어그램이다.

![교수·학생·과목 개체와 지도(1:n)·강의(1:n, 시간·장소)·등록(n:m, 성적) 관계를 그린 대학 E-R 다이어그램](./images/db-er-model-note-13.jpg '교수·학생·과목 개체와 지도(1:n)·강의(1:n, 시간·장소)·등록(n:m, 성적) 관계를 그린 대학 E-R 다이어그램 (강의 자료)')

![강의 관계(마름모)에 시간·장소 속성 타원이 달린 작은 도식](./images/db-er-model-note-14.jpg '강의 관계(마름모)에 시간·장소 속성 타원이 달린 작은 도식 (강의 자료)')

### E-R 다이어그램 표기법

| 기호               | 의미                                                      |
| ------------------ | --------------------------------------------------------- |
| 사각형             | 개체 타입                                                 |
| 이중 사각형        | 약한 개체 타입                                            |
| 마름모             | 관계 타입                                                 |
| 이중 마름모        | 식별 관계 타입                                            |
| 타원               | 애트리뷰트                                                |
| 밑줄 그은 타원     | 키 애트리뷰트                                             |
| 점선 밑줄 타원     | 부분 키(구별자)                                           |
| 이중 타원          | 다중 값 애트리뷰트                                        |
| 점선 타원          | 유도 애트리뷰트                                           |
| 타원에 연결된 타원 | 복합 애트리뷰트                                           |
| 선(링크)           | 개체 타입·관계 타입·애트리뷰트의 연결. 이중선은 전체 참여 |
| 레이블             | 사상 원소 수(1:1, 1:n, n:1, n:m)                          |

E-R 다이어그램의 특징은 다음과 같다.

- 다대다(n:m) 관계를 직접 표현한다.
- 세 개 이상의 개체 타입이 한 관계에 참여하는 다원 관계(n-ary relationship)를 표현한다.
- 두 개체 타입 사이에 관계가 둘 이상 있는 다중 관계(multiple relationship)를 표현한다.
- 관계 타입도 애트리뷰트를 가질 수 있다. 등록 관계의 성적이 그 예다.

![개체·약한 개체·관계·식별 관계·전체 참여와 일반·키·부분 키·다중 값·복합·유도 애트리뷰트 기호를 모은 E-R 표기법 기호표](./images/db-er-model-note-16.jpg '개체·약한 개체·관계·식별 관계·전체 참여와 일반·키·부분 키·다중 값·복합·유도 애트리뷰트 기호를 모은 E-R 표기법 기호표 (강의 자료)')

### 키 애트리뷰트

키 애트리뷰트(key attribute)는 한 개체 집합 안에서 개체마다 다른 값을 갖는 애트리뷰트나 애트리뷰트 집합이다. 키는 개체 타입 안의 모든 개체 인스턴스를 유일하게 식별하므로, 같은 키 값을 갖는 개체 인스턴스는 둘일 수 없다. E-R 다이어그램에서는 밑줄로 표시한다.

### 약한 개체 타입

자기 애트리뷰트만으로는 키를 명세할 수 없는 개체 타입을 **약한 개체 타입(weak entity type)** 이라 하고, 그 반대를 강한 개체 타입(strong entity type)이라 한다. 강한 개체 타입이 주 개체, 약한 개체 타입이 종속 개체가 된다.

| 용어                                          | 정의                                                                      |
| --------------------------------------------- | ------------------------------------------------------------------------- |
| 구별자(discriminator), 부분 키(partial key)   | 같은 강한 개체에 연관된 약한 개체들 사이에서만 서로를 구별하는 애트리뷰트 |
| 식별 관계 타입(identifying relationship type) | 약한 개체를 강한 개체에 연결해 유일하게 식별하게 하는 관계                |

대출과 상환에서 상환 번호 1, 2, 3은 대출마다 다시 시작하므로 상환 번호만으로는 상환을 식별할 수 없다. =={대출 번호, 상환 번호}로 식별하며, 상환 번호가 구별자다.==

## 논리적 데이터 모델

논리적 데이터 모델은 개념적 구조를 데이터베이스로 구현하기 위한 중간 단계로, 레코드(개체) 타입과 관계로 표현한다. 종류는 네트워크, 계층, 관계, 객체지향, 객체, 객체-관계, 확장 관계 데이터 모델이 있다.

![현실세계↔E-R 다이어그램↔(설계자)↔데이터 모델↔저장 데이터베이스 흐름도](./images/db-er-model-note-17.jpg '현실세계↔E-R 다이어그램↔(설계자)↔데이터 모델↔저장 데이터베이스 흐름도 (강의 자료)')

### 관계 데이터 모델

- 데이터베이스는 릴레이션(테이블)의 집합이다. 개체를 표현하는 개체 릴레이션과 관계를 표현하는 관계 릴레이션이 있다.
- 릴레이션 스키마로 개체와 관계를 모두 릴레이션으로 정의한다. 학생-등록-과목에서 등록 관계도 릴레이션 `등록(학번, 과목번호, 성적)`이 된다.

![학생·교수·과목·지도·등록·강의 6개 릴레이션 스키마를 필드 박스로 나열한 관계 데이터 모델 예](./images/db-er-model-note-18.jpg '학생·교수·과목·지도·등록·강의 6개 릴레이션 스키마를 필드 박스로 나열한 관계 데이터 모델 예 (강의 자료)')

### 데이터 구조도

자료 구조도(data structure diagram)는 레코드 타입 사이의 관계를 도형으로 표현한다. 1969년 Bachman이 제안해 Bachman 다이어그램이라고도 한다.

| 구성 요소    | 의미                                |
| ------------ | ----------------------------------- |
| 사각형 노드  | 레코드 타입(개체 타입)              |
| 링크(화살표) | 레코드 타입 사이의 일대다(1:n) 관계 |
| 레이블       | 관계 이름                           |

데이터베이스 스키마를 데이터 구조도로 그린 것을 스키마 다이어그램이라 한다. 스키마 다이어그램이 트리면 계층 데이터 모델, 그래프면 네트워크 데이터 모델이다.

|                   | 네트워크 데이터 모델                                    | 계층 데이터 모델                                        |
| ----------------- | ------------------------------------------------------- | ------------------------------------------------------- |
| 스키마 다이어그램 | 그래프(network)                                         | 트리(tree), 사이클 없음                                 |
| 관계              | 오너-멤버(owner-member) 관계: 두 레코드 타입 사이의 1:n | 부모-자식(parent-child) 관계: 두 레코드 타입 사이의 1:n |
| 구조 용어         |                                                         | 루트 레코드, 자식 레코드, 레벨                          |
| 대표 DBMS         | IDS                                                     | IMS                                                     |

==두 모델 모두 1:n만 직접 표현하므로 n:m 관계는 중간 레코드 타입을 두어 1:n 두 개로 나눠야 한다.== 관계 데이터 모델은 관계도 릴레이션으로 표현해 이 제약이 없다.

## 과제로 풀어 본 문제

**E-R 다이어그램 그리기.** 11주차 과제에서 다음 요구사항을 E-R 다이어그램으로 그렸다.

> 사원(Emp)은 사원번호(Eno), 이름(Name), 주소(Addr)로, 부서(Dep)는 부서번호(Dno), 부서이름(Dname), 예산(Budget)으로 구성된다. 사원은 한 부서만을 위해 근무(Works-for)하고, 근무는 근무 시간(Hours)으로 표현한다. 각 부서에는 부서를 관리(Manages)하는 사원이 한 명 있고, 부서를 관리하는 사원은 모두 다르다.

![사원과 부서의 E-R 다이어그램](./images/db-er-model-emp-dep.jpg '과제에서 그린 다이어그램. 사원번호와 부서번호에 밑줄을 그어 키를 표시했다')

과제에서는 원소 수를 적지 않았다. 요구사항에서 원소 수와 참여 제약을 읽으면 다음과 같다.

| 관계 | 원소 수         | 참여                           | 근거                                                                          |
| ---- | --------------- | ------------------------------ | ----------------------------------------------------------------------------- |
| 근무 | 사원 n : 부서 1 | 사원 전체 참여                 | 사원은 한 부서만을 위해 근무한다                                              |
| 관리 | 사원 1 : 부서 1 | 부서 전체 참여, 사원 부분 참여 | 부서마다 관리자가 한 명 있고, 관리자는 모두 다르다. 관리자가 아닌 사원도 있다 |

근무 시간(Hours)은 사원이나 부서가 아니라 "어떤 사원이 어떤 부서에서 근무하는 관계"의 성질이므로 관계 타입의 애트리뷰트로 그린다.

**관계 데이터 모델에서 개체와 관계를 같은 방법으로 표현한다는 뜻.** E-R 다이어그램에서는 개체를 사각형, 관계를 마름모로 구분하지만, 관계 데이터 모델에서는 둘 다 릴레이션이다. 학생과 과목은 개체 릴레이션, 등록은 관계 릴레이션이며 모양이 같고 같은 연산(관계 대수, SQL)으로 처리한다. 다만 1:1이나 1:n 관계는 별도 릴레이션 없이 외래 키로 표현하기도 한다.

**부모-자식 관계와 오너-멤버 관계의 함수성.** 둘 다 1:n 관계다. 자식(멤버) 레코드 인스턴스 하나는 부모(오너) 레코드 인스턴스 하나에만 연결되므로, 자식에서 부모로 가는 사상만 함수적이다. 그래서 레코드 인스턴스 수준에서는 부모가 없는 자식 인스턴스를 저장할 수 없고, 부모를 삭제하면 그 자식 인스턴스도 함께 삭제된다. 계층 모델은 레코드 타입마다 부모 타입이 하나뿐이고, 네트워크 모델은 한 레코드 타입이 여러 오너 타입의 멤버가 될 수 있다는 점이 다르다.

## 정리

- 데이터베이스 설계는 개념적 설계(E-R 모델) → 논리적 설계(관계 데이터 모델 등) → 물리적 설계 순서로 진행한다.
- 데이터 모델은 구조, 연산, 제약조건으로 구성된다.
- 관계 타입은 사상 원소 수(1:1, 1:n, n:1, n:m)와 참여 제약(전체, 부분)으로 특징짓는다.
- 자기 애트리뷰트만으로 식별할 수 없는 약한 개체 타입은 강한 개체의 키와 구별자를 합쳐 식별한다.
