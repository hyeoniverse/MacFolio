`docs/ui.md`의 버튼 표에는 "`IconButton`으로 옮길 수 있음 약 60곳"이 있었다. 뒤로 가기 꺾쇠, ••• 더 보기, 메일 시트의 동그란 취소·보내기, 음악의 재생 버튼 같은 것들이다. 모두 `<button>`에 `aria-label`과 Font Awesome 아이콘을 직접 적은 버튼이다. 이번에 이 가운데 45곳을 공통 `IconButton`으로 옮겼다. 목표는 하나다. **화면은 하나도 바뀌지 않는다.**([#245](https://github.com/hyeoniverse/MacFolio/pull/245))

## 왜 옮기나

화면이 그대로라면 옮길 까닭이 무엇인가. 셋이다.

- **이름이 빠지지 않는다.** 바로 앞 PR([#243](https://github.com/hyeoniverse/MacFolio/pull/243))에서 `IconButton`의 타입을 바꿔, 아이콘만 있는 버튼은 `label`이 없으면 타입 검사에서 막히게 했다. 직접 쓴 `<button>`은 이 검사를 받지 않는다. `aria-label`을 빠뜨려도 아무도 모른다.
- **`title`이 저절로 붙는다.** `IconButton`은 `title`을 따로 주지 않으면 `label`을 쓴다. 마우스를 올리면 버튼 이름이 보인다. 직접 쓴 버튼은 쓰는 곳마다 `title`을 따로 적어야 한다.
- **다음 변경이 한 곳에서 된다.** 켜짐 상태, 눌렀을 때의 색, 움직임 줄이기 같은 공통 동작을 고칠 때 `IconButton.css` 하나만 보면 된다.

```tsx
// 전 (ComposeView.tsx)
<button type="button" className="mail-sheet-circle" aria-label="취소" onClick={onCancel}>
	<i className="fa-solid fa-xmark" aria-hidden="true" />
</button>

// 후
<IconButton variant="circle" className="mail-sheet-circle" label="취소" icon="fa-solid fa-xmark" onClick={onCancel} />
```

## 무엇을 옮겼나

| 앱    | 곳  | 버튼                                                                                               |
| ----- | --- | -------------------------------------------------------------------------------------------------- |
| 사진  | 13  | 확대·축소(격자 2, 보기 2), 정보, 공유, 돌아가기, 프로젝트 페이지, 휴대폰의 •••·공유·검색·검색 닫기 |
| 음악  | 9   | 셔플, 이전 곡, 재생, 다음 곡, 반복, 다음 재생, 휴대폰 미니 재생·다음 곡, 뒤로 가기                 |
| 메일  | 7   | 시트의 취소·닫기·보내기 5, 휴대폰 새로운 메시지, 뒤로 가기                                         |
| 메모  | 6   | 찾기 이전·다음, 댓글 삭제, 버전 목록으로, 휴대폰 뒤로 가기 2                                       |
| 그 밖 | 10  | Safari 휴대폰 3, 메시지 3, 날씨 2, Finder 휴대폰 •••, 배경화면 지우기                              |

날씨의 사이드바 여닫기는 `IconButton`을 바로 쓰지 않고, 메모·사진이 이미 쓰는 `SidebarToggle`로 옮겼다. 이름('사이드바 보기'·'사이드바 가리기')은 같고 `aria-expanded`가 더해졌다.

옮기는 방법은 같다. `aria-label`은 `label`로, `<i>` 아이콘은 `icon`으로 옮긴다. 앱의 `className`과 `ref`, `aria-pressed`·`aria-expanded`, 처리기는 그대로 둔다. `aria-label`과 `title`이 달랐던 댓글 삭제는 `title`을 따로 적었다. 이름이 그대로라 역할과 이름으로 버튼을 찾는 E2E는 고칠 것이 없었다.

## variant="circle"

`IconButton`에는 도구 막대의 네모난 `tool`과 떠 있는 동그란 `float`가 있었다. 메일 시트의 취소·보내기나 사진 휴대폰의 공유처럼, 떠 있지 않은 동그란 버튼은 받을 자리가 없었다. 그래서 `circle`을 하나 더 두었다.

```css
.ui-icon-button.circle {
	flex: none;
	padding: 0;
	border-radius: 50%;
}
```

`circle`은 모양만 정한다. 크기(30·34·44·52px)와 바탕(유리, 회색, 파란색)은 앱마다 다르므로 앱의 CSS가 정한다. 메시지 보내기와 배경화면 지우기도 동그란 버튼이라 `circle`로 옮겼고, 모두 15곳이 쓴다.

## 모양이 같은 것을 어떻게 확인했나

확인 방법을 셋 놓고 골랐다.

| 방법                                        | 좋은 점                                                                                 | 걸리는 점                                                                       |
| ------------------------------------------- | --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 화면을 하나씩 열어 눈으로                   | 준비가 없다                                                                             | 45곳 × 데스크톱·휴대폰 × 켜짐·꺼짐·올림. 1px 차이는 못 본다                     |
| 스크린샷 비교 (전후 픽셀)                   | 차이를 확실히 잡는다                                                                    | 기준 스크린샷을 만들고 관리해야 하고, 시계·애니메이션 같은 무관한 차이도 잡힌다 |
| **E2E 중에 계산된 스타일을 떼고 붙여 비교** | 지금 있는 시험이 지나가는 모든 상태를 공짜로 훑는다, 어떤 속성이 다른지 이름으로 나온다 | 스크립트를 따로 써야 하고, 시험이 지나가지 않는 화면은 못 본다                  |

세 번째를 골랐다.

공통 CSS는 `components` 층에 있고, 앱의 CSS는 층 밖에 있어 늘 이긴다. 문제는 앱이 적지 않은 값이다. `tool`은 최소 폭 30px, 높이 28px, 좌우 여백 7px, 둥근 모서리 7px, 회색 글자, 올렸을 때 바탕을 더한다. 앱이 이 값을 덮지 않았다면 모양이 바뀐다.

이것을 버튼마다 확인하려고, E2E를 돌릴 때 페이지에 작은 스크립트를 넣었다. 화면에 보이는 `.ui-icon-button`마다 계산된 스타일을 모두 읽고, 공통 클래스(`ui-icon-button`·`tool`·`circle`·`float`)를 잠깐 떼고 다시 읽어 비교한다. 클래스를 뗀 상태가 곧 옮기기 전의 `<button>`이다. 시험이 지나가는 화면(휴대폰·데스크톱, 켜짐·꺼짐, 비활성, 마우스를 올린 상태)마다 기록되므로, 손으로 화면을 찾아다니지 않아도 된다.

![공통 클래스를 떼고 붙여 비교하는 방법](./images/icon-button-migrate-compare.svg '클래스를 뗀 상태가 옮기기 전의 버튼이다')

처음 돌렸을 때 차이가 난 곳은 다음과 같다.

- 음악 재생 버튼: 글자 색이 회색으로, 높이가 28px로, 켠 셔플에 바탕이 생겼다
- 찾기 이전·다음, 댓글 삭제: 폭이 24·26px에서 30px로
- 사진 도구 막대의 확대·정보·공유: 글자 색이 회색으로
- 뒤로 가기 꺾쇠: 높이 28px, 가운데 정렬

이 값들은 앱의 규칙에 적어 되돌렸다. 음악은 버튼이 여럿이라 점수가 0인 규칙 하나(`:where(.music .ui-icon-button)`)로 도구 막대 모양을 지웠고, 나머지는 원래 규칙에 `min-width: 0`·`height: auto`·`color: inherit` 같은 값을 더했다. 다시 돌린 뒤에는 크기·색·여백·모서리가 모두 같았다. 남은 차이는 `gap`·`justify-content`(아이콘 하나뿐이라 화면에 나타나지 않는다), `position: relative`·`z-index: 4`(끌기 영역 위로 올리는 공통 값), 휴대폰에서만 보이는 버튼의 `cursor`다.

## 숫자

- 31개 파일, 355줄 더하기, 227줄 지우기. 앱 CSS에 되돌리는 값을 적느라 더한 줄이 더 많다.
- `docs/ui.md`의 세는 법으로 앱 코드에 직접 쓴 `<button>`은 340곳에서 295곳이 됐다. 이어서 글자 버튼 30곳을 `Button`으로 옮긴 [#246](https://github.com/hyeoniverse/MacFolio/pull/246) 뒤에는 265곳이다.
- 지금 `<IconButton`을 쓰는 곳은 97곳이다.

![직접 쓴 버튼 수](./images/icon-button-migrate-counts.svg '아이콘 버튼 45곳, 글자 버튼 30곳을 옮긴 뒤의 수')

## 확인

- 앞의 비교 스크립트로 크기·색·여백·모서리가 모두 같은 것을 확인했다. 남은 차이는 앞에 적은 것뿐이다.
- 역할과 이름으로 버튼을 찾는 E2E 전체가 그대로 통과했다. 이름을 하나라도 바꿨다면 여기서 걸렸다.
- `IconButton`에 `label`이 없으면 타입 검사가 실패하므로, 옮긴 45곳은 모두 이름을 가진다.

## 옮기지 않은 것과 바뀐 것

- 메시지 삭제(`messages-bubble-action`): 평소에는 1px로 숨어 있다가 초점을 받을 때만 보이는 버튼이다. 아이콘 버튼 모양이 아니어서, 옮기려면 공통 모양을 거의 다 지워야 한다
- 사진 휴대폰 보기의 정보: 같은 알약 안의 좋아요 버튼과 짝이다. 하나만 옮기면 두 버튼의 CSS가 갈린다

날씨의 사이드바 버튼은 아이콘이 Font Awesome의 `table-columns`에서 메모·사진과 같은 사이드바 SVG로 바뀌었다. 세 앱이 같은 버튼을 쓰게 하려고 일부러 바꾼 것이고, 크기와 자리는 그대로다. 이번 PR에서 화면이 바뀐 곳은 이 아이콘 하나다.

## 남은 것·배운 것

- 앱의 `className`을 그대로 둔 채 옮겼으니, 앱 CSS에는 "공통 모양을 되돌리는" 값이 남았다. 언젠가 앱의 버튼 모양을 공통 `variant`로 옮기면 이 값들도 함께 지울 수 있다. 이번에는 "화면 그대로"를 지키려고 손대지 않았다.
- 계산된 스타일 비교 스크립트는 저장소에 넣지 않았다. 한 번 쓰고 버린 도구다. 공통 부품으로 옮기는 일이 또 있으면 다시 쓸 만하다.
- 공통 부품으로 옮기는 일의 어려움은 코드가 아니라 "앱이 적지 않은 값"에 있다. 앱이 덮지 않던 공통 값이 무엇인지 기계로 찾게 하니, 45곳을 눈으로 하나씩 비교하지 않고도 옮길 수 있었다.
