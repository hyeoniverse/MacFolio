[`docs/ui.md`](https://github.com/hyeoniverse/MacFolio/blob/main/docs/ui.md)의 버튼 표에는 "`IconButton`으로 옮길 수 있음 약 60곳"과 "`Button`으로 옮길 수 있음 약 33곳"이 있었다. 앞의 것은 뒤로 가기 꺾쇠, ••• 더 보기, 메일 시트의 원형 취소·보내기, 음악의 재생 버튼처럼 `<button>`에 `aria-label`과 Font Awesome 아이콘을 직접 작성한 버튼이다. 뒤의 것은 휴지통 비우기, 찾기의 완료, 글쓰기의 게시처럼 `<button>`에 글자를 직접 작성한 버튼이다. 이 가운데 아이콘 버튼 45곳을 `IconButton`으로([#245](https://github.com/hyeoniverse/MacFolio/pull/245)), 글자 버튼 30곳을 `Button`으로([#246](https://github.com/hyeoniverse/MacFolio/pull/246)) 옮겼다. 목표는 하나다. **화면이 한 픽셀도 바뀌지 않아야 한다.**

## 옮기는 이유

화면이 그대로인데 옮기는 이유는 세 가지다.

| 이유                  | 설명                                                                                                                                                                                                                                                                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 접근성 이름 누락 방지 | 직전 PR([#243](https://github.com/hyeoniverse/MacFolio/pull/243))에서 `IconButton`의 타입을 바꿔, 아이콘만 있는 버튼은 `label`이 없으면 타입 검사에서 실패하게 했다. 직접 작성한 `<button>`은 이 검사 대상이 아니라 [`aria-label`](https://developer.mozilla.org/ko/docs/Web/Accessibility/ARIA/Attributes/aria-label)을 누락해도 검출되지 않는다 |
| `title` 자동 지정     | `IconButton`은 `title`을 지정하지 않으면 `label` 값을 쓴다. 마우스를 올리면 버튼 이름이 툴팁으로 표시된다. 직접 작성한 버튼은 사용하는 곳마다 `title`을 별도로 지정해야 한다                                                                                                                                                                      |
| 변경 지점 단일화      | 활성 상태, 눌렀을 때의 색, 움직임 줄이기 같은 공통 동작을 수정할 때 `IconButton.css`·`Button.css` 하나만 확인하면 된다                                                                                                                                                                                                                            |

`aria-label`은 `label`로, `<i>` 아이콘은 `icon`으로 옮긴다. 앱의 `className`과 `ref`, `aria-pressed`·`aria-expanded`, 이벤트 핸들러는 유지한다. `aria-label`과 `title`이 달랐던 댓글 삭제는 `title`을 별도로 지정했다.

```tsx
// 전 (ComposeView.tsx)
<button type="button" className="mail-sheet-circle" aria-label="취소" onClick={onCancel}>
	<i className="fa-solid fa-xmark" aria-hidden="true" />
</button>

// 후
<IconButton variant="circle" className="mail-sheet-circle" label="취소" icon="fa-solid fa-xmark" onClick={onCancel} />
```

날씨의 사이드바 열기·닫기 버튼은 `IconButton`을 직접 쓰지 않고, 메모·사진이 이미 쓰는 `SidebarToggle`로 옮겼다. 이름('사이드바 보기'·'사이드바 가리기')은 같고 [`aria-expanded`](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-expanded)가 추가됐다.

`docs/ui.md`의 표에는 설정의 취소·완료·편집이 7곳(정보·GitHub)으로 기록되어 있었다. 프로젝트 항목에도 같은 클래스(`showcase-text-button`)를 사용하는 버튼 3곳이 있어 함께 옮겼다.

`<button>`을 `<Button>`으로 바꾸고, `Button`의 기본값과 같은 `type="button"`만 제거한다. 앱의 `className`, `type="submit"`·`form`, `disabled`, `title`, 처리기는 유지한다. `tone` 속성은 사용하지 않았다. 색은 기존처럼 앱의 CSS가 지정한다.

```diff
+import Button from '@/shared/ui/button/Button';
-				<button
-					type="button"
+				<Button
 					className="bin-empty-button"
 					onClick={…}
 				>
 					휴지통 비우기
-				</button>
+				</Button>
```

두 경우 모두 접근 가능한 이름이 그대로라, 역할과 이름으로 버튼을 찾는 E2E(`getByRole('button', { name })`)는 수정할 필요가 없었다.

## variant="circle"

`IconButton`에는 도구 막대의 사각형 `tool`과 부유하는 원형 `float` variant가 있었다. 메일 시트의 취소·보내기나 사진 휴대폰의 공유처럼, 부유하지 않는 원형 버튼에 맞는 variant가 없었다. 그래서 `circle`을 추가했다.

```css
.ui-icon-button.circle {
	flex: none;
	padding: 0;
	border-radius: 50%;
}
```

`circle`은 형태만 정의한다. 크기(30·34·44·52px)와 배경(유리, 회색, 파란색)은 앱마다 다르므로 앱의 CSS가 지정한다. 메시지 보내기와 배경화면 삭제도 원형 버튼이라 `circle`로 옮겼고, 모두 15곳에서 사용한다.

## 공통 CSS가 추가하는 값과 되돌리는 방법

공통 CSS는 `components` [캐스케이드 레이어](https://developer.mozilla.org/ko/docs/Web/CSS/@layer)[^layer]에 있고, 앱의 CSS는 레이어 밖에 있어 항상 우선한다. 문제는 앱이 지정하지 않은 속성이다. 앱이 이 값을 재정의하지 않으면 외형이 바뀐다.

| 클래스                 | 추가하는 값                                                                                                                                        |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.ui-icon-button.tool` | 최소 폭 30px, 높이 28px, 좌우 패딩 7px, 모서리 반경 7px, 회색 글자, hover 배경                                                                     |
| `.ui-button`           | `display: inline-flex`, 가운데 정렬, `gap: 6px`, `fade-in` 애니메이션, 안쪽 여백, 모서리 8px, 옅은 배경색, `font: inherit`, 비활성 `opacity: 0.45` |

앱의 reset 레이어(예: `.memo button { font: inherit }`)는 `components` 레이어보다 먼저 선언되어 우선순위가 낮다. 따라서 앱이 클래스로 덮어쓰지 않은 속성은 공통 CSS의 값으로 바뀐다.

되돌리는 방법은 세 가지를 검토했다.

| 방법                                           | 장점                                    | 단점                                                                      |
| ---------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------------- |
| 앱 CSS에서 버튼마다 덮어쓸 값을 직접 작성한다  | 변경 내용이 그 위치에서 바로 보인다     | 30곳마다 `display`·`gap`·모서리를 작성해야 하고, 명시도 경쟁이 생긴다     |
| `Button`에 스타일이 없는 `variant="bare"` 추가 | 앱 CSS를 수정하지 않는다                | 공통 컴포넌트에 "공통 모양을 사용하지 않는" 옵션이 생겨 역할이 모호해진다 |
| 앱마다 `:where()` 규칙 하나로 되돌린다         | 앱의 기존 규칙은 유지, 앱마다 규칙 하나 | 나중에 앱 모양을 공통 모양으로 맞출 때 이 규칙을 삭제해야 한다            |

아이콘 버튼은 차이가 난 버튼이 적어 대부분 기존 규칙에 `min-width: 0`·`height: auto`·`color: inherit` 같은 값을 추가했고, 버튼이 여러 개인 음악만 `:where(.music .ui-icon-button)` 규칙 하나로 도구 막대 스타일을 초기화했다. 글자 버튼은 30곳 모두 `display`·정렬·`gap`이 달라 세 번째 방법을 택했다.

```css
:where(.bin-empty-button):where(.ui-button) {
	display: inline-block;
	align-items: normal;
	justify-content: normal;
	gap: normal;
	animation: none;
}
```

[`:where()`](https://developer.mozilla.org/en-US/docs/Web/CSS/:where) 안의 선택자는 [명시도(specificity)](https://developer.mozilla.org/en-US/docs/Web/CSS/Specificity)가 0이다. 레이어 밖에 있으므로 공통 CSS보다 우선하고, 명시도가 0이므로 앱이 원래 작성한 규칙보다는 우선순위가 낮다. 앱의 규칙을 하나씩 수정하지 않고 공통 CSS가 추가한 값만 되돌릴 수 있다.

| 규칙                                          | 위치         | 명시도 | 결과                     |
| --------------------------------------------- | ------------ | ------ | ------------------------ |
| `.bin-empty-button` (앱 규칙)                 | 레이어 밖    | 0-1-0  | 가장 우선                |
| `:where(.bin-empty-button):where(.ui-button)` | 레이어 밖    | 0-0-0  | 공통 CSS보다 우선        |
| `.ui-button`                                  | `components` | 0-1-0  | 위 두 규칙이 없는 속성만 |
| `.memo button` (앱 reset)                     | reset 레이어 | 0-1-1  | 가장 낮음                |

![앱 CSS, :where 규칙, components 층의 .ui-button, 앱 reset 층이 이기는 순서](./images/text-button-migrate-cascade.svg ':where() 규칙은 공통 CSS보다 세고 앱 규칙보다 약하다')

이 작업의 목표는 "컴포넌트는 통일하고 화면은 유지"다. 화면을 공통 모양으로 맞추는 작업은 별도로 진행하고, 그 시각에 `:where()` 규칙이 삭제 대상 목록이 된다.

## 동일성 확인

### 방법

확인 방법은 세 가지를 비교했다.

| 방법                                                       | 장점                                                                                | 단점                                                                            |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 화면을 하나씩 열어 육안 확인                               | 준비 작업이 없다                                                                    | 75곳 × 데스크톱·휴대폰 × 활성·비활성·hover. 1px 차이는 식별할 수 없다           |
| 스크린샷 비교 (전후 픽셀)                                  | 차이를 확실히 검출한다                                                              | 기준 스크린샷을 생성·관리해야 하고, 시계·애니메이션 같은 무관한 차이도 검출된다 |
| **E2E 실행 중 클래스 제거·적용 상태의 계산된 스타일 비교** | 기존 시험이 거치는 모든 상태를 추가 작업 없이 확인하고, 다른 속성의 이름이 출력된다 | 별도 스크립트가 필요하고, 시험이 거치지 않는 화면은 확인할 수 없다              |

세 번째를 선택했다. E2E 실행 시 페이지에 작은 스크립트를 삽입한다. 화면에 표시된 `.ui-icon-button`·`.ui-button`마다 [계산된 스타일](https://developer.mozilla.org/ko/docs/Web/API/Window/getComputedStyle)을 모두 읽고, 공통 클래스(`ui-icon-button`·`tool`·`circle`·`float`, `ui-button`)를 잠시 제거한 뒤 다시 읽어 비교한다. 클래스를 제거한 상태가 옮기기 전의 `<button>`과 같다. `:where()` 규칙도 `.ui-button`을 조건으로 하므로 함께 빠진다. 데스크톱과 휴대폰(iPhone·Android) 프로젝트에서, 시험이 거치는 기본·활성·비활성·hover 상태가 모두 기록된다.

![공통 클래스를 제거·적용해 비교하는 방법](./images/icon-button-migrate-compare.svg '클래스를 제거한 상태가 옮기기 전의 버튼이다')

### 아이콘 버튼 결과

첫 실행에서 차이가 검출된 곳은 다음과 같다.

| 버튼                            | 차이                                                     |
| ------------------------------- | -------------------------------------------------------- |
| 음악 재생 버튼                  | 글자 색이 회색으로, 높이가 28px로, 활성 셔플에 배경 추가 |
| 찾기 이전·다음, 댓글 삭제       | 폭이 24·26px에서 30px로                                  |
| 사진 도구 막대의 확대·정보·공유 | 글자 색이 회색으로                                       |
| 뒤로 가기 꺾쇠                  | 높이 28px, 가운데 정렬                                   |

이 값들을 앱 규칙에 명시한 뒤 재실행하자 크기·색·패딩·모서리가 모두 같았다. 남은 차이는 `gap`·`justify-content`(아이콘 하나뿐이라 화면에 영향 없음), `position: relative`·`z-index: 4`(창 끌기 영역 위로 올리는 공통 값), 휴대폰에서만 표시되는 버튼의 `cursor`다.

### 글자 버튼 결과

첫 실행에서는 옮긴 버튼의 기록이 모두 달랐다. 대부분 `display`·정렬·`gap` 차이였고, 다음 차이가 추가로 있었다.

| 앱   | 차이                                                                                                                          | 되돌린 값             |
| ---- | ----------------------------------------------------------------------------------------------------------------------------- | --------------------- |
| 설정 | 둥근 모서리                                                                                                                   | `border-radius: 0`    |
| 설정 | 취소·완료·편집은 원래 글꼴을 상속하지 않던 버튼이라, `font: inherit`가 적용되자 글꼴이 바뀌어 너비가 26px에서 22.5px로 줄었다 | `font-family: revert` |
| 메모 | 게시·버리기와 휴대폰 목록의 이동·삭제가 비활성일 때 투명해졌다                                                                | `opacity: 1`          |
| 메모 | 이미지 창의 다시 고르기·더 보기에 배경색이 생겼다                                                                             | 배경색 없음           |

`:where()` 규칙을 추가하고 다시 실행한 뒤에는 기록된 64가지 조합(버튼·상태·화면 너비)이 모두 같았다. 애니메이션은 시험이 애니메이션을 끈 상태(`reducedMotion`)로 실행되어 비교에 잡히지 않으므로, 별도로 `animation: none`을 지정했다. 마지막으로 변경 전과 후를 각각 빌드해 '이 Mac에 관하여' 창을 캡처하고 비교했다. 두 이미지는 픽셀 단위로 동일했다.

### 화면이 바뀐 곳

날씨의 사이드바 버튼은 아이콘이 Font Awesome의 `table-columns`에서 메모·사진과 같은 사이드바 SVG로 바뀌었다. 세 앱이 같은 버튼을 쓰도록 의도적으로 바꾼 것이고, 크기와 위치는 그대로다. 두 PR에서 화면이 바뀐 곳은 이 아이콘 하나다.

## 옮기지 않은 버튼

- 메시지 삭제(`messages-bubble-action`): 평소에는 1px로 숨겨져 있다가 포커스를 받을 때만 표시되는 버튼이다. 아이콘 버튼 형태가 아니어서, 옮기려면 공통 스타일을 거의 모두 초기화해야 한다
- 사진 휴대폰 보기의 정보: 같은 캡슐형 그룹 안의 좋아요 버튼과 한 쌍이다. 하나만 옮기면 두 버튼의 CSS가 서로 달라진다
- Safari 프로젝트 데모 페이지의 버튼과, 목록 행·탭·카드처럼 그 앱에만 있는 모양의 버튼

글자 버튼은 표에 기록한 것을 모두 옮겼다.

## 남은 것·배운 것

- 앱의 `className`을 유지한 채 옮겼으므로, 앱 CSS에는 공통 스타일을 초기화하는 값과 `:where()` 규칙이 남았다. 이 규칙은 "공통 모양과 다른 곳"의 목록이다. 버튼 모양을 공통 `variant`로 맞출 때 이 값을 하나씩 삭제하면서 화면을 바꾸면 된다.
- 계산된 스타일 비교 스크립트는 저장소에 추가하지 않았다. 일회성 도구다. 공통 컴포넌트로 옮기는 작업이 또 있으면 재사용할 수 있다.
- 공통 컴포넌트로 옮기는 작업의 어려움은 코드 변환이 아니라 "앱이 지정하지 않은 속성"에 있다. `font: inherit` 한 줄이 설정 버튼의 너비를 26px에서 22.5px로 바꾼 것처럼, 육안으로 발견하기 어려운 차이를 스크립트가 검출했다.
- 캐스케이드 레이어 밖의 규칙은 레이어 안의 규칙보다 항상 우선하고, `:where()`는 명시도를 0으로 만든다. 이 둘을 함께 사용하면 "공통 CSS보다 우선하고 앱 규칙보다는 낮은" 규칙을 만들 수 있다.
