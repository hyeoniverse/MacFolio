[`docs/ui.md`](https://github.com/hyeoniverse/MacFolio/blob/main/docs/ui.md)의 버튼 표에는 "`IconButton`으로 옮길 수 있음 약 60곳"이 있었다. 뒤로 가기 꺾쇠, ••• 더 보기, 메일 시트의 원형 취소·보내기, 음악의 재생 버튼 등이다. 모두 `<button>`에 `aria-label`과 Font Awesome 아이콘을 직접 작성한 버튼이다. 이번에 이 중 45곳을 공통 `IconButton`으로 옮겼다. 목표는 하나다. **화면이 전혀 바뀌지 않아야 한다.**([#245](https://github.com/hyeoniverse/MacFolio/pull/245))

## 옮기는 이유

화면이 그대로인데 옮기는 이유는 세 가지다.

| 이유                  | 설명                                                                                                                                                                                                                                                                                                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 접근성 이름 누락 방지 | 직전 PR([#243](https://github.com/hyeoniverse/MacFolio/pull/243))에서 `IconButton`의 타입을 바꿔, 아이콘만 있는 버튼은 `label`이 없으면 타입 검사에서 실패하게 했다. 직접 작성한 `<button>`은 이 검사 대상이 아니라 [`aria-label`](https://developer.mozilla.org/ko/docs/Web/Accessibility/ARIA/Attributes/aria-label)을 누락해도 검출되지 않는다 |
| `title` 자동 지정     | `IconButton`은 `title`을 지정하지 않으면 `label` 값을 쓴다. 마우스를 올리면 버튼 이름이 툴팁으로 표시된다. 직접 작성한 버튼은 사용하는 곳마다 `title`을 별도로 지정해야 한다                                                                                                                                                                      |
| 변경 지점 단일화      | 활성 상태, 눌렀을 때의 색, 움직임 줄이기 같은 공통 동작을 수정할 때 `IconButton.css` 하나만 확인하면 된다                                                                                                                                                                                                                                         |

```tsx
// 전 (ComposeView.tsx)
<button type="button" className="mail-sheet-circle" aria-label="취소" onClick={onCancel}>
	<i className="fa-solid fa-xmark" aria-hidden="true" />
</button>

// 후
<IconButton variant="circle" className="mail-sheet-circle" label="취소" icon="fa-solid fa-xmark" onClick={onCancel} />
```

## 옮긴 버튼

| 앱   | 수  | 버튼                                                                                               |
| ---- | --- | -------------------------------------------------------------------------------------------------- |
| 사진 | 13  | 확대·축소(격자 2, 보기 2), 정보, 공유, 돌아가기, 프로젝트 페이지, 휴대폰의 •••·공유·검색·검색 닫기 |
| 음악 | 9   | 셔플, 이전 곡, 재생, 다음 곡, 반복, 다음 재생, 휴대폰 미니 재생·다음 곡, 뒤로 가기                 |
| 메일 | 7   | 시트의 취소·닫기·보내기 5, 휴대폰 새로운 메시지, 뒤로 가기                                         |
| 메모 | 6   | 찾기 이전·다음, 댓글 삭제, 버전 목록으로, 휴대폰 뒤로 가기 2                                       |
| 기타 | 10  | Safari 휴대폰 3, 메시지 3, 날씨 2, Finder 휴대폰 •••, 배경화면 지우기                              |

날씨의 사이드바 열기·닫기 버튼은 `IconButton`을 직접 쓰지 않고, 메모·사진이 이미 쓰는 `SidebarToggle`로 옮겼다. 이름('사이드바 보기'·'사이드바 가리기')은 같고 [`aria-expanded`](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Attributes/aria-expanded)가 추가됐다.

옮기는 방법은 모두 같다. `aria-label`은 `label`로, `<i>` 아이콘은 `icon`으로 옮긴다. 앱의 `className`과 `ref`, `aria-pressed`·`aria-expanded`, 이벤트 핸들러는 유지한다. `aria-label`과 `title`이 달랐던 댓글 삭제는 `title`을 별도로 지정했다. 접근성 이름이 그대로라 역할과 이름으로 버튼을 찾는 E2E는 수정할 필요가 없었다.

## variant="circle"

`IconButton`에는 도구 막대의 사각형 `tool`과 부유하는 원형 `float` variant가 있었다. 메일 시트의 취소·보내기나 사진 휴대폰의 공유처럼, 부유하지 않는 원형 버튼에 맞는 variant가 없었다. 그래서 `circle`을 추가했다.

```css
.ui-icon-button.circle {
	flex: none;
	padding: 0;
	border-radius: 50%;
}
```

`circle`은 형태만 정의한다. 크기(30·34·44·52px)와 배경(유리, 회색, 파란색)은 앱마다 다르므로 앱의 CSS가 지정한다. 메시지 보내기와 배경화면 삭제도 원형 버튼이라 `circle`로 옮겼고, 모두 15곳에서 사용한다.

## 외형 동일성 확인 방법

확인 방법은 세 가지를 비교했다.

| 방법                                                       | 장점                                                                                | 단점                                                                            |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 화면을 하나씩 열어 육안 확인                               | 준비 작업이 없다                                                                    | 45곳 × 데스크톱·휴대폰 × 활성·비활성·hover. 1px 차이는 식별할 수 없다           |
| 스크린샷 비교 (전후 픽셀)                                  | 차이를 확실히 검출한다                                                              | 기준 스크린샷을 생성·관리해야 하고, 시계·애니메이션 같은 무관한 차이도 검출된다 |
| **E2E 실행 중 클래스 제거·적용 상태의 계산된 스타일 비교** | 기존 시험이 거치는 모든 상태를 추가 작업 없이 확인하고, 다른 속성의 이름이 출력된다 | 별도 스크립트가 필요하고, 시험이 거치지 않는 화면은 확인할 수 없다              |

세 번째를 선택했다.

공통 CSS는 `components` [캐스케이드 레이어](https://developer.mozilla.org/ko/docs/Web/CSS/@layer)에 있고, 앱의 CSS는 레이어 밖에 있어 항상 우선한다[^layer]. 문제는 앱이 지정하지 않은 속성이다. `tool`은 최소 폭 30px, 높이 28px, 좌우 패딩 7px, 모서리 반경 7px, 회색 글자, hover 배경을 추가한다. 앱이 이 값을 재정의하지 않았다면 외형이 바뀐다.

이것을 버튼마다 확인하기 위해, E2E 실행 시 페이지에 작은 스크립트를 삽입했다. 화면에 표시된 `.ui-icon-button`마다 [계산된 스타일](https://developer.mozilla.org/ko/docs/Web/API/Window/getComputedStyle)을 모두 읽고, 공통 클래스(`ui-icon-button`·`tool`·`circle`·`float`)를 잠시 제거한 뒤 다시 읽어 비교한다. 클래스를 제거한 상태가 옮기기 전의 `<button>`과 같다. 시험이 거치는 화면(휴대폰·데스크톱, 활성·비활성, disabled, hover 상태)마다 기록되므로, 화면을 직접 찾아다니지 않아도 된다.

![공통 클래스를 제거·적용해 비교하는 방법](./images/icon-button-migrate-compare.svg '클래스를 제거한 상태가 옮기기 전의 버튼이다')

첫 실행에서 차이가 검출된 곳은 다음과 같다.

| 버튼                            | 차이                                                     |
| ------------------------------- | -------------------------------------------------------- |
| 음악 재생 버튼                  | 글자 색이 회색으로, 높이가 28px로, 활성 셔플에 배경 추가 |
| 찾기 이전·다음, 댓글 삭제       | 폭이 24·26px에서 30px로                                  |
| 사진 도구 막대의 확대·정보·공유 | 글자 색이 회색으로                                       |
| 뒤로 가기 꺾쇠                  | 높이 28px, 가운데 정렬                                   |

이 값들은 앱의 규칙에 명시해 원래 값으로 되돌렸다. 음악은 버튼이 여러 개라 명시도가 0인 규칙 하나([`:where(.music .ui-icon-button)`](https://developer.mozilla.org/en-US/docs/Web/CSS/:where))로 도구 막대 스타일을 초기화했고, 나머지는 기존 규칙에 `min-width: 0`·`height: auto`·`color: inherit` 같은 값을 추가했다. 재실행 후에는 크기·색·패딩·모서리가 모두 같았다. 남은 차이는 `gap`·`justify-content`(아이콘 하나뿐이라 화면에 영향 없음), `position: relative`·`z-index: 4`(창 끌기 영역 위로 올리는 공통 값), 휴대폰에서만 표시되는 버튼의 `cursor`다.

## 수치

- 31개 파일, +355/−227. 앱 CSS에 원래 값을 명시하느라 추가한 줄이 더 많다.
- `docs/ui.md`의 집계 기준으로 앱 코드에 직접 작성한 `<button>`은 340곳에서 295곳이 됐다. 이어서 글자 버튼 30곳을 `Button`으로 옮긴 [#246](https://github.com/hyeoniverse/MacFolio/pull/246) 이후에는 265곳이다.
- 현재 `<IconButton`을 사용하는 곳은 97곳이다.

![직접 작성한 버튼 수](./images/icon-button-migrate-counts.svg '아이콘 버튼 45곳, 글자 버튼 30곳을 옮긴 뒤의 수')

## 확인

- 비교 스크립트로 크기·색·패딩·모서리가 모두 같음을 확인했다. 남은 차이는 위에 정리한 항목뿐이다.
- 역할과 이름으로 버튼을 찾는 E2E 전체가 수정 없이 통과했다. 이름을 하나라도 바꿨다면 여기서 실패했을 것이다.
- `IconButton`에 `label`이 없으면 타입 검사가 실패하므로, 옮긴 45곳은 모두 접근성 이름이 있다.

## 옮기지 않은 버튼과 화면이 바뀐 곳

- 메시지 삭제(`messages-bubble-action`): 평소에는 1px로 숨겨져 있다가 포커스를 받을 때만 표시되는 버튼이다. 아이콘 버튼 형태가 아니어서, 옮기려면 공통 스타일을 거의 모두 초기화해야 한다
- 사진 휴대폰 보기의 정보: 같은 캡슐형 그룹 안의 좋아요 버튼과 한 쌍이다. 하나만 옮기면 두 버튼의 CSS가 서로 달라진다

날씨의 사이드바 버튼은 아이콘이 Font Awesome의 `table-columns`에서 메모·사진과 같은 사이드바 SVG로 바뀌었다. 세 앱이 같은 버튼을 쓰도록 의도적으로 바꾼 것이고, 크기와 위치는 그대로다. 이번 PR에서 화면이 바뀐 곳은 이 아이콘 하나다.

## 남은 것·배운 것

- 앱의 `className`을 유지한 채 옮겼으므로, 앱 CSS에는 "공통 스타일을 초기화하는" 값이 남았다. 이후 앱의 버튼 스타일을 공통 `variant`로 옮기면 이 값들도 함께 삭제할 수 있다. 이번에는 "화면 유지" 원칙에 따라 변경하지 않았다.
- 계산된 스타일 비교 스크립트는 저장소에 추가하지 않았다. 일회성 도구다. 공통 컴포넌트로 옮기는 작업이 또 있으면 재사용할 수 있다.
- 공통 컴포넌트로 옮기는 작업의 어려움은 코드 변환이 아니라 "앱이 지정하지 않은 속성"에 있다. 앱이 재정의하지 않은 공통 값을 스크립트로 검출하자, 45곳을 하나씩 육안으로 비교하지 않고도 옮길 수 있었다.
