이 글은 2026년 10월에 git 기록을 다시 읽으며 쓴 회고다. 10월 11일과 12일은 커밋이 모두 합쳐 세 개라 한 편으로 묶고, 날짜가 아니라 주제별로 정리했다. 화면은 캡처할 수 없어서 그때 코드 구조를 그림으로 대신한다.

![2024년 10월 11~12일 작업 흐름](./images/day-20241011-timeline.svg '11일 아침에 하나, 12일 새벽과 아침에 하나씩')

## 빌드: Create React App과 TypeScript

11일 커밋은 [첫 커밋](/memo/day-20240827) 뒤 45일 만의 커밋이다. `index.html`·`script.js`·`style.css`를 지우고 `create-react-app`의 TypeScript 틀로 옮겼다. 72개 파일이 바뀌었는데 그중 1만 9천 줄은 `package-lock.json`이다.

| 항목       | 값                                   |
| ---------- | ------------------------------------ |
| 빌드       | `react-scripts` 5.0.1 (CRA)          |
| React      | 18.3.1                               |
| TypeScript | 4.9.5                                |
| 그 밖      | react-toastify, Tailwind 3.4(개발용) |
| 시험       | CRA가 만들어 준 `App.test.tsx` 하나  |

## script.js를 컴포넌트로

같은 커밋에서 `script.js` 455줄을 Dock, DockItem, StatusBar, Safari, MusicPlayer 컴포넌트로 나눴다. 그림은 `public/imgs/`로 옮기고 주소는 `REACT_APP_IMAGE_URL` 환경 변수로 받았다. 공유 버튼은 주소를 복사하고 토스트를 띄우는 `clipboardHelpers.ts`가 되었다.

## Dock 다시 짜기

12일 새벽 3시 24분 커밋에서 Dock을 다시 짰다(커밋 메시지의 "docker"는 Dock이다). 앱 12칸의 목록을 코드에 두고, 화면 폭에 따라 Dock 폭을 95%·85%·70%로 바꿨다. 아이콘은 lucide-react를 들였다.

## 음악 플레이어를 React로

12일 아침 7시 29분 커밋에서 음악 플레이어를 React로 옮겼다. jQuery 선택자 대신 `useRef`로 audio·재생 막대·앨범 표지를 잡고, 재생 여부·현재 시각·곡 번호를 `useState`로 들었다. 컴포넌트 하나가 282줄이었다.

![10월 12일의 src 구조](./images/day-20241011-structure.svg '창 열고 닫기를 맡는 곳이 아직 없어서 앱마다 따로 했다')

## 지금과 비교하면

- **빌드 도구**: CRA는 2025년 3월에 Vite로 바꿨다([2025년 3월 23~24일 회고](/memo/day-20250323), [CRA에서 Vite로](/memo/cra-to-vite)).
- **Dock 폭**: 화면 폭을 세 구간으로 나눠 퍼센트를 고르던 방식은 Dock이 앱 칸만큼 넓어지는 한 줄로 바뀌었다([Dock 배치](/memo/dock-layout)).
- **시험**: CRA 기본 시험 하나에서, 지금은 브라우저 E2E와 단위 시험이 천 개를 넘는다([테스트를 붙이자 보인 버그들](/memo/bugs-found-by-tests)).

## 돌아보며

옮기기는 컴포넌트를 나누는 데서 멈췄다. 창을 열고 닫는 상태를 어디서 들고 있을지 정하지 않아서, 13일 아침 [AppContext](/memo/day-20241013)가 생기기 전까지는 앱마다 자기 창을 따로 다뤘다. 상태를 어디에 둘지를 먼저 정했다면 이튿날의 손질은 줄었을 것이다.
