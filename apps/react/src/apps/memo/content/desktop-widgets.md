바탕화면에는 폴더 아이콘 셋만 있었고, 휴대폰 홈 화면에는 소개와 음악 위젯 둘이 고정되어 있었다. macOS Sonoma부터는 위젯을 바탕화면에 바로 놓는다. 이 사이트도 그렇게 했다.

![바탕화면 위젯](./images/desktop-widgets-desktop.jpg '날씨·캘린더(작게)와 GitHub 잔디(중간), 그 아래 음악(중간)·사진·시계(작게), 최근 글(중간). 창·Dock 아래, 폴더 아이콘 위 층이다. 잔디는 E2E의 가짜 API 자료, 사진은 그림 폴더에 올린 배경화면 두 장이다')

## 위젯 여덟 가지, 화면 둘

위젯은 데스크톱과 휴대폰이 같은 부품(`desktop/widgets/Widget.tsx`)을 쓴다. 크기는 둘이다. 작게는 정사각형, 중간은 가로로 두 칸이다.

| 위젯    | 크기      | 내용                                                  | 누르면    |
| ------- | --------- | ----------------------------------------------------- | --------- |
| 날씨    | 작게·중간 | 날씨 앱의 첫 도시. 중간은 시간별 4칸까지              | 날씨 앱   |
| 캘린더  | 작게·중간 | 서울 기준 오늘. 중간은 이달 달력까지                  | -         |
| 시계    | 작게      | 바늘 시계 (서울)                                      | -         |
| 음악    | 중간·작게 | 지금 재생 중인 곡과 재생 단추                         | 음악 앱   |
| 최근 글 | 중간·작게 | 메모의 최근 글 3편 (작게는 2편)                       | 그 글     |
| 사진    | 작게·중간 | 고른 앨범·그림 폴더의 그림을 10초마다 넘긴다          | 사진 앱   |
| GitHub  | 중간·작게 | 지난 1년 기여 그래프(잔디)와 연속 기록. 들어가는 주만 | GitHub 앱 |
| 소개    | 중간      | 이름·하는 일·지역 (예전 휴대폰 소개 위젯)             | -         |

위젯의 빈 곳을 누르면 그 앱이 열린다. 단추·글처럼 누를 것이 있는 자리는 그것만 동작한다.

## 모양: 배경화면이 비치는 유리

![라이트·다크 모드의 유리 위젯](./images/desktop-widgets-glass.jpg '왼쪽은 라이트, 오른쪽은 다크. 시계·음악·잔디는 배경화면이 흐리게 비치는 유리, 캘린더·최근 글은 불투명한 판, 날씨는 불투명한 하늘 색')

모양은 네 번 바꿨다. 처음에는 알림처럼 반투명한 판이었는데, 흐림 없이 색만 비쳐서 위젯마다 분홍빛이 탁하게 돌았다. 그래서 macOS 바탕화면의 기본 위젯처럼 불투명한 흰 판으로 바꿨다. 깔끔했지만 이 사이트의 Dock·메뉴 막대·제어 센터는 다 유리인데 위젯만 종이 같았다. 그래서 유리로 맞췄다. 그런데 모두 유리로 하니 글이 많은 위젯이 읽기 어려웠다. 마지막으로 **읽는 위젯은 불투명하게, 보는 위젯은 유리로** 나눴다. 실제 macOS도 메모·캘린더처럼 글이 많은 위젯은 거의 불투명하다.

불투명한 판은 납작해 보여서 그림자와 그라데이션으로 두께를 줬다. 모든 위젯의 그림자는 가까운 짙은 그림자와 먼 옅은 그림자를 네 겹 겹친 `--shadow-lifted`다. 한 겹이면 판이 바탕에 붙어 보이고, 겹치면 조금 들린 것처럼 보인다. 캘린더·메모 판은 위가 흰색이고 아래로 조금 어두워지며(다크는 회색 700 → 850), 윗변에 1px 빛과 아랫변에 1px 그늘을 `inset` 그림자로 둔다. 날씨는 하늘 색 위쪽에 옅은 흰빛을 둥글게 번지게 하고, 메모 머리띠는 위가 조금 밝은 노랑이며, 캘린더의 오늘 동그라미에도 작은 그림자를 줬다.

- **판(시계·음악·사진·GitHub·소개):** 머티리얼 토큰 `--color-material-widget`(라이트는 흰색 48%, 다크는 짙은 회색 45%)에 `backdrop-filter: blur(28px) saturate(170%)`. 처음 반투명 판이 탁했던 까닭은 흐림이 없어서였다. 뒤를 충분히 흐리고 채도를 올리면 배경화면 색이 맑게 번진다. 가장자리에는 `inset` 그림자로 1px 빛(`--color-material-widget-edge`)을 둘러 판의 경계를 잡는다
- **날씨:** 날씨 앱의 하늘 색(맑은 낮, 밤, 흐림, 비, 눈…) 그라데이션을 불투명하게 칠한다. 처음엔 하늘 색도 78%만 칠했는데, 노을 배경화면 위에서 맑은 밤하늘이 탁한 보라가 되었다. 하늘 색이 곧 날씨라 비치게 두지 않았다
- **캘린더:** 비치지 않는 판(`--widget-background-solid`, 팝오버와 같은 흰 판, 다크 모드는 어두운 판)이다. 흐림도 끈다. 9~11px 숫자가 빽빽해, 산이나 노을처럼 무늬 있는 배경화면 위에서는 흐림이 있어도 주말의 흐린 숫자가 잘 읽히지 않았다. 처음에는 88%만 칠해 유리 느낌을 조금 남겼는데, 그래도 비쳐서 아예 불투명하게 했다. 작게도 이달 달력이고, 오늘은 진한 동그라미, 주말은 흐리게. 동그라미 안 글자는 예전에 판 색(`--widget-background`)을 썼는데, 판이 반투명해지자 글자도 비쳤다. 창 바탕 색(`--widget-on-label`)으로 바꿨다
- **최근 글:** 캘린더와 같은 불투명한 판. 메모 위젯처럼 불투명한 노란 머리띠(폴더 아이콘과 이름) 아래 점선, 그 아래 한 줄씩 구분선과 날짜. 반투명했을 때는 머리띠가 판 위에 떠 보이고 줄글 제목이 배경과 겹쳤다
- **GitHub 잔디:** GitHub처럼 정사각형 칸을 같은 간격으로 두고, 칸 크기는 위젯 높이에서 정해 일곱 줄이 꼭 맞게 한다. 1년 치를 그리되 최근 주부터 오른쪽에 놓고, 다 들어가지 않는 옛 주는 다음 줄로 넘겨 가린다. 그래서 위젯이 넓으면 더 많은 주가 보이고, 반쯤 잘린 열이 없다. 칸은 macOS 초록 단계의 둥근 사각형이고, 가장 많이 한 날에는 새싹이 돋는다(이 사이트의 새싹 농장처럼). 기여가 없는 날의 칸은 글자 색을 9% 섞은 반투명이라 유리 위에서도 칸이 보인다

## 데스크톱: 180px 칸 격자

![칸 격자와 놓기 규칙](./images/desktop-widgets-grid.svg '데스크톱은 칸에 붙여 놓고, 휴대폰은 페이지마다 위젯 세 줄까지')

자리는 픽셀이 아니라 칸으로 다룬다. 작은 위젯이 164px, 사이가 16px이라 한 칸은 180px이다. 중간 위젯은 두 칸에 사이 하나를 더해 344px이다. 1440×900 화면이면 메뉴 막대와 Dock을 뺀 높이에 가로 7칸, 세로 4줄이 들어간다(`gridOf`).

바탕화면 아이콘은 오른쪽 위부터 놓이므로 위젯은 macOS처럼 왼쪽 위부터 놓는다. 저장도 칸으로 한다(`macfolio:desktop:widgets`). 칸으로 저장하면 창 크기가 바뀌어도 같은 자리에 남는다.

- **끌어 옮기기**: 4px 넘게 움직이면 끌기다. 놓은 자리에서 가장 가까운 칸이 비어 있으면 거기에 붙고, 다른 위젯과 겹치면 놓기 전 자리로 돌아간다(`dropAt`). macOS도 위젯을 밀어내지 않는다. 끌기를 끝낸 위젯은 클릭으로 치지 않아 앱이 열리지 않는다.
- **크기 바꾸기**: 오른쪽 클릭 메뉴의 작게·중간. 그 자리에서 커질 수 없으면 빈 칸으로 옮기고, 빈 칸도 없으면 그대로 둔다(`resize`).
- **창을 줄였을 때**: 칸 밖으로 나간 위젯은 빈 칸에 그리고, 빈 칸도 없으면 그리지 않는다(`visibleLayout`). 저장한 값은 바꾸지 않는다. 창을 다시 키우면 원래 자리로 돌아온다.

층은 폴더 아이콘 위, 창 아래다. 위젯 층은 화면 전체를 덮지만 `pointer-events: none`이고 위젯만 포인터를 받는다. 빈 곳을 끌면 그 아래 아이콘 층이 받아 사각형 고르기가 그대로 된다.

## 위젯 편집…

![위젯 갤러리](./images/desktop-widgets-gallery.jpg '바탕화면 메뉴의 위젯 편집…. 왼쪽은 찾기와 위젯 종류, 오른쪽은 실제 위젯 미리보기. 올리면 왼쪽 위에 초록 + 가 뜨고, 누르면 빈 칸에 놓인다')

바탕화면을 오른쪽 클릭하면 **위젯 편집…**이 있다. macOS의 위젯 갤러리처럼 화면 아래 가장자리에서 유리 시트가 올라온다. 위 두 모서리만 둥글고 아래는 화면 밖으로 이어져, 화면 바닥에 묻힌 것처럼 보인다. 왼쪽 사이드바에는 위젯 검색 칸과 위젯 종류(모든 위젯, 날씨, 캘린더 …)가 앱 아이콘과 함께 있고, 오른쪽에는 고른 종류의 크기마다 실제 위젯을 그대로 그린 미리보기가 있다. 처음에는 모든 위젯을 '제안'으로 보인다. 미리보기는 `inert`로 감싸 누를 수 없게 했다. 미리보기에 올리면 조금 떠오르며 왼쪽 위에 초록 +가 뜬다. 누르면 그 미리보기가 시트 위로 떠올라 비어 있는 첫 칸(위 줄부터, 왼쪽부터)까지 날아가 내려앉는다. 편집 중에는 바탕화면의 위젯마다 왼쪽 위에 지우기(−) 단추가 생긴다. 아래 줄의 완료나 Esc로 끝낸다.

![갤러리에서 바탕화면으로 날아가는 시계 위젯](./images/desktop-widgets-flight.jpg '시계 위젯(작게)을 누르면 미리보기 자리에서 떠올라 위 줄의 빈 칸으로 날아간다')

날기는 Web Animations API(`element.animate`)로 한다. 누른 미리보기의 화면 자리와 갈 칸의 자리(`cellToPoint` + 위젯 층의 위치)의 차이만큼 옮기고, 70% 지점에서 6% 커졌다가 내려앉는다. 나는 동안은 갤러리 시트보다 위 층(`--z-widget-flight`)에 겉모습만 그리고(`inert`, `aria-hidden`), 끝나면 그때 저장해 진짜 위젯으로 바꾼다. 날고 있는 동안 또 누르면 받지 않는다. 움직임 줄이기를 켰으면 날지 않고 바로 놓는다.

사이드바의 '모든 위젯' 아이콘은 macOS처럼 바탕 없는 선 그림이다. 작은 위젯 둘과 세로로 긴 위젯 하나를 SVG로 그렸다.

처음 갤러리는 미리보기를 가로로 늘어놓고 넘치면 옆으로 스크롤했다. 그런데 미리보기에 올리면 커지는 효과가 위쪽에서 잘렸다. `overflow-x: auto`를 주면 세로도 `visible`일 수 없어서(`auto`가 된다) 목록 상자 밖으로 나간 부분이 잘린다. 지금은 세로로 스크롤하는 격자에 넉넉한 안쪽 여백을 둬서, 커지는 위젯과 +가 그 안에 들어온다.

## 휴대폰: 페이지마다 위, 길게 눌러 편집

![휴대폰 위젯](./images/desktop-widgets-mobile.jpg 'iPhone SE 크기. 왼쪽부터 1쪽의 소개·GitHub 잔디, 3쪽의 최근 글·사진(그림 폴더)·시계, 편집 중 사진 위젯의 앨범 시트(앨범과 그림 폴더)')

홈 화면 1~3쪽의 위에 위젯을 둔다. 1쪽은 소개와 GitHub 잔디, 2쪽은 날씨·캘린더·음악, 3쪽은 최근 글·사진·시계다. iOS처럼 작은 위젯은 아이콘 두 칸 폭, 중간 위젯은 한 줄을 다 쓴다.

앱 아이콘은 위젯 아래 남는 줄에 들어가고, 넘치면 다음 페이지로 간다. 원래는 첫 페이지만 위젯이 있어서 페이지 나누기(`pageApps`)가 "첫 페이지 칸 수, 나머지 칸 수" 둘만 받았다. 이제는 위젯이 있는 페이지마다 칸 수를 따로 받는다. 위젯 묶음의 높이를 `ResizeObserver`로 재고, 위젯 페이지는 앱이 모자라도 만든다.

편집은 iOS와 같은 몸짓이다. 홈 화면을 움직이지 않고 0.55초 누르면 편집이 된다. 위젯과 아이콘이 떨리고, 위젯마다 − 단추가 생기고, 그동안은 앱이 열리지 않는다. +는 아래에서 올라오는 갤러리 시트를 연다. 시트는 iOS처럼 화면의 아래 4/5만 덮어, 위에 남은 흐린 홈 화면을 누르면 닫힌다(처음에는 상태 표시줄 아래까지 다 덮어서 바깥을 누를 곳이 없었다).

한 페이지에는 위젯을 세 줄까지 둔다(작은 위젯 둘이 한 줄, 중간 위젯은 혼자 한 줄). 지금 페이지가 차 있으면 자리가 있는 첫 페이지에 더하고 그 페이지로 넘어간다. 어디에도 자리가 없는 크기는 갤러리에서 누를 수 없다. 구성은 `macfolio:mobile:widgets`에 남고, 휴지통의 '내 브라우저 데이터'에서 바탕화면 위젯과 함께 지운다.

사진 위젯은 앨범을 고른다. 데스크톱은 오른쪽 클릭 메뉴의 '앨범' 묶음에서, 휴대폰은 편집 중에 위젯 오른쪽 아래의 '앨범' 단추로 연 시트에서 고른다. 고른 앨범은 위젯과 함께 저장한다. 없어진 앨범이면 모든 앨범을 보인다.

## 사진 위젯에 내 사진: Finder › 그림의 폴더

![사진 위젯의 그림 폴더](./images/desktop-widgets-album.jpg '사진 위젯의 오른쪽 클릭 메뉴. 사진 앱의 앨범 아래 그림 폴더 묶음이 있고, 그림에 만든 위젯 폴더를 골랐다')

사진 위젯의 앨범은 사진 앱의 앨범, 곧 프로젝트 화면뿐이었다. 위젯에 걸 사진을 내가 따로 올릴 곳이 필요했다. macOS라면 사진은 홈의 그림 폴더에 둔다. 이 사이트의 Finder에도 그림 폴더가 있지만, 사진 앱의 앨범을 보여 주기만 하고 아무것도 올릴 수 없었다.

그래서 그림 폴더를 진짜 폴더로 열었다.

- **올리기:** 문서 폴더 값에 `그림`을 더했다. R2 키는 `pictures/…`다. 서버는 zod 계약(`DocumentUploadRequest`)과 키 모양으로 확인하고, DB에는 폴더와 키의 짝을 지키는 CHECK 제약을 새 마이그레이션으로 다시 건다(`'그림'`이면 키가 `pictures/`로 시작해야 한다). 바탕화면 폴더 값을 더할 때와 같은 방식이다
- **새 폴더:** Finder 구조의 기본 상위 폴더(`FINDER_BUILTIN_PARENT`)에 `pictures`를 더했다. 그림 안에 폴더를 만들고 올린 그림을 끌어 넣을 수 있다. 사진 앱의 앨범 폴더(`pictures/<앨범>`)는 그대로 읽기만 한다
- **위젯이 고르는 곳:** 위젯은 올린 파일 목록과 Finder 구조로 그림 폴더 트리만 다시 만든다(`folderSources`). 그림 폴더 바로 안의 그림, 그리고 그 안에 만든 폴더마다 하나씩이다. 안쪽 폴더는 `위젯 › 여름`처럼 이름을 잇는다. 고른 값은 앨범 id 자리에 `folder:<id>`로 저장하고, 폴더를 지우면 모든 앨범으로 돌아간다

Finder 트리 전체(블로그 글 목록까지)를 부르면 위젯 하나 때문에 글 목록을 받게 된다. 그래서 위젯은 같은 `buildTree`에 문서 파일과 구조만 넣는다. 데스크톱 Finder와 규칙은 같고, 받는 자료는 적다.

## 휴대폰에서 Finder 편집이 되지 않았다

그림에 폴더를 만들려고 휴대폰 파일 앱을 열었더니 새 폴더도, 이름 변경도, 휴지통도 없었다. 처음에 휴대폰 파일 앱은 같은 트리를 읽기만 하게 만들었기 때문이다. 바탕화면에서는 관리자로 로그인하지 않으면 메뉴가 흐리기만 하고 까닭을 말하지 않아서, 어디서도 되지 않는 것처럼 보였다.

![휴대폰 파일 앱의 편집](./images/desktop-widgets-files.jpg '왼쪽은 그림 폴더의 ••• 메뉴(새 폴더, 사진 올리기), 오른쪽은 위젯 폴더를 길게 누른 메뉴')

- **••• 메뉴:** 폴더 안이면 맨 위에 새 폴더와 파일 올리기(그림 폴더는 사진 올리기)가 있다. 올리기는 숨겨 둔 `<input type="file">`을 열고, 데스크톱에서 끌어다 놓을 때와 같은 `uploadInto`로 올린다
- **길게 누르기:** iOS 파일 앱처럼 항목을 0.5초 누르면 메뉴(열기, 이름 변경, 휴지통으로 이동)가 항목 아래에 뜬다. 손가락이 8px 넘게 움직이면 넘기기로 보고 취소한다. 메뉴를 띄운 뒤의 손 떼기는 항목을 열지 않는다
- **즐겨찾기에 그림:** 휴대폰에는 홈 폴더로 가는 길이 없어서 둘러보기의 즐겨찾기에 그림을 더했다
- **방문자:** 흐린 메뉴 아래에 "관리자로 로그인하면 편집할 수 있습니다."를 보인다. 데스크톱의 바탕화면·Finder 오른쪽 클릭 메뉴도 같다

편집은 데스크톱과 같은 `useFinderEdit`이 맡는다. 저장하는 구조도 같아서, 휴대폰에서 만든 폴더가 바탕화면 Finder에도 바로 보인다.

시험하다 버그를 둘 더 찾았다.

**같은 이름을 두 번 버리면 휴지통이 거절했다.** 실제 API로 폴더를 만들고 휴지통에 넣기를 두 번 했더니 두 번째에 `PUT /finder/layout`이 400이었다. 휴지통도 구조 안에서는 상위 폴더 하나(`trash`)라, "같은 폴더 안에 같은 이름의 폴더는 둘일 수 없다"는 규칙에 걸렸다. 화면에는 "저장하지 못함" 알림이 뜨고 폴더가 제자리로 돌아왔다. macOS 휴지통은 같은 이름을 몇 번이든 받는다. 그래서 휴지통 안은 이름 규칙에서 뺐다(`finderLayoutErrors`). 대신 되돌릴 때 그 사이 같은 이름이 생겼으면 `작업 2`처럼 번호를 붙인다(`putBackChange`). 번호를 고르는 `untitledName`이 대소문자를 가리지 않는다면서 첫 이름만은 그대로 비교하던 것도 함께 고쳤다.

**가상본 화살표가 화면 아래에 크게 떴다.** 휴대폰 파일 앱의 데스크탑 폴더에서 이력서·포트폴리오·자격증 가상본의 화살표가 아이콘이 아니라 화면 왼쪽 아래에 손바닥만 하게 그려져 있었다. 화살표는 `position: absolute`인데 휴대폰 아이콘 칸에 기준(`position: relative`)이 없어 화면까지 올라갔다. 칸에 기준을 주고 크기를 칸에 맞췄다.

## 작은 휴대폰에서 앱이 잘렸다

처음에는 위젯을 iOS처럼 늘 정사각형으로 두었다. PR 미리보기를 휴대폰으로 열어 보니 위젯 아래 앱이 잘려 있었다. WebKit의 iPhone 화면 크기로 재 보니 이랬다.

| 화면 (Playwright 기기) | 위젯 한 줄 | 1쪽 앱 칸 높이 / 내용 높이 | 1쪽 앱 수 |
| ---------------------- | ---------- | -------------------------- | --------- |
| iPhone SE (320×568)    | 129px      | 66px / 81px (잘림)         | 4         |
| iPhone 13 (390×664)    | 154px      | 112px / 112px              | 4         |
| iPhone 15 Pro Max      | 168px      | 158px / 158px              | 4         |

앱 한 줄이 81px인데 iPhone SE에는 66px만 남았다. 페이지 나누기는 적어도 한 줄은 놓으므로, 그 한 줄이 아래로 잘렸다. 잘리지 않는 기기에서도 1쪽에 앱이 네 개뿐이었다.

그래서 위젯 줄의 높이를 화면에서 정한다(`widgetRowHeight`). 정사각형이 기본이고, 위젯 아래에 아이콘 두 줄이 들어가지 않으면 그만큼 줄인다. 다만 112px보다는 줄이지 않는다. 위젯 줄 수가 가장 많은 페이지에 맞춰 모든 페이지가 같은 높이를 쓴다. 고친 뒤는 이렇다.

| 화면              | 위젯 한 줄 | 1쪽 앱 칸 높이 / 내용 높이 | 1쪽 앱 수 |
| ----------------- | ---------- | -------------------------- | --------- |
| iPhone SE         | 112px      | 99px / 99px                | 4         |
| iPhone 13         | 117px      | 185px / 185px              | 8         |
| iPhone 15 Pro Max | 155px      | 184px / 184px              | 8         |

위젯이 낮아지면 내용도 줄여야 한다. 위젯 상자에 `container-type: size`를 주고 높이로 컨테이너 질의를 건다. 안쪽 높이가 낮아지면 날씨는 아이콘을 빼고 기온 글자를 줄이고(120px 아래), 최근 글은 셋째 글을 반쯤 잘라 보이지 않고 뺀다(130px 아래). 데스크톱 위젯의 안쪽은 136px이라 어느 쪽에도 걸리지 않는다.

## 최근 글: 2.5MB 대신 6편

최근 글 위젯은 첫 화면에 바로 보인다. 그런데 글 목록은 메모 앱이 열릴 때 불러오는 묶음 안에 있었다. 검색 로봇용으로 빌드하는 `seo/posts.json`도 본문 HTML까지 담아 2,537,133바이트였다.

그래서 빌드할 때 작은 모듈을 하나 더 만든다(`virtual:recent-posts`). 저장소 글 중 날짜가 지난 최신 6편의 제목·날짜·분류만 넣는다. 개발 서버에서는 글 파일을 지켜보다가 바뀌면 다시 만든다.

관리자가 사이트에서 쓴 글은 빌드에 없다. 위젯이 처음 그려질 때 `GET /posts`를 한 번 묻고, 메모 앱과 같은 규칙으로 합친다(`mergeRecentPosts`). 같은 주소는 서버 글이 대신하고, 지운 글과 예약 글은 저장소 글까지 가린다. 데스크톱과 휴대폰의 위젯이 여럿이어도 묻는 것은 페이지마다 한 번이다.

## 날씨를 두 번 묻지 않게

날씨 위젯을 처음 붙였을 때 날씨 앱의 E2E 시험이 걸릴 자리가 보였다. 날씨 시험은 Open-Meteo를 가짜로 바꾸고, 날씨 앱을 연 뒤 일기예보를 몇 번 물었는지 센다.

```ts
expect(asked.forecast).toEqual(['37.5665']);
```

바탕화면의 날씨 위젯이 서울을 먼저 묻고 날씨 앱이 또 물으면 두 번이 된다. 시험만 고칠 일이 아니었다. 같은 도시를 같은 단위로 두 곳에서 따로 묻는 것 자체가 낭비다.

`useForecasts`가 장소·단위마다 받은 응답을 15분 동안 들고 있게 바꿨다. 위젯과 날씨 앱이 같은 응답을 나눠 쓴다.

- **실패**: 10초만 기억한다. 여럿이 동시에 다시 묻지는 않고, 오래 실패한 채로 남지도 않는다.
- **'다시 시도'**: 남은 값과 상관없이 새로 묻는다. 날씨 앱의 "실패하면 다시 시도로 한 번 더 묻는다" 시험도 그대로 통과한다.

다른 시험들이 바깥 날씨 서버에 닿지 않게, E2E의 기본 설정에서 Open-Meteo를 503으로 막았다. 날씨가 필요한 시험은 지금처럼 가짜 응답(`fakeWeather`)을 건다. Playwright는 나중에 건 경로를 먼저 쓰기 때문이다.

## 헛디딘 곳 넷

**시계 숫자가 돌아갔다.** 처음에는 숫자 열둘을 시계 가운데에 겹쳐 놓고 각자 `rotate(n × 30deg)`로 돌렸다. 숫자는 제자리에 갔지만 글자도 같이 돌아서 6이 거꾸로 섰다.

고친 방법은 이렇다. 가운데에서 그 방향으로 돌리고(`rotate`), 반지름만큼 나간 뒤(`translateY`), 다시 반대로 돌려(`rotate(-…)`) 글자를 세운다. 반지름은 시계 판 폭의 비율이라, 판에 `container-type: inline-size`를 주고 `-38cqw`로 썼다.

**휴대폰에서 시계가 잘렸다.** 시계 판은 위젯 폭의 78%인 정사각형이다. 작은 휴대폰에서 위젯 줄을 112px까지 낮추자 판이 높이를 넘쳐 아래 숫자와 도시 이름이 잘렸다. 판의 크기를 폭과 높이 가운데 작은 쪽으로 정한다. 시계 몸통에 `container-type: size`를 주고 `width: min(78cqw, calc(100cqh - 1.4em - var(--space-4)))`로 도시 이름 한 줄을 뺀 높이에 맞춘다. 판 안의 숫자는 판 폭(`cqw`) 기준이라 같이 줄어든다.

**떨리는 위젯이 상태 표시줄 아래에서 잘렸다.** 휴대폰 편집 중에 위젯이 ±0.8° 떨면 모서리가 위로 몇 px 나가고, 왼쪽 위 − 단추는 처음부터 위젯 밖으로 반쯤 나와 있다. 페이지 묶음(`.mobile-pages`)은 옆으로 넘기기 때문에 `overflow: hidden`이라, 맨 윗줄 위젯의 − 단추 위쪽과 모서리가 잘렸다. 묶음의 위쪽 안쪽 여백을 16px 주고 같은 만큼 바깥 여백을 빼서, 내용 자리는 그대로 두고 자르는 선만 위로 올렸다. 위젯 줄 높이를 잴 때는 그 안쪽 여백을 뺀다.

**편집 단추를 누를 수 없었다.** iOS는 편집 중에 +와 완료를 상태 표시줄 자리에 둔다. 그대로 따라 맨 위에 두었는데, Playwright로 누르자 이렇게 나왔다.

```text
<div role="button" aria-label="제어 센터 열기" class="mobile-statusbar …">…</div> intercepts pointer events
```

이 사이트의 휴대폰 상태 표시줄은 제어 센터를 여는 단추라 늘 맨 위 층에 있다. 그래서 +와 완료를 아래 페이지 점 줄의 양옆으로 옮겼다. 손가락이 닿기에도 아래가 가깝다.

## 시험

- **단위 시험:** 칸 계산(빈 칸 찾기, 놓기, 크기 바꾸기, 화면을 줄였을 때), 저장 형식 읽기(틀린 종류·크기·겹친 id·넘치는 줄은 빼고, 앨범은 남긴다), 휴대폰 위젯 줄 수·더할 페이지·줄 높이, 달력 칸, 시계 바늘 각도, 날짜 글자, 서버 글 합치기, 페이지 나누기
- **단위 시험(그림 폴더·휴지통):** 그림의 폴더 값·키·구조 규칙(contracts), 그림 폴더에 새 폴더와 올리기 자리(앨범 폴더는 안 된다), 사진 위젯이 고르는 곳(바로 안의 그림, 만든 폴더, 다른 곳에서 옮겨 온 그림), 휴지통의 같은 이름과 되돌릴 때 번호, API의 `pictures/` 키 확인
- **E2E 시험(데스크톱 8개):** 처음 모양, GitHub 잔디(20주·8주), 글·앱 열기, 끌어 옮기기와 새로고침 뒤 자리, 크기·지우기, 사진 위젯의 앨범, 그림 폴더를 고른 사진 위젯, 위젯 편집
- **E2E 시험(휴대폰 9개, iPhone·Android):** 페이지마다 위젯과 크기, GitHub 잔디, 위젯 아래 앱 두 줄이 잘리지 않는지, 글 열기, 길게 눌러 빼고 더하기와 저장, 자리가 없을 때, 사진 위젯의 앨범, 파일 앱에서 그림에 새 폴더·이름 변경·휴지통(관리자), 흐린 메뉴와 안내(방문자). 휴대폰 전용 시험 파일은 이름이 `mobile-`로 시작하면 휴대폰 프로젝트에서만 돈다(Playwright 설정의 `testMatch`)

## 남은 것

- 휴대폰 위젯은 빼고 더하기만 된다. 순서 바꾸기와 크기 바꾸기는 데스크톱만 된다.
- 최근 글의 저장소 글은 빌드할 때의 목록이다. 날짜가 미래인 저장소 글은 다음 배포에서 들어온다.
- 휴대폰 파일 앱은 끌어서 옮기기가 없다. 올린 그림을 다른 폴더로 옮기는 일은 데스크톱 Finder에서 한다.
