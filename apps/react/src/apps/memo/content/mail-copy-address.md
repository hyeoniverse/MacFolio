메일 앱의 새로운 메시지에는 받는 사람이 `김정현 <hyeoniverse.dev@gmail.com>`으로 정해져 있다. 이 사이트에서 메일을 보내지 않고 자기 메일 앱으로 보내고 싶은 사람도 있는데, 지금까지는 주소를 직접 골라 복사해야 했다. macOS 메일에서는 주소 칩을 눌러 '이메일 주소 복사'를 고른다. 여기서는 한 번 누르면 바로 복사되게 했다.

## 어디서

세 자리에 같은 버튼 `apps/mail/components/CopyAddress.tsx`를 둔다. `withName`이 거짓이면 이름 없이 주소만 보인다(읽기 화면처럼 이름이 이미 위에 있을 때).

| 곳                         | 보이는 것                            |
| -------------------------- | ------------------------------------ |
| 새로운 메시지의 받는 사람  | `김정현 <hyeoniverse.dev@gmail.com>` |
| 환영 메일의 보낸 사람 주소 | `hyeoniverse.dev@gmail.com`          |
| 보낸 메일의 받는 사람      | `김정현 <hyeoniverse.dev@gmail.com>` |

어디서 누르든 복사되는 것은 **주소만**(`hyeoniverse.dev@gmail.com`)이다. 이름까지 붙은 글자는 메일 앱의 받는 사람 칸에 붙여 넣으면 형식에 따라 받지 않을 수 있다.

휴대폰의 쓰기 시트도 같은 화면(`ComposeView`)을 써서 똑같이 된다.

```tsx
async function copyEmail() {
	const { email } = getProfile();
	try {
		await navigator.clipboard.writeText(email);
		notify({ app: 'mail', title: '이메일 주소 복사됨', body: email });
	} catch {
		notify({ app: 'mail', title: '이메일 주소를 복사하지 못했습니다', body: email });
	}
}
```

버튼의 접근성 이름은 `김정현 <hyeoniverse.dev@gmail.com> (눌러서 이메일 주소 복사)`이다. 화면 읽기 프로그램이 주소를 읽고 무엇을 하는 버튼인지 함께 알려 준다. 마우스를 올리면 `title`로 같은 안내가 뜬다.

## 모양

- 마우스 모양은 복사(`cursor: copy`)이고, 올리면 옅은 밑줄이 생긴다. 받는 사람 칩은 바탕이 조금 진해진다.
- 누르면 macOS 알림처럼 오른쪽 위(휴대폰은 위쪽 가운데)에 `이메일 주소 복사됨 · hyeoniverse.dev@gmail.com` 배너가 뜬다. 클립보드에 쓰지 못하면 `이메일 주소를 복사하지 못했습니다`가 뜬다.

처음에는 누른 자리 위에 잠깐 뜨는 검은 말풍선을 따로 만들었다. 메모의 코드 블록 복사 버튼을 보고 따라 한 것이다. 그런데 이 사이트는 공유 앱의 '링크 복사됨', 앱 항목 주소의 '링크를 복사했습니다'처럼 **복사는 알림(`notify`)으로** 알리고 있었다. 같은 "복사했다"가 두 모양이 되는 것보다 한 모양이 낫다. 말풍선은 휴대폰 시트의 잘리는 칸 밖으로 꺼내는 손질까지 필요했는데, 알림은 그런 것이 없다. 그래서 말풍선을 빼고 알림으로 바꿨다.

| 방법                                         | 좋은 점                                             | 걸리는 점                                                                     |
| -------------------------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------- |
| macOS처럼 주소 칩에 메뉴('이메일 주소 복사') | 실제 메일 앱과 같다                                 | 한 번 더 눌러야 하고, 메뉴에 다른 항목이 없다                                 |
| 누른 자리 위 말풍선 '복사했어요'             | 누른 곳 바로 위라 눈에 띈다                         | 사이트의 다른 복사와 모양이 다르고, 휴대폰 시트 밖으로 꺼내는 손질이 필요하다 |
| **사이트 알림(`notify`)**                    | 공유·링크 복사와 같은 모양, 실패도 같은 길로 알린다 | 누른 곳과 알림이 떨어져 있다                                                  |

말풍선 코드는 상태(`copied`)와 1.6초 타이머, CSS 35줄 가까이였다. 알림으로 바꾸며 이것이 모두 빠져, 두 번째 커밋은 40줄 더하고 85줄 지웠다. 첫 커밋(197줄 더하기)과 합쳐 보면 한 번 만들고 반쯤 걷어 낸 셈이다. 비슷한 일을 이미 어떻게 하고 있는지 먼저 찾아봤으면 한 번에 끝났을 일이다.

## 누르지 못하던 곳

처음 만든 뒤 환영 메일의 주소를 누르는 시험이 시간 초과로 실패했다. Playwright 기록을 보면 `macos-titlebar intercepts pointer events`였다. 메일 앱은 제목 표시줄 없는 창(`chrome="unified"`)이라, 창 위쪽 52px에 투명한 끌기 자리(z-index 3)가 내용 위에 덮여 있다. 읽기 칸의 머리(보낸 사람 줄)가 마침 그 높이에 있었다. 이 자리에 두는 버튼은 z-index를 올려야 누를 수 있다는 규칙(`Window.css`의 설명)대로 주소 버튼을 `z-index: 4`로 올렸다.

![창 위쪽의 끌기 자리와 주소 버튼](./images/mail-copy-address-layers.svg '투명한 끌기 자리가 위쪽 52px를 덮고 있어, 그 높이의 버튼은 z-index를 올려야 눌린다')

눈으로는 보이는 버튼이 눌리지 않는 버그라, 손으로 눌러 봤으면 "가끔 안 눌린다" 정도로 지나쳤을 수 있다. Playwright는 누르기 전에 그 자리 맨 위에 무엇이 있는지 확인하고, 다른 요소가 가리면 기다리다 실패하며 가린 요소 이름을 알려 준다. 이번에는 그 메시지가 원인을 바로 짚었다.

## 시험

- 환영 메일의 보낸 사람 주소를 누르면 클립보드에 주소가 들어가고 `이메일 주소 복사됨` 알림이 뜬다 (닫기 버튼으로 닫힌다)
- 새로운 메시지의 받는 사람을 누르면 이름 없이 주소만 복사된다
- 보낸 메일의 받는 사람 줄은 그대로 `받는 사람: 김정현 <hyeoniverse.dev@gmail.com>`으로 읽힌다

위 셋은 `e2e/mail.spec.ts`의 "사이트 주인의 주소를 누르면 이메일 주소를 복사한다 (새로운 메시지의 받는 사람, 환영 메일의 보낸 사람)" 하나에 들어 있다. 클립보드는 Playwright에 `clipboard-read`·`clipboard-write` 권한을 주고 `navigator.clipboard.readText()`로 읽어 확인한다.

## 남은 것·배운 것

- 복사할 수 있다는 것이 눈에 잘 띄지 않는다. 마우스 모양과 옅은 밑줄뿐이라, 휴대폰에서는 누르기 전에는 알 수 없다.
- 클립보드 쓰기는 보안 문맥(HTTPS)과 사용자 동작 안에서만 된다. 실패하면 주소를 알림 본문에 함께 보여 주어, 거기서라도 보고 옮겨 적을 수 있게 했다.
- 새 피드백 모양을 만들기 전에 사이트가 같은 일을 어떻게 알리고 있는지 먼저 찾는다. 같은 일은 같은 모양이어야 사용자가 배울 것이 준다.
