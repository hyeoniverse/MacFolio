메모 앱을 macOS 메모처럼 도구 막대 중심으로 바꾸면서, 글을 스크롤해도 도구 막대가 위에 남도록 `position: sticky`를 붙였다. 화면에는 버튼이 멀쩡히 보이는데, 눌러도 아무 일이 없었다.

## 배경과 증상

2026년 9월 말, 메모 화면을 macOS 메모처럼 다시 짰다. 그전에는 사이드바 여닫기 버튼과 목록/갤러리 전환 버튼을 창 위에 절대 위치로 띄워 두었는데, 이번에는 이 버튼들을 신호등 버튼과 같은 높이의 도구 막대에 차례로 놓았다. 그리고 글을 길게 스크롤해도 도구 막대가 위에 남게 하고 싶었다. 가장 먼저 떠오른 방법이 도구 막대에 `position: sticky; top: 0`을 거는 것이었다.

증상은 이랬다.

- 도구 막대의 버튼(사이드바 여닫기, 목록/갤러리 전환)이 화면에 보인다.
- 마우스를 올려도 hover 색이 바뀌지 않고, 눌러도 반응이 없다.
- 대신 그 자리를 잡고 끌면 창이 움직인다.

마지막 증상이 단서였다. 버튼 자리에서 창이 끌린다면, 클릭이 버튼이 아니라 창을 끄는 영역(`.macos-titlebar`)에 가고 있다는 뜻이다.

## 창 위에 깔린 끌기 영역

제목 표시줄이 없는 창(Safari, 메모처럼 도구 막대와 제목 표시줄이 합쳐진 모양)은 투명한 끌기 영역을 내용 위에 띄운다. 신호등 버튼이 들어 있고, 이곳을 잡아 창을 옮긴다.

```css
.container.unified .macos-titlebar {
	position: absolute;
	top: 0;
	left: 0;
	z-index: 3;
	height: 52px;
	background: none;
}
```

끌기 영역은 창 너비 전체를 덮으므로, 같은 높이에 있는 도구 막대 버튼은 그보다 위에 있어야 눌린다. 그래서 버튼마다 `z-index: 4`를 주었다.

```css
.memo-tool {
	position: relative;
	z-index: 4;
}
```

![메모 앱의 도구 막대](./images/memo-toolbar.jpg '메모의 도구 막대. 신호등 버튼이 있는 윗줄 전체가 창을 끄는 영역과 겹친다')

## z-index 4가 3보다 아래에 있었다

sticky를 붙이자 도구 막대가 **새 쌓임 맥락(stacking context)** 을 만들었다. 쌓임 맥락 안의 z-index는 그 안에서만 순서를 정한다. 버튼의 4는 도구 막대 안에서의 순서일 뿐이고, 밖에서 보면 도구 막대 전체가 z-index가 없는 한 덩어리로 끌기 영역(3) 아래에 깔렸다.

```text
창
├─ 끌기 영역            z-index 3
└─ 도구 막대 (sticky)   쌓임 맥락 → 창 안에서는 auto
   └─ 버튼             z-index 4, 도구 막대 안에서만 의미 있음
```

버튼에 z-index를 더 크게 줘도 소용이 없다. 경쟁은 버튼과 끌기 영역이 아니라, 도구 막대와 끌기 영역 사이에서 일어난다.

![쌓임 맥락 안에 갇힌 버튼](./images/stacking-context.svg '버튼의 z-index 4는 도구 막대 안에서만 통한다')

## 고른 방법과 버린 방법

| 방법                                        | 결과                                                                         |
| ------------------------------------------- | ---------------------------------------------------------------------------- |
| 버튼의 z-index를 더 키운다 (4 → 100)        | 효과 없다. 경쟁 상대는 버튼이 아니라 도구 막대 전체다                        |
| sticky 도구 막대 자체에 z-index 4를 준다    | 버튼은 눌리지만, 막대가 끌기 영역 전체를 덮어 빈 곳을 잡고 창을 옮길 수 없다 |
| 끌기 영역에 `pointer-events: none`          | 버튼은 눌리지만 창을 끌 수 없다                                              |
| 도구 막대는 두고, 그 아래 영역만 스크롤한다 | 쌓임 맥락이 생기지 않는다. 버튼도 눌리고 빈 곳으로 창도 끈다                 |

앞의 세 방법은 모두 "버튼"과 "창 끌기" 중 하나를 포기한다. 마지막 방법만 둘 다 지킨다. macOS 메모도 도구 막대는 그대로 있고 아래 목록만 스크롤하니 모양도 같다.

## 스크롤하는 쪽을 바꿨다

도구 막대를 붙이는 대신, 도구 막대는 그대로 두고 그 아래 영역만 스크롤하게 했다.

```css
.memo-list,
.memo-reader,
.memo-gallery {
	display: flex;
	flex-direction: column;
	overflow: hidden;
}

.memo-scroll {
	flex: 1;
	min-height: 0;
	overflow-y: auto;
}
```

도구 막대는 쌓임 맥락을 만들지 않으니 버튼의 z-index 4가 창 기준으로 다시 동작한다. 검색 칸 위치가 스크롤에 따라 흔들리지 않는 것도 덤이다.

![sticky 도구 막대 구조와, 도구 막대를 두고 아래만 스크롤하는 구조 비교](./images/sticky-stacking-context-scroll-area.svg '스크롤 상자를 도구 막대 아래로 옮겼다')

여기서 `min-height: 0`이 빠지면 안 된다. flex 자식의 기본 `min-height`는 `auto`라서, 내용이 길면 `.memo-scroll`이 내용 높이만큼 늘어나 스크롤이 생기지 않고 창 밖으로 넘친다. `min-height: 0`이 있어야 남은 높이 안에 갇히고 `overflow-y: auto`가 동작한다.

이 결정은 지금도 `apps/react/src/apps/memo/styles/toolbar.css`에 주석으로 남아 있다. 나중에 누군가(대개 나) 다시 sticky를 붙이려 할 때 막으려는 것이다.

```css
/* 목록·본문·갤러리: 위에 도구 막대, 그 아래만 스크롤한다.
   (도구 막대를 sticky로 붙이면 새 쌓임 맥락이 생겨 버튼이 창 끌기 영역 아래로 깔린다) */
```

## 확인

- Playwright의 `click()`은 누르기 전에 그 좌표에 실제로 대상 요소가 있는지 확인한다. 다른 요소가 덮고 있으면 기다리다 실패한다. 그래서 `e2e/memo.spec.ts`에서 도구 막대 버튼을 누르는 시험(사이드바 가리기, 목록/갤러리 전환)이 통과한다는 것 자체가 "덮이지 않았다"는 확인이 된다.

## 쌓임 맥락을 만드는 것들

z-index가 이상하게 동작하면, 조상 중에 쌓임 맥락을 만드는 요소가 있는지부터 본다. 흔한 것들은 이렇다.

- `position: sticky` 또는 `fixed`
- `position: relative`/`absolute`이면서 z-index가 `auto`가 아닌 것
- `opacity`가 1보다 작은 것
- `transform`, `filter`, `backdrop-filter`
- `isolation: isolate`, `will-change`, `contain`

브라우저 개발자 도구의 3D 보기나 레이어 보기로 쌓인 순서를 확인할 수 있다.

## 배운 것

- z-index는 "전역 순위"가 아니다. 같은 쌓임 맥락 안에서만 비교된다. 숫자를 키워도 안 될 때는 숫자가 아니라 조상을 봐야 한다.
- "보이는데 안 눌린다"는 거의 늘 무언가가 위에 덮여 있다는 뜻이다. `elementFromPoint`로 그 좌표의 실제 요소를 먼저 확인하면 빨리 찾는다.
- 이런 함정은 고친 자리에 주석으로 이유를 남긴다. 코드만 보면 sticky가 더 간단해 보이기 때문이다.

나중에 화면 전체의 z-index를 이름으로 정리할 때(/memo/z-index-layers)도 같은 점을 염두에 뒀다. 이름을 붙여도 쌓임 맥락 안에 갇힌 값은 밖과 비교되지 않는다.
